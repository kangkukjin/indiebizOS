# IndieBiz OS

**공유창고 — AI가 읽는 시대의 미디어 네트워크. 그리고 그것을 채우고 읽는 개인 AI 운영체제.**

[홈페이지](https://indiebiz-homepage.vercel.app) | [English](README.md) | 한국어

IndieBiz OS에는 두 개의 축이 있습니다. 하나는 **AI 에이전트 시스템** — 일상 언어를 행동 언어(IBL)로 컴파일하고, 자주 하는 일을 내가 소유하는 앱으로 굳히는 개인 운영체제입니다. 다른 하나는 **공유창고**입니다 — 세상에 아직 없는 것이고, 한 문단이면 설명이 끝날 만큼 단순합니다. 그래서 이 README는 공유창고부터 시작합니다.

---

## 공유창고 — 플랫폼 없는 미디어 네트워크

**폴더에 파일을 놓습니다. 그게 발행의 전부입니다.** 디스크의 `공유창고/0..4/` 폴더가 노드의 공개 주소에서 색인 없이·변환 없이 실시간으로 서빙됩니다 — 파일시스템이 곧 진실입니다. 사람은 브라우저로 열어보고, **다른 사람의 AI 에이전트는 `/manifest`(JSON)로 읽습니다.**

### 플랫폼은 인간용 매대였다

유튜브·블로그·트위터·쇼핑몰이 서로 다른 서비스로 존재하는 이유는 데이터의 본성이 아닙니다. **인간이 raw 데이터를 직접 못 다루니, 데이터 종류마다 다른 매대(UI)를 미리 지어 독점해야 했기 때문**입니다. 읽는 쪽에 AI가 서는 순간 그 전제가 사라집니다 — 렌더링은 방문마다 읽는 쪽 AI가 즉석에서 하니까요. 그래서 창고 하나가 내용물에 따라 무엇이든 됩니다:

| 창고에 놓는 것 | 그 창고가 되는 것 |
|---|---|
| 동영상 | 유튜브 |
| 글 | 블로그 · 트위터 |
| 상품 목록 | 쇼핑몰 |
| 서비스 목록 | 프리랜서 네트워크 |

방송국이자 쇼핑몰 — 그리고 **형식 자유(schema-on-read)**입니다: 창고는 바이트를 내주고(PDF는 PDF로, 스프레드시트는 스프레드시트로), 해석은 가져가는 쪽 AI의 몫입니다.

### 비용은 질문자가 낸다

기존 웹은 호스트가 조회·렌더링·전송 비용을 다 냈고, 그래서 손님이 몰리면 주인의 서버가 터졌습니다. 창고는 반대입니다: **주인은 파일을 놓을 뿐이고, 뒤지고·거르고·렌더하는 계산은 질문자의 AI가 자기 컴퓨트로 합니다.** 주인의 서빙 비용은 ~0. 그래서 CAPTCHA도 없습니다 — 웹이 봇을 막는 건 서버가 비용을 내는 경제의 증상일 뿐, 여기선 읽으러 오는 AI가 자기 비용을 들고 오므로 문은 "인간이냐 봇이냐"를 묻지 않고 **"누구냐(신원과 레벨)"만** 봅니다.

### 폴더의 숫자가 관문이다

방문자의 레벨(0 → 4)은 이웃 CRM의 등급과 *같은 척도*입니다 — 한 번 승급하면 메신저·포털 회원·창고에 동시에 적용됩니다. 방문자는 `0..자기 레벨`을 **하나의 평평한 목록으로 합쳐서** 보고(같은 이름은 높은 레벨이 이김), 자기 레벨 위의 파일은 **403이 아니라 404**입니다 — 존재 자체가 정보니까요. 유일하게 새는 건 `has_restricted` 플래그 하나, 의도된 *냄새*입니다: "여기 더 있다", 이름도 개수도 없이. 보안이 레벨이므로 주소는 숨길 필요가 없고, 정문은 자신 있게 열어둡니다.

### `/manifest` — 기계용 얼굴, 아주 작은 프로토콜

사람이 보는 페이지 옆에서 같은 목록이 JSON으로 나갑니다 — 제목, 크기·수정시각·직접 URL이 붙은 파일 목록, `has_restricted`, 자기를 설명하는 `about`, 그리고 **인증 방법을 명시한 `login` 블록**. 남의 AI 에이전트가 HTML을 긁거나 역공학하지 않고 당신의 노드를 읽습니다.

그리고 얼굴의 계약 전체가 이것뿐입니다: `GET /manifest` + `GET /f?path=` + 쿠키 로그인. **HTTP와 파일뿐** — IBL도, 인지 파이프라인도, IndieBiz OS 자체도 계약에 없습니다. 어떤 AI 시스템이든 오후 한나절에 같은 얼굴을 구현할 수 있고, 그래야 퍼집니다. RSS·TCP/IP가 그랬듯, 이기는 인터페이스는 지루하게 작습니다.

### 읽는 절반 — 이웃 피드, 파일로 하는 리트윗

이웃의 창고를 등록하면 폴러가 30분마다 그쪽 `/manifest`를 받아 경로·수정시각을 diff해 타임라인으로 만듭니다 — 첫 폴링은 `seed`(팔로우 직후 지난 글 보기), 이후 `new`·`changed`. 보관된 스냅샷은 동시에 **내 동네 전체의 파일명 색인**이 되어, 검색 한 번이 이웃 창고 전부를 훑습니다. 이 층은 **순수 기계 — 모델 호출 0, 토큰 0**입니다: 냄새의 수집은 기계, 해석은 AI.

**이웃이 IndieBiz OS일 필요도 없습니다.** 폴러 밑의 방언 어댑터 층이 nginx·Apache 디렉토리 색인, RSS·Atom 피드(HTML에서 자동 발견), Nextcloud 공개 공유, 심지어 일반 웹페이지의 파일 링크까지 전부 같은 매니페스트 통화로 정규화합니다 — 상대가 아무것도 설치하지 않아도 이웃이 됩니다. 블로그의 RSS도, 파일서버의 색인도 그대로 구독 대상이라 **이미 존재하는 웹 전체가 잠재적 첫 이웃**입니다 — 네트워크가 빈 방에서 시작하지 않습니다.

어댑터가 생기고 나니 문제가 뒤집혔습니다 — 세상엔 이미 창고가 아주 많은데 그걸 *볼* 방법이 없었죠. 그래서 이웃찾기가 두 갈래가 됐습니다: 나를 알린 사람이 오는 **소개글** 수신면과, 아직 나를 모르는 창고를 장르로 훑는 **둘러보기**(실시간 파싱 + 사용자가 고칠 수 있는 시드 목록). 방언 층에는 **neocities** 어댑터가 합류해 개인 홈페이지 169만 개가 창고 후보가 됐습니다. 그리고 한 이웃을 다른 이웃에게 건넬 수도 있습니다 — **공개 추천**은 기계가 사실만 채운 초안을 사람이 고쳐 써야 나갑니다(공개 발행이니까요). 본문이 작은 규약(`공유창고 Warehouse : <url>`)을 지키므로, 받는 쪽 이웃찾기에는 '＋ 창고이웃 등록' 버튼이 그 자리에 자동으로 붙습니다.

창고 주소는 별도 목록이 아니라 이웃의 **연락처 종류 하나**로 저장됩니다 — 이메일·Nostr 키 옆자리(주소만 아는 상대도 정상 이웃입니다). 리트윗은 표준 `.url` 바로가기 파일 하나가 내 창고에 놓이는 것이고, 내 매니페스트가 서빙될 때 원본으로 해소되어 **구독자의 클릭은 나를 거치지 않고 원 창고로 직행**합니다. 친구의 친구(FOAF) 발견이 프로토콜이 아니라 *파일*로 구현된 것입니다.

구독이 익명(레벨 0)에 머물지도 않습니다. 창고에는 가입면이 있고, 인앱 브라우저로 가입·로그인하면 그 자격이 **그 자리에서 캡처됩니다** — 어디에 손으로 옮겨 적을 필요가 없습니다. 이후 폴러가 매니페스트의 `login` 계약으로 로그인해 **승급받은 레벨의 파일까지 피드와 검색에 들어옵니다** — 쿠키가 만료·회수되면 자동 재로그인하고, 로그인이 실패해도 익명으로 계속 폴링합니다(피드는 멈추지 않습니다). 별도 키 교환은 없습니다: 가입 때 내가 만든 자격이 곧 열쇠입니다.

### AI가 채운다 — 생산이 곧 발행

이 시스템의 에이전트들이 만드는 산출물은 **만들어지는 순간 발행됩니다**. 매일 스케줄이 검사·저장된 IBL 함수로 아침 신문·AI 동향 보고서·최신 블로그 글을 창고에 떨어뜨리고, 비즈니스 아이템(나눕니다 · 팔아요 · 할수있습니다 …)은 DB에서 **가레지세일 진열대로 자동 물질화**됩니다 — 아이템마다 문서와 사진이 창고 폴더에 놓여, 외부인이 문의 없이 카탈로그 전체를 봅니다. 소개 문서 끝에는 연락 방법(Nostr 주소)이 자동으로 붙습니다. 구독하는 이웃에겐 이 모든 것이 트윗처럼 흘러갑니다.

### 제일 쉬운 실전 예 — 공유경제

나눌 물건을 `나눕니다`에 놓으면: 이웃들의 피드에 뜨고 → 필요한 이웃의 AI가 알아보고 → DM 한 통 → 건네주면 끝. **결제층 없이 전 루프가 닫히는** 첫 실전 사례입니다. 판매·의뢰 같은 거래 층은 이 위에 올라올 다음 장입니다.

## 1분 요약

**IndieBiz OS는 일상 언어를 진짜 행동 언어 — *IBL* — 로 바꿔 내 데스크톱과 폰에서 직접 실행하고, 자주 하는 일은 내가 소유하는 원탭 앱으로 굳혀줍니다.** 앱스토어도, 클라우드 계정도, 코드도 필요 없습니다.

원하는 걸 말하기만 하면 됩니다. *어떻게* 말하느냐는 오직 그 일을 *얼마나 자주* 하느냐로 갈립니다:

| 하고 싶은 일 | 얻는 것 | 표면 |
|---|---|---|
| *"강남 근처 5억 이하 전세 매물 찾아서 상위 5개를 보고서로 만들어줘"* — 일회성 | AI가 단계를 알아서 찾아 그냥 실행 | **자율주행** |
| 같은 종류의 일을 반복할 때 | 경량 모델이 **재사용 가능한 프로그램으로 번역** → 검사·검토 후 보관 | **조종실** |
| 매일 하는 일 | **탭 한 번 — 0토큰, 즉시 — 폰에서도** 도는 아이콘으로 결정화 | **앱** |

한 시스템, 한 사람, 일회성 질문부터 *써가며 직접 저작한 슈퍼앱*까지. 최소로 시작해 요청한 것만 자라며, AI 에이전트가 당신에게 맞게 끊임없이 벼려주는 대장장이입니다.

## 하나의 생각

대부분의 AI 하네스는 *더 많은 지능*으로 강해집니다 — 더 큰 모델, 더 긴 프롬프트, 더 많은 도구. IndieBiz OS는 다른 데 겁니다:

> **복잡성을 더 많은 지능이 아니라 *구조*로 다룬다 — 구조야말로 어떤 파운데이션 모델도 흡수하지 못하는 단 하나의 층이기 때문이다.**

더 좋은 모델은 *액션을 어떻게 생성하나*를 계속 흡수합니다. 그러나 *액션이 어디에 살고, 누가 소유하고, 얼마나 반복되고, 누구의 몸에서 도는가*는 흡수하지 못합니다 — 그건 생성 *주변의 삶*이고, 바로 거기서 IndieBiz OS가 일합니다.

이 베팅은 **두 개의 생성핵(generative core)** 위에 섭니다. 시스템의 차별점은 거의 전부 이 둘에서 *따라 나옵니다* — 그래서 이 README는 50개 기능을 나열하는 대신, 두 뿌리를 심고 나머지를 그 따름정리로 매답니다:

1. **밑에 진짜 언어가 있다 — IBL.** 시스템의 모든 부분이 컴파일되는 작고 규칙적인 어휘.
2. **어휘와 몸 사이의 깨끗한 이음매.** 능력이 *무엇인가*는 *어느 기계가 도느냐*와 분리된다.

이 둘을 이해하면 기능 목록은 스스로 재생성할 수 있습니다. 그게 핵심입니다.

## 무엇을 목표로 삼는가 — 자율주행이 아니라 입는 로봇

지금의 하네스들은 대체로 **자율**을 지향합니다: 목적지를 주면 AI가 혼자 거기까지 갑니다 — 당신은 명세하고, 결과를 받죠. IndieBiz OS는 **입는 인지 외골격**을 지향합니다. 사용자의 *정착된* 판단을 흡수해 반복되는 일이 거의 무의식적으로 일어나게 하고, 그렇게 해방된 의식을 *반복되지 않는 일*에 쓰게 합니다. 그리고 명확한 목적지가 없어도 됩니다: 가장 깊은 일 — 연구·집필·창업·"내가 뭘 원하는지 알아내기" — 에서 목적은 *알려진 뒤 추구되는 게 아니라 추구 속에서 생성*되니까요. **자율은 목적지를 *전제*로 다루고, 외골격은 *산물*로 다룹니다** — 한 걸음씩 공동저작하되, 판단은 여전히 당신이 쥐고서.

그래서 개발의 북극성은 **착용감(fit)**입니다: 외골격이 의도 속으로 *사라지는가*; *시도가 충분히 싸서* 당신의 취향이 빠른 루프를 도는가; 인간의 판단이 *더 멀리 닿는가* — 인간이 *덜 하는가*가 아니라. 성공은 *맨몸으론 못 만들었을 열매*이지, "내가 얼마나 안 해도 됐나"가 아닙니다. 자율주행차의 종착점은 운전석을 없애는 것이지만, 우리의 종착점은 *시스템이 스스로 몰 수 있게 돼도 운전석을 앉을 가치가 있게* 만드는 것입니다. (전체 비전: `data/system_docs/vision.md`.)

## 철학 — 주어지는 게 아니라 길러내는 시스템

IndieBiz OS는 설치해서 그대로 쓰는 소프트웨어가 아닙니다. **살아 있는 시스템**입니다 — 내 몸에 맞춰 벼린 갑옷, 또는 직접 길들여 타는 말처럼. AI 에이전트가 골격을 세우고, 당신의 삶을 묻고, 짓기 시작합니다 — 하지만 시스템은 *쓰임을 통해서만* 당신의 것이 됩니다. 당신의 습관이 그것을 빚고, 당신의 필요가 그것을 키웁니다.

**같은 설치본은 둘도 없습니다.** 프리랜서의 시스템은 소상공인의 것과 전혀 다릅니다. 남에게 넘기면 맞지 않습니다. 최소(코어 — IBL 엔진·인지 파이프라인·해마)로 시작해 필요에 따라 자랍니다: "내 투자 관리해줘"라고 하면 투자 패키지가 생겨납니다. 앱스토어도, 강제 업데이트도, 만능 정답도 없습니다. 당신의 AI 에이전트가 곧 당신과 함께 시스템을 계속 단조하는 대장장이입니다.

**하드코딩되는 것은 몸뿐, 세계는 임시로만 쥡니다.** 시스템이 고정하는 명사는 몸의 어휘(감각·자기·손발·타자)뿐이고, 세계에 대한 앎 — 사람·장소·사물·관계 — 은 스키마가 아니라 기억에, 신뢰도와 낡음이 표시된 *언제든 틀릴 수 있는* 퇴적물로만 저장됩니다. 기업 온톨로지가 세계를 먼저 모델링하고 그 유지보수에 끝없이 비용을 내는 것과 반대 방향입니다 — 여기서는 주행이 세계상을 계속 고쳐 씁니다. (헌법 조항: `data/system_docs/ibl.md` "명사의 자리".)

그리고 언젠가 이렇게 길러진 시스템들이 서로를 찾아냅니다 — 탈중앙 네트워크로 연결되고, 각자 고유하되 같은 언어를 말하면서. 그것이 비전입니다.

## 왜 이 형태인가 — 한쪽 끝이 아니라 스펙트럼 전체

사람들이 AI에서 원하는 건 둘인데, 시장은 그걸 *별개의 제품*으로 팝니다. 한쪽은 **자율주행**을 원해요 — 말하면 해줌. 빠르지만 끝나고 나면 *소유하는 게 없고* 매번 제값을 냅니다. 다른 쪽은 **산물**을 원해요 — 코드 생산 에이전트가 남는 걸 건네주죠. 하지만 그건 *코드*고, 코드는 돌리려면 **프로덕션 환경(터미널·서버·호스팅)**이 필요합니다.

진짜 일을 하는 한 사람은 그 둘 — 그리고 그 사이의 세 번째 — 을 **하나의 연속체**로 필요로 합니다. 세 번의 구매가 아니라:

- 일회성·탐색적 작업 → **자율주행** (모델이 단계를 *발견*하게)
- 반복되는 작업 → **함수** (자연어가 *간직되는* IBL 프로그램으로 컴파일됨)
- 매일 하는 작업 → **앱** (결정적으로 도는 아이콘, 0토큰)

어떤 단일 *작업*도 셋을 다 쓰진 않지만, 하나의 *삶*은 셋을 다 씁니다. 시장이 이 연속체를 안 파는 건 필요 없어서가 아니라, **개인 규모에서만** 하나의 제품으로 응집되기 때문이에요. 기업에선 세 단계가 세 역할로 갈라집니다 — 개발자가 생산하고, 운영이 자동화를 돌리고, 사용자가 앱을 누르고 — *세 사람*이니 *세 제품.* 그 전부를 *한 사람의 손*에 쥐여주면 하나의 시스템일 수밖에 없죠. **여기서 단일 사용자는 한계가 아니라, 스펙트럼을 응집시키는 *전제조건*입니다.** 그게 "IndieBiz"가 뜻하는 바예요.

### 링크 하나로 도착하고, 어디에든 설치된다

가장 선명한 시연은 지금 손에 든 기기 위의 IndieBiz OS이고, 거기까지 가는 방법은 **설치가 아니라 링크 하나**입니다. 원격 런처가 데스크탑과 *똑같은 표면들* — 자율주행·조종실·앱·공유창고·포식 브라우저 — 를 아무 브라우저에나 띄웁니다. 안드로이드폰, 아이폰, 아이패드, 부엌에 세워둔 낡은 태블릿, 오후에 빌린 노트북.

그리고 원하면 브라우저 탭처럼 보이는 것도 그만둡니다. 런처가 웹 앱 매니페스트를 함께 서빙하므로 **"홈 화면에 추가"가 곧 앱이 됩니다** — 자기 아이콘, 자기 이름, 주소창 없음, 앱 전환기에 독립 항목. 안드로이드든 iOS든 두 번 탭이면 끝이고, 플랫폼별 빌드도 서명도 스토어 승인도 업데이트도 없습니다. 원격 파인더도 같은 방식으로 **IBFind**라는 두 번째 앱이 되어 당신의 파일에 닿습니다. 둘 다 캐시하지 않아요 — 내가 가진 기계의 실시간 뷰라서, 서비스워커가 모든 요청을 그대로 통과시킵니다.

이게 중요한 이유는 폰이 봉인된 *소비* 기기이기 때문입니다: 빌드 툴체인도, 서버도, 자기 앱을 저작해 돌릴 방법도 없어요. 코드 생산 에이전트의 출력은 거기서 **좌초**합니다 — 못 돌리는 앱을 생성한 셈. IndieBiz OS의 "앱"은 컴파일된 바이너리가 아니라 *런타임이 이미 말하는 IBL 위의 선언*이라, 계기 하나를 선언하면 모든 표면에 동시에 그려지고 그중 하나가 **내가 가진 아무 기기의 브라우저**입니다. **저작과 실행이 한 순간으로 붕괴하고, 하드웨어는 상관없어집니다.**

그리고 브라우저는 **화면이 아니라 클라이언트**입니다. 파일은 양방향으로 건너갑니다 — 갤러리에서 올리고, 그 기기로 내려받고. 소리는 스트림을 물어온 기계가 아니라 손에 든 물건에서 납니다. 클립보드는 한 번 탭으로 내 PC에 닿고요. 정직하게 붙는 조건은 하나, 내 기계가 깨어 있어야 한다는 것 — 이건 클라우드가 내 것을 되빌려주는 게 아니라, 내 시스템이 나에게 닿는 일입니다.

가장 가까운 기존 사례 — Apple Shortcuts·Tasker — 는 수요가 실재함을 증명하지만, 스펙트럼의 *바닥*일 뿐이에요: 여전히 고정된 비주얼 언어로 단축어를 손수 저작해야 하고, *사용에서* 결정화되는 게 없으며, OS의 액션에 묶여 *당신의 맥락이 아닙니다.* IndieBiz OS는 그 온디바이스 실행 **더하기** 자율주행 온램프 **더하기** *당신의* 어휘예요. "슈퍼앱 같은" 게 아니라 — **한 사람이 개발자 없이 자기 자신을 위해 짓는 최초의 슈퍼앱.**

## 생성핵 #1 — 밑에 진짜 언어가 있다 (IBL)

모든 능력 — 웹 검색, 파일 쓰기, 폰 알림, 차트 — 은 하나의 언어 **IBL(IndieBiz Logic)**의 프로그램으로 조합됩니다:

```ibl
$뉴스 = [sense:search]{query:"AI 뉴스"}
[self:write]{path:"result.json",content:json($뉴스)}
```

6개 노드(`sense`·`self`·`limbs`·`others`·`engines`·`table`), 하나의 조합 가능한 어휘. 핵심은 액션 수 자체가 *아니라*, 목록이 *작게 유지된다*는 것입니다(정점 332개에서 크게 줄었고, 현재 수치는 아래 [내부 구조](#내부-구조-레퍼런스) 절을 빌드가 재생성합니다) — 관련 도구들을 단일 액션 + 파라미터/`op` 분기로 접기 때문이죠(안드로이드 전용 45개 액션이 `[limbs:android]{op}` 하나로). **언어는 작아지며 더 강해졌고**, 지금도 줄고 있습니다: 2026년 8월의 압축 작업이 163개를 144개로 줄이면서 오히려 표현력을 *늘렸습니다*. 사람이든 *작은 모델이든* 한 줄 쓰면 동작하는, 더 적고 더 조합 가능한 동사들. 모두가 한 어휘를 말하므로, 누적된 경험이 서로 안 맞는 도구 호출 더미가 아니라 *하나의 일관된 코퍼스*가 됩니다.

줄이는 수술은 셋인데, 도구 카탈로그가 보통 자라는 방식과 정반대라 이름 붙일 값어치가 있습니다:

- **복합어를 지우고 보편어를 세운다.** URL 하나가 박혀 있던 `[sense:pew_research]`를 은퇴시키고 `[sense:feed]{url}`을 세웠습니다 — 사전은 −1 +1인데 *가능성 공간*은 "어떤 피드든"으로 넓어지고 중복 파서도 하나로 수렴했습니다.
- **같은 모양의 낱말을 축으로 접는다.** 검색 동사 다섯이 `[sense:search]{source}` 하나로, 사업 원장 동사 넷이 `[self:ledger]{store, op}` 하나로. 단 축은 정직해야 합니다: 연락처는 `[self:ledger]{store:"contact"}`가 아니라 `[others:neighbor]{op}`로 접었습니다 — `store`는 *대등한 원장*의 축인데 연락처는 자식 컬렉션이라, 거기 넣었으면 축이 거짓말을 시작했을 것입니다.
- **절차는 낱말이 아니라 문장이다.** 기존 동사의 호출 순서일 뿐인 것은 새 동사가 아니라 **등록 스크립트**(`[self:script]`)나 앱 인스턴스로 얼립니다. 그래서 "이걸 낱말로 만들까?"의 기본 답이 *아니오*가 됩니다 — 언어 안에 박아 넣은 반(反)어휘-증식 장치입니다.

낱말을 만들기로 했다면 구현만으로 끝나지 않습니다. `description`과 `ops.values`는 모든 에이전트가 읽는 **카탈로그**에 “무엇이 가능한가”를 싣고, 해마 코퍼스의 `(자연어 의도 → IBL 코드)` 용례는 “어떤 말에서 그 낱말을 꺼내며 어떤 인자를 쓰는가”를 가르칩니다. 실행 흔적과 코퍼스에서 관측된 인자만 카탈로그의 `⟨인자: …⟩`가 됩니다. 그래서 **몸(핸들러)·사전(설명)·교재(코퍼스)·관측(인자/반환 모양)**이 함께 닫혀야 새 어휘가 실제로 살아납니다. 설명만 있으면 AI는 존재를 볼 수 있지만 자연스럽게 연상하지 못하고, 코퍼스만 있으면 실행할 몸이 없습니다.

이 작업에서 얻은 측정 교훈 하나는 일반적으로 쓸모가 있습니다: **호출 계수는 생존 신호가 아닙니다.** 은퇴시킨 액션 하나는 계수 19를 기록하고도 결과를 낸 적이 한 번도 없었습니다 — 계수는 "호출됐다"이지 "쓸모 있었다"가 아니었습니다. 살아남은 판별법은 핸들러를 열어 대체 경로를 실측하는 것입니다.

진짜 언어가 있어서 *따라 나오는* 것들:

### → 모든 작업의 세 가지 표면 (트릴레마)

컴파일 타깃이 있으므로, *같은* IBL 표현에 세 가지 방식으로 도달할 수 있습니다. 각 표면은 **{속도·표현력·주권}** 중 둘을 갖고 하나를 내줍니다:

| 표면 | IBL에 어떻게 도달하나 | 트레이드오프 |
|------|----------------------|--------------|
| **자율주행** | 고급 모델이 의도에서 단계를 *발견*하며 IBL을 emit. 새롭고 탐색적인 일에 적합. | 속도+표현력 −주권 |
| **조종실** | *경량* 모델이 자연어를 IBL로 **번역**(컴파일러 프론트엔드). 정적 검사와 효과 검토 뒤 실행하며, 시스템 상태·모델 기어·주행기록과 감독 개입도 한곳에 모입니다. | 표현력+주권 −속도 |
| **앱** | 아이콘이 고정된 IBL 표현을 직접 **호출** — 0토큰·결정론적. 가장 빠르고 발견 가능성 최고. | 속도+주권 −표현력 |

다른 하네스는 이걸 못 줍니다. 컴파일 타깃이 없으니까요: *조종실*이 번역해 넣을 곳도, 검사할 안정적 표현도, 아이콘이 *호출*할 표적도 없습니다. **세 표면은 UI 메뉴가 아니라 — 언어를 가졌다는 사실의 성질입니다.**

### → 결정화 (Crystallization)

빈도가 작업을 표면 사이로 흘려보냅니다. 자율주행이 한 번 해보고(탐색) → 그 IBL 흔적이 조종실의 초안으로 → 자주·안정적으로 반복되면 *소유하고 돌아오는* 2D 데스크탑 위의 **앱 아이콘(0토큰)**으로 결정화됩니다. 저장된 단축어는 간직하는 아이콘과 *같지 않습니다* — 차이는 **배치**에 있고, 대부분의 하네스엔 런처 표면이 아예 없어 증명된 흐름이 *살 곳*이 없습니다. 이건 *모델이 싸져도 살아남습니다*: 매일 하는 일에서 원하는 건 더 싼 토큰값이 아니라 결정성·즉각 응답·통제니까요. **굳히는 건 증명된 것만.**

(조종실의 두 규칙: 부작용 있는 단계는 명시적 확인을 거쳐야 실행되고[읽기 전용은 무마찰], 해마는 *사용자가 인정한 결과만* 학습합니다. 앱 계기는 선언 기반 — 각 계기는 IBL 액션의 `app:` 블록이고, 하나의 선언이 데스크탑·원격 런처·폰에 똑같이 렌더됩니다.)

### → 일하는 자리도 앱이다 — 문서·스프레드시트·코딩

앱 표면에 있는 것이 굳힌 IBL 호출뿐은 아닙니다. 파일과 저장소를 **사람과 AI가 같은 자리에서** 다루는 작업 공간 셋이 독립 창으로 열립니다:

- **문서** — DOCX·ODT·RTF·PDF를 원래 형식 그대로 편집하고(로컬 ONLYOFFICE 편집 서버), HWP·HWPX도 원형 그대로 고칩니다(로컬 오픈소스 엔진, 외부 글꼴 요청 없음). PDF 쪽 회전·삭제·재정렬, OCR 교정과 검색 가능한 사본, Markdown·소스 문서 미리보기와 내보내기.
- **스프레드시트** — 통합문서 편집, CSV/TSV 가져오기(식별자·전화번호·수식처럼 보이는 텍스트를 망가뜨리지 않고), 형식 변환 사본, 인쇄 양식, 그리고 고정된 시트 스냅샷에서 문서 보고서로 가는 표.
- **코딩** — 저장소를 열면 과제마다 따로 떨어진 작업 공간이 생기고, 실행자(Codex 같은 네이티브 CLI든 일반 API 모델이든 교체 가능)가 고친 뒤 검증 명령 → 변경 검토 → 승인 → 반영·커밋으로 닫힙니다.

셋을 묶는 규칙은 하나입니다: **엔진은 초안만 쓰고, 원본을 바꾸는 것은 당신의 명시적 저장뿐.** 그 사이 바깥에서 원본이 바뀌었으면 저장은 거절되고, 닫힌 편집 창의 뒤늦은 저장은 버려지며, 버전과 초안은 되돌릴 수 있습니다. AI의 변경안은 당신이 화면에서 본 선택에 묶여 **변경 추적**으로 들어오지, 파일을 몰래 고쳐 쓰지 않습니다. 그리고 여기에 새 어휘는 없습니다 — 에이전트는 이미 있던 `self:document`·`self:sheet`로 같은 편집 세션에 들어옵니다.

(정직한 범위: 편집 엔진은 당신의 PC 안에서만 열리므로 원형 편집은 데스크탑 전용이고, 코딩 앱의 쓰기 경계는 현재 macOS에서만 보장됩니다. 복잡한 한컴 문서의 전수 호환성 같은 미완료 항목은 `docs/DOCUMENT_APP_DESIGN_2026_10_02.md`·`SPREADSHEET_APP_DESIGN_2026_10_02.md`·`CODING_APP_DESIGN_2026_10_02.md`의 '구현 상태'에 그대로 적혀 있습니다.)

### → 통화 대수 (Currency Algebra)

`table` 노드는 도메인 무관 변환자 — filter / sort / take / select / compute / dedup / groupby / join / union / merge / **rename** / **flatten** — 를 가집니다. 목록과 레코드가 명시적인 값으로 흐르고, emitter(chart / spreadsheet / document / structure)가 그 값을 산출물로 바꿉니다. 그래서 어떤 검색 결과든 `>>`로 접착 코드 없이 조합됩니다:

```ibl
$접수 = [{id:"a",score:3},{id:"b",score:7},{id:"c",score:5}]
$접수 >> [table:filter]{where:($행)=>$행.score>=5} >> [table:sort]{by:"score",descending:true} >> [table:select]{columns:["id","score"]}
```

커버리지는 명사, 깊이는 통화 동사. *대수를 가진 언어*가 한 줄의 검색을 한 편의 보고서로 만듭니다.

### → 파이프만이 아니라 문장

파이프는 "그다음"밖에 말하지 못합니다. 그런데 실제 요구는 "찾은 것 *각각*에 대해", "~인 경우에만", "될 때까지"도 말합니다. 현재 IBL은 이것들을 문장 문자열이나 암묵 슬롯이 아니라 **값·식·블록**으로 표현합니다:

- **`[table:each] { … }`** — 입력 목록의 각 행을 `$it`과 `$i`로 받습니다. `mode:"map"`은 입력당 결과 하나, `flat_map`은 한 겹 펼침, `effect`는 값 없는 효과를 뜻하며 `parallel`을 써도 출력 순서는 보존됩니다.
- **블록** — `[if:Bool 식] { … } [else] { … }`, `[case:식] { … }`, `[repeat:…] { … }`, `[try] { … } [catch] { … } [finally] { … }`. 조건·인자·콜백은 같은 식 규칙을 쓰고, 판정할 수 없는 값을 조용히 false로 만들지 않습니다.

정직하게 덧붙이자면, 문법을 더하자 **판정 불능인데 단정해 버리는** 결함 부류가 통째로 드러났습니다 — 조건 평가 실패가 "else"로 보고되고, 빈 결과가 성공으로 보고되는 식이었죠. 하나씩 명시적 실패로 고쳤고, 이제는 그 모양을 일부러 찾습니다: **폴백 분기가 있는 자리마다, "모르겠다"가 "아니다"로 인쇄되고 있지 않은지 확인할 것.** 지금은 판정 불능이 조용한 거짓이 아니라 **오류**로 올라옵니다.

### → 한 문장 = 한 프로그램

현재 문법은 명시 값·함수·반복·실패를 한 구조로 다룹니다. 새 저장 프로그램은 `#!ibl edition=2`로 의미를 고정하고, 실행 전 `check:true`로 같은 컴파일러의 진단을 받습니다:

- **값** — 목록은 언제나 목록이고 `.items` 같은 가상 필드는 없습니다. 도구가 Record를 반환할 때만 선언된 `.items`·`.text`를 고릅니다. 문자열 보간은 `f"${값}"`로 명시합니다.
- **함수** — `[def:이름]($첫인자,$선택=기본값){…}`로 정의하고 `[fn:이름]{선택:값}`으로 부릅니다. 첫 인자가 파이프 자리이며 자유 변수와 재귀는 거절됩니다.
- **오류·반복** — 순차 실행은 실패 즉시 멈춥니다. 계속할 곳은 `try/catch`로 쓰고, 전건 실패를 값으로 모을 때만 `each{on_error:"collect"}`와 `Result`를 씁니다. 반복은 횟수·`while`·`until`을 명시합니다.
- **증거·재개** — 값과 원천 완전성·증거는 분리됩니다. 큰 결과는 참조로 회수하고, 끊긴 실행은 `resume:{run_id}`와 같은 코드·입력으로 이어 이미 끝난 외부 작업을 되풀이하지 않습니다.

선은 일부러 여기서 긋습니다. 범용 자료구조와 재귀는 언어로 들이지 않고 **등록 스크립트**(`[self:script]`)로 얼립니다 — 하네스 언어가 프로그래밍 언어로 자라는 순간, 작은 모델이 읽을 수 있다는 애초의 이유가 사라지기 때문입니다.

저장된 프로그램도 같은 함수 계약을 씁니다. 검사한 정의를 `[self:workflow]{op:"save",edition:2,code:...}`로 저장하고 `[fn:이름]{인자:값}`으로 호출합니다. 기존 저장본은 호환 어댑터가 원래 의미를 보존하지만, 새 코드를 쓰는 기준은 하나뿐입니다. 실제 계약과 예제는 [`data/system_docs/ibl.md`](data/system_docs/ibl.md)와 [`data/guides/ibl_composition.md`](data/guides/ibl_composition.md)가 정본입니다.

### → 개인 규모로 열린 웹에 발행하기

사적 액션을 돌리는 그 언어가 하나를 공개 인터넷에 *노출*할 수도 있습니다. `others` 노드의 작은 액션 가족이 IBL 흐름을 누구나 열 수 있는 진짜 웹 주소로 바꿔줍니다 — 빌릴 서버도, 배포할 프레임워크도 없이:

- `[others:portal]` — `/h/<주소>/`의 **개인 포털**: 가족·친구·이웃에게 로그인과 레벨(0 손님 → 4 가족)을 주면, *아무것도 설치하지 않고 브라우저로* 당신의 계기와 콘텐츠를 빌려 씁니다. 회원은 당신의 이웃 CRM과 통합됩니다 — 별도 계정 시스템 없음.
- `[others:family_news]` — `/n/<주소>/`의 **가족신문**, 폰 사진으로 조판되며 방명록·사진 업로드 포함.
- `[others:bulletin]` — `/b/<주소>/`의 **로그인 없는 자유게시판**; 주소를 아는 사람이 글·사진을 남깁니다.
- `[others:showcase]` — `/s/<주소>/`의 **공개 파일 공유**, 당신의 디스크에서 바로 서빙.
- `/r/<주소>/`의 **정기보고 발행 면** — 보고서 폴더를 *볼 때* HTML로 렌더하므로, 매일 새 보고서가 나와도 링크는 그대로고 내용만 늘 최신입니다(설정뿐, 전용 동사 없음). 별개로 `[others:publish]`는 내가 쓴 글을 Nostr 공개 장문(NIP-23)으로 발행하고 공유 링크를 돌려줍니다.

이것이 더 큰 비전의 첫 걸음입니다 — 개별적으로 길러진 시스템들이 서로를 찾아내는. 원리는 **"커뮤니티당 노드 하나"**: 당신의 시스템이 노드이고, 주변 사람들이 그 노드에 닿는 브라우저로서 바깥에서 같은 언어를 말합니다.

### → 공유창고 — 노드의 정문

위의 표면들이 *당신이 만드는 목적지*라면, 노드 자신이 주소를 갖는 정문 — 발행 폴더·레벨 관문·기계 얼굴·이웃 피드·리트윗 — 은 이 README의 [맨 앞](#공유창고--플랫폼-없는-미디어-네트워크)에서 다뤘습니다. 언어의 관점에서 한 가지만 여기 남깁니다: **그 전부가 IBL에 새 동사를 하나도 더하지 않았습니다.** 발행은 이미 있던 어휘(`self:copy`·`table:document`·`self:delete`)의 조합이고, 가장 바깥의 발견 고리 — `website`가 내 창고인 Nostr 프로필 + 인사와 주소만 담은 `#IndieNet` 노트 — 는 `[self:ledger]{store: "document", op: "publish"}` 입니다. 낯선 사람이 열린 릴레이에서 나를 찾고, *나에 대한 내용은 내 창고에서 읽습니다.*

## 생성핵 #2 — 어휘와 몸 사이의 깨끗한 이음매

능력의 *의미*(`[sense:here]` = "나 어디 있지?")는 몸 독립적이고, *어떻게* 도는지는 기계에 달렸습니다. 이 둘을 깨끗한 이음매로 갈라놓으면 두 번째 따름정리가 나옵니다.

### → 한 동사, 세 질문: 무엇을·어느 몸이·어느 표면에서

하나처럼 보이는 세 질문이 사실은 다릅니다. *이건 무슨 뜻인가?* — `[limbs:radio]{op: "play"}`는 어디서나 "이 방송을 틀어라"입니다. *어느 기계가 할 수 있는가?* — 스피커가 달린, 카메라가 달린, 그 파일이 놓인 디스크를 가진 기계만. *결과는 어디에 내려앉아야 하는가?* — 내가 지금 보고 있는 곳에. 이 셋 중 둘을 겹쳐놓으면 **맞는 기계에서 틀린 일이 조용히 일어납니다.**

이음매가 셋을 갈라둡니다. `runs_on` 태그가 각 액션을 정직하게 표시합니다 — `anywhere`, 또는 그 능력을 실제로 가진 기계에 묶임. 어휘는 브랜드를 말하지 않습니다: 허브는 맥일 수도 윈도우 PC일 수도 있고(그래서 태그도 macOS 가 아니라 *연산 기계*를 뜻하는 `pc_only`), 카메라를 찾는 액션은 '폰'이 아니라 *카메라*라고 말합니다. 본래 지표적인 감각 — *나 어디 있지*, *무엇이 보이지*, *무엇이 들리지* — 은 어느 몸에서나 같은 뜻이고, 다른 건 답하는 방식뿐입니다. 하드웨어가 없는 몸은 추측하지 않고 없다고 말합니다.

### → 사전이 몸마다 다른 몸들, 명함으로 말을 트다

이음매는 "어느 기계가 도는가"보다 한 층 더 깊이 자릅니다: **설치된 몸은 자기 어휘만 소유합니다.** 배포물은 전체 사전집이지만 설치는 실제로 가진 것만 싣고, 액션 카탈로그와 해마가 둘 다 소유-필터를 지납니다 — *남의 단어는 배우지 않는다.* (몸이 "가진 것"은 폴더가 아니라, 보유한 전체 사전집 위에 몸별로 그어지는 활성 원장입니다 — [무엇이 코어이고 무엇이 당신 것인가](#무엇이-코어이고-무엇이-당신-것인가) 참조.)

그러면 한 몸이 다른 몸을 어떻게 부릴까요? 특권 배관이 아닙니다. 각 몸은 **명함**(`GET /nodes/card`)을 내놓습니다 — 무엇을 할 수 있는지의 설명만 담은 투영, 몸끼리 등록할 때 자동 교환되는 ~70토큰짜리 냄새. 그다음엔 그냥 **자연어로 부탁합니다**(`[others:ask]`): 받는 몸이 *자기 사전으로* 컴파일해 실행하고 결과를 돌려주거나, 자기 어휘에 없으면 정직하게 거절합니다. 상대의 액션 이름을 흉내 내지 않으니 어느 쪽도 남의 사전을 알 필요가 없습니다.

몸을 특별하게 만드는 건 배선이 아니라 **등급**입니다. 몸들은 같은 이웃 CRM 안의 이웃이고, 그 레벨은 당신이 줍니다. 당신의 폰은 그저 최고 레벨 이웃이고, 낯선 몸의 부탁은 다른 모두에게 적용되는 바로 그 문에서 거절됩니다. (`[others:delegate]`는 *인격*에게 일을 맡기고, `[others:ask]`는 *몸*에게 능력을 부탁합니다.)

몸은 잠깐짜리일 수도 있습니다. USB를 낯선 PC에 꽂으면 원하는 동안 **얇은 손발**이 됩니다(`[self:limb]`가 발급하고 `[limbs:guestpc]`가 시킵니다). 두뇌와 신원은 허브에 남고 — USB에 실리는 건 비밀번호가 아니라 폐기 가능한 limb key 하나 — 작은 헬퍼가 허브로 *바깥으로* 접속하므로 그 PC의 방화벽은 건드릴 필요가 없습니다.

세 번째 질문인 표면은 진짜로 별개의 축입니다. 데스크탑 런처에서 재생을 누르면 그 기계에서 소리가 납니다. 폰 브라우저에서 **같은 계기**를 누르면 *거기서* 납니다 — 요청이 "어느 기계가 실행했나"가 아니라 "어느 표면이 물었나"를 싣고 오기 때문입니다. IBL 한 줄 그대로, 그걸 그리는 선언에는 분기가 없습니다. 같은 축을 타고 다운로드는 손에 든 기기로 내려가고(작업은 허브에서 일어났는데도), 클립보드는 반대 방향으로 건너갑니다.

이음매는 기억도 깨끗이 가릅니다: 사용자 세계-데이터(연락처·비즈니스·일정·건강)는 공유·동기화(CRDT 합집합 머지)하고, 각 몸의 주관적 기억(대화·해마·자기상태)은 사적으로 남습니다.

## 갈라진 마음 — 문제를 규정하고, 그다음 실행한다

대부분의 시스템은 단일 주체로 계획-실행합니다. IndieBiz OS는 문제 규정·실행·감독·평가를 **서로 다른 역할**로 가릅니다:

```
사용자 메시지
   ↓ 연상: 해마·심층메모리
   ↓ 반사: EXECUTE or THINK
   ↓ 세계 지도: 관련 이름·방법·도구의 작은 단서
   ├─ EXECUTE/반사 → 직접 실행 → 종료
   └─ THINK → 의식이 문제·달성 기준을 규정
                    ↓
                 실행기
                    ↔ 필요한 때만 의식 감독
                    ↓
           도구 없는 최종평가 → 필요하면 1회 최소 보완
                    ↓
       응답 전달 뒤 실행·관계·공간 기억의 지속 가치 선별
```

두 갈래의 검증은 같지 않습니다. `THINK`만 의식이 만든 달성 기준을 가지며, 최종평가자는 그 기준의 충족만 판정합니다. 미달이면 발견한 결함을 한꺼번에 넘겨 **최대 한 번** 보완하고 같은 기준으로 다시 봅니다. `EXECUTE`와 반사는 정상적인 짧은 조회에 평가 호출을 더하지 않습니다. 따라서 에피소드의 평가값 `NULL`은 실패가 아니라 “검수 대상이 아니었음”일 수 있습니다. `UNKNOWN`은 기준과 증거만으로 판정할 수 없었다는 뜻입니다.

의식 에이전트는 실행기가 보기 *전에* 원시 요청을 잘 규정된 문제로 다시 씁니다. 둘이 다른 주체이므로, 실행기는 *이미 규정된* 문제를 풉니다: 단일 계획-실행 주체라면 *고려했다가 자제*해야 할 빗나가거나 위험한 선택지가 애초에 프레임에서 대체로 빠집니다. 이건 **정렬이 아니라 봉쇄**입니다 — 안전을 규칙으로 덧대는 게 아니라 *목표에 녹여서*. 그리고 이건 단일 주체가 *가질 수 없는* 속성입니다 — 자기 질문을 지울 수 없으니까요. 더 뛰어난 추론 모델이 흡수하지 못하는 이유가 바로 이것입니다.

3단계 모델 티어 — **경량·중급·본격** — 가 이를 싸게 받칩니다. 다만 어느 인지 역할이 어느 티어를 쓰는지는 못박혀 있지 않습니다. **자동 변속기**(무의식 분류기)가 이미 작업마다 티어를 고르고, 그 위에 **수동 변속 레버**(`절약 / 균형 / 최대`)가 자동차 기어처럼 시스템 전체를 한 번에 변속합니다. 네 개의 인지 축 — *분류·평가·실행·의식* — 이 각각 선택된 기어를 통해 티어로 매핑되므로, 레버 하나가 재시작 없이 시스템 전체의 비용 대 품질을 재조정합니다. (모델은 — 그리고 그 API 키도 — 에이전트별 설정이 아니라 기어에서 흘러나옵니다.)

## 당신을 — 그리고 당신의 공간을 배우는 기억들

여러 기억이 대화에서 자동으로 배우고, 스스로를 청소합니다:

- **해마 (절차기억)** — fine-tuned 768차원 임베딩 모델이 자연어를 과거 IBL 코드로 연결합니다(코퍼스가 자라면 Apple Silicon 에서 로컬 재학습; 현재 세대의 Top-5 점수·코퍼스 크기는 `data/system_docs/memory.md` 의 해마 세대 표가 정본). 성공한 실행은 재사용 가능한 용례로 증류되어 *당신의* 반복 작업이 빨라집니다. 닫힌 루프가 회상된 용례의 실제 성공/실패를 기록해, 입증된 패턴은 떠오르고 나쁜 것은 가라앉습니다.
- **심층메모리 (관계기억)** — 매 대화 후 경량 패스가 당신에 대한 지속적 사실(선호·결정·중요 날짜)을 추출하고, 마지막 확인일과 함께 관련 시점에 회상합니다.
- **포식 기억 (공간기억)** — AI가 디스크·웹·코드를 *뒤져 찾을 때마다* 그 공간에 대해 배운 것을 세션 너머로 축적합니다: 폴더 정체, 검색 관습, 막다른 길, 그리고 *누구의 자료가 어디 사는가*의 주인 모델. 디스크를 뒤지며 쌓은 모델이 웹 검색의 중의성을 풀고, 그 역도 성립하는 *복리 루프*. 정보 포식 이론의 어휘를 빌리되, 새로운 건 그것을 stateless 모델에 결여된 *지속 기억*으로 다루고 — 컨트롤러도 정지공식도 없이 — 그 기억만 더한다는 점입니다. (`[self:forage]`, 맥 자아 전용.)
- **세계의 지도 (지식의 단서)** — AI가 이미 아는 것과 찾아볼 것으로 가는 구조적 어휘 카탈로그입니다. 분야·이름·문제–방법–도구 관계만 작게 건네고, 지식 내용은 모델과 원출처에 둡니다. 모든 작업 에이전트가 관련 조각을 한 번 선택하므로, 몰라서 언급하지 못한 방법과 도구를 상기하되 억지 대안 제안으로 목표를 바꾸지 않습니다.

주기적 정리 패스(아래 면역 순찰의 일부)가 근접중복을 병합하고, 낡거나 입증된 나쁜 항목을 가지치고, 모순을 정정해 기억이 비대해지지 않고 날카롭게 유지됩니다. 장기 기억 쓰기는 **최종 응답이 전달된 뒤** 사용자 원문에서 지속 가치가 있는 것만 한 번 선별하며, 저장 0건도 정상입니다.

## 시스템은 자기를 지켜본다

- **World Pulse** — 매시간: 경제, 날씨, 뉴스(6시간마다), 사용자 활동, 시스템 건강.
- **Self-Check** — 하루 1회, 결정론 점검: 정적 정합성 + 액션별 fixture 통화 probe + 골든 파이프라인(**모델 호출 0** — 이걸 대신하던 AI 순찰은 은퇴했습니다). `/self-inspect` 시 시스템 AI가 실패를 재시도해 transient/reproducible로 분류하고 수정 난이도(쉬움/중간/어려움)를 평가합니다.
- **커밋 시점 가드** — 어휘를 붙들어 온 검사(소스↔도구 스키마↔핸들러 삼각 일치)를 **이음매**, 즉 액션이 아닌 것들에까지 넓혔습니다: 열린 채 실패하지 않고 **닫힌 채 멈추는** 인증 게이트, 공개된 라우트가 정말 자기 게이트를 갖고 있는지 대조(오라클은 살아있는 라우트 테이블이지 다시 파싱한 목록이 아닙니다), async 코드 안의 블로킹 호출 탐지(이 서버는 자기 자신을 자주 부르므로 막힌 루프는 곧 자기교착입니다), 윈도우 이식성을 위한 유닉스 전용 import 스캔, 그리고 **신선 clone CI** — `main`이 그것을 쓴 기계에서만 통과한 적이 있었기 때문입니다.
- **부팅 관측** — 없어도 서버는 떠야 하는 서브시스템들은 "기록하고 넘어간다"로 감싸는 게 맞습니다. 문제는 사흘 뒤 "왜 스케줄이 안 돌았지?"의 답이 터미널 스크롤 저편에 있다는 것이죠. 이제 그 블록들이 전부 계측되고, 부팅 실패는 건강 엔드포인트에 드러납니다.
- **자기수리** — 당신이 직접 고치라고 명령하면 시스템은 자기 코드를 스스로 고칩니다. 다만 살아 있는 자신 위에서가 아닙니다. 변경은 전부 **격리된 작업 사본**에서 이뤄지고, 같은 사본에서 관련 검사를 통과한 **바로 그 바이트 묶음만** 정본에 반영됩니다. 적용·재기동·실패 시 복구는 백엔드 밖의 재기동 제어자가 맡습니다 — *자기 죽음 뒤에 실행돼야 하는 단계는 죽음을 넘어 사는 프로세스의 몫*이니까요. 격리가 실패했을 때 정본에 직접 쓰는 우회로는 없습니다. 기계로 확인되는 사실(실제 시험 보고서, 후보·환경 지문)을 다른 AI가 산문으로 다시 승인하는 절차는 없앴고, 의미 판단이 필요한 조건만 평가자가 봅니다. 권한은 *사람이 명령한 그 실행 하나*에 묶입니다: 스케줄·위임·외부 채널은 수리 권한을 얻지 못하고, 같은 이름의 다른 실행도 그 권한을 빌려 쓰지 못합니다.
- **프롬프트 구성** — 시스템에는 여러 종류의 LLM 에이전트(시스템 AI·프로젝트 에이전트·의식과 의식 감독·무의식 분류기·평가자·경험 증류·IBL 번역기 …)가 있고, 저마다 프롬프트를 다르게 조립합니다. 런처 안경(로고) 메뉴의 **프롬프트 구성** 창이 에이전트별로 그 조립을 층(시스템 프롬프트 / 턴 컨텍스트 / 사용자 메시지)으로, 조각마다 출처·조건·분량과 함께 보여줍니다. 실행기억·IBL 환경·프로젝트 기억·세계 상태 같은 가변 조각은 샘플 메시지 한 건으로 정본 빌더를 그대로 돌려 만들므로 분량이 실제 값입니다(임베딩 검색만, 모델 호출 0). 형제인 **가이드 파일** 창은 `data/guides/`의 모든 가이드를 등록·신선도·예산 표식과 함께 나열하고, 그 자리에서 읽고 고칩니다.

## 당신이 설계하는 에이전트, 위임하는 팀

단순히 "의사처럼 행동해"가 아닙니다 — 에이전트가 **누구**이고 **어떻게** 대화하는지를 정의하고, 에이전트는 *당신의* 맥락(복용 약·선호·지난 대화)을 기억합니다:

```yaml
agents:
  김_원장:
    role: |
      당신은 20년 경력의 내과 전문의 김원장입니다.
      항상 환자의 걱정을 먼저 인정한 뒤 질문하고,
      의학 용어는 일상 언어로 설명하며, 늘 명확한 다음 단계로 마무리합니다.
    allowed_nodes: [sense, self, limbs, others, engines]
```

에이전트가 *누구*인지를 정의하지, *어느 모델*이 도는지는 정의하지 않습니다 — 모델과 API 키는 위의 기어 레버가 중앙에서 결정합니다(특정 에이전트만 티어를 따로 고정하려면 **에이전트 핀**으로 오버라이드). 에이전트는 팀을 이뤄 위임합니다 — 동기로(`call_agent`, 결과 대기), 스케줄로(다른 에이전트의 시계에 일을 맡김), 또는 작업계획서로(`create_plan` → `execute_plan`, 각자 자기 파트를 실행하고 넘김). 소통 채널(Nostr·Gmail)을 가진 에이전트는 원격에서 명령을 받고 **IndieNet**(Nostr; DM은 최신 NIP-17 gift-wrap 암호화)으로 다른 사람의 에이전트와 닿습니다.

3. Claude가 저장소를 클론하고, 의존성(Python·Node.js)을 설치하고, 필요를 물어, 당신에 맞춘 시스템을 구성합니다.

> **왜 Claude Desktop인가?** IndieBiz OS는 `npm install`로 끝나는 정적인 앱이 아닙니다. 설치하는 에이전트가 곧 당신에게 맞춰 계속 단조하는 대장장이가 됩니다.

**필요한 것:** LLM API 키(Anthropic·Google·OpenAI) — 또는 키가 필요 없는 Claude Code / Codex 구독 로그인; 몇 가지 질문에 대한 답; 외부 API 키는 해당 기능을 실제로 쓸 때만. 공유창고·원격 접속 같은 공개 표면까지 켜려면 **Cloudflare 계정+본인 도메인**이 추가로 필요합니다 — 전체 세팅 지도는 [시작 가이드](GUIDE.md#1-시작하기)에 있습니다.

## 무엇이 코어이고 무엇이 당신 것인가

IndieBiz OS는 **표준 코어**(IBL 문법, 기능어 노드, 백엔드/프론트 엔진, 도구 패키지·앱 카탈로그)를 배포하지만, 설치되는 순간 *당신의 인스턴스*가 됩니다 — 당신은 어휘를 더하고, 앱을 설치·저술하고, 대화와 설정을 쌓습니다. 이 둘의 경계는 단일 진실 하나로 그어집니다: `data/core_manifest.json` — 리포에 커밋된 것에서 파생(`scripts/build_core_manifest.py`)되므로, 무엇도 손으로 태깅할 필요가 없습니다.

두 가지 보장이 따라옵니다:

- **설치가 모든 걸 당신에게 쏟아붓지 않습니다.** 많은 패키지가 자기 API 키를 요구합니다 — 다 깔면 못 쓰는 것에 파묻힙니다. 전체 카탈로그는 배포되되 **큐레이션된 소수만 기본 활성**이고, 나머지는 원할 때 켤 수 있게 대기합니다. 2026-09부터 그 스위치는 보유한 전체 사전집 위의 **몸별 활성 원장**입니다: 단어묶음을 깨우거나 잠재우면 원장과 프롬프트 캐시만 바뀌고 폴더 이동도 재빌드도 없으며, 잠든 묶음은 파일·설정·용례·벡터를 보존합니다. 조작은 **내 어휘**(런처 안경 메뉴, 설정 바로 아래)에서 합니다 — 묶음이 폴더·단어묶음 저장고·쓰레기통에 놓이는 아이콘 데스크톱 — 그리고 묶음은 `.iblpack` 파일 하나로 오갑니다: 저장고에서 가져오고, 묶음 자신의 메뉴에서 내보내며, 가져온 묶음은 잠든 채 도착해 깨워야 실행됩니다(형식: `docs/IBLPACK_FORMAT.md`). 각 패키지는 `origin`(core / user)을 갖고, 데스크탑 앱 패키징이 이 매니페스트에서 만들어지므로 당신이 커밋한 개인 앱·파일은 배포로 새지 않습니다. (개인 패키지를 백업용으로 커밋했다면? `origin: user`로 표시하면 코어에서 빠집니다.)
- **업데이트가 당신 것을 절대 덮지 않습니다.** 재설치·업데이트는 코어 소유 파일만 갱신합니다. 어떤 패키지를 켜고/껐는지, 당신이 저술한 어휘·앱, 설정, 대화 이력은 그대로 살아남습니다 — 업데이터가 번들의 기본 배치를 다시 강요하지 않고 *당신이 고른* 폴더 위치를 존중합니다.

이건 표준 문법과 당신의 개인 사전을 가르는 하부/상부(substrate/superstructure) 이음매와 같은 것을 — 패키지·앱·설치·업데이트 층까지 밀어낸 것입니다.

## 기술 스택

- **Backend**: Python FastAPI (포트 8765)
- **Frontend**: Electron + React (TypeScript)
- **AI Providers**: Anthropic (Claude), Google (Gemini), OpenAI (GPT), DeepSeek, OpenRouter, Ollama (로컬) — 여기에 API 키가 필요 없는 구독 로그인 CLI 하네스 둘, **Claude Code**와 **Codex** (Codex의 모델과 추론 강도는 설치된 Codex 자신의 모델 카탈로그에서 고르므로 새 모델이 코드 변경 없이 나타납니다)
- **Database**: SQLite
- **문서 엔진 (선택)**: ONLYOFFICE Docs(로컬 컨테이너, 이 PC의 loopback에만 게시) — 사무 문서·스프레드시트 원형 편집 · RHWP — HWP/HWPX · Tesseract — OCR. 없어도 시스템은 뜨고, 해당 편집 기능만 꺼집니다.
- **Deployment**: 로컬 우선, 원격 접근은 Cloudflare Tunnel 옵션

## 실행

```bash
# 개발 모드
./start.sh

# 또는 개별 실행
cd backend && python3 api.py        # 백엔드 (포트 8765)
cd frontend && npm run electron:dev  # 프론트엔드 (Electron)
```

`start.sh`는 저장소의 `.venv`로만 백엔드를 띄웁니다(`python3 scripts/bootstrap.py`로 생성; 시스템 파이썬으로 조용히 떨어지지 않습니다). `backend/api.py`는 재기동 제어자입니다: 기본 동작은 `start`이고, 운영은 `status` / `restart --wait` / `shutdown --wait`로 합니다.
