# AI 동향 보고서 가이드 (AI Trend Report)

**적용 범위:** 정기 AI 뉴스·동향 보고의 작성·갱신·발행을 요청받았을 때 사용한다. AI 분야라는 이유만으로
단발 심층연구·역사 비교에 적용하지 않는다. 심층연구는 의식이 작성하여 전달한 연구계획에 따라 진행한다.

**직전 보고서·원장을 읽고 새 자료를 더해 무엇이 달라졌는지(델타)를 쓰는** 정기 보고서다. 매번 같은 내용을 새로 쓰지 않는다.

**전체 보고서는 Markdown 저장과 공유창고 HTML 발행(즉시 공개)까지 완료한다.** 비공개·초안 요청 또는 NEW 0건이면 공개하지 않는다.

**작성 요청의 완료 범위:** 이 정기 보고서는 기존에 승인된 공유창고 발행 업무다. 작성 요청에 발행이라는 단어가 없어도 같은 호 HTML 발행까지 포함한다. 공개 글의 사용자 직접 작성 일반 원칙을 이 업무의 발행 금지로 확대하지 않는다(`decisions.yaml`의 `public-content-user-authored`). 이 승인은 다른 공개 채널로의 전송·게시까지 포함하지 않는다.

> **매일 점검하고, 검증된 신규 사건이 있는 날 발행한다.** 새 사건인지와 근거의 충분성은 실행자가 판단하며, 확정한 사건의 실제 행 수를 §3-0의 계수 계약으로 센다. 기계 계수는 의미 판단을 대신하지 않으며, 봉투의 필드 수나 후보 수를 신규 건수로 쓰지 않는다.

세 섹션 + 조건부 하나: ①투자·경제 ②기술·연구 ③AI 활용 사례 ④(걸릴 때만) indiebizOS 함의.

> **독자는 읽을 시간이 적다.** 화제가 된 뉴스는 더 많이 모으고, 항목마다 짧은 소개와 링크만 쓴다(§3-1). 깊은 해설은 그 호의 가장 큰 1~2건에만.

> **가이드와 원장은 매일 읽으므로 크기가 비용이다.** 상한: 가이드 35KB · 규칙 원장 12KB · 커버리지 태그는 명사구(호당 ≤25개·≤24자, `[self:ledger]`이 거절). 이력·실행 기록은 `git log`·`data/system_docs/changelog.log`·그날 보고서에 둔다. 규칙에 붙이는 실례는 **한 줄**까지다.

## 0. 저장·실행 규약 (예외 없음)

- **고정 폴더** `~workspace/outputs/ai_trend_reports/` · **파일명** `ai_trend_report_YYYY-MM-DD.md`(작성 당일, 사전순=시간순). 상태 파일 3종이 같은 폴더에 산다: `_coverage_ledger.json`(최근 10호 태그) · `_methodology_rules.md`(규칙 원장) · `_scan_log.json`(빈 날 점검 로그, §4-1 — 빈 날이 한 번도 없었으면 **아직 없다**, §1).
- **저장·검증은 결과·경로로 판단한다.** `[self:write]`·`[self:edit]`·`[self:list]`·`[self:grep]`·`[self:read]`로 값을 잇거나 셸·네이티브로 처리한다. 수단 자체는 경험의 가치가 아니다.
- **의미를 보존하며 왕복을 줄이는 IBL·셸을 택한다.** 등록 스크립트: GitHub 다건 = `github저장소메타` · arXiv 카테고리 피드 = `arxiv최신피드` · HTML 렌더 = `보고서HTML`.
- **AI 단계의 재료 관문에만 `criteria`를 둔다.** 행 수·필수 열·날짜 하한·중복 같은 반증 가능한 속성으로 검사한다. 취향 산문·결정론 단계에는 붙이지 않는다. 정본 `docs/IBL_QUALITY_CONTRACT_HANDOFF.md`, 최종 검수는 [결과물 검증 규약](result_quality.md).
- **목록은 필요한 열만 훑고 선택한 원문을 정독한다.** 왕복·전달량을 함께 줄이되 문자 수 감소를 실제 시간·토큰 절감으로 간주하지 않는다.

## 1. 직전 상태 읽기 (한 묶음)

등록된 비노출 관용구 `AI동향준비읽기`에 §0의 폴더를 전달해 상태 본문을 한 번에 읽는다. 구체 조합은 실행기억·등록 부품의 현행 계약에서 찾는다.

반환은 `previous_found`와 `documents`다. 각 문서는 `kind·found·path·text`를 가진다.
`kind`는 `previous`(직전 전체 보고서), `coverage`(최근 10호 태그), `rules`(규칙 원장),
`scan`(빈 날 점검 로그)이다. 목록·중간 실행 결과를 함께 되읽지 않는다.

- 직전 보고서는 `ai_trend_report_*.md`의 **파일명 내림차순** 첫 파일 전문(160줄 이후 포함)이다. 수정시각은 쓰지 않는다. `previous_found:false`일 때만 첫 호다.
- `coverage`·`scan` 부재는 `found:false`, 빈 파일은 `found:true,text:""`다. 규칙 원장은 필수이며 목록·권한·읽기 오류는 실패다. 준비 호출은 읽기 전용이다.
- 직전 본문의 주제·수치·지켜볼 점과 최근 10호 태그를 기준선으로 삼는다. 이전 보고서 참조로 유지한 질문은 확인일이 도래하거나 새 근거가 생겼을 때 해당 원문만 이어 읽는다. 규칙 원장의 실행일·재확인일이 도래한 규칙만 이번 자기 점검 대상으로 고른다.
- 접힌 응답은 같은 결과의 `value.documents`를 `read_result`로 한 번에 읽고 이후 `next_read`를 따른다. 문서별 재조회·프로그램 재실행은 하지 않는다.
- 받은 가이드·원장은 재사용한다. 컨텍스트 압축으로 잃었거나 파일 변경 근거가 있을 때만 필요한 부분을 다시 읽는다. 가이드 변경 확인은 받은 지문을 `if_hash`로 보낸다.
- `sense:crawl`의 분기는 `op:"links"`·`op:"content"`다. 다른 도구의 인자 이름을 추정하지 말고 계약이 불확실할 때 해당 서명만 조회한다.

## 2. 새 자료 조사

**수집 폭 하한:** 하한은 분량이 아니라 *어디를 열어 봤는가*다. 선별 전에 각 가지를 한 번은 연다 — ①투자·경제 뉴스(영·한) ②기술·연구 뉴스 ③공식 발표 채널(§2-6) ④논문(`arxiv최신피드`) ⑤오픈소스(`github저장소메타`) ⑥활용 사례(§2-3) ⑦회전 분야(§3-2) 하나 ⑧화제 뉴스 경로(§2-6: 회사명 뉴스·헤드라인·커뮤니티). 첫 훑기는 직전 전체 보고서 이후를 덮는다. 새 사건이 없는 가지는 비운다. 열지 못한 가지는 출처 절에 한 줄로 적는다.

**종료:** 하한과 §2-6 누락 점검 뒤에는 판단을 바꿀 자료가 더 필요한지에 따라 넓히거나 멈춘다. 질의 횟수는 할당하지 않는다.

**파이프라인:** §2-0의 입출력 계약에 회차의 질의·날짜를 연결해 수집·중복 제거·분류 초안을 만들고, rows_in·rows_dropped로 빈 가지의 원인을 살핀다. 초안 실패·품질 의심 시 개별 호출·읽기로 내려간다.

### 2-0. 관용구로 묶고, 판단에 필요한 결과만 받는다

수집·열 선택·반환을 묶는다. 본문은 수정·진단 때만 연다. 계약 확인은 `execute_ibl`의 `describe`로 해당 이름만 조회한다.

| 단계 | 관용구 | 사용 조건·반환 |
| --- | --- | --- |
| 시작 | `AI동향준비읽기{폴더}` | 비노출. §1의 상태 본문을 한 묶음으로 읽는다. |
| 후보 탐색 | `검색묶음추리기{질의들,기간,개수}` | 비노출. `{section,source,query}`(+선택 `type,sort`)를 4병렬 검색. 네이버는 **`type:"news"` 필수**(기본 웹 문서는 날짜 없음). 기간=일수(기본7), 개수=질의당 상한(기본6). `items`=제목·URL·요약·meta·dates, `queries`=질의별 성패·수신/표시 수. AI 요약·NEW 판정 없음. |
| 중복 수집 방지 | `미처리만고르기{후보,키,처리됨}` | 비노출. `키:"url"`로 이번 호에서 읽은 URL을 제외. 최근 10호 태그·주제의 기계적 제외나 URL 차이만으로 NEW 판정은 금지. |
| 페이지 수집 | `주소마다읽기{목록,개수}` | 상시. 필요한 페이지를 먼저 선택. URL 중복 제거 후 원문 문단·출처·실패 보존. |
| 원문 대목 확인 | `본문에서찾기{목록,패턴,문맥,개수}` | 상시. 정규식으로 수집 문단의 날짜·금액·계약 조건과 앞뒤 문맥 반환. 불일치·0건·문맥 부족이면 원문 추가 열람. |

질의·기간은 이번 호에 맞추며 성패·수신/표시 수를 보존한다. 구체 조합은 실행기억·등록 계약으로 찾고 가이드는 원리·입출력·실패 경계를 설명한다.

- `ok/failed/queries`·봉투의 원천 실패를 확인해 실패·부족 섹션만 보완한다. 빈 성공≠장애. `items`는 선별용(원문 검증 아님). 질의별 URL은 추적용으로 보존하고 본문 수집 전에 중복 제거한다.
- 날짜는 **`dates:{date,published_at,pubDate,published}`**(없는 값=null). 최상위 `date` 열은 없다. 후보 간 충돌·누락을 보존하며 원문 확인 전 발행일을 확정하지 않는다.
- 독립 질의를 묶고 `select/filter/본문에서찾기`까지 잇는다. 주장에 맞는 패턴을 쓰고 불일치·문맥 부족이면 전문을 읽는다. 검색 불일치≠원문 부재.
- 호출 간 값은 `inputs`·파일로 잇는다. 접힌 결과는 필요한 경로만 묶음 조회하고 전문 재타이핑·중복 조회를 피한다.
- `각각읽고요약`은 내부 AI 호출이며 날짜·원문 검증·발행 게이트를 완결하지 않는다. 기본 경로로 쓰지 않고, 증류가 필요할 때 §0의 `criteria`와 하위 모델 비용까지 포함해 선택한다.

그 뒤 순서는 **원문 검증 → 최종 사건 행 확정·저장 → §3-0 NEW 계수 → 산문 작성·저장 → 원장 갱신**이다.
`event_id·label·verified·date·publisher·url·summary`를 보존하고, NEW 하한은 오늘 기준 절대 날짜로 정한다.
관용구는 source 신뢰도·델타 서사·NEW 판단을 대신하지 않는다. 계수 0이면 점검 로그로 끝내며,
판정이 바뀌면 최종 행부터 수정하고 재집계한다.

맞는 함수가 없으면 일반 IBL로 조합한다. 영구 수리는 `docs/IBL_IDIOM_REPAIR.md`의 명시 등록·개정을 따른다. 한 호출 목표로 판단·품질 관문을 생략하지 않는다.

### 2-1. 투자·경제

경로: 구글 뉴스(한·영)·네이버 뉴스(`type:"news"`)·글로벌 웹, 필요 시 `sense:stock`의 뉴스·실적, 핵심 기사는 `crawl`로 원문. 대상: 자금조달·M&A, 반도체 수급·실적, 빅테크 투자, 정책·규제, **소송·수사·제재, 해고·인사·내부 갈등, 정부·기관의 AI 도입·금지**. 이런 사건은 공식 발표 없이 보도로만 나오므로 뉴스 검색에서 잡는다.

> **종목 시세는 뉴스성일 때만 한 줄.** 특정 사건이나 의미 있는 변화의 설명에 필요한 수치만 쓴다. 일별 종가·OHLC 추적은 `invest` 계기의 일이다. 규칙 원장 R3의 대조군 측정은 측정을 할 때의 품질 규칙이며 매일 측정할 의무가 아니다.

### 2-2. 기술·연구

경로: 뉴스 검색(모델 출시·벤치마크, 독립 질의는 병렬)·`sense:paper`의 arXiv·`arxiv최신피드` 스크립트(cs.AI·cs.CL·cs.LG, curl·XML 즉석 조합 금지), 중요 논문은 `crawl`. 대상: 새 모델·제품 출시·개발자 도구·벤치마크·논문·오픈소스·기법·에이전트·로보틱스, **안전·보안 사고, 교육·사회 사건**(시험·학교·공공기관의 AI 사용 논란 등).

> **GitHub 지표는 발견 수단이다.** 별·포크·푸시를 매일 표로 추적하지 않는다. README·코드를 읽고 무엇을 하는 물건이며 어떤 접근이 새로운지 소개한다. 이미 다룬 저장소는 릴리스·방향 전환·정지 같은 변화가 있을 때만 다시 싣는다.

### 2-3. AI 활용 사례

경로: 구글 뉴스 'AI 활용 사례'·영어 웹의 실제 사용 사례·네이버 블로그 'AI로 만든', 인상적인 것은 `crawl`. 분야 불문(과학·의료·창작·자동화·교육·행정·개인).

**선별 기준** — 둘 다(또는 한쪽을 강하게): **신규성**(흔한 챗봇 Q&A·요약 제외) · **파급력**(일하는 방식·판도를 바꿀 잠재력). 없는 날은 **비운다**(억지로 채우지 않는다).

**공란이 이어지면 조사 경로를 점검한다.** 3호 연속이면 §2-3-1의 대체 경로를 시도한다. 5호 연속이면 사례 정의나 주간 묶음 전환을 검토하고 근거를 짧게 남긴다. 빈칸을 채우려고 확인되지 않은 후기를 실사용 성과로 격상하지 않는다.

#### 2-3-1. 커뮤니티·오픈소스에서 활용 찾기

기사 외의 활용을 찾을 때는 사용자 경험(Reddit 등)과 공개 산출물(GitHub 등)을 함께 고려한다. 필요한 근거에 맞는 채널을 고르며 두 사이트를 매일 의무적으로 열지는 않는다.

**(A) Reddit** — 실제 사용 경험을 여러 각도로 검색한다. 스니펫에 멈추지 않고 유망 스레드 1~2개의 댓글 원문을 읽는다. 오래된 아카이브는 §2-5에 따라 배경으로만 쓴다.

**(B) GitHub** — 등록 스크립트 `github저장소메타`에 최근 2~4주 생성 기간·AI 관련 주제·정렬 기준·결과 상한을 명시하거나 GitHub 주간 Trending을 읽는다. 다건 메타는 저장소 목록으로 한 번에 요청한다(최대 8). 껍데기·단순 래퍼는 버리고 예상 밖 도메인·새 방식만. **남긴 것은 반드시 열어 읽고 '무엇을 하는 물건인가'로 소개** — 별·포크는 정렬 키일 뿐이다(§2-2).

**(B-2) 접근 실패:** 403·429·유료벽이 3호 연속이면 대체 경로로 바꾸고 출처 절에 한 줄 남긴다. 엔드포인트 장애와 사이트 장애를 구별한다. Reddit은 HTML→검색→HN·Lobsters·포럼·한국어 커뮤니티 순으로 대체하며 HN에는 `days`를 명시한다. 모두 막히면 활용 사례를 비우고 시도 경로를 남긴다. 설명형 UA·재시도 1회·다른 경로 1개를 확인하기 전에는 서비스 장애로 단정하지 않는다.

**(C) 공통 필터** — **1인칭인가**("I used AI to…" > "17 ways AI can…") · **구체적 결과가 적혔나**(진단명·수치·산출물). 통과한 사례는 날짜를 박아 "무엇이 새로운가"로 서술한다(부패가 빠르다).

### 2-4. 소스 신뢰도 (필수)

- **복수 소스 교차 검증**: 핵심 수치·주장은 독립 2개 이상 출처 전에는 단정하지 않는다. 한 곳뿐이면 "~에 따르면", 어긋나면 불일치를 그대로 적는다.
- **해석적 판정에도 적용**: 사유·의도·서사의 단정("사유는 하나다")도 독립 소스 2개 또는 이틀 이상 관측 전엔 내리지 않는다. 근거가 부족하면 추정으로 낮추고 미확인 조건을 밝힌다. 은퇴한 형식 규칙과 무관하게 정확성·교차검증 원칙은 유지한다.
- **여러 사건을 묶는 머리말 한 문장('축')은 이 원칙의 최우선 대상이다.** 반증 조건·재확인일을 못 쓰면 축을 세우지 않는다. '같은 날'이 근거면 각 날짜를 §2-5로 먼저 확정한다. 같은 낱말이 아니라 같은 원인·구조가 묶을 때만 축이다.
- **출처 표기**: 핵심 항목마다 매체·URL. **이 세션에서 실제 호출한** 결과에 나온 자료만 인용한다(권위 기관을 "있어 보여서" 인용 금지).
- **사실/추정 구분**: "~로 보도되었다" / "~일 가능성이 있다".

### 2-5. 신선도 검증 (필수)

`search`(gnews/ddg)는 몇 달~몇 년 전 기사도 섞어 준다.

- 자료마다 발행 시점을 확인한다. 스니펫에 없으면 `crawl`로, 끝내 불명이면 "시점 미상"으로 표시하거나 제외.
- **NEW 하드룰(재량 없음)**: `NEW`·`현재 동향`은 발행일이 `crawl` 원문 또는 구조화 필드로 **오늘 기준 2주 이내**임이 확인된 항목에만. 미확인은 `ONGOING`/배경으로 강등. 파이프 증류에서는 이 하한을 **절대 날짜로 지시문과 criteria에 박는다**(§2-0) — 게이트 계수의 정직성이 여기서 나온다.
- **시점이 생명인 항목은 구조화 날짜 소스를 1차 채널로** — `sense:stock`의 뉴스·실적, `sense:paper`의 arXiv 소스, `arxiv최신피드`. 자유형 뉴스 검색은 살을 붙이는 보조.
- **발표·재보도·최초 소개·실제 제공 시점을 구별한다.** 늦게 찾은 중요 발표는 원 발표일과 이번 호의 최초 소개를 함께 밝힌다. 수집기 날짜·저장소 생성일만으로 현재 기능 전체의 출시일을 확정하지 않는다. 2주 자격은 신속성의 증거가 아니다. 후속 제공·변경은 실제 변화일과 함께 설명한다.
- 예정된 관측일은 기관의 달력·시간대와 작성 마감에 대조한다. 검색 쿼리에 현재 연·월을 넣으면 최신 비중이 오른다.

### 2-6. 주요 발표 발견과 누락 점검 (필수)

- **공식 채널은 발표 종류별로 확인한다.** R4의 직접 훑기에 연구·기업 뉴스룸뿐 아니라 제품 블로그·릴리스 노트를 포함한다(Anthropic 뉴스룸만 읽고 `claude.com/blog`까지 봤다고 세지 않는다). 주요 모델·에이전트 제공사는 매호, 주변 분야는 회전한다. 목록이 막히면 공식 도메인 검색으로 보완한다.
- **회사명·헤드라인 경로를 공식 채널과 따로 연다.** 공식 채널에는 회사가 알리고 싶은 것만 있다. 주요 AI 기업(OpenAI·Anthropic·Google·Meta·Microsoft·엔비디아·xAI와 그 주의 화제 주체)의 이름으로 영어·한국어 뉴스를 검색하고, 구글 뉴스 AI 헤드라인과 네이버 뉴스(`type:"news"`)를 연다. 소송·해고·금지·사고는 대개 이 경로에서만 잡힌다.
- **화제성 축(필수):** 최근 48시간 독립 매체 3곳 이상 보도는 후보에 넣는다(전재·통신사 재배포는 한 곳). 미게재 이유는 출처에 한 줄 남기며 공식 발표가 아니거나 덜 중요해 보인다는 이유만으로 빼지 않는다. 화제성은 진위·성능 증거가 아니다(§2-4·§2-5).
- **사건 확정 전 누락 점검:** 최초 수집과 다른 경로로 **최근 7일**의 구글 뉴스 헤드라인·네이버 뉴스·HN(`days` 7)을 훑고 필요하면 커뮤니티를 더한다. 경로·기간을 줄여 완료로 처리하지 않는다. 후보·최근 보고서와 대조해 누락 사건 원문을 확인한다. 첫 조사는 직전 보고서 이후를 덮고 NEW 0건 판단 전에도 점검한다.
- **싣는 범위는 넓게, 깊이는 중요도로.** 최종 선정 전에 사용자 선택·실행 능력·접근 조건·비용·실패 위험 또는 투자·경제 판단을 크게 바꾸는 후보가 남아 있는지 대조한다. 현재 머리말과 반대 방향의 실적·제약도 같은 기준으로 확인한다. 원문이 읽기 쉽다는 이유로 덜 중요한 사건을 우선하지 않는다. 확인된 화제 뉴스는 짧게라도 싣고, 해설 1~2건은 변화의 중요도로 고른다. 발표 사실과 성능 주장은 나누며 독립 실증이 없어도 확인한 출시는 회사 발표로 소개할 수 있다. 재보도 횟수·조회수는 발견 신호이며 중요도·진위의 증거가 아니다.
- **누락·제외·보류를 구별한다.** 중요 보류 후보는 이유·다음 확인 원천을 기존 조사 기록에 남기고, 다음 호 준비 때 새 근거 유무를 재검토한다. 새 근거가 없으면 그대로 보류하며 미확인을 확정으로 올리지 않는다. 출처 절에는 화제·중요 후보의 제외·보류 이유와 접근 실패 등 판단에 필요한 한계만 짧게 남긴다. 전체 채널·누락 대조 경로와 무값 관측은 조사 기록에 둔다(§4). 제품명 태그만으로 후속 출시를 버리지 않으며 실제 발표일과 최초 소개를 구별한다(§2-5).

## 3. 델타 서술 — "무엇이 새로운가"

### 3-0. 발행 게이트 = 파이프 계수 (2026-09-02 개정)

확인한 사건에 `event_id·label·verified·date·publisher·url·summary`를 보관한다.
`verified`는 그 행에 적은 발표·날짜·진술의 확인이며 성능 전체의 독립 재현을 뜻하지 않는다.
출처와 검토 범위를 함께 남긴다. 같은 사건의 여러 출처는 같은 `event_id`를 사용한다.

**계수 계약:** 입력은 확정 사건 목록·실행일·2주 전 하한(YYYY-MM-DD)이다. `date`는 원문에서 확인한 발행일이며 발표일·재보도일·최초 소개일·제공일은 §2-5에 따라 별도로 구분한다. 재보도를 새 사건으로 세지 않는다. `verified`가 참이고 `label`이 NEW이며 하한 이상·실행일 이하인 행만 고른다. 비어 있지 않은 `event_id`를 확인한 뒤 같은 ID를 중복 제거하고 실제 행 수를 센다. 반환은 `events`(행 목록)·`new_count`(행 수)·`publish`(1건 이상 여부)다. 필드·형태·날짜 오류는 실패로 처리하며 검증된 0건으로 바꾸지 않는다.

`dedup`의 반환은 행을 `items`에 담은 Record다. **봉투의 필드 수를 사건 수로 세지 않으며** 행 목록을 꺼내서 세고,
보고서·저장 원장·커버리지도 같은 `events`에서 만든다. 원장은 `~workspace/outputs/ai_trend_reports/_verified_rows_YYYY-MM-DD.json`에 `{items:events,count:new_count}`로 저장한다(AI시대 뉴스 동기화가 이 이름을 읽는다). 도중에 검증
판정이나 행을 바꾸면 다시 집계한다. 정상 계수 결과를 단순 재확인하기 위한 별도 호출은 필요 없다.

- `publish:false` → §4-1의 점검 로그를 쓰고 전체 보고서 작성을 종료한다. CHANGED만 있으면 제목을 로그의 `changed`에 남긴다. 다음 전체 보고서의 기준선은 마지막 전체 보고서다.
- `publish:true` → 최종 행과 계수에 맞춰 보고서를 쓴다. 빈 분야에 새 사건을 만들어 넣지 않는다.

기계 계수는 날짜 범위·확인 표식·중복·행 수만 검사한다. 진술의 사실 여부와 사건 동일성은 행 확정 단계의 몫이며,
계수를 위해 별도 AI 평가 호출을 추가하지 않는다.

### 3-1. 항목 형식 — 많이, 짧게, 링크로

사건 하나가 항목 하나다.

- **항목 = 굵은 한 줄 제목 + 소개 1~2문장 + 링크.** 확인한 변화와 독자에게 중요한 이유를 연결한다. IndieBiz OS의 실제 작업과 관련되면 능력·비용·접근 조건·권한·사용자 판단에 주는 의미를 이 문장 안에서 설명한다. 미시험 효과는 기대와 확인 조건으로 구분하며 관련성이 약하면 억지로 붙이지 않는다. 이는 §3-5 발동 조건을 넓히지 않는다. 세부 배경은 링크가 맡되 원문(사건 행의 `url`)과 중요한 한계는 항목 곁에 보존한다.
- **해설은 그 호의 가장 큰 1~2건에만** 3~5문장으로 붙인다. 나머지에 해설·반론·배경 문단을 달지 않는다.
- **분량은 문장 길이가 아니라 항목 수로 채운다.** 확인된 화제 뉴스(§2-6)는 짧게라도 싣는다. 빈 분야에 사건을 만들어 넣지는 않는다.
- 항목 머리에 `[NEW]`·`[CHANGED]` 표지를 단다. CHANGED는 직전에 다룬 사건의 진전·반전이며 무엇이 바뀌었는지만 한 문장으로 쓴다(단순 주가 등락 제외). 변화가 작은 흐름은 싣지 않거나 한 줄로 끝낸다. 직전 전망 점검은 '지켜볼 점'에서 맞음·틀림 한 줄로 한다.

### 3-2. 반복 방지 (필수)

1. **분야 편중을 점검한다.** 로보틱스·바이오·에이전트·반도체·정책·오픈소스·창작·온디바이스 등에서 중요한 변화가 빠졌는지 보고 탐색 방향을 고른다. 새 주제 개수를 채우려고 중요하지 않은 사건을 채택하지 않는다.
2. **'지켜볼 점'은 교체되는 목록**: 해소된 항목은 다음 호에서 은퇴, 2~3회 무변화 이월 항목도 내린다. **여러 항목을 '승계' 한 줄로 묶어 은퇴 규칙을 우회하지 않는다** — 항목은 낱개로 세고 **상한 8개**. 질문이 실제로 해소됐는지 근거로 판단한다. 새 판단·기한이 생긴 질문만 갱신하며 형식적인 재확인일 이동으로 무변화 이월을 연장하지 않는다.
3. **분량 채우기 금지는 전 섹션에**: 쓸 게 없는 섹션은 짧게 끝내거나 비운다.
4. **커버리지 원장**: 전체 보고서를 저장할 때마다 `{date, tags:[...]}` 한 항목 append(최근 10호). 태그는 **명사구 ≤24자·호당 ≤25개** — `[self:ledger]`의 `list_limits`가 거절한다(§4). 다음 호는 직전 1개가 아니라 원장 전체를 기준선으로 대조한다. 의미검색용 `[self:memory]`와는 목적이 다르다.

### 3-3. 방법론 규칙의 생애주기

자기 방법론의 실패(커버리지 갭·성급한 단정·반복 패턴)를 발견하면 규칙을 세울 수 있다. 규칙은 `_methodology_rules.md`에 산다. **태어난 날 원장에 넣지 않는다.**

1. **탄생**: 보고서 본문('지켜볼 점'/'자기 점검')에 적고 *"다음 호에서 실행 여부를 자기 점검한다"*를 병기한다(예약 없는 규칙은 증발한다).
2. **수습**: 다음 호(들)에서 실제로 실행한다.
3. **승격**: **값을 낸**(새 발견 또는 판정 정정) 규칙만 원장 템플릿대로 추가. **반증 조건과 다음 재확인일 필수** — 못 쓰면 들어갈 수 없다.
4. **중복 대조(승격 전 필수)**: 가이드 전체 + 원장과 대조. 이미 있으면 추가가 아니라 **기존 규칙의 개정**.
5. **은퇴·참조 정리**: 재확인일 도래 시 반증 조건과 대조하고 은퇴 상태·사유를 남긴다(삭제 금지). 개정·은퇴 때 가이드와 다른 규칙의 참조도 함께 정리한다. 공통 편집 원칙은 가이드가 소유하고 원장은 해당 원칙을 참조한다. 형식 규칙의 은퇴로 정확성 원칙을 없애지 않는다.
6. **상한 활성 10개.** 11번째를 올리려면 하나를 병합·은퇴시킨다.
7. **원장은 12KB 이내:** 상태·내용·탄생·승격 각 한 줄·반증 조건·무값 카운터(연속 횟수·마지막 값 날짜)·다음 실행/재확인만 둔다. 회차 서사는 보고서 자기 점검에 두고 원장에는 카운터만 갱신한다.

### 3-4. 독자 층 규칙 (필수) — 장부와 브리핑은 다른 층

장부는 다음 실행의 근거이고 브리핑은 사용자가 읽는 변화다.

1. **TL;DR:** 항목당 쉬운 1~2문장. 주체·측정량·단위·기간·한계를 유지하며 증가율을 규모로, 전망 기관을 발표 주체로 바꾸지 않는다. 기호·등급·과거 호 참조·괄호 주석 없이 쓰고 전문용어는 첫 등장에 풀이한다.
2. **본문 = §3-1의 짧은 항목.** 증거 규율은 지키되 문장은 사람에게. TL;DR은 그 호의 큰 흐름 3~5줄, 본문은 낱낱의 항목이다. 같은 사실을 두 층에서 되풀이하면 층 분리 실패다.
3. **강조 기호 상한**: ★·⚠️ 합계 **항목당 2개**.
4. **장부 문장은 뒤에 둔다.** 등급·재확인 예약은 머리말·TL;DR에 쓰지 않는다. 중요한 한계는 항목 꼬리에, 방법론 판정은 자기 점검에 둔다. 무값 기록·상세 근거의 위치는 §4를 따른다.

### 3-5. indiebizOS 함의 (조건부) — 바깥 하네스가 우리와 같은 구조를 택했는가

독자는 하네스를 짓는 사람이다. 알고 싶은 것은 부품 겹침이 아니라 **구조 겹침**(08-26 사용자 지시). **발동 조건**: 아래 세 축 중 하나라도 실제로 걸리는 항목이 있을 때만. 없으면 **섹션을 생략하고, "함의 없음" 문장을 어디에도(자기 점검·괄호 포함) 남기지 않는다.**

1. **로컬 언어형(IBL의 자리)** — *자연어가 아니라 전용 표기로 도구를 부르나?* 예: 자체 문법·조합 연산자·사람이 읽고 쓴다. 아니오: 함수호출 JSON 스키마·프롬프트 템플릿. 걸리면: 그쪽이 IBL이 못 하는 무엇을 하나.
2. **문제규정 단계(의식 에이전트의 자리)** — *실행 전에 분리된 단계로 과제를 다시 정의하나?* 예: 별도 호출의 계획·성공 기준 채점·실행 단계 인계·쉬운 일 건너뛰기. 아니오: 추론 토큰·CoT, 한 프롬프트 안의 "먼저 계획하라". 걸리면: 언제 건너뛰나, 어느 급 모델인가.
3. **행동 고정(앱 표면의 자리)** — *반복 행동을 고정 표면으로 굳히나?* 예: 버튼·저장된 워크플로우·승격 경로. 아니오: 자유 생성만, 기록≠고정. 걸리면: 그쪽 승격 기준과 우리 것(앱 계기·`[self:workflow]`·`[self:script]`)의 차이.

**비교 증거:** 같은 목적·비슷한 작업 흐름·같은 구현을 구별한다. 티켓·폴더·세션 생성만으로 별도 문제규정 단계를 확인했다고 쓰지 않는다. 해당 축의 실행 전 판단과 인계가 확인되지 않으면 미확인으로 남기고 그 근거만으로 함의 섹션을 발동하지 않는다. 내부 기능 유무도 정본 문서·현재 관측과 시점에 근거한다. 도입·비도입을 성급히 단정하지 않고 확인할 차이와 적용 조건을 제시한다.

**형식**: 불릿 1~3개, 각 2~3문장, 머리에 축 이름을 괄호로. *"무엇이 → 어느 축에 걸리나 → 우리는 무엇을 해야/안 해도 되나"* — **세 번째가 안 써지면 싣지 않는다.** 위치 `## 4. indiebizOS 함의`. TL;DR엔 그 호 최대 변화일 때만 한 줄. 손볼 일은 '지켜볼 점'에 재확인일과 함께 — 보고서는 코드를 고치지 않는다.

## 4. 출력 형식

아래 골격으로 `[self:write]`해 §0 경로에 저장한다. AI가 직접 쓴다(`engines:newspaper` 위임 금지 — 신문이 아니라 분석 보고서다).

```markdown
# AI 동향 보고서 — YYYY-MM-DD

> 직전 보고서: ai_trend_report_<직전날짜>.md (없으면 "첫 보고서")

## 한눈에 보는 변화 (TL;DR)
- (3~5개, §3-4: 평문 재작성·기호/등급/과거 호 참조 금지)

## 1. 투자·경제
- **[NEW] 한 줄 제목** — 무슨 일이고 왜 볼 만한지 1~2문장. [매체](URL)
- (항목을 이어서. 그 호의 가장 큰 1~2건만 3~5문장 해설)

## 2. 기술·연구 동향
- (같은 형식. 소송·해고·금지·교육 사건도 성격에 맞는 섹션에)

## 3. 주목할 AI 활용 사례
- (같은 형식: 누가·무엇을, 왜 새로운가. 없으면 섹션 생략)

## 4. indiebizOS 함의
- (§3-5 걸릴 때만. 없으면 섹션 생략, "없음" 줄도 없음)

## 방법론 자기 점검
- (그 호에 **값 또는 판정을 낸 규칙만**: 도래 규칙의 존속 판정 · 수습 규칙의 승격/폐기 · 직전 호 정정의 방법론 원인 한 줄. "실행했고 무값"은 여기가 아니라 원장 카운터로. 셋 다 없으면 섹션 생략)

## 지켜볼 점 (다음 보고서 점검 대상)
- (새로 생기거나 판단·기한이 바뀐 질문만. 낱개 ≤8은 상한이며 채울 목표가 아니다. 변함없는 질문은 전문을 복사하지 않고 원 보고서 링크·짧은 주제명·재확인일로 유지한다. 유지 참조도 낱개 상한에 포함한다.)

## 출처
- [매체명](URL) — 원문 / 검색결과 등급
```

중요한 한계는 항목 곁에 짧게 적고 반복하지 않는다. 검색 횟수·규칙 번호·계수 과정·무값 채널 기록은 조사 근거·카운터에 둔다.

**상세 근거 분리:** 채널 목록·검토 범위는 독자가 열 수 있는 기존 근거 기록에 연결한다. 공개 HTML에 비공개 로컬 링크만 남기거나 공개 범위를 늘리지 않는다. 연결 불가면 필요한 근거를 출처 절에 보존한다. 접기는 렌더 지원을 확인한 때만 쓴다. 사건별 원문 링크·중요한 한계·주체·수치·단위·기간은 본문과 요약에 유지한다.

저장 직후:
- **커버리지 원장 append**: 전체 보고서의 날짜·태그를 §0의 `_coverage_ledger.json`에 `self:ledger`로 추가한다. 최근 10호만 유지하고 목록 제한으로 태그 ≤25개·각 ≤24자를 검증한다. 태그 상한으로 거절되면 태그를 줄여 다시 실행한다. 형태·손상 오류는 메시지의 원인을 수리하며 태그 축소로 우회하지 않는다. 전체 보고서 날만.
- **작업 이력**은 저장한 보고서·커버리지·규칙 원장으로 남긴다. 심층기억의 지속 가치 선별은 최종 응답 후 하네스가 맡는다. `self:memory save`는 즉시 저장하지 않으므로 보고서 기록 통로로 쓰지 않는다.
- **규칙 원장**: 승격·은퇴 판정이 난 날만 §3-3 템플릿대로 갱신 + 카운터(연속 무값·마지막 값 날짜) 갱신. 판정 없는 날은 카운터만.
- 저장한 내용과 영수증으로 경로·크기·완료를 확인한다. 저장 결과가 불확실하거나 내용이 변환·변경됐으면 필요한 부분을 재조회한다. 방금 쓴 전문과 원장을 의례적으로 모두 다시 읽지는 않는다.
- **공유판 발행**: 등록 스크립트 `AI동향발행`의 `src`에 저장한 원문의 절대 경로를 전달한다. 고정 출력은 `공유창고/0/오늘의 AI 보고서.html`이다. 원문 강조·출처를 보존하는 목차·요약·기사 구획 HTML이며, 기존 판을 먼저 삭제하거나 `table:document`로 대체하지 않는다.
- 발행은 HTML 완성 즉시 공개다(`published:true`, 검수 대기 없음). 오류나 `published:false`는 발행 실패이며 원문 저장 성공과 구분해 보고한다. 공개 경로·핵심 변화를 전달하고 GUI 열기는 요청받을 때만 한다.
- 링크는 반환된 `public_url`(`/f?path=파일명`)을 사용·필요시 검사한다. `public_url_checked:false`=접속 미검증. URL 없으면 `public_url_status`(미설정/오류/조회불가)와 로컬 발행을 구분한다. 주소 추측 금지.

### 4-1. 점검 로그 (계수 0인 날)

§3-0에서 `new_count == 0`이면 파이프가 `_scan_log.json`에 한 항목을 append 한다(§2-0의 계수 뒤, `[self:ledger]`, `max_items: 60`): `{date, new_count: 0, changed: [CHANGED 제목들], scanned: "가지·질의 요약 한 줄"}`. 사용자에겐 한 줄로 보고한다. 이 파일은 `ai_trend_report_*.md` 패턴 밖이라 다음 호의 기준선(§1)은 마지막 전체 보고서로 유지된다. 커버리지·규칙 원장은 건드리지 않는다.
