# 심층연구계획서 — 주제에 맞는 계획을 문서로 만들고 따라가기

이 가이드는 **의식 에이전트가** 사용자의 연구주제와 목적에 맞는 연구계획서를 작성하고 갱신하기
위한 교재다. 실행자에게 추천·주입하거나 읽도록 지시하지 않는다. 실행자는 의식이 작성하고
하네스가 저장·확인한 계획 본문을 받아 조사·근거·진행을 갱신한다. 모든 연구에 동일한 절차를
적용하는 공통 연구계획이 아니다.
깊이 연구하려는 요청에 사용한다. ‘심층연구’라는 단어가 없어도 되지만,
단순 조회·가벼운 비교·일상 대화까지 계획서 작성으로 확대하지 않는다.
가이드가 조회됐다는 사실만으로 계획서 작성이 의무가 되지는 않는다.

**계획은 질문에 맞는 증거와 판단 방법을 설계한다.** 사용자가 원하는 답과 그 답을 바꿀 관측에서
자료·방법·진행을 도출한다. 주제만 바꿔 붙인 ‘검색·비교·보고’나 사례 목록으로 끝내지 않는다.
목차·방법 이름은 이 연결을 설명하는 수단이며, 계획은 결론의 예고가 아닌 잠정 설계다.

**연구 순서: 의식의 목적·심층연구 판단 → 의식의 계획 작성 → 하네스의 저장·확인·전달 → 실행자의 예비 조사와 계획 보완 → 본조사 → 질문별 검수·보고.**
첫 자료 검색·수집이나 실험 전에 의식이 계획 본문을 작성하고 하네스가 실제 파일로 저장한다. 방법을 아직
모르면 잠정 접근·미확인 사항·첫 확인 질문을 적은 초안으로 시작한다. 예비 조사도 이 초안의
질문을 따라 수행한다. 조사를 끝내고 계획서를 소급 작성하는 것은 이 절차를 이행한 것이 아니다.
의식의 규정이나 대화 속 작업 예고는 계획의 재료이며, 저장된 연구계획서를 대신하지 않는다.
이미 같은 연구의 계획서가 있으면 먼저 읽고 이어 쓴다. 사용자에게 계획서 작성만 요청받았으면
문서를 전달하고 마친다. 연구 수행까지 요청받았으면 계획과 경로를 알리고 허용된 조사를 계속한다.
사용자가 검토 후 진행하라고 하지 않았다면 계획서 작성 자체를 별도 승인 대기로 만들지 않는다.

## 1. 대화와 기존 자료에서 연구의 목적을 복원한다

지금 문장만 보지 말고 관련 대화의 최초 질문·정정·선택을 읽어, 사용자가 무엇을 이해하거나
결정하려는지 파악한다. 이전 조사·에피소드·연구 프로젝트의 축적 자료가 있으면 관련 부분을 확인한다.
기억의 목차에서 주제 가지와 상위 맥락을 찾고, 필요하면 심층기억·실행기억·포식기억을 펼친다.
모든 기억을 읽는 절차가 아니라 이번 문제를 이해할 자료를 고르는 일이다. 과거 AI의 답은
검증된 사실이나 사용자의 결정으로 승격하지 않는다.

과거 운영 규칙은 당시 대상·행위·이유의 범위로 읽는다. 기존 항목의 삭제·등록 제한을 새로운
대안의 조사·비교 금지로 확대하지 않는다. 현재 사용자가 개선이나 새 선택지를 요청하면 기존
방식도 비교 대상으로 둔다. 조사·제안과 실제 설치·복원·적용은 구별하고, 후자의 권한을 넘지 않는다.
한 방식만 사용한 기록은 사용 이력이며 다른 방식이 불필요하거나 열등하다는 증거가 아니다.
아직 읽지 않은 대화의 주장이나 핵심 관계를 상투적인 분야 목록으로 확정하지 말고, 원문 복원과
그에 따른 질문 구체화를 첫 조사에 둔다.

전체 목적과 이번 하위 질문의 관계, 사용자에게 중요한 조건, 아직 모르는 것을 구분해 적는다.
명시한 요구·제약의 대상과 강도를 보존한다. 일부 행위의 제한을 더 넓은 금지로 확대하지 않는다.
AI의 추정은 구별한다. 탐색적 연구라 목적 자체가 아직 열려 있다면
그 상태를 보존한다. 중대한 해석 차이로 조사 방향이 갈릴 때 질문하고, 그 밖에는 잠정 해석을
밝히고 진행한다. 모든 빈칸을 사용자에게 채우게 하지 않는다.

### 질문에 따라 방법을 고른다

한 요청에 섞인 질문별로 필요한 답과 증거를 구분하고 그 관계에 따라 조사를 구성한다.
아래는 방법 선택의 예이며 고정 분류·필수 칸이 아니다.

| 원하는 답 | 계획에서 구체화할 조사와 판단 |
| --- | --- |
| 어떤 개념·방법·사례가 있는가 | 범위·용어·자료를 정해 차이·분포·공백을 지도화한다. 존재·보급·우수성을 구분한다. |
| 무엇이 어떤 조건에서 더 효과적인가 | 대상·지표·분모·조건을 맞춰 방법과 한계를 평가한다. 소개 자료의 기능 확인과 효과 입증을 구분한다. |
| 왜 이런 변화가 일어났고 어떤 설명이 타당한가 | 시기·맥락·사료의 출처를 확인하고 경쟁 설명을 가를 관측을 찾는다. 상관·시간적 선후만으로 인과를 확정하지 않는다. |
| 사람들은 어떻게 경험하고 의미를 부여하는가 | 대상·맥락·기록을 정해 공통점·차이·반대 사례를 해석한다. 소수 사례 빈도를 모집단 비율로 확대하지 않는다. |
| 무엇을 만들거나 도입하는 것이 적합한가 | 목적·제약에 맞춰 후보·샘플을 비교하고 필요하면 같은 과제로 시험한다. 선호·실현성·효과를 구분한다. |
| 시스템이 약속한 대로 작동하는가 | 계약·코드·당시 입출력·기록을 대조한다. 현재/당시 판본, 구현/작동, 절차 준수/결과 품질을 구분한다. |

‘어떤 방법이 있고 무엇이 좋으며 우리 시스템은 어떤가’는 지도화·효과 평가·내부 검증을 연결한다.
제품 비교표 하나로 대신하지 않는다. ‘고정 대 유연’, ‘단일 대 다중’ 같은 축은 질문 전체를 포괄하는지
확인하고 보완한다. 현재 구현은 관측 대상이지 대안을 제외하는 사용자 조건이 아니다.

축적된 연구 방법·표준·종합 연구에서 출발하고, 새 사례 몇 개를 정설로 만들지 않는다.
문헌 조사는 목적에 따라 범위 고찰(지형·개념·공백), 체계적 고찰(초점 질문의 근거 평가·종합)의
원칙을 선택한다. 원자료 분석·역사 해석·설계 시험을 문헌 수집으로 대신하지 않는다.
적용 범위와 생략한 절차를 밝히고, 수행하지 않은 엄격한 방법의 이름으로 품질을 인증하지 않는다.
PRISMA는 보고 지침이다. 잘 보고된 것과 방법·결론이 타당한 것을 구분한다.

## 2. 조사 전에 실행 가능한 연구계획서를 저장한다

의식은 사람이 읽을 수 있는 Markdown 계획 본문을 `research_plan`으로 반환한다. 하네스는 현재
작업공간의 `outputs/research_plans/<판본>/research_plan.md`에 저장하고 다시 읽어 본문 일치를
확인한다(회원은 사설 저장소). 저장 시각·지문·이전 계획 경로도 하네스가 기록한다. 의식이 작성·완료
시각을 추정해 쓰거나 아직 저장하지 않은 파일의 성공을 주장하지 않는다. 공용 `data/guides/`에
개별 계획을 저장하지 않는다. 사용자 지정 납품 위치는 계획에 보존하여 실행자가 저장본을 전달한다.
의식은 반환 전에 목적·질문·첫 조사·멈춤 조건을 확인한다. 저장이 확인된 뒤에만 실행자에게
계획 본문과 경로가 전달된다. 실행자는 사용자에게 경로를 알리고 계획된 조사를 시작한다. 미지정 방법과 잠정 가정은 그대로 표시하며,
미래의 조사 결과를 이미 확인한 내용처럼 채워 넣지 않는다.

계획은 보통 다음 내용을 연결하면 된다. 절 이름·분량·표 형식은 연구에 맞추며,
불필요한 칸이나 형식적인 가설을 만들지 않는다.

- **목적과 현재 질문:** 무엇을 이해하거나 판단하려는가. 이번 질문이 전체 목적에서 맡는 역할은 무엇인가.
- **출발점과 범위:** 이미 확인한 내용과 근거, 사용자의 조건, 잠정 가정과 중요한 미확인 사항은 무엇인가.
- **접근과 선택 이유:** 어떤 설명·방법·대안을 살피고 왜 그 접근이 이 주제에 맞는가. 참고한 방법론과 적용 한계는 무엇인가.
- **핵심 질문과 조사 방법:** 각 질문에 어떤 자료·분석·시험이 필요하며, 그 결과가 어떤 판단을 바꿀 수 있는가.
- **결과의 종합:** 하위 조사들을 어떻게 대조·연결해 원래 질문에 답할 것인가. 근거 충돌과 비교 한계는 어떻게 다룰 것인가.
- **진행과 멈춤:** 무엇부터 하고 어떤 결과에 따라 방향을 바꿀 것인가. 어느 정도면 답할 수 있으며 시간·비용의 한계는 무엇인가.
- **현재 상태와 산출물:** 확인한 것·남은 것·다음 행동, 근거와 중간 결과의 위치, 사용자에게 전달할 결과는 무엇인가.

질문마다 **증거 → 확보·선정 → 분석·판단 → 부족할 때의 다음 행동**을 연결한다.
자료명 대신 무엇을 확인해 어떤 답을 할지 적는다. 접근성·방법의 미확인은 잠정으로 두고
첫 예비 조사의 확인 대상과 계획 보완을 명시한다. 검색하지 않은 계획 단계에서 출처 열람을 주장하지 않는다.

‘검색 → 분석 → 보고서’만으로 계획을 채우지 않는다. 처음 보는 실행자가 질문·이유·확인 방법을
읽고 다음 조사를 시작할 수 있어야 한다. 반대로 아직 모르는 결론을 미리 정하고 근거를 수집하는
계획도 피한다. 확인 가능한 범위에 따라 조건부 결론이나 미해결 질문으로 끝날 수 있다.

자료 원문과 상세 근거는 기존 연구 라이브러리·노트·산출물에 두고 계획서에서 연결한다.
기존 과제 원장을 사용한다면 산출물 참조에 계획서 경로를 남긴다.
같은 계획을 여러 기억에 전문 복사하지 말고 현재 계획 문서 하나를 기준으로 삼는다.

### 연구 프로젝트의 질문·근거와 연결한다

[연구 프로젝트](research_project.md)에서는 같은 대화의 [연구 질문 기록](research_questions.md)을
먼저 읽고, 계획의 하위 질문에 해당하는 `question_id`를 연결한다. 참조에는 해당 프로젝트·대화의
신원도 함께 남겨 다른 대화의 질문과 혼동하지 않게 한다. 새로 지속할 질문만 기존 저장 절차로
등록하고 반환된 ID를 쓴다. 일반 대화에서는 파일과 출처 참조로 충분하며 별도 프로젝트 생성을 강제하지 않는다.

계획서는 전체 목적·접근·조사 간 관계와 다음 진행을 설명하고, 질문 기록은 잠정 답변·지지/반박
근거·남은 확인·다음 조사의 상세를 보존한다. 원문은 자료실에 둔다. 계획서의 진행 요약에는
참조한 질문 판본을 남기고, 재개할 때 최신 기록과 대조한다. 계획의 요약으로 질문 원장을 덮어쓰지 않는다.
근거는 실제 읽은 자료의 판본·위치로 연결하며 정확한 조회·갱신 계약은 연구 질문 가이드를 따른다.
‘사용자의 관점’ 문서에 AI의 실행 계획을 사용자 입장처럼 저장하지 않는다.

계획서 경로와 관련 질문을 대화에 남겨 다시 찾을 수 있게 한다. 새 계획을 전달할 때는 저장된 본문이
함께 주입된다. 후속 연구에서는 의식이 기존 파일의 현재 진행과 관련 질문 기록을 읽어 새 판본으로
잇는다. 실행 중의 진행·근거 갱신은 전달받은 계획 파일에 쓴다. 경로만으로 열람을 주장하지 않는다.

## 3. 계획에 필요한 예비 조사로 접근법을 보완한다

저장한 초안에서 접근법을 정하지 못한 질문에 한해 관련 기억·기존 자료와 필요한 원문을 살핀다.
예비 조사는 방법·자료 접근 가능성을 확인할 정도에서 멈추고 계획을 갱신한 뒤 본조사로 넘어간다.
결론을 위한 자료 수집·비교·종합 전체를 예비 조사라고 부르며 계획 작성을 미루지 않는다.
익숙한 도구나 기존 가이드의 방법을 바로 계획으로 굳히지 않는다. 해당 분야에서 이 문제를
다루는 개념·방법·대표 사례를 확인하고, 방법이 빠르게 바뀌는 분야라면 현재 이용 가능한
접근도 조사한다. 사용자가 방법 이름을 알려줄 때까지 기다리지 않는다.

예비 조사로 범위·용어·접근성·방법의 적합성을 확인해 계획을 보완한다. 접근이 충분히 정해졌으면
별도 예비 조사·개정은 불필요하다. 정립된 원칙의 채택과 이번 AI의 수행 능력 검증을 구분한다.
방법 채택마다 새 비교 실험을 요구하지 않고, 중요한 미확인 차이에 필요한 자료·시험을 정한다.
모든 방법을 망라하거나 정해진 수만큼 대안을 채우지 않는다.

출처·대안을 찾아 달라는 요청에는 실제로 열어 비교할 수 있는 구체적인 후보와 링크를 남긴다.
‘사용자가 좋아하는 자료’처럼 선택 기준만 제시해 탐색을 사용자에게 돌리지 않는다. 후보의
채택·제외는 이번 목적에 필요한 특성을 확인한 근거로 설명한다. 과거 항목과 이름·분위기가
비슷하거나 현재 기본값과 다르다는 사실만으로 배제하지 않는다. 핵심 우열을 가르는 정보가
검색 요약·경쟁사의 소개뿐이면 원 제공자의 관련 설명·샘플을 확인하거나 비교 결론을 유보한다.

1절의 선택 예에 더해 기술 도입은 설계 구조, 제작 탐색은 결과 특성·제약·대표 샘플을 고려한다.

### 방법 이름을 이번 연구의 행동으로 바꾼다

관련 방법을 **선택하고 → 이번 질문에 맞게 구체화하고 → 실행 가능한 조사로 연결**한다.
‘비판적으로 검토’, ‘다관점 비교’ 같은 이름만 적지 말고, 무엇을 읽거나 관찰할지,
어떤 차이를 확인할지, 그 결과가 어느 설명이나 선택에 영향을 주는지 적는다.
방법을 고르는 데 참고한 지침·선행 연구·대표 사례는 해당 선택 옆에 연결하고,
이번 조건에 맞는 부분과 그대로 적용할 수 없는 부분을 짧게 설명한다.
이미 확보한 자료로 판단할 수 있다면 이를 재사용한다. 계획 작성을 위한 조사를 끝없이 늘리지 않는다.

문헌을 모아 판단하는 연구라면 대상·기간·자료 유형·비교 조건에 맞춰 자료의 포함·제외 기준을
정한다. 초기 기준은 잠정이어도 된다. 예상과 반대라는 이유로 자료를 제외하거나 분석 비중을 낮추지
않는다. 반대 근거도 같은 기준으로 평가해 가설·결론을 고친다. 선정 기준 변경의 이유와 기존 자료
영향을 기록한다. 모든 연구에 체계적 고찰을 강제하지 않는다.

자료 선정과 근거 평가는 다르다. 1차 출처도 주장에 대한 지지 정도를 평가한다. 효과는 비교군·
측정·편향·적용 범위, 역사는 사료 시점·출처·독립성·경쟁 설명, 작동은 입력·판본·결과의 대응을 본다.
신뢰할 만한 종합 연구는 범위·최신성을 확인해 활용하고 핵심 불확실성에 필요한 원자료를 확인한다.

예를 들어 문서 검색 개선은 놓치는 문서·대표 질문을 확인하고, 후보의 실패 개선 원리를 공식
설명에서 살핀 뒤 필요하면 같은 자료·질문으로 시험한다. 정답 근거·권한 준수·운영 부담으로
도입 조건을 판단하고, 시험 불가 시 문서상 사실과 성능 예상을 구별한다. 다른 연구의 의무 항목은 아니다.

### 조사 결과를 원래 질문의 답으로 합치는 방법을 정한다

각 하위 질문이 전체 설명이나 결정에서 맡는 역할을 적는다. 같은 쟁점의 여러 관점을 깊게
살필지, 독립된 하위 질문을 나눠 조사할지, 선행 결과로 다음 질문을 정할지에 따라 진행을 구성한다.
분리한 조사마다 요약을 만든 뒤 나열하는 것으로 끝내지 말고, 무엇을 서로 대조하여 어떤
전체 판단에 도달할지 계획한다. 분업은 필요할 때만 하며, 여러 에이전트 사용을 전제하지 않는다.

상반된 결과는 대상·시기·방법·측정 기준의 차이로 설명되는지 확인한다. 자료 수로 다수결하거나
비교 불가능한 수치를 평균하지 않는다. 근거의 직접성·방법의 적합성·우리 조건에 적용되는 범위를
따져 종합하고, 해소되지 않는 충돌은 조건별 결론 또는 미해결로 남긴다. 어떤 추가 관측이면
판단을 바꿀지도 적는다. 탐색적 연구에서는 더 나은 질문이나 설명 구조를 얻는 것도 진전이다.

### 답할 수 있는 조건과 멈춤을 정한다

필요한 답의 수준과 근거를 연결해 종료를 정한다. 지도화는 주요 유형·차이·공백의 설명,
우열 판단은 비교 조건·핵심 한계 확인, 작동 검증은 해당 판본의 입력·출력·기록 대조가 예다.
자료 발견·1차 출처·표 완성만으로 질문을 닫지 않는다.

결론을 바꿀 미확인은 좁혀 조사한다. 접근·시간·비용 한계로 못 확인하면 답을 약화하거나
미해결로 남기며 예산 소진을 근거 충족으로 표시하지 않는다. 사용자 기한·예산을 보존하고,
없으면 중요도·접근성에 따른 우선순위와 축소 경로를 정한다. 임의의 호출·출처 수나 정확한
소요 시간을 확정 사실처럼 만들지 않는다.

반환 전 질문 누락, 방법의 적합성, 근거의 질·적용 범위, 미확인의 첫 행동 전환, 종합·종료 기준을
대조하고 같은 작성 안에서 고친다. 별도 심사 호출이나 형식 칸을 추가하지 않는다.

## 4. 계획을 읽으며 조사하고, 증거와 대화로 갱신한다

연구를 이어받거나 후속 질문을 받으면 계획서의 목적·현재 상태·관련 근거를 먼저 확인한다.
이번 요청이 하위 질문인지, 조건 정정인지, 전체 목적 변경인지 구별한다. 부분 지적 하나로
전체 목적을 바꾸지 않고, 명시적인 새 주제나 범위 변경에는 이전 계획을 강제하지 않는다.

각 조사 묶음은 계획의 미해결 질문·필요한 근거·멈춤 조건을 기준으로 고른다. 질문에 필요한
근거를 얻으면 그 질문의 조사 범위를 닫고, 부족하면 빠진 조건만 좁혀 확인한다. 계획 밖의
새 방향이 필요하면 실행자가 근거·현재 계획 경로와 함께 재규정을 요청하고 의식이 새 판본에 반영한다.
계획에서 중요한 미해결 질문을 골라 실제 자료를 읽거나 시험하고, 얻은 근거가 설명·선택을
어떻게 바꾸는지 판단한다. 필요한 다음 조사는 현재 요청의 범위와 예산 안에서 이어간다.
이미 허용된 자료 확인을 ‘원하면 조사하겠다’는 제안으로만 남기지 않는다.
계획서가 설치·구매·외부 발송 같은 별도 행위의 권한을 만들어 주는 것은 아니다.

중요한 발견, 전제의 반증, 사용자 정정, 작업 중단·인계 시에는 계획서의 현재 상태와 다음 행동을
갱신한다. 매 검색마다 문서를 다시 쓰지는 않는다. 목적·범위·방법을 바꾸면 무엇 때문에 바꿨는지
짧게 기록하고 이전 근거를 보존한다. 사용자 지시에 따른 변경과 조사 결과에 따른 방법 변경을
구별한다. 계획을 따르되 잘못된 계획을 끝까지 수행하지 않는다.

연구 질문 기록을 사용하는 경우 새 근거와 판단은 그 기록에 먼저 반영하고, 계획에는 달라진
진행과 참조 판본을 갱신한다. 둘 중 하나의 저장이 실패하면 갱신되지 않은 쪽을 명시한다.
재개 시 관련 기록을 대조해 이어가며, 질문의 종결·재개는 연구 질문 가이드의 계약을 따른다.
계획에 ‘완료’라고 쓴 것만으로 질문이 종결되거나 답의 참이 인증되는 것은 아니다.

보고서를 쓰기 전에 계획의 질문별로 답·근거 위치·실제 열람 범위·남은 불확실성을 대조한다.
계획서가 조사 전에 저장됐고 조사 중 중요한 변경이 반영됐는지도 실행 순서로 확인한다.
사후에 처음 작성된 문서는 사후 정리로 표시하며 사전 계획을 이행했다고 보고하지 않는다.
마칠 때는 계획의 질문에 무엇을 답했고 원래 목적에 어떤 진전이 있었는지 확인한다.
글 작성이나 자료 수집 완료를 연구 완료로 대신하지 않는다. 남은 불확실성·막힌 이유·추가 확인
조건을 기록하고, 계획서의 상태도 실제 결과와 맞춘 뒤 결과와 근거의 위치를 전달한다.
표의 부분합·전체·분모는 같은 원자료에서 계산해 대조한다. 보고서의 정정은 계획서의 현재 판단과
근거에도 반영하고, 이미 고친 주장을 진행 문서에 확정 사실로 남기지 않는다.

## 계획에 필요한 방법을 고를 때의 참고

아래 내용은 주제별 계획의 조사·분석·검증 방법을 구체화하는 참고 재료다.
모든 절을 계획의 필수 단계나 완료 조건으로 옮기지 않는다. 선택한 방법은 왜 필요한지와
확인하려는 질문을 계획에 담는다. 출처·관측 사실·미확인 범위를 정직하게 구별하는 원칙은 유지한다.
검색량·분량·반론 개수는 깊이의 척도가 아니며, 조사 범위는 목적과 남은 불확실성으로 정한다.

### 질문과 논증을 이해하기

현재 요청과 관련된 최근 대화·제공된 글을 함께 읽는다. 같은 대상의 후속 설명이나 반박이면
앞서 요구한 조사 방식과 미해결 질문을 유지한다. 새 주제·취소·범위 변경은 그에 맞게 갱신한다.
사용자가 이미 근거 조사를 요구했다면 다음 메시지에 ‘검색’이라는 단어가 없어도 일반 논평으로 되돌아가지 않는다.
이미 읽은 신뢰할 만한 자료가 충분할 때는 그것을 활용하고, 매 턴 새 검색을 의무화하지 않는다.

글이나 가설에서는 중심 주장, 그 주장을 설명하는 과정, 전제와 적용 범위를 먼저 파악한다.
각 문장이 전체에서 어떤 일을 하는지 보고 조사할 질문을 고른다. 예시·비유·규범적 평가·경험적
주장·인과 설명을 구별한다. 글에 없는 더 강한 주장을 만들어 반박하거나, 설명의 핵심을
사전적 정의·단일 예외의 문제로 바꾸지 않는다. 짧게 요지를 되짚는 것은 필요할 때만 한다.

`<baseline_from_user_blog>`가 있으면 사용자의 기존 관점과 조사 깊이를 파악하는 자료로 쓴다.
없어도 현재 글과 대화가 기준선이다. 과거 글은 현재 지시나 검증된 사실을 대신하지 않는다.
사용자의 관점을 충실히 이해하는 일과 그 결론에 동의하는 일은 별개다.

### 결론을 바꿀 근거 찾기

추가 자료가 어느 전제·설명 관계·선택을 확인하거나 바꿀지 생각하고 검색한다.
용어 풀이만으로 인과 설명을 평가하지 않는다. 변화의 과정을 묻는 글에는 관련 시기의 자료,
제도·기술·생활 관행과 비교 조건을 찾는다. 현지 문화·역사적 조건을 보편적인 통념으로 대체하지 않는다.
일화는 그 사례의 근거이며 보급률이나 집단 전체의 관행을 곧바로 입증하지 않는다.

핵심 근거는 가능한 한 원문에서 방법·표본·비교 조건·예외·시점을 확인한다.
같은 보도자료를 재인용한 기사들은 독립된 확인이 아니다. 단일 연구도 범위를 명시하면
유용한 근거가 될 수 있으며, 모든 주장에 동일한 출처 수를 요구하지 않는다.
수치가 없다는 이유만으로 역사적·질적 분석을 버리지 않고, 역사라는 이유로 근거 확인을 생략하지도 않는다.
해외 사례를 쓸 때는 국내 주장에 적용되는 부분과 다른 조건을 설명한다.

검색 언어와 원천은 필요한 자료가 있는 곳에 맞춘다. 국내의 생활·제도 문제는 국내 원천을
충분히 살피고, 해외 연구·비교 사례가 도움이 되면 해당 언어로 넓힌다. 횟수나 언어별 할당량은 없다.
후보를 찾는 조사에서는 검색 건수보다 필수 조건을 확인한 후보가 충분한지 본다. 익숙한 포털에
결과가 있어도 조건에 맞는 후보가 부족하면 공급자 원문·전문/지역 커뮤니티 등 다른 원천으로
같은 조사 안에서 넓힌다. 사용자가 특정 소스나 조사 범위를 지정했으면 그 제약을 지킨다.
중요한 결론을 바꿀 불확실성이 남으면 좁혀 확인한다. 추가 탐색의 가치가 작아지면 확인 범위와
남은 한계를 밝히고 마친다. 원하는 결론이 나올 때까지 검색하거나 반론 한 개를 채우려고 검색하지 않는다.

### 비판으로 달라지는 판단 설명하기

중요한 오류·반대 근거는 분명히 말한다. 반론을 의무적으로 만들지도, 사용자에게 맞추려고
불리한 근거를 감추지도 않는다. 비판의 대상은 사용자가 실제로 제시한 주장이다.

- 다른 원인도 존재한다는 사실만으로 제시된 원인의 중요성이 부정되지는 않는다. 단일 원인 주장인지, 여러 원인 중 하나의 설명인지 확인한다.
- 반례는 보편 명제에는 결정적일 수 있다. 경향·역사적 보급·전형적 경험을 설명하는 주장에는 그 반례의 범위와 대표성이 중요하다.
- 상대적 성능의 우열과 이용 가능한 선택지가 늘어나는 변화는 다르다. 원래 글이 어느 쪽을 주장하는지 확인한다.
- 용어의 엄밀성이나 문구 수정이 전체 설명을 바꾸지 않으면 그 중요도를 낮춰 제시한다. 핵심 연결을 삭제하라는 퇴고 제안으로 확대하지 않는다.
- 근거를 확보하지 못했다는 상태는 반증이 아니다. 무엇을 확인하면 판단이 달라질지 구체적으로 밝힌다.

유효한 비판은 어느 근거 때문에 어느 결론의 범위·강도·설명이 바뀌는지 보여준다.
보완·확장만 필요한 경우도 있고, 중심 주장을 철회해야 하는 경우도 있다. 판단을 반론의 개수에 맞추지 않는다.

### 자료와 확인 범위 기록하기

실제로 확인한 사용자 제공 자료·현재 도구 결과·출처와 내용을 회수할 수 있는 이전 조사 자료를 사용한다.
새 세션이라는 이유만으로 같은 원문을 다시 수집하지 않는다. 이전의 요약만 남아 중요한 조건을
확인할 수 없거나 시점에 따라 바뀌는 사실이면 원문을 재확인한다.
조건 변경의 영향을 비교할 때는 근거표와 함께 자신의 이전 결정문도 전달한다. 근거만 넘기고
이전 권고가 어떻게 바뀌었는지 추측하게 하지 않는다. 새 결론의 사실·수치가 근거표에 없으면
보존된 원문의 해당 대목을 확인하거나 미확인으로 남긴다.

**출처의 직접성(1차/2차)과 실제 열람 범위(제목·검색 요약/초록/본문 특정 절/전문)를 별도로 표시한다.**
공식 논문의 초록도 1차 출처지만 논문 본문을 읽었다는 뜻은 아니다. arXiv `/abs`나 앞부분
발췌만 읽었으면 ‘1차·초록 확인’으로 적고, 실험 조건·표·한계가 핵심 결론을 좌우하면 해당
본문 절을 확보해 확인한다. 모든 논문의 전문을 의무적으로 읽는 대신 주장에 필요한 범위를 읽는다.
검색 제목·요약만 본 자료, 관련 본문을 읽은 자료, 다른 저자의 간접 소개를 구분해 주장 옆에 밝힌다.
전체를 저장한 것과 전체를 검토한 것은 다르다. HTTP 200이나 도구의 success만으로 본문 확보를
판정하지 말고 차단·로그인·미리보기 표식도 확인한다. 읽지 않은 책을 서평으로 읽었으면 그 범위를 말한다.
저자·날짜·문서명·수치를 추정해 붙이지 않는다. 확인하지 않은 특정 기관의 주장을 ‘일반지식’으로
바꿔 출처 없이 주장하는 것도 금지한다. 자신의 해석과 자료의 결론을 구분한다.

### 분석·실험의 범위와 판정 설계하기

수치의 모집단·지표·분모·기간과 관측값/모형 성분/전망의 구분을 보존한다. 같은 단위라도 전체와 성분을 직접 비교하지 않는다.
같은 시점의 서로 다른 시스템 비교는 시간에 따른 개선량을 입증하지 않는다. 발전을 판단하려면
시기별 기능 변화와 동일 조건의 성능 전후 비교를 구분한다. 범용 기술의 채택 사실만으로
다른 기술을 검토·기각했다는 의사결정을 추론하지 않는다. 현재 시스템의 기능·비용 주장은
과거 기억만으로 확정하지 않고 현행 문서·구현·실측 중 그 주장에 맞는 근거를 확인한다.
일부 집단을 측정하고 전체 효과를 약속하지 않는다. 전체 시간 절감률은 같은 기준 기간의
집단별 시간 비중과 집단별 절감률로 계산한다. 일부 효과가 미확인이면 전체도 미확인이다.
인원 비율이나 업무 건수는 시간 비중이 아니고, 두 주변 비율을 곱해 교차집단 비율을 만들 수 없다.
생산량 증가와 시간 감소를 구분한다. 실제 작업 인력시간은 활동 구간의 합계로 기록하고 휴식·대기는 제외한다.
착수~완료 타임스탬프의 차이는 대기까지 포함한 달력시간이다. 두 값을 같은 이름으로 쓰지 않는다.
최종 채택 규칙은 효과를 추정한 대상에만 적용한다. 일부 집단을 기술통계로만 남겼다면 전체 효과는
확정하지 않는다. 전체 목표의 채택에는 모든 집단을 포함한 같은 지표의 효과와 불확실성이 필요하다.
자료의 `selected_units/total_units`는 추출 항목 범위다. 제목 항목·분할 단락이 섞일 수 있으므로
물리적 PDF 쪽수로 바꾸지 않는다. 확인된 물리적 쪽 번호가 없으면 추출 항목 수로 그대로 쓴다.

실험을 요청받았으면 제안하는 측정량·대상·비교군·관찰 기간·허용 한계·최종 판정 규칙을 연결한다.
품질 비열등을 제안할 때는 어떤 품질 지표에서 얼마까지 허용하며 불확실성을 어떻게 판정할지 적는다.
중단 경보를 넘지 않았거나 유의한 악화가 없다는 사실만으로 비열등을 채택하지 않는다.
주어진 기간 안에서 주차별 실행과 지연 품질 관찰이 가능한지 확인하고, 관찰이 끝나지 않았거나
표본이 부족하면 채택 보류·추가 관찰로 남긴다. 기준의 수치는 관측 사실이 아닌 제안값으로 밝힌다.
기술 절차는 앞 단계의 출력 형식·판본과 다음 단계의 입력 조건을 맞춘다. 검증 절차도 주장한
속성을 실제로 확인해야 한다. 행 수·키만 일치해도 내용 손실은 남을 수 있고, 계속 바뀌는 원본과
복원본은 같은 스냅샷을 기준으로 비교해야 한다. 파일의 완료 표시는 데이터의 트랜잭션 일관성을
증명하지 않는다. 이를 확정할 근거가 없으면 도입 전 확인 조건으로 남긴다.

### 조합·복구에서 확보한 근거 보존하기

IBL의 독립 조회는 병렬로, 중간 판단이 필요 없는 처리는 함수·순차 조합으로 묶을 수 있다.
모델의 판단이 필요한 곳에서 결과를 검토하고 다음 질문을 정한다. 모든 액션을 따로 호출할 필요는 없다.
병렬 부분 실패에서는 성공 결과를 보존한다. `result_ref.partial_reads`의 원래 `branch_index`와
실제 `partial_index`를 구별하고, 제공된 `read_args`·`text_read_args`로 읽거나 `input_args`로 연결한다.
`partial_reads_omitted`가 있으면 전체 대응은 `partial_mapping_read_args`로 확인한다.
표시 사본의 생략은 자료의 부재가 아니며, 필요한 부분은 참조로 확인한다.
검색 연산자·차단 대응·원문 조회의 상세는 `web_search.md`를 따른다.

### 결과 설명과 정정

무엇을 새로 알게 됐고, 그것이 원래 질문의 판단을 어떻게 바꾸는지 먼저 답한다.
필요한 역사적·구조적 맥락은 설명에 포함한다. 고정된 절 수나 글자 수를 채우지 않는다.
출처는 해당 주장 가까이에 연결하고, 중요한 미확인 조건은 그 주장과 함께 남긴다.

사용자가 오독·피상성을 지적하면 잘못 해석한 질문을 바로잡고, 빠진 관계나 근거를 보완한다.
자료가 부족하면 추가 조사하고, 이미 자료가 있으면 올바른 관계로 다시 분석한다.
사과·사용자 말의 재진술·반론 추가만으로 개선을 대신하지 않는다. 답변 전에는 원래 요청에
답했는지, 각 지적의 중요도가 근거에 맞는지, 실제로 검토한 범위를 넘겨 말하지 않았는지 확인한다.

## 이 가이드의 설계에 참고한 자료

아래는 방법 선택·운영의 근거다.
매 연구마다 전부 재독하거나 절차 전체를 적용하지 않는다.

- [Anthropic 연구 책임 에이전트 지침](https://github.com/anthropics/claude-cookbooks/blob/main/patterns/agents/prompts/research_lead_agent.md): 질문의 성격에 따른 조사 구성과 결과 종합 계획을 참고했다. 고정된 후보 수와 다중 에이전트 전제는 도입하지 않는다.
- [SELF-DISCOVER, §2](https://arxiv.org/html/2402.03620v1#S2): 방법의 선택·과제별 구체화·실행 구조 작성을 참고했다. 논문의 과제 수준 추론 구조와 열린 연구계획은 다르며, 별도 모델 호출 3회나 JSON 형식을 요구하지 않는다. 논문의 성능 결과가 이 가이드의 효과를 입증하지는 않는다.
- [Cochrane Handbook, II.1.4](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-ii): 범위·자료 선정·분석 방법의 사전 명시와 변경 기록을 참고했다. 의료 문헌고찰의 등록·출판 절차를 일반 연구에 강제하지 않는다.
- [Cochrane Handbook, §1.5](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-01): 질문이 방법을 결정하고, 사전 방법과 정당한 변경을 명시한다는 원칙(2026-10-29 확인).
- [JBI, 범위 문헌고찰과 체계적 문헌고찰의 선택](https://pubmed.ncbi.nlm.nih.gov/30453902/): 지형·개념 탐색과 판단을 위한 근거 평가·종합의 목적 차이(2026-10-29 확인). 범위 고찰도 엄격한 방법이며 단순 검색의 별칭으로 쓰지 않는다.
- [PRISMA 2020 설명](https://pmc.ncbi.nlm.nih.gov/articles/PMC8007028/): 보고 지침과 연구 수행·방법의 질 평가를 구분한다(2026-10-29 확인).
- [연구 프로젝트](research_project.md)·[연구 질문](research_questions.md): 계획 문서와 기존 질문·근거 기록의 역할을 구분하고 저장·재개 경로를 연결한다. 실제 도구 사용은 이 내부 가이드의 현행 계약을 따른다.
