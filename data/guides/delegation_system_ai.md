# 시스템 AI 위임 가이드

시스템 AI가 프로젝트의 전문 에이전트에게 작업을 위임하는 방법입니다.

## 위임 조건 (조건부 위임, 2026-10-05 개정)

기본은 **직접 수행**이다. 단순하거나 짧은 작업을 다른 에이전트에게 떠넘기지 않는다. 독립된 하위 작업에
충분한 분량이 있고, 전문성·독립 검증·동시 진행의 이점이 위임과 결과 통합 비용보다 클 때 위임할 수 있다.
자신이 할 수 있는 일이라는 이유만으로 유효한 분업을 금지하지 않는다.

| 상황 | 기본 선택 |
|---|---|
| 짧은 파일 수정이나 한 번의 조회로 끝나는 일 | 직접 수행 |
| 결과가 서로 독립적인 충분한 분량의 조사 두 개 | 적합한 전문 에이전트가 있으면 분담 |
| 생성한 결과를 다른 관점·독립 기준으로 검증 | 검증 범위를 분리해 위임 가능 |
| 앞 결과가 필요한 변형 계산 | 앞 결과를 받은 뒤 접수; 기다리는 동안 다른 검증 수행 |
| 적합한 대상이 없거나 전달할 문맥이 작업 자체보다 큼 | 직접 수행 |
| 사용자가 특정 에이전트에게 요청 | 요청대로 위임하되 실제 결과까지 회수 |

위임할 때만 짧은 목적과 이득의 근거를 남긴다. 시간 단축이 목적이면 실제로 겹쳐 진행할 필수 작업이 있어야 한다.
위임으로 권한이나 작업 범위를 넓히지 않는다. 사용자가 직접 수행이나 위임을 지정하면 그 의도를 따른다.

## 기본 도구

```
# 프로젝트/에이전트 목록 조회
[others:agents]

# 프로젝트 에이전트에게 위임
[others:delegate]{scope: "cross", agent_id: "프로젝트/에이전트", message: "작업 내용"}
```

## 위임 절차

1. **분업 판단**: 위 조건표로 직접 수행인지 위임인지 정한다(사용자가 지정했으면 그대로)
2. **적합한 에이전트 확인**: `[others:agents]`로 프로젝트/에이전트 목록과 `role_description` 확인
3. **전문성 기반 선택**: 작업 내용에 맞는 전문 에이전트 선택
4. **명확한 요청**: 입력·산출물·완료 조건을 구체적으로 전달
5. **결과 회수**: 접수증(`task_ref`·`child_task_id`)이 돌아온다. `mode:"async"` 면 완료 보고가 나중에 도착하고,
   `mode:"sync"` 면 같은 작업을 기다려 `response`(결과 전문)를 받는다. 접수는 완료가 아니다.

## 모드

| mode | 동작 | 언제 |
|---|---|---|
| `async` (기본) | 접수증 반환, 결과는 완료 보고로 도착 | 기다리는 동안 다른 필수 작업이 있을 때 |
| `sync` | 같은 접수 뒤 그 작업을 제한 시간 동안 기다려 `response` 반환. 시간 초과면 실패로 바꾸지 않고 `task_ref`·`state` 를 돌려주며 결과는 비동기 보고로 온다 | 앞 결과가 다음 단계에 필요할 때(파이프라인 `>>`) |
| `workflow` | 같은 프로젝트 전용. cross/system 에서는 미지원 오류 | 다른 에이전트 문맥에서 IBL 문장을 실행할 때 |

두 모드는 '기다리는가'만 다르다 — 접수·실행·결과 저장은 같다. 순환 위임(대상이 조상 사슬에 있음)은 접수가 거절된다.
접수한 작업의 상태는 `GET /system-ai/tasks/{task_id}` · `GET /projects/{p}/agents/{a}/tasks/{task_id}` (런처용 HTTP 조회)로도 볼 수 있다.

## 핵심 원칙: 의도를 전달하고, 실행 방법은 맡겨라

위임 시 자연어로 의도와 목적을 전달하세요. 위임받는 에이전트가 실행할 구체적인 IBL 코드를 대신 작성하지 마세요. 상대 에이전트는 자기 프로젝트의 맥락(페르소나, 메모, 도구, 히스토리)을 가지고 있으므로 실행 방법은 스스로 판단할 수 있습니다.

## 병렬 위임

서로 의존성이 없는 작업은 동시에 위임 가능:
```
[others:delegate]{scope: "cross", agent_id: "의료/내과", message: "두통 증상 분석"}
[others:delegate]{scope: "cross", agent_id: "study/학습", message: "두통 관련 최신 연구 검색"}
```

## 순차 위임

이전 결과가 필요한 경우 **반드시 순차적으로** 위임하세요:

1. TODO로 전체 계획 작성 (두 번째 작업은 pending 상태로)
2. 첫 번째 위임만 실행
3. **실제 결과가 도착할 때까지 대기** (다음 위임 보류)
4. 결과 도착 후 TODO 업데이트하고 두 번째 위임 실행

**중요**: `[others:delegate]`가 반환하는 "위임했습니다"는 **접수 확인**일 뿐입니다.

**절대 금지:**
- 결과를 받지 않은 상태에서 "검토했습니다", "확인했습니다", "개선점을 드립니다" 등의 표현 사용
- 위임 접수 확인만 받고 마치 결과를 받은 것처럼 행동
- 실제 결과 없이 다음 단계 작업(검토, 피드백, 개선 요청 등)을 위임

```
# ❌ 잘못된 예
[others:delegate]{scope: "cross", agent_id: "홍보/storyteller", message: "슬라이드 만들어줘"}
[others:delegate]{scope: "cross", agent_id: "홍보/storyteller", message: "검토했습니다. 개선점..."}  # 결과 없음!

# ✅ 올바른 예
[others:delegate]{scope: "cross", agent_id: "홍보/storyteller", message: "슬라이드 만들어줘"}
# → 여기서 멈추고 실제 결과 대기 → 결과 도착 후 다음 위임
```

## 파일 경로 원칙

파일 위치를 보고할 때는 **반드시 절대경로**를 사용하세요.

```
# ❌ "결과 파일: outputs/slides_abc123"
# ✅ "결과 파일: /Users/.../projects/홍보/outputs/slides_abc123"
```

## 스테이트리스 원칙

위임받는 에이전트는 **스테이트리스(stateless)** 상태입니다. 이전에 무슨 작업을 했는지 기억하지 못합니다.

위임 메시지에는 **작업에 필요한 모든 정보**를 포함해야 합니다:
- 수정할 파일의 **절대경로**
- 구체적인 **수정 내용**
- 필요한 **원본 데이터나 텍스트**
- **사용자의 원래 조건/제약사항** (금지 사항, 방식 지정 등)

순차 위임 시 **사용자가 처음에 지정한 조건/제약사항을 매번 포함**해야 합니다.

```
# ❌ "아까 만든 슬라이드를 수정해줘"
# ✅ "다음 슬라이드 파일을 수정해줘:
#     - 경로: /Users/.../outputs/slides_abc123
#     - 수정사항: 3번 슬라이드의 제목을 '새로운 시작'으로 변경"
```

## 시간 지정 위임 (스케줄러 경유)

사용자가 **특정 시간에 다른 에이전트에게 작업을 시키는 경우**, `[self:schedule]`에 `target_project_id`/`target_agent_id`를 지정하세요.

- 즉시 위임 → `[others:delegate]{scope: "cross", ...}` 사용
- 시간 지정 → `[self:schedule]` + `target_project_id`/`target_agent_id` 사용

```
# ❌ 스케줄 안에 delegate (결과 전달 불가)
[self:schedule]{at: "15:00", pipeline: "[others:delegate]{scope: 'cross', agent_id: '투자/analyst', message: '주식 현황 보고'}"}

# ✅ 스케줄러로 시간 지정 위임 (대상 에이전트가 직접 실행)
[self:schedule]{at: "15:00", target_project_id: "투자", target_agent_id: "analyst", pipeline: "내 주식 현재 가격을 확인하고 보고해줘"}
```

스케줄러 경유 위임 시 pipeline에는 자연어로 의도를 전달하세요. 대상 에이전트가 자신의 맥락과 도구로 실행 방법을 스스로 판단합니다.

## 주의사항

- 프로젝트 에이전트는 시스템 AI에게 위임 불가 (일방향)
- 위임 시 해당 프로젝트의 모든 에이전트가 자동 활성화됨
- 결과는 자동으로 돌아오므로 기다리면 됨
