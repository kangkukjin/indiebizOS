# IBL 부품의 생성·전달·적용

어휘·내장 함수·람다·명시 프로그램은 입력과 반환 계약을 가진 부품이다.
이름 있는 프로그램은 기존 `[def:]`로 작성하고 `&[fn:이름]`으로 전달한다.
어휘는 `&[node:action]`으로 참조한다. 참조 생성은 실행하지 않는다.

```ibl
[def:변환]($value,$op){return $op($value)}
[def:반복]($values,$job,$op){
  return $values >> [table:each]{return $job{value:$it,op:$op}}
}
$job=&[fn:변환]
$parts={normalize:abs,job:$job}
return [fn:반복]{values:[-2,3],job:get($parts,"job"),op:$parts.normalize}
```

입력 서명이 맞으면 부품을 교체할 수 있다. 이 예제에서 abs를 `($x)=>$x*2`로 바꾸면
변환·반복 본문을 복사하지 않고 다른 계산을 구성한다. 여러 문장의 읽기·검사·쓰기
프로그램도 명시 인자·반환을 가진 함수로 만든 뒤 같은 방식으로 전달한다.

내장 함수는 `$f(값)` 위치 인자를 받는다. 어휘·명명 함수는 `$f{이름:값}`을 받으며,
람다는 위치 인자와 매개변수 이름의 명명 인자를 모두 받는다. 서명이 다른 부품은 명시 함수로 맞춘다.
`$경로 >> $읽기{}`는 어휘의 receiver 계약에 따라 주입한다. 이미 receiver를 지정하면 중복 오류다.
기본값·별칭·op·필수 인자는 직접 호출과 동일하게 검사한다.

```ibl
$읽기=&[self:read]
$문서=$읽기{path:$경로,format:"text"}
return $문서.text
```

위 예제는 `경로` 입력과 현재 호스트의 self:read 권한이 필요하다. 도구를 참조하거나 함수로
감싸도 권한·사람 승인·공유 예산을 얻지 않는다. 승인 대기는 원래 code·inputs의 resume으로
이어가고, 효과 불명 영수증은 확인 없이 재실행하지 않는다.

람다는 호출할 작업을 담을 수 있다. `($p)=>[self:read]{path:$p,format:"text"}`는 생성 시
읽지 않고 일반 실행 자리에서 적용할 때 읽는다. map/filter/sorted/reduce·표 콜백과
조건·조건 값·and/or·기본값은 순수 호출만 받는다. 외부 읽기·쓰기 반복은 each 본문에서 한다.

변수·레코드·목록·함수 인자·반환·Result 안에서도 알려진 부품 계약을 보존한다.
get은 키가 없을 때만 기본값을 선택하며 존재하는 null은 보존한다. 모르는 계약은 check에서
incomplete와 실행 검사 의무로 보고한다. 분석 공유가 실행 횟수나 모델 방문 상한을 줄이지 않는다.

지역 정의만으로 먼저 실행하고 반복 가치가 확인되면 기존 workflow save로 정의 하나씩 저장한다.
저장된 함수는 기존 판본·활성 상태·호출자 검사와 describe를 따른다. Callable 자체를 HTTP/MCP·
Script JSON·결과 파일에 저장하거나 원격으로 전송하지 않는다. 원격에서는 원문과 일반 입력을 보내
그 호스트의 지원 사전에서 부품을 다시 해소한다. 값 전용 식 호스트는 도구 부품을 실행하지 않는다.

`try`·`??` 안의 값 타입 오류는 실행 검사로 남겨 기존 복구 경로를 보존한다. 구문·이름·효과·권한 오류를 감추지는 않는다. 복구 문맥은 분석 요약의 키에 포함된다.
