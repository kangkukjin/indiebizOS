# IBL 부품의 생성·전달·적용

어휘·내장 함수·람다·명시 프로그램은 입력과 반환 계약을 가진 부품이다.
이름 있는 프로그램은 기존 `[def:]`로 작성하고 `&[fn:이름]`으로 전달한다.
어휘는 `&[node:action]`으로 참조한다. 참조 생성은 실행하지 않는다.

```ibl
[def:변환]($value,$op){return $op($value)}
[def:반복]($values,$job,$op){
  return $values >> [table:each]{return $job{value:$it,op:$op}}
}
$job=&[fn:변환]
$parts={normalize:abs,job:$job}
return [fn:반복]{values:[-2,3],job:get($parts,"job"),op:$parts.normalize}
```

입력 서명이 맞으면 부품을 교체할 수 있다. 이 예제에서 abs를 `($x)=>$x*2`로 바꾸면
변환·반복 본문을 복사하지 않고 다른 계산을 구성한다. 여러 문장의 읽기·검사·쓰기
프로그램도 명시 인자·반환을 가진 함수로 만든 뒤 같은 방식으로 전달한다.

내장 함수는 `$f(값)` 위치 인자를 받는다. 어휘·명명 함수는 `$f{이름:값}`을 받으며,
람다는 위치 인자와 매개변수 이름의 명명 인자를 모두 받는다. 서명이 다른 부품은 명시 함수로 맞춘다.
`$경로 >> $읽기{}`는 어휘의 receiver 계약에 따라 주입한다. 이미 receiver를 지정하면 중복 오류다.
기본값·별칭·op·필수 인자는 직접 호출과 동일하게 검사한다.

```ibl
$읽기=&[self:read]
$문서=$읽기{path:$경로,format:"text"}
return $문서.text
```

위 예제는 `경로` 입력과 현재 호스트의 self:read 권한이 필요하다. 도구를 참조하거나 함수로
감싸도 권한·사람 승인·공유 예산을 얻지 않는다. 승인 대기는 원래 code·inputs의 resume으로
이어가고, 효과 불명 영수증은 확인 없이 재실행하지 않는다.

람다는 호출할 작업을 담을 수 있다. `($p)=>[self:read]{path:$p,format:"text"}`는 생성 시
읽지 않고 일반 실행 자리에서 적용할 때 읽는다. map/filter/sorted/reduce·표 콜백과
조건·조건 값·and/or·기본값은 순수 호출만 받는다. 외부 읽기·쓰기 반복은 each 본문에서 한다.

변수·레코드·목록·함수 인자·반환·Result 안에서도 알려진 부품 계약을 보존한다.
get은 키가 없을 때만 기본값을 선택하며 존재하는 null은 보존한다. 모르는 계약은 check에서
incomplete와 실행 검사 의무로 보고한다. 분석 공유가 실행 횟수나 모델 방문 상한을 줄이지 않는다.

지역 정의만으로 먼저 실행하고 반복 가치가 확인되면 기존 workflow save로 정의 하나씩 저장한다.
저장된 함수는 기존 판본·활성 상태·호출자 검사와 describe를 따른다. Callable 자체를 HTTP/MCP·
Script JSON·결과 파일에 저장하거나 원격으로 전송하지 않는다. 원격에서는 원문과 일반 입력을 보내
그 호스트의 지원 사전에서 부품을 다시 해소한다. 값 전용 식 호스트는 도구 부품을 실행하지 않는다.

`try`·`??` 안의 값 타입 오류는 실행 검사로 남겨 기존 복구 경로를 보존한다. 구문·이름·효과·권한 오류를 감추지는 않는다. 복구 문맥은 분석 요약의 키에 포함된다.

지원되는 저장 능력의 try/catch/finally와 `??`는 입력·하위 콜백에 적용하는 의미 관계로 저장한다.
상위 작성·검사는 하위 본문 없이 정상 결과·반환·복구 결과와 효과를 합성하며 도구를 실행하지 않는다.
복구 뒤 후속 문장은 보호된 본문 밖에서 적용하므로 그 문장의 실패가 앞선 catch에 잡히지 않는다.
실패 시점의 대입 상태는 성공 경로의 값으로 단정하지 않으며, `$error`의 부분 값·실패 근거와
catch 불가 종류·정리 실패 우선순위는 실행기가 보존한다. 임의 실패를 정적으로 제거하거나
복구 성공을 업무 완료 증거로 승격하지 않는다. 값 블록의 비지역 return은 정상 값/바인딩과
별도로 전달하며 대입과 후속 계산은 정상 경로에만 적용한다. fallback은 왼쪽의 부분 대입 후
실패를 보수적으로 반영한다. `case`도 선택값과 순서 있는 비교·가지의 관계로 저장한다.
선택값은 한 번 평가하고 첫 일치 뒤의 비교·가지는 실행하지 않는다. 불일치 경로만 다음 비교로
이어지며 else 없는 불일치는 Unit이다. 상위 검사는 하위 본문 없이 이 관계를 적용한다.
확정하지 못한 비교는 가능한 경로를 보존한다. 지원 밖의 형태는 명시적인 본문 검사 경계로 남는다.

## 부품 요구·병렬 자원·완료·수정 계승 (2026-10-27)

독립 함수의 `requirements`는 입력에서 추론한 요구와 조건부 여부를 기록한다.
`param_contracts`는 관측된 특수화이며 두 필드의 뜻을 혼동하지 않는다.
순수 조건에서 적용하는 미지 매개변수는 순수 콜백/Bool 반환 요구로 저장할 수 있다.
실제 인자를 적용할 때는 본문과 같은 검사기로 모순·효과를 검사한다.
필요하면 매개변수 뒤에 타입 계약 리터럴을 선언한다. 선언은 실행하지 않는다.

```ibl
[def:판정]($x:"Number", $p:{"$callable":{params:["Number"],result:"Bool",effects:["pure"]}}){
  return $p($x)
}
return [fn:판정]{x:2,p:($n)=>$n>0}
```

콜백 params 목록은 위치 인자, Record는 명명 인자다. 명시 요구는 `declared_requirements`에
표시하며 저장·describe·회상·개정 검사와 함수 입구가 같은 계약을 쓴다. 유한 구조 밖의
추론은 실행 검사/미확정으로 남긴다. 내부 Callable 반환은 유효하지만 공개 실행의
확정적인 전송 불가는 잎 효과 전에 `VALUE_PROTOCOL`과 값 경로로 거절한다.

`read_resources`·`write_resources`는 한 접근 요약을 사용한다.
check/describe의 `accesses`는 읽기/쓰기·자원 해소 상태·매개변수 관계를 같은 `ibl-access/1` 계약으로 표시한다. 정적 R/W·W/W 충돌은
컴파일에서, 동적 자원은 병렬 가지/each의 시작 전에 실제 바인딩으로 검사한다.
R/R과 독립 자원은 병렬성을 유지한다. 가지 안의 조회 결과가 다음 자원을 정해 전체
접근 범위를 확보할 수 없으면 순서를 명시한다. 개별 잎만 잠그는 트랜잭션은 아니다.
미선언/미해소 쓰기 자원은 기본 병렬 실행에서도 독립성 증명이 없으면 거절한다.
`composition:"ibl-composition/1"`은 기존 요청과 호환되는 표기이며 보장을 켜는 스위치가 아니다. 파일 별칭·상하위 경로·inode는
기존 자원 해소기를 사용한다. 판정 대상은 이 실행의 가지들이며 다른 프로세스를 잠그지 않는다.

요청 `completion`은 최종 값의 명시 완료 의무다. 예:
`[{id:"rows",predicate:"len($value)==2",sources:[{action:"sense:source",targets:{revision:"r1"}}]}]`.
위 action은 설명용 자리표시자다. 실제 어휘와 대상/판본을 선언한다. predicate는 $value를 받는
순수 Bool 식이며 실행 예산·취소를 공유한다. 원천 성공만으로 동등성을 추정하지 않는다. sources는 허용 원천의 대안이다.
봉투 `completion`은 의무별 satisfied/unsatisfied/undetermined, 조건/값 지문, 근거 참조를
보존한다. 업무 JSON의 complete 플래그는 증거가 아니다. 실패 감사 이력과 source_complete는
그대로 남고, 폐기된 시도/문장과 선택 결과의 의존 경로를 따로 읽는다. 명시 원천 호출에서
예약한 로컬 관측은 해당 의무와 호출 근거가 충족될 때만 확정한다. 계약이 없는 관측은
전체 실행의 기존 보수적 정책을 유지한다. 결과 참조는 완료 봉투를 보존하고 동일 계약·값에만
다시 적용한다. 필드/부분 집합이나 임의 의미 변환은 자동으로 동등하다고 인증하지 않는다.

수정 재개는 기존 resume/reuse와 별개인 `repair` 요청이다. 먼저 수정 code·같은 inputs와
`check:true,repair:{run_id:"원 실행"}`로 계획을 얻고, 실행할 때
`repair:{run_id:"원 실행",plan_hash:"검사 결과의 repair.plan_hash"}`를 보낸다.
검사된 실행 계획에서 효과의 입력·계산·조건·호출 좌표를 보존하면서 결과만 만드는 순수 계산을
수정할 수 있다. 효과가 있는 함수 내부의 후속 계산과 전달된 콜백도 같은 의존 관계로 판정한다.
반환값이 뒤 효과의 인자·선택에 쓰이거나 앞 계산의 완료가 다음 효과에 필요하면 그 계산은 고정한다.
repeat·순차/여러 배치 each는 효과의 입력·항목·횟수·종료 조건·조기 반환 선택을 보존한다.
다음 회차의 효과에 쓰이지 않는 누적 결과·내부 후속 계산은 수정할 수 있다. 수정한 계산이 실제로
완료돼야 다음 회차로 진행하며, 앞선 회차의 완료된 효과는 영수증으로 재생한다. 아직 실행하지 않은
원래 회차의 호출도 검증된 반복 경계 안에서 이어 갈 수 있다. `check`의 `repair.new_effects`가
이 정책을 표시한다. 반복 뒤 효과가 결과나 전체 반복의 완료를 요구하면 그 계산은 계속 고정한다.
문장 if/else는 조건을 보존하고 가지 내부의 결과 계산을 수정할 수 있다. 조기 반환으로 끝난
가지의 결과는 다른 가지의 후속 효과 의존에 섞지 않는다. 다만 반환값이 호출자 쪽 효과에 쓰이면
그 계산도 고정한다. 합류한 값이 뒤 효과의 인자/조건이면 가능한 모든 가지의 계산을 보존한다.
try/catch와 `??`는 복구 효과를 선택하는 실패 원인의 계산을 보존하고, 복구 내부의 결과만
만드는 후속 계산은 수정할 수 있다. finally는 반환·실패에도 실행되므로 본문 결과와 독립적인
정리 효과는 재사용할 수 있다. 정리가 부분 대입 값을 읽으면 그 값의 가능한 계산은 고정한다.
완결된 읽기 실패는 원래 Fault로 재생하며, 실패한 쓰기·승인 대기·완료 불명은 자동 계승하지 않는다.
값 블록 안의 return은 현재 함수/each/병렬 가지 프레임을 끝내며, 대입·파이프·뒤 문장에는
정상 경로만 이어진다. 반환과 독립된 정리 효과도 영수증으로 재사용하고 결과만 만드는 계산은
수정할 수 있다. 반환을 블록 값으로 바꾸어 효과 경로를 바꾸거나, 호출자·정리 효과가 소비하는
값을 바꾸는 수정은 거절한다. 대상 미확정 콜백은 구현 전체를 보수적으로 고정한다.
`case`의 효과는 선택값과 그 가지까지 도달하는 앞선 비교·완료 계산에 의존한다. 이 의존은
고정하며 가지 내부의 결과만 만드는 계산은 수정할 수 있다. 앞선 비교 실패가 복구 효과를
선택하면 실패 원인도 보존한다. 반환 경로는 다른 가지의 후속 계산에 합류하지 않는다.
입력·권한·완료 계약은 계속 보존한다. 저장 함수 판본을
교체하는 repair는 새 `function_refs`를 명시하며, 성공한 CAS 뒤 같은 실행의 resume도 그 판본을 쓴다.
효과에 영향을 주는 순수 정의와 미확정 요약은 변경 가능 부분으로 취급하지 않는다.
원문 공백 변경은 구조 신원으로 대응하고 함수/반복 경로는 원래 실행 계보를 보존한다.
완료된 효과는 다시 실행하지 않는다. 검증된 반복 경계 밖의 미기록 외부 호출, 효과 불명,
실패/승인 대기 영수증, 부품·대상 변경, 반복 재정렬, 새 효과 삽입은 거절한다. 계획 지문/CAS와 기존 Journal
배타 잠금을 사용한다. 응답 유실 뒤 같은 repair 요청은 같은 계보를 복원한다.
계승은 과거 완료 사실이며 현재 외부 상태를 재검증했다는 뜻은 아니다.
현재 효과 의존 증명이 없는 과거 기록은 새 수정 계승 권한으로 승격하지 않는다.

표준 문법 개정 범위는 선택적 매개변수 계약·정의 소유 완료 선언과 `propagate` 내장 연산이다. 기능어 코어의 노드 집합과
`STANDARD_CORE_NODES` 경계는 바뀌지 않으며 새 어휘를 추가하지 않는다.


### 계층 상승의 공통 계약과 정의 소유 완료

`ibl-component/1`은 어휘·등록/파일/세션 스크립트 어댑터·함수·람다의 파생 계약이다.
입력 관계·효과/접근·실패·완료·수명·수정 조건과 선언/도출 출처를 함께 표시한다.
하위 계약은 참조 그래프로 유지하고, 검사 보고서에는 요약을, 함수 describe에는
`component_contract`와 의존 `components`를 제공한다. 미상 효과/반환을 가짜 pure/성공으로 바꾸지 않는다.

정의에 선택적인 `:{completion:[...]}`을 붙인다. 아래 원천 이름은 설명용 자리표시자다.

```ibl
[def:검증읽기]($id):{
  completion:[{id:"값",predicate:"$value > 0",
    sources:[{action:"sense:source",targets:{id:{parameter:"id"}}}]}]
}{ return [sense:source]{id:$id} }
```

계약은 상수 Record이며 검사·저장·describe에서 실행하지 않는다. 대상 템플릿의
`{parameter:"인자",path:["필드",0]}`는 해당 호출의 입력 경로에 대입한다. `scope`는 반환 부분 경로,
`required:false`는 선택 의무다. 원천 대안은 `sources`에 적고 복구는 기존 catch/fallback을 쓴다.
함수 호출에 진입할 때 의무가 활성화된다. 조건부 업무는 해당 분기 안에서 의무를 소유한
부품을 호출한다. 호출하지 않은 부품은 충족으로 세지 않으며, 같은 지역 id를 반복 호출해도
인스턴스를 합치지 않는다. 반환값을 버려도 시작한 필수 의무의 실패는 남는다.

`component_completion`은 호출별 판정을 담는다. 실행 success·원천 감사 source_complete와
구분하며 감독/HTTP·MCP/앱·조종실·원격 화면이 같은 필수 의무 정책으로 읽는다.
`component_certificates`는 실제 반환 부분에 붙은 런타임 증거만 내보낸다. 검증된 결과 참조를
통해 포장·이동할 수 있지만 동일 값의 다른 출처로 옮겨붙일 수 없다. 일반 JSON, wire에 넣은
자칭 인증, 이전 실행의 승인 토큰은 이 증거가 아니다. 내보내기는 2,048개 Binding 방문으로
제한하고 남은 경로는 `uninspected`로 남긴다. 생략한 부분에 새 인증을 만들지 않는다.

`propagate(값)`은 실행기가 만든 Err 또는 catch의 `$error`를 원래 code/kind/partial/근거로
재전파한다. Ok이면 그 값을 반환한다. `error_of`로 관찰한 동일 실패에도 실행 중 capability가
보존된다. 일반 Record·저장/전송 후 진단에는 재전파 capability가 없으므로
`FAILURE_CAPABILITY`로 거절한다. `unwrap(Err)`의 `UNWRAP_ERR` 의미는 유지한다.
권한·취소·예산·suspended·protocol은 catch/collect를 우회하지 않는다.

표시 관계도 현재 값에 묶인다. `_display.mirror_fields`는 후보 선언이며, 현재 items의 문단을
정확히 이은 본문과 일치할 때만 본문 표시를 접는다. 선택된 items와 행 메타데이터를 본문으로
대신하지 않는다. 필터·순서·내용 변경, 잘못된 선언, 비교 예산 초과는 두 값을 보존한다.
이는 표시 중복 판정이며 같은 원천/완료/재실행 허가의 증명이 아니다.

같은 실행의 수정 계승은 완결된 `read_external` 실패 영수증도 원래 Fault로 복원한다.
고정된 효과 접두부와 원천 복구 분기는 그대로여야 한다. 실패한 쓰기/model/unknown·승인 대기·
완료 불명·효과 증거 없는 옛 실패 기록은 자동 계승하지 않는다. 순수 계산은 재실행될 수 있다.

## 저장 인터페이스의 재인증과 발견

`describe`의 `application_view`와 회수 후보는 같은 저장 의미 인터페이스에서 만든 짧은 뷰다.
입력·기본값·결과·효과·요구·완료 의무와 `apply` 검사 요청을 보여 준다. 실제 입력과 하위 능력을
대입해야 적합성을 판단할 수 있으며, 이 소개나 정적 검사가 실행 완료 증거를 대신하지 않는다.
`assert`의 실패 설명은 실패 가능한 경로에서만 요구하고, 슬라이스는 입력 목록의 행 관계를 보존한다.

옛 저장본이나 의미 판본·하위 인터페이스·어휘 계약이 바뀐 저장본은 `semantic_limit`에
본문 검사/재인증 필요 이유를 표시한다. 조회·검사만으로 저장소를 변경하지 않는다.
유지보수 시 다음 명령으로 감사한 뒤 적용한다. 도구와 업무 함수는 실행하지 않는다.

```bash
.venv/bin/python3 scripts/revalidate_function_interfaces.py
.venv/bin/python3 scripts/revalidate_function_interfaces.py --apply
```

재인증은 같은 카탈로그에 새 불변 판본을 CAS로 함께 게시한다. 본문과 과거 판본·실행 영수증은
보존하며 지원 밖의 정의와 그 의존자는 이유를 남기고 그대로 둔다. 이미 현재인 판본은 다시
쓰지 않는다. 새 업무 함수 저장에도 같은 인증 관문을 쓰며 작성자가 내부 관계식을 채우지 않는다.
실행 준비는 검사한 관계의 호출 위치·효과·자산 지문을 해당 구현에 연결한다. 하위 본문을 다시
컴파일해 적합성을 재판정하지 않으며, 실행 권한·현재 자원 충돌·완료 증거 검사는 실행기가 맡는다.
