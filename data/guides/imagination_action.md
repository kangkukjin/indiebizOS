# 상상행동 — 자연어 요구를 시스템 AI에 맡기는 훈련

> 정본 용어: **상상행동**. 이를 반복해 수행하는 활동을 **상상행동훈련**이라고 한다.
> 사용자가 “상상행동훈련을 하자”, “상상행동 해보자”, “상상 행동 훈련”이라고 하면 이 가이드를 읽고 진행한다.
> 2026-09-30 개정: 실행 절차·원장·예산·보고는 [긴문장 상상훈련 가이드](long_sentence_imagination.md)로 합쳤다.
> 이 문서에는 상상행동에만 있는 것(과제의 출발점, 외부 행동 격리, 개선 제안의 단위)을 둔다.

## 1. 무엇을 하는가

**사람들이 AI에게 부탁할 법한 일을 자연어로 상상하거나 수집하고, 그 요청을 실제 IndieBiz OS의
시스템 AI에 맡겨 수행한 경험으로 어휘·문법·구현·회상·판정의 부족한 곳을 찾는 훈련**이다.

**사람의 요구 → 실제 수행 경험 → 능력·표현의 공백 발견 → 개선 → 새로운 요구에서 재검증**

목표는 더 다양한 일을 정확하게 해내면서 모델 호출·토큰·시간과 사용자의 재작업을 줄이는 것이다.
새 어휘의 개수나 IBL 사용률 자체를 성과로 삼지 않는다.

| 훈련 | 출발점 | 작성자 | 보는 것 |
|---|---|---|---|
| [기존 상상훈련](imagination_training.md) | 미조합 어휘·문형 | 훈련자 | 이 조합이 표현되고 실행되는가 |
| [긴문장 상상훈련](long_sentence_imagination.md) | 복잡한 과제 | 훈련자 | 큰 일을 쓸 수 있는 언어인가 |
| 상상행동 | 자연어 요구 | 시스템 AI | 부탁한 일을 해냈는가. 못 했거나 비싸다면 왜인가 |

상상행동은 따로 도는 절차가 아니라 **긴문장 회차의 두 번째 실행**이다
([긴문장 가이드 §4-5](long_sentence_imagination.md#4-5-같은-과제를-시스템-ai에-맡긴다-두-번째-실행)).
같은 과제를 훈련자가 쓴 결과와 나란히 놓아야 막힌 원인이 언어인지 시스템의 이해·발견·판정인지 갈린다.

### “상상행동훈련을 하자”라고 했을 때

1. 이 가이드와 긴문장 가이드, [누적 원장](../../docs/LONG_SENTENCE_IMAGINATION_LEDGER.md)의 이전 결론을 읽는다.
2. 사용자가 지정한 분야·과제 수·예산·자료·실행 범위를 따른다. 지정이 없으면 과제 하나와 변형 하나로 시작한다.
3. §2의 원칙으로 자연어 과제를 만들고, 긴문장 가이드의 `task.md`·완료 조건·예산·원장 절차를 따른다.
4. 시스템 AI 실행(긴문장 §4-5)을 한다. 훈련자 작성 실행은 기준선이 필요할 때 함께 하며,
   생략했으면 원장에 “시스템 AI 실행만”이라고 적는다. 기준선이 없으면 막힌 원인을 언어와 시스템으로
   가르기 어렵다는 한계를 보고서에 남긴다.
5. 보고서에서 어휘·문법·구현·회상·판정 중 무엇을 개선할지 제안한다. 수리까지 요청받았다면 이어서 한다.

회차 번호·갭 ID(`L<회차>-<순번>`)·저장 위치는 긴문장 훈련과 한 줄로 잇는다.

## 2. 과제를 만드는 법

- **과제를 만들 때 현재 IBL 카탈로그나 미사용 어휘 목록을 정답 범위로 삼지 않는다.**
  자연어 요청과 원하는 결과를 먼저 적고, 수행 단계에서 현재 능력과 가이드를 찾는다.
- 실제 사용자 요청을 수집할 수도 있고, 생활·일·학습·제작·협업 상황을 상상할 수도 있다.
  현재 사용자의 프로젝트는 출발 사례이지 과제 세계의 한계가 아니다. 상상한 요청과 수집한 요청을 구분한다.
- 요청에 `each`, 함수 이름, 병렬 실행 등 해법을 미리 넣지 않는다. 실제 사용자에게 중요한
  조건·자료·산출물은 적되, 특정 어휘를 쓰면 통과하도록 만들지 않는다.
- 자료 형식의 차이, 부분 실패, 후속 수정처럼 현실적인 어려움을 포함한다. 어려운 문법을 억지로 쓰게
  만드는 퍼즐은 피한다.
- **규모를 고른다.** 파일 몇 개·수십 행 과제는 시스템 AI가 읽고 머리로 풀어 프로그램·회상·재사용이
  드러나지 않는다. 그 층을 보려면 모델이 자료를 머리에 담을 수 없는 규모나 반복될 일을 고른다.
- 수집한 요청은 출처와 맥락을 기록하고 개인 정보·비밀 값은 훈련용 자료로 대체한다.

요청 형태의 예시(고정 목록이 아니다):

- “이 폴더의 여러 견적서에서 이름이 달라도 같은 비용끼리 비교하고, 빠진 항목과 업체에 확인할 질문을 정리해 줘.”
- “이 회의 녹음과 메모에서 결정사항과 할 일을 정리해 줘. 담당자나 날짜가 서로 다르게 적힌 부분은
  어느 자료에서 나온 말인지 보여 줘.”
- “지난번 후보 목록에서 조건이 바뀐 것만 찾아 갱신하고, 내가 이미 제외한 후보는 다시 넣지 말아 줘.”

완료 조건은 요청에서 도출한다. 특정 도구 사용, 문장 길이, 사후에 떠오른 추가 요구를 새 합격 조건으로
넣지 않는다. 요청이 모호하면 명시한 가정으로 진행하고 그 모호함도 관찰 결과로 남긴다.
훈련 도중 도움말이나 정답 조각을 추가했다면 최초 시도와 도움 뒤 시도를 따로 남긴다.

## 3. 행동을 관찰할 수 있고, 실제 세계에 새지 않아야 한다

**리허설 표식은 기록을 가르지만 세계를 막지 않는다.** `/system-ai/chat`에 `origin:"training"`을 실으면 그 턴은
에피소드·궤적 source `training`, `rehearsal` 대화 스레드, 별도 CLI 세션으로 남고 증류와 RED 수리 그랜트를 받지 않는다
(2026-09-30). 그러나 표식은 통계 구분과 일부 보호일 뿐 모든 외부 발송·파일 쓰기를 차단한다는 보장이 아니다.
에이전트 명령 진입점(`/projects/…/command`)에는 아직 표식 자리가 없다. 아래는 훈련 환경이 갖춰야 할 조건이며,
모두 구현된 기능이라는 뜻이 아니다.

**지금 할 수 있는 범위:** 합성·사본 자료 읽기와 회차 폴더 쓰기만 있는 과제. 표식 없이 보냈다면 실사용 기록에
섞인 범위를 보고서에 밝힌다. 외부 발송·구매·공개·예약·기기 제어가 낀 과제는 아래 격리가 확인될 때만 한다.

**관찰할 대상은 실행에서 드러난 행동과 증거다.** 요청·제공 자료, 모델에 실제 전달한 자료, 모델의 도구
요청과 IBL, 도구의 입력·반환·오류, 재시도·병렬 분기·위임 관계, 최종 산출물과 상태 변경을 회차와
에피소드 번호로 연결한다. 모델 내부 사고의 완전한 열람을 뜻하지 않는다. 비밀 값은 제거하고
누락·마스킹된 범위를 표시한다. 회수 방법은 긴문장 가이드 §4-5에 있다.

훈련 시작 전 작은 사전 실행으로 기록의 연결과 외부 차단을 확인한다. 핵심 증거 저장이 실패하거나
격리를 확인하지 못하면 해당 행동의 실행을 중단하고 미검증으로 남긴다.

| 행동 | 훈련에서 수행할 형태 | 판정할 수 있는 범위 |
|---|---|---|
| 문서·메일·메시지 작성 | 시험용 자료로 작성하고 회차 폴더에 보존 | 내용·수신 대상 선택·첨부·요청 충족 |
| 파일·DB 수정 | 격리된 사본에서 실행하고 전후 차이 보존 | 사본에서의 변경 정확성 |
| 이메일·메신저 발송 | 실제 계정 대신 시험용 수신함·서비스 대역으로 전달 | 대역에서의 요청 구성·응답 처리 |
| 구매·예약·공개·기기 제어 | 검증된 시험 환경이나 대역이 있을 때만 실행 | 시험 환경의 계약 범위 |

대역은 모델에게 정답 IBL을 주는 것이 아니다. 모델은 평소처럼 요청을 이해하고 도구를 선택하며,
외부 서비스와 맞닿는 경계가 같은 입력·반환 계약을 가진 시험용 구현으로 이어진다. 실제 계정의
임시보관함에 쓰는 것 역시 실제 변경이다.

프롬프트에 “보내지 마”라고 쓰는 것만으로 격리를 보장하지 않는다. 실행 환경에서 실제 발송 자격증명을
제공하지 않고 외부 쓰기 연결을 차단하며, 셸·HTTP·브라우저·위임·예약 실행으로 돌아가는 길도 같은 제한을
받게 해야 한다. `side_effect` 선언은 분류에 사용하되 선언만으로 실제 연결의 차단을 대신하지 않는다.
종료 후 남은 예약·작업도 확인한다.

대역의 정상 응답뿐 아니라 잘못된 수신자·권한 거절·시간 초과·부분 실패를 넣어 오류 처리와 중복 발송
방지도 시험한다. **대역 성공을 실제 서비스 발송 성공으로 보고하지 않는다.** 대역이나 격리가 없으면
작성·검사·산출물 저장까지 수행하고 발송은 미검증으로 남긴다. 기록·격리의 미비를 어휘 부족과 구분해
개선 목록에 올린다. 리허설을 실사용 통계에 섞은 범위를 밝히고, 과거 운영 원장을 임의로 고쳐 맞추지 않는다.

## 4. 개선은 다른 일에도 통하는 단위로 제안한다

막힌 원인은 긴문장 가이드 §5의 분류에 **어휘·능력 공백**(필요한 정보나 동작을 현재 능력으로 얻을 수 없음)과
**문제 해석 실패**(요청·자료·완료 조건을 잘못 이해함)를 더해 가른다. 오류 메시지만 보고 어휘 부족으로
결론짓지 않는다. 최소 IBL 재현, 인자·결과 계약 확인, 다른 입력 대조로 근본 원인과 연쇄 오류를 가른다.

새 어휘를 제안하려면 기존 조합·스크립트·설명으로 해결되지 않는 이유와 입력·반환·효과를 적고,
다른 자연어 과제에서도 필요한지 살핀다. 특정 보고서 전체를 새 낱말로 감싸는 것과 여러 일에서 조합할 수
있는 능력을 추가하는 것은 구분한다. 어휘·문법 개정은 IBL의 표준/개인 사전 경계와
`new_action_checklist.md`를 따른다. “훈련에서 발견했다”는 사실만으로 자동 신설하지 않는다.
성공 실행에서 관용구를 자동 추출·작명·상시 추천하는 경로도 재개하지 않는다.

수정 뒤에는 원래 자료·요청·모델·조건을 고정한 전후 비교와, 수정 설계 때 보지 않은 변형 과제를 구분해
실행한다. 특정 예제의 성공을 전체 지능 향상으로 확대하지 않는다. 개선 효과는 **새로 해낼 수 있게 된 일**과
**같은 품질의 일을 더 적은 호출·토큰·시간·사용자 재작업으로 끝낸 정도**로 설명한다.

**훈련의 산출물은 자연어 과제와 실제 수행 증거, 그리고 그 증거가 뒷받침하는 발전 방향이다.**
