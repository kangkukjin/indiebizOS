# 상상행동 — 자연어 요구에서 출발하는 훈련

> 정본 용어: **상상행동**. 이를 반복해 수행하는 활동을 **상상행동훈련**이라고 한다.
> 사용자가 “상상행동훈련을 하자”, “상상행동 해보자”, “상상 행동 훈련”이라고 하면 이 가이드를 읽고 진행한다.

## 1. 무엇을 하는가

**세상에서 사람들이 AI에게 부탁할 법한 일을 자연어로 상상하거나 수집하고,
그 요청을 실제 IndieBiz OS에 맡겨 수행한 경험으로 어휘·문법·구현의 부족한 곳을 찾는 훈련**이다.

발전의 두 축은 **어휘와 경험**이다. 어휘는 할 수 있는 일을 넓히고, 경험은 어떤 능력이
필요하며 기존 능력을 어떻게 연결해야 하는지 판단할 근거가 된다. 실제 요청이 쌓이기를
기다리는 대신, 자연어 과제를 만들어 그 경험을 능동적으로 얻는다.

발전의 순환은 다음과 같다.

**사람의 요구 → 실제 수행 경험 → 능력·표현의 공백 발견 → 개선 → 새로운 요구에서 재검증**

목표는 더 다양한 일을 정확하게 해내면서 모델 호출·토큰·시간과 사용자의 재작업을 줄이는 것이다.
새 어휘의 개수나 IBL 사용률 자체를 성과로 삼지 않는다. 경험에서 부족함을 발견해도
기존 어휘 조합, 설명, 문법, 구현 가운데 무엇을 바꿔야 하는지 먼저 구분한다.

## 2. 기존 상상훈련과의 관계

| 구분 | 기존 상상훈련 | 상상행동훈련 |
|---|---|---|
| 출발점 | 미조합 어휘·문형 등 현재 IBL의 조합 공간 | 사람이 실제로 해결하고 싶은 일 |
| 과제 만들기 | 어휘 조합을 시험할 과제 구상 | IBL 해법을 넣지 않은 자연어 요청 생성·수집 |
| 수행 대상 | IBL 문장 조합·검수·실측 | 요청 이해부터 결과 전달까지 실제 수행 경로 |
| 주요 질문 | 이 조합이 표현되고 실행되는가? | 부탁한 일을 해냈는가? 못 했거나 비싸다면 왜인가? |

기존 상상훈련은 `imagination_training.md`를 따른다. “상상행동”을 기존 훈련의
미조합 액션 목록 채우기로 대체하지 않는다. 상상행동 중 언어 결함이 드러나면
기존 방식의 최소 IBL 재현을 원인 분석에 사용할 수 있다.

## 3. “상상행동훈련을 하자”라고 했을 때

1. 이 가이드와 이전 상상행동 결과가 있으면 그 결론을 읽는다.
2. 사용자가 지정한 분야·과제 수·예산·자료·실행 범위를 따른다.
3. 지정이 없으면 서로 다른 일에서 **자연어 과제 3개 정도의 작은 회차**로 시작한다.
   매번 수나 분야를 다시 묻지 않고, 선택한 범위와 이유를 짧게 알린 뒤 진행한다.
4. 과제를 실제로 수행하고 결과·막힌 지점·근거를 남긴다. 아이디어 목록만 만들고 끝내지 않는다.
5. 결과보고서에서 어휘·문법·구현·회상 중 무엇을 개선할지 제안한다. 수리·개정까지
   요청받았다면 그 범위의 구현과 재검증도 이어서 수행한다.

훈련은 회차 단위다. 반복 일정이나 무기한 실행은 별도 요청이 있을 때 정한다.

## 4. 과제를 만드는 법

### 4-1. 자연어 요구를 먼저 확정한다

- **과제를 만들 때 현재 IBL 카탈로그나 미사용 어휘 목록을 정답 범위로 삼지 않는다.**
  자연어 요청과 원하는 결과를 먼저 적고, 수행 단계에서 현재 능력과 가이드를 찾는다.
- 실제 사용자 요청을 수집할 수도 있고, 생활·일·학습·제작·협업 상황을 상상할 수도 있다.
  현재 사용자의 프로젝트는 출발 사례이지 과제 세계의 한계가 아니다.
- 요청에 `each`, 함수 이름, 병렬 실행 등 해법을 미리 넣지 않는다. 실제 사용자에게
  중요한 조건·자료·산출물은 적되, 특정 어휘를 쓰면 통과하도록 만들지 않는다.
- 보통 사람들이 원하는 일부터 시작하되 자료 형식의 차이, 부분 실패, 후속 수정처럼
  현실적인 어려움을 포함한다. 어려운 문법을 억지로 쓰게 만드는 퍼즐은 피한다.
- 수집한 요청은 출처와 맥락을 기록하고 개인 정보·비밀 값은 훈련용 자료로 대체한다.
  상상한 요청과 실제 수집한 요청을 구분한다.

### 4-2. 자연어 과제 예시

다음은 요청 형태의 예시이며 고정 과제 목록이나 현재 결함에 대한 주장이 아니다.

- “이 폴더의 여러 견적서에서 이름이 달라도 같은 비용끼리 비교하고, 빠진 항목과
  업체에 확인할 질문을 정리해 줘.”
- “이 회의 녹음과 메모에서 결정사항과 할 일을 정리해 줘. 담당자나 날짜가 서로
  다르게 적힌 부분은 어느 자료에서 나온 말인지 보여 줘.”
- “이 자료로 초보자에게 설명할 짧은 발표를 만들어 줘. 서로 모순되는 내용은 확정된
  사실처럼 쓰지 말고, 마지막에 내가 확인할 부분을 모아 줘.”
- “지난번 후보 목록에서 조건이 바뀐 것만 찾아 갱신하고, 내가 이미 제외한 후보는
  다시 넣지 말아 줘.”

## 5. 한 과제를 수행하고 진단하는 절차

### 5-1. 입력과 완료 조건을 고정한다

자연어 요청 원문, 제공 자료, 실행 환경, 요청을 충족했다고 판단할 근거를 기록한다.
완료 조건은 요청에서 도출한다. 특정 도구 사용, 문장 길이, 사후에 떠오른 추가 요구를
새 합격 조건으로 넣지 않는다. 요청이 모호하면 실제 사용자 업무에서처럼 확인하거나
명시한 가정으로 진행하고, 그 모호함도 관찰 결과로 남긴다.

### 5-2. 실제 IndieBiz 경로로 실행한다

**자연어 요청을 실행자에게 주고**, 요청 이해·자료 탐색·계획·IBL 작성·실행·결과 전달을
거친다. 훈련자가 미리 정답 IBL을 만들어 넘기면 최초 수행 능력을 재는 과제가 아니다.
실행자는 기존 가이드·기억·함수를 평소처럼 사용할 수 있다. 특정 낱말·함수를 강제하지 않는다.

계획만 작성, 문법 검사만 통과, 일부 도구만 직접 실행한 경우는 전체 수행 성공과 구분한다.
훈련 도중 도움말이나 정답 조각을 추가했다면 최초 시도와 도움 뒤 시도를 따로 남긴다.

실자료 조회와 시험용 자료를 구분하고, 쓰기는 회차의 작업용 사본·출력 위치를 사용한다.
외부 발송·구매·공개·실제 예약과 같은 행동은 훈련 요청만으로 실행하지 않는다.
필요하면 격리된 대역에서 그 직전까지 수행하고, 미검증 경계를 결과에 밝힌다.

훈련 실행은 기존 경로가 지원하는 `origin: training` 등의 출처 구분을 사용하고,
하위 실행에도 이어졌는지 확인한다. 자연어 진입점에 존재하지 않는 옵션을 만들어 넣지 않는다.
표식 전파를 보장할 수 없는 경로는 격리된 동일 하네스에서 수행하고 그 차이를 기록한다.
리허설을 실사용 성공·실패 통계에 섞거나, 과거 운영 원장을 임의로 고쳐 맞추지 않는다.

### 5-2-a. 행동을 관찰할 수 있고, 실제 세계에 새지 않아야 한다

**`origin: training`은 격리 환경을 대신하지 않는다.** 현재 출처 표식은 통계 구분과
일부 보호에 쓰이며, 모든 외부 발송·파일 쓰기를 차단한다는 보장이 아니다.
기존 궤적도 작은 메타데이터 중심이므로, 기록이 있다는 이유만으로 전 과정을
복원할 수 있다고 간주하지 않는다. 아래는 훈련 환경이 갖춰야 할 조건이며,
모두 구현된 기능이라는 뜻이 아니다.

**관찰할 대상은 실행에서 드러난 행동과 증거다.** 요청·제공 자료, 모델에 실제 전달한
자료, 모델의 도구 요청과 IBL, 도구의 입력·반환·오류, 재시도·병렬 분기·위임 관계,
최종 산출물과 상태 변경을 회차와 실행 id로 연결한다. 모델 내부 사고의 완전한 열람을
뜻하지 않는다. 큰 본문은 모델 컨텍스트에 반복 삽입하지 않고 회차의 별도 자료로
보존·참조하며, 비밀 값은 제거하고 누락·마스킹된 범위를 표시한다.

훈련 시작 전 작은 사전 실행으로 기록의 연결과 외부 차단을 확인한다.
핵심 증거 저장이 실패하거나 격리를 확인하지 못하면 해당 행동의 실행을 중단하고
미검증으로 남긴다. 운영용 기록기의 실패 무시 정책을 훈련의 완전성 보장으로 삼지 않는다.

| 행동 | 훈련에서 수행할 형태 | 판정할 수 있는 범위 |
|---|---|---|
| 문서·메일·메시지 작성 | 시험용 자료로 작성하고 회차 폴더에 보존 | 내용·수신 대상 선택·첨부·요청 충족 |
| 파일·DB 수정 | 격리된 사본에서 실행하고 전후 차이 보존 | 사본에서의 변경 정확성 |
| 이메일·메신저 발송 | 실제 계정 대신 시험용 수신함·서비스 대역으로 전달 | 대역에서의 요청 구성·응답 처리 |
| 구매·예약·공개·기기 제어 | 검증된 시험 환경이나 대역이 있을 때만 실행 | 시험 환경의 계약 범위 |

대역은 모델에게 정답 IBL을 주는 것이 아니다. 모델은 평소처럼 요청을 이해하고 도구를
선택하며, 외부 서비스와 맞닿는 경계가 같은 입력·반환 계약을 가진 시험용 구현으로
이어진다. 이메일은 수신자·본문·첨부를 실제 사람에게 보내지 않고 회차 수신함에 저장한다.
메신저도 가상 대화방으로 보낸다. 실제 계정의 임시보관함에 쓰는 것 역시 실제 변경이다.

프롬프트에 “보내지 마”라고 쓰는 것만으로 격리를 보장하지 않는다. 실행 환경에서
실제 발송 자격증명을 제공하지 않고 외부 쓰기 연결을 차단하며, 셸·HTTP·브라우저·
위임·예약 실행으로 돌아가는 길도 같은 제한을 받게 해야 한다. 시험 환경으로
연결되지 않은 쓰기는 기본 차단한다. `side_effect` 선언은 분류에 사용하되
선언만으로 실제 연결의 차단을 대신하지 않는다. 종료 후 남은 예약·작업도 확인한다.

대역의 정상 응답뿐 아니라 잘못된 수신자·권한 거절·시간 초과·부분 실패를 넣어
오류 처리와 중복 발송 방지도 시험한다. **대역 성공을 실제 서비스 발송 성공으로
보고하지 않는다.** 실제 서비스 연동 검증은 별도 시험 계정과 명시된 실행 범위에서 한다.

해당 대역이나 격리가 아직 없다면 작성·검사·산출물 저장까지 수행하고 발송은 미검증으로
남긴다. 이는 전체 과제 달성이 아니라 경계 전까지의 부분 훈련이다. 가능한 과제부터
시작하되, 기록·격리의 미비를 어휘 부족과 구분해 개선 목록에 올린다.

### 5-3. 사용자가 받을 결과로 판정한다

결과 상태는 **달성 / 부분 달성 / 미달 / 미검증**으로 구분한다.
IBL 실행 성공은 요청 달성의 충분조건이 아니다. 내용·파일·출처·요청 조건과 실제 결과를
대조하고, 사용자의 추가 설명이나 수정이 필요했던 부분도 기록한다.

관측 가능한 범위에서 전체 모델 호출(실행·원샷·의식·평가·수리 포함), 입력·캐시·출력
토큰, 벽시계, 실제 재작업을 기록한다. IBL 호출은 별도 값이며, 미관측은 미상이다.
품질 확인을 위해 의식 없는 운영 턴에 평가자를 자동 추가하거나 매 단계 새 평가 모델을
호출하지 않는다. 기존 증거와 결정론 검사를 우선 사용하고, 조사자의 사후 판단은 구분한다.

### 5-4. 막힌 원인을 분류하고 최소 재현으로 확인한다

| 원인 | 확인할 질문 | 개선 방향 |
|---|---|---|
| 어휘·능력 공백 | 필요한 정보나 동작을 현재 능력으로 얻을 수 없는가? | 기존 어휘 확장·새 어휘·공급자 검토 |
| 문법·통화 공백 | 개별 능력은 있는데 필요한 흐름·값 관계를 표현할 수 없는가? | 문법·입출력 계약 검토 |
| 구현 결함 | 표현한 문장의 실제 결과가 계약과 다른가? | 좁은 재현과 회귀를 갖춘 수리 |
| 발견·학습 문제 | 능력이 있는데 설명·예시·회상에서 찾거나 연결하지 못했는가? | 가이드·계약 설명·수동 선정 관용구의 소개 개선 |
| 문제 해석 실패 | 요청·자료·완료 조건을 잘못 이해했는가? | 맥락·계획·확인 과정 개선 |
| 과도한 비용 | 달성은 했지만 중복 읽기·작성·직렬 처리·재작업이 있는가? | 조합·반환·실행 경계 개선 |
| 실행 전제 부족 | 자료·권한·연결·외부 서비스가 준비되지 않았는가? | 전제 보충 또는 미검증 명시 |

여러 원인이 함께 있을 수 있다. 오류 메시지만 보고 어휘 부족으로 결론짓지 않는다.
최소 IBL 재현, 인자·결과 계약 확인, 다른 입력 대조로 근본 원인과 연쇄 오류를 가른다.

### 5-5. 개선은 다른 일에도 통하는 단위로 제안한다

새 어휘를 제안하려면 기존 조합·스크립트·설명으로 해결되지 않는 이유와 입력·반환·효과를
적고, 다른 자연어 과제에서도 필요한지 살핀다. 특정 보고서 전체를 새 낱말로 감싸는 것과
여러 일에서 조합할 수 있는 능력을 추가하는 것은 구분한다.

어휘·문법 개정은 IBL의 표준/개인 사전 경계와 `new_action_checklist.md`를 따른다.
“훈련에서 발견했다”는 사실만으로 자동 신설하지 않는다. **경험은 개정의 판단 근거**다.
성공 실행에서 관용구를 자동 추출·작명·상시 추천하는 경로도 재개하지 않는다.
일반 경험 기록은 유지하고, 이름을 주고 소개할 관용구는 기존 수동 선정·등록 원칙을 따른다.

### 5-6. 수정 뒤 새로운 과제로 다시 확인한다

원래 자료·요청·모델·조건을 고정한 전후 비교와, 수정 설계 때 보지 않은 변형 과제를
구분해 실행한다. 다른 표현·자료 형식·앞뒤 작업에서도 이득이 남는지 본다.
매일 같은 요청문이어도 뉴스·파일이 달라졌다면 동일 입력 비교가 아니다.

특정 예제의 성공을 전체 지능 향상으로 확대하지 않는다. 개선 효과는 **새로 해낼 수 있게 된 일**과
**같은 품질의 일을 더 적은 호출·토큰·시간·사용자 재작업으로 끝낸 정도**로 설명한다.

## 6. 회차 결과를 남기는 법

저장 위치는 `outputs/imagination_action/YYYY-MM-DD_N회차/`로 한다. 이전 상상행동
회차를 확인해 번호를 잇고, 없으면 1회차로 시작한다. 자연어 과제·자료 스냅샷·산출물·
최소 재현을 회차 폴더에 연결한다. 민감한 원자료를 공용 문서나 git에 복사하지 않는다.

보고서는 다음 순서로 작성한다. 칸을 채우기 위해 근거나 수치를 만들지 않는다.

1. **이번 회차의 요구:** 분야·선정 이유·자연어 요청 원문·상상/수집 출처.
2. **수행과 결과:** 입력·완료 조건·실행 경로·도움 여부·산출물·달성 상태.
3. **발견:** 막힌 지점·원인 분류·최소 재현·관측 증거·확실한 사실과 가설.
4. **개선안:** 기존 기능으로 해결 가능한지, 바꿀 능력·문법·구현·설명, 기대 효과와 손실 가능성.
5. **검증:** 관측 비용·품질, 수정했다면 원래 과제와 새로운 과제의 비교, 남은 미검증 범위.
6. **다음 회차:** 이전 해법에 맞추지 않은 새 요구나 이번 가설을 반증할 과제.

**훈련의 산출물은 자연어 과제와 실제 수행 증거, 그리고 그 증거가 뒷받침하는 발전 방향이다.**
