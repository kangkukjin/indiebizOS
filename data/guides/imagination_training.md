# 상상 훈련 (Imagination Training) — IBL 조합 능력 발달 절차

> 정본. 철학적 근거는 `data/system_docs/vision.md` 언어 철학 절, 회차별 갭 요약 누적은
> `docs/VOCAB_COMPOSABILITY_HANDOFF.md` §7. 1회차 실행 기록(2026-08-16)이 §7에 있다.

## 1. 이것이 무엇인가

운동선수가 머릿속에서 투구를 상상하며 훈련하듯, **다양한 IBL 조합을 요구하는 복잡한 과제를
상상하고 → 그에 대응하는 IBL 문장을 실제로 조합해 보고 → 실행기의 검수(dry-run)와 실측으로
피드백을 받아 → 언어의 갭을 찾아내는** 훈련이다.

산출물은 성공한 문장이 아니라 **갭의 원장**이다. 훈련의 목적은 문장을 많이 만드는 것이
아니라, 지금의 IBL로 **말할 수 없는 것·꼬여야만 말할 수 있는 것**을 찾아 언어를 발달시키는
것이다. 최종 산출물은 **결과보고서** — 사용자와 대장장이(개발 세션)가 읽고 시스템을 수정할
수 있는 형태여야 한다.

## 2. 왜 하는가

**실제 명령의 분포는 현재 언어의 표현력에 의해 이미 검열되어 있다.** 사용자는 지금의 IBL로
쉬워 보이는 것만 요구하고, 어려워 보이는 것은 입 밖에 내지 않는다. 표현 비용이 높은 가능성은
시도되지 않고, 시도되지 않으면 갭으로 관찰되지도 않는다. 실제 사용만 관찰해서 언어를
진화시키면 언어는 자기가 이미 잘하는 것 주변만 두터워지는 **닫힌 고리**에 갇힌다.
상상 훈련은 수요가 관찰되기를 기다리지 않고 수요를 상상해서 언어를 먼저 시험함으로써
이 고리를 끊는다.

IBL의 상상 훈련은 선수의 심상 훈련보다 유리하다 — 선수는 상상한 투구가 스트라이크인지
확인할 수 없지만, **상상한 문장은 실행기가 dry-run으로 검수할 수 있다**(결정론적 피드백을
받는 심상). 부작용 없는 문장은 실제 실행까지 가능하다.

## 3. 훈련 절차 (회차별)

### 3-1. 메뉴 준비
```
run_command: cd /Users/kangkukjin/Desktop/AI/indiebizOS && .venv/bin/python scripts/vocab_composition_metrics.py --list-never
```
- **미조합 액션 목록(행동 기준)이 훈련 메뉴**다. 4지표(파이프 길이 중앙값·미조합 수·문형 수·
  파트너 다양성)도 함께 기록해 둔다 — 회차 간 추이가 훈련의 성적표다.
- 문형 분포에서 **조합 0~소수인 문형**(예: 시간·조건·적용)을 이번 회차의 중점으로 고른다.

### 3-2. 과제 상상 (8~12건)
- 메뉴에서 미조합 액션을 뽑되, **한 번도 함께 쓰인 적 없는 액션 짝**을 우선한다 —
  "이 둘을 동시에 요구하는 현실적 과제가 있는가?"라는 질문 자체가 훈련이다.
- 상상은 **사용자의 실제 도메인에 접지**한다: 활성 프로젝트(부동산·투자·강의·법률·음악·
  가족신문 등)와 실제 생활 흐름에서 나올 법한 과제만. 공상적 수요는 어휘 증식의 뒷문이 된다.
- 6문형(조회/발신/축적/조건/적용/시간)을 회차 안에서 고루 커버한다.
- 각 과제는 "사용자가 실제로 말할 법한 자연어 의도" 한 줄로 적는다 — 이것이 나중에
  시드의 intent가 된다.

### 3-3. 문장 조합
- 과제마다 IBL 문장을 실제로 짓는다. 문법은 교재(`data/common_prompts/fragments/12_ibl_only.md`)와
  goal 가이드가 정본이다. **파라미터 이름은 추측하지 말고** 코퍼스 용례(`data/ibl_usage.db`
  `ibl_examples`)나 패키지 `tool.json` `input_schema`에서 확인한다 (validate가 param 이름을
  검사하지 않으므로 — 1회차 F2 발견 — 틀린 이름은 조용히 무시된다).

### 3-4. 검수 (전수)
```
run_command: curl -s -X POST http://127.0.0.1:8765/ibl/validate -H "Content-Type: application/json" -d '{"code": "..."}'
```
- 모든 문장을 dry-run 검수. 문법 오류·유령 액션/op·부작용 여부가 나온다.
- ★검수의 한계를 알고 쓴다: param 이름·통화 칸 규격·필드 실존은 검수가 못 본다.
  검수 통과 = "문법과 액션이 실존한다"이지 "의미가 통한다"가 아니다.

### 3-5. 실측 (선별)
- **부작용 없는 문장만**(sense 조회 + table 변환 체인) `/ibl/execute`로 실측한다.
  검수가 못 보는 것(통화 칸 규격, 필드 치환, 파이프 통화 소비)이 여기서 드러난다.
- ★**요청 body 에 `project_id` 를 반드시 실어라** (F21-1, 21회차 실측). 빼면 패키지 도구가
  전부 `활성 프로젝트 경로를 확보할 수 없어…` 로 거절된다 — 21회차 첫 실측 9건 중 6건이
  이걸로 죽었다. 문장 param 이 아니라 **body 필드**여야 each/폴백/병렬 가지까지 전파된다.
  ```
  curl -s -X POST http://127.0.0.1:8765/ibl/execute -H "Content-Type: application/json" \
       -d '{"code": "...", "project_id": "컨텐츠"}'
  ```
- 쓰기가 필요한 프로브는 **스크래치 원칙**: 임시 이름(예: "상상훈련_스크래치")으로 만들고
  프로브 후 반드시 삭제·원상복구한다. 사용자 데이터(기존 노트북·원장·이웃)는 건드리지 않는다.
- ★**오진 격리 의무**: 이상 동작을 발견하면 결함으로 단정하기 전에 최소 재현으로 격리한다
  (파이프 밖 단독 호출, 다른 param, 다른 액션). 1회차에서 "파이프 속 param 소실 결함"으로
  오진했던 것이 격리로 "param 이름 오타 + 검수 침묵"으로 반증된 사례가 있다.
- **발신 문형 실측 규약** (판정 2026-08-16): 실측은 `[self:notify_user]` **자기 수신 1건**까지만
  허용 — 프로브 후 알림함(REST `/notifications`)에서 그 알림을 정리한다(어휘 신설 없음 —
  훈련 도구를 위해 언어를 늘리지 않는다). `others:channel_send` 등 외부 발신은 **항상 검수만**
  (실발송은 이웃에게 닿는 되돌릴 수 없는 행동).

### 3-6. 분류
각 과제를 셋 중 하나로:
- **깨끗** — 조합·실행 모두 통과. 실행까지 검증된 것만 시드 후보.
- **꼬임** — 되긴 되는데 길거나 우회적. 문법·통화·명명 마찰의 신호(each가 태어난 경위가 이 부류).
- **불가** — 표현이 안 됨. 문법 갭 또는 어휘 갭.

## 4. 결과적으로 무엇을 해야 하는가

### 4-1. 결과보고서 작성 (의무 — 훈련의 최종 산출물)
- **저장**: `outputs/imagination_training/YYYY-MM-DD_N회차.md`
- **형식**:

```markdown
# 상상 훈련 N회차 결과보고서 (YYYY-MM-DD)

## 지표 스냅샷 (훈련 전)
미조합 N/144 · 파이프 길이 중앙값 · 문형 수 · 파트너 다양성 (--list-never 출력 요약)

## 과제 표
| # | 상상 의도(자연어) | 조합 문장 | validate | 실행 | 분류 |
(문장은 코드블록으로, 실행한 것은 결과 요지 한 줄)

## 갭의 원장 ★시스템 수정의 입력 — 가장 중요
분류 접두: G=문법 갭 / V=어휘 갭 / F=마찰(통화·검수·명명) / B=결함(버그)
각 항목마다:
- **한 줄 요약**
- **최소 재현** (그대로 실행하면 재현되는 문장)
- **실측 증거** (실제 출력 발췌)
- **제안** (수리성=바로 고칠 수 있는 것 / 판정성=사용자 결정 필요 — 반드시 구분)

## 시드 후보 (실행 검증 통과만)
intent + code 쌍. 관문: 실행까지 통과 + 갭 제약 없는 것만.

## 판정 요청 (사용자에게)
어휘 신설 후보·언어 개정급 갭 — 근거와 함께. 훈련은 제안만 하고 결정하지 않는다.
```

### 4-2. 원장 누적
- 갭 요약을 `docs/VOCAB_COMPOSABILITY_HANDOFF.md` §7에 한 줄씩 누적한다(회차·갭 ID·상태).
- 이미 있는 갭이 재발견되면 새 항목이 아니라 기존 항목에 증거를 더한다.

### 4-3. 후속 처리의 경계 (★훈련자가 지킬 것)
- **훈련 세션은 발견한 결함·갭을 스스로 고치지 않는다.** 수리는 보고서를 읽은 대장장이
  고리(별도 개발 세션)의 일이다 — 도는 몸이 자기 몸을 비행 중에 고치지 않는다.
- **어휘 신설 금지.** 상상이 발견한 어휘 갭은 후보일 뿐이고, 실제 반복 또는 사용자 판정이
  인준한다 (문법은 상상으로 벼리고, 어휘는 현실이 인준한다).
- **시드는 실행 검증 통과 문장만.** 검증 안 된 상상을 해마에 넣으면 번역기가 오염된다
  (합성 생성기가 '지역'을 '로컬 파일'로 오해했던 사건). 시드 절차는
  `.venv` 파이썬 + `_load_model_sync()` 선행 + `add_examples_batch(source='manual_seed')`.

## 6. 성공의 척도
훈련이 잘 되고 있다는 증거는 보고서의 두께가 아니라 **갭 원장의 항목이 "발견됨"에서
"수리됨/판정됨"으로 옮겨가는 것**이다. 같은 갭이 회차마다 재발견되기만 하면 훈련이
아니라 제자리 뛰기다.

4지표(미조합 수·문형 수·파이프 길이·파트너 다양성)는 **훈련의 성적표가 아니라 몸의
성적표**다 — 지표는 증류(에이전트 주행 경로)에서만 자라고, 훈련 실측(`/ibl/execute`
직접 호출)은 **일부러 거기 안 담긴다.** 리허설은 삶이 아니다(같은 규율: 자기시험의
의도된 실패를 건강 원장에서 격리한 18회차 B18-1 판정). 훈련이 축적 문형을 아무리
연습해도 그 회차의 축적 수는 안 움직이는 게 **정상**이며, 지표는 수리된 어휘를
사용자가 실제 주행에서 쓸 때 비로소 움직인다.
→ 그러므로 회차 보고서는 지표를 **훈련의 성적이 아니라 몸의 현황 스냅샷**으로 읽고,
  훈련 자신의 성적은 원장의 이동으로 적는다.
  (2026-08-22 19회차 관찰 1 판정 — 훈련 실측을 증류에 태우는 안은 기각: 검증 안 된
  상상이 번역기를 오염시키는 값이 지표가 움직이는 값보다 크다.)
