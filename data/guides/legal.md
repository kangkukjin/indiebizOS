# 법률 정보 가이드

`[sense:legal]` 단일 액션으로 국가법령정보센터(law.go.kr) 10개 영역을 통합 검색·조회한다. **query/id × target** 매트릭스가 핵심 분기.

대한민국 법령·판례 *공식 데이터*. 해석·의견은 별도 — 변호사 상담이나 학술 자료는 이 액션 범위 밖.

---

## 핵심 분기: query(검색) vs id(상세)

```
$s = [sense:legal]{query:"주택임대차보호법"}              # 검색 → $s.items (행마다 id)
[sense:legal]{id:$s.items[0].id}                         # 상세 → 법령은 조마다 한 행
[sense:legal]{id:"605077", target:"prec"}                # 판례 상세 (검색 때와 같은 target)
```

| 입력 | 호출 | 결과 |
|---|---|---|
| `query:"..."` | `/lawSearch.do` | `items`(title·meta·url·date·**id**) + `count` · `total` · `search_scope` |
| `id:"..."` | `/lawService.do` | `items` + 원천 키(`법령`·`PrecService` 등) |

`query`와 `id` 같이 들어오면 **id 우선**.

### 검색 결과 읽는 법
- **`id` = 상세 조회에 그대로 넣는 번호.** 검색 때 쓴 `target` 을 상세에도 준다. `url` 은 사람이 여는 공개 주소다(조회 번호로 쓰지 않는다).
- **이름에서 먼저 찾고, 없으면 본문에서 찾는다.** 법령명·사건명에 맞는 것이 0건이면 본문 검색으로 한 번 더 찾고 `search_scope:"body"` 와 `note` 로 알린다. 이름에 맞는 것이 있으면 이름 결과만 온다(`"name"`). 둘 다 없으면 `items:[]`·`count:0`·`"name+body"`.
- **`total` 이 `count` 보다 크면 첫 쪽(20건)만 온 것이다**(`note` 가 알린다). 검색어를 좁힌다.
- 이름 검색은 부분 일치다 — "민법" 의 첫 결과는 난민법이다. 특정 법령은 `title` 이 정확히 같은 행을 고른다: `filter($s.items,($x)=>$x.title == "민법")`.
- 용어 검색의 `dictionary_code`는 원천 사전구분코드다. `011403`은 한영사전이며 국문 정의가 아닐 수 있다. 상세의 `dictionary_name`·`dictionary_code`와 `summary`를 함께 확인한다. 같은 이름이라는 이유만으로 첫 항목을 정의로 단정하지 않는다.
- 판례 사건명은 "임금"·"손해배상(기)"·"유류분반환" 같은 짧은 이름이다. 쟁점을 문장으로 넣으면 대개 본문 검색 결과가 온다.

### 상세 결과 읽는 법
- **법령**: `items` 가 조마다 한 행 — `no`("제6조의3")·`title`("제6조의3(계약갱신 요구 등)")·`text`(조문 + 항·호·목 전체)·`date`(조문 시행일)·`chapter`(속한 장). `law` 에 이름·법령ID·시행일(`enforce_date`)·공개 주소. 원천 구조(부칙·개정문·조문단위 원형)는 키 `법령` 아래 그대로 있다 — 조문은 `items` 를 쓴다.
  - 조문 몇 개만 필요하면 행 연산으로 고른다: `[table:join]{left:[{no:"제162조"},{no:"제766조"}], right:$d.items, on:"no"}`. 민법은 1,193조라 식으로 한 조씩 거르면 계산 예산을 많이 쓴다.
- **판례·헌재결정·해석례·행정규칙·자치법규·조약·용어**: `items` 한 행 — `title`·`meta`·`summary`(판시사항·질의요지·용어 정의)·`date`·`id` + 원천 필드가 한글 이름 그대로(`판시사항`·`판결요지`·`참조조문`·`판례내용`·`사건번호` …, `<br/>` 는 줄바꿈으로).
- **영문법령**: 국문과 같이 `items`가 조마다 `no`·`title`·`text`·`date`·`chapter`·공개 `url`을 반환한다. `no`는 국문과 결합 가능한 `제6조의3` 형식이다. `law`에는 영문 이름·공포일·시행일, `addenda`에는 부칙 원문과 공포일이 있다. 원천 `Law`도 보존한다. **공포일은 시행일이 아니다.** 원천에 시행일이 없으면 `law.enforce_date`·조문의 `date`는 빈 문자열이다. 검색 행의 시행일도 참고하되 번역판과 국문판의 일치 여부는 별도 확인한다. 조문 본문이 비면 `SOURCE_ERROR`로 실패한다.
- **용어**: 공개 `url`, `dictionary_name`·`dictionary_code`를 보존한다. `summary`가 `counterforce` 같은 대역어이고 사전명이 한영사전이면 번역어만 확보된 것이다. 국문 정의를 얻었다고 보고하지 않는다.
- **못 찾은 번호는 실패다**(`NOT_FOUND`) — `[try]…[catch]` 나 `??` 로 받는다. 법령은 법령ID 와 법령일련번호 둘 다 받는다.
- **별표·서식(`law_form`)은 상세가 없다.** 검색 행의 `file_url`·`pdf_url` 이 파일이다.

## target 10종 (영역 분기)

`target` 파라미터로 검색·조회 대상 지정. 기본값은 `law`(법령).

| target | 영역 | 예시 |
|---|---|---|
| `law` (기본) | 법령 | 민법, 주택임대차보호법, 도로교통법 |
| `prec` | 판례 | 대법원·하급심 판결문 |
| `admrul` | 행정규칙 | 각 부처 훈령·예규·고시 |
| `ordin` | 자치법규 | 시·도·구·군 조례 |
| `exp` | 법령해석 | 법제처 유권해석 |
| `detc` | 헌재결정 | 헌법재판소 결정문 |
| `trty` | 조약 | 양자·다자 조약 |
| `eng_law` | 영문법령 | 영문 번역본 |
| `law_term` | 법률용어 | 용어 사전 |
| `law_form` | 별표·서식 | 법령 별표와 신청서 양식(파일 링크) |

## 파라미터

| 키 | 필수 | 설명 |
|---|---|---|
| `query` | (둘 중 하나) | 검색어. 이름(법령명·사건명)에서 찾고 0건이면 본문에서 찾는다 |
| `id` | (둘 중 하나) | 검색 결과 `items` 의 `id`. `law_id`/`precedent_id`도 호환 |
| `target` | (기본 law) | 위 10종 |

## 표준 워크플로우

### 1) 법령 텍스트 찾기
```
$s = [sense:legal]{query:"주택임대차보호법"}
$d = [sense:legal]{id:$s.items[0].id}
→ $d.items = 조마다 한 행, $d.law.enforce_date = 시행일
```

### 2) 판례 검색
```
$s = [sense:legal]{query:"전세 사기 임차인 보호", target:"prec"}
→ 사건명에 없으면 본문에서 찾은 목록(search_scope 확인)
[sense:legal]{id:$s.items[0].id, target:"prec"}
→ 판시사항·판결요지·참조조문·판례내용
```

### 3) 행정규칙 찾기
```
[sense:legal]{query:"공공 데이터 활용", target:"admrul"}
```

### 4) 자치법규 (특정 지자체 조례)
```
[sense:legal]{query:"서울특별시 옥외광고물 조례", target:"ordin"}
```

### 5) 법률 용어 확인
```
[sense:legal]{query:"선의의 제3자", target:"law_term"}
```

### 6) 영문 법령 (외국인 대응)
```
[sense:legal]{query:"Foreign Investment Promotion Act", target:"eng_law"}
```

## 활용 패턴

### "법적 근거"가 필요한 작업
계약서 검토·민원 답변·정책 인용 시:
1. `query` + `target:"law"`로 관련 법령 검색
2. 판단에 영향 주는 판례는 `target:"prec"`
3. 모호한 경우 `target:"exp"`(법령해석) 확인

### 강의/책 인용 자료
법령 인용 시 정확한 조항·시행일이 필요. ID 조회로 전문을 가져와 해당 조항 인용.

### 지자체 사업
자치법규(`ordin`)는 지자체별로 다름. 지자체명을 query에 포함해야 정확.

## 자주 하는 실수

- **target 오타**: 정확히 `law`/`prec`/`admrul`/... 중 하나. `precedent` 같은 별칭 안 됨.
- **id 는 검색 행의 `id` 칸**: `url` 속 번호나 기억한 번호가 아니라 `items[].id` 를 쓴다. 상세에도 검색 때의 `target` 을 준다.
- **query만으로 전문**: 검색 결과는 *목록*만 반환. 전문은 id로 다시 조회 필요.
- **본문 검색 결과를 이름 일치로 착각**: `search_scope` 가 `body` 면 제목이 아니라 본문에 검색어가 있는 것이다. 쟁점에 맞는지는 상세의 판시사항·참조조문으로 확인한다.
- **기한 계산**: 조문의 기간만으로 날짜를 내지 않는다. 첫날을 세는지·달력으로 세는지·말일이 휴일인지는 민법 제157조·제160조·제161조에 있다(같은 길로 가져온다). 어느 날부터 세는지는 사실관계 판단이다.
- **외국 법령**: 영문 *번역* 법령은 `eng_law`. 외국 법령 자체는 이 API에서 안 됨.
