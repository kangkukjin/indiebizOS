# 마케팅·홍보 가이드

홍보물(소개문, 카드뉴스, 슬라이드, 이미지·영상 소재, 상세페이지, 블로그 초안)을 만들거나 홍보 전략을 세울 때 이 가이드를 따릅니다.

<core_rules priority="critical">
1. **고객 관점 우선** — 고객은 드릴이 아니라 구멍을 원한다. 제품 기능·스펙 나열로 시작하는 홍보물은 실패작이다. 고객의 문제(페인포인트)로 시작하라.
2. **공개 발행물 경계** — AI가 조합한 문장을 그대로 공개 채널에 발행하지 않는다. AI의 역할은 초안·구조·앵글 제안까지. 최종 문안 확정과 발행 결정은 사용자 몫이다.
3. **분석은 AI, 결정은 사람** — 성과 팩트 정리·초안 생산은 자동으로 하되, 무엇을 내보내고 무엇을 중단할지는 사용자에게 제안하고 확인받는다.
</core_rules>

## 1. 시작점: 브랜드 브리프

홍보물을 만들기 전에 브리프를 먼저 만든다(또는 기존 브리프를 읽는다). 브리프 없이 곧장 소재를 만들면 매번 톤이 흔들린다.

**3C 분석**으로 재료를 모은다:
- **Company(자사)**: 무엇을 파는가, 한 줄 정의, USP(경쟁자가 못 하는 것), 자주 쓰는 톤·컬러
- **Competitor(경쟁사)**: 경쟁자는 어떤 소구 포인트로 말하고 있나 — 같은 말을 하면 묻힌다
- **Customer(고객)**: 고객이 겪는 문제, 검색하는 말, 망설이는 이유

**브리프 항목** (이 순서로 정리):
| 항목 | 내용 |
|------|------|
| 한 줄 정의 | 이 제품/서비스는 [누구]의 [문제]를 [어떻게] 해결한다 |
| USP | 2~4개. 기능이 아니라 "고객에게 무엇이 달라지는가"로 서술 |
| 타겟과 페인포인트 | 타겟별로 다른 문제를 겪는다 — 복수로 정리 |
| 톤 | 문장 스타일 (예: 담백/전문가/친근) + 쓰지 말아야 할 표현 |
| 컬러 | 자주 쓰는 색 + 피할 색 (이미지 소재 제작 시 준수) |
| 사회적 증거(RTB) | 믿을 수 있는 이유 — 실사용 후기, 숫자, 이력. **실재하는 것만**, 지어내기 금지 |
| 메인 카피 후보 | 3~5개 제안 → 사용자가 고른다 |

브리프는 프로젝트 폴더나 outputs에 파일로 남겨 재사용한다. 소재를 만들 때마다 다시 분석하지 않는다.

## 2. 소재 스토리보드 공식

이미지·영상·카드뉴스 소재는 이 3단 구조가 기본이다:

1. **후킹** = 고객의 페인포인트. 보는 사람이 "내 이야기구나" 해야 다음을 본다. 브랜드명·제품명으로 시작하지 마라.
2. **해결** = 우리의 강점이 그 문제를 어떻게 푸는가. 여기서 비로소 제품이 등장한다.
3. **CTA** = 행동 지시 + **지금 해야 하는 이유** (무료 체험, 한정, 즉시 효용). 이유 없는 CTA는 약하다.

예 (선크림): "선크림 바르면 여드름 나는 분?" → "논코메도제닉 검증, 모공을 막지 않습니다" → "오늘 첫 구매 샘플 증정"
반례 (기능 선행): "SPF50+ PA++++ 신제품 출시!" — 고객의 문제가 없으므로 스크롤이 지나간다.

## 3. 앵글 다양화

같은 카피의 자잘한 변형을 여러 개 만드는 것은 다양화가 아니다(플랫폼 머신러닝도 같은 소재로 취급한다). **페인포인트 축을 바꿔라**:

- 타겟 A: 품질이 불만인 사람 / 타겟 B: 가격이 부담인 사람 / 타겟 C: 시간이 없는 사람 — 각각 다른 후킹으로 별도 소재
- 유형도 다양화: 문제 공감형 / 사회적 증거형(후기 인용) / 비교형 / 데모형
- 순서: **처음엔 앵글을 넓게** 여러 개 → 반응 오는 앵글로 **좁힌 뒤** → 그 앵글 안에서 카피 테스트

## 4. 소재 수명과 성과 판단

- 오래 가는 소재(에버그린)는 화려한 것이 아니라 **브랜드 고유의 메시지를 담백하게 전한 것**인 경우가 많다. 위닝 소재를 찾으면 함부로 갈지 마라.
- 유료 광고를 집행 중이라면: 성과가 낮아 보여도 **단기 조정은 플랫폼 머신러닝 학습을 리셋**시켜 오히려 해칠 수 있다. 일 단위 관찰, 주 단위 조정이 기본. 소재 중단 같은 되돌리기 어려운 조정은 반드시 사용자 확인을 받는다.
- 성과 리포트 구조: 현황 팩트 → KPI 대비 → 소재별 성과 → 제안(무엇을 바꿀지). 팩트와 제안을 섞지 마라.

## 5. indiebizOS에서의 실행 경로

| 일 | 어휘 |
|----|------|
| 자사·경쟁사 사이트 분석 | `[sense:crawl]`, `[sense:search]` |
| 고객 목소리 리서치 | `[sense:search]{source:"naver"}` (후기·카페), `[sense:used]`·커뮤니티 관찰 |
| 소재 이미지 생성 | `[engines:image_gemini]` (브리프의 톤·컬러 파라미터에 반영) |
| 카드뉴스·슬라이드 | `[self:slide]` (aesthetic을 브랜드 톤에 맞춤) |
| 홍보 영상(쇼폼) | `[self:deck]{op:"video"}` — 스토리보드 공식대로 슬라이드 구성 후 영상화 |
| 발행 채널 | 블로그(vault), 공유창고, 포털, 게시판 `[others:bulletin]`, 웹앱 `[self:webapp]` |
| 정기 리포트 | 스케줄러 + `[others:delegate]{scope:"system"}` |

**주의**: 홍보능력 = 콘텐츠 품질 × 유통 × 꾸준함. 이 가이드는 품질만 다룬다. 유통(도달할 독자)은 채널의 꾸준한 발행으로만 쌓인다 — 한 번의 잘 만든 소재보다 지속 발행이 이긴다.
