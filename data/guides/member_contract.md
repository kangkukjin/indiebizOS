# 회원 액션 계약

## 회원 프로파일에 공개할 때

- 회원용으로 지원되는 기능은 기본 제공된다. 액션 지원 선언은 별개다. lands_on을 선언하기 전에 회원의 위치·출력·캐시·로그를 확인한다. 선언이 없는 관리 기능은 계속 제외한다.
- body는 limb_op:{op,...}를 어휘 소스에 선언하고 helper/Android 봉투 계약과 맞춘다.
- hub는 side_effect:false와 path_audited:{at,impl}가 필요하다. 지문은 패키지 하위 Python 파일도 포함한다.
  공유 라이브러리·외부 실행기까지 실제 경로 접근을 감사한다. 지문만 적어 접근 격리가 생겼다고 판정하지 않는다.
- 공개 사전 필터와 실제 중첩/직접 IBL 잎 실행 모두에서 거절 시험을 둔다.
- backend/test_member_* 검사는 영속 경로를 모두 임시화한다. 원문·경로가 주인 로그에 남는지 함께 본다.
- build_ibl_nodes.py로 파생하고 --check, backend 층·파일 크기 검사, 해당 플랫폼 봉투 검사를 통과시킨다.

설치 기기의 IBL 문서 변환과 직접 read/write는 같은 교환 어댑터를 쓴다. 성공한 read의
SHA-256은 해당 턴·로컬 작업·연결·요청 경로에만 보관하여 후속 write의 조건으로 전달한다.
쓰기 직전 자동 재독은 하지 않으며, 명시한 expected_hash는 교체하지 않는다. 파일 변경 여부와
실제 저장은 계속 기기가 판정한다. 지문이 없는 구형 기기의 응답을 조건부 쓰기 증거로 만들지 않는다.

텍스트 범위 읽기는 주인과 같은 CR/LF/CRLF 행 좌표를 사용하며 U+2028·수직 탭을
추가 행으로 세지 않는다. `numbered:true`는 판본2 Document.text에도 원본 1-기반
줄번호와 탭을 붙인다. 범위·줄끝·후행 공백은 그대로 보존한다.

설계와 단계별 잔여 검증: docs/EXTERNAL_SERVICE_APP_HANDOFF.md §11. 회원 시작 예시: member_start.md.

## 문서·미디어 어댑터

`lands_on:body`의 영속 결과는 회원 기기에 남는다. `member_transform:모듈:함수`는 패키지 안의
감사된 처리기를 지정하며 `path_audited:{at,impl}`가 필수다. hub 액션과 같은 지문 관문을 통과해야 한다.
현재 문서 어댑터는 명시된 회원 path를 base64로 받고, 턴 임시 폴더의 생성된 경로만 라이브러리에 전달한다.
PDF/DOCX/XLSX/XLS·텍스트 범위를 읽고, PDF/DOCX 양식을 채워 기기의 write 영수증까지 기다린다.
파일당 32MB, Office ZIP 해제 합계 128MB/1만 항목 한도. 외부 자원 relationship은 거절하고
DOCX 이미지 파일 추출은 끈다. 오류·본문에서 경로를 추측해 읽거나 쓰지 않는다.

출력 `files`는 확인된 기기 파일의 path/bytes/on/ref 목록이다. `ref`의 `member-file:…` 값은
그 턴 안의 path/src/dest/output 슬롯에만 다시 쓸 수 있다. 다른 턴·회원의 참조는 실패한다.
이것은 IBL 문법 추가가 아닌 어댑터의 불투명 값이다. 기존 `files:[인라인 문자열]`/`$file:0` 첨부
문법도 그대로 사용할 수 있다(합계 4MB). `files_from`으로 허브 파일을 읽는 경로는 회원에게 전달하지 않는다.

`limbs:radio`의 search/stations는 `ops.lands_on` 선언에 따라 감사된 허브에서 읽는다.
같은 어휘의 즐겨찾기 op는 회원에게 열리지 않는다(`ops.lands_on:false`, 주인 전용).
station_id 해소 뒤 재생/정지/상태/볼륨은
회원 자신의 기기로 간다. PC는 설치된 로컬 셸의 브라우저 오디오, Android는 MediaPlayer를 쓴다.
브라우저·기기가 지원하지 않는 스트림 형식이나 자동재생 거절은 성공으로 기록하지 않는다.
PC 재생 화면은 켜 두어야 한다. Android의 sense:here는 위치 허용 버튼에서 OS 권한을 준 뒤
측정하고, limbs:android는 공통 접근성 서비스로 연결한다. PC helper는 Android 봉투를 실행하지 않는다.

## 설치 없는 웹앱의 산출물

회원 표면은 자율주행(회원 전용 에이전트)과 앱 두 모드다. 내 파일은 앱의 보조 도구이며,
주인 설정·시스템 AI·조종실은 제공하지 않는다. 브라우저 내부 저장·계산·프로그램은
회원이 시작한 작업의 세션·작업 ID 검사 뒤 기본 실행한다. 위치·미디어의 승인과 브라우저 권한은 별개다.

선언형 앱의 `request: {message, output}`은 회원 전용 채팅으로 간다. output은 브라우저에서
상대경로로 검증하며 허브에 보내지 않는다. 성공 응답 본문을 작업별 고유 파일로 IndexedDB에
저장한 후에만 saved와 files(on:body)를 반환한다. 실패·취소·저장 실패는 파일 전달 완료가 아니다.
사용자는 결과의 내려받기 버튼으로 OS 파일을 얻는다. 일반 IBL write도 해당 작업의 저장
영수증으로 결과 파일을 표시한다. 주인 outputs·공유창고·시스템 AI 위임은 이 경로에 없다.

정기보고는 회원용 데이터 선언을 사용한다. 주인용 report.yaml을 그대로 재사용하지 않는다.
현재 제공 자료 기반 작성이며, 주인 보고서의 웹 조사·예약 실행·개인 가이드 복제는 지원하지 않는다.


## 중앙 기어와 사용 기록 (2026-10-15 개정)

회원 실행·분류·의식은 중앙 model_gear의 해당 축을 사용한다. 실행 축이 CLI라고 해서
background 경량 모델로 바꾸지 않는다. Claude Code는 동일 모델을 회원 전용 MCP로
연결한다. 내장 도구·주인 MCP·개인 설정·세션 영속은 끄고, 턴별 임시 설정과 인증된
loopback 브리지에서 회원 principal을 복원한다. 도구는 기존 회원 관문을 통과한다.
현재 Codex CLI는 회원 격리를 지원하지 않아 명시적으로 실패한다. 다른 모델로 강등하지 않는다.
기어 변경은 다음 회원 요청부터 반영한다. 원샷 제공자 캐시는 주인과 공유하지 않는다.

누적 작업 토큰·시간·모델/기기 호출 수·일일 대화 횟수는 기본 제한 없음(null)이다.
member_policy.json에 명시한 제한은 유효하다. 동시 실행·메시지 크기·개별 기기 명령의
응답 대기는 자원/전송 경계로 유지한다. 모델 제공자의 문맥 창·출력/구독 제한은 별개다.

member_usage.json은 날짜별 턴과 관측 토큰을 계속 합산한다. 실패·취소도 관측 비용을
누락하지 않는다. member_activity.sqlite3는 관리자 전용 원장으로 회원/기기, **수신한 요청
메시지 본문 전체**, 시작·종료·상태, 사용 모델, 도구 순서·상태와 작업 토큰을 보관한다.
본문은 축약·마스킹 없이 저장하며, 첨부나 workflow를 모델 입력에 덧붙이기 전의 message다.
요청 봉투 전체·모델 입력 전체를 저장한다는 뜻은 아니다. 별도 응답 원문·도구 인자/결과 전문·
파일 바이트 칸은 없지만, 회원이 메시지 본문에 넣어 보낸 내용은 요청 기록에 포함된다.
기록은 회원 고지에 알리며 개인 기억/증류로 쓰지 않는다. 전체 대화·파일의 백업을 대신하지 않는다.

현재 코드에는 작업 원장의 TTL·날짜별 자동 삭제·PC 등록 해제 연동 삭제가 없다. 연결 해제는
자격 폐기와 세션 종료이며 요청 기록 삭제가 아니다. 별도 삭제 없이는 남으며 유한 보존 기한을
보장하지 않는다. 보존 정책과 삭제 기능 마련은 별도 운영·개발 과제다.
관리자는 오늘/누적 및 최근 30일 사용량을 보고, 상세 작업은 날짜 제한 없이 최신 50건부터
이전 기록을 조회한다. **30일은 일별 사용량 합산 범위이며 보존 기한이 아니다.** 미측정 토큰은
0과 구별한다. 이 계약은 이전의 ‘중앙에는 집계만 보관’ 규약을 대체한다.

v2 접수 메타데이터와 완료 결과 RAM은 작업 원장과 별개다. 완료 후 30분을 넘긴 RAM 항목을
다음 submit/status 때 정리하며, 중앙 재시작에도 RAM은 소실된다. 이는 정각 삭제 타이머가 아니고
중앙 요청 본문을 지우지도 않는다. 접수 메타데이터에도 자동 만료·등록 해제 연동 삭제는 없다.
저장소별 범위와 코드 근거는 [회원 데스크톱 설계의 중앙 보존·삭제](../../docs/MEMBER_DESKTOP_DESIGN_2026_10_15.md#중앙-요청-본문의-보존삭제-현행-구현)를 따른다.

회원 실행 목적지는 액션의 `lands_on`을 기본으로 `ops.lands_on`에서 덮는다.
`hub`는 해당 op의 읽기·감사 지문 검사를, `body`는 기기 연결·변환 검사를 통과해야 한다.
`false`는 회원 비공개이며 어휘 통합으로 주인의 저장소를 새로 공개하지 않는다.
