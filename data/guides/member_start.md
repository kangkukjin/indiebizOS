# 회원 작업 공간 시작하기

이 가이드는 주인이 발행한 회원 작업 공간의 입문서다. 주인용 명령창과 회원용 명령창은 신원이 다르다.
회원용으로 지원되는 기능은 별도 공개 설정 없이 기본 제공된다. 묶음이 주인에게 잠들거나 공통 설정에서 명시적으로 끄면 회원에게도 닫힌다. 회원은 초대받은 HTTPS 주소의 `/m/app`을 열고 회원 키를 입력한다. PC·폰 모두 ZIP/APK 설치 없이 같은 웹앱을 사용한다. 키를 채팅에 붙이지 않는다.

## 웹앱으로 시작

1. **작업 공간 열기 → 새 작업 → 자율주행**에서 요청한다. AI가 필요한 도구를 반복 호출하며 진행 상황과 결과를 표시한다. 브라우저 내부 파일 저장·계산은 추가 승인 없이 실행한다. 위치·재생 등 필요한 승인은 같은 화면에 나타난다.
2. **앱 → 내 파일 → 파일 가져오기**로 기기의 파일을 선택한다. 가져온 사본은 브라우저 작업 공간의 `imports/`에 저장된다. 파일을 열어 편집하고 **기기에 내려받기**로 결과를 저장한다. 브라우저가 원래 파일을 자동 덮어쓰지는 않는다.
3. **앱**에서 공개된 앱과 내 앱을 실행한다. 내 앱은 작업 공간의 `apps.json`에서 불러온다.
4. 이전 작업을 열어 이어서 요청한다. 대화·기억·작업·파일은 이 기기, 이 브라우저, 이 허브 주소의 IndexedDB에 회원별로 보관된다. 새로고침 후에도 남지만 다른 기기와 자동 동기화하지 않는다.
5. **이 기기의 보관·복원 → 지속 보관 요청**, **기억 내보내기**로 데이터 삭제에 대비한다. 내보내기는 파일·프로그램까지 포함한 JSON이며 **백업 복원**은 기존 ID를 덮어쓰지 않고 합친다. 사이트 데이터 삭제·시크릿 창 종료 시 보관 데이터가 없어질 수 있다.

작업 중에는 탭을 열어 둔다. 폰의 화면 잠금·백그라운드 전환·탭 종료 시 실행이 중단될 수 있다. 중단되거나 완료 여부를 잃은 작업은 결과 불명으로 남기며 자동 재실행하지 않는다. 같은 회원 작업 공간은 한 브라우저 탭에서 실행한다.

웹앱 업데이트는 허브 배포 후 다음 접속·새로고침에 반영된다. 재설치하지 않는다. 데이터베이스 업그레이드는 기존 기록을 삭제하지 않는 방식으로 적용한다. 키는 현재 탭의 세션 저장소에만 보관하고 연결 종료 시 지운다.

예시 경로는 브라우저 작업 공간의 상대경로다. 일반 OS 폴더의 임의 경로·셸·네이티브 앱 조작은 웹앱이 제공하지 않는다. `run_javascript`가 제공되면 입력 데이터의 계산·변환을 이 기기의 격리된 JavaScript 실행기에서 수행한다(15초, 결과 32MB 제한). 파일 입출력은 IBL로 수행한다. 허브의 시스템 설정·개조 기능은 제공하지 않는다.

기존 PC 연결 프로그램과 Android 앱은 별도 선택지로 유지한다. PC에서는 선택 폴더와 승인한 OS 셸을, Android에서는 앱 저장소와 명시적으로 허용한 폰 기능을 사용한다. 아래 예시 중 네이티브 전용 기능은 웹앱에서 대신 허브 PC로 실행하지 않는다.

## IBL 시작 문장 열 개

1. **폴더 보기** — 폴더의 파일 목록을 읽는다. 확인: 결과 경로가 내 기기의 경로인지 본다.
```ibl
[self:list]{path:"."}
```

2. **텍스트 읽기** — 자신의 메모를 읽는다. 확인: 기기를 끊으면 허브 대신 읽기가 실패한다.
```ibl
[self:read]{path:"memo.txt"}
```

3. **새 메모 저장** — 승인 판에서 경로와 본문을 확인하고 허용한다. 확인: 성공 영수증 이후 파일이 생긴다.
```ibl
[self:write]{path:"memo.txt",content:"오늘의 메모"}
```

4. **폴더 만들기** — 로컬 승인이 필요한 작업이다. 확인: 내 파일 목록에 폴더가 생긴다.
```ibl
[self:mkdir]{path:"notes"}
```

5. **파일 옮기기** — 이미 있는 대상 파일에는 덮어쓰지 않는다. 확인: 원본이 옮겨지고 대상에 내용이 남는다.
```ibl
[self:move]{src:"memo.txt",dest:"notes/memo.txt"}
```

6. **읽은 내용을 다른 파일에 저장** — 파이프의 문자열을 로컬 쓰기로 전달한다. 확인: 두 파일 본문이 같다.
```ibl
[self:read]{path:"notes/memo.txt"} >> [self:write]{path:"notes/copy.txt"}
```

7. **등록 프로그램 보기** — 내 기기의 프로그램 원장을 읽는다. 확인: 허브에 설치된 프로그램은 나오지 않는다.
```ibl
[self:script]{op:"list"}
```

8. **완성한 프로그램 등록** — 웹앱에서는 `greet.js`에 `return "안녕하세요, " + input.name;`을 저장한 뒤 JavaScript로 등록한다. 실행 코드는 네트워크·DOM·기기 파일에 직접 접근하지 못한다.
```ibl
[self:script]{op:"register",id:"greet",path:"greet.js",interpreter:"javascript"}
```

9. **등록 프로그램 실행** — `input`으로 JSON을 받고 `return`으로 결과를 돌려준다. 실행 전에 프로그램 본문을 확인하고 승인한다.
```ibl
[self:script]{op:"run",id:"greet",args:{name:"회원"}}
```

10. **기억 가지고 옮기기** — **기억 내보내기**의 JSON을 다른 브라우저에서 회원 키로 연결한 뒤 **백업 복원**으로 가져온다. 동일 백업의 기존 ID는 중복 삽입하지 않는다. 웹 JSON과 네이티브 ZIP은 다른 형식이며, 독립 설치본의 `scripts/import_member_archive.py`는 현재 네이티브 ZIP용이다.

완료 여부를 잃은 작업은 **최근 작업 결과 → 결과 불명**에 남는다. 같은 효과를 다시 내는 명령을 자동으로
보내지 않는다. 원래 파일/실행 결과를 확인한 회원이 새 실행 여부를 결정한다.
세션 간 이어지는 대화·장기 기억의 정본은 웹앱에서는 IndexedDB, 네이티브 연결 프로그램에서는 로컬 SQLite다. 허브는 처리 동안 회원 본문을 보고,
모델 제공자에도 입력을 보내므로 로컬 전용 추론이라는 뜻은 아니다.

## 문서·라디오·폰 사용 예

- PDF 부분 읽기: `[self:read]{path:"report.pdf",pages:"2-4"}`
- 텍스트 범위: `[self:read]{path:"memo.txt",start_line:2,end_line:5}`
- 양식 완성: `[self:fill]{path:"form.docx",data:{이름:"회원"},output:"done.docx"}` — 회원 기기의 저장 완료를 확인한 뒤 성공한다.
- 라디오 묶음이 활성 상태면 `[sense:radio]{op:"korean"}` → `[limbs:radio]{op:"play",station_id:"kbs_1radio"}`.
  회원 기기에서 재생을 승인한다. 브라우저의 지원 형식에 따라 재생이 거절될 수 있다.
  `[limbs:radio]{op:"status"}`로 확인하고 `op:"stop"`으로 멈춘다. 회원 화면을 켜 둔다.
- 브라우저 위치 권한을 허용하면 `[sense:here]{}`로 현재 기기 위치를 요청할 수 있다.
- Android 네이티브 앱에서 해당 묶음이 활성 상태면 폰의 **위치 허용** 버튼 → `[sense:here]{}`. 정밀도도 함께 확인한다.
  **접근성 설정**에서 회원 앱 서비스를 켠 뒤 `[limbs:android]{op:"snapshot"}` → 탭/입력을 요청한다.
  위치·화면 접근은 매 작업 승인 대상이며, 허브 PC의 위치·화면으로 대체하지 않는다.

## 내 앱 만들기

자율주행에 프로그램을 작성·검증·등록하고 `apps.json`에 화면도 추가해 달라고 요청한다. apps.json은 작업 폴더에 놓는 선언형 앱 배열이다. 기존 등록 프로그램이 `greet`이면 아래처럼 쓸 수 있다. 저장 후 **앱 새로고침**을 누른다. 화면 실행도 회원 IBL 관문을 통과한다. 웹앱 내부 저장·계산에는 추가 승인이 필요하지 않으며 네이티브 OS 작업은 기기 승인을 따른다.

```json
[{"id":"greet","name":"인사 프로그램","icon":"👋","inputs":[{"key":"name","placeholder":"이름"}],"action":"[self:script]{op:\"run\",id:\"greet\",args:{name:\"$name\"}}","view":[{"type":"kv","rows":[{"k":"결과","v":"{stdout}"}]}]}]
```

## 정기보고

앱 → 정기보고 → 작성에서 종류·관심 범위·자료 내용 또는 가져온 파일 경로를 넣는다. 회원 전용 에이전트의 응답 문서는 이 브라우저의 `reports/`에 저장되고 결과에서 바로 내려받는다. 내 보고서는 이 기기의 보고서만 읽는다. 현재 제공 자료 기반 작성이며 자동 웹 조사·주인 스케줄 실행은 제공하지 않는다. 자료가 없으면 필요한 자료와 양식을 안내한다.
