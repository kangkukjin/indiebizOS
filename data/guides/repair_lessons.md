# 수리 교훈 — 장소에 붙지 않는 것들

수리에서 얻은 교훈 중 **특정 파일에 붙지 않는 것**을 부류별로 모은다. 파일에 붙는 교훈은 여기가 아니라 포식 기억에 그 파일의 주소로 있다 — 고칠 파일을 `[self:forage]{op: "recall", locus: "<그 파일·폴더의 절대 경로>"}` 로 열면 나온다.
여기 적힌 것은 처방이 아니라 **이 몸에서 실제로 틀렸던 방식의 기록**이다. 새 교훈은 수리 판정 증류가 가이드 제안 큐에 올리고, 사람·세션이 추려서 옮긴다(자동으로 붙지 않는다).

## 1. 신고와 계측을 믿기 전에

- **증폭기 뒤에서 센 숫자는 부풀어 있다.** 차단기·재시도·큐 뒤에서 계측하면 신고 건수가 사건 수보다 반드시 많다. 다발 실패는 원인 층(바깥 서비스 → 도구 직접 호출 → 백엔드 경유) 순으로 정상 여부를 먼저 보고, 계측기 자체를 의심한다.
- **살아 있는 턴 안에서 돌린 배터리의 빨강은 관찰자 효과일 수 있다.** 기준선 실측과 대조하고, 수행자가 진짜 몸을 보지 않게 격리한 결과와 견준다.
- **봉투가 `success: true` 여도 필터·비교가 틀릴 수 있다.** 결과가 이상하면 라이브 대신 서너 행짜리 합성 시험대로 조건별 통과·탈락을 눈으로 대조한다.
- **열거한 건수와 실제 grep 건수를 대조한다.** "선언 없음 N건"·"재사용 N곳"은 언급 횟수이거나 추정일 수 있다(실측과 3배 차이 난 적이 있다).
- **증상을 라우터 탓으로 돌리는 오진이 잦았다.** 오배치·침묵 실패를 보면 판정 전에 그 액션의 설계 의도(주석)와 영향 범위부터 읽는다.
- **검수 통과는 실행 성공이 아니다.** dry-run 이 valid 여도 join 키 부재 같은 것은 실행 단계에서만 드러난다. 실행 기록도 대화 DB·런타임 로그와 대조한다 — 기록이 실제 사건과 다를 수 있다.

## 2. 부류를 닫을 때 — 스윕과 관문

- **사람이 고른 스윕 범위는 반드시 샌다**(패키지 트리 누락 등). 부류 종결은 수동 스윕이 아니라 관문이 주장한다.
- **자리별 발견을 입구로 삼으면 같은 속의 새 종이 계속 나온다.** 수리 전에 전수 조사(census)로 히트를 뽑고 관문을 먼저 세운다.
- **'선언 ≠ 방출'만 보는 스윕은 "일치하지만 분류가 틀린 자리"를 못 잡는다.** 통화 부재 신고를 받으면 스윕 통과를 근거로 끝내지 말고 페이로드를 실측한다.
- **면제를 커버로 세지 않는다.** 고정물 면제분은 "측정 사각"으로 따로 적는다 — 아니면 '미검증 0'이 오보가 된다.
- **'조건부'로 유보한 항목은 그 조건이 아직 살아 있는지 다시 본다.** 유보 근거가 소멸했는데 유보만 남은 적이 있다.
- **가드의 사각지대는 선언되지 않은 자리와 같다.** 새 타입·자리는 코딩 규칙이 아니라 구조(선언)로 드러내야 관문과 가드가 같이 본다.
- **잔여를 동결 목록에 넣지 않는다.** 자리마다 사유 표식을 강제하고, 표면 명단의 실존을 관문이 검증한다. 기계가 판정할 수 없는 잔여는 관문 머리말에 "수용된 잔여"로 명문화한다.
- **기계 판정이 되는 결함 부류는 커밋 전 관문으로 탄생을 막는다**(동시성: timeout 미선언·리로드 워커의 스레드·`check_same_thread`). 판정 불능인 나머지는 표식 + 사유.
- **은퇴 관문은 과거를 소급 등록하지 않는다.** 앞으로의 은퇴만 등록하게 해서 표면 목록을 사람이 아니라 관문이 기억하게 한다.
- **열린 밭은 회차 채굴로 닫히지 않는다.** 규모만 전수 조사로 기록하고, 선언(예: 날짜 표기)을 판정 요청으로 넘기는 것이 뿌리 대응이다.

## 3. 고칠 때

- **주석이 "동형"이라 주장하는 두 벌 절차는 한쪽만 고쳐져 있다.** 주석을 근거로 끝내지 말고 양쪽을 실제로 대조한다.
- **같은 기능의 두 구현(SDK 판·REST 판)은 공개 인자가 요청 빌더까지 배선되는지 대칭으로 확인한다.** 배선 누락은 예외 없이 침묵 폐기로 나타난다.
- **계약·관용구를 은퇴·교체할 때는 카탈로그만이 아니라 런타임 오류 문구·독스트링까지 쓴다.** 하나라도 남으면 모델과 사람이 은퇴한 계약을 계속 배운다.
- **결측·구조 값은 "무주장"으로 둔다.** 결측을 문자열로 승격하거나 구조를 repr 로 흘리면 아무것도 주장하지 말아야 할 대상이 값을 주장한다.
- **비유한 수는 저장 경계에서 끊는다** — 그러지 않으면 비표준 JSON 리터럴이 파일까지 샌다.
- **소비자가 0인 배관은 깔지 않는다.** 목적이 이미 다른 가드로 달성됐으면 보류하고, 재론 조건(두 번째 숙주의 등장)을 적어 둔다.
- **구문 검사만으로는 모듈 최상위 NameError·순환 import 를 못 잡는다.** 격리 검증은 고아 import → 컴파일 → import 스모크 → 어휘 삼각 검증 → 안전장치 스모크 순이다.
- **액션 수가 줄었다고 복잡도가 준 것은 아니다.** 어휘 표면 총량(액션 + op 값)으로 복잡도가 op 축으로 도피하지 않았는지 본다.

## 4. 보고와 전달

- **보고의 "변경 파일·적용 상태"를 기억·서술로 쓰지 않는다.** 등록 스크립트가 세션 원장 + 바이트 대조 + git 원장을 읽어 만든다 — 판단 없이 관측만.
- **적용 예약은 작업 완료가 아니다.** backend 적용을 막지 않도록 현재 실행 구간은 닫되, 사용자 수리는 영속 인계가 재기동 뒤 같은 에이전트에서 이어간다. 실제 적용·검증 결과와 남은 기준을 확인하고, 실패·롤백이면 기존 증거와 격리 변경을 재사용해 필요한 부분만 보완한다.
- **수행자 판정은 롤백 뒤에도 보존한다.** 검증 명령의 종료 코드·출력을 지우지 않으며 자동 재개에 전달한다. 평가의 증거 부족은 기존 원문부터 회수해 재검수하고, 같은 실패를 무한 반복하거나 미판정을 완료로 기록하지 않는다.
- **외부 AI 도구에 맡긴 작업은 세션 샌드박스 클론에 커밋이 고립된다.** 정본 경로 명시·시작 전 뒤처짐 확인·완료를 push 나 patch 보고로 규정한다.
- **배포형 수리는 배포 뒤 실측으로 닫는다**(캡처만 하고 넘어가지 않는다 — 판독까지).

## 수리 변경과 검증 결과를 이어받기

- 수리 그랜트 중 패키지 실행 소스·어휘 선언도 코드와 같은 격리 세션에 쌓인다.
  파일 도구가 `staged:true`를 반환하면 라이브 적용 전이다. 패키지만 바꿨어도
  원래 요청 전체의 사본 검증을 끝낸 뒤 `[self:patch]{op:"apply"}`의 준비 판정을 받는다. 예약된 경우에만 턴을 끝낸다. 수동으로 라이브에 복사하지 않는다.
- `verify_cmd`는 활성화 전 읽기 검사, `active_verify_cmd`는 활성화 후 읽기 전용 확인이다.
  운영 HTTP 읽기는 `INDIEBIZ_VERIFY_BASE_URL`의 허용 경로(`/health`, `/xray/app`)를 쓴다.
  운영 포트 직접 접속·쓰기 요청은 차단된다. `failure_kind=environment`이면 개발을
  재시작하지 않는다. 환경 복구 후 운영자의 `retry_environment`가 변경 없는 묶음의
  실패 검사만 한 번 재예약하며, 시간 초과·결과 불명은 자동 반복하지 않는다.
  기능 검사는 사본에서 끝내고, 커밋은 기존 각인 서비스가 검증한 수리 델타만 맡는다. 인계된 관문 결과와 `output_path` 원문을 먼저 읽는다. 변경되지 않은
  범위의 검사를 반복하지 않고 남은 기준을 검증한다. 검사 명령의 시간 초과는 실패한
  assertion과 다르며, 부분 출력과 실제 파일·커밋 상태를 확인해야 한다.

- **CLI의 읽기 전용 제한과 수리 권한은 다른 경계다.** 승인 수리의 파일 읽기·편집은
  IBL의 사본 도구로, 검색·빌드·테스트는 MCP `run_command`로 실행한다. 이 경로가 같은
  사본과 검증 증거를 소유한다. 네이티브 셸 검사 결과로 이를 대신하지 않는다.
  기억 조회 등 격리 미지원 도구가 거절되면 인계된 근거와 지원된 사본 도구를 사용한다.
  승인·전송 오류는 요청이 서버에 도착하지 않았을 수 있으므로 도구 실행 통계와 함께 확인한다.
