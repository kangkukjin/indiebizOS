# 연구 실행 — 자료에 따라 조사와 판단을 조정하기

의식의 계획은 문제를 이해하고 첫 조사를 고르는 출발점이다. 사용자 원래 질문·명시 조건을
기준으로 실행자가 자료의 적합성, 세부 방법, 조사 범위와 멈춤을 판단한다. 계획만 요청했으면
수집을 시작하지 않는다. 저장 자료만 모드에서는 외부 획득·파일 쓰기를 하지 않는다.

## 첫 자료로 접근을 구체화한다

첫 조사에서 출처·지표의 정의·대상·기간과 접근 가능성을 확인한다. 계획의 후보가 질문과
맞지 않으면 적합한 자료·방법으로 바꾼다. 처음 제시된 지표나 보고서 형식을 유지하려고 원래
질문을 축소하지 않는다. 사용자만 아는 결정적 사실은 왜 필요한지 짧게 묻고, 그 답과 무관한
조사는 계속한다. 답이 없으면 관련 가정을 사실로 채우지 않고 조건부 결론으로 남긴다.

다음 조사는 현재 결론을 바꿀 중요한 불확실성을 기준으로 고른다. 세부 조정·가설 기각에는
재승인이 필요 없다. 전체 목적·접근의 재설계가 필요하면 근거와 현재 계획 경로를 붙여
reframe으로 의식에 전달한다. 계획이 새로운 행위의 권한을 부여하지 않는다.

이 시스템 자신의 운영 기록(에피소드·궤적·대화)이 근거인 연구는 [자기 점검 가이드](self_inspection_guide.md)
2절의 데이터 소스에서 출발한다. 원장은 `sense:sqlite`(읽기 전용, `tables`·`schema`로 현재 열 확인)로,
에피소드 집계는 등록 스크립트 `에피소드통계`로 읽는다. 표 이름·열을 기억으로 짐작해 탐색을 반복하지 않는다.

## 결론을 지탱하는 근거를 확인한다

핵심 주장·수치가 실제 읽은 원문에서 따라 나오는지 해당 대목과 대조한다. 검색 발췌나
초록만으로 결론을 지탱하기 어려우면 필요한 본문·표·방법·한계까지 확인한다. 확보할 수
없으면 주장 범위·강도를 낮추거나 미확인으로 남긴다. 고정된 주장 수·출처 수를 채우거나
별도 평가 모델을 매번 호출하는 절차는 아니다.

출처의 직접성(1차/2차)과 실제 열람 범위(검색 요약/초록/본문 일부/전문)를 구분한다.
저장·다운로드·HTTP 성공은 실제 검토의 증거가 아니다. 관측·추정·전망과 자신의 해석을
구분한다. 수치는 대상·기간·정의·분모·비교 조건을 맞추며 근거보다 강한 순위나 인과를
단정하지 않는다. 충돌은 조건·방법의 차이를 따져 종합하고 해소되지 않으면 남긴다.

원문·발췌·실행 결과는 기존 자료실과 참조로 재사용한다. 이미 수집한 웹 원문을 더 읽을 때는
저장본을 등록 스크립트 `수집원문`으로 읽고, 같은 주소를 다시 받거나 원문을 따로 저장하지 않는다.
부분 실패에서도 성공한 근거를 보존한다. 주장 이해, 원문 열람, 수치·실험 설계, IBL 복구의 세부 쟁점은
[연구 근거 확인 참고](research_evidence.md)의 필요한 절만 읽는다.

## 필요한 조사를 마치고 현재 판단을 남긴다

원래 질문에 필요한 답을 얻었거나 추가 조사의 판단 가치보다 비용이 커지면 확인 범위와
한계를 밝히고 마친다. 계획의 후보 목록 완주나 예산 소진을 근거 충족으로 표시하지 않는다.
사용자가 요구한 조사 범위를 임의로 생략하지 않으며, 답을 좌우하는 공백·생략 이유·결론에
미치는 영향과 다시 확인할 조건을 결과에 남긴다.

중요한 발견·전제 반증·사용자 정정·중단·인계 때 계획의 현재 판단과 다음 행동을 갱신한다.
매 검색마다 기록을 복제하지 않는다. 사후에만 정리했다면 사후 기록임을 밝힌다.
기존 연구 질문 기록을 쓰는 연구는 해당 기록의 근거·판본을 갱신하고 계획에서 연결한다.
계획의 요약으로 원장을 덮어쓰지 않는다. 계약은 [연구 질문](research_questions.md)과
[연구 프로젝트](research_project.md)를 따른다.

보고서는 무엇을 알게 됐고 왜 원래 질문에 그렇게 답하는지 먼저 설명한다. 핵심 주장 가까이에
근거와 중요한 미확인을 연결한다. 절차 준수·표 완성은 품질 판정이 아니다. 정정한 주장은
현재 계획의 판단에도 반영하고, 남은 질문·결과·근거의 위치를 전달한다.
