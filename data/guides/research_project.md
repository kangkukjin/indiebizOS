# 연구 프로젝트

런처 → 새 프로젝트 → 유형 **연구 프로젝트** → 이름을 입력한다. 여러 연구 프로젝트를
만들 수 있으며 각 대화에 독립 자료실이 붙는다. 프로젝트 안에서 새 대화를 만들고,
다시 열어 같은 주제를 이어간다. 대화마다 질문·사용자의 관점 문서를 관리하고 AI는 현재 대화에 연결된 자료만 검색·참조한다.
연구 창은 일반 프로젝트의 `ChatView` 자체를 재사용하며 같은 베이지색 화면·주황색 주요 버튼을 사용한다.
프로젝트를 다시 열면 마지막으로 선택한 주제가 열린다. 제목 옆 **연구주제들**에서 다른 주제를
선택하면 대화가 창의 남은 공간을 채운다. 입력창은 Enter로 전송, Shift+Enter로 줄바꿈한다.
주제를 선택하면 제목·자료실 버튼·메시지 기록·입력창이 있는 대화가 열린다. 자료 보존과 검색은
에이전트가 자동으로 수행한다. 창을 닫았다 다시 열어도 같은 주제의 기록을 읽고 이어서
질문할 수 있다. 최신 메시지부터 표시하며 과거 기록을 읽을 때는 스크롤 위치를 유지한다.

## 사용

- 제목 옆 **연구주제들**에서 주제 목록을 열고, 그 창의 **+ 새 세션**으로 교육·경제 같은 주제를 만든다.
  이름 입력과 만들기도 같은 창에서 수행하며, 생성 후 해당 주제 대화가 열린다.
- **연구주제들** 목록에서 각 주제 옆 **이름 변경**을 누르면 바로 수정할 수 있다.
  **저장** 또는 Enter로 반영하고, **취소** 또는 Esc로 취소한다. 빈 이름은 저장할 수 없으며,
  저장한 이름은 목록과 열린 대화 제목에 함께 반영된다. 대화 기록과 자료실은 유지된다.
- 대화 헤더는 주제 제목과 **연구주제들·연구 질문·사용자의 관점·자료실**을 한 줄에 표시한다.
  연구 대화에는 IBL 사전 버튼을 표시하지 않는다.
- 일반 프로젝트와 동일한 입력창에서 **첨부 버튼, 파일 드래그, 이미지 붙여넣기, 카메라**를 사용한다.
  사진·텍스트·PDF·DOCX 등 첨부 원본은 해당 대화 자료실에 자동 보존되고 대화 기록에 남는다.
  이미지는 기존 인지 경로의 이미지 입력으로, 문서는 추출 본문으로 전달된다. OCR은 별도 지원하지 않는다.
- 대화에서 질문하면 기존 자료를 회수하고 필요한 추가 조사를 진행하며, 실제 획득한
  IBL 결과와 파일을 자동 보존한다. 창을 닫아도 백엔드가 살아 있으면 실행은 계속된다.
- 대화 상단 **자료실**은 선택한 대화 자료만 연다. 자료 목록·검색·추가·원문 읽기를 제공한다.
  긴 원문은 다음 부분 읽기로 이어간다. **대화로 돌아가기**로 기록과 입력창을 다시 연다.
- 자료실의 **도구 → 대화 설정**에서 제목·사용자의 관점·조사 방식을 바꾼다. 저장 자료만 모드는
  외부 획득을 차단한다. 보관한 대화도 같은 목록 하단에 ‘보관됨’ 표시로 남으며, 해당 대화의 설정에서 보관 해제한다.
- 메시지에 마우스를 올리면 일반 프로젝트와 같은 **이 메시지 복사** 버튼으로 해당 발화의 본문을 복사한다.
- 대화가 길면 **이전 대화 읽기**로 앞선 기록을 불러온다. 대화 기록과 첨부는 재시작 뒤에도 유지된다.

자료 확보 범위 full은 도구가 확보해 반환한 본문 기준이다. 검색 결과 snippet은
페이지 전체 원문과 다르며, unknown은 전체 확보를 확인하지 못했다는 뜻이다.
연구 대화도 현재 기어의 실행 에이전트가 담당한다. API·CLI 모델 모두 같은 실행 경로를 사용하며,
API 보조 모델 설정을 별도로 요구하지 않는다. 대화마다 기록과 실행 세션이 분리되고 재접속 후 이어진다.
CLI의 IBL 호출은 해당 대화의 자료실로 원문을 보존한다. 네이티브 도구는 실제 반환된 본문과
읽기 파일을 보존하며, 반환되지 않은 원문까지 확보했다고 간주하지 않는다.

별도 API 평가 모델은 연구 대화를 시작하기 위한 필수 설정이 아니다. 주 실행 모델은 사용할 수 있는
상태여야 하며, 달성 기준에 따른 공통 평가가 실행될 때는 평가에 사용할 수 있는 모델도 필요하다.
텍스트 평가는 CLI 모델도 지원한다. 실제 선택된 제공자가 API 방식이면 해당 인증·모델 설정이,
CLI 방식이면 설치·로그인 등 실행 준비가 필요하다. 이미지 평가는 이미지 지원 모델이 필요하다.
평가 제공자 부재나 응답 실패는 평가 미완료로 다루며 통과로 간주하지 않는다.
세부 호출 조건과 대체 경로는 [연구 설계 §20](../../docs/RESEARCH_PROJECT_DESIGN_2026_10_10.md#20-실행-기어-연결-수정-2026-10-10)을 따른다.

대화 하나는 고유 신원을 가진 독립 에이전트다. 에이전트 표시 이름과 주행기록 이름은 대화 제목을 사용한다. 제목을 바꿔도 기존 이력·기억 신원은 유지한다. 역할·실행 기어의 기본값은 프로젝트 agents.yaml의 첫 에이전트에서 상속한다.
그 에이전트의 역할에 연구 지침을 추가하고, 모델은 일반 프로젝트와 동일하게 중앙 핀을
우선 적용한 뒤 모델 기어의 실행 축을 상속한다. 매 질문을 시작할 때 설정을 다시 읽는다.

일반 에이전트의 회상·인지·감독·영속 증류 경로를 그대로 사용하므로 해마·심층·포식기억도
같은 정책에 따라 작동한다. 원문 자료실은 대화별이며, 포식기억 같은 기존 공통 기억은 일반
프로젝트와 동일한 범위·정책을 따른다. 새 대화나 대화 전환만으로 모델을 호출하지 않는다.
선택한 대화에 보낸 요청만 실행하고 다른 에이전트에게 위임하지 않는다. 이미 맡긴 작업은
대화 전환으로 취소하지 않으며 해당 대화의 중단 버튼으로 멈춘다.

도구 실행 내역·판단 표시를 기록하여 다시 열었을 때도 공통 채팅 패널로 보여준다.
작업 중 텍스트를 보내면 일반 프로젝트의 조향 인박스로 전달한다(다음 도구 결과에서 반영).
작업 중 새 파일은 응답 완료 뒤 첨부한다. 조향은 수신을 보장하지 않으며 원래 입력 기록은 남는다.

## 사용자의 관점

대화 상단 **사용자의 관점**에서 장기 문서를 읽고 직접 수정하거나 Markdown으로 내려받는다.
기존 연구 방향 메모(`notes`)를 확장한 것이므로 이전 메모도 그대로 보존한다. 문서는 대화별로
독립적이며 매 실행에 전달된다. 현재 기어의 실행 에이전트가 새 주장·판단 기준·정정이 있을 때
기존 `thread_update`로 전체 문서를 갱신한다. 별도 API 요약 모델은 필요하지 않다.

핵심 주장·판단 기준·입장 변화·열린 질문을 정리하고 `[발언:메시지ID]`로 사용자 원문을 연결한다.
AI나 외부 자료의 주장을 사용자 입장으로 바꾸지 않는다. 질문·가정과 확정 입장을 구별하며,
관점을 이해하는 것과 사실 검증·동의를 구별한다. 사용자가 직접 고친 내용도 다음 실행에 반영한다.
수정 이력은 DB에 보존하며 화면에서 최근 20개를 볼 수 있다. 동시 수정은 revision으로 감지한다.
충돌 시 초안을 보존한 채 최신 문서를 다시 읽고 합친다. 문서는 12000자 이내다.

원문 전체를 매번 보내지는 않는다. 최근 사용자 발언 최대 20개·16000자를 문서와 함께 전달하고,
더 오래된 발언은 대화 기록으로 읽는다. 새 발언이 없는 단순 요청에서는 문서를 다시 쓰지 않는다.
저장 자료만 모드에서도 관점 문서 갱신은 가능하지만 외부 획득과 조사 모드 변경은 허용하지 않는다.
자동 정리는 실행 에이전트의 도구 사용으로 이뤄지므로 중단·실패하거나 저장을 수행하지 않은 턴에서는
직전 문서가 유지된다. 이 경우 대화에서 관점 정리를 요청하거나 직접 수정할 수 있다.

## IBL

```ibl
[self:project]{op:"create",name:"교육 연구",project_kind:"research"}
[self:project]{op:"thread_create",project_ref:"생성된 project_uid",title:"학급 규모"}
[self:project]{op:"thread_send",project_ref:"project_uid",thread_ref:"thread_ref",message:"학급 규모와 학습 효과를 조사해줘",request_id:"클라이언트의 고유 요청 ID"}
[self:notebook]{op:"search",project_ref:"project_uid",thread_ref:"thread_ref",query:"학급 규모"}
[self:notebook]{op:"read",project_ref:"project_uid",thread_ref:"thread_ref",version_ref:"version_ref"}
[self:notebook]{op:"read",project_ref:"project_uid",thread_ref:"thread_ref",version_ref:"version_ref",max_chars:3500}
[self:notebook]{op:"add",project_ref:"project_uid",thread_ref:"thread_ref",version_ref:"version_ref"}
```

thread_send의 task_ref는 기존 self:task로 조회·취소한다. 같은 request_id와 같은 내용의
재전송은 새 턴을 만들지 않는다. project_ref가 있는 notebook은 전역 name과 함께 쓸 수 없고 thread_ref가 필요하다. 연구 실행 중에는 생략하면 현재 대화를 사용한다. thread_send는 attachments:[{path,name}]도 받는다.

read의 `max_chars`는 반환 본문의 문자 수(인용 표식 포함)로 1~12,000의 정수이며 기본은 12,000이다.
여러 자료를 table:ai 등에 묶어 전달할 때 자료별 분량을 줄이고 필요한 부분을 이어 읽을 수 있다.
`total_chars`는 전체 길이, `next_cursor`는 다음 문자 위치다. 다음 요청에는 같은 `version_ref`와
반환된 `extraction_revision`, `next_cursor`를 `cursor`로 전달한다. `pages`에도 판본과 분량이 보존된다.
작은 페이지는 전체 문서 검토가 아니며, 인용 근거에는 실제 반환된 본문 부분만 기록된다.

## 저장과 복구

프로젝트의 conversations.db가 대화·자료 원장이고 research/objects가 확보한 원문이다.
research/index.db는 파생 검색 색인이다. 백업은 프로젝트 전체를 보존하되 라이브 SQLite는
온라인 backup/VACUUM INTO로 복사한다. 앱의 프로젝트 복제는 이를 적용하고 새 uid를 부여한다.
이름을 바꿔도 uid·원문 판본·인용은 유지된다.

원문 보존 실패는 조사를 실패 처리하고 추가 도구 획득을 차단한다. 디스크 공간·권한을
복구한 뒤 새 메시지로 이어간다. 추출·색인 실패는 자료를 삭제하지 않으므로 원문을 유지한
채 재시도한다. 삭제된 색인 DB는 다음 자료실 접근에서 재생성한다. 백엔드 재시작 때 남은
실행은 중단 상태로 보존하며 새 질문으로 계속할 수 있다. 진행 중인 대화는 먼저 중단한 뒤
프로젝트 이름 변경·복제·휴지통·삭제를 한다.

구현/범위 정본: `docs/RESEARCH_PROJECT_DESIGN_2026_10_10.md` §17.

기존 자동 수집 자료는 원래 대화 연결을 유지한다. 대화 연결 없이 추가했던 공용 자료는 **이전 공용 자료**라는 별도 대화에 보존하며 다른 대화에 자동 혼합하지 않는다. 같은 원문 바이트를 중복 저장하지 않아도 검색·조회·검색 제외 설정은 대화마다 구분된다.

웹 수집 원본 JSON은 그대로 보존하되, 검색에는 수집기가 추출한 기사 본문을 사용한다.
옛 원본도 새 추출 판본과 색인으로 갱신하며 이전 추출 판본·인용은 남긴다.
에이전트가 자료실에 직접 추가한 자료도 해당 대화 실행에 연결해 기록한다.

## 지속 연구 질문

대화 헤더의 **연구 질문**에서 질문·잠정 답변·지지 및 반박·남은 확인·다음 조사를
보존하고 판본별로 비교한다. 같은 대화의 다음 턴에 요약 목록이 전달된다.
종결은 판단 기록이며 진위 인증이 아니다. 사용·원문 인용 계약은
[연구 질문 가이드](research_questions.md)를 따른다.


## AI의 자료 재사용

이미 `version_ref`를 알면 `[self:notebook]{op:"read",version_ref:...,project_ref:...,thread_ref:...}`로
직접 읽는다. 판본 목록 `versions`는 자료를 고른 `source_ref`가 필수다. 자료 목록 전체를 다시
읽는 대신 필요한 검색 결과·참조를 이어 쓴다. `thread_update`의 `questions` 변경은
`notes/title/mode` 변경과 별도 호출한다. 두 종류를 한 호출로 합치면 실행 전 검사에서 거절된다.
