# 결과물 검증 — 원문, 최종 행, 산출물의 연결

수집 후보와 게재 항목은 다르다. 출처를 읽고 판단이 바뀌면 최종 행을 먼저 갱신한다.
동일 사건은 같은 식별자를 사용하고, 출처 URL·발행 기관·날짜·확인 상태·핵심 설명을
같이 보관한다. 본문 분류·계수·요약은 이 최종 행에서 파생한다. 새 숫자를 산문에서
손으로 합산하지 않는다. 날짜 미확인이나 확인하지 못한 조건은 요약에서도 남긴다.

산문을 쉽게 고쳐도 주체·행동·측정량·단위·기간·분모·인과·한계를 바꾸지 않는다.
핵심 주장마다 원천의 정확한 발췌를 확보한다. 매체명은 URL이나 제목의 추정이 아니라
실제 발행 정보를 따른다. 동일 자료를 다시 크롤하거나 모델에게 여러 번 요약시키기 전에
저장된 원문·턴 변수·read_result를 사용한다. 독립된 읽기와 AI 처리는 each auto로 병렬화한다.

최종평가는 도구 없는 별도 평가자가 수행한다. 하네스가 사용자 목표·전체 응답·실제 호출
원장·결과 발췌·생성 파일 내용·시각 산출물을 수집해 제공한다. 평가자는 그 자료로 요구
누락·증거 모순·미수행의 수행 보고·명백한 산술 오류를 판정한다. 입력의 발췌·생략을
미실행으로 단정하지 않으며 핵심 근거가 부족하면 UNKNOWN으로 남긴다.

실행자는 원천 발췌와 최종 행의 집계 근거를 작업 중 확보한다. 평가자가 새 검색이나
계수 재실행을 시작하지 않는다. 발견한 결함은 한 번에 모아 실행자에게 보완시키며,
보완은 최대 한 번이다. 기존 파일·응답의 국소 수정과 새 조사를 구분하고 필요한 부분만
수정한다. 재평가는 갱신된 실행 증거와 응답으로 이전 결함 및 의존 주장을 대조한다.
사소한 표현·오타·추가 개선 가능성만으로 재작업을 요구하지 않는다.

하네스는 평가 전후 응답·파일·공개 대기열의 지문을 확인한다. 모델에게 페이지 열람이나
content_checks 영수증을 재수집시키지 않는다. 승인된 초안만 공개하고 미승인 결과는
성공 경험으로 저장하지 않는다. 과제 완료 요청은 전체 과제 기준도 평가 입력에 포함한다.

실행 이력과 규칙은 구분한다. 같은 규칙의 재발은 새 규칙을 누적할 이유가 아니다.
새 규칙을 추가하기 전에 기존 규칙의 집행 경계를 고친다. 원장 상한은 내용을 버리라는
뜻이 아니며, 중복 문단을 합치고 실행 사례는 해당 실행 기록에 둔다. 태그는 저장소가
정한 길이 안의 명사구를 사용한다. 문자열을 잘라 수치·단위·고유명사를 손상시키지 않는다.

고용 수준과 신규 채용, 관측 변화와 인과 효과를 구분한다. 고용이 증가했더라도 AI가
없었을 경우와의 비교 없이 부정적 효과가 없다고 결론내릴 수 없다. 인구 × 고용률의
고정 시나리오 계산은 산술적 분해이며, 감소 원인의 인과 기여율이 아니다. 사용자 요청의
측정량을 대체하거나 한계를 적는 것만으로 원래 목표를 충족 처리하지 않는다.

평가자의 보완 지시와 기존 호출 입력·원문 evidence ID는 repair 인계에 함께 제공된다.
수정 대상으로 지정한 응답 블록은 target_blocks에 본문·id·hash와 version을 함께 전달한다.
실행자는 인계된 본문을 우선 사용하고 누락·변경된 블록만 읽는다. 독립적인 여러 블록은
patches 한 배열, 같은 블록의 겹치지 않는 수정은 replacements로 묶어 한 호출에 제출한다.
출처를 재탐색하기 전에 기존 근거를 재사용한다. 평가자는 직접 도구를 호출하거나
응답을 편집하지 않으며, 중간관리 의식은 진단에 필요한 도구를 계속 사용할 수 있다.
