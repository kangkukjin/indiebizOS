# 결과물 검증 — 원문, 최종 행, 산출물의 연결

수집 후보와 게재 항목은 다르다. 출처를 읽고 판단이 바뀌면 최종 행을 먼저 갱신한다.
동일 사건은 같은 식별자를 사용하고, 출처 URL·발행 기관·날짜·확인 상태·핵심 설명을
같이 보관한다. 본문 분류·계수·요약은 이 최종 행에서 파생한다. 새 숫자를 산문에서
손으로 합산하지 않는다. 날짜 미확인이나 확인하지 못한 조건은 요약에서도 남긴다.

산문을 쉽게 고쳐도 주체·행동·측정량·단위·기간·분모·인과·한계를 바꾸지 않는다.
핵심 주장마다 원천의 정확한 발췌를 확보한다. 매체명은 URL이나 제목의 추정이 아니라
실제 발행 정보를 따른다. 동일 자료를 다시 크롤하거나 모델에게 여러 번 요약시키기 전에
저장된 원문·턴 변수·read_result를 사용한다. 독립된 읽기와 AI 처리는 each auto로 병렬화한다.

최종 감독의 state.content_artifacts에 본문 지문과 evidence_id가 제공된다.
감독은 첫 검수에서 본문을 끝까지 읽고 content_checks에 세 범위를 구분해 남긴다.
보완 시에는 content_changes의 변경 구간과 그에 의존하는 주장부터 재검수한다.

- meaning: 본문·제목·요약·결론의 의미와 원천 일치.
- sources: 실제 원천의 귀속·날짜·핵심 사실. 자체 보고서 재인용은 원천 검증이 아니다.
- counts: 최종 행의 필터·유일성·계수를 다시 계산한 결과.

각 범위는 status, reason, evidence[{id,quote}]를 가진다. passed는 실제 읽은
증거의 발췌가 있어야 한다. 내용 자체가 없을 때만 not_applicable을 쓴다.
counts가 passed이면 calculations[{id,items_path,where,identity,expected}]를 남긴다.
id는 최종 행 JSON의 증거, where는 필드 동등 조건, identity는 사건 식별 필드 목록이다.
하네스가 필드 존재·필터·중복 제거·계수를 다시 계산한다. 원문에 없는 필드는 추정하지 않는다.
예: where={label:"NEW",verified:true}, identity=["event_id"]. 이름은 데이터가 소유한다.

파일 hash·읽은 범위·발췌·계수는 코드가 검증한다. 의미 대조와 사건 식별은 감독의
판단이므로 근거 부족을 passed로 표시하지 않는다. 발견한 오류는 한 번에 모아 수정하고,
바뀐 주장과 그에 의존하는 요약·계수를 재검수한다. 파일 바이트가 바뀌면 옛 승인은 무효다.

실행 이력과 규칙은 구분한다. 같은 규칙의 재발은 새 규칙을 누적할 이유가 아니다.
새 규칙을 추가하기 전에 기존 규칙의 집행 경계를 고친다. 원장 상한은 내용을 버리라는
뜻이 아니며, 중복 문단을 합치고 실행 사례는 해당 실행 기록에 둔다. 태그는 저장소가
정한 길이 안의 명사구를 사용한다. 문자열을 잘라 수치·단위·고유명사를 손상시키지 않는다.

고용 수준과 신규 채용, 관측 변화와 인과 효과를 구분한다. 고용이 증가했더라도 AI가
없었을 경우와의 비교 없이 부정적 효과가 없다고 결론내릴 수 없다. 인구 × 고용률의
고정 시나리오 계산은 산술적 분해이며, 감소 원인의 인과 기여율이 아니다. 사용자 요청의
측정량을 대체하거나 한계를 적는 것만으로 원래 목표를 충족 처리하지 않는다.

검수자는 확보된 증거를 대조하고 결함·파일 경로·완료 증거를 한 REWORK에 묶어 실행자에게
넘긴다. repair 인계의 tool_index에는 기존 호출 입력과 원문 evidence ID가 있다.
출처를 재탐색하기 전에 이 손잡이를 사용한다. 짧은 execute 결과도 evidence.id와 보인 page가
연결된다. 읽기 기록만 빠진 실제 발췌는 한 번의 제한된 출처 재확인으로 처리할 수 있지만,
발췌의 존재만으로 자동 승인하지 않는다. 원문에 없는 인용·미검수 범위는 계속 거절한다.
