# 내 목소리 나레이션 가이드 (Qwen3-TTS 목소리 복제)

사용자 본인의 목소리로 나레이션을 굽는다. 주 용도는 **강의 동영상 나레이션**.
절차는 등록 스크립트 `나레이션생성`에 박혀 있다 — 이 가이드는 *절차*가 아니라 **판단**을 담는다.
굽는 곳은 Modal GPU 다(2026-11-12 콜랩에서 옮겼다 — 같은 원고가 423초에서 137초로).

## 0. 언제 내 목소리인가 (판단 기준)

| 상황 | 목소리 |
|------|--------|
| 매일 오디오 브리핑 (04·06시 자동) | **Gemini/Charon 유지** — 내 목소리로 바꾸는 것은 사용자 판정 사항이다. 준비는 30초 안팎으로 줄었지만(§4) 브리핑 분량으로는 아직 재지 않았다 |
| 강의 동영상 최종 렌더 | **내 목소리** |
| 강의 동영상 시험 렌더 | `engine: "edge"` (무과금·즉시) — 구도만 보는 단계에 GPU 왕복은 낭비 |
| 짧은 안내·알림 음성 | Gemini/edge — 몇 초짜리에도 준비 1분이 붙는다(§4) |

원칙: **이따금·의도적으로 만드는 것에만 쓴다.** 자동으로 매일 도는 것에는 쓰지 않는다.

## 1. 쓰는 법

```
[self:script]{op: "run", id: "나레이션생성", args: {lecture_id: "<강의 id>"}}
```

덱의 장별 스피커 노트를 읽어 `outputs/lectures/<id>/narration/<slide_id>.wav` 로 굽는다.
그다음 평소대로 렌더하면 된다:

```
[self:deck]{op: "video", lecture_id: "<강의 id>"}
```

임시 문장(강의와 무관한 한두 줄):

```
[self:script]{op: "run", id: "나레이션생성", args: {texts: {"인사": "안녕하세요, ..."}, out_dir: "..."}}
```

옵션: `voice`(키·이름·별칭 — 기본은 원장 `voices.json` 에서 `default: true` 인 항목) · `gpu`(기본 `T4`) · `containers`(동시에 띄울 컨테이너 수 — 기본은 분량에 맞춰 자동, §4) · `force`(이미 있는 wav 도 다시 굽기) · `speed`(기본 **1.0** — §1-1 참조).

## 1-1. 표준 낭독 속도 = 1.0x (보정 없음)

**모든 나레이션은 구워진 그대로, 본래 목소리 속도로 나온다.** 후처리 감속은 걸지 않는다
(`나레이션생성.py` 의 `DEFAULT_SPEED = 1.0` — `retime()` 이 1.0 이면 그대로 통과한다).

- **왜 이 값인가**: 2026-09-01 사용자 판정 — 0.9x 보정을 없애고 본래 속도로. 이 판정이
  2026-08-17 의 옛 판정("원속도가 빠르다 → 10% 느리게가 표준")을 대체한다.
  옛 표준으로 구운 나레이션은 그 시점의 산물이니 새로 구운 것과 길이가 다르다.
- **느리게 하고 싶을 때만** `speed` 를 넘긴다 — `{speed: 0.9}`(10% 느리게) · `{speed: 0.85}`.
  타임스트레치 기구(ffmpeg `atempo`, 피치 보존)는 그대로 남아 있고 기본값만 무보정이다.
  표준 자체를 바꾸려면 `DEFAULT_SPEED` 한 줄만 고친다.
- **왜 모델이 아니라 후처리인가**(speed 를 넘길 때): Qwen3-TTS 에 속도 파라미터가 없고,
  프롬프트로 "천천히 읽어"는 재현되지 않는다. 후처리는 결정론이고 재굽기가 필요 없다.
  실측(원본 vs 0.9x): 스펙트럼 무게중심 비 **0.979~0.985** — 피치가 보존된다.
- **이미 구워둔 wav 는 건드리지 않는다** — 이 변경은 앞으로 굽는 것에만 적용된다.
  옛 0.9x wav 를 원속도로 되돌리려면 다시 굽거나(`force: true`) 되늘리면 된다:
  ```bash
  ffmpeg -y -i slow.wav -filter:a atempo=1.111111 -ar 24000 -ac 1 -c:a pcm_s16le orig.wav
  ```
  *오디오만 바꿔 기존 영상에 얹지 말 것*(싱크가 깨진다 — 씬 길이는 렌더가 다시 맞춘다).
- **재사용 멘트**: 인트로·아웃트로는 `outputs/narration/bookends3/` 가 표준이다 —
  **복제가 아니라 사용자가 직접 낭독한 실제 음성**(2026-09-01). 고정 자산이라 복제본보다
  실음성이 낫다는 판단. 이 판은 손대지 않은 그대로 쓴다 — 사람이 직접 읽은 것은 이미 제 속도다
  (실측: 구 복제판 인트로 2.73초 vs 실음성 3.03초 — 본문과 호흡이 맞는다).
  §1-1 에서 본문 감속 보정도 없앴으니(2026-09-01) 이제 인사말과 본문 모두 무보정이다.
  본문 나레이션과 음량이 갈리지 않도록 -27.8 LUFS 로 맞춰 두었다(정적 게인, 다이내믹 무손상).
  (`bookends2_slow/` 는 구 표준 복제판, `bookends2/` 는 그 원속도 판 — 둘 다 보존하되
  새 영상에 쓰지 말 것.)

## 2. 규약 — `narration/<slide_id>.wav` 가 TTS 를 이긴다

`[self:deck]{op:"video"}` 는 렌더할 때 그 장의 `narration/<slide_id>.wav` 를 **먼저 본다.**
있으면 그 파일을 쓰고 TTS 를 호출하지 않는다. 없으면 종전대로 스피커 노트를 TTS 로 굽는다.

**왜 파라미터가 아니라 파일 존재로 푸는가**: 슬라이드 `base.png`(글자 얹기) 선례와 같다 —
파일이 있으면 그게 이긴다. 파라미터를 늘리지 않으므로 자율주행·조종실·앱 어느 표면에서
불러도 똑같이 작동하고, 장별로 섞어 쓸 수 있다(어떤 장은 내 목소리, 어떤 장은 TTS).

결과의 `preset_narration` 이 미리 구운 오디오를 쓴 장 수다.

## 3. 목소리 원장 — `data/voice/voices.json`

목소리는 코드가 아니라 **데이터**다. 교체·추가는 이 원장만 고친다.

**★확정 (2026-09-01, A/B 청취) — 표준 레퍼런스는 원장에서 `default: true` 인 항목이다. 다시 A/B 하지 말 것.**
사용자가 구 표준과 나란히 듣고 현 표준을 골랐다. 결정적 차이는 출처다 —
구판들은 강의 녹음에서 잘라낸 것이고, 현 표준은 **조용한 환경에서 레퍼런스
전용으로 낭독한 녹음**(90.3초 원본에서 8.96초 구간)이다. 낭독 원고는
`outputs/narration/voice_ref_script.md` — 음소 균형·전사 안전(숫자·영어·고유명사 배제)·
설명조 말투를 노리고 쓴 것이라, 레퍼런스를 다시 만들 때도 이 원고를 쓰면 된다.

구판은 **지우지 않는다** — 되돌릴 여지로 원장에 남기고, 목소리 키를 명시할 때만 쓰인다.
기본값은 코드가 아니라 원장의 `default: true` 표시 한 곳이고(스크립트는 그 표시를 읽을 뿐), 그 밖에
목소리를 고르는 경로는 없다(덱 영상 렌더는 §2 규약대로 이미 구워진 wav 를 그냥 쓰므로
애초에 목소리를 모른다). **이미 구운 나레이션은 목소리를 바꿔도 다시 굽지 않는다.**

★목소리를 갈 때는 인사말도 함께 봐야 한다 — 본문만 새 목소리로 바꾸면 인사말과 본문의
음색이 갈린다. 2026-09-01 교체 때 실제로 걸렸던 문제이고, 인사말을 **사용자가 직접 낭독**해
(§1-1 `bookends3/`) 해소했다. 인사말은 매 영상에 그대로 들어가는 고정 자산이라
복제를 거치지 않는 쪽이 품질에서 앞선다 — 다음에 목소리를 갈더라도 이 판은 그대로 쓴다.

```json
{"voice1": {"name": "<부르는 이름>", "aliases": ["<별칭>"], "audio": "voice1.wav",
            "text": "<그 오디오의 정확한 전사>", "default": true}}
```

**레퍼런스 조건** (지키면 품질이 확 달라진다):
- 잡음 없는 **단독 발화 5~10초** (배경음악·다른 화자 없음)
- **모노 24kHz wav** — `ffmpeg -ss <시작> -t <길이> -i 원본 -ac 1 -ar 24000 -c:a pcm_s16le ref.wav`
- **`text` 는 그 오디오의 정확한 전사** — 어긋나면 복제 품질이 눈에 띄게 떨어진다.
  Whisper 로 자동 전사해도 되지만 **고유명사는 반드시 귀로 대조**할 것
  (실측: 같은 녹음에서 "하이젠베르크"가 한 구간에서만 "하이젠벨크"로 잘못 잡혔다).

**깨끗한 구간 찾는 법** — 긴 녹음에서 후보를 기계로 고른다:

```bash
ffmpeg -i 원본.mp3 -af "silencedetect=noise=-35dB:d=0.6" -f null - 2>&1 | grep silence_
```

무음과 무음 사이가 긴 곳이 연속 발화 구간이다. 여러 개 잘라 들어보고 고른다
(구 표준도, 현 표준도 이렇게 뽑은 후보 셋 중 사용자가 직접 고른 것이다).

## 4. 비용·시간 (Modal T4 실측, 2026-11-12)

- **준비는 30초 안팎** — 컨테이너 기동·패키지 불러오기·모델 적재. 여기에 컨테이너마다 첫 호출에서
  목소리 프롬프트를 만드는 20초가 붙는다. 모델 가중치는 볼륨에 남아 있어 다시 받지 않는다.
  이미지를 새로 지은 직후의 첫 실행만 1~2분 더 걸린다(새 이미지를 GPU 노드가 처음 당겨 온다).
- **글자 수가 시간이다** — 생성은 약 0.1초/자(batch 4, 컨테이너 하나). 같은 원고(11장 44조각 2,023자) 실측:
  컨테이너 하나 238초 · 자동(셋) 137초 · 여섯 129초. 옛 콜랩 경로는 423초였다.
  실측 배율은 결과의 `sec_per_char` 에 찍힌다(생성에 쓴 GPU 초 / 글자 — 컨테이너 수와 무관) —
  스크립트의 `SEC_PER_CHAR` 와 어긋나면 그 상수를 고친다(예산은 이 상수의 캡).
- **컨테이너를 늘려도 그만큼 빨라지지 않는다** — 컨테이너마다 준비를 따로 내고, 전체 시간은 가장 느린 것이
  정한다. 그래서 기본값은 컨테이너 하나가 생성 60초어치를 맡도록 분량에 맞춰 정해진다(최대 6).
  `containers` 로 직접 줄 수 있지만, 위 원고에서 셋과 여섯의 차이는 8초였고 GPU 시간은 약 두 배다.
- **짧은 문장도 1분** — 두 문장 실측 56~64초(준비 + 프롬프트 + 생성). 콜랩은 152초였다.
- **GPU 를 바꾸면** — `gpu: "A10G"` 는 같은 두 문장이 53초였고 생성 구간만 보면 T4 의 약 1.7배다(진짜 bf16).
  `L4` 는 2026-11-12 에 두 번 시도해 10분·3분 동안 컨테이너가 배정되지 않았다(원인 미확인 — 수급 또는 계정 한도).
  배정되지 않으면 스크립트가 무소식 기준으로 끊고 반납을 확인한다.
- **진행은 보인다**: `background: true` 로 걸면 `status` 의 `progress` 에 `[   98s] [gen] 24/44 · 컨테이너 2 …` 꼴 줄이
  실시간으로 실린다. 'running' 만 돌아오는 상태로 반복 대기하지 말 것 — progress 가 안 움직이면
  스크립트가 스스로 끊는다(무소식 300초, 준비 구간은 600초).
- **조각은 구워지는 대로 로컬로 온다** — 회수 단계가 따로 없다. 도중에 끊겨도 조각이 다 온 장은 저장되고
  못 받은 장은 결과의 `failed` 에 남는다. 다시 부르면 이미 있는 장은 건너뛴다.
- (speed 를 넘겨 재타이밍할 때도 로컬 ffmpeg 라 초 단위 — 비용 0.)
- **과금은 GPU 초 단위**다. 앱은 실행마다 새로 뜨고 끝나면 사라진다(배포해 두지 않는다).
  스크립트가 `finally` 에서 그 앱이 정말 멈췄는지 확인하고, 살아 있으면 멈춘다.
- **이미 있는 wav 는 건너뛴다** → 노트를 고친 장만 다시 굽는 재실행이 싸다. 전부 다시 구우려면 `force: true`.
- 도구 60초 제한을 넘으므로 에이전트 경로에서는 타임아웃이 날 수 있다(원장 timeout 은 2400초).
  타임아웃이 나도 **스크립트는 계속 돌아 파일은 남는다** — `narration/` 을 확인할 것.

## 5. 함정 (전부 실측 — 스크립트에 박혀 있지만 원인을 알아둘 것)

1. **Modal 준비물 둘** — `modal` CLI(`uv tool install modal`, 인증은 `modal token new`)와 계정의 **결제 수단**.
   결제 수단이 없으면 GPU 함수를 만드는 단계에서 `Please add a payment method` 로 거절된다(2026-11-12 실측).
   등록은 사람이 Modal 화면에서 한다.
2. **이미지 정의를 바꾸면 다시 지어진다** — 스크립트 안 `MODAL_APP` 의 `image` 가 그 정의다. 패키지 판은
   고정해 두었다(`qwen-tts==…`). 판을 올릴 때만 그 줄을 고치고, 고친 뒤 첫 실행은 빌드와 첫 당김으로 몇 분 걸린다.
   콜랩 때처럼 실행마다 다시 설치하지 않으므로 재설치로 의존성이 깨지는 일은 없다.
3. **T4 의 거짓 bf16 보고** — `torch.cuda.is_bf16_supported()` 가 T4(sm_75)에서 True 를 반환하지만
   네이티브 bf16 이 없다(에뮬레이션). **에러 없이 느려지기만** 해서 가장 알아채기 어렵다.
   `torch.cuda.get_device_capability()` 로 아키텍처를 직접 볼 것 — sm_80(Ampere) 이상만 진짜 bf16.
4. **프라이버시** — 목소리는 생체정보다. 스크립트는 레퍼런스(10초 이내)만 함수 인자로 넘기고,
   볼륨·이미지에는 저장하지 않는다(볼륨에는 공개 모델 가중치만 있다). **원본 녹음 전체를 올리지 말 것.**
5. **자원 반납은 확인까지** — 2026-09-10 콜랩 실사고의 교훈이다(정지 실패로 VM 이 켜진 채 과금됐다).
   Modal 앱은 로컬 프로세스가 끝나면 멈추지만, 스크립트는 `finally` 에서 그 실행의 앱 id 로 상태를 다시 본다.
   progress 의 마지막 줄이 `자원 반납 완료` 가 아니라 `확인 실패` 면 `modal app list` 로 직접 볼 것.
   (콜랩 세션 토큰 1시간 만료 함정은 `colab.md` §4 로 옮겼다.)

## 6. 왜 전용 IBL 어휘가 아닌가

`colab.md` §6 의 반-어휘-증식 규약을 따른다 — "새 특수 어휘 만들까?"의 기본 답은 "스크립트 등록".
4기준으로도 외부 인터페이스 하나만 강하고 조합성·빈도·실시간성이 약해 액션 문턱을 못 넘는다.

**승격 경로**(빈도가 신호를 줄 때): `[engines:tts]{engine: "qwen3"}` — 새 단어가 아니라
이미 있는 `engine` 축에 값 하나 추가라 어휘 비용이 사실상 0이다
(`sense:realty` 의 `source: molit/zigbang/naver` 와 같은 모양).
다만 짧은 문장도 1분이 걸리므로(§4) 승격하려면 백그라운드+상태파일 패턴이 필요하다.
