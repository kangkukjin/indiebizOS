# 내 목소리 나레이션 가이드 (Qwen3-TTS 목소리 복제)

사용자 본인의 목소리로 나레이션을 굽는다. 주 용도는 **강의 동영상 나레이션**.
절차는 등록 스크립트 `나레이션생성`에 박혀 있다 — 이 가이드는 *절차*가 아니라 **판단**을 담는다.

## 0. 언제 내 목소리인가 (판단 기준)

| 상황 | 목소리 |
|------|--------|
| 매일 오디오 브리핑 (04·06시 자동) | **Gemini/Charon 유지** — 콜랩 세션 기동이 수 분이라 자동 스케줄에 안 맞는다 |
| 강의 동영상 최종 렌더 | **내 목소리** |
| 강의 동영상 시험 렌더 | `engine: "edge"` (무과금·즉시) — 구도만 보는 단계에 GPU 왕복은 낭비 |
| 짧은 안내·알림 음성 | Gemini/edge — 몇 초짜리에 세션 여는 건 손해 |

원칙: **이따금·의도적으로 만드는 것에만 쓴다.** 자동으로 매일 도는 것에는 쓰지 않는다.

## 1. 쓰는 법

```
[self:script]{op: "run", id: "나레이션생성", args: {lecture_id: "<강의 id>"}}
```

덱의 장별 스피커 노트를 읽어 `outputs/lectures/<id>/narration/<slide_id>.wav` 로 굽는다.
그다음 평소대로 렌더하면 된다:

```
[self:deck]{op: "video", lecture_id: "<강의 id>"}
```

임시 문장(강의와 무관한 한두 줄):

```
[self:script]{op: "run", id: "나레이션생성", args: {texts: {"인사": "안녕하세요, ..."}, out_dir: "..."}}
```

옵션: `voice`(기본 `kkj`) · `gpu`(기본 `T4`) · `force`(이미 있는 wav 도 다시 굽기) · `speed`(기본 **0.9** — §2 참조).

## 1-1. 표준 낭독 속도 = 0.9x (10% 느리게)

**모든 나레이션은 기본으로 0.9배 속도로 나온다.** 스크립트가 wav 를 회수한 직후
`ffmpeg atempo` 로 제자리 타임스트레치하므로, 부르는 쪽은 아무것도 안 해도 된다
(`나레이션생성.py` 의 `DEFAULT_SPEED`).

- **왜 이 값인가**: 2026-08-17 사용자 판정 — 원속도가 듣기에 빠르다. 10% 느리게가 표준.
- **왜 모델이 아니라 후처리인가**: Qwen3-TTS 에 속도 파라미터가 없고, 프롬프트로
  "천천히 읽어"는 재현되지 않는다. 후처리는 결정론이고 **재굽기가 필요 없다**.
- **피치는 보존된다** — atempo 는 타임스트레치라 음높이가 안 바뀐다.
  실측(원본 vs 0.9x): 스펙트럼 무게중심 비 **0.979~0.985**. 단순 리샘플이었다면 0.90 이 나온다.
- **길이는 1/0.9 = 약 1.11 배**가 된다. 씬 길이를 나레이션에 맞추는 렌더 경로라
  타임라인은 자동으로 다시 맞는다 — *오디오만 늘려 기존 영상에 얹지 말 것*(싱크가 깨진다).
- **두 번 늘어나지 않는다**: 재실행 시 이미 있는 wav 는 건너뛰고, `force:true` 는 새로 구운 뒤 한 번만 늘린다.
- **되돌리거나 바꾸려면** `speed` 를 넘긴다 — `{speed: 1.0}`(원속도) · `{speed: 0.85}`(더 느리게).
  표준 자체를 바꾸려면 `DEFAULT_SPEED` 한 줄만 고친다.
- **이미 구워둔 옛 wav 를 표준에 맞추려면** 다시 굽지 말고 늘리기만 하면 된다:
  ```bash
  ffmpeg -y -i old.wav -filter:a atempo=0.9 -ar 24000 -ac 1 -c:a pcm_s16le new.wav
  ```
- **재사용 멘트**: 인트로·아웃트로는 `outputs/narration/bookends2_slow/` 가 표준(0.9x) 판이다.
  (`bookends2/` 는 표준 도입 전 원속도 판 — 새 영상에 쓰지 말 것.)

## 2. 규약 — `narration/<slide_id>.wav` 가 TTS 를 이긴다

`[self:deck]{op:"video"}` 는 렌더할 때 그 장의 `narration/<slide_id>.wav` 를 **먼저 본다.**
있으면 그 파일을 쓰고 TTS 를 호출하지 않는다. 없으면 종전대로 스피커 노트를 TTS 로 굽는다.

**왜 파라미터가 아니라 파일 존재로 푸는가**: 슬라이드 `base.png`(글자 얹기) 선례와 같다 —
파일이 있으면 그게 이긴다. 파라미터를 늘리지 않으므로 자율주행·조종실·앱 어느 표면에서
불러도 똑같이 작동하고, 장별로 섞어 쓸 수 있다(어떤 장은 내 목소리, 어떤 장은 TTS).

결과의 `preset_narration` 이 미리 구운 오디오를 쓴 장 수다.

## 3. 목소리 원장 — `data/voice/voices.json`

목소리는 코드가 아니라 **데이터**다. 교체·추가는 이 원장만 고친다.

**★확정 (2026-08-17, A/B 청취) — 표준 레퍼런스는 `kkj`(1판)다. 다시 A/B 하지 말 것.**
원장에 `kkj2`(2판, SNR 점수 상위 구간)도 등록돼 있지만 **채택되지 않았다** — 사용자가 두 판을
같은 문장으로 구워 들어보고 `kkj` 를 골랐다. `kkj2` 파일·항목은 되돌릴 여지로 남겨두되,
**명시적으로 `voice: "kkj2"` 를 넘길 때만** 쓰인다. 기본값은 `나레이션생성.py` 의
`args.get("voice") or "kkj"` 한 곳뿐이고, 그 밖에 목소리를 고르는 경로는 없다
(`[self:deck]{op:"video"}` 는 §2 규약대로 이미 구워진 wav 를 그냥 쓰므로 목소리를 모른다).

```json
{"kkj": {"name": "강국진", "audio": "kkj.wav", "text": "<그 오디오의 정확한 전사>"}}
```

**레퍼런스 조건** (지키면 품질이 확 달라진다):
- 잡음 없는 **단독 발화 5~10초** (배경음악·다른 화자 없음)
- **모노 24kHz wav** — `ffmpeg -ss <시작> -t <길이> -i 원본 -ac 1 -ar 24000 -c:a pcm_s16le ref.wav`
- **`text` 는 그 오디오의 정확한 전사** — 어긋나면 복제 품질이 눈에 띄게 떨어진다.
  Whisper 로 자동 전사해도 되지만 **고유명사는 반드시 귀로 대조**할 것
  (실측: 같은 녹음에서 "하이젠베르크"가 한 구간에서만 "하이젠벨크"로 잘못 잡혔다).

**깨끗한 구간 찾는 법** — 긴 녹음에서 후보를 기계로 고른다:

```bash
ffmpeg -i 원본.mp3 -af "silencedetect=noise=-35dB:d=0.6" -f null - 2>&1 | grep silence_
```

무음과 무음 사이가 긴 곳이 연속 발화 구간이다. 여러 개 잘라 들어보고 고른다
(현재 `kkj` 는 3 후보 중 사용자가 직접 고른 것).

## 4. 비용·시간 (T4 실측)

- 세션당 **모델 다운로드 5~10분** — 콜랩은 세션이 사라지면 매번 다시 받는다.
- **문장당 40~60초**. 30장 덱이면 대략 30분. (0.9x 재타이밍은 로컬 ffmpeg 라 초 단위 — 비용 0.)
- GPU 는 컴퓨트 유닛을 소모한다. 스크립트가 `finally` 에서 원격 파일 삭제 + `colab stop` 까지 한다.
- **이미 있는 wav 는 건너뛴다** → 노트를 고친 장만 다시 굽는 재실행이 싸다. 전부 다시 구우려면 `force: true`.
- 도구 60초 제한을 넘으므로 에이전트 경로에서는 타임아웃이 날 수 있다(원장 timeout 은 2400초).
  타임아웃이 나도 **스크립트는 계속 돌아 파일은 남는다** — `narration/` 을 확인할 것.

## 5. 함정 (전부 실측 — 스크립트에 박혀 있지만 원인을 알아둘 것)

1. **콜랩 CLI 의존성 핀** — `colab` CLI 가 `jupyter-kernel-client` 를 버전 고정 없이 요구하는데
   1.x 에서 `KernelClient` → `JupyterKernelClient` 로 개명돼 **모든 `exec` 이 죽는다.**
   `colab update`·재설치 때마다 재발한다. 처방:
   ```bash
   uv pip install --python ~/.local/share/uv/tools/google-colab-cli/bin/python 'jupyter-kernel-client<1.0'
   ```
   스크립트가 이 증상을 감지하면 처방을 그대로 되돌려준다.
2. **`colab upload` 의 상대경로는 루트(`/`) 기준** — `/content` 가 아니다. 목적지는 절대경로로.
3. **T4 의 거짓 bf16 보고** — `torch.cuda.is_bf16_supported()` 가 T4(sm_75)에서 True 를 반환하지만
   네이티브 bf16 이 없다(에뮬레이션). **에러 없이 느려지기만** 해서 가장 알아채기 어렵다.
   `torch.cuda.get_device_capability()` 로 아키텍처를 직접 볼 것 — sm_80(Ampere) 이상만 진짜 bf16.
4. **프라이버시** — 목소리는 생체정보다. 스크립트는 레퍼런스(10초 이내)만 올리고,
   끝나면 원격 파일을 지우고 세션을 반납한다. **원본 녹음 전체를 올리지 말 것.**

## 6. 왜 전용 IBL 어휘가 아닌가

`colab.md` §6 의 반-어휘-증식 규약을 따른다 — "새 특수 어휘 만들까?"의 기본 답은 "스크립트 등록".
4기준으로도 외부 인터페이스 하나만 강하고 조합성·빈도·실시간성이 약해 액션 문턱을 못 넘는다.

**승격 경로**(빈도가 신호를 줄 때): `[engines:tts]{engine: "qwen3"}` — 새 단어가 아니라
이미 있는 `engine` 축에 값 하나 추가라 어휘 비용이 사실상 0이다
(`sense:realty` 의 `source: molit/zigbang/naver` 와 같은 모양).
다만 세션 기동이 수 분이라 승격하려면 백그라운드+상태파일 패턴이 필요하다.
