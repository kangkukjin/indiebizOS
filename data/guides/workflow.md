# 함수·워크플로 저장과 재사용

현재 IBL 프로그램을 명시 인자의 함수로 저장하고 이름으로 호출한다.
함수는 모델이 큰 프로그램을 조합할 때도, 앱·스케줄이 정해진 절차를 실행할 때도 사용한다.
다시 만들 비용이 크고 입력·반환·완료 조건이 분명한 절차를 저장한다.

## 저장

```ibl
#!ibl edition=2
[self:workflow]{op:"save",code:"[def:배수합]($목록,$배수=2){return sum($목록) * $배수}",description:"목록 합계에 배수를 곱한다"}
```

`code`는 하나의 `[def:이름]($인자,$선택=기본값){...}` 정의다. 저장 전에 컴파일러가 검사한다.
이름은 정의에서 가져오며 `id` 또는 `workflow_id`로 저장 ID를 지정할 수 있다.
본문의 모든 외부 값은 인자로 선언한다. 문자열은 그대로이며 보간은 `f"${값}"`이다.
`return`은 즉시 함수에서 반환한다. 실행 응답의 `value`가 반환값이다.
검사 통과는 실제 업무 성공의 보증이 아니며 미확정 도구 경계는 검사 결과에 표시된다.

## 호출과 조합

```ibl
#!ibl edition=2
[fn:배수합]{목록:[1,2,3],배수:3}
```

결과는 숫자 18이다. 같은 함수를 다른 함수·반복 안에서도 호출할 수 있다.
관용구를 쓸 때에는 이름과 계약을 조회하고, 수정할 때만 본문을 펼친다.
`[self:workflow]{op:"run",workflow_id:"배수합",params:{목록:[1,2,3]}}`도
저장본의 판본을 읽어 실행한다. 호출자가 판본을 다시 선택할 필요는 없다.

## 조회·수정·삭제

- `op:"list"`: 저장 목록과 입력·실행 가능 여부.
- `op:"detail",workflow_id:"이름"`: 저장 원문과 메타데이터.
- `op:"save",code:"..."`: 같은 이름의 저장본이 있으면 그 정의의 개정이다(`workflow_id` 생략 가능, 설명을 안 주면 기존 설명 유지).
  이 함수를 부르는 저장 정의가 개정 뒤 검사를 통과하지 못하면 저장을 거절하고 그 호출자를 알려 준다.
- `op:"delete",workflow_id:"이름"`: 저장 정의 삭제. 부르는 저장 정의가 있으면 거절한다.

함수 이름은 저장 정의·관용구 전체에서 하나다 — 다른 저장 ID나 관용구가 가진 이름으로는 저장되지 않는다.
저장·삭제는 같은 저장소 잠금 안에서 현재 정의를 읽고, 변경 후 이름 공간을 컴파일한 뒤 반영한다.
같은 ID의 이름 변경은 옛 이름을 제거한 상태로 검사한다. 호출 관계는 컴파일러의 이름 해소를
따르므로 호출 구문의 공백은 영향을 주지 않고, 문자열 속 예시나 같은 이름의 지역 함수는 구별한다.
인자·반환이 바뀌는 이행은 **새 이름**(예: `[def:배수합2]`)으로 저장하고, 호출자를 하나씩 새 이름으로
다시 저장한 뒤, 호출자가 없어진 옛 정의를 지운다. 앱·스케줄의 호출자도 명시적으로 옮긴다.
기존 판본의 ID에 현재 판본을 덮어쓰지 않으며, 과거 원문의 본문과 실행 실적을 일괄 치환하지 않는다.
저장본은 정의 하나다. 지역 함수로 분해한 프로그램은 보조 함수부터 하나씩 저장한다.

## 예약 실행

```ibl
#!ibl edition=2
[self:manage_events]{op:"create",title:"계산",time:"08:00",repeat:"daily",do:"run_workflow",action_params:{workflow_id:"배수합",params:{목록:[1,2,3],배수:3}}}
```

예약 실행은 저장된 함수의 판본을 자동 해소한다. 인자는 `action_params.params`에 보존하며,
동적인 값이 필요하면 함수 안에서 명시적으로 읽는다. 원문 파이프라인을 예약할 때는
`#!ibl edition=2` 헤더와 `inputs`를 저장한다. 현재 IBL에서 생성한 예약 원문은 작성 문맥의 판본을 고정한다.

## 중단과 재개

현재 실행은 `resume:{run_id}`와 동일한 코드·inputs·주체·프로젝트로 재개한다.
완료한 호출은 재사용하고 결과 불명 외부 작업은 자동 반복하지 않는다.
자세한 조합·실패 처리·재개는 `ibl_composition.md`를 따른다.
기존 무표기 저장본의 해석은 `docs/compatibility/ibl_workflow_legacy.md`에 보존한다.
