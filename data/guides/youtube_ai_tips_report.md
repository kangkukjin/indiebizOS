# 유튜브 AI 팁 보고서 가이드 (YouTube AI Tips Report)

유튜브에 넘치는 "AI 활용법" 콘텐츠를 **매일 조금씩(2~4편) 골라 자막으로 읽고, 실행 가능한 팁으로 증류해 누적하는 일간 보고서**다.

> **원리 = 영상을 보지 않는다.** 유튜브 영상의 팁은 거의 전부 말(자막)에 산다. `[sense:video]{op: "transcript"}`로 자막만 뽑아 읽으면 15분 영상이 몇 천 토큰이다. 화면 시연만 있고 말로 설명 안 된 부분은 "영상 확인 필요"로 정직하게 남긴다.
>
> **누적이 자산이다.** 보고서는 그날의 기록이고, 팁 DB(`db/tips.json`)와 다룬 영상 원장(`_covered_videos.json`)이 쌓여가는 자산이다 — 부동산 보고서의 순회 DB와 같은 원리. 같은 영상을 두 번 다루지 않고, 같은 팁의 재탕은 "이미 수집(날짜)"로 갈음한다.

- **원장·DB** (같은 폴더):
  - `_covered_videos.json` — 다룬 영상 원장 (중복 방지의 단일 진실, §4)
  - `db/tips.json` — 증류한 팁 누적 DB (§4)
  - `_scan_log.md` — 장애로 보고서를 못 쓴 날의 한 줄 로그
- 폴더가 없으면 첫 작성 시 `[self:write]`가 자동 생성한다.

> **배포 = 로컬 md 누적 + 공유창고 누적 등재.** 매 호 HTML 판을 **`공유창고/0/AI 팁들/` 폴더 안에 `AI 팁 보고서 <YYYY-MM-DD> <주제>.html`로 새로 넣는다 — 덮어쓰지 않고 쌓는다** (부동산 보고서 선례: 호마다 주제가 달라 최신 한 장이 이전 호를 대체할 수 없다. 날짜 우선 = 폴더 안 사전순이 시간순, `AI 팁 보고서` 접두 = 창고 밖으로 내려받거나 리트윗됐을 때 정체 보존).
>
> HTML 렌더의 유일한 통로는 **등록 스크립트 `보고서HTML`** 이다(자족 문서 — 스타일 인라인·다크모드 대응). 즉석 변환기를 `/tmp` 에 쓰지 않는다 — 그렇게 쓴 것은 재부팅에 사라지고 다음 호가 또 쓴다. **공유판에는 사용자 개인 시스템(IndieBiz OS 내부 구조 등) 맥락을 싣지 않는다** — "우리 시스템에의 함의" 절은 md 원본에만 둔다. 이 제거는 사람 손이 아니라 변환기의 `drop_lines` 가 집행하고 제거한 줄 수를 신고하므로, 검수는 그 숫자를 본다. `/r/` report_publish 공개면 발행은 하지 않는다.
>
> **셸(`run_command`)은 IBL 등가물이 없는 일에만 쓴다.** 원장·DB(JSON 배열) 갱신은 등록 스크립트 `json원장`, 공유창고 HTML 렌더는 `보고서HTML` 이 맡는다 — 파이썬 원라이너·히어독으로 읽고 다시 쓰지 않는다. **payload 는 나르지 말고 가리킨다**: 수십 행짜리 원장 갱신을 `args` 리터럴로 박지 말고 `[self:write]` 로 파일에 고정한 뒤 `args_file: "<payload 경로>"` 로 넘긴다(2026-09-01 개통 — 이 마찰이 이틀 연속 셸 우회를 낳았다). 네이티브 경로로 돈 주행은 경험 증류에 접지되지 않아 해마에 아무것도 남지 않고, 매일 도는 작업이라 그 손실이 매일 누적된다.
>
> **파이프 안 AI step(`[table:ai]`·`[table:brief]` — 재료 분류·증류·요약)을 쓸 때는 `criteria` 를 함께 달아라** (품질 계약 2026-08-27, 정본=docs/IBL_QUALITY_CONTRACT_HANDOFF.md). 기준 미달이 위치 있는 실패가 되고 사유를 얹은 재시도 1회가 자동으로 붙는다. 기준은 결과의 **반증 가능한 속성**으로(행 수·필수 열·언어 같은 — 취향 산문은 판정 불능만 낳는다), 뒤 step 들이 의존하는 재료 관문에만(판정도 원샷 AI 호출=비용). 본문(모델 문맥에서 직접 쓰는 글)은 criteria 시야 밖이고, 결정론 step 에 걸면 재시도 없이 실패만 남는다.
>
> **수집 결과를 통째로 문맥에 들이지 말 것 — 선별은 얇게, 정독은 고른 것만.** 이 작업의 벽시계는 거의 전부 모델 시간이고, 그 크기는 왕복 수가 아니라 **모델이 읽는 문자수**를 따라간다(측정은 `에피소드통계`의 결과천자). 검색·후보 목록은 표 꼬리(`select`·`take`·`dedup`)로 필요한 열만 남겨 읽고, 자막 전문 정독은 선별(§2-3 컷오프·조회수·중복 축)을 통과한 편에만 쓴다. 경계: 증류에 필요한 정독까지 접지 말 것 — 얇게 훑고 고른 뒤 깊게 읽는 두 단이 원리다.

## 1. 무엇을 팁으로 치는가 — 증류 헌법

이 보고서의 품질은 여기서 결정된다. 유튜브는 과장의 문법("상위 1%만 아는", "업무 시간 99% 절감")으로 말한다 — **껍질을 벗기고 알맹이만 증류한다.**

1. **실행 가능해야 팁이다.** 단계·도구 이름·프롬프트 예문·설정 방법이 있는 것만. "AI를 적극 활용하세요" 같은 덕담·마인드셋 설교는 팁이 아니다 (영상 전체가 덕담이면 그 영상은 "팁 없음"으로 원장에 남기고 보고서에서 뺀다).
2. **과장 보정.** 제목·썸네일의 주장("10배", "99%")과 실제 내용의 간극을 한 줄로 짚는다. 특정 유료 도구 홍보·협찬 냄새가 나면 `[홍보성]` 표시.
3. **실측 아님을 명시.** 자막만 읽고 쓰는 것이므로 팁의 실효는 검증 전이다. 따라해 볼 가치가 특히 큰 것만 **"시도 후보"**로 그날 호에 2~3개까지 적는다 — 가벼운 제안이지 과제가 아니다. **★시도 후보는 그날 호 안에서 끝난다 (사용자 지시 2026-08-13)**: 이전 호 후보를 세어 누적 개수를 집계하거나, "미검증 부채"·"검증 0건"·"실험이 증류를 못 따라간다" 같은 표현으로 실험을 재촉하거나, "부채를 갚는 호"를 제안하지 않는다. 팁을 시스템에 적용할지는 전적으로 사용자의 선택이며, 사용자가 실제로 해본 결과를 알려준 경우에만 후속 호에서 그 결과를 언급한다.
4. **사용자 맥락 함의.** 사용자는 Claude Code·IndieBiz OS를 쓰는 고급 사용자다. 팁마다 "이미 우리가 하는 것 / 우리 시스템에 이식할 만한 것 / 해당 없음"을 한 줄로 (md 원본에만, §0).
5. **출처 정직.** 팁마다 영상 제목·채널·URL·타임스탬프(자막에서 추정 가능하면)를 단다. 이 세션에서 실제 자막을 읽은 영상만 인용한다 — 날조 금지.

## 2. 매일 절차

> ⚠️ **파이프라인의 자리 (2026-08-27 사용자 판정으로 개정).** 옛 조항은 전면 금지("검색·자막·작성을 `>>`로 엮지 않는다")였는데, 그 금지는 struct 의 파이프 본문 이음매가 자막 봉투를 못 읽던 **결함 시절의 판정**이었다(수리 `935470cf` — 외부화 봉투 따라가기+grounded 대조 성립). 지금의 경계는 이렇다:
>
> - **증류 초안은 문장으로 해도 된다** — 영상별로 자막을 뽑아 구조화 추출(grounded)로 증류하는 것까지 한 문장으로 엮을 수 있다. grounded 가 §1 헌법 ⑤(날조 금지)를 기계로 집행한다: 팁마다 자막 원문 발췌(`_quote`)가 붙고 코드가 원문 대조로 탈락시킨다(실측 2026-08-27: 2만 자대 자막 2편 → grounded 통과 42행). **매번 무에서 다시 짓지는 않는다 — §2-0의 성공 배관 골격을 먼저 불러와 그 회차의 주제·검색어·원장 상태에 맞게 재컴파일한다.** 골격은 처방이 아니라 출발점이다(2026-08-30 개정 — 부동산 가이드가 같은 개정[§3-0]으로 제작 시간을 절반으로 줄인 실측이 근거).
> - **판단이 필요한 몫은 여전히 하나씩 읽고 한다** — 원장 갱신(`_covered_videos.json`·`db/tips.json` upsert), 재탕 판정(기존 팁 DB 와 대조), §1 헌법 4(사용자 맥락 함의), 자막이 부실한 영상의 교체·재시도, 최종 보고서의 편집. 문장이 뽑은 초안은 **재료**다 — 그대로 발행하지 않는다.
> - 초안 문장이 실패하거나 품질이 의심스러우면 옛 방식(하나씩 호출하고 읽고 판단, `deep_research.md` 원칙)으로 내려간다 — 그 원칙 자체는 폐기되지 않았다.

### 2-0. 성공 배관을 재컴파일하는 출발점 (2026-08-30)

2026-08-28 사본 실증에서 이 보고서의 전 절차(검색→원장 제외→날짜 확인→선정→증류→절제→작성→원장 델타)가 **23문장 완성 프로그램으로 완주**됐다(원문 정본=`docs/IBL_REPORT_PROGRAMS_HANDOFF.md`). 배관을 회상하지 못한 주행은 같은 일을 수십 개의 미세 호출로 매번 재조립한다 — 부동산 보고서가 같은 개정(housing_report.md §3-0)으로 제작 시간을 절반으로 줄인 실측(2026-08-30)이 이 절의 근거다. 목적은 판단을 없애는 것이 아니라, **매번 같은 배관을 다시 생각하는 모델 턴을 없애고 판단을 소수의 의미 있는 칸에 모으는 것**이다.

#### 기본 골격 — 먼저 이 모양으로 묶는다

1. **상태 읽기**: 원장(`_covered_videos.json`)·직전 보고서를 처음에 읽어 변수로 잡는다. 오늘 주제(§2-2)는 여기서 판단한다 — 직전 호의 '지켜볼 점'이 주제 풀보다 앞선다(08-28 실측 ①).
2. **검색 한 묶음**: 주제 질의 2~3개(한·영 병행, §2-3)를 `&` 병렬로 → `union → dedup(video_id) → 원장 제외`. 원장 제외는 산문 지시가 아니라 `not_in` 술어로 박는다.
3. **날짜 확인 팬아웃**: `each + [sense:video]{op:"info"}` 로 일괄 확인 → 180일 필터 → 정렬 → select. 6개월 규칙이 문장 안 술어가 된다(실측 8/24 ①). 컷오프 탈락분은 too_old 원장 델타로 남긴다.
4. **심사 한 칸**: 신선 후보 전체를 `[table:ai]` 한 칸에 — 모든 행 유지 + selected/reason, 정확히 N편 선정. `criteria` 필수(§0).
5. **증류 팬아웃**: 선정 편마다 `transcript → self:struct(grounded)` 를 each 로. 자막 실패는 `on_error: "continue"` 로 흘리고 교체·재시도는 문장 밖 판단이다.
6. **절제 한 칸**: 팁 전체를 `[table:ai]` 한 칸에 — 영상당 2~5건·전체 8~15건·영상 균형, 기존 팁 DB 요지 주입으로 재탕 대조(dedup_note), hype 보정, implication.
7. **산문·조립·상태 쓰기**: 본문·TL;DR·시도·영상평·지켜볼 brief 5칸 내외 + M·K 계산 + `[table:document]` 조립. 저장은 §2-6 순서(원장 먼저) — 원장·DB 갱신은 `json원장`, HTML 은 `보고서HTML`.

$증류 = $선정 >> [table:each]{do: "[sense:video]{op: 'transcript', video_id: '$it.video_id'} >> [self:struct]{schema: 'tip(실행형 팁 제목), how(따라할 수 있게 — 단계·도구 설정·프롬프트 예문), tools(언급된 도구들), hype(과장 간극 한 줄 — 없으면 빈 문자열), timestamp(MM:SS 추정)', grounded: true}", keep: ["title","uploader","url","video_id","view_count","duration"], limit: <N>, on_error: "continue"}

## 4. 원장·DB 스키마

`_covered_videos.json`:
```json
{
  "covered": [
    {"id": "<video_id>", "title": "...", "channel": "...", "date": "YYYY-MM-DD",
     "upload_date": "YYYYMMDD", "topic": "프롬프트",
     "verdict": "tips_3|no_tips|no_transcript|too_old|too_long_skipped"}
  ],
  "recent_topics": [{"date": "YYYY-MM-DD", "topic": "프롬프트"}]
}
```
- **upsert 기준 = video_id.** 건너뛴 영상(`no_transcript`·`no_tips`)도 기록한다 — 재시도 낭비 방지.
- **`verdict` 접두가 집계의 자다.** `tips_*`만 "다룬 영상"이고 나머지는 "후보로 검토했으나 탈락"이다.
  머리줄 `K` 계산: `len([c for c in covered if c['verdict'].startswith('tips_')])` (§3).
- `recent_topics`는 최근 10건 롤링.

`db/tips.json` (append-only 배열):
```json
[
  {"tip": "팁 제목", "how": "방법 요약 한두 줄", "topic": "프롬프트",
   "source": {"video_id": "...", "title": "...", "channel": "...", "url": "..."},
   "date": "YYYY-MM-DD", "report": "ai_tips_report_YYYY-MM-DD_프롬프트.md",
   "try_candidate": false}
]
```
- 이 DB가 쌓이면 "지금까지 모은 프롬프트 팁 전부" 같은 질의·통합 리포트의 원천이 된다.

- 2026-09-01 수리 ⑦ (①·⑥ 의 뿌리 — 같은 날 백엔드 수리): 실측 ① 의 무한 대기는 증류 어휘의 문제가 아니라 **CLI 프로바이더의 무방비 읽기**였다. 유일한 시간 한도가 `proc.wait()`(=stdout 이 이미 닫힌 뒤)에 있어, 자식이 파이프를 연 채 침묵하는 진짜 멈춤에는 아무 한도도 없었다 — 로그에도 호출 시작 줄만 있고 짝이 되는 결과 줄이 없다. 무출력 마감(10분)을 걸어 무한 대기를 **유한한 정직 실패**로 바꿨고(`on_error:"continue"` 가 그 행만 버리고 계속 간다), 마감으로 끊긴 호출에는 형식 되먹임 재시도를 붙이지 않는다(출력이 틀린 게 아니라 없는 사건 — 대기 두 배 방지). 진행 표시는 **좌표는 소유하고 움직임은 공유한다**로 개정 — 단일 step 프로그램(`[table:each]` 한 문장)도 자기 좌표를 신고하고, each 는 행마다 회차를 찍는다. 이제 recover 가 `step 1/1 [table:each] · each 2/4행(<id>) · 하위 step 2/2 [self:struct]` 로 답하므로 **멈춤과 느림이 구별된다**(그 시각이 새로워지면 도는 중, 멈춰 있으면 멈춘 것). 실측 ⑥ 의 `args_file` 도 같은 날 개통 — 이제 원장 48행은 파일을 가리켜 어휘층으로 통과한다(§0·§2-6).
