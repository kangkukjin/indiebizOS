# 유튜브 AI 팁 보고서 가이드 (YouTube AI Tips Report)

유튜브에 넘치는 "AI 활용법" 콘텐츠를 **매일 2~4편 골라 자막으로 읽고, 실행 가능한 팁으로 증류해 누적하는 일간 보고서**다.

> **원리 = 영상을 보지 않는다.** 팁은 거의 전부 말(자막)에 산다. `[sense:video]{op: "transcript"}`로 자막만 읽으면 15분 영상이 몇 천 토큰이다. 화면 시연만 있고 말로 설명 안 된 부분은 "영상 확인 필요"로 정직하게 남긴다.
>
> **누적이 자산이다.** 보고서는 그날의 기록이고, 팁 DB(`db/tips.json`)와 다룬 영상 원장(`_covered_videos.json`)이 쌓이는 자산이다. 같은 영상을 두 번 다루지 않고, 같은 팁의 재탕은 "이미 수집(날짜)"로 갈음한다.
>
> **이 가이드는 매일 06시 주행이 조사 전에 통째로 읽는 재료다 — 크기가 곧 매일의 비용.** 상한 30KB. 실측 기록은 여기가 아니라 `docs/YOUTUBE_TIPS_FIELD_NOTES.md`에 덧붙인다(§2-7). 개정 이력은 `git log`·`data/system_docs/changelog.log`. 원장은 통째로 읽지 않고 필요한 열만 접어 읽는다(§2-1).

## 0. 저장·원장·배포·실행 규약 (예외 없음)

- **고정 폴더** `~workspace/outputs/ai_tips_reports/` · **파일명** `ai_tips_report_YYYY-MM-DD_<주제>.md`(주제는 한 단어, H1과 같은 표기. 날짜 우선 순서 불변 — 사전순=시간순이 정기보고 앱과 §2-1의 전제).
- **원장·DB**: `_covered_videos.json`(다룬·탈락 영상 원장, 중복 방지의 단일 진실 §4) · `db/tips.json`(팁 누적, append-only) · `_scan_log.json`(수집 불가 날, §2-7).
- **배포 = 로컬 md 누적 + 공유창고 누적 등재.** 매 호 HTML을 `공유창고/0/AI 팁들/AI 팁 보고서 <YYYY-MM-DD> <주제>.html`로 **새 파일로 쌓는다**(덮어쓰기 금지 — 호마다 주제가 다르다). 렌더의 유일한 통로는 등록 스크립트 **`보고서HTML`**(`drop_lines`는 **리스트** — 문자열을 주면 글자 단위로 쪼개져 66줄이 지워진 사고가 있다). 공유판에는 "우리 시스템 함의" 절 등 개인 시스템 맥락을 싣지 않는다 — 제거는 변환기의 `drop_lines`가 집행하고 `dropped_lines`가 팁 수와 같은지, `links`가 영상+출처 건수 이상인지 검산한다. `/r/` 공개면 발행은 하지 않는다.
- **관용구 저장**: §2-0의 `AI팁보고서쓰기`는 등록 스크립트 `AI팁보고서`의 잠금·검수 지문·복구 저널로 원장→DB→md를 저장한다. `committed` 뒤 같은 행을 수동 append/upsert하지 않는다. 아래 직접 저장 규칙은 수동 보완·예외 경로에 적용한다.
- **셸은 IBL 등가물이 없는 일에만 — 보고서 md·원장·현장 노트의 저장·편집은 `[self:write]`·`[self:ledger]`·`[self:edit]` 로**(셸 `cat >` 로 쓴 파일은 쓰기 원장·증류에 접지되지 않는다, 09-05 10시 호 실측). 원장·DB는 **`[self:ledger]`**(읽기 `op:"select"` · 갱신 `upsert`/`append` · 최상위 키는 `set`에 `target` 필수). 큰 payload는 `[self:write]`로 파일에 고정한 뒤 **`items_file`**로 가리킨다(리터럴로 박지 않는다). 손 전사 금지 — 원장 행은 소스에서 팬아웃해 파일로 고정한 뒤 그 파일을 넘긴다.
- **파이프 AI step(`[table:ai]`·`[table:brief]`·`[self:struct]`)에는 `criteria`** — 뒤 step이 의존하는 재료 관문에만, 반증 가능한 속성(행 수·필수 열·값 집합)으로. 정본 `docs/IBL_QUALITY_CONTRACT_HANDOFF.md`.
- **얇게 훑고 고른 것만 정독.** 벽시계는 모델이 읽는 문자수를 따른다(`에피소드통계` 결과천자). 후보 목록은 `select`·`take`로 열을 접어 읽고, 자막 정독은 §2-3 선별을 통과한 편에만.

## 1. 무엇을 팁으로 치는가 — 증류 헌법

유튜브는 과장의 문법("상위 1%만", "99% 절감")으로 말한다 — 껍질을 벗기고 알맹이만 증류한다.

1. **실행 가능해야 팁이다.** 단계·도구 이름·프롬프트 예문·설정 방법이 있는 것만. 덕담·마인드셋 설교는 팁이 아니다(영상 전체가 덕담이면 `no_tips`로 원장에 남기고 보고서에서 뺀다).
2. **과장 보정.** 제목·썸네일 주장과 실제 내용의 간극을 한 줄로. 홍보·협찬 냄새는 `[홍보성]`.
3. **실측 아님을 명시.** 자막만 읽었으므로 실효는 검증 전. **시도 후보는 그날 호 안에서 끝난다**(사용자 지시 08-13) — 2~3개까지의 가벼운 제안이며, 누적 집계·"미검증 부채"·실험 재촉·"부채를 갚는 호" 제안 금지. 적용 여부는 사용자 선택이고, 사용자가 결과를 알려준 경우에만 후속 호에서 언급한다.
4. **사용자 맥락 함의.** 사용자는 Claude Code·IndieBiz OS를 쓰는 고급 사용자다. 팁마다 "이미 하는 것 / 이식 후보 / 해당 없음"을 한 줄로(md 원본에만).
5. **출처 정직.** 팁마다 영상 제목·채널·URL·타임스탬프. 이 세션에서 실제 자막을 읽은 영상만 인용한다. `grounded: true` 구조화 추출이 이 조항을 기계로 집행한다(원문 발췌 `_quote` 대조). **관문은 끄지 않는다**(2026-09-07 ep2952: '근거 필드 누락'은 추출기 형식 오류라 핸들러가 1회 재시도하고, '전멸'은 발췌 표기 차이다 — 둘 다 자막이 없다는 뜻이 아니다). 관문을 끄고 뽑은 팁이 있으면 항목 머리에 `[근거해제]` 표식을 달고, 방법 칸에는 원문에 없는 단계를 쓰지 않는다(빈 값이 정직하다).

## 2. 매일 절차

**기본 경로는 등록 관용구 `AI팁보고서쓰기`다.** 주제·날짜·저장 위치를 정해 이름으로 호출한다. 검색·선정·두 차례 추출·중복 비교·영상별 내용 검토·편집·최종 검수는 관용구 안에서 매번 수행한다. 주제가 바뀌어도 같은 조사 방식이면 설정만 바꾼다. §1의 품질 기준은 그대로 적용하며, §2-1~2-5와 아래 세부 단계는 사전 주제 선택·결과 검토·실패 보완의 기준이다. 정상 실행에서 같은 조사를 따로 반복하거나 본문을 다시 타이핑하지 않는다.

### 2-0. AI팁보고서쓰기 — 기본 호출과 후속 처리

1. §2-1~2-2로 **이번 주제와 기준일**을 정한다. `~workspace/outputs/ai_tips_reports/`를 현재 작업공간의 **실제 절대경로**로 해소한다. 기존 운영 원장이 있는 곳을 `root`로 주며, 새 빈 폴더를 사용해 중복 비교를 건너뛰지 않는다.
2. 아래 설정으로 `[fn:AI팁보고서쓰기]`를 호출한다. `$주제`·`$날짜`·`$보고서폴더`는 앞에서 정한 값이다. 내부 관용구이므로 상시 목록에 없어도 이름으로 부른다. 필요하면 `[self:memory]{op:"recall",node:"보고서/유튜브 AI 팁",store:"실행"}`으로 서명을 확인한다.

```ibl
$설정 = {topic:$주제,date:$날짜,root:$보고서폴더,mode:"commit",reader_context:"Claude Code·IndieBiz OS를 사용하는 고급 사용자. 개별 기능의 구현 여부와 효과는 확인된 사실만 사용한다."}
[fn:AI팁보고서쓰기]{설정:$설정}
```

- **설정**: `topic`은 한 단어 주제, `date`는 `YYYY-MM-DD`, `root`는 원장·보고서 폴더 절대경로다. `reader_context`에는 확인된 독자 맥락만 준다. 선택값 `run_id`는 회차 식별자(영문·숫자·밑줄·하이픈, 80자 이하)이며 생략하면 날짜·주제로 정해진다.
- **모드**: 일상 보고서는 `commit`으로 검수 통과 후 로컬 md·원장을 반영한다(Git 커밋이 아님). 초안만 요청받으면 `draft`; 기본값도 draft이므로 운영 호출은 mode를 명시한다. 같은 run에서 draft→commit으로 바꿀 수 없다. 검수 초안을 운영 반영하려면 새 run_id와 commit 설정으로 다시 검수한다.
- **성공 확인**: 반환 `items`의 `status`가 `committed` 또는 `reviewed_draft`인지 확인한다. `report`는 본문, `evidence`는 실행 상태·검수 근거, `report_hash`는 검수 본문 지문이다. `new_tips/tips/videos/candidates/checked`는 이번 팁/누적 팁/누적 다룬 영상/원장 후보/이번 확인 건수다(draft의 누적은 반영 예정치). 파일 존재만으로 성공을 판정하지 않는다.
- **후속 처리**: `committed`이면 반환 report를 확인하고 **§2-6의 4번(HTML)부터** 수행한다. `reviewed_draft`는 원장 반영·배포 완료가 아니며 초안으로 보고한다. 관용구는 HTML·공유창고 등재·알림을 수행하지 않는다. 내부 검수 통과도 하네스의 공개 승인을 대신하지 않는다. 검수된 본문을 손으로 고쳐 배포하지 않는다.
- **재개**: 유효한 최종 내용 검수의 탈락은 관용구가 회차당 한 번 자동 보완한다. 탈락 이유·기존 본문·판정을 보존하고, 같은 기준으로 영상별 내용 검토·편집·최종 검수를 다시 수행한다. 재탈락하면 중단하며 같은 run 재호출로 자동 보완 횟수를 초기화하지 않는다. 그 밖의 실패는 봉투의 뿌리 오류와 `evidence`를 읽어 보완한 뒤 **같은 설정·run_id로 재호출**한다. 완료 단계는 재사용된다. 명시적 재검토는 등록 스크립트의 `revise`에 실행 폴더·`from=reviewed`·보완 사유를 전달한다. 기존 판정·본문은 revision 파일로 남고 내용 검토부터 다시 수행한다.
- **비교 입력과 준비 실패**: 후보 문맥과 기존 팁은 양쪽으로 자동 분할하며 모든 비교 쌍을 유지한다. 준비가 막히면 실행 상태의 `preparation_failure`에 최초 원인·확정 여부·`resume`가 남는다. 후보 추출 영수증이 있으면 자막과 팁을 바깥 AI가 다시 읽고 재작성하지 말고, 원인을 보완한 뒤 같은 설정으로 관용구를 재개한다. 이미 수동으로 원장을 갱신한 회차는 다시 반영하지 않는다.
- **검색 0건·부분 복구**: 정상 0건은 빈 결과로 기록하고 다른 검색 결과로 진행한다. 실제 검색 장애만 해당 질의에 한 번 자동 재시도한다. 검색별 질의·시도 번호·원 응답·결과 지문을 보존하며 성공/빈 검색은 재호출하지 않는다. 재시도 후에도 장애가 남으면 멈추고, 같은 회차를 명시 재개하면 실패한 질의만 다시 실행한다. 전체 0건·미처리 영상 없음은 완료 보고서로 위장하지 않는다. 결과가 없었던 검색 층은 보고서의 조사 한계에 표시한다.
- **긴 자막**: 전체 구간을 나눠 추출하고 후보별 관련 원문 위치를 전 구간에서 확인한다. 상세·검토는 방법·조건·반례의 실제 원문을 받는다. 구간별 성공 결과는 보존하므로 같은 회차 재개 시 실패한 구간만 다시 처리한다. 이미 저장된 자막은 재다운로드하지 않는다. 불확실한 위치 선택·한 후보의 과도한 근거 범위는 실패로 남기며 임의 절단하지 않는다.
- **예외**: `needs_evidence`, 개별 AI 입력 상한, 원장 변경, 자료 교체는 맹목적으로 재시도하지 않는다. 공식 근거 보강·분할 검토 등 필요한 부분을 아래 절차로 보완하고, 조사 입력·설정 변경이나 완료된 보고서의 수정은 새 run으로 검수한다. 지원되지 않는 보완은 수동 경로로 수행하되 같은 품질 기준을 지킨다. 실패를 숨기거나 관문을 끄지 않는다.

호출 이름이 없거나 본문 수리가 필요하면 정본 `data/idioms/ai_tips_report.ibl`과 `docs/AI_TIPS_REPORT_IDIOM.md`의 재등록 절차를 확인한다. 본문 변경·재등록은 `docs/IBL_IDIOM_REPAIR.md`를 따른다. 긴 자막의 전 구간 분할·개별 AI 입력 57,000자 상한과 자동 재작성·외부 근거 대조의 한계도 그 문서가 설명한다. 새 관용구를 매번 만들지 않는다.

**수동 보완·예외 경로의 단계**(정상 관용구 실행에서는 중복 수행하지 않는다):

1. **상태 읽기** — 원장은 `[self:ledger]{op: "select"}`로 `id·verdict`만, 직전 보고서는 사전순 마지막 md. 오늘 주제는 여기서 판단(§2-2).
2. **검색 한 묶음** — 질의 다섯 갈래(§2-3)를 `&` 병렬 → `union → dedup(video_id) → 원장 제외(not_in)`. 원장 제외는 산문이 아니라 술어.
3. **날짜 확인 팬아웃** — `each + [sense:video]{op:"info"}` → ISO 날짜로 180일 필터 → 정렬 → select. `upload_date`는 `YYYY-MM-DD`, 기준일도 같은 형식으로 준다. 날짜 확인 실패 행은 최신으로 간주하지 않는다. 탈락분은 `too_old`로 원장 델타.
4. **심사 한 칸** — 신선 후보 전체를 `[table:ai]` 한 칸에, 모든 행 유지 + `selected/reason`, 정확히 N편. `criteria` 필수.
5. **증류 1차 — 제목만, 병렬** — 선정 편마다 `transcript → [self:struct]{schema: "tip(실행형 팁 제목·동사로 끝남), timestamp(MM:SS)", grounded: true, known: $기존팁제목}` 을 `[table:each]{…, parallel: 4, on_error: "continue"}` 로. `how`·`tools`·`hype` 는 여기서 쓰지 않는다(2026-09-06: 편당 18건을 뽑아 6할을 버리면서 후보마다 200자 `how` 를 쓴 것이 출력의 절반이었다 — 후보 재현율은 그대로 두고 버려질 본문만 안 쓴다). `known` 에는 오늘 주제 기존 팁의 제목(`tips.json` select `tip`)을 넣어 아는 것을 다시 뽑지 않는다. 근거는 앵커 한 토막만 — 문장 확장은 코드가 한다(`quote_expanded`). 긴 자막의 외부화 파일·스필 참조는 struct 가 봉투째 따라간다 — 파일 경로를 손으로 옮기지 않는다. 자막 실패 편의 교체·재시도는 문장 밖 판단.
6. **절제 한 칸** — 1차 팁 전체와 video_id로 연결한 출처·인기 및 영상 선정 근거를 `[table:ai]` 한 칸에: 전체 8~15건을 목표로 하되 영상별 최소 할당량 없이 실행 가능한 팁만 선정, 재탕 대조(`dedup_note`), `selected`. 채택 팁마다 출처 판단·인기 판단·실행 가능성과 효용의 가치 판단을 짧고 구체적으로 남긴다. 뒤의 내용 검토·편집·최종 검수에도 이 근거를 인계한다.
6b. **증류 2차 — 선정분만 상세** — 선정된 팁의 영상마다 `transcript → [self:struct]{schema: "tip(주어진 제목 그대로), how(따라할 단계·설정·명령어·프롬프트 예문 구체 — 원문에 단계가 없으면 빈 문자열, 지어내지 않는다), tools, hype(과장 간극 한 줄), timestamp(MM:SS)", grounded: true, instruction: "다음 팁 제목들에 대해서만: …"}` 을 `parallel: 4` each 로. 선정 안 된 후보의 본문은 영원히 쓰지 않는다.
7. **산문·조립·상태 쓰기** — TL;DR·본문·시도·영상평·지켜볼 brief 5칸 내외 + M·K 계산 + `[table:document]`. 저장은 §2-6 순서(원장 먼저).

수동 조합 규칙: **검색어는 매 호 새로**(§2-3 규칙이 그날 검색어를 정한다 — 고정하면 같은 후보만 돈다) · 자막 플래키(같은 영상이 한 번은 성공, 다음은 실패)는 교체·재시도 1회 · 발행자는 `channel`/`uploader`, 신원은 채널 ID·URL로 확인 · 소스 장애·품질 실패 때만 문장을 하나씩.

**실행 예산(목표)**: 관용구를 한 번 호출하고 필요한 복구·배포만 잇는다. 호출 수·속도를 맞추려고 영상별 내용 검토·최종 검수를 생략하지 않는다. 선정 2~4편(또는 정직한 실패 기록)·증류·절제·검법(§2-6)·머리줄 M·K 일치가 채워지면 닫는다. 느릴 것을 미리 알아맞혀 `wait` 를 실을 필요는 없다(09-07: 표면 대기는 늘 상한까지 간다). 그래도 넘기면 티켓을 받아 봉투가 안내하는 `recover{wait: …}` 한 번으로 기다린다(셸 sleep 폴링 금지).

**수동 경로의 실패 복구**: 실패 봉투의 뿌리 오류부터 고친다. `resume.vars_ref`는 성공한 변수 복구용이며 실패한 변수나 생성되지 않은 파일을 만들어 주지 않는다. `~workspace/`로 고정한 중간 파일과 검증된 변수에서 재개하고, 완료된 수집·증류는 다시 실행하지 않는다. 끝에서는 `select`·`take`·짧은 `$return`으로 판단에 필요한 결과만 돌려준다.

**값 전달·구조화 규칙**

- 기존 팁 목록은 `known: ${기존팁.items.*.tip}`로 전달한다. each의 do 안에서도 같은 값 참조를 쓰며 제목을 코드에 손으로 붙이지 않는다. 따옴표·줄바꿈이 든 목록은 실행기가 데이터로 주입한다. known을 빼서 구문 오류를 우회하지 않는다.
- `grounded:true`와 `schema`의 `timestamp(MM:SS)`를 함께 사용한다. 코드는 원본 자막의 시간과 `_quote`를 연결해 시각을 채운다. `timestamp:null`/`_timestamp_error`는 근거 위치가 없거나 여러 곳이라는 뜻이므로 00:00으로 채우지 않는다. 그 행만 원문을 확인하거나 시각 미확인으로 표시한다. `timestamp_grounded`와 `missing_timestamp`도 확인한다.
- `try_candidate`는 `contains(tip, "툴 콜")` 같은 식으로 만든다. Python의 `in` 대신 이미 지원하는 contains를 쓴다.
- 자막은 `$자막 >> [self:write]{path:"${출력}/transcripts/${it.video_id}.json",format:"json"}`으로 원문·구간·언어를 함께 보존한다. 뒤의 `struct{file:...}` 두 단계가 같은 JSON을 읽는다. 타임스탬프 문자열을 직접 조립할 필요가 없다. 원문 파일·스필 참조가 없으면 실패로 확인하며 미리보기를 전문 대신 쓰지 않는다.
- `schema:"tip(제목), how(단계), timestamp(MM:SS)"`의 명시된 필드는 정적 검사와 결과 행의 누락 검사에 함께 쓰인다. `table:ai`에도 같은 선택적 schema를 쓸 수 있다. 의미·재현 가능성은 instruction/criteria로 판단하고, 필드 존재 검사를 AI에게 반복시키지 않는다.
- `source` 객체는 일반 값 구성으로 만든다. `try_candidate` 불리언도 그대로 복사한다. 결과를 JSON으로 저장해 원장 append의 items_file로 넘긴다. 아래 `$편집`, `$주제`, `$날짜`는 앞에서 만든 값이다.

```ibl
$중첩팁 = $편집 >> [table:each] {
  $return = [{
    tip:$it.tip, how:$it.how, topic:$주제, date:$날짜,
    try_candidate:$it.try_candidate,
    source:{video_id:$it.video_id,title:$it.title,channel:$it.uploader,url:$it.url}
  }]
}
```

### 2-3. 검색·선정

**순서: 후보 메타데이터 → 영상 선정 → 선정 영상만 자막·팁 추출 → 팁 비교·선발.** 검색된 모든 영상에서 팁을 먼저 추출하지 않는다. 메타데이터만으로 팁의 실재·정확성을 확정하지 않고, 자막과 독립 내용 검토에서 재판단한다.
**검색은 다섯 갈래**(각 `count: 12`): ①한국어 주제어 ②영어 원천(AI 팁의 원천은 대부분 영어권, 한국 채널은 며칠~몇 주 뒤 중계 — 원본이 잡히면 원본을 출처로) ③**고유명사·모델명·워크플로 어휘**(주제어는 아카이브·강좌 화석을 부른다 — 8/21·8/23·8/24·8/26 네 번 확인) ④**회의론**(`trap·overrated·limitations·hallucination·후회` — 반대편 시각은 구조적으로 늙어 따로 걸어야 하고, 수확률은 낮지만 통과분의 밀도가 높다) ⑤주제에 따라 행위 어휘("목소리 복제"처럼 — 한국어권은 '생활 AI'=폰 어시스턴트, '음성'=편집기 튜토리얼로 선점돼 있다). **한 질의에 한 영역** — 개념을 나열한 긴 질의는 0건을 낸다. 리뷰·랭킹 주제는 한 채널이 도배하므로 도구 이름으로 직접.

**선정 2~4편**: ①원장에 있는 영상 제외 ②**6개월 하드룰**(사용자 지시 08-12) — 후보마다 `op:"info"`로 `upload_date`를 확인해 180일 초과는 탈락, 원장에 `too_old`. 검색 결과에 날짜가 없으므로 생략 불가(창간호 3편이 전부 초과였다). 제목의 "2026"은 신선도를 보장하지 않는다. 컷오프 하루 차이 탈락도 원칙대로(원장이 재검토 경로를 남긴다) ③**누구의 팁이며 어떤 반응을 얻었는가** — 채널·업로더·신원 링크·설명 발췌와 조회수·좋아요·댓글·구독자·조회 시점을 함께 보고 AI가 선정한다. 직접 시연·전문성·근거의 확인 범위와 발행자의 자기주장을 구별한다. 인기 판단은 경과일·주제·언어·채널 규모를 고려하며, 고정 조회수 순위나 인기=정확성으로 대체하지 않는다. 미확인(null)은 실제 0과 다르다 ④1시간 이상 장편은 하루 1편 ⑤뉴스·단순 시연 후순위, **시니어·초보 튜토리얼을 건너뛰지 말 것**(비자명한 조작 지식이 거기 몰린다) ⑥**층을 섞는다** — 한·영 층은 주제에 따라 다른 독자(사무직 vs 분석 직군)·다른 이해관계(도구 콘텐츠 채널 vs 교육 판매자)를 대변하므로, 같은 날 다른 층의 영상이 가장 값싼 교차 확인이고 정면 대립은 논점을 좁힌다. 회의론이 6개월 안쪽에 있으면 반드시 넣는다.

### 2-4. 자막 추출·통독
`[sense:video]{op: "transcript", video_id, language}` — 영상 언어에 맞게(ko 먼저, 없으면 en). 자막 없는 영상은 `no_transcript`로 원장에. **긴 자막(1만 자 초과)은 파일로 외부화되고**(`saved_to_file`·`file_path`), 병렬 가지의 큰 결과는 스필 참조(`ref.path`)로 온다 — 둘 다 `[self:struct]`가 봉투째 따라가므로 파이프로 잇거나 `file: <ref.path>`로 넘기면 된다(옛 "`.json` 거절"은 09-02 수리). 손으로 구간을 옮겨 적지 않는다.
**자동자막 함정**: 고유명사가 뭉개진다(promptfoo→"Prompt Fu", 소넷→"소네"). 웹 검색의 2차 요약 사이트가 같은 자막을 옮겨 적어 틀린 철자가 여러 출처에서 "확인"되므로 **원 프로젝트(GitHub·공식 문서)까지 가거나 철자 불확실을 명시**한다. 모델명이 스폰서명과 겹치면(Sol→Salad) 광고 구간과 대조.

### 2-5. 증류·작성
재현 가능한 팁만 추출한다(보통 영상당 2~5개, 최소 개수 없음). **영상 요약이 아니라 팁 단위로 재조직**. 보고서는 전부 한국어, 도구 이름·프롬프트 예문·메뉴 경로는 원문 그대로(번역하면 따라할 수 없다). 재탕은 오늘 주제의 기존 팁(§2-0 `$기존팁`)과 대조해 "이미 수집(날짜)" 한 줄로. 서로 모르는 두 편이 같은 결론에 이르렀거나 정반대를 말했으면 그것이 그 호의 가장 강한 신호다 — TL;DR에 올린다.

**편집 검수**: 대립은 같은 대상·조건에 대한 양립 불가능한 주장일 때만 쓴다. 추적 대상과 저장 위치처럼 함께 적용할 수 있는 설명은 보완 관계다. 교차 확인과 편집자의 추론을 구분하고, 근거 없는 순위·효과·보편성을 덧붙이지 않는다. 자막만 읽었다면 화면의 코드·시연 유무를 단정하지 않는다. 구체적인 절차가 없는 항목은 팁 수와 DB에서 빼고 참고 원칙으로 분리한다. 편수를 채우려고 영상별 최소 개수를 강제하지 않는다.

**누락 검법**: 예산으로 중단한 each의 rows_requested = rows_processed + rows_unprocessed, rows_processed = ok_count + error_count를 확인한다. 예산 중단은 성공이 아니다. 완료한 쓰기를 반복하지 말고 미처리 입력만 분할한다. 필터 연산자는 startswith이며 starts_with는 없다. 숫자 개수·중복 검사는 코드로 하고 AI는 내용 판단에 쓴다.

### 2-6. 저장·배포 순서
**관용구 `committed`는 1~3번을 완료한 상태다.** 반환 본문·검수 근거·건수를 확인하고 4번으로 간다. 아래 1~3번은 수동 경로의 저장 순서이며, 그 경우도 내용 검수 후 반영한다. `reviewed_draft`나 실패 상태에서 배포로 넘어가지 않는다.

1. `_covered_videos.json` upsert — 오늘 날짜 확인한 영상 **전부**(선정·탈락·quota) + `recent_topics` 10건 롤링. 행은 소스에서 팬아웃해 파일로 고정하고 `args_file`로. **검법: 날짜 확인 편수 == 오늘 날짜로 기록된 원장 행수**(08-27: 24/25만 적혀 가장 신선한 편이 빠졌다).
2. `db/tips.json` append(오늘 팁). 머리줄 M·K는 갱신 **후** 원장에서 센다(§3).
3. 보고서 md 저장(`files`/`files_from` 경유 — 긴 본문을 도구 호출 JSON에 인라인하지 않는다).
4. `보고서HTML`로 공유판 생성 — `links`·`dropped_lines` 검산(§0). 감독 턴에서는 `publication_pending` 초안이며 `items.path`의 비공개 파일이 검수 대상이고 `public_target`은 승인 후 공개될 위치다.
5. `[self:notify_user]` 공개 대상의 절대경로 + TL;DR을 한 번 등록한다. 감독 턴의 알림은 `queued_for_review` 상태로 대기한다.
6. 의식이 실제 초안·원장·알림 수치를 검수한다. 승인 뒤 하네스가 검수한 HTML 바이트를 공개하고 알림을 전달한다. 미승인·취소 시 초안을 남기며 공개·알림은 보류한다. 본문을 다시 쓰거나 승인 알림을 재호출하지 않는다.

### 2-7. 장애 로그와 실측 기록
검색·자막이 전멸하면(낡은 yt-dlp가 조용히 죽는 부류) `[self:ledger]{path:"outputs/ai_tips_reports/_scan_log.json", op:"append", item:{date:"YYYY-MM-DD", reason:"...", retry:"다음 날"}, max_items:60}` 후 종료. **새 실측(검색어 처방·주제 특성·도구 마찰)은 가이드가 아니라 `docs/YOUTUBE_TIPS_FIELD_NOTES.md` 끝에 덧붙인다** — 같은 처방이 세 번 반복되면 그때 §2-2~2-4의 규칙으로 승격한다. 도구·어휘 결함은 실측 기록이 아니라 수리 경로(자기수정)로 보낸다.

## 3. 보고서 출력 형식
**머리줄 정의(고정)**: `M` = 팁 누적 = `db/tips.json` 길이. `K` = 다룬 영상 = 원장 `covered` 중 **`verdict`가 `tips_`로 시작하는 것만**. 탈락분(`too_old`·`no_tips`·`no_transcript`·`quota`·`not_selected`·`retracted`)은 K가 아니다 — 총수는 괄호로 병기: `다룬 영상 103편(후보 등재 585편)`.

```markdown
# 유튜브 AI 팁 보고서 — YYYY-MM-DD — <주제>
> 오늘의 영상 N편 · 누적: 팁 M개 / 다룬 영상 K편(후보 등재 T편)

## 한눈에 (TL;DR)
- (오늘 최고의 팁 2~3개 — 교차 확인·정면 대립이 있으면 여기)

## 오늘의 팁
### 1. <동사로 끝나는 실행형 제목>
- **방법**: (단계·프롬프트 예문·설정 — 이것만 읽고 따라할 수 있게)
- **출처**: [영상 제목](URL) — 채널 · MM:SS
- **보정**: (과장 간극·홍보성·주의점. 없으면 생략)
- **우리 시스템 함의**: (md 원본에만 — 이미 함/이식 후보/해당 없음)

## 시도 후보
- (그날 것 2~3개까지. 없으면 절 생략. 누적·"부채" 금지)

## 오늘의 영상
- [제목](URL) — 채널 · 조회수 · 길이 · 한줄평(팁 밀도·과장)

## 지켜볼 점 / 내일 주제 후보
## 이 호의 한계
- (자막만 읽음 · 날짜 확인 N편 중 통과 M편 · 정독은 그중 몇 편 · 안 읽은 이유)
```
**분량은 수확에 비례** — 팁이 적은 날은 짧은 호가 정상이다.

## 4. 원장·DB 스키마
