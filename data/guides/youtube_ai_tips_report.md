# 유튜브 AI 팁 보고서

주제에 맞는 최근 유튜브 영상 몇 편을 골라 자막을 읽고, 써볼 만한 팁을 한국어 보고서로 정리한다. 기본 흐름은 **영상 선정 → 팁 추출 → 보고서 작성**이다.

## 1. 주제와 영상 고르기

- 최근 보고서의 다음 주제 후보나 사용자의 요청으로 주제를 정한다. 같은 주제를 계속 돌지 않는다.
- 한국어·영어 검색어 2~3개로 찾아 보통 2~4편을 고른다. 후보가 부족하면 적은 편수로 작성해도 된다.
- `sense:video`의 `op:"info"`로 업로드 날짜가 기준일의 **180일 이내**인지 확인한다. 제목에 적힌 연도는 날짜 근거가 아니다.
- `_covered_videos.json`에 있는 영상 ID는 다시 사용하지 않는다. **다른 영상의 팁이 과거 팁과 같아도 괜찮다.** 누적 팁 의미 비교는 하지 않는다.
- 주제 적합성·구체적인 설명·출처·최근성을 보고 고른다. 채널과 조회수·독자 반응도 참고하되, 인기만으로 정확성을 단정하지 않는다. 초보자용 튜토리얼도 좋은 자료다. 1시간 넘는 영상은 가급적 한 편 이하로 한다.

## 2. 자막 읽고 팁 뽑기

선정한 영상의 자막을 `sense:video`의 `op:"transcript"`로 읽는다. 영상 화면을 본 것처럼 쓰지 않는다.

- **한 번 읽을 때 제목과 방법을 함께 뽑는다.** 실행할 단계·설정·명령·프롬프트 예문을 구체적으로 적는다.
- 보통 영상당 2~5개지만 할당량은 아니다. 쓸 만한 팁이 없으면 빼고, 숫자를 채우지 않는다.
- 과장된 효과는 낮춰 표현하고, 자막만으로 알 수 없는 부분은 빼거나 주의점으로 적는다. 도구명·옵션을 추측해서 보충하지 않는다.
- 모든 팁에 **영상 출처 링크**를 붙인다. 인용문이나 초 단위 시간은 필수가 아니다. 직접 인용을 쓰고 싶을 때만 원문 문구를 확인한다.
- 긴 자막은 입력 크기에 맞춰 순서대로 나누어 읽는다. 이미 읽은 원문을 다시 색인하거나 별도의 내용 심사에 보내지 않는다.

## 3. 보고서 쓰기

추출한 팁 중 쓸 만한 것을 골라 이번 보고서 안의 반복을 정리한다. 대체로 5~12개면 충분하며, 수확이 적으면 짧게 쓴다. 별도의 검수 AI나 재작성 심사 없이 작성 단계에서 내용과 표현을 정리한다.

```markdown
# 유튜브 AI 팁 보고서 — YYYY-MM-DD — <주제>
> 자막을 읽은 영상 N편 · 이번 팁 L개 · 누적: 팁 M개 / 다룬 영상 K편

## 한눈에
오늘 건질 만한 내용을 짧게 정리한다.

## 오늘의 팁
### 1. <팁 제목>
- **방법**: 따라할 단계·설정·예문
- **출처**: [영상 제목](URL) — 채널
- **주의점**: 필요한 경우만
- **우리 시스템 함의** (편집자 해석): 사용자 환경에 적용해볼 점

## 오늘의 영상
영상 링크·채널·업로드 날짜, 확인된 반응 지표

## 다음 주제 후보
필요한 경우 한 가지

## 이 호의 한계
자막만 읽었으며 화면과 실제 효과는 직접 확인하지 않았다.
일부 자료를 읽지 못했다면 그 범위를 적는다.
```

사용자는 Claude Code·IndieBiz OS를 사용하는 고급 사용자다. 적용 아이디어는 편집자 해석으로 쓰고, 실제 시스템에 이미 구현됐는지는 추측하지 않는다. 시도 여부는 사용자가 선택한다. 실험 부채나 후속 실험을 만들지 않는다.

## 4. 관용구로 실행하기

등록 관용구 **`AI팁보고서쓰기`**를 한 번 호출한다. 주제 준비부터 공유창고 저장까지 관용구가 끝낸다.

```ibl
[fn:AI팁보고서쓰기]{}
```

- 기본값은 오늘 날짜·기존 보고서 폴더·전날까지 최근 보고서의 다음 주제 후보(없으면 코딩)·현재 독자 맥락이다. 원장이나 최근 보고서를 밖에서 먼저 열 필요가 없다.
- 주제를 지정하려면 `{설정:{topic:"평가",reader_context:"AI·LLM 평가를 실제 오류 사례에 적용"}}`처럼 호출한다. `date`, `root`, `share_root`, `run_id`도 필요한 때만 지정한다.
- 기본 `mode:"commit"`은 로컬 보고서·팁 DB·영상 원장과 공유창고 HTML을 모두 저장한다. 초안만 필요하면 `mode:"draft"`를 쓴다.
- 반환 `value`의 `status`, `summary`, `report`, `shared_report`, `new_tips`로 결과를 전달한다. `completed`는 공유판까지 저장 완료, `draft`는 초안, `publication_pending`은 감독 하네스의 공개 대기다.
- 같은 설정으로 재호출하면 완료한 단계·추출 구간을 재사용한다. 공유 저장만 실패했다면 공유 저장만 재개한다. 설정을 바꾸거나 같은 날 다른 회차를 만들 때는 새 `run_id`를 준다. 현재 상태 판본은 v5다.

본문 재열람·수동 원장 갱신·별도 HTML 변환으로 완료 절차를 반복하지 않는다. 내부 구현은 `docs/AI_TIPS_REPORT_IDIOM.md`에 있으며 일상 실행 때 읽을 필요는 없다.

## 5. 실패는 작게 처리하기

검색 하나가 실패하거나 영상 하나의 자막이 없으면, 읽을 수 있는 나머지 자료로 진행하고 한계를 적는다. 팁 추출의 일부 구간이 실패해도 얻은 팁을 사용할 수 있다. 개별 자료 실패를 보고서 전체 실패로 확대하지 않는다.

모든 자료를 읽지 못했거나 쓸 팁이 전혀 없으면 그 사실을 보고한다. 보고서를 지어내지 않는다. 저장 실패·원장 충돌은 저장 완료로 보고하지 않는다. 자동으로 심사·보완을 반복하지 않는다.

## 6. 저장과 공유

- 보고서: `outputs/ai_tips_reports/ai_tips_report_YYYY-MM-DD_<주제>.md`
- 팁 누적: 같은 폴더의 `db/tips.json`
- 다룬 영상: `_covered_videos.json` · 최근 주제는 `recent_topics`에 보관

- 공유판: `공유창고/0/AI 팁들/AI 팁 보고서 <날짜> <주제>.html`

공유판은 기존 `보고서HTML` 렌더러로 만들며 개인적인 ‘우리 시스템 함의’와 개인 맥락의 요약을 제거한다. 기존 호를 덮어쓰거나 `/r/`에 발행하지 않는다. 반환된 경로·요약을 사용자에게 한 번 전달하면 끝이다. 별도 알림 전송은 요청받은 경우에만 한다. 감독 턴의 공개 대기 처리는 하네스에 맡긴다.

관용구 수리나 초안 작성 요청만 받았다면 운영 보고서 작성·공유·알림을 새로 시작하지 않는다.
