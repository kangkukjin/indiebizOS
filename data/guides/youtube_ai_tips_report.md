# 유튜브 AI 팁 보고서 가이드 (YouTube AI Tips Report)

유튜브에 넘치는 "AI 활용법" 콘텐츠를 **매일 조금씩(2~4편) 골라 자막으로 읽고, 실행 가능한 팁으로 증류해 누적하는 일간 보고서**다.

> **원리 = 영상을 보지 않는다.** 유튜브 영상의 팁은 거의 전부 말(자막)에 산다. `[sense:video]{op: "transcript"}`로 자막만 뽑아 읽으면 15분 영상이 몇 천 토큰이다. 화면 시연만 있고 말로 설명 안 된 부분은 "영상 확인 필요"로 정직하게 남긴다.
>
> **누적이 자산이다.** 보고서는 그날의 기록이고, 팁 DB(`db/tips.json`)와 다룬 영상 원장(`_covered_videos.json`)이 쌓여가는 자산이다 — 부동산 보고서의 순회 DB와 같은 원리. 같은 영상을 두 번 다루지 않고, 같은 팁의 재탕은 "이미 수집(날짜)"로 갈음한다.

## 1. 무엇을 팁으로 치는가 — 증류 헌법

이 보고서의 품질은 여기서 결정된다. 유튜브는 과장의 문법("상위 1%만 아는", "업무 시간 99% 절감")으로 말한다 — **껍질을 벗기고 알맹이만 증류한다.**

1. **실행 가능해야 팁이다.** 단계·도구 이름·프롬프트 예문·설정 방법이 있는 것만. "AI를 적극 활용하세요" 같은 덕담·마인드셋 설교는 팁이 아니다 (영상 전체가 덕담이면 그 영상은 "팁 없음"으로 원장에 남기고 보고서에서 뺀다).
2. **과장 보정.** 제목·썸네일의 주장("10배", "99%")과 실제 내용의 간극을 한 줄로 짚는다. 특정 유료 도구 홍보·협찬 냄새가 나면 `[홍보성]` 표시.
3. **실측 아님을 명시.** 자막만 읽고 쓰는 것이므로 팁의 실효는 검증 전이다. 따라해 볼 가치가 특히 큰 것만 **"시도 후보"**로 그날 호에 2~3개까지 적는다 — 가벼운 제안이지 과제가 아니다. **★시도 후보는 그날 호 안에서 끝난다 (사용자 지시 2026-08-13)**: 이전 호 후보를 세어 누적 개수를 집계하거나, "미검증 부채"·"검증 0건"·"실험이 증류를 못 따라간다" 같은 표현으로 실험을 재촉하거나, "부채를 갚는 호"를 제안하지 않는다. 팁을 시스템에 적용할지는 전적으로 사용자의 선택이며, 사용자가 실제로 해본 결과를 알려준 경우에만 후속 호에서 그 결과를 언급한다.
4. **사용자 맥락 함의.** 사용자는 Claude Code·IndieBiz OS를 쓰는 고급 사용자다. 팁마다 "이미 우리가 하는 것 / 우리 시스템에 이식할 만한 것 / 해당 없음"을 한 줄로 (md 원본에만, §0).
5. **출처 정직.** 팁마다 영상 제목·채널·URL·타임스탬프(자막에서 추정 가능하면)를 단다. 이 세션에서 실제 자막을 읽은 영상만 인용한다 — 날조 금지.

## 2. 매일 절차

> ⚠️ **파이프라인 금지.** 검색·자막·작성을 `>>`로 엮지 않는다. 하나씩 호출하고 읽고 판단한다 (`deep_research.md` 원칙).

### 2-1. 원장 읽기

```
[self:read]{path: "/Users/kangkukjin/Desktop/AI/indiebizOS/outputs/ai_tips_reports/_covered_videos.json"}
```
- 다룬 영상 ID 목록(중복 방지)과 `recent_topics`(최근 주제 10개 롤링)를 파악한다. 없으면 첫 작성.

### 2-2. 오늘의 주제 선정 (한 단어)

최근 주제와 겹치지 않게 하나 고른다. 주제 풀 (로테이션 — 고정 큐가 아니라 참고 풀, 그날 검색에서 발견되는 흐름·새 도구 출시를 따라 벗어나도 된다):

`프롬프트 / 자동화(업무·n8n·Make) / 코딩(바이브코딩) / 이미지생성 / 영상제작 / 글쓰기(블로그·책) / 자료조사(리서치·요약) / 에이전트 / 문서업무(엑셀·PPT·보고서) / 학습(공부·영어) / 생활 / 마케팅(SNS·쇼츠) / 신도구(새로 나온 것)`

- 사용자가 특정 주제를 지목하면 그날은 그 주제 (풀보다 우선).

### 2-3. 검색·선정

```
[sense:search_youtube]{query: "<주제> AI 활용법", count: 12}
```
- 쿼리 2~3개를 변주한다 (주제 + "활용법"/"꿀팁"/"프롬프트"/구체 도구명). **한국어·영어 쿼리를 병행한다** (예: 한국어 1개 + 영어 1~2개 — "prompt engineering tips" / "Claude Code workflow" 등). ★조사 대상은 언어·국가 무관 — **보고서만 한국어**다 (§2-5). AI 팁의 원천은 대부분 영어권이고 한국 채널은 그걸 며칠~몇 주 뒤 중계하는 경우가 많다: 원천으로 직접 가면 더 신선하고 밀도가 높으며, 6개월 규칙과도 궁합이 좋다. 같은 팁이 영어 원본과 한국어 중계판 양쪽에서 잡히면 원본을 출처로 삼는다.
- **선정 2~4편**: ①원장에 있는 영상 제외 ②★**6개월 규칙 (하드 필터, 사용자 지시 2026-08-12)**: 후보마다 `[sense:video]{op: "info", video_id: "..."}`로 `upload_date`(YYYYMMDD)를 확인해 **오늘 기준 180일 초과는 탈락** — 낡은 영상은 시대에 뒤진다(AI 도구는 반년이면 세대가 바뀐다). 검색 결과에는 날짜가 안 실리므로 **이 확인을 생략하면 안 된다**(창간호 실측: 확인 없이 고른 3편이 전부 6개월 초과, 하나는 2023년 영상이었다). 탈락 영상은 원장에 `too_old`로 기록해 재검토 낭비를 막는다 ③조회수·제목의 구체성(구체적 도구·방법 언급 = 팁 밀도 예상) ④1시간 이상 긴 영상은 하루 1편까지. 뉴스 보도·단순 시연은 후순위.

### 2-4. 자막 추출·통독

```
[sense:video]{op: "transcript", video_id: "<id>", language: "ko"}
```
- 영상의 언어에 맞게 뽑는다 (한국어 영상=ko, 영어 영상=en — ko를 먼저 시도하고 없으면 en). **자막이 아예 없는 영상은 건너뛰고** 원장에 `no_transcript`로 기록한다 (다시 시도하지 않게).
- 자동 생성 자막의 오탈자는 감안하고 읽는다 (도구 이름이 뭉개지면 검색으로 교차 확인).

### 2-5. 증류·작성

- §1 헌법대로 영상당 팁 2~5개를 증류한다. **영상 요약이 아니라 팁 추출이다** — 영상 구조를 따라가지 말고 팁 단위로 재조직한다.
- **보고서는 영상의 언어와 무관하게 전부 한국어로 쓴다.** 영어 영상의 팁은 번역해 증류하되, 도구 이름·프롬프트 예문·메뉴 경로는 원문 그대로 싣는다 (프롬프트를 번역하면 따라할 수 없게 된다 — 필요하면 한국어 설명을 병기).
- `db/tips.json`과 대조해 이미 수집한 팁의 재탕이면 새 항목을 만들지 말고 보고서에 "이미 수집(날짜·호)" 한 줄로.

### 2-6. 저장 순서 (원장 먼저 — 보고서가 실패해도 데이터는 남게)

1. `_covered_videos.json` upsert (오늘 다룬·건너뛴 영상 전부 + `recent_topics` 10개 롤링)

5. `[self:notify_user]`로 저장 경로(절대경로)와 TL;DR 알림

yt-dlp 검색·자막이 전멸하면 (유튜브 정책 변화로 낡은 yt-dlp가 조용히 죽는 부류 — 2026-08-04 실측 선례) `_scan_log.md`에 한 줄 append 후 종료:

## 4. 원장·DB 스키마

`_covered_videos.json`:
```json
{
  "covered": [
    {"id": "<video_id>", "title": "...", "channel": "...", "date": "YYYY-MM-DD",
     "upload_date": "YYYYMMDD", "topic": "프롬프트",
     "verdict": "tips_3|no_tips|no_transcript|too_old|too_long_skipped"}
  ],
  "recent_topics": [{"date": "YYYY-MM-DD", "topic": "프롬프트"}]
}
```
- **upsert 기준 = video_id.** 건너뛴 영상(`no_transcript`·`no_tips`)도 기록한다 — 재시도 낭비 방지.
- `recent_topics`는 최근 10건 롤링.

`db/tips.json` (append-only 배열):
```json
[
  {"tip": "팁 제목", "how": "방법 요약 한두 줄", "topic": "프롬프트",
   "source": {"video_id": "...", "title": "...", "channel": "...", "url": "..."},
   "date": "YYYY-MM-DD", "report": "ai_tips_report_YYYY-MM-DD_프롬프트.md",
   "try_candidate": false}
]
```
- 이 DB가 쌓이면 "지금까지 모은 프롬프트 팁 전부" 같은 질의·통합 리포트의 원천이 된다.
