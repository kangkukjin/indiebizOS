# 세계의 지도 — 지식으로 가는 구조적 어휘 카탈로그

IBL의 어휘는 도구를 가리키고, IBL 문장은 도구를 조합해 일을 한다. 세계의 지도는 관련 지식을
떠올리거나 검색할 이름을 공급한다. 방법과 도구뿐 아니라 세계를 이해하는 개념도 그 입구다.
지도에 있다는 것과 이 몸에 설치·연결되어 있다는 것은 별개의 사실이다.
도서관의 카탈로그처럼 분야·개념·방법·도구·자료원의 이름과 구별·연결을 보존한다.
지식 본문을 복제하지 않는다. 항목별 설명을 늘리기보다 빠진 분야의 입구를 보강한다.
세계의 통용 수단과 충실히 접촉하는 것이 목표다. 이미 적절한 접근을 유지하며,
새로움·대안·관점 전환을 의무로 삼지 않는다. 직접 구현이 학습 목적이면 그 목적을 존중한다.

## 지도를 그리는 단위

`world.yaml`과 fragments의 각 항목은 **알아볼 수 있는 이름 → 짧은 뜻과 구별 → 위치와 연결**을 담는다.
도구·라이브러리·프로토콜뿐 아니라 이름 붙은 알고리즘·분석법·설계 방법도 이 형식에 들어갈 수 있다.
자료원도 자료를 얻고 비교하는 수단으로서 포함한다. 현재 목록은 기존 도구 지도에서 시작한 첫 범위다.

| 필드 | 편집 기준 |
|---|---|
| `name` | 모델이 해당 지식을 떠올릴 수 있는 통용 이름. 새 이름을 임의로 만들지 않는다. |
| `hint` | 개념의 뜻과 인접 개념과의 구별을 한 줄로 쓴다. 방법·도구는 대상·연산·결과를 드러낸다. |
| `aliases` | 이름을 모르는 사용자가 말할 작업·상황·입력·산출물 표현. 넓은 주제어만으로 채우지 않는다. |
| `path` | 이름을 몰라도 분야에서 내려가며 찾아갈 편집 분류. 개념의 분야 또는 방법의 목적·작업을 드러낸다. |
| `source` | 이름·기능·적용 조건을 확인할 근거. 상세 통로와 한계는 원본에서 확인한다. |

예: ‘제약이 많은 인원 배정’ → `OR-Tools` → ‘제약을 만족하는 배치·일정 최적화’.
structure 모드는 이름과 검토된 관계를 짧게 전달한다. 관계 없는 어휘는 분류와 이름으로 표시한다.
뜻·근거·해시는 검색과 내부 기록·상세 조회에 남긴다. names 모드는 분류와 이름만 전달한다. 설치·호출 통로는 필요할 때 가이드에서 읽는다.
version 2의 fragments에 관계와 추가 노드를 분리하고, 종류 미검토 항목은 term으로 보존한다.
분류 path를 일반화 관계로 자동 바꾸지 않는다. 근거 문서 변경은 재검토 대상으로 표시한다.

## 제대로 된 어휘를 주는가

평가 질문은 전문용어를 숨긴 **실제 질문과 작업**으로 만든다. 허용 집합은 관련 지식에 이르는 어휘다.

- 그 이름을 받으면 질문을 이해하고 작업할 관련 지식이 떠오르는가?
- 주제만 비슷하고 해당 연산은 못 하는 도구가 섞이지 않는가?
- 조건이 다른 유사 작업을 구별하는가? 예를 들어 표 추출·문서 변환·스캔 OCR을 같은 일로 보지 않는다.
- 다른 분야의 유용한 방법과 주제 전환을 놓치지 않는가?
- 실제 응답에서 방법 선택·결과가 나아지는가? 이름 언급·도구 호출 횟수만으로 성공 처리하지 않는다.

현재 선택기는 이름·별칭·설명의 로컬 어휘 검색이다. 위 기준을 자동으로 이해하는 의미 판단기가 아니다.
우선 질문→방법의 대응과 잘못 섞인 후보를 검토해 사전을 고치고, 남는 누락을 근거로 검색 개선을 판단한다.
알려진 정답을 모두 통과시키는 별칭 추가만으로 품질이 검증됐다고 하지 않는다.

## 운영

사용자·모델에 보이는 이름은 **세계의 지도**, 호환 주입 블록은 `<method_map>`이다.
기존 설정·사건·파일 경로의 `knowledge_catalog`는 호환성을 위해 유지한다.
정본을 편집한 뒤 `scripts/build_knowledge_catalog.py`로 색인을 만들고 `--check`로 검증한다.
전체 지도 크기와 턴마다 추출하는 작은 조각의 크기는 별개다. 기본으로 모든 작업 에이전트가 받는다.
자동 주입은 이름과 핵심 연결이며 설명과 상세 근거는 open에서 연다.
상세 구조·추출 상한·회귀 기록은 [구조 구현 계약](../../docs/WORLD_MAP_STRUCTURE_PLAN_2026_09_17.md)에 있다.

## 충실도 감사

[과제별 감사](../../docs/METHOD_MAP_AUDIT_2026_09_16.md)는 등재 공백과 검색 공백을 나눠 기록한다.
[고정 질문](audit_cases.json)과 `scripts/audit_method_map.py`로 기준판과 현재판을 다시 비교할 수 있다.
추가 확인용 질문에 맞춰 별칭을 보완하지 않으며, 다음 개선에서는 새로운 질문으로 일반화를 확인한다.
이름 선택의 성공과 실제 작업 결과의 개선은 별도로 판단한다.

전체 목록·분야·ID·이웃·조상은 등록 스크립트 `세계지도`로 열람한다.
이름을 모르면 `browse`의 빈 path에서 시작해 category 행의 browse로 내려간다.
분류는 편집상 위치이며 같은 분야의 어휘가 서로 대체 가능하다는 뜻이 아니다.
`bridges.yaml`의 여러 분야 입구와 `bridge_relations.yaml`의 참조는
[근거 노트](../../docs/world_map/H_catalog_bridges.md)에 확인 범위를 기록한다.
[사용법](../guides/world_map.md), [관계 근거](../../docs/world_map/G_structure_evidence.md)를 참고한다.
`evaluation.yaml`과 `scripts/evaluate_world_map.py`는 검색·문맥의 개발 회귀용이다.
모델 응답 품질 비교는 지도 없음/이름/구조의 동일 과제 실험으로 별도 판정한다.
