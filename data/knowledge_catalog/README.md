# 세계의 지도 — 지식으로 가는 구조적 어휘 카탈로그

IBL의 어휘는 도구를 가리키고, IBL 문장은 도구를 조합해 일을 한다. 세계의 지도는 관련 지식을
떠올리거나 검색할 이름을 공급한다. 방법과 도구뿐 아니라 세계를 이해하는 개념도 그 입구다.
지도에 있다는 것과 이 몸에 설치·연결되어 있다는 것은 별개의 사실이다.
도서관의 카탈로그처럼 분야·개념·방법·도구·자료원의 이름과 구별·연결을 보존한다.
지식 본문을 복제하지 않는다. 항목별 설명을 늘리기보다 빠진 분야의 입구를 보강한다.
세계의 통용 수단과 충실히 접촉하는 것이 목표다. 이미 적절한 접근을 유지하며,
새로움·대안·관점 전환을 의무로 삼지 않는다. 직접 구현이 학습 목적이면 그 목적을 존중한다.

## 지도를 그리는 단위

`world.yaml`과 fragments의 각 항목은 **알아볼 수 있는 이름 → 짧은 뜻과 구별 → 위치와 연결**을 담는다.
도구·라이브러리·프로토콜뿐 아니라 이름 붙은 알고리즘·분석법·설계 방법도 이 형식에 들어갈 수 있다.
자료원도 자료를 얻고 비교하는 수단으로서 포함한다. 현재 목록은 기존 도구 지도에서 시작한 첫 범위다.

| 필드 | 편집 기준 |
|---|---|
| `name` | 모델이 해당 지식을 떠올릴 수 있는 통용 이름. 새 이름을 임의로 만들지 않는다. |
| `hint` | 개념의 뜻과 인접 개념과의 구별을 한 줄로 쓴다. 방법·도구는 대상·연산·결과를 드러낸다. |
| `aliases` | 이름을 모르는 사용자가 말할 작업·상황·입력·산출물 표현(**일상 한국어**). 번역어·약어도 여기. 넓은 주제어만으로 채우지 않는다. |
| `path` | 이름을 몰라도 분야에서 내려가며 찾아갈 편집 분류. 개념의 분야 또는 방법의 목적·작업을 드러낸다. |
| `source` | 이름·기능·적용 조건을 확인할 근거. 상세 통로와 한계는 원본에서 확인한다. |

예: ‘제약이 많은 인원 배정’ → `OR-Tools` → ‘제약을 만족하는 배치·일정 최적화’.
structure 모드는 이름과 검토된 관계를 짧게 전달한다. 관계 없는 어휘는 분류와 이름으로 표시한다.
뜻·근거·해시는 검색과 내부 기록·상세 조회에 남긴다. names 모드는 분류와 이름만 전달한다. 설치·호출 통로는 필요할 때 가이드에서 읽는다.
version 2의 fragments에 관계와 추가 노드를 분리하고, 종류 미검토 항목은 term으로 보존한다.
분류 path를 일반화 관계로 자동 바꾸지 않는다. 근거 문서 변경은 재검토 대상으로 표시한다.

## 제대로 된 어휘를 주는가

평가 질문은 전문용어를 숨긴 **실제 질문과 작업**으로 만든다. 허용 집합은 관련 지식에 이르는 어휘다.

- 그 이름을 받으면 질문을 이해하고 작업할 관련 지식이 떠오르는가?
- 주제만 비슷하고 해당 연산은 못 하는 도구가 섞이지 않는가?
- 조건이 다른 유사 작업을 구별하는가? 예를 들어 표 추출·문서 변환·스캔 OCR을 같은 일로 보지 않는다.
- 다른 분야의 유용한 방법과 주제 전환을 놓치지 않는가?
- 실제 응답에서 방법 선택·결과가 나아지는가? 이름 언급·도구 호출 횟수만으로 성공 처리하지 않는다.

선택기는 둘이다(2026-09-17). 글자 채널 = 이름·별칭·설명의 로컬 어휘 검색(`<method_map>`), 의미 채널 = 가지 사전 `branches.yaml` 로 가지를 먼저 고르는 임베딩 회상(`<world_map>`·`<world_memory>`, 정본 `docs/TREE_MEMORY_RECALL_COMMON_DESIGN_2026_09_17.md`). 어느 쪽도 위 기준을 자동으로 이해하는 의미 판단기가 아니다 — 관련성 판단은 받는 AI 의 몫이다.
**가지 사전**: 가지(분류 경로 앞 두 단)마다 `cues`(찾는 말 — 일상 표현)·`gist`(요약)·`see_also`(함께 볼 가지). 어휘를 옮기거나 가지를 합치면 같이 고친다 — `backend/test_tree_recall.py` 가 사전과 트리의 어긋남을 잡는다. 회상 색인은 `scripts/build_recall_index.py`(평소엔 회상이 스스로 동기화).
**가지는 분야→하위 분야 한 축이다**(2026-09-18 정비: 167→67가지, 단독 가지 0). 도구·개념·방법을 다른 가지로 가르지 않는다 — 도구는 그것이 섬기는 방법의 가지에 둔다(OpenFOAM 은 `계산/공학` 이 아니라 전산유체역학이 있는 `공학/기계와 제작`). 1~2항목 가지는 만들지 않고 이웃 가지에 넣는다. ID 는 두고 `path` 만 고친다. `build_knowledge_catalog.py --check` 의 가지 관문이 사전↔트리 어긋남·요약 없는 가지는 실패로, 1~2항목 가지는 경고로 말한다.
우선 질문→방법의 대응과 잘못 섞인 후보를 검토해 사전을 고치고, 남는 누락을 근거로 검색 개선을 판단한다.
알려진 정답을 모두 통과시키는 별칭 추가만으로 품질이 검증됐다고 하지 않는다.

## 운영

사용자·모델에 보이는 이름은 **세계의 지도**, 호환 주입 블록은 `<method_map>`이다.
기존 설정·사건·파일 경로의 `knowledge_catalog`는 호환성을 위해 유지한다.
정본을 편집한 뒤 `scripts/build_knowledge_catalog.py`로 색인을 만들고 `--check`로 검증한다.
전체 지도 크기와 턴마다 추출하는 작은 조각의 크기는 별개다. 기본으로 모든 작업 에이전트가 받는다.
자동 주입은 이름과 핵심 연결이며 설명과 상세 근거는 open에서 연다.
상세 구조·추출 상한·회귀 기록은 [구조 구현 계약](../../docs/WORLD_MAP_STRUCTURE_PLAN_2026_09_17.md)에 있다.

## 넓은 어휘와 갱신

`atlas/*.yaml`은 인문·사회·예술·생활·자연과학·공학을 포함하는 분야별 편집 어휘다.
AI 일반 지식에서 작성한 편집 초안이며 모든 항목을 외부 문헌으로 개별 검증했다고 주장하지 않는다.
`source`의 [편집 원천](../../docs/world_map/I_atlas_editorial_2026_09_17.md)과
[관계 검토](../../docs/world_map/J_atlas_relations_2026_09_17.md)가 확인 범위를 구별한다.
분류는 모든 어휘를 찾는 구조이고, 명시 관계는 추가 검토한 연결만 갖는다.

1. 기존 한국어·영어 표제를 먼저 찾는다. 같은 개념의 번역·약어는 aliases로 더하고 ID를 유지한다.
2. 없는 개념이면 맞는 atlas 파일에 이름·종류·분류·짧은 검색 힌트·별칭·편집 출처를 추가한다.
   새 파일은 world.yaml의 fragments에 등록한다. 도구는 통용 방법의 분야에 배치한다.
3. 관련성이 없는 분야 단어를 별칭으로 늘리지 않는다. 검색 실패는 등재 공백과 표현 불일치로 나눈다.
4. 의미 관계는 별도 검토한다. 외부 확인과 편집상 연관을 구별하고, 근거 변경 시 재검토한다.
5. 색인을 다시 빌드하고 아래 진단 및 분야 탐색 검사를 실행한다. 폰 번들은 참조 자료까지 자동 파생한다.

```bash
.venv/bin/python3 scripts/build_knowledge_catalog.py
.venv/bin/python3 scripts/build_knowledge_catalog.py --check
.venv/bin/python3 scripts/audit_method_map.py --cases data/knowledge_catalog/atlas_audit_cases.json --presentation structure --output outputs/world_map/atlas_audit.json
.venv/bin/python3 scripts/build_body_bundle.py android
.venv/bin/python3 -m pytest backend/test_world_map_atlas.py backend/test_world_map_browse.py -q
```

### 일상 별칭은 눈가림으로 쓴다 (2026-09-18)

항목 텍스트가 이름 + 짧은 뜻 + 영어 번역어뿐이면 의미 회상이 표면 낱말에 휘둘린다("가게 장부" 질문에 `장부맞춤`). 전 항목에 일상 한국어 별칭 4개씩을 붙였다(5,043개, 항목당 평균 5.5개·한국어 별칭 없는 항목 0).
- **쓰는 쪽은 평가 질문을 보지 않는다.** 별칭 작성자는 `이름·뜻·분야`만 받고, 평가 질문 작성자는 `이름·뜻`만 받는다. 서로의 산출물을 못 본다 — 질문에 맞춘 별칭이 구조적으로 불가능하다.
- 별칭은 동의어가 아니라 **상황·증상·가진 것·원하는 것**이다. 이름과 뜻의 낱말을 되풀이하지 않고, 이웃 항목과 구별되게 쓴다. 기계 검사(`qc_aliases.py`)가 길이·영어·이름 재사용·여러 항목에 같은 별칭을 버린다.
- 새 항목을 넣을 때도 같은 규칙이다. 작성 도구와 기록 = `data/_backups/2026-09-18_world_memory_rebuild/`.
- 측정(눈가림 새 질문 40, 주입 3건에 표적이 든 수): 정비 전 12 → 가지 정비만 11 → **가지 정비 + 별칭 28**. 가지 @1 5→12, @2 12→18. 실제 사용자 발화 300건에서 글자 채널이 새로 끼어든 것 0.
- ★`docs/TREE_MEMORY_RECALL_COMMON_DESIGN` 부록 A 의 24문항은 가지 사전을 쓴 쪽이 이미 읽었다 — 더는 새 질문이 아니다. 평가는 매번 새 눈가림 질문으로(`evaluate_fresh.py`).

고정 진단 질문에 맞춰 별칭을 사후 보강한 경우에는 그 질문을 독립 평가로 세지 않는다.
이번 확장에는 예약 갱신이나 무검토 외부 어휘 수입을 추가하지 않았다.
캐시는 파일 내용이 같은 경우만 재사용하므로 편집은 다음 조회부터 반영된다.
확장 결과와 검색 공백은 [확장 보고서](../../docs/WORLD_MAP_ATLAS_EXPANSION_2026_09_17.md)에 기록했다.

## 충실도 감사

[과제별 감사](../../docs/METHOD_MAP_AUDIT_2026_09_16.md)는 등재 공백과 검색 공백을 나눠 기록한다.
[고정 질문](audit_cases.json)과 `scripts/audit_method_map.py`로 기준판과 현재판을 다시 비교할 수 있다.
추가 확인용 질문에 맞춰 별칭을 보완하지 않으며, 다음 개선에서는 새로운 질문으로 일반화를 확인한다.
이름 선택의 성공과 실제 작업 결과의 개선은 별도로 판단한다.

전체 목록·분야·ID·이웃·조상은 등록 스크립트 `세계지도`로 열람한다.
이름을 모르면 `browse`의 빈 path에서 시작해 category 행의 browse로 내려간다.
분류는 편집상 위치이며 같은 분야의 어휘가 서로 대체 가능하다는 뜻이 아니다.
`bridges.yaml`의 여러 분야 입구와 `bridge_relations.yaml`의 참조는
[근거 노트](../../docs/world_map/H_catalog_bridges.md)에 확인 범위를 기록한다.
[사용법](../guides/world_map.md), [관계 근거](../../docs/world_map/G_structure_evidence.md)를 참고한다.
`evaluation.yaml`과 `scripts/evaluate_world_map.py`는 검색·문맥의 개발 회귀용이다.
모델 응답 품질 비교는 지도 없음/이름/구조의 동일 과제 실험으로 별도 판정한다.
