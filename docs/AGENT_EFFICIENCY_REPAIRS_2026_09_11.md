## 영상 제작의 실행 계약

1. 원문·원고와 선택한 디자인으로 내용을 작성한다. 동일 디자인의 장들은 HTML 틀과 장별 JSON을 `슬라이드틀적용`에 넘길 수 있다. 렌더는 모델 호출 없이 이루어지고 동일 입력·PNG 지문은 재사용한다. 기존 슬라이드 노트는 보존한다.
2. `영상제작파이프라인`의 `mode=inspect`로 정본 원고·덱 순서·선택 음성·인사말·참고 파일·제작법을 확인한다. 제작이나 모델 호출은 없다. 반환하는 `supervision_checkpoint`는 감독이 제작 전에 원문의 논지·대안·인칭·분량을 확인할 수 있는 경계다. 이 점검 자체가 의미 검수 합격을 뜻하지 않는다.
3. 같은 인자와 `manifest_hash`를 지정해 `mode=run`한다. 원고→노트→변경 장 음성→인사말 결합→기존 영상 렌더→음량 측정을 프로그램이 수행한다. 원고·목소리 파일·옵션·스크립트 버전이 달라진 음성만 재생성한다. 같은 덱의 중복 실행은 잠금으로 차단한다.
4. 완료 단계는 출력 지문과 함께 남기고 재실행 시 재사용한다. 원천 입력이 제작 중 바뀌면 완료 결과를 보존하고 중단한다. TTS 작업의 PROGRESS를 전달하고 부분 실패나 자원 정리 실패를 완료로 보고하지 않는다.
5. 측정 결과는 길이·음량·파일 정합성의 근거다. 실제 의미·발음·문장 끝·시청각 품질은 필요한 원문과 `sense:listen`/이미지 근거로 검수한다. 음성 엔진·사용자 목소리·디자인을 비용 때문에 자동 하향하지 않는다.

제작법은 `data/recipes/narrated_video_v1.json`, 사용법은 `data/guides/video_workflow.md`에 있다. 새 영상 전용 어휘나 인지 코어 분기는 추가하지 않았다. 실강 녹음 타임라인이 있는 덱은 복제 음성 파이프라인으로 진행하지 않아 녹음 우선 렌더와의 혼선을 막는다.

## 비용 제어의 의미와 한계

의식의 소프트 몫은 탐색을 멈추고 판단을 회수하는 제어값이다. 실제 전체 작업 한도와 다르다. 사용자가 설정한 `world_pulse_config.json.agent_resource_limits`의 `hard_token_limit`, `deadline_s`는 실행·의식·내부 호출이 공유한다. 기본은 둘 다 미설정이다. 캐시 포함 입력+출력 토큰의 관측량이지 과금액이 아니다.

CLI 내부의 모델 왕복은 CLI가 소유한다. 현재 구현은 호출/도구 경계의 입장 제어와 사용량 관측 이후 취소이며, 보이지 않는 개별 API 요청을 정확히 사전 제한한다고 주장하지 않는다. 보완 재검수 예상량도 추정이다. 중단 출력의 실제 전체 사용량을 알 수 없을 때에는 부분 측정으로 표시한다.

보완 문맥 비교는 `문자 수 / 2`, 캐시 읽기 가중치 0.1의 입력 작업량 휴리스틱이다. 실제 모델 가격·속도 예측이 아니며 불확실하거나 백그라운드 작업이 있으면 기존 문맥을 유지한다. 계획의 조건부 P2인 **일반 실행 도중 임의 세션 교체**는 적용하지 않는다. 먼저 불필요한 유입과 보완 경계를 고친 뒤 실제 주행으로 추가 필요성을 판정한다.

검수 증거는 모델이 실제 확인한 범위를 기록한 것이다. 파일 지문 비교가 검수의 의미적 정확성을 증명하지 않는다. 검사기 코드 변경 자동 무효화는 `validator_paths`에 실제 검사 파일을 기록한 경우에 적용된다. 수정한 주장과 연결된 요약·수치·개수·유일성·출처·인과 관계는 재검수 계약에 계속 남는다.
