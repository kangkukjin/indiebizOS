# 자율주행 도구 원샷 차단 실험

2026-09-08. 사용자 요청: 자율주행에서 원샷 AI를 막아 두고 사용자가 앱에서 보고서를 직접 실행해 비교한다. 보고서는 이 작업에서 시작하지 않았다.

## 현재 설정과 되돌리기

이 맥의 `data/agent_tool_policy.json`을 다음으로 설정했다:

```json
{"allow_agent_tool_oneshot": false}
```

`true`로 바꾸면 기존 허용 동작으로 돌아간다. 파일은 로컬 런타임 설정이라 gitignore 대상이며 커밋하지 않는다. 파일이 없는 설치의 기본값도 허용이다. 손상된 파일은 차단으로 처리한다. 실행 시 파일을 읽으므로 설정 복구에 코드 변경·재빌드가 필요 없다. 이미 실행 중인 IBL 범위의 정책은 자식에게 그대로 승계하고 끝나면 복원한다.

## 차단 범위

- 자율주행/에이전트가 시작한 IBL 도구 실행. 기존 call channel `agent`를 사용하며, 채널 미상일 때 명시된 agent_id가 있으면 에이전트로 취급한다. 앱 직접 호출은 system_ai 신원이어도 channel `app`이므로 유지된다.
- 현재 `ai_call:true`인 5액션(self:ask, self:struct, table:ai, table:brief, table:structure)을 에이전트 카탈로그에서 제외하고 실행 전에 거절한다. 이름 목록을 엔진에 하드코딩하지 않고 기존 레지스트리 메타데이터를 읽는다. 해당 액션이 직접 포함된 상시 관용구도 소개에서 제외하며 정책 전환을 관용구 캐시 키에 반영한다. 저장된 정의는 삭제하지 않는다.
- 기타 도구 내부에서 공용 `oneshot_ai_call`/`system_ai_call`을 부르는 경로도 모델 획득 전에 차단한다. 따라서 액션 이름을 달리하거나 role을 classify/background 등으로 바꿔도 우회되지 않는다. 도구가 AI 실패 시 결정론적 폴백을 갖고 있다면 모델 호출 없이 그 폴백이 실행될 수 있다.
- IBL의 `criteria`는 추가 AI 심사를 요구하므로 해당 step의 실제 작업 **이전**에 차단한다. 파일을 먼저 쓰고 검증에서 막히는 일이 없도록 했다. criteria를 조용히 무시하거나 통과로 처리하지 않는다.
- 관용구·중첩·each 병렬 워커는 같은 범위를 승계한다. 제한된 부모 안에서 channel을 app으로 바꿔도 제한이 풀리지 않는다. 종료·예외·워커 복원 뒤에는 범위가 남지 않는다.

## 유지되는 것

- 앱·수동·스케줄러가 IBL을 직접 실행하는 경로와 그 안의 원샷 기능.
- 주 에이전트의 모델·기어·보고서 지시·일반 데이터 조회·계산·파일 저장.
- **IBL 도구 밖**에서 하네스가 수행하는 분류·번역·최종 평가 등. 따라서 전체 에피소드의 모든 AI 하위 호출이 0이어야 하는 실험은 아니다.
- 보고서 앱의 작성 버튼은 기존처럼 시스템 에이전트에 위임한다. 위임된 에이전트의 IBL에는 차단이 적용된다.

이 기능은 하네스의 지원된 도구 경로에 대한 실험 제한이다. 임의 셸 프로그램이 외부 모델 API를 직접 호출하는 것까지 막는 OS/네트워크 샌드박스는 아니다. 모델에게 그런 우회도 하지 않도록 명시하며, 실제 비교에서는 셸·별도 위임으로 추가 AI를 호출하지 않았는지 함께 확인한다.

## 관측과 검증

- `ibl.started.allow_agent_tool_oneshot`에 설정 상태를 기록한다. 차단 시 `ai.policy_blocked`에 액션과 차단 사실을 남긴다(자료/프롬프트 본문 없음).
- 오류는 `blocked:true`, `error_type:tool_ai_policy`이고 중첩 traceback은 `policy` 종류를 보존한다. 정책 차단에 파라미터 수정·재시도 힌트를 붙이지 않는다.
- `backend/test_tool_ai_policy.py`: 설정 복구·손상, 역할 변경, 도구 밖 인지/앱 보존, 데이터 기반 액션 제어, criteria의 부작용 전 차단, 내부 원샷, 스레드 전파/복원, 카탈로그 전환, 실제 IBL 직접·파이프·함수·병렬 경로.
- 기존 criteria 배터리는 허용 상태에서의 계약 시험이므로 로컬 실험 설정을 격리했다. 차단 상태의 검증은 새 배터리가 담당한다.
- 라이브 검사는 에이전트 원샷 거절, 일반 take 성공, 앱의 빈 입력 AI 단계 성공(모델 호출 0)을 확인했다. 검증 때문에 실제 보고서나 유료/구독 모델 호출을 시작하지 않았다.

최종 검증: 집중 40건 통과, 전체 backend 회귀 3,086건 통과(exit 0). 라이브 5건(직접/파이프/병렬 차단, 일반 take 성공, 앱 빈 입력 AI 단계 성공) 통과. Android 번들·어휘/문서 파생 일치·층·은퇴 계약·diff 검사를 통과했다. 초기 전체 검사에서 로컬 차단 설정과 기존 criteria 배터리의 충돌, 공개 결과 정규화 경계 검사 실패가 드러났고, 설정 격리와 최외곽 public_result 적용 후 전체를 다시 통과했다.

## 다음 보고서 비교

사용자가 기존 보고서 작성 버튼으로 실행한다. 후속 감사에서는 전체 시간·주 모델 입출력(추론 포함)·IBL 횟수·차단 시도·오류/수리·자료 범위·보고서 품질을 함께 비교한다. 자료가 바뀌는 실전 재실행은 동일 입력 통제 실험과 구분한다. 원샷이 사라졌다는 이유만으로 품질 유지나 순이익을 미리 주장하지 않는다.
