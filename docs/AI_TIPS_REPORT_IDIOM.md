# 내부 관용구: AI팁보고서쓰기

## 범위

유튜브 자료 검색부터 원문 보존, 두 차례 추출, 누적 팁과 의미 중복 비교, 내용 검토,
편집, 최종 검수, 로컬 보고서·원장 저장까지 연결한다.
노출 관용구로 승격하지 않는다. 스케줄·공개 업로드·메시지 발송은 포함하지 않는다.

정본은 `data/idioms/ai_tips_report.ibl`, 결정론 부품은
`data/scripts/ai_tips_report.py`이다. 새로운 IBL 액션은 만들지 않는다.
기존 판본 1 관용구의 보수 개정이다. 호출 서명·판본을 바꾸지 않으며 실행 상태 v2는 IBL 판본 2와 다르다.
모델 호출은 IBL의 self:struct/table:ai가 실행 축 모델을 사용한다.
검토를 한 번의 요약 호출로 대체하거나 모델 등급을 낮추지 않는다.

## 호출 계약

호출 이름은 `AI팁보고서쓰기`, 입력 슬롯은 `설정` 객체 하나다.

| 키 | 의미 |
| --- | --- |
| topic | 이번 주제. 검색·추출·선정·편집의 입력이며 고정된 AI 분야 이름이 아님 |
| date | 보고서 기준일 YYYY-MM-DD. 영상 업로드 날짜를 직접 확인해 이전 180일로 제한 |
| root | 절대경로. 기존 _covered_videos.json과 db/tips.json, 직전 보고서를 이 자리에서 읽음 |
| mode | draft(기본): 실행별 검수 초안만 저장. commit: 검수 통과 후 지정 root 원장·보고서에 반영 |
| run_id | 같은 회차의 재진입 식별자. 생략 시 날짜·주제에서 결정 |
| reader_context | 독자 수준과 환경의 확인된 사실. 없는 구현 상태를 추측해 채우지 않음 |

결과는 items 1행: status(reviewed_draft 또는 committed), report(절대경로),
evidence(실행 상태·검토 근거), report_hash, new_tips, tips, videos, candidates,
checked. published는 false다. 전체 통과 전에는 성공 영수증을 내지 않는다.

draft를 시작한 run의 mode를 commit으로 바꿔 부르지 않는다. 실행 설정은 불변이다.
같은 root/run_id/설정으로 다시 부르면 완료 단계의 입력을 비워 검색·추출을 반복하지
않고 최초 미완료 단계부터 이어 간다. 유효한 최종 내용 검수가 탈락하면 관용구가 회차당
한 번 자동 보완한다. 기존 판정·본문·실패 입력을 revision-N 파일에 보존하고, 탈락 이유를
전달해 영상별 내용 검토·편집·최종 검수를 다시 수행한다. 수집·추출 결과는 재사용한다.
다시 탈락하면 중단하며 재진입으로 자동 보완 횟수를 초기화하지 않는다. 원인을 별도로
보완한 뒤에는 부품의 op=revise, from=reviewed와 reason으로 명시적 재검토를 시작할 수 있다.
완료된 보고서나 조사 입력 변경은 새 run에서 검토한다. 저장 도중 중단은 같은 run으로 복구한다.

## 품질 경계

- 한국어·영어·구체 도구·회의적 관점·실행 동사 다섯 층으로 검색한다.
- 선정 2~4편, 60분 초과 최대 1편. 검색 결과의 상대 날짜로 업로드 날짜를 추측하지 않는다.
- 자막 전문과 원본 봉투를 실행 폴더에 남긴다. 스필 참조를 회수하며 미리보기로 대체하지 않는다.
- 1차는 제목·시점, 2차는 선정 팁의 방법·도구·조건을 추출한다. 두 번 모두 grounded=true.
- 각 인용문을 원문과 대조하고 시점도 확인한다. grounded 탈락·인용 누락·시점 누락·부분 실패를 숨기지 않는다.
- 영상별 할당량은 없다. 8~15개를 목표로 하지만 근거 없는 팁으로 수를 채우지 않는다.
- 독립 내용 검토는 전달 범위가 표시된 자막 원문과 추출 행을 다시 비교한다. 외부 공식 근거가 필요하면 needs_evidence로 멈춘다.
- 최종 본문·요약·출처·건수·원장 갱신은 같은 최종 팁에서 파생한다.
- 검수는 두 층이다. 독립 검토가 자막 원문 대조를 담당하고, 최종 검수는 그 판정·근거 행과
  편집된 본문을 비교한다. 검색·실측 메타데이터·누적 원장 건수도 전달해 인계 누락을 막는다.
  최종 항목은 근거·실행 가능성·새로움·조건·출처·편집 해석 분리·건수다.
- 한계 문구를 붙이는 것으로 실행 가능성 부족을 대신하지 않는다. 구체 행동이나 선택 조건이
  없는 추상적 원칙은 팁에서 제외한다. 빈 누적 원장은 신규 원장으로 명시하고 이번 팁끼리도 중복을 검토한다.
- 검수 지문, 저장 본문, 보존 자막을 다시 대조한다. 원장이 조사 중 달라지면 반영을 거부한다.
- 반영은 공유 파일 잠금과 전후 내용 저널을 사용한다. 원장들을 먼저 쓰고 보고서를 마지막에 쓴다.
  여러 파일의 물리적 단일 트랜잭션은 아니며 중단된 쓰기는 다음 동일 run이 복구한다.

주제만 바뀌고 위 조사 방식·결과 계약이 같으면 같은 관용구를 재사용한다.
주식 전망·법률 판단처럼 근거 소스와 검증 방식이 달라지면 topic만 바꾸어 적용하지 않는다.

## 현재 한계

긴 자막은 영상 전체를 단일 AI 요청에 넣지 않는다. 시간 표기를 포함한 원문이 36,000자를
넘으면 `ai_tips_sources.py`가 전 구간을 나눠 추출하고, 후보별 관련 위치를 전체 구간에서 색인한다.
경계 양옆 문맥을 겹쳐 읽으며 핵심 구간의 누락·중복은 인덱스로 검사한다. 큰 단일 세그먼트도
원래 시간·문자 오프셋을 유지해 나눈다. 구간별 추출·색인 영수증을 즉시 저장하여 재개 시 성공한
형제 호출을 반복하지 않는다. 전 구간 처리가 끝나야 후보 비교로 진행한다.
색인은 방법·조건·예외·반례·철회·참조 위치를 고르며 모델이 쓴 요약을 원문 대신 사용하지 않는다.
선택 위치의 실제 자막을 모아 후보별 상세 추출·불확실한 신규성 보완·독립 내용 검토에 전달한다.
짧은 원문의 전문 전달 계약은 유지한다. 긴 원문의 후속 검토는 전체 구간 색인으로 찾은 관련
원문을 읽는 방식이며, 전달 범위와 모델의 위치 선택을 보고서·검수 입력에 명시한다.
위치 선택은 의미 판단이므로 완전한 재현율의 증명은 아니다. 불확실한 색인은 승인할 수 없다.
개별 AI 요청의 57,000자 상한은 유지한다. 한 후보의 관련 원문 자체가 36,000자를 넘거나
후보·원장 한 행만으로 요청 상한을 넘는 경우에는 저장 결과를 보존하고 범위 보완을 요구한다.
이 경우에도 근거를 조용히 잘라 성공으로 처리하지 않는다.
전문 검토 입력은 모든 구간의 시작 시점·원문을 순서대로 문자열에 보존한다. 반복 JSON 키만
없애며 요약·절단하지 않는다. 원본 구간 객체·길이·지문은 실행 폴더에 별도로 유지한다.
누적 팁과 새 후보 문맥을 양쪽 모두 분할하고, 후보×기존 팁의 모든 쌍을 정확히 한 번 비교한다.
배치마다 candidate_ids·known_ids·요청 지문을 저장하며 응답의 범위·원문 변경과 비교 쌍 누락·중복을 거절한다.
이미 발급한 배치는 재진입·코드 개정 때 다시 나누지 않는다. 후보 범위가 없는 이전 v2 실행 상태는
원래의 전 후보 배치로 해석한다. 빈 원장은 비교 AI를 호출하지 않는다. 후보 인용의 앞 30초·뒤 90초 원문을
범위가 표시된 발췌로 함께 전달한다. 발췌에서 unknown이 나오거나 일부 후보 판정이 누락되면,
해당 후보만 보존 자막(긴 원문은 전 구간 색인의 관련 원문)과 관련 기존 팁 전부로 한 번 재검토한다. 원 비교 성공 행은 바꾸지 않는다.
전문에 방법이 없다고 확인된 unsupported는 이유를 남겨 제외하며, 여전히 unknown이면 중단한다.
잘못된 ID·중복 근거·봉투의 부분 실패·전체 배치 누락은 이 보완으로 통과시키지 않는다.
추가 문맥도 요청 크기에 포함하며 상한을 넘으면 잘라 보내지 않는다. 보완 전후 모든 배치·후보
판정의 완전성과 중복 근거 ID를 검사한다. 후보 한 건과 기존 팁 한 건의 조합조차 상한을 넘으면 accepted 결과를 보존하고
blocked를 반환한다. 전건 비교 후 후보끼리의 중복·선정을 별도로 판단한다.
편집자는 확정 팁·검토 이유·추가 원문과 비교 범위 지문을 받아 산문만 구성한다.
최종 검수에는 전체 원장을 되풀이하는 대신 지문·범위·모든 비교 판정과 연결 근거를 전달한다.
현재 검토하는 후보의 모든 배치 판정과 이유를 전달하며, 동일 이유는 배치 ID 목록으로 묶는다.
검토 행에서 최종 팁과 같은 본문은 중복 전달하지 않고 후보 ID·판정·이유를 남긴다.
최종 검수 요청이 커지면 비교 근거만 무손실로 나누며 각 요청에는 보고서 전체와 나머지 검수 자료를 넣는다.
분할별 요청 지문·ID를 검사하고 모든 분할의 일곱 항목이 참일 때만 완료한다. 어느 분할의 실패도
자동 보완 이유에 함께 전달한다. 한 근거 행도 상한을 넘으면 멈추며 임의로 줄이지 않는다.
전체 감사 기록은 상태에 남기고, 전문 재검토에서 제외한 후보와 이유는 보고서 한계에도 표시한다.
최종 검수는 판정 이유와 실제 최종 방법이 일치하는지도 검토하며 불확실하면 통과시키지 않는다.
검수에서 특정 known_id의 설명 모순이 지적되면 재검토 입력에 그 원장 항목의 원본을 붙인다.
과거 판정은 보존하고 독립 검토가 정정 이유를 남기며, 최종 검수는 원본과 정정이 실제로 모순을
해소했는지 다시 확인한다. 원장 전건 재비교와 비교 결과의 인계 검토는 별도 단계의 책임이다.
외부 공식 문서의 자동 검색·HTML 공개본 제작은 아직 포함하지 않는다.
내용 검토가 needs_evidence로 멈추면 호출자가 실제 웹 원문을 수집해 부품의 op=evidence,
candidate_ids(근거를 요청한 후보), data(출처 URL·text가 있는 원문 items)로 연결할 수 있다.
검색 요약이나 작성자의 추정을 원문 대신 넣지 않는다. 실패·잘림·출처 누락·대상 후보 오류는 거절한다.
등록은 검토 통과가 아니다. 같은 관용구를 다시 부르면 자막과 추가 원문을 독립 검토하고,
확인한 표기·조건만 교정하며 근거가 부족하면 계속 멈춘다. 추가 원문은 별도 파일·지문과 함께
보존하고 편집·최종 검수에 전달하며 보고서에 출처를 표시한다. 최종 검수 때 원문 변경도 차단한다.
편집 자동 보완은 최종 내용 검수의 유효한 탈락에만 적용한다. 비교 단계의 전문 재검토와 별개로 각 1회다. 원문·본문 지문 변경, 원장 충돌,
검수 응답 형식 오류와 추가 근거 필요는 이 경로로 복구하지 않는다.
따라서 일반적인 보고서 생성의 모든 예외를 무인으로 복구하는 관용구라고 부르지 않는다.

## 실행 경계 v2 (2026-09-23)

검증 완료된 입력·상태·영수증을 먼저 저장하고 다음 AI 요청을 준비한다. 준비 실패는
status=blocked, accepted, evidence, resume를 반환한다. 같은 회차 재진입은 확정된 추출을
재호출하지 않는다. 영수증에 버전·설정/원장 범위·입력·출력 지문을 붙인다.
준비 실패의 원인·확정 여부·재개 인자는 상태의 preparation_failure에도 보존하고 준비 성공 시 해제한다.
v1 실행 상태는 자동 변환하지 않으며 기존 증거를 보존하고 새 run_id를 요구한다.

단계: start → queries → search → metadata → videos → transcripts → candidates →
compared → chosen → details → reviewed → draft → finish. compared는 전건 비교를 검증한다.
긴 원문은 candidates와 compared 사이에서 source_requests → source_scanned(구간별) →
sources_indexed를 거친다. 짧은 원문은 추가 AI 호출 없이 통과한다. 자막의 옛 크기 제한으로
실패한 회차도 저장된 input-transcripts 지문·전문을 검증한 뒤 사용하므로 자막을 다시 받지 않는다.
revise의 from=reviewed는 원래대로 내용 검토·편집·최종 검수만 무효화한다.
비교 단계의 catch는 저장된 실패 입력을 검증하고 unknown·판정 누락에 한해 전문 재검토를 수행한다.
comparison-before-retry.json·input-comparison-repair.json·comparison-after-retry.json과 상태에
전후 판정·요청·원문 지문을 보존한다. 보완 결과를 정상 compared 검증기에 다시 넣고 다음으로 간다.
