# AI팁보고서쓰기

한 호출이 주제 준비 → 영상 선정 → 자막에서 팁 추출 → 보고서 작성 → 로컬·공유창고 저장까지 끝낸다.
정본은 `data/idioms/ai_tips_report.ibl`(판본 2), 연결 코드는 `data/scripts/ai_tips_report.py`다.
일상 사용법은 `data/guides/youtube_ai_tips_report.md`를 따른다.

## 호출과 완료

`[fn:AI팁보고서쓰기]{}`로 실행한다. 선택 입력 `설정`에는 topic, date(YYYY-MM-DD),
root(절대경로), share_root, mode, reader_context, run_id를 줄 수 있다.
기본값은 오늘·기존 운영 폴더·현재 독자 맥락·commit이다. 주제는 전날까지 최근 호의
다음 후보에서 가져오고 없으면 코딩으로 시작한다. 기본 회차는 날짜·auto·v5로 고정한다.
주제를 지정하면 날짜·주제·v5를 사용한다. 이전 상태는 자동 변환하지 않는다.

최종 `value`는 status, report, shared_report, summary, topic, new_tips, video_count,
누적 건수, limitations, evidence 경로와 report_hash를 담은 Record다.
중간 자막·프롬프트·실행 결과 전체를 업무 값으로 돌려주지 않는다.

- `completed`: 로컬 보고서·원장·팁 DB와 공유창고 HTML 저장 완료.
- `draft`: 실행 폴더 draft.md만 작성. 원장·공유창고는 쓰지 않는다.
- `publication_pending`: 감독 하네스의 전달 대기. 실제 공개 완료로 표현하지 않는다.

반환 경로·요약을 전달하면 끝이다. 호출자가 보고서·상태 파일을 다시 읽거나 HTML을
따로 만들 필요가 없다. 알림 전송은 별도 요청이 있을 때만 한다.

## 작성 흐름

1. 주제와 독자 맥락으로 검색어 2~3개를 만든다. 기존 영상 ID를 제외한다.
2. 메타데이터로 180일 이내 날짜를 확인하고 AI가 관련 영상 몇 편을 고른다.
3. 자막에서 팁의 제목·구체 방법·주의점을 함께 추출한다.
4. 추출 결과를 골라 보고서를 작성한다. 코드는 출처 연결·건수·파일을 조립해 저장한다.
5. 기존 보고서HTML 렌더러로 개인 의견을 제거한 공유판을 저장한다. 모델 호출은 없다.

별도 제목 추출·원문 색인·재추출·내용 검토·최종 심사·자동 재작성은 없다.
인용문·타임스탬프를 생성·검증하지 않는다. 확인되지 않은 방법은 제외하거나
불확실하다고 설명한다. 출처 ID와 저장 형식만 코드로 확인한다.
누적 팁을 모델에게 보내지 않으며 다른 영상의 같은 팁도 허용한다.

짧은 영상 N편의 정상 경로는 모델 호출 N+3회(검색어·선정·영상별 추출·작성)다.
긴 자막만 32,000자 단위로 나누고 경계 문맥을 겹쳐 읽는다.
개별 자료 실패는 판본 2 try/catch로 해당 행의 실패로 처리하고 보고서에 한계를 적는다.
자료나 팁이 전혀 없으면 실패한다. 실제 원문 절단·예산 초과를 정상 완료로 감추지 않는다.
보고서에는 자막을 읽은 영상만 표시한다. 팁을 쓴 영상 또는 끝까지 추출했지만 팁이
없던 영상만 처리 원장에 넣고, 선택하지 않았거나 실패한 영상은 다음에 다시 다룬다.

## 저장과 재개

start → queries → search → metadata → videos → transcripts → compose → finish.
extracted_part가 각 구간 결과를 즉시 저장한다. 같은 설정 재호출은 완료 단계를
재사용하며 완료된 회차는 외부 조회·AI 호출 없이 짧은 결과를 그대로 반환한다.
로컬 반영 후 공유 저장이 실패해도 준비된 본문과 저널에서 공유만 재개한다.

commit은 파일 잠금·전후 저널로 원장·팁 DB·md를 반영한다. 다중 파일 DB의 원자성을
가정하지 않는다. 공유판은 일반 요약으로 바꾸고 ‘우리 시스템 함의’ 줄을 제거한다.
원장 충돌·같은 이름의 다른 보고서는 덮어쓰지 않는다. 감독 전달 큐를 그대로 존중한다.

## 등록과 검증

스크립트 ID와 관용구 이름은 유지한다. 판본 2 본문은 `.venv`에서
`IBLUsageDB.add_examples_batch` 단일 경로로 등록한다. 동일 이름의 판본 2가 있는지
먼저 확인하여 중복 등록하지 않는다. 레거시 행과 개정 이력은 보존한다.
판본 2 조회는 판본 2 정의를 우선하며 레거시 전체 실행 결과를 반환하는 다리를 타지 않는다.

테스트: `.venv/bin/python3 -m pytest data/scripts/test_ai_tips_report.py`.
실제 판본 2 이름 호출·실행기·each·스크립트·저장을 쓰고 검색과 AI 응답만 고정한다.
실제 모델 품질·전체 시간·토큰 절감은 고정 응답 테스트만으로 확정하지 않는다.
