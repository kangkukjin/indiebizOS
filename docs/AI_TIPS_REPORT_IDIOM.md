# 내부 관용구: AI팁보고서쓰기

## 범위

유튜브 자료 검색부터 원문 보존, 두 차례 추출, 누적 팁과 의미 중복 비교, 내용 검토,
편집, 최종 검수, 로컬 보고서·원장 저장까지 연결한다.
노출 관용구로 승격하지 않는다. 스케줄·공개 업로드·메시지 발송은 포함하지 않는다.

정본은 `data/idioms/ai_tips_report.ibl`, 결정론 부품은
`data/scripts/ai_tips_report.py`이다. 새로운 IBL 액션은 만들지 않는다.
모델 호출은 IBL의 self:struct/table:ai가 실행 축 모델을 사용한다.
검토를 한 번의 요약 호출로 대체하거나 모델 등급을 낮추지 않는다.

## 호출 계약

호출 이름은 `AI팁보고서쓰기`, 입력 슬롯은 `설정` 객체 하나다.

| 키 | 의미 |
| --- | --- |
| topic | 이번 주제. 검색·추출·선정·편집의 입력이며 고정된 AI 분야 이름이 아님 |
| date | 보고서 기준일 YYYY-MM-DD. 영상 업로드 날짜를 직접 확인해 이전 180일로 제한 |
| root | 절대경로. 기존 _covered_videos.json과 db/tips.json, 직전 보고서를 이 자리에서 읽음 |
| mode | draft(기본): 실행별 검수 초안만 저장. commit: 검수 통과 후 지정 root 원장·보고서에 반영 |
| run_id | 같은 회차의 재진입 식별자. 생략 시 날짜·주제에서 결정 |
| reader_context | 독자 수준과 환경의 확인된 사실. 없는 구현 상태를 추측해 채우지 않음 |

결과는 items 1행: status(reviewed_draft 또는 committed), report(절대경로),
evidence(실행 상태·검토 근거), report_hash, new_tips, tips, videos, candidates,
checked. published는 false다. 전체 통과 전에는 성공 영수증을 내지 않는다.

draft를 시작한 run의 mode를 commit으로 바꿔 부르지 않는다. 실행 설정은 불변이다.
같은 root/run_id/설정으로 다시 부르면 완료 단계의 입력을 비워 검색·추출을 반복하지
않고 최초 미완료 단계부터 이어 간다. 유효한 최종 내용 검수가 탈락하면 관용구가 회차당
한 번 자동 보완한다. 기존 판정·본문·실패 입력을 revision-N 파일에 보존하고, 탈락 이유를
전달해 영상별 내용 검토·편집·최종 검수를 다시 수행한다. 수집·추출 결과는 재사용한다.
다시 탈락하면 중단하며 재진입으로 자동 보완 횟수를 초기화하지 않는다. 원인을 별도로
보완한 뒤에는 부품의 op=revise, from=reviewed와 reason으로 명시적 재검토를 시작할 수 있다.
완료된 보고서나 조사 입력 변경은 새 run에서 검토한다. 저장 도중 중단은 같은 run으로 복구한다.

## 품질 경계

- 한국어·영어·구체 도구·회의적 관점·실행 동사 다섯 층으로 검색한다.
- 선정 2~4편, 60분 초과 최대 1편. 검색 결과의 상대 날짜로 업로드 날짜를 추측하지 않는다.
- 자막 전문과 원본 봉투를 실행 폴더에 남긴다. 스필 참조를 회수하며 미리보기로 대체하지 않는다.
- 1차는 제목·시점, 2차는 선정 팁의 방법·도구·조건을 추출한다. 두 번 모두 grounded=true.
- 각 인용문을 원문과 대조하고 시점도 확인한다. grounded 탈락·인용 누락·시점 누락·부분 실패를 숨기지 않는다.
- 영상별 할당량은 없다. 8~15개를 목표로 하지만 근거 없는 팁으로 수를 채우지 않는다.
- 독립 내용 검토는 자막 전문과 추출 행을 다시 비교한다. 외부 공식 근거가 필요하면 needs_evidence로 멈춘다.
- 최종 본문·요약·출처·건수·원장 갱신은 같은 최종 팁에서 파생한다.
- 검수는 두 층이다. 영상별 독립 검토가 자막 전문 대조를 담당하고, 최종 검수는 그 판정·근거 행과
  편집된 본문을 비교한다. 검색·실측 메타데이터·누적 원장 건수도 전달해 인계 누락을 막는다.
  최종 항목은 근거·실행 가능성·새로움·조건·출처·편집 해석 분리·건수다.
- 한계 문구를 붙이는 것으로 실행 가능성 부족을 대신하지 않는다. 구체 행동이나 선택 조건이
  없는 추상적 원칙은 팁에서 제외한다. 빈 누적 원장은 신규 원장으로 명시하고 이번 팁끼리도 중복을 검토한다.
- 검수 지문, 저장 본문, 보존 자막을 다시 대조한다. 원장이 조사 중 달라지면 반영을 거부한다.
- 반영은 공유 파일 잠금과 전후 내용 저널을 사용한다. 원장들을 먼저 쓰고 보고서를 마지막에 쓴다.
  여러 파일의 물리적 단일 트랜잭션은 아니며 중단된 쓰기는 다음 동일 run이 복구한다.

주제만 바뀌고 위 조사 방식·결과 계약이 같으면 같은 관용구를 재사용한다.
주식 전망·법률 판단처럼 근거 소스와 검증 방식이 달라지면 topic만 바꾸어 적용하지 않는다.

## 현재 한계

단일 자막 본문 50,000자, 개별 AI 요청 57,000자 상한을 넘으면 멈춘다.
누적 팁은 known_id로 전건 분할 비교한다. 후보 인용의 앞 30초·뒤 90초 원문을
범위가 표시된 발췌로 함께 전달한다. 이 발췌에서도 판정할 수 없으면 unknown을 유지한다.
추가 문맥도 요청 크기에 포함하며 상한을 넘으면 잘라 보내지 않는다. 배치·후보 ID의 완전성과 중복 근거 ID를 검사하고,
unknown이면 중단한다. 후보 자체 또는 기존 팁 한 건이 상한을 넘으면 accepted 결과를 보존하고
blocked를 반환한다. 전건 비교 후 후보끼리의 중복·선정을 별도로 판단한다.
편집·최종 검수에는 전체 원장을 되풀이하는 대신 지문·범위·비교 판정과 연결 근거를 전달한다.
최종 검수는 판정 이유와 실제 최종 방법이 일치하는지도 검토하며 불확실하면 통과시키지 않는다.
외부 공식 문서 자동 대조·HTML 공개본 제작은 아직 포함하지 않는다.
자동 보완은 최종 내용 검수의 유효한 탈락에만 적용한다. 원문·본문 지문 변경, 원장 충돌,
검수 응답 형식 오류와 추가 근거 필요는 이 경로로 복구하지 않는다.
따라서 일반적인 보고서 생성의 모든 예외를 무인으로 복구하는 관용구라고 부르지 않는다.

## 실행 경계 v2 (2026-09-23)

검증 완료된 입력·상태·영수증을 먼저 저장하고 다음 AI 요청을 준비한다. 준비 실패는
status=blocked, accepted, evidence, resume를 반환한다. 같은 회차 재진입은 확정된 추출을
재호출하지 않는다. 영수증에 버전·설정/원장 범위·입력·출력 지문을 붙인다.
v1 실행 상태는 자동 변환하지 않으며 기존 증거를 보존하고 새 run_id를 요구한다.

단계: start → queries → search → metadata → videos → transcripts → candidates →
compared → chosen → details → reviewed → draft → finish. compared는 전건 비교를 검증한다.
revise의 from=reviewed는 원래대로 내용 검토·편집·최종 검수만 무효화한다.
배치 내부 일부 호출까지 개별 영수증으로 확정하는 기능은 아직 없으며, 비교 단계 실패 후에는
그 단계의 배치를 다시 실행한다. 범용 실행기나 별도 상태 DB는 추가하지 않았다.

관용구의 구조 criteria는 행 보존·grounded·answer/keyed 검사로 옮겼다. 원문 독립 검토와
최종 편집 검수는 유지했다. 바깥 인계는 input_as로 실제 봉투를 전달하며 each 안의 4개
명시 봉투는 추가 subprocess 비용을 만들지 않도록 보존했다.

## 품질을 유지하는 자동 보완 (2026-09-23 재구성)

영상별 검토부터 마감까지를 지역 함수로 묶고 최초 검토와 보완에 같은 함수를 호출한다.
기존 일곱 가지 내용 기준·자막 전문 대조·모델 선택·두 차례 grounded 추출을 유지한다.
최종 검수의 일곱 판정은 실제 bool이어야 하며, 빈 방법은 통과 팁으로 인정하지 않는다.
빈 자막 구간이 임의 인용과 일치해 잘못된 시점을 통과시키는 허점도 막았다.
자동 보완 전 원문·초안·원장과 거절 입력의 지문을 다시 확인한다. 더 낮은 기준으로
통과시키거나 팁 수를 맞추지 않는다. 보완은 추가 모델 호출을 쓰므로 비용 절감은 보장하지 않는다.
원장의 최근 주제는 지침대로 마지막 10건만 유지한다.

## 재등록

스크립트는 self:script register의 ID `AI팁보고서`로 등록한다.
관용구는 `scripts/register_idiom.py`로 위 IBL 파일을 add/update한다.
topic은 `보고서/유튜브 AI 팁`. always_on 승격 옵션을 주지 않는다.
등록 DB는 로컬 실행 저장소이며 재현 가능한 본문은 Git에 보관한다.
