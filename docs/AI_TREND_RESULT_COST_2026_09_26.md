# AI 동향 보고서의 상태·검색 결과 전달

4064번은 결과 재조회 9회에서 174,529자를 읽었다. 도구 왕복 합은 0.661초이고,
수신 후 다음 행동·응답까지의 구간 합은 44.773초다. 직후 모델 응답 9개의 집계는
입력 738,634(캐시 675,072), 출력 824토큰이다. 이 집계는 이전 맥락과 다음 판단도
포함하므로 재조회를 없앴을 때의 순수 절감량이 아니다.

## 선택

이름만 붙이는 관용구는 결과 크기를 줄이지 않는다. 결정론적 준비·열 선택을 한 호출에
묶고, 판단이 필요한 원문은 충분히 읽는다. 별도 요약 AI를 매번 추가하지 않는다.
`뉴스모아선별산문쓰기`, `논문검색해주목할것추리기`, `각각읽고요약` 등 기존 비노출
정의도 확인했지만 내부 AI 호출·날짜 검증·보고서 게이트의 범위가 달라 기본 경로에서 제외했다.

재사용하는 기존 함수:

- `직전보고서찾아읽기`: 비노출, 한 파일의 앞 160줄이 필요한 경우에 한정.
- `미처리만고르기`: 비노출, 같은 호에서 이미 읽은 URL만 제외. 과거 주제와의 의미 비교는 하지 않음.
- `주소마다읽기`·`본문에서찾기`: 기존 상시 함수. 선택 URL의 문단을 수집하고 주장에 맞는 대목·앞뒤 문맥을 반환.

신규 비노출 함수:

- `AI동향준비읽기(폴더)`: 파일명순 최신 전체 보고서와 규칙·커버리지·점검 원장을
  `documents` 한 묶음으로 반환. 보고서의 후반을 자르지 않으며 선택 파일은 목록에서
  부재를 확인한다. 필수 파일 실패·권한 실패를 빈값으로 바꾸지 않는다. 쓰기와 AI 호출은 없다.
- `검색묶음추리기(질의들,기간=7,개수=6)`: 4개씩 병렬 검색하고 제목·URL·summary·meta·날짜
  원형과 질의·섹션을 남긴다. 질의별 받은 수·표시 수·성공·실패를 별도로 보존하고
  `results`/`items`의 중복 표현은 반환하지 않는다. 여러 질의의 같은 URL은 섹션 추적을 위해 유지한다.
  도구 원문은 기존 실행 증거에 남으며 이 함수의 표는 전체 응답의 손실 없는 복제본이 아니다.

## 등록·재현

원본은 `data/idioms/ai_trend_prepare.ibl`, `search_batch_view.ibl`이다.
`ai_trend_seeds.json`의 함수 2건과 호출 예 2건을 기존 `add_examples_batch` 경로로 등록한다.

```sh
.venv/bin/python3 scripts/register_webapp_idioms.py --seed-file ai_trend_seeds.json
.venv/bin/python3 scripts/register_webapp_idioms.py --seed-file ai_trend_seeds.json --apply --local-encoder
.venv/bin/python3 -m pytest scripts/test_ai_trend_idioms.py -q
```

등록 전 SQLite 온라인 백업을 `data/_backups/`에 만들고, 이름 충돌·컴파일·의미 검색 색인을
확인한다. 두 함수와 호출 예의 `always_on=0`을 확인했다. 모든 작업에 주입되는 소개는 늘지 않는다.
함수 ID는 4878·4879다. 가이드의 이름·호출·반환 설명을 통해 사용한다.

## 측정과 검증

4064번 첫 검색 묶음의 저장 원문
`data/spill/supervision/1a78551ca84b447783d52524679d66bb/707afa68f8533e9f289ff51755acecb048d23d6ba80face2cacfc7a865568ed7.txt`
을 고정 어댑터 입력으로 재생했다. 외부 검색·AI 호출·보고서 재발행은 하지 않았다.

| 비교 | 기존 | 신규 |
| --- | ---: | ---: |
| 질의 수 | 8 | 8 |
| 후보 행 수 | 43 | 43 |
| 결과 값 JSON 문자수(UTF-8 문자, indent=2) | 44,404 | 31,244 |

질의·행 순서·title·url·summary·meta·date가 전건 동일한 것을 단언했다.
선별용 반환 문자수는 **29.6% 감소**했다. 이는 결과 값의 문자수 비교이며 모델 토큰·최종
보고서 시간의 절감률이 아니다. 큰 결과는 여전히 표시 한도에 걸려 묶음 조회가 필요할 수 있다.
준비 결과도 미리보기이면 `value.documents` 한 번으로 회수하도록 가이드에 명시했다.

실행기 시험은 긴 보고서 후반, 최신 파일 선택, 선택 파일 부재/빈 파일, 권한 실패,
빈 검색/원천 장애, 부분 원천의 증거, 섹션·상충 날짜 보존, 요청 상한의 수량 관측,
가이드 호출을 확인한다. 라이브 호출은 정상 프로젝트 문맥에서 준비 읽기와 소량 검색을
확인하고, 기존 미처리 URL 제외·본문 문맥 함수도 고정 자료로 확인한다.
원문 준비의 첫 HTTP 시험은 판본·프로젝트 문맥을 잘못 주어 실패했으며 이를 바로잡아 재검증했다.

보고서 가이드는 35KB 상한 안에서 교체했다. 앞 호출의 변수가 다음 호출로 자동 상속된다고
가르치지 않으며, 컨텍스트 압축 이후 필요한 내용을 다시 읽는 것은 허용한다.
실제 다음 보고서의 시간·총토큰·내용 품질은 아직 측정하지 않았다.
