# Android 제어의 중복 관측 축소

## 범위와 계약

이번 변경은 UI 변경 전 중복 화면 조회와 설정 변경 시 전체 기기 상태 수집을 줄인다.
원격 실행 프로세스 재사용·배치 실행·전송 프로토콜·취소 계약은 변경하지 않는다.
그 후속 검토는 [연속 제어 비용 조사와 설계](ANDROID_CONTROL_SEQUENCE_DESIGN_2026_10_24.md)에
기록했다. 세 폰의 읽기 전용 비교 결과와 제안이며, 연속 제어 기능은 아직 구현하지 않았다.

`phone_ui.py`는 화면 조회 요청에만 직접 snapshot을 호출한다. 변경 요청은 uiControl을
한 번 보내고 Android 서비스가 잠금 안에서 읽은 최신 before와 동작 후 새 screen으로
검증한다. snapshot_id·대상 요소·포커스·비밀번호 검사는 그대로 유지된다. 기존 서비스의
uiControl이 미지원이면 실행 전 실패, 반환 유실·잘못된 응답이면 unknown이다. 실패한
변경을 다시 보내지 않는다. 정상 변경의 화면 읽기는 3회에서 2회로 줄며, 폰 프로세스 간
호출도 한 번 줄어든다. 실제 화면 관측이 필요한 읽기·완료 검증은 생략하지 않는다.

`HardwareControl.setSystem`은 밝기·자동 밝기·회전·자동 꺼짐에서 변경할 키만 읽는다.
`HardwareSettingUpdate`가 순서대로 한 번 쓰고 같은 키를 다시 읽어 전후값과 verified를
돌려준다. setter 성공만으로 완료 처리하지 않는다. 읽기 실패·부분 쓰기 실패는 전파하고
재전송하지 않는다. 밝기는 자동 모드와 밝기 두 키, 회전 고정은 방향과 자동 회전 두 키를
함께 확인한다. 미조회 값은 채우지 않는다.

설정 응답은 observation_scope:settings와 필요한 필드·before·settings_write만 가진다.
전체 기기의 배터리·연결·센서·카메라 조회 2회를 없앴다. 전체 status와 화면 전원·손전등은
기존 동작을 유지한다. 데스크톱 폰 컨트롤은 부분 결과를 기존 표시와 병합하고, 전체 조회는
기존 상태를 교체한다. 병합된 나머지 표시는 이전 관측이며 새로 검증한 값이 아니다.
기기 선택이 바뀌면 컴포넌트 key가 달라져 이전 폰 상태를 재사용하지 않는다.

## 검증과 배포

- Python 회귀: backend/test_phone_ui.py, test_phone_device.py, test_android_control.py.
  정상 조작의 호출 순서·관측 횟수, 오래된 APK, 화면 판본 거절, 응답 유실, 부분 설정 응답,
  원 영수증 재개와 변경 재전송 없음, 데스크톱 상태 병합을 확인한다.
- Kotlin: HardwareSettingUpdateTest가 키별 읽기/쓰기 횟수·순서, 실제 적용값 불일치,
  미확인 설정, 부분 실패와 관측 실패의 무재전송을 검사한다.
- Android arm64 단위 검사 31건 통과, arm32·arm64 컴파일 및 0.22(versionCode 22)
  APK 빌드 통과. 프런트엔드 tsconfig.app.json 검사 통과.

UI 스크립트는 허브의 다음 원격 호출부터 읽는다. 설정 수집 변경은 새 APK 설치 뒤 적용된다.
USB 연결 폰은 없었으며, 실제 폰의 설정 변경·화면 조작을 통한 전후 시간 비교는 미실시다.
빌드·단위 검사를 설치 완료나 실측 지연 개선으로 보고하지 않는다.


최종 관련 회귀는 6개 파일 합계 130통과다(1차 59, 추가 70, 브라우저 1).
브라우저 검사는 최초 샌드박스의 로컬 소켓 생성 제한으로 실패했고, 허용 환경에서 다시
실행해 통과했다. IBL 파생 정합성도 통과했다. backend 전수 검사는 실행하지 않았다.

0.22의 arm64-v8a·armeabi-v7a APK를 기존 서명으로 검증해 중앙 업데이트 원장에 발행했다.
각 폰의 설치 요청·설치 완료 확인은 수행하지 않았다. 조종실 손발의 앱 업데이트로 설치한
뒤 설정 조회 축소가 적용된다. APK·런타임 발행 원장은 Git 커밋 대상이 아니다.
