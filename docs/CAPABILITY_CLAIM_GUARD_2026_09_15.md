# 능력 부정 주장과 최종 응답 채택

## 문제와 범위

현재 도구를 확인하지 않고 "눈이 없다", "그 기능이 없다"고 단정하며 작업을 포기하는
응답을 교정한다. 미확인 상태의 중단은 허용한다. 과제 달성 기준을 늘리지 않으며
새 IBL 어휘·문법도 추가하지 않는다.

구현은 `backend/cognition/capability_guard.py`와 `capability_guard_runtime.py`.
`agent_pipeline.py`의 일반 실행·의식 되묻기·감독 평가·구 평가 경로가 공통
`adopt_response`를 사용한다. 고정 재기동/세션 초기화 안내는 제외한다.

## 동작

1. 부정 어구는 검사 후보만 지명한다. 후보가 없으면 추가 모델/몸 조회는 0회다.
2. 설정된 classify 모델이 도구 없는 API 요청으로 응답·사용자 요청·실행 증거를 읽는다.
   상태는 unsupported / limited / unknown / meta. 인용·비판은 meta다. limited에는
   제공된 실행 증거 ID가 필요하며, 대상·범위와 증거의 관계는 모델이 판단한다.
3. unsupported이면 현재 실행자의 도구와 활성 사전을 읽기 전용으로 한 번 조회한다.
   실행자의 노드 제한을 적용하고 모델이 만든 셸/IBL/파일 경로는 실행하지 않는다.
   `[self:body]`는 변경 이력 어휘이므로 이 용도로 오용하지 않는다.
4. 관련 기능 항목이 발견되면 기존 실행자가 현재 권한·이미지·대화·실행 증거와 남은
   턴 예산으로 원래 작업을 한 번 이어간다. 항목 존재는 접근/실행 성공의 보증이 아니다.
   추가 능력 조사 라운드 대신 실제 원작업을 수행하게 한다.
5. 재응답에 후보가 있으면 남은 판정 예산으로 검사한다. 무근거 단정이 남으면 판정된
   **정확한 원문 문장**을 대상이 붙은 미확인 표현으로 교체하고 끝낸다. 거짓 단정 뒤에
   모순되는 주석을 덧붙이지 않는다. 제한 확인·미확인·메타는 보존한다.

조회 실패/검색 결과 없음은 능력 부재의 증거가 아니다. 첫 판정 실패 시 원문을 보존하고
검사 실패를 기록한다. 재판정 실패 시 새 문장을 유죄로 간주하지 않으며, 이미 판정한
동일 원문만 교정한다. 취소·턴 예산 소진 시 새 작업을 시작하지 않는다. 평가 후 새로
생긴 단정에는 조회·문구 교정만 허용하고, 승인/전달된 작업에 새 실행을 붙이지 않는다.

## 비용 경계

`world_pulse_config.json`의 선택적 `capability_guard` 블록으로 끄거나 아래 기본 상한을
낮출 수 있다. 설정이 없으면 활성화한다. `enabled:false`로 되돌릴 수 있다.

| 설정 | 상한 |
|---|---|
| `max_judgments` | 턴당 2회 |
| `max_lookups` | 턴당 1회 |
| `max_resumes` | 원작업 재개 턴당 1회 |
| `input_bytes` | 판정 시스템 프롬프트+입력 UTF-8 24,000바이트 |
| `output_tokens` | 판정 API 출력 1,600토큰 |
| `judge_timeout_s` | 판정 호출 대기 15초 |
| `lookup_timeout_s` | 몸 조회 대기 3초 |

긴 본문은 부정 위치 주변을 발췌하고 증거는 입력·결과 쌍으로 예산 안에 넣는다.
생략 여부와 생략 호출 수를 판정기에 알린다. 판정 API는 도구/세션/재시도/자동 이어쓰기를
사용하지 않는다. SDK 연결 시간 제한과 대기 마감을 함께 적용한다. 시간 초과 뒤 요청이
정리 중이어도 출력 상한과 최대 4개 읽기 작업의 동시성 제한은 유지한다. 원작업 재개는
별도 판정 예산이 아니라 기존 작업의 권한·턴 토큰/시간 예산을 소비한다.

제한된 전송은 Gemini SDK, OpenAI 호환 SDK(DeepSeek 포함), Anthropic SDK를 지원한다.
classify가 네이티브 CLI나 미지원 전송이면 다른 모델/무제한 호출로 폴백하지 않고 검사
실패로 기록한다. 실행 모델 선택은 바꾸지 않는다.

## 전달·저장·관측

하위 실행/평가의 `final`은 후보로 보류한다. 스트리밍 초안과 도구 활동은 계속 전달하고,
채택 후 `final` 한 번만 방출한다. `_after_response_async`와 과제 요약은 동일한 채택
본문을 사용한다. ChatView는 도구 시작 전 보이던 이번 턴의 임시 말풍선을 최종
`response` 수신 시 정리한다. 이전 턴·도구 기록은 유지한다.

기존 궤적에 `capability.judged/lookup/resumed/adopted/failed/skipped`를 남긴다.
판정 입력/결과, 몸 조회, 교정 전후 본문은 기존 턴 증거 저장소에 ID로 연결한다.
모델 사용량은 `model.call_*`, `model.input`, `model.usage`와 현재 턴 토큰 원장에 합류한다.

## 검증과 한계

- `backend/test_capability_guard.py`: 눈 없음→확인→원작업 재개, ffmpeg 일반화→미확인,
  메타/정당한 제한 보존, 반복 단정 교체, 취소/판정 실패/조회 실패/긴 응답, 허위
  원문/증거 ID 거절, 경로별 final·저장 일치.
- `frontend/scripts/test-capability-chat.mjs`: 실제 ChatView를 격리 Chromium에 띄워
  초안→도구→교정 응답→중복 수신→이력 재로드를 확인. API/WS는 고정물이며 실 계정
  데이터를 변경하지 않는다. 화면은 `outputs/capability_guard/chat-adopted.png`.
- 실제 설정의 DeepSeek 분류 모델은 눈 없음과 ffmpeg의 `missing.srt` 오류를 기능 전체
  부재로 일반화한 주장을 unsupported, 이를 인용해 비판한 문장은 meta로 판정했다.
  관측 지연 약 0.9~1.8초/회, 출력 63~69토큰/회. 이는 연결 확인이며 일반 정확도나
  운영 비용에 대한 대조 실험 결과가 아니다.

어구 후보와 경량 의미 판정에는 누락·오판 가능성이 있다. 전반적인 프레임의 좁음이나
무능 단정 없이 나쁜 수단을 선택하는 경우까지 교정하지 않는다. 기능 사전은 특정 파일·URL
접근이나 외부 프로그램 옵션을 증명하지 않는다. 운영 효과는 실제 원작업 재개·완수,
검사 실패·예산 소진, 추가 모델 사용량으로 확인한다.
