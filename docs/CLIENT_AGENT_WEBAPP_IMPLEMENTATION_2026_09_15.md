# 클라이언트 담당 에이전트 — 첫 구현

외부 클라이언트의 채팅과 앱 요청을 허브가 받아 처리하고, 산출물은 요청자에게 전달한다.
주인의 SystemAI·개인 에이전트·스케줄러를 외부 요청으로 호출하지 않는다.
설계 정본: `CLIENT_AGENT_WEBAPP_PLAN_2026_09_15.md`. 이 문서는 첫 구현 범위와 실제 계약을 설명한다.

## 실행 경로

`웹 채팅 / 공개 앱 → /m/run 또는 /m/requests → client_agent.run → MemberSessionManager → MemberRunner → 기존 IBL`

- `MemberRunner`의 역할 이름은 **클라이언트 담당 에이전트**다. 인증 주체는 여전히 member이며 에이전트 이름은 권한이 아니다.
- `client_agent.py`는 services 층의 전송 독립 함수다. 인증은 표면에서 세우고 서버의 principal에서만 읽는다.
- 웹앱의 기본 모드·버튼은 `action_id + args`를 보낸다. 서버가 현재 공개 카탈로그에서 템플릿을 찾는다. 문자열 입력은 JSON 리터럴 안에서 이스케이프한다.
- 목록의 행 클릭·동적 옵션과 사용자 로컬 apps.json의 IBL은 기존 `code` 호환 경로를 이용한다. 모두 같은 클라이언트 요청 처리와 실행 직전 회원 관문을 지난다. 모든 하위 UI 액션의 ID 전환은 후속 범위다.
- 네이티브 helper에는 기존 앱 IBL 계약을 유지한다. 웹용 동작 ID와 보고서 산출물 전달을 native 설치 요구로 바꾸지 않는다.
- 조회·파일 동작 등 결정된 IBL은 모델을 초기화하지 않는다. 자연어 작업은 기존 인지 파이프라인과 API 모델을 쓴다.
- 기기 연결 없는 허브 텍스트·공개 검색도 가능하다. 파일·미디어·위치 단계에서 기기 연결을 확인한다.
- 도구 설명에서 회원 경로가 지원하지 않는 인자·주인용 예제를 제거했다. `describe`는 공개된 액션만, `read_result`는 이번 회원 턴의 증거 저장소만 조회한다. 회원 카탈로그를 간결하게 공급하며 주인용 교재를 함께 싣지 않는다.
- `ask_user_question`은 회원 전용 비차단 구현이다. 질문을 결과로 반환하고 실행기를 해제한다. 다음 답변은 같은 작업 ID의 대화로 이어진다.

## 버전 1 계약

`/m/profile`의 `client_protocol`은 version, 서버 epoch, retry_window_s를 반환한다.
새 요청은 `version:1`, `request_id`, `task_id`(conversation ID), `message` 또는 `action_id + args`를 보낸다.
인증 key와 기존 body_session은 HTTP 어댑터 필드이며 공통 실행 함수에 신원을 주입하는 수단이 아니다.
`capabilities`는 기기 기능 설명이지 허브 권한 부여가 아니다. 브라우저는 files와 javascript를 알린다.

요청별 원장은 RAM에만 있으며 키는 인증된 회원 ID + 기기 ID + request_id다.
본문 충돌·이전 브라우저 세대·진행 중 재호출은 재실행하지 않는다. 끝난 동일 요청은 보관된 결과를 돌려준다.
기본 보관/재전송 창은 30분, 최대 512건·64MB(진행 중 결과 예산 예약 포함)다. 재시작 epoch 불일치는 결과 불명이다.
브라우저는 연결 실패나 새로고침 뒤 작업을 자동 재실행하지 않는다. 30분을 넘는 재전송의 중복 방지나 영구 작업 큐는 제공하지 않는다.

이벤트에는 request_id와 conversation_id가 들어간다: accepted, progress, input_required,
client_action_required, result_ready, delivered, error. 기존 NDJSON의 event/result 포장은 유지한다.
기존 `/m/chat` HTTP/WS와 request_id 없는 `/m/run`은 기존 세션 어댑터로 남아 있다.

첨부는 최대 5개의 `{id,name,text,sha256}` 인라인 텍스트(개당 256KB)로 전달하고 지문을 확인한다.
이것은 서버 파일 경로 참조가 아니다. 큰/바이너리 파일은 기존 클라이언트 파일 읽기·문서 변환을 이용한다.
첨부 선택 UI·별도 업로드 객체 저장소·재접속 동기화는 아직 추가하지 않았다.

## 실제 조사와 산출물 전달

- 기존 `sense:search`, `sense:crawl`에 감사된 외부 경로를 추가했다. 새 IBL 낱말은 없다.
- 외부 search는 source:ddg 단일 질의다. 개인 관점 편집·주인 브라우저·로그인 쿠키·공유 원문 캐시를 사용하지 않는다.
- ddgs의 전역 분산 캐시를 비활성화하고 검색 워커에도 회원 문맥을 보존한다. 주인 검색 경로는 그대로 둔다.
- crawl은 공개 HTTP(S) 텍스트만 읽는다. DNS 결과의 모든 주소를 검사하고 검증한 IP로 직접 접속한다. 리다이렉트도 재검사한다. 로그인·브라우저 자동화 폴백은 없다. 크기·읽기 시간에 한도가 있다.
- 정기보고 제작은 서버의 `research_report` 절차다. 검색 후 최소 2개의 읽을 수 있는 원문을 확보하고 모델로 보고서를 만든다. 실패하면 템플릿을 대신 저장하며 완료라고 하지 않는다.
- 채팅에서도 같은 공개 검색·원문 읽기와 회원 파일 저장 도구로 보고서를 요청할 수 있다.
- 보고서 앱의 결과는 산출물 ID·이름·MIME·크기·SHA-256·본문으로 전달한다. 경로를 허브 PC의 outputs로 해소하지 않는다.
- 브라우저가 지문 확인 → IndexedDB 저장 → 재읽기 확인 → `/m/receipts`를 완료해야 delivered가 된다. 서버는 수신자·요청·산출물·크기·지문을 대조한다.
- 일반 IBL 파일 쓰기도 브라우저 저장 크기/지문을 검증하고 전달된 파일 목록을 반환한다.
- 영수증 통신만 실패해도 이미 저장된 파일은 보존하고 내려받을 수 있다. 생성 완료·기기 저장·허브 확인을 구분한다.

허브의 요청별 임시 폴더는 턴 종료 시 정리한다. 재전송을 위한 결과 본문은 위 한도 안에서 RAM에 한시 보관한다.
주인의 보고서 폴더·공유창고·기억에 회원 산출물을 영속하지 않는다.

## 초대와 연속 작업

주인 관리창에서 새 사용자 이름 → 초대 키 발급 한 번으로 이웃 생성·키 발급·기기 결합·승인을 수행한다.
기존 사용자에게 다른 기기용 키를 추가할 수도 있다. 발급 실패 시 이번에 만든 이웃은 되돌리고 실패 키는 폐기한다.
별도 USB 파일·사용자별 기능 허가 단계가 없다.

브라우저 새로고침 전의 대기 poll은 새 연결 세대의 명령을 가져가지 못한다.
회원의 회상 입력에는 현재 작업의 결과 요약만 포함한다. 과거 memory_recall/memory_save 봉투·바이너리 파일을 다시 넣지 않으며,
회상 본문 한도 때문에 빠진 맥락은 생략 사실을 모델에 전달한다.

## 후속 범위

다른 앱의 제작 흐름 이관, 모든 행 클릭/옵션의 동작 ID 전환,
`/nodes/ask`의 독립 IndieBiz 인증 어댑터, 오프라인 작업/동기화는 이번 첫 구현에 포함하지 않는다.
현재 원격 런처와 기존 주인 장치 간 통신은 변경하지 않는다.

## 검증

- 전체 backend 회귀를 실행했고 새 코드에서 발견된 async 선언 조회와 MIME 규약 검사 2건을 수정한 뒤 해당 검사와 회원/요청/관리 회귀를 다시 통과했다.
- TypeScript 실제 프로젝트 검사와 Vite 배포 빌드를 통과했다. IBL·회원 셸·Android 번들을 재생성했다.
- 로컬 검증 서버에서 인증 계정만 시험용으로 대체하고 실제 API 어댑터·MemberSessionManager·모델 API·검색·공개 페이지 읽기·브라우저 IndexedDB를 연결했다. 가짜 보고서 응답을 사용하지 않았다.
- 앱 보고서: 실제 검색/원문 확인/모델 작성 → 브라우저 저장 → SHA-256 수신 확인 → 다운로드 확인.
- 채팅 보고서: 실제 검색 → 회원 IBL 파일 쓰기 → 기기 저장 영수증/파일 재읽기 확인.
- 실제 DOCX 라이브러리로 양식 채우기 후 브라우저에 전송된 문서의 내용 확인. 위치는 Playwright가 허용한 시험 좌표를 브라우저 geolocation으로 반환해 왕복을 확인했으며 실제 GPS 측위 검증은 아니다.
- 새로고침 뒤 파일 유지·다른 회원 저장소 분리·좁은 화면의 가로 넘침과 JS 오류를 검사했다. 운영 사용자/기기용 키를 시험 목적으로 발급하지 않았다.
