# connected_limbs 장치 소개 최소화와 드라이버 정보 이관 수리계획

작성일: 2026-11-01. 상태: **구현 반영, 검증 범위는 §7**. §1~6은 구현 기준 설계다.

**장치 소개에는 식별·환경·배치·용도와 드라이버 참조만 남긴다.**
연결 상태·권한·설치 판본·조작법·검증·복구 정보는 드라이버 쪽에서 갱신·관리하고,
필요한 작업을 할 때 해당 대상의 정보를 조회한다. 에이전트에는 대상을 고르는 정보와
사용할 수단의 입구를 주고, 모든 장치의 운영 상세를 매 턴 읽히지 않는다.

이 계획은 [하드웨어 드라이버 소유 구조 수리계획](HARDWARE_DRIVER_OWNERSHIP_REPAIR_2026_11_01.md)의
장치 소개 부분을 구체화한다. 진행 중인 드라이버 개편의 레지스트리·조회 경로를 재사용한다.
[제어 드라이버 설계](CONTROL_DRIVER_DESIGN_2026_10_20.md)의 실행·검증·복구 책임과
[IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)의 품질·시간·전체 토큰 기준을 따른다.

## 1 근거와 범위

오늘 #5665의 새 실행 세션 첫 요청에서 connected_limbs는 6,613자였다.
장치 11개 행은 2,237자, Android·PC·TV 제어 요약은 3,579자,
공통 안내·포장 등은 797자였다. 이는 문자 수이며 실제 토큰 수가 아니다.

최종 사용자 지시에 따라 존재 안내만 남기는 직전 안을 대체하고, 아래 다섯 범주의 장치별 소개를 유지한다.
장치가 늘면 짧은 소개 행은 늘지만, 장치별 상태·드라이버 본문·절차 설명이 함께 늘어나지는 않게 한다.
상시 입력 고정 크기나 3,000~3,500자 같은 이전 목표는 완료 조건으로 사용하지 않는다.

기준선은 다른 에이전트의 드라이버 개편이 반영된 정본에서 고정하고 그 개편과 이번 수리의 효과를 구분한다.
게스트 헬퍼 문서 분할·배포 구현은 기존 개편이 맡는다. 상황 관측 전달, CLI 세션 보존, v7,
전체 IBL 목록과 시스템 구조 설명은 이번 범위에서 바꾸지 않는다.

## 2 장치 소개에 남기는 다섯 범주

| 범주 | 남길 정보 |
| --- | --- |
| 식별 | 장치 이름과 고유 ID. 본체의 __local__ 및 동명이인 장치 구분 유지 |
| 환경 | 장치 종류와 OS 등 등록된 기본 환경. 상세 프로브·프로세스·권한·연결 상태는 제외 |
| 배치 | 사용자가 적은 장소와 배치 설명 |
| 용도 | 사용자가 적은 사용 목적과 역할 |
| 드라이버 참조 | 대상에 해당하는 드라이버를 찾을 수 있는 ID와 조회 가능한 가이드/계약 참조 |

배치·용도는 기존 registration.context를 활용한다. 임의의 모델 요약으로 사실을 만들거나
별도 저장 필드를 중복 관리하지 않는다. 사용자 설명을 문자 목표에 맞춰 무음 절단하지 않는다.
환경도 등록 자료를 사용하고, 소개를 만들려고 매 턴 원격 장치를 탐침하지 않는다.

드라이버 참조는 이름만 있고 찾아갈 수 없는 표식이 아니어야 한다. 기존 guide_db.json과
guide_registry에서 대상별 연결을 파생하며 별도 수동 사전을 만들지 않는다.
여러 장치가 같은 드라이버를 사용하면 짧은 참조를 공유하고, 필요한 공통 조회 위치만 한 번 제공한다.
조작면이 여러 개면 해당 참조를 구분하되 호출 예·인자·성공 판정은 펼치지 않는다.

공통 안내는 이 목록이 등록된 대상의 소개이며 실시간 접속·실행 가능을 보증하지 않는다는 의미와
조회 입구만 짧게 담는다. 장치 소개에 새 행동 규칙이나 제어 전 일괄 조회 절차를 붙이지 않는다.
기존 허용 범위·오프라인 장치의 발견 가능성·본체 소개·등록 제외 기준을 유지한다.

## 3 드라이버가 갱신하고 관리할 정보

| 정보 | 소유·제공 경로 |
| --- | --- |
| 연결·중지 상태와 관측 시각 | 기존 장치/관측 원장을 드라이버가 조회하고 필요한 동작 결과에서 갱신 |
| 사용자 세션·machine 서비스·실제 권한·지원 가능성 | 대상별 실행 범위와 권한 관측. 실제 호출 단계에서 확인 |
| 드라이버 매핑 충돌·지원 미확인 | 드라이버 발견/상세 조회에서 대상과 함께 표시 |
| 설치 부품·설치 세대·판본·업데이트 상태 | hardware_driver_status와 기존 PC/폰 설치 구현 |
| 호출 인자·예제·준비·완료 판정·복구 | 기존 드라이버 가이드와 실행 부품·함수/액션 계약 |
| 기기별 상세 환경·관측 본문 | 기존 단일 대상 조회와 control_observations |

동적 상태를 가이드 Markdown에 덧붙이라는 뜻이 아니다. 기존 등록·관측·설치 원장을 정본으로 유지하고,
드라이버가 그 자료의 확인·갱신과 실행 계약을 맡는다. 소개에서 뺀 권한·설치 세대 등이 실제 실행의
대상 결속과 검증에서도 빠지지 않도록 한다. 사용자 세션과 machine 서비스의 신원을 합치지 않는다.

## 4 필요한 정보를 사용하는 경로

소개로 대상과 드라이버를 선택하고, 필요한 계약·상태가 없을 때 기존 조회를 이용한다.
이미 현재 문맥에 있는 유효한 계약을 매번 다시 읽도록 강제하지 않는다.
선택한 부품에 계약을 붙이는 callable_control_briefs·surface_control_guide 경로는 유지한다.

현재 self:limb list의 limb 인자는 이름/ID로 좁힌 장치 상세 조회이며,
target 인자는 해당 대상의 관측 목록 조회다. 두 계약을 구별하고 기본적으로 모든 기기의 상세 원장을
먼저 읽게 만들지 않는다. 가이드/describe와 기존 드라이버 지문 처리를 사용한다.
설치 전 대상은 기존 설치 가이드 경로로 찾는다.

직전 안의 간략 검색·페이지 조회 확장은 이번 수리의 필수 변경에서 제외한다.
현재 소개와 단일 대상 조회로 연결하며 새 어휘·검색 서비스·요약 모델을 추가하지 않는다.

다른 에이전트의 진행 중인 파일을 덮어쓰거나 드라이버 개편을 재구현하지 않는다.
소개에서 뺀 내용을 다른 상시 문맥 블록으로 이동하지 않는다.

## 6 검증과 완료 조건

기존 test_associative_recall.py, test_guide_registry.py, test_control_driver.py와
select_tests.py가 찾는 전이 소비자를 확인한다. 실제 구현 변경 범위에 따라
REGRESSION_TESTING.md 및 어휘 파생·층 검사·몸 번들 규약을 적용한다.

- 소개가 다섯 범주만 포함하고 대상·드라이버 참조가 정확한지 확인한다.
- 장치 수를 1·10·100·1,000개로 늘려 소개 행의 증가와 드라이버 본문/상태의 비주입을 구분해 측정한다.
- 단순한 소개 생성이 원격 탐침이나 전체 설치 상태 조립을 유발하지 않는지 확인한다.
- 본체·동명이인·오프라인·중지 상태·여러 OS에서 대상 선택과 기존 접근 경계를 보존한다.
- 권한·설치 세대·가이드 판본·지원 상태가 바뀌었을 때 드라이버가 현재 정보를 사용한다.
- PC/폰/TV 제어 및 원격 설치·전송에서 필수 인자·조건·결과 판정과 실패 복구를 유지한다.

동일 장치 자료로 소개 문자량을 비교하고 필요한 추가 가이드/상태 조회까지 포함한다.
실제 모델 비교는 비하드웨어 요청·단순 제어·대상 탐색·여러 기기 작업을 구분해
입력·출력·캐시·전체 완료 시간·품질을 기록한다. 격리 실행/기록 재생을 활용하고 끝난 원격 설치나
삭제를 측정 목적으로 반복하지 않는다. 모델 비교가 없는 항목은 문자 절감만 보고한다.

이 문서 반영은 계획의 완료다. 구현 완료는 최소 장치 소개로 대상과 드라이버를 선택하고,
동적 정보와 실행 계약을 드라이버가 관리하며, 그 상세가 상시 입력으로 돌아오지 않는 것을 확인한 시점이다.

## 7 구현과 검증 (2026-11-01)

기준선은 선행 드라이버 수리가 반영된 `8b3a50a6f1900aa3c16b962dc8cbaaebbdb3b7ad`다.
이번에는 `_connected_limbs`의 소개 책임만 축소했다. 새 어휘·저장 필드·모델·검색 서비스를 추가하지 않았다.

### 구현

- 각 `limb`는 `name`, `device_id`, `kind`, `os`, `adapter`, `drivers`와 사용자 context 원문만 가진다.
  종류·OS·어댑터는 등록된 기본 환경이며 서비스 권한이나 실행 가능을 뜻하지 않는다. 빈 속성은 생략한다.
- 대상의 플랫폼·어댑터·실행 범위를 기존 `driver_catalog`/`driver_matches`로 대조한다.
  장치별 ID 참조와 공통 `driver`의 ID·가이드 파일·조작면만 출력한다. 등록은 회상당 한 번 읽으며,
  구형 `control_*` 등록도 같은 카탈로그에서 가이드 참조로 호환 해석하며 설치 부품을 추정하지 않는다.
  구형 OS 대표 매핑이 겹치면 관련 소유자를 제외하고 충돌을 상세에 보존한다.
  충돌한 드라이버를 임의 선택하지 않는다. 충돌·미지원 상세는 기존 대상별 `drivers` 응답에 남는다.
- 본체 `__local__`, 동명이인의 ID, 설명이 있는 오프라인/중지 장치와 무설명 네트워크 기기의
  발견을 유지한다. 초대·만료·회원·제거 대상은 기존 경계대로 제외하며 사용자 설명은 무음 절단하지 않는다.
- 연결 상태·호스트·중지·권한·설치 세대·부품·관측 개수·control_brief와 긴 행동 안내를 제거했다.
  소개는 원격 탐침, 가이드 본문 읽기, 설치 상세 조립, 관측 개수/본문 조회를 호출하지 않는다.
- 공통 안내에는 소개가 실시간 접속/실행 가능을 보증하지 않는다는 뜻과 조회 입구만 둔다.
  `read_guide(query=guide)`는 가이드, `self:limb list`의 `limb`는 이름/ID의 장치 상세,
  `target`은 대상 관측이다. 기존 선택 부품·앱/사이트의 호출 요약과 가이드 지문 재사용을 유지한다.
- 업데이트 대상/설치 세대 결속, 권한 검사, 실행 결과 검증과 복구는 기존 드라이버가 계속 소유한다.
  소개에서 숨긴 정보를 다른 상시 블록으로 이동하지 않았다.

새 control_brief는 모든 규모에서 0개다. 상시 입력이 고정 크기라는 주장은 하지 않는다.

추가 조회 재생은 실제 모델의 선택 대신 아래 조회를 명시했다. 이전 소개에 이미 실린 빠른 호출은
재조회하지 않는 것으로 세고, 새 소개에서는 필요한 가이드 절 응답 전체를 더했다.
단일 대상 상세는 기존 핸들러의 현재 반환 전체를 양쪽에 동일하게 더했다.

문자량 합계는 각 응답을 한 번씩 연결한 크기다. 여러 라운드의 누적 입력 토큰·출력·캐시·후처리 비용,
실제 모델의 대상 선택 품질과 전체 완료 시간은 미측정(null)이다. 별도 모델 비교 없이 전체 비용
절감이나 목표 달성 향상을 주장하지 않는다.
