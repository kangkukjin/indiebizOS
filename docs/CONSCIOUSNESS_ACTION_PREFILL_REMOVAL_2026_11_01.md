# 의식의 자동 액션 선정과 상세 계약 선주입 제거 설계

작성일: 2026-11-01. 상태: 구현 완료. 범위와 검증·실측 한계는 §7.

의식은 목표·제약·판단에 필요한 맥락과 작업 구조를 전달한다. 어떤 액션을 실제 사용할지는
실행자가 전체 액션 요약과 관측을 보고 판단하며, 필요한 상세 계약은 기존 describe로 조회한다.
의식의 자동 추천 목록과 그 목록을 근거로 펼치는 계약을 제거한다. 사용자가 직접 고른 액션은 보존한다.
목적은 [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)에 따라 판단 능력을 유지하며 전체 입력과 왕복 비용을 줄이는 것이다.

## 1 현재 경로와 제거 범위

| 경로 | 현재 동작 | 변경 |
| --- | --- | --- |
| 의식 출력 | capability_focus.highlight_actions에 액션 추천 | 필드·선정 지시·출력 예제 제거 |
| 초기 실행자 입력 | 추천 이름과 최대 4개 액션의 계약 또는 드라이버 조회 안내를 자동 첨부 | 추천 기반 첨부 전체 제거 |
| 후속 턴 계승 | 기존 추천을 보존하거나 경량 모델로 수정 | 새 계승 입력·출력에서 추천 필드 제외 |
| 재규정 | 실행자에게 추천 액션 목록 재전달 | 목록 전달 제거 |
| 감독 문맥 | focused_actions에 추천 액션의 스키마를 자동 확장 | 자동 확장 제거, 명시적 스키마 조회 유지 |
| 사용자 직접 선택 | action_hint → user_selected_action으로 선택과 현재 계약 전달 | 독립 경로 유지, 의식 추천 목록을 경유하지 않음 |

오늘 #5665·#5666의 추천 상세 계약은 각각 13,224자·11,508자였다. 다만 이후 하드웨어 드라이버 개편
8b3a50a6에서 일부 액션은 조회 참조로 바뀌었다. 이 과거 수치를 이번 수리의 예상 절감량으로 사용하지 않는다.
구현 직전 정본에서 기준선을 다시 고정하며, 이미 진행된 다른 입력 수리와 효과를 구분한다.

실행자의 전체 액션 요약·IBL 문법·허용 범위, describe/read_guide, 평가·권한·완료 기준은 유지한다.
사용자 직접 선택 계약, 해마 사례, 선택한 드라이버 계약은 자동 추천 계약과 구분한다.
상상실행 초안 imagined_ibl의 기존 생성·검증 정책은 이번 변경 범위가 아니다. 그 초안에서 추천 목록을
새로 추출하거나 상세 계약을 자동 주입하지 않는다. 전체 카탈로그·시스템 구조 축소도 별도 검토다.

## 2 출력 계약과 책임

capability_focus는 당장은 기존 hint를 보존하는 객체로 유지한다. 이름 변경과 필드 이전을 함께 하지 않는다.

```json
{"capability_focus": {"hint": ""}}
```

hint는 필요한 작업 분해·입출력·의존 관계·불확실성을 담고, 자명하면 비운다.
액션 이름을 반드시 추천하거나 op를 미리 결정하라는 지시를 없앤다. 삭제한 목록과 상세 계약을 hint나
task_framing에 옮겨 쓰지 않는다. 사용자 지정 도구나 이미 확보한 도구 관측은 출처 있는 맥락으로 전달할 수 있다.
복잡한 작업의 분해 기능 자체와 목표·제약·달성 기준은 유지한다.

전체 액션 요약은 실행자가 능력을 발견하는 입구다. describe는 선택한 액션의 실제 호출 계약을 확인하는
수단으로 유지하며, 모든 실행 앞에서 반드시 조회하도록 강제하지 않는다. 기존 문맥으로 충분하면 활용한다.

## 3 사용자 직접 선택 보존

사용자가 마법책에서 고른 액션은 프런트엔드 selectedAction → 요청의 action_hint →
ibl_usage_rag.build_execution_memory_from_hint → user_selected_action으로 전달된다.
이 경로의 현재 계약·허용 범위 검증을 유지하고, 의식 프롬프트의 “highlight_actions 1순위로 옮겨라”만 제거한다.
의식이 비활성인 EXECUTE에서도 사용자의 선택이 실행자에 전달돼야 한다.

의식의 추천을 사용자 선택으로 재분류하지 않는다. 사용자 선택의 취소·변경, 없는 액션·허용되지 않은 액션의
기존 처리도 유지한다. 사용자 직접 선택 경로의 상세 계약은 이번 자동 선주입 제거의 대상이 아니다.

## 4 옛 규정과 세션의 처리

과거 저장 규정에 highlight_actions가 있어도 기록을 삭제하거나 전체 규정을 거절하지 않는다.
현재 사용할 규정의 투영에서 해당 필드를 제거하며 나머지 hint·목표·기준·출처는 보존한다.
기존 ibl_focus 별칭을 읽는 호환 경로도 hint만 계승한다. 잘못된 형태의 은퇴 필드만으로 모델 재시도를
발생시키지 않되, 현행 필드의 자료형 검증은 계속 적용한다.

초기 의식·회원 의식·재규정·저장 규정 읽기·후속 패치 병합 후에 같은 계약을 적용한다.
기존 의식 출력 처리 경계에 공통 투영을 두고 재사용하며, 소비자마다 별도 제거 규칙을 복제하지 않는다.
계승 모델에 보내는 previous에서도 추천을 빼고, 병합 후에도 옛 값이 다시 남지 않는지 확인한다.

이미 CLI 대화 이력에 들어간 과거 계약은 코드 변경만으로 사라지지 않는다. 진행 중인 작업을 강제로
초기화하거나 이력을 편집하지 않는다. 전후 비교는 독립된 새 세션에서 하고, 기존 세션에는 새 추천 계약이
추가되지 않는 것과 옛 문맥이 남는 것을 구분해 보고한다.

## 6 검증과 효과 판정

기존 test_prompt_builder, test_consciousness_output_routing_2026_09_07, test_framing_inheritance_2026_10_07,
test_reframe, test_member_runner, test_vocabulary_prompt, test_conscious_supervisor, test_ibl_usage_rag를 중심으로
scripts/select_tests.py의 전이 소비자를 확인한다. consciousness_schema_check.py의 생산자/소비자 정합도 검사한다.
검사기의 실제 소비자 범위가 재규정·감독·회원 경로까지 닿는지 확인하되, 퇴거 필드를 허용 목록에 넣어
불일치를 숨기지 않는다. 역사 기록에 문자열이 남는 것과 활성 소비가 남는 것은 구분한다.

- 의식 신규 출력·계승·재규정·회원 경로에 자동 추천과 그 상세 계약이 새로 추가되지 않는다.
- 옛 규정이 주어져도 목표·기준·hint는 유지되고 추천 스키마 조회는 실행되지 않는다.
- 사용자 직접 선택은 THINK/EXECUTE에서 보존되며, 선택 변경·취소·허용 범위 검증이 동작한다.
- 실행자 describe와 감독의 명시적 스키마 조회가 정상 동작하고, 휴면/비허용 액션은 기존 경계를 따른다.
- 추천 제거로 목표 기준이나 실행 권한이 바뀌지 않고 선택 문맥이 다른 필드에 자동 복제되지 않는다.

실제 모델 비교는 독립된 새 세션에서 같은 목표·모델·도구 결과를 사용한다. 단순 실행, 복잡한 작업,
낯선 액션, 실패 후 재규정, 후속 계승, 사용자 직접 선택을 포함한다. 원격 설치·삭제를 다시 하지 않고
격리 실행/기록 재생을 사용하며 실제 실행과 재생을 구분한다.
초기 입력뿐 아니라 describe 추가 횟수, 잘못된 호출, 완료 품질, 전체 입력·출력·캐시·후처리 비용과
대기 시간을 함께 비교한다. 초기 문자 감소만으로 전체 토큰·속도 개선을 주장하지 않는다.

구현 시 REGRESSION_TESTING.md와 backend 몸 번들·층·파생물 검사를 따른다.
구현 완료 기준은 모든 추천 생산·계승·자동 확장 경로가 제거되고,
사용자 선택과 명시적 계약 조회 및 목표 달성이 유지되는 것을 확인한 시점이다.

## 7 구현과 검증 — 2026-11-01

초기·회원 의식, 후속 계승·패치, 재규정, 감독에서 자동 추천 생산과 계약 확장을 제거했다.
`consciousness_agent.project_framing`이 현재 사용할 사본에서 은퇴 필드를 제거하고 `ibl_focus`를
현행 키로 정규화한다. 옛 기록 원본과 hint·목표·기준·출처는 보존한다. 은퇴 필드의 잘못된 자료형은
재시도 사유가 아니며, 현행 hint 오류는 기존 한 번 정정 절차를 거친다. 심층연구의 추가 계획에도
같은 검증을 전달한다. 사용자 직접 선택은 THINK/EXECUTE에서 현재 계약을 계속 전달한다.

자동 describe·추천 기반 드라이버 참조와 감독 `focused_actions`를 없앴다. 명시적 describe,
감독의 `tool:`/`ibl:` 근거 조회, 전체 허용 액션 요약, 드라이버 호출 요약, 상상실행·평가·권한은 유지한다.
사용처가 사라진 `deferred_action_guides`와 두 가이드의 `defer_action_contracts` 메타데이터도 정리했다.
스키마 감사는 재규정·감독·회원·계승의 focus 소비를 추적하며 은퇴 필드를 허용 목록에 넣지 않는다.

### 새 세션 모델 비교

기준선은 구현 직전 정본 `607e8a9c`다. `scripts/probe_consciousness_prefill.py`로 같은 모델(opus,
medium effort), 같은 목표·고정 규정·관측을 새 CLI 세션에 넣고 순수 IBL을 실제 실행했다.
전후 실행 순서를 번갈아 배치했으며 실제 기기의 설치·삭제·원격 명령은 실행하지 않았다.
재규정은 전후 render 경로, 후속은 고정된 계승 규정의 실행 입력 재생이다. 계획 모델의 생성·계승
판단 전체를 호출한 시험은 아니며 그 연결은 회귀 시험으로 확인한다. 사용자 선택 계약은 두 조건 모두 유지한다.

전체 토큰에는 해당 왕복 입력이 포함된다. **초기 입력 감소는 확인했으나 전체 비용·속도 개선은 확인하지 못했다.**
의식 생성·후처리 모델 비용은 미측정이며 운영 전체의 절감으로 주장하지 않는다.

옛 CLI 세션에 이미 실린 계약은 그대로 남는다. 활성 작업을 초기화하거나 과거 이력을 수정하지 않았다.
하드웨어 측정 스크립트의 추천 입력은 `--baseline`과 `--after`의 역사 조립기로만 재생한다.
기본 `--after=8b3a50a6`이며 현재 자동 추천 경로를 되살리지 않는다. 후속 명시적 describe 추산은
현재 공개 계약을 사용하므로 초기 조립의 고정 역사 비교와 구분한다.
