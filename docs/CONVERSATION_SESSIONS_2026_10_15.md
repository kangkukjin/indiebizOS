# 대화 세션의 저장과 실행

시스템 AI·앱메이커·일반 프로젝트 에이전트의 대화를 세션 단위로 소유한다. 새 세션은 새 대화 맥락으로 시작하며, 이전 세션은 다시 열어 이어간다. 중앙관리형 회원의 자율주행은 기존 로컬 task를 대화 세션으로 사용한다. 연구 프로젝트는 이미 주제별 대화·자료실·분석을 소유하므로 기존 구조와 전용 ChatSession 연결을 유지한다.

## 저장 계약

- 시스템 AI는 system_ai_memory.db, 일반 프로젝트는 프로젝트 conversations.db를 정본으로 유지한다. conversation_sessions가 소유자·이름·생성/갱신시각을 가진다. 모든 대화는 자동 저장되며 별도 보관·복원 상태 없이 언제든 이어간다. 기존 원문 테이블의 session_id가 처음 저장할 때부터 소속을 고정한다. 전체 시간순 로그를 화면에서만 나누지 않는다.
- 기존 원문 ID와 내용은 유지하고 대상별 ‘기존 대화’ 세션에 멱등 이관한다. 연구·리허설 프로젝트 기록은 일반 세션 이관에서 제외한다. 새 세션은 무작위 ID를 가지며 다른 소유자의 ID로 조회·실행할 수 없다.
- conversation_turns는 세션 아래의 요청 실행, conversation_events는 진행·도구·결과 사건, conversation_task_links는 별도 MCP/위임 콜백이 돌아올 원래 소속이다. 같은 세션의 실행은 하나만 접수한다. 서로 다른 세션은 독립 실행할 수 있고, 화면 전환·창 닫기는 중단 요청이 아니다.
- 실행 중 앱 재시작은 interrupted로 표시한다. 자동 재실행하지 않는다. 도구 실행의 실제 완료 전에는 새 턴을 접수하지 않는다. 명시적 중단은 해당 세션 실행에만 전달한다.
- TODO·질문·계획, CLI provider의 재개 키, 프레이밍·pursuit 문맥과 요약 체크포인트도 세션별로 분리한다. 에이전트 설정·역할·장기기억·작업 파일은 기존 공유 범위를 유지한다. 세션은 파일 시스템을 복제하는 작업 트리가 아니다.

## 길어진 대화

원문은 계속 보관하며 화면은 최근 50건부터 이전 기록을 더 읽는다. 모델에는 해당 세션의 최근 대화를 문자 예산으로 제한하고 기존 재귀 요약 체크포인트를 앞에 붙인다. 체크포인트는 가장 오래된 미처리 구간부터 따라잡으며 적용 경계와 요약 판본을 남긴다. 이것은 토큰 수를 직접 세는 제한은 아니다. 최근 대화의 이미지 처리는 기존 정책을 따른다.

따라서 세션의 기록 길이와 모델 한 번의 입력 길이는 별개다. 긴 세션도 계속 이어갈 수 있지만 오래된 모든 원문이 매번 모델에 입력되는 것은 아니고, 요약에는 정보 손실이 있을 수 있다. CLI 모델은 기존 provider의 컨텍스트 관리도 함께 적용한다.

## 화면

모든 대화 표면은 대화창 맨 위의 **히스토리 · 새 세션** 버튼을 사용한다. 별도 세션 컬럼은 없다. 히스토리를 열어 제목을 선택하면 현재 대화창에 그 세션이 나타나며, 새 세션은 빈 대화로 시작한다. 새 세션 버튼을 다시 누르면 같은 소유자의 미사용 기본 제목 세션을 재사용한다. 메시지·실행 이력·작업 연결이 있거나 이름을 지정한 세션은 재사용하지 않는다. 생성과 조회는 한 쓰기 트랜잭션으로 묶어 여러 창의 동시 요청도 빈 세션을 중복 생성하지 않는다. 일반 프로젝트의 에이전트 선택 목록은 유지하되 그 아래 세션 목록은 제거한다. 첫 사용자 요청이 기본 제목이 되며, 시스템 AI의 예약 실행도 작업의 최초 요청으로 기본 제목을 채운다. 공백을 정리한 앞 60자를 쓰며 이미 정해진 제목은 유지한다. 예약 요청의 기록 유형은 agent_report로 보존한다. 현재 선택과 진행 중 실행은 재접속해 회수한다.

시스템 AI·앱메이커·일반 프로젝트의 히스토리는 모든 세션을 마지막 대화 날짜별로 보여준다. 이름 옆 편집·보관 버튼과 별도 안내문 없이 제목을 누르면 바로 열린다. 창은 최대 폭 1040px·화면 폭 94%·높이 82%를 사용하고 목록이 내부에서 스크롤된다. 과거 DB의 archived 열은 남아 있어도 조회·재개 조건과 API 응답에 쓰지 않는다. 본문은 기기 시간대 날짜 구분선과 50건씩 이전 기록 읽기를 유지한다. 연구 프로젝트는 같은 상단 버튼을 쓰되 새 세션은 새 연구 주제 생성이며 자료실·분석·주제별 저장은 그대로다.

원격 `/launcher/app`과 구형 기기용 `/launcher/lite`는 같은 `/chat-sessions` API를 쓴다. 화면 크기와 무관하게 목록은 히스토리 창에서만 표시한다. 경량판은 ES5/XHR와 구식 블록 레이아웃을 유지한다. 늦게 도착한 다른 세션의 조회·전송 결과는 현재 화면을 덮어쓰지 않는다.

폰 자체 엔진(`phone-local`)도 같은 저장 모듈과 API 계약을 사용한다. `phone_chat_sessions.py`는 폰의 시스템 AI/프로젝트 실행자를 세션에 바인딩하며, 최근 대화와 실행 취소를 세션별로 격리한다. 폰의 원문은 폰 로컬 DB에 남는다. 공통 웹 표면은 새 번들 설치 후 이 API를 사용하며 맥 원격 대화로 대체하지 않는다.

회원 데스크톱/브라우저/네이티브 셸도 위쪽 히스토리와 새 세션 버튼을 사용하며 작업 폴더 설정은 앱 표면에서 연다. 기존 tasks·conversations(task_id) 구조를 유지한다. ‘새 세션 시작’은 입력 전에 빈 세션을 실제 저장한다. 미소속 옛 대화는 회원 로컬 저장소에서 ‘기존 대화’로 멱등 이관하며 사건 기록을 임의의 500개 창으로 잘라 버리지 않는다. 회원 기기의 기존 단일 실행 제한은 유지한다. 다른 세션을 열고 보거나 새 빈 세션을 만들 수 있지만 동시에 두 작업을 실행하지는 않는다. 최근 40개 저장 기록과 기존 문자 제한을 회수하며, 회원용 새 요약 서비스는 이번 변경에 포함하지 않는다. 회원 장기기억은 기존대로 공유한다.

## 구현과 검증

저장: backend/datastore/conversation_sessions.py. 서비스/API: chat_session_service.py, api_chat_sessions.py. 화면: SessionWorkspace.tsx, useConversationSession.ts. 연구 연결은 ChatView의 외부 ChatSession 우회 경로를 유지한다.

회귀는 세션 A/B/A 재개, 기존 기록 이관, 소유권·취소·중복 실행, 요약/CLI 키/패널 격리, 실제 채팅 어댑터의 저장·맥락 전달을 검사한다. Playwright는 실제 React 화면과 회원 셸에서 대화 표시·전환·재접속을 검사하고, 프로젝트 목록의 배치·연구 전용 연결 유지·IndexedDB 이관도 검증한다. 모델 응답은 시험용으로 대체하며 실서비스 모델 호출을 통과한 것으로 주장하지 않는다.

대화 헤더는 세션 제목·히스토리·새 세션·IBL 사전을 한 줄에 놓는다. 데스크톱 공통 대화창의 이전 대화 읽기도 같은 줄에 놓고 본문에서는 제거한다. 이전 기록을 불러온 뒤 읽던 스크롤 위치를 유지한다. 제목 아래 도우미·모델 설명 줄은 표시하지 않는다. 좁은 화면은 버튼 간격을 줄이고 제목을 말줄임한다. 원격·폰은 기존 조종실 사전을 대화용 팝업에서도 재사용하고, 액션 선택은 대화 입력칸에만 추가한다. 회원·구형 런처도 기존 세션 제목과 두 버튼을 한 줄에 놓는다.

### 기존 DB의 응답 전달 복구 (2026-10-16)

정보센터 에피소드 4792는 AI의 최종 답변과 평가가 남았지만 첫 도구 사건 저장에서
`no such column: stream_content`가 발생해 대화로 전달되지 않았다. 새 DB 생성문에만
열을 추가하고 기존 `conversation_turns`의 스키마 이전을 빠뜨린 것이 원인이었다.
`ensure_schema`가 기존 열을 확인해 누락된 스트림 버퍼를 기본값과 함께 추가한다.
반복 초기화는 기존 실행·사건·작성 중 버퍼를 보존한다. 오류 사건 저장도 실패할 때
`chat_runs`는 원래 예외를 유지하고 세션 실행을 실패로 기록한다.

- 이전 스키마·새 스키마 양쪽에서 프로젝트/시스템 AI의 실제 채팅 어댑터를 검사하고,
  오류 알림 저장 실패에서도 완료로 오기록하지 않는 회귀를 추가했다. 관련 32건 통과.
- 일반 backend 전수 10,449건 통과·1건 건너뜀, 재시작 프로세스 검사 24건 통과.
- 정보센터 DB를 SQLite backup으로 보존한 뒤 검수 원문의 SHA-256을 대조해
  해당 세션에 최종 답변 2,890자를 복구했다. 복구 영수증과 백업은
  `data/_backups/2026-10-16_chat_response_recovery/`에 둔다.
- 실행 백엔드의 코드 지문 일치, health/대화 조회 200, 시스템 AI 기존 DB의 자동 이전,
  실제 Electron 정보센터 대화창의 답변 표시를 확인했다. 추가 유료 모델 호출은 하지 않았다.

### 히스토리 단순화 (2026-10-16)

모든 대화의 자동 저장·선택·재개만 유지한다. 세션 보관 상태와 API 변경 옵션,
화면의 연필·보관 버튼·복원 안내·재개 제한을 제거했다. 새 DB는 보관 열을 만들지 않으며,
과거 DB에 남은 값은 원문을 건드리지 않고 무시한다. 데스크톱·원격·경량 런처의
선택/전송 조건도 같은 계약을 따른다. 연구·회원 히스토리 창 역시 넓혔다.

- 기존 상태값이 있는 DB의 원문 보존·즉시 재개를 포함한 저장/폰/실행 검사 39건 통과.
- 일반 backend 전수 10,450건 통과·1건 건너뜀, 재시작 검사 24건 통과.
- React·원격·연구·회원 화면 검사 15건 통과. 최종 React 검사도 별도 통과했다.
  빌드와 겹친 중간 실행 1회는 Vite 접속 거절로 실패해 빌드 완료 후 재실행했다.
- TypeScript·Vite 빌드, i18n 검사 및 소스 구문 검사, 회원 셸·폰 매니페스트 생성 완료.
  실제 Electron 정보센터에서 큰 히스토리 창·버튼/안내 제거·기존 대화 유지와
  실행 백엔드의 코드 지문 일치·세션 API의 보관 필드 제거를 확인했다.
  실제 폰/회원 앱 재배포와 추가 모델 호출은 하지 않았다.

이전 대화 읽기도 제목·히스토리와 같은 헤더 줄에 놓는다. 원격·폰·구형 런처까지 적용하며, 더 읽을 기록이 없는 세션에서는 버튼을 숨긴다.

회원 공통 셸도 세션 제목·이전 대화 읽기·히스토리·새 세션·IBL 사전을 같은 줄에 놓는다.
세션 스냅샷과 저장 형식은 유지하고, 처음에는 최근 메시지 50개를 표시한 뒤 이전 대화 읽기로
50개씩 더 펼친다. 앞에 기록을 붙일 때 읽던 위치를 유지하고 세션을 바꾸면 표시 범위를 초기화한다.
사전은 회원에게 공개된 낱말과 설명만 받아 입력창에 삽입하며 자동 실행하지 않는다.
연결·백업·개인정보 안내·작업 결과는 앱 화면으로 옮기고 대화창의 별도 제목과 세션 안내 줄은 없앤다.
회원 데스크톱 설치물은 공통 셸을 내장하므로 웹 서버 갱신과 별도로 다시 빌드해야 한다.
