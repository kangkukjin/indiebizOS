# 주요 IBL 구현 감사 후 수리 — 2026-09-15

## 문제와 변경

상위 사용 기능에서 search/crawl을 제외한 select/filter/take/union/read/write/edit/memory를 감사했다. take에서는 추가 결함이 없었고, 나머지 기능의 데이터 보존·실패 전파·조회 범위 문제를 수정했다.

- **memory 식별자**: 대화 메시지 ID가 memory_id로 투영돼 같은 번호의 무관한 장기기억을 읽거나 삭제했다. 이제 대화는 원시 결과와 items 모두 conversation_id로 구분한다. read/delete/move는 대화 식별자가 섞인 요청을 거절한다. 장기기억의 정수 memory_id는 유지한다.
- **memory 검색 범위**: node/category를 적용하기 전에 top_k를 잘라 존재하는 기억을 누락했다. SQLite 벡터 KNN의 후보 rowid 서브쿼리와 LIKE 쿼리에 같은 필터를 적용한다. 가지 이름의 `%`, `_`는 패턴이 아닌 리터럴이며 `/` 경계를 지킨다. 필터가 있으면 분류·가지가 없는 대화는 결과에 섞지 않는다.
- **write/edit 저장 실패**: 원본을 비운 뒤 쓰던 경로를 같은 디렉터리의 임시 파일 쓰기→flush/fsync→원자적 교체로 바꿨다. 쓰기/flush/교체 실패 시 원본 바이트를 보존하고 임시 파일을 정리한다. 기존 파일 모드와 심볼릭 링크 대상을 유지한다. RED 준비·완료 관문도 유지한다.
- **edit 동시 실행**: 같은 정규화 파일 경로의 읽기→변경→저장 전체를 OS 잠금으로 직렬화한다. write도 같은 잠금에 참여한다. 잠금 파일은 교체 대상 inode와 분리해 핸들러 재로드·다중 프로세스에서도 같은 경로를 잠근다. 실패 시 잠금은 해제된다.
- **edit 줄바꿈**: 읽을 때 개행을 보존한다. 균일 CRLF 파일은 self:read에서 받은 LF 본문으로 여러 줄을 교체해도 CRLF를 유지한다. 줄 범위 교체도 기존 블록의 CRLF를 따른다.
- **union 실패 전파**: on_error:stop은 items/table 보유 여부와 무관하게 실패 분기를 전파한다. 전 분기 실패도 실패로 반환한다. 기본 skip의 부분 데이터 보존·경고 계약은 유지한다. 같은 분기 처리기를 쓰는 merge도 동일하게 적용된다.
- **select/filter 행 검증**: 객체가 아닌 행을 성공 결과에서 조용히 버리지 않고 입력 오류를 반환한다.
- **read PDF 범위**: 공개 pages 문자열을 1-기반 양끝 포함으로 파싱한다(2, 1-5,8). 중복은 한 번만 읽고 잘못된 범위는 거절한다. 기존 내부 0-기반 목록 입력은 검증 후 유지한다. 예외에서도 PDF 핸들을 닫는다. 회원 문서 어댑터도 같은 파서를 사용한다.
- **read 메모리 사용**: 전체 파일을 readlines()로 보관하지 않고 한 줄씩 읽으며 전체 행수를 센다. 선택 범위만 보유하고, 범위 없는 읽기는 표시 상한까지만 보유한다. blocks 전체 읽기의 절삭은 truncated/warning으로 알린다.

- **핸들러 캐시의 병렬 무효화**: 전체 회귀 도중 파일 변경 감지와 병렬 read가 겹쳐 캐시 재조회에서 KeyError가 발생했다. 조회 시 모듈 참조를 잡아 현재 호출이 그 스냅샷으로 끝나도록 수정했다. 도구 캐시와 패키지 캐시 각각을 조회 도중 비우는 결정론적 재현을 추가했다.

## 검증과 경계

`backend/test_core8_reliability_2026_09_15.py`에 23개 회귀 사례를 추가했다. 저장 중 부분 쓰기·fsync·교체 실패를 각각 주입하고 원본 보존을 확인했다. 두 편집의 실행 순서를 제어해 모두 남는지 검증했다. 실제 IBL의 PDF/select/filter 및 workflow union 경계를 통과시켰다. 기억은 임시 SQLite DB로 검색→읽기/삭제를 검증하며, 모델을 호출하지 않고 실제 sqlite-vec KNN 후보 필터를 실행했다.

정식 재기동 후 백엔드 상태 ACTIVE, /health 응답 healthy를 확인했다. 실행 중인 코드 지문과 디스크 manifest 지문도 일치한다. 검사 로그는 로컬 outputs/core8_fix_2026_09_15에 보관했다.

회원 개방의 path_audited는 변경 후 재감사했다. member_documents는 명시된 기기 파일만 임시 작업공간으로 받고, 입력 옵션을 제한하며 DOCX 이미지 추출을 끈다. PDF 범위 파서 변경은 파일 경로를 생성하거나 추가 입력을 열지 않는다. fill의 경로·기기 출력 영수증 경계는 유지했다. 패키지 구현 지문을 새 코드에 맞춰 갱신하고 어휘 빌드로 파생물을 재생성한다.

파일 잠금은 이 쓰기 경로를 사용하는 호출 사이의 협력 잠금이다. 외부 편집기의 직접 쓰기를 잠그는 기능은 아니다. 전체 행수 반환을 위해 범위 읽기도 파일 전체를 스캔하며, 보유 메모리는 선택한 본문과 한 줄 크기에 좌우된다. 명시적으로 매우 큰 범위를 요청하면 그 본문만큼의 메모리가 필요하다. 과거에 이미 전달된 출처 없는 정수 ID에 출처를 소급 부여하지 않는다.
