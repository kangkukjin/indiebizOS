# 대화 조향과 중단 인계

작업 중 접수한 지시는 도구 호출이 없어도 실행자에게 전달되어야 한다. 프로세스가
죽었을 때는 기존 사건을 다음 실행자의 문맥으로 잇고, 결과가 불확실한 효과를
성공이나 실패로 추정하지 않는다. 이 계약은 API·CLI 공통 `cognitive_stream` 경계가
소유한다. IBL 실행기를 바꾸거나 별도 작업 큐를 만들지 않는다.

## 접수·전달·확정

`steer_inbox`는 활성 작업의 별칭을 정규 `(agent, task)`로 해소한다. 접수와 종료
확정은 같은 잠금을 쓴다. 대화에 속한 조향은 기존 `conversation_events`에,
연구 대화는 `research_events`에 `handoff.steer.accepted`를 커밋한 뒤 접수 응답을
낸다. 저장 실패·길이 초과·대기열 포화·이미 확정된 응답은 명시적으로 거절한다.
기존 지시를 밀어내거나 시간 만료로 버리지 않는다. HTTP/WS의 저장 호출은
이벤트 루프 밖에서 수행한다.

도구 결과 부록의 기존 전달 경로는 유지한다. API의 도구 없는 응답, CLI의
Bash/Read 등 IBL 밖 도구, 최종 답변 생성 중 들어온 지시는 `dialogue_continuation`이
최종 확정 전에 회수한다. 이전 결과와 추가 지시로 인지 경로를 다시 실행하며,
표면에는 마지막 확정 응답 하나만 내보낸다. 스트리밍 중간 본문은 계속 보인다.
CLI는 기존 세션 매핑으로 재개하며, 기존 정책이 세션을 초기화하거나 의식이
history를 축약해도 직전 결과를 후속 요청에 함께 전달한다.

추가 실행도 같은 작업 신원·권한 범위·취소 상태·턴 자원 예산 안에 있다.
실패·취소·예산 소진이면 재실행하지 않고 미처리 상태를 남긴다. 전달 자체는
처리 완료가 아니다. 성공 응답 확정 때만 전달한 지시의 `steer.completed`를 남긴다.
이것은 모델에 전달하고 응답을 생성했다는 실행 계약이며, 지시 내용의 의미적 준수를
기계적으로 증명한다는 뜻은 아니다.

## 중단 인계

`conversation_handoff`는 같은 소유자·세션(연구는 같은 프로젝트·스레드)의 사건만
읽는다. 기존 `tool_start`/`tool_result`도 읽으므로 새 기록을 만들기 전의 중단도
인계할 수 있다. 호출 ID로 시작과 결과를 짝짓고, ID가 없으면 순서로 추정하지 않는다.

- `effect_unknown`: 시작은 있으나 대응 결과가 없다.
- `result_observed`: 결과는 있지만 성공을 명시하지 않았다.
- `completed` / `failed`: 도구 결과가 명시한 성공/실패다. 전체 목표의 완료는 아니다.
- `accepted_unverified`: 접수증은 있으나 완료를 확인하지 않았다. `task_ref`, `resume`,
  `run_id`를 보존하여 기존 조회/재개 경로로 확인하도록 전달한다.

다음 요청에는 미처리 조향, 원래 요청, 도구 관측, 남은 응답을 복구 문맥으로 붙인다.
취소된 작업의 자동 재개와 불확실한 쓰기·발송·결제의 재제출을 금지하는 지침을 함께
전달한다. 프로그램은 과거 도구를 자동 재실행하지 않는다. 실행자는 현재 요청과
관련된 기록을 확인하고 재계획한다. 복구 문맥은 과거의 승인을 새로 발급하지 않는다.

복구 문맥을 받은 실행이 실패하면 다시 인계한다. 성공 실행이 받은 턴은 인계 확인을
남겨 반복 주입을 줄인다(효과의 해결을 선언하는 표식은 아니다). 발췌에서 빠진 턴이나
일부만 전달한 큰 턴은 확인 처리하지 않는다. 모델 응답이 생성됐어도 표면 저장 전에
중단되었다면 그 응답은 다음 턴에 남긴다.

큰 턴의 발췌 전달은 전체 인계 확인과 별도로 `handoff.finished.recovery_previews`에
원문 사건·상태의 지문으로 기록한다. 모델 실행과 표면 저장이 모두 완료된 뒤 같은
기록을 다시 만났을 때는 발췌 본문 대신 취소/미확정 상태, 도구 상태별 건수,
미처리 지시 건수와 소유 대화로 한정한 원문 DB 조회 위치를 전달한다. 새 CLI 세션이나
API 실행도 이 위치로 원문을 읽을 수 있으며, 관련 작업을 잇기 전에는 원문과 현재
효과를 확인해야 한다. 발췌 전달을 효과 해결·전체 목표 완료로 간주하지 않는다.
늦은 도구 결과나 추가 지시 등 발췌 밖의 원문이 바뀌면 다시 상세 발췌를 전달한다.
실패·취소·표면 저장 중단은 전달 확인으로 기록하지 않는다. 기존 기록에는 지문이
없으므로 적용 후 한 번 상세히 전달한 다음부터 이 규칙을 사용한다. 기존 CLI에 이미
누적된 맥락이나 원본 사건은 삭제하지 않는다.

저장소에 연결된 사용자 대화/연구 실행은 프로세스 종료를 넘는다. 대화 소유권이 없는
내부 실행은 메모리 보존만 하며, 프로세스를 넘는 인계를 보장하지 않는다. 모델 없는
시험은 전달·수명·기록 계약을 검증한다. 실제 모델이 모든 추가 지시를 정확하게 해석하는지와
외부 시스템의 효과가 완료됐는지는 각각 별도로 확인해야 한다.

## 회귀 검사

- `backend/test_dialogue_continuation.py`: 실제 인지 경계, CLI 자식 프로세스와 세션 재개,
  최종 응답/접수 경합, 취소·실패·예산, 소비자 조기 종료.
- `backend/test_conversation_handoff.py`: 실제 SQLite와 자식 프로세스 강제 종료,
  기존 사건 인계, 소유권 격리, 연구 대화 접수, 접수증·불확실 효과, 발췌 확인 경계,
  재기동 후 발췌 중복 억제·원문 변경 재전달·표면 전달 실패·이전 미전달 턴의 회수.
- `backend/test_steer.py`: 기존 도구 부록·HTTP·WebSocket 입구와 별칭 격리.
- 공통 수명 변경이므로 `docs/REGRESSION_TESTING.md`의 종합 회귀 및 재기동 시스템 묶음도 실행한다.

  기존 반복 문맥 17,943자 → 전달 지문 확인 뒤 1,128자(93.7% 감소). 원본 사건과
  취소·불확실 상태를 보존하며 전체 인계 확인 목록은 빈 상태다. 실제 모델의 토큰·지연
  개선을 측정한 결과는 아니다. 기존 CLI에 누적된 맥락은 유지한다.
- 직접 인계·대화 검사 31개 통과. 전이 소비자 선택은 264/810 파일(33%).
  제한 환경에서 소켓·브라우저·OS 격리 실행이 차단되어 정상 권한에서 재검증했다.
- backend 비-system 전체 11,309 통과·9 건너뜀, 실제 재기동 시스템 검사 25 통과.
  IBL 파생 정합·backend 층 가드·Android 몸 번들 검사 통과. 실행 중인 봉인 세대의
