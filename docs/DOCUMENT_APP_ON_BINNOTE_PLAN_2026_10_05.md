# 문서 앱 = 빈노트의 얼굴 + 형식별 엔진

작성일: 2026-10-05. 상태: **완료(2026-10-06) — 빈노트·옛 문서 창 모두 은퇴, 인수 시험 3종은 새 화면으로 이전. 후속 과제는 §6 끝 '후속'.** 독자: 이 일을 이어받는 구현자.
상위 계획: [공통 기반 위의 앱 구성](APP_COMPOSITION_ON_IBL_PLAN_2026_10_05.md) §6-4~5 의 문서 앱 몫.

사용자 명제(2026-10-05): *앱 모드의 빈노트는 사실 문서 앱의 기본 모습이어야 한다. 문서 앱은 기본적으로
문서를 읽고 고치는 앱이기 때문이다. 빈노트는 텍스트 파일만 다루는데, 여러 문서 형식을 지원하면 된다.
가능하면 IBL 로 구현한다.* 같은 날 **빈노트 은퇴(문서 앱에 흡수)** 를 승인했다.

## 0 출발점

| | 빈노트 (`BinNote.tsx`) | 문서 앱 (`DocumentWorkspace.tsx`) |
| --- | --- | --- |
| 모습 | 큰 캔버스, 상단 열기·저장, 하단 AI 한 줄 | 목록·세션·제안·버전이 한 화면에 깔린 관리 화면(별도 창) |
| 형식 | `.md`·`.txt` | 원문(txt·md·html·tex·typ), DOCX류, HWP/HWPX, PDF |
| 구현 | escape React, 파일은 `[self:read/write/list/mkdir/delete]`, AI 는 `/system-ai/chat` 에 글 전체 | React + 전용 HTTP 작업표, AI 는 원샷 호출 |
| 저장 안전 | 브라우저 임시저장뿐 | 초안·스냅샷·조건부 저장·버전·복구 |

빈노트는 모습이 맞고 문서 앱은 몸이 맞다. 빈노트의 얼굴을 문서 앱의 기본 화면으로 삼고 캔버스 자리에
형식별 엔진을 끼운다. 새 낱말은 없다 — `[self:workspace]` 와 뷰 `engine` 위에 선다.

## 1 목표 형태

`data/instruments/document.yaml` 한 장, 앱 모드 인라인(별도 창 없음).

- 상단: 파일명, 폴더칩, 새 문서 / 열기 / 다른 이름으로 / 저장.
- 캔버스: `engine` 뷰가 자료 capabilities 로 편집기를 고른다 — 원문은 빈노트 캔버스, DOCX류는 ONLYOFFICE,
  HWP/HWPX 는 RHWP, PDF·그 밖은 열람(`[self:read]` 투영 → `blocks`).
- 하단 AI 한 줄(`ai_dock`): 선택이 있으면 선택만, 없으면 글 전체. 제안 박스 → 반영/첨부/닫기.
- 버전·복구·내보내기는 접어 둔다.

## 2 메울 틈

1. **캔버스 크기** — 원문 엔진이 18줄 고정폭 textarea, 계기 화면은 좁은 스크롤 페이지. → 엔진이 있는 모드는
   넓은 캔버스 배치, 원문 엔진에 빈노트 캔버스·자동 초안 저장(서버 초안이 브라우저 임시저장을 대신한다).
2. **새 문서** — `[self:workspace]{op:"open"}` 은 있는 파일만 연다. 새 문서 버튼은 `[self:write]`(원문)·
   `[table:document]`(DOCX)로 만든 뒤 여는 선언으로. 어휘 변경 없음.
3. **AI 독 ↔ 엔진** — `ai_dock` 이 폼 textarea 전용이었다. → `engine` 뷰에도 `ai_dock` 을 선언할 수 있게 한다.
   action 은 `$resource·$sel·$start·$end·$text·$dock` 을 받고 스칼라 본문을 돌려준다. 반영은 엔진이
   사람의 편집으로 캔버스에 넣는다(선택 범위 또는 전체) — 초안·저장·버전은 평소 편집과 같은 길.
4. **관용구 원장** — `선택교정`·`검토본저장` 이 해마에만 있고 워크플로 원장에 없어 `[fn:…]` 이 거절된다.
   원장 등록 + 글 전체용 관용구 하나.
5. **폴더 탐색** — `tree` 뷰가 아직 없다. 1차는 `files` 입력 + 최근 문서 `list_action`. 기본 폴더는 기존
   `outputs/binnote` (노트 이전 불요).
6. **사무 문서의 AI 수정** — DOCX·HWP 는 서버 제안 경로가 없다(엔진 bookmark). 1차 AI 독은 원문 형식만.
   DOCX 는 편집기 안의 기존 선택 교정을 `engine` 밑에 유지.

## 3 순서

1. **렌더러** — 틈 1·3. `prims-engine.tsx`(원문 엔진 캔버스화·독), `prims-edit.tsx`(독 UI 공용화),
   `GenericInstrument.tsx`(엔진 모드 캔버스 배치), 검증기 `iblbuild_appview.py`(engine `ai_dock`), 문서 표면.
2. **데이터** — 틈 2·4·5. 관용구 원장 등록·시딩, `document.yaml`, `build_ibl_nodes.py --check`.
3. **검증** — md·txt·html·docx·hwp·pdf 각각 열기→수정→저장→버전 복구→내보내기를 화면으로 확인. 문서 회귀를 새 경로로.
4. **은퇴** — `BinNote.tsx`, `DocumentWorkspace.tsx`, 홈 타일 둘(빈노트·문서) → "문서" 하나. HTTP 작업표는
   엔진 I/O 에 필요한 경로만 남긴다. 빈노트의 브라우저 미저장 초안(`binnote.draft`)은 은퇴 전에 한 번 건진다.
5. **후속** — 폰·원격 원문 편집(지금은 열람 강등), `tree` 교체, DOCX AI 제안.

## 6 진행 기록

- **1단계 완료(2026-10-05 밤, 미커밋).** 원문 엔진 = 빈노트 캔버스(넓은 편집면·자동 서버 초안·Cmd+S·원본 줄바꿈 보존·
  코드포인트 주소·줄바꿈 혼합 문서는 열람만). engine 뷰 `ai_dock`(선택 있으면 선택, 없으면 전체 → 제안 → 반영/첨부/닫기,
  요청 뒤 그 자리가 바뀌면 거절, 양 끝 공백 보존, 한 번 되돌리기). 독 표면은 form 독과 한 컴포넌트(`AiDockPanel`).
  engine 이 있는 모드는 넓은 배치. 검증기·회귀(`test_app_view_engine.py::test_engine_canvas_dock_is_valid_and_checked`)·
  문서 표면 3곳. 확인용 최소 `data/instruments/document.yaml`(이름 '문서 (새)', 경로 입력 → 열기 한 모드).
  화면 확인(브라우저, md): 열기 → 문단 선택 → 독 요청 → 선택 대체 → 자동 초안 → 저장 → 파일 내용 일치,
  선택 없이 요청하면 전체 대체로 뜸. 시험 파일 `projects/앱모드/outputs/binnote/문서앱_시험.md` 는 3단계까지 둔다.
- 1단계에서 본 것:
  - 홈 그리드에서 새 앱 타일이 기존 타일(공개파일)과 **같은 자리에 겹쳐** 놓였다(자동 자리 배정이 저장된 배치와 충돌). 이 일의 범위 밖.
  - 독으로 포커스가 가면 캔버스의 선택 강조가 사라진다(브라우저 기본). 상단의 "선택 N자"와 독 안내문으로 대신 알린다.
  - DOCX·HWP·PDF 엔진은 이번에 열어 보지 않았다(3단계).
- **2단계 완료(2026-10-05 밤, 미커밋).** `data/instruments/document.yaml` 세 모드 — 문서함(`[self:file_find]` >> 폴더 빼기 >> 최근순,
  고르면 open → engine) · 새 문서(같은 이름이 있으면 멈춤 → `[self:write]` 빈 파일 → open) · 열기(경로). 캔버스 선언은 YAML 앵커 한 벌.
  원문 엔진에 "버전·사본" 패널(다른 이름으로 사본 저장, 저장 버전 되살리기 → 작업 초안). 드릴 뷰에 engine 이 있어도 넓은 배치.
  화면 확인(브라우저): 문서함 목록 → 열기, 버전 2개 표시 → 이전 버전 되살리기(초안, 원본 그대로), 새 문서에서 있는 이름은 거절·새 이름은 빈 캔버스.
- 2단계 판정:
  - **관용구 원장 등록(틈 4)은 하지 않았다.** 독은 `[self:ask]` 한 줄이면 되고(가이드의 "가볍게 지금 답"), `선택교정` 은 제안을 서버에
    남기는 흐름이라 "반영은 캔버스에서" 와 맞지 않는다. 소비자 없는 정의를 원장에 올리지 않는다 — 시스템 AI 가 열린 문서를 고칠 때 쓰는
    관용구로 해마에 그대로 둔다.
  - **버전·사본은 선언이 아니라 엔진 패널.** `[self:workspace]{op: restore|export}` 를 표면에서 부르면 작성 창이 쥔 세션과 부딪힌다
    (그 창의 client 만 허용). 저장과 같은 자리(엔진)에 두었다.
  - **새 문서는 원문 형식만.** DOCX 새 문서(템플릿)는 옛 화면의 `/documents/new` 에만 있다 — 4단계 전에 길을 정한다.
- 커밋 때 할 일: `document.yaml` 이 git 에 추적되면 코어 계기가 된다 → `build_core_manifest.py`·`build_dist_filter.py` 재실행
  (지금 `frontend/package.json` 의 `!instruments/document.yaml` 제외 줄은 미추적 상태의 파생값). changelog.log 한 줄.
- 남은 것(3단계 전): 문서함은 평면 목록이다(하위 폴더의 파일도 한 줄로 섞여 나온다 — `tree` 뷰가 생기면 교체). 폴더 만들기·삭제 버튼 없음.
  시험 파일 `문서앱_시험.md` 에는 되살리기 시험이 남긴 작업 초안이 있다.
- **3단계 완료(2026-10-06).** 새 계기에서 DOCX(ONLYOFFICE: 열기 → 본문 입력 → 원본 저장 → python-docx 로 파일 내용 확인),

### 옛 문서 창 기능 이관 (2026-10-06, 사용자: "유용하면 옮겨라. 단 기본 모양새가 달라지지 않게 — 설정 같은 곳에 들어가면 할 수 있게")
기본 모양(문서함 → 캔버스 → 하단 AI 한 줄)은 그대로 두고 두 곳의 "⚙ 도구" 에 모았다.
- **캔버스의 ⚙ 도구 패널**(`generic/engine-source-tools.tsx`, 평소 접힘 — 옛 "버전·사본" 자리): 다른 이름으로 사본 · 다른 형식(pdf·docx·odt·rtf·html·txt·epub)
  변환 사본 · 저장 버전 되살리기 · 저장 상태 복구 · 미리보기(md·html) · 시트 표 넣기/갱신과 강의 재료 전달(옛 `DocumentReferences` 를 그대로 싣고,
  선택 고정·제안 적용만 엔진의 세션으로 잇는다). 고정한 선택과 제안은 그때의 글에 묶여 글이 바뀌면 사라진다.
- **계기의 ⚙ 도구 탭**(`document.yaml` 네 번째 모드): 틀(보고서·회의록·제안서·공문·신청서·계약서 초안·이력서·빈 문서)로 새 문서 — DOCX·MD·TXT.
  본문은 선언 안에서 마크다운으로 짓고 DOCX 는 `[table:document]` 가 렌더한다(옛 `/documents/new` 서비스 불요, 새 낱말 없음). 만든 자리는 고른 폴더.
- **다른 창이 쥔 세션**: 엔진이 빼앗지 않고 "이 창에서 초안 이어 쓰기" 를 묻는다(옛 reclaim).
- **홈 타일 '문서 (옛 창)' 제거.** 시트 앱의 "문서에 표 보고서 만들기" 는 옛 창을 여는 대신 만든 문서의 경로를 알려 준다.
- 옮기지 않은 것: **파일 가져오기(업로드 사본)** — 데스크톱에서는 "열기" 가 원본을 제자리에서 열고, 가져오기는 사본을 만들 뿐이라 뺐다. 필요하면 매니페스트 `file` 입력으로 붙인다.
- 화면 확인(브라우저, md): 틀(회의록)로 만들기 → 캔버스, ⚙ 도구 패널, 미리보기, docx 변환 사본(경로 표시), 캔버스 선택 고정 → XLSX 표 제안 → 적용.
  강의 재료 전달과 연결 갱신(선택 구간 갱신 제안), 세션 되찾기는 눌러 보지 않았다.

### 빈 페이지가 기본 화면, 탭은 ⚙ 안으로 (2026-10-06, 사용자 지시)
- 앱을 열면 바로 쓸 수 있는 빈 페이지가 선다 — 선언의 첫 모드 "빈 페이지"(입력 없는 `auto_run`): 문서함 폴더에 비어 있는
  "무제 …" 문서가 있으면 그것을 다시 열고(빈 파일이 쌓이지 않게), 없으면 `무제 날짜 시각.md` 를 만들어 연다. 새 낱말 없음.
- 캔버스가 서 있는 동안 계기의 탭 줄(빈 페이지·문서함·새 문서·열기·틀로 새 문서)과 입력줄은 화면에서 빠지고 캔버스의
  "⚙ 도구" 패널 맨 윗줄에 접힌다(문서별 도구와 한 버튼). 종이는 창을 가득 채우고 글줄은 읽기 좋은 폭으로 가운데.
  선언에 레이아웃 키는 없다 — 문서 엔진이 `InstrumentMenuContext`(generic/manifest.ts)로 탭 줄을 맡는다(claim).
  사무·한글 편집기와 편집기가 서지 못한 화면에는 ⚙ 한 줄(MenuBar)이 얹힌다. 캔버스가 없는 화면(문서함 목록·새 문서 입력)은 탭 줄이 그대로 보인다.
- ⚙ 에서 지금 탭을 다시 고르면 그 모드가 새로 선다(빈 페이지 = 새 빈 페이지, 열기 = 다시 입력). 옛 모드 "⚙ 도구"는 "틀로 새 문서"로 개명.
- 인수 시험 대역(`test_document_app_support.open_document`)은 ⚙ 를 편 뒤 열기 탭을 누른다.
- **작성 세션 잠김 수리(같은 날, 사용자 신고 "다른 창이 작성 중입니다")**: 세션은 창이 죽어도 남는데 놓는 길(close)을 아무도 부르지 않았고,
  엔진은 남의 세션을 보면 acquire 를 불러 409 로 죽어 "이 창에서 초안 이어 쓰기" 화면에 닿지 못했다(앱을 다시 띄우면 창 식별자가 바뀌어 열었던 문서가 전부 잠김).
  수리(`generic/prims-engine.tsx` DocumentEngine): ① 원문 문서는 떠날 때(언마운트·pagehide) 세션을 놓는다 — 초안이 남으면 서버가 거절해 세션째 보존.
  ② 남의 세션을 만나면 BroadcastChannel 로 그 창의 생존을 묻고, 답이 없으면 죽은 창이므로 조용히 reclaim(초안 보존), 살아 있으면 가져오기 버튼.
  ③ 빈 페이지 모드는 세션이 없는(아무도 쥐지 않고 초안도 없는) 가장 최근 빈 "무제"만 다시 쓴다 — 쥐인 것이면 새로 만든다(파일명에 초 포함).
  남은 것: 창이 pagehide 없이 죽으면(강제 종료) 빈 "무제"가 쥐인 채 남아 다음에 새 파일이 하나 생긴다.
- **기본 형식 = 텍스트, 넓게 보기 토글(같은 날, 사용자 지시)**: 빈 페이지는 `무제 날짜 시각.txt` 로 만들고 빈 `.txt` 만 다시 쓴다. "새 문서"의 기본 형식도 txt.

- **⚙ 안의 탭은 화면을 옮기지 않는다 · 문서함 탭 은퇴(같은 날, 사용자 지시)**: "열기"는 데스크탑에서 문서함 폴더에서 시작하는 OS 파일 창을 바로 띄우고

- **새 한글 문서 · 빈 페이지 버튼 제거 · 파일 창 실패 대비(같은 날, 사용자 지시)**: "새 문서" 형식에 한글(.hwpx/.hwp) — 0바이트는 한글 문서가 아니므로

  "열기"가 아무 창도 못 띄우던 것: 창만 새로 고쳐지면 preload 는 새것·메인 프로세스는 옛것이라 `select-file` 호출이 거절되고 그 거절이 삼켜졌다 — 이제 작은 창(경로 입력)으로 떨어진다.
