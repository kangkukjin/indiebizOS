# 9월 20일 에피소드의 IBL 재사용·학습·불필요한 호출 수리

## 관측 범위

2026-09-20 00시 이후 완료된 실사용 에피소드 3899~3917, 19건을 읽기 전용으로
조사했다. 당시 실행 중인 3918은 집계에서 제외했다. 원장·과거 용례를 수정하거나
실제 조사·발행 작업을 재실행하지 않았다.

IBL 시작/종료 기록은 181쌍(설명·원문 조회와 중첩 포함), 전체 호출 실패는 19건이다.
파이프 포함 88건, 함수 포함 64건으로 이미 조합이 쓰이고 있었다.
누적 입력 12,246,003토큰에는 캐시 읽기 10,036,549가 포함되며 출력은 80,761이다.
이를 모두 신규 입력 비용이나 낭비로 해석하지 않는다.

## 수정한 계약

### 큰 원문과 변수의 수명

3909의 `$연구원문`은 400만 자 한도로 보존되지 않았다. 반환 봉투는 `too_large`를
싣고도 다음 호출에서 변수로 읽으라는 안내를 함께 했다. 이후 미할당 오류 5회와
파일·통화 복구 시도가 이어졌다.

- `ibl_turn_vars`는 큰 값을 별도 스필 파일에 보관하고 턴 원장에는 참조·지문·형을
  기록한다. 인라인 총량도 오래된 이름을 지우는 대신 값을 외부화한다.
- 파서·실행기에는 참조 봉투 대신 복원한 원형을 제공한다. 표·산문·스칼라와
  봉투의 부가 근거를 유지하며, 재할당 시 값과 형이 함께 갱신된다.
- 다음 문장이 참조한 이름만 읽는다. 긴 입력이 없는 짧은 필터 호출에서 재타이핑
  검사를 위해 다른 변수들의 원문을 모두 복원하지 않는다.
- 참조 파일 부재·지문 불일치는 이름을 포함한 복원 오류다. 원장 쓰기 실패도
  `unavailable`로 알리며 보존 성공 안내를 붙이지 않는다. 스필의 24시간 수명은 유지한다.
- 같은 프로세스의 병렬 저장은 잠금으로 합쳐 다른 이름의 갱신을 잃지 않는다.

### 한글 함수의 경험 검증

3906·3907·3908·3909·3913·3916은 합성 접지 검증에서 스킵됐다. 검증기의 영문 전용
액션 정규식은 `[fn:본문에서찾기]` 등 한글 함수를 놓쳤다. 실제 원문을 그대로 선택해도
`$원문 >> [fn:본문에서찾기]`가 거절되는 것을 재현했다.

별도 정규식을 없애고 IBL 공통 스캐너의 `source_heads`로 이름·순서를 읽는다.
원문 선택과 의존 생산자 복구는 유지한다. 쓰지 않은 함수, 실행하지 않은 새 파이프,
문자열·주석 속 가짜 호출은 계속 거절한다. 절대 홈 경로·장문 본문 등 기존 코퍼스
입구 관문은 완화하지 않는다. 이전 기록을 새 성공으로 소급 적재하지 않는다.

### 모델 호출 절약

- 단일 예약 위임의 완료 통보는 시스템 원장에 대응하는 자식 결과가 하나 있고
  pending이 0인 경우 원문을 기존 최종 전달 경로로 보낸다. 원래 예약 요청과 실제
  위임 메시지가 같은 경우만 적용한다. 실패·부분 완료도 문구를 바꾸지 않고 전달한다.
- 일반 사용자 대화의 위임, 다중 위임·이전 작업 사이클, 결과 미도착은 기존 경로다.
  이미 완료된 같은 예약 결과를 다시 받아도 최종 응답을 재생성·중복 저장하지 않는다.
- 기존 경량 분류 프롬프트에서 개념·가설의 후속 대화와 외부 조사·실행 요청을 구분한다.
  길거나 복잡한 논지만으로 THINK를 요구하지 않는다. 추가 분류 모델·규칙 분기는 없다.

### 반복 오류의 교정 정보

- 실행자의 API 작업대 스키마에서는 감독 전용 `execute`를 제외한다. 공유 MCP
  작업대는 두 역할이 사용하므로 설명에서 실행자는 자신의 도구를 직접 쓰도록 명시한다.
- MCP supervision 스키마에 offset≥0, limit 1~24000을 노출한다. 실행 결과 조회의
  60000자 한도와 구분한다. 백엔드의 역할·예산 검사는 유지한다.
- 잘못된 배열 인용 오류는 작은따옴표로 감싸는 유효한 예제를 안내한다. 검색어를
  자동으로 다시 쓰지 않는다. 필드 오류에는 행의 `_error`와 봉투의 `errors`를 구분한다.
  실행 프롬프트도 실제 열과 변수 보존 상태를 확인하도록 맞춘다.
