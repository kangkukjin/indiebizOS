# 에피소드 4028~4036 실행 계약 점검과 수리

최근 4032~4036 점검에 이어 요청된 앞선 세 회 4029~4031의 로그·사건 원장·대화 기록을 확인했다.
이미 관측된 4028 건강 조회 실패도 같은 수리 범위에 포함했다. 개인 의료 내용은 이 문서에 복제하지 않는다.

## 관측과 원인

- 4029·4031: IBL 실행 없이 응답 완료. 추가 실행 오류 없음.
- 4030: 검색 가이드의 `crawl >> fn:본문에서찾기`가 `PIPE_COLLISION`, `MISSING_ARGUMENT`으로 거부됐다.
  기존 함수 본문은 입력 자리 `목록`을 가졌지만 현재 판본 호환 어댑터가 그 정보를 버렸다.
  실행자는 변수와 명시 인자로 재시도해 완료했다. 병렬 수집·검색어 묶음·관용구 재사용은 관측됐다.
- 4028: 건강 액션의 설명에 있는 `person`, `days`가 서명에 없어 `UNKNOWN_ARGUMENT`가 발생했다.
  실행자는 테이블·스키마를 조사한 뒤 SQL로 우회했다. 핸들러는 이미 해당 인자를 지원한다.
- 4034·4036: 능력 판정의 `ValueError`를 기록하고 원래 응답으로 완료했다.
  당시 실패한 판정 원문과 세부 사유가 보존되지 않아 정확한 실패 조건은 소급 확정할 수 없다.
  기존 검증은 모델이 Markdown까지 원문과 일치하게 문장을 복사해야 했다.

## 변경

- 건강 조회의 대상자·기간·이미지 포함·활성 투약 옵션과 기존 저장의 시각·메모 인자를 원천 YAML에 선언하고 파생물을 재생성한다.
- 기존 관용구의 파이프 입력 자리를 공통 `pipe_input_param`으로 읽어 호환 계약에 전달한다.
  회원 제공 함수에도 같은 판정을 적용한다. 함수명·분야별 특례나 새로운 어휘는 추가하지 않는다.
  명시 인자 충돌과 입력 누락은 계속 거부한다.
- 능력 판정은 하네스가 제공한 후보 ID로 원문을 선택할 수 있게 한다.
  혼합 문단의 부분 문장은 기존 정확한 quote 방식도 유지하며 후보 밖 문장·없는 ID·근거 없는 제한 판정은 거부한다.
  실패한 판정 원문·입력은 기존 비공개 증거 저장소에, 이유는 사건 원장에 남긴다.
  실패 시 원문 보존과 호출·조회·재개 예산은 유지한다. 일반 사실의 불확실성을 능력 부족과 구별하도록 판정 지침을 보완한다.

## 비용과 범위

4032~4036은 모두 IBL 0회, 의식 OFF의 EXECUTE 경로다. 평가 미실행은 설정과 일치한다.
전체 관측 입력+출력은 캐시 포함 368,034토큰이며 증류 85,312토큰, 저장은 전부 completed_empty였다.
저장 0건은 정상 계약이므로 이 사례만으로 증류를 끄거나 기억 정책·모델 설정을 변경하지 않는다.
판정 ID 선택은 원문 복사 실패를 줄이는 구조 보완이며, 당시 두 ValueError의 정확한 원인을 재현했다는 주장은 하지 않는다.
시간·총토큰 절감은 동일 조건의 후속 실사용 비교가 필요하다.

## 검증

격리된 실행기억에서 기존 함수의 파이프 실행·명시 인자 충돌·입력 누락과 건강 조회 인자 전달을 검증한다.
능력 판정은 Markdown 원문 보존, 후보 ID/문장/근거 위조 거부, 실패 증거 보존, 기존 예산·입력 크기 시험을 포함한다.
실제 사용자 원장에 재기록하거나 의료 상담을 재실행하지 않는다.

- 집중 회귀: `test_capability_guard.py`, `test_ibl_v2_assets.py`, `test_ibl_callable_contracts.py` 71개 통과.
- 건강 액션의 기존 용례 63개 재검토 후 원장 갱신. 어휘·문서 파생, 몸 번들, 층·은퇴 계약 검사 통과.
- 공식 재기동 완료, ACTIVE 및 실행 소스 지문 일치 확인. 실제 서버에서 두 실패 문장을 `check:true`로 재검사:
  `issues:[]`, `executed:false`. 외부 실행을 하지 않은 호환 경계는 `incomplete`로 정직하게 남는다.
- 전체 백엔드 최종 회귀: **5,863 통과, 1 skipped, 실패·오류 0** (정본 맥 정상 권한, 527초).
  처음 샌드박스 실행의 소켓·브라우저·LibreOffice 권한 실패와 검토 전 용례 원장 실패는
  권한 복원·원장 갱신 후 전체 재실행에서 해소됐다. 실행 기록은 `/tmp/episodes4028-4036-native.xml`.
