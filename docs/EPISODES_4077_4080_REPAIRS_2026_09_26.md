# 에피소드 4077~4080: IMAP 선택 범위와 자격증명 기록 수리

## 확인한 오류와 수정

4079·4080의 IMAP 인증과 요청한 1건·10건 조회는 성공했다. 그러나 조회 생산자가
전체 검색 건수보다 반환 수가 적다는 사실만 `truncated=true`로 기록해, IBL 봉투
해석기가 범위 불명의 원천 절단으로 판정했다. 생산자가 기존 공통 계약의
`truncations: [{scope: "selection", unit: "messages", retained, total, parameter: "max_results"}]`를
명시하도록 고쳤다. 실제 source 절단은 여전히 PARTIAL_SOURCE이며, 본문 미리보기의
`body_truncated`도 남긴다. 실패 판정기·문법·어휘 수를 바꾸지 않는다.

비밀번호 전달 문장이 에피소드·과제 제목과 완료 조건·후처리 오류에 재노출됐다.
기존 마스킹은 영문 필드명·벤더 접두·숫자가 섞인 긴 값 위주라 영문 소문자 앱
비밀번호를 한글로 전달한 경우를 놓쳤다. 명시적인 한글 자격증명 전달 문형을
공통 마스킹에 포함하고, JSON의 설정 키와 같은 객체 안의 반복 값도 가린다.
과제의 상태·사건·턴 저장과 감독 증거·사건 저장에 마스킹을 적용한다. 증거 지문은
가려진 실제 저장 본문으로 계산하며, 실행에 사용되는 호출자 입력은 변경하지 않는다.
에피소드 요청과 시작 미리보기는 길이를 자르기 전에 마스킹한다.

기존 IMAP 구현은 4078에서 정본에 적용됐으나 미커밋 상태였다. 그 구현·계층 배정·
어휘 설명·회귀 시험을 함께 정본 커밋으로 보존한다. 실제 계정 자격증명은 커밋하지 않는다.

## 검증과 범위

- 가짜 IMAP 서버로 TLS·계정 선택·검색·MIME·읽음 상태 보존·인증 실패와 Gmail/Nostr 회귀를 검사한다.
- 실제 IBL 봉투 해석기에 제한 조회 결과를 전달해 성공을 확인하고, 원천 누락을 추가하면 실패하는지 검사한다.
- 합성 자격증명으로 SQLite 과제 상태·사건·턴 및 감독 증거·사건의 영속 결과를 검사한다.
- JSON 유효성, 저장 증거의 지문, 원본 실행 인자 보존, 일반 문장의 오탐을 검사한다.
- 실제 설정 계정으로 읽기 전용 조회 후 IBL 봉투 해석기에 전달하여 제목 10건·
  `success=true`·`scope=selection`을 확인했다. 본문·제목·자격증명은 검증 로그에 출력하지 않았다.
- 과거 대화·에피소드·증거 파일을 일괄 재작성하지 않는다. 새 저장 경로를 고치는 범위다.
- 4078의 ACHIEVED 판정 및 시간·토큰 최적화는 이번 코드 수정에 포함하지 않는다.
  목표와 구현 완료의 의미를 정하는 후속 검토 없이 판정기를 바꾸지 않는다.

전체 백엔드 초회 실행은 6,621건 통과·3건 실패였다. 실패는 기존 IMAP 시험의
환경변수 폴백, 직접 실행 진입점 누락, 계정 식별자 비교의 검사 사유 누락이었다.
시험 환경을 격리하고 pytest 직접 실행 진입점과 프로토콜 식별자 비교 사유를
보완한 뒤 `test_imap_reader.py`, `test_single_runner.py`, `test_value_judgment_gate.py`의
47건을 재실행해 전부 통과했다. 비밀 마스킹·과제 원장·감독 저장 경로의 관련
회귀도 통과했다. 수정 후 전체 배터리를 다시 실행한 결과로 과장하지 않는다.
