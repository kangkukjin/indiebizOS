# 에피소드 4279·4280 실행 경계 수리

## 관측과 원인

2026-10-03의 4279는 다국어 UI 구조 조사, 4280은 영어 UI 보강 수리다.
4279에서는 `self:grep` 파일 목록의 `total`이 파일 수가 아닌 일치 줄 수여서
봉투 불변식 경고가 두 번 났고, 넓은 본문 검색의 긴 줄이 `PARTIAL_SOURCE`로 중단됐다.
문서 네 개의 원문·구조화 블록을 함께 반환한 뒤 본문을 다시 추출하면서 표시 절단도 반복됐다.

4280은 수리 사본 생성 뒤 첫 MCP 호출에서
`MCP tool call requires approval, but approval policy is never`로 거절됐다.
Codex 네이티브 실행을 read-only로 제한하면서 허용해야 할 수리 MCP 도구를 연결하지 않았다.
추가 점검에서는 기존 격리 `run_command`가 CLI MCP 표면에 없어 사본 검증 증거를
생성할 통로도 끊겨 있었다. CLI 오류는 `item.error`에 있었으나 결과 본문으로 옮기지 않았고,
감독은 MCP 실행이 서버에 기록됐다고 가정해 실패 통계에서도 빠뜨렸다.

## 변경

- 승인 수리의 Codex는 execute_ibl/read_guide/run_command만 명시 허용한다.
  네이티브 셸 read-only와 approval_policy=never는 유지한다. 일반 실행과 의식 감독의
  도구 정책은 유지한다. Claude 수리에도 같은 run_command 브리지를 연결한다.
- 새 IBL 낱말 없이 기존 run_command를 얇은 MCP·HTTP 경계로 노출한다.
  활성 감독의 소유자이며 현재 수리 그랜트가 있는 실행자만 호출할 수 있다.
  기존 system_tools → system_essentials → repair_process로 연결해 같은 사본, OS 쓰기
  경계, 취소, 후보 지문과 검증 증거를 유지한다. 요청자가 작업 디렉터리나 다른 도구를 고르지 못한다.
  게이트 파일은 기존 워치독의 안전장치 검사 대상에 포함한다.
- Codex의 MCP error 본문과 전송 실패 표지를 보존한다. 서버 도착 전 실패도 감독 원장에
  남기며, 서버의 정상 응답에 담긴 업무 실패를 CLI에서 다시 집계하지 않는다.
- grep의 total을 items와 같은 단위로 정렬한다. content는 일치 줄 수를 유지하고,
  files_with_matches/count는 파일 수, total_matches는 일치 줄 수다. summary 모드에서
  전수 계수가 있으면 불필요한 본문 스캔을 생략한다. 폴백 스캔이 미완료면 source 절단과
  total_complete=false를 보존한다. 본문 잘림을 성공으로 숨기지 않는다.
- 교재에는 본문만 반환하기, 필요한 줄 범위 읽기, 기존 결과 참조 재사용,
  파일 위치부터 좁히는 검색을 명시했다. 수리 교재는 CLI의 사본 검증 경로를 명시한다.

카탈로그 원본과 파생물을 함께 갱신했다. self:grep의 로컬 용례 14건은 모두 content
모드(기본 13건, 명시 1건)이어서 total 의미를 유지한다. 회원 경로 감사는 패키지 내
변경이 fs_grep의 집계·검색 절차에 한정됨을 확인하고 기존 회원 파일 격리 검사로 대조했다.

## 검증

- 재현·통합 검사는 `backend/test_episode4279_4280_repairs.py`에 보존한다.
- 실제 Codex CLI + 임시 MCP 서버에서 read-only/never 설정으로 execute_ibl와
  run_command 두 호출 성공을 확인했다. 실제 사용자 수리는 실행하지 않았다.
- 실제 HTTP dispatch → 도구 핸들러 → OS 격리 명령 경로를 임시 Git 저장소로 검증했다.
  사본의 수정본을 읽어 검사하고 증거를 기록했으며 정본은 원래 바이트를 유지했다.
- 초기 중첩 샌드박스에서는 macOS sandbox-exec 기동 자체가 거절됐다.
  해당 OS 경계 검사 7개는 외부 샌드박스 없이 재실행하여 모두 통과했다.
- 4279의 경고를 냈던 실제 두 검색을 다시 실행했다. frontend/src는 파일 9개·일치 줄 10개,
  scripts는 파일 3개·일치 줄 4개로 분리되며 total=len(items), truncated=false를 확인했다.
- 종합 회귀(`backend/ -m "not system"`): 8,571 통과, 6 실패, 1 건너뜀,
  115 제외, 755.85초. 그중 종전 검색 단위를 기대한 테스트 2건과 교재 크기 상한 1건을
  수정했다. 새 테스트의 직접 실행 진입점도 추가했다. 교재는 상한을 늘리지 않고
  기존 중복 문장을 합쳐 35,980바이트로 유지했다.
- 최종 관련 회귀와 권한·어휘 배포 시스템 검사: **350 통과**, 146.06초.
  일반 Codex에서 수리 명령 도구를 숨기는 마지막 설정 변경 후 권한·감독 검사도
  **118 통과**(실제 OS 명령 검사 1건 제외)했다.
- 남은 기존 문제는 `test_render_core.py`의 script 블록 수 전제 2건이다.
  공통 러너 관문은 기존 미커밋 `test_tool_calls_record_edition_2026_10_03.py`의
  직접 실행 진입점 누락도 지적해 커밋을 차단했다. 본문을 보존하고 pytest 위임 진입점만
  추가했으며 별도 작업인 이 파일은 이번 커밋에 포함하지 않는다.
  종합 회귀 전체를 수정 후 다시 실행한 결과로 보고하지 않는다.
- IBL 빌드 `--check`, Android 몸 번들 재생성, backend 층 가드, diff 검사 통과.
  안전장치 자체 검사 **30 통과**. 회원 파일·공통 통화 관련 검사 **68 통과**.

## 범위와 남은 확인

영어 UI 구현 자체는 이 수리의 대상이 아니다. 4280을 다시 실행하거나 중단된 다른
수리·자동화를 재개하지 않았다. 문서 출력·검색 교재를 보강했지만 모델이 실제 다음 턴에서
중복 읽기를 줄이는지는 후속 에피소드로 확인해야 한다. 시간·토큰 절감률은 측정하지 않았다.
