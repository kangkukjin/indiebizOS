# 유튜브 AI 팁 보고서 에피소드 3352 수리

시스템 AI의 실행 스레드에 agent_id가 없어 감독 객체를 만들고도 주 실행이 찾지 못했다.
그 결과 큰 호환 의식 프롬프트와 옛 최종 평가 경로를 사용했고, 공개와 알림이 검수보다 먼저 끝났다.
공통 인지 진입점이 신원을 보충하고 종료까지 보존하도록 수리했다.

## 실행·감독·비용 계약

- MCP 실행 및 감독 도구의 재진입은 agent/task로 활성 턴의 토큰 원장을, episode/task로 활성 에피소드를 찾는다. 병렬 each도 ContextVar를 승계한다. 종료된 턴이나 다른 과제의 원장에 붙이지 않는다.
- 원샷 호출은 연결 클라이언트만 공유하고 프롬프트·버퍼·계측을 복사해 제공자당 최대 4개를 수행한다. 전경 우선순위와 동시 호출 상한은 유지한다.
- each 예산 중단은 `success:false`이며, 시도하지 않은 행을 `rows_processed`에 포함하지 않는다. `rows_requested`, `rows_unprocessed`, 성공·오류 수를 보존한다. 중간 단계의 부분 실패는 `incomplete_steps`로 요약과 감독에 남는다. 같은 경계 수량을 합산하지 않으며 의도한 limit 표본과 예산 중단을 구분한다.
- 대표 용례 복구는 선택된 성공 호출이 참조한 변수의 가장 가까운 앞선 생산자까지 자동으로 포함한다. 독립 문장을 실행 순서대로 보존하며, 원문에 없던 데이터 파이프 합성은 계속 거절한다. 미완료 호출은 성공 용례에서 제외한다.

## 최종 검수와 전달

내용 검수 지침은 최종 호출에만 추가한다. 실제 산출물, 원천 증거와 편집자 해석의 구분,
동일 조건에서의 대립 여부, 절차의 재현 가능성, 자막과 화면의 관측 범위, 부분 중단 복구를 확인한다.

등록 스크립트 실행기는 감독 턴의 `INDIEBIZ_REVIEW_STAGING`을 동기·백그라운드 자식에게 전달한다.
`보고서HTML`은 `stage_artifact` 계약에 따라 공유창고 대상 출력을 비공개 초안으로 생성한다.
응답의 `publication_pending`과 `items.path`는 초안, `public_target`은 승인 후 공개 위치다.
`self:notify_user`의 에이전트 알림은 `queued_for_review`로 보관하고 같은 제목의 보완본은 대체한다.
기타 시스템 서비스의 즉시 알림은 이 경로를 사용하지 않는다.

의식은 기존 응답 version/hash와 함께 `pending_delivery.hash`를 `delivery_hash`로 승인한다.
하네스가 파일 지문을 다시 확인하고 같은 바이트를 원자적으로 공개한 후 알림을 전달한다.
본문 재생성, 추가 평가 호출, 에이전트의 승인 알림 재호출은 필요하지 않다.
미승인·취소·변경된 지문은 공개되지 않는다. 공개 오류는 사건으로 남기고 목표 달성을 취소한다.
이 계약은 협력하는 등록 스크립트와 에이전트 알림에 적용되며 임의 셸/외부 도구까지 원자화하지 않는다.
여러 파일과 외부 알림 전체의 분산 트랜잭션은 아니므로, 도중 장애의 실제 전달 내역은 사건 원장으로 확인한다.

## 기존 자료 정정

- 보고서의 과장된 대립·순위·화면 관측 단정을 수정했다. 절차 없는 원칙 하나를 팁에서 제외해 당일 14개, 누적 610개로 정정했다. 원장 선정 4편과 날짜 확인 63편은 유지된다.
- 로컬 마크다운, 공개 HTML, 당일 팁 증분·누적 DB, 해당 영상의 분류, 관련 사실 기억 525를 함께 고쳤다. 사실 기억의 임베딩과 검색 트리도 갱신했다.
- **감사 정정:** 실행 주행 원문 16문장은 원래 저장되어 있었다. 실패한 것은 검색 가능한 대표 용례의 코퍼스 적재였다. 성공 원문에서 의존성을 닫은 후보 수집과 지침 회상 사례 2개를 `add_examples_batch`로 복구·색인했다.
- 역사적 에피소드 원문·usage 사건은 덮어쓰지 않았다. 기존 자료와 SQLite 백업은 `data/_backups/2026-09-10_episode3352_repairs/`에 있다.
