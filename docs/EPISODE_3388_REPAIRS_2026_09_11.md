# 에피소드 3388 후속 수리 — 2026-09-11

정본 저장소 main에 반영하는 후속 수리다. 앞선 비용 수리의 실제 사용자 진입 누락을 바로잡는다.
3388의 당시 ACHIEVED·시각·토큰·사건을 성공한 통합 감독 기록으로 소급 변경하지 않는다.

## 확인된 원인과 변경

### 1. 감독을 시작하지 못한 작업 신원

3388은 episode와 202개 사건의 task_id가 비어 있었고, compatibility_plan·goal_eval만 실행됐다.
HTTP 프로젝트 명령 `_run_agent_command`에 task 발급이 없으며 공통 cognitive_stream도 agent_id만 보충했다.
이 HTTP 누락은 코드에서 확인했다. 3388의 실제 HTTP/WS 전송 경로는 보존 로그만으로 확정하지 않았다.

- HTTP 명령은 매 요청 새 task를 만들고 에피소드 시작 전에 명시 바인딩한다. 대화 DB에도 task를 남기며,
  위임 대기 상태를 보존하고 완료·실패를 기록한다. 에피소드를 끝낸 뒤 워커 문맥을 정리한다.
- 외부 채널은 소유자 확인 후 task를 먼저 발급한다. 내부 메시지는 받은 task를 유지하고 누락이면 독립 발급한다.
- 에피소드 자체도 빈 task를 허용하지 않는다. 생성은 contextvar 내부라 비동기 이벤트 루프의 이웃 thread-local을 바꾸지 않는다.
- cognitive_stream은 에피소드에 바인딩된 ID, 기존 워커 ID, 새 ID 순서로 정해 작업 범위에만 복원한다.
  감독·MCP 재진입·초안·턴 변수·토큰 원장이 동일 신원을 받는다. force_role 내부 호출은 감독을 열지 않는다.
- 추가로 발견한 누락: 프로젝트 에이전트는 의식의 imagined_ibl을 저장하지 않았다. 시스템 AI 분기에 있던
  초안 저장을 공통화했다. `$초안`을 실제로 회수할 수 있고 저장 실패는 숨기지 않는다.

### 2. 원자료 중복 표시와 재조회 왕복

`items`를 선택해도 큰 `data` 배열이 그대로 붙어 있었고, 파이프 final_result 안에도 같은 문제가 있었다.

모델 표시 경계에서 items 옆의 큰 보조 값을 접고 `_model_omitted`에 생략한 필드·크기·개수를 표시한다.
오류·부분 실패 등 정직성 메타데이터는 유지한다. 실행 통화·턴 변수·저장 원문은 보존한다.
기존 final_result의 문자열/객체 타입과 축약하지 않은 작은 원문의 바이트 계약도 유지한다.

`execute_ibl(code:"", read_result:{id,offset,limit,path?})`에 선택 경로를 추가했다.
path는 키·배열 인덱스 목록이다. 예 `["final_result","items"]`, `["items",0]`.
중첩 JSON을 해제한 해당 값에 문자 페이지를 적용한다. 생략하면 기존처럼 원 봉투를 읽는다.
모델 스키마·MCP 설명·압축/전체 교재·언어 문서를 맞췄다. 새 어휘나 추가 AI 호출은 없다.

보존된 실제 결과의 재생(외부 요청·모델 재호출 없음):

| 결과 | 이전 모델 표시 | 수리 후 모델 표시 | 표시 글자 감소 |
|---|---:|---:|---:|
| KOSIS 직접 결과 | 261,950자 | 13,788자 | 94.74% |
| KOSIS → 열 선택 | 302,516자 | 2,901자 | 99.04% |

원자료 359,889자·925,368자는 모두 동등하게 복구했다. 이는 두 도구 결과의 MCP 바깥 제한 적용 전
JSON 글자 수다. 전체 작업의 토큰·금액·시간 절감률은 아니다. 재생 수치는
`outputs/research/episode3388-projection-replay.json`에 남겼다.

### 3. 읽기와 계산식 오류

- self:read는 XLS/XLSX/XLSM을 확장자 또는 format으로 구분한다. XLS는 xlrd 읽기 전용 어댑터로
  기존 text·table 통화에 연결한다. 날짜·불리언·빈 셀·오류 셀을 구분하며 수식은 저장된 값만 읽는다.
  중간 변환 파일은 만들지 않는다. 의존성을 requirements-tools에 선언하고 정본 .venv에 설치했다.
- path뿐 아니라 file_path/target도 확장자 판단에 사용한다. 없는 시트를 지정하면 다른 시트로
  조용히 대체하지 않고 사용 가능한 시트와 함께 실패를 반환한다. 읽기 종료·실패 모두 자원을 닫는다.
- `filter{where:"len(text) > 200"}`에는 필드 부재만 말하던 오류 대신 기존
  `compute{set:{문자수:"len(text)"}} >> filter{where:"문자수 > 200"}` 경로를 안내한다.
  계산 DSL을 중복 신설하지 않았다. 어휘 도움말·실행 오류·파생 카탈로그를 함께 갱신했다.

### 4. 검수와 기존 보고서

최종 검수 지시에 원 정의의 조건, 비교 단위·분모·기간·조사 계열, 집계/하위 집단/인과 구분,
요약의 한계 보존을 짧게 추가했다. 중간 점검마다 이 최종 검수 지시를 추가하지 않는다.
호환 평가 프롬프트에도 같은 내용 검수 기준을 반영했다. 별도 평가 에이전트나 매 단계 반성을 추가하지 않았다.

기존 `projects/정보센터/outputs/이사빈도_디지털노마드_검증보고서_20260911.md`도 정정했다.

체감의 원인을 확인한 사실처럼 서술한 부분을 수정했다. 공식 브리핑의 한국 20대 이동률 증가도 반영해
전국 평균과 구분했다. MBO·Census·국가데이터처·리치먼드 연준의 확인한 출처를 연결했다.
백업은 `data/_backups/2026-09-11_episode3388_report/`이다. 개인 산출물은 코드 커밋에 넣지 않는다.
정보센터 심층메모리의 관련 단어 검색에서 이 주장이 전파된 행은 발견되지 않았다.
