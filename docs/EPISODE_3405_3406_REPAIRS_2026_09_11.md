## IBL·관용구 실측

`world_pulse.db`의 `trajectory_event.kind=ibl.started`와 `ibl_code_corpus`를 결합했다.
아래는 실행자와 감독을 합친 호출 수다. 파이프·병렬·대입 열은 해당 구문이 든 호출 수로,
서로 중복될 수 있다. 에이전트 라운드나 도구 전체 호출 수와 혼동하지 않는다.

| 에피소드 | IBL 호출 | `>>` 포함 | `&` 포함 | 변수 대입 포함 | `[fn:…]` 포함 |
|---|---:|---:|---:|---:|---:|
| 3405 | 22 | 13 | 2 | 3 | 0 |
| 3406 | 39 | 18 | 2 | 1 | 0 |

검색·KOSIS 조회 뒤 `select/take`, 결과 저장과 차트, 원문 읽기에 IBL을 쓴다.
파이프와 변수는 쓰지만 반복 패턴을 이름으로 부르는 단계는 정착하지 못했다.
현재 상시 관용구 중 `주소마다읽기`는 독립 URL들의 원문 읽기,
`위치마다읽기`는 위치를 지정한 반복 읽기에 맞는 후보다. KOSIS·차트 작업 전체를
무조건 기존 관용구로 대체할 수 있다는 뜻은 아니다.

3406 이하 최근 사용자 에피소드 30개(`source=usage`)에는 IBL 시작 사건 652개가 있다.
코퍼스에서 코드를 복원한 645개 중 `[fn:…]` 포함 호출은 5개, 해당 에피소드는 3개다.
`최신파일읽기` 1회, `직전보고서찾아읽기` 2회, 턴 안에서 정의한 `유튜브팁보고서작성` 2회다.
따라서 모든 fn 호출을 재사용 관용구의 성공으로 세면 안 된다. 코드 미복원 7건은
사용 여부를 판정하지 않았다. 최근 두 에피소드의 코드는 모두 복원했다.

계획용 감독 프롬프트는 실행 환경 지도가 붙기 전에 따로 보존됐고, runtime의 도구
문맥도 원시 액션만 실었다. 실행자에게 보이던 관용구가 계획자의 선택지에는 빠졌다.
`ibl_access.idioms_map`을 공개 계약으로 승격해 계획·재계획에도 같은 지도를 전달한다.
임의 관용구 추가나 호출 할당량 대신, 반복 구간에 실제 서명이 맞는 이름을 hint로
전달하게 했다. 원시 액션 전용 highlight_actions에 관용구를 섞지 않는다.

## 수리한 경계

1. 짧은 감독 execute 결과에도 원문의 `evidence.id`와 실제 보여 준 `page`를 반환하고
   그 범위의 읽기 기록을 남긴다. 긴 결과는 첫 12,000자만 기록하며 숨은 꼬리는 미검수다.
   붙어 있는 읽기 범위를 합쳐 페이지 경계를 걸친 실제 인용도 인정한다. 빈틈은 합치지 않는다.
2. 인용 자체는 저장 원문에 있지만 읽기 기록만 없는 경우, 해당 구간과 주장의 관계를
   한 번만 별도 확인한다. 최대 8,000자 분량의 발췌 문맥, 60초, 추가 읽기 2회 이내다.
   수정·execute는 금지하고 모델의 명시적 확인이 있어야 한다. 원문에 없는 인용은
   자동 보정하지 않는다. 재확인 실패·취소·산출물 변경은 승인하지 않는다.
3. 재검수 입력에서는 전체 사건 전문과 계획의 중복을 줄이고 기존 호출의 입력·출력
   증거 ID 목록을 제공한다. 산출물은 첫 검수에서 전체를 읽고, 보완 후에는 동일 바이트의
   읽기 이력과 실제 변경 구간을 분리한다. 큰 변경의 표시하지 못한 뒷부분은 미검수로 남는다.
   읽기 이력 재사용은 내용 승인 재사용이 아니다. 새 hash와 의미·출처·계수 판단은 계속 요구한다.
4. REWORK 인계에 산출물 경로·증거 ID와 원문 호출 목록을 넣는다. 실행자는 이미 확보한
   출처를 찾으려고 전체 파일시스템을 검색하거나 다시 크롤할 필요가 줄어든다.
5. 감독 프롬프트는 확보된 근거의 검수와 실행자의 보완을 구분한다. 발견한 결함을
   한꺼번에 넘기고, 재검수는 변경한 주장과 의존 요약·계수·출처부터 본다. 사용자 측정량을
   다른 지표로 대체하거나 fallback을 적는 것만으로 원래 목표를 충족 처리하지 않는다.
6. 차트는 형식 미지정 시 `.html/.htm` 경로를 HTML로 해석한다. 명시한 PNG/HTML과
   경로가 충돌하면 렌더 전에 구체적 오류를 낸다. 원본 호출 인자는 변경하지 않는다.
7. KOSIS의 추가 차원은 미지정과 명시한 ALL을 구분한다. 명시한 obj_l2/obj_l3=ALL을
   실제 요청에 보존한다. objL 오류에는 전달한 분류와 다음 점검 방법을 남긴다.
   파이프가 에러 문자열만 전달해도 복구 안내가 살아남는다.
