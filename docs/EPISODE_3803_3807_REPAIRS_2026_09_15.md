# 에피소드 3803–3807: 경로·계측·불필요한 왕복 수리

## 문제와 변경

#3807은 비밀번호 최소 길이 8→4 변경을 성공했지만 442.8초·도구 62호출·
오류 기록 7건을 사용했다. 실행 응답은 39개인데 요약은 0라운드였고,
#3803도 10응답을 0으로 집계했다.

- **REPAIR 재판정**: 의식이 `needs_repair:false`를 명시하면 THINK로 돌아가며
  system_repair 모델 전환·RED 그랜트를 발급하지 않는다. 명시적 `#repair`는
  사용자 선택으로 유지한다. 누락·잘못된 타입을 false로 추측하지 않는다.
  최초 분류는 보존하고 `cognition.route`에 이전 분류·정정 이유를 남긴다.
  수리 규정 프롬프트도 후보를 확정 사실로 쓰지 않는다.
- **라운드 집계**: 공통 함수에 system_repair를 포함한다. 동일 호출·응답 중복은
  제거하고 의식·평가·배경 원샷은 제외한다.
- **부재 관찰**: 순수 self:read의 ENOENT는 tool.finished에
  `observation=missing_read`로 남기고 연속 실행 실패를 늘리지 않는다.
  원래 오류와 증거는 보존한다. 같은 조회 반복·쓰기·권한·혼합 프로그램 오류는
  기존 감독을 유지한다.
- **가이드 신원**: MCP HTTP 헤더/stdio 환경의 agent·task를 read_guide 브리지로
  전달하고 HTTP 처리 동안만 복원한다. 실제 반환한 world_tools 본문만 자작
  관문에 기록한다. 목록 조회·읽기 실패는 관문 해제 근거가 아니다.
- **빌드 보고**: package.json의 build를 실행하고 lint가 없으면 생략한다.
  빌드 전후 관례 출력 디렉토리의 파일 크기·mtime을 비교해 갱신된 후보를 보고한다.
  후보가 하나일 때만 output_dir을 확정한다. 여러 경로·커스텀 경로·미갱신은
  미확정으로 남겨 오래된 .next를 사칭하지 않는다. 기존 배포처를 따르도록
  후속 안내를 바꾸고 ANALYZE 환경도 실제 전달한다.
- **읽기·검수 지침**: 이미 읽은 구간·spill 사본 중복 조회를 줄이고 줄/문자
  페이지 단위와 EOF를 구분한다. 작은 사이트 정책 변경은 관련 경계·동작을
  검증하며 이미 본 동일 화면을 별도 비전 모델로 다시 판독하지 않는다.
  브라우저는 같은 driver를 유지하고 화면 변경 뒤 낡은 ref를 재사용하지 않는다.

## 검증 범위

`backend/test_episode3803_3807_repairs.py`는 실제 파이프라인의 그랜트/모델 분기,
명시 태그·사용자 출처 유지, 라운드 중복 제거, 부재와 실제 실패의 감독 차이,
MCP→HTTP 신원 전달·복원과 가이드 관문, 정적/Next/커스텀/실패 빌드 보고를
외부 모델·배포 호출 없이 검증한다. 관련 기존 회귀 163개 통과.

전체 backend 회귀도 실행했다. 작업 전 미커밋 상태의 압축·이미지변환 스크립트를
registry가 가리키는 문서 감사 실패와, 별도 test_read_formats 파일의 직접 실행
진입점 누락이 발견됐다. 후자는 pytest 위임 진입점만 보완하되 해당 미커밋 파일
전체를 이번 커밋에 포함하지 않는다. 전자는 다른 작업의 파일을 임의로 커밋하지
않으므로 미해결 상태로 보고한다.

실제 사이트 재배포·시험 게시물 작성은 반복하지 않았다. 브라우저의 당시 60초
시간 초과 자체는 별도 재현되지 않아 타임아웃 수치나 자동 재시도 정책을
추측으로 바꾸지 않았다. 시간·호출 감소는 다음 실사용 주행에서 측정해야 한다.
