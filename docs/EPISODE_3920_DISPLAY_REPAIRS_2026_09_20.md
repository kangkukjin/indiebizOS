# 에피소드 3920 — 결과 미리보기와 불필요한 도구 탐색 수리

## 관측과 변경

2026-09-20 후티 배경 해설에서 `주소마다읽기`의 `each`가 크롤링의
`_display.limit_rows:false`를 버려 문단 결과가 일반 표의 앞 8행으로 표시됐다.
제목·날짜·공유 버튼만 받은 뒤 본문을 추가 조회했고, 이미 발췌한 문단도 재조회했다.
`each`와 `union`은 성공한 비어 있지 않은 출력들의 호환 표시 정책을 공통 함수로 합친다.
문단 표시를 모두 선언했을 때만 행 제한을 해제하고, 글자 예산은 가장 작은 값을 공유한다.
일반 표·스칼라와 혼합하면 문단 정책을 추측하지 않는다. 실패와 원문은 보존한다.

묶음 검색 4개를 연결한 뒤 앞 8행만 표시하면 마지막 두 검색어의 결과가 아예 보이지 않았다.
모든 검색 배치 경로(ddg/naver/guardian 공통, gnews, hn)는 `_display.group_by:query`를 선언한다.
모델 표시기는 묶음별 첫 행을 차례로 선택하고 슬롯이 남으면 다음 행을 선택한다.
글자 예산도 대표 행들이 나눠 쓴다. 원문 순서와 저장된 값은 바꾸지 않으며
`_preview.selection/group_by/indices/groups_total/groups_shown`으로 표본임을 밝힌다.
일반 표와 묶음 열이 빠진 투영은 기존 앞부분 미리보기를 유지한다.

공통 프롬프트는 제공 여부와 무관하게 `todo_write`를 요구했다.
실제 실행자는 도구 목록에서 `todo|plan`을 찾았지만 빈 목록을 받았다.
계획·진행 표시 자체를 요구하고, 현재 제공된 진행 도구 또는 응답을 사용하도록 고쳤다.
진행 표시만을 위한 도구 탐색은 요구하지 않는다.

## 보존과 감사

- 모델 미리보기만 바꾼다. 앱·저장 변수·`read_result`의 원문, 검색 순서와 건수는 그대로다.
- 여러 페이지의 예산을 더하지 않는다. 긴 발췌는 여전히 글자 예산에 따라 잘릴 수 있다.
- `group_by`는 생산자 선언이다. 임의의 `query` 열만 보고 표를 검색 결과로 추정하지 않는다.
- web 패키지의 변경은 세 배치 응답에 표시 메타데이터를 추가한 것뿐이다.
  검색·크롤링의 네트워크 대상, 회원 주체, 저장 경로, 인증 및 부작용 경로는 변경하지 않았다.
  변경 차이를 재감사하고 두 hub 액션의 `path_audited`를 현재 구현 지문으로 갱신했다.
- 사전 의식 생략이나 전체 초기 프롬프트 축소는 이 수리에 포함하지 않는다.
  이 변경만으로 실제 에피소드의 시간·토큰 절감량이 확정되는 것은 아니다.

## 검증

`backend/test_episode3920_display_repairs.py`가 다음을 네트워크 호출 없이 검증한다.

- 순차·병렬·중첩 each의 문단 설정, 공통 예산, 혼합 결과와 부분 실패
- 수집 → 필터 → 열 선택 → 모델 표시 → 원문 조회의 값 보존
- 묶음 검색의 대표성, 글자 예산 배분, 표시 슬롯을 넘는 묶음 수의 명시
- 병렬 소스 union·dedup·select 후 표시 설정과 검색 순서 보존
- 모든 검색 배치 경로의 표시 선언과 실패·정상 0건 보존

기존 미리보기·each·결과 조회 회귀와 backend 층/IBL 빌드/폰 번들 정합성도 검사한다.

전체 `pytest backend/ -q` 실행에서 독립 패키지의 모듈 경로와 새 테스트의 직접 실행
진입점 누락 두 건을 발견했다. 병합 함수를 `common.currency`로 옮기고 테스트 진입점을
보완한 뒤, 두 실패 항목을 포함한 관련 회귀 120개가 통과했다. 나머지 전수 항목은
최초 실행에서 통과했으며, 이 보완 뒤 전수를 다시 실행하지는 않았다.
