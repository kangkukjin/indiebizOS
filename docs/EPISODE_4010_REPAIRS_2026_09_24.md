## 오류와 인과

1. **비교 요청 분할 결함**: 후보 28개와 시점 앞 30초·뒤 90초 자막 문맥을 담은 요청은
   기존 팁을 제외해도 81,498자였다.
   기존 팁 한 건을 더하면 81,718자로 개별 요청 상한 57,000자를 초과한다.
   기존 분할기는 누적 팁 쪽만 나눴으므로 어떤 배치도 만들지 못했다.
2. **원인 표시와 준비 상태 기록 부족**: 저장 판본 1의 독립 문장은 실패 뒤 다른 문장도 실행한다.
   뒤쪽 변수 누락과 try/catch의 2차 오류가 최종 오류 앞부분을 차지했다. 원래 오류는
   root_failures와 긴 문자열 뒤쪽에 있었고, 준비 단계의 blocked·resume는 반환에만 있었다.
   state.json에는 후보 확정 영수증은 있었지만 준비 실패 이유가 남지 않았다.
3. **개별 복구 호출 오류**: seq 28의 파이프 오른쪽 병렬식은 현재 문법 검사에서 거절됐다.
   seq 307은 JSON 객체인 video_decisions를 배열 select로 읽으려 했고,
   seq 331은 긴 본문·근거를 한 AI 입력에 넣어 상한을 넘었다. 이 셋은 실행자의 조합/입력 오류다.
   오류를 성공으로 바꾸는 코어 우회는 추가하지 않는다.
4. **불필요한 검수 왕복**: 개별 복구가 만든 criteria는 수정 사항이 없는 빈 corrections를
   필수 값 누락으로 판단해 다시 호출했다. 등록 관용구는 이미 구조 검사를 결정론 코드로
   수행한다. 이번 수리는 정상 관용구 경로를 복원하며 검수 기준을 약화하지 않는다.

## 변경

- 후보와 기존 팁을 모두 나누고 각 배치의 후보 ID·기존 팁 ID·요청 지문을 기록한다.
  모든 후보×기존 팁 쌍이 정확히 한 번 포함됐는지 판정 수용 전에 확인한다.
- 응답의 원 요청 변경, 배치 누락, 다른 배치 후보의 판정, 비교 범위 누락·중복을 거절한다.
  unknown·누락 보완은 해당 배치의 후보만 대상으로 한다. 정상 판정은 그대로 보존한다.
- 이미 발급한 요청은 재진입 때 그대로 복원하고 지문을 확인한다. 과거 실행 상태에서
  candidate_ids가 없으면 기존의 전 후보 범위를 유지한다. 빈 원장은 비교 AI 호출이 없다.
- 준비 실패는 state.json의 preparation_failure에 원인·확정 여부·재개 인자를 저장한다.
  준비가 성공하면 해제하며 완료된 검색·추출을 반복하지 않는다.
- 공통 파이프라인의 오류 문자열은 최초 할당 실패부터 보여 준다. 후속 오류·트레이스백은
  보존한다. 판본 1의 독립 문장 실행 의미와 판본 2의 중단 의미는 변경하지 않는다.

이는 한 업무의 후보 수 제한을 늘리는 변경이 아니다. 두 자료 집합을 전건 비교할 때
양쪽 입력과 모든 비교 쌍을 보존하는 분할·검증을 이 관용구의 소유 코드에 구현한 것이다.
원인 우선 오류 표시는 같은 실행기를 쓰는 다른 관용구에도 적용된다.

## 검증 범위

실제 에피소드의 입력을 읽기 전용으로 재구성하면 18개 요청, 최대 56,918자이며
28×655=18,340개 쌍이 정확히 한 번씩 포함된다. 기존 회차 원장·보고서는 변경하지 않는다.
이전 live-v3의 실제 비교 응답 513개도 기존 범위·지문 그대로 검증된다.
재현 결과는 `outputs/episode4010_repair/comparison-replay.json`에 원본 지문·분할 크기·전건 계수로 남긴다.
`outputs/episode4010_repair/subprocess-replay/`에서는 당시 수집·추출 입력을 별도 원장 사본으로
다시 검증하고 실제 스크립트 프로세스가 18개 비교 요청을 성공 반환하는 것까지 확인했다.
외부 검색·추출 AI는 다시 호출하지 않았으며 이 재현이 비교 AI의 판정 품질을 입증하지는 않는다.

고정 외부 응답을 사용한 이름 호출의 전체 경로에서 양쪽 분할, 원문 보존, 판정 누락·unknown
보완, 잘못된 후보·입력·배치 범위 차단, 재진입·기존 판본 호환을 검사한다.
원문 또는 후보 한 건과 기존 팁 한 건조차 상한을 넘는 경우에는 계속 정직하게 중단한다.
외부 자료 실패·추가 근거 필요·내용 검수 탈락을 무조건 성공으로 바꾸지 않는다.
실제 AI의 보고서 품질과 벽시계·토큰 절감은 이 결정론 재현으로 입증한 것이 아니다.
