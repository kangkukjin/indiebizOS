# 에피소드 4010 — 관용구가 판단을 줄이지 못한 이유

목적 정본: [비전](../data/system_docs/vision.md), [IBL 진화 목적과 개선 판단](IBL_EVOLUTION_PURPOSE.md).
구현 수리와 회귀 결과는 [별도 기록](EPISODE_4010_REPAIRS_2026_09_24.md)에 있다.

## 결론과 앞선 수리의 한계

이번 문제의 직접 원인은 비교 입력의 한쪽만 분할한 결함이다. 그러나 입력 상한을 고쳐
실행 가능하게 만드는 것만으로 사용자의 목적을 달성하지 못한다. 목적은 품질을 유지하면서
실제 완료 시간과 전체 토큰을 줄이고, 그 개선을 다른 작업에도 전달하는 것이다.

현재 관용구는 절차를 한 이름으로 호출하는 능력은 갖췄지만, 이 보고서에서는 **앞서 확정한
판단을 믿고 이어 쓰는 범위가 좁고, 내부 문제를 바깥 실행자가 다시 풀어야 하는 범위가 크다.**
관용구 등록·실행 완료·회귀 통과를 효율적인 능력의 정착과 구분해야 한다.
앞선 수리 보고가 회귀 통과를 중심에 둔 것은 개선 목적에 비해 좁은 판단이었다.

새 원칙이 없어서만 생긴 문제도 아니다. 기존 `IBL_IDIOM_REPAIR.md`는 이미 동일 품질에서
판단·재작성·수리를 줄였는지 비교하라고 한다. 이번 개발에서는 그 비교를 완료하지 않은 채
관용구를 일상 실행 경로로 안내했다. 규칙을 추가하기보다 기존 목적을 실제 채택 판단에 적용해야 한다.

## 원인과 개선할 책임 경계

### 1. 단계별 절약을 전체 작업의 절약으로 검증하지 않았다

첫 추출은 제목·인용·시각만 만든다. 선정 후에야 `how` 등 방법을 상세 추출한다.
이 설계에는 버릴 후보의 긴 본문을 쓰지 않는 합리적인 목적이 있었다.
하지만 중복 비교는 상세 추출보다 먼저 수행되며, 제목만으로 방법의 같고 다름을 판단하기 어렵다.
이를 보완하려고 후보마다 앞 30초·뒤 90초 자막을 붙이고, 불확실하면 전문으로 다시 판단한다.
이전 live-v3는 최초 비교 27개 묶음 뒤 전문 재검토 요청 23개를 더 사용했다.

따라서 검토할 가설은 “처음부터 긴 보고서 본문을 모두 쓰자”가 아니다.
**후속 판단에 필요한 최소 의미—행동·적용 조건·차별점·근거 위치—를 한 번 추출하면
제목만 추출한 뒤 재독해하는 것보다 전체 비용이 낮은가**다. 추가 출력과 후보 누락 위험까지
같이 비교해야 하며, 현재 자료만으로 승자를 단정하지 않는다.
이 문제는 문서 분류·자료 조사·고객 문의 처리에서도 나타나는 중간 표현의 문제다.

### 2. 감사 기록 보존과 모델에게 다시 읽히는 자료를 충분히 분리하지 못했다

`comparison_candidates`는 겹치는 자막 구간을 후보마다 붙인다. `novelty_view`는 판정과 이유를
후속 선택·검토로 전달한다. 최종 검수는 비교 기록을 나눌 때 보고서 전체와 나머지 검수 자료를
각 분할에 복제하고, 나머지 여섯 기준도 매번 확인하게 한다. 필요한 인계도 있지만 반복도 생긴다.
전부 저장해야 한다는 요구가 매 판단에 전부 재전달해야 한다는 요구는 아니다.

같은 18개 요청에서 원문을 하나도 버리지 않는 두 가지 표현을 오프라인 비교했다.

| 표현 | 합계 문자 수 | 기존 대비 |
| --- | ---: | ---: |
| 현재 후보별 자막 복제 | 1,000,341 | 기준 |
| 자막 구간별 ID와 참조 목록 | 1,128,141 | 12.78% 증가 |
| 영상별 자막 공유 + 기존 시간 범위 | 863,427 | 13.69% 감소 |

두 실험 모두 후보별 원래 구간 목록을 정확히 복원했다. 결과는
`outputs/episode4010_repair/context-sharing-probe.json`에 있다.
작은 구간마다 ID를 붙이면 참조 관리비가 절약보다 커졌다. 공통화도 측정 없이 정답이 아니다.
두 표현 모두 모델의 참조 해석 정확도·실제 토큰·완료 시간은 미검증이며 운영 코드에 적용하지 않았다.
13.69%의 문자 감소도 반복 판단 전체를 해결하지 않는다.

개선 위치는 원문 보관·근거 참조·단계별 입력 투영의 접점이다. 기존 통화·스필·입력 투영을
먼저 활용한다. 후속 검수에는 자신이 검증할 주장과 관련 근거를 전달하고, 필요할 때 원문을
확장한다. 해시는 같은 자료임을 증명할 뿐 의미 판단의 옳음을 증명하지 않는다.

### 3. 기억이 커질수록 매회 판단 비용도 커지는 구조다

현재 중복 판정은 모든 새 후보와 원장 전건의 조합을 AI에게 비교시킨다.
이번 수리는 18,340개 비교 쌍을 보존해 상한 문제를 닫았지만 비교 범위를 줄이지 않았다.
이는 원장의 누적을 재사용 가능한 의미 기억으로 전환하는 부분이 부족하다는 뜻이다.

검토할 경로는 근거가 연결된 방법 표현, 관련 후보 검색, 불확실할 때 범위 확장, 유효한 판단의
재사용이다. 단순 top-k 검색으로 바꾸고 원장 전건과 비교했다고 말할 수는 없다.
주제·도구명이 달라도 같은 방법인 사례, 같은 도구라도 다른 방법인 사례로 검색 누락을 재고,
전건 경로와 대조해야 한다. 원문·원장·규칙·판정 설정 변경에 따른 무효화도 필요하다.
이것은 새 검색기를 무조건 만들라는 결론이 아니다. 기존 기억·검색·지문 기능을 확인하고
고정 자료에서 절감과 누락의 관계를 먼저 입증한다. 사전 정리 비용의 회수 조건도 센다.

### 4. 실패할 때 관용구의 경계가 유지되지 않았다

관용구가 실패한 뒤 호출자는 자막·원장·검토 입력을 직접 다시 읽고 절차를 재구성했다.
예상했던 판단 절약이 복구 국면에서 사라지고, 커진 대화 이력을 이후 라운드가 계속 부담했다.
원인 우선 표시는 개선됐지만 배치 하나의 성공을 개별 영수증으로 확정하는 경로는 이 관용구에 없다.
일부 배치 실패 시 단계 전체를 다시 실행할 수 있는 한계도 남아 있다.

시스템 전체에 재개 기능이 없다는 뜻은 아니다. `ibl_v2_runtime.invoke`에는 요청 지문,
정의 의존성 검사, 호출 영수증과 재생 경로가 있다. 이 보고서는 판본 1 관용구와 자체 단계
영수증을 사용한다. 필요한 것은 별도의 범용 엔진 신설보다 **기존 실행기와 관용구 내부
작업 단위 사이에서 확정 결과·실패 범위·재개가 이어지는지** 검증하고 연결하는 것이다.
판본 2로 옮긴다는 사실만으로 하위 호출의 비용·부작용 보존이 보장되지는 않는다.

외부에는 완료 결과, 막힌 판단, 유효한 중간 결과, 필요한 추가 근거, 재개 인자가 전달되어야 한다.
기계적 오류와 사용자 판단이 필요한 불확실성을 구분한다. 반복 입력 크기·형식 문제의 수습을
사용자에게 돌리는 것은 의식의 해방이 아니다.

### 5. 검수가 늘어나는 것과 품질이 좋아지는 것을 구분해야 한다

구조 검증·원문과의 의미 대조·편집 검수는 서로 다른 책임이다. 현재 코드도 일부를 분리했다.
그러나 수동 복구에서는 빈 `corrections`를 불합격으로 보는 criteria가 추가 왕복을 만들었다.
정상 관용구에서도 최종 검수 분할마다 보고서 전체의 기준을 반복한다.
형식·ID·개수는 코드가 검사하고, AI는 새로운 의미 판단과 변경으로 영향받은 주장에 집중해야 한다.
독립 의미 검토를 통째 제거하거나 모델을 낮추는 것을 절감의 출발점으로 삼지 않는다.

보고서의 실제 가치도 별도로 봐야 한다. 일곱 검수 항목 통과는 사용자가 이미 아는 내용인지,
실제로 무엇을 바꿀 수 있는지에 대한 사용자 평가를 대신하지 않는다. 독자 맥락은 현재 실행에
전달되지만, 그 사실만으로 개인의 판단이 축적된다고 입증되지는 않는다.
사용자가 남긴 선택·수정은 근거와 적용 범위를 가진 다음 실행의 자료로 활용하되,
응답이 없음을 만족·성공으로 기록하지 않는다. 매 실행마다 새 평가 AI를 더 붙이는 해법도 아니다.

## 적용 순서와 완료 기준

1. **기준선 확정**: 같은 자료·원장·모델·추론 설정·독자 맥락에서 수동 경로와 수정된 관용구를
   비교한다. 4010 수동 복구만으로 정상 관용구 대비 성능을 계산하지 않는다. 별도 출력과 원장
   사본을 쓰고 실제 발행을 반복하지 않는다. 현재 계측을 활용해 단계·역할·재시도를 연결하며,
   식별할 수 없는 토큰은 미배정으로 남긴다. provider 기본 맥락 비용도 따로 측정한다.
   원샷은 이미 도구·이력을 줄이는 경로를 쓰므로 전체 의식 프롬프트를 항상 복사한다고 단정하지 않는다.
2. **작은 비교 실험**: 먼저 원문 공유 표현, 그다음 최소 의미 추출과 검수 책임 분리를 각각 비교한다.
   기존 구현을 대조군으로 보존한다. 최종 사용 가치·출처 정확성·중복 누락을 방식 표시 없이 평가하고,
   입력·캐시·출력·하위 평가·복구·후처리 토큰과 실제 완료 시간을 함께 센다.
3. **실패와 성장 검증**: 작은 원장과 큰 원장, 긴 자막, 생소한 주제, 불확실한 근거, 배치 중간 실패,
   원문 변경에서 확인한다. 신규성 있는 팁이 없을 때의 정직한 결과도 설계한다.
   현재 `stage_chosen`과 `stage_reviewed`는 선택/통과 팁 0개를 오류로 처리한다. 이는 4010의
   원인은 아니지만 결과 없음과 실행 실패의 구분을 검토할 지점이다. 팁 수를 맞춰 통과시키지 않는다.
4. **공통 능력으로 환류**: 근거 있는 항목 추출·비교는 문헌 조사에, 부분 실패 재개는 다수 문서
   처리에 적용해 본다. 아직 사용하지 않은 입력까지 이득이 전달될 때 공유 부분을 기존 공통층에
   둔다. 보고서의 주제·선정 기준·원장 정책은 업무 코드에 남긴다. 새 IBL 낱말은 필요 조건이 아니다.

채택 조건은 같은 사용자 목표에서 품질을 유지·향상하면서 시간과 전체 토큰을 함께 줄이는 것이다.
일부 축만 개선되면 그 범위만 보고한다. 반복 실험의 편차·실패·사람의 수정량과 준비 비용도 남긴다.
현재 상태는 **입력 상한 결함 수리 완료, 근본 원인 분석과 무손실 표현 실험 완료,
