# 에피소드 4011 — 긴 원문의 처리 단위와 근거 인계

## 원인과 목표

검색 수리 뒤에도 남았던 실패는 `BLeFFJCnL5s`의 자막이 단일 추출 상한을 넘은 사건이다.
원문 2,032개 세그먼트, 시간 표기를 포함한 전달 문자열 94,138자였다. 단일 상한을 높여도
상세 추출·불확실한 신규성 재검토·독립 내용 검토가 전문을 다시 받으므로 다른 단계에서 막힌다.

처리 단위를 영상 하나에서 **원문 구간과 후보별 근거**로 바꿨다. 문법·새 어휘·실행기의
업무 분기를 추가하지 않았다. `AI팁보고서쓰기`와 결정론 스크립트의 형제 모듈
`data/scripts/ai_tips_sources.py`가 업무 정책을 소유한다.

## 알고리즘

1. 자막 원본·타임스탬프·지문을 보존한다. 긴 원문은 모든 구간을 나누되 핵심 구간의
   인덱스는 빠짐없이 한 번씩 덮는다. 경계 양옆은 문맥으로 겹쳐 읽는다. 긴 단일 세그먼트는
   문자 오프셋으로 나누고 원래 시간을 유지한다. 연속 문자 조각은 다시 붙일 때 공백이나
   가상의 타임스탬프를 만들지 않는다.
2. 모든 구간에서 제목·시점·인용 후보를 추출한다. 동일 영상·시점·제목·인용이 경계 중첩으로
   반복된 경우만 결정론적으로 합친다. 의미 중복은 이후 비교·선정이 맡는다. 팁 0건인 구간도
   읽은 결과로 확정한다. 긴 자료의 각 구간에 누적 원장 전체를 반복 주입하지 않는다.
3. 후보별 방법·조건·반례·예외·철회·참조 위치를 **전체 원문 구간**과 대조한다. 후보 묶음이
   커지면 묶음을 다시 나눈다. 모델은 원문 위치 ID만 고르고, 코드는 ID가 해당 구간 안인지,
   모든 후보에 판정이 있는지, 원문·요청 지문이 같은지 검사한다. 모호하면 uncertain을 남긴다.
4. 관련 위치의 실제 원문을 모은다. 모델이 생성한 요약을 근거로 바꾸지 않는다. 최초 인용의
   주변 문맥도 보존한다. 후보별 근거 묶음과 전체 구간을 대조한 기록을 연결한다.
5. 중복 비교·선정 뒤 상세 추출은 이 원문 묶음에서 수행한다. 긴 영상의 독립 내용 검토도
   후보별로 나눈다. 불확실한 신규성 보완은 같은 원문과 관련 기존 항목을 받는다.
   짧은 자료는 기존 전문 전달 방식으로 처리한다.
6. 최종 검수와 보고서는 실제 전달 범위를 밝힌다. 전체 원문을 처음 읽고 관련 위치를
   고른 것과, 후속 검토가 전문을 다시 읽은 것은 다르다. 불확실한 색인은 승인할 수 없다.
   최종 검수 전에도 원본·구간 파일·추출/색인 영수증·근거 묶음의 지문과 완료 범위를 검사한다.

전체 자막이 길다는 이유로 실패하지 않지만 개별 모델 요청의 상한은 유지한다. 한 후보가
너무 넓어 관련 원문만 36,000자를 넘거나 단일 후보·기존 항목 조합이 요청 상한을 넘으면
범위 보완을 요구한다. 근거를 절단하거나 불확실한 후보를 통과시키지 않는다. 이는 문서 전체
길이의 제한과 다르며, 무제한 입력·모든 내용 판정의 무인 성공을 보장한다는 뜻이 아니다.

## 재개와 호환성

구간 추출과 관련 위치 색인은 각 호출 직후 잠금 아래 영수증을 저장한다. 실패한 형제 호출이
있어도 성공분은 남으며, 같은 회차 재진입 시 미완료 요청만 내준다. 영수증은 빈 결과도 포함한다.
전체 구간이 끝나기 전에는 후보 비교로 넘어가지 않는다. 중복 비교·상세·내용 검토는 기존
단계 영수증을 유지한다. 모든 종류의 외부 호출에 개별 캐시를 추가한 것은 아니다.

이전 판본에서 자막 크기로 실패한 회차는 저장된 `input-transcripts.json`의 입력 지문과
본문을 먼저 검증한다. 현재 계약으로 수용할 수 있으면 추출 계획을 만들며 재다운로드하지 않는다.
기존 실행 상태 v2, 호출 이름·설정 서명·원장·완료 결과 계약은 유지한다. 확정된 옛 보고서는 바꾸지 않는다.

## 검증

- 실제 이름 호출·레거시 깊이 가드·each·try/catch를 거친 긴 원문 전체 초안 흐름.
- 자막 끝의 후보, 멀리 떨어진 조건·반례가 근거 묶음과 후속 검토에 전달되는지 확인.
- 추출 도중·색인 도중 실패 후 성공한 형제 호출의 재사용, 완료 재진입의 추가 모델 호출 0건.
- 구간 누락, 잘못된 위치 ID, 중복 ID, 요청 변경, 부분 실패, 원문·구간·영수증·근거 파일 변경 거절.
- 긴 원문의 신규성 보완과 최종 내용 재검수, 기존 짧은 원문 경로, 옛 자막 실패 입력 재개.
- 단일 세그먼트 문자 분할의 무손실 복원과 원래 시간 보존.

실제 실패 입력의 재현은 `outputs/episode4011_long_source_replay.py`와
`outputs/episode4011_long_repair/summary.json`에 남겼다. 원래 4편을 별도 회차에 복사하고
실제 스크립트 프로세스·struct 파일 읽기·크기 및 시간 근거 검증을 실행했다. 긴 영상은
6개 구간, 나머지 3편은 각각 한 구간이다. struct 읽기 9회 중 최대 본문 프롬프트는
18,264자였고, 긴 원문의 색인 요청 6개 중 최대 직렬화 크기는 37,057자였다.
추출·색인이 끝난 뒤 다시 요청하면 추가 요청은 0건이다.

이 재현과 집중 회귀의 외부 AI 응답은 고정했다. 실제 팁의 의미 품질, 위치 선택 재현율,
모델 총토큰·벽시계 절감률은 측정한 것으로 주장하지 않는다. 원문 크기·호출 수는 토큰이 아니다.
운영 보고서·원장·에피소드 상태는 바꾸지 않았다. 원본 상태 SHA-256은
`2a55fe4e2f39bd608bba62fe8479d95ef32b5d927d0fdf92c074ab434a5f45d2`로 동일하다.

집중 회귀 120개·문서 드리프트 17개가 통과했고 실제 실패 입력 재현도 통과했다.
전체 backend 회귀는 5,773개 통과·1개 건너뜀(492.61초)이었다.
수정 본문은 등록 개정 원장을 보존해 같은 이름으로 재등록했다. 스크립트는 호출마다 새
프로세스에서 읽으므로 서비스 재시작은 필요하지 않다. 사용자 요청으로 중단한 보고서는 재개하지 않았다.
