# 에피소드 4011 — 빈 검색 결과와 검색별 복구

## 사건과 중단

2026-09-24 에피소드 4011은 ‘평가’ 주제로 `AI팁보고서쓰기`를 호출했다.
검색 다섯 갈래 중 세 갈래에서 33행을 얻었지만, 두 질의의 0건 응답이 도구 오류로
반환되어 보고서의 부분 실패 검사에서 중단됐다. 사용자의 중단 요청에 따라 해당 실행자의
프로세스와 자식에 SIGINT를 보냈다. 에피소드 종료 시각은 03:27:58이며, 이후 `/health`의
live_turns와 `/nodes/active-work`가 모두 비었음을 확인했다. 시스템 서비스는 유지한다.

직접 원인은 유튜브 검색 도구의 잘못된 빈 결과 계약이다. 정상 조회 0건과 공급자 장애가
같은 실패로 표현됐다. 관용구도 팬아웃 결과를 영상 행으로 바로 펼쳐 질의별 0건의 증거를
잃고, 일부 장애 시 성공 질의를 재사용하는 단위가 없었다. 품질 검사를 끄는 대신 두 경계를 수리했다.

## 구현

- `tool_youtube.search_youtube`: 정상 응답에 영상이 없으면 success=true, count=0,
  results=[]/status=empty. 액션 핸들러에서는 items=[]가 된다. 공급자 예외, 응답 형식 불량,
  읽지 못한 항목은 실패로 남긴다. 상한 조정 정보도 빈 응답에서 보존한다.
- 배치 검색 sections에는 success/status/raw_count를 남긴다. 중복 제거 후 0건과
  실제 원 검색 0건을 구별하며, 실제 오류의 success=false/errors/partial 계약은 유지한다.
- 관용구의 검색 each는 `{stratum,query,attempt,data}`를 반환한다. 검색 결과의 items와
  성공·실패·개수·부분 처리 증거를 명시적으로 넘겨, 빈 items도 질의 봉투 안에 보존한다.
- `ai_tips_search.py`: 검색별 성공·빈 결과·오류, 원 응답, 시도 번호와 입력 지문,
  결과 지문을 보존한다. 질의 변경·층 누락/중복·잘못된 영상 ID·부분 처리·시도 변경은 거절한다.
- 정상 빈 검색은 다시 부르지 않는다. 실제 장애만 같은 질의로 한 번 자동 재시도한다.
  자동 보완 후에도 실패하면 멈춘다. 명시적 같은 회차 재진입은 실패한 검색만 한 번 더 호출하며,
  이미 사용한 자동 재시도 횟수를 초기화하지 않는다. 정상 검색은 재실행하지 않는다.
- 옛 회차의 평탄화된 실패 입력도 저장된 입력 지문을 확인해 질의별로 회수한다. 옛 오류
  문구를 해석해 정상 0건으로 위장하지 않는다. 해당 질의를 새 도구 계약으로 다시 확인한다.
- 정상 0건인 검색 층은 보고서 조사 한계에 표시한다. 모든 결과가 비거나 미처리 영상이
  없을 때는 보고서·원장을 만들지 않는다. 성공 영상의 날짜·근거·내용 검수는 그대로다.

질의별 결과를 보존한 뒤 다음 단계로 이어 쓰는 원칙은 검색·팬아웃 작업 전반에 적용된다.
0건의 정상 통화 수리는 유튜브 검색의 모든 소비자에게 적용되며, 보고서의 검색 횟수·층별
정책은 업무 스크립트에 둔다. 업무 이름을 실행기나 파서에 넣지 않았다.

## 검증

실제 사건의 `input-search-initial-failed.json`과 당시 원장 스냅샷을 별도 출력 폴더로
옮겨 재현했다. 성공한 세 질의의 33행은 그대로 보존하고, 실패했던 두 질의만 수정된
백엔드의 HTTP/IBL/유튜브 경로로 실제 실행했다. 둘 다 정상 0건으로 돌아왔고,
중복·기존 영상 제외 후 메타데이터 조회 대상으로 25편을 반환했다. 완료 검색을 다시
진입하면 요청 0건이다. 원래 에피소드 상태 파일은 SHA-256으로 변경 없음을 확인했다.

- 실행 스크립트: `outputs/episode4011_search_replay.py`
- 실제 입력·응답·영수증: `outputs/episode4011_repair/replay/`
- 요약: `outputs/episode4011_repair/search-replay.json`

집중 회귀 154개가 통과했다. 실제 IBL 이름 호출·try/catch·each를 사용해 0건 검색,
실패 질의만 보완, 지속 장애 중단, 명시적 재개, 원장 미반영, 완료 재진입, 응답 조작 거절,
옛 회차 회수를 검사했다. 외부 AI 응답은 고정했으며 실제 보고서의 모델 품질 검증은 아니다.
유튜브 도구의 빈 응답·잘못된 응답·공급자 장애·지연 목록·배치 계약도 검사했다.

전체 backend 회귀는 5,771개 통과·1개 건너뜀·2개 실패였다. 두 실패는 변경된 검색 계약의
용례 재검토 원장 누락과 새 테스트의 직접 실행 진입점 누락이었다. 검색 소비 용례 19건을
읽고 계약 호환성을 확인해 원장을 갱신했으며, 테스트 진입점은 pytest로 위임했다.
수정 후 두 실패를 포함하는 관련 검사 17개가 모두 통과했다. 전체 회귀를 다시 실행한
결과로 바꿔 적지 않는다. 문서 드리프트 검사도 별도로 17개가 통과했다.

수정 본문은 같은 이름·설정 서명으로 재등록했다. 이전 본문과 실적은 등록 개정 원장에
보존됐다. 패키지 서브모듈은 핸들러 reload만으로 갱신되지 않으므로 관리 재시작 후 실제
검색 응답으로 적용을 확인했다. 보고서 작업은 재개하지 않았다.

## 범위와 남은 한계

중단 직전 바깥 AI가 검색을 수동 복구한 뒤 자막 단계에서 다른 제한에 걸렸다.
`BLeFFJCnL5s`의 자막이 단일 추출 50,000자 상한을 넘었다. 현재 상태의
last_failure는 transcripts다. 이번 검색 수리가 이 자막 제한을 해결한 것은 아니다.
후속 상세 추출·불확실한 신규성 재검토·내용 검토도 영상의 자막 전문을 단일 요청에 싣는다.
따라서 첫 추출의 숫자 상한만 늘리거나 앞부분만 자르는 수정으로는 이 문제를 해결할 수 없다.
전체 구간의 처리 증거를 보존하는 분할 추출과, 후보별 근거를 넘기는 후속 검토 계약을
함께 바꾸고 긴 실제 입력으로 검증해야 한다.
긴 자막을 임의로 잘라 품질 검사를 통과시키지 않았으며, 전체 보고서의 무인 완료나
시간·토큰 절감, 앞서 논의한 원자 팁·검색 기반 중복 판정 알고리즘의 구현을 주장하지 않는다.
운영 보고서·원장과 중단한 회차 상태는 재현 실험에서 수정하지 않았다.
