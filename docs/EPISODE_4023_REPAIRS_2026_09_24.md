# 에피소드 4023에서 드러난 실행 오류 수리

대상은 홈페이지 에이전트의 2026-09-24 후속 갱신 실행(4023)이다. 앞선 작업에서
등록한 관용구를 이 에피소드가 사용했다고 간주하지 않는다. 해당 실행은 옛 가이드를
읽은 대화를 재개했고, 새 관용구 호출·현재 가이드 재열람은 관측되지 않았다.

## 수정

- **배포 URL**: 개행 없는 stdout에 stderr의 `Vercel CLI …`가 붙던 결함을 제거했다.
  두 스트림을 독립적으로 읽고 stdout을 우선한다. ANSI 장식을 제거하고 배포 호스트
  경계를 검사한다. CLI가 성공했지만 주소가 없으면 `url:null`과 확인 필요 경고를
  반환한다. 주소를 얻으려고 배포를 재실행하지 않는다.
- **빌드 검사**: lint 실패를 한 줄로 축약해 버리고 전체 성공으로 반환하던 처리를
  고쳤다. 빌드 자체는 계속해 산출물을 확인하되 `build_success`와 `lint` 실행 결과를
  따로 반환하고, 선언된 lint가 실패하면 전체 `success:false`다. 린트 설정 누락도
  실패다. lint 스크립트 자체가 없으면 기존처럼 생략한다.
- **가이드 갱신**: 매 턴의 기존 가이드 목차, `read_guide` 결과, 의식이 선택해 전문을
  주입하는 경로에 `catalog_revision`을 붙인다. 파일명·내용의 SHA-256 지문 앞 16자리다.
  후속 대화의 옛 전문에 지문이 없거나 현재 목차와 다르면 필요한 가이드를 재열람하도록
  안내한다. 가이드 전문 캐시는 사용하지 않아 mtime을 보존한 교체도 새 본문을 전달한다.
  홈페이지 이름을 코어에 넣거나, 관용구를 자동 실행하거나, 추가 모델 호출을 만들지 않는다.
- **브라우저 요소**: 옛 ref의 요소를 유일하게 확인할 수 없으면 `REF_NOT_RESOLVED`와
  snapshot 복구 절차를 반환한다. 임의의 다른 요소를 누르지 않는 기존 계약은 유지한다.

`web_builder.md`, `browser_action.md`와 `engines:web`의 원본 계약·파생 카탈로그를
함께 갱신했다. `engines:web`를 쓰는 로컬 용례 23건을 검토했다. 기존 build→deploy
합성은 린트 실패 시 진행을 멈추는 것이 맞으며, 호출 인자 변경은 필요 없다.

## 검증 및 적용 범위

- 집중 회귀 79건 통과: 스트림 경계·ANSI·주소 미확인·비정상 호스트, 빌드/린트 결과
  네 조합, ref 복구, 같은 mtime으로 바뀐 가이드, 후속 목차/열람 지문의 일치를 포함한다.
- 실제 npm fixture에서 lint exit 2와 build 성공을 실행했다. 산출물 경로를 유지하며
  전체 실패·빌드 성공·린트 실패·구체적인 설정 오류를 함께 반환했다.
- 관리 재기동 뒤 라이브 `/ibl/read_guide`가 로컬과 같은 지문 및 네 홈페이지/웹앱
  관용구를 반환했다. 제어자 상태는 ACTIVE다. 공개 홈페이지를 재배포하지 않았다.
- 지문 계산 1회 로컬 관측은 약 2.9ms다. 목차 전체의 지문 하나를 쓰므로 어느 가이드든
  바뀌면 과거 전문을 재확인하는 보수적 방식이다. 파일별 버전 목록을 상시 주입하지 않는다.
  전체 작업의 시간·토큰 절감이나 다음 모델의 실제 관용구 채택률은 아직 측정하지 않았다.

전체 회귀는 5,853건을 실행해 5,852건 통과, 새 테스트 파일의 직접 실행 진입점 누락을
검사하는 `test_r2_direct_run_delegates_to_pytest` 1건이 실패했다. `__main__`에서 pytest로
위임하도록 수정한 뒤 관련 18건·파일 직접 실행 14건·전체 실패 목록 재검사(`--lf`) 1건이
모두 통과했다. 이후 전체 5,853건을 다시 실행한 것은 아니다. 서비스 코드 실패는 없었다.
어휘 빌드 `--check`, backend 층, 은퇴 계약, Android 몸 번들 `--check`도 통과했다.
실행 증거는 `data/_backups/2026-09-24_episode4023_repairs/`에 둔다.

## 별도로 남는 사항

- 홈페이지 소스는 정본 저장소 밖 `HomePages/indiebiz-homepage`에 있다. 해당 프로젝트의
  package.json에는 lint 스크립트만 있고 ESLint·Next ESLint 설정 의존성과 flat config가
  없다. 저장소 AGENTS.md의 작업 범위 제한 때문에 외부 폴더의 실제 수정은 사용자에게
  범위 확인을 요청했다. IndieBiz의 실패 보고 수리와 홈페이지 설정 수리는 서로 다르다.
- 경험 증류의 입력 예산 초과 생략은 비용 관문이다. 원문은 실행 원장에 남는다.
  성공 여부를 위조하거나 의미 증거를 임의로 자르는 방식으로 관문을 제거하지 않았다.
