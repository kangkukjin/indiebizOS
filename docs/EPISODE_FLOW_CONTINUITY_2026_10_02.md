# 실행·검수 구간과 전체 수리 과제의 수명 분리

코딩 앱 구현 에피소드의 흐름에서 드러난 공통 문제를 고친다. 앱 구현 자체는 이 변경의 대상이 아니다.
이전 `749efb93`의 적용·평가 재개는 남은 개발의 지속성과 임시 이미지 증거의 수명을 충분히 보존하지 못했다.

## 계약

- 완료 대기와 재기동이 `common/completion_contract.process_birth_time`의 같은 프로세스 신원을 사용한다. macOS 시계 보정에도 출생 신원은 유지하며 PID 재사용과 명시 취소는 여전히 거절한다. 당시 사건이 실제 OS 시계 보정 때문이었다는 단정은 하지 않는다.
- 승인된 사용자 자기수리에서 검수의 research 보완은 `waiting_execution`으로 인계한다. 국소 응답 보완은 여전히 턴당 한 번이며, 그 뒤 미달 기준이 남아도 같은 전체 목표의 실행으로 돌아간다. 적용 대기·검수 대기·개발 대기를 구별한다.
- 원래 criteria 계약, 기준별 unmet/unverified 상태, 진행 파일의 지문, 기존 증거·격리본 위치를 보존한다. 평가자가 언급하지 않은 기준은 면제하거나 완료로 추정하지 않는다. 전체 승인이 있을 때만 모든 기준을 met로 기록한다.
- 다음 실행은 같은 사용자 승인·행위자·목표를 검증하고 기존 의식 규정을 계승한다. 재연상·재분류·재규정과 전체 조사를 반복하지 않는다. 기존 staging 소유권은 한 번만 이전하며 이미 적용·폐기한 세션을 미적용 파일로 되살리지 않는다.
- 같은 미달 기준과 구현·산출물 상태가 연속 세 번이면 blocked로 보존한다. 보고 문구·타임스탬프·로그 양 증가는 진전으로 세지 않는다. 진전이 있으면 임의의 전체 개발 횟수 제한으로 끊지 않는다. 사용자 취소는 모든 대기 상태에 우선한다.
- 이미지 검수는 평가 역할의 모델이 이미지를 지원하면 그대로 사용하고, 준비된 비전 슬롯으로만 대체한다. 초기화 실패 객체는 캐시하거나 호출하지 않는다. 지원하는 경로가 없으면 이미지 없는 텍스트 승인으로 우회하지 않고 평가 대기로 남긴다.
- 시각 관측은 packet의 원본 바이트와 지문을 검증한다. pytest 임시 파일이 없어져도 관측은 유효하다. 이전 체크포인트도 저장된 바이트가 지문과 일치하면 복원한다. 구현 파일과 실제 전달 초안은 계속 현재 상태와 비교하므로 관측 복원으로 코드 변경을 승인할 수 없다.
- 시험 스크립트는 실패의 앞·뒤 진단을 즉시 반환하고 마스킹된 전체 출력을 `data/spill/test_outputs`에 보존한다. 시한 초과도 부분 출력을 남긴다.

## 범위와 검증

새 코드로 생성하는 대기에 적용한다. 과거 blocked 에피소드를 소급 실행하지 않는다.
실제 모델에 코딩 앱을 다시 맡겨 소요 시간이나 토큰 감소를 측정한 변경은 아니다.
회귀는 시계 보정/취소, 여러 개발 구간의 전체 기준 보존과 완료, 무진전 차단/진전 시 지속,
임시 이미지 소멸과 증거 변조, 구현 파일 변경 거절, 준비되지 않은 평가 경로, 시험 실패 출력 회수를 확인한다.

검증 결과: 최종 관련 회귀 361개 통과, 실제 재기동·장애 복구 23개 통과.
종합 회귀는 8,351개 통과·4개 실패·1개 건너뜀·100개 system 제외였다.
이번 계약 변경에 따른 모의 provider 준비 상태와 이미지 평가 경로 검사 2개는 갱신 후
위 361개 묶음에서 통과했다. 기존 render_core의 script 개수 기대 검사 2개는 남아 있다.
완료 요청 계승 등 마지막 보강은 관련 묶음으로 재확인했으며 종합 전체를 반복하지 않았다.
층 경계와 Android 몸 번들 파생 검사도 통과했다.
