# 조종실 주행기록 빈 목록 수리

2026-09-21 13:19 에피소드 3947의 `supervision.decision`이 직렬화 후
4096자에서 잘려 유효하지 않은 JSON으로 저장됐다. 주행기록의 IBL 횟수 집계는
다른 종류의 사건에도 `json_extract`를 평가했고, `malformed JSON` 오류를
빈 목록으로 바꿨다. 확인 당시 원본 주행 1,304건은 보존돼 있었다.

- 사건 저장은 JSON 값의 구조를 보존해 마스킹하고 직렬화한다. 긴 내용은 작은 필드를
  보존하며 큰 필드를 생략하고, 생략 여부·원래 길이·지문·생략 필드 수를 남긴다.
  기존 4096자 제한을 유지한다. `store`·`seq`로 감독 원문 기록에 다시 연결된다.
- IBL 집계는 관련 종류의 유효한 JSON만 읽는다. 라운드 집계도 파손되거나
  객체가 아닌 사건을 건너뛴다. 기존 사건 원문은 변경하지 않는다.
- DB 조회 실패는 API 오류로 전달한다. 데스크탑은 첫 조회 실패 시 재연결 문구를
  표시한다. 조회 실패를 기록 부재로 보고하지 않는다.

검증: `test_episode_journal_json.py`의 과거 파손 사건·긴 문자열·이스케이프·DB 오류
회귀와 기존 Codex 주행/출처/궤적 테스트 27개 통과. 프런트엔드 TypeScript 검사 통과.
실제 API에서 최근 20건과 에피소드 3947의 반환을 확인했다.

## 발생 원인과 재발 방지

직렬화 뒤 문자열 절단은 궤적 원장 도입 커밋 `6a1078189`부터 있었다.
작성 시점에는 작은 메타데이터만 전달할 것으로 기대했지만, 감독의 결정·응답 명세도
같은 경로로 들어오면서 상한을 넘었다. 9월 11일·15일의 기존 손상도 남아 있었다.
DB의 TEXT 칸에는 JSON 검증이 없었고, 조회 예외를 빈 목록으로 숨겨 결함이 드러나지 않았다.
기존 궤적 시험은 실행 신원·순번·원문 비복제를 검증했지만 크기 경계의 저장→조회는 없었다.

첫 수리 `a2703206`은 문법을 보존하는 미리보기 봉투와 조회 오류 전파를 넣었다.
후속 보강은 큰 사건에서도 원문 연결·계수 필드를 보존하도록 저장기를 분리했다.
문자열 마스킹이 JSON 문법을 바꿀 가능성도 없애고, 비유한 숫자 등 잘못된 입력은
저장 실패 경고를 남긴다. 실행 본체는 계속 진행한다.

`trajectory_payload.ensure_payload_guards`가 신규 INSERT와 data UPDATE에 JSON 객체를
강제한다. `world_pulse` 스키마 v2와 독립 에피소드 초기화가 같은 정의를 사용하므로
저장 함수를 우회한 SQL도 손상된 JSON을 넣지 못한다. 과거 손상 행은 수정·삭제하지 않는다.
조회에서는 기존 파손분을 격리하고, DB 장애는 HTTP 오류로 전달한다.
