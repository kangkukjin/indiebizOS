# 의식 없는 실행·반사의 평가 생략

2026-09-12 사용자 판정: 의식 에이전트가 작동하지 않는 실행·반사 경로에는 평가도 없어야 한다.

실행 중 도구 실패·쓰기·미분류 호출이 `Supervisor.enabled`를 켜고, 긴 작업의 watcher·알림·스크립트 공개·과제 완료 요청도 같은 승격을 만들고 있었다. 파이프라인은 이 상태만 보고 최종 평가를 호출했으며, 감독이 없는 경우에는 EXECUTE의 SelfReflect가 별도로 남아 있었다.

## 적용한 경계

| 경로 | 감독·평가 |
|---|---|
| 의식 없는 EXECUTE, Reflex, 사실 통보 | 중간 감독·최종 평가·SelfReflect 모두 생략 |
| 의식의 규정이 있는 THINK/REPAIR | 기존 검수·보완 유지 |
| 감독 객체 없는 호환 경로 | 의식의 규정이 있는 턴만 GoalEval/SelfReflect 허용 |

분류 결과 이름만으로 판단하지 않고 실제 의식 규정의 존재와 반사/강제 역할 여부를 실행 전에 확정한다. 오류·쓰기·반복·지연이 이 선택을 바꾸지 않는다. `configure`가 규정 없는 턴의 활성 상태를 해제하며, `review`·`finalize`도 비활성 호출을 차단한다. 계측 객체와 도구 기록은 남지만 이 객체의 존재가 AI 감독 호출을 뜻하지 않는다. 규정 없는 사건은 harness 역할로 기록한다.

평가 없는 경로의 알림은 직접 전달하고 등록 스크립트에는 검수 작업대를 전달하지 않는다. `pursuit done`은 기존 실행자 원장 경로로 완료하며 승인 대기로 남기거나 평가자를 깨우지 않는다. 의식이 작동한 경로의 비공개 산출물·알림 승인 계약은 유지한다.

평가 미실행은 `cognition.evaluation.path=none`이며 최종 판정은 NULL이다. 성공 승인이나 검수 실패를 만들어 기록하지 않는다. [최종 응답 후 기억 선별](MEMORY_FINAL_RETENTION_2026_09_12.md)은 그대로 사용하며 정상적인 평가 생략을 기억 저장 실패로 보지 않는다. 명시적인 `#think`·REPAIR 등 의식이 실제 작동하는 기존 진입 규칙은 바꾸지 않았다.

데스크탑·원격 조종실 안내와 anatomy/architecture/memory 정본 문서를 맞췄다. IBL 문법이나 낱말은 추가하지 않았다.

## 검증

실제 파이프라인을 THINK/EXECUTE/Reflex/규정 없음/사실 통보 × 읽기/쓰기/실패/미분류 × 감독 객체 유무로 실행하여 평가 호출 여부와 최종 응답을 검사한다. 의식 없는 반복 실패·정체·이정표의 감독 호출 금지, 직접 알림, 평가 없이 과제 완료, 전경·백그라운드 스크립트의 작업대 전달 여부도 검사한다. 외부 AI 모델 호출과 실제 사용자 자료 쓰기는 대역으로 대체한다.

별도 확인: TypeScript 검사, 프런트엔드 빌드, Android 몸 번들 재생성, 실행 중 백엔드 코드 지문 일치와 ACTIVE/ready 상태.
