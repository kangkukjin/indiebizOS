# 평가자의 기준 소유권 복원 — 2026-09-12

사용자 지시: 의식은 문제·목표를 규정하고 평가는 그 달성 여부를 판별한다. 평가가 일반적인 흠 찾기로 일을 늘려서는 안 된다. 의식 없는 실행·반사는 평가하지 않는 앞선 경로 수리를 유지한다.

## 확인한 원인

기준 자체가 전혀 없었던 것은 아니다. `final_evaluator.prepare`는 의식의 criteria/achievement_criteria를 전달했다. 그러나 공통 평가 프롬프트는 목표 충족과 별개로 도구 적절성, framing의 노력선, 추가로 할 수 있었던 작업, 시각 품질을 심사하게 했다. 평가 입력도 추천 도구·접근 방향과 시스템 구조 문서를 반복 주입했다. 의식이 기준을 비워도 감독 최종평가가 실행되며, 감독 없는 경로는 자기반성으로 우회할 수 있었다. 합격 후 하네스가 시간 합산 불일치를 이유로 REWORK를 새로 만드는 독립 경로도 있었다.

이것은 과거 에피소드에 평가가 늘 불필요했다는 통계적 단정이 아니다. 코드와 프롬프트가 허용한 역할 범위가 사용자의 원칙보다 넓었다는 확인이다. 이미 끝난 에피소드·평가 기록은 고치지 않았다.

## 변경

- 의식 프롬프트가 완료 판정에 필요한 품질·증거·허용 대안·멈춤선을 명시적 달성 기준에 담도록 한다. 추천 수단과 잠정 조사량을 나중에 합격 조건으로 승격하지 않는다.
- 공통 평가 프롬프트를 기준 판정으로 줄인다. 의식의 추천 도구·규정 산문·시스템 구조는 별도 심사 근거로 주입하지 않는다. 사용자 원문과 관련 대화는 기준 해석용 맥락이다.
- `criteria_contract`는 의식이 정한 항목에 ID를 부여한다. 사용자 직접 인용 여부를 구분하되, 인용이 없는 의식 기준도 단순 제안으로 격하하지 않는다. 하네스가 임의의 fallback을 생성하지 않는다.
- NOT_ACHIEVED는 기존 기준 ID·미달 증거·최소 보완을 담은 DEFECTS를 요구한다. 빈 지적·알 수 없는 기준·근거 누락은 UNKNOWN으로 남겨 자동 보완을 막는다. 자유 산문의 추가 요구를 실행자에게 넘기지 않는다. 연결 형식은 코드가 검증하며, 지적이 의미상 기준에 해당하는지의 판정은 기존 평가 모델의 책임이다.
- 최종평가 시작 시 기준을 고정해 보완과 재평가에도 같은 계약을 전달한다. 명시적 과제 완료 요청은 기존 과제 기준도 함께 고정한다. 실행 중 의식의 정상 재규정은 최종평가 시작 전까지 반영한다.
- 의식이 있어도 달성 기준이 없으면 최종평가와 자기반성 호출이 없다. 알림·스크립트 출력·과제 완료도 검수 대기 상태로 남기지 않는다. 실행 중 기준이 제거되면 이미 대기 중인 전달도 처리한다.
- 시간 합산 관측은 평가 자료로 유지하지만 합격 후 하네스가 별도 사유로 재작업시키지 않는다. 응답·파일·공개 대상 지문과 취소·전달 성공 검사는 승인 대상의 동일성을 보장하는 기존 실행 계약으로 유지한다.

새 에이전트나 모델 호출은 추가하지 않았다. 공통 평가 프롬프트 본문은 5,905자에서 1,722자로 70.8% 감소했다(파일 문자 수 기준, 전체 호출 토큰·시간·코인 절감률은 아님). 산술·출처·이미지 품질은 의식이 정한 목표를 실제로 막는 경우에 해당 기준의 증거로 판정한다. 평가 기준이 잘못되었거나 부족하면 의식이 실행 전·중간 감독에서 고쳐야 한다.

## 검증

- 전체 backend 회귀: 4,012 passed, 1 skipped (249.53초). 기존 테스트의 평가자 독립 수리 심사 기대를 새 역할 계약으로 갱신했다.
- 마지막 과제 기준 정정 처리까지 포함한 집중 회귀: 42 passed. 이전 과제 기준을 새 기준과 함께 의무로 부과하지 않는지 확인했다.
- THINK/EXECUTE/Reflex/의식 없음/기준 없음/문맥 갱신 × 읽기/쓰기/실패/분류 불가 × 감독 유무, 48개 실제 파이프라인 조합을 검증했다.
- 기준 밖·근거 없는 지적은 한 번의 평가 뒤 UNKNOWN으로 끝나며 보완 호출이 없다. 유효한 지적은 보완 후 갱신된 증거로 한 번 재평가한다. 자유 산문 추가 요구 제거, 기준 고정, 기준 없는 알림·스크립트·과제 완료 전달을 검증했다.
- Android 몸 번들 재생성, IBL 파생물 신선도, 의식 출력 스키마, backend 층 검사, 은퇴 계약 검사 통과.
- 실제 외부 모델 호출·알림 없이 호출 경계와 보완·전달 경로를 시험했다. 수정 후 실제 작업 에피소드의 품질·시간·코인 변화는 아직 측정하지 않았다.
- 실행 백엔드 ACTIVE/ready, 활성 사용자 작업·자식 작업·후처리 0, 라이브 코드 지문과 수정 코드 일치 확인.
