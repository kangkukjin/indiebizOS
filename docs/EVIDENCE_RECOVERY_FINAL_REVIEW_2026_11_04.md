# 원문 회수와 실패 후속 실행의 책임 정리

## 문제와 재현

에피소드 5812는 원문을 저장했지만 최종 검수가 요청한 범위를 회수하지 못했다.
저장소 `c61a0d9bc98041998187cc216f704a82`의 증거
`5bc51d258d3873c272ae870c39367a4fc335b10a105c349b713ba853f775aaf7`는
인증서와 일치하는 1,277자 원문이다. CRLF 세 개가 `Path.read_text()`의
보편 줄바꿈 처리로 LF가 되어 1,274자로 읽혔다. 그 결과 인증과 `[0, 1277)`
범위 검사가 모두 실패했다. 저장된 원문이 잘못되거나 없어졌던 것이 아니다.

같은 실행에는 이후 보완된 검사 실패, 비 Git 폴더에서의 git 명령 실패,
진단 검사 실패, 순차 실행으로 재시도한 병렬 자원 충돌도 남아 있었다.
기존 경로는 이 실패 이력이 남아 있으면 최종 검수 전에 실행자를 한 번 더 열었다.
실패 사실의 보존과 현재 업무의 추가 실행 필요성을 같은 조건으로 사용한 것이다.

## 수정한 책임

- `supervision_store`는 인증서와 본문을 줄바꿈 변환 없이 읽고 원문 그대로 쓴다.
  현재 턴, 동일 대화의 이전 턴, 마스킹 경로 조회, 실행 기록 조회가 같은 문자 좌표를 쓴다.
  증거 ID·인증서·본문 일치, 판본, 범위 검사를 완화하거나 끝 좌표를 잘라 맞추지 않는다.
- 실행 파이프라인이 최종 검수를 예정했고 감독·완료 기준도 유효하면,
  과거 실패에 대한 의미 판단을 그 검수가 맡는다. 별도 사전 판정 모델을 추가하지 않는다.
  기존 실패 후속 실행은 이 경우 `final_review_owned`로 기록하고 실행 예산을 소비하지 않는다.
- 최종 검수 입력에 기존 복구 원장의 실패 관측을 전달한다. 같은 대상·조건의 후속 근거,
  현재 완료 기준과의 관련성을 대조한다. 실제 결함은 기존 REWORK 보완으로,
  증거 부족은 기존 UNKNOWN/원문 회수로 보낸다. 승인만으로 실패를 지우거나
  관측 성공 영수증을 만들지 않는다.
- 검수 미예정·감독 비활성·완료 기준 없음·코드 수리 영수증 종료 경로는 기존 후속 실행을 유지한다.
  취소·예산·적용 인계 경계와 무관한 성공이 실패를 지우지 못하는 계약도 유지한다.

## 검증

보존된 위 증거를 읽기 전용으로 재검사했다. 변경 후 `integrity=verified`,
`chars=1277`, 회수 길이 1,277자이며 원문 바이트를 UTF-8로 해독한 문자열과
정확히 일치한다. 과거 에피소드·평가 판정·증거 파일은 수정하지 않았다.

보존된 평가 패킷의 최초 58개 호출도 새 후속 실행 경계에 읽기 전용으로 재생했다.
실패 관측 4개를 그대로 유지하면서 `final_review_owned`를 기록하고 기존 응답을
반환했으며 실행자 호출은 없었다. 이 재생은 최종 모델의 판정까지 다시 수행한 것은 아니다.

자동 회귀는 모듈별 시험에 추가했다.

- `test_supervision_store`: CRLF·CR·LF 혼합, Unicode 좌표, 이전 턴·기록 조회,
  줄바꿈만 변조해도 인증 실패.
- `test_evaluation_input`: 원문 범위 전체를 회수해 재평가하며 실행자를 열지 않음.
  기존 변조·판본·범위·마스킹·입력 예산 검사는 그대로 유지.
- `test_task_continuation`: 최종 검수 소유권, 기준/검수가 없는 경로의 복구,
  실제 실행 파이프라인에서 한 실행·한 검수·한 최종 응답.
- `test_final_evaluator`: 해결됨/무관한 성공만 있음/근거 부족을 나누어
  추가 실행 0회/필요한 보완 1회/미확정 보존을 검사. 실패 관측은 보존.

시험의 평가 모델은 통제된 응답이다. 이는 경계·전달·실행 횟수의 검증이며,
실제 모델이 모든 과제에서 해소 여부를 정확히 판단한다는 실험은 아니다.
원래 심층연구 전체를 재실행하거나 과거 UNKNOWN을 ACHIEVED로 바꾸지 않았다.

## 구조적 판단

이번 두 결함은 검증이 엄격해서 생긴 것이 아니라, 저장과 읽기가 다른 원문을
사용하고 실패 관측과 목표 판단의 책임이 겹쳐서 생겼다. 새 예외나 승인 조건을
늘리는 대신 원문 좌표는 저장소, 최종 의미 판단은 예정된 검수로 모았다.
이를 시스템 전체가 불필요하게 복잡하다는 증명으로 일반화할 수는 없지만,
경계마다 자료를 재해석하고 같은 판단을 중복 소유하는 구조가 변경에 취약하다는
구체적 사례다. 최종 검수 없는 경로의 일반적인 의미 해소까지 새로 자동화하지 않는다.
