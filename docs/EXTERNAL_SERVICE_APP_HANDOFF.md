## 0. 한 문장

**주인은 하네스를 발행하고, 회원은 그 하네스를 자기 하드웨어 위에서 쓴다.**
가족·사무실에서 한 사람만 indiebizOS 를 설치·관리하고, 나머지는 PC·폰에 얇은 앱 하나를 깔아
클로드 코드를 쓰듯 AI 에이전트를 부린다. 회원의 파일은 회원 PC 에서 처리되고 회원 PC 에 저장되며,
음악은 회원 기기에서 난다. 회원은 하네스를 바꿀 수 없고, 회원의 기억은 회원 하드웨어에만 쌓인다.

**첫 성공 기준(이 한 흐름이 통과하면 가장 어려운 부분을 지난 것)**:
> 회원 A 가 자기 PC 의 파일을 정리하고 다음 대화에서 그 일을 기억하되, **주인과 회원 B 에게는 그 내용이
> 전혀 나타나지 않는다** — 동시 대화 중에도.

## 1. 목적

1. **커뮤니티당 노드 하나**의 완성. 2026-07 공개 표면 가족(포털·창고·게시판)은 *브라우저로 보는* 참여였다.
   이 앱은 *일을 시키는* 참여다 — 설치 없이 능력을 빌리던 회원이 자기 하드웨어를 몸으로 내놓는다.
2. **AX 사다리의 첫 단**(08-21 판정 "조직-몸 AX 는 실패, 몸통은 개개인이 자기 몸을 익힘"과의 정합).
   회원은 시작 문장을 익히고 자기 손발과 자기 기억·얼린 문장을 갖는다. **졸업 경로는 열린 관찰이 아니라
   최소 완료 조건이다**: 회원 기억·스크립트 내보내기 + 독립 설치본 가져오기(§3-7). 없으면 팔란티어형
   "사다리 없는 앱"이고 이 목적은 실패다.
3. **주인 = 하네스 발행자**. 클로드 코드에서 Anthropic 이 모델·하네스를 쥐고 사용자가 기계를 대는 관계의
   자리를 indiebizOS 주인이 맡는다. 경영자 몸은 조종이 아니라 발행(공통 팔·시작 문장·창고 규약).

## 2. 확정 설계 (대화에서 합의된 것 — 바꾸지 말 것)

### 2-1. 회원에게 없는 것 셋 / 있는 것 셋

| 없다 | 있다 |
|---|---|
| **하네스 편집권** — 어휘 추가·패키지·설정·프로젝트·스케줄·시스템 수정 | 주인이 활성으로 발행한 어휘의 **사용** |
| **주인의 데이터** — 기억·해마 용례·프로젝트 폴더·이웃 명부·창고 비공개층·**내부 운영 문서** | **자기 하드웨어** — 파일·소리·화면·센서가 자기 기기에서 |
| **어휘의 전부** — 회원 프로파일에서 잠든 낱말은 존재하지 않는다(09-13 "잠든 어휘는 학습하지 않는다") | **자기 층** — 자기 기억·자기 얼린 문장(회원 기기에서 실행) |

### 2-2. 기억의 분리 — 7종 대응표

| 기억(memory.md #) | 어디에 | 비고 |
|---|---|---|
| #2 작업 기억(대화 이력) | 회원 하드웨어 | 허브는 턴 스코프 임시 상태만(§3-6). 허브 conversations DB 에 0행 |
| #5 관계 기억(심층메모리) | 회원 하드웨어 | 허브에 절대 남기지 않음 |
| #7 포식 기억(냄새지도) | 회원 하드웨어 | 그 사람 디스크의 지도 |
| #3 일화 기억(에피소드) | 회원 하드웨어 | 허브 `episode_log` 에 0행 — §6 누출 관문 |
| #4 해마 **용례**(문장→코드 쌍) | 회원 하드웨어 | 문장·슬롯 값에 개인정보가 실린다 |
| #4 해마 **통계**(골격·성공/실패·오류부류·지연) | 허브 | 사용자 지시 "실행기억은 남길 수 있다"의 정확한 범위. **골격 치환기 전에는 기록 자체를 끈다** |
| #6 자기 상태(action_health) | 허브 | 골격 단위 카운트 |
| #1 의미 기억(문서·어휘) | 허브 | 회원은 **발행분만** 읽음 — 활성 패키지 가이드·시작 문장. `system_docs/`·시스템 메모·주인 프로젝트 문서는 회원 프롬프트 밖 |

**골격 규칙**: 허브에 올라가는 실행기억은 IBL 코드의 슬롯 값을 자리표로 치환한 골격 + 결과 메타뿐이다.
문장 원문·값이 붙은 쌍은 회원 하드웨어의 해마에 남는다. 가이드 원칙 "완성 문장 금지·자리표 골격"과 같은
모양이므로 새 규칙이 아니다.

**읽기 방향도 분리한다(2차 개정)**: 회원 응답에 주인의 기억이 섞이는 것은 저장 누출과 **별개의 축**이다.
해마 회상·심층메모리·포식·문서 공급원 전부가 행위자(주인/회원 A/회원 B) 축을 갖고, 회원 세션은 자기 것과
주인의 발행분만 읽는다(§4 선행 수리·§6 시험).

**전송 층은 분리하지 않는다(정직하게 고지)**: 회원 데이터는 턴 동안 허브 프로세스를 지나고 주인의 API 키로
모델 제공자에게 간다. 분리는 *저장 층*의 보장이다. 고지문은 코드가 아니라 데이터(앱 첫 화면 텍스트, 주인이
고침 — 가족/사무실이 다르다).

### 2-3. 착지 = 회원의 몸

"결과는 어느 표면이 물었나로 착지한다"(remote_access.md)의 확장. 회원 세션은 **몸 = 회원의 손발**로
바인딩되고, 하드웨어에 닿는 액션(파일 읽기·쓰기·목록·찾기, 재생, 열기, 화면, 기억 저장·회상)은 그 손발에서
돈다. 순수 연산(sense 조회·table 변환·engines 생성의 연산부)은 허브에서 돌고 산출물은 손발로 떨어진다.
**손발 미연결이면 정직 거절** — 회원의 파일을 허브에 대신 저장하는 폴백 금지.

## 3. 구조

### 3-0. 새 물건은 테넌트 경계다 (2차 개정)

부품은 기존 것이 맞다(§3-1 표). 그러나 "합성"이라는 말이 실제 변화를 가렸다 — **단일 주인용 실행기에 여러
사람의 세션을 넣는 일**이다. 현재 시스템 AI 는 싱글턴이다: `SystemAIRunner._instance` + 클래스 변수 메시지
큐 `internal_messages` + 인스턴스 하나의 `cancel_event`(`system_ai_runner.py`), `get_system_ai_runner()` 전역
싱글턴(`system_ai_core.py`), 초기화 때 주인 프로필을 읽는다. 여기에 `profile=member` 깃발을 꽂으면 회원 A 의
취소가 주인 턴을 끊고, 회원 B 의 메시지가 주인 큐에 섞인다.

**답은 몸에 이미 있는 모양이다**: 프로젝트 에이전트는 각자 `AgentRunner` 인스턴스로 같은 인지 파이프라인
(무의식→의식→실행→평가)을 탄다. 회원 세션은 시스템 AI 의 변종이 아니라 **프로젝트 에이전트 모양의 세션 러너**다.

**회원 세션 계약(구현 전에 고정)** — 러너 인스턴스마다 분리되는 것:

| 분리 대상 | 회원 세션에서 | 공유 금지 대상(주인 객체) |
|---|---|---|
| 실행 상태 | 세션별 러너 인스턴스·메시지 큐·`cancel_event`·진행 티켓 | `SystemAIRunner._instance`·`internal_messages` |
| 프롬프트 | 회원 프로파일로 조립(활성 사전 member 축·발행 가이드·회원 시작 문장·고지) | 주인 프롬프트 캐시·시스템 메모·`system_docs` |
| 기억 공급원 | 손발 `memory_recall`(회원 로컬) + 행위자 축 회상(§4) | 주인 해마 용례·심층메모리·포식 지도 |
| 취소·수명 | 세션 단위. 회원 앱 연결 끊김 = 세션 정지(진행 중 봉투는 §3-8 멱등 규약으로 마무리) | 주인 활성 작업 표식(`thread_context._touch_active_work`) |
| 행위자 봉투 | `agent=member:<id>`·`origin=member`·`task_member_*` | `system_ai`·`origin=user` |
| 임시 파일 | 턴 스코프 디렉토리(§3-6) | `outputs/`·프로젝트 폴더 |
| 비용·한도 | 세션·턴 예산, 회원 동시 실행 상한(§3-8) | 주인 비용 원장(집계만 `member:*` 로 분리) |

공통 인지 코드(의식·실행자·평가자·IBL 엔진)는 재사용한다. 실행 중인 주인용 객체를 회원과 공유하지 않는다.

### 3-3. 신원 — 열쇠 한 장

- **발급 = 주인의 행위 하나**: `[self:limb]{op:issue}` 가 만드는 limb key(`limb_keys.mint`)에 **이웃 id 를 결합**한다.
  회원 = 이웃 CRM(business.db)의 한 사람, 레벨 = 이웃 등급(0~4, 숫자만). `body_trust.grant_body` 가 이미
  device_id→레벨을 갖고 있으므로, 회원 열쇠 발급 = `mint` + `grant_body(device_id, name, level)` 한 묶음.
- 앱이 지니는 것은 **limb key 하나**. 허브 비밀번호·런처 세션 없음(USB 손발 선례 그대로). 유출 = 그 키만 폐기.
- 인증 경로: `is_public_remote_path` 의 `/limb/*` 자체 인증을 재사용. 회원 채팅 WS 도 limb key 로 인증(런처
  세션 아님 — 런처 세션은 소유자 표면이다).
- **특권 배관 아님**: 손발은 주권 몸이 아니라 회원 세션의 손이다(엔진 없음, 자기 사전 없음). no-privileged-rails 의
  "엔진 자동위임 매장"과 충돌하지 않는다 — 두 주권 몸 사이의 빌림이 아니라 한 세션이 자기 몸에 손을 뻗는 것이다.
  회원이 *자기 indiebizOS* 를 갖게 되는 날(졸업) 그 관계는 이웃 문법(`[others:ask]`)으로 바뀐다.

**행위자 봉투 — 회원 세션의 세 칸**

| 칸 | 값 | 효과 |
|---|---|---|
| `agent` | `member:<이웃id>` | 채널·게이트·**회상**·기록자 판정 축. 주인 표면의 `system_ai` 와 구별 |
| `task` | 러너가 `task_member_*` 발급 | write_ledger→episode→tasks 조인 유지(단, 저장은 §6 관문 뒤·원문 없음) |
| `origin` | **`member`**(신설) | `origin=='user'` 만 자기수정 그랜트(`thread_context` 276행·`agent_pipeline` 447행)를 받으므로 회원은 fail-closed 로 자동 차단. `portal` 과 구별하는 이유: portal 은 무몸(브라우저), member 는 몸(손발) 바인딩 |

### 3-4. 어휘의 부재와 실행 권한 — 각각 집행한다 (2차 개정)

**두 층이다. 하나로 접지 말 것.**

| 층 | 무엇 | 어디서 | 성격 |
|---|---|---|---|
| **부재**(학습 정책) | 회원 프로파일에서 잠든 낱말은 프롬프트·카탈로그·회상에 없다 | `activation.json` 의 프로파일 축 owner/member, `set_package_active(..., profile=)`(`HUMAN_AUTHORITY` 필수), `vocabulary_state.revision` 재조립 | 우회 유도가 없게 하는 정책. **집행이 아니다** |
| **권한**(집행) | 실행 직전, 이 행위자가 이 액션을 이 자원 범위에서 이 몸에서 돌릴 수 있는가 | 엔진 chokepoint(`_resolve_and_maybe_forward` 앞) 한 자리. 사용자가 직접 친 IBL·저장한 문장·`[table:each]`/`>>` 중첩·`fn:` 전개·`[self:script]` 안의 문장 **전부** 같은 관문을 지난다 | fail-closed |

**권한 관문의 판정 축은 선언이다(이름 아님)**:
- 부작용 축 = **`side_effect`**(op 단위 `ops.side_effect` 포함). `returns` 는 반환 형태 축이라 부작용 판정에 쓰지
  않는다 — `[self:script]` 가 `returns: items` 이면서 `side_effect: true` 인 것이 반례(system_essentials).
- 실행 위치·자원 축 = **`lands_on`**(신설: `hub` | `body`). 회원 세션에서 **선언이 없는 액션은 거절**한다 —
  "허브 로컬 실행" 기본값은 1차 문서의 오류였고, 몸의 다른 게이트가 전부 fail-closed 인데 여기만 열려 있었다.
  `hub` 는 순수 연산(sense 조회·table·engines 연산부)에 주인이 명시적으로 준 표식이다.
- 하드 거부(프로파일 밖, 데이터가 아니라 헌법): `others` 노드 전부(회원이 주인 이름으로 남에게 부탁·발신·발행
  금지), `self` 의 하네스 편집 부류(package·install_lib·limb·manage_events·webapp·주인 스코프 script/ledger/memory
  쓰기), `limbs` 의 주인 기계 부류(os_open·open_window·screen·guestpc·android). 이들은 `lands_on` 선언을 받지
  않으므로 관문이 자동으로 거절한다(★이름으로 넘겨짚지 말 것 — 포털 핸드오프의 CCTV 오분류 교훈).
- `build_ibl_nodes.py --check`: `lands_on: body` 인데 `limb_op` 없음 → 실패. `side_effect: true` 인데 `lands_on`
  없는 액션이 회원 허용 패키지에 있음 → 실패(회원에게 켜기 전에 선언을 강제).

### 3-5. 실행 프로파일 `member` — 엔진 chokepoint 의 세 번째 갈래

- 자리: `ibl_engine._resolve_and_maybe_forward` (현재 `profile == "phone"` / 데스크탑 두 갈래). 회원 세션(`origin==member`
  이고 `thread_context` 에 바인딩 device_id)이면 §3-4 권한 관문 뒤 세 번째 갈래:
  - `lands_on: body` → 손발 봉투로 번역해 `phone_jobs.enqueue(device_id, envelope)` → `wait_result`.
  - `lands_on: hub` → 허브 로컬, 파일 입출력은 턴 스코프 디렉토리(§3-6) 안에서만.
  - 그 외 → 거절.
- **번역표는 데이터**: 어휘 소스 yaml 에 `limb_op:` 매핑(예 `self:read`→`{op:"read", path:$path}`,
  `limbs:music{op:play}`→`{op:"play", ...}`, `self:memory`→`{op:"memory_save"|"memory_recall"}`). 엔진 코드에
  액션 이름을 박지 않는다(헌법 "몸의 명사=코드, 세계의 명사=데이터").

### 3-6. 허브 연산과 "허브 디스크 0" 사이의 계약 (2차 개정)

"턴 동안 RAM 만"은 지킬 수 없는 약속이었다 — 문서·이미지·표 생성 엔진은 파일을 쓴다. 계약:

- **턴 스코프 격리 임시 디렉토리**: 회원 턴마다 `data/_member_tmp/<session>/<turn>/` 하나. 회원 세션에서 허브
  로컬 액션이 읽고 쓰는 유일한 경로. 프로젝트 폴더·`outputs/`·주인 디스크의 다른 어디에도 쓰지 않는다(경로 이탈=거절).
- **입력 전달**: `lands_on: hub` 액션이 회원 파일을 받아야 하면 손발 `read` 봉투로 가져와 턴 디렉토리에 놓고,
  그 경로를 턴 네임스페이스 안에서만 해소한다(`$file:` 참조도 여기서만).
- **후속 참조**: 파이프(`>>`)·`[table:each]` 의 중간 산출물·경로 참조는 전부 턴 디렉토리 안. 턴 밖 경로가
  통화에 실려 나가면 관문이 거절한다.
- **착지**: 최종 산출물은 턴 종료 전에 손발 `write` 봉투로 회원 기기에(단순 `output_path` 이동이 아니라 통화
  안의 모든 파일 참조를 훑어 옮기고 참조를 회원 경로로 치환).
- **삭제**: 턴 종료(성공·실패·취소·연결 끊김) 시 디렉토리 통째 삭제. 세션 종료·부팅 시 고아 디렉토리 청소.
- **시험**: 턴 뒤 `data/_member_tmp/` 0항목, 주인 디스크 전체에서 표식 파일 grep 0(§6).
- 2-2 표의 "허브는 턴 스코프 임시 상태만"이 이 계약을 가리킨다.

### 3-7. 회원의 얼린 문장과 졸업 (2차 개정)

- **두 종류를 가른다**. 현재 `[self:script]` 는 Python·Bash 등록 프로그램 실행기다. "실행 시 허브에 동봉"은 회원
  코드를 허브에서 돌린다는 뜻이 되어 하네스 불가침과 충돌한다 — 1차 문서의 오류.

| 종류 | 저장 | 실행 | 검사 |
|---|---|---|---|
| **회원 프로그램**(Python·Bash 등) | 회원 기기(로컬 `scripts` 원장) | **회원 기기**에서 손발 `script_run` 봉투, 로컬 승인 판 아래 | 허브는 id 로 부를 뿐 본문을 받지 않는다 |
| **회원 IBL 문장**(관용구·`fn:`·시작 문장) | 회원 기기(로컬 해마·문장 원장) | **허브**가 해석·실행 | 전개된 문장의 모든 액션이 §3-4 권한 관문을 **회원 권한으로** 다시 지난다 |

- **졸업 = 최소 완료 조건**(§1-2): `내보내기`(회원 로컬 SQLite 전부 — 대화·기억·해마 용례·포식·프로그램·문장을
  한 묶음으로) + 독립 설치본의 `가져오기`(어휘와 축적물은 사람을 따라간다는 기존 원칙의 집행). 가져온 뒤 옛
  허브와의 관계는 이웃 문법(`[others:ask]`·신뢰 레벨)으로 바뀐다.

### 3-8. 얇은 몸·표면·한도·재연결

**PC(`helper/`, Go 단일 실행파일)** — `mode: member` 추가 op: `play`·`open`·`memory_save`/`memory_recall`·
`script_run`/`script_list`·`export`. **승인 판**: `side_effect` 봉투(shell·write·play·script_run)는 헬퍼 콘솔/트레이
확인(자동 허용 목록은 회원 로컬 설정 파일). 읽기·목록·회상은 무확인. 판단은 허브가 아니라 회원의 손에서.
**로컬 채팅 셸**: 헬퍼가 `127.0.0.1:<port>` 로 런처 셸 HTML 서빙(`launcher_app_common` 매개변수화, `__MEMBER`
주입 — 렌더러 **포크 금지**). **로컬 기억 저장소**: SQLite 하나(대화·기억·해마 용례·포식·프로그램·문장·**작업 원장**).
손발은 IBL 을 모르는 얇은 몸 — 봉투 계약(op 목록)만 공유, 허브 DB 스키마를 베끼지 않는다.

**폰(`phone-companion/`)** — 빌드 플레이버 `member`: 온디바이스 Python 백엔드·폰-로컬 Gemini·BaseBundle 을 뺀
껍데기(WebView 채팅 셸 + `AgentForegroundService` 롱폴 + `PhoneAccessibilityService` + 센서 + hls.js 재생).

**재연결과 멱등(2차 개정)** — 파일 쓰기가 끝난 뒤 결과 회신만 끊기면 재시도가 같은 쓰기를 반복한다. `phone_jobs` 는
서버 uuid 뿐이고 결과는 5분 안에 1회 pop 이라 재조회가 불가능하다. 회원 앱 계약에 포함:
- 허브가 봉투에 **멱등 키**(`session:turn:step`)를 싣고, 손발은 로컬 작업 원장에 키→결과를 기록해 같은 키는 실행
  없이 원장의 결과를 회신한다.
- 허브의 재시도는 항상 같은 키로. `wait_result` 시간 초과 뒤 재연결 시 `result_query(key)` 봉투로 재조회.
- 세션 정지(연결 끊김) 중 진행 중이던 side_effect 봉투는 손발이 완료까지 돌린 뒤 원장에 남기고, 다음 연결에서
  허브가 미회수 결과를 당겨간다.

**한도·비용** — `portal_core.authorize_and_count` 재사용(레벨별 일일 한도·전역 한도)에 **턴 예산**(모델 호출·출력
토큰 상한)과 **회원 동시 실행 상한**(세션 수·세션당 동시 봉투 수)을 더한다. 대화형 루프는 요청 횟수만으로
비용을 막지 못한다. 비용은 contextvars 비용 원장을 `agent=member:*` 로 집계.

**감사로그** — `portal_core.audit_log` 는 코드 원문 300자를 저장한다(`code[:300]`). 회원 세션에서는 골격 치환 후의
코드·행위자·ok·오류 부류만. 골격 치환기가 없는 동안은 코드 칸을 비운다.

**허브 라우트** — 최소: `/limb/connect`(기존)·`/m/chat`(WS, limb key 인증)·`/m/app`(폴백 셸). 프로젝트·설정·조종실
API 는 회원 인증으로 **라우트 자체가 없다**(`is_public_remote_path` 화이트리스트 방식 — 거절이 아니라 부재).

## 4. 선행 수리 — 회상의 행위자 축 (착수 여부와 무관)

`ibl_usage_rag.IBLUsageRAG.get_references(user_query, k, allowed_nodes)` 는 몸·행위자 축이 없다. 활성 어휘
필터를 지난 주인 용례에는 주인의 **문장 원문**이 실려 있어, 회원 프롬프트에 주인 개인정보가 들어간다.
이 축은 **이미 열려 있는 경로**에도 있다 — `body_ask._compile` 이 이웃의 부탁을 컴파일할 때
`_filter_foreign_refs` 는 남의 액션만 거르고 주인 용례의 원문은 거르지 않는다(모델이 되풀이하면 새는 표면).
심층메모리·포식 회상도 같은 부류.

수리: 회상 공급원 전부(해마 용례·심층메모리·포식·문서)에 `actor` 축을 넣고, 행위자가 `system_ai`/`user` 가
아니면 **자기 것 + 주인 발행분**만 회상한다. 시험은 §6 읽기 격리. 외부 서비스 앱 1단계보다 먼저.

## 5. 판정 필요 (사용자 결정 — 언어 개정·파괴적 변경 2종만 묻는다)

1. **어휘 소스 필드 신설** `lands_on: hub|body` + `limb_op:` — 어휘 선언 스키마 확장(빌드 `--check` 삼각 검증 대상 추가).
   회원 세션에서 선언 없음=거절. 대안은 프로파일별 하드코딩 목록인데 헌법 위반이라 권하지 않음. **추천: 신설.**
2. **행위자 봉투 `origin` 값 `member` 신설** — `user`/`portal` 옆. 대안 `portal` 재사용은 "몸 있음/없음"을 잃음. **추천: 신설.**
3. **회원 얼린 문장** — §3-7 두 종류 구분으로 허용(프로그램은 회원 기기, 문장은 허브 해석+재검사). **추천: 허용.**
4. **헬퍼 한 바이너리 두 모드**(`limb`/`member`) — 승인 방향이 반대(limb=허브가 자동승인, member=회원이 명령을 승인).
   **추천: 한 바이너리, 설정 파일의 `mode` 로.**
5. **회상 행위자 축**(§4) — 회상 공급원 시그니처 변경. 언어 개정은 아니나 인지 경로 공통 변경이라 알림. **추천: 선행 집행.**

## 6. 누출 관문 — 카운터가 아니라 실패하는 시험 (쓰기 + 읽기)

기존 기록자들은 회원 턴을 주인 저장소에 **기본으로 적는다.** 지켜볼 게 아니라 시험이 실패하게 한다
(feedback: no-counter-watch · pitfall: test-writes-to-real-store — 시험은 영속 경로 **전부** 임시화).

### 6-1. 쓰기 격리

| 기록자 | 지금 쓰는 곳 | 회원 세션(origin=member)에서 |
|---|---|---|
| 시스템 AI 대화 이력 | `system_ai_memory.db:conversations` | 쓰지 않음 → 손발 `memory_save` 봉투로 회원 로컬에 |
| 에피소드 로거 | `world_pulse.db:episode_log` | 쓰지 않음(요약 포함) → 회원 로컬 |
| 해마 증류 `cognitive_distill._after_response` → `ibl_usage_db.add_example` | 문장·코드 쌍 | 골격 치환기가 있으면 통계 경로만(`record_recall_outcome`·`update_success_by_code`), **없으면 기록 자체를 끈다**. `add_example` 은 회원 로컬 해마로 |
| 심층메모리 `_distill_deep_memory` | 에이전트 `memory.db` | 쓰지 않음 → 회원 로컬 |
| 포식 `self:forage` | `forage_surveys/<몸>/` | 몸 = 회원 손발 → 회원 로컬(허브 색인에도 0행) |
| `backend_runtime.log`·body_ask `_log`·`portal_core.audit_log` | 요청·코드 원문 포함 | 원문 미기록, 메타(agent·골격·ms·success·오류부류)만 |
| `write_ledger`·`tasks` | 원장 | 유지하되 payload 에 원문 없음(골격·경로 해시) |
| 턴 임시 디렉토리(§3-6) | — | 턴 뒤 0항목 |

### 6-2. 읽기 격리 (2차 개정 — 핵심 관문)

주인·회원 A·회원 B 에게 서로 다른 **표식 기억**(해마 용례 문장·심층메모리 항목·포식 항목·파일 하나씩)을 넣고,
세 세션을 **동시에** 돌려:
- 각 응답·프롬프트 조립물·회상 결과에 자기 표식만 있고 다른 둘의 표식이 0회.
- 회원 프롬프트에 `system_docs/`·시스템 메모·주인 프로젝트 문서의 표식 0회(발행 가이드의 표식은 있어야 함).
- 회원 A 의 쓰기가 회원 B 의 다음 턴 회상에 나타나지 않음.

### 6-3. 시험 형태

회원 세션 한 턴 뒤 위 저장소 전부에서 `agent LIKE 'member:%'` 또는 표식 문자열이 **0행**, 회원 로컬 SQLite 에
대화·에피소드 각 1행 이상. 골격 치환은 슬롯 값 문자열이 허브 DB·로그·감사로그 어디에도 없음을 grep 으로.
관문의 되돌림 문장을 실제로 돌려볼 것(pitfall: gate-prescription-untested).

## 7. 구현 순서 (2차 개정 — 격리를 앞에, 폰은 마지막)

0. **선행 수리** — 회상 행위자 축(§4). 읽기 격리 시험(§6-2)을 먼저 써서 빨강 확인 후 초록.
1. **PC 에서 회원 두 명의 대화·기억 격리** — 판정 1·2 반영. 신원 결합(`[self:limb]{op:issue}` 에 `neighbor_id`/`level`
   → `limb_keys.mint`+`body_trust.grant_body`), **회원 세션 러너**(§3-0 계약 전부), 활성 사전 member 축, 실행 직전
   권한 관문(§3-4, 선언 없음=거절), 쓰기·읽기 격리 시험 초록, 골격 치환기(없으면 통계 기록 끔), 감사로그 수정,
   턴 예산·동시 실행 상한. 몸 없이 검증 가능한 부분은 여기서 끝낸다(파일 액션은 "몸 없음" 거절).
   **첫 성공 기준(§0)의 절반** — 두 회원의 대화가 서로와 주인에게 안 보인다.
2. **로컬 파일 읽기·쓰기와 승인·재연결** — 헬퍼 `mode: member`(승인 판·로컬 SQLite·로컬 셸 서빙·작업 원장),
   엔진 세 번째 갈래, `limb_op` 번역, 턴 스코프 디렉토리(§3-6) + 착지 + 삭제, 멱등 키·재조회(§3-8).
   **첫 성공 기준(§0) 완주** — 회원 A 가 자기 파일을 정리하고 다음 대화에서 기억한다.
3. **회원 스크립트와 졸업** — §3-7 두 종류(프로그램=회원 기기 `script_run`, 문장=허브 재검사), `export`/설치본 `import`.
4. **폰 플레이버** — `phone-companion` `member` 빌드. 폰 실기: 저장소·스피커·센서·조작.
5. **문서 7표면 + 가이드** — `remote_access.md` "표면 분리" 표에 셋째 행(회원 손발), `communication.md` 손발 절 개정,
   `memory.md` 두 부류 → 세 부류 + 읽기 방향, `ibl.md` `lands_on`·`side_effect` 권한 축, `new_action_checklist.md`,
   회원용 시작 문장 열 개(해례 형식, 완성 처방 금지).

## 8. 검증 배터리

1. `build_ibl_nodes.py --check` 초록(새 필드 삼각 검증·`side_effect`↔`lands_on` 대조 포함) · `check_backend_layers.py` · `check_file_size.py`.
2. §6 쓰기·읽기 격리 시험 전부 초록(동시 세션 포함).
3. 회원 세션에서 `[self:package]`·`[others:ask]`·`/projects/*`·`/config/*` 가 **거절이 아니라 부재**. 사용자가 직접 친
   IBL·저장 문장·중첩 안의 금지 액션은 실행 직전 관문에서 **거절**(부재와 별도로 확인).
4. 취소 격리: 회원 A 의 취소가 주인·회원 B 턴에 영향 0. 주인 `SystemAIRunner` 큐에 `member:*` 메시지 0.
5. 종단(PC): 회원 PC 파일 정리 → 회원 PC 에서 읽고 쓰고 저장, 턴 뒤 허브 디스크에 표식 파일 0·임시 디렉토리 0. 음악 → 회원 PC 스피커.
6. 재연결: 쓰기 완료 후 회신 끊김 → 재시도가 같은 키로 원장 결과를 받아 **2회 실행 0**. 미회수 결과 다음 연결에서 회수.
7. 승인 판: side_effect 봉투가 회원 확인 없이 돌지 않음, 읽기는 확인 없이 돎. 손발 미연결 → 정직 거절(허브 폴백 0).
8. 한도: 레벨별 일일 한도·턴 예산·동시 실행 상한 초과 시 감사로그(원문 없음)·거절. 비용 원장 `member:*` 집계.
9. 졸업: `export` → 독립 설치본 `import` → 같은 질문에 같은 기억으로 답. 옛 허브와는 `[others:ask]` 로만.
10. 회귀: 원격 런처·폰 네이티브·포털·USB 손발(`limb` 모드) 무손상. keeper 3스트라이크 안에서 재기동.
11. 종단(폰): 5번을 폰에서.

## 9. 함정(기존 교훈에서)

- 부류 스윕은 관문을 먼저 쓰고 고쳐라 — 기록자·회상 공급원 목록을 손으로 고르면 샌다(§6 표는 출발점, 정본은 시험).
- 파생본에 규칙을 파일별로 전개하지 말 것 — `limb_op`·`lands_on` 은 어휘 소스 한 곳, 파생물은 빌드.
- "다음 증류가 갱신할 것"류 위임된 낙관 금지 — 골격 치환기는 1단계 실물, 없으면 기록을 끈다.
- 반환 형태(`returns`)로 부작용을 판정하지 말 것 — 축이 다르다(§3-4).
- 라이브 백엔드 편집에 표식 의례 불요(keeper). 새 backend 모듈 = 층 폴더 + `LAYERS` 배정, 스크립트는 `import boot_paths`.
- 커밋은 pathspec(동시 세션 공유 인덱스). 민감정보(limb key 실물) 커밋 금지 — `data/limb_keys.json` 은 이미 밖.
- 시각 산출물(헬퍼 콘솔·폰 화면)은 내 눈으로 보고 완료.

## 10. 열린 관찰(⏳, 구현 뒤)

- 회원의 `fn:`/얼린 문장 실사용 빈도(사다리가 실제로 오르는가) — 졸업 자체는 관찰이 아니라 완료 조건(§1-2).
- 골격 통계가 주인 해마 회상 품질에 기여하는가(성공률 표시에 회원 골격이 섞일 때 오염 여부).
- 승인 판 마찰 — 자동 허용 목록이 어디까지 자라는가(클로드 코드 permission 학습 곡선과 대조).
- 턴 예산·동시 실행 상한의 실측 적정치(가족/사무실).
