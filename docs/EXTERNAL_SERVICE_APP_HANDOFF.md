## 0. 한 문장

**주인은 하네스를 발행하고, 회원은 그 하네스를 자기 하드웨어 위에서 쓴다.**
가족·사무실에서 한 사람만 indiebizOS 를 설치·관리하고, 나머지는 PC·폰에 얇은 앱 하나를 깔아
클로드 코드를 쓰듯 AI 에이전트를 부린다. 회원의 파일은 회원 PC 에서 처리되고 회원 PC 에 저장되며,
음악은 회원 기기에서 난다. 회원은 하네스를 바꿀 수 없고, 회원의 기억은 회원 하드웨어에만 쌓인다.

**첫 성공 기준**:
> 회원 A 가 자기 PC 의 파일을 정리하고 다음 대화에서 그 일을 기억하되, **주인과 회원 B 에게는 그 내용이
> 전혀 나타나지 않는다** — 동시 대화 중에도, 강제 종료 뒤에도.

## 1. 목적

1. **커뮤니티당 노드 하나**의 완성. 공개 표면 가족(포털·창고·게시판)은 *브라우저로 보는* 참여였다. 이 앱은
   *일을 시키는* 참여다 — 설치 없이 능력을 빌리던 회원이 자기 하드웨어를 몸으로 내놓는다.
2. **AX 사다리의 첫 단**(08-21 판정 "조직-몸 AX 는 실패, 몸통은 개개인이 자기 몸을 익힘"과의 정합). 회원은
   시작 문장을 익히고 자기 손발·기억·얼린 문장을 갖는다. **졸업 경로(내보내기+가져오기)는 최소 완료 조건**이다.
   없으면 팔란티어형 "사다리 없는 앱"이고 이 목적은 실패다.
3. **주인 = 하네스 발행자**. 클로드 코드에서 Anthropic 이 모델·하네스를 쥐고 사용자가 기계를 대는 관계의 자리를
   indiebizOS 주인이 맡는다. 경영자 몸은 조종이 아니라 발행(공통 팔·시작 문장·창고 규약).

## 2. 확정 설계

### 2-1. 회원에게 없는 것 셋 / 있는 것 셋

| 없다 | 있다 |
|---|---|
| **하네스 편집권** — 어휘 추가·패키지·설정·프로젝트·스케줄·시스템 수정 | 주인이 활성으로 발행한 어휘의 **사용** |
| **주인의 데이터** — 기억·해마 용례·프로젝트 폴더·이웃 명부·창고 비공개층·내부 운영 문서 | **자기 하드웨어** — 파일·소리·화면·센서가 자기 기기에서 |
| **어휘의 전부** — 회원 프로파일에서 잠든 낱말·비공개 액션은 존재하지 않는다 | **자기 층** — 자기 기억·자기 얼린 문장(회원 기기에서 실행) |

### 2-2. 기억의 분리 — 7종 대응표

| 기억(memory.md #) | 어디에 | 비고 |
|---|---|---|
| #2 작업 기억(대화 이력) | 회원 하드웨어 | 허브는 턴 스코프 임시 상태만(§3-6). 허브 conversations DB 에 0행 |
| #5 관계 기억(심층메모리) | 회원 하드웨어 | 허브에 절대 남기지 않음 |
| #7 포식 기억(냄새지도) | 회원 하드웨어 | 그 사람 디스크의 지도 |
| #3 일화 기억(에피소드) | 회원 하드웨어 | 허브 `episode_log` 에 0행 |
| #4 해마 **용례**(문장→코드 쌍) | 회원 하드웨어 | 문장·슬롯 값에 개인정보가 실린다 |
| #4 해마 **통계**(골격·성공/실패·오류부류·지연) | 허브 | 골격 치환기가 없는 동안은 기록 자체를 끈다 |
| #6 자기 상태(action_health) | 허브 | 골격 단위 카운트 |
| #1 의미 기억(문서·어휘) | 허브 | 회원은 **발행분만** 읽음(활성 패키지 가이드·시작 문장). `system_docs/`·시스템 메모·주인 프로젝트 문서는 회원 프롬프트 밖 |

- **골격 규칙**: 허브에 올라가는 실행기억은 IBL 코드의 슬롯 값을 자리표로 치환한 골격 + 결과 메타뿐이다.
  문장 원문·값이 붙은 쌍은 회원 하드웨어의 해마에 남는다.
- **읽기 방향도 분리한다**: 회원 응답에 주인의 기억이 섞이는 것은 저장 누출과 별개의 축이다. 회상 공급원
  전부가 요청 주체(§3-3) 축을 갖고, 회원 세션은 자기 것과 주인 발행분만 읽는다.
- **전송 층은 분리하지 않는다(정직 고지)**: 회원 데이터는 턴 동안 허브 프로세스를 지나고 주인의 API 키로 모델
  제공자에게 간다. 분리는 저장 층의 보장이다. 고지문은 데이터(앱 첫 화면 텍스트, 주인이 고침).

### 2-3. 착지 = 회원의 몸

회원 세션은 **몸 = 회원의 손발**로 바인딩되고, 하드웨어에 닿는 액션(파일 읽기·쓰기·목록·찾기, 재생, 열기, 화면,
기억 저장·회상)은 그 손발에서 돈다. 순수 연산은 허브에서 돌고 산출물은 손발로 떨어진다. **손발 미연결이면 정직
거절** — 회원의 파일을 허브에 대신 저장하는 폴백 금지.

## 3. 구조

### 3-0. 새 물건은 테넌트 경계다

부품은 기존 것이다(§3-1). 그러나 실제 변화는 **단일 주인용 실행기에 여러 사람의 세션을 넣는 일**이다. 시스템 AI 는
싱글턴이다(`SystemAIRunner._instance`·클래스 변수 `internal_messages`·인스턴스 하나의 `cancel_event`,
`get_system_ai_runner()` 전역). 여기에 깃발을 꽂지 않는다. **회원 세션은 프로젝트 에이전트 모양의 세션 러너**
(`AgentRunner` 인스턴스)다 — 같은 인지 파이프라인, 다른 인스턴스.

| 분리 대상 | 회원 세션에서 | 공유 금지(주인 객체) |
|---|---|---|
| 실행 상태 | 세션별 러너·메시지 큐·`cancel_event`·진행 티켓 | `SystemAIRunner._instance`·`internal_messages` |
| 프롬프트 | 회원 프로파일로 조립(활성 사전 member 축·발행 가이드·시작 문장·고지) | 주인 프롬프트 캐시·시스템 메모·`system_docs` |
| 기억 공급원 | 손발 `memory_recall` + 주체 축 회상(§3-3) | 주인 해마 용례·심층메모리·포식 지도 |
| 취소·수명 | 세션 단위. 연결 끊김 = §3-6 끊김 수명 규약 | 주인 활성 작업 표식 |
| 행위자 봉투 | principal `member:<id>`·`origin=member`·`task_member_*` | `owner`·`origin=user` |
| 임시 파일 | 턴 스코프 디렉토리(§3-6) | `outputs/`·프로젝트 폴더 |
| 비용·한도 | 세션·턴 예산, 동시 실행 상한(§3-8) | 주인 비용 원장(집계만 `member:*`) |

### 3-3. 신원과 권한의 주체

**발급 = 주인의 행위 하나.** `[self:limb]{op:issue}` 가 limb key(`limb_keys.mint`)를 만들고 **회원(이웃)에 결합**한다.
회원 = 이웃 CRM(business.db)의 한 사람, 레벨 = 이웃 등급(0~4, 숫자만). 기기 ≠ 사람: 한 회원이 PC·폰 등 여러 기기를
갖는다. `body_trust.grant_body` 는 기기마다 새 이웃을 만드는 함수이므로 **기존 회원에 기기를 연결하는 op** 는 별도
구현이다 — 발급 op 가 `neighbor_id` 를 받으면 그 이웃의 `contacts` 에 `body` 행을 추가한다(새 이웃 생성 금지).
레벨은 사람에 붙고 기기는 상속한다. 앱이 지니는 것은 limb key 하나(허브 비밀번호·런처 세션 없음). 유출 = 그 키만
폐기. 회원 채팅 WS 도 limb key 로 인증한다.

**권한의 주체(principal) = 전송 관문에서 인증된 요청 주체.** 실행 에이전트 이름이 아니다.

| 주체 | 인증한 관문 | 값 |
|---|---|---|
| 주인 | localhost / 런처 세션 / 조종실·앱 · 프로세스 내부(스케줄러·자가점검) | `owner` |
| 회원 | limb key(`/limb/connect`·`/m/chat`) | `member:<이웃id>` (+ `device_id`) |
| 이웃 몸 | `/nodes/ask` 의 `device_id`→`body_trust` (전송은 런처 세션) | `body:<이웃id>` |
| 포털 회원 | 포털 쿠키 | `portal:<이웃id>` |
| 무인증 공개면 | 게시판·가족신문·공개 경로 | `anonymous` |

**불변조건 — 주체는 좁힐 수만 있고 넓힐 수 없다.**
- 요청 본문의 `principal`·`device_id`·`origin` 은 **주장이지 인증 증거가 아니다**. 수신 관문은 인증된 자격
  (limb key·런처 세션·localhost)과 주체의 결합을 검증한다.
- 전송 관문이 세운 주체보다 **넓은** 주장(회원 연결이 `owner` 를 주장, `body:A` 안에서 `body:B` 를 주장)은
  거절되고 현재 주체가 유지된다. 주체가 없거나 불일치하면 **주인 권한으로 복원하지 않는다**.
- 좁히는 주장은 허용된다(런처 세션으로 인증된 폰이 `device_id` 로 `body:` 를 주장 = 좁힘).
- 회원 주체인 동안 `origin=user` 가 잘못 복원돼도 **자기수정 그랜트(RED)는 열리지 않는다** — 그랜트 발급·조회가
  origin 만이 아니라 주체를 본다. 이 조건은 시험 하나로 고정한다(§6-2).
- 전달 범위: 회상 공급원 전부(해마·심층메모리·포식·문서), 중첩 실행(`>>`·`[table:each]`·`fn:` 전개·`[self:script]`
  안의 문장), **회상 캐시 키**, 워커 풀(`base/execution_workers.py` 의 제출 시점 승계 묶음), 프로바이더 밖 복원
  (`/ibl/execute` 봉투 — 좁힘만).
- **작업 회신의 귀속**: `/limb/result`·`/limb/progress` 는 그 키의 기기에 발급된 작업인지 검사한다(`phone_jobs`
  작업에 device_id 를 박고 회신 시 대조). 회원 B 의 헬퍼가 회원 A 의 결과를 덮어쓸 수 없다.

**행위자 봉투(회원 세션)**: principal `member:<id>`(정본 판정 축) · `agent=member:<id>`(표시·채널 게이트, 판정 축
아님) · `task=task_member_*`(원장 조인, 저장은 §6 관문 뒤·원문 없음) · `origin=member`(신설 — `portal` 은 무몸,
`member` 는 손발 바인딩).

### 3-4. 어휘의 부재와 실행 권한 — 각각 집행한다

| 층 | 무엇 | 어디서 | 성격 |
|---|---|---|---|
| **부재**(학습 정책) | 회원 프로파일에서 잠든 낱말·비공개 액션은 프롬프트·카탈로그·회상에 없다 | `activation.json` 프로파일 축 owner/member, `set_package_active(..., profile=)`(`HUMAN_AUTHORITY`), `vocabulary_state.revision` 재조립 | 우회 유도를 없애는 정책. 집행이 아니다 |
| **권한**(집행) | 실행 직전, 이 주체가 이 액션을 이 자원 범위에서 이 몸에서 돌릴 수 있는가 | 엔진 chokepoint(`_resolve_and_maybe_forward` 앞) 한 자리. 직접 친 IBL·저장 문장·중첩·`fn:` 전개·`[self:script]` 안의 문장 전부 | fail-closed |

**판정 축은 선언이다(이름 아님)**:
- 부작용 축 = `side_effect`(op 단위 `ops.side_effect` 포함). `returns` 는 반환 형태 축이라 쓰지 않는다
  (`[self:script]` 가 `returns: items` + `side_effect: true` 인 것이 반례).
- 실행 위치 축 = `lands_on`(신설: `hub` | `body`). 회원 세션에서 **선언 없는 액션은 거절**한다.
- **액션별 공개 판정**: 회원 활성 패키지 안에서도 액션마다 공개 여부를 선언에서 유도한다. 공개 액션 = `lands_on`
  선언이 있고(`hub` 면 §3-6 의 감사 표식까지) 하드 거부 부류가 아닌 것. **비공개 액션은 카탈로그와 실행 양쪽에서
  제외**한다. 파일 기능과 관리 기능이 한 패키지에 있어도 패키지를 쪼개지 않는다.
- 하드 거부(헌법): `others` 노드 전부, `self` 의 하네스 편집 부류(package·install_lib·limb·manage_events·webapp·
  주인 스코프 script/ledger/memory 쓰기), `limbs` 의 주인 기계 부류(os_open·open_window·screen·guestpc·android).
  이들은 `lands_on` 을 받지 않아 관문이 자동 거절한다(★이름으로 넘겨짚지 말 것 — CCTV 오분류 교훈).
- `build_ibl_nodes.py --check`: `lands_on: body` 인데 `limb_op` 없음 → 실패. **공개 액션인데 선언 불완전** → 실패.
  비공개 액션은 검사 대상이 아니다(패키지를 켤 수 있게).

### 3-5. 실행 프로파일 `member` — 엔진 chokepoint 의 세 번째 갈래

`ibl_engine._resolve_and_maybe_forward` 의 두 갈래(phone/데스크탑) 옆에, 주체가 `member:` 이고 바인딩 device_id 가
있으면 §3-4 관문 뒤: `lands_on: body` → 손발 봉투로 번역해 `phone_jobs.enqueue(device_id, envelope)`→`wait_result` /
`lands_on: hub`(감사 표식 유효) → 허브 로컬, 파일 입출력은 §3-6 안에서만 / 그 외 → 거절.
**번역표는 데이터**: 어휘 소스 yaml 의 `limb_op:` 매핑(예 `self:read`→`{op:"read", path:$path}`). 엔진 코드에 액션
이름을 박지 않는다.

### 3-6. 허브 연산 계약 — 임시 저장·접근 격리·끊김 수명

**턴 스코프 격리 임시 디렉토리**: 회원 턴마다 `data/_member_tmp/<session>/<turn>/` 하나. 회원 세션의 허브 로컬
액션이 읽고 쓰는 유일한 경로(경로 이탈=거절). 입력 파일은 손발 `read` 봉투로 가져와 여기 놓고 턴 네임스페이스
안에서만 해소(`$file:` 포함). 파이프·`[table:each]` 중간 산출물도 여기. 최종 산출물은 손발 `write` 봉투로 착지.

**임시 디렉토리 지정 ≠ 접근 격리.** 작업 디렉토리를 바꿔도 핸들러의 절대경로 읽기·공용 캐시 쓰기·하위 프로세스는
제한되지 않는다. `lands_on: hub` 는 위치 표식이지 접근 제한 장치가 아니다.
- **첫 구현**: 입출력 경로와 내부 저장 경로(캐시·로그·산출)를 사람이 확인한 허브 액션만 회원에게 개방한다.
- **감사 표식 = 구현 지문**: 어휘 소스에 `path_audited: {at: <날짜>, impl: <핸들러 파일 해시>}`. 빌드 `--check` 가
  현재 핸들러 지문과 대조해 다르면 그 액션을 회원 세션에서 닫는다. 계약: **옛 감사 표식으로 바뀐 코드를 자동
  개방하지 않는다.** 재검증 = 사람이 다시 확인하고 지문을 갱신하는 것뿐이다.
- **집행 수단은 구현 단계의 선택**: 공통 파일 접근 계층(핸들러의 경로 해소를 한 함수로 모아 턴 밖을 거절) 또는
  별도 격리 실행 환경. 무엇이든 §6 시험이 판정한다.
- **파일 참조 = 선언된 참조만**: 착지 시 옮기는 대상은 통화의 `files` 필드·`$file:` 참조·`returns: file` 로 파일임이
  선언된 것에 한한다. 일반 문자열을 훑어 경로처럼 생긴 본문을 옮기지 않는다.

**끊김 수명 규약 — 연결 종료 ≠ 작업 종료**:
1. 연결 끊김 → 신규 실행 중단(큐의 미발급 봉투 취소, 새 모델 호출 없음).
2. 진행 중 작업(허브 로컬·손발 봉투)의 **종료 또는 중단을 확인한 뒤에만** 턴 임시 저장소를 삭제한다. 늦게 나온
   산출물은 착지하지 못하면 삭제된다(허브에 남기지 않는다).
3. 회원 기기에서 완료된 작업의 결과는 손발 로컬 작업 원장에서 재조회한다(§3-8).
4. 최종 산출물은 회원 기기의 **저장 완료 확인**을 받은 뒤에야 전달 완료다.
5. 세션 종료·부팅 시 고아 디렉토리 청소. 시험: 턴 뒤 `data/_member_tmp/` 0항목, 주인 디스크 표식 파일 0.

### 3-7. 회원의 얼린 문장과 졸업

| 종류 | 저장 | 실행 | 검사 |
|---|---|---|---|
| **회원 프로그램**(Python·Bash 등) | 회원 기기(로컬 `scripts` 원장 + 파일 실물) | **회원 기기**에서 손발 `script_run` 봉투, 로컬 승인 판 아래 | 허브는 id 로 부를 뿐 본문을 받지 않는다 |
| **회원 IBL 문장**(관용구·`fn:`·시작 문장) | 회원 기기(로컬 해마·문장 원장) | **허브**가 해석·실행 | 전개된 모든 액션이 §3-4 관문을 **회원 주체로** 다시 지난다 |

현재 `[self:script]` 는 Python·Bash 등록 프로그램 실행기이므로 회원 코드를 허브에서 돌리지 않는다(하네스 불가침).

**졸업 = 최소 완료 조건**: `export`(회원 로컬 SQLite 전부 — 대화·기억·해마 용례·포식·문장 — **+ 프로그램 파일
실물·필요한 자원 파일·의존성 정보**(인터프리터 역할·패키지 목록)) + 독립 설치본의 `import`. 가져온 뒤 옛 허브와의
관계는 이웃 문법(`[others:ask]`·신뢰 레벨)으로 바뀐다. **손발은 주권 몸이 아니라 회원 세션의 손**이므로 졸업 전의
라우팅은 no-privileged-rails 와 충돌하지 않는다.

### 3-8. 얇은 몸·재연결·한도

**PC(`helper/`, Go 단일 실행파일, `mode: member`)** — 추가 op `play`·`open`·`memory_save`/`memory_recall`·
`script_run`/`script_list`·`export`·`result_query`. **승인 판**: `side_effect` 봉투(shell·write·play·script_run)는 헬퍼
콘솔/트레이 확인(자동 허용 목록은 회원 로컬 설정). 읽기·목록·회상은 무확인. **로컬 채팅 셸**: `127.0.0.1:<port>` 로
런처 셸 HTML 서빙(`launcher_app_common` 매개변수화 `__MEMBER`, 렌더러 포크 금지). **로컬 저장소**: SQLite 하나
(대화·기억·해마 용례·포식·프로그램·문장·작업 원장). 손발은 IBL 을 모르는 얇은 몸 — 봉투 계약만 공유.

**폰(`phone-companion/`, 플레이버 `member`)** — 온디바이스 Python·폰-로컬 Gemini·BaseBundle 을 뺀 껍데기(WebView
채팅 셸 + `AgentForegroundService` 롱폴 + `PhoneAccessibilityService` + 센서 + hls.js 재생).

**작업 원장과 멱등** — 정확히 한 번 실행은 약속하지 않는다. 약속은 "두 번 실행을 기계가 시작하지 않는다"까지다.
- 허브가 봉투에 멱등 키(`session:turn:step`) + **요청 지문**(본문 해시)을 싣는다. 같은 키·다른 본문 → 거절.
- 손발 작업 원장은 **4상태**: `접수`·`실행 중`·`완료`·`결과 불명`. 같은 키는 실행 없이 원장의 결과를 회신. 헬퍼
  재시작 시 `실행 중` → `결과 불명`.
- **결과 불명인 부작용 봉투는 자동 재실행하지 않는다**. 허브는 상태를 회원에게 보이고(승인 판) 사람이 결정한다.
  읽기·회상은 재실행해도 된다.
- 재시도는 항상 같은 키로. 시간 초과 뒤 재연결 시 `result_query(key)` 로 재조회. 세션 정지 중 완료된 결과는 다음
  연결에서 회수.

**한도·비용** — `portal_core.authorize_and_count` 재사용(레벨별 일일·전역 한도) + **턴 예산**(모델 호출·출력 토큰) +
**동시 실행 상한**(세션 수·세션당 봉투 수). 비용은 contextvars 비용 원장을 `member:*` 로 집계.

**감사로그** — `portal_core.audit_log` 는 코드 원문 300자를 저장한다. 회원 세션에서는 골격 치환 후 코드·주체·ok·
오류 부류만. 골격 치환기가 없는 동안은 코드 칸을 비운다.

**허브 라우트** — 최소: `/limb/connect`·`/m/chat`(WS, limb key)·`/m/app`(폴백 셸). 프로젝트·설정·조종실 API 는 회원
인증으로 **라우트 자체가 없다**(거절이 아니라 부재).

## 4. 선행 수리 — 요청 주체 축 (착수 여부와 무관, 2026-09-14 착수)

**결함**: 해마 회상 `ibl_usage_rag.get_references(user_query, k, allowed_nodes)` 와 그 캐시 키(쿼리·k·노드·활성
revision)에 요청 주체 축이 없다. `body_ask._execute` 는 이웃의 부탁을 `agent_id="system_ai"` 로 실행한다. 따라서
활성 어휘 필터를 지난 주인 용례(문장 원문 포함)가 이웃 부탁의 컴파일 프롬프트에 들어갈 수 있다. 심층메모리 지도·
포식·결정 원장 회상도 같은 부류.

**사실 관계(정확히)**: 확인된 것은 **누출 가능한 경로**다. `data/body_ask_log.jsonl` 집계(2026-09-14): 총 22건 중
기기 신원이 있는 부탁 2건(낯선 몸 거절 1·npub 1), 그중 **컴파일 0건·성공 0건**. 즉 이 경로로 주인 용례가 남의
프롬프트에 실린 사건은 **0건**이다.

**수리(0단계)**: `base/principal.py` — 전송 관문(`remote_access_guard`)이 주체를 세우고(로컬·세션=owner, 외부
공개 경로=anonymous), 이후는 **좁힘만**(`narrow()` — 넓히는 주장은 거절·현재 유지). `/nodes/ask` 는 신뢰 판정 뒤
`body:<id>` 로 좁히고, 포털 게이트는 `portal:<id>`/`anonymous` 로 좁힌다. 회상 공급원(해마 `_search_active`·회상
믹스인 `_build_execution_memory`·심층메모리 검색·포식 회상)은 주체가 owner 가 아니면 주인 것을 내지 않고, 캐시 키에
주체를 넣는다. 증류(`distill_experience`)는 owner 가 아니면 쓰지 않는다. RED 그랜트(`red_grant.issue_grant`·
`active_grant`)는 origin 과 별도로 **주체가 owner 일 때만**. 스냅샷/복원(`thread_context.snapshot`)에 주체를 실어
스레드 이동을 건넌다. 시험 = §6-2 읽기 격리 + 그랜트 시험.

## 6. 누출 관문 — 카운터가 아니라 실패하는 시험

시험은 영속 경로 **전부** 임시화(pitfall: test-writes-to-real-store). 관문의 되돌림 문장을 실제로 돌려본다.

### 6-1. 쓰기 격리 — 저장소 두 부류

| 부류 | 저장소 | 조건 |
|---|---|---|
| **내용 저장소** | conversations·episode_log(+summary)·memory.db·forage·ibl_usage.db 의 용례(intent·ibl_code 원문)·backend_runtime.log 본문·body_ask `_log` 원문 | 회원 주체 행 **0행**, 표식 문자열 0회 |
| **메타 저장소** | 비용 원장·`portal_core` 감사로그·action_health·해마 통계·write_ledger·tasks | 회원 주체 행은 있되 **허용 필드만**(주체·골격·ok·오류부류·ms·비용·경로 해시). 원문·슬롯 값·회원 경로 실물 0회 |
| 턴 임시 디렉토리 | `data/_member_tmp/` | 턴 뒤 0항목 |

기록자별 처방: 대화 이력·에피소드·심층메모리·포식 → 손발 봉투로 회원 로컬 / 해마 증류 → 골격 치환기 있으면 통계만,
없으면 기록 끔 / 로그·감사로그 → 원문 미기록.

### 6-2. 읽기 격리 · 주체 불변조건 (핵심 관문)

주인·회원 A·회원 B 에게 서로 다른 **표식 기억**(해마 용례·심층메모리·포식·파일)을 넣고 세 세션을 **동시에** 돌려:
- 각 응답·프롬프트 조립물·회상 결과에 자기 표식만, 다른 둘의 표식 0회. A 가 데운 캐시를 B 가 받지 않음.
- 회원 프롬프트에 `system_docs/`·시스템 메모·주인 프로젝트 문서 표식 0회(발행 가이드 표식은 있어야 함).
- 회원 A 의 쓰기가 회원 B 의 다음 턴 회상에 나타나지 않음.
- 주체 불변조건: 좁힌 주체 안에서 `owner` 주장 → 무시·현재 유지. `body:A` 안에서 `body:B` 주장 → 거절.
  회원 주체 + `origin=user` → RED 그랜트 발급 0·조회 None. `body_ask` 경로에서 주체 `body:<id>` 로 세워지고 회상이
  주인 용례를 내지 않음. 중첩 실행·`fn:` 전개·워커 풀 안에서 주체 유지.
- 강제 종료: 회원 A 턴 중 헬퍼·허브 강제 종료 뒤에도 위 조건 유지, 임시 디렉토리 0항목.

## 9. 함정

- 부류 스윕은 관문을 먼저 쓰고 고쳐라 — 기록자·회상 공급원 목록을 손으로 고르면 샌다.

- 위임된 낙관 금지 — 골격 치환기는 1단계 실물, 없으면 기록을 끈다.
- `returns` 로 부작용을, `agent_id` 로 권한을, 날짜만으로 감사 유효성을 판정하지 말 것. 임시 디렉토리 지정을 접근
  격리로, 연결 종료를 작업 종료로 착각하지 말 것.
- 라이브 백엔드 편집에 표식 의례 불요(keeper). 새 backend 모듈 = 층 폴더 + `LAYERS`, 스크립트는 `import boot_paths`.
- 커밋은 pathspec. limb key 실물 커밋 금지. 시각 산출물은 눈으로 보고 완료.

### 반영한 범위

- **0·1단계 보강**: 기존 principal·회상·RED 관문에 더해 MemberRunner가 직접 run_command/read_guide를

### 설계와 현재 구현의 경계

1. 공개 후보는 기존 파일/프로그램 body 경로에 self:fill, limbs:radio, sense:here,
   limbs:android를 더했다. sense:radio는 감사된 hub 읽기로 선언했다. 주인이 묶음 공개를 켜기 전에는
   회원에게 보이지 않는다. 이번 작업에서 실제 회원 발급·실사용 공개 선택은 바꾸지 않았다.
2. **문서 전달 구현**: self:read는 텍스트 범위·PDF/DOCX/XLSX/XLS, self:fill은 PDF/DOCX 양식을 지원한다.
   body의 member_transform 선언과 path_audited로 허브 임시 변환을 따로 감사한다. 회원 원본만 base64로
   수신하고, 임의 허브 경로를 핸들러에 전달하지 않는다. 결과는 회원 저장 승인을 받고 write 영수증 이후
   files 목록으로 반환한다. 턴 안의 불투명 파일 ref와 기존 files/$file 인라인 첨부 문법을 지원한다.
   32MB 입력/출력, Office ZIP 해제 128MB/1만 항목 한도. 외부 자원 연결·DOCX 이미지 추출은 개방하지 않는다.
3. **미디어·폰 개방 구현**: PC는 로컬 번들 브라우저 오디오, Android는 MediaPlayer로 play/stop/status/volume을
   수행한다. 재생 실패·형식 미지원은 실패 응답이다. PC 화면은 켜 두어야 하며 브라우저 지원 형식에 한한다.
   위치는 폰의 OS 권한과 로컬 승인 후 1회 측정한다. 접근성 snapshot/tap/type/swipe/key/long_press/open_app은
   자신의 연결된 폰에만 간다. 기본 limb/주인 실행은 바꾸지 않는다. 실제 폰의 종단 검증은 아래에 남긴다.
4. 허브의 슬롯 골격은 정규식으로 값을 가리는 대신 **사전에 실재하는 액션 이름만** 남긴다.
   사용자 슬롯 이름·fn 이름·주석도 원문일 수 있기 때문이다. 회원 원문 코퍼스·증류는 끈다.
5. 포털 계기의 authorize_and_count는 slug/instrument/포털 키를 전제로 하므로 회원 채팅에 가짜 계기를
   만들지 않았다. member_policy/member_usage의 별도 원자 예약으로 레벨별/전체 일일 한도·동시 상한을
   집행한다. 모델/봉투/시간 예산은 턴 문맥이 집행한다. 공통 카운터 추출은 기능 완료에 필요한 변경이 아닌 별도 구조 개선 대상으로 둔다.
6. 결과 불명은 원장·UI·다음 턴의 로컬 회상에 남는다. 허브 재시작 후 주인 디스크에서 회원 본문을
   복구하지 않는다. 회원에게 새 부작용 실행을 자동 약속하지 않는다.
7. 졸업 원본의 해마·포식은 네이티브의 통계/검색 색인에 자동 혼합하지 않고 원본으로 보존한다.
   통계 재시딩은 가져오기 효과에 포함하지 않는 설계 선택이다. 같은 질문의 기억 복원 관문은 네이티브 대화/심층기억 읽기로 검증한다. 옛 허브와 이웃을 맺는
   일은 기존 이웃 기능을 쓰며, 가져오기 자체가 허브 키/연결을 이식하지 않는다.

회원 승인 화면은 접속한 허브에서 받아 실행하지 않는다. scripts/build_member_shell.py가 공통 member_shell/launcher_app_common을
PC 바이너리와 APK의 정적 자산으로 파생한다. /m/app은 회원 키를 확인하고 PC 연결 프로그램을 내려주는 HTTPS 진입점이다. 실행 화면은 기기의 로컬 번들이다. `build_member_shell.py --check`로 번들 드리프트를 검사한다.


> 현재 기본 진입점은 §13의 설치 없는 웹앱이다. 위 설치형 번들 설명과 §12는 선택형 네이티브 연결 프로그램의 구현 이력이다.

## 12. 회원 작업 공간으로의 보완 (2026-09-14)

이전 §11 구현은 격리된 회원 채팅이었다. 사용자가 요구한 제품은 **회원 기기를 작업장으로 삼는 자율주행·앱 웹 작업 공간**이다. 채팅만으로 그 제품이 완성됐다고 판단한 것은 잘못이었다.

현재 구현:

- `/m/app`에서 초대 키와 플랫폼을 선택하면 승인된 키가 든 연결 ZIP을 받는다. 허브 비밀번호는 주지 않는다. PC 연결 프로그램이 loopback 웹 작업 공간을 열며, 키는 로컬 설정만 보유하고 브라우저에는 한시 토큰만 준다.
- 작업 폴더 선택·새 작업·작업 목록·대화·진행 기록·중단·파일 탐색/편집/가져오기·앱 화면을 제공한다. 작업과 사건 기록은 회원 기기의 SQLite에 저장된다. 브라우저를 새로고침해도 작업 목록을 다시 열 수 있다.
- `/m/run`은 회원 인증 후 공통 인지 파이프라인을 실행하고 NDJSON 진행/결과를 로컬 작업 원장에 보낸다. PC 작업에만 `run_command`를 제공하며, 허브의 셸 대신 회원 기기의 셸로 보낸다. 요청마다 실제 연결과 기기의 작업 ID를 확인한다. Android에는 PC 셸 도구를 제공하지 않는다.
- 파일 API의 상대 경로는 작업에 고정된 폴더 기준이며 `..`·심볼릭 링크로 그 밖을 읽고 쓰는 것을 차단한다. **셸은 회원 OS의 사용자 권한으로 실행된다. 폴더를 시작 위치로 지정하지만 OS 샌드박스는 아니다.** 회원의 명령 승인이 필요한 이유다. 허브의 시스템 관리 경로는 이 실행과 연결되지 않는다.
- `/m/apps`는 공개된 어휘의 선언형 앱을 공통 원격 런처 렌더러로 표시한다. 소유자 독립 앱 파일을 읽지 않고, 닫힌 액션·주인 경로·커스텀 렌더러는 제외한다. 앱 실행은 모델을 초기화하지 않고 동일한 회원 IBL 관문을 통과한다. 기기 효과는 로컬 승인을 거친다.
- 회원은 자기 폴더에 `apps.json`과 등록 프로그램을 만들어 앱을 추가할 수 있다. 데이터와 프로그램은 자신의 기기에 남는다. 앱 프레임은 로컬 승인 토큰이 없는 sandbox iframe이고 직접 HTTP 호출도 닫혀 있다. Android의 네이티브 다리는 프레임이 얻을 수 없는 일회성 비밀값을 요구한다.
- 기기 프로그램이 살아 있으면 브라우저 창을 닫아도 진행된다. 승인이 필요한 작업은 화면에서 승인해야 하며, 승인 대기에는 한도가 있다. 연결 단절·기기 재시작으로 최종 결과를 잃은 작업은 `unknown`으로 남기고 자동 재실행하지 않는다.
- Android는 같은 작업·앱 UI와 로컬 SQLite 작업 원장을 사용한다. 작업 폴더는 앱 저장소로 고정하며 외부 파일은 기존 OS 가져오기/내보내기로 주고받는다. 데스크톱 셸·인터프리터의 제공을 약속하지 않는다.

공개 범위는 '모든 설치 앱 일괄 공개'가 아니다. 소유자가 회원에게 연 묶음 안에서도 `lands_on`과 감사 지문을 가진 구현만 실행된다. 허브 파일에 직접 쓰던 미전환 앱은 자동 공개하지 않는다. 이 관문과 회원 기기의 일반 명령 실행을 구분한다.

검증: 실제 Go 연결 프로그램 + 브라우저에서 작업 제출, 승인, 기기 파일 생성, 앱 목록 조회, 파일 편집, 새로고침 후 작업 복원을 확인했다(허브와 모델만 시험 대역). Python 시험은 실제 IBL 실행·인지 관문·NDJSON 회원 인증·외부 스필 경로 차단을 검사한다. Go 시험은 작업별 대화 분리, 상대 경로/심볼릭 링크, 로컬 셸 종료 코드, 진행 기록 보존과 결과 불명 복구를 검사한다. 유료 모델을 사용한 실제 외부 회원 접속 및 Android 실기기 검증은 시행하지 않았다. OS 서명 배포도 별도다.


## 13. 설치 없는 웹앱으로 전환 (2026-09-14)

제품의 기본 진입점 `/m/app`은 회원 키만 입력하면 사용하는 웹앱이다. PC·폰에 ZIP/APK를 요구하던 흐름을 교체했다. 기존 helper/Android는 선택 기능으로 남긴다.

- 공통 자율주행·앱·파일 화면을 유지하고 로컬 API 어댑터를 브라우저 실행기로 교체했다. 공개 어휘·인증·회원 인지·IBL 잎 관문은 기존 구현을 사용한다. `/m/run` NDJSON 결과를 브라우저 작업 원장에 기록한다.
- 파일·프로그램·작업·대화·기억·결과 영수증의 영속 저장소는 회원 기기의 IndexedDB다. 회원 키의 해시로 공간을 구분한다. 허브가 파일 작업을 대신 실행하지 않는다. 원본 OS 파일은 사용자가 선택하여 사본을 가져오고, 결과를 다운로드한다.
- 브라우저 기기 회상은 `javascript_available=true`, `shell_available=false`를 알린다. `run_javascript`와 JavaScript 등록 프로그램은 승인 후 opaque-origin iframe 안의 Worker에서 15초 이내 실행한다. 키·부모 DOM·네트워크·브라우저 파일 저장소 접근을 주지 않는다. 프로그램 실행 승인은 실제 실행할 본문을 표시한다.
- 작업 ID·연결 세대·요청 키 지문을 검사한다. 실행 전에 수신 영수증을 저장하고, 재전송은 결과만 반환한다. 결과 불명/중단 요청을 자동 재실행하지 않는다. 탭 잠금으로 동일 브라우저 회원의 동시 실행을 막고, 이전 연결의 `/m/run`·취소·결과 회신도 거절한다.
- 파일과 기억을 포함한 JSON 백업·병합 복원·지속 보관 요청을 제공한다. 키는 내보내기에 포함하지 않는다. 웹 JSON은 기존 졸업 ZIP과 다른 형식이며, 독립 설치본 가져오기 스크립트는 현재 ZIP용이다.
- 웹 UI와 실행기는 허브가 배포한다. 새 접속·새로고침으로 갱신하며 재설치는 없다. 이는 앞의 네이티브 번들 고정 계약과 다르다. 같은 origin의 웹 코드 배포자를 신뢰하는 구조이며 회원별 저장소 구분을 악성 허브 코드에 대한 암호학적 격리로 주장하지 않는다.

제한: 브라우저가 지원하는 기기 기능만 제공한다. OS 셸·네이티브 앱의 임의 조작은 웹앱 기능이 아니다. 탭 종료·화면 잠금·폰 백그라운드에서 지속 실행을 보장하지 않는다. 사이트 데이터 삭제 시 기억·파일도 지워지므로 백업이 필요하다. 허브는 AI 처리 중 본문을 보고 모델 제공자에게도 전송한다.

검증: 브라우저에서 helper 없이 로그인, 요청·승인·파일 생성/읽기, JavaScript 계산과 외부 fetch 차단, 새로고침 후 작업 보존, 선언형 파일 앱 실행, 회원 B의 A 파일 접근 실패, 파일 가져오기와 JSON 백업 병합/중복 복원, 중복 탭 차단, 폰 크기의 화면 배치를 확인했다. 허브와 모델만 시험 대역이며 실제 IndexedDB와 브라우저 실행기를 사용했다. 별도 자동 검사는 연결 세대·도구 발행·요청 중복/충돌·승인 거부·경로 이탈을 검사한다. 실제 외부 회원의 유료 모델 대화 및 Android/iPhone 실기기 검증과는 구분한다.

최종 검사: backend 전체 pytest, 웹앱/작업 공간 추가 pytest, frontend TypeScript 검사, backend 층 검사, IBL 파생물 검사, 기존 회원 셸 번들 일치 검사를 통과했다. 실제 HTTPS `/m/app` 응답은 새 브라우저 실행기를 포함하며 `Cache-Control: no-store`를 반환한다.
