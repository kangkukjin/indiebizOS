# 외부사용자의 경험 공유와 AX — 논의 메모

작성일: 2026-09-18
상태: 후속 검토용 구상. 구현 지시나 확정된 기억 정책이 아니다.
기록 목적: 외부사용자 런처의 출발점과 여러 사용자의 작업 경험을 전체 실행기억으로 축적하려는 의도를 보존한다.

## 1. 출발점 — 한 관리자가 여러 사람의 업무 환경을 마련한다

외부사용자 런처의 아이디어는 잘 사용하고 있는 원격런처에서 시작됐다.
원격런처는 주인이 자기 시스템을 원격으로 조작하는 표면이므로, 이를 사무실 직원에게 그대로
제공하면 시스템 자체를 변경하거나 주인 PC의 파일을 건드릴 수 있다는 문제가 있다.

외부사용자는 관리 기능을 제외한 웹앱으로 자기 일을 자기 하드웨어에서 수행한다.
관리자는 모델·도구·업무 환경을 구성하고 여러 사람에게 제공한다. 각 사용자가 시스템을
설치하고 관리해야 하는 부담을 줄이면서, 관리자가 마련한 능력을 함께 이용하는 구상이다.

현재 구현을 읽을 때는 실행 장소를 구분한다. AI 호출과 일부 검색·문서 처리는 허브에서,
파일 보관·다운로드·재생 등의 기기 동작은 사용자 브라우저에서 수행한다.
설치 없는 웹앱이 사용자 PC 전체 파일을 자유롭게 수정한다는 의미는 아니다.

## 2. 사용자가 밝힌 기억 공유의 방향

- 심층기억과 포식기억은 사용자마다 달라야 한다.
- 실행기억과 세계기억 등 공통으로 활용할 수 있는 기억은 공유하는 방향을 생각한다.
- 특히 각자가 작업한 경험이 전체의 경험으로 남기를 바란다.
- 관리자와 외부사용자는 다르므로, 같은 방식으로 생산된 기억이라고 간주할 수는 없다.
- 이런 경험의 축적을 통해 AX를 진행할 수 있지 않을까 하는 문제의식이다.

사용자 발언:

> 나는 작업한 기억이 전체 경험으로 남기를 바래. 다만 외부자와 관리자는 다르지.

따라서 앞선 대화에서 제시된 “개인 사례는 개인에게만 남기고 관리자가 선택한 방법만 공유한다”는
구분을 최종 요구로 고정하지 않는다. 전체가 작업 경험을 통해 학습한다는 의도가 중심이며,
그것이 원본 대화·파일·개인정보를 다른 사용자에게 전부 공개하라는 뜻인지는 별도로 결정해야 한다.

## 3. 사용자가 제기한 미결 질문

1. 외부사용자가 생산한 기억을 임시로 저장한 뒤 공통 실행기억으로 재추출해야 하는가?
2. 어차피 성공한 실행기억만 남는다면 별도 재추출 없이 공유해도 되는가?
3. 누구의 실행에서 나온 기억인지 출처 레이블을 붙여야 하는가?
4. 관리자와 외부사용자의 경험을 어떻게 함께 활용하면서 차이를 보존할 것인가?

“성공한 실행기억만 남는다”는 이번 논의의 가정·질문이다. 이 메모에서 현재 런타임의
모든 기억 저장 경로가 그렇게 동작한다고 검증하거나 선언하지 않는다.

## 4. 대화에서 제안한 검토안 — 아직 채택되지 않음

### 성공과 공유 가능성은 별도로 판단한다

성공한 실행에도 고객 정보·파일 경로·계정 정보가 들어갈 수 있다.
관리자 권한으로 성공한 절차가 외부사용자의 권한이나 다른 기기에서도 실행 가능한 것은 아니다.
성공은 해당 조건에서 방법이 작동했다는 근거이며, 공개 범위와 다른 환경의 적용 가능성은 별도 문제다.

### 후보 흐름

```text
각 사용자의 작업
  → 출처·실행 조건·결과 근거를 포함한 임시 경험
  → 개인 값과 재사용할 방법을 구분하여 재추출
  → 추출된 방법의 유효성·공유 가능성 검증
  → 공통 실행기억에 합류하거나 기존 방법의 근거 보강
  → 현재 사용자의 권한·도구·환경에 맞게 회상하고 실행
```

원본 작업의 성공이 추출·일반화한 방법의 성공까지 보장하지는 않는다.
구체적인 검증 방식과 자동 합류 여부, 관리자 검토가 필요한 조건은 미정이다.
관리자가 매번 승인해야 한다는 요구는 이번 대화에서 확정되지 않았다.

### 출처 레이블의 후보 정보

| 정보 | 목적 |
|---|---|
| 실행 주체 식별자·당시 역할 | 누구의 실행에서 나온 경험인지 추적 |
| 당시 권한·도구·실행 환경 | 적용 가능한 조건과 한계 판단 |
| 원본 경험과 추출본의 연결 | 오학습 원인 확인·수정·철회 |
| 성공 근거·검증 상태 | 경험과 일반화된 방법의 신뢰도 구분 |
| 공개 범위 | 어떤 사용자가 회상할 수 있는지 판단 |

출처와 공개 범위는 서로 다른 축이다. 외부사용자에게서 나온 방법도 공통으로 활용할 수 있고,
관리자에게서 나온 경험도 개인 자료나 관리 권한에 종속되면 그대로 공개할 수 없다.
출처 식별자를 보관하더라도 다른 사용자의 프롬프트에 실명이나 원본 내용을 모두 넣을 필요는 없다.
경험을 공유하는 것이 그 경험을 만든 사람의 실행 권한까지 전달하는 일이어서는 안 된다.

## 5. 다음에 결정할 사항

- “전체 경험으로 남긴다”의 보존 단위: 원본 경험, 개인정보를 제거한 사례, 실행 절차, 집계 중 무엇인가?
- 임시 경험은 어디에 얼마 동안 보관하고, 재추출 후 원본과 연결 정보는 어떻게 처리할 것인가?
- 재추출과 검증을 모든 실행에 적용할 것인가, 외부사용자 실행이나 민감한 작업에만 적용할 것인가?
- 공통 기억의 합류·수정·철회는 어디까지 자동화하고 누가 관리할 것인가?
- 성공 조건이 다른 사례나 서로 모순되는 방법을 어떻게 보존·선택할 것인가?
- 심층기억·포식기억의 개인화와 공통 실행기억의 학습 경계를 어떻게 검사할 것인가?
- 다른 기억 종류의 공유 범위는 무엇인가? 작업·일화기억 전체의 공유 여부까지 확정한 것은 아니다.

## 6. AX 관점의 의미

한 사람이 성공한 업무 경험이 다음 사람의 시행착오를 줄이고, 여러 사람의 실무 경험이
관리자가 처음 마련한 업무 환경을 계속 개선하게 한다. 단순히 설정을 배포하는 단계에서
조직의 업무 방법이 축적되는 공통 기반으로 발전시키려는 구상이다.

이번 기록은 이 방향과 질문을 보존한다. 기존 기억 격리 정책을 변경하거나, 외부사용자의
원본 경험 수집·공유를 새로 활성화하지 않는다.
