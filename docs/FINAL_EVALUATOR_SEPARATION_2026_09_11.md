# 의식 중간관리와 최종 평가의 역할 분리

사용자 결정: 도구를 가진 의식의 계획·중간관리는 유지하고, 최종평가만 통합 전의
도구 없는 평가자로 되돌린다. 최종평가가 직접 조사·편집을 이어가며 작업을 늘리지 않게 한다.

## 근거

실사용 에피소드 3518(2026-09-11 22:42, 첫날 여행 일정·식당 상담)은 총 683.261초였다.
첫 답변까지 약 208초, 첫 평가 약 100초, 실행자 보완 약 273초, 재평가 약 102초였다.
중간 감독은 0회이며, 최종 검수·보완이 약 475초(70%)를 차지했다. 휴무 가능성 누락과
체류시간 100분→80분은 유효한 지적이었지만, 보완 패치 실패와 여러 도구 왕복이 붙었다.
마지막 모델 판정은 APPROVED였으나, 새 증거로 읽기 기록이 초기화되고 지도 JSON 두
블록을 재열람하지 않아 하네스는 UNKNOWN으로 끝냈다. 버전·해시는 일치했다.
과거 원장과 응답 파일은 수정하지 않았다.

## 구현

- `supervisor_runtime`은 계획·재규정·중간관리에만 도구를 제공하고 final 호출을 거부한다.
- `final_evaluator`는 기존 `CognitiveEvalMixin._evaluate_achievement`와 `role="evaluate"`
  원샷을 재사용한다. 제공자는 `tools=[]`, `no_tools=True`, `execute_tool=None`, 독립 호출로 실행한다.
- 하네스가 사용자 원문·제안 기준의 구분·전체 응답·실제 액션 원장·도구 결과 발췌·생성 파일
  본문·이미지·공개 대기 초안·알림을 제공한다. 보완 뒤에는 새 실행 증거를 다시 합친다.
  스트림과 작업대에 중복 기록된 호출은 대응시키고 실제 반복 호출 및 달라진 결과는 보존한다.
- 평가자는 실제 필수 요구 누락·증거 모순·미수행 보고·명백한 산술 오류를 판정한다.
  사소한 표현이나 새 개선 목표는 보완 사유가 아니다. 국소 수정과 새 조사를 구분해 인계한다.
- 감독 턴의 최종 보완은 최대 한 번이다. 기존 실행자가 변경 부분을 수정하고 한 번 재평가한다.
  과거 설정의 max_repairs가 더 커도 이 상한을 유지한다. 감독 비활성의 기존 평가 루프는 그대로다.
- 본문·인용의 페이지 열람 영수증이나 content_checks를 최종 승인 조건으로 요구하지 않는다.
  의미·출처·계수 검토의 근거는 제공된 실행 증거이며, 평가 중 응답·파일·대기열 변경은 지문으로 막는다.
- 승인한 바이트의 공개·알림, 전체 과제 기준을 포함한 완료 처리, 미승인의 성공 학습 제외는 유지한다.
  공개 대기물이 있는 국소 보완은 응답 전용 도구 제한으로 알림 수정이 막히지 않게 한다.
- 원장의 평가 경로는 `goal_eval`, 역할은 `oneshot:evaluate`이다. 에피소드 요약은 최종
  `[GoalEval] 최종 판정`을 우선해 공개 실패 등을 앞선 모델 합격으로 덮지 않는다.
  평가 응답이 UNKNOWN으로 시작하면 설명에 ACHIEVED가 나와도 승인으로 파싱하지 않는다.
  작업대 비용은 중간관리와 최종평가의 호출 횟수·시간을 따로 기록한다.

## 검증

도구 차단·전체 응답 전달·반복 호출 보존·보완 1회 상한·갱신 증거·공개 전 초안/알림
평가·전체 과제 완료·평가 중 파일 변경 거부·최종 판정 추출 회귀가 통과했다.
최종 파서 보완 후 `test_final_evaluator.py`와 `test_goal_eval_streaming.py` 24건도 통과했다.
전체 `.venv/bin/python3 -m pytest backend/ -q --tb=short` 재실행은 종료 코드 0으로 통과했다.
구조·은퇴 계약·IBL 파생물·폰 번들 검사와 `git diff --check`가 통과했다.

실행 중인 백엔드는 공식 `api.py restart` 제어 경로로 새 코드에 재기동했다.
기존 워커는 활성 사용자 턴·완료 처리 없이 `thread:tqdm_monitor`만 남아 일반 drain이
보류됐다. 오래된 재기동 대기를 공식 취소 요청으로 회수한 뒤 제한 시간·force 옵션으로
이 상주 스레드를 정리했고, 새 코드 세대의 `restarted` 결과를 확인했다.

실사용 지연 감소율은 아직 측정하지 않았다. 제공된 증거가 부족한 작업은 UNKNOWN 또는
한 번의 보완으로 끝날 수 있으며, 평가자에게 도구를 다시 주어 조사하는 폴백은 없다.
