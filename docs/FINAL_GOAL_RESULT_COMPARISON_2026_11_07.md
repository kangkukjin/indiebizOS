# 최종 평가의 책임: 사용자 목표와 최종 결과 비교

## 사용자 결정과 범위

2026-11-07 사용자 결정: 평가에 근거물을 계속 모으는 일은 새로운 연구에 가깝다.
최종 평가는 초기 목표와 최종 결과의 비교로 줄인다. 연구 중 사실 확인·실험·자기검사는
실행자가 수행하고, 중간감사의 실행 조정과 최종 결과 비교는 별개 책임이다.

최종 비교의 입력은 사용자 원래 목표와 명시 정정, 최종 응답, 그 응답이 전달하는 파일
본문·이미지 및 공개 대기 초안·알림이다. 내부 계획과 의식이 만든 조건을 추가 요구로
사용하지 않는다. 비교 결과의 `method=goal_result`는 목표 부합성을 뜻한다.
외부 사실·실험·인용을 독립 검증했다는 뜻이 아니다.

## 반복 실패의 원인

연구 에피소드 5892는 보고서가 정상 저장됐지만 최종 검수에서 `created_files=없음`이었다.
기존 수집은 파일의 제출 여부를 작성 도구와 영수증 형식에서 추정했다. 이번 셸의 반환은
`report` 키였고, 최종 답변의 명시적 보고서 링크도 관측된 출력 후보가 아니면 읽지 않았다.

앞선 `33ad4bd6`은 수집 자료가 제출물을 밀어내던 배분을, `90895480`은 네이티브 편집
영수증 연결을 고쳤다. 모두 특정 생산 경로의 수리는 됐으나, **최종 결과를 읽는 일과
그 결과를 어떻게 만들었는지 증명하는 일의 결합**을 그대로 유지했다.

또 입력 원장의 투영에서 원문 길이를 버려, 15,901자 증거에 대한 24,000자 요청이 유효로
처리된 후 실제 읽기에서 실패했다. 평가 자료 선택·범위 회수·재실행이 연결되면서 작은
전달 결함이 새 연구와 재검수의 조건으로 커졌다. 이번 변경은 이 복구 프로토콜에 예외를
더하지 않고 최종 비교에서 실행 증거의 수집·요청·회수 자체를 제거한다.

## 구현과 대체한 경로

- `supervisor_content.discover`: 최종 응답의 명시 파일을 직접 읽는다. 생성 영수증·도구
  이름으로 제출 여부를 판정하지 않으며, 본문의 인용 링크를 재귀 수집하지 않는다.
- `final_evaluator.prepare`: 최종 결과와 해당 바이트 지문을 고정한다. 실행 이력 병합,
  산술·assertion 근거, 연구 질문·인용 원문, 보완 증거, 이전 판본 diff를 입력에 넣지 않는다.
- `cognitive_eval._evaluate_achievement`: 사용자 목표·정정과 최종 결과를 전문으로 전달한다.
  근거별 우선순위·발췌 대신 `CompleteInput`이 기존 전체 전송 한도를 확인한다. 넘으면
  `input_too_large`로 마치며, 누락된 본문을 본 것처럼 판정하지 않는다.
- 감독·비감독 최종 경로 모두 한 번 비교하고 판정을 반환한다. UNKNOWN의 증거 회수,
  NOT_ACHIEVED의 실행자 재호출, 최종 응답 자동 패치 루프를 제거한다.
- 원래 사용자 목표·정정과 제출물 판본이 비교 중 바뀌면 승인을 무효화한다. 공개 대기
  초안의 지문 확인과 승인 전 발행 차단은 유지한다. 연구 실행·중간감사의 도구와
  사용자가 승인한 자기수리의 적용·재개 제어는 해당 소유 경로에 남는다.

최종 평가자 프롬프트·의식의 역할 설명·프롬프트 구성 화면·장기 구조 문서를 함께 갱신한다.
이전 근거 재감사 설계 문서의 최종 평가 관련 부분은 이 결정으로 대체한다. 연구 자료의
저장·조회 기능과 개별 근거의 불변성 검사는 연구 실행에서 계속 사용할 수 있다.
