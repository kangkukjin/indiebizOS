# 한글 관용구 계측과 시험 원장 격리

2026-09-14. 실행 가능한 한글 관용구가 통계에서 0으로 보이는 결함을 수리했다.

## 원인과 수정

`system_tools_ibl._execute_ibl_unified`는 실행 파서와 별개로 영문 전용 정규식으로
`actions`를 추출했다. 실행은 성공해도 `[fn:주소마다읽기]`는 목록에 남지 않았다.
`에피소드통계`는 그 목록을 세어 잘못된 0을 표시했다.

- 기록기를 기존 `ibl_scanner.source_heads`에 연결했다. 한글·공백 표기를 받아들이고,
  문자열·주석 속 호출 예시는 제외한다. 새 문법이나 별도 스캐너를 만들지 않았다.
- `ibl.started.fn_count`는 전체 원문의 fn 머리 수다. actions의 표시 상한 100개와
  무관하게 기록한다. 원문에 작성된 구문 수이며 성공 횟수나 분기·반복의 실행 횟수가 아니다.
  지연 do 문자열 안의 코드는 이 원문 지표에 포함하지 않는다.
- 구판 사건은 `code_sha256`으로 코퍼스를 연결해 같은 스캐너로 읽을 때 복원한다.
  동일 해시가 여러 호출에 등장하면 사건마다 센다. 과거 append-only 원장은 수정하지 않는다.
  원문도 없는 구판은 `fn=null`·`fn미측정`으로 표시하고 합계에서도 0으로 바꾸지 않는다.
- 모든 pytest 회귀의 기본 `episode_logger._get_db`를 테스트별 임시 DB로 연결했다.
  DB는 테스트 대상 폴더 밖의 형제 저장소에 두어 파일 목록·산출물 검사에 섞이지 않는다.
  개별 테스트의 명시적 DB 대역은 계속 사용할 수 있다. 시험 표식은 그대로 유지한다.
  기존 test 행이나 usage와 합산된 과거 누계는 삭제하거나 추정해 재작성하지 않는다.
- `fn_recognizer.corpus_stats`의 시험 전용 행을 실사용 반복의 근거에서 제외했다.
  함께 확인된 경로 함수 import 오류도 정본 `runtime_utils.get_base_path`로 고쳤다.

관용구의 always_on 설정·등록 목록·실행 본문은 변경하지 않았다.

## 검증

관련 회귀는 실제 관용구 실행과 기록의 연결, 한글·공백 이름, 문자열/주석의 가짜 호출,
100개 미리보기 밖의 fn, 같은 원문을 두 번 호출한 과거 사건, 원문 없는 과거 사건의
개별·합계 표시, 임시 DB 기록과 시험 전용 행의 반복 인식 제외를 확인한다.

운영 DB 읽기 전용 확인에서 과거 에피소드 3781/3782/3783의 fn은 각각 0/4/3으로
복원됐고 세 건 모두 fn미측정은 0이었다. 모델을 다시 호출하거나 원래 작업을 재실행하지 않았다.

전체 백엔드 회귀는 4,329건 통과·1건 건너뜀·1건 실패였다. 실패는 격리 DB가 테스트
대상 폴더 목록에 나타난 것이며, 위 형제 저장소로 옮겨 수정했다. 이후 관련 62건을
함께 재실행해 모두 통과했다. 전체 검사를 다시 실행한 결과는 아니다.
검사 전후 운영 코퍼스의 시험 전용 행은 4,123건, 누계는 17,903회, 마지막 기록 시각도
그대로였다. IBL 파생물·폰 번들·층 구조 검사를 통과했고 적용된 백엔드 ACTIVE를 확인했다.
