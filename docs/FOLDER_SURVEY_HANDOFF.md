# 폴더 조사(Folder Survey) 핸드오프 — 포식 기억의 예산·축척·겹침 (2026-09-03 설계)

*성격: 설계 결정화(사용자와의 대화에서 확정된 개념). 아직 코드 아님. 선행 정본: `FORAGER_MEMORY_SCHEMA.md`(저장소 2층·defeasible·provenance), `FORAGER_MEMORY_GUIDE.md`, `FILE_FORAGING_RESEARCH.md`. 실증 사례: 블로그 폴더 라우팅 사전(커밋 `76f46d68`, `guides/blog.md`).*

> 한 줄: **폴더 하나를 지명하면 AI가 예산 안에서 그 폴더를 조사해 두 층(정리의 판단 + 아이템 속성)을 저장하고, 다음 질문부터 회상이 그것을 자동으로 쓴다.** 전체는 낮은 해상도, 지명한 곳은 높은 해상도 — 중심시/주변시 구조.

## 0. 왜 (실증)

- **블로그 실험(2026-09-02~03)**: 수천 편·수십 폴더에 주인이 "왜 이렇게 나눴나·판별어·예외"를 사전으로 적자, RAG 만으로 못 찾던 글이 잡혔다. 뿌리 수리 후(폴더 라벨을 임베딩·필터에) 단어 질의 재현율 0→4건, 폴더 필터로 폴더 전부 회수. **엔진은 폴더의 *라벨*(무엇)을 알고 사전은 폴더의 *이유*(왜)를 안다 — 어느 쪽도 상대를 대신 못 한다.**
- **미디어 폴더 실측**: 천여 편, 한 층에 여러 축이 섞임. 폴더 지식만으로는 매 질문 천여 개 이름을 다시 읽어야 한다 → **아이템 목록 층이 같이 필요**(블로그는 posts 색인이 이미 있었다).
- **조금씩 쌓기의 실측**: 포식 기억은 대화 턴 종료 후 그 턴만 보고 증류되는 경로뿐이라 74일간 폴더 정체 30건(하루 0.4건). 폴더를 훑어서 생기는 기억은 0. **투자(조사)가 본체, 조금씩은 수정.** 원 설계의 "선스캔 캐시 금지"는 *캐시*(파일 목록·내용 요약)에 대한 것이었고 *판단*(축·예외·배제)까지 막은 과잉 일반화였다.

## 1. 개념 — RAG 와의 관계

RAG 는 **내용**을 색인한다. 폴더 조사는 **내용에 없는 것** 둘을 색인한다: ①사람이 아이템을 놓을 때 새긴 *정리의 판단* ②파일명·위치에 담긴 *아이템 속성*. 보완 관계 — 에이전트는 둘 다 쓴다(블로그: 노트북 ask → category 필터 검색).

### 두 층
| 층 | 내용 | 거처 |
|---|---|---|
| **폴더 지식** | 분할의 축 · 겹치는 축 · 명명 관습 · 예외의 위치 · 죽은 가지 · 기질(외장·마운트·포맷) · **주제어** | `forage_map`(kind=identity/convention/dead_branch/substrate) + territory 앵커 1 |
| **아이템 목록** | 파일마다 **유형별 추출기**가 뽑은 속성 — 영상: 제목·연도·자막·부속 / 논문: 제목·저자·연도·초록 첫 문단 / 사진: 촬영일·GPS·기기 / 문서: 제목·첫 줄 | 파일 색인(path/name/ext/mtime/kind) 위에 추출 속성만 보탬. 추출기는 있는 패키지(사진 EXIF·노트북 PDF 본문·mdls)를 재사용. **무엇이든 들어갈 수 있으나 제약 셋**: 조사 예산(아이템 상한) · 필드 화이트리스트(찾기·라우팅에 쓰이는 속성만, 본문은 RAG 몫) · 유형별 추출기가 없는 파일은 이름만 |

### 세 출처 (provenance 로 구분, 한 저장소)
- **선언**(주인) — AI 가 못 지움, 의심 표식만.
- **관찰**(AI 조사) — defeasible, prune_reason.
- **제안**(AI 가 정리하며 만든 폴더+이유) — 승인 대기, 승인되면 선언으로.

## 1.5 입구 둘 — 말과 앱, 같은 기록
- **말**: "이 폴더 조사해" → AI 가 가이드(disk_search §1b)대로 스크립트를 부르고 report 를 읽어 판단을 note 한다.
- **앱(계기)**: 폴더를 고르면 같은 스크립트를 부르고, 만들어진 사전을 사용자가 고쳐 승인한다.
둘은 **같은 원장·같은 단언 저장소**에 쓴다 — 입구가 둘이지 시스템이 둘이 아니다. 갱신도 같다: 재조사(차이만) + 사용자 편집 + AI 정리 제안(승인 전 '제안' 출처).

## 2. 예산과 축척

**조사 예산**(생산)과 **회상 예산**(소비, 프롬프트 토큰)은 다른 예산이다. 회상 예산은 이미 메모리 계층(상주 골격 / 페이징 상세 / 콜드 포식, `disk_skeleton`)이 다룬다. 이 문서는 조사 예산.

- 조사 = 예산 안의 **투영**(축적 아님). 백만 파일의 디스크 전체 조사 = 골격(자식 폴더마다 한 줄 + 전체의 축·관습·기질)에 예산을 씀. 하위 폴더 지명 = 그 부분 나무에 예산을 **새로** 써서 축척을 올림. 아이템 목록은 조사가 아이템 축척까지 내려간 자리에만.
- **조사 원장**(신규, 작음): `survey(locus, body, surveyed_at, depth, budget_spent, dir_mtime, item_resolution 0/1)`. "어디에 얼마나 썼나"가 곧 해상도 지도. AI 는 이걸 보고 "이 폴더는 아직 거칠다"를 알고 추가 조사를 제안한다.
- 상위 조사는 **표본**으로: 골격 걷기는 수백 ms(실측), AI 가 자식마다 이름+파일 몇 개를 보고 한 줄. 예산 단위는 열린 질문(§7).

## 3. 겹침 규칙 (바탕화면 조사 ⊃ 바탕화면/AI 조사)

1. **상속**: 조상의 단언 중 `generalizes=1`(명명 관습·기질·배제 규칙)은 하위에 적용.
2. **가림**: 같은 자리에 대해 더 구체적 locus 의 단언이 조상의 한 줄을 이긴다. 조상의 한 줄은 **지우지 않는다** — 조상 축척의 회상에선 그 크기가 맞다.
3. **모순의 신고**: 하위 조사가 조상의 한 줄과 어긋나면 조상 항목에 `surface_flag`. 하위 재조사가 조상을 공짜로 검증한다.

**위치 기반 회상**(✅ `recall{locus}` — 자동 주입 없음, AI 가 지명해 묻는다): 지명한 locus 에서 → 조상에서 상속분 → 그 자리의 자기 단언 → 자식 골격 한 줄씩, 회상 예산 안에서. 가장 세밀한 조사가 있는 자리까지만 내려간다. 주제어 필드가 낱말 일치의 약점을 메운다.

## 4. 신선도 — 축척별

각 조사는 자기 locus 의 `dir_mtime` 만 본다. 하위 파일이 바뀌어도 상위 축척의 한 줄은 안 낡는다. 갱신 = 차이만 재조사. 아이템 목록은 mtime 차이로 증분.

## 4.5 기존 포식 기억의 흡수 — 병렬 시스템이 아니라 한 위계
지금 있는 것들은 **이 위계의 축척들**로 자리를 옮긴다. 새 저장소를 만들지 않는다.
| 기존 | 이 시스템에서의 자리 |
|---|---|
| `disk_skeleton`(집중 폴더 아래 디렉토리 트리, 상시-on) | **0 예산 조사** = 가장 거친 축척(폴더 이름만). 위계의 뿌리 |
| `focus_folders.json`(집중 관심 폴더) | 조사 후보의 기본 목록 — 앱의 "조사할 폴더" 첫 화면 |
| `forage_map`(단언) | 그대로 **이 시스템의 단언 저장소**. 출처(provenance)로 선언/조사/증류/제안 구분 |
| 대화 턴 종료 후 증류(note_map 자동) | **'조금씩 수정' 채널** — 같은 저장소에 provenance=distilled 로. 조사가 본체, 증류가 수정 |
| `owner_model`(주인 모델) | 몸 독립 층 그대로 — 취향·습관은 조사가 못 만든다 |
| `[self:forage]{recall/note/forget}` | 어휘 불변. recall 에 `locus`(폴더 지명 통째) — **자동 주입은 폐지**(2026-09-03 사용자 판정: 기억이 많으면 '무엇을 넣나'가 판단이 되고 그 판단은 AI 것). 시스템 프롬프트가 "위치 질문이면 답하기 전에 recall" 을 말하고, 어휘가 기억의 입구다 |
| 조사 원장 `survey` | 신규 — "어디에 예산을 썼나" |

## 5. 표면 — 앱은 계기, 어휘 불변

- 새 낱말 없음. 조사 절차 = `[self:script]` 로 얼림(있는 동사: fs_query/find/read + `[self:forage]{op:"note"}` + 파일 색인). 헌법 "새 낱말의 기본 답 = 아니오".
- 앱(계기, `custom_app_instrument.md` 규약) 화면 셋: ①조사된 폴더 목록 + 신선도 + 해상도 ②조사/갱신 버튼(폴더 선택) ③만들어진 사전 편집·승인(선언 층 입력).
- 가이드 통로: 파일 찾기 가이드에 "포식 회상 → 아이템 목록 → 파일시스템" 순서를 적는다(결정화의 나머지 절반 — 통로 없는 결정화는 매번 재발명).
- **개인정보 경계(사용자 판정 2026-09-03)**: 조사 산출물·단언·사전은 저장소 밖(gitignore)이고, **문서·changelog·커밋 메시지에도 그 내용(장치 경로·폴더명·제목·편수)을 옮겨 적지 않는다 — 기제만 적는다.** 포식 기억은 개인정보다.
- 몸 가로지르기: locus 는 몸 기준 토큰(`~workspace/`)·볼륨 라벨. 폴더 지식=몸별(`forage_map.body`), 취향=몸 독립(`owner_model`).

## 6. 짓는 순서 · 측정

1. **조사 스크립트 + 사전 형식**(축·겹침·관습·예외·죽은 가지·기질·주제어) + 조사 원장. 첫 대상 = 축이 섞이고 파일명이 풍부한 미디어 폴더(두 층의 값이 다 드러남).
2. 위치 기반 회상(상속·가림·골격) + 주제어 매칭 + 가이드 통로. — ✅ 2026-09-03 구현(`_assemble_by_locus`, 2-gram 매칭, `<surveys>` 힌트, 가드 `test_forage_location_recall.py`).
3. 앱 계기.

측정 = 블로그 방식 그대로: 폴더 몇 개, 같은 질문의 **왕복 수·재현율** 조사 전후 비교. 유사도 상승은 근거가 아니다(질의 길이 교란).

## 7. 열린 질문

- 조사 예산의 단위: 단언 수 / 읽은 파일 수 / 토큰 / 시간 — 상위(골격)와 하위(아이템)에 다른 단위가 맞을 수 있다.
- 아이템 목록의 거처: 파일 색인 확장 vs json 원장(폴더별) — 파일 색인 확장이 "새 물질화 그래프 금지" 헌법에 가깝다.
- 제안 층(AI 가 정리)의 승인 UI 와, 승인 전 제안이 회상에 섞일지.
- 취향(좋았던 것·다시 볼 것)은 조사가 못 만든다 — 질문 때마다 한 마디씩 선언 층에 쌓는 이음매.
