# 포식 기억의 근거와 의미를 보존하는 수리 계획

작성일: 2026-10-18. 상태: **수리 계획 작성 완료, 구현 전**.

포식 기억을 다시 사용할 때 무엇을 보고 얻은 지식인지, 어디까지 적용되는지,
그 근거가 지금도 같은지를 알 수 있게 한다. 동시에 자료를 사용하며 발견한 뜻을
장소의 기억으로 축적하고, 다음 작업에서 그 뜻과 근거를 함께 회수한다.
AI가 조사하고 의미를 판단하며, 시스템은 관측의 범위·판본·연결을 보존한다.

목적과 개발 기준은 [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)을 따른다.
앞선 [호출 계약 수리](CALLABLE_COMPONENT_REPAIR_DESIGN_2026_10_18.md)에서 제외했던
포식 기억의 두 과제를 구체화한다. 가이드 전체 지문 정책은 이 계획의 대상이 아니다.

## 1 현재 구조와 수리 대상

현재 포식 기억은 장소별 `memory.md`의 `## 단언`이 정본이고 SQLite는 색인이다.
단언은 자연어이며 `kind`, `prior_class`, `generalizes` 등으로 성격과 상속을 표시한다.
`provenance`도 이미 있고, 자동 증류는 실제 도구 관측이나 사용자 선언을 근거로 받는다.
따라서 의미와 출처가 전혀 없는 구조를 새로 만드는 작업은 아니다.

| 현재 경계 | 확인된 제약 | 수리 목표 |
| --- | --- | --- |
| 단언과 실제 자료 | `locus_mtime`은 locus 하나의 stat이다. 폴더 안 파일의 내용 변경을 놓칠 수 있다 | 실제 관측 대상과 조사 범위를 근거로 변경을 판정 |
| 관측과 저장 | 자동 증류가 도구 결과 지문을 남기지만, 그 지문만으로 원천 파일의 현재 판본을 비교할 수 없다 | 도구 반환의 판본과 원천 자료의 판본을 구별해 보존 |
| 문서와 색인 | 문서 렌더는 출처의 짧은 표시를 남기고 파서는 상세 provenance를 복원하지 않는다 | 문서에서 근거와 의미의 연결까지 재색인 가능 |
| 일반화와 축적 | 통합 증류 프롬프트와 적용기가 `generalizes:true`만 받는다 | 특정 자료에만 적용되는 지속적인 의미도 저장 가능 |
| 의미와 발견 | 장소 검색은 단언과 `찾는 말`을 사용하며, 장소를 지정하면 단언을 회수한다 | 이 경로로 의미와 사용 조건을 함께 발견하고 상세 근거로 이동 |

근거: [포식 저장과 회상](../backend/datastore/forage_memory.py),
[문서 렌더와 동기화](../backend/datastore/forage_doc.py),
[증류 준비와 적용](../backend/cognition/distill_memory_adapters.py),
[통합 증류 계약](../backend/cognition/unified_distill.py),
[장소 검색](../backend/datastore/forage_recall_store.py).
과거 `FORAGER_MEMORY_SCHEMA.md`의 주인모델·자동 주입 설명을 현재 기능으로 복원하지 않는다.
현재 포식 회상은 [공통 연상 흐름](../backend/cognition/associative_recall.py)의 `auto=False`를 유지한다.

## 2 설계 원칙과 완료 범위

한 단언을 **뜻과 적용 범위, 관측 근거, 현재 확인 상태**의 연결로 다룬다.
자료의 의미는 자유로운 문장으로 적는다. 주문·결제·논문·사진 같은 분야별 필드를
코어에 추가하거나, 모든 자료에 단위·행·키 양식을 채우게 하지 않는다.
기계가 공통으로 구조화할 부분은 출처 주소, 관측 범위, 판본과 확인 결과다.

문서가 정본인 원칙, 기존 주체·장소 경계, `surface_flag`와 폐기 가능한 단언,
명시적인 `[self:forage]` 회상을 유지한다. 별도 의미 사전, 상시 프롬프트 블록,
전 디스크 감시기, 매 회상마다의 모델 호출을 추가하지 않는다.

첫 구현은 로컬 파일과 명시적으로 조사한 디렉터리 목록의 판본 대조를 완성한다.
웹·책·노트북도 의미와 출처를 같은 형식으로 저장하되, 기존 출처 제공자가 비교 가능한
판본을 주지 않으면 현재성은 미확인으로 반환한다. 회상이 임의의 네트워크 재조사를 시작하지 않는다.

## 3 근거와 조사 범위를 기록한다

### 단언과 근거의 연결

기존 `provenance` 안에 판본 있는 `evidence` 구조를 추가한다. AI는 이번 작업에서
실제로 받은 관측의 참조를 선택하고, 시스템이 참조를 해소해 출처와 판본을 채운다.
AI가 써 준 해시나 `complete:true`를 검증된 관측으로 받아들이지 않는다.

| 근거 요소 | 저장할 뜻 |
| --- | --- |
| 관측 참조 | 기존 증류 job과 observation ID, 또는 해소 가능한 도구 영수증 참조 |
| 출처 | 몸·주소·출처 종류. 원천 파일과 도구 반환을 별도로 식별 |
| 관측 내용 | 파일 본문, 본문의 일부, 디렉터리 목록, 명시적 사용자 선언 중 무엇을 보았는가 |
| 조사 범위 | 읽은 부분, 열거한 루트·깊이·필터·제외 조건, 완전성 및 절단 사유 |
| 판본 | 실제 읽은 바이트나 정규화된 목록의 지문, 비교 방법과 관측 시각 |
| 연결 상태 | 기계 관측으로 연결됨, 사용자 선언, 이전 자료로서 판본 없음 등을 구분 |

근거 참조의 수명보다 기억이 길 수 있으므로 비교에 필요한 작은 판본·범위 정보는
기억 문서에 남긴다. 원문 전체를 복제하지 않는다. 원문 영수증이 만료돼도 저장된
지문과 범위는 남고, 원문 열람 가능 여부는 현재성 판정과 별도로 표시한다.

### 관측 시점의 판본

원천의 판본은 실제 읽기·열거 경계에서 확보한다. 증류 시점에 파일을 다시 stat한 값을
옛 관측의 판본으로 소급하지 않는다. 읽기 전후 파일 상태가 달라지거나 열거 중 변경을
탐지하면 그 관측은 불안정으로 기록하고, 완전한 기준선으로 사용하지 않는다.
원자적 스냅샷이 없는 파일시스템을 한 시점의 완전한 스냅샷이라고 표현하지 않는다.

전체 파일 관측은 바이트 지문을 비교 기준으로 삼는다. 메타데이터만 비교한 결과는
`metadata` 수준으로 표시하고, 같은 mtime·크기라는 이유로 내용까지 같다고 확정하지 않는다.
부분 읽기는 해당 부분과 읽기 방식에만 근거가 있다. 비교 가능한 부분 지정자를
제공하지 못한 도구의 관측은 원문 반환의 지문만 보존하고 현재 원천과의 비교는 미확인으로 둔다.

디렉터리는 이름·상대 경로·종류로 구성된 목록을 정렬해 지문을 만든다.
이 지문은 파일의 추가·삭제·이름 변경을 비교하며 파일 내용의 동일성을 보장하지 않는다.
내용에 대한 단언에는 실제 읽은 파일의 근거를 별도로 연결한다.
깊이 1 목록은 바로 아래만 설명하고, 재귀 조사와 동일하게 취급하지 않는다.
표본·검색 결과·잘린 목록으로 폴더 전체의 부재를 증명할 수 없다.

### 수집 경로

기존 도구 관측을 증류 큐에 넘기는 경계에 출처 판본과 범위를 전달한다.
`prepare_forage`는 자유문에서 주소를 추출한 결과와 출처 제공자가 증명한 읽기 대상을 구분한다.
`apply_forage`는 실제 관측 ID·주소·범위를 대조한다. 현재의 도구 결과 완전성 검사와
자동 `dead_branch` 거절을 유지한다.

직접 `note`는 기존 provenance 입력 안에서 관측 참조를 받을 수 있게 한다.
참조의 주체·몸·접근 범위를 검증한 뒤 공통 해소기로 연결한다.
참조 없이 사람이 적은 단언도 저장할 수 있지만 기계 관측으로 표시하지 않는다.
경로를 지정했다는 이유만으로 `note`가 임의의 파일 전체를 읽어 근거를 만들어 주지 않는다.

## 4 문서 정본에서 근거를 왕복 보존한다

`## 단언`의 사람이 읽는 문장과 표식은 유지한다. 새 단언에는 기계가 발급한
문서 내 안정적인 참조 ID를 붙이고, 같은 문서의 `## 근거`에 버전 있는 JSON 블록으로
해당 ID의 출처·조사 범위·판본을 보존한다. JSON은 기계가 만들며 사람이 양식을 채우지 않는다.
상세 근거를 별도 수기 원장이나 DB 전용 사실로 두지 않는다.

단언 본문·장소·종류·적용 범위의 지문을 근거 연결에 함께 둔다. 사람이 문장을 고쳐 뜻이
달라지면 이전 관측이 새 문장을 뒷받침한다고 자동 인정하지 않는다. 연결을 재확인 필요로
표시한다. 단순한 공백 정규화는 현재 `_claim_key`의 규칙을 공유한다.
같은 ID를 복제하거나 충돌하는 근거를 적으면 명시 오류로 돌려주고 부분 덮어쓰기를 하지 않는다.

`render_section`·`parse_section`·`sync_doc_to_db`를 함께 확장한다. 문서→색인→문서 왕복과
빈 색인에서의 재생성으로 근거가 보존돼야 한다. 단언 삭제는 그 근거 연결도 제거하고,
문서 분할·하위 노드 이동은 소유 단언과 근거를 같이 옮긴다. `_gone` 처리는 기존 정책을 따른다.
기존 증류 영수증의 pending projection과 문서 변경 대조를 재사용해 중단·동시 편집을 처리한다.

옛 문서는 그대로 읽는다. 상세 근거가 DB에 남아 있으면 최초 이관에서 문서에 옮기고,
지문이 없는 옛 출처는 `legacy`로 보존한다. 현재 파일을 읽어 과거 관측처럼 채우지 않는다.
옛 바이너리는 새 근거 절을 이해하지 못하므로 새 형식 쓰기는 지원하는 몸에서만 허용하며,
롤백은 이관 전 백업과 짝을 맞춘다. 구버전의 쓰기를 통한 무손실 왕복을 보장하지 않는다.

## 5 회상에서 무엇이 확인됐는지 드러낸다

`freshness`의 기존 `stale`·`missing` 표시는 호환용으로 유지하고 상세 `evidence_status`를 추가한다.
새 상태를 소비하는 포식 핸들러·표시·증류·정리 경로를 함께 갱신한다.
빈 `freshness`는 여전히 최신 보증이 아니며, 새 상태를 숨긴 채 빈 값만으로 판단하지 않도록 한다.

| 상태 | 정확한 뜻 |
| --- | --- |
| `unchanged` | 명시된 범위와 비교 방법으로 필요한 근거를 모두 대조했고 변화가 관측되지 않음 |
| `changed` | 연결된 근거 중 하나 이상의 판본이나 조사 대상 집합이 달라짐 |
| `missing` | 접근 가능한 몸에서 근거 대상의 삭제를 확인함 |
| `unknown` | 미연결·옛 자료·미지원·권한·오프라인·예산 초과·불안정 관측 등으로 충분히 확인 못 함 |

상태에는 `checked_at`, 비교 방법, 확인·미확인 근거 수, 사유와 근거별 결과를 붙인다.
변경된 근거가 있으면 전체 상태는 `changed`, 삭제만 확인되면 `missing`, 그 밖의
미확인 근거가 있으면 `unknown`, 모두 대조됐을 때만 `unchanged`다.
서로 다른 실패는 근거별 결과에서 보존한다. 외장 볼륨 미연결을 삭제로 처리하지 않는다.
사용자 선언은 선언한 사실의 출처이며, 현재 자료의 내용 검증을 대신하지 않는다.

근거가 달라졌다는 사실은 단언이 거짓이 됐다는 판정이 아니다.
회상은 원 단언과 변경 사유를 함께 보여 주고 AI가 다시 읽어 유지·수정·폐기하도록 한다.
코드는 자동 삭제하거나 confidence를 임의로 재조정하지 않는다.

### 확인 비용과 호출 계약

`recall`에 선택 인자 `evidence_check`를 제안한다. `metadata`가 기본이며,
`content`는 이번 작업에 실제로 쓰는 장소의 근거를 내용으로 대조할 때 사용한다.
기존 동사 안의 선택 인자이며 새 IBL 액션을 만들지 않는다.
기본 경로가 내용을 읽지 않았으면 비교 방법을 표시하며, 내용 동일성을 요구하는
근거의 전체 확인 상태는 `unknown`으로 남긴다.

먼저 기존 검색으로 장소와 반환 단언을 정한 뒤 그 근거만 확인한다. 장소를 명시한 회상의
단언 전체 반환 원칙을 유지하고, 확인 예산 때문에 단언 자체를 숨기지 않는다.
한 호출에서 같은 파일은 한 번만 대조한다. 서로 다른 호출에 걸친 mtime 캐시는
내용 동일성의 증거로 승격하지 않는다.

대조기는 호출의 시간·열거 항목·읽기 바이트 예산을 받아 검사하며, 소진되면 검사한 범위와
미검사 사유를 반환한다. 구체적인 기본 예산은 구현 단계의 대형 자료 시험으로 결정하고
코드의 한 설정에 명시한다. 예산이 설정되지 않은 무제한 재귀·전체 해시는 허용하지 않는다.
디렉터리의 새 파일 탐지는 저장된 열거 범위를 다시 비교해야 하며, 기존 파일 목록만
stat해서 그 범위에 추가가 없다고 말하지 않는다.

검사 시점 이후 자료가 바뀔 수 있으므로 결과는 그 시점의 관측이다.
계산에 실제 사용하는 입력은 해당 작업에서 읽은 판본으로 고정하거나 실행 경계에서 재확인한다.

## 6 자료를 사용하며 발견한 의미를 축적한다

### 무엇을 남길 것인가

기존 종류와 `prior_class:semantic`을 사용한다. AI가 자료의 해석·선택·결합에 재사용할
가치가 있다고 판단한 사실을 자연어 단언으로 남긴다. 다음은 작성 가능한 내용의 예이며
필수 양식이나 새 kind 목록이 아니다.

- 이 표의 한 행은 결제가 아니라 주문 항목이다.
- 이 금액 열은 천 원 단위이며 취소 항목도 포함한다.
- 원본은 수집 폴더에 있고 보고서 폴더의 파일은 계산 결과다.
- 두 자료는 고객 번호로 연결하지만 특정 기간 이전 자료에는 그 번호가 없다.

적용되는 파일·자료 묶음을 locus와 문장에 밝히고, 실제로 확인한 헤더·설명·관측을 근거로
연결한다. 일부 행을 보고 전체 자료의 관습으로 일반화했으면 그 추론과 표본 범위를 드러낸다.
원천에 명시된 설명, 사용자 선언, AI의 해석을 provenance에서 구분하고,
근거가 있다는 사실만으로 AI 해석이 옳다고 보증하지 않는다.

### 증류와 상속을 분리한다

지속적인 재사용 가치와 하위 장소로의 일반화는 다른 판단이다.
`unified_distill`과 `apply_forage`를 함께 고쳐 `generalizes:false`도 허용한다.
예를 들어 특정 CSV의 단위는 다음 회차에도 쓸 수 있지만 그 폴더의 모든 CSV로 상속해서는 안 된다.
기존 단언의 기본값은 바꾸지 않고, 새 증류는 근거가 뒷받침하는 범위만 선택하게 한다.

기존 통합 증류 호출에 의미·사용 조건·적용 범위에 대한 판단을 포함한다.
추가 모델 호출이나 모든 파일을 정기적으로 읽는 별도 루프는 만들지 않는다.
현재 `SAME` 처리가 반환만 하고 끝나는 경계도 정리한다. 같은 문장을 다시 말했다는
이유로 강화하지 않고, 새로운 실제 관측이 연결됐을 때만 근거를 추가·재확인한다.
작업 재시도는 기존 candidate_key와 영수증을 사용해 중복 저장하지 않는다.

충돌하는 단언은 자동으로 하나를 정답으로 고르지 않는다. 기존 UPDATE·surface 표식을
사용해 원 단언과 새 근거를 보존하고, 회상에서 충돌과 적용 범위 차이가 드러나게 한다.
일반적인 작업 절차는 가이드·실행기억, 주인에 대한 사실은 심층기억이라는 경계도 유지한다.

### 다음 작업에서 실제로 찾게 한다

장소를 모를 때는 기존 `찾는 말`과 단언을 사용하는 `ForageStore`로 후보를 찾고,
주소를 지정한 회상으로 의미·적용 범위·상태·근거 문서 위치를 함께 얻는다.
상세 근거 JSON을 검색 본문이나 상시 프롬프트에 통째로 넣지 않는다.
문서에서 찾아볼 수만 있고 회상 결과에는 빠지는 구현은 완료로 보지 않는다.

장소 후보 본문은 현재 길이 제한이 있으므로 의미 단언이 늘어도 조용히 검색에서 사라지지
않는지 시험한다. 필요하면 기존 검색 저장소 안에서 단언별 조각으로 색인하고 결과를
장소로 합친다. 별도 의미 검색 서비스를 만들지 않고 절단·누락 여부를 관측 가능하게 한다.
단언·찾는 말·근거가 수정되면 기존 장소 검색 캐시와 색인도 무효화한다.

## 7 변경 위치와 구현 순서

| 단계 | 주요 변경 위치 | 완료 조건 |
| --- | --- | --- |
| A 문서 왕복과 이관 | `forage_doc.py`, `forage_memory.py`, 기존 `tree_doc.py` 연결 | 상세 근거를 포함해 문서만으로 색인 재생성, 옛 문서 보존, 중단 복구 |
| B 관측과 현재성 | 도구의 읽기·열거 반환 경계, `distill_memory_adapters.py`, `forage_memory.py` | 실제 관측의 범위·판본 연결, 제한된 대조, 네 상태의 정확한 반환 |
| C 의미 축적 | `unified_distill.py`, `distill_memory_adapters.py`, `cognitive_distill.py`의 잔존 입구 대조 | 일반화하지 않는 의미 저장, 새 근거로만 재확인, 충돌 보존 |
| D 회상과 교재 | `forage_recall_store.py`, pc-manager의 `handler.py`·`ibl_actions.yaml`, 관련 가이드·memory 문서 | 의미로 장소 발견, 장소 회상에서 의미·근거·확인 상태 연결, 공개 계약 일치 |

기계적인 근거 해소·대조가 기존 모듈을 비대하게 만들면 datastore 층의 작은 공통 모듈로
분리한다. 신규 backend 모듈은 층 검사에 등록하고 파일 1500줄 제한을 지킨다.
실제 읽기 도구의 출처 생산자는 구현 착수 시 추적해 확정하고, 기존 자료·영수증
포맷이 충족하는 범위는 재사용한다. 포식 전용 읽기 도구를 따로 만들지 않는다.

`forage_consolidation.py`의 병합·삭제·상속 조정도 근거 연결을 보존해야 한다.
동일 단언의 근거 추가와 의미 변경을 구별하고, 직접 note·문서 편집·통합 증류의
세 쓰기 경로가 같은 검증과 직렬화를 쓰도록 한다.

## 8 검증과 인수 기준

| 검증 축 | 반드시 통과할 사례 |
| --- | --- |
| 파일 판본 | 부모 폴더 mtime이 같아도 파일 변경 탐지. 크기·mtime을 유지한 내용 변경은 content 대조에서 탐지 |
| 목록 범위 | 추가·삭제·이름 변경, 깊은 경로 변경, 필터 제외, 잘린 열거. 범위 밖을 확인했다고 하지 않음 |
| 불안정 관측 | 읽기·열거 도중 변경, 권한 거절, 끊긴 볼륨, 심볼릭 링크 대상 변경, 검사 예산 소진 |
| 근거 신원 | 위조 관측 ID·다른 주체·다른 몸·현재 경로와 무관한 영수증을 근거로 채택하지 않음 |
| 문서 정본 | DB 삭제 후 재색인, 근거 포함 왕복, 직접 문장 수정, ID 중복, 단언 삭제, 문서 분할·이동 |
| 이행과 복구 | 옛 문서와 DB 근거 이관, 지문 없음 표시, 중단 뒤 재시도, 동시 편집 충돌, 이관 전 백업 복원 |
| 의미와 상속 | 파일 하나의 단위를 저장·재회상하되 형제 파일과 자식 장소에는 일반화하지 않음 |
| 재확인과 충돌 | 같은 문장만 반복하면 근거 불변, 실제 재관측은 갱신, 새 해석과 기존 단언 충돌을 숨기지 않음 |
| 발견과 사용 | 일상 질문으로 장소를 찾은 뒤 행 의미·단위·결합 조건과 근거를 얻어 새 과제에 사용 |
| 조합 | 여러 장소 회상의 상태를 필터링하고 변경된 근거만 재조사. 부분 미확인이 전체 성공으로 둔갑하지 않음 |
| 비용 경계 | 반환하지 않는 전체 기억에 파일 검사를 수행하지 않음, 공유 근거는 호출 내 한 번 검사, 예산 초과 명시 |

기존 `test_forage_doc.py`, `test_forage_location_recall.py`, `test_tree_recall.py`,
`test_unified_distill_2026_09_21.py`, `test_distill_queue.py`,
`test_imagination_round78_79_forage.py`를 출발점으로 전이 소비자를 선택한다.
새 대조 모듈을 만들면 모듈별 회귀를 추가한다. 저장·재색인·증류 계약이 여러 기억 경로에
영향을 주므로 선택기와 [회귀 절차](REGRESSION_TESTING.md)에 따라 종합 회귀와 관련 system 묶음을 실행한다.
IBL 소스를 변경하면 빌드·`--check`, backend 변경은 Android 번들 재생성과 층 검사를 수행한다.

고정 자료 시험은 위 계약을 검증한다. 별도로 표 자료·코드 저장소·문서 모음의 서로 다른
과제에서 기존 방식과 새 방식을 비교해 뜻을 잘못 사용한 결과, 다시 읽은 자료 범위,
전체 토큰·모델 호출·완료 시간을 기록한다. 저장과 대조 비용을 포함한다.
실패 사례나 비교 측정이 생길 때까지 구조 수리를 미루지 않으며, 실측 전 절감률을 주장하지 않는다.

두 수리는 A부터 D까지 연결되어야 완료다. 근거를 저장하기만 하거나, 의미를 적게 했지만
찾아 쓰지 못하거나, 미확인을 최신으로 취급하는 상태는 완료가 아니다.
실제 개인 포식 문서와 DB의 이관은 저장소 코드 검증 후 별도 백업 아래 수행한다.
개인 기억·원문·출처 식별정보를 Git에 넣지 않는다.
