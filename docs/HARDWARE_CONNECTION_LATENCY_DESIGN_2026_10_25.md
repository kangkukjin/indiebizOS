## 4. 1단계 — 상주 PC 결과 즉시 전송

### 목표 구조

```text
작업 실행 → 기존 영속 spool 기록 → 알림 channel → 사건 publisher → /limb/resident/events
명령 수신 ← 기존 WebSocket / HTTP sync
```

**첫 구현은 기존 HTTP events endpoint를 재사용한다.** 하나의 WebSocket에서 비동기 송수신을 새로 다중화하지 않는다.
현재 서버 WebSocket도 요청 하나에 응답 하나인 sync 구조다. client에서 writer만 늘려서는 수신 장벽을 제거하지 못한다.
별도 HTTP publisher는 이미 폰에서 검증한 서버 계약을 그대로 사용하며, Go 공용 client의 연결 풀을 활용할 수 있다.

### 구체적 변경

- `resident_runtime.go`에 버퍼 1의 비차단 알림 channel 및 종료 context를 둔다. 알림은 메모리 신호이며 사건 자체는 계속 디스크에 둔다.
- `event()`는 **원자 저장 성공 후** 알림을 보낸다. 알림 누락/병합에도 publisher가 spool을 재조회하므로 사건은 유실되지 않는다.
- 새 `helper/resident_events.go`에 배치 조회·전송·ACK 정리와 재시도 루프를 분리한다. 기존 64건/4MiB 배치 한도와 사건 ID를 유지한다.
- 서버가 `event_push:1`을 응답하기 전에는 기존 sync 보고를 유지한다. 협상 후 사건 전송은 publisher가 맡는다.
- 구형 허브나 events 404에서는 사건을 지우지 않고 sync 보고로 돌아간다. 동일 서버가 계속 event_push를 광고하면서 404인 경우 매 sync마다 모드를 진동시키지 않도록 재협상에 backoff를 둔다.
- 모드 전환 중 두 통로가 같은 사건을 보내도 **동일 ID**를 사용한다. ACK된 해당 파일만 삭제하며, 이미 지워진 파일의 동시 정리는 무해해야 한다.
- 500ms 고정 sleep을 종료·새 사건·새 작업 상태에 반응하는 대기로 바꾼다. 완료 직후 반드시 500ms 기다리는 구조를 없애되 busy-spin은 금지한다.
- publisher 오류 backoff는 명령 수신을 멈추지 않는다. 취소·등록 폐기·제거 응답은 기존 공통 처리에 연결한다.
- 등록 세대 확인·교체 처리도 기존 sync와 같은 의미를 유지한다. 새 세대로 옛 사건을 잘못 귀속시키지 않는다.
- `stop()`/로컬 제거/업데이트 재시작은 publisher까지 소유한다. context 취소→in-flight HTTP 종료→goroutine join 순서로 정리하고, `r.mu`를 잡은 채 네트워크나 join을 기다리지 않는다.
- `restartDue`의 ACK 전 재시작 방지 및 기존 30초 상한을 보존한다. publisher 종료와 spool 카운트 사이 경합을 검사한다.

### 경합을 반드시 재현할 것

현재 코드는 spool을 읽은 뒤 busy를 판단한다. 그 사이 작업이 끝나면 “보낼 사건 없음 / 실행 중 아님”으로 판단해 long-poll을 시작할 가능성이 있다.
이는 **코드에서 추론한 경합**이며 TV1에서 20초 지연을 실측했다는 뜻은 아니다.
테스트로 수신 응답을 의도적으로 막고, 그 동안 완료한 사건이 독립 경로로 전달됨을 확인한다.

### 유지해야 할 계약

- ACK 유실 → 같은 사건 재전송. 명령 재실행 금지.
- 네트워크 단절 → spool 보존. 완료를 실패로 위장하거나 부작용 명령 재접수 금지.
- 재시작 중 실행했던 작업 → 기존 unknown/복구 규칙 유지.
- 제거·일시정지 중에도 필요한 종료 보고는 가능하되 새 작업 수신 권한을 넓히지 않는다.
- publisher가 shared WebSocket에 동시에 쓰지 않는다.

## 5. 2단계 — TV 연결을 호출 사이에 유지

### 소유 위치와 실행 경계

`send_keys()`는 이미 **한 요청 안의 최대 40개 키**에 연결 하나를 사용한다. 빠진 것은 **요청 사이**의 재사용이다.
`TV제어`의 호출별 스크립트 프로세스에 전역 cache를 추가해도 프로세스 종료 시 소켓이 닫힌다.
따라서 장기 수명의 허브 서비스가 소켓을 소유해야 한다.

구현 전 작은 설계 확인 단계에서 기존 등록 스크립트 어댑터·실행 문맥을 읽고 다음 경로를 확정한다:

1. 선호: 기존 `TV제어` 호출의 입력/반환 계약은 유지하고, **설치된 고정 드라이버만** 허브 서비스로 연결하는 등록 어댑터를 둔다.
2. 기존 스크립트 실행 경계를 유지해야 한다면, 실행별 권한이 검증되는 좁은 내부 RPC가 필요하다. 이미 있는 인증·실행 문맥 전달을 재사용할 수 있는지 먼저 확인한다.
3. 단순 localhost HTTP 접근이나 caller가 적은 `origin:user`를 권한 증명으로 삼지 않는다. 안전한 연결 경계를 확보하지 못하면 2단계 확대 구현 전에 그 결정을 기록한다.

**아직 결정되지 않은 부분은 위 호출 경계 하나다.** 현 단계에서 존재하지 않는 내부 RPC나 등록 어댑터를 구현 완료 기능으로 취급하지 않는다.
새 프로토콜을 택하면 범용 임의 Python 코드를 허브에서 실행하는 기능으로 넓히지 않는다.
TV 이름·별칭 분기는 IBL 파서/언어 코어에 추가하지 않는다. 모델·프로토콜 처리는 드라이버 계층이 소유한다.

### 서비스 설계

후보 모듈 `backend/services/tv_transport.py`는 등록된 TV ID별 세션을 관리한다. 새 모듈은 `scripts/check_backend_layers.py`에 배정한다.
기존 프레임 처리와 검증 구현을 추출해 재사용하고, `tv_control.py`와 서비스 양쪽에 WebSocket 구현을 복제하지 않는다.

- 키: 정규 장치 ID + 연결 설정 판본/지문. 별칭을 세션 키로 사용하지 않는다.
- 매 명령에서 `hardware_registry.connection()`의 활성·일시정지·해제 상태와 현재 권한을 확인한다. 열린 소켓은 지속 권한을 뜻하지 않는다.
- 장치별 실행 잠금: 같은 TV의 요청은 순서 보존, 다른 TV는 독립 실행. 큐 대기도 전체 deadline에 포함한다.
- 초기 제안: 60초 idle TTL, 최대 8개 유휴 세션. **측정 후 조정할 설정값**이며 이미 존재하는 상수가 아니다. 실행 중 세션은 LRU 회수하지 않는다.
- 처음 사용할 때만 연결·승인 handshake. close/EOF/ping 처리자는 하나로 두고 reader 충돌을 막는다.
- 연결 설정·토큰 변경, 등록 해제/정지, TV 전원 종료, 허브 종료 시 해당 세션 폐기. 토큰 갱신 callback과 설정 지문 변경의 경합도 다룬다.
- 명령을 보내기 전 확실히 끊긴 연결은 새로 연결할 수 있다. 연결 교체 후에도 권한·deadline을 재확인한다.
- 명령 바이트를 일부라도 보냈거나 전송 여부가 불명인 채 연결이 끊기면 **unknown**. 전원 토글·키·음량 변경을 자동 재전송하지 않는다.
- 전원 켜기는 기존 WOL 및 실제 전원 관측을 유지한다. 잠든 TV를 상시 ping으로 깨우는 설계는 피한다.
- HTTP REST/UPnP/SmartThings 연결 재사용은 WebSocket 단계 뒤 별도 소단계로 둔다. 서로 다른 호스트·인증의 session을 섞지 않고, 기존 redirect 차단·크기/시간 제한을 유지한다.
- 기존 Samsung 로컬 자체 서명 인증서의 명시 등록 IP 범위를 외부 HTTPS로 확대하지 않는다. 토큰/URL 비밀값은 로그·실측 산출물에 넣지 않는다.

### 결과·취소 의미

`sent`, `verified`, 실제 관측 결과의 차이를 유지한다. WebSocket 프레임 송신 성공이나 pong은 화면·음량 변경 증거가 아니다.
연속 키 중간 실패는 완료된 전송 수와 남은 불확실성을 반환한다. 전체 키 묶음을 처음부터 재실행하지 않는다.
실행 전 취소는 전송을 막고, 실행 중 취소는 다음 키 전송을 막는다. 이미 보낸 키를 되돌렸다고 보고하지 않는다.
취소/timeout 후 사용 가능한 연결인지 확인하고, 상태가 불명인 소켓은 폐기한다.

## 9. 구현 기록 (2026-10-25)

### 1단계 PC

`resident_events.go`가 디스크 큐를 별도 HTTP publisher로 전송한다. 저장 후 두 알림 채널로
publisher·수신 루프를 깨운다. 구형 허브는 sync 보고를 유지하고 events 404 뒤에는 1분간
재협상을 제한한다. 동일 ID·64건/4MiB 배치·ACK된 전송 파일만 삭제하는 계약을 유지한다.
실패 backoff는 명령 수신과 분리되며, 종료 context는 HTTP·WebSocket 대기까지 취소한다.
등록 제거·세대 확인·작업 취소를 두 통로가 공유하고, 새 작업을 저장한 뒤 취소를 적용한다.
업데이트의 오래된 빈 큐 스냅샷은 작업 잠금 아래 다시 확인해 ACK 전 재시작을 막는다.
기존 30초 상한은 유지한다.

검증: Go 전체 `go test -race -timeout 180s ./...` 통과, 추가 WebSocket 차단·빈 스냅샷
검사 통과. HTTP/WS 수신 차단 중 결과 보고, ACK 유실, 404 재협상, 종료·세대 불일치,
동시 ACK, 배치 한도·업데이트·무사건 대기를 자동 검사했다. Windows 일반/상주,
macOS arm64/amd64/legacy, Linux amd64 빌드를 완료했다. macOS 산출물은 개발용 ad-hoc
서명이며 실제 개인키 서명·대상 Mac 적용은 별도다.

첫 전체 backend 회귀는 **11903 통과·18 건너뜀·1 실패**였다. 실패는 새 TV 시험 파일의
직접 실행 `pytest.main()` 진입점 누락이며 PC 기능·신규 바이너리 통합 검사는 통과했다.
진입점을 추가한 관련 재검증 87개 통과. 이 수치를 전체 통과로 기록하지 않는다.
실장치 배포·비교 결과는 후속 기록에서 확정한다.


### 2단계 TV 호출 경계와 수명

선택한 경계는 기존 `script_ops.op_run`의 전경 실행 어댑터다. 등록 계약 검사·IBL 권한 검사
이후, 설치 경로·Python 인터프리터·소스 SHA-256·제한 없는 주인 문맥을 확인한 고정 드라이버만
허브의 `tv_transport`로 연결한다. 검증한 동일 바이트를 로드하며 임의 Python의 프로세스 내
실행 기능은 열지 않는다. 수정된 드라이버·수리 사본·백그라운드·EPG·비주인/제한 문맥은 기존
프로세스/기기 실행 경계를 유지한다. HTTP/RPC 엔드포인트와 IBL 낱말은 추가하지 않았다.

IBL 실행의 검사 콜백은 `script_process.invocation_scope`로 전달한다. 각 키·대기·네트워크
경계에서 취소/예산·현재 권한·등록 상태와 설정 지문을 다시 확인한다. 장치 ID별 FIFO 큐 대기는
전체 timeout에 포함한다. 다른 장치는 독립 실행하며 60초 유휴 TTL·최대 8개 유휴 세션을 쓴다.
명령 전 확인된 단절만 재연결하고, 전송 도중 오류·중간 취소는 `sent`와 `unknown`을 남긴다.
키·전원·음량 변경은 재전송하지 않는다. WOL 직전에도 취소를 검사하고 미확인 전송을 보존한다.

WebSocket 프레임 구현은 기존 `tv_control.Remote` 한 벌이다. 연결당 reader 하나가 ping·분할
메시지·EOF를 처리하고 write 잠금이 pong과 키 송신을 직렬화한다. 토큰 저장은 현재 연결 설정과
비교한 조건부 갱신으로 변경된 등록을 덮어쓰지 않는다. 등록 정지/해제·설정 변경·전원 종료·TTL·
허브 종료에서 세션을 회수한다. 유휴 등록 변경은 다음 reaper 확인(1초 주기)에 소켓을 닫고,
활성 요청은 다음 전송/대기 경계에서 중단한다. 이미 전송한 명령은 되돌렸다고 보고하지 않는다.

REST/UPnP/SmartThings도 장치·origin·인증 헤더별 HTTP 세션을 재사용한다. redirect·환경 proxy·
자동 재시도를 쓰지 않고 응답 크기/시간을 제한한다. 자체 서명 인증서 허용은 명시 등록 TV의
로컬 WebSocket에만 남긴다. TV제어의 공개 입력·반환·관측 범위·WOL 전원 판정은 유지한다.

실행 전 복귀: 허브 환경 `INDIEBIZ_TV_PERSISTENT=0`이면 기존 프로세스 경로를 선택한다.
이미 시작한 명령의 오류를 다른 경로로 재실행하는 fallback은 없다. 드라이버를 정당하게 수정하면
서비스의 고정 소스 지문도 검토·갱신하고 허브를 재시작해야 한다. 지문 불일치는 기존 경로 선택이다.

현재 자동검증: TV·원장·단일 시험 진입점 관련 87개 통과. 첫 전수에서 발견한 진입점 누락은
수정했다. 최종 전수, 실제 PC 배포와 TV 접근 여부·속도 비교는 아래 후속 실측으로 확정한다.

### TV 전원 켜짐 후 후속 검증

사용자가 거실TV를 켠 뒤 실제 허브의 공개 status 10회 모두 reachable:true,
power:on, verified:true(전원 범위)를 확인했다. 중앙값 **1.28초**, 최댓값 **1.4988초**.
앞선 꺼짐/미응답 상태와 조건이 다르므로 전후 속도 개선율로 해석하지 않는다.

별도 검증 프로세스에서 설치 드라이버와 동일 Manager 구현으로 실제 TV에 연결해
HTTP pool·WebSocket 재사용, **60.0915초** 유휴 뒤 세션 제거·소켓 종료, 이후 재연결,
Manager 종료 시 소켓 회수를 통과했다. handshake 1.1888초/1.3817초.
허브 내부 소켓 직접 계측과 구분하며, 키 송신은 차단해 전원·입력·음량 변경은 없었다.
초기 측정 도구의 제거→소켓 정리 사이 검사 경합을 고쳐 재검증했고 제품 코드는 그대로다.
실제 키 효과·전원 순환·강제 네트워크 단절 복구와 오프라인 Mac 적용은 여전히 남았다.
상세 원자료와 재현 도구는 위 적용 증거의 `powered-on-*` 파일에 보존한다.
