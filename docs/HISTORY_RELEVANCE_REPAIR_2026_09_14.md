# 현재 지시와 대화 히스토리 — 2026-09-14 수리

과제 원장 오연결 수리 이후, 일반 대화 이력에도 같은 원칙이 적용되는지 조사했다.
현재 요청과 무관한 이전 목표·출력 형식·작업별 제약은 지금의 문제가 되어서는 안 된다.
반면 같은 작업의 후속 질문·정정·명시적인 지속 지시는 적용 범위 안에서 이어져야 한다.

## 확인된 결함

1. 의식 프롬프트는 이미 정의한 문제에 맞춰 과거를 요약하라고 했지만, 문제를 정의하기
   전에 현재 지시를 기준으로 과거의 관련성을 판단하는 순서가 약했다.
2. `cognitive_consciousness._apply_consciousness_to_history`는 빈 요약을 판단 부재와
   같게 처리하여 원본을 실행자에게 전달했다. 관련 과거가 없다는 판단이 취소되는 버그다.
3. CLI 프로바이더는 히스토리가 비어 있지 않으면 저장 세션을 재개했다. 이 경로는
   선별 요약을 직렬화하지 않으므로, 의식이 제외한 과거를 CLI의 옛 대화에서 다시 읽을 수 있었다.

## 수리 계약

- 의식의 판단 순서는 현재 지시 해석 → 필요한 과거 채택 → 문제·제약·기준 규정이다.
  최근이라는 이유만으로 과거를 채택하지 않는다. 새 주제 선언이 없어도 독립 요청을 처리한다.
  대명사 없이 이어지는 질문, 정정, 중간에 다른 주제가 끼었던 이전 작업의 명시적 재개도 다룬다.
  assistant의 추정을 사용자 결정으로 승격하지 않는다.
- `history_summary`의 유효한 문자열은 교체 결정이다. 공백뿐인 문자열도 빈 결정으로 처리한다.
  빈 문자열이면 `[]`; 내용이 있으면 그 요약만 전달한다. 의식 미실행·필드 누락·비문자열은
  결정이 없는 경우이므로 기존 이력을 유지한다. 형식 실패를 무관함으로 추정해 정보를 지우지 않는다.
- 비어 있지 않은 교체 메시지에 하네스 내부 표식 `_history_replacement:true`를 붙인다.
  CLI 공통 프로바이더가 이 구조 표식을 읽어 이전 세션 매핑과 크기를 비우고 새 세션에
  교체본을 싣는다. 모델 산문이나 한국어 요약 접두어를 파싱해 세션을 고르지 않는다.
  API 프로바이더는 기존처럼 role/content/images만 직렬화한다.
- 원본 대화·체크포인트·과제 원장 데이터는 수정하지 않는다. 선택은 실행 맥락에만 적용한다.
  새 모델 분류 단계나 출력 필드는 추가하지 않는다. 일반 EXECUTE/반사 경로의 세션 재개는 유지한다.

  선택한 요약만 받는지 검사한다. 모델 호출과 실행 모델만 대역으로 둔다.
