# 홈페이지 검토 자료 수집 관용구

4022번은 홈페이지 갱신 필요성 판단을 위해 사이트·변경 이력·정본문서·링크·화면을
개별 조회했다. 3860번에도 같은 종류의 요청이 있었다. 이번 변경은 반복되는 자료 수집을
현재 IBL 함수로 묶고, 갱신 판단과 수정·배포의 범위를 구별한다.

## 변경

- `홈페이지살펴보기(사이트, 화면=true)`: 사이트 ID 해소 → 본문·링크·선택 화면/HTTP 상태.
  본문 수집을 갱신하고 링크는 그 스냅샷을 재사용한다. 각 단계 실패와 성공 자료를 함께
  반환하며 화면 하위 검사의 `ok=false`도 전체 `ok`에 반영한다.
- `홈페이지갱신검토자료(사이트, 저장소, 기준시각, 정본문서, 화면=true)`: 앞 함수를 호출하고
  정본문서와 지정 시각 이후 커밋을 모은다. 문서 목록은 경로 배열이며 비어 있으면 `ok=false`다.
  새 어휘와 자체 모델 호출을 추가하지 않았다. `always_on=0`, 홈페이지 가이드에서 발견한다.
- `웹앱작업 history`: 제품 저장소 경로와 시간대 있는 ISO 시각을 받아 고정 HEAD까지 전건
  조회한다. committer 시각을 쓰고 날짜가 역전된 커밋도 순회한다. 명령 오류·시간 초과는 실패다.
  4022번의 `self:body log` 104/100 절단은 올바른 불완전 신호였다. 그 신호를 없애지 않고
  이 작업의 호출 경로에서 임의 상한·모호한 최근 N일을 제거했다. 기존 body log 계약은 유지한다.
- 등록기는 의존 순서대로 함수 한 개씩 확정한 뒤 후속 함수·호출 용례를 등록한다.
  첫 적용에서 선행·후행 함수를 같은 배치로 검증해 후행 함수가 거절된 문제를 고쳤다.
- `web_builder.md`에 새 두 함수와 기존 `웹앱작업준비`·`웹앱검사하기`의 호출·입출력·실패
  계약을 연결했다. 실제 사이트 ID와 달랐던 점검 예제도 고쳤다. 가이드 검색 설명·키워드도 연결했다.

## 소스와 등록

정본 정의는 `data/idioms/homepage_inspect.ibl`, `homepage_review.ibl`이며
`homepage_seeds.json`에 정의·호출 용례를 보존한다. 검사는 두 소스의 일치를 확인한다.

```sh
.venv/bin/python3 scripts/register_webapp_idioms.py --seed-file homepage_seeds.json
.venv/bin/python3 scripts/register_webapp_idioms.py --seed-file homepage_seeds.json --apply --local-encoder
```

등록 전에 SQLite backup을 `data/_backups/`에 보존한다. DB 쓰기는 기존 `add_examples_batch`
입구를 사용한다. 이미 다른 본문으로 등록된 이름은 덮어쓰지 않는다.
운영 등록 ID는 4866·4867이고 호출 용례까지 총 4행을 의미 검색 색인에 넣었다.
재적용 `inserted=0`, 상시 소개 꺼짐을 확인했다.

## 검증과 한계

- 전용 검사 22개 통과(기존 웹앱 8개 포함): 실제 임시 Git 저장소의 104건과 날짜 역전,
  빈 기간·잘못된 날짜·저장소 오류, IBL 합성 실행의 단계 실패·스크린샷 하위 실패,
  사이트 없음·문서 없음·문서 실패, 등록 의존 순서와 멱등성.
- 운영 `[fn:홈페이지갱신검토자료]` 실행 성공 및 `source_complete=true/ok=true`.
  기준 시각 `2026-09-18T16:28:00+09:00`, HEAD `4bc18d9dd97927a6da4cdc0637cf69f16bf11fb5`에서
  커밋 79건, 정본문서 2개 전문, 링크 28개와 HTTP 200·스크린샷을 수집했다.
  IBL 실행 계측 19,371ms. 캡처를 실제로 열어 정상 화면을 확인했다.
- `web_builder.md`·`홈페이지갱신검토자료`·`홈페이지 평가` 가이드 조회에서 네 함수 모두
  안내됨을 확인했다. 직접 HTTP의 `edition:2` 계약 조회도 두 새 함수에 성공했다.
- 다른 등록 사이트 `irepublic-brain`에서도 `화면:false` 호출이 성공했다. 본문·링크 12개를
  수집하고 화면 단계는 명시 생략했다. 특정 홈페이지에 주소·문서를 하드코딩하지 않았다.
- 운영 검증 원문: `data/_backups/2026-09-24_homepage_idioms/live_review.json`(Git 제외).
- 전체 `.venv/bin/python3 -m pytest backend/ -q` 종료 코드 0. 실행 중 추가한 등록기 회귀를
  포함한 최신 전용 검사 22개도 별도로 통과했다. 어휘·문서 파생 `--check`, 층 가드,
  은퇴 계약 검사와 Android 번들 검사 통과. 전체 로그는 같은 백업 폴더에 보존했다.

이 시간은 **자료 수집 한 호출**의 시간이다. 4022번의 최종 판단까지 포함한 137초와 같은
범위의 비교가 아니며 전체 토큰 절감을 입증한 수치가 아니다. 큰 문서는 원문으로 반환하므로
호출자가 필요한 정본문서만 선택하고 결과 미리보기의 필요한 필드를 읽어야 한다.

화면은 기존 `engines:web check`의 데스크톱 1280×800 캡처다. 모바일·하위 페이지·미적 품질을
자동 검수하지 않으며 링크 목적지 상태도 검사하지 않는다. URL을 읽는 시각과 Git HEAD는
별개의 관측이다. registry 수정일을 배포 완료 시각으로 추정하지 않는다.
수정·배포·해마 재학습은 이 관용구가 수행하지 않는다.
