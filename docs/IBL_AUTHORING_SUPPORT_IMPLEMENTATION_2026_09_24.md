# IBL 작성 지원 — 첫 구현 묶음

[도입 계획](IBL_AUTHORING_SUPPORT_PLAN_2026_09_23.md)의 첫 묶음인 개발 시험 도구,
구/신 검사 대응, 공통 진단·AI 조회 보강을 구현했다. CodeMirror·LSP 설치는 다음 단계다.
기존 함수 조회 `describe:["fn:이름"]`는 이미 구현돼 있어 재사용했다.

## 작성자가 달라지는 동작

- `len(4)`, `has([],"x")`, `unwrap(1)`, 숫자로 관측할 수 없는 리터럴 등의 확정 오류를
  실행 전에 거절한다. 숫자 문자열은 공통 `value_semantics`를 경유한 런타임 숫자 관측을 그대로 사용한다.
- 반복문이 변수를 바꿨는데 반복 전의 필드가 남아 있다고 인증하던 문제를 고쳤다.
  1회가 확정되면 본문 뒤 타입을, 일반 반복은 보수적으로 합친 타입·미상을 사용한다.
  모든 반복에 대해 정밀한 고정점 타입 분석을 완성한 것은 아니다.
- 진단은 기존 `code/message/source_span`을 유지하면서 `rule/severity/location/call_path/hint`와
  타입 진단의 `expected/actual`을 제공한다. `location`은 제출 원문 또는 저장 함수 내부의
  URI·원문 지문·줄·열·끝 위치다. UTF-16이 아닌 Unicode 코드 포인트 좌표다.
- 같은 함수가 다른 타입으로 여러 번 호출돼도 마지막 호출의 서명만 남기지 않는다.
  `functions`에 관측한 서명 `specializations`와 정의 위치를 싣는다. 서로 다른 서명의 요약은
  Unknown으로 두고 개별 관측을 최대 32개 보여준다. 선언되지 않은 보편 서명을 추측하지 않는다.
- `warnings/preflight`가 선언된 AI 호출의 방문 상한과 반복되는 전체 목록 입력을 관측한다.
  리터럴·입력 목록·변수·함수 인자/반환·파이프·each·repeat를 따라간다.
  전체 목록을 의도적으로 비교할 수 있으므로 `repeated_ai_batch`는 실행 차단 오류가 아니다.
  실행 결과에도 `precheck_warnings`를 남긴다.
- 검사 API의 구문 오류도 `issues`로 제공하여 조종실·AI가 같은 오류 계약을 읽는다.
  파서가 처음 구문 오류에서 멈추는 동작은 유지한다. 의미 오류 여러 개는 한 검사에 모인다.

모든 기능은 기존 컴파일러·check 경로를 사용한다. 새 IBL 어휘·추가 모델 호출·검사 캐시는 없다.
소스나 정의가 바뀌면 다시 컴파일한다. `source_hash/plan_hash`는 식별자이며 실행 승인 토큰이 아니다.

## 구/신 검사 대응표

| 예전 검사·목적 | 현재 의미에서의 대응 | 이번 묶음 상태 |
| --- | --- | --- |
| 구문·변수·인자 이름/op | 현행 파서, 자유 변수·명시 인자, callable variant 검사 | 기존 유지. 구문 오류도 공통 issues로 전달 |
| 필수 인자·파이프 자리 | `MISSING_ARGUMENT`, `PIPE_COLLISION`, `UNKNOWN_ARGUMENT` | 기존 유지. 진단 힌트·함수 호출 경로 추가 |
| prose/items/effect 이음매 | Text/List/Record/Unit 및 명시 pipe_input | 새 의미로 대체. 옛 봉투 추출 규칙을 새 값에 적용하지 않음 |
| 죽은 파이프 연결 경고 | 입력 자리가 없거나 명시 인자와 겹치면 컴파일 오류 | 새 의미로 대체. 옛 경고를 단순 복제하지 않음 |
| 확정 열 누락 | 리터럴/입력/함수 반환 Record의 필드 검사 | 기존 유지. 반복 뒤 오래된 필드 인증 보완 |
| 관측 열에 없는 열 경고 | 호환 Record와 열린 선언은 필드 미상 | 정밀화 잔여. 확정 부재로 오차단하지 않음 |
| rename의 동적 열 충돌·drop 필드 소실 | 도구·콜백 계약과 실제 행 구조의 관계 | 일반 관계 추론 잔여. 전부 이식됐다고 주장하지 않음 |
| 표 투영·계산 식 검증 | 현행 순수 식 및 콜백 검사 | 기존 유지 + 일부 내장 함수 입력·리터럴 숫자 관측 검사 |
| each 입력 일부 누락(limit) | 현행 each는 전건, limit 인자는 오류 | 해당 없음. 행 예산 중단은 런타임 실패로 관측 |
| each collect/flat_map 반환 | List/Result/Unit과 명시 mode/on_error | 기존 유지 |
| 반복 AI 전체 입력 증폭 | 현재 AST에서 불변 목록 인자와 반복 건수 관측 | 연결. 지역/저장 함수의 명시 인자·파이프 포함 |
| AI 방문 상한·inspect 제외 | 선언 effects/ai_call/ai_inspect_param | 연결. 어휘명 분기 없이 사전 선언 소비 |
| 분기/반복 문맥 | 현행 스코프·타입 합류 | 기존 유지 + 반복 재할당 보수적 분석 |
| 함수 내부 반환·타입 | 호출별 검사, 함수 계약 조회 | 호출 경로·정의 위치·복수 관측 서명 보강 |
| 모르는 계약 | guards/incomplete, preflight unknowns | 보존. 0회·완전 검증으로 둔갑시키지 않음 |

preflight의 상한은 선언된 모델 호출만 대상으로 하며 스크립트 내부·조건에 따른 재시도·토큰은
포함하지 않는다. 동적 건수·호환 내부 호출·분석 예산 초과가 있으면 전체 상한은 null이다.
분석 예산은 AST 방문 2,000·함수 깊이 8이며 경고·미상 목록은 최대 32개다.
분석기 예외는 abstained로 표시하고 기존 타입 진단을 지우지 않는다.

## Hypothesis 설치와 검증 표본

프로젝트 .venv에 Hypothesis 6.168.1을 설치했다. `backend/requirements-dev.txt`와
CI pytest 설치 명령에 연결했으며 운영 requirements·폰 런타임 의존성에는 넣지 않았다.
정확 핀은 재현 가능한 생성 시험을 위한 개발 설정이다. 업그레이드 시 아래 시험을 함께 돌린다.

현재 코퍼스를 읽기 전용으로 조사했을 때 현행 헤더가 있는 용례는 1,203개지만 최장이 180자였고,
실행 원장의 현행 헤더 소스는 1개·62자였다. 이 수치는 조사 시점의 `source_edition` 판정이다.
이를 긴 현행 프로그램 30개의 실사용 검증 근거로 부풀리지 않았다.

대신 공개 가능한 **6개 구조 × 입력 크기 0/1/3/10/50 = 합성 30건**을 만들었다.
보고서 구조·파일 표현·기록 쓰기 대역·조건 분기·반복 집계·행별 실패 수집에
7개 함수의 다층 호출을 연결했다. 각 프로그램은 약 39~41줄이며 외부 도구는 메모리 대역이다.
기대 결과는 단순 Python 계산으로 별도 산정한다. 개인 원문·운영 DB를 수정하지 않는다.

각 정상형에 미정의 변수 오류를 넣은 변이와, 열린 Record의 미선언 필드를 미상으로 남기는
변이를 검사한다. Hypothesis는 숫자 문자열·중첩 map/함수·반복 변경에 대해
최대 160개 생성 예를 시험한다. pytest 테스트 개수와 생성 예 개수를 합산하지 않는다.
이는 프로그램을 쓰는 모델의 첫 생성 품질 시험과 다르다.

## 비교 결과와 재현

`scripts/check_ibl_authoring.py`는 외부 실행 없이 고정 사례·오류·긴 순서 검사를 재현한다.
`--baseline-ref 0f16fa09`는 해당 커밋의 **컴파일러 파일만** 현재 공통 파서·타입·런타임과
연결한 비교다. 전체 과거 체크아웃이나 과거 운영 시스템 성능 비교로 해석하지 않는다.

| 측정 | 이전 컴파일러 | 이번 컴파일러 |
| --- | ---: | ---: |
| 이번에 선택한 확정 오류 9종 탐지 | 0/9 | 9/9 |
| 합성 정상 프로그램 30건의 오차단 | 0 | 0 |
| 202문장 단순 순서 warm p95, 10회 | 6.758ms | 6.122ms |
| 502문장 단순 순서 warm p95, 10회 | 11.857ms | 7.463ms |

이번 정상형 30건은 실제 메모리 대역 실행 결과도 기대값과 일치했다.
선택된 결함 9종의 탐지율을 전체 언어 오류 탐지율로 일반화하지 않는다.
속도는 로컬 참고치이며 라이브 사전 로딩·외부 I/O·모델 작성은 포함하지 않는다.
전체 토큰·실사용 완료 시간·최대 메모리 개선은 아직 측정하지 않았다.
원본 수치: [benchmark.json](experiments/ibl_authoring_support_2026_09_24/benchmark.json).

재현 명령:

```bash
.venv/bin/python3 -m pip install -r backend/requirements-dev.txt
.venv/bin/python3 -m pytest backend/test_ibl_authoring_support.py
.venv/bin/python3 scripts/check_ibl_authoring.py --baseline-ref 0f16fa09
```

검증 기록:

- 최종 IBL·표면·저장 함수·이행·러너 집중 회귀: **185 passed**, 6 warnings (24.88초).
- 전체 backend 회귀: **5,759 passed, 1 skipped, 1 failed** (502.93초).
  실패는 새 시험 파일의 직접 실행→pytest 위임 진입점 누락이었다.
  진입점을 추가한 뒤 해당 가드와 관련 회귀를 위 185건으로 재검증했다.
  마지막 수정 후 전체 스위트를 다시 돌렸다고 집계하지 않는다.
- 어휘/문서 파생 `build_ibl_nodes.py --check`, Android 번들, 층 구조,
  은퇴 계약, 값 의미론, Windows 이식성, diff 검사를 통과했다.
- 외부 모델·실제 쓰기 도구는 이번 신규 시험에서 호출하지 않았다.

## 잔여 범위

실제 장문 코퍼스 확보·외부 도구의 전후 비교, 콜백의 정밀 입력/반환 추론,
여러 구문 오류의 복구·부분 AST 편집 지원, 위치 기반 완성/심볼 조회는 다음 묶음이다.
자동 수리·CodeMirror·LSP는 설치하지 않았다. 이 기록은 전체 1B/1C 및 IDE 완성 보고가 아니다.
