# 올바른 IBL 문장의 조합 경계 시험

2026-09-08, 정본 `cc91ac7c`에서 시작. 자연어 모델의 코드 작성 능력이 아니라 파서·바인딩·엔진·도구의 실행 계약을 시험했다.

**첫 56개 문장은 모두 파싱됐지만 30개가 실행 실패 또는 잘못된 값을 냈다. 공통 원인을 고친 뒤 같은 56개가 모두 기대한 결과를 냈으며, 추가 7개 문장도 통과했다.** 시스템 전체에 오류가 없다는 뜻은 아니다. 외부 서비스 없이 재현 가능한 값 전달과 제어문 경계에 집중했다.

## 방법

- 문자열(한글·앞자리 0·따옴표·개행·백슬래시), 0, true/false, null, 객체·배열 경로, 빈 목록을 교차했다.
- 함수 호출·식 할당·조건식·each·try/catch·repeat·병렬 each를 실제 파서와 실행기로 실행했다. 표 변환과 파일 읽기도 실제 도구를 썼다.
- 기존 격리 실행기를 재사용했다. 임시 폴더 밖 파일과 외부 도구는 허용하지 않았다. 모델·외부 API는 호출하지 않았다.
- 각 문장의 파싱 여부, 실행 성공 여부, 최종 값·타입을 독립적으로 검사했다. `False == 0` 같은 Python 비교로 타입 손실을 숨기지 않도록 기대값을 JSON 타입까지 비교했다.
- 첫 56개는 정상 결과 50개와 거절되어야 하는 6개다. 없는 경로·미할당 변수·틀린 each 별칭·함수 인자 누락을 무조건 통과시키는 수리가 되지 않도록 했다.

| 집합 | 파싱 통과 | 기대한 결과와 일치 |
|---|---:|---:|
| 최초 문장, 수리 전 | 56/56 | 26/56 |
| 같은 문장, 최종 수리 후 | 56/56 | 56/56 |
| 추가 검증 문장 | 7/7 | 7/7 |

반복 과제의 기대값은 검토 과정에서 기존 계약에 맞춰 정정했다. `$i`는 0부터 시작하고 param 치환은 문자열이므로 두 회차의 마지막 값은 숫자 2가 아니라 문자열 `"1"`이다. 수리 전 네 반복 문장은 모두 실행 오류였으므로 이 정정은 26/56이라는 최초 성적을 바꾸지 않는다. 기대값 정정과 중간 시도 원본도 보존했다.

## 발견과 수리

### 1. 함수 인자가 코드로 바뀌는 문제

```ibl
[def:항등]{$return = $값}
[fn:항등]{값:"서울"}
```

`$return = 서울`로 바꿔 식 평가기에 넘겨서 `서울`을 변수 이름으로 오독했다. 0과 false는 빈 식이 되었고, 따옴표·개행은 식을 깨뜨렸다. 삽입된 `$b` 문자열이 다른 인자 b의 값으로 다시 치환되는 경우도 있었다.

함수 식·조건은 실제 값을 실행기의 바인딩으로 전달하고, 일반 param 문자열 치환은 한 번만 수행한다. 인자를 그대로 반환할 때 `007` 같은 식별자 문자열의 타입을 유지한다. 산술식의 숫자 관측 규칙은 유지한다. 추가 조건식 검증에서 분기별 조건이 별도의 AST 위치에 있다는 점도 반영했다.

### 2. 중첩 경로 접근의 불일치와 거짓 성공

```ibl
[table:each]{items:[{user:{value:"서울"}}],
  do:"[table:take]{items:[{got:$it.user.value}],n:1}"}
```

each는 `user.value` 전체를 단일 열 이름으로 찾다가 실패했다. 함수 param의 `$자료.user.value`는 더 나빴다. 실제 값을 찾지 않고 객체 JSON 뒤에 `.user.value`라는 문자열을 붙여 성공으로 반환했다. 없는 경로도 이런 거짓 값을 냈다.

양쪽을 공용 `field_path` 해석기에 연결했다. 기존처럼 `a.b`라는 실제 열이 있으면 each에서는 그 열을 우선한다. 객체 경로·배열 인덱스·null·false·0은 값을 보존하고, 함수의 없는 경로는 오류로 처리한다. 명시적인 옵셔널 함수 경로는 None이다.

### 3. each 안에서 유효한 지역 변수를 거절

each의 사전 검사가 `$error`와 `$i`를 무조건 유령 변수로 봤다. 올바른 try/catch·repeat도 실행 전에 거절됐다.

파싱한 제어문 구조를 따라 catch/finally 안의 `$error`, repeat 몸·조건의 회차 변수를 그 범위에서만 허용한다. 블록 밖에서 사용하는 경우는 계속 거절한다. 기본 each 별칭과 한글 별칭, 순차와 병렬 2개 실행 모두 확인했다.

### 4. 변수가 든 배열이 문자열로 남는 문제

```ibl
[repeat:2]{[table:take]{items:[{n:$i}],n:1}}
```

배열 안에 `$i`가 있으면 JSON 파싱이 실패했고, 배열 전체가 원본 문자열로 남았다. 나중에 반복 변수가 치환돼도 표 도구가 목록을 받지 못했다.

객체와 같은 재귀적 값 파서를 배열에도 적용했다. 배열 구조를 보존한 채 변수 값만 나중에 치환한다. 잘못된 배열 구분자는 파싱 오류로 거절한다. 기존 repeat의 문자열 param 계약은 회귀검사에서 확인해 유지했다.
