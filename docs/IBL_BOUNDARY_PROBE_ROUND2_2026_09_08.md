## 발견한 원인과 수리

1. **선택 경로를 필드명으로 오독.** `${it.missing?}`뿐 아니라 존재하는 `${it.zero?}`도 `?`가 붙은 열을 찾다가 실패했다. each가 공용 경로 해석 전에 선택 표기를 분리하도록 했다. 없는 선택 경로는 null, 실제 false/0/null은 원래 값이며, 없는 필수 경로는 계속 오류다.
2. **객체와 목록의 문자열화.** `items:[$it]`에서 객체 행이 JSON 텍스트 행으로 바뀌었다. 인용문 밖에서는 객체/목록 리터럴로 전달하고, `text:"$it"`처럼 문자열 자리에 놓인 것은 문자열로 유지한다. 와일드카드로 얻은 목록도 구조를 유지한다.
3. **중첩 each의 이름 범위 침범.** 안쪽 `$it.id`에 바깥 행의 id가 들어가 성공으로 반환됐다. 별칭이 다른 안쪽 행은 유령 변수로 거절됐다. 원문에서 안쪽 do와 닫힌 함수 정의의 구간을 구별하고, 안쪽 이름을 보호한다. 다른 별칭의 바깥 행은 따옴표 깊이에 맞춰 전달한다. 중첩 each의 입력은 바깥 행에서 받을 수 있으며, 안쪽 별칭을 블록 밖에서 쓰는 것은 거절한다.
4. **중첩 반복·오류 처리의 이름 범위 침범.** `[repeat:2]{[repeat:3]{…$i…}}`의 마지막 값이 안쪽 회차 `"2"` 대신 바깥 회차 `"1"`이었다. AST 치환이 안쪽 반복 변수와 catch/finally의 `$error`를 보호하도록 했다. 반복 param의 문자열 타입과 0부터 시작하는 기존 계약은 유지한다.
5. **중첩 함수와 each의 잘못된 호출 서명.** 안쪽 함수의 `$x`를 바깥 함수의 필수 인자로 세거나, 안쪽 지역 할당이 바깥 함수의 인자를 숨겼다. 함수 정의는 별도 스코프로 제외하고, 지연 파싱되는 each do의 이름 범위를 파싱해서 판정한다. 원장에 남은 옛 서명도 v3 마이그레이션으로 갱신한다. 정본 DB는 SQLite backup 후 적용했으며, 본문·성공 통계는 보존했다. 2건의 불필요한 error 인자를 제거했고 다른 1건은 인자 표시 순서만 바뀌었다.
6. **검사 순서에 따른 파서 이중 로딩.** 단독 시험은 통과했지만 전체 회귀에서는 중첩 함수 정의 표를 못 찾았다. `ibl.ibl_parser`와 `ibl_parser`가 별도 인스턴스를 만들고, 재귀 파서와 실행기가 서로 다른 정의 표를 봤다. 시험 6곳·보조 스크립트 6곳의 파서/값 파서 import를 정본 flat 경로로 통일했다. 재귀 콜백과 실행 파서의 동일성 가드를 추가했다.

새 어휘나 관용구는 추가하지 않았다. 이번 변화는 같은 조합을 다시 실행했을 때 값과 이름이 달라지는 결함을 줄인다. 모델이 어떤 관용구를 선택하는지, 실제 보고서 비용이 얼마나 줄었는지는 이 결정론적 시험으로 측정하지 않았다.
