**같은 문장의 기대값 일치율이 수리 전 34/100에서 수리 후 100/100으로 바뀌었다.** 수리 대상 66개 중 29개는 틀린 결과를 내면서 성공으로 표시됐고, 37개는 실행 오류였다. 이 숫자는 고장 가능성이 높은 경계를 의도적으로 고른 시험의 성적이며 시스템 전체의 실패율이 아니다. 66개의 독립된 버그를 고쳤다는 뜻도 아니다.

## 시험 구성

문법 검사만이 아니라 실제 파서·타입 검사·제어문·함수 실행기·표 변환·파일 도구를 사용했다. 임시 폴더와 고정 입력으로 격리했으며 모델과 외부 API는 호출하지 않았다. 최종 값은 JSON 타입까지 비교해 0과 false가 같다고 판정하지 않는다.

- 80개: 10종 값 × 8가지 조합. 한글, 앞자리 0 문자열, 양쪽 따옴표, 개행/백슬래시, 달러 참조처럼 보이는 두 문자열, 0, false, null, 중첩 객체를 교차했다. 배열 행, 목록형 do, 선택 경로 식, 중첩 데이터 전달, 함수/행 이름 겹침, 함수 안의 정의, 표 연쇄 변환을 시험했다.
- 12개: catch의 오류 정보 할당·조건·문자열 보간·each 전달, 반복/행 이름 겹침, 선택 경로 조건식.
- 8개: 없는 필수 경로·누락 인자·스코프 밖 참조·틀린 별칭·지원하지 않는 식·실패한 복구의 거절 대조군.
- 아래 기대값 검토 후 최종 계약상 정상 결과 90개, 정직한 거절 10개다.

### 기대값 정정 2건

`nested_do_list_4/5`는 실행할 do 원문에 미할당 `$child.id`/`${child.id}`를 직접 적었으므로 거절이 옳다. 이를 데이터 문자열이라고 가정했던 기대값을 고쳤다. 반면 `nested_data_4/5`는 **행 데이터로 전달된** 같은 글자이므로 변수로 다시 해석하면 안 된다. 후자는 실제 결함이며 수리했다.

최초 실행과 최초 기대값은 보존했다. `baseline_reviewed`는 과거 결과에 확정 기대값을 적용한 재판정이며 새 실행으로 표시하지 않는다. 코드 100개는 전후 동일하다. 기존 오류를 무조건 성공시키는 방식으로 성적을 올리지 않았다.

## 발견과 수리

1. **배열 행의 인덱스 접근 실패.** `items:[[1,2]]`의 `$it.0`을 스칼라 행의 없는 필드로 거절했다. 객체와 목록 모두 공용 `field_path`를 통해 읽는다. 범위를 벗어난 필수 인덱스는 계속 오류다.
2. **목록형 do의 중첩 스코프 손실.** 안쪽 `do:["…$it.v…"]`가 보호 대상에서 빠져 바깥 행의 값으로 바뀌었다. 문자열과 목록 형태 모두 안쪽 이름 범위를 보존한다.
3. **데이터의 달러 문자를 재실행.** 바깥 행의 `"$child.id"`가 안쪽 행의 id인 2로 바뀌었다. 코드로 삽입하는 값의 달러 문자는 표준 Unicode escape로 운반하고 최종 문자열 파서가 복원한다. 변수 참조와 이미 주어진 값을 구별하며, 객체·목록 안의 문자열에도 적용한다.
4. **함수 인자가 each 별칭에 가려짐.** 함수 안의 `each as:"x"` 때문에 함수 전체에서 인자 x를 예약어 취급했다. 이제 행 이름은 그 each의 do 안에서만 바깥 주입을 막는다. 입력과 뒤 문장에서는 함수 인자를 읽을 수 있다. 실행기의 주입과 호출 서명 계산을 함께 맞췄으며, 현재 이름 붙은 원장의 저장 서명이 달라지는 행은 없었다.
5. **함수 안 do의 닫힌 정의를 변형.** 바깥 함수 인자가 do 문자열 안의 중첩 `[def:g]` 몸까지 치환해 g의 인자를 상수로 만들었다. each 행, 함수 인자, 제어문 값이 같은 `bind_scoped_code` 경로를 사용하며, 닫힌 함수 정의는 그 함수의 호출자가 채운다.
6. **catch에서 오류 정보를 식으로 사용하지 못함.** `$return=$error.action`이 `$return=read`라는 코드가 되어 이름 오류를 냈고, 조건식도 실패했다. 식·조건에는 문자열 치환 대신 실제 값 바인딩을 전달한다. each do는 인용문 깊이를 고려하는 코드 치환을 사용한다. 반복 안 each가 같은 이름을 쓰는 경우도 안쪽 행 이름을 보호한다. 기존 반복 param의 문자열 타입은 유지한다.
7. **선택 경로가 식·조건에서만 실패.** `${x.v?}`를 `v?`라는 필드로 찾았다. 식 할당과 조건 평가에서도 선택 표기를 분리한다. 실제 0/false/null/문자열/객체를 보존하고, 없는 선택 경로는 null로 처리한다. 필수 경로와 실패한 할당의 진단은 유지한다.

어휘·관용구를 늘리지 않았다. 검증된 조합이 입력 모양이나 중첩 방식 때문에 틀어지는 실행 결함을 수리했다. 모델의 관용구 선택률이나 실제 보고서의 비용 절감은 이번 결정론적 시험의 측정 대상이 아니다.
