# IBL 조합 경계 시험 — 네 번째 100문장 수리

2026-09-08, 정본 `a2883dab`에서 시작. 직전과 같은 규모의 **새로운 100개 문장**을 고정하고 실제 실행 결과를 비교했다.

**기대 결과 일치율은 수리 전 20/100 → 수리 후 100/100.** 수리 전 80개 불일치 중 **47개는 틀린 값을 내면서 성공으로 표시**됐고, 33개는 실행 오류였다. 고장 가능성이 높은 조합을 의도적으로 고른 시험이며, 시스템 전체의 실패율이나 독립 버그 80개의 발견을 뜻하지 않는다.

## 방법과 기대값 검토

실제 파서·타입 검사·함수·반복·복구 실행기와 표/파일 도구를 사용했다. 외부 서비스와 모델은 호출하지 않았고, 파일 작업은 임시 폴더에서 실행했다. 문법 통과만 세지 않고 사전에 적은 최종 값과 JSON 타입까지 비교했다. 실제 보고서의 비용·품질이나 모델의 관용구 선택률은 측정하지 않았다.

- 64개: 8종 값 × 8가지 조합. each/함수 인자와 회차 이름 겹침, 반복 후 바깥 인자 보존, 목록형 do의 중첩 반복, 행/함수 참조가 든 주석, 가짜 블록이 든 주석.
- 12개: catch에서 없는 필수 경로 거절, 선택 경로의 null, 문장 안 선택 경로의 빈 문자열.
- 8개: catch의 실제 오류 필드를 파라미터·each·식·조건으로 전달하는 대조군.
- 16개: 일부 행 실패 후 뒤 행의 값 보존, 반복 결과 누적과 이름 겹침.

100개 모두 전후 문법 검사를 통과했다. 확정 계약상 정상 결과 96개, 정직한 거절 4개다.

`r4_fn_comment_4/5/6/7`의 기대값은 검토 중 정정했다. **do 원문의 따옴표 안 치환은 문자열 보간**이므로 0/false/null/객체는 기존 규약상 각각 `"0"`, `"False"`, `""`, JSON 문자열이 된다. 최초 기대값은 원시 타입으로 잘못 적었다. 이 네 문장의 수리 전 실행은 모두 주석의 없는 필드를 읽다 실패했으므로, 정정 전후 수리 전 점수는 모두 20/100이다.

최초 코드·기대값·실행 결과를 보존했다. `before_reviewed`는 같은 과거 결과를 확정 기대값으로 재판정한 것이며 새 실행이 아니다. 최종 비교의 전후 100개 코드와 기대값이 동일함을 기계적으로 확인했다.

## 수리한 결함

1. **바깥 값이 반복 회차를 덮어씀.** each의 `as:"x"`나 함수 인자 x가 내부 `[repeat:2,as:"x"]`의 x까지 바꿨다. 반복 몸과 조건의 이름 범위를 AST 주입과 지연 코드 주입 양쪽에서 보호한다. 함수 전체의 인자 목록에서 회차 이름을 지우던 계산도 해당 블록 안에서만 제외하도록 맞췄다. 반복 밖의 같은 이름은 여전히 호출 인자다. catch/finally의 error도 같은 지역 범위를 지킨다.
2. **목록형 do 안의 반복 변수를 미할당으로 오판.** 문자열형 do만 파싱하고 목록형은 원문 그대로 훑어 `$i`를 인자/오타로 셌다. 실제 실행처럼 문장 목록을 연결해 분석한다.
3. **주석을 실행 코드로 읽음.** 주석 속 `$it.missing`·`$x.missing` 때문에 정상 문장이 실패했다. 지연 바인더가 주석을 보존하되 치환하지 않는다. 추가 검증에서 주석의 `}`가 블록을 끊고 따옴표가 문자열 상태를 오염시키는 경로도 확인해, 파서 전처리·괄호 추출·문자열 위치 검사에서 함께 수리했다. 문자열 안의 Markdown 제목·URL 조각·개행·들여쓰기는 보존한다.
4. **전달된 달러 문자열을 변수 검사기가 다시 참조로 읽음.** 실행 치환은 `$child.id`를 Unicode escape로 보호해도, 자유 변수 검사기가 파싱 후 원래 문자를 복원해 미할당으로 거절했다. 검사 전용 AST에서 이스케이프된 dollar를 참조로 세지 않게 했다. 실행할 원문과 최종 데이터는 바꾸지 않으며, 실제로 적은 미할당 `$child.id`는 계속 거절한다.
5. **없는 오류 필드를 빈 문자열로 바꿈.** catch의 필수 `$error.absent`가 빈 문자열로 성공했다. 필수 결측은 오류, 선택 결측은 값 자리 null/문장 안 빈 문자열로 구분한다. 바인딩 오류도 실행 오류와 같은 경로로 처리해 원래 try 오류·catch 오류와 traceback을 함께 보존하고 finally를 실행한다. finally가 실패할 때 스칼라 결과에서도 진단을 남긴다. 반복 바인딩 실패도 회차 정보를 보존한다.
6. **종료 조건에서 회차 변수 미할당.** 추가 검증에서 while/until의 회차 이름은 서명상 지역 변수인데 평가 시 현재 값이 없음을 확인했다. 조건에 0부터 시작하는 실제 회차를 바인딩한다. 바깥 인자가 같은 이름이어도 회차 값이 우선한다.

새 어휘나 관용구는 추가하지 않았다. 이미 표현 가능한 조합이 이름 겹침·주석·오류 복구 때문에 틀어지지 않도록 실행 기반을 수리했다. 저장된 이름 붙은 관용구 39개의 호출 서명을 점검했으며, 변경 필요 0개·파싱 실패 0개라 운영 원장은 수정하지 않았다.
