# IBL 문장 경계 시험 6회차 — 지연 코드·통화·함수 범위

2026-09-08, 정본 기준 `cef3c8d9`. 문법적으로 올바른 75문장을 직접 실행·each·중첩·함수·반복·병렬 형태로 비교했다. 같은 문장과 기대값으로 **44/75 → 75/75**를 확인했다. 성공해야 할 문장 72개와 거절해야 할 음성 대조군 3개이며, 기준 코드의 불일치 31개는 실행 실패 30개와 **성공했으나 다른 값을 반환한 1개**다. 31개의 독립적인 버그라는 뜻은 아니다.

## 공통 경로의 수리

1. **지연 실행 경계를 첫 문장에서도 세운다.** 기존 엔진은 앞 결과가 있어야 do를 IR로 컴파일했다. 첫 each의 문자열 안에 `$items`가 있으면 바깥 파이프 바인더가 그것을 자기 통화로 먼저 읽었다. 이제 일반 값 치환 전에 지연 코드를 컴파일하며, 함수 정의/제어 블록의 독립된 범위는 건드리지 않는다.
2. **통화 바인더도 실행 표현을 읽는다.** `${it.v} / $items.v`에서 행 값이 이미 묶였어도, 기존 바인더는 표시용 원문 `str(Template)`을 다시 읽어 `${it.v} / [7]`을 기록했다. `$items`를 공통 `bind_template`에 연결해 아직 남은 Ref만 해소한다. 바인딩된 `$items` 모양의 데이터는 Literal로 보존하고, 목록→텍스트 경고와 행 수 상한은 유지한다.
3. **명시 입력이 자동 전달보다 우선한다.** `[table:take]{items:[{v:{x:7}}],n:1} >> [table:take]{items:$items.v,n:1}`은 `{x:7}`을 선택해야 한다. 기존 data-ops 입구는 `_prev_result`를 먼저 채택해 `{v:{x:7}}`을 반환했다. 개별 take만 고치지 않고 변환자의 공통 입력 선택을 수정했다. 명시 items/table/inputs/입력 쌍을 먼저 읽으며 빈 목록도 명시 입력이다. chunk의 items도 같은 우선순위를 갖는다.
4. **지연 함수 호출에 작성 위치의 정의 표를 연결한다.** `[def:f]` 뒤의 `each{do:"[fn:f]…"}`가 f를 찾지 못했다. 파서가 각 each에 함수 범위를 남기고, 컴파일된 트리에 기존 함수 표 참조를 연결한다. 지역 정의가 바깥 정의보다 우선하며 행마다 계획 원본을 변경하지 않는다. 함수 본문을 문자열로 끼워 넣지 않는다.
5. **행 이름은 지역 이름이다.** 추가 검사에서 함수가 each 밖의 `$it`를 사용해도 누락 인자로 검출되지 않고 그대로 방출되는 문제를 발견했다. 전역 예약은 `$items`만 남겼다. `$it`는 해당 each의 do에서만 지역 행 이름이며, 함수의 다른 위치에서는 명시 인자가 필요하다. 함수가 호출자 행을 암묵적으로 캡처하지 않는다.

새 어휘나 관용구를 추가하지 않았다. 기존 문장과 관용구가 거치는 컴파일·바인딩·입력 선택·함수 범위 경로를 수리했다. `$items`의 행별 필드 선택과 텍스트 보간 계약은 유지한다.

## 검증과 실험의 정정

- 고정 75문장: `scripts/ibl_boundary_cases_round6.py`. 기준 코드와 최종 코드의 문장/기대값/결과는 [감사 JSON](experiments/ibl_boundary_round6_2026_09_08.json)에 보존했다.
- 별도 25개 불변식: 부분 바인딩의 값 보존·JSON 전송·계획 불변, 명시 입력과 빈 통화, 함수 정의 앞당김·병렬·지역 이름 우선·닫힌 인자 범위 등을 검사한다.
- 최종 전체 backend: **3,003 passed, 2 skipped, 100 warnings / 110.01초**. 기존 경고이며 원시 기록은 `outputs/ibl_round6_full_verified.txt`.
- 앱 API에서 열 선택, 지연 함수 2행, 혼합 보간, 누락 인자 거절을 확인했다. 모델·외부 서비스 호출은 없다. `outputs/ibl_round6_live.json` 및 `outputs/ibl_round6_live_project.json`에 기록했다. 최초 파일 smoke는 프로젝트 컨텍스트 없이 요청해 거절됐으며, 수동모드 프로젝트를 지정한 요청에서 정상 동작했다.

실험 설정도 오류 가능성이 있으므로 다음 정정을 제품 오류 수와 구분한다.

- bare 파일명 쓰기는 outputs/로 리다이렉트되므로 읽기 경로를 `outputs/probe.txt`로 바로잡았다.
- 함수의 최상위 인자에 직접 쓴 `$items`는 데이터가 아니라 살아 있는 참조다. 달러 문자열 보존 시험에서는 행 데이터→함수 인자 경로로 전달하도록 바로잡았다.
- each는 스칼라 행을 `{value:…}`로 승격한다. 직접 실행과 each를 동일한 값으로 비교하는 통화 시험은 객체 값을 가진 열로 고정했다.
- 재사용한 fixture의 dedup 품질 판정기가 스칼라 행에 `.get`을 호출하고, 이 예외가 정상 엔진 결과를 덮는 문제도 수리했다. 품질 판정 실패는 품질 verdict에 남기며 엔진 결과를 변경하지 않는다.
- 첫 경계 수리 도중 함수 정의의 지역 슬롯까지 미리 치환하는 회귀가 기존 8개 검사에서 드러났다. 정의를 닫힌 범위로 보호한 뒤 통과했다. 이것을 기준 코드의 결함 수에 섞지 않았다. 마지막 검토에서는 기존 공백·숫자 열 이름 계약과 빈 부분 보간의 텍스트 타입도 별도 검사해 보존했다.

정정 전 원시 기록도 outputs/에 보존했다. **최종 44/75 기준치는 정정된 동일 문장을 기준 커밋의 실제 생산 모듈로 다시 실행한 결과**다. 작업 파일을 되돌리지 않고 별도 프로세스 메모리에서 해당 커밋의 모듈만 로드했다. 현재 fixture/오라클을 양쪽에 공통 사용했다.

## 증거의 범위

이번 시험은 잘못된 순서의 바인딩, 값 유실, 명시 입력 무시, 함수 범위 단절을 줄였다는 증거다. 모든 언어 조합의 무결성, AI의 관용구 선택 개선, 보고서 품질·토큰·벽시계 비용 절감은 증명하지 않는다. 실제 폰 설치/실행과 몸 사이의 지역 함수 정의 이동도 검증하지 않았다. 함수 정의 표의 기존 프로세스 수명·보존 상한은 유지한다.

어휘·문서 파생, Android 번들, backend 층, 은퇴 계약, 파일 크기, diff 공백 검사를 통과했다. 자동 리로더로 앱에 반영되었으며 수동 재시작은 하지 않았다.
