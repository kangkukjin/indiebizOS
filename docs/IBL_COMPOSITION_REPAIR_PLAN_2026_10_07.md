# IBL 작업 연속성과 조합 능력 수리 계획

긴문장 상상훈련에서 반복된 계약 불일치·재실행·발견 비용을 공통 능력의 개선으로 연결한다.
확실하고 작은 결함을 먼저 닫고, **승인과 대기를 포함한 작업 연속성 → 실행 경계와 작업 제어 →
부분 수정과 검증 → 능력 발견과 축적** 순서로 발전시킨다. 기존 계약·원장·Script·평가기를 확장한다.
목적은 [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)의 품질·실제 완료 시간·전체 토큰이다.

## 1단계 승인과 대기를 이어가는 실행 계약

우선 닫을 반례는 [28회차](experiments/long_sentence_imagination/round_28/report.md)의
위임 1회 뒤 승인 2회가 필요한 프로그램이다. 소유자는 기존 Journal·Runtime·action_requires·
approval_tokens와 HTTP/MCP/승인 화면이다. 같은 실행을 찾는 핸들·호출 신원·권한을 재사용한다.

1. 실제 도구 실패와 **실행 전 승인 대기**를 분리한다. 승인 대기는 완료된 실패 영수증으로 고정하지 않는다.
   실행 ID·프로그램 판본·호출 위치와 반복 순번·해석된 인자·행위자·대기 이유를 보존한다.
2. 사람의 승인은 정확한 작업 인스턴스와 대상·인자 지문에 결속한다. 전역 토큰 소비 횟수를 늘리지 않는다.
   동적 반복의 두 삭제는 서로 다른 작업이며, 일괄 승인을 지원한다면 사람이 본 유한 대상 집합과 정확히 결속한다.
3. 승인 뒤 기존 실행을 재개한다. 이미 완료된 호출은 영수증으로 복원하고 대기한 호출만 집행한다.
   순수 계산의 재실행은 허용하지만 완료된 외부 효과를 반복하지 않는다. 효과 불명은 확인 전 재실행하지 않는다.
4. 승인 뒤 코드·인자·대상·권한이 바뀌면 그 승인을 적용하지 않는다. 취소·만료·재기동 후 재승인은
   기존 완료 작업을 유지한 채 해당 대기 지점에 다시 결속한다. 이전 실행 포맷의 resume은 호환 경로로 보존한다.
5. 긴 작업의 pending 접수증도 같은 중단·이벤트 재개 계약으로 연결한다. 현 유한 wait의 반환 의미는 유지하고,
   지속 대기가 필요한 호출만 자식 작업의 완료 이벤트를 기다리게 한다. HTTP 연결 수명과 작업 수명을 분리한다.

기계가 보장하는 것은 확인된 완료 효과의 중복 방지다. 응답을 잃은 외부 서비스에 보편적인 exactly-once를
약속하지 않는다. 공급자가 멱등 키·상태 조회를 제공하면 이를 이용하고, 없으면 효과 불명을 노출한다.
새 스택 VM·언어 키워드는 선행 조건이 아니다. 기존 재생 방식으로 위 성질이 충족되는지 먼저 구현한다.

**완료 조건:** 위임 1회→삭제 A 승인→삭제 B 승인→보고서의 전체 흐름에서 위임·삭제 각각 1회.
승인 응답 재전송, 승인 전후 프로세스 종료, 만료, 인자 변경, 루프와 병렬 가지, 효과 불명 주입에서도
무승인 실행·중복 효과가 없어야 한다. HTTP와 MCP가 같은 실행을 회수하고 사용자 화면에 대기 이유와
남은 작업을 표시해야 한다. 승인 전 실행 가능한 check 안내는 보조이며 재개 계약을 대신하지 않는다.

**대체할 경로:** 승인 후 전체 요청 신규 실행, 승인 두 개 때문에 수동으로 프로그램을 쪼개는 강제 우회.
일반 도구 실패를 무조건 재시도하거나 과거 실패 영수증을 성공으로 바꾸지 않는다.

## 2단계 원시 부품과 Script의 계약 연결

소유자는 기존 callable_contract·op 투영·어댑터·script_ops와 빌더다. 1단계와 독립인 계약 정합·발견
작업은 먼저 진행할 수 있다. background Script의 재개 연결은 1단계의 지속 실행 계약을 소비한다.

- 입력·반환·효과·자원·오류·실행 위치·동기/비동기 지원을 기존 정의에서 한 번 해소해 describe·check·
  실행·회상이 공유하게 한다. 반환 선언과 실사용 관측은 구분하고, 다른 op·다른 입력 조건의 관측을 빌리지 않는다.
- 기존 표 변환 부류의 계약 검증을 확장한다. 모든 선언된 행 생산자×행 소비자, 순수 함수 중첩,
  별칭·nullable·빈 자료·부분 실패에서 동일 계약을 적용한다. 도메인명이나 액션 목록을 엔진에 넣지 않는다.
- 효과 추론은 IBL의 합성 가능한 코드와 명시 경계에서 수행한다. 원시 핸들러의 파일·네트워크·
  프로세스·모델 효과는 검토된 선언이 기준이다. AST는 명백한 불일치를 신고하는 보조 수단이고,
  unknown은 검토나 격리 근거 없이 자동 완화하지 않는다. 같은 의미의 두 선언이 있으면 한 소스로 수렴한다.
- L26-4는 기존 plain JSON Script의 입력/반환 설명과 프로토콜·background 지원을 함께 다룬다.
  기존 stdin/stdout·비동기 접수증·operation_outcome을 보존하며 목록/상세 조회에서 사용 계약을 확인한다.
  새 wire로 이행할 필요가 있으면 생산자와 소비자를 함께 바꾸고 기존 비동기 소비자의 회귀까지 닫는다.
- 외부 계산의 입력·코드·환경 판본·결과·산출물 참조를 기존 Script 원장에 연결한다.
  상태 객체는 세션 수명을 지키고 export한 값만 다음 실행으로 넘긴다. 임의 셸을 자동으로 pure로
  등록하거나 ~turn 경계를 풀지 않는다. 영속 스크립트는 기존 등록·정의 갱신 경로를 사용한다.

**완료 조건:** 등록 스크립트의 적합한 입력·반환을 원문 코드 없이 발견해 호출하고, 결과를 IBL의
다음 함수와 최종 검증에 연결한다. 정상·부분 실패·동기·background의 값과 효과 기록이 일치한다.
코드·환경·입력 변경은 이전 근거를 현재 성공으로 승계하지 않는다. `시험`의 기존 비동기 실행을 보존한다.

**대체할 경로:** 계약을 알아내기 위한 구현 원문 전독, 같은 부품의 별도 설명/타입 표, 낱말별 .items 우회.
재귀 지원 여부는 이 단계의 완료를 막지 않는다.

## 3단계 비동기 작업의 소유권과 종료 계약

소유자는 task_receipts·delegation_tasks·SystemAIRunner·steer_inbox와 각 실제 작업 실행기다.
통합할 것은 작업의 상태와 전달 규칙이며, 위임·렌더·신문·노트북을 단일 실행기로 바꾸지 않는다.

- 접수 시각·주체·부모·결과/실패·취소 지원과 상태 전이의 책임을 기존 작업 원장에 명확히 둔다.
  task_receipts는 한 관측 계약을 제공하고, 어댑터는 실제 작업을 관찰·제어하는 기능만 맡는다.
- 부모 실행 중 완료, 부모 종료 후 완료, 재기동 사이 완료를 기존 보고/회수 원장으로 잇는다.
  전달 이벤트에 고유 신원을 두고 미회수 보고를 보존한다. 재전달은 가능하되 같은 완료의 재처리를 막는다.
  L29-1의 메모리 큐 연기만으로 재기동 내구성이 보장된다고 간주하지 않는다.
- 취소 요청→요청 수신→실제 종료 확인을 구분한다. 에이전트의 특정 작업 취소를 상주 러너 전체 중지로
  대체하지 않는다. 해당 작업의 자식·프로세스와 소유권을 연결하고, 취소할 수 없는 원격 작업은 그대로 노출한다.
- 프로젝트 에이전트·시스템 AI·웹소켓 등 부모 표면이 다르더라도 읽은 결과의 회수 표식과
  미회수 완료 보고의 전달 규칙을 공유한다. 실행 저장소를 무조건 물리 통합하지 않는다.

**완료 조건:** 접수 전후 취소·완료/취소 경합·부모 종료·재기동·중복 완료 보고·부모 대기 중 완료에서
유령 작업·보고 유실·거짓 cancelled·같은 결과의 불필요한 새 턴이 없어야 한다.
지원하지 않는 취소와 결과가 확인되지 않은 작업은 명시적으로 남는다.

**대체할 경로:** 작업 종류마다 별도로 판단하는 종료·통지·회수 정책. 각 실행기의 실제 종료 어댑터는 유지한다.

## 4단계 부분 수정과 완료 근거를 연결

소유자는 기존 결과 참조·의존성·읽기/모델 재사용·산출물 저장·criteria·최종평가다.
1단계의 같은 실행 재개와 **새 입력이나 수정 프로그램의 새 실행**을 분리한다.

- 수집·정규화·계산·표현의 입력/출력 참조와 정의·설정·원천 판본을 연결한다. 전체 새 DAG 저장소를
  먼저 만들지 않고 기존 기록에서 어떤 의존을 해소할 수 없는지 확인해 필요한 계약만 확장한다.
- 표시만 변경되면 계산 결과로 새 표현을 만들고, 원천이나 정책이 변경되면 영향을 받는 계산만 새로 수행한다.
  실패·부작용·unknown은 재사용 자격을 별도로 판정한다. 33회차의 파일 지문 수리는 선행 상태로 확인하되
  mtime/size만으로 모든 내용 변경과 읽기 중 변경이 검출된다는 보증을 하지 않는다.
- 각 완료 기준을 원천 스냅샷·산출물 판본·검증 범위·결과 참조에 연결한다. 재독 일치는 저장 무결성의
  근거로만 사용한다. 원문 보존·총량 보존·결합의 행 중복/누락·부분 자료의 null 의미는 별도의 검사 근거다.
  업무별 정답은 함수·데이터에 두며 코어는 이 근거의 연결과 유효성을 맡는다.
- 기존 평가자는 필요한 기준별 검증 근거를 받는다. 이미 있는 근거를 다시 설명하기 위한 AI 왕복을 줄이고,
  기준이나 산출물이 바뀌면 이전 승인을 현재 승인으로 사용하지 않는다. 평가 모델이나 재수집을 상시 추가하지 않는다.

**완료 조건:** 표현 변경은 수집/모델 호출 0, 정책 변경은 유효 원천 재수집 0, 실제 원천 변경은 낡은 결과
재사용 0을 해당 입력 조건에서 확인한다. CRLF 손실·빈 키 누락·중복 조인으로 만든 오답은 저장 재독이
성공해도 완료 기준의 독립 검사에서 실패한다. 검증 비용도 전체 작업 비용에 포함한다.

## 5단계 발견과 재사용이 실제 행동으로 이어지게 하기

소유자는 기존 실행기억·스크립트/관용구 목록·describe·회상·세계 지도와 계획/실행 맥락이다.
세계 지도의 이름·관계 제공 역할은 유지하고, 실행 가능한 부품의 계약은 기존 능력 조회에서 제공한다.
현재 하위 과제와 입력 형식·환경·효과 제약에 맞는 후보를 연결하며 적합 후보가 없으면 새 구현을 허용한다.

계약을 찾은 뒤 원문을 모두 읽지 않아도 호출할 수 있게 하고, 후속 요청에서는 자기 결과·코드 참조를
직접 회수한다. 검증된 부분 프로그램은 입력·반환·적용 조건·의존 판본과 함께 기존 선정/등록 경로로 축적한다.
훈련 기록을 운영 기억에 무조건 시딩하지 않는다. 제시·이름 언급·실행·품질 기여를 구분한다.

**완료 조건:** 저장 부품의 이름을 주지 않은 새 과제와 입력 변경에서 적합 후보의 발견→계약 조회→
실행→결과 기여를 확인한다. 부품이 부적합한 과제에서는 사용을 강요하지 않는다. 사용률만 늘거나
IBL 선택 때문에 전체 품질·시간·토큰이 악화되면 개선으로 판정하지 않는다.

## 실행 순서와 검증 규칙

작은 수리 묶음 뒤 첫 구조 구현은 1단계의 **위임 1회와 승인 2회의 전체 흐름**이다. 2단계의 정적 계약
정합과 목록 발견은 독립적으로 착수할 수 있다. 비동기 Script 연결·3단계는 지속 실행 계약을 소비한다.
4단계의 독립 품질 검사는 처음부터 적용하고, 자동 부분 재계산은 앞선 효과·원천 계약 위에 확장한다.
5단계의 완전한 축적을 기다리지 않고 각 단계의 소비자 발견성을 함께 개선한다.

각 묶음은 기존 소유자·생산자·소비자·대체 경로·인수 시험을 함께 변경한다. 기존 원장에 상태를 남기고
관련 계약 명세를 갱신한다. 개별 업무 성공을 범용 성능 향상으로 확대하지 않는다.
[회귀 절차](REGRESSION_TESTING.md)의 선택기와 관련 검사를 사용하며, 허브·영향 범위 미확정은 전수로 확인한다.
구조 구현의 선행 조건으로 새로운 대규모 벤치마크 체계를 만들지 않는다. 계약 인수 후 독립 AI의
미사용 과제·부분 실패·후속 수정으로 실제 작성 행동과 비용을 관측한다. 비교 조건이 다른 실행은 절감률로 합치지 않는다.
