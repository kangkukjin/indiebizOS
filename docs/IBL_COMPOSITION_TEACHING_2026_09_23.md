# IBL 조합 교재와 검증 경계 개선

2026-09-23. [개선 방향 조사](IBL_COMPOSITION_DIRECTIONS_2026_09_23.md)의 첫 구현.
목표는 새 요구에 맞춰 함수·관용구·일반 액션을 한 프로그램으로 연결하도록 가르치는 것.

## 반영

- 실제 기본 환경에 쓰이는 compact 교재에 실행 가능한 def→each→fn→if 예제와
  `read_guide(query="ibl_composition.md")` 입구를 추가했다. 문법 전문의 파일도 명시했다.
  2,746자에서 3,528자로 증가했다. 4,200자 상한을 시험해 전문 상시 주입을 막는다.
- 상세 교재도 같은 가이드를 가리킨다. `guide_db.json`에 IBL 주제로 등록했다.
  가이드 정확 파일명 조회와 compact/full 환경 조립을 실제 함수로 검사한다.
- 새 가이드는 파이프, 지역 함수 안의 기존 관용구, 독립 병렬, 빈 결과, 장애 복구,
  실패 항목만 재시도, 전량 분할·통합을 다룬다. 기존 상시 관용구 선정은 변경하지 않았다.
  변형이 필요할 때만 해당 관용구의 정의를 열고 지역 함수로 바꾸도록 안내한다.
- 기본 each의 봉투 오류와 on_error:keep의 실패 행을 구분한다. 실행기 docstring과
  실제 실패 안내가 지원하지 않는 filter 연산자 exists를 권하던 부분도 ne/null로 고쳤다.
  실패 0건에서는 _error 열 자체가 없으므로 봉투 계수로 먼저 분기하도록 예제와
  data-ops의 결측 열 안내를 맞췄다. 전부 성공·전부 실패도 같은 재시도 프로그램으로 시험한다.
- `/ibl/validate`가 def와 fn을 일반 노드/액션으로 오인하던 거짓 오류를 고쳤다.
  지역 함수→저장된 코드 소스 순으로 호출 몸을 읽고 쓰기·AI 호출을 펼친다.
  실행기와 검수기가 공유하는 본문 정규화·인자 주입 함수는 workflow_contract의
  공개 함수로 승격하고 기존 호출처도 함께 옮겼다(층 밖의 private 참조 금지 규약).
  each 내부 호출에는 실행기와 같은 함수 정의 표를 연결한다. 실행하지 않은 함수 정의는
  쓰기로 표시하지 않으며, 모르는 몸·재귀/중첩 검수 상한은 효과 미확정으로 표시한다.
- check:true의 정적 타입 검사와 검증 API는 서로 다른 표면이다. 이번 API 수정이
  기존 check:true에서 모든 함수가 거절됐다는 뜻은 아니다. 교재는 정적 통과를
  실제 입력 크기·내용 품질·외부 서비스 성공으로 해석하지 않도록 한다.

## 실행 예제의 경계

교재의 fenced IBL 블록을 시험이 직접 추출한다. 파서·함수 해소·table 연산·블록·반복은
실행기를 사용하고, 크롤링만 고정 응답으로 대체한다. 관용구 조회·실적 기록은 시험 대역을
사용해 운영 해마 실적을 올리지 않는다. 실제 외부 AI·웹은 호출하지 않는다.

- 새 함수 안에서 정렬 관용구를 부르고 결과에 가중 점수를 붙인다. 최소 점수를 높인
  변형은 정상적인 빈 목록을 반환한다.
- 빈 결과와 읽기 장애는 서로 다른 상태를 반환하며 catch 진단도 남는다.
- 첫 성공 주소는 한 번, 실패 주소는 두 번만 읽는다. 두 번째에도 실패한 경우와
  회복한 경우를 각각 확인한다. 실패 이력과 최종 미해결 실패를 혼동하지 않는다.
- 분할은 빈 문자열, 3조각, 130조각을 시험한다. 모든 ID·위치·본문을 모으면 원문과 같다.
- 함수 속 쓰기·AI 호출, each 속 함수, 존재하지 않는 액션, todo, 재귀 상한을 검사한다.

함수 인자로 전달한 목록에 봉투 count가 항상 남는다고 가정하지 않는다. compact 예제는
호출 전에 알고 있는 행 수를 개수 인자로 명시한다. 소스가 큰 실제 업무에서는 처리 상한과
미처리 계수를 함께 확인한다.

## 범위와 후속 측정

이 시험은 교재와 실행기가 일치하는지 검증한다. 생성 모델의 새로운 업무 조합 성공률이나
실제 총토큰 절감은 아직 측정하지 않았다. 교재에 없는 도메인·구조 조합을 따로 남기고,
같은 모델·자료·품질 기준으로 첫 완주·수리·중복 실행·내외부 AI 비용을 비교해야 한다.

AI 팁 보고서 스크립트의 누적 기록 입력 초과와 영수증 확정 시점은 이번 수정에 포함하지
않았다. 교재는 그 부류를 피하는 설계를 가르치지만 기존 스크립트의 오류를 소급 수리하지는
않는다. 동적 크기 검사·재개 경계·관용구 선택의 추가 개선도 별도 후속 대상이다.
