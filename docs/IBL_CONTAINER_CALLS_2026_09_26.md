# 객체·목록 값 자리의 호출

## 문제와 결정

에피소드 4071은 `return {budget:[fn:본문에서찾기]{...},gpu16:[fn:본문에서찾기]{...}}`를
작성했다가 `PURE_EXPRESSION`으로 거절되어, 같은 호출을 임시 변수로 분리해 다시 제출했다.
값을 만드는 자리에서 기존 호출을 조합할 수 있게 하여 이 작성·수정 왕복을 없앤다.
공통 목적은 [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)을 따른다.

객체 필드·목록 원소·호출 인자 객체에 호출과 `>>`, `&`, `??` 조합을 허용한다.
임의 어휘 이름을 컴파일러에 추가하지 않는다. 기존에 유효했던 코드의 뜻은 유지하며
판본 1과 기능어 코어 노드 집합은 변경하지 않는다.

## 실행 계약

- 객체 필드와 목록 원소는 원문의 순서대로, 중첩 값은 그 자리에서 평가한다.
  호출 인자도 먼저 원문 순서로 완성한 뒤 바깥 함수를 호출한다.
- 각 호출은 한 번 실행한다. 같은 함수·같은 인자가 두 위치에 있으면 별개의 두 호출이다.
  자동 병렬·중복 제거·외부 호출 캐시는 추가하지 않는다. 병렬은 `&` 또는 each의 명시 옵션이다.
- 잡히지 않은 실패가 나면 뒤의 값과 바깥 호출은 실행하지 않는다. 객체 전체에 트랜잭션이나
  롤백을 부여하지 않는다. 이미 완료된 쓰기는 기존과 같이 남는다.
- 기존 `Runtime.eval`/`invoke`를 그대로 통과해 권한·공유 예산·취소·효과·출처·진단·영수증을 보존한다.
  완료 영수증은 같은 실행 재개에서 재사용하고, 완료가 불명인 쓰기는 `EFFECT_UNCERTAIN`으로 막는다.
  기록된 실패도 재사용하므로 resume를 실패 호출의 자동 재시도로 해석하지 않는다.
- 값을 앞 문장으로 끌어올리는 AST 변환은 하지 않는다. 기존 실행기가 이미 자식 노드를
  순차 평가하므로, 분기·반복·함수 프레임과 원문 위치를 보존하는 직접 평가가 더 작고 명확하다.

## 경계와 검사

- 순수 자리인 산술·비교·내장 함수 인자·조건·람다·보간·기본값의 규칙은 유지한다.
  그 안에 객체·목록으로 감싸도 도구 호출은 허용되지 않는다. 먼저 호출 결과를 변수로 받는다.
- 객체·목록 안에 if/try/repeat/def 등의 제어 블록을 직접 넣는 것은 `VALUE_EXPRESSION`으로 거절한다.
  실행 문장이나 명시 함수 본문을 사용한다. `[table:each]{...}{...}`는 기존의 호출 및 반환 프레임이다.
  따라서 컨테이너 자체는 새로운 변수 범위·return 프레임을 만들지 않는다.
- 정적 오류는 전체 프로그램의 어떤 필드에 있든 외부 실행 전에 거절한다.
  중첩 호출의 타입·필수 인자·의존 정의·효과·AI 호출 상한을 기존 검사에서 관측한다.
- 병렬 쓰기 검사는 바깥 호출의 자원뿐 아니라 인자 안에서 실행하는 호출도 조사한다.
  함수 본문·인자 양쪽을 포함하며, 지역 정의가 가린 같은 이름 어댑터의 효과는 더하지 않는다.
  정적으로 알 수 없는 자원까지 무충돌로 증명하지는 않는다.

## 검증

회귀는 고정 응답 어댑터와 임시 파일·영수증 DB를 사용한다. 실제 메일·웹 검색·사용자 파일 변경은 없다.
값·타입 동등성, 깊이 우선 순차 실행, 미실행 분기, 함수 반환 격리, 중첩 인자의 실패,
each·명시 병렬, 실패 근거와 원문 위치, 공유 예산·취소, 재개 중복 방지·불명 쓰기 차단,
병렬 쓰기 충돌, 모델 호출 관측, 순수 자리 제한과 교재 예제를 검증한다.
에피소드 4071의 호출 모양도 고정 원문과 실제 관용구 경계로 재현한다.

이번 변경은 표현 오류 한 종류를 제거한다. 실제 총토큰·완료시간의 개선량은
새 사용자 작업의 전후 측정 없이는 주장하지 않는다.

## 구현과 확인 결과

- `ibl_v2_compile.py`: 값 구성에서 호출·조합을 허용하는 검사와 순수 자리 검사를 분리했다.
  인자 안의 호출을 포함하도록 선언된 병렬 쓰기 자원 수집을 보강했다.
- `ibl_v2_runtime.py`: 기존 순차 평가 경로를 유지하고 실행 계약을 주석에 명시했다.
  새 실행기·임시 변수 변환·권한 우회·자동 재시도는 추가하지 않았다.
- 새 회귀 `test_ibl_container_calls.py` 33개 통과. 실제 기존 관용구를 사용하는
  에피소드 4071 재현은 인라인·임시 변수 방식의 결과 행이 같고 각각 원천 2회만 호출했다.
- 코어·조합·교재·영수증 마이그레이션 관련 167개 통과.
- 전체 backend 실행은 6,577개 통과·1개 건너뜀·2개 실패(572초)였다. 실패는 새 모의 크롤
  응답의 필수 필드 누락과 새 테스트 파일의 직접 실행 진입점 누락이었다. 두 준비 문제를
  보완한 뒤 새 파일을 직접 실행해 32개, 러너 가드 4개를 재검증해 모두 통과했다.
  실행 코드의 수정은 없었으며 전체 6,579개 대상에서 남은 실패는 없다. 전체를 다시 돌린 수치는 아니다.
- 마지막 검토에서 지역 함수가 가린 어댑터의 쓰기 자원을 중복 집계할 수 있는 경로를 보완했다.
  실제 선택된 정의의 본문과 인자만 조사한다. 이 경계 사례 1개를 추가한 뒤
  새 회귀·코어·조합·교재·영수증·러너 가드를 함께 다시 실행해 최종 204개가 통과했다.
- 현재 앱 `/ibl/validate`와 `/ibl/execute`에서 중첩 함수 인자·객체·목록·파이프 실행,
  같은 실행의 resume, 순수 람다의 호출 거절을 확인했다. 값은 `{a:3,b:[4],rows:[{n:2}]}`다.
  실행 코드에는 외부 도구·모델 호출이 없었다. 관리 워커가 변경을 반영한 상태여서 수동 재기동은 하지 않았다.
- 어휘·파생 문서, 몸 번들, 백엔드 층, 은퇴 계약 관문 통과.
