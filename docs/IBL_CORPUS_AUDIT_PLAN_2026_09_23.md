# 새 문법 기준 IBL 코퍼스 전수조사 계획

상태: **착수. 스냅샷과 핵심 모집단 전수 정적 검사 완료, 우선 함수 계약 검토 진행.**
결과·검사 한계·남은 작업은 [첫 실행 묶음 기록](IBL_CORPUS_AUDIT_PROGRESS_2026_09_23.md)을 따른다.
운영 코퍼스 수정·전 행 의미 판정·모델 재학습은 아직 완료하지 않았다.
조사 기준: 2026-09-23, 정본 main `0b6f87ec88eb0da7a0231b4efd60a1b74f06408a`.
목적: 모든 학습·회상 용례의 현재 문법 적합성과 의도 보존을 판정하고, 검증된 자료가
작성·회상·저장·호출·재학습 전 경로에서 일관되게 사용되도록 한다.
상위 기준: [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md).

## 1. 현재 확인한 규모와 범위

아래는 SQLite 읽기 전용 연결과 JSON 파일 열람으로 얻은 계획용 집계다.
실행 시작 시 일관된 스냅샷을 만들고 다시 확정한다. 과거 감사의 행 수를 재사용하지 않는다.

| 대상 | 현재 규모 | 이번 조사에서의 역할 |
| --- | ---: | --- |
| `data/ibl_usage.db`의 `ibl_examples` | 3,677행, 서로 다른 코드 2,239종 | 운영 회상·함수 원장 전수 판정 |
| `data/training/_proposed_verify_intents_20260525.json` | 40행 | 재학습 입력 전수 판정 |
| `data/training/ibl_distilled.json` | 735행 | 재학습 입력 전수 판정 |
| `data/training/ibl_training_balanced_20260516.json` | 1,873행 | 재학습 입력 전수 판정 |
| 위 학습·회상 자료 합계 | **6,325행** | 물리적 행 수. 파일·DB 사이 중복 포함 |
| `data/world_pulse.db`의 `ibl_code_corpus` | 9,382건 | 과거 실행 원문·판본·실적을 보존하면서 전수 분류 |

운영 용례 중 alias 보유 행은 50개, 현재 헤더로 시작하는 행은 8개다. alias 행 수는
고유 함수 이름 수와 다르며, 헤더 수는 문법·의미 검증 통과 수가 아니다.
실행 원문 원장의 edition은 1이 9,368건, 2가 14건이다. 헤더만으로 판본을 추정하면 안 된다.

연결 자산도 목록화한다: `data/idioms/`의 정의·선정집·seed, `data/workflows/`,
해마의 가지 문서, 프롬프트·가이드·사전 예제, 스크립트 등록 예제,
스케줄·트리거·앱에 저장된 IBL과 학습용 export/배포 묶음.
원장·로더에서 실제 경로와 소비자를 찾아 범위를 확정한다. Python 스크립트 본문 전체를
IBL로 바꾸는 작업은 아니며, 그 안의 IBL 문자열과 호출 계약은 조사 대상이다.

과거 로그·감사 산출물·백업·호환 테스트는 원문 보존 대상으로 분류한다.
현재 회상·시딩·학습에 다시 들어오는 경로가 있으면 그 유입 경로를 고친다.

## 2. 판정 기준과 기존 도구의 한계

기준은 [현재 명세](../data/system_docs/ibl.md), [주 교재](../data/guides/ibl_composition.md),
실제 edition 2 컴파일러와 활성 사전의 계약이다. 문서와 구현이 충돌하면 충돌 자체를 결함으로 기록한다.

9월 9일 감사는 [기록](corpus_review_2026_09_09/README.md)과
`scripts/review_corpus_2026_09_09.py`에 행별 판정·해시·백업·재적용 틀이 있다.
이 틀은 활용하되 `ibl_parser`·`typecheck_code` 중심의 구형 검사를 새 문법 합격 근거로 쓰지 않는다.
주간 `backend/cognition/corpus_vocab_audit.py`도 현재 구형 파서를 직접 사용한다.
재학습기는 DB 전체와 `data/training/*.json`을 읽으므로, 보고서에만 “격리”라고 적어도
실제 로더에서 제외하지 않으면 다시 학습된다.

각 행에는 두 종류의 결과를 따로 남긴다.

- **조치:** 현재형 유지 / 현재형으로 전환 / 호환 실행 보존 / 격리 / 판단 보류.
- **검증:** 정적 검사 결과(valid·invalid·incomplete·failed), 의도 검토,
  고정 입력 실행 결과, 외부 환경 확인 여부. 미실행은 미실행으로 남긴다.

`incomplete`를 합격으로 합치거나 `failed`를 용례 오류로 단정하지 않는다.
호환 보존은 옛 본문을 새 작성 예제로 계속 노출한다는 뜻이 아니다.
필요하면 현재 문법의 명시 호출 예제와 반환 계약을 제공하고 옛 본문은 실행용으로 보존한다.

## 3. 단계별 실행

### 0단계 — 모집단과 기준선 고정

1. SQLite 온라인 backup으로 `data/_backups/YYYY-MM-DD_ibl_corpus_audit/`에 원장을 보존한다.
   JSON·정의·사전·모델/색인 식별자와 git HEAD도 기록한다. 살아 있는 DB 파일을 단순 복사하지 않는다.
2. 파일 목록·DB 키·행 수·내용 해시·수집 시각을 manifest로 고정한다.
   각 저장소의 스냅샷 시각 차이와 이후 추가·변경·삭제분은 별도 증분 원장으로 추적한다.
3. 현재 회상 질의와 기대 함수/액션, 기존 저장 함수의 입출력 계약을 기준선으로 보존한다.
4. 전수조사 대상과 보존 대상, 추출 실패를 구분해 목록에 남긴다. 읽지 못한 파일을 조용히 건너뛰지 않는다.

완료 조건: 모든 원본에 식별자·행 수·해시가 있고 모집단 합계를 재현할 수 있다.

### 1단계 — 전수 추출과 판본·의존성 분류

1. 저장 판본·헤더·호출 문맥을 공통 `ibl_edition` 규칙으로 해소한다.
   충돌·불명은 별도 판정하며, 구문 오류를 이유로 다른 판본으로 자동 재시도하지 않는다.
2. 독립 프로그램, 함수 정의/몸, 명시 입력이 필요한 예제, 예약된 내부 코드,
   설명 속 코드 조각을 구분한다. 입력 없는 함수 몸을 독립 프로그램으로 검사하는 오탐을 막는다.
3. 함수 호출 → 정의 → 하위 함수·스크립트·액션의 전이적 의존성을 수집한다.
   동적 이름·없는 정의·비활성/미보유 사전·마스킹된 원문은 별도 상태로 남긴다.
4. 판본·입력/함수 문맥을 포함한 코드 그룹을 만들어 중복 검토를 줄인다.
   물리적 행과 의도는 합치거나 삭제하지 않는다. 그룹 판정은 각 행의 의도 확인 후 적용한다.
5. 실행 원문 9,382건도 빠짐없이 판본·구문·의존성·재사용 연결을 분류한다.
   과거 실패 사례는 그대로 보존하며, 현재 학습 후보로 승격할 때만 별도 현재형 후보를 만든다.

완료 조건: 모든 행에 분류 결과 또는 추출/판정 보류 사유가 있다.

### 2단계 — 새 문법의 정적 검사와 의미 위험 탐지

검사기는 효과 없는 공통 컴파일 경로를 사용한다. 읽기 전용 스냅샷의 정의·사전을 주입하여
검사 중 운영 원장을 초기화하거나 외부 도구를 실행하지 않는다. 새 검사기의 정상·오류·미확정·기반 실패
분류를 작은 고정 표본으로 먼저 확인한 후 전수 실행한다.

| 변화 | 반드시 확인할 의미 |
| --- | --- |
| 명시 값과 입력 | 암묵 `$prev`·이전 턴 변수·자동 items 추출, 자유 변수, 필요한 inputs/함수 인자 |
| 함수·파이프 | 명시 서명, 첫 인자의 파이프 자리, 중복 전달, 반환형, 같은 이름의 판본별 해소 |
| 문자열·식 | 일반 문자열과 f 문자열, 한 번 보간, 문자열 숫자·null·결측·Unit의 구별 |
| `&` | 가지 순서 목록과 중첩 보존, 옛 자동 병합/펼침 의존, 쓰기 충돌 |
| `??`·실패 | 빈 결과의 정상 반환, 실패만 폴백, 부분 결과·원천 누락·취소/권한 증거 보존 |
| `each` | map/flat_map/effect, 명시 return, collect의 Result 처리, 순서·전건 처리·구형 limit |
| 표 변환 | filter/compute/select 콜백, 실제 생산자 필드, 각 도구의 Record/List 계약 |
| 제어·반환 | return 범위, repeat의 Unit, 실패 즉시 중단, try/catch/finally 경계 |
| 중첩 코드 | workflow·예약·스크립트 인자 속 코드의 독립 판본·입력·실행 문맥 |

완료 조건: 100% 정적 판정과 위험 태그 부여. 문법을 통과한 행도 다음 의미 검토를 생략하지 않는다.

### 3단계 — 전 행 의도 검토와 전환안 작성

우선순위는 상시 노출 함수·반사/직접 실행 후보 → 최근 호출·다수 의존 함수 → 일반 회상 용례
→ 학습 전용 용례다. 우선순위는 순서이며, 저빈도 자료도 전수 판정한다.

- 한 묶음은 고유 코드 약 100개를 초기 작업 단위로 삼고, 긴 함수·의존성은 더 작게 나눈다.
  매 묶음마다 원본 행 목록, 자연어 의도, 문제, 제안 코드, 보존할 반환/실패/효과 계약을 기록한다.
- 구형 AST와 실제 계약에 근거해 변환한다. 헤더 추가나 문자열 일괄 치환을 전환으로 간주하지 않는다.
- 의도와 기존 실행이 이미 어긋난 경우, “동등한 이관”과 “기존 결함 수리”를 구분하고
  기대 결과를 명시한다. 비교 기준은 옛 동작만이 아니라 원래 사용자 의도다.
- 의도 불명·누락 입력·접근 불가 의존성은 추측으로 채우지 않고 보류/격리한다.
- 함수 정의는 하위 의존성부터 검증한다. 같은 이름의 현재형 정의를 등록하면 기존의 현재 판본
  호출도 새 정의로 해소될 수 있으므로, 이름을 유지했더라도 호출자를 전수 대조한다.
- 원본 ID·의도·출처·관측 실적은 보존한다. 변경 후 코드를 과거 성공 횟수만으로 검증됐다고
  표시하거나 즉시 반사 후보로 승격하지 않는다. 코드 버전별 실적 연결/자격 정책을 먼저 확정한다.

완료 조건: 6,325행 각각에 근거 있는 조치 판정. 모든 전환안에 원본 연결과 변경 이유가 있다.

### 4단계 — 의미 검증과 회상 검증

1. 전환한 고유 프로그램/함수마다 대표 입력과 의도별 기대 출력을 검증한다.
   위험 태그에 따라 0/1/N건, 빈 결과, null/결측, 부분 실패, 중첩 목록, 잘못된 타입,
   문자열 식별자, 중간 중단·부작용 순서의 경계 사례를 추가한다.
2. 외부 도구·발송·삭제·유료 생성은 고정 응답과 효과 기록기로 대체한다.
   실제 새 엔진에서 값·타입·순서·호출 인자·실패 증거를 확인한다.
   고정 응답 검증과 실제 외부 서비스 확인을 보고서에서 구분한다.
3. 기존 함수와 호출자의 반환 계약을 함께 검사한다. Record에서 List로 바꾼 경우처럼
   공개 계약 변경이 필요하면 호출자 전환과 한 묶음으로 다룬다.
4. DB·JSON·함수 정의·가지 문서·검색 결과에서 같은 버전이 연결되는지 확인한다.
   새 문법 질의와 경계 질의에서 옛 본문을 새 작성법으로 재노출하는지 검사한다.

완료 조건: 채택할 전환안의 의미 검증 통과. 외부 미확인·미확정 계약은 개별 항목으로 남고
사용 자격에 반영되어야 한다. 정적 통과만으로 검증을 끝내지 않는다.

### 5단계 — 소규모 적용, 전량 적용, 증분 마감

1. 읽기 전용 검증이 기본인 별도 적용기를 만든다. 원본/후보 해시 대조, 멱등성,
   변경 중단·복구를 임시 DB/파일로 검증한다. 9월 9일 적용기를 그대로 재실행하지 않는다.
2. 먼저 대표적인 작은 묶음을 적용해 회상·호출·색인을 확인하고 나머지를 순차 반영한다.
   DB와 여러 파일은 하나의 원자적 트랜잭션이 아니므로 적용 journal과 복구 절차를 둔다.
3. 적용 직전 원본을 재대조한다. 병행 증류·사용 기록을 덮어쓰지 않으며 코드/의도 충돌은
   재검토하고 새 행은 증분 감사한다. 통계만 갱신된 행은 최신 통계를 보존한다.
4. 추가 시딩은 `add_examples_batch` 단일 입구를 사용한다. 기존 행 변경은 판본을 이해하는
   경로로 코드 파생 메타데이터·FTS·벡터·함수 조회·가지 문서/캐시를 함께 갱신한다.
5. 격리/호환 보존 자료가 회상·학습·자동 실행에서 어떤 자격을 갖는지 실제 소비자에 적용한다.
   `_archive`라는 이름이나 보고서 표지만으로 제외됐다고 가정하지 않는다.
6. 현재 모델을 유지한 채 변경 코드만 재임베딩하고, 대상 키 집합과 벡터/FTS 키 집합·내용을
   대조한다. 수만 같아도 엉뚱한 행에 붙었을 수 있으므로 ID·내용 해시를 확인한다.
7. 기준 시점 이후 증분까지 마감하고 이후 신규 등록은 아래 상시 관문으로 넘긴다.

완료 조건: 재적용 pending 0, 충돌 미해결 0, 적용/제외 전수 대사 일치, 운영 회상·호출 확인.

### 6단계 — 재유입 방지와 재학습 분리

- 시딩·증류·함수 저장·import·학습 export·주간 감사를 판본을 이해하는 공통 검사로 연결한다.
  과거 호환 자산 보존과 새 작성 예제의 기준을 구분한다. 새 문법의 정상 코드가 구형 감사에서
  오탐되거나, 구형 코드가 새 교재로 다시 유입되는 것을 회귀로 막는다.
- `build_ibl_nodes.py --check`, `check_retired_contracts.py`, 용례 재검토 원장과 새 감사의
  책임을 정리한다. 파생 사전·문서 마커는 정본 소스에서 빌드한다.
- 구현 변경 시 관련 판본·함수·회상·이관 회귀와 전체 backend 회귀를 수행한다.
  backend 변경에 필요한 폰 번들 manifest도 재생성한다.
- 가중치 재학습은 코퍼스 정비가 끝난 뒤 별도 채택 단계다. 우선 현재 모델 재색인과 회상
  검증을 마친다. 재학습 시 라이브 모델과 분리된 출력·정식 백업 경로를 준비하고,
  같은 코드 계열/의도 변형이 학습·평가 양쪽에 새지 않는 분할로 직전 모델과 비교한다.
  채택 후 전체 재색인과 관리 재시작을 한다. 재학습 여부가 전수조사 완료 판정을 대신하지 않는다.

## 4. 산출물과 완료 기준

예정 산출물은 manifest, 행별 판정 JSONL, 코드 그룹별 전환안, 의미 검증 fixture/결과,
적용/복구 원장, 최종 보고서다. 원장은 행 식별자·의도/코드 해시·판본 근거·의존성·위험 태그·
조치·정적 상태·의미 검증·변경 전후 해시·증거 위치·적용 상태를 포함한다.
원문과 개인 입력은 로컬에 보존하고 커밋할 재현 자료는 민감 정보 검사를 거친다.

진척은 “처리한 코드 수”만으로 보고하지 않는다. 원본별 총행/추출/정적검사/의도검토/
의미검증/적용/격리/보류 수와 의존성 미해결 수를 매 묶음 대사한다.
같은 코드의 여러 행을 검토할 때도 행별 판정 누락을 집계한다.

완료는 다음 두 수준을 구분한다.

1. **전수조사 완료:** 스냅샷과 마감 증분의 모든 행에 판정이 있고 누락·무근거 통과가 없다.
   보류가 있으면 그 수와 이유를 공개한다.
2. **현재 코퍼스 정비 완료:** 현재 작성·회상·학습에 노출되는 대상의 확정 오류와 미해결 이관이 0,
   채택 전환안의 의미 검증 완료, 격리/호환 자산의 소비 경계 확인, 색인·원장 대사와 재유입 관문 통과.

유효한 과거 실행 원문을 새 문법으로 덮어쓰거나, 판정하기 어려운 행을 삭제해서 0을 만들지 않는다.
시간·토큰 개선은 별도 대표 과제 측정으로 확인하며 이번 조사에서 측정하지 않았다면 주장하지 않는다.

실행 순서: **스냅샷 → 전수 분류 → 정적 검사 → 전 행 의도 검토 → 의미 검증 → 적용·증분 마감 → 상시 관문**.
첫 실행 묶음의 목표는 모집단 manifest와 위험 분포표까지다. 이때 고유 코드·긴 함수·호환 경계의
실제 분포를 확인한 뒤 남은 묶음 수와 소요 시간을 산정한다.
