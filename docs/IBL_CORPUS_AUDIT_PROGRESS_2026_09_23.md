## 확인한 결과

현재 학습·회상 6,325행을 빠짐없이 추출했다. 판본·함수 문맥을 포함한 코드 그룹은 2,393개다.
각 행에 원본 위치/ID, 의도·코드 해시, 판본 근거, 현재 문법 검사 결과, 위험 태그,
정적 호출 의존성, 검토·실행·적용 상태를 남겼다. 행 키 중복과 누락을 대사했다.

| 원본 | 행 수 | valid | incomplete | invalid |
| --- | ---: | ---: | ---: | ---: |
| 운영 `ibl_examples` | 3,677 | 185 | 2,781 | 711 |
| proposed verify intents | 40 | 40 | 0 | 0 |
| distilled | 735 | 49 | 261 | 425 |

| **학습·회상 합계** | **6,325** | **364** | **4,750** | **1,211** |

이는 **원문을 현재 문법으로 해석했을 때의 정적 결과**다. 구형 함수 몸은 기존 파서가 계산한
자유 입력을 선언한 검사 전용 함수로 감쌌다. 검사기는 운영 원문을 바꾸지 않는다.
valid도 의도 보존·외부 실행 성공을 증명하지 않는다. incomplete는 호환 어댑터와 Unknown
경계가 남았다는 뜻이며 실패나 합격으로 합산하지 않는다. 검사 기반 failed는 0건이다.

학습·회상의 판본 1은 6,317행, 판본 2는 8행이다. 판본 1은 기존 파서에서 모두 파싱됐다.
현재 문법 invalid 1,211행은 현재형 전환의 검사 결과이며 구형 판본 실행 결과와 별도다.
실행 원문에는 과거 실패 사례도 포함되므로 과거 원장의 오류 수를 현재 학습 오류 수에 더하지 않는다.

학습·회상 행 중 대표 위험은 파이프 1,117행, 표 콜백 289행, 병렬 210행, each 168행,
`$return` 할당 30행, fallback 23행이다. 위험 태그는 중복 집계다.
확정 진단 중 타입 불일치는 678행, 파이프 입력 충돌은 567행, 알 수 없는 인자는 176행이다.
같은 행에 여러 진단이 붙는다.

## 상시 소개 함수 우선 검토

alias 보유 50행의 현재형 검사는 invalid 38 / incomplete 10 / valid 2였다.
상시 소개되는 구형 함수 7행과 같은 이름의 현재형 정의 2행을 먼저 읽어 계약 검토 원장에 남겼다.

| 대상 | 확인한 전환 요구 |
| --- | --- |
| 좁혀서읽기 | grep 봉투의 items 추출, each 본문·반환, 파일·줄번호와 읽기 범위 보존 |
| 주소마다읽기 | dedup 반환형, 숫자 입력, each 결과·실패·원천 출처를 함께 전환 |
| 열추려보기 | 구형 `$return`과 현재 return의 차이. 기존/현재 정의의 반환 봉투·음수 take 계약 대조 |
| 정렬해추리기 | desc→descending, 인자 순서·반환형·음수 take 계약 대조 |
| 본문에서찾기 | 구형 filter의 정규식·주변 문맥·출처·일치 계수 기능을 현재 콜백만으로 대체할 수 없음 |
| 관련자료골라읽기 | 판정 스크립트의 prepare/select/finish와 each의 값·불확실 판정·실패 계수를 함께 전환 |
| 의미로본문찾기 | 중복 파이프 입력, each 봉투 접근, 문맥·선별 결과 계약 전환 |

현재형 `열추려보기`·`정렬해추리기`의 0/1/N 입력과 문자열 ID 보존을 실제 순수 연산으로 확인했다.
음수 take 거절, 구형 `$return` 할당의 Unit 반환, 병렬 중첩 보존, 빈 목록의 fallback 비실행,
일반 문자열의 비보간까지 **11개 프로브 통과**. 외부 도구 호출은 0이다.

특히 `$return` 할당은 **현재 문법의 정적 검사를 통과해도 함수 결과를 Unit으로 만들 수 있다.**
따라서 valid/incomplete 행에 헤더만 붙여 일괄 전환할 수 없다.
구형 7행의 현재형 전환안과 의미 검증은 아직 남아 있다. 현재형 2행도 기존 호출자 전수 대조는 남는다.
나머지 6,316행의 개별 의도 검토는 미착수이며, 이 보고서는 전체 의미 검토 완료 보고가 아니다.

## 연결 자료와 증분

SQLite 3개를 온라인 backup으로 보존하고 471개 파일·모델 가중치 해시를 기록했다.
DB별 quick_check는 통과했으며 파일 수집 중 변경과 추출 오류는 없었다.
DB 사이의 시점은 동일 트랜잭션이 아니므로 각각의 수집 시각을 manifest에 남겼다.

연결 자료 386개 파일의 IBL 후보 4,612개를 추출했다:
구조화 문자열 1,143 / 문서 인라인 3,219 / 문서 코드 블록 231 / IBL 파일 1 / Python 문자열 18.
인라인 어휘·설명·동적 문자열을 실행 가능한 프로그램으로 오인하지 않도록 추출 문맥과 위치를 보존했다.
이 자료의 **후보 추출**이 끝난 것이며 전부의 문맥 판정·의미 검증이 끝난 것은 아니다.
프로젝트 외부 앱·배포 export·동적 import의 재귀 추적도 후속 범위다.

마감 대조에서 학습·회상·실행 원문 행의 추가/삭제/코드·의도 변경은 0이었다.
`calendar_events.json`, `event_triggers.json`, `guides/world_pulse.md`의 파일 바이트 변경은 기록했다.
이 세 파일에서 추출한 IBL 후보의 추가/삭제는 0이었다. 실행 문맥의 변화 여부는 후속 검토 대상이다.

## 재현 자료와 검사 범위

개인 원문·행별 의도는 Git 제외 백업 안에 보존했다:
`data/_backups/2026-09-23_210528_ibl_corpus_audit/`.

- `manifest.json`: 원본·DB·모델 지문과 수집 시각.
- `audit/rows.jsonl`, `groups.jsonl`: 15,707건 전수 원장과 11,628개 코드/판본/문맥 그룹.
- `audit/summary.json`, `contracts.json`: 집계·스냅샷 계약·검사 한계.
- `audit/surface_candidates.jsonl`, `surfaces.json`: 연결 자료 후보와 파일별 추출 결과.
- `audit/priority_review.jsonl`, `value_probes.json`: 우선 9행 계약 검토와 순수 값 검증 증거.
- `audit/drift.json`: 기준선 이후 증분.

도구는 `scripts/ibl_corpus_snapshot.py`, `audit_ibl_corpus_v2.py`, `ibl_corpus_surfaces.py`,
`probe_corpus_v2_values.py`다. 스냅샷 생성 외에는 해당 백업의 audit 디렉터리에만 결과를 쓴다.
SQLite 원본은 읽기 전용 연결이며 검사 어댑터의 도구 실행은 차단한다.
실행기의 API 사전 병합 규칙과 현재 컴파일러를 재사용한다.
전체 선언 사전으로 검사하고 활성/비활성 상태를 별도 기록한다. 실제 주체 권한·몸별 필터와
동적 script 계약 정밀화는 이 정적 판정에 포함하지 않는다. 문자열 내부 코드와 동적 의존성의
전체 해소는 후속 문맥 검토가 필요하다.

새 감사 회귀 18개와 현재 문법 코어 회귀 63개, 합계 **81개 통과**.
스냅샷 변조 거부, 읽기 전용 DB, 실행 차단, valid/invalid/incomplete/failed 구분,
함수 판본·이름 정합, API 사전 병합, 코드 조각과 프로그램 구분을 검사했다.
운영 backend 코드는 변경하지 않았고 전체 backend 회귀는 이번 묶음에서 실행하지 않았다.
