## 실제로 발견한 차이

- 서울 지역 코드 조회는 핸들러가 무시하는 `query`를 `city`로 수리했다.
- 애플 10-K 공시 조회는 무시되는 `type`을 `filing_type`으로 수리했다.
  두 수리는 실제 핸들러를 불러 외부 의존성만 대역으로 바꾼 검사로 확인했다.
- 좌표 소수 리터럴은 현재 언어에서 `Decimal`이다. 기존 JSON 어댑터의
  `plain_arguments`가 이를 거절한다. 숫자가 우연히 Python float와 같게 비교되는 경우까지
  검사하여, 해당 6행은 전환하지 않았다. 최초 적용 2행도 이 때문에 복구했다.
- 질문에 없는 지역·파일·ID·상품 세부 모델, 투룸을 빌라로 대체한 조건, 카메라 검색을 현재
  영상 관측으로 간주한 예제, 전체 목록과 제한된 페이지의 차이는 보류했다.
- 실제 사업 DB에는 예제의 `invoices` 표가 없었다. 통계표 ID 대응, 경도/위도 순서,
  회의를 임의로 60초만 녹음하는 예제, 참가 가능 여부와 대회 정렬의 차이도 보류 사유다.

보류는 격리와 다르다. 이 593행은 구형 원문으로 남아 있으며, 현재 회상·학습에서 자동
제외된다고 주장하지 않는다. 입력을 받는 함수로의 재작성 및 소비 자격 연결이 후속 작업이다.

## 검증 범위와 한계

두 묶음의 원문→후보 조합 235개에 7가지 응답을 넣어 **1,645개 fixture 검사**를 통과했다.
빈/단일/여러 결과, 문자열 ID·null·순서·중첩, 오류, 권한 거절, 불완전 응답을 확인했다.
실제 컴파일러·실행기·호환 값 관문·봉투 디코더를 사용하고 외부 도구 실행만 대역으로 막았다.
호출 횟수와 입력 인자도 대조했다. 따옴표 없는 구형 문자열은 명시 문자열로 직렬화했다.

현재 호환 계약의 Unknown 경계 때문에 정적 상태는 모두 **incomplete**다.
이를 native 계약 증명이나 외부 서비스 성공으로 합산하지 않는다. 외부 호출은 0회이며,
카메라·녹음·폰 기능도 실제 동작시키지 않았다. `error_count` 기반 partial은 거절되지만
`partial: true`만 있는 봉투는 현 디코더에서 일반 값으로 남는다. 이것도 검사·한계로 기록했다.

DB 406행의 벡터를 현재 로컬 모델로 재생성하여 행별 저장 바이트를 확인했고 FTS 무결성을
검사했다. 400행은 이전 벡터와 달랐고 6행은 같은 바이트였다. 값이 같은 것을 재색인 누락으로
세지 않았다. 모든 새 소스는 FTS에서 확인했고 대표 하이브리드 회상 8건은 해당 ID·새 코드가
상위 5개에 나타났다. 가지 문서는 엄격 갱신을 통과했다. 모델 가중치를 재학습하지 않았다.

기존 벡터에는 원본 없는 키 2와 누락된 키 4845가 있었다. 원본 행은 바꾸지 않고 백업 후
고아 벡터를 제거하고 누락 벡터를 생성했다. 현재 DB/벡터 키는 3,684개로 정확히 일치한다.
전체 회귀 뒤 고아 키 2가 다시 나타나, 관용구 트리 테스트의 DB 지정 누락도 추적했다.
트리 기본 경로만 임시 DB로 바뀌고 벡터 저장소는 운영 경로에 남아 있었다. 같은 문제의
`test_hippo_tree.py` fixture도 고쳤다. 해당 fixture들에서
벡터 DB와 색인 호출도 격리했고, 키 2를 다시 정리한 증거는
`data/_backups/2026-09-23_224411_ibl_corpus_audit/vector_test_leak/verification.json`에 있다.

적용기는 읽기 전용 검토가 기본이며 `--apply`에서만 쓴다. 원문/의도·구현 지문을 재대조하고,
DB 쓰기 잠금 안에서 최신 통계를 읽는다. JSON은 최신 파일에 검토 행만 합쳐 교체한다.
DB와 JSON 사이 중단은 journal을 남기고 같은 원장으로 이어서 적용한다. 재시도 때 이미
적용된 행의 새 실적을 초기화하지 않는 검사를 통과했다. 두 묶음 모두 재적용 pending은 0이다.

## 회귀 테스트의 코퍼스 재유입 차단

마감 증분을 추적하다가 테스트 두 파일의 저장 대역이 운영 학습 파일을 보호하지 못함을 발견했다.
대역은 `ibl_distilled.json`에 대한 `write_text`만 막았는데 실제 저장은 `.distill.tmp`를 쓴 뒤
`replace`하는 방식이었다. 수동 관용구 저장 경로도 같은 운영 파일을 쓸 수 있었다.

두 모듈의 증류·관용구 저장 루트를 임시 작업 공간으로 옮겼다. 이제 임시 파일 교체까지 실제로
실행하고 결과를 확인한다. 관련 검사 38개 통과 전후 운영 학습 파일 해시는 같았다.

해당 테스트의 의도·코드·출처·provenance가 일치하는 **44행**을 원문 그대로 별도 보관했다.
첫 조사 전부터 있던 37행과 조사 중 추가된 7행이다. 운영 예제를 일괄 중복 제거한 것은 아니다.
활성 학습 입력 `data/training/*.json` 밖의 `_archive/2026-09-23_regression_fixture_leaks.json`에
보존했고 나머지 698행은 그대로 유지했다. 앞선 문맥 없는 제안 40행 격리와 별개다.

현재 활성 학습·회상은 **6,255행**이다: DB 3,684 + balanced 1,873 + distilled 698.
판본 2는 684행(기존 15 + 이번 669), 판본 1은 5,571행이다.
