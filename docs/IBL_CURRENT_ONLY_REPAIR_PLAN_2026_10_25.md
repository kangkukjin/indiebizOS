# 현행 IBL만으로 작동하는 시스템 수리 계획

작성: 2026-10-25. 상태: **구현·저장소 전환·로컬 기동 검증 완료**.
코드 조사 기준: 정본 main `bcb5e6c3dbd0fec081fabf226fffdfba18f3fc0b`.
목적: [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)의 품질·완료 시간·전체 토큰 기준 아래,
현재 IBL과 주변 시스템이 구판을 유지하기 위해 부담하는 분기·데이터 조회·교재·배포 의존을 제거한다.

이 계획의 완료 상태는 **현행 입력 계약과 현행 자산만으로 작성·검사·실행·저장·회상·재개가 닫히는 것**이다.
판본 1 거절을 성공 기준으로 삼았던 [실행 지원 종료 설계](IBL_EDITION1_RETIREMENT_DESIGN_2026_10_25.md)의
후속 목표다. 이전 구현·검증 이력은 보존하며, 이후 구조 정리의 완료 기준은 이 문서가 소유한다.
사용자의 구현 요청에 따라 정본 main에서 아래 계획을 적용했다. 실제 결과와 검증 범위는 §7에 기록한다.

## 1 목표와 범위

현재 실행 가능한 언어는 하나다. 작성자는 현행 문법·값·함수·입출력 계약만 알면 된다.
실행기는 구판인지 판별하거나 옛 함수 이름을 수집하지 않고, 현행 컴파일 계획을 실행한다.
저장·회상·학습은 현행 자산 집합에서 시작하며 과거 원문을 매번 읽고 걸러내지 않는다.
구판 이관과 역사 해석은 현재 실행을 준비하는 과정에 들어오지 않는다.

여기서 없앨 부가 부담은 구판 때문에 추가되는 정상 경로의 작업이다. 현행 입력 검증,
권한·취소·예산, 함수 개정의 일관성, 실행 증거·재개·검수는 현행 기능의 책임이므로 유지한다.
같은 검증을 여러 내부 함수에서 다시 하는 중복은 줄이되, 서로 다른 외부 입력·권한 경계는 유지한다.

역사 원문·revision·실적·영수증은 보존한다. 보존 데이터와 실행 자산의 선택 경로를 분리하고,
역사 조회는 명시적으로 요청할 때만 읽는다. 과거 언어를 실행하거나 재분석해야 하는 일은
해당 Git revision의 격리 환경에서 수행한다. 현행 배포에 구판 파서·변환기·실행기를 포함하지 않는다.

범위는 실행기뿐 아니라 HTTP·MCP·앱·예약·트리거·위임·회원·폰, 함수 원장,
해마·학습·프롬프트·시딩·패키지 import, 검사 참조·재개·배포까지다.
새 언어 판본, 별도 통합 프레임워크, 상시 이관 서비스, 추가 AI 판정은 만들지 않는다.

## 3 현행 계약의 책임 배치

### 요청과 작성

외부 API·파일·패키지의 판본 표시는 형식 식별 정보로 유지할 수 있다. 지원하는 형식은 하나이며,
입력 경계의 현행 스키마가 유효성을 판단한다. 지원 밖 번호에는 일반 지원 형식 오류를 반환한다.
구판 종류별 검출기나 금지 목록을 추가하지 않는다. 현행 요청으로 정규화한 뒤 내부 호출에
판본 선택 인자·전용 거절·판본 ContextVar를 전달하지 않는다.

새 모델 작성은 현행 문법만 가르치고, 도구 요청 생산자가 필요한 형식 정보를 채운다.
기존 외부 API의 명시 판본 요구는 유지하여 무표기 과거 요청을 현행으로 재해석하지 않는다.
저장 원문·예약·외부 import의 형식도 보관된 메타데이터와 헤더로 확인한다.
무표기 자료를 신판으로 간주하는 일괄 기본값 변경은 하지 않는다. 이관 검증을 마친 자산만
현행 저장소에 넣으며 헤더·메타데이터 충돌과 미확인 형식은 일반 입력 오류로 닫는다.

언어 판본, 함수 revision, 저장 스키마, 값 와이어 프로토콜은 서로 다른 식별자다.
`ibl-value/1`, `ibl-resume/1`, `schema:1` 등을 판본 1과 혼동해 없애지 않는다.
현행 기능이 사용하는 프로토콜은 실제 소비자와 계약을 기준으로 유지한다.

### 함수와 저장 자산

`function_store`의 운영 카탈로그는 현행 언어의 정의와 상태만 가진다. 현행 함수의
active·hold·quarantine·retired 상태, 불변 revision, 조건부 쓰기, 고정 참조는 유지한다.
구판 항목은 역사 목차로 분리하고 정상 snapshot·이름 해소·컴파일에서 읽지 않는다.
기존 불변 원문 객체는 복사·재작성하지 않고 역사 목차가 원래 ID·revision으로 가리킬 수 있다.
역사 목차는 기존 저장소의 보존 자료이며 새로운 상시 서비스나 두 번째 쓰기 정본이 아니다.

신판 우선 선택과 판본별 동명 함수 해소를 제거한다. 필요한 이름 별칭은 실제 현행 호출자가
쓰는 계약인지 확인하며, 구판으로 연결하는 별칭은 운영 집합에 남기지 않는다.
과거 참조를 현재 함수로 자동 리디렉션하거나 옛 성공 횟수를 새 함수에 합산하지 않는다.
역사 화면의 재사용은 검토·컴파일을 거친 새 현행 정의 등록으로 처리한다.

### 기억과 교재

해마 원문과 과거 실행 이력은 그대로 보존한다. 현재 회상·학습·내보내기는 기존 후보 색인이나
저장소 조회 경계에서 현행 집합을 선택한다. 구판 원문 전체를 로딩한 뒤 항목별 판본 검사로
제외하는 흐름을 없앤다. 기존 색인을 재구축할 수 있도록 출처와 자격을 저장하며 새 분류 서비스를 만들지 않는다.
의미 있는 과거 경험의 자연어 회상은 유지하되, 역사 코드가 실행 교재 목록에 섞이지 않게 한다.

서명·반환형·함수 정의·의존성은 현행 컴파일러가 소유한다. 회상 카드·감독·증류·정적 감사가
구판 파서로 따로 해석하지 않는다. 프롬프트·가이드·도움말은 현행 사용법만 설명하며
판본 선택이나 구판 거절 안내를 상시 교재로 싣지 않는다. 이관 설명은 이행 문서에만 둔다.

### 결과와 도구

`text_result`의 판본 의존 반환은 모든 소비자를 조사한 뒤 도구의 현재 반환 계약으로 통일한다.
직접 Python 호출·JSON 핸들러·IBL 어댑터가 요구하는 반환형을 확인하며, 문자열을 일괄 봉투로
바꾸는 식으로 공통 기능을 깨뜨리지 않는다. 현행 값과 JSON 도구 사이의 변환·정밀도 검사,
정상 빈 값·실패·부분 결과·원천 완전성은 유지한다.
`ibl_engine`의 권한·라우팅·후처리처럼 현행 도구가 쓰는 부분은 구판 프로그램 처리와 분리한다.

### 역사와 이관

역사 열람은 저장한 원문·판본·hash·참조를 표시하며 구판 코드를 파싱하거나 실행하지 않는다.
과거 hash로 이어지는 실적·증거 연결은 그대로 둔다. 필요한 과거 hash 계산은 역사 조회 경계에서만
사용하며 새로운 프로그램의 hash 계산과 분리한다. 기존 현행 실행 지문도 이유 없이 바꾸지 않는다.

구판을 분석하는 일회성 도구는 운영 import·시작 경로·배포 번들에서 제거한다.
이관 코드 자체는 Git 이력에서 복원할 수 있게 하고, 실행에 필요한 구판 파서를 현행 backend에
남겨두지 않는다. 오래된 설치본의 업그레이드는 지정된 이행 버전을 거친 다음 현행 배포로 들어온다.
현행 서버가 부팅하면서 과거 설치본을 자동 이관하거나 구판 지원을 되살리지 않는다.

| 4 실행과 부팅 정리 | 판본 문맥·구판 거절 심벌·retired_names·판본별 선택 제거. 구판 파서·전용 모듈 삭제. 완료된 이관 부팅 검사 제거 | 정상 부팅·검사·실행·회상이 구판 코드나 이관 자료를 import/조회하지 않음. 설치 전제 미충족은 실행 시작 전에 판정 |

| 6 최종 인수 | 전체 회귀, 관련 기기·입구 점검, 정상 경로의 import/파일 읽기·추가 작업 대조, 미적용 기기 보고 | 아래 완료 기준 충족. 기능·구조 완료와 측정한 비용 결과를 구분해 기록 |

각 단계는 기능·호출자·테스트·교재 변경을 함께 묶는다. 현행 능력의 공백을 발견하면 필요한
공통 능력을 먼저 수리한다. 거절 함수를 늘리거나 필수 작업을 삭제해 단계 완료를 맞추지 않는다.
단계별 커밋은 검증 가능한 상태로 만들고, 부분 이행 상태를 정상 운영 배포로 활성화하지 않는다.
수리 구현이 시작되면 이 문서에 실제 완료 범위와 잔여 항목을 갱신한다.

## 5 적용과 복구

일회성 데이터 변경은 기존 원장의 저장 API·잠금·generation/revision 비교를 사용한다.
대상 목록과 기대 버전·백업·적용 순서를 먼저 확정한다. 백업은
`data/_backups/YYYY-MM-DD_ibl_current_only/`에 두고 SQLite는 `.backup` 또는 `VACUUM INTO`로 확보한다.
카탈로그·색인 변경 사이에 중단돼도 원문과 기존 운영 집합을 복구할 수 있어야 한다.

자동 실행 접수를 멈추고 관련 진행 작업을 완료시키거나 상태·후속 처리를 보존한 뒤 전환한다.
재개를 기다리는 현행 실행은 함수 참조·입력·컴파일 지문·영수증 호환성을 확인한다.
새 코드에서 재개할 수 없는 실행은 명시 보류하고, 이미 수행한 외부 효과를 처음부터 반복하지 않는다.
과거 실행 기록은 새 resume/reuse 입력으로 자동 승격하지 않는다.

`edition1_retirement` 부팅 검사는 기존 배치의 완료와 현재 집합의 정합을 확인한 뒤 제거한다.
미완료 이관 저장소는 새 배포를 활성화하기 전에 기존 이행 도구로 복구한다. 설치·갱신 경계의
저장 형식 검사로 이 전제를 보장하고, 정상 부팅에 구판 배치 탐색을 남기지 않는다.
새 설치는 이행 도구 없이 바로 현행 저장 형식으로 시작한다.

장애 복구는 영향받은 코드·목차·소비자의 해당 변경만 되돌린다. 이후 사용자 데이터와 실행
증거를 백업 전체 복원으로 덮지 않는다. 구판 런타임을 현행 코드의 스위치로 재활성화하지 않는다.
외부 폰·회원 PC는 설치/지원 상태를 별도로 기록하고, 업데이트하지 않은 기기의 정상 동작을
중앙 검증 결과로 대신하지 않는다.

## 6 검증과 완료 기준

### 기능 보존

현행 지역·저장 함수, 중첩 조합, 파이프·병렬·반복·조건·실패 처리, 명시 입력·반환,
JSON 도구·스크립트 호출, 검사 참조 실행, 부분 결과·재개·재사용을 확인한다.
HTTP·MCP·앱·예약·트리거·위임·회원 경로는 같은 현행 프로그램의 의미와 실행 신원을 보존해야 한다.
외부 효과는 격리 대역으로 대상·내용·횟수·순서를 대조한다.

기존 구판 거절 시험은 현행 요청 스키마·없는 함수·잘못된 참조·지원 밖 형식의 경계 시험으로
정리한다. 구판 거절 전용 심벌을 시험 때문에 유지하지 않는다. 효과 발생 전 실패 보장은
현재 계약의 부정 사례로 유지하고, 폐지된 계약과 보존할 회귀 의미를 구분해 삭제 근거를 남긴다.
공통 보장을 검사하던 시험을 일괄 삭제하거나 skip하여 통과시키지 않는다.

### 구조와 정상 경로의 부담

기존 층·은퇴 계약·배포 검사와 모듈별 시험을 사용한다. 새 상시 감사 서비스나 실행마다
구판을 찾는 검사를 만들지 않는다. 정적 import/호출 분석과 대표 동적 경로의 모듈·파일 접근을
함께 확인하고, 문자열 개수 감소만으로 제거를 판정하지 않는다.

최종 완료에는 다음 조건이 모두 필요하다.

1. 운영 배포에 구판 파서·실행기·호환 변환기·구판 거절 전용 심벌이 없다.
2. 현행 컴파일·함수 해소에 구판 이름 집합과 판본별 선택이 없다.
3. 정상 실행·저장·회상·학습이 구판 원문이나 역사 목차를 읽고 제외하는 과정을 거치지 않는다.
4. 부팅과 정상 작업에 구판 이관 배치 확인·자동 번역·별도 모델 호출이 없다.
5. 과거 자료 접근은 명시 역사 조회에 한정되고, 과거 ID·revision·hash·실적·원문이 보존된다.
6. 새 작성과 운영 교재는 현행 문법만 사용한다. 필요한 외부 형식 표시는 경계에 한정된다.
7. 필요한 기능과 권한·격리·취소·예산·결과·재개 보장이 현행 계약으로 검증된다.
8. 새 설치·기존 설치 전환·갱신된 배포 번들의 검증과 미적용 기기 보고가 끝난다.

동일한 현행 작업으로 변경 전후의 부팅·컴파일/실행 시간, 역사 파일 읽기, 로드 모듈,
함수 목록 작성·회상 후보 처리, 프롬프트 분량과 실제 모델 호출·토큰을 가능한 범위에서 대조한다.
구판을 처리하는 정상 경로의 추가 작업이 사라졌다는 구조 근거를 우선 확인한다.
성능 측정을 정리 착수의 선행 조건으로 삼지 않으며, 미측정 속도·토큰 개선을 주장하지 않는다.

### 검사 절차

[회귀 검사 규약](REGRESSION_TESTING.md)에 따라 개발 중에는 변경의 전이 소비자 검사를 실행한다.
이번 전체 수리는 언어·부트스트랩·저장·회상·배포에 걸치므로 최종에는
`.venv/bin/python3 -m pytest backend/ -n auto --dist loadfile`로 system 포함 전체 회귀를 실행한다.
frontend 변경 시 `npx tsc -p tsconfig.app.json`, backend 변경 시 Android 몸 번들 재생성,
어휘·설명 변경 시 소스 YAML 빌드와 `build_ibl_nodes.py --check`, 층·은퇴 계약·배포 관련 관문을 수행한다.
파생 파일과 문서 마커는 직접 편집하지 않는다.

최종 보고에는 제거한 의존, 보존한 기능·역사, 적용한 데이터와 기기, 실행한 검사와 미검증,
실제 측정 결과를 적는다. 계획·커밋·구판 거절 성공만으로 구조 수리 완료를 선언하지 않는다.


## 7 실제 구현과 인수 기록

- 요청·재개·저장은 현행 스키마 한 벌을 검증한다. 무표기 기본값 1, 구판 전용 거절 함수,
  판본 ContextVar, 구판 함수 이름 집합과 신판 우선 선택을 제거했다. 정상 함수 해소는 운영 카탈로그만 읽는다.
- 함수 카탈로그 schema 2와 명시 역사 목차를 분리했다. 현행 함수 60개 중 active 59개는
  보유 어휘 계약으로 컴파일했으며 오류가 없었다. hold 1개는 그대로 유지했다.
- 원문 용례 3,899건의 기존 열을 바꾸지 않고 실행 자격 색인·현재 view·FTS·벡터 후보를
  분리했다. 현재 후보 1,503건, 역사 원문 2,396건이다. 일반 회상·학습·감사는 현재 view에서 시작한다.
  역사 함수 24개와 원문 용례는 명시 조회로 열 수 있다. 역사 원문은 현재 파서로 재해석하지 않는다.
- 파서·슬롯 바인딩·턴 변수 주입·구판 정적 격자·자동 작명·부팅 이관 모듈을 제거했다.
  감독·계측·통계·용례 검사는 현행 AST를 읽는다. 현재 검사 참조의 원문 복원 기능은
  `checked_program_sources`로 보존했다. 도구 값/JSON 봉투, 권한·예산·취소·검사 참조·재개는 유지했다.
- 새 설치/업데이트는 현행 배포 함수 설치기를 사용한다. 개인이 고친 정의와 hold 상태를
  덮지 않는다. 외부 모델 압축파일에서는 모델 파일만 설치하며 실행 DB·훈련 파일을 덮어쓰지 않는다.
- 원문을 한 줄 문서로 표시할 때 JSON으로 인코딩해 줄바꿈·주석·따옴표를 보존한다.
  현재 가지 문서 81개를 이 형식으로 재생성했다. 이전 문서는 백업에 보관했다.
- 일회성 전환은 `scripts/install_current_ibl_storage.py`로 수행했다. 이 스크립트는 서버에서
  import하지 않는다. 백업은 `data/_backups/2026-10-25_ibl_current_only/`에 있다.
  카탈로그를 마지막에 게시하고, 원문 열 hash 일치와 중단 후 재실행을 시험했다.

제거된 구현·시험의 출처는 `docs/experiments/ibl_current_only_2026_10_25/removed.json`과
`retired_tests.json`에 기록했다. 구판 문법·암묵 변수·구판 실험 하네스의 계약을 시험하던 항목은
구현과 함께 은퇴시키고, 현재 기능 검사는 현행 원문과 명시 실행 영수증으로 갱신했다.
현행 함수 입력 추출의 개인정보 관문은 유지했다. 구판 증류에만 있던 1,000자 상한을
현행 전체 원문 선택 경로에 새 제약으로 옮기지 않았다.

검증·운영 인수의 최종 수치는 같은 디렉터리의 `acceptance.json`에 기록한다.
폰 엔진 번들은 재생성한다. 실제 Android/Windows 기기에 설치해 실행한 것으로 보고하지 않는다.
정상 경로의 역사 자료 읽기 제거는 저장소/컴파일/역사 조회 격리 시험으로 확인하며,
전체 응답 시간이나 토큰 절감률을 측정했다고 주장하지 않는다.
