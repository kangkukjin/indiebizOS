# IBL 판본 1 실행 지원 종료 설계

작성: 2026-10-25. 상태: **정본 구현·로컬 이관·전체 회귀 완료**.
위 완료는 구판 실행 지원 종료 범위다. 구판 판별·거절·역사 조회 의존까지 정상 경로에서
제거하는 후속 목표와 인수 기준은 [현행 IBL만으로 작동하는 시스템 수리 계획](IBL_CURRENT_ONLY_REPAIR_PLAN_2026_10_25.md)을 따른다.
후속 수리는 계획 수립 상태이며, 아래 구현 이력을 전체 구조 정리 완료로 해석하지 않는다.
목적 정본: [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md).
상위 구조: [구조 수렴 설계](IBL_SYSTEM_CONSOLIDATION_DESIGN.md).
저장 계약: [함수 원장 통합](IBL_FUNCTION_MEMORY_UNIFICATION_DESIGN_2026_10_24.md).

## 1 결정과 완료 범위

운영 IBL은 판본 2의 값·함수·조합 의미로 통일한다. 판본 1은 자산 이관 기간에만 실행하며,
이관을 마친 배포에서 구판 프로그램 실행기와 판본 간 함수 호출을 제거한다.
과거 원문·판본·실적·실행 증거는 열람 가능하게 보존한다. 기록의 보존이 실행 지원을 요구하지는 않는다.

완료는 판본 2가 기본값인 상태가 아니다. 모든 운영 입구가 판본 1을 효과 발생 전에 거절하고,
활성 프로그램과 그 전이 의존성이 판본 2이며, 구판 실행 분기가 배포 코드에서 제거된 상태다.
업데이트하지 않은 외부 기기는 호환 불가로 명시하며 중앙 서버가 구판 실행을 대신하지 않는다.
그 기기까지 업데이트됐다는 뜻으로 중앙 퇴출 완료를 보고하지 않는다.

영구적인 dual-mode, 요청별 구판 허용 스위치, 실패 시 구판 재시도, 런타임 자동 번역은 두지 않는다.
판본 번호는 역사 자료의 해석과 지원 범위 협상에 남는다. `ibl_v2_*` 파일 이름을 바꾸는 작업은
퇴출의 선행 조건이 아니며, 이름보다 실제 실행 의존성을 제거한다.

이 문서는 2026-09-23의 [호환 도입 설계](IBL_V2_ASSET_INTEGRATION_2026_09_23.md)를
운영 종료 목표로 확장한다. 기존 무표기 자산의 뜻을 보존한다는 원칙은 이관 검증에 유지하고,
그 원칙을 근거로 운영 실행 지원을 무기한 유지하지 않는다. 이하 §2의 수치는 설계 당시 관측이며, 구현 결과는 §12에 기록한다.

## 2 확인된 현재 상태

조사 기준은 정본 main `6b204f0c`와 2026-10-25 로컬 함수 카탈로그 generation 3이다.
카탈로그·운영 데이터는 Git와 별도로 변하므로 구현 시작과 배치 적용 직전에 다시 조사한다.

| 확인 사항 | 근거 | 퇴출 영향 |
| --- | --- | --- |
| 무표기 원문은 1, 새 모델 작성 요청은 2 | `backend/base/ibl_edition.py`의 `source_edition`, `authoring_request` | 보관 원문 판별과 새 요청의 실행 판별을 구분해야 한다. |
| 판본 2 진입점은 구판이면 None 반환 | `ibl_v2_entry._handle_request`, `system_tools_ibl._execute_ibl_unified_impl` | 반환 후 구판 파싱·실행으로 내려가는 경로를 제거해야 한다. |
| HTTP 검수와 스케줄에도 구판 분기 존재 | `api_ibl.validate_request_code`, `ibl_scheduled.execute_scheduled` | 모델 도구만 고쳐서는 퇴출되지 않는다. |
| 판본 2가 판본 1 함수를 호출할 수 있음 | `ibl_v2_compile`의 fn 해소, `ibl_v2_compat.function_adapters` | 루트 판본뿐 아니라 전이 함수 의존성까지 검사한다. |

트리거의 실제 저장 위치는 `trigger_engine.TRIGGERS_PATH`가 정하는
`data/event_triggers.json`이다. 앞선 구조분석 보고서의 `triggers.db` 표기를 이관 입력으로 사용하지 않는다.
전체 운영 원문·대기 실행·외부 기기 수는 아직 집계하지 않았으며 아래 0단계의 산출물이다.

판본 선택·구판 함수 실행·동명 함수 해소·구판에서 신판 함수 호출 거절 관련 기존 회귀 11건이
2026-10-25 조사에서 통과했다. 이것은 현 호환 동작의 확인이며 퇴출 구현 검증은 아니다.

## 3 제거할 것과 유지할 것

| 구분 | 처리 |
| --- | --- |
| 판본 1 프로그램 파싱·암묵 변수 주입·조합 실행·구판 함수 호출 | 운영 의존성을 옮긴 뒤 제거 |
| 판본 2에서 판본 1 함수로 넘어가는 호환 어댑터 | 제거. 판본 2 함수의 내부에 구판 실행을 숨기지 않음 |
| 구판 이름·workflow ID의 자동 실행 우회 | 제거. 이관 관계는 진단·역사 조회용이며 실행 시 자동 리디렉션하지 않음 |
| 과거 원문·판본·함수 revision·실적·실행 결과 | 불변 역사로 보존. 운영 후보와 분리 |
| JSON 도구 봉투, `legacy-envelope`, `registered-json/1` 등 | 판본 2가 쓰는 도구 연결 계약은 유지. 언어 판본과 프로토콜 번호를 혼동하지 않음 |
| `plain_arguments`, 공통 값 비교·식 평가·잎 도구 라우팅 | 판본 2 소비자를 보존. 구판 전용 분기만 제거 |
| `.iblpack`·옛 설치 입력의 데이터 읽기 | 판본 1을 자동 활성화하지 않음. 역사 가져오기 또는 이관 필요 진단으로 제한 |

`ibl_v2_compat.py`는 파일 전체 삭제 대상으로 지정하지 않는다. `plain_arguments` 등 살아 있는
공통 책임은 기존 도구 경계 모듈로 옮기고 구판 함수 실행 책임만 없앤다. `workflow_engine.py`,
`ibl_engine.py`도 CRUD·현행 라우팅과 구판 조합 실행이 섞여 있어 호출 관계별로 분리한다.
공통 식 트리와 평가기는 이미 공유되므로 새 실행기나 제3의 중간 언어를 만들지 않는다.
IBL 밖에서 핸들러를 직접 쓰는 HTTP·앱 소비자의 반환 계약도 조사한다. 구판 언어를 지우면서
`text_result` 같은 공통 생산자의 반환 모양을 전역 변경해 별개 API를 깨뜨리지 않는다.

## 4 최종 실행 계약

역사 판별은 계속 원문을 원래 판본으로 읽는다. `source_edition()`의 기본값을 무조건 2로
뒤집어 옛 기록의 해시·조회·실적 의미를 바꾸지 않는다. 실행 자격 판단은 기존 `ibl_edition`
소유자에서 따로 제공하고 모든 실행·검수·등록 입구가 같은 판단을 사용한다.

| 입력 | 최종 동작 |
| --- | --- |
| 명시 edition 2 또는 `#!ibl edition=2` | 현재 컴파일·실행 경로 |
| 명시 edition 1 또는 구판 저장 참조 | `EDITION_RETIRED`, executed=false, 도구 호출 0회 |
| 판본이 없는 외부 HTTP·원격 원문 | `EDITION_REQUIRED`, executed=false. 구판일 수 있는 요청을 신판으로 재해석하지 않음 |
| 새 AI·MCP 작성 및 현행 UI 생성 | 해당 생산자가 현재 판본을 붙여 위와 같은 실행 입구 사용. 명시 구판은 덮어쓰지 않고 거절 |
| 판본 필드와 헤더가 충돌 | 기존 `EDITION_CONFLICT`, executed=false |
| 구판 steps 배열 | 구판 프로그램 입력으로 거절. 내부의 단일 도구 호출 자료구조까지 금지하지 않음 |
| v2 루트의 pinned 의존성에 구판 함수 존재 | 컴파일 전 또는 의존 해소 중 `EDITION_RETIRED`; 한 잎도 실행하지 않음 |
| 구판 실행의 resume·reuse·검사 참조·자동 후속 | 실행 자격 거절. 기존 결과는 읽을 수 있으나 새 프로그램으로 자동 재실행하지 않음 |

위 오류 이름 중 새 이름은 구현할 계약이다. 표준 응답·MCP 실패 전달·UI 표시를 기존 오류
체계에 연결하고, 사용자에게 거절 원문 또는 참조와 이관 필요 이유를 표시한다.
구판 요청의 `check`도 실행 가능으로 통과시키지 않는다. 역사 구문 분석은 운영 검수와 분리한다.
기능 협상은 실행 지원 `[2]`, 새 작성 기본값 2, 외부 원문의 판본 명시 필요를 표현한다.

함수 목록과 `describe`는 역사 자료의 존재와 현재 실행 가능성을 구별한다. 은퇴 함수 이름을
모르는 함수로 숨기지 않으며, 존재하는 판본 2 대체 정의를 안내할 수 있지만 자동으로 호출하지 않는다.
권한·주체·허용 노드·파일 범위·쓰기 승인·취소·예산은 기존 계약을 그대로 유지한다.

## 5 이관 조사와 소유자

조사는 실행하지 않고 각 원장의 읽기 경로에서 원문·참조·상태·버전을 수집한다.
새 상시 DB나 관리 서비스를 만들지 않는다. 기존 `scripts/ibl_v2_assets.py`의 조사 기능과
`function_consumers`를 확장하고, 결과는 구현 작업의 실험 디렉터리에 고정한다.
현재 inventory의 해마 alias 목록은 함수 정본이 아니므로 함수 원장 기준으로 고친다.
조사 중 lazy migration·색인 갱신·설치가 일어나는 읽기 API는 그대로 호출하지 않는다.
읽기 전용 연결 또는 일관된 백업에서 조사하고, 마지막 변경 시점과 자료 지문을 기록한다.

| 표면 | 조사 대상과 연결할 기존 소유자 |
| --- | --- |
| 함수·배포 | `function_store`, `function_library`, `function_migration`, `data/idioms` 배포 입력·설치기 |
| 앱·계기 | `data/instruments`, 어휘 소스의 app 블록, 프론트 실행 요청·HTML 표면·저장된 앱 자료 |
| 자동 실행 | calendar_events, event_triggers, 프로젝트 schedules, switch·채널 응답·위임의 저장 프로그램과 steps 배열 |
| 인지·기억 | `corpus_policy`, `ibl_usage_rag`, `hippo_tree`, `ibl_name_search`, `reusable_catalog`, 증류·시딩·학습 내보내기 |
| 대기·재개 | 구판 pipeline 상태·턴 변수 참조, `ibl_run_journal`·continuation·검사 참조·저장 위임. v2 실행도 구판 의존 여부 확인 |
| 회원·원격 | `member_runner`, `ibl_member_library`, 원격 API·MCP, 기기 지원 협상·폰/회원 배포 번들·오프라인 설치 입력 |
| 내부 직접 호출 | `ibl_parser`, `execute_pipeline`, 구판 fn 실행기 등을 import하거나 동적 호출하는 운영 모듈·패키지·스크립트 |
| 역사 | 완료 실행·은퇴/보류/격리 함수·옛 코퍼스·백업. 운영 이관과 분리하되 재활성화 경로 조사 |

각 조사 항목에는 `owner + location/record_id + source_hash/revision + edition + state +
dependencies + callers + disposition + evidence`를 기록한다. 이는 일회성 이관 결과의 형식이며
새 실행 자산 원장이 아니다. 처리는 이관, 이미 현행, 역사 보존, 명시 중지, 미해소로 나눈다.
동적 함수명·생성 원문·외부 코드의 누락은 정상 0건으로 세지 않는다.

조사기는 상위 요청의 edition과 원문 헤더를 함께 읽고 충돌도 기록한다. 문자열에 `[fn:`가
있다는 정규식만으로 판본·의존성을 확정하지 않는다. 함수는 컴파일러/기존 구판 파서,
저장 소비자는 소유자의 구조를 사용한다. 알려지지 않은 입력 형식은 미해소로 남긴다.

단순히 최근 호출이 없다는 이유로 활성 작업을 폐기하지 않는다. 모든 활성 항목은 현행 이관
또는 이유 있는 중지로 처리하며, 필요한 기능을 버려 완료 수치를 맞추지 않는다.
도달할 수 없는 외부 클라이언트는 업그레이드 필요 상태로 남기고 중앙 실행 차단으로 경계를 닫는다.

## 6 함수와 프로그램의 의미 이관

### 함수 정체성과 동명 정의

기존 등록 계약은 같은 function_id의 언어 판본 변경을 거절한다. 이 계약을 유지한다.
구판 원문·revision을 수정하지 않고 새 판본 2 함수 ID를 등록하거나 검증된 기존 판본 2 ID를 선택한다.
구판 ID/revision → 신판 ID/revision·검증 근거의 관계는 새 정의의 provenance와 이관 결과에 남긴다.
실행 시 이 관계를 따라가지 않으며 과거 성공 횟수를 새 함수 실적으로 복사하지 않는다.

활성 동명 9쌍은 인자·기본값·파이프 자리·결과·효과를 대조한다. 현재 판본 2 함수의 의미를
구판에 맞춰 몰래 바꾸지 않는다. 필요한 차이는 호출자에서 명시하거나, 별개 기능이면 별개 이름을 쓴다.
활성 동명이 없는 14개는 기능을 유지하는 신판 정의를 만든다. 보류 2개는 자동 활성화하지 않는다.
기존 current 참조는 검증된 새 참조로 명시 갱신하고, pinned 참조는 승인된 이관 묶음에서만 교체한다.

### 자동화 가능한 변환과 판단이 필요한 변환

| 차이 | 이관 계약과 검증 |
| --- | --- |
| `$return =`와 `return` | 구판의 뒤따르는 효과가 필요한지 확인. 중간 값 변수에 저장하고 필요한 효과 뒤 반환하는 구조로 바꿈 |
| 암묵 입력·자유 변수·턴 변수 | 명시 인자/inputs와 기본값으로 옮김. 첫 인자의 파이프 자리와 null·빈값·중복 인자 검사 |
| 봉투 추출·items 가상 접근 | 실제 생산자 계약을 확인해 값 또는 명시 필드 접근으로 연결. 빈값·메타정보 추가에도 같은 결과 모양 유지 |
| 문자열 치환·문자열 식·동적 코드 | 리터럴과 보간·식·명시 함수 호출을 구분. 데이터의 `$`, JSON 모양 문자열, 따옴표를 코드로 실행하지 않음 |
| each의 자동 펼침·원 행 통과 | map/flat_map/effect와 결과 수집을 명시. 0/1/N행·중첩 목록·부분 실패에서 결과 확인 |
| 빈 결과 fallback과 실패 fallback | `??`는 현행 실패 의미 유지. 빈 목록 대체가 업무 요구면 별도 조건 분기로 표현 |
| 구판 재귀·goal·criteria·특수 제어 | 현행 대응 능력과 종료·완료 조건을 개별 확인. 재귀는 가능한 명시 반복으로 바꾸며 한도·효과를 보존 |
| 구판 steps·files·resume | 원문과 inputs, 현행 결과 참조로 새 실행 작성. 기존 실행 진행 위치를 신판 run_id로 위조하지 않음 |

원문 AST를 읽어 후보를 만들 수 있지만 범용 자동 변환의 성공을 약속하지 않는다. 해소하지 못한
동적 코드나 현행 능력의 공백은 공개된 잔여 항목이다. 판본 1 해석기를 script 안에 숨기는 방식은
이관으로 세지 않는다. 현행 언어가 표현하지 못하는 필수 기능은 공통 능력 수리 또는 기존 도구
구현으로 해결하고 계약·관측을 유지한다. 단순 퇴출을 위해 업무 전체를 불투명한 Python으로 옮기지 않는다.

비교 기준은 반환값·타입, 성공/실패, 원천 완전성, 외부 효과의 대상·내용·횟수·필수 순서,
권한·취소·예산·재개 의미다. 의도된 오류 수리는 종전 결함을 복제하지 않고 기대 의미와 차이를 적는다.
로그 ID·시각 등 비결정 값은 비교에서 분리한다. 외부 효과는 임시 파일/격리 DB/기록·재생 어댑터로
대조하며, 송신·결제·장치 제어를 신구 양쪽에서 실제로 두 번 수행하지 않는다.

## 7 적용과 장애 복구

여러 원장이 하나의 트랜잭션이라고 가정하지 않는다. 먼저 신판 함수를 비활성 후보로 준비하고,
소비자 변경안과 함께 투영한 원장으로 검사한다. 필요한 배치 검사·공개는 `function_library`와
`function_store.publish`에 연결한다. 별도 쓰기 우회로로 카탈로그·DB를 직접 편집하지 않는다.

적용 배치는 함수 원장 generation, 개별 revision, 소비자 파일/DB 행의 기대 버전을 고정한다.
관련 자동 실행과 신규 호출의 유입을 멈추고 진행 중 실행을 처리한 다음, 잠금과 조건부 쓰기로
소비자를 갱신하고 신판 정의를 공개한다. 구판 은퇴 검사는 갱신된 모든 소비자를 확인한 뒤 한다.
다른 세션이 바꾼 항목이 있으면 재조사하며 해당 변경을 덮어쓰지 않는다.

소유자가 다른 적용 사이에 중단되면 영향받은 작업은 계속 정지 상태로 둔다. 적용 원장에는
배치 ID·기대/적용 버전·완료 단계·이전 값의 백업 위치를 남기고, 같은 배치 재시도는 이미 적용한
단계를 중복 실행하지 않는다. 전역 서비스나 범용 이행 프레임워크는 만들지 않고 이관 CLI의
재개 가능한 기록으로 관리한다. 복구 완료 전 스케줄러가 부분 이관 상태를 실행하지 못하게 한다.

백업은 `data/_backups/YYYY-MM-DD_ibl_edition1_retirement/`에 두고 라이브 SQLite는
`.backup`/`VACUUM INTO`로 확보한다. 코드·함수·소비자 변경의 복구는 해당 배치의 변경만 되돌린다.
백업 전체 복원으로 이후 사용자 데이터와 실행 기록을 덮지 않는다. 외부 효과는 파일 복원으로
취소되지 않으므로 별도 증거로 보존하고 재실행 여부를 판정한다.

진행 중인 구판 실행과 구판 의존 v2 실행은 종전 배포에서 완료시키거나 명시 중단·후속 처리한다.
장기 대기 작업을 무한히 기다리는 정책은 두지 않는다. 각 작업의 완료/중단/수동 후속 결정을 남긴다.
신판 배포가 구판 영수증을 새 작업의 완료 증거로 자동 승격하거나 이미 완료한 쓰기를 반복하지 않는다.
기존 v2 계획도 구현 지문 변경으로 재개가 막힐 수 있으므로 전환 대상 대기 실행에 포함한다.

최종 전환 뒤 구판 지원이 필요해지는 장애는 기능 스위치로 우회하지 않는다. 원인과 영향을 확인하고
필요하면 관련 실행을 멈춘 뒤 이전 검증 배포와 일치하는 데이터 배치로 복구한다. 이 경우 퇴출은
미완료로 되돌리고 재개 조건을 기록한다. 역사 재현은 보관한 Git revision의 격리 환경에서 수행하며
구판 평가기를 현행 배포의 숨은 실행 기능으로 포함하지 않는다.

## 10 검증과 최종 인수

기존 시험의 구판 실행 기대는 새 거절 계약과 이관된 동등 기능 시험으로 바꾼다. 실패를 줄이려고
시험을 통째 삭제하거나 skip하지 않는다. 과거 버그 재현의 의미는 현행 계약 회귀 또는 이관 증거에 보존한다.

| 검증군 | 필수 확인 |
| --- | --- |
| 실행 경계 | 모델·MCP·HTTP 실행/검수·직접 함수·스케줄·트리거·위임·회원·재개에서 구판 거절과 도구 호출 0회 |
| 이관 의미 | 반환 뒤 효과, 빈값/메타정보, 문자열 보간, each/실패/fallback, 파이프 인자, 동명 함수·전이 호출 |
| 원장·기억 | 과거 hash/revision·실적 불변, 새 ID 귀속, 구판 후보 제외, hold/quarantine 불변, 옛 설치 입력의 재유입 차단 |
| 적용 장애 | 기대 버전 충돌, 파일/DB 부분 적용, 재시도, 중단 후 재개, 자동 실행 정지, 변경 한정 복구 |
| 기기·격리 | 구판 클라이언트 거절·지원 협상, 회원/주인 분리, 업데이트된 몸 번들, 미접속 기기의 명시 상태 |
| 공통 도구 | `legacy-envelope`·등록 JSON 스크립트·현행 잎 호출이 구판 함수 실행 없이 동작 |

구판 호출을 금지하는 검사는 제거할 운영 심벌과 import 경계를 대상으로 한다. 역사 문서의
`edition=1` 문자열까지 금지하지 않는다. 직접 Python 호출도 거절 또는 제거됐는지 확인하고,
동적 import·패키지 디스패치의 알려진 경로는 실행 시험으로 보완한다. 외부 실행은 격리 대역을 쓴다.

검사 절차는 [REGRESSION_TESTING.md](REGRESSION_TESTING.md)를 따른다. 개발 중은 관련 선택 검사,
최종 언어 전환은 전체 backend 검사와 해당 문서의 언어·값/스크립트·원장·배포 system 묶음을 실행한다.
프론트 변경은 `npx tsc -p tsconfig.app.json`, backend 변경은 Android 몸 번들 재생성과 관련 기기 검사를 포함한다.
어휘 설명·스키마가 바뀌면 소스 YAML에서 빌드하고 `build_ibl_nodes.py --check`를 실행한다.
은퇴 계약은 `data/retired_contracts.yaml`과 기존 검사기에 등록하며 문서·오류·도움말까지 갱신한다.

최종 인수는 다음 조건을 모두 충족해야 한다.

1. 활성 구판 함수·운영 프로그램·구판 전이 의존·미해소 내부 실행 경로가 0이다.
2. 필요한 업무는 현행으로 이관됐거나 이유를 가진 명시 중지 상태이며, 조용히 누락된 업무가 없다.
3. 구판 구문 실행기·조합 실행 분기·회원/주인 함수 호환 호출이 운영 배포에 없다.
4. 과거 원문·증거는 읽을 수 있고 재활성화·import·재개로 구판 실행을 되살릴 수 없다.
5. 판본 2가 쓰는 도구·스크립트 계약, 권한·취소·부분 실패·재개 보장이 유지된다.
6. 적용 장애와 배치 복구, 전체 회귀 및 관련 배포 검증이 끝났고 기기별 미적용 상태가 보고돼 있다.

품질·시간·전체 토큰의 변화는 별도 관측한다. 구판 제거와 검사 통과만으로 성능 향상을 주장하지 않는다.
이 설계의 직접 성과는 같은 업무에 두 언어 의미와 그 사이의 실행 변환을 유지할 필요가 없어지는 것이다.


## 12 구현과 로컬 이관 결과

2026-10-25 정본에서 구현했다. 외부 요청은 명시 판본 2만 검사·실행하고, 무표기는
`EDITION_REQUIRED`, 명시 판본 1은 `EDITION_RETIRED`로 효과 발생 전에 거절한다.
새 모델 작성과 앱 표면은 판본 2를 명시한다. 역사 판별 기본값은 1로 유지한다.

- 구판 파이프라인·each·제어 블록·암묵 파일 치환 실행기와 판본 간 함수 어댑터를 제거했다.
  `workflow_engine.execute_pipeline`은 실행하지 않는 거절 표면만 남았다.
  JSON 도구 경계와 역사 자료 파서·정적 감사는 남는다. `api_pipeline`은 별개의 HTTP 도구 파이프라인이다.
- 활성 구판 함수 23개를 종료했다. 9개는 기존 판본 2 정의로, 14개는 검토한 새 정의로 이관했다.
  활성 판본 2는 59개다. 판본별 보류 1개씩은 그대로 두었다. 구판 ID·revision은 새 정의로 리디렉션하지 않는다.
- 활성 캘린더 3건과 트리거 2건을 소유자 저장 함수와 CAS로 이관했다. 회원 앱 6개와 15개 실행 템플릿을 갱신했다.
  새 정의는 별도 ID를 가지며 옛 실행 실적을 승계하지 않는다.
- 배치는 정상 정지 상태에서만 적용한다. 원장에 미완료 표식을 남기고 단계별로 재개하며,
  미완료 배치가 있는 서버는 부팅을 거절한다. 장애 후 재개·CAS 충돌·구판 고정 참조 거절을 검사했다.
- 해마의 역사 원문은 보존한다. 현재 검색은 판본 2 함수 원장도 후보로 삼으며,
  대응 해마 행이 없다는 이유로 새 함수가 사라지지 않는다. 구판 호출문 자동 번역은 제거했다.

증거는 `docs/experiments/ibl_edition1_retirement_2026_10_25/`의 `before.json`, `after.json`,
`migration_result.json`, `retired_tests.json`이다. 백업은
`data/_backups/2026-10-25_ibl_edition1_retirement/`에 있다.
구판 함수 23개의 원문·revision 보존과 해마 3,899행의 백업 대비 동일성을 확인했다.

`retired_tests.json`에는 종료한 구판 전용 테스트·보조 함수 265개의 원 커밋·원문 해시와
현재 계약을 검사하는 파일을 기록했다. 이것은 옛 테스트 전체가 판본 2에서 동등하게
통과했다는 뜻이 아니다. 암묵 변수·구판 봉투·파일 번호 치환처럼 폐지한 계약은 거절 검증으로,
값·순서·실패·부분 결과·권한·재개·문서 보존 계약은 판본 2 실행 검증으로 옮겼다.
새 skip/xfail은 추가하지 않았다. 구판 전용 테스트 258개와 보조 함수 7개가 위 목록에 해당한다.

최종 검증(`verification.json`):

- backend 전체(`system` 포함): **11510 통과, 18 기존 skip**, 843.23초. 판본 경계·저장/검색·회원·예약·패키지 배포·긴문장·프로세스 복구 검사를 포함한다.
- TypeScript, 어휘 빌드 `--check`, Android 몸 번들, 층 구조·은퇴 계약·정직성 전파·검사/실행 정합 검사를 통과했다.

  잠든 보유 어휘의 예문은 정적으로 검사하지만 검사용 계약으로 실행할 수는 없다.

외부 폰·원격 PC의 설치본은 이 작업에서 업데이트하거나 인증하지 않았다. 배포 번들은
갱신하지만 중앙 서버의 구판 지원을 되살리는 호환 경로는 제공하지 않는다.

로컬 백엔드를 정상 재기동한 뒤 `ACTIVE`와 `/ping` 성공을 확인했다. 실제 HTTP API에서
