# 함수 첫 입력 슬롯의 파이프 연결 — 2026-09-13

에피소드 3656에서 모델은 검색 결과를 필터한 뒤 `[fn:주소마다읽기]{개수:3}`에
파이프로 연결했다. 관용구는 `$목록 >> …`로 시작하지만 함수 호출기는 `목록`
명시 인자만 인정해 실행을 거절했다. 3696의 `목록:` 명시 호출은 정상 동작했다.

## 판정

단순 안내 강화와 입력 연결의 의미 개정을 비교했다. 자족형 호출의 노출 효과를
확인한 09-09 결정을 유지하면서 파이프 조합도 허용한다. 관용구 이름이나
`목록`이라는 이름을 엔진에 특례로 넣거나, 여러 누락 인자 중 하나를 추측하지 않는다.

프로그램 `[def:]`와 이름 붙은 관용구에서 **본문 첫 파이프가 맨몸 자유 변수
방출로 시작하는 경우** 그 변수가 입력 슬롯이다. 예: `$자료 >> [table:take]{n:$수}`.
앞 통화가 있으면 그 한 인자를 채우며, 명시 인자가 있으면 명시값을 우선한다.
빈 목록도 명시값이다. 경로 참조·병렬·조건·후속 문장에는 이 규칙을 적용하지 않는다.
앞 통화가 없거나 나머지 필수 인자가 없으면 기존과 같이 실패한다.
독립 문장 사이의 통화 초기화도 유지한다. 저장 워크플로의 별도 호출·기본값 규약은
변경하지 않는다.

```ibl
$주소 >> [table:filter]{where:{field:"approved",op:"eq",value:true}}
```

위 결과를 이어 받는 호출은 다음처럼 같은 문장 안에 쓴다.

```ibl
$주소 >> [table:filter]{where:{field:"approved",op:"eq",value:true}} >> [fn:주소마다읽기]{개수:3}
```

기존 `[fn:주소마다읽기]{목록:$주소,개수:3}`도 그대로 동작한다.
두 경로 모두 URL 중복 제거, 개수 제한, 원문·출처·실패 행 보존이라는 기존 본문을 사용한다.

## 구현과 정본

- `workflow_contract.pipe_input_param`: 파싱된 함수 몸의 구조 판정 한 벌.
- `ibl_control_blocks._execute_fn`: 명시 인자에 없는 첫 입력 슬롯만 앞 통화로 채운다.
- `ibl_access`: 모델 지도·잎 액션 병기에 같은 판정으로 연결 가능 인자를 표시한다.
- `curate_idioms`: 실제 파이프가 있는 호출 예제에만 첫 입력 인자 생략을 허용한다.
- `data/idioms/curated.json`: 입력 계약과 검색·필터 뒤 파이프 예제. 기존 명시 호출 예제 유지.

관용구 본문과 필수 서명 자체는 바꾸지 않는다. 따라서 이전 실행 실적을 재설정하지 않는다.
신규 용례는 선정집 등록기의 `add_examples_batch` 경로로 해당 관용구만 반영하며,
실행 DB를 먼저 SQLite backup API로 백업한다. 사용자 원문·과거 실패 기록은 고치지 않는다.

이 변경은 함수 호출의 실행 의미에 대한 언어 개정이다. 파서 표기·desugar 타깃·
always_on·STANDARD_CORE_NODES 집합은 그대로이며, 새 어휘는 없다.

크롤러만 고정 응답으로 붙여 다음을 검증한다.

- 빈 입력, 명시 빈 목록의 우선권, 개수 0에서 외부 크롤 0회.
- 앞 통화보다 명시 목록 우선, 다른 필수 인자 누락 거절, 독립 문장 경계 유지.
- 임의 이름의 로컬 함수에도 같은 규칙, 병렬·경로·후속 변수의 추측 금지.

LSE 사이트의 접근 차단을 이번 수리로 해결했다고 주장하지 않는다.
