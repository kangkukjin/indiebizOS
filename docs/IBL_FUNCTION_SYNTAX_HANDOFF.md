## 1. 있던 것과 없던 것
- 있던 것: 워크플로 = 이름 붙은 함수(다섯 부품: 이름·인자=미할당 `$이름`·기본값·`$return`·닫힌 스코프, 2026-08-22). 스크립트 =
  파이썬 함수. `[table:each]{do}` = 익명 함수.
- 없던 것(실측 9,117 실행 중 workflow 22, 전부 프로브): ①정의가 프로그램 밖(원장)에 살아 `save`→`run` 왕복, 몸통이 따옴표 문자열로
  실려 이스케이프·치환 사고(changelog 13건 중 여럿) ②앞으로 부르기 불가(주 프로그램 먼저 쓰고 나중에 채우는 하향식) ③보이지 않음.

## 2. 문법
| 모양 | 뜻 |
|---|---|
| `[def: 이름]{ …IBL 줄들… }` | 같은 프로그램 안의 정의. 몸은 줄(문자열 아님). 파서가 프로그램 앞으로 올린다(선언은 실행 순서에 없음). |
| `[def: 이름]{todo}` | 이름만 걸어 둔 빈 함수 — 불리면 정직 실패. 하향식 작성의 자리표. |
| `[fn:이름]{인자}` | 호출. `[node:action]` 모양이라 파서·교재·회상이 새 노드 하나를 배우는 셈. 정의가 없으면 저장 워크플로의 같은 이름. |
| 시그니처 | 몸의 미할당 `$이름`(워크플로와 같은 계산 `_free_vars`). 누락은 시그니처를 보여 주며 거절. |
| 스코프 | 닫힘 — 바깥 변수 불가시, 몸의 할당은 밖으로 안 나감(블록 `[if:]`·`[try]` 와 다름 — 그것들은 스코프를 안 만든다). |
| 반환 | `$return = …` 이 있으면 그 **값**(식 할당 봉투가 아니라 value; 리스트면 items 로 승격), 없으면 마지막 문장의 통화. |
| 앞 통화 | `[A] >> [fn:x]{}` — 몸의 첫 문장이 받는다(변환자면 자연스럽게 이어짐). |
| 재귀 | 모양으로는 가능(정의 표 참조), 실행 깊이 5에서 정직 거절 — 반복은 `[repeat:]`/`[table:each]`. |

## 3. 구현
- 파서 `ibl_parser_blocks._parse_def_block` · `ibl_parser._bind_fn_defs`(정의 표 `_FN_TABLES[tid]` + 호출 step 에 `_fn_ref{table,name,params,todo}`,
  정의 문장 앞당김 후 문장 경계 재표기). ★몸통을 호출 step 에 박지 않는다 — 재귀 정의가 자기 자신을 품는 순환 구조가 되어
  실행기의 치환 걷기가 무한 재귀했다(첫 판 실측). step 은 비순환·JSON-안전.
- 실행기 `ibl_engine.execute_ibl`: `_def` 는 정의 신고(무동작), `_node=="fn"` 은 `ibl_control_blocks._execute_fn` — 인자 주입은 워크플로와
  같은 `_apply_caller_params`(배관 키 `_raw`·`_prev_result` 는 인자에서 뺀다), 몸은 `execute_pipeline`(닫힌 step_results), 반환은
  `_promote_final_currency`(`$return` 봉투→값 개정 포함, 워크플로 run 과 같은 함수). `_nest` 가 `_fn_depth` 를 잇는다.
- 검증기 면제: `ibl_registry.foreign_actions`·`ibl_usage_rag._validate_ibl_actions`·`ibl_param_vocab.check_code_params`·
  `workflow_engine` runnable — `fn` 은 어휘가 아니라 호출.

## 4. 사다리에서의 자리
관용구(고쳐 쓰는 골격) → **`[def:]`(한 프로그램 안에서 이름 붙여 굳힌 것)** → 워크플로 원장(여러 프로그램에서 되풀이될 때 저장,
`[fn:이름]` 으로 같은 모양 호출). §7(워크플로=관용구의 얼린 칸) 제안은 이 개정이 흡수한다.

## 5. ⏳ 관찰
- 실사용 프로그램(정기 보고서·개발 주행)에서 `[def:]` 가 쓰이는가 — 궤적의 `fn` 머리 수. 교재 예제가 회상·관용구로도 보이는가(리허설 저장 #).
- 저장 워크플로 폴백이 실제로 불리는가(실측 0 이던 자리).

## 6. 관용구 = 이름 붙은 함수 (2026-09-05, 사용자 판정 "그 세 가지도 진행")

> 사용자: "이 함수 기능은 우리가 가진 관용구의 모양을 바꾸지 않을까? 관용구를 쓰기 더 쉬워질 것 같다. 그런 모양의 관용구를 가르쳐야
> 함수도 배우고 관용구도 잘 쓰겠지."

1. **이름**: 관용구 행에 `alias` 열. 증류의 두 번째 답에 `phrase_name`(짧은 한국어 동사형 명사, 붙여 씀) — `sanitize_fn_name`·`unique_fn_name`
   (같은 골격이면 같은 이름, 다른 골격이 이름을 차지하면 숫자 접미). 기존 18건은 `scripts/replay_idioms.py --name-idioms --apply` 로 반성기가 작명.
   가지 문서 머리 `### 이름 — 의도 · …` + `호출:` 줄, 이름을 고치면 색인이 따라온다. 색인 텍스트 = 이름 + 의도 + 머리 열.
2. **해소**: `[fn:이름]` 은 프로그램의 `[def:]` → 저장 워크플로 → **이름 붙은 관용구**(해마 `find_phrase_by_alias`, 골격 파싱·`${슬롯}`=시그니처·
   같은 인자 주입) 순. 이름으로 부른 관용구는 쓰인 것으로 귀속(`update_success_by_code`) — 상시 블록 순위·재학습 회상 귀속이 움직인다.
   없으면 관용구 이름 목록을 실어 정직 거절.
3. **가르치는 모양**: `<ibl_idioms>` 와 회상 `kind="phrase"` 참조가 "호출 한 줄 `[fn:이름]{슬롯: "…"}` + 정의 블록 `[def: 이름]{…}`" 로.
   그대로 쓸 때는 이름만, 고칠 때는 정의를 붙여 넣는다 — 함수를 배우는 것과 관용구를 배우는 것이 같은 학습이 된다.
   워크플로 원장은 사실상 관용구 원장에 흡수된다(은퇴는 별도 판정).
