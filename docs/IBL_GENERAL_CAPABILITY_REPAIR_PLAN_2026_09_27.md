# IBL 일반 능력의 현황 재평가와 다음 수리 계획

상태: **R1 및 R2의 F2·F4는 계약 구현. R2의 F3와 R3~R6은 미구현.**
기준: 정본 `main`의 `a5678e5d57d8f8ec047670d5ab4c0a5339ff6b56` 이후 문서 작업.
작성: 2026-09-27. 운영 관측은 완료된 에피소드 4106~4117까지.
후속 갱신: Fable 검토에 따라 확인된 작은 결함을 수리하고, 첫 작업 단위·시험·비용 우선순위를 구체화했다.
목적 정본: [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md), [vision.md](../data/system_docs/vision.md).
이전 설계·구현 이력: [구조 수렴 설계](IBL_SYSTEM_CONSOLIDATION_DESIGN.md).

## 1. 목적은 유지하고, 남은 일을 다시 정한다

**도구를 어휘로 포함하는 IBL과 주변 시스템을 진화시켜, AI가 실행 의도를 쉽고 정확하게 표현하고
다양한 작업에서 결과 품질을 유지·향상하면서 실제 완료 시간과 전체 토큰 소비를 줄인다.**

도달하려는 능력도 유지한다. 처음 보는 요구를 분해하고, 작은 능력을 긴 프로그램으로 조합하며,
결과를 보고 필요한 부분만 수정하고, 얻은 능력을 다시 더 큰 조합의 부품으로 쓰는 것이다.
기존 단계의 구현 완료나 테스트 통과를 이 목표의 달성으로 바꾸지 않는다.

현 시점의 판단은 다음과 같다. **표현·실행 기반은 상당 부분 갖췄지만, 그 기반을 작업의
진행·완료·축적에 연결하는 계약이 부분적이다.** 기능이 있는 것, 모델이 활용하는 것,
새로운 작업에서도 품질과 비용이 좋아지는 것은 서로 다른 상태다.

따라서 다음 개발은 결함 목록을 늘리는 데서 멈추지 않는다. 먼저 판정·참조·복구의 뜻을 맞추고,
그 위에서 작성·맥락·기억이 다음 실행을 쉽게 만드는 방향으로 연결한다. 운영 실패나 비교 실험을
기다려야 착수하는 계획이 아니다. 구조상의 공백으로 개발을 정하고, 관측으로 효과를 설명한다.

이 문서가 이후 개발 우선순위와 현재 잔여를 소유한다. 이전 문서는 설계 이유와 구현 이력을
보존한다. 목적·언어 명세·코드 계약을 이 문서에 복제해 새 정본으로 만들지는 않는다.

## 2. 조사 범위와 근거의 강도

- **코드 확인:** 컴파일·실행·참조 표시, 실행 추적, 품질 판정·최종평가, 프롬프트 조립,
  실행기억·세계 지도·증류, Script 연결의 현행 경계를 읽었다. 저장소 전체를 전수 감사한 것은 아니다.
- **운영 관측:** `data/world_pulse.db`를 읽기 전용으로 조회해 4106~4117의 시간·사용량·호출·
  참조 사건·기억 제시/사용 사건을 대조했다. 4111~4112의 상세 분석과 수리 이력도 함께 사용했다.
- **격리 탐침:** 모델·외부 도구 호출 없이 네 경계를 재현했다(§4). 임시 저장소와 판정 대역만
  사용했다. 최초 조사에서는 운영 코드를 변경하지 않았고, 후속 수리 범위는 §4·§6에 구별한다.
- **한계:** 후속 수리 전 에피소드도 포함된다. 이 표본으로 수리 후 실패율이나 보편적 절감률을
  계산하지 않는다. 산출물 전체의 의미 품질을 새로 재심사하지도 않았다.

프로그램 실행 수와 다르며 조회·설명 등도 포함한다. 참조 사건 수도 재사용 효용의 점수가 아니다.

확인한 변화와 남은 질문:

1. 이전 §6.2의 4096~4101과 달리 **참조 입력의 성공 사용이 실제로 관측된다.** 따라서
   “참조 기능이 없다/전혀 쓰이지 않는다”를 현재 진단으로 유지하면 틀린다.
2. 4112는 수정·빌드·배포·화면 동작 검사를 수행했다. 30 실행 라운드와 큰 누적 입력은
   비용 신호지만 그 모두가 낭비라는 뜻은 아니다. 같은 산출물 기준으로 줄일 왕복을 찾아야 한다.
3. 실행 모델의 system 입력은 이 표본에서 51,967~59,832자였다. 도구 없는 대화인 4114~4116도
   52,037자였다. 이는 고정 맥락의 검토 근거이며, 이 문자 전체를 제거할 수 있다는 증거는 아니다.
4. 4112의 글자 기반 method_map은 no_match였지만 별도 의미 회상 world_memory는 세 후보를
   제공했다. **의미 검색이 없다는 진단은 틀리다.** 후보 제시가 더 적합한 방법 선택으로 연결되는지는 별도다.
5. 4112의 해마 후보 사용 사건은 0/7이지만 저장 함수 호출 자체는 두 곳 있었다. 제시 후보 미사용을
   모든 기억의 무용함으로 해석하지 않는다. 세계 지도의 `mentioned`도 방법의 효과를 증명하지 않는다.

**우선순위 판단:** 일곱 사례에서 캐시 읽기는 전체 토큰의 약 77~95%다. 청구액이나 지연의 같은
비율이라는 뜻은 아니지만, 여러 라운드에서 커지는 문맥을 되읽는 비용은 공통 수리 대상이다.
4112를 기준 사례로 **R4의 첫 작업을 R3보다 먼저** 둔다. 브라우저 참조 오류 수리는 이미 끝났으므로
그 실패를 다시 고치는 것이 아니라, 확보한 본문을 전달·재독하는 분량과 왕복을 줄인다.
R3의 의미 연결을 모두 완성해야 비용 수리에 들어갈 수 있다는 의존성은 없다.

## 4. 기준 코드에서 재현한 결함과 수리 상태

### F1. 재판정 불능을 성공으로 표시하는 모순

기준 코드의 `ibl_quality.apply_criteria`에 첫 판정 fail, 재시도 뒤 unjudgeable을 주면 다음이 반환됐다.

```json
{"success": true, "criteria_verdict": "pass_after_retry",
 "criteria_note": "재판정 불능 — 통과 처리: 판정자 응답 없음"}
```

처음부터 판정 불능인 경우의 `unjudged`와도 다르다. 실행을 계속하도록 한 기존 정책과
품질을 확인했다는 판정은 분리해야 한다. 실행 계속 정책을 일괄 실패로 바꾸자는 뜻은 아니다.
기존 criteria 시험은 첫 판정 불능과 재시도 성공은 다루지만 이 조합의 의미를 보호하지 않는다.
**수리: R1 계약 구현.** 재판정 불능은 `unjudged`로 반환하고 최초 미달 사유와 재시도 표지를 보존한다.
`agent_pipeline`도 출처 표지만으로 통과를 추정하지 않으며 혼합 파이프에 미판정이 있으면 이를 우선한다.
증류의 결과 증거에 quality/quality_feedback을 본문 발췌와 별도로 전달하고, workflow 안내도 같은 뜻으로 고쳤다.

### F2. 실행 기록의 의도한 표본이 원천 누락으로 변함

[body_ops.op_trajectory](../data/packages/installed/tools/system_essentials/body_ops.py)는
요청 limit을 넘으면 앞뒤 사건을 골라 `truncated:true`를 반환한다. 생략 범위를 설명하지만
`truncations.scope=selection`은 없다. 그 반환 모양을 현재 `decode_envelope`에 전달하면
`PARTIAL_SOURCE`가 발생했다. 실제 4111에도 이 경계에서 복구가 필요했던 기록이 있다.

원천이 고장난 경우와 사용자가 선택한 요약 조회는 다르다. 어댑터의 원천 누락 검사를
느슨하게 하지 말고 생산자가 선택 범위를 선언해야 한다. 중간 사건을 모두 읽었다는 보장은
추가되지 않는다. **수리: R2 중 F2 계약 구현.** 같은 limit 선택이 있는 changes/log/writes/trajectory/
file/diff 여섯 경로에 `selection`을 선언했다. 표본 수·전체 수·기존 생략 설명은 유지한다.
이 표지는 행 선택만 설명한다. diff 본문의 `lines` 제한 등 별도 필드의 뜻을 전수 검증했다는 주장은 아니다.

### F3. 결과 ID의 소유 범위가 읽기 안내에서 드러나지 않음

`model_result_view.evidence_store`는 현재 감독 턴 또는 actor/task별 저장소를 고른다.
`_read_reference`는 ID·경로·페이지·입력 인자를 제공하지만 그 ID가 속한 저장소 범위와
수명을 명시하지 않는다. 임시 저장소 A에서 만든 ID를 B의 `read_result`로 읽으면
`FileNotFoundError`다. 이 격리 자체는 옳다. 4111의 과거 실행 ID 재사용 실패와 같은 구조다.

반면 [ExecutionTraceService.document](../backend/services/execution_trace.py)는 이미
권한·소유 범위가 결합된 `source_ref`로 과거 증거를 읽는다. 필요한 것은 전역 파일 검색이나
공용 캐시가 아니라 **참조가 자신에게 맞는 기존 읽기 경로를 안내하는 계약**이다.
**판정: 격리는 정상, 참조 전달·오용 진단은 공백. R2에서 연결한다.**

### F4. 핸들러의 복구 구조가 공통 오류 경계에서 사라짐

브라우저 핸들러의 실패 모양인 `success:false, error_code:REF_NOT_RESOLVED,
recovery:{op:snapshot,...}`를 [decode_envelope](../backend/ibl/ibl_v2_adapters.py)에 전달하면
`Fault(code=TOOL, details={})`가 된다. 현재 전달 허용 목록에 `error_code`와 `recovery`가 없다.
오류 산문은 남지만 다음 행동을 구성할 구조는 유실된다. §6.7의 usage·stage 보강만으로
모든 복구 정보가 연결됐다고 볼 수 없다. **수리: R2 중 F4 계약 구현.** 기존 허용 목록에
`error_code`·`recovery`만 추가해 생산자가 낸 값을 그대로 전달한다. 현재 recovery 생산자는
브라우저 한 곳이므로 공통 복구 스키마나 자동 실행기는 만들지 않는다. 다른 생산자가 생기면
그 실제 차이를 보고 공통 형태의 필요성을 판단한다.

이 네 탐침은 외부 서비스를 모사해 운영 성공을 주장한 시험이 아니다. 기준 함수의 경계
동작을 격리 확인한 것이다. 원래 홈페이지의 펼침 버그 자체는 `a5678e5d`에서 수리됐으며
다시 미수리로 세지 않는다.

### R3. 요구의 완료 조건과 산출물 근거를 연결한다 — R1·R2 위에서

**목표:** “무엇을 실행했는가”와 “요구 중 무엇을 충족했는가”를 끝까지 함께 전달한다.

현재 `criteria_contract`·assert·업무 검사·최종평가·실행 추적은 각각 존재한다. 새 평가 엔진을

이것은 **제안하는 최소 의미 항목**이며 지금부터 모든 함수의 반환을 새 봉투로 강제하자는 뜻은 아니다.
구현은 기존 평가 사건·영수증·전달 manifest의 필드를 우선 사용하고 중복 상태 저장을 제거한다.

- 결정 가능한 조건은 기존 검사로 판정한다. 의미 판단이 필요한 명시 기준만 기존 선택적 평가가 맡는다.
- 의식 없는 실행도 명시된 조건·업무 검사 근거를 전달할 수 있어야 한다. 기준이 없으면
  확인한 실행 사실을 전달하며, 사용자 요구 충족을 독립 판정했다고 표시하지 않는다.
- 하위 함수의 통과가 상위 목표 통과가 되려면 그 조건을 실제로 포함한다는 연결이 있어야 한다.
  상위 조건에 포함되지 않은 단순 함수에는 목표 판정 의무를 추가하지 않는다.
- 사용자 정정·산출물 수정 뒤에는 영향받는 판정을 낡은 근거로 구분한다. 예전 승인으로
  새 파일의 품질을 보증하지 않으며, 영향 없는 읽기와 검증은 보존한다.

**소유자:** `supervisor_handoff`·`ibl_quality`·기존 평가/전달 경로·실행 추적·업무 검사 소비자.
**대체:** 작업 종료 상태나 산문의 “완료”를 요구 충족으로 추정하는 연결.
**완료 조건:** 기준 없음, 일부 충족, 미판정, 실패, 승인 뒤 내용 변경, 사용자 기준 정정,

### R4. 알려진 절차는 묶고 판단할 지점에는 작은 충분한 결과를 준다 — 다음 우선 구현

**목표:** 함수·참조·부분 재사용이 실제 작성에서 가장 자연스러운 경로가 되게 한다.

분해 지침을 다시 늘리는 것으로 끝내지 않는다. 기존 describe의 함수 계약, `check.functions`,
결과 참조, `continuation.reuse_args`, 프롬프트 조립을 하나의 작성 흐름에서 소비한다.

- 호출 계약에서 다음 연결에 필요한 입력·반환·효과·실패를 일관되게 제공한다. 잘 모르는
  필드·서명만 조회하고, 확인한 계약은 그 버전으로 다시 사용하게 한다.
- 프로그램은 알려진 읽기·변환·반복·검사를 실행하고, 새 판단이 필요한 값·근거·미해결점을
  반환한다. 후속 수정은 기존 읽기 영수증·명시 참조를 사용한다. 거대 프로그램 강제는 하지 않는다.
- 기본 카탈로그·역사·가이드·도구 본문의 구성 비용을 기존 `prompt_composition`과 실제
  `model.input`으로 분리한다. 얇은 전체 능력 안내와 필요한 상세 계약의 단계적 노출을 구현하되,
  관련도가 낮다는 이유로 사용 권한이나 전체 탐색 경로를 없애지 않는다.
- 원문·계약·이미지는 보존하고 표시만 선택한다. 이미 읽은 계약/가이드는 지문으로 구분하며
  변경 시 재조회한다. 사용자 요구·필수 근거를 일률 상한으로 잘라 비용을 낮추지 않는다.
- Codex의 세션 재설정·auto-compact는 이미 있다. 압축기 신설을 출발점으로 삼지 않고
  공통 입력·결과 설계와 기존 제공자별 문맥 정책을 연결한다. 새 상시 요약 모델은 추가하지 않는다.

**소유자:** `ibl_access`·`prompt_builder`·`model_result_view`·기존 계약 조회/검사·제공자 맥락 경계.
**대체:** 상세 카탈로그의 불필요한 상시 반복과 사람이 다시 구성해야 하는 후속 호출 안내.
**완료 조건:** 새 다단계 과제에서 입력→지역 함수→조합→부분 실패→참조/읽기 재사용→수정이
끊기지 않는다. 단순 조회는 직접 실행을 유지한다. 전체 목록·필수 근거·이미지·허용 능력의
발견 가능성을 잃지 않는다. 호출 감소만으로 품질·시간·토큰 개선을 선언하지 않는다.

**첫 한 커밋 — 선택한 텍스트의 이중 직렬화 제거:** `model_result_view.read_result`는 현재
선택한 문자열도 JSON 문자열로 만든 뒤 봉투의 text에 넣는다. TSX 같은 본문은 따옴표·개행이
다시 이스케이프되고 그 길이를 기준으로 페이지가 나뉜다. 기존 조회에 선택 문자열용
`format:text`를 연결하고 발급하는 `read_args`·`next_read`·길이 안내가 이를 함께 사용하게 한다.
현재 JSON 기본값과 구조 값 읽기는 보존한다. 명시 입력의 `$ref`는 전체 원값을 계속 가리킨다.
새 낱말이나 요약 모델 없이 원문 전달의 분량·페이지 왕복을 줄이는 한 커밋이다. F3의 과거 참조
안내나 R3 완료를 선행 조건으로 삼지 않는다.
**첫 시험:** 기존 `backend/test_episode3632_result_reads.py`에 한글·개행·따옴표·역슬래시가 많은
긴 TSX fixture를 추가한다. 안내된 next_read만 따라 읽어 원문과 바이트가 같고, 같은 limit에서
기존 JSON 모드보다 총 전달 문자와 페이지 수가 줄어야 한다. Record/List/JSON 모드와 참조 입력은
기존 의미가 같아야 한다. 실행 명령은 `.venv/bin/python -m pytest backend/test_episode3632_result_reads.py -q`.
4112의 저장된 읽기 대상·limit에도 같은 재생을 적용해 페이지 수와 표시 문자 차이를 남긴다.
이는 입력 경계 검증이며 모델의 30라운드가 실제로 몇 회 줄었는지, 전체 토큰·시간이 얼마나
개선됐는지는 후속 동등 과제 실행에서 따로 측정한다.

**그다음 잔여:** 이미 있는 `ibl_access.render_action_brief`와 compact 모드의 실제 주입 경로를

compact 자체나 참조 기능을 새로 발명할 과제로 취급하지 않는다.

### R5. 이름의 회상을 문제에 맞는 방법 선택으로 연결한다 — R4와 독립 보강 가능

**목표:** 사용자가 도구 이름을 말하지 않아도 적절한 기존 함수·라이브러리·방법을 찾는다.

글자 검색과 의미 검색이 이미 있으므로 새 검색기를 만드는 것으로 시작하지 않는다.
짧은 후속 지시에 이전 질의를 보충하는 `catalog_recall.previous_query`도 이미 있다.
현재 사용자 의도와 인용 자료·실행 로그를 구분한 질의, 하위 작업에 맞는 적용 조건,
후보를 실행 계약으로 좁히는 연결을 기존 회상 경로에 넣는다. 최초 요구가 넓으면 분야의
입구를 제시하고, 구체화된 하위 작업에서 필요한 후보만 더 찾는다.

세계 이름→관련 방법/제약→기존 어휘·등록 Script·설치된 라이브러리의 연결 가능성을
확인하게 한다. 지도 등재는 설치·권한·실행 보증이 아니다. `python_libraries`도 기존
Script의 modules/describe/call 경로를 사용하며 새 Python 어휘를 되살리지 않는다.

**소유자:** `catalog_recall`·`knowledge_catalog`·`world_context`·기존 실행기억·계약 조회.
**대체:** 인용 로그의 표면 단어가 현재 의도를 대신하는 질의와, 이름 제시만으로 발견을 완료 처리하는 관측.
**완료 조건:** 이름 없는 요구, 짧은 후속 지시, 긴 인용 로그가 포함된 요구에서 질의 출처가
유지된다. 후보의 적용/제약을 확인해 기존 실행 경로로 연결할 수 있다. 무관 후보를 쓰도록
강제하지 않는다. `mentioned`·실제 호출·산출물 기여를 혼동하지 않고, 방법 선택 효과는 별도 관측한다.

**첫 한 커밋 — 의미 후보에 기존 관계 묶음 연결:** `catalog_recall.world_memory_detail`의
의미 검색은 현재 후보 label을 제시한다. 선택된 ID를 기존 `world_context.assemble`에 연결해
적용 조건·필수 의존·부적합 조건을 글자 검색과 같은 규칙·예산으로 표시한다. `assemble`의 seed
출처도 lexical 상수 대신 실제 semantic/context/primary 출처를 보존하게 한다. 관계가 없는 이름은
기존 분야 경로로 보여 주며 지도 등재를 설치·실행 보장으로 바꾸지 않는다.
**첫 시험:** `backend/test_method_selection_contract.py`(추가 예정)에 이름 없는 요청과 고정된
의미 후보/관계 fixture를 넣는다. 검증된 필수 조건이 후보와 함께 나오고, 조건을 예산 안에 담지
못하거나 미검증 필수 관계가 있으면 추천 묶음이 제외돼야 한다. 출처가 semantic으로 남고
이미 글자 검색으로 제시한 후보는 중복되지 않아야 한다. 검색 모델 호출을 추가하지 않는다.
실행 명령은 `.venv/bin/python -m pytest backend/test_method_selection_contract.py backend/test_world_noun_refutable.py -q`.
짧은 후속 지시·긴 인용 로그에서 현재 의도를 분리하는 질의 연결은 이 커밋 다음 잔여로 남긴다.

### R6. 성공한 한 번과 재사용 가능한 능력의 근거를 구별한다 — R3·R5에 연결

**목표:** 축적한 함수가 새로운 입력·더 큰 조합에서 믿고 선택할 수 있는 부품이 된다.

`ibl_v2_experience.abstract_call`은 이미 명시 입력을 함수 인자로 올리고 AST·계획 지문을
검증하며 `new_input_successes:0`을 남긴다. 이 기능을 다시 만들지 않는다. 기존 provenance의
적용 조건·의존 계약·원 실행 근거·새 입력 사용 근거를 조회·회상·재검토가 함께 소비하게 한다.
전송/실행 성공, 명시 기준 통과, 다른 입력에서의 성공을 하나의 성공률로 바꾸지 않는다.

R3의 미판정 상태는 경험의 신뢰 범위를 제한하는 근거다. 평가가 없다는 이유로 모든 유용한
절차를 버리거나, 반대로 “검증된 정답”으로 승격하지 않는다. 동작 증거만 있는 후보도 그 범위로
소개할 수 있다. 코드·의존 계약 개정 시 이전 버전의 성공을 새 버전에 자동 이전하지 않는다.

**소유자:** `ibl_v2_experience`·`ibl_distill_value`·`unified_distill`·`corpus_policy`·회상/정의 조회.
**대체:** 저장 개수·단순 실행 성공·이름 언급을 능력 축적의 효과로 사용하는 해석.
**완료 조건:** 미검증 원 실행, 검증된 원 입력, 새 입력 성공, 개정 후 근거 만료가 구분돼
추천/조회에 전달된다. 지역 함수→저장→새 상위 함수→하위 정의 변경의 경계를 검사한다.
빈 증류는 계속 정상이며 매 턴 저장·재시험·추가 평가를 의무화하지 않는다.

**첫 한 커밋 — 새 입력 사용의 근거를 실제 호출에 연결:** `ibl_v2_experience`가 남기는
`new_input_successes:0`을 근거 없이 성공률로 해석하지 않도록, 기존 `ibl_v2_learning`의 실제
함수 호출 결과에 정의·의존 지문, 사용한 입력의 지문, 실행 결과와 품질 상태를 함께 기록한다.
값 원문은 복제하지 않는다. 같은 정의·의존·입력 조합의 재호출은 새 입력 증거 한 건으로만
계수하고 원 입력 재생은 제외한다. 새 입력의 실행 성공과 명시 기준 통과는 별도 근거로
provenance 조회·회상에 표시한다. 과거 기록에 입력 지문이 없으면 소급 추정하지 않는다.
**첫 시험:** `backend/test_new_input_evidence.py`(추가 예정)에 임시 정의/DB로 원 입력 A,
새 입력 B 성공, B 반복, 입력 C 실패, B 미판정, 정의 또는 의존 변경 후 B 호출을 둔다.
원 입력은 새 입력 수 0, B 성공·반복은 한 건, C 실패는 성공 근거 0이어야 한다. 미판정은
품질 통과로 계수하지 않고 개정 전 근거는 새 지문에 승계하지 않는다.
실행 명령은 `.venv/bin/python -m pytest backend/test_new_input_evidence.py backend/test_ibl_input_abstraction.py -q`.
첫 커밋은 실행·품질 근거의 구별까지다. R3의 목표 기준 연결과 새 상위 함수의 조건 적합성은 후속 잔여다.

## 6. 구현 순서와 완료 판정

1. **R1 + R2의 F2·F4: 계약 구현.** 확인된 판정·선택·복구 결함을 최소 경계 수리했다.
2. **R4 첫 커밋 우선.** 4112의 본문 재독 경계를 기준으로 원문 전달·왕복 비용을 줄인다.
   R2의 F3도 독립된 작은 안내 연결로 진행할 수 있으며 R4의 대기 관문으로 두지 않는다.
3. **R3 첫 커밋.** 응답·기준 지문을 기존 평가와 연결한다. 이어서 파일·하위 조건으로 넓힌다.
4. **R5 + R6.** R5의 의미 후보 연결과 R6의 실제 호출 근거는 위 첫 커밋들과 독립 착수 가능하다.
   R6의 목표 충족 근거까지 넓히는 단계는 R3을 사용한다.

여기서 병행 가능은 코드 의존 관계 설명이며, 자동 예약·다중 에이전트·별도 작업 생성을 지시하지 않는다.

| 상태 | 의미 | 갱신 시 필요한 근거 |
| --- | --- | --- |
| 미구현 | 이 문서에서 다음 변경과 완료 조건을 정함 | 소유자·의존성·대체할 경로 |
| 계약 구현 | 생산자·소비자·교재·이행·회귀가 연결됨 | 변경 커밋, 경계 시험, 남은 범위 |
| 운영 사용 확인 | 실제 실행이 새 경로를 사용함 | 변경 이후 에피소드/실행 지문·사용 사실 |
| 효과 확인 | 요구 품질을 보존하며 시간·전체 토큰 개선을 관측 | 비교 조건·캐시·내부 호출·증류를 포함한 기록 |

| 묶음 | 현재 상태 | 남은 범위 |

| R1 | 계약 구현 | 실제 운영의 상태 소비·효과 관측 |

추가 예정 시험 파일과 명령은 첫 커밋의 인수 조건이며 지금 통과한 시험으로 세지 않는다.
표의 상태는 서로를 자동 함의하지 않는다. 한 항목의 구현이
끝나면 남은 간극을 해당 항목에서 갱신하고, 다른 항목을 계속 미구현으로 방치하거나 완료 이력
아래에 묻지 않는다. 에피소드별 상세 수리는 changelog·커밋에 남기고 이 문서에는 목표와
잔여 상태의 변화를 반영한다. 새 결함은 기존 R에 연결하거나, 기존 범위로 설명되지 않을 때만 추가한다.

## 7. 검증은 어떻게 할 것인가

- **경계 회귀:** F1~F4와 정상/부분/실패/취소/권한 거절을 기존 시험에 연결한다. 해당 수리의
  완료 조건을 검사하고 저장소의 전체 회귀·파생물 규약을 따른다.
- **조합 검증:** 미등록 새 요구, 재사용할 기존 함수가 있는 요구, 간단한 조회를 구별한다.
  중첩 함수·긴 결과·다중 자료·사용자 정정·쓰기 결과 불명에서 R별 의미가 보존되는지 본다.
- **운영 관측:** 기존 에피소드·trajectory·supervision 원장을 사용한다. 모델·설정·자료·목표가
  다른 턴의 비용을 단순 전후 개선율로 만들지 않는다. 실패 뒤 재요청도 같은 목표 비용에 포함한다.
- **품질 우선:** 보고서 필수 근거·전체 목록·이미지·사용자 조건을 덜 제공한 절감을 인정하지 않는다.
  새로 필요한 설치·서비스·외부 효과는 기존 권한 경계를 따른다.
- **비용 분리:** 입력/출력/캐시, 주 실행/내부 모델/증류, 사용자 대기/후처리를 구분한다.
  표시 문자 감소·함수 증가·참조 사용·도구 호출 감소는 효과를 설명하는 보조 지표다.
- **대기 관문 금지:** 구현 전 모든 업무의 A/B를 요구하지 않는다. 설계한 성질을 구현·검증하고
  실제 비교가 가능한 범위에서 효과를 확인한다. 미측정은 미측정으로 남긴다.

최초 문서 작업은 코드 대조·읽기 전용 기록 집계·격리 탐침·문서 링크/차이를 검사했다.
이번 F1·F2·F4 수리는 `backend/test_repair_plan_boundaries.py`와 기존 품질·body·브라우저
경계 시험을 함께 검사하며 전체 backend 회귀·파생물 검사 결과는 이번 changelog에 기록한다.
이전 수리의 통과 수치를 이번 검증 성적으로 옮기지 않는다. 실제 모델 업무의 시간·전체 토큰
절감률과 R3~R6의 일반 능력 개선은 아직 측정하지 않았다.
