# IBL 일반 능력의 현황과 다음 수리 계획

**현재 순서: R4 입력 조각 측정(착수함) → R4 한 단위 수리 → R5 의도별 발견 → 소비자와 함께 R3·R6 확장.**
L15 계열·취소 시험은 관련 작업에 작은 수리로 끼운다. 각 비용 변경 묶음은 같은 조건의 재실행과 품질 판정까지 닫는다.

2026-10-01 개정. 코드 재점검은 `60660caa`, 보고서 수집 폭 복원은 `c0cd804a` 기준이다.

세 과제 각 1회의 기준선은 첫 변경의 전후 비교에 사용한다. 집계기·반복 실험을 착수 조건으로 두지 않는다.
아래 기준선 실행·기능 변경은 **예정**이며 수행 완료가 아니다.

목적: [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md) · [vision.md](../data/system_docs/vision.md).

## 1. 판단과 우선순위 수정

목표는 새 요구를 쉽게 표현·분해·조합하고, 필요한 부분만 고쳐 재사용하면서 **품질을 유지하거나
높이고 실제 완료 시간과 전체 토큰을 줄이는 것**이다. 구조 개선의 범위는 이 일반 능력에서 정하며,
세 고정 과제는 변경 확인용 표본이다. 특정 과제의 정답을 코어에 넣거나 측정 대기를 모든 개발의
선행 조건으로 만들지 않는다. 비용 변경을 비교할 실행에서는 변경 전 기준 구성을 먼저 보존한다.

이전 계획은 작은 경계 결함 L15-1·2를 먼저 두고 반복해서 관측된 맥락 비용을 뒤로 밀었다.
또한 “기능이 있다”에서 “적합할 때 발견하고 선택한다”로 넘어가는 구현·검증 단위를 충분히 정하지 않았다.
이를 R4·R5의 본 작업으로 바꾸고, 관측 가능한 품질·비용 비교를 묶음의 종료 단계에 넣는다.

다만 다음 구별은 유지한다.

- 캐시 읽기 비중은 비용 조사 근거다. 캐시 토큰이 같은 비율의 지연·청구액이라는 뜻은 아니다.
- 사용 0건만으로 기능 결함을 확정하지 않는다. 사용 가능한 **적합한 기회**가 있었는지부터 본다.
- R3의 기존 평가·전달 소비자는 이미 있다. R6도 추출·저장·호출 계수 경로가 있다. 소비자 부재를
  일반화하지 않고, 새 지문·계수가 바꿀 실제 판단과 소비 시험을 정한 뒤 확장한다.
- 고정 과제의 개선만으로 보편성을 선언하지 않는다. 변경에 맞는 미사용 분야·변형도 별도로 확인한다.

### 2.1 오늘 착수한 R4 측정: ep4197

당시 CLI 원문과 궤적을 대조했다. 로그의 message 55,963자에는 system 46,900자가 이미 포함된다.
**46,900 + 도구 정책/구분자 813 + 턴 메시지 8,250 = 55,963자**이며, 약 10만 자라는 합산은 중복이다.
턴 메시지의 회상은 8,112자다. 고정 입력의 분해는 다음과 같다.

| 조각 | 실측 문자 수 |
| --- | ---: |
| 액션 카탈로그 | 22,400 |
| 시스템 구조 설명 | 10,425 |
| 기본 지침·압축 IBL 문법·관용구 | 12,775 |
| 위임·역할·날짜·구분자 | 1,300 |

앞 두 조각이 고정 입력의 70.0%다. 첫 수리 후보는 카탈로그 내 액션 설명 154줄(19,324자)이다.

17라운드 뒤 이력 압축에도 원 요청은 보존됐다. **조각별 토큰 귀속은 미측정**이므로 문자 수×26이나
“전체 비용의 절반”을 실측으로 쓰지 않는다. 회상 출처·원문 구간·라운드별 토큰·후처리와 대조 검사는

## 4. 한 벌 기준선과 실행 기록의 사후 검토

### 4.1 고정 과제와 실행 조건

| 과제 | 요청·입력 정본 | 품질 판정 |
| --- | --- | --- |
| 작은 견적 비교(4180, 후속 4181) | [7회차 요청](experiments/long_sentence_imagination/round_7/task.md), round_1/input의 요구·견적 4파일 | 6개 조건·누락 가격 정직성. 인원/자료 부재 후속은 별도 세션 연속성 검사 |
| 가계부 결산(4182) | [8회차 요청](experiments/long_sentence_imagination/round_8/task.md), round_6/input의 ledger·rules.json·fixed.json만 | [6회차 조건](experiments/long_sentence_imagination/round_6/task.md)의 집합·합계·AI 표시·근거·파일 재읽기 |
| 주문·배송·반품 대사(4183) | [9회차 요청](experiments/long_sentence_imagination/round_9/task.md), round_9/input | 10개 조건. 내용 9개와 저장 후 검증을 별도로 판정 |

과거 에피소드는 비교 설계의 출발점이다. 당시 모델·문맥이 다르고 가계부의 빈 달/튄 달, 대사의
지연율 분모처럼 해석 차이도 있으므로 새 동조건 기준선을 만든다. 의미를 두 실행에 똑같이 명시하고
요청·완료 조건을 실행 전에 고정한다. 정답·해법은 실행자에게 주지 않는다.

기존 실행 기록에 요청/입력 경로와 변경 여부, 완료 조건, 코드 판본, 실제 역할별 모델/제공자·추론
설정, consciousness_enabled, 새 세션 여부를 남긴다. 기어 이름만으로 모델이 같다고 보지 않는다.
실제 cognition.route·평가 경로는 사후 기록에서 확인한다. 전면 스냅샷·새 manifest 시스템은 만들지 않는다.
origin:training과 분리된 이력·산출물을 사용하고 기대값/gen.py/훈련자 답안은 입력에서 제외한다.
training의 증류 0은 정상이다. 현재 운영 설정은 실험을 위해 바꾸지 않는다.

**세 과제 각 1회로 기준선 한 벌을 시작한다.** 첫 R4 변경 뒤 같은 요청·입력·모델·의식 설정으로
각 1회 비교한다. 이후 묶음은 영향을 받는 과제를 고르며, 조건이 유지된 기준선은 재사용한다.
비교 도중 관련 코드·설정·입력이 바뀌면 그 비교는 미확인으로 남긴다. 읽기 전용 측정·설계·관련
회귀는 기준선과 독립적으로 진행하며, 비교 실행 중에는 해당 실행의 코드를 바꾸지 않는다.

한 쌍의 품질·시간·토큰 차이를 그대로 보고하되 반복성과 일반화는 주장하지 않는다. 차이가 작아
잡음과 구별하기 어렵거나 기존 변동 범위와 겹칠 때, 지표가 상충하거나 조건 차이가 의심될 때만
해당 과제를 추가 실행한다. 한 쌍만으로 변동 범위를 산출하지 않는다. 두 쌍·순서 교차를 일률적인
필수 조건으로 두거나 작은 문구 수정마다 세 과제를 전수 재실행하지 않는다.

### 4.2 선택을 관측하고 개선할 단위

기능 사용 횟수를 올리는 것이 목표는 아니다. 실행 후 같은 판정 규칙으로 **기회 → 발견 → 선택 →
기여**를 잇는다. 다음 표의 기회는 변경 전후 공통으로 판정하고 근거 호출 ID를 남긴다.

| 대상 | 기회(분모) | 선택·기여(분자와 근거) |
| --- | --- | --- |
| 값/읽기/모델 재사용 | 성공 결과가 남아 있고 입력·의존·권한·효과·보존 조건이 같아 새 계산에 그대로 쓸 수 있는 단계 | 실제 참조/재사용 성공 수, 피한 재수집·모델 호출. reuse 옵션을 썼지만 전부 miss면 재사용 성공 아님 |
| 프로그램 회수 | 같은 절차의 후속 요청인데 앞 프로그램이 현재 문맥에 없고 허용된 호출 이력에 남은 경우 | calls:true→원문 조회→재사용 연결. 문맥에 이미 있는 코드 사용도 유효하며 회수 미사용을 벌점으로 세지 않음 |
| 회상 후보 | 사전 정한 적용 조건을 만족하고 접근 가능한 부품/방법이 해당 작업에 존재하는 경우 | 적합 후보 공급, 계약 열람, 실제 호출/방법 적용, 산출물 기여를 각각 센다. 이름 언급만으로 기여 판정 금지 |
| Script 등 대안 | 값 가공·조판에서 복수 실행 수단이 모두 적합한 구간 | 검토한 계약·선택·결과·작성/수정 비용을 기록. Script 사용률 자체에 목표치를 두지 않고 IBL로 잘 끝낸 대안도 인정 |

적합 후보가 없으면 발견률 분모에 넣지 않고 **후보 공백**으로 센다. 후보는 있지만 제시되지 않음,
제시됐으나 부적합, 계약을 못 찾음, 선택했으나 실패를 구분한다. 무관 후보를 빼서 선택률을 높인
척하지 않도록 원래 제시 수·적합 수·전체 기회 수를 함께 공개한다. 분모 0은 N/A, 관측 누락은 미측정이다.
새로운 기회가 생기면 공통 기회와 신규 기회를 나눠 변화 이유를 보존한다.

기존 recall.used·호출 원장·context.input_ref_resolved·영수증·model.input/usage를 우선 사용한다.
세계 지도 evidence=mentioned와 실행기억 evidence=executed도 구분하고 실제 산출물 기여는 원문으로
대조한다. 자동 판정 불가능한 기회/기여는 근거를 붙인 사후 검토로 남긴다. 매 턴 자기보고나 새 모델을
붙이지 않는다. **기존 실행 기록을 사람이 사후에 읽어 간단한 표로 남기는 것으로 시작한다.**
새 집계기 구현은 전제가 아니다. 로그에 없는 기회·거절·선택은 0으로 채우지 않고 미측정으로 둔다.

## 5. 다음 구현 묶음과 소비자

### R4. 맥락·반복 비용과 선택 마찰 — 주 작업

소유자: prompt_composition·prompt_builder·ibl_access·model_result_view·제공자 입력 경계.
§2.1에서 ep4197의 고정/회상 조각과 라운드 입력을 실측했다. 카탈로그 액션 설명 19,324자를
첫 검토 대상으로 삼는다. 누적 이력·결과 재독·계약 탐색의 비용은 별도로 확인하며,
prompt_composition의 추정 토큰을 실제 청구 토큰으로 쓰지 않는다.

**첫 변경 단위:** 측정에서 큰 중복 조각을 하나 골라 기존 compact 안내·describe·가이드·결과 참조로
상세 조회를 이어 준다. 필수 계약·전체 탐색·권한·이미지·사용자 조건은 유지한다. 단순 삭제와 상시
요약 모델 신설은 하지 않는다. 제거한 본문과 대체 조회를 한 쌍으로 검사한다.

**선택 개선 단위:** 이미 제공하는 continuation.reuse_args·result_ref.input_args·calls:true가 필요한
시점의 응답에서 보이고 바로 실행 가능한지 확인한다. 단서가 없거나 묻히는 경계를 고치며 상시
프롬프트에 또 긴 지침을 쌓지 않는다. Script는 복잡한 가공의 기존 가이드에서 발견할 수 있게 하되
선택을 강제하지 않는다. 현재 힌트만으로 충분하다면 더 추가하지 않고 R5의 적합성 문제로 돌린다.

인수: 필수 정보/발견 가능성 보존 회귀 + §4의 동일 구성 재실행. 품질이 유지된 상태에서 고정·누적
토큰, 라운드·거절, 재독/불필요 재실행과 실제 시간·전체 토큰을 비교한다. 단순 조회·새 다단계 과제와
후속 변경을 함께 보며, 줄인 입력 때문에 상세 조회가 늘어 총비용이 악화되면 부분 성과/퇴행으로 기록한다.

### R5. 현재 의도에 맞는 후보와 사용 계약 — 후속 핵심 작업

소유자: catalog_recall·world_context·기존 실행기억·계약 조회.
의미 후보의 관계/필수 조건/예산 전달은 이미 있다. 다음 변경은 검색 질의에서 사용자 지시와 인용·
실행 로그를 구분하고, 짧은 후속 목표·새 주제 전환을 두 회상 경로가 같은 기준으로 반영하는 것이다.
인용 자체가 분석 대상이면 그 정보는 보존한다. 새 상시 질의 분류 모델을 추가하지 않는다.

**인수:** 이름 없는 요청·긴 무관 로그·짧은 후속·주제 변경에서 적합 후보 공급과 계약 접근을 검사하고
§4의 기회별 발견/선택/기여를 비교한다. 무관 후보를 쓰도록 강제하지 않는다. 개인 조건 연결은 기존
개인 기억의 권한·출처·최신성을 지키며, 기억 부재를 자격 미달로 판정하지 않는다.
고정 세 과제 외에 적합한 저장 부품이 있는 후속 자료 변경과 이름을 주지 않은 미사용 분야 한 과제를
포함한다. 별도 임시 코퍼스에 준비한 부품은 준비 비용과 설정을 밝혀 효과를 부풀리지 않는다.

### R2·L15와 취소 시험 — 관련 경계의 작은 수리

- L15-1: 실패 직전 해석된 인자를 기존 값 저장소의 read_args/input_args로 잇고, 앞 6개 밖 완료
  호출도 조회한다. 순수 계산→후반 실패→부분 수정에서 원값·타입·권한·마스킹·불완전성을 보존한다.
- L15-2: 코드·인자·환경 중 변경 차원을 지문과 함께 안내한다. RESUME_DIVERGED와 효과 불명 거절,
  같은 영수증 복원은 유지하고 자동 재실행하지 않는다.
- F3: 현재/최근 결과 ID와 과거 source_ref의 범위·읽기 경로를 발급자가 안내한다. 근거 없는 만료
  추정·전역 저장소 검색을 하지 않는다.
- L15-3: 금지·인용·가정과 긍정 수리 의도를 구별한다. 명시 #repair·의식 정정·권한 경계는 유지한다.
- 취소 회귀: 생성 전/후 취소를 결정론적으로 나눠 검사한다. 0.15초 뒤에는 PID가 반드시 있다는
  시험 가정을 제거한다. 단독 재검 통과로 기존 묶음 실패를 닫지 않는다.

안전·정확성 결함이 주 작업을 막으면 먼저 수리한다. 그렇지 않으면 이 목록을 소진해야 R4/R5를
시작하는 순서를 만들지 않는다. 각 변경은 관련 회귀로 닫고 행동·비용에 영향을 주는 묶음만 §4와 연결한다.

### R3·R6. 근거를 실제 판단에 쓰는 소비자와 함께 확장

우선순위는 R4/R5 뒤다. 다만 기존 소비자의 확정된 승인 오류·잘못된 추천은 즉시 해당 경계에서 고친다.

섞어서 소비자를 만들지 않는다. 실사용 누적을 기다리지 않고 임시 저장소에서 생산→소비를 검증할 수 있다.

## 6. 실행 순서와 한 묶음의 종료

1. **R4 읽기 전용 측정:** ep4197 조각 분해를 완료했다(§2.1). 기준선이나 집계기를 기다리지 않는다.
   첫 변경을 적용하기 전 세 과제 각 1회의 비교 기준을 확보한다. 새 검증 기반 구축은 요구하지 않는다.
2. **R4 한 단위 변경:** compact 액션 설명에서 상세 조회로 옮길 중복을 고른다. 관련 회귀 뒤 같은
   세 과제를 각 1회 비교하고 §7의 품질·시간·토큰을 판정한다. 추가 반복은 §4의 불명확한 경우만 한다.
3. **R5 한 단위 변경:** 질의/후보 적합성 연결을 고친다. 같은 기준선 구성과 적합 부품/미사용 과제로
   발견·선택·기여 및 총비용을 재측정한다. 후보 제시 수만 늘린 것을 개선으로 세지 않는다.
4. **작은 수리:** L15·F3·취소 시험은 해당 묶음에 함께 넣거나 독립 회귀로 처리한다. 주 작업의 전제 목록이 아니다.
5. **R3·R6 확장:** 사용할 소비자의 판단을 정한 뒤 생산·전달·소비까지 구현한다. 관련 조합 검증과
   영향을 받는 고정 과제 재실행을 함께 닫는다.

각 묶음은 **변경 → 관련 회귀 → 동조건 재실행 → 독립 품질 확인 → 비용/선택 비교**를 기록한다.
미실행/환경 불일치면 계약 구현·효과 미확인으로 남기고 필요한 재실행을 적는다.

## 7. 품질 집행과 효과 판정

### 7.1 비용 수리가 품질을 깎으면 통과하지 못하게 한다

비용 변경의 인수 조건에 **산출물과 실행 근거를 대조하는 독립 검사**를 포함한다. 이는 실험/변경
채택의 검사이며 모든 실사용에 새 평가 모델이나 보편 발행 차단기를 붙이라는 뜻이 아니다.
검증기·기준은 전후 결과를 보기 전에 고정하고, 실행자 자기평가를 합격 근거로 대신하지 않는다.

- 합성 세 과제: 기대 집합·합계·누락/부분 실패·AI 표시·근거·최종 md/json 내용·저장 후 재읽기를
  각각 검사한다. 파일 존재·봉투 success만으로 통과하지 않는다. 숫자 없는 집계·지연율 분모 등
  모호한 조건은 시작 전에 두 실행에 동일하게 명시하고 사후에 낮추지 않는다.
- 조사/보고서: 현재 업무 가이드의 필수 조사 가지를 실제 수집 호출/결과와 대조한다. 연 가지와
  새 사건 수를 구분하며, 못 연 가지의 실패·미확인 표시를 최종 출처 절에서도 확인한다.
  출처·기간·주요 사실 보존은 독립 검토한다. 사건/글자 수를 늘리는 것으로 품질을 대체하지 않는다.
- 검토에서 필수 항목/조사 가지/출처 누락은 불합격이다. 자동 검증기를 새로 만들거나 바꾸는 경우에만
  해당 누락을 잡는 음성 시험을 함께 둔다. 첫 비교는 기존 검증과 산출물·실행 기록의 직접 대조로
  시작한다. 정직한 부분 완료도 완전 달성과 구분하고 부분 결과의 절감을 완전 달성의 절감으로 보고하지 않는다.

동향 보고서 반례는 R4 검증에서 별도로 다룬다. 합성 세 과제는 조사 범위 축소를 잡지 못한다.
보고서에 영향을 주는 변경에서는 가이드의 필수 가지와 실제 수집/산출물을 직접 대조한다.
`scripts/test_ai_trend_idioms.py`의 기존 인자 전달·예제 실행 검사는 실제 주행의 조사 폭까지
보증하지 않는다. 반복해서 필요한 부분만 자동화하며 새 보고서 검증기 완성을 R4 착수 조건으로 두지 않는다.

필수 품질 조건이 깨지면 시간·토큰이 줄어도 개선 채택을 거절하고 원인을 고친다. 경계 수리가
필요한 부분 완료를 정직하게 드러낸 경우는 가치가 있지만 품질/비용 동시 개선으로 보고하지 않는다.
