# 관용구를 문장 속 표현으로 쓰기 — 2026-09-07

사용자 의도: 단어를 매번 조립하는 대신 외운 관용구를 연결해 복잡한 문장을 만든다.
이번 범위는 ① 부르기 쉬운 형태 ② 유용한 관용구 선정·등록. 자동 선택기나 새 문법을 추가하지 않았다.

## 호출 형태

`[fn:이름]{인자}`와 기존 `>>`가 이미 충분하다. 원문·목록은 앞 통화로 받고,
짧은 값·지시만 인자로 받도록 정의를 다듬는다. 결과는 다음 낱말·관용구로 흘린다.
교재에는 실행 가능한 호출 표기, 입력 종류·제약, 문장 안에서 쓰는 예시를 함께 싣는다.

- 상시 지도는 공용 `phrase_call_line`으로 실제 호출 문법을 표시한다.
- 재파싱되는 `do` 안의 인자는 each의 리터럴 규약으로 이스케이프한다.
  `O'Reilly`·큰따옴표·백슬래시·개행이 지시에 들어가도 코드가 되지 않는다.
- 함수 몸은 타입 검사에서도 `[def:]` 문맥으로 읽는다.
- 인식기는 저장 본문의 `;`도 정본 문장 분리기로 센다.
- 40자 절감 관문은 짧은 재사용 표현을 탈락시켰다. 호출이 더 길어지는 경우만 거절한다.
  유용성은 반복 가능한 의미·조합·단순 인자로 고른다. 자동 작명은 다시 켜지 않는다.

## 선정

재현 가능한 등록 입력·교재: `data/idioms/curated.json`.
실행 정본은 기존 해마 원장/가지 문서이며, 선정집과 본문이 달라지면 옛 교재는 표시하지 않는다.

| 이름 | 선정·수리 이유 |
|---|---|
| 중복빼고추리기 | 생산자 종류와 무관하게 중복 제거→앞 N개. 파이프 입력, 인자 2개 |
| 각각읽고요약 | URL 목록→각 원문 읽기·요약. 호출자가 each 안쪽 프로그램을 다시 쓰지 않음. 실패 행 보존 |
| 잘라각각종합 | 긴 원문을 파이프로 받음. 덩이 수에 맞게 전량 처리, 부분 실패는 중단. 지시 2개 |
| 원장에누적 | 두 통화→중복 없는 JSON 누적. 기존 행 우선이며 upsert가 아님을 명시 |
| 좁혀서읽기 | 검색→일치 자리 읽기. 상위 3곳·각 30줄이라는 범위를 명시 |
| 최신파일읽기 | 이름순 대신 수정시각순. 파일만 선택. 검색 200건·분 단위 시각·160줄 범위를 명시 |
| 고치고확인하기 | 문자열 치환→패턴 위치 확인. 의미 검증·테스트 통과를 약속하지 않음 |
| 덜어내고요지만 | 웹 원문 보존→짧은 요지. AI 입력 상한과 분할 요약의 경계를 명시 |

상시 소개 제외(이름은 남아 기존 호출 가능):
표보고조회하기(중간 판단 누락), 행마다붙이기(호출자가 반복 본문을 재작성),
띄우고기다리기(작업 인자·실패 종료 계약 부족), 모아서추리기(두 출처·같은 질의로 고정).
새 표현 2개와 기존 6개를 선정했고, 각각 실제 조합 용례를 해마 단일 입구로 등록한다.

## 재현

```bash
.venv/bin/python scripts/curate_idioms.py
.venv/bin/python scripts/curate_idioms.py --apply --local-encoder
.venv/bin/python -m pytest backend/test_idiom_composition_2026_09_07.py -q
```

검사는 전체 선정집을 먼저 확인한다. 적용은 SQLite backup 후 실행 이력 없는 정의만 교체하고,
사용된 정의의 변경은 거절한다. 재적용은 같은 호출 용례를 중복 삽입하지 않으며 벡터도 갱신한다.
값 없는 `…` 호출은 전용 출처·실행 0인 것만 회수한다. 사용자 실행 증거는 지우지 않는다.

검증은 실제 파서·함수 해소·파이프·변환자·파일 도구를 사용하고 웹/AI만 고정 응답으로 격리한다.
두 관용구와 일반 낱말 연결, 중복·오류 행 보존, 8덩이 초과, 두 통화 누적과 멱등성,
수정시각과 이름순의 반례, 찾기·읽기·편집, 원문 보존, 인자 구두점을 확인한다.
라이브 `/ibl/execute`에서도 `take → 중복빼고추리기 → select`를 실행하여 3행→2행을 확인했다.
모델이 자연 요청에서 더 자주 선택하는지는 이 검증으로 주장하지 않는다.
