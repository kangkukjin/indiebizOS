# 원샷 호출 없는 관용구 3개 추가 — 2026-09-09

사용자 요청: 기존 상시 관용구에 분야를 넓힐 수 있는 3개만 추가하고 등록·노출한다.
핵심 원칙은 **관용구 실행 중 추가 AI 호출 0회**다. 원장에누적·위치마다읽기·최신범위읽기에
아래 세 이름을 더한다. 실행 정본은 해마 원장, 재현 가능한 등록 입력은 `data/idioms/curated.json`이다.

| 관용구 | 입력 → 결과 | 쓸 곳 |
|---|---|---|
| 미처리만고르기 | 후보·처리됨·키 → 처리 이력에 없는 고유 후보 | 뉴스·논문 수집의 재처리 방지, 제출·주문 목록 대조 |
| 묶어순위내기 | 목록·묶음·값열·개수 → 그룹별 합계·건수, 합계 내림차순 | 상품별 매출, 부서×항목 지출, 종목별 누적 운동 시간 |
| 주소마다읽기 | URL 목록·개수 → 중복 없는 페이지들의 원문 문단과 출처·실패 | 조사 자료·학습 자료·제품 설명 원문 수집 |

미처리만고르기는 `dedup` 후 `join how:anti`이며 복합키도 받는다. 후보의 첫 행과 순서를
보존한다. 같은 키의 내용 변경을 감지하는 upsert가 아니다. null·빈 키는 미일치로 남으므로
키를 확인하고 사용한다. 처리 목록을 자동으로 저장하지 않는다.

묶어순위내기는 `groupby → sort → take`다. 숫자 관측 없는 그룹의 합계는 null이며 건수는
그룹 전체 행수다. 단위를 섞어 환산하거나 평균·의미 평가를 하지 않는다. 그룹 키 이름으로
결과 열인 합계·건수를 쓰지 않는다.

주소마다읽기는 `dedup → take → each(crawl)`다. 수는 페이지 기준이며 원문은 문단 단위로
돌아와 행 수가 더 많을 수 있다. 크롤 원문은 전문 보관하고 모델 표시만 제한한다. 접근 제한과
추출 한계를 상속한다. 실패 페이지는 출처가 붙은 `_error` 행으로 남긴다.

## 등록과 노출

기존 관용구의 본문·승격 상태를 바꾸지 않고 새 3개만 `curate_idioms.py --apply --local-encoder`로
등록한다. 각 정의에 대표 호출 1개와 생산자가 다른 조합 용례 2개를 함께 심는다.
등록 전 라이브 SQLite를 `data/_backups/` 아래에 SQLite backup API로 보존한다.
등록용 임베딩은 검색 색인을 만드는 절차이며, 관용구 본문의 원샷 호출과는 별개다.

상시 지도와 마지막 잎 액션 아래의 `↳ 관용구` 줄에 여섯 이름이 소개된다.
`sense`가 허용되지 않은 자아에는 주소마다읽기가 노출되지 않는다. 등록·노출은 실행 권한을
추가하지 않는다. `/packages/reload`는 관용구 지도·병기 캐시도 비워 다음 프롬프트에 반영한다.

## 검증

`backend/test_idiom_expansion_2026_09_09.py`가 실제 파서·함수 실행기·표 변환자를 사용해
복합키·중복·빈 입력·처리 완료·null 집계·0개 읽기·부분 실패·관용구 연결을 검사한다.
웹 응답은 고정 대역이며 실제 crawl 핸들러의 문단 변환도 별도로 검사한다.
본문은 검토한 비-AI 원시의 닫힌 집합에 속해야 한다. fn/script/AI 술어·criteria 등
추가 판단을 숨길 수 있는 경로를 통과한 것으로 간주하지 않는다.

원장 대역으로 여섯 이름이 예산 안에서 지도와 잎 액션 줄 양쪽에 소개되는지,
노드 제한과 노출 해제·명시 reload가 양쪽 표면에 적용되는지도 검사한다.
이 검사는 결과 계약의 검증이며 모델의 자연 선택률이나 전체 업무 시간 절감 실험은 아니다.
