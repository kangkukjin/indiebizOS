- 양성 기준 프로그램 8개와 부적합 호출을 먼저 검증했다. 파일을 실제 읽었지만 본문이 최종 반환에서 빠지는 경우도 품질 실패로 판정했다.

## 발견한 결함과 수리 검증

1. **`좁혀서읽기`의 결과 누락.** `each`가 3개 파일을 읽었지만 스칼라 본문을 모으지 않아 원래 grep 행만 반환했다. 실행은 `success:true`였고 기존 테스트도 통과했다. 본문에 `collect:true`를 넣고 실제 원장에 같은 이름·서명으로 개정했다. 이전 본문과 실적은 `ibl_idiom_revisions`에 보존했다. 새 테스트는 위치뿐 아니라 뒤따르는 29줄 본문도 확인한다.
2. **`각각읽고요약`의 출력 설명 누락.** 실제 요약 열은 `message`인데 현재 지도 조건의 두 실행이 `요약`을 select하다 실패했다. 교재에 성공 행의 `title·url·message·rows_in`과 실패 행의 `_error`를 명시했다. `좁혀서읽기`의 본문 열 `value`도 명시했다. 기존 함수의 반환 형태는 유지했다.

같은 첫 생성 코드 64개를 수정 전 카탈로그와 수정 후 카탈로그에 각각 재생했다. 모델을 다시 호출하지 않았으며, 수정 전 재생 결과는 최초 기록과 64/64 일치했다. 함수 본문 변경만으로 `좁혀서읽기`를 호출한 6개 실패가 모두 성공했다. 첫 성공 수는 없음 9→9, 현재 지도 12→14, 짧은 지도 13→15, 후보만 12→14였다. 이것은 수정된 설명을 보고 모델이 다시 선택한 결과가 아니다.

그 다음 두 문제 과제 × 세 제공 조건 × 두 반복, **새 모델 생성 12건**으로 확인했다. 모두 첫 시도에 성공했다. 현재 지도 4건의 출력 합계는 수정 전 1,496→수정 후 404토큰, 수리 시도 4→0이었다. 이 후속 비교는 작은 확인 표본이며, 설명 보완의 효과 크기를 확정하는 독립 대규모 검증은 아니다. 나머지 과제 전체를 수정 후 새로 생성한 성적과 섞지 않았다.

## 적용한 판단과 남은 검증

- 관용구 제도와 현재 지도 제공 방식은 유지한다. 소수 표본으로 전역 프롬프트를 더 짧게 바꾸지 않는다.
- 관용구의 값은 이름 수·호출 수보다, 동일 결과 기준에서 최초 성공률과 수리 포함 생성량으로 평가한다. 실행 성공만으로는 본문 누락을 잡지 못했다.
- 단순 조합의 이름을 늘리는 근거는 얻지 못했다. 안정적인 입출력 연결·실패 보존을 재사용하는 단위에는 이득이 관측됐다.
- 이 실험은 기존 관용구에 맞춘 작은 과제, 한 모델, 두 반복이다. 자율 보고서 작업·실제 출처 품질·주제 선정·사용자 수정량·유료 도구 비용을 측정하지 않았다. 다른 하네스 대비 indiebizOS 전체의 우열이나 장기 비용 이득을 주장할 수 없다.
- 다음 전체 업무 실험에서는 동일 자료 스냅샷과 품질 심사로 보고서를 비교하고, 재작성·사용자 수정량까지 기록해야 한다. 이번 변경은 그 전체 실험을 완료했다는 뜻이 아니다.
