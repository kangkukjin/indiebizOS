# 관용구 수리와 재사용 검증

관용구의 성공 기준은 이름을 호출한 횟수가 아니라 **같은 품질에서 판단·재작성·수리가 줄었는가**다. 전체 보고서보다 정규화·중복 제거·각각 읽기·누적처럼 입력과 결과를 검증할 수 있는 중간 단위를 먼저 고친다.

## 기존 본문을 고치는 경로

1. `[self:memory]{op:"recall", store:"실행", expand:"이름"}`으로 현재 정의와 서명을 읽는다. 실패 에피소드의 실제 입력과 뿌리 오류를 확인한다.
2. 같은 이름·인자를 유지한 `[def:]`를 이번 프로그램 안에서 검증한다. 실패 입력뿐 아니라 빈 입력·누락 값·중복·경계 날짜도 확인한다. 자료 수집이나 외부 쓰기를 다시 실행하지 말고 고정 입력과 임시 출력으로 수리 부위를 재현한다.
3. 검증된 본문만 `.ibl` 파일에 두고 다음 경로로 명시 개정한다. 이는 시스템 수정 작업이다. 매 보고서 실행이나 자동 증류가 수행하는 단계가 아니다.

```bash
.venv/bin/python scripts/register_idiom.py --update 이름 --body 수리.ibl --reason "뿌리 오류와 검증한 입력·결과"
```

같은 id·이름·호출 서명·소개 층을 유지한다. 이전 행 전체(본문·성공/실패·평균 비용)는 `ibl_usage.db`의 `ibl_idiom_revisions`에 새 본문과 함께 원자적으로 보존된다. 새 본문의 실적은 0회, 평균 비용은 미측정으로 시작한다. 서명을 바꾸면 기존 호출자가 깨지므로 이 경로는 거절한다. 선정집(`data/idioms/curated.json`)에 실린 본문은 해당 교재도 함께 맞춘다.

판본 2 본문(`#!ibl edition=2` 한 정의)도 같은 스크립트가 받는다(2026-09-26) — 같은 이름의 같은 판본 행만 개정하며, 여러 정의를 한 번에 심을 때는 `scripts/register_webapp_idioms.py --seed-file`을 쓴다.

자동 증류는 경험을 남기지만 신규 이름이나 본문 개정을 약속하지 않는다. 신규 관용구는 `scripts/register_idiom.py --add`로 수동 등록한다. `--promote`는 상시 소개와 호출 용례를 추가하는 별도 선택이다.

## 실패에서 재개

- 실패 봉투의 뿌리 오류를 먼저 고친다. 실패한 할당과 그 변수에 의존하는 후속 문장은 성공 자료가 아니다.
- `resume.vars_ref`는 저장된 성공 변수의 복구 위치다. 실패 변수·생성되지 않은 파일을 복원하지 않는다. 중간 파일은 `~workspace/` 등 해석이 분명한 경로를 사용한다.
- 정규화·조인·열 변환 결과는 필요한 열과 행만 반환한다. 원문·자막은 통화로 전달하거나 파일에 보존하고 모델이 판단할 경계에서만 읽는다.
- 식 검사·dry-run 통과는 결과 품질·비용 개선의 증거가 아니다. 실제 입력으로 재실행하고 다음 사용 기록에서 같은 수리가 다시 나타나는지 확인한다.

## 동일 조건 비교

같은 모델·모델 설정·권한·프롬프트 버전·자료 스냅샷·품질 기준을 고정한다. 외부 검색·자막은 고정 fixture로 대체하고, 두 방식의 원장·출력 폴더는 각각 같은 초기 상태로 복제한다. 한쪽 실행이 다른 쪽의 원장을 바꾸면 비교는 무효다.

A는 기존의 개별 호출·수동 배관, B는 검증된 관용구·조합이다. 품질 기준은 실행 전에 고정하고 결과물을 방식 표시 없이 평가한다. 방식 순서를 번갈아 여러 번 실행해 다음을 함께 기록한다.

| 측정 | 기준 |
|---|---|
| 품질 | 필수 출처·날짜·행 수·누적 무결성 + 사람이 읽은 유용성 |
| 시간 | 동일 시작/종료 지점의 벽시계, 수집 대기 포함 |
| 토큰 | 신규 입력·캐시 입력·출력·하위 AI 호출을 분리; 누락은 미측정 |
| 수리 | 실패 IBL 호출, 실패 뒤 재작성한 호출, 같은 뿌리 오류의 재발 |
| 사람 수정 | 사용자가 고친 내용과 편집 시간; 미응답은 0으로 간주하지 않음 |
| 데이터 왕복 | IBL 코드·반환 문자수, 모델 입력 토큰과 구별 |

품질 미달 결과를 싸다고 승자로 고르지 않는다. 같은 품질을 통과한 쌍의 비용과 편차를 비교한다. 오프라인 회귀는 마찰 제거를 증명하며 실제 보고서 시간·모델 토큰 절감은 다음 실사용 또는 위 비교에서 따로 검증한다.
