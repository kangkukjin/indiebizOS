## 추가한 두 관용구

### 위치마다읽기

```ibl
[self:grep]{path:"notes",pattern:"TODO",file_pattern:"*.txt",limit:20}
>> [fn:위치마다읽기]{개수:5,줄수:12}
```

grep 결과의 앞 개수곳을 지정 줄 수만큼 읽고 `파일·줄번호·value(본문)`를 모은다. 실패한 위치는 `_error`로 남긴다. 개수와 줄 수를 바꿔도 본문 수집·행의 출처·실패 보존을 다시 작성할 필요가 없다. 전체 일치 위치만 필요한 경우에는 grep만 사용한다.

### 최신범위읽기

```ibl
[fn:최신범위읽기]{폴더:"reports",패턴:"*.md",시작줄:25,줄수:7}
```

수정시각 기준의 최신 파일을 찾아 25~31줄 본문을 반환한다. 후보가 없으면 파일 읽기를 시도하지 않고 빈 items를 반환한다. **검색 상한 200건과 수정시각 분 단위의 한계는 남아 있다.** 후보가 잘렸거나 수정시각 동률인 경우 전체 최신을 보장하는 도구로 쓰면 안 된다. 이 전제는 호출 카드에 명시했다.

두 항목은 실제 해마 원장에 등록했고 조합 용례도 심었다. 모델 실행 중에는 원장을 바꾸지 않았으며, 실험 실행은 별도 fixture 원장을 사용해 모델 실험 통계를 운영 성공 횟수에 섞지 않았다.

## 비교 실험

- 실제 생성 모델: `claude-opus-5`, 설정 `claude_code/opus`, effort medium. 보조 Haiku 사용량도 감사 기록에 별도 보존했다.
- 8과제 × 3조건 × 2반복 = 48건을 두 번, 총 96건. 각 건 최대 한 번 수리, seed 20260908로 순서를 섞고 동시 생성 2개.
- 조건: 등록 함수 없음 / 실제 현재 지도 / 같은 활성 관용구의 짧은 지도. 후보를 정답에 맞춰 미리 좁히는 조건은 이번 주 비교에서 사용하지 않았다.
- 같은 IBL 참고서·자료·권한·품질 오라클을 사용했다. 첫 실행 실패 때 같은 초기 파일에서 전체 프로그램을 한 번 더 생성했다. 인지 과정은 직접 측정하지 않고 최초 성공·재작성 횟수·생성량을 대리 지표로 봤다.
- 실제 파서·타입 검사·함수·표 변환·파일 도구를 실행했다. 외부 웹과 AI 요약은 fixture 실행기의 격리 대상이며 이번 8과제는 외부 웹/요약을 필요로 하지 않는다.
- 미리 작성한 기준 프로그램 8개를 통과시킨 뒤 모델 생성을 시작했다. 오라클은 실제 본문 줄·위치·실패 행·읽기 횟수·저장 파일 내용을 검사하며, 관용구를 불렀는지는 성공 기준으로 쓰지 않는다.
- 부적합 대조군은 전체 위치만 찾기와 가장 오래된 파일 읽기다. 최신 파일 관용구를 강제로 쓰게 하지 않았다.

## 발견한 실행 결함과 수리

별도의 고정 6문장으로 `self:read` 범위 문제를 재현했다. 수리 전에는 여섯 문장 모두 성공으로 표시됐다.

- `start_line:0`을 1로 바꾸거나 비정수 시작 줄을 무시해 파일 머리를 읽었다.
- 시작 줄보다 이른 끝 줄을 최소 1줄로 바꿨다.
- 음수 offset/limit은 잘못된 슬라이스와 줄 범위를 냈다.
- **`limit:0`이 전체 파일 반환으로 바뀌었다.**

정수·범위·서로 충돌하는 시작/끝 옵션을 하나의 정규화 경로에서 검사한다. 잘못된 다섯 문장은 명시 실패로 바뀌었고, 0줄은 빈 본문을 반환한다. 문단 blocks 모드도 0줄과 생략을 구별한다. 빈 범위의 표시도 `줄 없음`으로 고쳤다. 정당한 1-기반 양끝 포함 범위와 0-기반 offset/limit은 같은 본문을 반환한다.

모델 실험에서는 `end_line: $줄번호 + 3`의 파싱 실패가 따옴표 이스케이프 문제로 진단되는 것도 발견했다. 산술식 자리에 맞는 진단과 **먼저 변수에 계산하거나 줄 수를 limit로 지정하는 방법**을 안내하도록 고쳤다. 이 문구 수리는 두 번째 모델 생성 완료 뒤에 했으므로 위 생성 성적에 효과가 포함되지 않는다. 새 문법이나 어휘는 추가하지 않았다.

선정집 재적용이 모든 항목을 다시 `always_on=1`로 만드는 문제도 고쳤다. 호환 항목의 `always_on:false`를 존중하고, 비활성 항목이 demote 목록에 있는 것을 등록 충돌로 오판하지 않는다. 이것이 있어야 이번 선별이 다음 등록 때 되돌아가지 않는다.

## 판단

관용구는 AI의 기억력 부족을 보충하는 장치만은 아니다. **이미 검증한 실행 계약을 다시 작성하지 않고 재사용하게 하는 장치**로 가치가 있었다. 모델이 기본 액션을 기억해도 값의 모양·실패 보존·결과 수집 옵션을 매번 올바르게 연결한다는 보장은 없었다.

앞으로의 승격 기준은 이름의 짧음보다 **어떤 실패를 없애는지, 반환 형태가 명확한지, 요구가 조금 바뀌어도 사용할 수 있는지**로 두는 것이 좋다. 단순 두 액션 축약은 상시 제공에서 빼고, 안정된 중간 단위를 소수 유지한다. 이번에는 짧은 지도가 현재 지도보다 더 좋지 않았으므로 현재의 조건·입출력·골격·조합 예 제공 방식을 유지했다.

이 결과는 한 모델·8과제·두 반복의 작은 실험이다. 새 후보에 맞춘 과제와 범위 변형이 포함되어 있다. 저자가 관용구를 만드는 비용, 실제 보고서의 출처 품질·사용자 수정량·자율 선택·장기 운영 비용까지 포함한 보편적 우월성은 입증하지 않았다.
