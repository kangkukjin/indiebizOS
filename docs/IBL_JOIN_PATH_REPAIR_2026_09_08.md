## 직접 입력 join

실행기 `_op_join`은 `left/right` 직접 입력을 파이프보다 우선하지만, T1 머리·T2 이음매 검사는
`items` 파라미터만 인정했다. 열·통화 검사도 두 입력을 읽지 않았다. 합성 키나 할당 여부의
문제가 아니라 실행기와 검사기의 입력 계약 불일치다. 과거 한 호출만 통과한 정확한 실행
분기는 이번 수리에서 확정하지 않았다.

사전의 `flow.input_params: [left, right]`를 세 검사 경로가 함께 소비한다. 두 슬롯이 모두
non-null이면 입력 묶음으로 검사하고, 한쪽 누락은 면제하지 않는다. 특정 액션 이름을 검사기에
넣지 않는다. 직접 입력의 열은 하류 검사에도 전달된다. 구체 계약은
`docs/IBL_STATIC_TYPECHECK_HANDOFF.md`의 2026-09-08 절.

## 공유 파일 경로

`self:write/read`는 프로젝트 기준, `self:ledger`는 저장소 루트 기준으로 상대경로를 해석한다.
시스템 AI의 프로젝트 경로가 `data/`일 때 같은 `outputs/…`가 두 파일을 가리킨다. 이것은
기존 경로 계약이라 이번 수리에서 바꾸거나 다른 뿌리의 파일을 자동 탐색하지 않는다.

공유 파일은 양쪽에 `~workspace/outputs/…`를 쓰거나 쓰기 결과의 절대경로를 넘긴다.
카탈로그·IBL 기본 교재에 기준을 명시하고, 원장 미존재 응답은 해소된 `path`와 해결 `hint`를
반환한다. `items_file`에도 같은 저장소 기준이 적용된다.

확정할 수 없으므로 열린 열로 추론해 유효한 하류 선택을 오거절하지 않는다.
