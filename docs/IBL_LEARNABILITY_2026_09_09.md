# IBL 작성 규칙 정리

2026-09-09. 목표는 작성자가 외울 예외를 줄이는 것이다. 새로운 연산자·액션·AI 관용구를 추가하지 않았다. 기존 값 구성과 반복 블록으로 데이터 재구성을 먼저 가르치고, 검사기와 실행기가 그 표기를 같은 뜻으로 읽도록 고쳤다.

## 먼저 배우는 예제

```ibl
$상품 = [
  {id:"007", price:"3", qty:2},
  {id:"008", price:"4", qty:1}
]
$결과 = [table:each]{items:$상품} {
  $return = [{
    id:$it.id,
    label:"고정",
    total:$it.price * $it.qty,
    source:{id:$it.id},
    active:true,
    missing:null
  }]
}
```

문자열은 `"고정"`, 참조는 `$it.id`, 계산은 `$it.price * $it.qty`다. 객체 키는 `id`처럼 식별자 모양이면 따옴표를 생략한다. 특수문자 키는 문자열로 쓴다. `true/false/null`은 파라미터와 계산식에서 같은 값이다. 중복 키와 임의 코드 실행은 허용하지 않는다.

결과의 id는 `"007"`, `"008"`이고 total은 6, 4다. 복사·문자열 함수는 원형을 유지한다. 숫자 문자열은 산술 자리에 놓였을 때만 공용 숫자 규칙으로 읽는다. assign·compute·select·reduce가 이 규칙을 공유한다. 숫자를 문자열로 붙이려면 `str($값)`을 쓴다.

`each`는 행마다 같은 본문을 실행하고 반환한 목록을 합친다. `$return=[]`이면 그 행에서 0개를 보낸다. 입력이 파이프로 오고 옵션이 없으면 `[table:each] { ... }`라고 쓴다. 기본 처리 상한은 기존대로 20행이며, 더 많이 처리하려면 `limit`을 지정한다. 목록·객체·괄호 안은 여러 줄로 배치하고 `>>`, `&`, `??`, `| take: 1` 같은 연결 표기도 줄을 나눌 수 있다.

기존 `select{columns:{...}}`와 `compute{set:{...}}`의 문자열 식 슬롯은 계속 지원한다. 그 자리는 문자열을 식으로 해석하므로 문자열 상수의 안쪽 인용이 필요하다. 처음 배우는 재구성에는 위의 일반 값 구성을 사용하면 된다. 모든 고급 표기를 동시에 배울 필요가 없다.

## 원문은 원문대로 저장한다

```ibl
$자막 >> [self:write]{path:"~workspace/transcript.json",format:"json"}
[self:struct]{file:"~workspace/transcript.json",
  grounded:true, schema:"tip(실행형 제목), timestamp(MM:SS)"}
```

앞에서 얻은 `$자막`의 구간 목록과 transcript/text/content, 언어·출처·시간 정보를 함께 보존한다. 긴 자막의 외부 파일도 전문을 읽어 JSON에 넣는다. 저장 뒤 캐시 파일이 삭제돼도 `struct{file}` 또는 `read >> struct`로 같은 원문을 읽을 수 있다. 실행 경고·내부 진단은 다음 실행에 재전파하지 않는다. 임의의 items 목록을 원문으로 추측하지 않는다.

원문 파일·스필 참조가 없으면 미리보기를 전문 대신 쓰지 않고 실패한다. struct 입력 상한 60,000자를 넘는 경우도 일부만 처리하지 않고 나눠 처리하도록 안내한다. 상한 자체를 늘리거나 추가 AI 호출로 자동 복구하지 않는다.

## 결과 필드는 한 설명을 공유한다

```ibl
[table:ai]{items:[{id:"007",title:"예제"}],
  instruction:"각 행의 선정 여부와 이유를 추가한다",
  schema:"selected(불리언), reason(선정 이유)"}
>> [table:select]{columns:["id","selected","reason"]}
```

struct의 기존 `schema`와 ai의 선택적 `schema`를 같은 계약으로 읽는다. `필드(설명), 다른필드(설명)`처럼 이름이 명시된 목록은 실행 전 열 추론과 실행 후 누락 검사에 함께 쓴다. 괄호 안 쉼표는 설명의 일부다. 자유 주제 라벨(`finance` 등)과 모호한 산문은 종전처럼 모델에게 전달하고 필드 이름을 추측하지 않는다.

새 검사는 **필드 이름의 존재**를 확인한다. null은 허용하며 불리언 타입·내용의 정확성·행 개수·원문 근거를 보증하지 않는다. 이 의미 검사는 기존 instruction·grounded·criteria가 맡는다. ai의 색인 병합 뒤 검사하므로 원래 있던 필드를 모델에게 다시 출력하게 하지 않는다. 필드 누락은 `error_type:"schema"`로 실패하며 검사 자체는 AI를 호출하지 않는다.

## 서로 다른 열 이름을 한 이름으로 받기

```ibl
[{파일:"a.txt"}]
>> [table:rename]{map:{파일:"file",path:"file"}}
>> [table:select]{columns:["file"]}
```

같은 새 이름을 가리키는 옛 이름들은 후보 집합이다. 위 문장은 `파일` 또는 `path` 중 입력 전체에 있는 한 열을 `file`로 바꾼다. 후보가 없거나 둘 이상이면 오류다. 행마다 `파일`과 `path`가 섞여 있어도 두 열이 관측되므로 오류이며, 우선순위 선택이나 행별 합치기를 하지 않는다. 단일 옛 이름의 부재와 기존 열 덮어쓰기도 오류다. 관측 열 없는 빈 items는 판정을 유보한다. 명시 table은 0행이어도 columns가 있으면 그 열로 판정한다.

리터럴·직접 items·select 결과의 확정 열과, 검색 카탈로그에서 관측한 열은 구분한다. 정적 검사기는 후보를 묶어 검사하며, 확정된 위반은 오류, 관측 열에서 의심되는 위반은 경고, 동적 지도나 열 미상 입력은 실행 때 판정한다. 위 예제처럼 실제 후보가 하나이면 나머지 후보가 없다는 이유로 거절하지 않는다.

## 구현과 검증 범위

- 공용 식 평가기가 키·리터럴·수치 관측을 소유한다. each와 직접 items 입력은 값 반환 봉투를 공용 경계에서 해제한다.
- 각 코드 본문은 같은 IR로 실행·검수한다. 검수 목적으로 외부 참조를 숫자 1로 치환하던 우회를 제거했다. 블록의 지역 슬롯과 바깥 변수 타입도 분리했다.
- 필드 계약은 사전의 `schema_param` 메타데이터로 연결한다. 검사기 코드에 내용어 이름을 넣지 않는다.
- [회귀 시험](../backend/test_ibl_learnability.py)은 실제 IBL 엔진의 값·반복·배치, 코드 IR 왕복, 검수와 실행의 일치, 실제 파일 쓰기·읽기·캐시 삭제, 원샷 스텁으로 필드 누락을 검사한다. 외부 검색과 유료 모델을 호출하지 않는다.
- 전체 백엔드 회귀: 3,161 통과, 2 건너뜀. 앱 `/ibl/validate` HTTP 200, 보고서 구문·정적 검사 오류/경고 0.
- [보고서 예제](experiments/ibl_learnability_2026_09_09/README.md)는 문법·정적 검사만 한다. 길이는 거의 같지만 원문 직렬화와 이중 인용을 요구하는 구조 투영을 줄였다. 실제 보고서 품질·시간·토큰과 초보자 학습 시간은 이번 변경에서 측정하지 않았다.

변경 전 정상 입력에서 숫자처럼 생긴 문자열이 복사 과정에 숫자로 바뀌던 동작은 달라진다. 명시된 schema 필드를 누락한 모델 출력과 너무 긴 원문은 이제 실패하므로, 이전의 조용한 품질 손실이 실행 오류로 드러날 수 있다.
