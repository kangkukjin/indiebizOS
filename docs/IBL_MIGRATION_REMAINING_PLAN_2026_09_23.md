# IBL 전환 잔여 작업 계획

상태: **1~4단계 구현·정본 반영 완료. 5단계 Mac 실행 확인·PC 도우미 4종·소유자 Android APK 준비 완료. 소유자 Android 실기기 설치는 연결 대기.**
구현·검증·설치 상태는 [배포 기록](IBL_MIGRATION_RELEASE_2026_09_23.md)을 따른다. 아래 근거는 작업 전 조사 기록이다.
조사 기준: 정본 main `ae708f9b`, 2026-09-23.
목적: [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)의 정확한 작성·재사용·완료 비용 개선.
이번 계획에는 모델 비교, 상상훈련, 대규모 코퍼스 재학습을 넣지 않는다. 사용하면서 성과를 확인하되,
변경한 계약의 회귀 검사와 빌드 검증은 구현 완료 조건으로 유지한다.

## 판단

핵심 값·함수·제어 문법을 다시 설계할 단계는 아니다. 현재 의미론 위에서 **작성 → 검사 → 저장 →
호출 → 예약 실행 → 재사용**이 같은 계약을 따르게 만드는 것이 우선이다.
앞선 완료 보고의 “기기 업데이트가 남았다”는 설명만으로는 현재 잔여 범위를 충분히 설명하지 못한다.
주 교재와 주인/회원 모델 도구는 전환했지만 일부 작성 표면·운영 호출자·저장 교재·학습 경로가 남아 있다.

## 1순위 — 새로 만드는 코드의 전 경로를 하나로 연결

하나의 작업 단위로 작성 표면, 교재, 저장·실행 호출자를 함께 바꾼다.

- 번역 결과에서는 바깥 코드 펜스만 제거하고 원문·헤더·마지막 식을 보존한다.
  설명이 섞인 응답을 정규식으로 잘라 실행하지 않고 실제 파서의 진단으로 돌려준다.
- 조종실과 body_ask는 새 작성임을 명시하고 `code/edition/inputs`를 검사부터 실행까지 보존한다.
  새 검사 응답의 valid/incomplete/invalid, 오류 위치와 효과를 화면에 표시한다.
  실행 HTTP 성공과 프로그램 success를 구분해 기록한다.
- 작업별 상세 계약 주입도 공통 작성 판본을 사용한다. `workflow.md`, 사전 설명,
  핸들러 도움말을 현재의 명시 인자·값 반환·저장 예제로 동시에 교체한다.
  과거 업무 사례의 원문과 실행 실적은 보존하고, 현재 작성법을 가르치는 경로만 교정한다.
- 저장 함수 실행은 저장 메타데이터를 읽는 공통 진입점으로 보낸다. 매 호출자가 판본을 다시 고르지 않게 한다.
  스케줄·트리거·앱의 신규 코드 저장은 의미를 명시적으로 고정하고, 새/기존 저장본을 같은 진입점에서 해소한다.
  기존 무표기 저장본은 예전 의미를 유지한다. HTTP 생략 기본값만 일괄 변경하는 방식은 쓰지 않는다.
- 주체·프로젝트·허용 노드·예약 출처를 새 실행기로 그대로 전달한다. 폰의 직접 스케줄도 같은 계약을 쓴다.

**완료 조건:** 새 프로그램의 번역 원문, 조종실 검사·실행, 저장 후 이름 호출, 예약 직접 실행이
같은 입력에서 같은 값·실패 의미를 갖는다. 기존 저장 앱·스케줄은 회귀가 없다.
Frontend TypeScript 검사와 변경 표면의 회귀 검사를 수행한다. 별도 신판 안내 교재는 만들지 않는다.

## 2순위 — 자주 연결하는 도구의 계약을 실행 전 검사 가능하게 만들기

전 사전 168개를 일괄 수작업 변환하지 않는다. 첫 묶음은 `self:edit`, `self:grep`,
`sense:search`, `sense:crawl`로 정한다. 기존 코퍼스의 최근 관측 순 서로 다른 프로그램 300개에서
각각 64/15/17/16개에 나타났다. 이는 프로그램 내 포함 빈도이며 전체 호출 수나 성능 실험 결과가 아니다.
이 도구들은 파일 수정·검색·자료 수집의 공통 연결부라 여러 업무에 영향을 준다.

- 기존 YAML을 정본으로 필수 인자, 타입, 반환 필드, 외부 읽기/쓰기 효과, 확인 가능한 쓰기 자원을 선언한다.
- op/source에 따라 계약이 달라지면 데이터로 분기를 선언한다. 파서에 개별 도구 이름을 추가하지 않는다.
- 검색 결과에서 후속 프로그램이 쓸 필드를 보장하고, 부분 원천·0건·권한 실패를 구분한다.
  기존 전체 결과와 근거를 보존하며 근거 없이 items/text만 추출하거나 반환 모양을 바꾸지 않는다.
- describe, 컴파일러, 실행 경계 검사가 같은 계약을 소비하게 한다.
  사용자 데이터의 가변 필드는 Unknown으로 남기되 확정 가능한 오류까지 Unknown에 묻지 않는다.
- 저장 함수도 본문을 펼치지 않고 입력·반환·효과·미확정 경계를 조회할 수 있게 한다.
  컴파일러의 현재 추론을 사용하며 별도 추정기를 만들지 않는다.

**완료 조건:** 첫 묶음의 잘못된 인자·필드 연결과 확인 가능한 병렬 쓰기 충돌을 효과 전에 거절하고,
정상 0/1/N건 및 부분 실패 결과는 기존 실행 의미를 유지한다. 해당 YAML·도움말·교재·파생물을 함께 갱신한다.
AI 도구나 나머지 사전 정밀화는 이 묶음 뒤에 실제 공통 필요가 있는 것만 추가한다.

## 3순위 — 입력을 분리한 성공 프로그램이 관용구로 축적되게 만들기

현재의 inputs 제외는 개인 입력을 학습 본문에 박아 넣지 않으려는 보호다. 이를 단순 제거하지 않는다.

- 성공한 실행의 소스와 명시 입력 이름으로 함수 후보를 추출한다. AST를 이용해 입력 이름을
  함수 인자로 닫고 기존 반환·제어·효과 순서를 보존한다. 실제 개인 입력값은 함수 본문에 넣지 않는다.
- 이미 선언된 함수와 그 호출 관계를 우선 보존한다. 임의의 상수를 일반화하거나 여러 실행을
  문자열로 합치지 않는다. 자동으로 닫을 수 없는 경우에는 원 실행 기록과 제외 이유를 남긴다.
- 기존 증류의 선택·작명 호출을 재사용한다. 새 상시 모델 호출을 추가하지 않는다.
  원문 동일성만 확인하던 새 언어 저장 관문은 허용된 AST 변환과 출처를 검증하게 보완한다.
- 추출 후보, 원 실행 성공, 저장 함수의 후속 호출 실적을 구분한다.
  함수로 포장한 것만으로 새로운 입력에 검증됐다고 기록하지 않는다.
- 이름·입력·반환·효과·참조 정의·원 실행 출처를 저장/회상/호출에서 일관되게 제공한다.
  변경 대상은 학습 입구와 재사용 연결이며 기존 코퍼스 전체의 재작성은 하지 않는다.

**완료 조건:** 명시 inputs가 있는 성공 프로그램을 개인값 없는 함수로 저장하고,
다른 입력과 다른 함수에서 다시 호출할 수 있다. 자유 변수·개인값 유출·출처 없는 효과 추가는 거절한다.
현재의 `add_examples_batch` 등 원장 입구를 유지한다.

## 4순위 — 사전이 성장해도 재개 기록을 운영할 수 있게 만들기

- 계획의 의존성을 실제 참조한 함수·하위 함수·액션·스크립트의 전이적 집합으로 제한한다.
  호출 해소 순서와 이름 충돌을 함께 검증하고, 런타임 의미론/권한 변경은 계속 재개를 막는다.
  동적 디스패치는 증명 가능한 선언 경계까지 보수적으로 포함한다.
- 실행 기록에 생성/종료 시각, 완료·중단·불명·정리 차단 상태를 남긴다.
  기존 주행기록/회수 경로에서 실행 핸들과 마지막 확인 지점을 조회할 수 있게 연결한다.
- 완료 기록의 보존 기간·용량 정책을 명시하고 기존 상태 관리에 정리 기능을 붙인다.
  진행 중·잠긴 기록과 결과 불명 작업은 자동 삭제하지 않는다. 정리된 핸들은 재개 불가임을 분명히 알린다.
  큰 결과는 안전한 원문 참조와 영수증의 수명을 맞춘다. 용량을 맞추려고 결과를 잘라 저장하지 않는다.
- 불명 효과는 외부 영수증을 확인하는 대상으로 유지한다. 같은 요청의 맹목 재전송이나
  “완료로 간주” 버튼으로 바꾸지 않는다. 회원 기록은 현재 사적 세션 수명을 유지한다.

**완료 조건:** 미사용 관용구 추가는 기존 재개를 깨지 않고, 실제 의존 정의 변경은 재개를 막는다.
완료 기록 정리는 가능하되 실행 중·결과 불명 상태의 안전성과 회원 데이터 수명이 유지된다.

## 5순위 — 대상별 배포 마무리

1. 소유자 Mac: 위 변경을 정본 main에 반영하고 관리 재시작으로 실제 실행 코드를 확인한다.
2. PC 회원: 기존 재다운로드/설치 경로로 현재 helper를 제공한다. 능력 협상 실패 시 업데이트가
   필요한 프로그램을 구체적으로 안내한다. 이번 일만을 위해 새 자동 업데이트 시스템을 만들지 않는다.
3. 소유자 Android `:app`: 새 엔진·라우트·filelock 의존성이 든 APK를 빌드하고 설치 가능한 대상에 배포한다.
   사용자가 기기를 연결해야 한다면 설치 파일과 절차를 먼저 완성하고 그 물리 단계만 남긴다.
4. Android 회원 `:member`: 로컬 인터프리터가 없는 현재 제품 계약을 유지한다.
   새 IBL 작성은 허브에서 동작하지만 로컬 Python/Bash/Node 실행까지 지원한다고 표시하지 않는다.

**완료 조건:** 코드·배포 파일·설치된 대상의 능력을 각각 구분하여 기록한다.
설치 확인과 프로토콜 연결 검사는 필요하지만 모델 성능 비교를 출시 조건으로 두지 않는다.

## 순서와 이번 범위의 끝

구현 순서: **1 → 2 → 3 → 4**, 이후 최신 결과를 묶어 **5**에서 대상별 배포한다.
각 묶음은 정본 반영과 필요한 회귀 검사까지 마친 뒤 다음으로 진행한다.
기기 연결을 기다리는 동안 앞선 코드 작업을 멈출 필요는 없다.

이번 계획에서 미루는 것은 일반 IDE/LSP, 정밀 행별 lineage, 전 코퍼스 자동 번역,
두 파서의 전면 통합, 일반 재귀·성능 캐시, 새 script wire의 background 및 오프라인 푸시 큐다.
이들은 현재 작성·축적 경로를 닫는 전제가 아니다. 새 wire background와 푸시 큐를 나중에 지원할 때는
별도 작업 핸들·중복 방지·완료 조회 계약으로 다뤄야 하며 구형 경로로 몰래 우회하지 않는다.

완료의 의미는 구형 자료가 사라졌다는 것이 아니라, **새로 작성하고 저장하는 경로는 현재 언어로
연결되고, 과거 자료의 호환 실행은 원문 의미 보존을 위해 명시된 경계 안에 남는 것**이다.
