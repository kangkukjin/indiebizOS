# 조건 선별과 표본 절단의 구분 — 2026-09-08

부동산 보고서 ep3090의 진단을 코드·궤적과 대조했다. 원장 조회 뒤 조건으로
70행을 25행으로 줄인 자리는 `_restate_scope`가 상류 `total:70`을 유지하며
`truncated:true`를 만든 결함이었다. 원장 `select`는 limit을 주지 않으면
전량 반환한다. 기존 P23 회귀도 잘못된 선별 의미를 정답으로 고정하고 있었다.

## 봉투 의미 개정

| 변환 | total | truncated |
|---|---|---|
| filter·dedup·groupby·since·flatten·중복 제거 merge | 기존 값이 있으면 새 결과 행수 | 선별 자체로 켜지 않음, 실제 상류 표지는 보존 |
| take·원천 limit | 표본을 뽑은 집합의 기수 유지 | 일부 반환이면 신고 |
| sort·select 등 행 보존 | 유지 | 유지 |

`total` 없는 봉투에는 추정치를 만들지 않는다. 불완전한 입력에서 집합을
다시 만들면 `total == count`와 `truncated:true`가 공존할 수 있다. 전자는
관측된 결과의 기수이고 후자는 원천 누락이 복구되지 않았다는 뜻이다.
집합을 재정의하면 낡은 summary를 제거하며, 0행 groupby도 상류 표지를 보존한다.
중앙 방출 함수의 옵션으로 구현해 표형 입력과 items 입력에 같은 뜻을 적용한다.

경고문도 절단 위치에 따른 처방으로 바꿨다. 원천 누락은 원천 조회를 나눠
복구하고, 전달 메시지만 잘렸으면 저장된 변수·파일을 읽는다. 요청한 상위 N개
표본은 추가 수집을 요구하지 않는다. 하류 필터가 없는 원천을 복구할 수는 없다.

## 리터럴 표의 직행 경로

해당 궤적의 `each{items:…, do:"[self:time]"}`는 결과를 쓰지 않는 동작으로
리터럴 행을 흘려보냈다. passthrough 표지는 정직했지만 실행은 불필요했다.
기존 `compute{items:…, set:…}`로 곧바로 계산할 수 있다. 기본 프롬프트,
부동산 가이드와 IBL 명세에 이 경로를 적었다. 새 어휘는 추가하지 않았다.
