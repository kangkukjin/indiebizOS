## 0. 실측 — 지금의 IBL 은 어디까지 언어인가

프로그래밍 언어의 뼈대를 기준으로 현재(액션 150, 2026-08-21 밤) 상태를 정직하게 적는다.
"있음"은 *쓰이고 검증된* 것만, "△"는 있으나 반쪽, "✗"는 없음.

| 뼈대 | 상태 | 지금 모습 · 근거 |
|---|---|---|
| 순차 `>>` · 병렬 `&` · 폴백 `??` · 독립 `;` | ✅ | `ibl_parser.py`. `??` 의 가지는 **단일 액션만**, `&`·`??` 혼용 금지(2026-08-05) |
| 변수 `$x = …` · `$x.필드` · `$file:N` | ✅ | `workflow_engine.py` D4(2026-08-05). 미할당 `$var`=호출자 params 주입 자리 |
| 분기 `[if:]`·`[else if:]`·`[else]`·`[case:]` | △ | `ibl_parser_blocks.py`. 분기 **몸통엔 어떤 액션이든** 온다. 그러나 **조건은 `node:action{…}.field <op> 값` 한 형태** — `_evaluate_condition_and_value`(ibl_executors ~1061): 좌변=액션 실행 결과의 필드 경로, 연산자 6개(`== != > >= < <=`), 우변=리터럴. **변수 좌변 불가, 건수·비어있음·존재·정규식·논리 결합(and/or) 불가, AI 판단 불가** |
| map `[table:each]{items\|파이프, do, as, limit, on_error}` | ✅ | 2026-08-15 고차 문장. 행별 `_ok/_error/_result`, `on_error: continue\|stop` |
| **반복 (until / n회 / while)** | ✗ | `[goal:]` 은 **스케줄러 라운드**(every·max_rounds·until·deadline — `goal_evaluator.py`)라 문장 *안*의 루프가 아니고, success_condition 은 **AI 평가 프롬프트**(결정론 아님) |
| **reduce / 누적 / 상태 전달** | ✗ | groupby 는 고정 집계 5종뿐. "행을 돌며 값을 모아 다음 행에 넘긴다"가 없음 |
| 함수·서브루틴 | △ | `[self:workflow]{op:"run", name, params}` — 호출·파라미터 주입 됨. 반환은 **몸통 마지막 문장의 items 만**(effect 로 끝나면 통화 없음). 재귀 깊이 추적은 있음(`depth`) |
| **오류 처리** | ✗ | `>>` 는 한 step 실패 = 문장 전체 실패(`steps_completed/steps_total` 신고). 부분 계속·대체·정리(finally) 없음. `??` 는 *단일 액션* 대체뿐 |
| **스필 (중간 결과를 밖에 내리고 참조만 흘리기)** | △ | `[self:write]` 는 파이프 싱크로 동작(content 생략 시 `_prev_result` 저장)하나 **뒤에도 통화가 그대로 따라감** — write 가 "내렸다"는 사실이 파이프를 가볍게 만들지 않는다. `[self:read]` 로 재개하는 관용구 없음 |
| 파생 열 계산 | ✅ | `[table:compute]` (2026-08-21, `1a8c314`) |
| 긴 작업 핸들 | ✅ | `[self:script]{run, background}` → `{status, job_id, wait}` (2026-08-21) |
| 반환 모양 가시성 | ✅ | 카탈로그 `⟨열: …⟩` (2026-08-21, `4866609`) |
| 실행 가시성 (어느 step 에서 왜) | △ | 봉투 `results[]`·`steps_completed` 있음. **긴 문장의 "여기서부터 재개"** 없음 |
| 시간·트리거 | ✅ | `[self:trigger]`·`[self:schedule]`·`[table:since]` |

한 줄 요약: **지금 IBL 은 "파이프라인 + map + 값 분기" 언어다.** 파이썬으로 치면 `a \| b \| c`, 리스트 컴프리헨션, 단순 `if` 까지. `while`·`try`·누적·함수 반환값이 없다.

### 0.1 왜 이것이 지금 드러났나
08-21 진단에서 조합이 안 일어난 1차 원인은 언어가 아니라 교재 조항·코퍼스였고 그건 수리됐다(`a473151` ~ `4866609`).
그러나 그 뒤 "모델이 완벽히 쓴다고 가정해도 남는 것"을 세니 위 표가 나왔다. 조합률이 오르기 시작하면 모델은 곧
이 벽에 부딪힌다 — `?? ` 가지에 파이프를 넣으려다 거절, 조건에 `$var` 를 쓰려다 거절, 3단 파이프가 2단에서 죽어
전부 다시. **지금 고치지 않으면 "조합하라"는 교재와 "조합하면 죽는다"는 경험이 충돌해 다시 단일 호출로 퇴행한다.**

## 1. 목표와 원칙

**목표**: 한 문장 = 한 프로그램. 수집→판단→분기→반복→누적→산출이 **한 `execute_ibl` 호출**로 끝나고,
중간에 모델 컨텍스트를 거치지 않으며, 실패하면 *어디서 왜* 가 정직하게 남고 *거기서부터* 다시 돌 수 있다.

**원칙** (전부 기존 헌법의 연장):
1. **표준만 늘린다, 사전은 안 늘린다.** §2 의 모든 것은 문법 또는 기능어(`table`·`self`) — 내용어 0개.
2. **반-어휘-증식 시험을 문법에도 적용한다.** 각 항목은 "왜 `[self:script]` 가 아니라 문법이어야 하는가"에 답해야 한다.
   답 = *다른 문장과 조합되어야 하는 것*(분기·반복·오류처리는 문장을 감싸므로 스크립트 안에 가둘 수 없다) /
   답 못 하면 script 로 보낸다(§3).
3. **통화 하나**(`{items:[…]}`)는 불변. 새 제어 구조도 통화를 받고 통화를 낸다. 스칼라는 `$변수` 로만 산다.
4. **판정 불능 ≠ 거짓**(B8 부류). 새 술어·루프 종료 조건도 "못 읽음"을 거짓으로 접지 않는다.
5. **침묵 클램프 금지**. 반복 상한·스필 크기 상한은 신고한다.
6. **파서는 이름-무검증** 유지. 제어 키워드(`if/case/goal/repeat/try/...`)는 **예약어**로 헌법에 명시한다.
7. **원샷 낱말은 술어·압축기로 쓴다.** 긴 입력 문제의 답은 문법이 아니라 `table:ai`(압축)·`table:brief`(판정)·스필(외부화)의 조합이다 — 사용자 판정(08-21).

## 2. 개정안 — 다섯 개

각 항목: 문법 → 의미 → 실패 규약 → "왜 script 가 아닌가" → 비용 → 집행 위치.

### 2.1 술어 확장 — 조건이 *데이터 비교* 를 넘어서게

**지금**: `[if: sense:host{op:"status"}.cpu_percent > 80]`. 좌변은 반드시 액션 실행, 연산자 6개, 우변 리터럴.

**개정**:
```
[if: $검색.count > 0]                          # 변수 좌변 (실행 없이 이미 가진 값)
[if: empty($검색)]  [if: exists($x.url)]       # 통화 술어: empty / exists / count()
[if: $r.title matches "속보|긴급"]              # 정규식
[if: $a.price > 100 and $a.stock != 0]        # and / or / not (우선순위: not > and > or, 괄호 허용)
[if: [table:brief]{instruction: "이 기사들이 청주 부동산과 직접 관련 있으면 yes, 아니면 no"} == "yes"]
                                               # AI 술어 — 원샷 낱말이 조건값이 된다
```
- 좌변 문법 = `$변수[.경로]` | `node:action{…}[.경로]` | `count($x)` `empty($x)` `exists($x.경로)` | 원샷 낱말 호출.
- AI 술어는 **`message` 를 좌변값으로** 쓴다(brief 의 계약). 비용 고지는 dry-run 이 이미 `ai_call` 플래그로 한다.
- **실패 규약**: 좌변 읽기 실패 = 기존대로 `condition_errors` (거짓으로 접지 않음). AI 술어가 yes/no 밖을 내면 판정 불능.
- **왜 문법인가**: 조건은 문장을 *감싼다*. 스크립트 안에 넣으면 분기 양쪽의 IBL 문장을 스크립트가 다시 불러야 한다(층 역전).
- **비용**: `_evaluate_condition_and_value` 교체(작은 식 파서 — `table:compute` 의 ast 화이트리스트 재사용 가능). 교재 §블록 갱신. 코퍼스 시드(조건 10~20건).
- **위치**: `ibl_executors.py` 조건 평가기 + `ibl_parser_blocks.py`(괄호·and/or 토큰) + ibl.md 문법 1항.

### 2.2 반복 — `[repeat:]`

**지금**: 없음. `[goal:]` 은 스케줄러(분 단위 라운드, AI 평가 종료)라 "이 문장 안에서 조건 될 때까지" 가 아니다.

**개정**:
```
[repeat: until $st.status == "done", max: 30, every: "10s"]{
  $st = [self:script]{op: "status", job_id: "$job"}
}
[repeat: 5]{ … }                               # 고정 횟수 (반복 인덱스 $i)
[repeat: while count($queue) > 0, max: 100]{ … }
```
- 의미: 몸통을 `>>` 파이프/문장 묶음으로 실행, 매 회 종료 조건(2.1 술어) 평가. `max` **필수**(상한 없는 루프 금지), `every` 선택(휴지).
- 통화: 마지막 회차의 items (또는 `collect: true` 면 전 회차 items 를 이어붙인 items — 2.3 과 연결).
- **실패 규약**: `max` 도달 = `halted: "max"` 정직 신고(성공 아님·실패 아님 — 통화는 냄). 조건 판정 불능 = 즉시 중단 + `condition_errors`. 몸통 step 실패 = 2.4 의 규약을 따름(기본 stop).
- **왜 문법인가**: 반복 몸통은 IBL 문장이다. `[self:script]{status, wait}` 같은 *한 액션 안의 대기*는 이미 있고 그걸로 충분한 경우(단일 작업 기다리기)는 많다 — 그래서 `repeat` 의 정당성은 **몸통이 여러 액션으로 이뤄진 반복**(수집→판단→다시 수집)에만 있다. 단일 액션 반복이면 `each` 나 액션 자체의 `wait` 를 쓰라고 교재가 말해야 한다.
- **`goal` 과의 관계**: `goal` = 세션 밖(시간·스케줄러·AI 판정), `repeat` = 문장 안(즉시·결정론 종료). 둘을 합치지 않는다 — 합치면 한 키워드가 두 실행 모델을 나른다.
- **비용**: 파서 블록 1개 + 실행기(깊이 +1 재귀, each 선례) + 상한·휴지 + dry-run 검수(몸통 부작용 전파). 중간 크기.
- **위치**: `ibl_parser_blocks.py`, `ibl_executors.py`(each 옆), ibl.md.

### 2.3 누적 — `[table:reduce]` 와 `collect`

**지금**: 행→행(compute·each), 행→집계(groupby 고정 5종)만. "행을 순회하며 상태를 넘기는" 길 없음.

**개정** (두 층):
1. **`collect`** — `each`/`repeat` 의 옵션. 회차 결과를 이어붙여 하나의 items 로(= flatten 내장). 대부분의 "누적"은 이것으로 끝난다(수집 루프의 결과 모으기).
2. **`[table:reduce]{init, step, as}`** — 진짜 fold. `step` 은 **compute 식**(2.1 의 식 언어와 동일): `[table:reduce]{init: 0, step: "acc + 보증금", as: "총보증금"}` → 스칼라를 `message`/`value` 로 내고 `$변수` 로 받는다.
- **왜 문법/기능어인가**: `collect` 는 제어 구조의 옵션이라 문법. `reduce` 는 **경계선** 이다 — 식이 한 줄인 누적(합·최대·문자열 이어붙이기)은 기능어가 맞지만, 상태가 dict 이고 분기가 있는 누적은 `[self:script]` 가 이긴다. **판정**: `reduce` 는 식 한 줄만 허용(ast 화이트리스트), 그 이상은 명시 거절 + script 안내. 이 선을 넘는 순간 IBL 이 파이썬을 재발명한다.
- **비용**: collect=작음. reduce=작음(compute 평가기 재사용).

### 2.4 오류 처리 — `[try:]`/`[catch]` 와 `>>` 의 `on_error`

**지금**: step 실패 = 문장 사망. `??` 는 단일 액션 대체. 정리(finally)·부분 계속 없음.

**개정**:
```
[try]{ [sense:crawl]{url: "$u"} >> [self:struct]{schema: "…"} }
[catch]{ [sense:search]{source: "naver", query: "$u"} }       # $error 바인딩(step·action·error·_prev_result)
[finally]{ [self:notify_user]{message: "수집 시도 끝: $error.summary"} }
```
- 파이프 수준: `>>` 에 문장 옵션 `{on_error: stop|skip|null}` — `skip` = 실패 step 을 건너뛰고 **직전 통화로** 다음 step, `null` = 빈 items 로 계속. 기본은 **stop**(지금과 동일 — 조용한 계속은 B8).
- `??` 가지 제한(단일 액션) 해제 — **괄호 파이프 허용**(`A ?? (B >> C)`): 병렬 괄호 분기(2026-08-19) 와 같은 규칙·같은 파서 경로.
- **실패 규약**: catch 도 실패하면 원 오류 + catch 오류 둘 다 봉투에(덮어쓰기 금지). finally 는 결과를 바꾸지 않는다(통화는 try/catch 의 것).
- **왜 문법인가**: 오류 처리는 문장을 감싼다. script 안에 넣으면 IBL 문장이 script 의 인자가 된다(고차 문장 설계가 금지한 "코드 문자열이 파라미터 층을 지나는" 모양).
- **비용**: 파서 블록 1 + 실행기 + `$error` 바인딩 + `??` 괄호(파서 분기 재사용). 중간.

### 2.5 스필 — 통화 대신 *참조* 를 흘리기

**지금**: `A >> [self:write]{path} >> B` 에서 B 는 여전히 A 의 전체 통화를 받는다. 문장이 길수록 봉투가 커지고,
**모든 step 결과가 모델 컨텍스트로 돌아온다**(`results[]`). 긴 입력 문제의 절반은 여기서 난다.

**개정**:
1. **스필 싱크**: `[self:write]{path, spill: true}` — 뒤에는 `{items: [], ref: {path, kind: "items", count, bytes}}` 만 흐른다. 다음 step 이 items 가 필요하면 `[self:read]{path: "$ref.path"}` 로 재개(결정론). 기본 `spill: false`(현행 유지).
2. **봉투 다이어트**: `execute_ibl` 응답의 `results[]` 는 step 별 **요약**(shape·count·bytes·첫 행) + `final_result` 만 기본. 전체는 `verbose: true` 또는 `[self:body]{op:"writes"}`/실행 원장에서. (※ 이건 언어가 아니라 **하네스 이음매** 변경 — `execute_ibl` 하나라 헌법 위반 아님.)
3. **자동 스필 임계**: 통화 바이트가 임계(예 200KB)를 넘으면 엔진이 `data/spill/<task>/<step>.json` 으로 내리고 `ref` 로 바꾼 뒤 **신고**(침묵 금지). 소비 step 이 `ref` 를 받으면 투명하게 읽는다(변환자 `_get_items` 에 ref 해소 한 줄).
- **왜 문법/엔진인가**: 크기는 문장이 모르는 런타임 사실이다. 엔진만 안다.
- **비용**: 1=작음(write 옵션+통화 규약). 2=중간(응답 모양 변경 — MCP 브리지·조종실 소비자 확인). 3=중간(변환자 `_get_items` 의 ref 해소 + 정리 정책: `data/spill` 은 소유 선언에 `cache`, 24h 삭제 후보).
- **2번이 가장 큰 레버다**: 08-21 실측에서 에피소드당 IBL 47회의 결과가 전부 컨텍스트에 쌓였다. 요약만 돌려주면 같은 47회가 절반 이하의 토큰이다 — 조합과 무관하게 즉시 효과.

### 2.6 (부속) 실행 가시성 — 재개 지점
긴 문장이 7단에서 죽으면 1~6단을 다시 돌리지 않게: 실패 봉투에 `resume: {from_step: 7, prev_ref: …}` 를 싣고(2.5 의 스필을 자동 사용),
`execute_ibl(code, resume=…)` 로 그 지점부터. 이건 2.5 위에 얹는 것이라 마지막.

## 3. 문법으로 만들지 *않을* 것 — script 의 자리

반-증식 시험을 통과 못 한 것들. 교재가 **명시적으로** script 로 보내야 모델이 문법을 찾다 실패하지 않는다.
- 상태가 dict/리스트이고 분기가 섞인 누적(파서·상태기계) → `[self:script]`
- 외부 라이브러리가 필요한 계산(통계·이미지·오디오) → script (`self:install_lib` + register)
- 문자열 포매팅 언어(템플릿 엔진) → 없음. 산문은 `table:brief`/`table:document`, 값 삽입은 `$변수` 까지.
- 사용자 정의 함수 *정의* 문법(`def`) → 없음. `[self:workflow]{save}` 가 그 자리(이름 붙은 문장). 다만 **반환 규약**(2.3 과 함께: 마지막 items 또는 `$return` 변수)은 보강한다.
- 타입 시스템 → 없음. 통화 하나·스칼라는 변수. `⟨열⟩` 가 실질적 타입 힌트.

## 4. 집행 순서 (마일스톤)

값싸고 효과 큰 순. 각 M 은 독립 커밋·배터리·교재·시드·헌법 줄 갱신을 포함한다.

| M | 내용 | 크기 | 즉시 효과 |
|---|---|---|---|
| **M1** | 2.5-2 봉투 다이어트(results 요약) + 2.5-1 `spill: true` | 중 | 모든 에피소드의 토큰 즉시 감소. 조합과 무관 |
| **M2** | 2.1 술어 확장(변수 좌변·count/empty/exists·and/or·matches·AI 술어) | 중 | `[if:]` 가 실제로 쓰이기 시작(지금 표본 1회·실패) |
| **M3** | 2.4 `??` 괄호 파이프 + `>>` on_error + `[try]/[catch]/[finally]` | 중 | 긴 문장 생존율 |
| **M4** | 2.2 `[repeat:]` + 2.3 `collect` | 중 | 수집 루프·대기 루프가 문장 안으로 |
| **M5** | 2.3 `[table:reduce]`(식 한 줄) · 2.5-3 자동 스필 · 2.6 재개 | 중 | 마무리 |

각 M 의 **완료 정의**: ①배터리(기존 `test_pipe_currency_failures.py` P1~P19 회귀 + 신규) ②dry-run 검수 경고 ③교재 `12_ibl_only.md` 절 ④ibl.md 문법 1항·"언어의 경계" 예약어 목록 ⑤`iblbuild_validators.STANDARD_CORE_NODES`/표준-코어 가드(기능어 추가 시) ⑥시드 10~20·재학습 대기열 ⑦`changelog.log` 한 줄.

**M1 을 먼저** 하는 이유: 언어 개정이 아니라 이음매 변경이라 헌법 절차가 가볍고, 효과가 가장 크고 즉시 측정된다(에피소드당 결과 토큰).

## 5. 측정 — 무엇이 바뀌면 성공인가

기준선(2026-08-16~21, 220 에피소드 · `ep_scan.py`/`analyze.py` — 세션 스크래치에 있던 것을 `scripts/ibl_composition_metrics.py` 로 옮길 것):
- 조합률 15%(파이프 83·병렬 127 / 1,363) · 연속 동일 액션 ≈700 · `??` 0 · `[if:]` 1(실패) · each 1 · `$변수` 1
- 파이프 길이 중앙값 2
- 에피소드당 IBL 호출: 보고서류 41~47

목표(M4 이후 2주 실사용):
- 조합률 ≥ 40%, 연속 동일 액션 ≤ 200, `[if:]`·`[repeat:]`·`[try]` 각 실사용 ≥ 10, 파이프 길이 중앙값 ≥ 3
- 보고서류 에피소드 IBL 호출 ≤ 20, **결과 토큰 −50%**(M1)
- 긴 문장(≥5 step) 완주율 — 지금은 측정 불가(그런 문장이 없다). M3 후 측정 시작.

실패 신호: 조합률은 오르는데 에피소드 총 토큰이 안 줄면 → 접기만 하고 스필/요약이 안 먹는 것 → M1 재점검.

## 7. 열린 질문 (사용자 판정 필요)

1. **AI 술어의 기본 기어** — 조건 판정 한 번에 고급 기어(Opus) 를 쓰면 분기마다 비용. 원샷 버킷 다이어트(`abf7aa9`, 6.5K) 로 싸졌지만, 술어는 **경량 기어 기본**이 맞지 않나(판정 품질 vs 비용).
2. **`repeat` 의 `every` 휴지 상한** — 문장 안에서 몇 분까지 기다려도 되나. `[self:script]{status, wait}` 는 240초. 문장 전체 실행 타임아웃과의 관계.
3. **봉투 다이어트의 기본값** — `results[]` 요약을 기본으로 하면 지금 결과 전체를 읽는 소비자(조종실·포털·폰)가 깨질 수 있다. 호출 플래그(`verbose`)로 가르는 게 맞나, 소비자별 기본이 맞나.
4. **스필 디렉토리 수명** — `data/spill` 24h 자동 삭제를 기계에 맡길지(지금 원칙: 실삭제=사용자 결정) — 캐시 계급이면 예외인지.
