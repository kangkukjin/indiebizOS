# IBL 호출 사이의 구조 보존과 검사·실행 정합

에피소드 3565의 여섯 실패 부류를 계기로, 실행자가 이미 확보한 자료의 열과 중첩 구조를 추측하며 수정 왕복을 만드는 경계를 수리했다. 특정 증시 보고서의 순서는 고정하지 않는다. 평가·기억 역할은 이번 변경 대상이 아니다.

## 변경

- `ibl_value_types`가 검사 형과 실제 값의 구조 추론을 소유한다. 행의 열, 바깥 봉투, 중첩 필드, 병렬 분기, 빈 결과를 구별하며 표시 문자열과 무손실 저장 형을 분리한다. 깊이·관측 예산을 넘으면 미상으로 남긴다.
- 턴 저장소는 기존 값 읽기 API를 유지하면서 값과 구조를 원자적으로 기록한다. 구형 저장은 실제 값에서 복원하며, 명시 resume는 그 값의 형을 사용한다. 재대입과 부분 성공에 새 값의 형이 따라간다. 크기 초과 재대입에서 옛 값/형이 살아남는 일도 막았다.
- `typecheck(given=...)`가 앞 호출의 형을 받는다. 병렬 봉투를 단항 변환자에 넘길 때 내부 행의 열 합집합을 쓰던 오류를 고쳤다. 실제 봉투를 읽는 select, 내부 items를 펼치는 flatten, 행을 합치는 union은 구별한다. 확정된 필드 부재만 오류이며 빈 결과·미상·원천 행 복구 가능성은 거절하지 않는다.
- 여섯 문장의 실제 `fields` 인자를 재생하면서 추가 원인을 확인했다. 실행기는 select의 columns/cols/fields를 읽지만 검사기는 columns만 보았다. 사전의 `flow.columns_param_aliases`로 같은 우선순위를 선언했다. compute도 같은 방식으로 반환 열을 이어받는다.
- `flatten.keep`은 기존 공통 점 경로 해석기를 사용한다. 예 `keep:["data.symbol"]`은 해당 경로 이름의 열을 만든다. 이름을 바꾸려면 기존 rename을 쓴다. 리터럴 점 포함 키, null, 충돌 접미사, 일부 결측 신고는 유지한다.
- 계산식 진단은 사전에 선언한 처방으로 set 형태와 `col("특수문자 열")`을 안내한다. 검사기 코드에 액션 이름을 넣지 않는다.
- 검색의 비편집 gnews 배치와 주가 이력의 보장 출력 열을 해당 패키지 사전에 선언했다. 검색 단일 조회의 원문 행 복구, 편집 모드, 다른 소스, 동적 매개변수는 미상/열린 구조로 유지한다. 빌드는 출력 구조 선언과 변환 규칙을 검사한다.
- 모델 표시 사본에서만 병렬 봉투의 중첩 JSON 문자열을 풀고, data와 단일 items 행의 동일한 필드를 한 벌로 표시한다. `_model_shared`는 옮겨 보인 필드를 지목한다. 원본 값, 가격 이력 같은 고유 자료, 출처·실패·절단 표지와 result_ref 조회는 유지한다. 앱/실행기의 원래 결과 계약은 바꾸지 않는다.
- `turn_vars.live`는 기존 이름 목록을 유지하고 `types`를 추가한다. 동일한 구조의 연속 병렬 분기는 개수로 묶어 구조 안내 자체의 반복도 줄인다.

## 검증

`backend/test_ibl_shape_handoff_20260912.py`는 검색 열 추측, 봉투에 대한 종목 열 선택, 대입문 계산식, 이력 flatten 뒤 신원 열 손실, 이미 평탄한 이력의 재-flatten, 특수문자 계산식의 여섯 부류를 재현한다. 정상적인 봉투 투영·flatten·union과 호출 간 저장, 재대입·빈 결과·서로 다른 행 열·부분 실패·명시 resume·구형 저장·원천 행 복구를 함께 검사한다. 표시는 원본 불변·고유 이력·실패 표지·증거 조회까지 대조한다. 공급자나 AI 호출은 사용하지 않는다.

3565에 저장된 첫 시세 결과의 표시 대상은 기존 직렬화 기준 18,589자였고, 새 표시 변환에서는 12,735자였다(31.5% 감소). 같은 저장 봉투에 새 형 안내(2,093자)까지 포함한 재생 비교는 20,703 → 16,953자, 약 18.1% 감소다. 이는 저장 자료의 JSON 표시 크기 비교이며 전체 입력, 청구액 또는 완료 시간의 절감률이 아니다. 실패를 사전 차단해도 수정 모델 응답이 필요하면 왕복은 남으므로 여섯 실패 구간의 비용을 전부 절감액으로 계산하지 않는다.

검사 결과: 전체 backend 회귀 **4,031 passed, 1 skipped**. 마지막 경계 보완을 포함한 집중 검사 **44 passed**. 사전 빌드/check, Android 본체 번들, backend 층 가드, 은퇴 계약 가드를 통과했다. 검사/실행 정합 관문은 fixture 144개와 교재 예제 11개에서 거짓 차단 0건이었다. 내부 AI의 판단·반환 범위 조정은 별도 비교 과제로 남기고, 경험·기억 추출 호출 통합과 `&`의 자동 대상 인자 추가는 포함하지 않는다.
