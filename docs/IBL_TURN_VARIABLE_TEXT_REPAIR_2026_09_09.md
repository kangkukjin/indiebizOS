# 턴 변수 이름과 파일 산문 바인딩 수리

2026-09-09 `YOUTUBE_TIPS_FIELD_NOTES.md` 현장 보고의 두 증상을 재현했다.
검증은 작은 `table:each`·`table:take`와 임시 파일로 수행해 AI 호출을 재실행하지 않았다.

## 원인과 변경

1. `ibl_turn_vars.referenced`만 선행 숫자를 제외하는 사설 정규식을 사용했다.
   파서는 `1차`를 저장했지만 다음 호출의 검색기는 발견하지 못해, 살아 있는 값을
   주입하지 않고 미할당으로 거절했다. 공통 `common.ibl_vars.find_names`로 통일했다.
   `$1차`·`${1차}`·`${ 1차 }` 모두 같은 턴의 기존 결과를 재사용한다.
2. `bind_template`이 일부 참조를 해소한 뒤 미해결 참조가 남으면, 내부 `parts`만
   갱신하고 문자열 뷰에는 이전 컴파일러 슬롯을 남겼다. 파일 쓰기/JSON 직렬화는
   그 낡은 뷰를 받아 `{{_step_2000000_result}}`를 기록했다. 현재 `parts`로 문자열
   뷰를 재구성하고, 바인딩된 문자열 조각은 `Literal`로 보존한다. 빈 문자열이
   끼어 있던 산문이 우연히 단일 참조처럼 보여 목록 원형으로 바뀌지도 않게 했다.
3. 문자 그대로의 산문 전달 경로인 `files`도 파이프에서 재검사되는 결함이 있었다.
   첨부 본문을 일반 문자열로 치환하던 방식을 IR의 `file` 참조 바인딩으로 바꿨다.
   삽입된 `$items`·슬롯·다른 첨부 참조는 데이터로 유지하며, 주변 소스에 적힌
   참조만 계속 바인딩한다. 두 자리 첨부 번호와 범위 밖 참조의 거절도 유지한다.

IBL 소스 문자열의 `$이름` 보간 자체는 기존 문법이다. `self:edit`만 특별 취급하지
않는다. 변수 이름을 문서에 글자 그대로 쓰려면 `old_string`·`new_string` 본문을
`files`로 전달한다. 사용 예는 `data/system_docs/ibl.md`의 파일 참조 절에 추가했다.

## 회귀

`backend/test_turn_variable_text_2026_09_09.py`는 숫자 변수의 호출 간 `each` 결과
재사용, 부분 바인딩 후 전송 왕복과 삽입 데이터 보존, 실제 `self:edit`의 슬롯
누출 방지, 직접 호출/파이프의 첨부 산문 보존, 첨부와 정상 변수 보간의 혼합을
검증한다. 기존 IR·턴 변수·첨부·학습성 회귀도 함께 검사한다.

관련 회귀 291건 통과. 전체 백엔드 검사에서 새 시험의 직접 실행 진입점 누락을
발견해 고친 뒤 직접 실행 8건과 러너 가드 4건을 재검증했다.
어휘/문서 파생 검사, backend 계층 검사, Android 몸 번들 생성도 통과했다.

후속 수리: `test_each_currency_contract.py`의 C13 실패는 옛 `each{` 표기만 찾는
검사기의 오탐이었다. 교재는 `[table:each]{옵션} { IBL 본문 }`과 현행 통화 계약을
정확히 설명하고 있었다. 검사 대상을 `[table:each]` 액션 표기로 맞추고, 은퇴한
감싸기 금지·`rows_replaced`·`passthrough_rows`·`keep` 검사는 그대로 유지했다.
후속 검증은 `each` 계약 13건 통과, 전체 backend 3,192건 통과·2건 건너뜀·실패 0건이다.
