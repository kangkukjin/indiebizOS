# IBL 판본 2 — 기존 어휘·관용구·학습 경로 연결

새 조합을 실제로 작성하고 재사용할 수 있도록 초기 코어의 운영 연결을 보완했다.
모델 비교 실험·추가 모델 호출·전체 재학습은 수행하지 않았다.
사용법 정본은 [판본 2 가이드](../data/guides/ibl_v2.md)다.

## 기존 자료를 모두 다시 써야 하는가

아니다. 기존 무표기 코드의 실행 의미는 판본 1로 유지한다. 필요한 변화는
**자료의 판본을 구분하고, 새로운 판본의 생성·저장·검사·회상·호출을 연결하는 것**이다.
`$return =`를 `return`으로 일괄 치환하면 뒤의 쓰기 실행 여부가 달라지고,
each의 펼침이나 `$x`의 봉투 추출도 문법 치환만으로 보존할 수 없다.

기존 해마 용례 3,669개·이름 있는 관용구 48개를 읽기 전용으로 조사했다.
원본 DB를 SQLite backup으로 보관한 뒤 검토된 판본 2 씨앗 8개만 추가했다.
기존 행의 본문·성공/실패·의도는 변경하지 않았다.

`열추려보기`와 `정렬해추리기`는 같은 이름의 판본 2 정의를 별도 행으로 등록했다.
두 판본의 이름 조회와 실행 실적을 분리한다. 판본 1은 기존 봉투를,
판본 2는 목록 자체를 반환한다. 나머지 기존 관용구는 호환 어댑터로 재사용한다.

씨앗 정본: [ibl_v2_seeds.json](../data/idioms/ibl_v2_seeds.json).
적재는 `add_examples_batch` 단일 경로이며, 배치에서도 별칭·서명·반환·출처를 보존한다.
`scripts/ibl_v2_assets.py seed --apply`를 다시 실행해도 동일 용례를 더 넣지 않는다.

## 어휘와 관용구 연결

명시 `callable_contract`는 기존처럼 네이티브 값 계약을 따른다.
그 밖의 설치·활성 액션은 기존 실행기를 경유하는 호환 계약으로 연결했다.
본문에 도구 이름별 분기를 추가하거나 새 표준 낱말을 만들지 않았다.

호환 계약의 결과는 **기존 JSON 봉투 전체인 Record**다. 임의로 message/items 중 하나를 고르지 않는다.
명시된 인자 키는 기존 단일 검증기를 공유한다. 열린 코어 인자와 실제 값 타입은 기존 핸들러가 검사한다.
효과는 unknown이며, 검사는 `incomplete`와 경계 종류를 반환한다. 잘못된 값·권한 거절·부분 원천은 성공으로 덮지 않는다.
순수 콜백·Unit·Result·정밀 숫자를 구형 JSON에 손실 변환하지 않는다.

기존 관용구 호출도 명시 인자를 받고 원래 봉투를 반환한다. 임의 파이프 자리 추측은 하지 않는다.
컴파일 시 본문·서명의 지문을 고정하고 실행 전에 변화를 확인한다. 지역 정의와 판본 2 정의가 우선한다.
기존 판본 함수의 실행을 새 판본 문법으로 다시 파싱하지 않는다.

사전은 한 컴파일 안에서 도구 스키마와 구현 파일 지문을 공유한다.
매 액션마다 전체 패키지 목록을 다시 조회하던 비용을 제거하며,
서로 다른 컴파일 사이의 오래된 전역 캐시는 새로 만들지 않았다.

## 학습과 회상의 판본

- 원장 입구: boot_paths의 기존 검증자·서명 슬롯을 통해 판본별 검사기를 연결한다.
  판본 2 함수는 명시 인자로 검사하며, 독립 예제의 미정의 입력은 거절한다.
- 검색·표시: 회상 XML과 접힌 카드에 판본을 붙인다. 새 함수 정의를 구형 `[def:]`로 다시 감싸지 않는다.
  긴 새 프로그램은 명시 확장 전에는 반사 실행 후보로 쓰지 않는다.
- 이름 조회: 기존 조회의 기본값은 판본 1이다. 판본 2 라이브러리는 해마와 workflow에서 별도 읽는다.
  본문 교체 API는 판본을 바꾸며 기존 행을 덮어쓰지 못한다.
- 증류: 기존 한 번의 선택 호출을 유지한다. 완전한 성공 프로그램 한 개를 한 source_id로 보존한다.
  여러 호출의 반환 범위나 서로 다른 판본을 자동 연결하지 않는다. 외부 inputs가 필요한 실행과 부분 실패는
  닫힌 재사용 예제로 바꾸지 않는다. 검사 성공은 실행 성공이 아니다.
- 실적: 호출된 판본 2 라이브러리의 정확한 원문에 기록한다. 같은 이름의 지역 재정의와 구형 정의에 잘못 귀속하지 않는다.
- 원문 관측: `ibl_code_corpus`에 edition 컬럼을 추가한다. 구형 행의 기본값은 1이며,
  판본 1 해시는 그대로 유지하고 판본 2는 판본과 소스로 해시를 만든다. 궤적과 원문 키는 일치한다.
  같은 문자열을 두 판본으로 실행해도 누계가 섞이지 않는다. 검사 호출은 실행 코퍼스에 넣지 않는다.
- 빌드: 해마/학습 JSON의 판본 2 소스를 판본 2 컴파일러로 검사한다. 문자열 치환이나 구형 파서로의 묵시적 폴백은 없다.

새 조합의 작성 안내는 판본 2를 우선한다. 기존 API 무표기 기본값을 바꾸지 않아
스케줄·앱·개인 스크립트의 기존 호출 의미를 유지한다. 도구 설명에 실린 구형 예제도 판본 1임을 표시했다.

## 검증과 범위

격리 DB에서 같은 이름의 두 판본 등록·실행·실적 분리, 지역 재정의, 기존 함수의 반환,
정의 변경 감지, 실제 사전의 도구 연결, 열린 코어 인자, 비공개 매개변수 차단,
권한 실패·큰 정수 경계, 원문 코퍼스와 궤적의 해시 일치, 증류의 단일 프로그램 보존을 검증한다.
외부 메시지를 실제 전송하거나 운영 스크립트를 실행해 검사하지 않는다.

본문을 자동 번역하지 않고, 두 계산 관용구를 판본 2로 옮겨 결과를 대조했다.
IDE/LSP, 정확한 행별 lineage, 지속 실행 재개, 원격 기기의 새 script wire 협상은
이 연결 작업의 전제가 아닌 추가 기능이다. 기존 실행 경로를 호환 모듈로 감싸는 방식은 설계 10.2가 허용한 이행 형태다.
회원/원격의 지원하지 않는 새 스크립트 프로토콜은 계속 실행 전에 거절한다.

전체 backend 회귀 5,617개 통과·1개 건너뜀, 집중 회귀 168개 통과를 확인했다.
씨앗 8개 모두 기존 인코더로 의미 검색 색인에 반영했고, 재적재 시 추가 행은 0개다.
어휘·폰 번들 파생, 층·파일 예산, 이벤트 루프, 검수 일관성 관문도 통과했다.

검증 결과는 [후속 검증 기록](experiments/ibl_composition_core_v2_2026_09_23/asset_integration.json)에 기록한다.
