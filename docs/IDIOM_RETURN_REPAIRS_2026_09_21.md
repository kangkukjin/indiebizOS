# 관용구 반환 계약과 빈 파일 후보 수리

등록 관용구 47개를 재검사했다. 상시 소개는 기존 5개에 판정 관용구 2개를 더한 7개이며,
이번 수리는 이름을 추가하거나 소개 층을 바꾸지 않는다.

## 수정

- `본문에서찾기`, `미처리만고르기`: 미상 입력을 받아도 성공한 표 변환은 items다.
  filter/sort/dedup/since의 `flow.emits`를 items로 선언하고 어휘를 재빌드했다.
  anti/semi join의 왼쪽 열 보존도 emits의 종류를 덮어쓰지 않는다.
- `띄우고기다리기`: 반복 본문에서 생긴 변수의 타입을 바깥으로 전달하고,
  `$return = $st` 같은 통짜 참조 대입이 이를 scalar로 바꾸지 않게 했다.
  반복 중 재할당되는 입력은 미상으로 시작하고, 실행되지 않을 수 있는 변수 경고는 유지한다.
- `최신범위읽기`: else 없는 조건문의 불일치 경로는 직전 통화를 통과시킨다.
  실제 계약은 **후보가 있으면 본문 문자열, 없으면 빈 items**다. 현재 타입 격자는
  서로 다른 종류의 합집합을 `?`로 표시하므로 scalar 단정을 제거했다.
- `최신파일읽기`, `직전보고서찾아읽기`: 빈 후보를 read에 넘겨 프로젝트 폴더를 읽던
  오류를 막았다. 두 이름도 파일 없음에는 빈 items를 반환하며, 직전 보고서는 디렉터리를
  후보에서 제외한다. 호출 인자와 기존 정렬 기준(수정시각/파일명)은 유지한다.
- `주소마다읽기`, `나레이션스크립트띄우고대기하기`: 최신 추론에 맞춰 반환 열 정보를 보충했다.
- 콜드 API 검수: 관용구/워크플로 타입 조회를 검수 진입에서 멱등 연결한다.
  import 부수효과에만 의존하면 재시작 직후 이름 호출이 모두 `?`가 됐다.
  캐시된 함수도 `fn_returns`에 계약을 표시한다.

`--refresh`는 기존 이름의 길이·슬롯 수에 신규 등록 정책을 재적용하지 않는다.
구문·액션·인자·타입 검증과 트랜잭션 안의 정의 변경 검사는 유지하며,
반환형·서명 외 필드는 바꾸지 않는다. 실제 본문 개정은 기존 `update_idiom` 경로를 쓴다.

## 운영 반영

SQLite backup API 백업:
`data/_backups/2026-09-21_225524_관용구_반환형수리/`.
백업에는 원장, 갱신 전 가지 문서, 47개 원본 행과 변경 영수증을 보관했다.

- 본문 개정 2개: 이전 행·실적은 `ibl_idiom_revisions`에 보존하고 새 본문의 실적은 초기화.
- 메타데이터 갱신 6개: 본문·실적·소개 여부 보존.
- 47개 전부 반환형·서명이 새 추론과 일치함을 확인했다. 본문 개정 외 45개는
  반환형·서명 이외 필드가 백업과 같다.
- 실행 중인 API에서 47개 정의의 반환형이 원장과 일치하고, 이름 호출 검수에서도
  수정된 계약을 확인했다. 실제 프롬프트 소개는 7개다.

## 검증

`backend/test_idiom_return_repairs.py`는 표 관용구 실제 반환, 파일 유무 양쪽,
작업 상태의 참조 반환, 반복 변수, 조건문 불일치, 기존 등록 메타데이터 보존,
콜드 API 및 캐시된 반환형을 검사한다. 파일·표는 실제 파서/엔진/핸들러를 쓰고,
외부 작업 시작과 상태 조회는 fixture로 격리했다.

최종 집중 검사(수리 회귀·기존 타입 검사·판정 관용구 등록)는 60개 통과했다.
어휘 `--check`와 Android 몸 번들을 검증했다.

전체 백엔드 회귀는 5,361개 통과했다. 이 실행 시작 뒤 추가한 콜드 API 연결·캐시 표시
수정은 위의 최종 집중 검사 60개와 운영 `/ibl/validate`, `/ibl/execute`의
`check:true`로 별도 확인했다. 실행·검수 일치 검사도 fixture 148개·교재 11개에서
거짓 거절 0건이다. 회귀 로그는 운영 백업 폴더에 보관했다.

## 에피소드 3973 후속: 현재 코드에 남은 검증 누락과 중복 비용

함수 밖에서는 오류인 `search >> brief >> take`가 `[def:이름]{…}` 안에서는
정상으로 판정되어 수동 등록 관문까지 통과했다. 함수 본문 검사기가 식 구문 오류만
바깥에 전달하고, 산문을 표로 취급하는 등의 확정 타입 오류는 버렸기 때문이다.

- 함수 본문의 확정 오류를 전부 전달한다. 종류 불일치, 없는 열, 문장 경계의 입력
  누락을 등록·개정 전에 거절하고, 오류가 있는 함수 추론은 성공 캐시에 넣지 않는다.
- 함수 첫머리는 호출자의 통화를 받을 수 있으므로 미상 입력으로 검사한다.
  인자에 따라 달라지는 경고는 계속 유보하며, 정상적인 파이프형 관용구는 허용한다.
- 기존 등록 47개와 선정집 19개는 강화된 관문을 통과했다. 이번 변경에는 원장 수정이 없다.

선정집 검증에는 별도의 중복 비용도 있었다. 각 본문을 `_gates`에서 이미 검사했는데,
37개 용례마다 전체 19개 정의의 인자를 다시 검사했다. 프로파일에서 인자 검사에
전체 시간의 약 96%가 쓰였고, 파일 상태 조회는 약 874만 회였다. 각 본문은 개별 관문에서,
용례 인자는 해당 용례에서 검사하도록 바꿨다. 정의 전체를 붙이는 조합 타입 검사와
어휘 존재 검사는 유지했다. 같은 선정집의 일반 실행 측정은 40.676초에서 4.276초로
줄었다(동일 머신에서 각 1회, 전체 회귀 검사 병행 중이므로 성능 보장치는 아님).

회귀는 잘못된 함수의 직접 정의·외부 이름 호출·반복 호출·등록 거절과 정상적인
미상 입력 수용을 확인한다. 선정집 본문·대표 용례·추가 용례 각각의 잘못된 인자가
계속 거절되는지도 검사한다. 실행 중인 `/ibl/validate`의 `typecheck` 결과에서도
오류 본문의 거절과 정상 파이프 본문의 통과를 확인했다.

후속 전체 백엔드 회귀는 5,367개 통과·1개 건너뜀이다. 이 실행 이후 추가한 선정집
중복 검사 제거와 그 회귀 3개는 최종 집중 검사 42개로 별도 확인했다. 실행·검수 일치
관문은 fixture 148개·교재 11개에서 거짓 거절 0건이고 Android 번들도 일치한다.
