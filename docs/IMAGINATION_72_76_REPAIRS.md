근거는 `docs/experiments/imagination_round{72,73,74,75,76}_2026_09_28/report.md`와 각 탐침이다.

## 공통 원인과 수리 방향

1. **계약이 여러 곳에 따로 있었다.** 어휘의 인자·파이프 선언, 판본 2 어댑터, 실제 핸들러가 서로 달랐다. 파이프 수신 계약을 선언에서 파생하고 빌더가 누락을 검사한다. 값 검증과 중첩 프로그램 검사는 선언의 `value_validator`·`code_params`로 선택하여 컴파일·실행에서 공유한다. 파서에 개별 액션 이름을 추가하지 않았다.
2. **성공의 범위가 불명확했다.** 일부 행의 합계를 전체 합계처럼 내고, 일부 파일만 스캔해도 완전한 결과로 보였다. 전체 모집단·반환 행·절단·원천 불완전성을 구분한다. 이미지를 못 읽거나 지원하지 않는 거래 유형을 받으면 성공으로 위장하지 않는다.
3. **읽기와 쓰기, 준비와 확정이 섞였다.** 조회가 주체·이미지 폴더를 만들고, 검침은 발신 성공 전에 기준선을 확정했다. 조회의 숨은 쓰기를 없애고 검침 확정은 실행 전체의 성공 뒤로 미뤘다.
4. **시간과 값의 뜻을 각 소비자가 다시 구현했다.** 반복 주기 해석과 타이머 실행을 한 경로로 모았다. 숫자 스칼라는 공통 값 경계에서 변환하고, 외부 시세·매물은 단위와 선택한 가격에 맞는 통화를 함께 전달한다.

## 기존 원장 보정과 남은 제약

- SQLite 온라인 백업 후, 기존 원문 메모 또는 명백한 인센티브 꼬리 문구를 근거로 **가맹점 27행만** 보정했다. 거래 건수·유형별 금액 합계 불변을 확인했다. 백업과 변경 영수증은 `data/_backups/2026-09-29_imagination72_76/`에 있으며 git에 넣지 않는다.
- B72-1의 과거 의심 거래 2건은 원문이 없고 확인 당시 폰도 연결되지 않았다. 금액만으로 이체라고 단정하지 않았고 해당 거래의 금액·유형은 바꾸지 않았다. 새 알림의 파싱·증거 보존 경로는 수리했다.
- since의 성공 후 확정은 **외부 서비스까지 묶는 트랜잭션이 아니다**. 발신 성공 직후 프로세스가 죽으면 재시도 발신은 중복될 수 있다. 외부 효과의 정확히 한 번 처리는 별도 멱등 키가 필요하다.
- 짧은 달에 존재하지 않는 지정일은 건너뛴다. 말일·공휴일의 새 의미를 추정하여 추가하지 않았다.
- 보고서의 G/V 항목(조건식·날짜 산술, 분류 편집·휴지통·내용 해시·말일/공휴일·등기 조회)은 버그 수정과 별개인 언어/기능 확장 후보다. 이번에는 새 어휘나 문법을 추가하지 않았다.
- 외부 API의 실제 시세·매물 정확도와 전체 모델 업무 성능은 이번 로컬 회귀만으로 검증되지 않는다. 회귀는 임시 파일·DB와 모의 외부 응답으로 수행했으며 외부 메시지를 보내지 않았다.
