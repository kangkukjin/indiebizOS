# 상상훈련 56회차 수리 — 도구 경계의 계약 정합성

## 문제와 원인

[발견 보고서](experiments/imagination_training_2026_09_25/report.md)의 B56-1/2/3은
결합·시간 조회 알고리즘보다 **현재 IBL 값 계약과 기존 도구 계약 사이의 불일치**였다.

- 결합 도구는 `flow`에서 분기 묶음을 받는다고 선언했지만 현재 호환 계약에는 파이프 입력이
  없었다. `left/right`는 잎 도구의 입력 스키마에 컨테이너 타입도 없어서 정상 목록이 거부됐다.
- `time`은 정상 문자열을 반환하지만 공통 호환 계약은 JSON 실행 봉투 Record를 요구했다.
  문자열을 JSON 모양으로 만드는 우회는 값을 상태로 오해하게 하므로 수리가 될 수 없다.
- 결합 경로를 복구한 뒤 실패 분기 검사를 추가하자 `branches_skipped`가 공통 정직 표지와
  완료 증거 목록에서 빠진 것이 드러났다. 일부 출처를 잃고도 전체 성공으로 보고할 수 있었다.

## 변경

1. `join/merge/union`에 명시 값 계약을 선언했다. 목록·Record·기존 JSON 문자열을 받으며,
   `inputs`를 파이프 수신 자리로 쓴다. 기존 left/right 및 별칭은 같은 정본 인자로 해소된다.
   join은 두 출처, merge/union은 두 개 이상의 출처를 처리하는 기존 알고리즘을 그대로 쓴다.
2. `requires/exclusive`를 공통 계약 제약으로 추가했다. 한쪽 입력만 주거나 직접 입력과
   분기 묶음을 동시에 주면 거부한다. 컴파일러도 파이프 수신 인자의 존재를 계약 검사에
   반영해 실행 직전 검사와 같은 판단을 한다. 언어 코드에 액션 이름을 넣지 않았다.
3. 빌더는 pair/same-kind flow의 묶음 입력, 파이프 자리, 값 계약, 잎 스키마 컨테이너 타입을
   함께 대조한다. 선언의 한쪽만 수정해 같은 결함이 재발하는 것을 차단한다.
4. `ibl_edition.text_result`는 잎 도구에서 성공이 확인된 텍스트만 현재 판본의 명시 봉투로
   감싼다. 기존 판본은 원래 문자열을 유지한다. time은 `/message`를 Text로 꺼낸다.
   같은 결함을 가진 파일 복사·이동·삭제, 이미지 읽기·평가의 성공 반환에도 적용했다.
   도구 오류는 그대로 실패이고, 이미지 평가의 부정적 판정은 성공적으로 얻은 평가 내용이다.
   기존 맨 문자열 반환 가드의 허용 부채도 실측 28→23으로 낮춰 제거한 경로의 재진입을 막았다.
5. `branches_skipped`를 공통 정직 표지에 포함하고, 실패·생략 분기는 완료 증거로 보존한다.
   현재 어댑터는 이를 `PARTIAL_SOURCE`, 부분 값, `source_complete:false`로 전달한다.
   사용자 items나 본문 안의 동명 필드는 상태로 해석하지 않는다.
6. `self:delete`의 기존 `missing_ok`를 어휘 입력 선언에도 연결했다. 누락된 선언 때문에
   잎 핸들러가 이미 지원하는 멱등 삭제에 도달하지 못하던 경계도 함께 복구했다.

다중 출처 flow는 설치 사전의 join/merge/union 세 항목을 전수 확인했다. `returns:scalar`
선언과 평문 반환 경로도 점검했다. scalar는 반드시 원시 문자열이라는 뜻이 아니며,
ask·설계 도구처럼 이미 JSON 객체를 반환하는 도구를 일괄 문자열로 바꾸지 않았다.
read/edit/list의 기존 명시 어댑터와 delegate의 구조화된 성공 응답은 유지했다.

## 검증

- 실제 잎 호출 회귀: 목록/봉투/별칭/명시 묶음/파이프, 세 출처, 빈 출처, join 기본값과 null,
  충돌·누락 입력, 실패 분기·원천 절단, 원문처럼 생긴 JSON·숫자·Error 문자열을 검사했다.
- 임시 파일을 실제 복사·이동·삭제해 작업이 일어난 뒤 반환 판정만 실패하는 경로를 검사했다.
  이미지 모델 응답은 고정했다. 외부 AI의 시각 품질을 검증했다는 의미는 아니다.
- 라이브 HTTP 재실행: 원래 12과제 전부 검사 통과, 실행 대상 10과제 전부 기대값 통과.
  추가 대조 7개에서 병렬 결합·세 출처·빈 목록·두 종류의 부분 실패·JSON 모양 텍스트·임시 파일
  정리를 확인했다. [29개 요청과 응답 증거](experiments/imagination_training_2026_09_25/repair_evidence.json).
- 모든 HTTP 호출은 `origin:training`. 예약·발신 과제는 검사만 했으며 시험이 만든 파일은 정리했다.
- 변경된 인자 선언을 쓰는 저장 용례 66건(join 6, merge 7, union 40, delete 13)을 검토했다.
  기존 저장 원문의 입력 해석·반환 의미를 유지하므로 원문 이관 없이 네 액션의 검토 원장을 갱신했다.
  이 검토는 용례 속 외부 조회·발신을 재실행했다는 의미가 아니다.

전체 backend 회귀: **5,961 통과, 1 건너뜀**, 541.79초. 샌드박스에서 로컬 서버·프로세스·문서
렌더링 제한을 확인한 뒤 실제 실행 환경에서 재검사했다. 실행 명령은
`.venv/bin/python -m pytest backend/ -q -o addopts='' --junitxml=/tmp/imagination56-full-native.xml`,
로그는 `/tmp/imagination56-full-native.log`다. 새 교재 예제를 포함한 교재 검사 30개도 통과했다.
`build_ibl_nodes.py --check`, `build_body_bundle.py android --check`, backend 층 가드와
`git diff --check`를 통과했다.

## 호환 경계

새 어휘·문법을 추가하지 않았다. 기존 저장 원문의 실행 의미와 원래 문자열은 보존한다.
새 계약의 입력 충돌 검사는 모호한 호출을 거부하며, 원천 누락은 성공으로 덮지 않는다.
회원 경로 감사 지문은 시스템 필수 도구의 반환부 변경 후 갱신했다. 감사 대상 read/fill/script의
경로 처리와 권한 로직은 바뀌지 않았음을 대조했다.
