# Jev 판정 어휘 (2026-09-21)

사용자 요청: Jev API 키를 .env에 저장하고 AI가 즉석 IBL 조합에 쓸 판정 어휘를 만든다.

## 계약

`[table:judge]`는 ai-ops 패키지의 변환자다. 표준 파서·엔진 변경은 없다.
기존 생성형 세 원자(struct/ai/brief)는 기어 실행 축을 유지한다. judge만 별도 인증과
typed evaluation API를 쓰는 제공자 어댑터이며, 범용 모델명을 기존 기어에 하드코딩하지 않는다.
이것은 `ONESHOT_VOCAB_DESIGN.md`의 생성형 원샷 계약과 구별되는 접근 경로다.

입력 행×독립 질문을 요청 한 번에 묶는다. 내부 질문 ID는 행/질문 인덱스이고,
질문 본문에도 `items[i]` 경로를 넣는다(API의 ID 자체는 모델이 보지 않는다).
원 행과 순서를 보존하고, 질문 결과만 `judgment_<질문>_<필드>` 열에 추가한다.
기존 table:filter는 중첩 경로를 받지 않으므로 값/상태를 평평한 열로 제공한다.
결과 열 충돌은 거절한다.
질문 형태는 boolean/choice/score. 완전한 계약·예문은 `data/guides/judgment.md`가 소유한다.

boolean의 중간 확률과 choice/score의 낮은 confidence는 value:null/status:unknown이다.
통신·계약 오류는 실행 실패다. 응답 누락/추가·타입·확률분포·범위·등급표를 검증한 뒤에만
통화를 방출한다. 자동 LLM 폴백·재시도·묵시적 행 삭제는 없다.

API 키는 gitignore된 .env에만 저장한다. .env.example은 변수 이름과 자리표시자만 포함한다.
오류 응답/예외의 원문은 키·입력 반사를 막기 위해 반환하지 않는다. HTTP 리다이렉트도 따르지 않는다.
사용량은 ProviderMetrics로 기존 활성 턴 원장에 합산하고 실행 봉투에도 보존한다.

## 검증 기록

- 직접 API 한국어 1행·3질문(boolean/choice/score) 배치 성공.
  제공자 모델 jev-1.13.0, 입력 504/출력 77토큰, 응답 627ms(단일 표본; 성능 보장 아님).
- 회귀 시험은 배치 요청 수·원 행 보존·불명·임계 경계·입력 제한·응답 누락·오류 비노출·
  사용량 계측·criteria 엔진 가로채기 방지·용례 문법을 검증한다.
- 실제 IBL 실행기를 통해 12개 용례 실행 성공: 한국어/영문 의도, 참/거짓 필터,
  unknown 필터, 선택·점수·정렬, 다중 질문, 문장 비교, 조건 분기.
  백엔드 서버는 꺼져 있었으므로 동일한 실행기 `_execute_ibl_unified`를 직접 호출했다.
- 신규 판정 및 통화 파이프 회귀 75개 통과.
- 전체 backend 회귀를 실행했다. 최초 실행에서 용례 승인 원장과 신규 시험의 직접 실행
  러너 관문 2건이 실패했고, 원장 갱신·pytest 진입점 추가 후 관련 회귀 84개가 통과했다.
  어휘 빌드 --check, backend 층 관문, Android 파생 검사도 통과했다.
- 해마/다음 학습 JSON에 용례 12건을 등록·색인했다. 환불 판정과 다중 판정 회상에서
  judge 용례 적중 확인. 가이드를 guide_db에 등록하고 인자·동반 어휘 관측을 갱신했다.
