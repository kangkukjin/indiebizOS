# 판정 관용구 등록 계약 수리

에피소드 3973에서 등록한 `관련자료골라읽기`·`의미로본문찾기`는 실행되지만
반환형이 각각 `scalar`·`?`로 소개됐다. 또한 원천 실패 행을 결과에 붙이고도
새 크롤의 `error_count=0`을 그대로 반환할 수 있었다.

## 수정

- `table:take`의 사전 흐름 선언을 성공 시 실제 반환형인 `items`로 정정했다.
  구현은 그대로이며 script의 데이터 의존 scalar 선언을 출력에 잘못 계승하지 않는다.
  두 관용구 본문과 호출 서명은 유지하고 정적 반환형은 `items⟨열 미상⟩`로 산정한다.
- 등록기에 `--refresh 이름`을 추가했다. 현재 본문을 관문으로 검증한 뒤 반환형·서명만
  갱신하고 가지 문서를 다시 그린다. 실행 통계·원문·용례·벡터는 유지한다.
  선정집 재적용도 같은 경로로 계약을 갱신해 낡은 반환형이 남지 않게 한다.
- 판정 보조 스크립트는 원천 실패 행/신고 건수와 새 크롤 실패를 합쳐 최상위
  `error_count`·`partial`에 반영한다. 상세 출처는 기존 `source_markers`에 보존한다.
- 선정집·판정 가이드에 개수=0의 의미를 명시했다. 외부 호출과 정상 자료 선별은
  없지만 원천 실패 행은 반환한다. 문맥 확장 때문에 문단 수는 선별 상한보다 클 수 있다.
- 보조 스크립트 등록 설명에 빠졌던 입력 인자와 단계별 반환값도 보완했다.
  전체 회귀의 문서 감사가 prepare/select/finish 입력 11개 누락을 검출했다.
- 상시 선정 회귀의 기대 목록도 사용자 지정 두 관용구를 포함하도록 갱신했다.
  실행 선정집은 이미 7개였지만 회귀만 종전 5개를 기대하고 있었다.
- 어휘 빌드가 이전 등록 때 누락됐던 판정 스크립트의 코어 배포 목록도 재생성한다.

## 검증 범위

새 회귀는 실제 파서·이름 호출·each·표 변환을 사용하고 판정/웹 통신만 격리한다.
직접 목록·파이프 전달, 원천 실패 보존·최종 집계, 0개 요청의 외부 호출 생략,
타입 추론·선정집 용례, 메타데이터 갱신의 멱등성과 기존 실행 통계 보존을 확인한다.
실제 라이브 등록 두 건과 상시 소개에서도 반환형·서명·교재 일치를 확인한다.

- 관련 회귀: 보조 스크립트·등록/이름 실행·정적 타입 검사 48건 통과.
- 라이브: 두 이름 모두 개수=0·원천 실패 1행 입력에서 외부 호출 없이 오류 건수 1·
  partial=true·실패 행 보존 확인. 등록 DB와 가지 문서의 반환형도 일치한다.
- 어휘/문서 파생 검사와 Android 몸 번들 생성 통과.
- 전체 백엔드 회귀 5,342건 실행: 첫 실행 5,339건 통과·3건 실패.
  실패한 등록 인자 설명·상시 선정 기대 목록·새 테스트의 직접 실행 진입점을 수정하고
  해당 검사 2건 및 러너 관문 4건을 다시 실행해 모두 통과했다. 전체 재실행은 하지 않았다.
- 라이브 원장 변경 전 SQLite backup과 수집 가지 문서를
  `data/_backups/2026-09-21_222905_판정관용구_등록수리/`에 보존했다.

실행 모델의 비용 계측이나 관용구 효용 비교 실험은 이번 등록 수리의 범위 밖이다.
