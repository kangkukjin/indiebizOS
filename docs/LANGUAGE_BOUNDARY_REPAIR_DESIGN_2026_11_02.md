작성일: 2026-11-02. 상태: **R0~R2 경계 수리, R3 미시작 순차 쓰기와 읽기 전용 병렬·반복 호출의 조향 구현. 제한된 실제 평가 모델 비교 완료(§11), 실행 scope 확장(§12)**.
조사 기준 HEAD: `ba16938919990592423669efee3849da6dd1b623` 및 아래에서 읽은 작업 트리.
동시에 편집 중인 program/control/재기동 계열은 이번 설계의 구현 완료 근거로 사용하지 않는다.

목적 정본은 [vision](../data/system_docs/vision.md)과 [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)이다.

현행 구현과 이번 연구 실행 #5766의 읽기 전용 조사다. 연구 산출물·spill·런타임 로그는
로컬 자료이며 보존 수명이 다르다. 이 문서는 아래의 비식별 계수와 코드상의 책임을 남긴다.

## 1. 해결할 문제와 범위

**언어·부품·표시·검수 경계를 넘어도 대상·값·근거·목적·진행·효과를 유지하고,
필요한 부분만 자세히 보거나 수정하여 작업을 이어 간다.** 먼저 확인된 평가 입력 초과를
수리하고, 그 수리를 공통 경계의 보존·선택·부분 개입으로 연결한다.

새 언어·코어 어휘·목표 DB·상주 감독을 추가하지 않는다. Python/셸을 강제로 IBL로 감싸지
않고, 기존 도구·함수·Script·참조·원장 소유자를 유지한다. 모든 어휘를 한꺼번에 개정하지
않는다. 사용자의 목적·권한·완료 기준과 평가자의 도구 없는 원샷 계약도 유지한다.
성능의 목표는 같은 품질에서 전체 완료 시간과 토큰을 줄이는 것이다. 입력 축소만으로
달성을 주장하지 않으며, 현재 IBL과 Python의 동조건 우열은 미확인이다.

### #5766 평가 입력 초과의 직접 근거

`data/world_pulse.db`의 `episode_log`/`trajectory_event`를 `mode=ro`로 읽었다.
해당 실행은 `run_ece4eb009f8ab35fac21`, 턴 저장소는
`data/spill/supervision/04ea9d451d9f4d669bf445e70c857a0f`다.
`data/backend_runtime.log`의 `[GoalEval] 평가 입력`과 `model.input`이 본문 크기에서 일치한다.

| 항목 | 실제 기록 |
| --- | ---: |
| 보고서 파일 본문 | 22,682자 |
| 평가 user 본문 | 1,116,531자 |
| 평가 system 본문 | 5,594자 |
| history / images | 0자 / 0개 |
| 생성 파일 첨부 합 | 1,030,646자 |
| 도구 trace 표시 | 23,978자 |
| 기준 / 최종 응답 | 5,267자 / 1,266자 |
| 공급자가 거절한 실제 입력 / 상한 | 1,122,132자 / 1,048,576자 |

생성 파일 첨부가 평가 user 본문의 약 92.3%다. 보고서 길이나 대화 누적만으로 설명할
실패가 아니다. 위 항목은 일부가 본문의 부분집합이며 모두 합산하는 비용 표가 아니다.
전송 상한은 이 실행의 공급자 오류가 보고한 문자 한도다. 모델의 토큰 창과 혼동하거나
모든 공급자에 같은 숫자를 적용하지 않는다. 평가 결과는 UNKNOWN이며 연구의 내용 불합격이 아니다.

`final_evaluator.prepare`는 발견한 산출물마다 최대 120,000자 인자를 주어 발췌하고,
나머지 파일에는 `_collect_created_files(full_content=True)`를 호출한다. 이 후자도
`bounded_attachment`의 파일별 제한을 적용한다. **full_content가 무제한 전문 첨부라는
해석은 틀리며, 파일 수에 따라 총량이 커지는 것이 확인된 문제**다. 여러 파일·맥락 전체의
예산이 없고 `_evaluate_achievement`에서 합친 후 공급자로 보낸다.

## 3. 수리 전후에 지킬 불변 조건

1. **접기와 펼치기:** 같은 입력·환경·정의에서 직접 조합과 저장 호출은 약속한 업무 값,
   실패 종류·부분 결과·효과 범위를 보존한다. 실행 ID·시간·추적 그래프의 바이트 동일성은 요구하지 않는다.
2. **같은 관측의 확대:** 요약→본문→영역은 같은 대상·판본·선택 범위를 가리킨다.
   재관측이면 새 시점과 판본을 명시한다. 만료·접근 거절·마스킹으로 복원 불가이면 미확인이다.
3. **부분 수정:** 바뀐 입력/정의와 그 실제 의존 부분만 무효화한다. 미상 의존성은 보수적으로
   처리한다. 완료된 쓰기·효과 불명 쓰기를 자동 재시도하거나 성공으로 추정하지 않는다.
4. **목표 보존:** 사용자 요청·정정·기준 판본은 축약 과정에서 조용히 제거·완화하지 않는다.
   과거 기준의 상속도 현재 요청과 연결되어야 한다.
5. **유한한 전달:** 실제 전송 요청이 해당 공급자의 문자/바이트 제한과 모델 입력 예산을
   모두 만족해야 한다. 생략은 위치·범위·조회 가능성을 남기며, 필수 정보가 안 들어가면 명시적으로 중단한다.
6. **판정 분리:** 접수·실행·효과·목표 달성·검수 승인은 별개다. 공급자 실패는 모델 판정이 아니다.

기존 evaluator는 `no_tools=True`, `history=[]`의 원샷이다. 참조만 넘겨 놓고 스스로
읽을 수 있다고 가정하지 않는다. 평가자가 부족한 증거를 지정하면 기존 controller의
회수·재평가 경로가 운반한다. 평가자에게 셸·쓰기 권한을 추가하지 않는다.

### 4.2 보존 원본과 표시 자료

기존 TurnStore의 마스킹된 원문과 산출물 snapshot은 승인 대상의 정본으로 유지한다.
모델에 보내는 자료는 그 원본의 제한된 표시다. 내부 선택 레코드는 기존 정보를 재사용해
`source_ref, subject/path, revision/hash, role, range, completeness, criterion_ids`를 연결한다.
이는 새 IBL 반환 봉투나 모든 도구의 필수 필드가 아니다. 모르는 관계는 미확인으로 둔다.

- 제출물: 최종 응답·pending delivery·명시된 제출 경로로 확인한 대상. 알려진 기준과
  관계를 보존하며 가능하면 본문 전체를 보낸다. 경로가 언급됐다는 사실만으로 최종본을 확정하지 않는다.
- 보조 자료: 연구 계획·증거 집계·자료 원문·중간 파일. 기존 명시 관계가 있는 근거를 우선
  표시하고 나머지도 존재·크기·판본·조회 참조를 잃지 않는다. `sources/` 같은 폴더명만으로 중요도를 결정하지 않는다.
- 같은 마스킹 원문·판본·범위의 반복 첨부만 합친다. 여러 주장과 같은 근거의 관계는 모두
  보존한다. 같은 경로나 비슷한 문장이라는 이유로 서로 다른 관측·역할을 합치지 않는다.
- 원문 보존과 모델 열람을 구분한다. manifest에 있다고 내용을 검토한 것으로 기록하지 않는다.
  생략된 파일·문단·액션의 부재를 결함으로 단정하지 않는다. 액션 목록을 줄인 경우 기존
  프롬프트의 ‘전수·없으면 안 한 일’ 문구도 completeness에 맞게 바꿔야 한다.

### 4.3 전체 예산과 선택 규칙

1. 실제 선택된 공급자·모델에서 모델 입력 예산을 구하고 전송 한도는 별도 단위로 얻는다.
   현재 모델 창 데이터는 재사용한다. 공급자 전송 제한은 adapter의 능력/설정으로 관리하며,
   지원되는 메타데이터가 없으면 출처 있는 보수적 설정을 사용한다. 토큰 추정은 추정으로 기록한다.
2. system 정책, 사용자 원문·정정, criteria 계약, 응답/제출 판본, 취소·권한·효과 미확인 등
   필수 상태와 생략 표식의 공간을 먼저 확보한다. 최종 요청 wrapper·이미지 참조·출력 여유도 계산한다.
3. 남은 예산에 제출물 본문, 기준별 관련 근거, 검사·원장·계획 발췌를 배분한다. 기준 하나나
   큰 파일 하나가 전부 차지하지 않게 초기 몫을 나누고 잔액을 재배분한다. 기존
   [research_review.allocate/passage](../backend/base/research_review.py)를 활용하되 문자열 일치는
   관련 구간 선택의 보조일 뿐 의미적 지지 판정이 아니다.
4. file/trace/context/recovered 섹션은 한 예산의 소비자다. 개별 제한은 보조이고, JSON
   escaping·섹션 표제·생략 메타데이터까지 포함한 실제 조립 결과로 다시 확인한다.
5. 공급자의 최종 요청 구성 뒤에도 검증한다. 넘으면 모델을 호출하지 않고 `input_too_large`
   범주와 초과량을 반환한다. 기준이나 정책을 잘라서 강제로 맞추지 않는다.
6. 필수 내용만으로 한도를 넘거나 핵심 증거를 넣을 수 없으면 UNKNOWN과 미포함 범위를
   남긴다. 정상 입력에 추가 평가 호출을 강제하지 않는다. 고정 N자 절단만으로 승인하지 않는다.

크기 계획은 모델 선택 뒤 동일한 원샷 provider를 대상으로 한다. 예산을 얻으려고 다른
모델로 먼저 분류하거나 호출 직전에 재해소해 모델을 바꾸지 않는다. 평가 경로에 먼저
적용하며 실행자 전체 카탈로그/정상 문맥을 줄이는 정책으로 확대하지 않는다.

### 4.4 부족한 증거와 전달 실패의 회복

기존 `UNKNOWN_REASON: evidence`와 evidence_index를 유지한다. 기존 출력에 선택적인
구조화 요청(기준 id·기존 증거 id·판본·범위)을 붙여 controller가 범위를 검증하고 같은
원문을 회수할 수 있게 한다. 자유 텍스트 요청은 기존 회수 경로를 유지한다. 새 URL 수집이나
검사 실행은 원문 회수가 아니므로 자동 페이지 회수에 섞지 않는다.

회수한 자료는 최초와 같은 예산으로 재조립하고 부족하다고 지정된 구간의 몫을 확보한다.
같은 발췌를 다시 보내는 순환을 막되, 다른 필수 기준·미확인 상태는 유지한다. 기존 최종
증거 회수 한도 1회와 취소·시간·토큰 예산을 유지한다. 자동 회수와 기존 실행자 회수가
같은 부족분에 이중 발동하지 않게 한다. 여전히 부족하면 구체적인 UNKNOWN으로 끝낸다.

전송 오류는 기존 `last_failure_kind`/원샷 실패 문맥을 확장해 구조적으로 전달한다.
일반 작업 문자열 API를 한꺼번에 깨지 않고 평가 호출자는 실패 메타데이터를 먼저 읽는다.
`input_too_large`, `deadline`, 인증/통신 실패, 모델의 UNKNOWN/NOT_ACHIEVED를 구분한다.
표준 오류에 ACHIEVED 등의 단어가 있어도 판정 파서를 호출하지 않는다.
크기 오류는 바뀐 예산·축소된 요청이 있을 때만 제한된 재조립 1회를 허용한다.
동일 입력의 무조건 retry, 산출물 재작성, 완료된 외부 행동 재실행은 하지 않는다.

### 4.5 관측과 승인

기존 평가 사건에 section별 원문/표시 문자 수, 직렬화 바이트, 토큰 추정/실측 구분,
공급자 제한의 출처·단위, 선택/생략 개수, 회수 참조, 준비/모델/회수 시간을 기록한다.
본문·비밀값은 계측 로그에 복제하지 않는다. 최종 승인에는 기존 response/file/delivery/
criteria 지문 검사를 그대로 적용한다. 압축본의 지문으로 원 산출물 지문을 대체하지 않는다.

## 5. R1 — 언어와 부품 사이의 의미 보존

대상은 [Binding](../backend/common/expression_eval.py),
[IBL runtime](../backend/ibl/ibl_v2_runtime.py),
[component runtime](../backend/ibl/ibl_v2_component_runtime.py),

[파일 Script 연결](../backend/ibl/ibl_file_script.py)이다.
기존 증거·원장·read_scope를 연결하며 Python 내부 계산의 모든 의미 계보를 자동 추론하지 않는다.

동일 계산을 직접/저장 함수/등록 Script/턴 Script 경로로 수행하는 작은 대조 묶음을 만든다.
입력 참조→값 선택→조합→표시→재입력에서 타입·결측·빈값·원천 불완전성·부분 실패·효과
범위를 검사한다. 경로별 지원 계약이 다르면 그 차이를 명시하며 가짜 동등성을 만들지 않는다.
불투명 Python/셸 결과는 명시된 원천·출력·효과만 연결하고 선언 밖 의존성은 미확인으로 둔다.

실제 누락을 찾은 경계만 수정한다. 새 공통 봉투·전용 오류 대수를 추가하지 않는다.
과거 이름 호출 오류를 다시 구현하는 대신 현재 직접/저장 호출의 교환 성질을 회귀로 보존한다.
원문 접근 불가·마스킹 제한을 우회해서 재사용하지 않는다.

## 6. R2 — 부품 적합성과 상세 관측

### 적합성

[function_store](../backend/datastore/function_store.py)의 불변 판본,
[callable_contract](../backend/ibl/ibl_callable_contract.py)의 인자·조건·효과 선언과 기존
describe/교재/회상이 같은 정의를 읽는지 확인한다. 소개 문장에만 남은 숨은 전제는 정본
계약/설명으로 옮기고 파생 표면에서 재생성한다. 입력 형태·적용 범위·실패·효과·수정 가능한
경계를 우선하며 매 호출 모든 본문을 싣지 않는다. 전체 어휘를 작업별로 끄거나 숨기지 않는다.

기계적으로 검사할 수 있는 제약과 의미상 적합성은 구분한다. 기간·목적·자료 선정 같은
가변 판단은 함수 인자/작은 함수로 분리한다. 모든 옵션을 범용 정책 언어로 만들지 않는다.
기존 부품 그대로/부분 변경/즉석 작성 중 선택은 현재 실행 모델이 하며 새 라우터를 추가하지 않는다.

기본 프롬프트에는 언어와 맡길 일의 크기를 독립적으로 선택하는 기준, 전체 비용,
부품의 적용 조건, 새 관측이 판단을 바꾸는 경계, 전환 시 근거·상태 보존을 짧게 둔다.
상세 문법과 특정 작업 절차는 기존 환경·가이드가 맡는다. 의식 에이전트는 공통 기본
프롬프트를 직접 읽지 않으므로 역할 프롬프트에도 계획 단계의 선택 원칙을 맞춘다.
2026-11-02 `base_prompt_v7.md`와 `consciousness_prompt.md`의 기존 선택 문단을 보강했다.
새 언어 라우터·추가 호출·고정 IBL 우선순위는 없으며, 프롬프트 반영은 실제 선택 품질이나
속도·토큰 개선의 검증과 구분한다. 기존 mtime 갱신 경로로 다음 프롬프트 조립에 반영된다.

### 상세 관측

result_ref/read_scope와 situation의 subject/revision을 자료 원형의 위치에 연결한다.
문단·표 행/열·이미지 영역·음성 구간의 단위와 좌표계를 소유 어댑터가 선언한다.
이미 있는 음성 source_hash/ranges 등부터 연결하고 모든 매체에 임의의 새 스키마를 씌우지 않는다.
‘저장된 관측 확대’와 ‘지금 다시 관측’을 명확히 구분한다.

관계 손실은 생산자에서 고친다. 예를 들어 웹 카드의 제목·링크·이미지는 구조상 관계가
확인될 때만 함께 묶고, 서로 다른 상품을 이름 유사성만으로 합치지 않는다. 이 공통 원칙과
각 페이지에서 실제 관계를 추출할 수 있는지는 별도의 검사다.
확대 관측만으로 실행을 취소하거나 재시작하지 않으며 조회 비용도 기존 usage에 포함한다.

## 7. R3 — 제한된 부분 개입과 재개

[task_receipts.steer/cancel](../backend/base/task_receipts.py), 기존 IBL 실행 좌표·재사용·
자원 계약을 사용한다. 첫 범위는 지원되는 읽기/순수 계산 부품의 **다음 실행 경계**다.
임의 Python stack을 붙잡아 수정·복구하는 기능을 약속하지 않는다.

개입 요청은 root task, 부품 호출 신원, 기대 대상/정의 판본, 변경 인자/정의,
request_id를 연결한다. 어댑터가 실제로 아는 다음 경계만 표시한다. 미지원 조향은 현재처럼
명시 거절하고, 요청 접수·적용 완료·취소 확인·효과 불명을 분리한다.
같은 request_id의 중복은 같은 요청으로 처리하고, 기대 판본 불일치는 조용히 덮어쓰지 않는다.

정책/입력 교체는 해당 부품과 의존 결과만 무효화한다. 무관한 성공 결과와 기존 사용자
목적은 유지한다. 쓰기 부품은 다음 단계로 별도 인수하며, 멱등성 또는 효과 확인 계약이
없는 결과 불명 쓰기는 재실행하지 않는다. 늦은 응답·외부 변경·취소 경합도 상태로 남긴다.
기존 자기수리·프로그램 적용 권한과 배포 경계는 바꾸지 않는다.

## 9. 적용 순서와 완료 기준

1. **R0 구현:** 크기 계측·자료 역할 구분·전체 예산·최종 전송 관문·실패 분리·제한된 회수까지
   하나의 수직 경로로 완성한다. cap만 낮추고 종료하지 않는다. #5766 형태의 요청이 전송 가능하고
   부족한 근거를 정직하게 다루는 것이 첫 인수 목표다. 같은 입력 조건의 내용 승인까지 보장한다는 뜻은 아니다.
2. **R1 보존 검사 및 발견된 경계 수리:** 기존 기반을 유지하며 누락 소비자를 연결한다.
3. **R2 적합성/상세 관측:** R1이 확인된 경로부터 병행 가능하다. 과거 모든 결함을 다시 수리하지 않는다.
4. **R3 읽기·순수 계산 개입 → 쓰기 개입:** 각각 독립 인수한다. 지원되지 않는 범위를 숨기지 않는다.
5. **축적:** 검증한 조합과 적용 조건·변경 이유를 기존 함수/Script 판본과 기억에 남긴다.
   새 관용구 수를 성과로 세지 않고 유지·발견 비용까지 본다.

배포는 기존 적용·검수 절차를 따른다. 되돌릴 때도 입력 초과 요청을 무제한 경로로
자동 재전송하거나 승인되지 않은 산출물을 공개하지 않는다. 기존 증거와 작업 상태를
보존하고 검수 미완료로 남길 수 있어야 한다. 소프트웨어 변경의 롤백은 이미 실행한 외부
행동을 취소하는 것이 아니다.

## 10. 구현과 인수 범위 (2026-11-02)

- R0: `evaluation_input`이 원문·snapshot과 표시를 분리하고 실제 선택된 원샷 공급자에서
  파일·맥락·trace·회수 증거를 함께 배분한다. 사용자 요청·정정·기준·권한 상태는 필수다.

  Codex 문자 한도 출처는 위 #5766의 실제 거절이다. 다른 공급자에 그 한도를 복사하지 않는다.
  전달 실패를 판정 파서보다 먼저 확인한다. 크기 오류의 무조건 재시도는 없으며,
  자동 한도 재협상도 이번 구현에 없다. 검증된 TurnStore 참조의 지정 구간 회수는 최대 한 번,
  같은 원본·기준·예산으로 재평가하고 실행자 보완과 중복하지 않는다.
- R1: 직접/저장 함수/등록 Script 결과 채널/파일 Script의 JSON 값 대조와 기존 참조·부분 실패
  검사를 유지했다. 실제로 발견한 별칭 정규화의 필드 근거·인증 범위 유실을 고쳤다.
  불투명 Python 내부의 계보를 추론하거나 임의 예외를 언어 간 동일 오류로 변환하지 않는다.

  ID·판본·Unicode 문자 좌표를 반환한다. 음성 어댑터는 원본 파일 해시와 초 단위 구간을
  기존 관측 영수증/상황 기록에 연결한다. 부분 청취와 전체 원본 판본 확인은 구별한다.

## 11. 후속 인수 — 쓰기 경계와 실제 평가 모델 비교 (2026-11-02)

### 부분 개입의 확장

`ibl_run_control`은 같은 SQLite 원장 안에서 `(node_id, ordinal)`을 기존 `calls`의
호출 ID에 연결한다. 별도 효과 원장을 만들지 않는다. 다음 **미시작 순차 쓰기**는
`write_resources`를 선언하고 변경 전후 읽기/쓰기 자원 신원이 같을 때만 인자를 바꾼다.
대상 경로 변경·자원 신원 미상·효과 계약 변경은 적용하지 않는다. 실제 부품의 권한 및
원문 판본 검사도 그대로 실행하며, 모든 부품에 공통 CAS를 새로 제공하지는 않는다.

완료된 쓰기를 포함하는 프로그램을 재개해도 완료 영수증을 재사용한다. 효과 발생 뒤
프로세스가 사라져 반환 영수증이 없으면 기존 `EFFECT_UNCERTAIN`으로 중단하며,
새 request_id로 그 호출을 다시 조향할 수 없다. 요청 적용 여부와 효과 관측은 별개다.
`call_ref`와 `effect_state`의 `not_started`/`returned`/`unknown`을 노출한다.
`returned`는 값 반환 관측이고 목표 달성이나 외부 효과의 독립 검증은 아니다.
취소 전에 접수된 미시작 쓰기는 실행하지 않고, 이미 시작한 쓰기의 늦은 반환은 보존한다.

병렬 계획은 전체 효과가 읽기/순수이며 직접 호출 위치가 분기마다 고유한 경우에 한정한다.
이 후속 인수 당시에는 공유 함수·람다 본문의 병렬 호출과 `table:each`를 제외했다.
전역 호출 순번이 불명확한 읽기 전용 반복 위치의 후속 수리는 §12를 따른다. 병렬 쓰기,
동적 의존/정의 교체는 미지원이다. 기존 병렬 자원 충돌 입장 검사를 유지한다.

회귀: `test_ibl_run_control.py`의 완료 효과 재사용, 효과 발생 직후 중단, 자원 변경 거절,
원문 판본 충돌, 취소 전/후 경합, 무관한 병렬 결과 재사용과 모호한 공유 위치 제외.

## 12. 반복 호출의 실행 좌표와 취소 경합 (2026-11-02)

읽기 전용 `table:each`와 공유 함수·람다의 병렬 호출은 같은 `node_id`를 여러 작업자가
실행한다. 전역 호출 순번은 도착 순서에 의존하므로 특정 항목을 지시하는 주소가 될 수 없다.
기존 실행 경로(route), 프레임 본문 ID와 진입 순번으로 scope를 만들고, 그 안의 호출 순번을
주소에 추가한다. 임의 실행 스택 변경이나 정의 교체는 하지 않는다.

- 범위: 계획 전체 효과가 읽기/순수인 순차·병렬 each, 공유 함수·람다 및 그 중첩 조합.
  기존 미시작 순차 쓰기 지원은 유지하지만 쓰기를 포함하는 병렬/each 계획은 여전히 제외한다.
- 노출: 현재 열린 프레임의 호출만 `status.progress.boundaries`에 `scope`와 `scope_context`로
  표시한다. 자식 함수·병렬 분기·each 본문은 각자 진입 시 자신의 좌표를 연다.
  아직 시작하지 않은 항목의 scope를 예측해 접수하지 않는다.
- 적용: 같은 root task·plan·scope·node·정의 판본·순번·기대 인자 지문이 맞는 경계에만 적용한다.
  scope 누락/위조·종료·다른 호출 위치는 거절한다. 도착/완료 순서가 바뀌어도 대상이 바뀌지 않는다.
  프레임 종료 시 미도달 요청은 `not_applied / scope_closed`로 확정해 다음 항목으로 넘기지 않는다.
- 보존: 기존 SQLite journal에 scope·경계·기존 호출 ID의 연결만 추가했다. 재개 시 같은 좌표의
  적용 인자와 반환 영수증을 사용한다. 이전 버전의 node 주소 요청도 같은 계획의 재개에서 유지한다.
  새 task·goal·효과 원장이나 추가 모델 호출은 없다.
- 취소: 병렬 취소 경합에서 한 분기가 공유 검사 간격을 갱신해 다른 분기의 호출 직후 검사를
  건너뛰게 하는 결함을 확인했다. 검사 간격은 작업자별로 두고 관측된 취소는 실행 전체에 유지한다.
  이미 시작한 호출의 반환 영수증과 기존 정리(cleanup) 계약은 보존한다.

회귀는 `test_ibl_run_control.py`의 each/함수/람다/중첩 조향·한 항목만 변경·기존 결과 재사용,
순차 다음 항목 격리·만료 요청·위조/누락 좌표·입력 판본 충돌·취소·이전 주소 재개와
