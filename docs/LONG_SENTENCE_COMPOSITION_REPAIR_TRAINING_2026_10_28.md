## 목적과 판정

**작은 능력으로 큰 일을 완수하고, 그 능력을 저장한 뒤 새로운 요구에 재조합하여 더 큰 일을 쉽게 구성·변경·완료하는가**를 확인한다.
최근 수리의 회귀시험을 반복하는 데 머무르지 않고, 실제 산출물을 만드는 과제에서 저장·발견·적용·실행·수정 재개가 이어지는지 본다.

## 실행 범위와 회차

서로 이어지는 두 회차로 구성한다. 각 회차는 준비·작성·검수·실행·변형·진단을 합해 **60분 상한**이다.
첫 회차의 완료 상태를 보존한 뒤 둘째를 시작한다. 첫 회차가 막혔다면 완료된 부분과 재개 입력을 남기고, 둘째의 선행 조건이 성립했는지 따로 판단한다.
상한을 자동 연장하거나 쉬운 과제로 바꿔 완료 처리하지 않는다. 세부 시간 배분은 실행자가 시작할 때 정한다.

회차 번호는 실행 직전 원장에 따라 배정한다. 이 설계 작성만으로 번호를 점유하거나 실행 항목을 만들지 않는다.
원자료·로그·산출물은 `outputs/long_sentence_imagination/YYYY-MM-DD_N회차/`, 비민감 최소 재현·요약은
`docs/experiments/long_sentence_imagination/round_N/`에 둔다. 첫 회차 결과를 둘째 회차의 명시 입력으로 연결한다.

훈련자는 전체 IBL을 작성·실행하고 시스템 AI에도 같은 자연어 업무를 맡긴다. 각 실행자의 자기 능력·결과는 다음 단계에 계승한다.
훈련자 해법·정답·새로 저장한 능력이 AI의 독립 실행에 섞이지 않도록 자료·출력·카탈로그 접근을 구분한다.
사용 가능한 격리 방식은 시작 시 확인하며 존재하지 않는 API나 저장소 격리 옵션을 만들지 않는다.
이름 접두사나 별도 폴더만으로 공유 카탈로그·대화가 격리됐다고 판단하지 않는다.

101회차에서는 공유 리허설 세션 때문에 독립 전이가 성립하지 않았다. 이번에도 실제 대화·참조·카탈로그 노출을 확인한다.
분리를 확인하지 못하면 가능한 수행 관측을 계속하되 **독립 발견·전이는 미검증**으로 적는다.
훈련자의 설계 지식 개입도 기록하고, 훈련자의 성공을 시스템 AI의 독립 작성 성공으로 바꾸지 않는다.

## 자료와 업무 규칙 준비

주제는 **세 도서관의 교육 키트 공급 계획**이다. CSV·JSON·텍스트의 신청·재고·견적 자료를 합쳐 약 2,400행으로 준비한다.
정확한 행수는 시작 전에 고정하고 규모 자체를 합격 조건으로 삼지 않는다. 개인정보 없는 합성 자료를 쓰는 이유는
기대값과 읽기 실패·희귀 입력을 통제하기 위해서다. 파일 읽기·등록 Python 실행·로컬 원장 쓰기는 실제 경로를 사용한다.

업무 조건을 자료와 함께 제공한다. 작성자가 가격·납기·제품 동등성을 추측해야 정답을 맞히게 만들지 않는다.

| 자료 | 최소 내용과 경계 |
| --- | --- |
| 신청 목록 | 도서관·프로그램·품목 ID·요청 수량·필요일. 중복 행의 처리 기준과 같은 품목의 별칭표를 제공한다. |
| 보유 재고 | 도서관별 사용 가능 수량·예약 수량. 부족량은 요청량과 실제 사용 가능 재고로 계산한다. |
| 견적 | 품목·단가·포장 단위·납기·유효일·출처. 누락 가격은 0이 아니며 미확정 납기는 납기 충족이 아니다. |
| 보관 사본 | 최신 자료 읽기 실패 때 사용할 판본·시각. 사본으로 확정 가능한 조건과 보류할 조건을 구분한다. |
| 정책 | 납기·예산·가격 동률 처리와 판정 우선순위. 동시에 여러 조건을 만족하는 표본을 포함한다. |
| 보고용 정보 | 선택적 표시 필드의 누락·빈 값 등 정상 자료의 드문 형태. 원문과 출처를 보존한다. |

공급 가능·자료 부족 보류·최신 원천 실패 후 사본 사용 경로가 실제로 발동할 자료를 둔다.
업무 규칙에 따른 기대값을 실행 전에 계산해 작성자 입력과 분리한다. 소수의 경계 표본은 수동 대조하고,
전체 수량·금액·보류 목록은 독립 검증기로 확인한다. 같은 정규화 스크립트를 정답 생성기와 실행 구현 양쪽에 그대로 써서 같은 오류를 통과시키지 않는다.

원천이 일부 실패한 상황에서 알 수 없는 정답을 요구하지 않는다. 사본 출처·신선도·미확인 사유와 추가 확인 목록이 기대 결과다.
출고 내역과 최종 보고서의 수량·금액·출처 연결도 비교한다. 반환값만 맞고 최종 파일이 틀리면 미달이다.

등록 Python은 형식·단위 정규화만 맡는다. 결합·정책·반복·복구·출고·전체 보고까지 하나의 새 스크립트에 넣지 않는다.
어휘 읽기, 실제 등록 스크립트, 표 연산, 인자로 받은 정책 콜백을 연결하는 경로는 훈련자 실행에서 확인한다.
새 내부 의미 계약 필드를 작성자가 수동으로 채우는 방식으로 성공시키지 않는다. 외부 스크립트의 정당한 입출력·효과 선언과 내부 인증 자료는 구분한다.

## 첫 회차 요청과 수행

### 시스템 AI에 보낼 주 요청

아래 요청에 실제 자료·출력 위치와 제공한 업무 규칙 위치를 덧붙인다. 함수 이름·분해 방법·정답·훈련자 프로그램은 덧붙이지 않는다.

> 세 도서관의 교육 프로그램에 필요한 키트를 준비하려고 한다. 신청 목록, 보유 재고, 공급업체 견적을 대조해 도서관별 부족 수량과 조달안을 만들어 줘. 품목명이 달라도 같은 제품이면 제공한 별칭 근거로 연결하고, 가격이나 납기가 확인되지 않은 것은 확정하지 마. 최신 견적을 읽을 수 없으면 보관 사본을 사용하되 그 사실을 표시해 줘. 준비 가능한 도서관의 출고 요청은 지정된 로컬 시험 원장에 기록하고, 보류한 항목은 이유와 추가 확인 목록을 남겨 줘. 최종적으로 도서관별 내역과 전체 합계, 사용 자료의 출처를 보고해 줘. 이 처리는 다음 행사에도 다시 사용할 수 있게 보관해 줘. 실제 주문이나 외부 발송은 하지 마.

### 저장과 내부 수정 재개

훈련자는 요구→분해 이유→입출력·실패·효과→구현→최상위 조합 순으로 작성한다. 기존 능력은 실제 검색·소개·describe로 찾는다.
적합한 기존 능력이 있으면 사용하고 없으면 새로 만든다. 현재 설치의 59개를 억지로 끼워 넣거나 조회만 한 것을 재사용으로 세지 않는다.

검증한 처리 부품을 저장하고, 그것을 호출하는 도서관 처리 능력도 저장한다. 이번 훈련에서는 검증된 부품의 명시 저장·재조합이 대상이다.
일괄 등록·자동 해마 시딩은 범위가 아니다. 훈련용 등록은 구분 가능한 이름과 판본을 기록하고, 정규 사용 능력을 덮어쓰지 않는다.

주 실행과 이어지는 수정 시도에서 다음 상태를 관측한다.

1. 앞 도서관의 처리와 다음 도서관의 출고 원장 기록이 완료된다.
2. 다음 도서관 내부의 **결과만 만드는 순수 보고 계산**이 희귀 입력을 처리하지 못해 실패한다.
3. 새 함수 판본으로 해당 계산을 수정하고, 현행 `check`·`repair`·명시 함수 참조를 통해 같은 실행 계보를 이어 간다.
4. 완료한 효과는 보존하고 아직 처리하지 않은 회차를 완료하여 전체 산출물을 만든다.

자연 발생한 해당 실패가 없으면 정상 성공으로 기록한다. 훈련자 경계 확인에는 회차 자료/프로그램 사본에
통제된 보고 계산 결함을 넣은 별도 시도를 사용할 수 있다. 이것은 **의도적 복구 탐침**이며 AI의 자발적 오류나 최초 업무 실패로 세지 않는다.
이미 완료한 원래 실행을 초기화하지 않고 별도 시험 실행을 사용한다. 라이브 코어를 바꾸거나 저장된 실행 기록을 조작해 실패를 만들지 않는다.
실패가 출고 입력·선택이나 복구 효과를 결정하는 계산에 걸렸다면 안전한 수정 대상이 아니므로 위치를 정직하게 분류한다.

해당 실패가 실제 발생한 실행자에게만 다음 후속 요청을 보낸다.

> 일부 출고 요청은 이미 기록됐는데 보고서 작성이 실패했어. 이미 기록한 요청은 다시 만들지 말고, 문제가 난 표시 계산을 고쳐 남은 도서관 처리와 전체 보고를 마쳐 줘. 너 자신의 직전 결과와 중간 참조는 재사용해도 된다. 다른 실행자의 trainer/harness/drafts와 정답은 참조하지 마.

별도 부정 사례는 출고 수량·대상·선택 조건을 바꾼 repair를 **검사까지만** 요청한다.
원래 효과를 계승할 수 없다며 거절하는 것이 기대다. 이를 실제 새 출고로 실행하지 않는다.

## 둘째 회차 요청과 재축적

첫 회차의 저장 판본과 산출물을 확정한 뒤 아래 요구를 공개한다. 변형 자료와 기대값은 운영자가 미리 고정하되 첫 작성에 노출하지 않는다.
이 문서 전체를 이미 본 실행자에게는 요구의 비공개성을 주장하지 않는다.

> 이제 여러 도서관의 결과를 묶어 지역 전체 공급 계획을 만들어 줘. 새 공급업체는 포장 단위가 다르고 운송비도 별도로 제시한다. 납기 우선안과 예산 우선안을 비교하고, 도서관 사이의 남는 재고를 이동하는 안도 함께 제안해 줘. 앞서 보관한 처리 능력을 활용하고, 이번 지역 계획도 다음 행사에서 다시 사용할 수 있게 보관해 줘. 앞서 기록한 출고 요청을 다시 등록하지 말고 이번에는 비교 계획과 제안서를 만들어 줘. 너 자신의 이전 산출물과 저장 능력은 활용해도 되지만 다른 실행자의 해법이나 정답은 참조하지 마.

새 공급업체 자료, 포장 반올림·운송비·재고 이동의 허용 조건과 동률 처리 규칙을 별도 입력으로 제공한다.
이는 새 자료에 대한 새 계획 실행이다. 하위 부품 교체를 기존 효과가 있는 실행의 repair와 혼동하지 않는다.
기존 결과 참조를 재사용할 때는 원자료 판본·신선도를 확인한다. 변한 자료를 읽어야 한다면 필요한 수집부터 수행하고 그 비용을 남긴다.

새 정규화 부품·정책을 적용하고, 저장 인터페이스의 새 필드·요구·효과·완료 정보가 상위 조합에 전달되는지 확인한다.
새 지역 능력을 저장한 다음 별도 호출에서 재발견·검사·실행한다. 이름·행수만 바꾼 반복은 재조합 전이와 구분한다.
지역 능력의 결과가 실제로 다른 조합에 사용되지 않았다면 저장 후보/재호출 확인까지만 기록한다.

## 효과 관측과 핵심 경계의 증거

외부 효과는 회차 전용 로컬 시험 원장/사본 쓰기로 한정한다. 실제 주문·발송·공개·예약은 하지 않는다.
`origin:"training"`을 지원하는 진입점으로 전달하고 실행 id·출처·결과 회수 경로를 확인한다. 표식만으로 격리됐다고 판단하지 않는다.
파일·등록 스크립트·대역의 효과 선언과 허용 위치를 실제 계약으로 확인하고, 준비는 업무 실행 전에 끝낸다.

원장은 요청마다 별도 흔적을 남겨 실제 호출 수를 셀 수 있어야 한다. 덮어쓰기·중복 제거가 반복을 숨기는 구현은 증거로 부족하다.
업무 키·효과 사이트·회차·요청 인자·원장 항목·완료 영수증을 연결한다. 검사 전후, 최초 실패 직후, repair 뒤의 증거를 비교한다.
새 실행의 새 업무 효과와 같은 계보의 중복 효과를 구분하며, 아직 실행하지 않은 회차의 정상 호출까지 중복으로 세지 않는다.

| 경계 | 필요한 관측과 통과 조건 |
| --- | --- |
| 검사와 저장의 무실행 | 업무 읽기·정규화 runner·원장 쓰기가 check/save 때문에 실행되지 않는다. 인터페이스 도출에 필요한 소스·계약 메타데이터 읽기는 구분한다. |
| 본문 없는 작성 | 작성자가 하위 본문을 복사하거나 내부 코드를 읽지 않고 소개·계약·진단으로 상위를 작성한다. 열람했다면 시점과 도움받은 범위를 남긴다. |
| 본문 없는 기본 검사 | 지원 함수의 상위 check/save가 하위 본문 분석을 요청하지 않는다는 직접 증거가 필요하다. 실행기의 구현 읽기는 허용한다. 작성자의 비열람만으로 검사기 경계를 입증하지 않는다. |
| 값과 완료 | 행·수량·출처·사본 사용·보류 이유가 최종 파일까지 이어진다. 정상 종료·업무 JSON complete·복구 성공을 완료 의무 충족과 혼동하지 않는다. |
| 안전한 내부 수정 | 결과만 만드는 계산의 수정이 허용되고 기존 출고·정리 효과는 각각 한 번이다. 순수 계산의 재실행은 허용한다. |
| 반복과 분기 | 완료 회차를 보존하고 미완료 회차는 진행한다. 판정 우선순위·조기 반환·정리가 실제 발동한 경우 그 결과와 효과를 대조한다. |
| 위험한 수정 | 효과의 입력·대상·도달 조건을 바꾸는 repair는 효과 실행 전에 거절된다. |
| 부품 교체와 재축적 | 새 부품을 선언/관계 적용으로 연결하고 상위도 같은 인터페이스로 저장·발견·호출한다. 업무 이름별 코어 수정은 필요하지 않다. |

검사기의 본문 비열람 등 일반 실행 로그에 없는 구조 증거는 기존 격리 회귀의 차단 계측을 활용할 수 있다.
라이브 코어에 임시 분기를 추가하거나 전체 훈련을 테스트 함수 호출로 대신하지 않는다.
참조할 구현 검증은 `backend/test_function_revalidation.py`와 최근 의미 인터페이스·repair 관련 회귀다.
기존 회귀 성공과 이번 업무에서 직접 관측한 사실을 별도 칸에 기록한다. 계측이 없으면 해당 구조 항목은 미검증이다.

현재 재인증 상태는 기존 읽기 감사로 확인할 수 있다. 조회가 카탈로그를 쓰지 않는지 함께 본다.
구형 상태를 만들려고 실제 59개 능력의 인증을 삭제하거나 정상 카탈로그를 되돌리지 않는다.
재인증의 전이 무효화·CAS·멱등성은 이미 존재하는 회귀 증거와 구분하고, 이번에 새로 밟은 판본 교체만 실사용 관측으로 기록한다.

반환·정리·fallback·case 등 모든 문법을 억지로 강제하지 않는다. 실제로 발동한 경계는 검증,
그 형태를 쓰지 않았거나 실패 조건이 발동하지 않은 경계는 미검증으로 남긴다. Callable 같은 실행 중 값은
허용 프레임 안에서만 사용하고 결과 파일에는 일반 데이터를 남긴다. 전송 수명을 이번에 밟지 않았다면 검증했다고 쓰지 않는다.
