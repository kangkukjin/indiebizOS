# 긴문장 상상훈련의 반복 탐색과 복구 비용 검증 설계

작성일: 2026-10-19. 상태: 다음 회차 설계, 실행 전.
현재 원장의 마지막 회차는 76이다. 실행할 때 원장에서 다음 번호를 확정하며, 이 설계만으로 77회차를 시작하거나 번호를 예약하지 않는다.

이번 훈련은 **기존 조사에서 근거를 찾아 판단하고, 요구가 바뀌면 필요한 부분만 이어서 처리하는 일**을 맡긴다.
과제 달성 여부와 함께 반복 탐색·작성 오류·복구 이후 개입이 만든 비용을 추적한다.
결함 수를 목표로 삼지 않고, 관측한 반복이 공통 개선으로 이어질 수 있는지 확인한다.

## 출발 근거와 검증할 가설

최근 보고서에서 원인을 분류한 뒤 남겨 둔 비용을 출발점으로 삼는다.
원본 실행을 다시 호출하는 대신 보존된 요청·응답·계측을 읽고, 이미 수리된 문제와 열린 후보를 구분한다.

| 근거 | 이번에 확인할 가설 | 반증과 판정 경계 |
| --- | --- | --- |
| [72회차 L72-5](experiments/long_sentence_imagination/round_72/report.md): IBL 조회 뒤 네이티브 목록·읽기 중복 | H1. 같은 자료를 확보했어도 결과의 위치·범위·판본을 알아보기 어려워 다시 탐색한다 | 앞 응답이 잘렸거나 다른 범위를 읽거나 실제 신선도 확인이 필요했다면 중복 낭비가 아니다 |
| [76회차](experiments/long_sentence_imagination/round_76/report.md): 기본·변형에서 문법 거절과 재작성 5주기 | H2. 설명이 존재해도 필요한 시점에 적용하기 어려운 문법·진단이 왕복을 만든다 | 정확한 도움을 받은 뒤 한 번에 복구했고 다른 사례에도 반복되지 않으면 일반적 설계 문제라는 근거는 약하다 |
| [연구 에피소드 4917~4919 수리 기록](CONSCIOUS_SUPERVISOR_PLAN_2026_09_10.md#2026-10-18--회복-뒤-늦은-지시와-연구-계약-49174919): 복구 후 늦은 감독 지시 | H3. 실행자·감독이 공유하는 작업 상태가 어긋나면 이미 끝낸 복구를 반복한다 | 관련 수리가 반영됐으므로 정상 작동하면 회귀 확인이다. 감독이나 복구가 발동하지 않으면 미검증이다 |

H1을 주 가설로 삼고 H2·H3은 자연스럽게 발생할 때 함께 관측한다. 오류나 감독 호출을 일부러 만들지 않는다.
이미 수정된 모델 표시의 중복 wire 문제도 현재 리비전에서 재발하지 않으면 새 발견으로 세지 않는다.
많은 누적 입력 토큰 자체는 낭비의 증거가 아니다. 캐시 읽기·새 입력과 반복된 판단의 이유를 구분한다.

기준 문서는 [진화 목적](IBL_EVOLUTION_PURPOSE.md), [훈련 절차](../data/guides/long_sentence_imagination.md),
[상상행동](../data/guides/imagination_action.md), [IBL 조합 교재](../data/guides/ibl_composition.md)다.

## 주 과제와 사용자 요청

주제는 **작은 작업실의 회원 PC 도입 검토**다. 설치나 장치 제어를 수행하지 않고,
현재 문서가 보장하는 범위와 아직 확인해야 할 조건을 구별하여 사용자가 도입 여부를 판단할 수 있게 한다.
행별 집계 정답만으로 통과할 수 없도록 문서의 설계 의도·구현 상태·실검증 한계를 함께 해석한다.

시스템 AI에는 아래 요청과 입력·출력 경로, 고정된 자료 판본의 기준 시각만 제공한다.
가설 표·훈련자 프로그램·정답표·비용 분석 기준은 제공하지 않는다.

> 작은 작업실에서 직원 두 명이 각자 Windows와 Mac을 쓰고 있어. IndieBiz OS를 도입하면
> 내가 모델 설정을 한곳에서 관리하면서 직원은 자기 PC의 작업 폴더에서 일하게 할 수 있는지 검토해 줘.
> 제공한 문서 묶음을 근거로 지금 시작할 수 있는 범위, 먼저 확인해야 할 조건, 보류할 범위를 나눠 줘.
> 각 PC에서 파일을 다루는 권한과 결과가 남는 위치, 연결이 끊겼을 때 처리도 설명해 줘.
> 설계에 적힌 계획을 실제 검증된 기능으로 쓰지 말고, 문서끼리 설명이 다르면 그대로 알려 줘.
> 내가 읽을 짧은 판단 메모와, 담당자가 확인할 순서대로 정리한 점검 목록을 저장해 줘.
> 중요한 판단에는 어느 문서의 어느 부분이 근거인지 연결하고, 답이 없는 것은 확인할 질문으로 남겨 줘.
> 지금은 문서 검토만 해 줘. 실제 PC 연결·설치·설정 변경은 하지 마.

운영자는 부족한 사용자 조건에 대해 가상의 답을 즉석에서 늘리지 않는다.
자료로 결정할 수 없는 조건은 질문과 조건부 결론으로 남기는 것이 이 과제의 완료 조건이다.

## 입력과 정답의 분리

다음 실제 문서의 실행 시작 시점 사본을 사용한다. 원문 전체를 보존하되 실행자에게 처음부터 본문을 모두 주입하지 않는다.
파일명을 가진 자료 폴더와 간단한 출처 목록만 제공하고, 필요한 문서·범위를 고르는 행동을 관측한다.

| 자료 | 역할 |
| --- | --- |
| `docs/MEMBER_DESKTOP_DESIGN_2026_10_15.md` | 중앙 관리·권한·데이터 소유·연결 복구·구현과 인수 범위 |
| `data/system_docs/remote_access.md` | 원격 런처·회원 표면·원격 실행을 혼동하지 않는지 확인 |
| `data/guides/pc_control.md` | 장치 제어와 회원의 로컬 파일 작업을 구별하는 인접 자료 |
| `data/system_docs/anatomy.md` | 전체 제품에서 해당 기능의 위치를 찾는 입구 |

자료별 원 경로·수집 시각·SHA-256·코드 리비전과 미커밋 변경 유무를 기록한다.
자료에 자격증명이나 개인 식별 정보가 있으면 사본에서 제거하고 제거 범위를 적는다.
인용 좌표는 제공한 사본 기준이며, 원본 문서는 수정하지 않는다.

검수자는 시작 전에 원문에서 다음 여섯 질문의 근거 구간과 답변 가능 범위를 별도 정답표에 고정한다.
중앙 모델 관리, 회원별 실행 위치, 파일 접근 권한, 결과 저장·소유, 연결 단절 처리,
Windows·Mac별 구현 및 실검증 범위다. 문서에 답이 없으면 그 항목의 기대값은 미확인이다.
실행자에게 구현 소스를 열어 답을 보충하라고 요구하지 않는다.

정답표·훈련자 출력·다른 실행자의 출력은 실행자 자료 폴더 밖에 둔다.
비밀 위치라는 이유만으로 격리를 가정하지 않고 실제 도구 접근 기록을 대조한다.
오염이 관측되면 해당 실행의 독립성은 무효로 표시한다. 기존 지식과 교재 참고도 기록한다.

## 필수 변형

기본 실행이 끝난 뒤 같은 대화에 다음 후속 요청을 보낸다. 자료 판본은 그대로 유지한다.

> 조건이 바뀌었어. Mac 직원은 출장 중 네트워크 없이도 파일 작업을 계속해야 해.
> 그리고 다른 직원의 폴더에는 접근하지 못해야 해. 앞서 만든 검토를 이 조건에 맞춰 고쳐 줘.
> 처음 검토는 그대로 보존하고, 바뀐 결론과 그대로인 결론, 추가로 확인할 질문을 구분해 줘.
> 자료는 앞서 준 판본 그대로야. 실제 장치 시험은 하지 마.

이 변형은 새로운 문서나 정답을 추가하지 않고 **요구만 바꾼다**.
오프라인 동작·권한 격리를 지원한다고 미리 가정하지 않는다. 근거가 부족하면 조건부 판단과 확인 항목이 정답이다.
기존 근거를 다시 읽는 것 자체는 실패가 아니다. 같은 본문 전체를 재수집할 필요가 있었는지 별도로 판단한다.
최초 파일의 해시, 유지된 판단의 근거, 수정된 판단의 새 요구 연결을 대조한다.

## 두 실행과 품질 판정

훈련자는 공개 계약과 교재를 사용해 자료 선택·근거 추출·판단·산출물·검수를 연결하는 전체 IBL을 작성한다.
의미 판단이 필요한 부분에는 모델 호출을 사용할 수 있으며 그 비용을 포함한다.
지역 함수는 필요에 따라 정의하고, 핵심 작업을 별도 Python 스크립트 하나로 대체하지 않는다.
최초 초안과 수정본, 실패 시점, 실제로 펼쳐 본 계약을 보존한다.

시스템 AI는 같은 자연어 요구와 자료를 독립적으로 받으며 풀이 수단을 강제하지 않는다.
핵심 작업을 네이티브 도구로 처리하면 과제 달성과 IBL 독립 작성 능력을 나누어 보고한다.
훈련자와 AI는 각각 자신의 기본 결과를 받아 변형을 수행한다.
훈련자에게 본 설계의 가설과 제품 지식이 있다는 점을 밝히고, 두 실행의 시간을 곧바로 IBL의 성능 우열로 해석하지 않는다.

품질은 다음 항목을 모두 검수한다.

- 여섯 질문에 근거 있는 답 또는 명시적 미확인이 있고, 사용자가 결정할 수 있는 결론으로 연결된다.
- 주요 사실과 권고의 전제는 사본의 정확한 구간으로 추적된다. 설계·구현·실기 검증을 구별한다.
- 문서 충돌이 없는데 억지로 만들지 않으며, 누락을 기능 부재로 단정하지 않는다.
- 메모와 점검 목록의 결론이 서로 일치하고, 실제 파일을 다시 읽어 내용과 링크를 확인한다.
- 변형은 새 조건의 영향을 설명하고 최초 결과를 보존한다. 관련 없는 결론을 이유 없이 바꾸지 않는다.

파일 존재·해시·인용 구간은 작은 결정적 검사로 확인하고, 의미와 전제는 검수자가 원문과 직접 대조한다.
별도 평가 모델을 추가하지 않는다. 시스템의 기존 평가가 실행되면 해당 비용과 놓친 항목을 기록한다.
완료·부분 달성·미달과 비용 진단의 성패는 별도로 판정한다.

## 비용을 원인까지 추적하는 방법

기존 에피소드·도구 사건·모델 사용량으로 한 타임라인을 만든다. 새 상시 계측 체계는 만들지 않는다.
공급자 토큰이 개별 도구 호출에 배분되지 않으면 임의로 나누지 않고 해당 모델 호출 수준에서 유지한다.

| 관측 | 확인할 내용 |
| --- | --- |
| 자료 발견 | 목록·검색·가이드·describe 호출의 목적, 실제 작업 판단에 쓰인 결과 |
| 자료 재독 | 원천·내용 해시·요청 범위·반환 완전성·재독 이유. IBL과 네이티브 호출을 함께 대조 |
| 작성과 복구 | 거절 문법·위치·제시된 진단·수정량·그 뒤 성공 여부. 기존 회차와 같은 원인인지 확인 |
| 문맥 전달 | 접근 가능한 모델 입력에서 같은 원문·계약·결과가 반복 전달된 구간. 보이지 않는 입력은 미측정 |
| 감독 | 개입의 근거 사건, 실행자의 복구 완료 시점, 지시 생성·전달·처리 시점과 추가 행동 |
| 전체 비용 | 사용자 요청부터 검수 가능한 결과까지의 벽시계, 역할별 input/output/cache와 계측 포함 범위 |

비용이 큰 구간 세 곳 이내를 골라 **무엇을 했는가 → 왜 필요했는가 → 생략하거나 재사용해도 될 근거 → 고칠 위치**를 적는다.
원인을 설명할 수 없으면 후보로 남긴다. 조회·도구·문자 수 감소를 토큰 절감으로 환산하지 않는다.
겹치는 병렬 작업 시간을 합쳐 사용자 대기 시간으로 쓰지 않는다.

반복 작업은 다음 세 가지로 판정한다.

- **필요한 재확인**: 다른 범위·미반환 본문·신선도·최종 산출물 검수 등 새 정보를 얻거나 품질을 보장했다.
- **확인된 중복**: 동일 판본·동일 범위의 충분한 결과가 사용 가능했고 새 정보나 검수 목적 없이 같은 일을 반복했다.
- **추가 확인 후보**: 앞 결과의 가용성·문맥·실제 의도를 확인할 증거가 부족하다.

“작성자 실수”는 책임 분류이지 분석 종료 사유가 아니다. 같은 오류가 최근 다른 과제에서도 관측되면
문법·오류 안내·계약 발견 중 어떤 공통 요소가 영향을 주는지 살핀다. 설명 존재만으로 설명의 효과를 입증하지 않는다.
반대로 단발 실수를 이유로 새 문법·상시 프롬프트를 추가하지 않는다.

## 실행 예산과 범위

훈련 실행 요청을 받으면 기본 60분 상한을 적용한다. 자료·원본 사건 확인 10분,
훈련자 기본·변형 15분, 독립 AI 기본·변형 20분, 품질·비용 대조 10분, 원인 격리 5분을 목표로 한다.
이 배분은 상한을 늘리는 근거가 아니며 새 모델 실행은 종료·회수할 시간을 남겨 두고 시작한다.
운영·기록 비용과 훈련자 모델 사용량도 별도로 남기고, 미측정은 0으로 쓰지 않는다.

현재 기어·모델·리비전을 기록하고 `origin:training`으로 실행한다.
작업 ID와 status URL로 모두 종료를 확인한다. timeout이면 같은 작업을 회수하고 재접수로 대체하지 않는다.
외부 발송·장치 제어가 없는 문서 과제이며, 쓰기는 해당 회차의 산출물에 한정한다.
훈련 중 라이브 구현·프롬프트·교재를 수정하지 않는다. 진단에는 보존된 기록을 우선 사용한다.

훈련 격리는 유지한다. 이 회차로 증류·장기 경험 축적·실사용 대화 전체의 문맥 효과까지 검증했다고 쓰지 않는다.
H3이 발동하지 않으면 과거 사건의 재생 검증을 후속 수리 시험에 연결한다.
새 실험을 억지로 더해 세 가설 모두에 결론을 만들지 않는다.

## 수리와 다른 분야의 검증으로 잇기

이번 설계는 실행·수리 요청을 대신하지 않는다. 훈련 후에는 다음 형식으로 개선 후보를 남긴다.

> 관측 사건과 반복 비용 → 공통 원인과 확신 수준 → 바꿀 계약·표시·진단·기억 경로 →
> 유지할 품질과 없어질 중복 → 원래 과제 및 다른 과제에서 확인할 행동.

기존 원인과 같으면 기존 갭에 증거를 추가한다. 새 갭은 실제 실행 후에만 발급하며 0건도 유효하다.
근거가 충분한 개선을 모두 A/B 대기 상태로 미루지 않는다. 다만 효과를 주장할 때는 효과에 맞는 관측이 있어야 한다.

수리까지 요청받으면 모든 훈련 작업 종료를 확인한 뒤 한 가지 공통 원인을 먼저 수정한다.
원래 요청·입력 판본·모델·완료 조건을 고정해 기본→변형 순서를 다시 실행한다.
수리 전 출력과 정답을 새 실행에 주입하지 않는다. 대화·네이티브 세션·작업 원장을 함께 격리할 수 없으면
엄밀한 전후 비교가 아닌 후속 관측으로 보고한다. 캐시와 서비스 지연, 동시 변경도 별도 조건으로 남긴다.
코드 검사만 통과하고 AI 경로를 다시 보지 못했으면 행동·시간·토큰 효과는 미검증이다.

다른 분야의 전이 검증은 **연구 자료 관리 방식의 도입 검토**로 고정한다.
자료는 `docs/RESEARCH_PROJECT_DESIGN_2026_10_10.md`, `data/guides/research_project.md`,
`data/guides/research_questions.md`의 사본이며, 문서 보존·근거 연결·미완료 질문의 재개를 다룬다.

> 두 사람이 서로 다른 주제를 오래 조사할 예정이야. 원문이 바뀌거나 없어져도 나중에 판단 근거를
> 확인하고, 끝내지 못한 질문을 이어갈 수 있는 자료 관리 방식을 제공한 문서로 검토해 줘.
> 현재 할 수 있는 것과 확인할 조건을 나누고, 시작 절차와 근거를 짧게 저장해 줘.
> 실제 프로젝트 생성이나 자료 등록은 하지 마.

전이 과제는 수리안 작성 전에 요청·자료·품질 기준을 고정하고 실행 결과는 수리 설계에 사용하지 않는다.
수리 이후 한 번의 성공은 다른 분야에서의 작동 확인이며 절감률의 증명은 아니다.
전이 분야의 비용 개선까지 주장하려면 수리 전 기준선도 별도로 확보해야 한다.
이 검증은 원 회차의 60분에 몰아넣지 않고 후속 수리 검증 예산에 포함한다.

## 남길 결과

실행 때 가이드의 회차 폴더에 `task.md`, 최초·수정 IBL, 자료 판본 목록, 독립 요청과 결과,
최소 실행 증거, `report.md`를 남긴다. 보고서 안에 품질 판정과 비용 타임라인 요약을 함께 두고
별도 대시보드·중복 보고서는 만들지 않는다. 민감한 원문·전체 실행 로그는 git에 넣지 않는다.

최종 보고는 **과제 달성 → 가장 큰 비용 구간 → 필요한 비용과 줄일 후보 → 공통 원인 → 다음 검증** 순서다.
“오류 없이 성공”과 “같은 품질을 더 적은 비용으로 달성”을 구별하며,
해결되지 않은 후보가 다음 회차에서 사라지지 않도록 기존 갭 또는 후속 검증 항목에 연결한다.
