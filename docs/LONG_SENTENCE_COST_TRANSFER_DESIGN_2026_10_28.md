# 상상훈련 설계 — 조건 변경의 비용과 다른 과제로의 전이

작성일: 2026-10-28. 상태: **설계 완료·실행 전**.
사용자 요청: 100회차 반성에 대한 논의를 바탕으로, 축적한 능력의 효과를 확인하는 상상훈련을 설계한다.
실행·수리·예약은 이번 요청에 포함하지 않는다. 회차 번호는 실제 시작 때 원장에서 정한다.

## 1. 이번에 답할 질문

**사용자 조건이 바뀌었을 때, 이미 확보한 근거와 결과를 활용하여 품질을 지키면서
필요한 부분을 수정하는가? 그 능력이 다른 과제에서도 나타나며, 개선 전후의 총비용은 어떠한가?**

공통 능력 하나인 ‘조건 변경에 따른 근거 활용과 부분 수정’을 본다. 문법 수·결함 수·IBL 사용률을
목표로 삼지 않는다. 새 기능 입장 시험이나 최근 커밋의 전수 회귀를 이 회차에 끼워 넣지 않는다.
IBL 실행기의 자동 재사용과 에이전트가 기존 근거를 활용하는 행동은 구분한다. 전자가 호출됐다는
사실만으로 후자의 개선이나 전체 비용 절감을 선언하지 않는다.

근거와 절차:

- [진화 목적](IBL_EVOLUTION_PURPOSE.md): 품질·시간·전체 토큰과 다른 작업으로의 적용을 함께 본다.
- [긴문장 가이드](../data/guides/long_sentence_imagination.md), [상상행동 가이드](../data/guides/imagination_action.md): 실행·출처·격리·원장 절차의 정본.
- [10월 19일 비용 설계](LONG_SENTENCE_COST_DISCOVERY_DESIGN_2026_10_19.md): 반복 탐색과 복구 비용의 가설·과제를 계승한다. 설계의 존재를 실행 실적으로 세지 않는다.
- [100회차 보고서](experiments/long_sentence_imagination/round_100/report.md): 재사용 증거의 발견 마찰과 동시 변경에 의한 측정 교란을 반영한다. 진행 표시 수리의 성능 검증으로 대체하지 않는다.

## 2. 최소 실행 구성과 비교의 의미

이번은 **시스템 AI 실행 중심의 상상행동**이다. 훈련자의 전체 IBL과 시스템 AI의 시간을 비교하면
작성자의 사전 지식·해법 차이가 섞이므로 전체 훈련자 실행을 기본으로 추가하지 않는다.
언어 계약 때문에 막혔는지 불명확할 때만 진단 시간 안에서 최소 IBL 재현을 만든다.
따라서 이번 결과만으로 ‘훈련자가 긴 IBL을 쉽게 작성한다’는 능력은 판정하지 않는다.

| 실행 | 내용 | 대화와 공개 시점 | 목적 |
| --- | --- | --- | --- |
| A1 | 회원 PC 도입 검토 | 새 대화 | 최초 품질·경로·비용 기준선 |
| A2 | 오프라인·폴더 격리 조건 추가 | A1 종료 후 같은 대화 | 기존 근거 활용·변경 영향·수정 비용 |
| B1 | 연구 자료 관리 도입 검토 | A와 분리한 새 대화 | 다른 작업에서 같은 능력의 기준선 |
| B2 | 원문 소실·한 달 뒤 재개 조건 추가 | B1 종료 후 같은 대화 | 다른 작업의 조건 변경 수행 |

각 대화에 기본 과제와 후속 과제만 순차적으로 준다. 다른 대화의 답·정답표·평가 가설·후속 요청을
미리 제공하지 않는다. B는 A와 다른 제품 기능을 다루지만 둘 다 문서 기반 도입 검토다.
**이 전이는 가까운 과제 사이의 전이이며, 다른 산업·기기·산출물 형식까지 일반화한 증거는 아니다.**
두 과제는 10월 19일 설계에 공개되어 있었으므로 ‘개발자도 보지 않은 비공개 시험’이라고 부르지 않는다.
실행자에게 정답을 주지 않고 현재 수리의 설계·튜닝에 B 결과를 사용하지 않는 보류 과제로 취급한다.

### 비교 가능한 과거 기록부터 확인한다

준비 시간 안에 보존 기록만 읽고 동일 요청·자료 해시·모델/기어·완료 조건·계측 범위가 맞는
기본→후속 실행 쌍이 있는지 확인한다. 설계 인용 유무만으로 실행 여부를 결정하지 않는다.
없거나 조건이 다르면 **이번 A/B를 새 기준선으로 확정**한다. 옛 코드를 라이브에 되돌려 기준선을 만들지 않는다.

비교는 다음 세 가지를 혼동하지 않는다.

1. A1 대 A2, B1 대 B2: 서로 다른 요구의 비용이다. 후속이 빨라도 개선 전후 절감률이 아니다.
2. 과거 A1→A2 대 현재 A1→A2: 조건이 맞는 경우에만 판본 사이의 관측 차이다. 여러 변경이 있으면 특정 수리의 효과로 귀속하지 않는다.
3. 같은 자료·조건의 수리 전 A/B 대 수리 후 A/B: 한 공통 원인의 수정 효과를 검토하는 후속 비교다.

## 3. 자료를 고정한다

실행 시작 시 아래 파일을 읽기 전용 입력 사본으로 보존한다. 원 경로·바이트 수·SHA-256·수집 시각·
HEAD·관련 미커밋 변경의 지문을 `task.md`에 적는다. 원문 사본은 로컬 회차 폴더에 두고 비밀 값은 제외한다.
각 사본에 문서 ID와 줄 번호를 붙여 인용 좌표를 고정한다. 삭제한 범위도 표시한다.

| 과제 | 입력 문서 |
| --- | --- |
| A | `docs/MEMBER_DESKTOP_DESIGN_2026_10_15.md`, `data/system_docs/remote_access.md`, `data/guides/pc_control.md`, `data/system_docs/anatomy.md` |
| B | `docs/RESEARCH_PROJECT_DESIGN_2026_10_10.md`, `data/guides/research_project.md`, `data/guides/research_questions.md` |

실행자에게는 해당 입력 폴더와 출처 목록을 주고 필요한 범위를 스스로 찾게 한다. 원문 전체를
프롬프트에 넣거나 비용을 부풀리려고 복제하지 않는다. 실제 자료 규모에서 수행한 결과로 한정한다.
사본 판본에 대한 검토이므로 웹 검색·제품 코드 열람·실기 시험으로 자료의 빈칸을 채우지 않는다.

입력·자기 산출물·평소 공개 가이드는 사용할 수 있다. 훈련자의 `harness/`, 정답표, 다른 실행의
결과는 참조하지 않도록 명시하고 접근 기록을 확인한다. 도구 권한으로 격리되지 않았다면
그 한계를 적고, 오염이 관측된 실행은 독립 수행 근거에서 제외한다.

## 4. 실행자에게 줄 요청

각 요청에 실제 입력·출력 경로만 채운다. IBL·함수·재사용 옵션·자료 읽는 순서는 지정하지 않는다.

### A1 — 회원 PC 도입

> 작은 작업실에서 직원 두 명이 각각 Windows와 Mac을 씁니다. 제공한 문서를 근거로,
> 제가 모델 설정을 한곳에서 관리하면서 직원은 자기 PC의 작업 폴더에서 일할 수 있는지 검토해 주세요.
> 현재 시작할 수 있는 범위, 먼저 확인할 조건, 보류할 범위를 구별해 주세요.
> 회원별 실행 위치, 파일 접근 권한, 결과의 저장 위치와 소유, 연결 단절 처리도 설명해 주세요.
> 설계 계획·구현·실제 검증을 구별하고, 문서끼리 다르면 그 차이를 밝혀 주세요.
> 판단 메모와 담당자 점검 목록을 지정한 출력 폴더에 저장하고 주요 판단에 문서 ID와 근거 위치를 붙여 주세요.
> 제공된 사본만으로 검토하며 PC 연결·설치·설정 변경은 하지 마세요.

### A2 — 조건 변경

> Mac 직원은 출장 중 네트워크 없이도 파일 작업을 계속해야 합니다. 직원끼리는 다른 직원의 폴더에
> 접근하지 못해야 합니다. 이 조건으로 앞의 검토를 수정해 주세요. 자료 판본은 그대로입니다.
> 처음 결과를 보존하고 새 파일에 바뀐 결론, 유지되는 결론, 추가 확인할 질문과 근거를 구별해 주세요.
> 앞서 정한 다른 요구는 유지합니다. 실제 장치 시험은 하지 마세요.

### B1 — 연구 자료 관리

> 두 사람이 서로 다른 주제를 오래 조사하려 합니다. 제공된 문서를 근거로 원문과 판단 근거를
> 보존하고 미완료 질문을 이어갈 자료 관리 방식을 검토해 주세요. 대화별 자료의 범위,
> 확보한 원문과 검색 결과의 차이, 자료 판본, 질문과 잠정 결론의 보존을 설명해 주세요.
> 지금 가능한 범위와 확인할 조건을 구별한 판단 메모와 시작 점검 목록을 지정한 폴더에 저장하고,
> 주요 판단에 문서 ID와 근거 위치를 붙여 주세요. 제공된 사본만 사용하고 실제 프로젝트 생성이나 자료 등록은 하지 마세요.

### B2 — 조건 변경

> 조사한 웹 원문이 나중에 바뀌거나 사라져도 당시 판단 근거를 확인할 수 있어야 합니다.
> 한 달 뒤에는 아직 답하지 못한 질문과 당시의 잠정 결론을 구별해서 이어가야 합니다.
> 이 조건에 맞춰 앞의 검토를 수정해 주세요. 자료 판본과 다른 요구는 그대로입니다.
> 처음 결과를 보존하고 바뀐 결론, 유지되는 결론, 추가 확인할 질문과 근거를 새 파일에 적어 주세요.
> 실제 웹 수집이나 프로젝트 변경은 하지 마세요.

추가 질문에 답할 운영자 규칙: 자료에 없는 조직·권한·운영 정보는 ‘아직 정하지 않았으니
조건부 결론과 확인 질문으로 남겨 달라’고 답한다. 새 사실이나 유리한 해법을 즉석에서 주지 않는다.

## 5. 결과를 보기 전에 확정할 품질 기준

운영자는 준비 단계에 사본에서 다음 항목의 기대 주장·근거 좌표·답변 불가 범위를 정답표로 확정한다.
정답표는 제품에 대한 기억으로 쓰지 않고 해당 판본을 직접 대조한다. 준비 시간 안에 확정할 수 없으면
모델 실행을 시작하지 않고 준비 미완료로 기록한다. 후속 결과에 맞춰 기대값을 낮추지 않는다.

| 대상 | 필수 검수 항목 |
| --- | --- |
| A1 | 중앙 모델 관리, 회원별 실행 위치, 로컬 권한, 결과 소유·저장, 연결 단절, Windows/Mac 인수 범위의 여섯 항목 |
| A2 | 오프라인 작업 요구와 기존 연결 단절 설명을 구별, 직원 간 폴더 접근의 보장 범위·한계 확인, 영향받는 추천·질문 갱신 |
| B1 | 대화별 자료 범위, 실제 확보와 검색 발췌의 구별, 원문 판본, 질문·잠정 결론 보존의 네 항목 |
| B2 | 원문 변경/소실 뒤 당시 근거 확인의 조건, 미확보 자료의 한계, 미완료 질문과 잠정 결론의 재개 조건 갱신 |
| 공통 | 계획·구현·실검증 구별, 핵심 주장의 근거 정확성, 문서 충돌·미확인의 정직한 표시, 메모와 목록의 일치 |
| 후속 공통 | 최초 파일 보존, 변경·유지·미확인 구별, 무관한 요구의 누락 없음, 실제 저장 파일 확인 |

필수 항목마다 충족/미충족/판정 불가와 근거를 남긴다. 자료가 답하지 못하는 기능은 명시적 미확인이
올바른 결과다. 근거 없는 지원 보장이나 요청 누락을 문장 품질 점수로 상쇄하지 않는다.
전체 달성은 필수 항목을 모두 충족했을 때만 인정한다. 운영자가 고친 결과는 최초 결과와 분리한다.

## 6. 최소 계측과 비용 판정

새 상시 계측기나 별도 평가 모델을 만들지 않는다. 기존 에피소드·도구 사건·모델 usage와 산출물을 쓴다.
`origin:"training"`을 사용하고 기본·후속의 대화 연결, 작업 ID·episode ID·코드 세대·종료 상태를 기록한다.
진입점과 회수 절차는 현행 가이드 §4-5를 따른다. 실행 중 API 계약을 추측하여 새 경로를 만들지 않는다.

| 기록 | 집계 방법 |
| --- | --- |
| 과제 품질 | 위 필수 항목별 판정과 운영자의 수정 필요 내용 |
| 시간 | 요청→실제 파일 준비, 요청→검수 완료를 분리. 각 턴과 기본+후속 합계를 기록 |
| 모델 사용 | 실행·내부 AI·감독·검수 등 역할별 input/output/cache_read/cache_create, 공급자 정의와 포함 범위 기록 |
| 작성 마찰 | 검사 거절·재작성 주기·추가 도움·사용자 개입, 같은 오류의 재발 여부 |
| 근거 활용 | 읽은 문서/범위/해시, 앞 결과의 참조, 새 판단의 대상. 중복 후보는 큰 구간 세 곳 이내만 분석 |
| 훈련 운영 | 자료 준비·정답표·실행 관리·보고·진단의 시간과 훈련자 모델 사용량. 후속 수리는 별도 집계 |

에피소드 합계와 개별 usage를 함께 더하지 않는다. input에 캐시가 포함되는지는 공급자 계약으로 확인하고
모르면 분리 불가로 남긴다. 실제 요금은 청구값 또는 확인된 단가·사용량이 있을 때만 산출한다.
훈련자 토큰을 얻지 못하면 미측정으로 쓰고 **훈련 전체의 총비용은 불완전**하다고 보고한다.
프로그램 내부 AI 호출 0을 훈련자 비용 0으로 쓰지 않는다.

동일 자료를 다시 읽었어도 다른 범위·부족했던 맥락·검수 목적이면 필요한 비용일 수 있다.
동일 판본·범위의 충분한 결과가 사용 가능했고 새 정보나 검수 목적이 없다는 증거가 있어야 중복으로 판정한다.
도구 기록에 필요한 입력이 보이지 않으면 낭비 확정 대신 관측 한계로 남긴다.
IBL이 아닌 도구를 쓴 것은 실패가 아니다. 경로별 비용과 결과를 그대로 기록한다.

## 7. 예산·환경·중단 기준

이번 실행 상한은 **60분, 과제 요청 4회(A1·A2·B1·B2)**다.
필수 확인 질문의 답변은 대화별 최대 1턴을 추가할 수 있어 사용자 턴의 총상한은 6회다.
확인 답변도 같은 시간 예산에 포함한다. 시스템 내부 모델 호출 수는 실제로 집계하며,
실패한 과제를 다시 보내 성공 사례를 고르지 않는다.

| 구간 | 상한 배분 |
| --- | --- |
| 환경·과거 기준선 확인·사본·정답표 고정 | 15분 |
| A1→A2 | 15분 |
| B1→B2 | 15분 |
| 품질 대조·비용 집계·필요시 최소 재현·보고 | 15분 |

한 턴은 최대 7분을 관측 예산으로 두고, 시간 초과 시 기존 작업의 종료·취소·회수를 우선한다.
클라이언트 timeout을 종료로 간주하거나 재접수하지 않는다. 남은 예산으로 다음 과제와 검수를
끝낼 수 없으면 시작하지 않는다. 보고·정리가 상한을 넘으면 시간을 별도로 적고 실험은 늘리지 않는다.
입력/출력 토큰은 진행 중 계측 가능한 범위를 밝힌다. 모든 역할을 포괄하는 강제 토큰 상한을
지원하지 않는다면 있다고 주장하지 않는다. 사용자 지정 비용 한도가 있으면 그 한도를 우선한다.

같은 모델·기어·자료·완료 조건을 유지하고 모델 판본, 캐시 상태, 서비스 지연, 기기 부하를 기록한다.
훈련 중 라이브 코드·프롬프트·교재를 바꾸지 않는다. 다른 세션의 편집으로 코드 세대나 관련 입력이
바뀌면 해당 실행은 품질 관측으로만 보존하고 안정된 판본의 성능 비교에서 제외한다.
측정 창을 확보할 수 없으면 안정화 대기로 기록하며 강제 재기동이나 다른 세션 중단을 하지 않는다.

외부 행동은 없으며 읽기 전용 사본과 회차 출력만 사용한다. 새 훈련 실행을 위해 실사용 메모리·
캐시·대화를 삭제하지 않는다. 실행 사이의 장기 기억·공유 상태를 격리할 수 없으면 비교의 한계로 적는다.

## 8. 수리와 효과 확인은 어떻게 이어지는가

이번 결과가 정상이라도 낭비를 만들어 내지 않는다. 발견이 있으면 최소 재현·관측·영향·유지할
품질을 남기고, 가장 큰 공통 원인 하나를 후속 수리 후보로 정한다. 작성자 실수도 반복성과 안내의
발견 가능성을 분석하되 단발 오류마다 상시 프롬프트나 새 어휘를 추가하지 않는다.

수리는 별도 요청 범위다. 요청받았으면 같은 날에도 할 수 있지만 모든 훈련 작업 종료와 최초 증거
보존을 먼저 확인한다. 재현 가능한 결함은 수리 전 실패하는 회귀시험으로 남기고, 계약 공백이나
정책 선택은 먼저 그 판정을 명시한다. 발견자·수리자·검토자의 역할과 검증 범위를 기록한다.
반드시 다른 날짜나 다른 모델이어야 하는 것은 아니며, 동일 작성자의 검토를 독립 감사라 부르지 않는다.

수리 후 검증은 새 세션에서 **A1→A2와 B1→B2 전체 쌍**을 같은 사본·모델·조건으로 재실행한다.
기준선의 답·정답표·초안은 주입하지 않는다. A 결과로 수정할 때 수리자는 B의 상세 출력·실행 경로를
수정 확정 전까지 열람하거나 튜닝에 사용하지 않는다. 기준선 보고에 필요한 B의 품질·비용 요약은 남긴다.
같은 세션에서 이미 B 상세 결과를 읽었다면 그 한계를 공개하고 ‘수리자가 보지 않은 과제’라고 쓰지 않는다.
B를 수리에 사용했다면 보류 시험 지위를 해제하고, 별도의 새 과제·기준선을 준비하기 전에는
미사용 과제로의 전이가 입증됐다고 쓰지 않는다. 이 후속 실행은 별도 60분 예산이며 자동 예약하지 않는다.

### 사전에 정하는 결론의 수준

- **능력 확인:** 해당 판본에서 기본·후속의 품질 기준을 통과했다. 전후 절감 주장은 없음.
- **전이 관측:** A에서 확인한 행동이 B에서도 나타났다. 가까운 두 과제의 결과로 한정한다.
- **개선 후보:** 비교 가능한 전후에서 품질을 유지하고 시간·전체 토큰이 함께 줄었다. 작업별 원자료와 차이를 제시한다.
- **부분 성과:** 품질이나 한 비용 축만 좋아졌거나 다른 축이 악화됐다. 상충을 숨기지 않는다.
- **미판정:** 기준선·계측 누락, 판본/조건 변경, 결과 오염, 예산 중단으로 비교할 수 없다.

한 번씩의 전후 실행은 관측 차이이지 안정적인 절감률의 증명이 아니다. 효과가 작거나 조건 차이가
큰 경우 결론을 유보한다. 반복 검증이 필요한 후보만 별도 예산에서 동일 조건의 쌍을 총 3회 이상
확인하고 개별값·범위를 보존한다. 3회도 통계적 확증을 보장하지 않으며 평균만으로 퇴행을 가리지 않는다.
초기 작성·등록·훈련·수리 비용은 매회 실행 비용과 분리하고, 반복 사용으로 회수되는지 검토한다.

## 9. 실행 후 남길 최소 결과

기존 회차 폴더의 `task.md`에는 사본 목록·기대 기준·비교 조건·예산을, `report.md`에는
아래 표와 주요 비용 구간 세 곳 이내·발견·미검증을 쓴다. 재현 가능한 비민감 증거만
`docs/experiments/long_sentence_imagination/round_N/`에 남기고 큰 원문·로그는 로컬 `outputs/`에 둔다.
정답표는 실행자 입력과 분리해 보존한다. 실행 때 기존 원장의 요약과 갭 표를 함께 갱신한다.
이번 설계 단계에는 실행 원장·회차·갭 ID를 만들지 않는다.

| A 기준선 | 실행 후 기입 | | | | | |
| B 기준선 | 실행 후 기입 | | | | | |
| A 개선 후 | 후속 수리를 수행했을 때만 | | | | | |
| B 개선 후 | 후속 수리를 수행했을 때만 | | | | | |

훈련 운영 비용과 후속 수리 비용은 표 아래 별도로 적는다. 마지막 판정은

무엇을 주장할 수 없는가’ 순서로 작성한다. 가이드에 새 문장을 넣는 것을 효과 확인으로 세지 않는다.
