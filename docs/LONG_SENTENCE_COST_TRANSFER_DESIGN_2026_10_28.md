# 긴문장 상상훈련 설계 — 더 큰 일의 완수와 능력 축적

작성·운영 개정일: 2026-10-28. 상태: **능력 성장 중심으로 운영 설계 정정; 이번 개정에서 실행 없음**.
초판의 A/B 보조 과제는 101회차에 실행됐다. 최초 설계는 git 이력에, 실행 당시 계약·원본·사후 판정은
[101회차 기록](experiments/long_sentence_imagination/round_101/report.md)에 보존한다.
현재 기본 훈련은 §1~2이며, §3~9는 선택적 비용·전이 실험이다. 회차 번호는 실제 시작 때 정한다.

## 1. 본래 목적과 운영 원칙

**낯설고 더 큰 일을 끝까지 수행하고, 그 해결 능력을 다음 과제의 조합 단위로 축적한다.**
요구를 분해하고 IBL로 표현·조합하며, 실행 결과와 근거를 보존하고, 실패한 부분을 복구해
실제 산출물까지 완수한다. 그 과정의 공통 한계를 개선하고 새 과제에서 다시 쓴다.

기본 성장 경로는 **새 요구 → 전체 프로그램 → 실행·검수·복구 → 검증된 부품과 계약 →
다른 부품과 재조합한 더 큰 일**이다. 기존 기능을 단순 반복하거나 문서 오류를 찾는 데 머물지 않는다.
새 기기·원천·패키지의 이음새는 좋은 후보지만, 훈련을 여는 필수 사건은 아니다.
현재 부품만으로도 더 깊은 의존 관계·다른 산출물·새로운 조건을 가진 일을 상상하고 실행한다.

품질을 유지·높이면서 완료 시간과 전체 토큰을 줄이는 것이 진화 목적이다. **능력의 성장과
비용 개선은 각각 증거로 판단한다.** 비용 기준선·완전한 계측·정답표·독립 감사가 없다는 이유로
훈련·능력 축적·공통 개선을 미루지 않는다. 절감을 입증하지 못했으면 절감만 미판정으로 남긴다.
사용자가 정한 예산·실행 범위와 권한·외부 효과 격리는 계속 지킨다.

근거와 절차:

- [진화 목적](IBL_EVOLUTION_PURPOSE.md): 큰 행위의 조합·축적과 품질·시간·전체 토큰.
- [긴문장 가이드](../data/guides/long_sentence_imagination.md): 작성·실행·출처·격리·원장 절차의 정본.
- [상상행동 가이드](../data/guides/imagination_action.md): 자연어 요구에서 독립 수행까지.
- [10월 19일 비용 설계](LONG_SENTENCE_COST_DISCOVERY_DESIGN_2026_10_19.md): 비용을 조사하는 선택 과제. 모든 훈련의 입장 조건이 아니다.
- [101회차 정정 보고서](experiments/long_sentence_imagination/round_101/report.md): 품질 일부 미충족, 독립 전이·비용 개선 미검증. 그 범위를 훈련 전체의 한계로 확대하지 않는다.

## 2. 기본 훈련 — 완수하고 축적한 것으로 더 큰 일 하기

### 과제와 성장 경로

시작할 때 `task.md`에 **완수할 일·완료 조건·가져다 쓸 부품·확장할 능력·실행 범위와 예산**을 적는다.
정확한 답을 미리 알 수 없는 과제는 근거·품질·실패 표시 조건을 정한다. 기존 기록은 활용하되
전 회차의 모든 감사·수리·비용 집계 완료를 기다리지 않는다. 새 과제에 직접 필요한 미해결 경계만 드러낸다.

다음은 분야를 바꿔 사용할 수 있는 설계 예시이며, 실행 성과나 지원 능력의 보증은 아니다.

| 흐름 | 수행할 일 | 남길 능력과 증거 |
| --- | --- | --- |
| 주 과제 | 여러 형식의 요구·일정·견적을 결합해 충돌과 누락을 확인하고, 실행 가능한 계획·항목별 산출물·근거표를 함께 만든다. | 읽기·정규화·결합·판단·산출물 작성의 전체 IBL과 실제 결과. 일부 자료 실패도 보존한다. |
| 조건 변경·복구 | 자원·일정 조건이 바뀌거나 일부 원천이 실패하면 영향받는 부분을 찾아 갱신하고 전체 결과의 일관성을 확인한다. | 보존된 중간 결과·실패 위치·재개 입력, 실제 재사용과 재실행 범위. |
| 축적 | 실제로 통과한 부분을 입력·반환·적용 조건·외부 효과·실패/복구·검증 범위와 함께 보존한다. | 찾을 수 있는 프로그램·파일·결과 참조. 등록 전에도 조합하며 등록 자체를 능력의 증거로 세지 않는다. |
| 더 큰 재조합 | 검증된 결합·계획 부품을 새로운 원천과 연결해, 예를 들어 여러 작업 장소의 배치·조달·일정 변경을 함께 처리한다. | 새 전체 프로그램과 사용 가능한 산출물, 어떤 이전 부품을 실제 사용했는지. 이름·행 수만 바꾼 반복과 구별한다. |

기본 한 회차는 주 과제와 변형 하나다. 재조합은 변형 안에서 수행할 수도 있고 다음 회차의 주 과제가
될 수도 있다. 모든 확장을 한 회차에 강제하지 않으며, 아직 수행하지 않은 재조합은 후보라고 기록한다.
한 회차보다 큰 과제는 전체 목표를 유지한 단계·입출력 참조·재개점으로 나눈다. 상한에서 멈추면
완료 범위와 남은 요구를 보존하고 부분 달성으로 보고한다. 쉬운 과제로 바꾸어 원래 일을 완수했다고 하지 않는다.

### 실제 수행과 시스템 AI

훈련자는 전체 흐름을 IBL로 작성하고 실제 실행한다. 검사 통과·실행 종료·사용 가능한 결과를
각각 확인한다. 필요할 때 수정·복구하여 완료까지 진행하며 최초 시도와 도움 뒤 결과를 구별한다.
독립적인 분해·발견·조합·완료와 이전 능력의 활용을 보려면 같은 자연어 과제를 시스템 AI에 맡긴다.
훈련자 첫 초안이 통과했거나 비용 기준선이 없다는 이유로 독립 수행을 자동 생략하지 않는다.
상상행동이 중심인 회차는 시스템 AI 실행을 중심으로 하고, 언어 작성만 보는 회차는 범위를 명시한다.
모든 회차에 이중 실행·여러 대화·여러 모델을 강제하지 않으며 실제 확인한 능력만 보고한다.

### 훈련을 지원하는 비용·검토·수리

- **비용:** 기존 기록에서 관측할 수 있는 시간·역할별 토큰·수정량을 수집한다. 미측정 범위를 밝히고 실행한다. 동일 조건의 비교는 절감 주장에 필요하며 능력 성장 훈련의 선행 조건은 아니다.
- **검토:** 핵심 완료 조건·근거·실패 표시와 다음 사용에 필요한 계약을 확인한다. 사용을 막는 오류는 바로 정정하고 불확실한 부분은 구별한다. 모든 인용·문서·과거 보고서의 완전 감사로 범위를 늘리지 않는다.
- **수리:** 작성 프로그램의 수정·복구는 훈련 안에서 한다. 시스템의 공통 결함은 최소 재현·영향·소유 위치·확인 방법과 함께 기존 수리 흐름에 연결하고, 수리까지 맡은 범위에서는 최초 증거 보존과 실행 종료 후 처리한다. 비용 개선 입증이나 독립 감사 완료를 수리 착수 조건으로 삼지 않는다.
- **진행:** 사용자 상한과 실제 권한·격리 제약은 지킨다. 안정된 비용 비교가 불가능한 경우와 실제 실행이 불가능한 경우를 구분한다. 전자는 비교 한계를 적고 수행하며 후자는 막힌 경계와 재개 조건을 남긴다.

회차의 핵심 결과는 **완수한 일, 재사용한 능력, 새로 축적한 프로그램·계약, 드러난 공통 한계**다.
회귀검사는 최근 변경의 정확성을 담당하고, 훈련은 기존 부품으로 아직 해보지 않은 전체 일을 수행한다.
새 결함이 없어도 더 큰 일을 완수하고 재조합한 증거는 성과다. 비용 절감이 없으면 그 사실도 함께 남긴다.

### 선택적 보조 실험 — 조건 변경 비용과 가까운 과제로의 전이

아래 §3~9의 A/B는 101회차에 사용한 문서 도입 검토 과제다. 이 파일의 변경 전 판본과
[실행 전 계약](experiments/long_sentence_imagination/round_101/task.md)·원본 산출물은 과거 실행의 근거이며,
현행 운영 정정으로 당시 수행 범위를 바꾸지 않는다. 이 보조 실험은 기본 훈련을 대신하지 않는다.
재실행하려면 별도 실행 범위에서 선택한다. 이번 문서 개정은 재실행 요청이 아니다.

| 실행 | 내용 | 의도한 대화 조건 | 관측 대상 |
| --- | --- | --- | --- |
| A1 | 회원 PC 도입 검토 | 새 대화 | 최초 품질·경로·비용 |
| A2 | 오프라인·폴더 격리 조건 추가 | A1 종료 후 같은 대화 | 근거 활용·변경 영향 |
| B1 | 연구 자료 관리 도입 검토 | A와 분리한 새 대화 | 다른 작업의 수행 |
| B2 | 원문 소실·한 달 뒤 재개 조건 추가 | B1 종료 후 같은 대화 | 다른 작업의 조건 변경 |

101회차는 공유 세션에서 실행되어 독립 전이를 입증하지 못했다. 새로운 비교에서도 대화·자료 격리를
확인하지 못하면 독립 비교라 부르지 않는다. 가능한 수행 관측까지 포기할 이유는 아니며 범위를 명시한다.
이 A/B는 시스템 AI 중심이며 훈련자 전체 IBL 작성 능력을 판정하지 않는다. B도 문서 검토라서
다른 산업·기기·산출물 형식까지 일반화할 수 없고, 이미 공개된 과제를 비공개 시험이라 하지 않는다.

비교 가능한 과거 요청·자료·모델·완료 조건이 없으면 이번 기록을 관측 기준선으로 남긴다.
기본 대 후속은 서로 다른 요구의 비용이며 전후 절감률이 아니다. 판본 간 비교는 조건 차이를 밝힌다.
IBL 자동 재사용과 에이전트의 근거 활용도 구별하며, 재사용 호출만으로 전체 절감을 선언하지 않는다.

## 3. 보조 실험의 자료를 고정한다

실행 시작 시 아래 파일을 읽기 전용 입력 사본으로 보존한다. 원 경로·바이트 수·SHA-256·수집 시각·
HEAD·관련 미커밋 변경의 지문을 `task.md`에 적는다. 원문 사본은 로컬 회차 폴더에 두고 비밀 값은 제외한다.
각 사본에 문서 ID와 줄 번호를 붙여 인용 좌표를 고정한다. 삭제한 범위도 표시한다.

| 과제 | 입력 문서 |
| --- | --- |
| A | `docs/MEMBER_DESKTOP_DESIGN_2026_10_15.md`, `data/system_docs/remote_access.md`, `data/guides/pc_control.md`, `data/system_docs/anatomy.md` |
| B | `docs/RESEARCH_PROJECT_DESIGN_2026_10_10.md`, `data/guides/research_project.md`, `data/guides/research_questions.md` |

실행자에게는 해당 입력 폴더와 출처 목록을 주고 필요한 범위를 스스로 찾게 한다. 원문 전체를
프롬프트에 넣거나 비용을 부풀리려고 복제하지 않는다. 실제 자료 규모에서 수행한 결과로 한정한다.
사본 판본에 대한 검토이므로 웹 검색·제품 코드 열람·실기 시험으로 자료의 빈칸을 채우지 않는다.

입력·자기 산출물·평소 공개 가이드는 사용할 수 있다. 훈련자의 `harness/`, 정답표, 다른 실행의
결과는 참조하지 않도록 명시하고 접근 기록을 확인한다. 도구 권한으로 격리되지 않았다면
그 한계를 적고, 오염이 관측된 실행은 독립 수행 근거에서 제외한다.

## 4. 실행자에게 줄 요청

각 요청에 실제 입력·출력 경로만 채운다. IBL·함수·재사용 옵션·자료 읽는 순서는 지정하지 않는다.

### A1 — 회원 PC 도입

> 작은 작업실에서 직원 두 명이 각각 Windows와 Mac을 씁니다. 제공한 문서를 근거로,
> 제가 모델 설정을 한곳에서 관리하면서 직원은 자기 PC의 작업 폴더에서 일할 수 있는지 검토해 주세요.
> 현재 시작할 수 있는 범위, 먼저 확인할 조건, 보류할 범위를 구별해 주세요.
> 회원별 실행 위치, 파일 접근 권한, 결과의 저장 위치와 소유, 연결 단절 처리도 설명해 주세요.
> 설계 계획·구현·실제 검증을 구별하고, 문서끼리 다르면 그 차이를 밝혀 주세요.
> 판단 메모와 담당자 점검 목록을 지정한 출력 폴더에 저장하고 주요 판단에 문서 ID와 근거 위치를 붙여 주세요.
> 제공된 사본만으로 검토하며 PC 연결·설치·설정 변경은 하지 마세요.

### A2 — 조건 변경

> Mac 직원은 출장 중 네트워크 없이도 파일 작업을 계속해야 합니다. 직원끼리는 다른 직원의 폴더에
> 접근하지 못해야 합니다. 이 조건으로 앞의 검토를 수정해 주세요. 자료 판본은 그대로입니다.
> 처음 결과를 보존하고 새 파일에 바뀐 결론, 유지되는 결론, 추가 확인할 질문과 근거를 구별해 주세요.

## 5. 결과를 보기 전에 확정할 품질 기준

운영자는 실행 전에 아래 필수 요구와 근거 확인 방법을 정하고, 사본으로 확정할 수 있는 기대 주장·
근거 좌표·답변 불가 범위를 적는다. 제품 기억으로 정답을 만들지 않는다. 준비 시간에 확정하지 못한
항목은 미확인으로 표시하고 수행한다. 완전한 정답표를 기다리며 훈련을 미루지 않으며, 사후에는
보존 사본으로 대조한다. 판정 불가를 충족으로 올리거나 결과에 맞춰 요구를 낮추지 않는다.

| 대상 | 필수 검수 항목 |
| --- | --- |
| A1 | 중앙 모델 관리, 회원별 실행 위치, 로컬 권한, 결과 소유·저장, 연결 단절, Windows/Mac 인수 범위의 여섯 항목 |
| A2 | 오프라인 작업 요구와 기존 연결 단절 설명을 구별, 직원 간 폴더 접근의 보장 범위·한계 확인, 영향받는 추천·질문 갱신 |
| B1 | 대화별 자료 범위, 실제 확보와 검색 발췌의 구별, 원문 판본, 질문·잠정 결론 보존의 네 항목 |
| B2 | 원문 변경/소실 뒤 당시 근거 확인의 조건, 미확보 자료의 한계, 미완료 질문과 잠정 결론의 재개 조건 갱신 |
| 공통 | 계획·구현·실검증 구별, 핵심 주장의 근거 정확성, 문서 충돌·미확인의 정직한 표시, 메모와 목록의 일치 |
| 후속 공통 | 최초 파일 보존, 변경·유지·미확인 구별, 무관한 요구의 누락 없음, 실제 저장 파일 확인 |

필수 항목마다 충족/미충족/판정 불가와 근거를 남긴다. 자료가 답하지 못하는 기능은 명시적 미확인이
올바른 결과다. 근거 없는 지원 보장이나 요청 누락을 문장 품질 점수로 상쇄하지 않는다.
전체 달성은 필수 항목을 모두 충족했을 때만 인정한다. 운영자가 고친 결과는 최초 결과와 분리한다.

## 6. 최소 계측과 비용 판정

새 상시 계측기나 별도 평가 모델을 만들지 않는다. 기존 에피소드·도구 사건·모델 usage와 산출물을 쓴다.
`origin:"training"`을 사용하고 기본·후속의 대화 연결, 작업 ID·episode ID·코드 세대·종료 상태를 기록한다.
진입점과 회수 절차는 현행 가이드 §4-5를 따른다. 실행 중 API 계약을 추측하여 새 경로를 만들지 않는다.

| 기록 | 집계 방법 |
| --- | --- |
| 과제 품질 | 위 필수 항목별 판정과 운영자의 수정 필요 내용 |
| 시간 | 요청→실제 파일 준비, 요청→검수 완료를 분리. 각 턴과 기본+후속 합계를 기록 |
| 모델 사용 | 실행·내부 AI·감독·검수 등 역할별 input/output/cache_read/cache_create, 공급자 정의와 포함 범위 기록 |
| 작성 마찰 | 검사 거절·재작성 주기·추가 도움·사용자 개입, 같은 오류의 재발 여부 |
| 근거 활용 | 읽은 문서/범위/해시, 앞 결과의 참조, 새 판단의 대상. 중복 후보는 큰 구간 세 곳 이내만 분석 |
| 훈련 운영 | 자료 준비·정답표·실행 관리·보고·진단의 시간과 훈련자 모델 사용량. 후속 수리는 별도 집계 |

에피소드 합계와 개별 usage를 함께 더하지 않는다. input에 캐시가 포함되는지는 공급자 계약으로 확인하고
모르면 분리 불가로 남긴다. 실제 요금은 청구값 또는 확인된 단가·사용량이 있을 때만 산출한다.
훈련자 토큰을 얻지 못하면 미측정으로 쓰고 **훈련 전체의 총비용은 불완전**하다고 보고한다.
프로그램 내부 AI 호출 0을 훈련자 비용 0으로 쓰지 않는다.

동일 자료를 다시 읽었어도 다른 범위·부족했던 맥락·검수 목적이면 필요한 비용일 수 있다.
동일 판본·범위의 충분한 결과가 사용 가능했고 새 정보나 검수 목적이 없다는 증거가 있어야 중복으로 판정한다.
도구 기록에 필요한 입력이 보이지 않으면 낭비 확정 대신 관측 한계로 남긴다.
IBL이 아닌 도구를 쓴 것은 실패가 아니다. 경로별 비용과 결과를 그대로 기록한다.

## 7. 보조 실험의 예산·환경·중단 기준

이 보조 실험을 선택했을 때의 상한은 **60분, 과제 요청 4회(A1·A2·B1·B2)**다. 기본 훈련은 가이드의 예산을 따른다.
필수 확인 질문의 답변은 대화별 최대 1턴을 추가할 수 있어 사용자 턴의 총상한은 6회다.
확인 답변도 같은 시간 예산에 포함한다. 시스템 내부 모델 호출 수는 실제로 집계하며,
실패한 과제를 다시 보내 성공 사례를 고르지 않는다.

| 구간 | 목표 배분(전체 상한 안에서 조정) |
| --- | --- |
| 환경·사본·완료 조건, 있는 기준선 확인 | 15분 |
| A1→A2 | 15분 |
| B1→B2 | 15분 |
| 품질 대조·비용 집계·필요시 최소 재현·보고 | 15분 |

한 턴은 7분을 목표로 관측하되 실제 실행 중이면 전체 상한 안에서 기존 작업을 회수한다.
클라이언트 timeout을 종료로 간주하거나 재접수하지 않는다. 준비·정답표·상세 비용 분석이 수행 시간을
소진하지 않게 하고, 남은 예산으로 완료할 수 있는 범위를 실행한다. 상한에서는 완료 범위·남은 조건·
재개점을 보존한다. 보고·정리가 상한을 넘으면 시간을 별도로 적고 실험은 늘리지 않는다.
입력/출력 토큰은 진행 중 계측 가능한 범위를 밝힌다. 모든 역할을 포괄하는 강제 토큰 상한을
지원하지 않는다면 있다고 주장하지 않는다. 사용자 지정 비용 한도가 있으면 그 한도를 우선한다.

같은 모델·기어·자료·완료 조건을 유지하고 모델 판본, 캐시 상태, 서비스 지연, 기기 부하를 기록한다.
훈련 중 라이브 코드·프롬프트·교재를 바꾸지 않는다. 다른 세션의 편집으로 코드 세대나 관련 입력이
바뀌면 해당 실행은 품질 관측으로만 보존하고 안정된 판본의 성능 비교에서 제외한다.
안정된 측정 창을 확보하지 못해도 실행 가능한 훈련은 계속하고 판본·비교 한계를 적는다. 실제 실행이나
권한·격리가 불가능할 때만 해당 경로를 보류한다. 강제 재기동이나 다른 세션 중단으로 측정 창을 만들지 않는다.

외부 행동은 없으며 읽기 전용 사본과 회차 출력만 사용한다. 새 훈련 실행을 위해 실사용 메모리·
캐시·대화를 삭제하지 않는다. 실행 사이의 장기 기억·공유 상태를 격리할 수 없으면 비교의 한계로 적는다.

## 8. 수리와 효과 확인은 어떻게 이어지는가

이번 결과가 정상이라도 낭비를 만들어 내지 않는다. 발견이 있으면 최소 재현·관측·영향·유지할
품질을 남기고, 가장 큰 공통 원인 하나를 후속 수리 후보로 정한다. 작성자 실수도 반복성과 안내의
발견 가능성을 분석하되 단발 오류마다 상시 프롬프트나 새 어휘를 추가하지 않는다.

수리는 별도 요청 범위다. 요청받았으면 같은 날에도 할 수 있지만 모든 훈련 작업 종료와 최초 증거
보존을 먼저 확인한다. 재현 가능한 결함은 수리 전 실패하는 회귀시험으로 남기고, 계약 공백이나
정책 선택은 먼저 그 판정을 명시한다. 발견자·수리자·검토자의 역할과 검증 범위를 기록한다.
반드시 다른 날짜나 다른 모델이어야 하는 것은 아니며, 동일 작성자의 검토를 독립 감사라 부르지 않는다.

수리 자체는 해당 계약의 회귀검사와 원래 전체 과제·새 변형에서 확인한다. A/B 비용·전이 효과를
비교하기로 한 경우에만 새 세션에서 **A1→A2와 B1→B2 전체 쌍**을 같은 사본·모델·조건으로 재실행한다.
이 비교가 없으면 비용·독립 전이 주장을 유보하며, 수리한 능력의 활용이나 다음 훈련을 미루지 않는다.
기준선의 답·정답표·초안은 주입하지 않는다. A 결과로 수정할 때 수리자는 B의 상세 출력·실행 경로를
수정 확정 전까지 열람하거나 튜닝에 사용하지 않는다. 기준선 보고에 필요한 B의 품질·비용 요약은 남긴다.
같은 세션에서 이미 B 상세 결과를 읽었다면 그 한계를 공개하고 ‘수리자가 보지 않은 과제’라고 쓰지 않는다.
B를 수리에 사용했다면 보류 시험 지위를 해제하고, 별도의 새 과제·기준선을 준비하기 전에는
미사용 과제로의 전이가 입증됐다고 쓰지 않는다. 이 후속 실행은 별도 60분 예산이며 자동 예약하지 않는다.

### 사전에 정하는 결론의 수준

- **능력 확인:** 해당 판본에서 기본·후속의 품질 기준을 통과했다. 전후 절감 주장은 없음.
- **전이 관측:** A에서 확인한 행동이 B에서도 나타났다. 가까운 두 과제의 결과로 한정한다.
- **개선 후보:** 비교 가능한 전후에서 품질을 유지하고 시간·전체 토큰이 함께 줄었다. 작업별 원자료와 차이를 제시한다.
- **부분 성과:** 품질이나 한 비용 축만 좋아졌거나 다른 축이 악화됐다. 상충을 숨기지 않는다.
- **비용·전이 미판정:** 기준선·계측 누락, 판본/조건 변경, 결과 오염 등으로 해당 비교를 할 수 없다. 별도로 확인한 과제 달성·능력 축적은 그대로 기록한다.
- **부분 달성/미검증:** 요구 일부 미충족이나 예산 중단으로 완수하지 못한 범위다. 비용 미판정과 구별한다.

한 번씩의 전후 실행은 관측 차이이지 안정적인 절감률의 증명이 아니다. 효과가 작거나 조건 차이가
큰 경우 결론을 유보한다. 안정적인 절감 주장을 위해 반복을 선택한 경우에만 별도 예산에서 조건을 맞추고
개별값·범위를 보존한다. 예를 들어 3회 이상의 쌍을 관측할 수 있다. 3회도 통계적 확증을 보장하지 않으며 평균만으로 퇴행을 가리지 않는다.
초기 작성·등록·훈련·수리 비용은 매회 실행 비용과 분리하고, 반복 사용으로 회수되는지 검토한다.

## 9. 실행 후 남길 최소 결과

`docs/experiments/long_sentence_imagination/round_N/`에 남기고 큰 원문·로그는 로컬 `outputs/`에 둔다.
정답표는 실행자 입력과 분리해 보존한다. 실행 때 기존 원장의 요약과 갭 표를 함께 갱신한다.
이번 운영 설계 정정에는 새 실행 원장·회차·갭 ID를 만들지 않는다. 101회차의 원본·보고서·검사기는 수정하지 않는다.
