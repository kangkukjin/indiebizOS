# 심층연구 능력을 기르는 긴문장 상상훈련 설계

사용자의 질문을 연구 가능한 문제로 바꾸고, 필요한 근거를 모아 판단하며, 실제 확인에서
드러난 반례로 계획과 결론을 고치는 능력을 기른다. 첫 과제는 **개인 문서가 쌓였을 때
필요한 답과 근거를 더 정확하게 찾아내는 방법**이다. 영상 제작은 다루지 않는다.

핵심 질문은 “계획서를 작성했는가”보다 **그 계획으로 중요한 불확실성이 줄었고,
사용자가 더 나은 판단을 할 수 있게 됐는가**다. 현재 방식의 장점을 유지하면서 계획,
자료 획득, 근거 판단, 실험, 종합, 재개 중 어디를 바꾸면 수행 능력이 좋아지는지 발견한다.

상태: 2026-11-01 설계. 현재 가이드·구현과 과거 훈련 기록을 확인했다. 이번 설계의
실제 연구·훈련 실행이나 제품 수리는 아직 수행하지 않았다. 실행 회차 번호는 착수할 때
누적 원장에서 배정한다. 진행 중인 다른 훈련의 원장·세션·설정을 공유하지 않는다.

## 현재 심층연구 방식과 확인할 간극

기준은 [심층연구 가이드](../data/guides/deep_research.md),
[긴문장 상상훈련](../data/guides/long_sentence_imagination.md),
[IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)이다. 아래는 현재 소스에서 확인한 계약이며,
실제 모델이 이 계약대로 잘 수행한다는 실측 결과와 구분한다.

| 연결 | 현재 계약과 근거 | 훈련에서 확인할 것 |
| --- | --- | --- |
| 요청에서 연구 판단으로 | [의식 지침](../data/common_prompts/consciousness_prompt.md)의 `deep_research` 판단. 단순 조회·가벼운 비교까지 모두 심층연구로 만들지는 않는다 | 복합적인 질문에 연구가 필요한 이유를 이해하는가. 실제 진입 경로에서 의식이 작동했는가 |
| 의식에서 계획으로 | [research_planning.prepare](../backend/cognition/research_planning.py)가 의식에게 가이드와 기존 맥락을 전달한다. 계획 완성 호출은 도구 없이 수행하며, 방법의 미확인은 저장 뒤 예비 조사로 남긴다 | 모르는 방법을 확정하지 않고, 무엇을 먼저 확인해야 하는지 구체화하는가 |
| 계획에서 실행자로 | 같은 모듈의 `persist`가 파일 저장·재독·지문을 확인하고 `execution_block`이 본문과 경로를 전달한다. 계획 실패는 무계획 실행으로 우회하지 않는다 | 사전 계획과 실제 첫 조사의 순서, 전달된 본문과 실행한 방법이 맞는가 |
| 가이드에서 과제별 지침으로 | [guide_registry](../backend/datastore/guide_registry.py)는 의식 전용 가이드를 실행자 추천·자동 주입에서 제외한다 | 중요한 연구 원칙이 과제별 계획으로 충분히 번역되는가. 원본 가이드의 좋은 문구만으로 실행자 이해를 추정하지 않는다 |
| 실행에서 계획 수정으로 | 실행자는 진행·근거를 갱신하고 중요한 목적·방법 변경은 `reframe`으로 의식에게 돌린다 | 반례를 부록에만 적는가, 실제 조사와 판단을 바꾸는가 |
| 연구 대화의 후속 연결 | [ResearchRunner](../backend/cognition/research_runner.py)와 계획 모듈이 현재 계획을 회수하고 `keep` 또는 `revise`를 판단한다 | 같은 주제의 질문은 이어가고, 설명만 요청한 턴에는 불필요한 새 조사를 하지 않는가 |
| 결과에서 평가로 | `evaluation_block`은 초기 계획의 증거와 현재 문서를 제공한다. 완료 표시는 달성 증명이 아니며 질문별 답·근거·불확실성을 대조하도록 한다 | 그럴듯한 보고서, 정상 종료, 검수 승인과 실제 목표 달성을 구별하는가 |

따라서 “의식이 계획하고 실행자가 연구한다”는 이해는 맞다. 다만 **모든 요청이 자동으로
이 경로를 거친다는 계약은 아니다.** 일반 대화의 진입 설정과 연구 프로젝트의 지속 계획은
구별해야 한다. 연구 필요성 판단과 연구 경로 안의 수행 품질도 별도로 관측한다.

가이드는 이미 질문에 맞는 방법, 반대 근거, 예비 조사, 계획 갱신, 실제 열람 범위와 멈춤
조건을 요구한다. 이 항목들을 새로 발명해야 한다고 진단하지 않는다. 반면 저장과 형식
검증만으로 계획의 질을 보장할 수 없으므로, **지침이 행동과 결과로 연결되는지**가 실험 대상이다.

과거 [37회차](experiments/long_sentence_imagination/round_37/report.md)는 연구 보고서를
완성한 뒤에도 부분집단의 효과를 전체에 적용하는 의미 오류를 발견했다.
[63회차](experiments/long_sentence_imagination/round_63/report.md)는 질문·원문·판본의
보존과 재개를 시험했다. 이번 훈련은 그 능력을 바탕으로 **질문에 맞는 연구법 선택과
결론의 수정**을 중심에 둔다. 과거 결함이 현재도 남아 있다고 가정하지 않는다.

## 첫 과제의 자연어 요청

아래 요청을 훈련자와 시스템 AI에 동일하게 준다. 중괄호의 자료·출력 경로는 착수 때
준비한 실제 경로로 치환한다. 풀이 코드, 추천 검색 방식, 정답표는 넣지 않는다.

> 개인 문서가 쌓이면서 분명 읽었던 내용을 다시 찾지 못하거나, 검색 결과는 많지만
> 내 질문에 답이 되는 근거를 찾지 못하는 일이 있습니다. 제공한 문서 묶음과 검색 실패
> 사례를 바탕으로 이 문제가 어디서 생기는지 연구해 주세요. 키워드 검색을 개선하면
> 충분한지, 의미 검색이나 여러 방법을 섞는 방식이 도움이 되는지, 검색을 바꿔도 해결되지
> 않는 문제가 있는지 알아보고 싶습니다. 방법들의 소개를 모으는 데서 끝내지 말고,
> 관련 근거를 조사한 뒤 이 자료에 적용할 수 있는 방법을 실제로 비교해 주세요.
> 현재 사용할 수 있는 도구와 로컬 실행 환경을 이용하고, 새 유료 서비스 가입이나 구매,
> 개인 문서의 외부 업로드는 하지 마세요. 문서와 시험 질문은 모두 공개 가능하게 준비한
> 자료이며, 외부 원문 조사는 허용합니다. 처음 예상한 방식이 맞지 않으면 그 이유를
> 확인해서 판단을 바꿔 주세요. 마지막에는 어떤 조건에서 무엇을 바꾸는 것이 좋을지,
> 아직 판단할 수 없는 것은 무엇인지 설명하고, 비교 결과와 다시 실행할 수 있는 자료를
> {출력 경로}에 남겨 주세요. 자료는 {입력 경로}에 있습니다.

이 과제에서 얻을 것은 특정 검색 제품의 추천이 아니다. 질문 유형, 문서 상태, 검색 결과,
답변의 근거가 어떻게 연결되는지 설명하고, **이번 조건의 실패를 줄이는 선택과 그 한계**를
제시해야 한다. 기존 방식을 유지한다는 결론도 근거가 충분하면 좋은 연구 결과다.

## 자료와 비교 조건

첫 회차는 작고 실제로 재실행할 수 있는 문서 묶음으로 시작한다. 준비와 검수도 회차 예산에
포함한다. 아래 수량은 품질을 인증하는 기준이 아니라 실행 가능한 첫 표본의 설계값이다.

- 실제 문서 8개: 이 저장소의 공개 가능한 가이드·설계 설명에서 고른다. 예를 들어
  연구 프로젝트·연구 질문·IBL 조합·결과 검수 등 서로 겹치고 다른 내용을 포함한다.
  실행자의 비공개 구현을 알아야 답하는 질문은 제외한다. 선택 파일·라이선스/공개 가능
  범위·원문 판본을 확인하고 입력 사본과 해시를 보존한다.
- 통제 자료 4개: 같은 용어의 다른 뜻, 변경 전 조건, 조건이 다른 반대 설명, 관련성이
  낮은 문서를 만든다. 합성 자료임을 표시하며 실제 제품의 과거 사실로 위장하지 않는다.
  날짜·적용 대상·판본 관계를 본문에서 판별할 수 있게 한다.
- 질문 12개: 정확한 용어, 다른 표현의 같은 뜻, 여러 문서 연결, 판본 구별, 조건에 따른
  상충 해석, 자료에 답 없음의 여섯 유형을 각각 2개 준비한다. 각 유형의 1개는 개발용,
  나머지는 보류 질문으로 둔다. 답 없음은 허용한 문서 묶음 안에서의 부재다.
- 질문별 기대 근거: 정답 문구 하나보다 필요한 원문 구간·허용되는 답의 범위·핵심 오류를
  운영자가 원문에서 확인해 보존한다. 두 문서가 필요한 질문은 한 문서 발견만으로
  충족되지 않도록 표시한다. 정답표는 방법을 만드는 실행자에게 주지 않는다.

실제 문서와 통제 자료가 맡는 역할을 보고서에서 구분한다. 통제 자료에서 발견한 문제는
실제 제품 오류가 아니라 해당 입력에서의 연구·검색 행동이다. 검증자가 답을 원문에서
확정할 수 없는 질문은 실행 전에 고치거나 탐색 질문으로 따로 분류한다.

개발용 질문과 실제 사용자 실패 사례로 방법을 조사·선택한다. 보류 질문은 방법과
설정이 고정된 뒤 같은 검색 실행 계약에 넣는다. 실행자가 미리 읽거나 보류 결과를 보고
조정했다면 그 질문은 개발용으로 옮기고, 이후 결과를 미사용 질문 성능으로 보고하지 않는다.

검색의 효과를 비교할 때는 문서 판본, 질문, 전처리, 결과 개수, 답변 생성 조건을 맞춘다.
기본 비교는 같은 문서에서 **기준 방식과 근거를 들어 선택한 대안 하나**다. 연구에서
키워드·의미·혼합 접근을 검토하되 세 방식의 구현을 무조건 요구하지 않는다. 실행 환경에서
시험하지 못한 접근은 문헌상 근거와 미검증 상태로 남기며 구현한 방법과 같은 순위로 놓지 않는다.

문서 분할·색인 갱신·순위화·답변 생성은 서로 다른 원인 후보다. 처음부터 “벡터 검색이면
해결된다”로 문제를 고정하지 않는다. 검색 결과가 올바른데 답변이 틀리는 경우도 남겨 둔다.

## 연구가 실제로 이어져야 하는 과정

1. **질문을 정한다.** 사용자의 실패 사례를 보고 무엇이 검색 실패이고 무엇이 자료 부재,
   판본 혼동, 답변 오류인지 잠정적으로 구분한다. 원인을 확정하기 전에 필요한 관측을 정한다.
2. **의식이 잠정 계획을 쓴다.** 어떤 질문에 어떤 문헌·원문·실험이 필요한지, 무엇을 보면
   판단을 바꿀지 연결한다. 아직 모르는 방법은 예비 조사의 질문으로 남긴다.
3. **예비 조사로 방법을 정교화한다.** 방법의 공식 설명·연구 원문에서 작동 원리와 적용
   조건을 확인하고, 로컬 환경에서 가능한 시험을 정한다. 외부 벤치마크의 우위를 이번
   개인 문서에서의 우위로 곧바로 가져오지 않는다.
4. **전체 IBL 프로그램으로 비교를 실행한다.** 문서 읽기·판본 보존·질문별 검색·결과 합류·
   근거 연결·산출물 생성을 조합한다. 검색 구현은 기존 도구나 범위가 분명한 스크립트를
   부품으로 쓸 수 있지만, 연구 전체를 새 스크립트 하나에 숨기지 않는다.
5. **반례를 조사한다.** 대안이 실패한 질문을 같은 기준으로 읽고, 색인·질문 표현·판본·
   근거 선택 중 어디에서 기대가 어긋났는지 좁힌다. 성공한 질문만 남겨 결론을 만들지 않는다.
6. **종합해 판단한다.** 유형별 성과와 실패 원인, 준비 비용·실행 비용·운영 부담을 함께
   설명한다. 권고를 바꾼 근거와 그대로 유지한 근거를 구별한다.
7. **후속 조건을 반영한다.** 새 자료나 요구가 들어오면 영향받는 질문과 방법을 고르고,
   유효한 원문·계산은 이어 쓴다. 새 판본 확인과 필요한 재색인을 생략하지 않는다.

이것은 관측할 연결이며 시스템 AI에게 정답 풀이로 주입하는 절차가 아니다. 특히 첫 계획에
모든 검색 결과와 구현 선택을 미리 채우지 않는다. 판단이 필요한 경계에서는 결과 참조를
반환하고 다음 프로그램으로 잇는다. 전체 IBL을 한 호출로 고집해 탐색을 없애지 않는다.

훈련자는 [IBL 조합 교재](../data/guides/ibl_composition.md)의 작성 순서로 최초 초안과
수정본을 보존한다. 계획·수집·비교·판단·보고의 입출력이 어떻게 이어지는지 설명한다.
이 설계에서 사용한 함수 역할은 구현 명세이며 새로운 IBL 어휘나 이미 검증된 프로그램이 아니다.

## 첫 회차의 변형과 후속 연구

기본 실행이 끝난 뒤 같은 대화에 다음 요청과 갱신 자료를 준다. 기본 산출물은 보존한다.

> 문서 두 개가 갱신됐습니다. 변경 전 판본은 참고용으로 남아 있지만, 지금의 질문에는
> 현재 조건을 적용해야 합니다. 기존 질문 중 하나는 새 문서 때문에 답이 달라지고,
> 하나는 여전히 답을 알 수 없습니다. 앞서 고른 검색 방식을 그대로 써도 되는지 확인하고,
> 달라지는 결과와 결론만 필요한 만큼 갱신해 주세요. 예전 결과와 무엇이 왜 달라졌는지도
> 설명해 주세요. 권한과 출력 위치는 이전과 같습니다.

기대값은 운영자가 새 원문에서 사전에 고정한다. 어떤 질문이 달라지는지는 풀이에 직접
알려주지 않는다. 과거 답을 그대로 재사용하거나, 문서 수가 늘었다는 이유만으로 답 없음
질문을 추측으로 채우면 실패다. 무관한 근거와 결과는 보존하되, 전체 재색인이 구현상
필요했다면 그 이유와 비용을 남긴다. 전체 재색인 자체를 자동으로 결함으로 보지는 않는다.

다음 과제는 각각 별도 유한 회차로 진행한다. 첫 회차에 모두 밀어 넣거나 자동 반복하지 않는다.

| 과제 | 새로 넓힐 연구 능력 | 결과로 확인할 것 |
| --- | --- | --- |
| 검색 연구의 새 분야 전이 | 다른 용어와 문서 구조에서도 방법·실험을 다시 선택 | 예를 들어 공개 교육 자료에서 미사용 질문으로 확인. 앞 연구의 승자 강제 금지 |
| 성인 학습에서 복습 방식과 장기 기억 | 단기 수행과 지연 기억, 대상·측정 시점이 다른 연구의 종합 | 관련 원문으로 조건부 답과 학습 실험안을 작성. 실제 장기 학습 실험을 하지 않았다면 효과를 입증했다고 하지 않음 |
| 같은 현상의 경쟁 설명 연구 | 상관과 인과, 여러 설명을 가를 관측, 반대 사례 해석 | 예를 들어 공개 도서관 이용 변화의 원인을 조사. 지표·지역·시기 차이를 보존하고 원인을 못 가르면 미해결로 남김 |
| 기존 연구의 설명만 요청하는 후속 | 연구를 계속할 때와 설명할 때의 구별 | 기존 근거로 답할 수 있는 질문에 새 계획·검색을 불필요하게 반복하지 않음 |

일반화를 확인하려면 주제명만 바꾸지 않고 **필요한 답과 증거의 종류가 다른 연구**로
옮겨야 한다. 검색 실험 성공만으로 역사·인과·질적 연구까지 잘한다고 보고하지 않는다.

## 평가 기준과 완료 판정

계획 품질, 실제 연구 수행, 최종 질문에 대한 답, IBL 작성·조합 능력을 따로 판정한다.
각 항목은 달성·부분 달성·미달·미검증과 근거로 남긴다. 점수 합계가 핵심 오류를 가리지 않게 한다.

| 평가 대상 | 확인할 근거 | 실패 또는 미검증의 예 |
| --- | --- | --- |
| 문제 설정 | 원래 질문과 계획의 하위 질문·완료 조건 | 근거를 찾는 문제를 인기 제품 목록으로 바꿈 |
| 방법의 적합성 | 각 질문과 문헌·실험·판정의 연결 | 제품 소개만으로 실제 효과를 단정하거나, 인용 수를 품질로 사용 |
| 조사와 근거의 질 | 실제 읽은 원문 구간·판본·조건, 제외 이유 | 초록만 읽고 본문 실험을 확인했다고 주장하거나 같은 출처 재인용을 독립 증거로 셈 |
| 비교의 타당성 | 같은 입력·설정·질문별 결과·실패 목록 | 후보마다 다른 문서·정답 공개 범위를 사용하고 우열을 단정 |
| 반례에 대한 수정 | 예상과 다른 결과에서 추가 확인·계획·결론으로 이어진 흔적 | 반대 결과를 기록했지만 권고에는 반영하지 않음 |
| 종합과 답변 | 유형별 판단·지지 근거·반대 근거·적용 범위 | 일부 유형에서의 이득을 모든 문서와 질문의 우위로 확대 |
| 실제 사용 가능성 | 비교를 다시 돌릴 입력·설정·프로그램·결과와 명확한 도입 조건 | 보고서만 저장하고 실험은 제안으로 남김 |
| 비용과 멈춤 | 남은 불확실성, 추가 조사 이유, 시간·토큰 | 출처 수를 채우느라 조사하거나 예산 소진을 근거 충분으로 표현 |

검색 시험은 고정된 상위 k개 결과에서 질문별 필수 근거의 포함 여부를 본다(k는 실행 전에
정하고 방식 간 동일하게 쓴다). 답변 생성까지 비교하면 같은 생성 조건에서 정답 범위,
인용의 지지 여부, 판본 선택과 답 없음 판단도 확인한다. 검색과 답변을 한 지표로 접지 않는다.
준비·색인 시간과 질의 시간, 모델 비용도 나눈다. 작은 표본의 평균 하나로 우월성을 보증하지 않는다.

필수 산출물은 저장된 계획과 중요한 개정 이유, 주장에 연결된 근거, 비교 가능한 실험 결과,
재실행 가능한 프로그램과 설정, 결론과 미해결 사항이다. 별도 파일 양식을 강제하지 않고
하나의 보고서와 데이터 파일로 묶어도 된다. 실제 실행되지 않은 방법은 명시한다.

**근거 날조, 무효 비교를 근거로 한 우열 확정, 현재/과거 판본 혼동, 실험 미실행을 실행으로
보고하는 경우는 전체 달성으로 처리하지 않는다.** 반대로 충분히 조사한 뒤 우열을
결정할 수 없다고 답하는 것은 연구 실패와 같지 않다. 원래 질문에 대해 확인된 범위,
조건부 판단, 결론을 바꿀 추가 관측을 제시했는지로 평가한다.

## 독립 실행과 실패 원인 분리

훈련자는 공개된 계약으로 전체 IBL을 작성·실행하고, 시스템 AI는 같은 자연어 요청과
자료로 독립 수행한다. AI에 훈련자의 계획·프로그램·결론·정답표를 주지 않는다. 자신의
앞선 결과는 재사용할 수 있다. 본 설계 작성자는 연구 구현을 읽었으므로 그 내부 지식이
훈련자 수행에 도움을 줬다면 기록하며, 훈련자 성공을 AI 독립 능력으로 바꾸어 말하지 않는다.

일반 시스템 AI 경로는 긴문장 가이드 §4-5의 `origin:"training"` 진입점과 작업 접수증을
사용한다. 의식 활성 여부·모델·설정·라우팅을 먼저 관측한다. 일반 요청이 연구 경로로
들어가지 않았다면 그 사실을 보존하고, 별도의 명시적 연구 요청으로 경로 안의 능력을
확인할 수 있다. 후자를 처음부터 자발적으로 연구를 선택한 성공으로 합치지 않는다.

연구 프로젝트의 영속 계획·질문 원장·자료실을 시험하는 후속 회차는 해당 진입점의 출처와
격리 지원을 별도로 확인한다. 현재 `research_runner.stream`에는 `user` 출처 설정이 있으므로
일반 채팅의 훈련 표식이 자동 적용된다고 가정하지 않는다. 연구 프로젝트는 새 세션·자료실을
분리할 수 있고 실제 기록 혼입 범위를 확인한 경우에 사용한다. 일반 경로의 성공으로 연구
프로젝트의 영속 계승까지 검증했다고 쓰지 않는다.

실패할 때는 최초로 필요한 정보가 사라지거나 잘못 해석된 연결을 찾는다.

| 관측한 현상 | 구분할 원인 | 개선 후보와 확인 방법 |
| --- | --- | --- |
| 무엇을 검증할지 없는 포괄적 계획 | 질문 해석 또는 계획의 구체화 | 의식의 계획 작성 지침에서 질문·필요 증거·판단 변경의 연결을 보완하고 같은 요청으로 비교 |
| 계획은 구체적인데 실행자가 다른 조사 수행 | 전달 누락, 읽기·이해 실패, 실행 수단 부재 | 전달 본문·첫 행동·도구 실패를 대조. 정보 전달을 고칠지 계약 설명을 고칠지 구분 |
| 좋은 검색 결과가 있는데 결론이 틀림 | 의미 해석·근거 범위·종합 실패 | 원문과 주장·판단의 대응을 보존하는 공통 계약 또는 평가 입력을 개선 |
| 실패한 질문을 숨기거나 계속 검색만 함 | 선정 편향·실험 계약·멈춤 판단 | 질문별 실패를 보존하고 결론에 필요한 추가 관측만 선택하도록 개선 |
| 반증 이후 계획과 실행이 어긋남 | 진행 갱신과 재규정 경계 | 최신 계획·실험 결과·변경 이유가 실제 소비자에게 이어지는지 확인 |
| 저장 문서의 완료 표시만 믿고 승인 | 평가 기준 또는 평가 자료 부족 | 원 요청·실행 결과·근거 범위를 함께 대조하도록 기존 평가 경로 개선 |
| 다른 분야에서 다시 실패 | 과제에만 맞춘 처방 | 공통 능력과 분야별 데이터·방법을 나눠 미사용 과제로 재검증 |

위 표는 가설이다. 관측 전에는 결함으로 등록하지 않는다. 설명을 더 길게 만드는 것보다
어느 생산자가 어떤 정보를 제공하고 어느 소비자가 무엇을 확인해야 하는지 먼저 정한다.
새 평가 모델·상시 프롬프트·새 IBL 어휘를 기본 처방으로 추가하지 않는다.

## 개선 효과를 확인하는 방법

최초 관측을 보존한 뒤, 수리 요청이 있을 때 별도 작업으로 개선한다. 모든 훈련 작업의
종료와 증거 회수를 확인한 후 라이브 가이드·프롬프트·코드·설정을 바꾼다. 훈련 중
실행자가 자신의 평가 기준이나 기본 지침을 고쳐 통과하는 것은 허용하지 않는다.

비교는 다음 세 가지를 구분한다.

- **현재 방식의 능력 확인:** 훈련자와 독립 AI가 각각 어디까지 해냈는가. 서로 다른
  사전 지식을 가진 두 실행의 성능 차이를 연구계획의 효과로 해석하지 않는다.
- **개선 전후 확인:** 같은 과제·모델·자료·권한·예산으로 현재 방식과 수정안을 비교한다.
  보류 질문을 이미 사용했으면 새 질문 묶음으로 확인한다. 자료를 기억한 효과와 수리
  효과를 분리하고, 가능하면 중요한 결과를 다른 입력으로 한 번 더 확인한다.
- **연구 자체의 기여 확인:** 필요할 때 별도 격리 회차에서 직접 해결과 연구 경유를
  비교한다. 같은 결과 품질·총예산을 주고 실제 계획·검색 행동을 기록한다. 직접 해결도
  스스로 연구했다면 무연구 대조군이라고 부르지 않는다. 이 비교 없이 “연구해서 더
  좋아졌다”는 인과적 효과를 주장하지 않는다.

전후 비교는 먼저 같은 입력 판본을 사용하고, 이후 새 자료에서 전이를 확인한다. 실시간
웹이 바뀌었으면 원문 스냅샷·검색 시각 차이를 남긴다. 자료 고정 비교와 새 자료를 찾는
능력 시험은 다른 목적이므로 둘을 섞어 수리 효과를 계산하지 않는다.

사용 가능한 결과가 준비될 때까지의 경과 시간, 작성·조사·검수·복구 비용, 의식·실행·
내부 모델·평가의 실제 토큰을 함께 기록한다. 미측정은 0으로 두지 않는다. 품질을 유지하고
시간·토큰을 줄이면 비용 개선, 품질만 높고 비용도 늘면 품질 개선과 비용 증가로 보고한다.
자료 수집량이나 보고서 길이의 증가는 자체로 연구 능력 향상이 아니다.

## 회차 운영과 남길 기록

기본 상한은 긴문장 가이드의 **60분**이다. 준비 8분, 훈련자 기본·변형 15분, 독립 AI
기본·변형 25분, 검수·진단 12분을 목표로 잡되 실제 시간은 별도로 기록한다. 환경 준비나
원문 접근에 시간이 더 걸리면 완수를 꾸미거나 상한을 늘리지 않고 완료 부분과 재개 입력을
남긴다. 비용 비교·전이·추가 대조군은 이후 회차이며 첫 실행의 선행 조건이 아니다.

실행 전에 현재 HEAD와 관련 파일 지문, 모델·권한·자료·완료 조건·시간 상한을 고정한다.
관련 판본이 다른 훈련이나 수리로 도중에 바뀌면 그 구간의 비교는 오염됐다고 표시한다.
관련 없는 미커밋 작업은 정리하거나 이 훈련의 커밋에 포함하지 않는다.

기록 위치는 기존 규약을 사용한다. 로컬 원자료·로그·산출물은
`outputs/long_sentence_imagination/YYYY-MM-DD_N회차/`, 비민감 재현과 회차 보고는
`docs/experiments/long_sentence_imagination/round_N/`, 요약과 실제 발견은
[누적 원장](LONG_SENTENCE_IMAGINATION_LEDGER.md)에 남긴다. 새 실행 원장을 만들지 않는다.

연구 고유의 관측은 최초 계획·전달 본문·중요한 개정, 실제 열람 범위, 질문별 실험 결과,
결론이 바뀐 근거와 시점, 재사용·재실행 범위다. `research.guide_supplied`와
`research.plan_saved`는 계획 공급·저장의 증거이며 연구 품질의 증거와 구분한다.
기존 궤적과 파일로 확인하고, 내부 사고를 추정하거나 매 단계 별도 심사 모델을 붙이지 않는다.

종료 시 검사 통과·실행 종료·연구 질문의 달성을 나누고, 실행 중인 작업은 접수증으로
회수한다. timeout을 종료로 취급하지 않는다. 최종 보고는 **새로 답한 질문, 판단을 바꾼
근거, 아직 답하지 못한 질문, 다음 연구에 재사용할 방법·프로그램, 고쳐야 할 공통 능력**을
중심으로 쓴다. 자료와 질문을 보존한 성공, 올바른 연구 판단, 일반적인 개선 효과를 각각 구별한다.
