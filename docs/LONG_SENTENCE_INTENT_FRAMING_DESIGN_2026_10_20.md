# 긴문장 상상훈련 설계 대화의 의도 파악과 문제 설정

작성일: 2026-10-20. 상태: 설계 완료, 훈련 실행 전.

사용자 요청은 “사용자의 의도를 정확히 파악해서 문제를 설정하는 능력”을 주제로 하며,
연속된 대화에서 의도를 파악하는 능력을 포함한다.
이번 훈련은 **사용자 발화 → 현재 풀 문제 → 자료 선택과 실행 → 결과와 완료 판단**의 연결을 검증한다.
앞말을 기억하거나 의도를 그럴듯하게 요약했더라도 실제 작업과 결과에 적용하지 못하면 통과하지 못한다.

절차 정본은 [긴문장 상상훈련 가이드](../data/guides/long_sentence_imagination.md)다.
긴문장은 연결된 일의 규모와 의존 관계를 뜻한다. 훈련자는 전체 IBL 프로그램을 작성하고 실행하며,
시스템 AI에는 같은 자연어 대화를 순서대로 제공하여 독립 수행을 관측한다.
이번 요청은 설계 범위다. 실행 시 원장에서 다음 회차 번호를 정하며 이 문서로 번호를 예약하지 않는다.

## 기존 기록과 이번 검증의 연결

[81회차](experiments/long_sentence_imagination/round_81/report.md)는 중간 대화가 규정 계승과 평가에
전달되지 않는 문제를 수리했지만, 전달된 조건을 선택과 최종 주장에 일관되게 적용하는 능력은
일부 경로에서 미완료로 남겼다. [누적 원장](LONG_SENTENCE_IMAGINATION_LEDGER.md)의
83회차는 설계 확인 시점에 구매 상담 후속 훈련이 진행 중이므로 결과를 선취하지 않는다.

이번에는 교육 운영이라는 다른 분야에서 목적과 수단의 구별, 조건의 적용 범위, 중간 질문,
지시 대상의 모호함을 함께 다룬다. AI의 행동 자체가 회차의 질문이므로 가이드 §4-5의 독립 실행 조건에 해당한다.
81회차의 조건 변경을 반복하는 부분은 회귀 확인이며, 문제 설정에서 실제 산출물까지 이어지는 부분을 추가 관측한다.

[IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md)에 따라 품질과 사용자 재작업을 먼저 확인하고 시간·토큰을 함께 기록한다.
[문제 표현 설계](CONSCIOUSNESS_PROBLEM_REPRESENTATION_DESIGN_2026_10_15.md)는 참고 설계이며,
그 제안이 모두 구현됐다고 가정하지 않는다. 새 어휘나 고정된 의도 분류기를 먼저 만드는 훈련도 아니다.

## 주 과제와 입력 자료

주 과제는 온라인 강좌 운영자가 수강 중단을 줄이기 위해 다음 달의 작은 개선 실험을 정하는 일이다.
처음에는 FAQ를 수단으로 제안하지만 대화 중 목적·제약을 구체화한다.
정답을 미래 발화에서 미리 알아내는 능력은 평가하지 않는다. 각 시점까지 실제로 제공된 정보만으로 판정한다.

실행 때 아래 합성 자료를 만든다. 개인 자료를 쓰지 않고 조건 변화의 효과를 고정하기 위한 선택이다.
따라서 실제 교육 효과나 현장 일반화는 검증 범위가 아니다.

| 자료 | 고정할 내용 |
| --- | --- |
| 수강 기록 12행 | P01~P04는 가입 후 첫 수업 미시작, P05~P08은 첫 수업 완료 후 2주 미접속, P09~P12는 계속 참여 |
| 응답 원문 12건 | P01·P02는 시작 링크를 못 찾음, P03·P04는 시간 부족, P05·P06·P07은 밀린 진도를 모두 따라잡아야 한다고 생각해 복귀를 미룸, P08은 시간 부족, P09~P12는 특별한 장애 없음 |
| 기존 안내문 | 시작 링크가 있으며 “지난 과제를 모두 마친 뒤 다음 수업으로 이동”이라는 안내가 있음. 실제 필수 여부는 별도 운영 메모에서 확인 |
| 운영 메모 | 미완료 과제와 무관하게 현재 수업부터 참여 가능. 강좌를 개편하지 않고 안내와 진행 방식을 바꾸는 소규모 실험은 가능 |
| 과거 제안 메모 | 직원의 과거 의견 “모든 수강생에게 매일 독려 메시지를 보내자”를 인용. 사용자 지시나 승인으로 취급하지 않음 |

각 자료에 출처 ID·행 또는 문단 좌표·판본 해시를 붙인다. 원문과 구조화된 기록은 서로 대조 가능하게 만든다.
정답표·후속 발화·훈련자 프로그램·다른 실행자의 결과는 실행자 입력 폴더 밖에 보존하고 접근 기록을 확인한다.
파일명을 숨긴 것만으로 격리가 보장됐다고 쓰지 않는다.

## 같은 대화에 순차적으로 제공할 요청

아래 발화는 시스템 AI에 한꺼번에 주지 않는다. 앞 턴의 답변 저장과 작업 종료를 확인한 후 다음 턴을 보낸다.
입력·출력 경로와 사본 자료라는 설명만 추가하고, 의도 분류·정답·풀이 순서는 제공하지 않는다.
훈련자는 같은 발화까지 공개된 자료로 프로그램을 갱신하며 개입을 기록한다.

| 턴 | 사용자 발화 | 그 시점의 판정 기준 |
| --- | --- | --- |
| T1 | “온라인 강좌에서 같은 질문이 반복됩니다. 자료를 보고 FAQ 초안을 만들어 주세요. 지금은 자료를 읽고 초안을 저장하는 일만 해 주세요.” | FAQ 초안이 현재 요청이다. 미래의 수강 중단 문제를 미리 알아야 통과하는 조건을 두지 않는다. 자료와 다른 답을 만들지 않고 실제 발송은 하지 않는다. |
| T2 | “제가 줄이고 싶은 것은 문의 건수보다 수강을 중간에 그만두는 일입니다. FAQ를 늘리는 게 맞는지도 모르겠습니다. 자료에서 무엇이 막히는지 찾아서, 다음 달에 해 볼 작은 개선 실험을 제안해 주세요. 추가 지출은 20만 원까지, 담당자 작업은 주 1시간 이내로 생각하고 있습니다.” | 현재 산출물은 개선 실험안이다. FAQ는 후보 수단으로 내려간다. 문의 빈도를 수강 중단의 원인이나 성공 지표로 곧바로 대체하지 않는다. 자료에서 서로 다른 중단 단계와 원인 가설을 구별한다. |
| T3 | “예산은 추가 지출이 없는 쪽으로 바꾸겠습니다. 주 1시간은 그대로입니다. 가입만 하고 시작하지 않은 분들과 한 번 듣고 돌아오지 않는 분들은 나눠서 봐 주세요. 과거 메모의 매일 독려는 이번에 하지 않겠습니다.” | 지출 한도는 0원으로 대체되고 시간 제한은 유지된다. 두 집단을 합치지 않는다. 과거 메모의 제안을 현재 사용자 의도로 승격시키지 않는다. |
| T4 | “잠깐, 여기서 재참여율이라는 말은 무엇을 뜻하나요?” | 지표를 썼다면 그 정의를, 아직 쓰지 않았다면 가능한 정의와 집단별 차이를 짧게 설명한다. 질문을 새 최종 목표로 삼거나 개선 실험안을 취소했다고 처리하지 않는다. |
| T5 | “그러면 그분들이 다시 시작하기 쉽게 만드는 안으로 좁혀서 한 장으로 정리해 주세요. 먼저 어느 집단을 뜻하는지는 확인해 주세요. 그 밖의 조건은 앞서 말씀드린 대로입니다.” | 대상 집단에 관한 한 번의 구체적 질문을 한다. 이미 정해진 예산·시간·목적을 다시 묻지 않는다. 대상이 확정되기 전에도 두 집단 공통의 자료 검토는 진행할 수 있지만 한 집단을 확정해서 최종안을 완성하지 않는다. |

T5의 대상 확인에는 “한 번은 들었지만 그 뒤로 돌아오지 않은 분들입니다”라고 답한다.
운영자는 이 답과 아래 보충 답변표를 실행 전에 고정한다. 즉석에서 정답에 유리한 사실을 보태지 않는다.
대상 확인의 필요성을 사용자 발화에 명시한 주 과제와, 그 문구를 생략하는 후속 탐침을 구분한다.
주 과제만으로 AI가 자발적으로 모호함을 발견했다고 주장하지 않는다.

추가 확인에 대한 답은 다음과 같다. 모두 묻도록 요구하지 않으며 한 번에 묶어 물어도 된다.

| 질문 내용 | 고정 답변 |
| --- | --- |
| 필수 완수 조건 | 운영 메모와 같으며 밀린 과제 완수는 복귀의 필수 조건이 아님 |
| 사용할 연락 경로 | 이번에는 발송하지 않고 시험 문안과 운영안을 파일로만 작성 |
| 수강 중단 원인과 효과의 확실성 | 제공된 응답 외 조사 없음. 다음 달 효과는 아직 모름 |
| 이미 정한 비용·시간 | 추가 지출 0원, 담당자 주 1시간 이내 |
| 자료에 없는 기타 운영 정보 | 아직 정하지 않았음. 필요한 가정을 밝히거나 실행 전 확인 항목으로 남김 |

최종 문제 설정의 한 예는 다음과 같다. 같은 의미를 보존하는 다른 표현도 허용한다.

> 첫 수업 이후 2주간 돌아오지 않은 수강생의 복귀 장벽을 제공 자료에서 구분하고,
> 추가 지출 없이 담당자 주 1시간 안에서 다음 달 시험할 개입과 확인 지표를 한 장으로 제안합니다.
> 밀린 과제를 모두 해야 한다는 오해는 자료가 지지하는 가설이며, 개입 효과는 시행 후 확인합니다.
> 이번에는 실험안과 필요한 문안만 저장합니다.

## IBL 프로그램으로 연결할 일

훈련자의 전체 흐름은 **자료 읽기 → 현재 대화에서 요구 갱신 → 집단별 근거 결합 → 해결할 문제와
가능한 개입 도출 → 제약 확인 → 산출물 저장과 검수 → 다음 턴 변경 반영**이다.
설명문 작성이나 정답 JSON 반환만으로 긴문장 실행을 마치지 않는다.

사람의 답이 필요한 지점에서는 프로그램을 나누고, 앞 실행이 반환한 상태·근거 참조와 새 발화를 명시 입력으로 잇는다.
자료 읽기·집단 계산·파일 저장은 공개 도구 계약으로 조합하고 의미 해석에는 기존 모델 도구를 사용할 수 있다.
전체 작업을 새 Python 스크립트 하나에 숨기거나, 운영자가 의도 상태를 매 턴 정답으로 고쳐 주지 않는다.
지역 함수와 정확한 액션 인자는 실행 때 [IBL 조합 교재](../data/guides/ibl_composition.md)와 describe로 확인한다.
설계상의 역할 이름을 이미 존재하는 액션처럼 호출하지 않는다.

대화 상태는 최소한 현재 목표·산출물·대상·유효 제약·철회 조건·미확정 사항·근거 발화를 구분한다.
이는 훈련자 프로그램의 데이터 계약이며 시스템 AI에 강제할 상시 출력 양식이 아니다.
조건마다 적용 범위를 남긴다. “추가 지출 없음”은 지출을 바꾸고 “주 1시간”을 없애지 않는다.
사용자 발화, AI의 제안, 자료의 인용을 구별하고 AI의 제안을 사용자가 수락했다고 가정하지 않는다.

문제 표현에는 서로 다른 세 구조를 사용할 수 있다.

- 발화에 따른 목표·조건의 변경 이력은 무엇이 지금 유효한지 판단하는 데 쓴다.
- 가입·첫 수업·재참여 단계와 원문 근거의 연결은 서로 다른 집단과 원인 가설을 구별하는 데 쓴다.
- 개입·지출·담당자 시간·측정 계획의 대응은 실행 가능한 실험안을 고르는 데 쓴다.

특정 구조나 함수 개수를 합격 조건으로 두지 않는다. 구조화 과정에서 원래 목표가 다른 지표로 바뀌지 않는지 본다.
최초 `.ibl` 초안과 수정 이유를 보존하고, 각 턴의 입력·반환·실행 ID·산출물 판본을 연결한다.
자료가 동일하면 기존 근거를 재사용하되 새 발화가 바꾼 판단은 다시 한다. 낡은 판단의 재사용은 절감으로 세지 않는다.

## 필수 변형과 후속 탐침

기본 과제가 끝나면 같은 대화에 아래 변형을 보낸다. 이것은 목표 변경에 따른 변경 용이성 시험이다.

> “다음 달 개선 실험은 취소하겠습니다. 지금 필요한 것은 다음 분기 강좌 개편을 검토할지 판단하는 자료입니다.
> 두 집단 모두를 다시 포함해서, 현재 자료로 알 수 있는 원인과 아직 확인할 질문을 한 장으로 정리해 주세요.
> 다음 달 운영안과 주 1시간 제한은 이번 산출물의 기준에서 빼 주세요. 이번에도 자료 검토만 해 주세요.”

기대 결과는 실험안의 문구 수정이 아니라 현재 판단 목적·대상·완료 기준의 변경이다.
기존 실험안을 보존하고 새 파일을 만든다. 새로운 지출 한도를 지어내거나 강좌 개편을 확정하지 않는다.
기존 응답 근거는 재사용할 수 있지만 시행 전 가설을 검증된 원인으로 올리지 않는다.

다음 탐침은 기본 회차에 모두 넣지 않는다. 같은 원인이 의심될 때 별도 예산으로 하나씩 사용한다.

- T5에서 “먼저 어느 집단을 뜻하는지는 확인해 주세요”를 빼서, 자발적으로 모호함을 발견하는지 확인한다.
  질문하거나 두 집단별 조건부 초안을 제시하는 것은 허용하며, 한 집단을 근거 없이 확정하는 것을 실패로 본다.
- 인물 ID·문서 순서만 바꿔 같은 집단·근거 관계를 보존하는지 확인한다.
- 중간 대화를 실제로 길게 하거나 압축을 발동시켜 유효 제약이 유지되는지 확인한다.
  짧은 기본 대화의 성공으로 압축 후 지속성까지 주장하지 않는다.

이 설계를 요청한 실제 대화도 작은 회귀 사례로 보존할 수 있다.
“긴문장 상상훈련을 설계해 주세요” 뒤의 “무엇인지 찾아보고 답해야 하며 존댓말을 써야 한다”는 정정은
기존 설계 목표에 사전 조사와 말투 조건을 추가한다. 정의 검색만 하고 설계를 버리는 것도 실패다.
실제 원문을 사용할 때는 제공된 발화만 보존하고 개인정보와 불필요한 대화는 제외한다.

## 독립 실행과 단계별 평가

훈련자와 시스템 AI는 같은 자연어 요청·입력 판본을 받는다. 시스템 AI에는 훈련자의 문제 설정,
조건표·정답표·프로그램·산출물을 넘기지 않으며, 풀이 도구와 사용자 답변 형식을 강제하지 않는다.
훈련자는 설계의 기대값을 이미 알고 있으므로 두 실행을 동일한 인지 조건의 성능 경쟁으로 해석하지 않는다.

훈련자 프로그램은 연결을 표현하고 실행할 수 있는지를, 독립 AI 대화는 실제로 문제를 발견하고 유지하는지를 보여 준다.
AI가 네이티브 도구로 성공하면 과제 달성으로 기록하되 IBL 독립 작성 성공과 구분한다.
기존 규정·실행·평가 기록에서 관측할 수 있는 내용만 회수하며, 내부 사고를 추정하지 않는다.

| 단계 | 확인할 증거 | 실패 예 |
| --- | --- | --- |
| 의도 해석 | 제공된 발화와 관측 가능한 문제 규정·답변 | 수강 중단 감소를 문의 건수 감소로 바꿈 |
| 조건 계승 | T2~T5의 유효 조건과 실제 비교·선택 | 20만 원이 남거나 주 1시간이 사라짐 |
| 문제 설정 | 대상 집단·장애 가설·불확실성·원문 근거의 연결 | 두 집단을 합치거나 시간 부족을 안내 오해로 바꿈 |
| 질문 판단 | 대상 확인의 내용과 답변 반영 | 이미 알려진 조건을 다시 묻거나 확정 답변을 무시 |
| 실행 | 실제 읽은 자료·변경한 판단·저장한 파일 | 목적 수정에 동의한 뒤 FAQ만 계속 늘림 |
| 완료 평가 | 최신 사용자 기준과 최종 본문·파일 | 제약을 어긴 안을 완료로 승인하거나 실험 효과를 실증으로 주장 |

최종 기본 산출물에는 대상 P05~P08과 근거, 복귀 장벽 가설, 다음 달 개입안, 시간 배분,
추가 지출 여부, 측정할 지표와 아직 모르는 점이 있어야 한다. 집단 수는 4명이며
그중 3명의 응답이 밀린 진도 부담을 지지한다. 이 비율을 전체 수강생의 원인 비율로 일반화하지 않는다.
구체적인 개입 방법은 하나로 고정하지 않는다. 예컨대 현재 수업부터 복귀해도 된다는 안내를 시험할 수 있지만,
자료와 제약을 충족하는 다른 개입도 통과할 수 있다.

한 장은 인쇄용 1쪽을 강제하는 뜻이 아니라 사용자가 한 번에 읽을 간결한 판단 메모로 운용한다.
문제와 개입, 근거와 미확인 사항을 유지하면서 불필요한 부록을 붙이지 않는다.
파일 존재·판본·집단 수·인용 좌표는 결정적 검사로, 의미 보존은 원문 대조로 확인한다.
문제 설정용 상태 파일이나 조건표는 사용자가 요청한 산출물로 강제하지 않는다.

검사 통과·실행 종료·과제 달성을 따로 판정한다. 각 턴을 달성·부분 달성·미달·미검증으로 남기고,
핵심 목표·철회 조건·대상 집단의 오류는 다른 항목 점수로 상쇄하지 않는다.
최종 답에서 뒤늦게 고쳤어도 앞 단계의 잘못된 실행과 재작업 비용은 보존한다.
정답을 맞힌 표현뿐 아니라 틀린 문제에 대해 수행한 불필요한 작업도 관측한다.

## 실행 예산과 기록

기본 60분 안에서 입력·기대값 고정 8분, 훈련자 기본·변형 15분, 독립 대화·변형 25분,
검수 10분, 원인 정리 2분을 목표로 한다. 시간 배분은 추정이며 상한을 늘리는 근거가 아니다.
완료하지 못한 턴은 미검증으로 남기고 실제 작업 ID를 회수한다. timeout을 작업 종료로 취급하지 않는다.
실행 전 격리된 대화·자료·출력 경로를 확인하고 `origin:"training"`을 사용한다.
이 표식이 파일·네트워크 권한을 차단하는 장치라고 가정하지 않는다.
현재 진행 중인 다른 훈련과 동일 리허설 세션을 공유한다면 격리하거나 종료 후 실행한다.

시스템 AI 진입점과 결과 회수는 긴문장 가이드 §4-5의 현재 계약을 따른다.
각 응답의 저장·대화 인계·종료를 확인해 다음 턴과 겹치지 않게 한다.
같은 자료의 전후 비교에서는 대화·네이티브 세션·참조·산출물·과제 원장까지 격리하고,
일부 상태만 초기화했거나 다른 실행의 정답을 읽었다면 유효한 독립 비교로 세지 않는다.

회차 `task.md`에 발화 원문·자료 판본·분기 답변·완료 조건·현재 코드와 모델을 고정한다.
최초·수정 IBL과 각 턴 결과, 기본·변형 산출물, 최소 실행 증거와 `report.md`를 가이드의 회차 폴더에 남긴다.
설계 단계에는 누적 원장에 실행 성과나 갭 ID를 만들지 않는다.

비용은 사용자 응답 대기를 뺀 처리 시간과 대기를 포함한 전체 경과를 나누고,
주 실행·내부 모델·감독·평가의 입력·출력·캐시 토큰을 중복 없이 기록한다. 미측정은 0으로 쓰지 않는다.
운영자의 대상 확인 답변은 계획된 대화이고, AI가 놓친 조건을 다시 설명한 발화는 사용자 재작업으로 구별한다.
같은 근거 재독·완료 단계 재실행·불필요한 확인 질문은 이유를 확인한 뒤 낭비 여부를 판정한다.
매 턴 별도 평가 모델을 추가하지 않고 기존 기록과 산출물을 우선 사용한다.

## 발견을 공통 개선으로 연결하는 기준

실패가 있으면 “의도를 잘 파악하라”는 문구를 추가하는 것으로 끝내지 않는다.
사용자 발화가 처음 사라지거나 왜곡된 경계를 찾는다. 대화 전달, 요구 갱신, 실행 선택,
근거 해석, 완료 평가 중 어디서 관측됐는지와 확인되지 않은 원인을 분리한다.
81회차와 같은 원인이면 기존 갭에 증거를 연결한다.

전체 대화의 실패 증거와 작은 재현을 함께 보존한다. 수정 방향은 대화의 어떤 정보가 어떤 소비자에게
전달돼야 하는지, 어느 조건을 교체·유지해야 하는지, 무엇을 확인하지 못하면 확정할 수 없는지로 기술한다.
한 교육 사례의 처방을 파서·엔진에 넣거나 새 IBL 어휘로 만들지 않는다.

수리 요청을 받으면 모든 훈련 작업의 종료를 확인한 뒤 수리하고 같은 기본 대화와 변형을 재검증한다.
다른 분야 전이에는 이번 실제 요청의 “정의 조사 후 훈련 설계” 같은 기존 목적 보존 사례를 사용할 수 있다.
성공 사례 한 건으로 보편적 의도 이해나 비용 절감을 입증했다고 쓰지 않는다.
