# 긴문장 상상훈련 설계 — 훈련을 설계하고 실행하고 다시 설계하기

상태: 설계 완료, 훈련 미실행. 회차 번호는 실제 시작 때 누적 원장에서 배정한다.
사용자 요청: “긴문장상상훈련을 설계해줘. 주제는 긴문장 상상훈련이야.”

## 1. 무엇을 훈련하는가

**과거 훈련에서 필요한 다음 과제를 찾아, 실행 가능한 훈련으로 만들고, 실제 결과에 근거해 다음 설계를 고치는 능력**을 시험한다.
긴문장 상상훈련을 설명하는 글의 길이나 보고서 개수를 평가하지 않는다.
요구·자료·프로그램·실행 증거·달성 판정·후속 설계가 연결되어야 한다.

외부 훈련자가 이 전체 과제를 IBL로 수행하는 실행과, 같은 자연어 요구를 받은 시스템 AI의 독립 실행을 비교한다.
각 실행 안에서 만드는 작은 훈련은 한 과제와 변형 하나뿐이다. 작은 훈련은 자료를 처리하며,
다시 다른 훈련이나 에이전트를 생성하지 않는다. 다음 회차는 제안까지만 작성한다.

## 2. 주 과제 — 시스템 AI에도 그대로 줄 자연어 요구

> 긴문장 상상훈련이 다음 훈련을 더 잘 설계하도록 도와줘. 제공한 과거 훈련 기록을 읽고,
> 반복된 어려움, 이미 해결됐다는 근거가 있는 문제, 아직 확인하지 못한 능력을 구분해 줘.
> 그 근거로 다음 훈련 후보 세 개를 제안하고, 각 후보가 새로 확인할 능력과 완료 조건을 적어 줘.
> 이번에는 그중 ‘훈련 결과의 완료 판정과 근거 보존’을 시험하는 후보를 구체화해 실제로 수행해 줘.
> 제공한 시험용 훈련 기록으로 결과 주장과 실행 증거를 대조하고, 검사 통과·실행 종료·요구 달성을
> 각각 판정하는 과제를 만들어. 숫자가 없으면 미상으로 남기고, 같은 실행이나 비용을 두 번 세지 마.
> 과제와 판정 기준을 먼저 저장한 다음 실행하고, 어떤 결과가 어느 입력과 실행에서 나왔는지 연결해 줘.
> 이후 제공하는 변경 자료에는 네가 이미 얻은 결과를 활용하되, 바뀐 근거에 의존하는 판정은 다시 확인해 줘.
> 마지막으로 최초 예상과 실제 결과의 차이, 작성하거나 고치는 데 걸린 비용, 다음 훈련안 하나를 남겨 줘.
> 네가 제안한 다음 훈련은 시작하지 말고, 기존 훈련 기록과 실제 시스템 설정은 수정하지 마.

운영자는 이 문단에 입력·출력 경로와 아래의 공개 판정 계약을 붙인다.
훈련자의 분해·IBL 초안·기대값·산출물은 시스템 AI에 제공하지 않는다.
시스템 AI가 IBL 외 수단을 택하면 과제 달성과 IBL 작성 능력을 나누어 기록한다.

## 3. 입력을 어떻게 준비하는가

### 실제 기록: 과제를 고르는 근거

실행 시작 시점에 **종료된 최근 8개 회차**의 원장 요약과 보고서, 관련 가이드의 사본을 고정한다.
진행 중인 회차는 제외한다. 파일별 경로·내용 해시·수집 시각·코드 리비전·작업 트리 상태를 남긴다.
보고서가 없거나 원장과 충돌하면 그 상태를 보존한다. 읽을 수 없는 증거를 확인했다고 쓰지 않는다.
회차 번호만으로 자료를 합치지 않고 출처 경로와 제목도 보존한다.

실제 기록은 후보 선정과 해석의 자료다. 기록이 말하는 ‘수리 완료’를 현재 환경의 실검증으로 바꾸어 적지 않는다.
실자료에서 새 결함을 반드시 찾을 필요는 없다. 근거가 충분하면 갭 0건도 유효하다.

### 합성 기록: 실행 결과를 독립적으로 검증하는 재료

실제 기록과 분리된 `SYN-*` ID의 훈련 12건, 실행 24건, 실행 이벤트 총 2,400행을 준비한다.
훈련별 요구 목록, 검사 결과, 실행 상태, 산출물, 검수 증거, 비용 관측을 서로 다른 파일에 둔다.
여러 파일의 ID·판본·참조를 연결해야 전체 판정이 나오게 한다.

| 심을 조건 | 기대하는 처리 |
| --- | --- |
| 검사 통과 뒤 실행 실패 | 검사 통과와 실행 실패를 함께 표시한다. |
| 실행 성공이지만 필수 표 누락 | 요구 달성을 완료로 쓰지 않고 미충족 조건을 남긴다. |
| 동일 실행·과금 이벤트의 중복 수록 | 실행 ID·이벤트 ID로 한 번만 집계한다. |
| 같은 ID의 서로 다른 내용 | 조용히 한쪽을 고르지 않고 충돌로 남긴다. |
| 로그·산출물·검수 증거 중 하나 없음 | 확인 가능한 사실은 보존하고 나머지는 미검증으로 표시한다. |
| 일부 토큰 관측 없음 | 관측 합계와 누락 범위를 함께 적고 총량은 미상으로 둔다. |
| 실패 후 수리·재실행 성공 | 최초 실행과 수리 후 실행을 분리하고 최초 성능을 덮어쓰지 않는다. |
| 같은 갭이 다른 이름으로 재등장 | 명시적 연결 근거가 있으면 기존 갭에 연결하고, 의미 유사성만 있으면 후보로 표시한다. |

행 수는 규모 가정이며 점수가 아니다. 반복 행만 늘리지 않고 판정에 필요한 의존 관계를 만든다.
합성 자료의 사실표와 독립 검증기는 운영자 전용 위치에 둔다. 생성 스크립트·정답·다른 실행자의
산출물이 실행자에게 노출되면 해당 실행을 독립 비교에서 제외한다.

## 4. 실행 전에 공개할 판정 계약

1. 각 실행의 **검사 결과 / 실행 상태 / 과제 달성**을 별도 칸에 둔다.
2. 달성은 모든 필수 조건의 근거가 있을 때만 쓴다. 일부만 충족이면 부분 달성, 관측상 목표를
   이루지 못했으면 미달, 판단할 증거 자체가 부족하면 미검증으로 쓴다. 조건별 근거를 함께 남긴다.
3. ‘근거 없음’과 ‘실패 증거 있음’을 구분한다. 실패하도록 설계된 변형은 약속한 실패 표시와
   결과 보존을 지켰다면 과제 달성이 가능하다.
4. 모든 판정 행은 요구 ID·입력 판본·실행 ID·산출물 또는 검수 참조로 거슬러 올라갈 수 있어야 한다.
5. 비용은 훈련 작성·실행·복구와 운영·회고를 구분한다. 동일 과금 이벤트만 합산하고 요약 누계와
   원시 이벤트를 중복 합산하지 않는다. 벽시계 시간은 병렬 작업 시간의 합으로 대신하지 않는다.
6. 실제 과거 기록의 수치와 합성 기록의 수치는 별도로 집계한다. 가상 결함을 실제 시스템 결함으로 등록하지 않는다.

정확한 숫자 정답은 비공개지만 위 의미 계약은 양쪽 실행자에게 동일하게 제공한다.
후보의 참신함과 근거의 타당성에는 단일 정답을 강제하지 않는다. 인용한 원문이 주장과 맞는지 대조한다.

## 5. 훈련자 IBL의 설계

아래는 책임 분해이며 실행 검증된 함수나 새 어휘의 목록이 아니다.

| 부품 | 입력 → 반환 | 확인할 연결 |
| --- | --- | --- |
| 기록 읽기 | 자료 목록 → 원문·판본·출처·읽기 실패 | 일부 실패를 빈 정상 결과로 바꾸지 않기 |
| 경험 정리 | 실제 기록 → 확인 사실·열린 질문·후보 세 개 | 관측과 해석 구분, 근거를 가진 과제 선정 |
| 훈련 구체화 | 공개 계약·합성 자료 명세 → 요구·완료 조건·기본/변형 계획 | 실행 결과를 보기 전에 기준 고정 |
| 근거 대조 | 요구·실행·검수·산출물 → 조건별 판정·충돌·미상 | 여러 파일의 결합, 누락과 실패의 보존 |
| 비용 집계 | 과금 이벤트·실행 구간 → 관측 비용·누락·포함 범위 | 중복 제거, 최초/수리 후 분리 |
| 결과 전달 | 판정·비용·출처 → 저장한 표·보고서·재독 결과 | 반환 성공과 사용 가능한 산출물 구분 |
| 변경 반영 | 이전 결과·변경 자료 → 갱신 판정·재사용/재실행 내역 | 변경 영향과 신선도 |

실행 프로그램은 다음처럼 세 경계로 나누는 것을 기본안으로 한다.

- 준비: 실제 기록 읽기 → 후보와 작은 훈련의 과제·판정 계약 저장.
- 수행: 고정된 과제의 합성 자료 읽기 → 대조·집계 → 결과 저장·재독.
- 변경: 변경된 입력과 자신의 이전 결과 연결 → 영향받는 판정 갱신 → 회고·후속 설계.

준비 결과로 과제의 의미가 정해지므로 그 경계에서 기준을 고정한다. 내부 변수의 자동 승계나
생성된 코드의 자동 실행을 가정하지 않는다. 프로그램 사이에는 명시적인 결과 참조·파일을 쓴다.
실제 IBL은 현재 공개 계약을 조회한 뒤 작성하고 최초 초안을 보존한다. 핵심 대조·조합을
새 Python 스크립트 하나에 숨겨 전체 IBL 작성 성공으로 세지 않는다.

## 6. 필수 변형 — 빠졌던 증거가 늦게 도착한다

기본 입력에서 한 실행의 최종 산출물과 검수 기록을 의도적으로 누락한다.
기본 실행이 끝난 뒤 그 자료를 추가하고, 다른 한 산출물은 **같은 경로의 새 내용**으로 교체한다.
이는 요구 변경이 아니라 입력 변경 시험이다. 기본 프로그램의 판정 규칙은 유지한다.

실행 전 운영자가 고정할 기대:
- 누락 자료와 관련된 조건은 새 증거에 따라 갱신된다. 새 자료가 실패를 보이면 완료로 올리지 않는다.
- 같은 경로라도 내용이 달라지면 관련 판정을 재확인한다.
- 변경과 무관한 판정·근거는 동일하게 보존된다.
- 동일 실행·과금 이벤트를 다시 세지 않는다.
- 자기 결과의 재사용은 허용한다. 실제 재독·재계산 범위를 기록하며 재사용을 추측으로 주장하지 않는다.

재사용이 없어도 결과가 정확하면 정확성은 달성할 수 있다. 다만 부분 재개 능력과 비용 개선은
입증하지 못한 것으로 분리한다. 입력 변경 때문에 코드를 고쳤다면 최초 견고성과 수정 후 성공도 구분한다.

## 7. 독립 비교와 종료

훈련자와 시스템 AI에 같은 판본의 입력·공개 계약·변경 자료를 주고 출력 경로를 분리한다.
시스템 AI에는 자연어 요구만 전달하며 훈련자가 정한 함수와 프로그램 분할은 강제하지 않는다.
각 실행 안의 작은 훈련은 별도의 독립 AI 실행을 또 만들지 않는다.

실제 실행 시 가이드의 `origin:"training"`과 검증된 요청·회수 경로를 사용한다.
접수·timeout을 완료로 세지 않고 작업 ID로 종료를 확인한다. 모델·권한·교재·소스 리비전 차이를 남긴다.
과거 기록, 실행별 출력, 정답 영역을 분리할 수 없으면 독립성의 한계를 먼저 기록한다.

훈련 전체 상한은 가이드 기본값인 60분이다. 준비·기본 작성/실행·변형·시스템 AI 비교를 포함한다.
준비 10분, 훈련자 기본/변형 20분, 시스템 AI 기본/변형 25분, 대조 5분을 목표 배분으로 둔다.
상한 때문에 못 끝낸 경로는 미검증으로 남기고 예산을 늘리지 않는다. 종료 보고·증거 회수·정리는 별도 계측한다.
설계 문서를 작성한 이번 작업은 실행 회차로 세지 않는다.

## 8. 산출물과 합격 조건

실제 회차의 기존 폴더 규약 아래 `task.md`, 최초/수정 IBL, 입력 명세, 실행 증거,
`verdicts.json`, `report.md`를 둔다. 다음 훈련안은 보고서의 한 절로 남긴다.
실행 종료 후 회차 원장에는 요약과 **실제로 발견한** 갭만 연결한다.

필수 완료 조건:
1. 후보 세 개가 과거 기록의 근거와 아직 확인할 능력에 연결되어 있다.
2. 작은 훈련의 요구·완료 조건·변형 기대가 실행 전에 저장되어 있다.
3. 기본·변형의 모든 합성 실행에 대해 상태·요구 충족·근거·비용 집계가 독립 기대와 일치한다.
4. 보고서에서 ‘검사 통과=실행 성공=과제 달성’이라는 잘못된 합치기가 없다.
5. 저장 파일의 재독뿐 아니라 독립 원자료와 판정값도 대조한다.
6. 재사용·수정·도움받은 지점·미측정 비용을 숨기지 않는다.
7. 다음 훈련안은 이번 관측으로 선택 이유가 설명되며 주제 이름만 바꾼 반복에 머물지 않는다.

기본·변형·훈련자·시스템 AI의 달성 여부를 따로 보고한다. 새 결함 수·문장 길이·함수 수는 점수가 아니다.
양쪽의 전체 토큰을 관측하지 못하면 토큰 우위를 주장하지 않는다. 한 번의 성공으로 보편적 향상을 선언하지 않는다.

## 9. 이번 설계가 새로 확인하는 것

기록 감사만으로 끝내지 않고 **감사 → 새 요구 설계 → 실행 전 기준 고정 → 실제 수행 →
늦은 증거 반영 → 다음 설계 수정**을 연결한다. 관측된 거짓 완료가 생기면 근거·완료 판정 계약으로,
새 증거를 무시하면 신선도·재사용 계약으로, 중복 비용이 생기면 실행 신원·계측 계약으로 원인을 좁힌다.
이 연결은 훈련 기록 외에도 조사 보고서, 문서 검수, 다단계 업무의 완료 관리에 적용할 수 있다.

훈련 중 발견한 문제는 원장에 남긴다. 이 설계 요청으로 훈련 실행·라이브 수리·관용구 등록·예약을 시작하지 않는다.
