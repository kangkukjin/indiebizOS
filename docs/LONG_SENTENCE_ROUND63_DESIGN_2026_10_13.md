# 긴문장 상상훈련 63회차 설계 — 연구 질문을 실원문 근거로 이어가고 종결하기

상태: **설계만**(2026-10-13). 실행·수리는 별도 요청으로 한다. 설계 작성은 회차로 세지 않으며,
원장 항목은 훈련 시작 때 63번으로 만든다. 실제 관측·명세 보완·검증 범위는 회차 보고서가 정본이다.
사용자 요청: "다음 긴문장 상상훈련을 설계해줘."

## 1. 회차의 계기와 무엇을 훈련하는가

개정한 가이드 §2 의 첫 적용이다. 계기는 **2026-10-13 `b3d26f00` 로 들어온 새 이음새** — 연구 대화의
질문 기록(`[self:project]` thread_update 의 `questions[]` / thread_messages 의 `questions_only`)과
근거 참조(`[self:notebook]` read 의 `version_ref·extraction_revision·locator·quote`)다.
새 낱말·op 는 0 이고 기존 어휘의 인자가 늘었다. 긴문장 훈련에서 사용 0회, 계약 문서 §6 이 스스로
"실제 모델이 기록을 얼마나 잘 유지하는지는 별도 실사용 검증 대상" 으로 남겨 둔 자리다.

훈련하는 능력: **실제 공개 원문을 자료실에 보존하고, 질문마다 잠정 답변·지지·반박·남은 확인을 원문
인용으로 묶어 판본을 쌓으며, 기억 없는 다음 호출이 그 기록만으로 조사를 이어받아 계약대로 종결하거나
다시 여는 것.** 51회차(접수증 파일 하나로 저녁·아침을 잇기)의 연구판이고, 62회차의 "판본이 다른
증거 연결" 제안을 실자료로 옮긴 것이다. 정본 문서:
- [연구 질문·근거 계약](RESEARCH_QUESTION_EVIDENCE_CONTRACT_2026_10_13.md) · [연구 질문 가이드](../data/guides/research_questions.md) · [연구 프로젝트 가이드](../data/guides/research_project.md)
- [긴문장 상상훈련 가이드](../data/guides/long_sentence_imagination.md)(§2·§3·§6 개정 `1275e6ad`) · [원장](LONG_SENTENCE_IMAGINATION_LEDGER.md)

이번 회차는 **되먹임 블록**(§8)을 처음 품는다. 56회차 수리 뒤 독립 AI 를 같은 요청으로 다시 돌려
최초 기준선 옆에 적는다. 개정 §6 의 첫 집행이며, 주 과제와 분리해 판정한다.

## 2. 주 과제 — 시스템 AI에도 그대로 줄 자연어 요구

> 긴 문맥 언어모델과 검색증강 생성(RAG)의 상대 성능을 조사하는 연구 대화를 열어 줘.
> 제공한 공개 논문 원문 여덟 편을 그 대화의 자료실에 보존하고, "어떤 조건에서 긴 문맥이 RAG 를
> 이기는가", "둘을 섞는 방식이 비용 대비 나은가", "평가 벤치마크가 결론을 바꾸는가" 세 질문을
> 기록해 줘. 질문마다 잠정 답변을 쓰고, 지지하는 문장과 반박하는 문장을 원문에서 정확히 인용해
> 연결하고, 아직 확인하지 못한 것과 다음에 볼 것을 남겨 줘. 근거가 충분한 질문만 답변으로 종결하되,
> 반박을 지우거나 숨겨서 종결 조건을 맞추지 마. 저장이 끝나면 질문 기록을 다시 읽어 저장된 것과
> 네가 뜻한 것이 같은지 확인하고, 질문별 판본·근거 수·상태를 표로 남겨 줘.
> 그다음 이 대화의 기억이 없는 새 호출로서, 기록만 읽고 조사를 이어받아 종결 가능한 질문을 판정해 줘.
> 이후 제공하는 추가 논문 한 편은 이미 종결한 질문과 충돌할 수 있어. 영향받는 질문만 다시 열고
> 나머지 질문의 판본은 그대로 두며, 무엇을 왜 바꿨는지 적어 줘. 다른 대화의 자료는 쓰지 말고,
> 논문이 참인지는 판정하지 말고 인용이 원문과 같은지만 보장해 줘.

운영자는 입력·출력 경로와 §4 의 공개 판정 계약을 붙인다. 훈련자의 분해·IBL 초안·기대값은 시스템 AI 에
주지 않는다. 시스템 AI 가 IBL 외 수단을 택하면 과제 달성과 IBL 작성 능력을 나누어 기록한다.

## 3. 입력 — 실자료 우선(§3 개정)

**실원문 8편 + 늦게 오는 1편.** 시작 시점에 `[sense:paper]`(arXiv·OpenAlex·Semantic Scholar) 로
"long context vs retrieval augmented generation", "lost in the middle", "hybrid retrieval long context",
"long context benchmark evaluation" 계열을 검색해 공개 초록·원문 PDF 가 있는 8편을 고르고, 9편째는
결론이 반대 방향인 것으로 따로 둔다. 선정 결과(제목·출처·URL·수집 시각·파일 해시)는 `task.md` 에 고정한다.
논문의 주장이 참인지는 과제가 아니며, 설계 문서는 어느 논문이 무엇을 주장한다고 미리 적지 않는다.
읽기 전용·공개 자료이며 외부 발송·구매·게시는 없다. 합성 자료는 쓰지 않으므로 이유를 적을 일이 없다.

**운영자 사전 표(비공개).** 8편의 원문을 자료실에 넣어 `version_ref·extraction_revision` 를 얻은 뒤,
질문 셋 × 논문별로 "지지 후보 문단 / 반박 후보 문단 / 무관" 을 locator 단위로 미리 표시한다.
의미 분류는 운영자 판단이고 점수가 아니다. 점수가 되는 것은 **계약이 기계적으로 보장하는 것**뿐이다.

| 심는 조건 | 기대하는 처리 |
| --- | --- |
| 원문에 없는 문장을 quote 로 연결 | 서버 거부, 프로그램은 거부를 보존하고 성공으로 세지 않음 |
| 같은 인용을 지지·반박에 동시에 | 거부 |
| 다른 대화 자료의 version_ref | 거부 |
| 잘못된 extraction_revision | 거부 |
| gaps 가 남은 질문을 answered 로 | 거부. gaps 를 지워 통과시키는 우회는 판정 실패 |
| 반박이 있는 질문을 objections 없이 answered 로 | 거부 |
| 같은 질문을 두 프로그램이 같은 expected_revision 으로 갱신 | 한쪽 충돌, 최신 판본 재읽기 뒤 재저장, 판본 사슬 유지 |
| 같은 문장·범위의 질문 재생성 | duplicate_candidates 안내, 자동 병합 없음 |
| 종결 뒤 늦게 온 반박 자료로 내용 변경 | 해당 질문만 자동 재개, 무관 질문 판본 불변, 과거 판본·종결 이유 보존 |
| 기억 없는 새 호출 | questions_only 조회만으로 질문·근거·이력을 회수해 이어감 |

## 4. 실행 전에 공개할 판정 계약

1. 검사 결과 / 실행 상태 / 과제 달성을 별도 칸에 둔다. 달성은 모든 필수 조건의 근거가 있을 때만.
2. **인용 원문 일치·접근 이력·판본 사슬·종결 조건은 코드가 보장하는 것**이고, 인용이 주장을 실제로
   지지하는지·논문이 참인지·출처가 독립인지는 판정하지 않는다(계약 §3). 보고서에서 둘을 섞으면 실패.
3. 거부는 결함이 아니다. 거부를 받고 정직하게 보존하면 달성, 거부를 우회하면 미달.
4. 모든 판정 행은 `(project_ref, question_id, revision)` 과 실행 ID·산출물로 거슬러 올라간다.
5. 재개 호출은 앞 프로그램의 변수·result_ref 를 받지 않는다. 받은 것은 `project_ref·thread_ref` 두 값뿐.
6. 비용은 작성·실행·복구·운영을 구분하고 같은 과금 이벤트를 두 번 세지 않는다.

## 5. 훈련자 IBL 의 설계 — 책임 분해

| 부품 | 입력 → 반환 | 확인할 연결 |
| --- | --- | --- |
| 자료 보존 | 논문 8건 경로 → `version_ref`·실패 목록 | `[sense:paper]` download → `[self:notebook]` add, 일부 실패를 빈 성공으로 바꾸지 않기 |
| 원문 읽기 | version_ref → 문단 locator·원문 | `[self:notebook]` read 의 cursor 넘김, 긴 PDF 의 절단 신고 |
| 인용 고르기 | 질문·원문 → 지지/반박 후보 `{version_ref,extraction_revision,locator,quote}` | `[table:ai]` 로 의미 분류, 코드로 quote 가 locator 원문의 부분문자열인지 사전 검사 |
| 질문 기록 | 질문 3 + 근거 → question_id·revision | thread_update 의 질문별 변경 묶음, 전부-아니면-무 |
| 재독 대조 | question_id → 저장 판본 | thread_messages questions_only 로 뜻한 것과 저장된 것의 전건 대조 |
| 종결 판정 | 저장 판본 → answered/open 사유 | gaps 비움·objections 요건을 코드가 먼저 확인, 거부 보존 |
| 재개 | project_ref·thread_ref → 이어받은 판정 | **다른 프로그램·다른 호출**, 접수증 없이 기록만으로 |
| 변경 반영 | 9편째 → 영향 질문 재개·판본 사슬 | expected_revision 충돌 1회를 의도적으로 유도해 재읽기 경로 확인 |

프로그램은 세 경계로 나눈다. **보존·기록**(자료 → 질문·근거 저장·재독) / **재개**(기록만 읽고 종결 판정) /
**변경**(9편째 반영·재개·회고). 재개와 변경 사이에 운영자가 같은 질문에 변경 1건을 넣어 충돌을 만든다.
핵심 대조·조합을 Python 스크립트 하나에 숨겨 전체 IBL 작성 성공으로 세지 않는다. 최초 초안을 보존한다.

## 6. 필수 변형 — 늦게 도착한 반박과 판본 충돌

기본 실행이 세 질문 중 하나 이상을 answered 로 종결한 뒤, 9편째(반대 결론)를 자료실에 추가한다.
동시에 운영자는 종결하지 않은 질문 하나의 notes 가 아닌 `provisional_answer` 를 한 번 갱신해 판본을 올린다.

실행 전 고정하는 기대:
- 9편째의 반박이 닿는 질문만 다시 열리고(status open), 종결 이유·과거 판본은 이력에서 읽힌다.
- 운영자가 올린 질문에 훈련자 프로그램이 옛 expected_revision 으로 쓰면 충돌을 받고, 최신 판본을 읽어
  다시 저장한다. 작성 내용을 버리지 않는다.
- 무관한 질문의 revision 은 변하지 않는다. "모두 다시 저장" 은 미달이다.
- 자료 9건의 version_ref 와 읽기 영수증을 다시 세지 않는다. 재사용은 실제 조회 기록으로 판단한다.

## 7. 독립 비교와 관찰 C

훈련자와 시스템 AI 에 같은 논문 8건(정답표 없음)·공개 계약·출력 경로를 준다. 시스템 AI 는
`POST /system-ai/chat` 에 §2 원문과 `origin:"training"` 으로 보내고, 재개·변형은 같은 대화의 후속 요청이다.
접수·timeout 을 완료로 세지 않고 작업 ID 로 종료를 확인한다.

**관찰 C(측정만, 10분 상한).** 같은 연구 대화에 `thread_send` 로 "지금까지의 질문 기록을 읽고 종결
가능한 질문을 판정해 줘" 를 한 번 보내, **연구 실행의 주 모델이 요약 목록(7,500자 예산)만 받고도 공개
도구로 전체 기록을 읽고 갱신하는지**를 본다. 계약 §5 가 약속한 사용 방식의 첫 실측이며, 갱신이 없어도
결함으로 등록하지 않고 관측으로 남긴다. 독립 AI 가 도는 동안에는 보내지 않는다(44회차 교훈).

## 8. 되먹임 블록 — 56회차 수리 뒤 독립 AI 재실행(§6 개정 첫 적용)

주 과제 전에, 5분 상한으로 56회차 `task.md` 의 요청문을 **글자 그대로** 시스템 AI 에 보낸다
(기본 1회, 보증금 상한 변경 후속 1회). 실서비스 읽기 전용이며 HTTP 뿐이라 브라우저 격리 문제는 없다.

| 기준선(10-11, 수리 전) | 값 | 이번에 볼 것 |
| --- | --- | --- |
| ep4604 기본 | 146.758초, 수집 IBL·비교 Python, RESULT_MISSING(L56-5) | 같은 오류가 재발하는가, 경로 선택이 바뀌었는가 |
| ep4605 변형 | 56.470초, 재검색 0, 반환 오류 재발 | 가이드 수리(복구 안내)가 후속 턴에서 효력이 있는가 |

표본 1회이므로 일반화하지 않는다. 산출물은 56회차와 같은 완료 조건으로 대조하되, 실서비스 매물은
그날 다르므로 **건수·가격이 아니라 구조·실패 구분·원응답 보존**을 비교한다. 시간·토큰은 나란히 적고
절감률로 환산하지 않는다. 못 돌리면 미검증으로 남기고 주 과제를 줄이지 않는다.

## 10. 이번 설계가 새로 확인하는 것과 하지 않는 것

새로 확인하는 것: 연구 질문 이음새의 첫 긴문장 사용, 실원문 인용 계약의 거부 경계, 기억 없는 재개,
늦은 반박에 의한 재개와 판본 충돌 복구, 그리고 **수리가 독립 AI 를 바꿨는지를 재는 첫 되먹임**.
이 연결은 연구 외에도 법률·의료 준비철(53·55회차)의 "모델 제안을 원천으로 확인" 과 같은 꼴이다.

하지 않는 것: 새 낱말·op·인자, 다른 대화로의 질문 공유, 유사 질문 자동 병합, 논문 진위·출처 독립성
판정, 관용구 등록·해마 시딩, 라이브 코드 변경. 발견한 결함의 수리는 훈련 종료·작업 회수 뒤 별도로 한다.
