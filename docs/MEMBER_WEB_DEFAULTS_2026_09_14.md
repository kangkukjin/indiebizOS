# 외부사용자 웹앱 — 기본 제공과 기기 산출물

## 제품 계약

외부사용자는 주소와 회원 키로 로그인한다. 지원되는 기능은 기본 제공하며 사람별 기능 허가표를 만들지 않는다.
주인의 활성 묶음과 공통 제외 설정은 유지하되, 별도 공개 버튼을 누르지 않아도 회원 지원 기능을 쓸 수 있다.
하드웨어 기능이 없는 브라우저에 네이티브 제어를 소개하지 않는다.

표면은 자율주행과 앱 두 가지다. 자율주행은 회원 전용 에이전트의 채팅이며 시스템 AI·설정·조종실을 포함하지 않는다.
파일은 앱 안의 보조 도구에서 가져오고 내려받는다. AI 추론은 허브/모델 제공자가 처리하고 기기 저장은 브라우저가 담당한다.

## 확인한 기존 구현과 수정

| 항목 | 기존 | 수정/유지 |
|---|---|---|
| 회원 기능 기본값 | 별도 공개 선택 없으면 모두 닫힘 | 회원 지원 기능은 기본 허용, 명시적 공통 제외는 유지 |
| 회원 에이전트 | 별도 MemberRunner·회원 주체 | 유지. 시스템 AI 싱글턴을 사용하지 않음 |
| 파일 | 회원 IndexedDB 및 감사된 문서 변환 | 유지. 브라우저 저장·계산의 반복 승인 제거 |
| 앱 카탈로그 | 선언형 일부만 노출, 독립 앱 제외 | 주인 경로 별칭·명시적 원격 대상·필터 뒤 빈 탭도 제외 |
| 정기보고 | 회원에게 앱 자체가 없었음. 주인 앱은 @hub·주인 가이드·시스템 AI 위임 사용 | 회원 전용 작성·내 보고서 앱 추가 |
| 결과 전달 | 최종 채팅 결과에서 파일을 직접 받기 어려움 | 기기 저장 영수증을 표시하고 내려받기 제공 |

기본 허용은 액션의 회원 지원 선언을 대신하지 않는다. `member_profile`의 선언·실행 위치·감사 지문 검사를 유지한다.
선언이 없는 주인 관리 기능과 지원되지 않는 브라우저 기기 작업은 카탈로그·실행 양쪽에서 제외한다.

## 앱 제작 요청과 저장

`data/member_apps.yaml`의 `request: {title, message, output}`은 앱 버튼을 회원 전용 채팅 작업으로 연결한다.
이것은 UI 선언이며 새 IBL 낱말이 아니다. 요청 프레임은 인증 키 없이 부모에게 메시지를 전달하고 부모가 회원 세션으로 제출한다.
화면에는 간단한 작업명을 보여주며 내부 작성 지시를 사용자 요청으로 길게 표시하지 않는다.

`output`은 브라우저에서 상대경로로 검증하고 `/m/run`에는 보내지 않는다. 성공 응답 본문을 작업 ID가 붙은 고유 파일로
회원 IndexedDB에 저장한 뒤에만 작업을 완료 처리한다. 저장 실패·취소·빈 응답은 전달 실패다. 파일 경로와 `on:body`·`saved`
영수증은 작업 기록에 보관한다. 일반 IBL write의 파일도 같은 회원 작업의 완료 영수증에서 모은다.
결과의 내려받기는 실제 파일 바이트를 해당 브라우저에서 OS 다운로드로 보낸다.

정기보고 작성은 브라우저 전용 선언이다. 선택형 네이티브 헬퍼에 브라우저 저장을 약속하지 않는다.
주인용 `data/instruments/report.yaml`·스케줄·공유창고·시스템 AI 위임을 실행하지 않는다.

## 남은 기능 범위

정기보고는 **제공 자료 기반 작성**이다. 기존 회원 사전에는 일반 웹 검색·크롤링이 없으며,
주인의 검색 구현은 로그인 브라우저·개인 관점·캐시 등을 사용할 수 있어 단순 공개로 옮길 수 없다.
주인용 자동 자료 수집과 예약 보고서가 회원에게도 완성됐다고 주장하지 않는다.
자료가 없으면 필요한 자료와 작성 양식을 안내한다. 검색하지 않은 최신 사실·링크·수치를 만들지 않는다.

현재 회원용으로 전환된 앱만 제공한다. 주인 런처의 모든 앱을 외부사용자의 기기 관점으로 옮기는 작업과
지원 기능을 기본 허용하는 정책은 별개의 범위다. OS 전체 파일 접근·네이티브 앱 조작은 설치 없는 웹앱 기능이 아니다.

## 검증

- 회귀 검사: 기본 허용 후에도 관리 기능·미지원 기기 기능 차단, 주인 경로/원격 대상 카탈로그 제거,
  실제 회원 IBL write에 `@hub`를 붙여도 회원 기기 봉투만 사용하고 허브 파일이 생기지 않음.
- 브라우저 런타임: 응답을 저장한 뒤 완료 처리, 기기 저장 실패 시 실패 반환, 새 세션에서 파일 재열기,
  다른 회원 저장소에 파일 없음, 절대경로 거절, 브라우저 내부 작업의 반복 승인 없음.
- 실제 Chrome·IndexedDB: 로그인 → 정기보고 작성 → 저장 → 내려받은 파일 내용 검증 → 새로고침 후 복원,
  두 모드 및 내 파일 진입, 390px 화면의 가로 넘침 없음, 다른 회원 파일 분리 확인.
- 브라우저 시험의 허브와 모델 응답은 시험 대역이다. 유료 모델의 보고서 품질·실제 외부 HTTPS 로그인·
  Android/iPhone 실기기 시험을 대신하지 않는다. 실재 회원 키나 주인 파일을 시험에 사용하지 않았다.

구현 회귀: `backend/test_member_defaults_and_delivery.py`. 기본 설계: `EXTERNAL_SERVICE_APP_HANDOFF.md` §14.

최종 확인: 회원 관련 회귀 55건과 추가 러너 검사 10건, TypeScript 검사·Vite 빌드,
IBL 파생물·회원 셸 번들·Android 매니페스트·층·파일 크기 검사를 통과했다.
전체 backend 실행에서는 브라우저 전용 앱 필터를 반영하지 못한 시험 설정과 새 시험 파일의
직접 실행 진입점 누락 두 건이 실패했다. 둘 다 수정하고 해당 파일 및 러너 검사를 다시 통과했다.
전체 backend를 수정 후 다시 전량 실행한 것은 아니다. 실행 중인 `/m/app`이 현재 코드와 일치하고,
회원 지원 묶음들이 별도 공개 선택 없이 활성인 것도 읽기 전용 조회로 확인했다.
