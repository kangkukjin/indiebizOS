# 최종 응답 후 장기 기억 선별

2026-09-12. 사용자가 승인한 수정: 기억을 최종 보고 전에 쓰지 않고, 사실 중에서도 지속적으로 쓸 가치가 있는 것만 보존한다. 특정 구매 에피소드의 절차를 고정하지 않는다.

## 원인과 변경

자동 증류는 사용자 원문을 선별했지만 `self:memory save`는 실행자가 작성한 본문을 즉시 저장했다. assistant 출처·작업기록 분류는 근거 없는 분석이나 휘발성 시세의 저장을 막지 못했다. [3548/3549 감사](EPISODE3548_3549_CONSCIOUSNESS_OFF_AUDIT.md)의 구매 기억 27번에서는 평가자가 기각한 분석이 최종 보고에서 제거된 뒤에도 남아 있었다.

- 도구 `save`는 본문을 저장하거나 대기열에 넣지 않는다. `success:true, saved:false`는 정책 안내의 정상 응답이며 저장 성공이 아니다. 대화 중에는 `automatic_selection`, 대화 밖에서는 `not_saved`를 반환한다. 추가 호출·저장 완료 보고를 금한다. category/node/keywords도 이 경로에서 적용하지 않는다.
- 기존 `distill_queue`와 `_after_response`가 최종 응답 후 사용자 원문을 선별하는 유일한 AI 장기 기억 쓰기 경로다. 검수·보완 후 최종 본문이 전달된 뒤 큐에 적재한다. 취소·예외로 중단된 파이프라인은 증류를 적재하지 않는다. 검수가 UNKNOWN/NOT_ACHIEVED면 심층 증류를 생략한다. 검사가 필요 없어 생략된 정상 응답은 허용한다.
- 원문 ID·사용자 출처·질문/요청 여부·retention을 검증하며, 선별 모델이 이번 대화 밖의 구체적인 지속 용도를 `future_use`로 설명하지 못하면 제외한다. 저장 내용은 모델의 재서술이 아니라 원문이고 최종 응답의 SHA-256을 출처에 남긴다. 가치 판단 문구 자체는 사실 본문에 저장하지 않는다.
- 사소한 사실·진행 기록·AI 분석·권고·조사 결과·휘발성 값·일회성 조건은 에피소드/산출물에서 회상한다. 의견을 객관적 사실로 만들지 않는다. 명시적 지속 선호·확정 결정은 사용자가 그렇게 말했다는 사실로 보존한다. 0건 저장은 정상이다. 기존 중복 비교·별도 보충·정정 이력 보존은 유지한다.
- `save`는 실제 쓰기가 없어 사전의 `side_effect:false, returns:scalar`로 정렬했다. 이 호출만으로 최종 평가가 발동하지 않는다. 실제 도구 실패·다른 변경 등 기존 평가 조건은 유지한다.
- 기억 지도 안내·공통 프롬프트·카탈로그·도구 스키마·런타임 안내·정본 문서를 함께 바꾸고 은퇴 계약을 등록했다. 새 AI 호출이나 별도 기억 큐는 추가하지 않았다.

이 계약은 AI의 장기 기억 입구에 적용한다. 저장소의 CRUD는 정정·색인·문서 동기화에 계속 사용한다. 외부 조사 결과 전체를 새로운 자동 장기 기억 입력으로 확장하지 않았다. 내용의 지속 가치 판단은 기존 선별 모델이 담당하므로 이 변경이 모든 의미 판단 오류를 기계적으로 없앤다는 뜻은 아니다.

## 기존 오염 정리

기억 27번의 본문·출처 지문이 감사 당시와 같은지 대조한 뒤 DB와 기억 트리를 `data/_backups/2026-09-12_memory_final_retention/`에 백업했다. 저장소 삭제 API로 해당 행을 제거하고 트리를 다시 동기화해 부활하지 않음을 확인했다. 다른 25개 행은 모든 필드가 동일하다. 원문/개인 기억은 커밋하지 않고 [정리 영수증](experiments/memory_final_retention_cleanup_2026_09_12.json)에 ID·지문·검증 결과만 남겼다. 다른 과거 기억 전체를 일괄 삭제하지 않았다.

## 검증

`backend/test_memory_final_retention.py`는 즉시 저장 금지, 저장하지 않는 호출의 평가 조건, 최종 전달 후 수정 본문 적재, 검수 도중 종료·예외, 미승인 증류 금지, 지속 용도 없는 후보 제외, 모델 분석 대신 원문 저장을 검사한다. 기존 기억·감독·증류 큐 회귀도 실행했다. 실제 외부 모델로 새로운 구매 에피소드를 실행하거나 비용 절감률을 측정한 검증은 아니다.

검증 결과: `.venv/bin/python -m pytest backend/ -q` 전체 3,947건 통과(실패·오류 0, 기존 수집 제외 1개: test_narration_injection). 사전 파생 일치·은퇴 계약·층 검사 통과. `scripts/build_ibl_nodes.py`와 `scripts/build_body_bundle.py android`로 파생물을 재생성했다.

실행 적용: 활성 사용자 턴과 미처리 후속 작업이 없음을 확인한 뒤 기존 재기동 제어자로 반영했다. 종료를 기다리던 과거 브라우저 드라이버도 제어자가 회수했다. 새 워커의 코드 지문이 현재 정본과 일치하며 ACTIVE·ready·새 요청 수락을 확인했다.
