# 모델 문맥을 충분히 사용하는 압축 정책

2026-10-01 사용자 결정: IBL 기본 문맥과 검색·개발 기록을 작업 자산으로 보존한다.
문맥이 커졌다는 이유만으로 비용 절약용 조기 압축을 반복하지 않는다.

## 현재 정책

- Codex: `models_cache.json`의 `max_context_window`(없으면 `context_window`)를
  CLI `model_context_window`에 전달한다. 압축 문턱은 같은 창의
  `effective_context_window_percent`이며 다시 50%로 낮추지 않는다.
  현재 gpt-6-astra 카탈로그 기준 창 872,000, 압축 828,400토큰이다.
  카탈로그를 못 읽으면 임의 한도를 만들지 않고 CLI 기본값을 따른다.
- Claude Code: `CLAUDE_CODE_AUTO_COMPACT_WINDOW=300000` 강제를 제거한다.
  CLI의 모델·계정별 기본 문맥 관리에 맡긴다. 압축 자체를 끄지는 않는다.
- 두 CLI: 별도의 크기 기반 fresh 세션 리셋을 기본 해제한다. CLI 자체 압축과
  중복해서 기록을 버리지 않는다. 명시적 새 대화·권한 지문 변경·유실 세션 복구는 유지한다.
- API: `data/model_context_windows.yaml`의 모델별 한도를 사용한다.
  입력 예산은 `min(창 × 95%, 창 − 요청 출력 예산 − 1024)`이다.
  5%는 추정 오차·도구 증가 여유이며 비용 절약을 위한 50/80% 문턱이 아니다.
  시스템 프롬프트와 도구 정의도 계산에 포함한다. 캐시 적중분도 문맥 공간을 차지한다.
- OpenRouter: 공개 모델 메타데이터의 `context_length` 우선. 실패하면 공급자/모델
  규칙으로 판정하므로 GPT-4.1과 Claude의 창을 OpenAI 옛 128K로 취급하지 않는다.
- Ollama: `/api/ps`에 있는 실제 할당된 `context_length`를 우선한다.
  로컬 모델의 이론상 최대값을 근거로 RAM/VRAM 할당을 자동 확대하지 않는다.
  이 경로는 기존처럼 요약이 아니라 오래된 도구 결과 축소를 사용한다.

## REFLEX 실행 문맥 (2026-10-19 사용자 결정)

무의식의 기존 분류 호출에 `REFLEX`를 추가한다. 현재 요청과 짧은 최근 대화만으로
대상·행동·범위가 명확한 단순 조회·조작에 사용하며, 해마 유사도로 분류를 생략하던
옛 반사 경로와 다르다. 모델·기어·공통 시스템 프롬프트(System structure 포함)·전체
IBL 어휘·도구 정의·이번 턴 회상은 기존 EXECUTE와 같다. 새 분류 호출은 추가하지 않는다.

사용자가 `#reflex`를 붙이면 무의식 분류 호출 없이 REFLEX로 결정하고 의식 단계도
건너뛴다. 대소문자를 구분하지 않으며 여러 명시 태그가 있으면 기존 우선순위를 보존해
`#repair > #think > #execute > #reflex` 순으로 선택한다. 명시 선택에도 아래의
문맥 적합성 검사와 실행 전 일반 경로 복귀는 그대로 적용한다.

과거 CLI 트랜스크립트만 재개하지 않고, 최근 사용자·최종 답변 최대 4개(합계 6,000자)를
별도 실행 세션에 전달한다. 긴 발화를 잘라 넣지 않고 기존 EXECUTE로 돌린다.
첨부 판독·대화 소유권이 없는 호출·별도 coding 세션도 기존 경로를 사용한다.
HTTP `/system-ai/chat`(원격 런처 자율주행 탭·훈련 리허설)은 2026-10-19 긴문장 79회차 L79-1 수리로 같은 소유자
세션의 턴을 열어 소유권을 가진다 — 그 전에는 이 경로의 모든 요청이 `missing_conversation_binding` 으로 EXECUTE 였다.
동시 요청으로 턴을 못 열면 옛 무소유 경로로 가고 `conversation.binding_skipped` 사건을 남긴다.
HTTP 직접 수행의 완료는 답변 저장과 턴 해제 뒤에 공개한다. 완료 조회 뒤의 순차 후속을
동시 요청으로 오인해 REFLEX와 영수증 인계가 빠지지 않도록 한다(80회차).
이는 보존 중인 주 세션의 조기 압축·리셋이나 어휘 스코핑이 아니다.

실행자는 도구 호출 전에 문맥 부족 표식을 내면 기존 전체 문맥 경로로 한 번 돌아갈 수 있다.
도구를 호출한 뒤에는 자동 승격·재실행하지 않는다. 별도 실행 안의 후속 호출은 그 턴의
임시 세션만 재개한다. 주 CLI의 세션 ID·크기·기록은 그대로 유지한다.

별도 실행의 요청·최종 답변·완료 여부·결과 참조는 기존 conversation_events에 남긴다.
다음 일반 실행이 미전달 결말을 주 문맥에 받고, 정상 응답 뒤에만 전달 완료를 기록한다.
다른 대화·실행 주체에는 인계하지 않는다. 취소·실패 후 외부 효과가 있었다면 미완료로 남긴다.
최종 사용자 답변은 기존 대화 저장·검수·증류 경로를 그대로 지난다.

동작 근거는 `cognition.reflex_context`, `cognition.reflex_fallback`, 기존 `model.input`·
`model.usage`로 확인한다. 짧은 세션도 공통 문맥을 포함하므로 입력이 몇백 토큰으로
줄어드는 기능이 아니다. 실제 절감률·지연 개선은 같은 작업의 모델 사용량으로 판단한다.

## 한계와 확장

API의 글자 수 추정(2자/토큰)은 실제 토크나이저와 같지 않다. 이미지·추론·언어에
따라 차이가 있으므로 수치는 실제 토큰 측정값으로 보고하지 않는다.
미확인 모델은 카탈로그의 보수적 fallback과 경고를 사용하며, 최대값을 확인했다고
주장하지 않는다. 새 모델의 한도는 출처와 함께 데이터 규칙에 등록하거나
생성자의 `context_window_tokens`로 명시한다. 별도 모델 호출은 추가하지 않는다.
CLI/API/구독의 한도는 서로 다를 수 있어 OpenAI API의 창을 Codex에 복사하지 않는다.
