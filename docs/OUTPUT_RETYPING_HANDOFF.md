### 2a. 결과 되받아쓰기 → **턴 범위 이름 변수** ✅ 집행(09-06, 사용자 판정)

턴으로**. 판정 "그렇게 고쳐" → 같은 세션 집행.
- 왜 `$rN` 이 아닌가: 번호는 봉투 일련번호라 뜻이 없고, 해마 코퍼스에 남으면 그 프로그램은 다른 주행에서 재사용 불가.
- 왜 resume 명시 확장이 아닌가: 참조가 언어 밖(도구 인자)에 살고, 경로 베끼기가 남고, 한 호출에 하나라
  `$a & $b >> [table:join]` 이 안 되고, 표면마다 파라미터 배관이 필요.
- 구현: `backend/ibl/ibl_turn_vars.py`(키=(agent, task_id) → `data/spill/turn_vars_*.json`, 24h GC 동승; code 가 참조하는
  이름만 preset) · 실행기 `_want_live_vars` 컨텍스트 → 내부 키 `_live_vars`(중첩 파이프 봉투는 안 부풀림) · 표면
  `_attach_turn_vars`(단일 step 할당 포함) · 봉투 `turn_vars{injected, live, too_large, note}` · 죽은 마지막 할당의 슬롯 pop
  (오류 봉투가 산 변수로 둔갑하던 자리) · 절단 다음 걸음 문구 · 도구 스키마·MCP docstring·12_ibl_only 한 줄 · ibl.md 개정.

  예약 이름 미주입. `resume` 은 턴을 넘는 24h 회수 자리에 그대로.
- 가드: `backend/test_turn_vars_2026_09_06.py`(다음 호출 참조·세 호출 합성·단일 문장·다른 턴 격리·task 없음·재할당 우선·

### 2b. 파일 되받아쓰기 → 겹침 관문 + 줄범위 편집
- `[self:write]`·`[self:edit]` 인자(new_string·content·`$file:N` 해소 뒤) 중 대상 파일 **현재 내용과 그대로
  겹치는** 구간 ≥ 2,000자 = `warning`(줄 a~b 를 짚고 "edit 차분·줄범위·$변수 로 가리킬 것"), ≥ 8,000자 =
  거절. 임계는 `data/lifecycle_policy.yaml` 데이터, 코드엔 상수 이름만. 탐지는 문자열 일치만(어휘 이름 없음).
- `old_string` 되타이핑 오타(끊→끓, ep2884)의 근본은 "모델이 원문을 다시 친다"이다 — 09-05 셸 그림자 관문이
  연 **줄범위 edit**(`edit 줄범위`)를 가이드·거절 처방에서 첫 선택지로 올린다. 갈린 줄 진단(`3bb6ff39`)이
  이미 줄을 짚으므로 처방 문구에 "그 줄범위로 edit" 한 걸음을 잇는다.
- 같은 편집을 두 자리(워크트리+라이브, ep2884)는 수리 경로가 **한 번 적용·기계 전파**: `[self:patch]` propose→
  apply 가 diff 를 옮기는지 확인, 모델이 라이브에 다시 치는 자리를 닫는다(repair_staging).

### 2c. 배관 재타이핑 → 코퍼스가 "이건 이름이 있다"를 말한다
- `ibl_code_corpus` 가 원문 해시·누계를 가진다. 실행 관문에서 들어온 다문장 code 를 슬롯 정규화 해시로
  대조해 **같은 프로그램이 이미 이름(alias)이 있으면** 봉투 `note: "이 프로그램은 [fn:이름]{슬롯…} — 다음부터
  이름으로"`, 이름은 없지만 성공 누계 ≥ 2 면 증류 자동 작명 대상 표시. 실행은 그대로(거절 아님).
- 자동 작명(`code_name→alias`)이 보고서 가지 밖 모든 가지에 적용되는지 확인.
- 05시 주행 `[fn:]` 0 은 가르침만으로 안 먹은 증거 — 위 note 가 관문 한 겹.

### 2d. 같은 실행 두 번 → 봉투가 알린다
- 턴 안 같은 인자 해시 재실행(`rerun_dup`, ep2884 15K자 셸 두 번·ep2882 5쌍)은 두 번째 실행에 `note: "같은
  실행이 이 턴에 있다 — vars_ref 로 주입할 것"`. 실행은 한다(거절 아님).

### 2f. 사고 토큰 — 조치 없음

## 7. 반성 — 보편 문제라면 처방도 보편 처방과 대조해야 한다 (09-06, 사용자 요청)

다른 세션의 진단: 되받아쓰기는 IBL 의 문제가 아니라 "모델이 데이터 버스 노릇을 하는 모든 LLM 호출"의 문제. 업계 처방과 대조:

| 처방(외부) | 핵심 | 우리 대응물 | 차이 |
|---|---|---|---|
| Anthropic 프로그래매틱 툴 호출 / 코드 실행 MCP | 중간 결과는 샌드박스에 머물고 **코드가 print 한 것만** 모델 컨텍스트로(150K→2K 토큰) | `>>` 파이프(프로그램 안), 턴 범위 변수(호출 사이) | **기본값이 반대** — 우리는 봉투가 final_result 전체를 모델에 돌려주고, 모델이 그걸 들고 있다가 다시 친다 |
| CodeAct(2024) | 변수가 데이터 흐름 — 한 호출의 출력이 다음 인자로 코드 안에서 흐름 | `$이름`, `&`, `>>` | 같음(IBL 이 먼저 가진 것) |
| MemEx(Databricks) | 커널이 **타입 있는 객체**를 턴 넘어 보관, 모델은 print 만 봄. **전사 오류 2배 감소** | 턴 범위 변수(문자열) | 전사 오류 감소는 우리 끊→끓(ep2884)과 같은 병 — 되받아쓰기는 시간만 아니라 **오류**의 원천 |
| Claude Code Edit(old_string 앵커) vs apply_patch | 모델은 줄 번호를 못 셈 → 짧은 앵커; 패치는 문맥 줄 echo 대신 가시성 | `[self:edit]` old/new, 줄범위 edit | §2b 의 "줄범위 edit 우선" 권고는 **철회** — 앵커는 이미 짧았다(27개 199자). ep2884 의 낭비는 같은 패치를 두 자리에 친 것 |

**반성 1 — 관문은 뿌리가 아니다.** 09-06 집행 5건 중 3건(되받아쓰기 관문·평가자 형식·최종 응답 규약)은 *쓰는 쪽에 말하는* 처방이다. 업계는 반대로 **기본 경로에서 되받아쓸 재료를 모델에 주지 않는다**. 관문·규약은 백스톱과 계측으로 격하하고, 뿌리는 봉투 기본값이다.

**반성 2 — 봉투 기본값 반전(언어 개정 후보, 판정 필요).** 지금: `final_result` 원형 전부 → 모델. 제안: 문장의 결과는 **턴 변수로 보관**되고 봉투에는 **미리보기**(통화 형태·열·건수·앞 N행/N자)만 실린다. 전체가 필요하면 모델이 `>> [table:take]`·`[table:select]`·`verbose:true` 로 *요구*한다 — "모델이 보는 것 = 모델이 print 한 것". 이름 없는 결과는 그림자로만 남고 참조는 이름을 붙였을 때만(이미 그렇다). 예상: 입력 재독(라운드당 111~177K자)과 출력 되받아쓰기 둘 다 줄고, 절단 문제가 구조적으로 사라진다(미리보기는 항상 작다).

**반성 3 — IBL 이 이미 맞게 가진 것.** 프로그램 안 파이프는 프로그래매틱 툴 호출과 같은 형태였다. 구멍은 호출 경계(2a 로 닫힘)와 기본 반환(반성 2)뿐이다. 진단은 시스템 전체의 것, 처방은 언어에 두는 것이 맞다 — 셸·챗 우회 통로는 계측만 가능.

**반성 4 — 우회 통로 계측.** `[출력해부]` 는 IBL 봉투만 본다. Bash 원라이너·프로바이더 직접 호출의 되받아쓰기는 턴 전체 출력(도구 인자 전부) 기준으로 재야 한다 — `ibl_call_cost` 를 tool_calls 전체(Bash 포함)로 넓히는 것이 다음 걸음.
