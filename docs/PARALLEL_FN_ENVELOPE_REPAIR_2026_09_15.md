# 병렬 함수 반환의 중복 실행 기록 요약

2026-09-15. 모델에게 전달하는 결과 사본에서만 병렬 분기 속 함수 실행 기록을 요약한다.

## 문제와 수정

`diet_envelope`는 최종 값이 단독 함수 봉투이면 내부 `results`를 요약했지만,
`workflow_parallel`이 반환하는 분기 목록이면 `_diet_fn_result`의 객체 검사에서
그대로 반환했다. 병렬 함수의 중간 원문이 최종 결과 안에 중복되어 전달됐다.

기존 요약기가 반환 목록을 따라 함수 봉투를 찾도록 확장했다. 객체와 JSON 문자열
표현을 모두 처리하고, 바뀐 곳만 복사한다. 요약할 함수가 없는 문자열의 공백과
직렬화도 유지한다. 함수·목록 중첩은 기존 깊이 상한 안에서만 방문한다.

엔진 함수 표식(`fn_source`, `fn`, `steps_total`, `results`)을 갖춘 봉투만 요약한다.
일반 업무 객체의 속성이나 `items`·`rows` 내부는 순회하지 않는다. 최종 업무 값,
오류·부분 실패·출처·정의·재개 정보는 보존한다. 원본 객체와 저장 원문은 수정하지
않고, 상세 실행 원문은 기존 `result_ref`/`read_result`로 조회한다. 추가 AI 호출은 없다.

## 검증 범위

수정 전 신규 회귀 15건이 모두 요약 표지 누락으로 실패했고, 수정 후 통과했다.
기존 5건과 합쳐 `backend/test_nested_fn_envelope.py` 20건을 검증했다.

- 관용구·프로그램 정의·저장 워크플로 × 목록/분기의 객체·JSON 문자열 표현.
- 성공과 실패 분기 혼합, 반환값·오류·경고·traceback·재개 정보 및 순서 보존.
- 함수와 목록 중첩, 업무 객체 안의 닮은 필드와 일반 산문·숫자·null 보존.
- 실제 파서·함수·병렬 실행기 통과(잎 액션만 결정론 시험 대역).
- 실제 모델 전달 함수 통과 및 저장된 중간 원문을 경로 지정으로 다시 읽기.
- 원본 불변·반복 요약의 안정성·내부 verbose 원형 보존·전달 문자 감소.

같은 합성 봉투와 모델 전달 경로에서 목록 방문만 종전 동작으로 되돌려 비교하면
직렬화 결과가 254,322자에서 3,628자로 줄었다. 최종 업무 값과 부분 실패 배열은
동일했다. 원문 저장·사건 기록은 메모리 시험 대역으로 두었고 모델은 호출하지 않았다.
인위적으로 긴 중간 원문을 넣은 재현이므로 실제 보고서의 전체 토큰·비용·벽시계
절감률을 측정한 결과는 아니다.
