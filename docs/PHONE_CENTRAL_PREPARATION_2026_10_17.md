# 등록된 폰의 중앙 요청 준비

등록된 원격 장치는 중앙 요청으로 준비·실행·종료한다. 매번 폰에서 대기 화면이나 설치 버튼을
누르게 하는 절차를 기본 사용 흐름에서 제거한다. Android 최초 권한 허용은 별도다.

## 구현

- 주인용 폰 런처에서 미디어 화면·카메라 대기·화면 업데이트 버튼을 제거했다.
- 영상·콘텐츠 요청은 등록 자격이 일치하는 세션 전용 출력 화면을 열고 실제 가시성·출력
  표면 준비를 기다린 뒤 서비스를 시작한다. 화면은 잠금 위에 표시하며 잠금은 풀지 않는다.
- 카메라·마이크 준비가 필요하거나 Android의 백그라운드 서비스 제한이 적용되는 요청은
  기존 센서 연결 화면을 자동으로 연다. 준비된 Android 9 센서는 불필요한 화면 없이 시작한다.
- 화면 시작 기한·취소·세션 신원 검사를 유지한다. 중앙 종료는 해당 화면을 닫고, 폰에서
  출력 화면을 닫거나 벗어나면 해당 콘텐츠/영상 세션도 끝낸다. 일반 통화 수락은 변경하지 않는다.
- 등록된 폰의 최초 시작 화면에서 센서·자동 화면 열기 권한을 설정한다. 권한이나 등록이
  없으면 중앙에 실제 실패 원인을 보고하며 수동 대기 모드를 요구하지 않는다.
- 주인용 폰은 설정된 서명 UI 피드를 최초 15초 뒤, 이후 60초마다 확인해 새 판본을 자동 적용한다.
  서명·기원·호환성·순번·자산 검증과 상태 인계/복구는 유지한다. 회원용 앱은 기존 설치 선택을 유지한다.
  피드가 미설정이면 내장 화면을 사용한다. APK·엔진 업데이트는 기존 중앙 APK 배포 경로를 따른다.

`UI_MODULAR_REPAIR_IMPLEMENTATION_2026_10_16.md`의 수동 UI 설치 설명 중 주인용 Android
폰에 해당하는 부분은 이 자동 적용 정책으로 대체한다. 운영 배포 채널을 새로 발행한 것은 아니다.

## 검증과 인수 경계

- `:app:testArm32DebugUnitTest`: 22개 통과. 이 작업의 준비 경로 5개, 기존 시작 표식의
  만료·닫기·접수 경합 4개, 서명 검증 4개 등을 포함한다. 동시 작업의 화면 검사도 빌드에 포함됐다.
- `:app:assembleArm32Debug`, `:app:assembleArm64Debug`, `:member:compileMemberDebugKotlin`: 통과.
- `backend/test_media_sessions.py`, `backend/test_media_script.py`, `backend/test_surface_display.py`:
  34개 통과. 브라우저에서 입력 중 초안·DOM·실행 상태 보존과 표시 교체 실패 복구를 검사한다.
- `npx tsc -p tsconfig.app.json`, 은퇴 계약 검사, diff 공백 검사: 통과.
- 선택기는 지정한 Kotlin 변경 5개에서 backend 시험 0/710개를 선택했다. Kotlin/JUnit과
  직접 소비자인 미디어 계약·표시 인계 시험을 명시적으로 실행했다. backend 전수는 실행하지 않았다.

검사 시 USB 장치 목록이 비어 있어 이번 변경 APK는 삼성1에 설치하지 못했다. 실제 Android의
백그라운드/잠금 상태에서 중앙 영상 수신·카메라 시작·종료, 최초 권한 화면 및 자동 UI 적용은
실기기 인수가 남았다. 현재 빌드의 UI 신뢰 설정은 `{}`로, 운영 피드가 연결돼 있지 않다.
APK 빌드 성공이나 세션 접수만을 실제 표시·센서 동작 성공으로 보고하지 않는다.
