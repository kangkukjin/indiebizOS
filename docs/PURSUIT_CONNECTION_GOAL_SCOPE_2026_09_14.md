# 전체 목표를 기준으로 과제 연결

에피소드 3793은 같은 속초 여행의 숙박 호텔 온라인 체크인 방법을 묻는 후속 질문이었다.
선택기는 여행 과제를 찾았으나 재검토기는 직전 작업인 아침 식당 조사와 다르다는 이유로
detach했다. 이후 실행자의 과제 메모 쓰기가 거절됐고, 답변에도 내부 연결 실패가 노출됐다.

## 변경

- 후보 선택에 title·status뿐 아니라 전체 goal_criteria를 전달한다. next를 후보의 범위로 쓰지 않는다.
- 상세 검토의 입력을 identity(목표·대상·원발화), recent_work(next/progress/framing),
  다른 후보의 목표로 나눈다. 과거 실행 계획·framing_meta·대형 산출물 기록은 연결 판정에서 제외한다.
- 같은 목표의 실행 준비·이용 조건 확인과 이전에 다루지 않은 하위 질문은 keep이다.
  실제 목표 범위·산출물 추가는 amend, 같은 과제의 전제 정정은 rewrite로 구별한다.
- 최근 발화가 특정하는 대상부터 확인한다. 후보에 상세한 이름이 있다는 사실은
  맥락 없는 ‘그 대상’의 선행 발화가 아니다. 다른 대상·기간·목적의 새 요청과 모호한 지칭은 분리한다.
- 선택에서도 evidence를 먼저 쓰게 하고 기존 pursuit.judgment 원장에 기록한다.
  id만 반환하는 기존 응답은 계속 허용하되 새 evidence의 자료형과 알 수 없는 키는 검증한다.

판정 호출은 기존 선택·재검토 두 단계다. 추가 감독·재시도 루프는 넣지 않았다.
keep은 과제 연결 때문에 새 의식을 요구하지 않지만, 사용자 질문의 실행 분류가 별도로
THINK/REPAIR를 선택하는 경로는 유지한다. 과제의 전체 목표와 과거 사건은 수정하지 않는다.

## 검증

현재 background 모델 DeepSeek의 도구 없는 실제 호출로 아래 8건의 선택과 재검토를 대조했다.
입력 사례는 `backend/test_pursuit_connection_2026_09_14.py`의 CASES에 보존한다.

| 사례 | 선택 | 재검토 |
| --- | --- | --- |
| 아침 식당 조사 뒤 같은 호텔 체크인 질문 | 여행 | keep |
| 같은 숙박의 휠체어 대여 가능 여부 | 여행 | keep |
| 자료 정리 뒤 목표에 포함된 PDF 출력 | 보고서 | keep |
| 한국어 보고서에 영문 산출물 추가 | 보고서 | amend |
| 같은 보고서의 서울→부산 대상 정정 | 보고서 | rewrite |
| 기존 여행과 별개의 다음 달 제주 출장 | 없음 | detach |
| 매출 보고서 후보와 무관한 제주 정책 후속 질문 | 없음 | detach |
| 두 숙박 후보와 최근 대화 없이 ‘그 호텔’ | 없음 | detach |

실제 3793 시작 직전의 pursuit_event 상태와 당시 최근 메시지 6개도 읽기 전용으로 복원했다.
같은 입력을 두 번 실행해 모두 올바른 과제를 선택하고 keep으로 판정했다.
이 시험은 도구 실행·과제 원장 쓰기를 하지 않았으며 시험 궤적을 실사용 원장에 넣지 않았다.
이 결과는 고정 사례의 관측이며 모든 자연어 연결 판정의 무오류를 보장하지 않는다.

자동 회귀는 후보에 전체 목표 전달, 다른 후보·최근 작업의 구분, 불필요한 과거 실행 자료 제외,
연결 뒤 같은 과제의 메모 쓰기, 전체 목표 보존, 선택 근거 기록·형식 검증을 확인한다.
기존 오선택 분리·사용자 정정·늦은 요약 차단 회귀도 유지한다.

전체 backend 회귀는 4,337개 통과, 새 시험 파일의 직접 실행 진입점 누락 1개 실패였다.
해당 진입점을 pytest로 연결하고, 최종 변경 상태에서 과제 원장·연결·단일 러너 검사
50개를 다시 실행해 모두 통과했다. 전체 회귀를 두 번째로 실행하지는 않았다.
Android 몸 번들 재생성과 운영 `/health` 정상 응답도 확인했다.

## 함께 발견한 확정 오류

커밋의 실사용 코퍼스 계약 검사에서 `table:dedup{key: ...}`가 차단됐다.
핸들러는 `by`만 읽어 `key`로 지정한 열을 무시하고 기본 중복 기준을 사용했다.
`key`를 정규 인자 `by`의 별칭으로 등록하고 어휘를 재생성했다. 공통 인자 정규화가
단일 키·복합키를 같은 실행 경로로 전달하고, 둘 다 지정하면 `by`가 우선한다.
복합키·파이프 타입 관련 검사 35개가 통과했다.
