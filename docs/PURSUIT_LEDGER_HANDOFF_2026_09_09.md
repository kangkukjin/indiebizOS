## 0. 한 문장

의식이 턴 시작에 내는 규정(문제·접근·전제·달성 기준)은 지금 인프로세스 객체에 살고 턴(또는 30분)이 끝나면 죽는다. 며칠에 걸친
일은 매 턴 사용자가 맥락을 다시 실어야 하므로 외골격이 아니라 매번 새로 켜는 도구다. **규정을 자아의 원장에 과제 단위로 영속화하고,
새 턴이 그 과제의 이어짐이면 첫 규정이 과거 규정·깨진 전제·진행을 제약으로 받게 한다.** 재료(의식 출력·재규정 삼중항)는 이미 나온다. 새로
생기는 것은 저장소보다 **계약**이다 — 어느 과제인가/규정이 아직 맞는가의 두 판단, 과제 완료/턴 달성의 두 기준, 보관/상태/주입의 세 상한,
늦은 갱신의 버전 규칙(§13).

## 2. 설계 원칙 대조 (헌법·판정과의 정합)

- **AI 가 할 일을 고정 프로그램으로 만들지 말 것**(사용자 판정 09-03 ×3): 과제 객체는 **AI 가 읽고 고쳐 쓰는 데이터**다. 코드가 소유하는
  것은 수명(생성 방아쇠·주입·망각·재기동 복원)과 크기 상한뿐. 진행·남은 것·기다리는 조건의 **내용**은 의식·실행자·턴 끝 경량 AI 가 쓴다.
  단계 열거형·상태기계로 일의 순서를 강제하지 않는다.
- **새 낱말의 기본 답 = 아니오**: IBL 어휘를 늘리지 않는다. 과제는 reframe·ask_user_question 과 같은 **의식↔실행자 이음매** 부류다
  (해마 코퍼스에 섞이면 안 되는 신호). 어휘 노출은 §10 판정 (a).
- **몸의 명사=코드, 세계의 명사=데이터**: 과제 자체는 세계의 명사(데이터 행). 상태 집합 `{active, parked, done, abandoned}` 는 몸의
  수명이라 코드.
- **주관적 기억은 자아별 사적**(memory.md 두 부류): 과제는 자아의 마음이다. 시스템 AI 는 `system_ai_memory.db`, 프로젝트 에이전트는
  그 `conversations.db` — 체크포인트와 같은 분할. 폰 자아와 **비동기화** (§10 (b) 확인).
- **관문은 카운터가 아니라 실패시키는 것**: §8.
- **결정권=가역성**(구성요소 생명주기): 망각은 표식→보관, 삭제 아님. 부활 기록.
- **회상 비용 게이트**: 상시 주입은 목차만(결정 원장·기억 지도와 같은 원칙), 본문은 결박된 과제 하나만.

이름: **pursuit** (가칭. 한 글자 규칙: `task`=턴, `project`=폴더, `goal`=IBL 블록, `workflow`=저장 함수라 모두 불가). id `pursuit_{hex8}`.
저장: SQLite 표 `pursuit` (자아별 DB, 위 §2). 원장 모듈 `backend/datastore/pursuit_ledger.py` (LAYERS `data`).

**세 층의 상한** (아스트라 ④):
- **사건 층**(`pursuit_event`: turns·revisions·goal_changes) — 덧붙이기만, 상한 없음. 오래된 과제일수록 기록이 많은 것이 정상이다. 90일
  `abandoned` 뒤 보관 이동 대상.
- **상태 층**(위 표의 산문 필드) — 고쳐 쓰기, 필드별 상한. 초과는 **잘라내기가 아니라 거절**(작성자에게 압축을 요구 — 봉투 부작용 정직성과
  같은 결). 압축된 상태는 `artifacts`·사건 층 참조를 남겨 되짚을 수 있어야 한다.
- **주입 층**(§7) — 매 턴 읽는 양. 보관 상한과 **독립**: 본문 주입은 필드 우선순위(next → 깨진 전제 → progress → framing → goal_criteria →
  open_questions)로 예산까지 싣고, 잘린 필드는 `…(pursuit read 로 전문)` 표식을 남긴다.

## 4. 수명

### 4.1 생성 — 방아쇠 셋 (reframe 의 두 방아쇠 설계를 잇는다)
1. **의식의 판단**: 규정 출력에 `scope: "turn" | "pursuit"` 한 필드를 더한다(프롬프트 `.md` 수정=라이브). 판단 기준 한 줄: "산출물이 이 턴에
   끝나는가, 아니면 이 턴은 여러 턴 중 하나인가". `pursuit` 면 `title`·`goal_criteria` 도 낸다. 의식이 없는 EXECUTE/Reflex 턴은 **새 과제를 만들지는 않는다**(반사는 정의상
   한 턴짜리) — 그러나 **기존 과제에 참여는 한다**(§4.2 결박은 경로와 독립).
2. **판단 없는 기계 방아쇠**: 턴이 **끝을 못 봤다는 정직한 신호**가 나면 승격 — (i) 재규정이 일어난 턴, (ii) `ask_user_question` 으로 끝난
   턴, (iii) THINK 평가가 최종 NOT_ACHIEVED 로 닫힌 턴. 셋 다 "다음 턴이 이어질 것"의 증거다. 승격 시 title 은 규정 첫 줄에서 기계로 딴다.
3. **사용자 명시**: "이건 과제로 잡아 둬" — 실행자 도구 `pursuit`(§5) 로 생성.

### 4.2 결박 — 새 턴이 어느 과제의 이어짐인가
- 회상 0단계(`cognitive_recall._build_execution_memory`, 결정 원장 `_decision_scent` 옆)에 `_pursuit_scent` 신설: `active`·`parked`
  과제 **목차** 상시 주입(§7 형식). 결정 원장과 같은 이유 — 이어짐은 턴 중간에도 드러나므로 키워드 게이트만으로는 못 잡는다.
- **판단 둘로 가른다** (아스트라 ①). 현재 fit 게이트는 한 호출로 "같은 태스크인가"와 "규정이 아직 맞는가"를 합쳐 답하고, 규칙 2가
  **반박을 fits=false 로** 돌린다(`cognitive_consciousness.py` fit 프롬프트). 장기 과제에서 "아니야, 그 접근은 틀렸어"는 **같은 과제를
  잇는다는 강한 신호**이므로, 이 규칙을 결박에 그대로 쓰면 실패를 기억해야 하는 순간에 연결이 끊긴다.
  1. **선택**(`select`): 목차의 과제들 중 이 메시지가 어느 것의 이어짐인가, 아니면 새 일인가. 주제·대상·산출물의 동일성만 본다.
     반박·정정은 선택을 끊지 않는다. 명시 지정(사용자가 title/id 를 말함·조종실에서 고름 → `thread_context.pursuit_id`)은 **이 단계만** 건너뛴다.
  2. **재검토**(`review`): 선택된 과제의 규정을 `keep` / `amend`(고쳐 쓴 전문, 현재 amended_framing 규칙) / `rewrite`(전면 재작성)
     중 하나로. 반박·새 사실 단언은 여기서 `rewrite` 가 된다 — 그것이 곧 재규정이며 깨진 전제+근거가 `revisions` 에 남는다(§4.3 즉시
     갱신과 같은 경로). 턴의 `achievement_criteria` 는 이 단계가 새로 낸다(과제 `goal_criteria` 와 별개).
- **경로와 독립** (아스트라 ⑤): 선택은 의식 앞, 회상 0단계 직후에 일어난다 — THINK 뿐 아니라 EXECUTE/Reflex 턴도 결박된다("어제
  보고서를 PDF 로 저장해"는 반사이면서 과제의 마지막 단계일 수 있다). 비용 묶기: 활성·parked 목차가 비어 있으면 호출 없음, 명시 지정이면
  호출 없음, 그 외는 경량 한 번(`oneshot_ai_call`, 분류기와 같은 자리). 재검토는 의식이 있는 THINK 에서만 규정 전문을 다루고, EXECUTE/Reflex
  는 `keep` 으로 본문을 제약으로 받기만 한다(진행 갱신은 §4.3 대로 모든 경로에서).
- 30분 framing 캐시는 이 원장의 "가장 최근 활성 과제" 조회로 흡수·폐지(§9).
- 결박된 THINK 턴의 `TurnChannel.original/current` 는 원장 행에서 온다 — reframe 은 손대지 않아도 그대로 작동한다.

### 4.3 갱신
- **즉시**: `reframe._revise` 성공 시 원장 훅 — `assumptions` 의 해당 항목 `broken`+evidence, 새 규정으로 `framing/approach/criteria` 교체,
  `revisions` 에 삼중항 추가. (지금 `framing_cache_set` 이 있는 자리.)
- **턴 끝**: 증류 4단계(해마·심층·가이드 피드백·…) 옆에 다섯째 — 결박된 턴이면 경량 AI 가 궤적 요약을 보고 `progress/next/open_questions/
  artifacts` 를 **고쳐 쓴다**(누적 금지, 상한 안). 결박 없는 턴은 호출하지 않는다(비용). **1단계 범위다**(아스트라 ③) — 규정만 남기고 진행을
  미루면 다음 날 문제 정의는 기억해도 어제 무엇을 끝냈는지 모른다.
- **늦은 갱신의 버전 규칙** (아스트라 ③): 증류는 영속 큐의 백그라운드 워커에서 돈다(`_after_response_async`). 워커가 하나라 증류끼리는
  순서가 지켜지지만, B턴의 실행자 도구 쓰기·재규정 훅은 A턴의 늦은 요약과 겹친다. 그래서 **모든 쓰기는 `{pursuit_id, task_id, base_version,
  patch}`** 를 싣고, 원장은 `base_version == 현재 version` 이면 적용, 아니면 **거절하지 않고 재합류**한다 — 최신 상태 + patch 를 경량 AI 에
  다시 넣어 고쳐 쓰기(사건 층은 순수 덧붙이기라 충돌 없음). 재합류 실패는 `pursuit_event` 에 `merge_failed` 로 남기고 patch 를 버리지 않는다
  (`resume_vars` 스필과 같은 24h 회수 자리).
- **실행자 도구**(§5)가 턴 중에 직접 쓸 수도 있다 — 사람이 메모하듯. 같은 버전 규칙.

### 4.4 종료·망각·재기동
- `done`: 턴 평가의 ACHIEVED 는 **턴 기준**일 뿐 과제를 닫지 않는다. 과제는 의식/실행자가 `goal_criteria` 에 비추어 "전체가 끝났다"고
  표시할 때만 `done`(도구 `pursuit{op:done}` 또는 의식 출력 `pursuit_done: true`). 되돌릴 수 있다(`active` 재개는 `revivals` 기록).
- `parked`: 사람이 세움 / 30일 무접촉(구성요소 생명주기 일일 순찰에 편입 — 새 순찰 만들지 않음). 목차에는 남되 맨 아래 한 줄.
- 90일 더 무신호 → `abandoned`(보관, 삭제 아님). 목차에서 빠지고 조종실 "보관"에서만 보인다.
- 재기동: 원장이 영속이므로 복원 절차 없음. `episode_orphans` 가 CUT/ORPHAN 으로 닫은 턴이 결박돼 있었으면 `progress` 끝에 "끊긴 턴 N —
  마지막 확인 사실까지만 유효" 한 줄을 기계가 붙인다(다음 의식이 낙관하지 않도록).
- 대화 삭제(`clear_conversations`)와 과제는 **독립** — 대화가 지워져도 과제는 남는다(체크포인트와 다름: 과제는 대화의 파생물이 아니라
  자아의 의도). 과제 삭제는 조종실에서만, 한 트랜잭션(행+revisions).

## 5. 실행자 도구 `pursuit` (이음매 도구, IBL 어휘 아님)

두-경로 대칭(reframe 과 같다): 인프로세스는 system_tools 디스패치, Claude Code 는 `mcp_server.pursuit → /ibl/pursuit`.
```
pursuit {op: "note",  progress?, next?, open_question?}   # 고쳐 쓰기 (누적 아님)
pursuit {op: "wait",  waiting_for, probe?}                 # 기다리는 조건 기록 (+선택 IBL 한 문장)
pursuit {op: "park" | "done" | "abandon", why}
pursuit {op: "open",  title, goal_criteria}                # 사용자 명시 생성
pursuit {op: "read",  id?, section?}                       # 잘린 필드 전문·사건 층(revisions/turns) 펼쳐 읽기 — 목차 `+N건` 의 되펼침
```
설명문 골자: "여러 턴에 걸친 일의 확보된 사실·다음 할 일을 적는다. 한 턴에 끝나는 일에는 쓰지 않는다. 진행은 누적이 아니라 고쳐 쓰기."
`op: "note"` 는 결박된 과제가 없으면 정직 거절("이 턴은 과제에 결박되지 않았다 — open 으로 먼저").

## 6. 이 설계가 여는 문 (본 핸드오프 범위 밖, 순서만 고정)

- **실패 회상**(★★★ 두 번째): 새 과제의 첫 규정 때 `revisions` 가 있는 과거 과제를 **해마와 같은 검색기**(`ibl_usage_rag` 의 의도 문장
  검색)로 찾아 깨진 전제 top-3 을 `<prior_breaks>` 로 제약 주입. 재료·검색기·주입 자리가 전부 이미 있어 이 원장만 생기면 하루 일.
- **조건 재개**(★★): `waiting_for.probe` 를 world_pulse 순찰이 돌려 참이 되면 과제를 `active` 로 올리고 목차 맨 위에 "조건 충족" 표식.
  시각 스케줄러로 대부분 흉내 낼 수 있어 뒤로.
- 체크포인트 보존 관문(★★)은 과제가 생기면 우선순위가 내려간다 — 중요한 상태는 과제에 있다.

## 8. 관문 (실패시키는 것, 세지 않는 것)

- **G1 결박 누락**: 의식이 `scope: pursuit` 를 냈는데 턴 종료 시 원장에 행이 없으면 self-check RED (`__telemetry__:pursuit_bind`).
- **G2 재규정 미반영**: 한 턴의 궤적 `framing.revised` 수 > 그 턴이 결박된 과제의 `revisions` 증가분 → RED. ("한 방향만 보는 감사는
  반대로 샌다" — 생산자(궤적)와 소비자(원장) 둘을 대조.)
- **G3 예산**: 목차·본문 상한 초과는 렌더 거절(잘라내기 금지). 원장 쓰기도 상한 초과 거절.
- **G4 고아 과제**: 30일 무접촉 `active` 는 순찰이 `parked` 로 내린다(관문이 아니라 생명주기 규칙 — 기존 순찰 공유).
- **G5 삭제 정합**: 과제 삭제는 revisions 와 한 트랜잭션. 부분 삭제 상태가 관측되면 RED.
- **G6 버전 위반**: `base_version` 없는 쓰기는 거절. 재합류 실패 patch 가 24h 넘게 남으면 RED.
- 회귀 고정물 `backend/test_pursuit_ledger.py` P1~P12: 승격 방아쇠 3종 / 선택 결박 / 명시 결박(선택만 건너뜀) / 재검토 keep·amend·rewrite /
  재규정 반영 / 턴 끝 고쳐 쓰기(누적 아님) / 상태 층 상한 거절·사건 층 무상한 / 망각 두 단계·부활 기록 / 재기동 복원 / 삭제 트랜잭션.
- **시나리오 셋을 먼저** (아스트라 권고, 문서가 약속하는 맥락 유지의 실증):
  S1 **같은 과제의 전제를 반박하기** — "아니야 그 접근은 틀렸어" → 선택은 같은 과제, 재검토는 rewrite, revisions 에 깨진 전제+근거, 다음 턴
  본문에 broken 으로 보인다.
  S2 **중간에 다른 일을 했다 돌아오기** — 무관한 턴 셋 뒤 "아까 그거 이어서" → 선택이 옛 과제를 고르고 progress/next 가 그대로다.
  S3 **요약이 끝나기 전에 다음 턴 시작하기** — A턴 증류가 느린 채 B턴이 progress 를 쓴다 → A 의 늦은 갱신이 B 를 덮지 않고 재합류한다
  (version 이 3, 두 내용이 모두 남음). 기존 `test_reframe.py`·`test_framing_amend_gate.py` 는 그대로
  초록이어야 한다(재규정·fit 은 저장 위치만 바뀐다).

## 9. 정리(소멸)할 것

- `cognitive_consciousness._FRAMING_CACHE` 와 `framing_cache_get/set/clear*`: 원장의 "이 자아의 가장 최근 활성 과제" 조회로 대체.
  30분 TTL 의 의도("오래된 동선이 새 대화로 새지 않도록")는 fit 게이트가 "이어짐인가"를 묻는 것으로 흡수된다 — 시간이 아니라 판단이 막는다.
- `reframe._revise` 의 `framing_cache_set` 호출 → 원장 훅.
- 의식의 fit 게이트: 한 호출 → **선택·재검토 두 호출**로 분리(§4.2). 규칙 2(반박=fits=false)는 재검토의 `rewrite` 로 옮겨 간다 — 과제 연결은
  끊지 않는다. `test_framing_amend_gate.py` 는 재검토 단계의 시험으로 이름·대상만 옮긴다.

## 10. 판정 요청 (사용자 몫)

- **(a) 언어 개정 여부**: 과제를 IBL 에서 열 수 있게 할 것인가 — 예: `[self:memory]{op:"recall", node:"과제/…"}` 류로 노출.
  **기본안=아니오**(이음매 도구 §5 만, 어휘 불변). 노출하면 해마 코퍼스에 과제 이름이 섞이고 어휘가 는다.
- **(b) 폰 자아 공유**: 주관적 기억이므로 **비동기화가 기본안**(맥 자아만 과제를 가짐). 폰에서 같은 과제를 이어 하고 싶다면
  business.db 류 CRDT 가 아니라 "맥의 과제 목차를 폰이 읽기만" 하는 단방향이 맞다 — 지금은 결정 불요.
- 이름 `pursuit` 는 판정 사항 아님(내부 명사, 어휘 아님). 더 나은 낱말이 있으면 바꾸면 된다 — 단 `task` 는 불가(§1).

## 11. 단계

1. **원장 + 과제 선택 + 규정 재검토 + 진행 저장 + 재기동 후 이어 하기** (아스트라 권고 범위): `pursuit_ledger.py`(상태·사건 두 표·version) +
   `cognition/pursuit_bind.py`(`_pursuit_scent`·선택 호출·scope/goal_criteria 처리·reframe 훅·턴 끝 다섯째 증류·재합류·G1/G2/G5/G6) +
   의식 프롬프트 `scope`·`goal_criteria`·`pursuit_done` 필드 + fit 게이트 분리 + framing 캐시 소멸 + `pursuit{note,read,done}` 도구 두 경로 +
   P1~P12 + **S1~S3**. 이것이 "다음 날 이어 하기"의 최소 단위다.
2. **나머지 도구·망각·패널**: `pursuit{wait,park,abandon,open}` + 생명주기 편입 + 조종실 최소 패널(목록·열기·park/done/삭제).
3. **문서 의무**: memory.md 7종 표에 과제 행 추가(작업기억 #2 의 상위 층으로 위치, 흐름도에 `[과제]` 가지) · architecture.md · anatomy.md
   포인터 · changelog.log · 의식·실행자 가이드에 "언제 과제로 잡는가/잡지 않는가"(완성 처방 금지, 자리표 골격).
4. §6 의 문 둘은 별도 핸드오프.

## 12. ⏳ 관찰 (집행 뒤)

- 승격 방아쇠 3종의 비율 — 의식 판단 대 기계 방아쇠. 기계 방아쇠만 발동하면 `scope` 지시가 안 읽히는 것.
- fit 결박의 오탐 — 새 일을 옛 과제에 붙이는 쪽이 더 해롭다(옛 지도로 새 땅). amended_framing 하한·연쇄 상한을 그대로 쓴다.
- 결박된 턴에서 실행자가 `progress` 를 다시 캐는가(되풀이 검색·읽기) — 과제가 제약으로 **읽히는지**의 증거. "소비처에 닿지 않는 출력 필드"
  부류(의식 출력 5개월 미도달)의 재발 여부를 G2 와 같은 대조로 본다.
