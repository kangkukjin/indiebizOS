# 원격 설치·장기 작업의 대상, 결과, 재개

에피소드 4664에서 로컬/원격 파일 조회 혼동, 작업 대기 인자 오류, sh 문법 오류,
설치 종료 코드를 뒤 명령으로 덮는 셸, 중복 패키지와 비규약 백업 위치를 관측했다.
목적은 설치 한 건에 새 IBL 액션을 추가하는 것이 아니라 같은 표현을 빌드·검사·변환에도
쓰고 원격 관측 왕복과 재작업을 줄이는 것이다. 목적 기준은 IBL_EVOLUTION_PURPOSE.md.

## 기존 소유자와 변경

- 대상·관용구: guestpc_prepare/run/check. 준비의 device_id와 workspace(cwd/env)를
  명시 값으로 전달한다. 실행 접수증으로 재관측하며 다른 대상·명령의 재개를 거절한다.
  전역적인 암묵 대상이나 로컬 파일 도구 재라우팅을 추가하지 않는다.
- 접수·보존: 기존 resident_pcs/resident_store/task_receipts. 새 원격 작업 저장소 없음.
  접수증에 cwd/shell, 재관측에 원장의 device/op/request_id를 제공한다. env/stdin은
  원장 투영에 추가하지 않는다. task_ref만 남은 상주 작업도 대상 복원이 가능하다.
- 동기 결과: guest-helper handler가 비정상 exit·error·cancelled·timeout·unknown을
  실행 실패로 올리고 details.execution_result와 task_ref를 보존한다. 대기만 끝난
  셸은 접수된 상태로 돌려준다. 화면 대기 취소와 휴대형 task 상태 어휘는 유지한다.
- 단계 실행: scripts/remote_steps.py. 대상 PC에서 argv·검증 명령을 실행하는 CLI.
  기존 원격 task 아래에 단계별 파일 원장을 둔다. 원격 전송·취소·재접속 계약은 그대로다.
  저장소 단위 OS 잠금, 계획·호스트·루트 지문, 실행 전 영속 기록, 시도별 출력·종료 코드,
  완료 단계 재사용·검증 재실행, 명시한 실패 단계 재시도를 제공한다.
- 설치 내용: scripts/remote_install.py에만 있다. Git fast-forward와 파일 보존,
  의존성 설치·빌드·import/pip 검증을 argv 계획으로 만든다. 일반 실행기에는 IndieBiz의
  패키지 이름·설치 순서·백업 정책이 들어가지 않는다.

## 실패·재개 의미

명령 실패는 이후 단계를 막는다. 설치 성공·검증 실패는 검증만 재시도한다. 완료 단계의
검증이 나중에 실패하면 자동 설치하지 않고 보류한다. 프로세스가 완료 기록 없이 죽으면
살아 있는 자식이나 이미 적용된 효과가 있을 수 있어 재실행하지 않는다. 실제 효과를
확인한 후 남은 작업을 새 계획으로 작성한다. 이것은 임의 외부 부작용의 exactly-once나
롤백 보장이 아니다. 원격 헬퍼의 전체 timeout과 각 단계의 timeout도 서로 다르다.

## 구현 범위와 검증

회귀는 backend/test_remote_steps.py와 기존 guestpc/resident 시험에 둔다. 실제 subprocess의
실패·시간제한·배타 잠금, 검증만 재시도, 계획 변경 거절, 미확정 실행 재전송 방지,
임시 Git 저장소의 ignored 충돌 백업·추적 변경 거절·패키지 정리를 확인한다.
실제 IBL 컴파일러/실행기와 격리 상주 원장으로 대상 고정·참조 복원·동기 실패를 확인한다.

실기기에서 새 조리법으로 전체 설치를 재실행하거나 Windows 프로세스 종료 경로를
검증한 것은 아니다. 맥26의 기존 업데이트는 병행 재설치하지 않는다. 새 헬퍼 바이너리나
새 IBL 액션은 필요 없다. 관용구는 정본 시드와 함께 기존 등록 도구로 개정한다.
정량적인 시간·전체 토큰 절감은 동일 조건의 후속 작업에서 측정해야 한다.

사용·인자·예제 정본: ../data/guides/guest_helper.md의 '대상 고정과 단계 실행'.

## 최종 확인

- 전체 backend 회귀(`-n auto --dist loadfile`, system 포함): 10,268 통과, 13 건너뜀, 252.14초.
- 어휘 빌드 `--check`, 은퇴 계약 관문 통과. Android 몸 번들 파생 실행 완료.
- 선택기 기준 변경 9개 파일에서 전이 시험 68/660개(10%)였으며 설치 경로 변경을 고려해 전수를 실행했다.
- 관용구 3개 실제 개정, 관련 19개 검색 색인 확인. 기존 선택 인자의 호출도 컴파일·실행 검사했다.
- 실행 중 API에서 새 함수 서명과 맥26 기존 작업의 대상·폴더·요청ID 복원을 읽기 전용 확인. 패키지 캐시 갱신 성공, 백엔드 건강 조회 정상.
- 첫 전수의 테스트 진입점 규약 누락과 검사 중 수동 용례 검토 원장 갱신 감지는 해결 후 최종 전수에서 재확인했다.
