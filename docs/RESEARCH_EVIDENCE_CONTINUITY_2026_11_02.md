# 연구 근거의 제출·검수·대화 계승

2026-11-02 연구보고서 `projects/정보센터/outputs/IndieBizOS_연구품질_개선_심층연구_2026-11-02.md`의
R1–R5를 기존 연구 저장소와 실행·평가 경로에 반영한다. 새 연구 에이전트·IBL 낱말·상시 모델 호출은 없다.

## 계약과 소유 지점

| 제안 | 구현 | 소유 |
| --- | --- | --- |
| R1 제출 파일까지 근거 연결 | 명시한 프로젝트 내부 텍스트 파일의 실제 판본을 인용 검사에 포함한다. 경로·SHA-256·표지 오프셋·주장 주변을 평가 입력에 연결한다. 응답과 파일의 중복 표지는 근거를 공유하되 각각의 주장 위치를 보존한다. | base/research_review, final_evaluator, research_threads |
| R2 예산과 미검토 | 인용당 최대 2,400자·총 16,000자를 동등 배분하고 짧은 근거의 남은 몫을 재분배한다. 어휘가 겹치는 원문 주변을 고르고 원문 내 정확한 발췌 오프셋·전체 길이·partial/missing을 남긴다. | research_review, research_library |
| R3 일반 심층연구 | 저장된 `_research_plan`이 있는 일반 프로젝트 턴만 자료실을 연결한다. 프로젝트·에이전트·대화 신원으로 같은 질문 원장을 계승하며 대화 신원이 없으면 과제별로 격리한다. | research_context.TurnResearch, agent_pipeline, research_task_session |
| R4 질문 선택 | 명시 질문 ID·현재 요청과 어휘 관련성·오래된 열린 질문을 선택 순서에 반영한다. 잠정 답·반박 위치·gaps·next_probes를 작은 예산에 넣고 초과 항목은 omitted로 센다. | research_questions.context, research_runner._context |
| R5 표적 검수 | 기존 평가 안에서 파일의 주장과 실제 원문을 대조한다. 수치의 분모·기간·비교군, 인과의 통제·대안, 권고의 반박·적용 조건을 확인한다. | final_evaluator.RESEARCH_POLICY |

`valid`/`reading_verified`는 이번 실행의 원문 읽기 기록이 있다는 뜻이다. `semantic_status=unreviewed`는
자료실이 의미 판단을 하지 않는다는 뜻이며 기존 평가자가 그 판단을 맡는다. `unreviewed` 목록은 발췌
예산 때문에 일부 원문이 빠진 인용이다. URL·일반 각주는 `unresolved_references`로 남기며 자료실
읽기 영수증으로 바꾸지 않는다. 기존 도구 근거로 확인할 수 있는지는 평가자가 판단한다.

최종 평가가 꺼졌거나 보완이 끝나도 유효하지 않은 자료 표지는 성공으로 숨기지 않는다.
일반 파이프라인은 최종 전달 전에 인용 오류를 알리고, 평가 뒤 응답이 바뀌면 기존 판본 검증 경로가
평가 결과를 UNKNOWN으로 바꾼다. 연구 실행 저장 상태도 failed로 남긴다. 연구 전용 대화 역시
응답과 제출 파일을 함께 검사하여 실패를 표시한다. 이는 의미 오류를 기계적으로 탐지한다는 뜻이 아니다.

## 대화와 실행 수명

자료는 기존 conversations.db와 research/objects에 저장한다. `research_task_links`는 일반 대화/과제를
기존 research_threads에 연결하는 작은 원장이다. 기존 자료 저장·읽기·질문 도구를 재사용한다.
도구 반환 관측과 MCP 재진입은 활성 실행 신원에 묶고, 종료·취소 시 문맥과 active_run을 정리한다.
비정상 종료 후 다음 연결에서는 살아 있는 실행을 보존하면서 중단된 원장을 복구한다.
다른 대화 자료를 자동 사용하지 않으며 과거 산출물을 전량 가져오지 않는다. 일반 프로젝트의
위임·권한 계약은 그대로이며 연구 전용 대화의 독립 실행 제한을 일반 턴에 적용하지 않는다.

## 범위와 한계

- R1의 인용 추출 대상은 최종 응답/전달 명세에 명시한 내부 텍스트 파일이다. PDF·이미지·외부 경로는
  기존 산출물 검수를 따르며 이 변경으로 자동 인용 연결을 제공하지 않는다. 재귀 링크를 읽지 않는다.
- 문맥 선택은 결정론적 ID와 어휘 일치다. 상위 질문 그래프·질문 자동 병합·중요도 판정 모델은 만들지 않는다.
  관련 원문을 놓칠 수 있으므로 partial/missing과 기존 evidence 보완 경로를 유지한다.
- 일반 프로젝트의 새 UI와 모든 후속 턴의 연구 모드 강제는 없다. 심층연구로 선택된 턴만 자료실을 연결한다.
  의식의 계획 선택은 기존 경로이며, 실행자는 전달받은 실제 question_id를 계획 진행에 연결한다.
- 근거 quote 예산은 유지하지만 파일별 주장 위치·자료실 안내가 추가되어 전체 프롬프트 토큰이 같다는
  뜻은 아니다. 실제 모델의 연구 품질·완료 시간·전체 토큰 개선은 아직 비교 측정하지 않았다.

## 검증

새 회귀는 backend/test_research_review.py와 test_research_task_session.py 및 기존 research_library,
research_questions, final_evaluator 시험에 넣었다. 파일 전용 인용의 평가 전달, 순서 교환 시 동등 배분,
늦은 반박 조건과 정확한 발췌 위치, 같은 표지의 여러 주장, 외부/심볼릭 링크 제외, 판본 변경,
오래된 관련 질문, 일반 대화 격리·재사용, MCP 신원, 실제 네이티브 반환 보존, 취소·재개를 확인한다.

검증 결과:

- 전체 backend(system 포함, xdist loadfile): 11,817 passed, 24 skipped, 2 failed, 498.63초.
  실패는 내부 발췌 창의 clamp 사유 표기와 새 시험 파일의 직접 실행 진입점 누락이었다.
- 두 실패를 수정한 뒤 해당 검사 파일과 연구 관련 전체 묶음: 163 passed, 30.55초.
  최종 관련 묶음에는 빈 근거의 missing 표시와 기존 자료실 신원 재사용 회귀도 포함한다.
  수정 후 전수를 다시 실행한 것으로 보고하지 않는다.
- backend 층·파일 크기/가이드 예산·IBL 파생 신선도 검사 통과. Android 엔진 번들 재생성.
- 외부 AI·유료 검색을 재호출하는 A/B 실험은 하지 않았다.
