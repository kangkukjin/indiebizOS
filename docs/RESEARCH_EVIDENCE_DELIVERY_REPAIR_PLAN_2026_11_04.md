# 검수 자료 배분과 실행 응답 중복 수리계획

작성일: 2026년 11월 4일. 상태: **계획 작성 완료, 구현 전**.
근거: [5811 조사 보고서](EPISODE_5811_RESEARCH_CONTEXT_AUDIT_2026_11_04.md), [재현 집계](experiments/episode5811_context_audit_2026_11_04.json).
코드 대조 기준: `ff3b2c1073258d69f7aed10b7a00045c6de80c24`.
목적 정본: [IBL 진화 목적](IBL_EVOLUTION_PURPOSE.md), [비전](../data/system_docs/vision.md).

연구자가 확보한 원문을 검수에 충분히 전달하면서 같은 본문·주소·설명을 반복 입력하는 비용을 줄인다. **원문 후보를 먼저 보존하고 최종 요청에서 한 번 배분하며, 표시 중복은 원문과의 관계를 확인한 뒤 접는다.** 조사 질문·반대 근거·판정 기준을 줄이지 않고 기존 자료실·증거 저장소·평가 호출·결과 표시의 책임을 수정한다.

## 2 보존할 계약

1. 사용자 요청·정정·권한·달성 기준은 필수 입력이다. 자료 표시를 줄이면서 이들을 발췌하지 않는다. 평가자는 기존의 도구 없는 호출을 사용하고, 실제 근거 부족은 `UNKNOWN`으로 남긴다.
2. 자료실의 자료 ID·추출 판본·locator·읽기 영수증과 턴 증거 저장소의 해시·문자 좌표는 서로 다른 신원이다. 두 좌표계를 연결하되 같은 것으로 바꾸지 않는다. 이미 읽은 구간만 후보에 넣고, 미열람 원문을 회수했다는 이유로 연구자의 읽기 이력을 새로 만들지 않는다.
3. 저장된 원문, IBL 업무 값과 typed wire, 이미지, `inputs` 참조, 재개·복구 인자는 유지한다. 변경은 모델 표시와 검수 요청 조립에 적용한다. 앱·REST의 구조화된 업무 결과에 모델 전용 축약을 흘리지 않는다.
4. 같은 문자열이어도 다른 판본·원천·역할·주장을 합치지 않는다. 원문 한 벌을 공유할 수 있어도 지지·반박 관계와 각 주장 위치는 별도로 남긴다.
5. 부분 읽기·생략·마스킹·실패·외부 효과 미확인은 정상 성공과 구별한다. 참조가 있다는 사실은 본문 전달이나 의미 검토의 증거가 아니다.
6. 원문 회수 요청은 기존 기준 ID와 불변 증거 ID·판본·범위로 검증한다. 요청된 회수 범위를 다시 자르거나 최신 판본으로 바꾸지 않는다. 수신 확인이 없는 MCP에서 전송 성공을 기억 유지의 증거로 취급하지 않는다.

## 4 R0 재현 입력과 품질 기준 고정

**작업**

- 기존 `scripts/research_episode5811_context.py`를 확장해 최초 검수와 재검수, 실행 결과의 원문·표시·최종 전송 크기를 같은 실행 ID에 연결한다. 누계 사용량을 중복 합산하지 않는다.
- 원래 요청·달성 기준·산출물·읽기 영수증·질문 판본·모델 설정의 해시를 고정한다. 읽기 전용 실자료가 없으면 명시적으로 미실행으로 남기고 최신 웹 결과로 대체하지 않는다.
- 일상 회귀용으로는 개인정보 없는 합성 자료를 기존 모듈별 테스트에 둔다. 긴 문단 끝의 부정·조건, 여러 날짜·단위, 멀리 떨어진 반박, 같은 인용의 서로 다른 주장, 다른 추출 판본을 포함한다.
- 실자료 사본이 필요한 모델 비교는 기존 격리 데이터 루트와 증거 경로를 사용한다. 운영 연구 질문·읽기 이력·보고서를 수정하지 않는다. 원문이나 자격증명을 Git에 넣지 않는다.

**산출물과 인수**: 재현기와 합성 회귀가 최초 검수의 원문 누락, 중복 본문, 필수 경고 보존을 각각 드러내고 제공자 보고 사용량과 집계가 일치한다. 이 단계는 모델 성능 개선의 증명이 아니다.

## 5 R1 읽은 원문 후보를 최종 검수까지 보존

`ResearchLibrary.citation_review()`의 유효성·읽기 증명 수집을 내부 공통 단계로 추출한다. 현재의 발행 검사 소비자(`research_threads`, `research_task_session`, `research_context`의 제출 검사)는 동일한 invalid 판정을 얻는다. 평가 경로는 같은 수집 결과의 **발췌 전 후보**를 사용한다. 검수자용 전체 원문이 다른 호출의 기존 응답에 무조건 추가되지 않도록 내부 경로에서 구분한다.

후보에는 다음 정보를 연결한다. 이는 내부 전달 자료이며 새 사용자 API나 새 영속 원장이 아니다.

| 정보 | 계약 |
| --- | --- |
| 원문 신원 | 현재 프로젝트·대화·연구 run, 자료 version_ref, extraction_revision, locator, access_id |
| 읽은 원문 | 해당 영수증의 실제 quote와 그 안의 문자 좌표. 문서 전체 좌표를 알 수 없으면 만들어내지 않음 |
| 주장 연결 | 산출물 경로·해시·인용 위치와 기존 claim_context의 실제 범위. 같은 표지의 다른 사용 위치도 보존 |
| 질문 연결 | 질문 ID·판본 지문·supporting/contradicting 관계와 원문 anchor |
| 회수 주소 | 마스킹을 거쳐 고정한 턴 증거의 ID·판본·길이와 원문 신원으로 돌아가는 대응 |

`final_evaluator.prepare()`에서 같은 턴의 `TurnStore.evidence()`로 읽은 구간을 고정한다. 후보 본문은 기존 증거 저장소에 한 벌만 두고 packet·checkpoint에는 참조와 대응 정보를 남긴다. 재개 시 DB의 최신 quote를 다시 선택하지 않고 해당 증거를 무결성 검증해 읽는다. 런타임 객체·DB 연결·콜백을 checkpoint에 직렬화하지 않는다.

여러 영수증의 중복은 원천·판본·구간의 동일성이 증명될 때만 공유한다. 겹친다는 이유로 분리된 문장을 이어 새 원문을 만들지 않는다. 동일 내용의 별도 원천은 관계를 유지한다. 대량 영수증은 순회·페이지 방식으로 고정해 메모리 폭증을 피하고, 기존 읽기 제한과 취소 계약을 적용한다. 저장·자료 접근 실패는 누락 사유와 복구 가능성으로 표시한다.

**제거할 중복**: 검수 경로의 `citation_review → 16,000자 발췌 → 문자열화 → 전체 배분에서 재발췌`를 `동일한 유효성 확인 → 판본 고정 후보 → 최종 배분`으로 바꾼다. 다른 소비자가 필요로 하는 요약 표시는 같은 후보에서 파생하며 유효성 확인을 복제하지 않는다.

**인수**: 5811의 52개 인용 구간 24,472자가 회수 가능한 후보로 보존된다. 읽기 이력은 증가하지 않는다. 연구 상태가 조립 중 바뀌면 기존 충돌 처리가 작동한다. 과거 checkpoint는 기존 판정·회수 의미를 유지하며 새 후보를 가지고 있다고 추정하지 않는다.

## 6 R2 검수 자료를 한 번 배분하고 한 번 표현

### 배분 순서

기존 `EvaluationPrompt.prepare_request()`를 최종 배분의 소유자로 유지한다. 최종 제공자 포장, JSON 직렬화, 이미지 여유, 생략 목록까지 포함한 `model_request_budget` 관문은 그대로 사용한다.

1. 사용자 원문·정정·기준·권한과 평가 정책을 고정한다. 이것만으로 요청 한도를 넘으면 모델 호출 전에 기존 오류를 반환한다.
2. 요청된 회수 구간을 완전하게 확보하고, 명시된 제출 산출물을 우선 배정한다. 회수 자료가 크다고 검수 대상 보고서의 존재를 숨기지 않는다. 함께 담을 수 없으면 불충분 상태를 드러낸다.
3. 전달할 주장과 연결된 읽은 원문을 배정한다. 본문·날짜·단위·조건이 들어 있는 인용 문단 전체를 먼저 시도한다. 남은 여유를 의미 없이 채우기 위해 미인용 수집자료까지 넣지 않는다.
4. 길이 때문에 나눠야 하면 기존 주장별 창·질문 anchor를 활용한다. 원문 내 여러 구간, 지지·반박 관계, 인용 사용 위치를 함께 선택하고 선택·생략 범위를 표시한다. 특정 언어의 부정어 목록이나 새 중요도 모델로 핵심 문장을 자동 확정하지 않는다.
5. 도구 요약·보충 자료는 기준과 연결된 실패·미확인·효과 확인을 보존하며 나머지 여유를 나눈다. 대응 기준이 없는 자료에 기준 ID를 임의로 부여하지 않는다. 등장 순서만으로 뒤쪽 반례가 계속 탈락하지 않도록 기존 공정 배분 성질을 유지한다.
6. 본문과 메타데이터를 함께 직렬화해 최종 한도를 검사한다. 줄여야 할 때는 한 배분 계획에서 선택을 다시 계산한다. 이미 선택한 구조화 레코드를 별도 단계에서 임의 문자 위치로 잘라 JSON이나 좌표 대응을 깨지 않는다.

인용 원문 전량이 작으면 전부 전달한다. 거대 문서에서는 완전 전달을 주장하지 않고 기준별 미확인과 회수 주소를 남긴다. **원문 후보 확보, 요청에 표시한 범위, 의미 검토 결과**를 각각 기록한다. 기존 구획 `complete`가 원문 전체나 의미적 승인을 뜻하지 않도록 최종 metadata에서 범위를 명확히 한다.

### 반복 표현 제거

- 회수 가능한 원문 목록을 `evidence_references()`의 정규화 결과 한 벌로 만든다. 전체 해시·판본·원문 길이·좌표 단위·충돌 상태는 여기서 정의하고 구획에서는 그 항목을 가리킨다.
- `EVIDENCE_REQUESTS`는 실제 불변 ID를 사용하는 현행 계약을 유지한다. 모델이 새 별칭 프로토콜을 배워야만 회수할 수 있게 바꾸지 않는다. 표시용 번호는 실제 ID를 찾는 보조 표지일 뿐이며 요청 검증을 우회하지 못한다.
- `research_claims`는 경로·해시를 문서 항목에 공유하고 인용 위치·본문 범위를 연결한다. 연결된 범위가 실제 제출 본문에 모두 표시됐을 때만 반복 claim_context를 생략한다. 산출물이 부분 표시되면 해당 주장 구간을 함께 제공하거나 미표시로 남긴다.
- `research_citations`, `evidence_index`, 구획 manifest에서 같은 원문·주소·설명을 반복하지 않는다. 관계·원천·판본·역할이 다른 항목은 유지한다. 원문만 공유하고 각 관계를 잃지 않는다.
- 모듈마다 별도 주소 표를 만드는 대신 같은 선택 계획에서 모델 표시와 회수 허용 목록을 파생한다. 선택되지 않은 자료도 복구 가능 여부를 명시한다. manifest가 너무 커지는 경우에도 생략을 숨기지 않는다.

**인수**: 동일 제공자 한도에서 5811의 제출 파일, 인용 52곳 전체, 특히 Micron ¶30·¶33·¶44가 첫 검수에 들어가고 실제 사용자 메시지는 기존 298,385자보다 작다. 이것은 해당 fixture의 구조적 목표다. 원문과 다른 판본·주장 연결을 섞지 않으며, 회수·checkpoint 복원·예산 계승 시험을 모두 통과한다. 재검수 0회는 모델 비교의 관측 항목이며 기계적으로 `ACHIEVED`를 강제하는 조건이 아니다.

## 7 R3 실행 응답의 본문 중복과 반복 안내 제거

### 본문 관계를 확인한 뒤 표시에서 공유

자료실 읽기 생산자는 `text`와 `blocks`의 관계를 현재 결과의 표시 메타데이터로 선언한다. `common/value_relations.py`가 선언을 검증하며, `model_result_view._fold_twin_fields()`는 검증 결과만 사용한다. 어휘 이름이나 특정 에피소드 이름으로 분기하지 않는다.

기존 `mirror_fields` 계약을 확장해 원본 문자열 경로·블록 목록 경로·본문 필드·정확한 연결 규칙을 표현한다. 새 별도 미러 체계를 만들지 않는다. 허용된 타입과 유한한 경로만 검증하고, 빈 값·잘못된 선언·처리 한도 초과는 양쪽 표시 유지로 돌아간다. 단일 블록은 정확한 문자열 일치, 여러 블록은 선언된 순서·구분자까지 같은 경우에만 인정한다. `strip()`·정렬·접두사 일치·의미 유사도로 접지 않는다.

블록의 종류·위치·페이지·표·인용 표지는 유지한다. 구조를 가진 블록을 기준 표현으로 남기고 중복된 평문 필드를 기존 모델 미러 표지로 가리키는 것을 기본으로 한다. 저장 원문과 typed wire에는 접힌 표지를 쓰지 않는다. 어느 원래 경로로 `read_result`나 `inputs`를 사용해도 원래 값이 돌아와야 한다. 변환·필터·선택 뒤에는 관계를 재검증하고, 오래된 선언을 신뢰하지 않는다.

미러 제거는 표시 예산 배분 전에 적용해 중복 본문이 예산을 나눠 먹지 않게 한다. 원문 저장·마스킹·기존 상태 판정은 그보다 먼저 이루어진다. JSON 전송량만 줄이고 모델이 읽을 본문을 없애는 변경은 허용하지 않는다.

### 고정 사용법과 호출별 사실 분리

`continuation.hint`, `_hint`, `_preview.note` 중 매번 같은 사용법은 기존 도구 스키마·IBL 교재가 소유하도록 맞춘다. 실제 `reuse_args`, `read_args`, `input_args`, run·판본·좌표, 불완전성, 호출별 주의사항은 응답에 유지한다. 스키마에 이미 설명돼 있는 내용부터 제거하고, 누락된 설명 때문에 스키마가 커지면 그 상시 토큰도 비교에 포함한다.

마스킹으로 입력 재사용이 불가능한 경우, 부분 성공, 외부 효과가 불명인 경우, 재사용 조건이 달라진 경우는 짧아도 구체적으로 설명한다. 작은 결과는 요약+참조가 더 클 수 있으므로 현재처럼 실제 직렬화 크기를 비교해 더 작은 표현을 선택한다. `read_result`의 다음 페이지·완료 범위를 숨기지 않는다.

**인수**: 7,978자 사례에서 본문 한 벌이 기존 본문 예산 안에 온전히 보이고 원문 참조·블록 메타데이터가 보존된다. 동일 문자열의 다른 출처를 합치지 않는다. 부분 실패·이미지·타입·마스킹 시험 및 공개 경계 행렬이 통과하고 앱/REST 구조화 결과는 동일하다.

## 8 R4 상황 관측의 중복 메타데이터 축소

이번 단계는 한 응답에 포함된 baseline의 표현만 다룬다. MCP에서 이전 응답을 받았다고 가정한 delta, 수신 커서 조작, 과거 CLI 메시지 삭제는 구현하지 않는다.

`projection_row()`와 `prepare()`가 만드는 한 snapshot 안에서 반복되는 task·subject context·source_ref 메타데이터를 공유한다. 각 관측에는 대상·facet·현재 값·판본·관측 상태·출처 연결을 알 수 있는 정보가 남아야 한다. 상태·근거에 각각 공간을 보장하는 기존 배분, 생략 건수, 전체 snapshot의 `read_result`를 유지한다.

request·conflict·needs_recheck·unresolved·pending·receipt 등 상태를 보존하며 최초 관측과 변경, 늦게 도착한 결과, 불명 효과를 일반 정상 근거와 합치지 않는다. 같은 응답의 업무 본문과 겹친다는 이유로 관측을 아예 없애지 않는다. 수신 확인이 없어도 해당 baseline만 읽고 현재 상태와 누락을 이해할 수 있어야 한다. 현재 bytes 한도를 임의로 낮춰 얻은 크기 감소를 수리 성과로 세지 않는다.

**인수**: 기존과 같은 관측 집합을 직렬화했을 때 더 작고 해석 결과가 같아야 한다. 동일 예산에서 변경·실패 정보 전달률이 떨어지지 않아야 한다. 전달 실패·재개·문맥 압축 뒤 baseline 복원과 API의 실제 수신 확인 계약이 유지돼야 한다. 보존을 확인하지 못한 관측 형식은 기존 표시를 사용한다.

### 실제 모델 비교

검수 비교와 실행 비교를 분리한 뒤 함께 측정한다. 고정된 결과를 표시만 바꾸는 재생은 정보 보존과 입력 크기를 확인하고, 실제 실행 비교는 도구 선택·추가 읽기·최종 품질까지 확인한다. 두 종류의 결과를 같은 성능 증거로 합치지 않는다.

| 비교군 | 확인할 내용 |
| --- | --- |
| 5811의 고정 산출물·자료 | 원래 기준에서 첫 검수 근거 충분성, 재검수 횟수, 제공자 보고 입력·출력·캐시, 검수 전체 시간 |
| 오류를 넣은 산출물 | 수치·단위·시점을 바꾸거나 반박·조건을 누락했을 때 승인을 거절하는지. 근거가 없으면 UNKNOWN을 유지하는지 |
| 다른 주제의 상충 자료 연구 | 질문·인과·대안·반례·조건부 결론·미해결 보존. 주제별 예외 처리 없이 개선되는지 |

| 부분 실패와 재개 | 재독·반복 실행 증가, 잃어버린 경고, 완료 행동의 중복 실행 여부 |

모델·기어·자료 스냅샷·기준을 맞추고 비교군 순서를 교차한다. 주요 정상/오류 사례는 각 조건 3회부터 측정해 개별 결과와 중앙값·범위를 남긴다. 이는 변동 확인용 소규모 비교이며 일반적인 통계적 우위를 증명하지 않는다. 품질 판정이 갈리거나 시간이 크게 흔들리면 원인을 확인하고 해당 사례를 더 측정한다. 코드의 의미적 승인 결과만으로 품질을 평가하지 않고 동일 산출물의 주장·근거를 사람도 대조할 수 있게 한다.

측정은 기존 `evaluation.input_budget`, `context.result_projected`, `situation.context_prepared`, `model.usage` 사건과 에피소드 원장에 연결한다. 선택 범위·본문/메타데이터 크기·최종 전송 크기를 같은 호출에 귀속하며 새 계측 원장을 만들지 않는다. 캐시 읽기를 입력에 다시 더하지 않고, 실제 토큰과 문자 추정치를 구분한다. 후처리·복구·재독까지 포함한 총토큰과 완료 시간을 보고한다.

**품질 관문**: 정상 사례의 핵심 사실·반론·범위·미확인이 유지되고, 심은 중대 오류의 신규 거짓 승인이 0건이어야 한다. 압축된 자료의 참조만 보고 읽었다고 주장하는 경우는 실패다.

**효율 관문**: 고정 입력의 검수·도구 최종 직렬화가 작아지고, 실제 비교의 완료 시간과 전체 토큰도 함께 개선되는지 확인한다. 재독·재검수·캐시 제외 입력이 늘면 그 비용을 포함한다. 한 축만 개선되면 부분 성과로 기록한다. 9.7% 문자 감소 실험을 토큰 절감 목표나 보장치로 재사용하지 않는다.

## 10 적용 순서와 되돌리기

| 단계 | 선행 조건 | 반영 단위 | 현재 상태 |
| --- | --- | --- | --- |
| R0 | 조사 결과 | 재현기·합성 회귀·비교 입력 | 계획 |
| R1 | R0 | 후보 보존·참조·checkpoint 호환 | 계획 |
| R2 | R1 | 전체 배분·단일 참조 표시·회수 검증 | 계획 |
| R3 | R0 | 생산자 선언·공통 관계 확인·모델 표시·스키마 설명 | 계획 |
| R4 | R0 | 상황 표시 직렬화와 경계 검사 | 계획 |
| R5 | R2·R3·R4 | 실제 모델 비교·종합 회귀·활성 확인 | 계획 |

기본 구현 순서는 R0→R1→R2→R3→R4→R5다. R1과 R2 사이에는 기존 표시가 동작하는 상태를 유지하고, 최종 연결 뒤 중복된 선절단 경로를 평가 소비자에서 제거한다. 운영 중이던 평가 packet을 새 자료로 다시 만들어 판정을 섞지 않는다. 포맷 판본을 기존 packet에 명시하고, 옛 packet의 복원은 기존 계약으로 수행한다. 생존 기간이 지난 호환 경로는 제거 조건을 구현 기록에 남긴다.

각 변경은 정본 main에 경로 지정 커밋한다. backend 변경 시 Android body manifest를 재생성하고 관련 층·파생물·파일 크기 검사를 통과시킨다. 어휘 설명이 실제로 바뀌면 소스와 교재에서 수정하고 파생물을 빌드한다. backend와 새 MCP 프로세스에서 실제 표시·회수까지 확인한다. 재기동은 기존 제어 경로를 사용하며 수동 keeper 표식을 만들지 않는다.

실패 시 해당 단계의 커밋을 되돌릴 수 있게 원문·typed 값·자료실 스키마를 보존한다. 표시 오류는 원래 표시로, 평가 배분 오류는 해당 호환 경로로 돌아가되 부정확한 완료 판정을 유지하지 않는다. 되돌리기가 사용자 데이터나 다른 세션의 변경을 지우지 않도록 변경 파일과 packet 판본으로 범위를 한정한다.

## 11 완료 보고에 남길 것

구현자는 이 문서에 단계별 커밋·검사 범위·실패와 수정·비교 조건·원자료 참조·활성 세대를 추가한다. [해부도](../data/system_docs/anatomy.md)의 상태도 실제 완료 범위로 갱신한다. 완료는 코드 반영, 계약 검사, 품질 관문, 실제 표시·회수 확인을 각각 구분해 보고한다. 모델 비교가 끝나지 않았다면 기능 수리와 비용 효과를 분리한다.

현재 완료된 것은 현행 소유자·소비자·회귀 계약과 연결한 수리계획 작성이다. R0~R5의 코드 구현·운영 활성화·성능 검증은 수행하지 않았다.
