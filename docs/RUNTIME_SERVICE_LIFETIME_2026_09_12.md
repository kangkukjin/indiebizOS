# 상주 구성요소와 실제 작업의 수명 분리

2026-09-12, 정본 main. R1 재기동 보호 장치의 상주 수명 오집계를 수리한다.

## 관측과 원인

12:27·12:37 재기동 결과는 `deferred / drain_deadline_or_unknown`이었다.
사용자 루트와 최종 저장은 0이지만 자식 6개가 남았다. `tqdm_monitor`,
`tool-async-loop`, AnyIO worker, 비동기 작업, 프로세스와 waitpid 스레드다.
12:45 사용자 재시작 후에도 같은 부류가 다시 등록됐다. 해당 프로세스는
설치된 Playwright의 `driver/node`임을 실행 파일 경로로 확인했다.

R1은 작업 중 생성한 Thread·Task·Popen을 실제 종료까지 소유한다. 유한 도구에는
필요한 보호지만, 영구 루프·공유 드라이버·풀 워커를 처음 만든 요청에 붙이면
요청이 끝나도 자식이 남는다. `run_forever` 루프만 남긴 독립 재현에서도
루트 0 / 자식 1이었다. 스레드가 존재한다는 사실은 AI 호출이나 계속 일하고
있다는 증거가 아니다.

## 변경 계약

- `system_tools`의 루프 생성은 서비스 수명이다. 호출은 루프에 제출하기 전에
  예약하고, 타임아웃 뒤에도 실제 coroutine의 finally까지 유지한다. 루프 접수가
  늦어져도 부모 자격을 잃지 않으며 실행 전 취소는 효과 없이 예약을 반환한다.
- `runtime_worker_adapters`는 AnyIO asyncio 백엔드의 각 함수 제출을 추적한다.
  취소와 함수 시작을 같은 잠금으로 구분한다. 대기 중 취소는 실행하지 않고,
  실행 중 `abandon_on_cancel`은 실제 함수 종료까지 소유한다. 풀 워커 재사용은
  이전 요청의 자격을 붙잡지 않는다. 사전 import된 run_sync 별칭도 같은 경계를 지난다.
- tqdm 모니터와 AnyIO 풀 스레드의 **클래스 생성 경계**를 분리한다. 이름 또는
  daemon 플래그로 임의 스레드를 제외하지 않는다. AnyIO의 asyncio 백엔드와
  tqdm 모니터 내부 API는 실제 설치 라이브러리로 검증하며 의존성 교체 때 이 시험을 유지한다.
- Playwright 시작에서 생성하는 공유 transport·드라이버를 서비스로 분리한다.
  `service_scope(own_processes=True)`는 작업 카운터 없이 프로세스 출생 영수증과
  자손 관측을 유지한다. 정상 재기동과 워커 사망 후 회수 경로가 그대로 읽는다.
  워커 사망 뒤에도 살아야 하는 외부 재기동 수행자는 이 옵션을 사용하지 않는다.
- 브라우저 자동 종료 타이머의 sleep은 작업이 아니다. 시간이 되면 저장·종료를
  finalizer로 접수한다. drain 중에는 새 정리 작업을 접수하지 않는다.
  `_close_internal`이 실행 중인 자기 타이머를 취소해 저장을 중단하던 결함도 수정했다.

기존 작업·하위 프로세스·증류의 완료 기준, 재기동 기본 대기 시한과 강제 정책은 유지한다.
서비스 표시를 이유로 카운터를 삭제하거나 알 수 없는 작업을 완료로 간주하지 않는다.
평가·기억 모델 호출과 IBL 언어 계약에는 변경이 없다.

## 검증

`test_runtime_services.py`는 실제 AnyIO 풀 재사용/실행 중 취소/접수 전 취소,
진행률 모니터와 같은 이름을 가진 일반 스레드, 도구 타임아웃, 루프 접수 전
예약/취소, 브라우저 타이머와 저장 finalizer를 검사한다. 실제 Playwright로
외부 URL 없이 빈 페이지에서 두 번 실행하고, 호출 후 작업 수 0과 드라이버
프로세스 영수증을 확인한다. 쿠키 저장은 임시 디렉터리만 사용한다.

`test_restart_process.py`는 실제 HTTP 동기 엔드포인트에서 AnyIO worker와
상주 프로세스를 만든 뒤 **force 없이** 재기동하고 프로세스 회수를 확인한다.
기존 타임아웃·프로세스·접수 경쟁·취소·최종 저장 시험도 유지한다.

전체 backend 실행은 4,041 통과 / 1 skip / 시험 진입점 규약 1 실패(260.03초)였다.
새 시험의 `__main__ → pytest` 진입점을 추가한 뒤 해당 규약과 수명 시험 21개가
통과했고, 파일 직접 실행으로도 새 시험 10개 전부 수행됨을 확인했다.
수명·재기동 프로세스 집중 실행도 종료 코드 0이었다. Android 번들, 어휘/문서
파생물, 층 가드, 은퇴 계약 검사와 diff 공백 검사를 통과했다.
