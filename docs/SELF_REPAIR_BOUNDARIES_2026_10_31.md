# 변경 대상의 소유권과 자기수리 경계

## 원칙

수리 턴이라는 이유로 모든 변경을 코어 변경으로 취급하지 않는다. 코어는 실행·해석·
권한 검사·작업 지속·프로세스 생존을 구현하는 기질이다. 그 기질이 관리 연산으로
조회·검증·개정하는 정의와 데이터는 입력이다. 입력의 개정과 입력을 처리하는 구현의
교체를 구분한다. 파일 확장자나 '수리'라는 표현으로 구분하지 않는다.

| 변경 대상 | 반영 계약 | 완료 근거 |
|---|---|---|
| 관리되는 정의·데이터 | 소유 관리 연산의 검증·충돌 검사·저장 | 저장된 판본과 새 호출 결과, 사용자 목표 |
| 실행 구현 | 같은 후보의 검사·정본 반영·기존 활성화 절차 | 적용·활성화·커밋 영수증과 원 증상 재검사 |
| 지침·권한·목표 기준 | 업무 중 편의상 변경하지 않는 통제 경계 | 별도 명시 요청의 범위와 기존 통제 |

구현 변경도 전체 재기동과 동의어가 아니다. 등록 순수 부품은 부품 게시, 워커 구현은
세대 교체, 제어 기반은 기반 인계를 사용한다. 기존 활성화 계약을 유지한다.
관용구 본문은 관리되는 정의이고, 관용구 해석기·실행기는 구현이다. 관용구를 Python
파일에 복제하거나 코어 회귀시험을 만들 수 있다는 이유만으로 정의 개정을 코드 수리로
확대하지 않는다. 배포 시드도 갱신해야 하는 개발 요청은 정의 개정과 소스 변경을 각각
검증하며, 운영 원장 반영을 소스 파일 수정으로 대신하지 않는다.

## 실행 경계

- `repair_workspace`는 파일·코드 작업 대상이다. 관리 원장의 소유권을 덮어쓰지 않는다.
- 함수 원장은 다른 운영 데이터와 같이 프로세스의 `INDIEBIZ_BASE_PATH`에 속한다.
  RED 권한이 있어도 원장이 사본으로 바뀌지 않는다. 정의 이름별 예외 목록은 없다.
- 격리 시험은 `repair_process`가 별도 BASE_PATH와 OS 쓰기 경계를 제공한다. 시험 자식의
  원장 개정은 운영 원장을 수정하지 않는다. 파일·셸의 사본 경계도 그대로 유지한다.
- 개정은 기존 불변 판본·컴파일·저장 호출자 검사·expected_revision 충돌 검사를 따른다.
  이미 컴파일한 계획은 판본을 고정하므로 개정 확인은 새 호출로 한다.
- 완료 경로는 RED 권한의 존재가 아니라 실제 적용 대상의 존재를 본다. 미수집 셸 변경도
  후보 델타에서 확인한다. 빈 사본이나 조사만 한 턴은 원래 목표를 일반 평가한다.
  코드 변경·적용 인계·파손된 사본 기록은 적용 영수증 검사를 생략하지 않는다.
- 정의 개정 성공만으로 사용자 업무 전체를 성공으로 처리하지 않는다. 코드와 관리
  대상이 섞인 작업도 전체 기준을 유지한다. 기준을 낮추거나 새 승인 요청을 만들어
  진행을 넘기는 방식으로 해결하지 않는다.

## 관측한 결함

에피소드 5648은 중지 관용구 결함을 찾아 사본 검사까지 수행했지만 실제 원장은 고치지
못했다. 함수 원장도 수리 문맥의 사본으로 해소되고, 마지막에는 코드 적용 영수증을
요구했다. 코드 수리 기반의 보호를 정의 개정에 잘못 적용한 공통 경계 문제다.

`외부PC작업중지확인`은 작업 확인 단계에서 접수증과 bare task reference를 정규화한 뒤,
취소 단계에서 원래 입력의 task_ref를 다시 사용했다. 취소도 확인 결과의 task_ref를
사용하도록 본문·배포 시드를 맞추고, 운영 정의는 expected_revision을 통해 명시 개정한다.
외부 PC의 실제 프로세스 종료는 해당 기기의 확인 사건으로만 판정한다.

## 검증 범위

`test_function_store`는 수리 문맥의 관리 연산 전체 경로·개정·새 호출·충돌 거절과
격리 시험 자식의 원장 분리를 검사한다. `test_repair_policy`는 실제 후보·빈 후보·
미수집 변경·기록 파손·재개 인계의 완료 경계를 검사한다. `test_final_evaluator`는
정의만 바꾼 수리 턴도 원래 기준으로 평가하고 미달을 성공으로 바꾸지 않음을 확인한다.

`test_guestpc_resident_idioms`는 실제 IBL·작업 원장·취소 어댑터로 접수증과 bare reference,
취소 요청과 취소 확인을 검사한다. 외부 PC에는 접속하지 않는다.
`test_function_model`은 선택적 실제 실행 모델 검사다. 저장 정의의 실패를 진단하고
관리 연산으로 개정·재호출하는 행동을 확인한다. 전체 자연어 분류·감독 파이프라인이나
실제 원격 기기의 종료까지 검사했다고 해석하지 않는다. 실행 결과는 작업 기록에 남긴다.
