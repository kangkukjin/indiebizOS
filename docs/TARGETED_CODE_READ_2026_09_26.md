# 대상별 코드 조사: 검색 → 범위 병합 → 읽기 → 확인표

## 문제와 적용 범위

ep4078에서 `좁혀서읽기`에 `def _channel_(read|search)|get_system_gmail`을
주었을 때 검색 위치는 네 곳이었지만, 앞 세 곳을 읽는 계약에 따라 네 번째
`_channel_search`는 읽히지 않았다. 표본 읽기와 지정 대상 전체 조사는 다른 계약이다.
기존 관용구의 본문은 보존하고, 후자에 `대상별좁혀읽기`를 추가한다.

분해의 단위를 실행 가능한 부품으로 만든다. AI는 조사할 대상과 범위를 정하고,
IBL 프로그램은 대상별 검색·구간 병합·본문 읽기·확인표 생성을 한 번의 호출로 수행한다.
해석이나 수정 결정은 이 결과를 받은 AI가 한다. 새 어휘나 실행기 변경은 없다.

## 호출

```ibl
#!ibl edition=2
[fn:대상별좁혀읽기]{
  대상:[
    {name:"gmail",pattern:"get_system_gmail"},
    {name:"read",pattern:"^def _channel_read"},
    {name:"search",pattern:"^def _channel_search"}
  ],
  루트:"backend/ibl/channel_engine.py"
}
```

필수 인자는 `대상:[{name,pattern}]`과 `루트`다. `pattern`은 정규식이다.
선택 인자는 `파일패턴:"*.py"`, `앞줄:2`, `뒷줄:29`, `검색상한:20`이다.
대상은 1~64개, 검색상한은 대상당 1~200개다. 상한을 넘으면 미완료로 표시한다.

반환 Record:

- `items`: 모든 입력 대상의 이름·패턴·상태·미확인 사유·일치 위치.
  상태는 `read`, `not_found`, `search_failed`, `partial`이다.
- `ranges`: 파일별로 겹치거나 인접한 범위를 합친 발췌. 본문은 구간마다 한 번만 넣고,
  각 대상의 `matches[].range_id`가 참조한다. 경로·줄 범위·발췌 SHA-256도 남긴다.
- `all_targets_read`: 모든 대상에서 검색과 일치 주변 읽기가 확인된 경우에만 참이다.
  호출 성공 여부만으로 조사 완료를 판단하지 않는다.
- `unmerged_ranges`, `read_requests`: 병합 전 구간 수와 실제 읽기 요청 수.

찾지 못한 대상도 행을 남긴다. 잘못된 정규식·검색 실패·검색 상한 초과·본문 절단·읽기 실패·
검색 후 일치 줄 변경은 사유로 보존한다. 검색 도구의 제외 범위도 대상별로 전달한다.
`read`는 지정한 일치 주변을 받았다는 뜻이며 함수 전체나 의미를 검토했다는 뜻은 아니다.
필요한 추가 조사에서는 미확인 대상이나 부족한 범위만 좁혀 다시 호출한다.

## 구성과 등록

- 정의·호출 용례: `data/idioms/code_read_seeds.json`.
- 값 처리: 등록 스크립트 `코드조사범위` → `data/scripts/targeted_code_read.py`.
  `prepare`는 입력 검사, `plan`은 범위 병합, `finish`는 대상별 확인표를 맡는다.
  대상 파일 접근은 기존 `self:grep`·`self:read`가 맡는다.
- 독립 검색·읽기는 각 단계에서 `table:each{parallel:4}`로 실행한다.
  범위 병합은 모든 검색이 끝난 뒤, 확인표는 모든 읽기가 끝난 뒤 수행한다.
- 내부 AI 호출은 없다. 새 정의 전체를 상시 프롬프트에 넣지 않고, 기존 좁혀서읽기
  안내에서 새 이름을 가리킨다. 해마의 의미 검색 색인과 describe로 발견·확인한다.
- 재등록: `.venv/bin/python3 scripts/register_webapp_idioms.py --seed-file code_read_seeds.json --apply --local-encoder`.
  SQLite 백업 후 `add_examples_batch`로 등록하며 같은 정의는 중복 삽입하지 않는다.

## 실제 자료 확인

2026-09-26 정본의 `channel_engine.py`에 위 호출을 실행했다. 임의 정의 주입 없이
공개 판본 2 입구가 해마에 등록된 정의를 읽어 실행했다.

| 대상 | 일치 줄 | 상태 |
|---|---|---|
| gmail | 44, 91 | read |
| read | 994 | read |
| search | 1018 | read |

네 위치의 요청 구간은 `[42,73]`, `[89,120]`, `[992,1023]`, `[1016,1047]`이었다.
마지막 두 구간을 `[992,1047]`로 합쳐 **네 위치를 세 번 읽기**로 확인했다.
`all_targets_read=true`, 실행의 `source_complete=true`였다.
기존 `좁혀서읽기`의 본문 SHA-256은 변경 전과 일치한다.

이 결과는 네 번째 위치의 누락 방지와 중복 읽기 감소를 입증한다.
전체 에이전트 실행시간·토큰 절감률을 측정한 것은 아니다. 새 경로는 대상별 검색과
등록 스크립트 세 단계의 비용도 든다. 앞 세 곳만 필요한 표본 조사에는 기존 관용구를 쓴다.

회귀는 `backend/test_targeted_code_read.py`에 있다. 실제 IBL 검색·읽기로 네 번째 대상,
EOF, 구간 병합, 잘못된 정규식, 없는 대상, 검색 상한을 검사하고, 값 처리에서는
읽기 실패·일치 줄 변경·짧은 본문·중복 위치·잘못된 입력 계약을 검사한다.

검증 결과: 새 회귀와 기존 관용구 관련 검사 54개, 문서 정합성 검사 17개 통과.
전체 `pytest backend/`는 1,154개 통과 후 로그 비밀값 마스킹
(`backend/base/logging_utils.py:149`)에서 장시간 진행되지 않아 중단했다.
그 실행에서 발견한 신규 등록부의 `op` 설명 누락은 수정했고 문서 검사를 다시 통과했다.
전체 회귀 통과를 주장하지 않는다.
