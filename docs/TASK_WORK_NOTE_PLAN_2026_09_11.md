# 기존 작업 상태의 표시 개선과 재측정 계획

상태: **2026-09-12 축소 개정 — 계획만 수정, 실행 코드·성능 실험 미수행**.
기존 P0–P4 계획을 이 세 단계로 대체한다. 새 작업노트 저장소와 의미 기록 확장은 보류한다.
검토 기준은 정본 main `5284ec07`. 최종 평가 분리는 09-11 23:26에 커밋됐으며
현재의 도구 없는 최종 평가·보완 1회 정책을 비교 기준에 포함한다.

## 1. 이번에 해결할 작은 문제

기존 `handoff_state`는 이미 `tool_index`·artifacts·evidence를 전달한다.
3406 보완 R3–8의 출처 재탐색은 이 수리가 겨냥했던 문제이므로, 과거의 6라운드를
새 기능으로 줄일 수 있는 현재 비용으로 계산하지 않는다.

확인된 표시 공백은 `turn_vars`가 실제 변수 목록 대신 “남아 있다”는 산문이라는 점이다.
기존 `ibl_turn_vars`가 값을 저장하고 `ibl_envelope.summarize_result`가
shape·count·길이 등을 요약한다. 먼저 이 둘을 기존 문맥 구성에 연결한다.
이 공백이 유일한 원인인지, 작은 표시만으로 충분한지는 재측정으로 판단한다.

[전체 반성](SYSTEM_REFLECTION_2026_09_11.md)의 I-1(결과 축소), C-3(신원),
C-4(지시 전달) 중복 지적을 적용해 저장소·신원 객체·주입 큐·축소 정책을 추가하지 않는다.
해당 문서는 개정 시점에 미추적 검토 자료다. 그 안의 다른 설계 제안까지 채택하는 것은 아니다.

## 2. 세 단계

### 1단계 — 기존 문맥에 실제 사용 가능한 변수 목록 표시

- 기존 턴 키·저장소를 그대로 사용한다. 목록은 해당 작업에 지금 존재하는 변수만 담는다.
  표시 내용은 `이름 / shape / count(알 수 있을 때) / 글자수` 한 줄씩으로 제한한다.
  기존 요약기의 `bytes`는 현재 `len(str)` 값이므로 UTF-8 바이트 수로 표기하지 않는다.
- 요약기의 판정 의미를 재사용하고 값 본문·미리보기는 목록에서 제외한다.
  별도 이름 짓기·자료 해석·노트 요약 모델 호출은 추가하지 않는다.
- `supervisor_handoff.handoff_state`의 기존 `turn_vars` 자리에 목록을 넣는다.
  실행 시작·같은 작업의 재개 문맥도 기존 구성 지점에서 같은 표시 함수를 사용한다.
  새 사용자 턴에는 이전 턴의 변수가 자동 승계되지 않는다. 명시적으로 복구된 값만 표시한다.
- 기존 `tool_index`와 출처·산출물 참조는 유지한다. 이름 없는 결과까지 변수로 자동 등록하지 않는다.
- 기존 문맥 예산 안에서 항목 수·표시량을 제한하고 생략 여부를 알린다.
  목록 생성 때문에 필요한 목표·도구 결과가 밀려나거나 새로운 축소 단계를 거치지 않게 한다.
- 현재 `load`는 읽기 오류도 빈 사전으로 돌려준다. 표시용 읽기에서는 없음과 조회 실패를
  구분하는 최소 보완이 필요하다. 실패하면 “목록 확인 불가”로 표시하고 도구를 재실행하지 않는다.
- 목록은 시작·재개·인계 경계에서만 구성한다. 매 도구마다 전량 읽기·파일시스템 탐색을
  하지 않는다. 큰 저장소의 읽기·요약 비용을 확인하고, 부담이 크면 기존 읽기 결과를
  재사용하거나 표시를 제한한다. 이를 위해 별도 캐시 저장소를 만들지 않는다.
- API·CLI가 공유하는 문맥 구성에서 처리한다. CLI 내부의 매 추론이나 자체 도구 직전에
  갱신을 주입하는 기능은 범위 밖이다. 필요한 제공자 차이는 전달 연결에만 둔다.
- 비교용 표시 on/off 하나를 기존 설정·시험 방식에 맞춰 둔다.
  끈 상태에서는 목록을 만들거나 전달하지 않는다.

**최소 변경 위치:** `ibl_turn_vars.py`의 표시용 조회, 기존 요약기 호출,
`supervisor_handoff.py`, 실제 시작·재개 문맥 구성부.
새 모듈 둘이나 DB 테이블은 만들지 않는다. 정확한 변경량은 구현 때 확인하며 줄 수를 보장하지 않는다.

**완료 조건:** 같은 작업의 보완 실행자가 이미 저장한 값을 이름으로 참조할 수 있고,
다른 작업·만료된 값이 사용 가능한 것처럼 표시되지 않는다. 목록 작성용 모델 호출은 0회다.

### 2단계 — 수리 후 상태에서 작은 비교

3406 유형의 조사·자료 재사용 과제 한두 건을 골라 다음 두 조건을 비교한다.

| 조건 | 구성 |
|---|---|
| A | 현재 수리 완료 상태, 실제 변수 목록 표시 끔 |
| B | 같은 상태에 1단계 표시만 켬 |

같은 자료·초기 파일·모델·기어·평가 정책을 사용한다. 세션과 도구 캐시 조건을 기록하고,
가능하면 입력·도구 응답을 고정한 기존 시험 경로를 활용한다. 운영 작업이나 외부 쓰기를
중복 실행하지 않는다. A의 실행 기준은 3406 당시가 아니라 현재 코드다.

기존 실행 원장으로 다음을 비교한다.

- 출처 위치를 잃어서 생긴 검색·재크롤링·재읽기 라운드와 실제 변수 참조 여부.
- 전체 역할의 모델 라운드, 출력 토큰, 신규·캐시 입력 토큰, 전경 시간과 후처리 비용.
- 목록의 추가 입력량과 생성 시간. 호출 수 감소를 전체 비용 감소로 대신 보고하지 않는다.
- 사용자 요구의 대상·기간·측정량 충족과 근거 정확성. 새 해석·최신성 확인을 위한
  재읽기는 불필요한 반복으로 세지 않는다.

3406의 R21 출력 27,650토큰은 **최초 실행 담당 모델 출력의 69.5%**였다.
이 긴 생성 비용과 출처 재탐색 비용은 따로 본다. 변수 목록이 긴 생성을 줄인다고 가정하지 않는다.

한두 과제의 결과는 후속 개발 필요성을 판단할 탐색 자료다. 차이가 불분명하면
표본을 필요한 만큼 보강하거나 결론을 유보하고, 일반적 절감률로 확대하지 않는다.
짧은 작업의 표시 생략과 비용 증가 여부도 확인한다.

### 3단계 — 남는 실패에만 대응하거나 종료

- A에서 재탐색이 이미 사라졌다면 추가 저장 기능의 필요 근거가 없다.
  B도 이득이 없거나 비용만 늘면 표시를 채택하지 않고 종료한다.
- 표시에서 누락되거나 찾기 어려운 문제면 기존 인계·표시를 고친다.
  값이 실제로 보존되지 않는 문제가 확인될 때만 기존 보존 경로의 보완을 논의한다.
- 기존 저장소로 부족해 지속 자료 지도가 필요하다는 증거가 남을 때만 옛 P1 저장소
  제안을 재검토한다. 그 전에 I-1 단일 소유·C-4 합류 방향과 충돌 없이 들어갈 위치를
  정한다. 작은 1단계 표시 수리에 전체 통합 리팩터링을 선행 조건으로 걸지는 않는다.
- 추가 변경 C를 시험하게 되면 B와 다시 비교한다. A→B→C는 한 요소씩 검증하는
  순서이며, C를 반드시 만들거나 의미 기록을 자동으로 도입한다는 뜻이 아니다.
- 옛 P2의 `pursuit.note` 기록 확대·의미 패치·판단 의존 관계와 자동 재확인 시스템은
  보류한다. 기존 응답·`summarize_pending`·인계로 부족한 구체적 사례가 먼저 필요하다.

## 3. 유지할 계약과 검증 범위

- 저장됨·전달됨·결론이 기록됨·검증됨을 구분한다. 네 상태의 구분은 해석 규칙이며
  새 상태 원장이나 모델 열람 영수증 시스템을 만들라는 뜻이 아니다.
- 계획 발행을 실행 완료로 표시하지 않는다. `next`나 목록을 읽었다고 부작용을 재실행하지 않는다.
- 참조의 작업 범위·수명을 정직하게 표시한다. 오래된 값이 남아 있다는 사실이
  현재 목적에 적합하다는 뜻은 아니다. 사용자 정정이 과거 계획보다 우선한다.
- 최종 평가의 도구 없음·보완 1회 정책을 유지하고 새 노트 읽기·검수 호출을 추가하지 않는다.
- 기존 주제별 시험에 같은 작업/다른 작업, 빈 목록/읽기 실패, 생략, 재개·인계 전달,
  표시 off, 원래 값 불변 사례를 추가한다. 사건별 새 시험 파일·관문은 기본 선택으로 삼지 않는다.
- 구현 시 실제 전달 문맥을 API·CLI 대표 경로에서 확인하고 저장소 필수 회귀·층·파생물
  검증을 수행한다. 문서만 고치는 이번 개정에는 런타임 시험이나 모델 재실행을 하지 않는다.
