# 결과 전달과 과제 갱신 경계의 수리

상태: **2026-09-12, 3536 분석과 fable 검토를 반영해 A → B·계측 → C로 축소 구현.**
구현 전 기준은 정본 main `5b67e5d6`이다. `dc7195be`의 보완 본문 인계·묶음 패치 예시는
이미 적용됐다. 새 작업노트 저장소·어휘·주입 채널을 만드는 대신 기존 경계만 고쳤다.

## 1. 관측과 해석의 범위

3536은 9월 12일 01:23의 호텔 동 선택 질문이다. 전경 132.6초, 실행 7라운드,
도구 없는 최종 평가 1회로 승인됐다. 보완이 없었으므로 앞선 묶음 패치 수리의 효과를
검증한 사례는 아니다. 3518과 직접 비교해 절감률을 계산하지 않는다.

| 관측 | 이번 수리 |
|---|---|
| 검색·크롤링을 묶어 실행하고 실패 뒤 `$본문` 재사용 | 조합·변수 저장은 이미 작동하므로 유지 |
| 최종 50행·4,430자가 8행으로 표시되고 조회 중 빈 코드 입력도 실패 | A: 기존 미리보기 임계만 6,000자로 조정 |
| 요약의 progress 초과를 수정한 다음 next 초과를 발견 | B: 잘못된 필드를 첫 재요청에 함께 보고 |
| 과제 요약 실패 비용이 마지막 성공 비용에서 빠짐 | B와 함께 기존 후처리 비용 기록 수정 |
| 호텔 동 선택 기준과 옛 경유시간 계산 지시가 함께 전달됨 | C: 장기 규정은 보존하고 현재 실행 지시를 분리 |

요약 모델 호출 3회의 지연 합은 46.2초·44,306토큰이다. 앞선 실패 두 호출만
34.1초·32,758토큰이다. 경험 증류까지 포함하면 후처리 4라운드·약 52.7초 경과다.
기존 `postprocess.json`의 13.51초·15,133토큰은 마지막 성공한 큐 시도만 포함했다.
토큰은 캐시를 포함한 처리량이며 청구액이 아니다. 전경 실행 103.4초에는 도구 시간도 포함된다.

근거는 `data/world_pulse.db`의 episode 3536 / `run_de2db61fe7e4ddb51ce1`,
과제 원장과 [실행 원장](../data/spill/supervision/6b8ac4061ef34216b0f0e336937305f3/events.jsonl)이다.
운영 기록과 과거 비용 파일은 수정하지 않는다.
[전체 반성](SYSTEM_REFLECTION_2026_09_11.md)의 I-1·C-3·C-4 경고에 따라
새 축소 단계·신원 객체·주입 채널은 추가하지 않았다. 이 검토 문서는 별도 미추적 자료다.

## 2. A — 작은 결과는 기존 전달 경계에서 전량 반환

`data/lifecycle_policy.yaml`의 `envelope_preview.min_chars`와 순수 코어 기본값을
3,000 → 6,000자로 바꿨다. 별도 판정이나 업무 예외는 없다. 큰 표의 8행 미리보기,
산문 한도, 원문 참조·변수 보존, 앱 전체 전달은 기존 계약을 따른다.

기존 시험에 50행·약 4KB의 문단을 필터링하고 `provider_tool_result`까지 전달하는
회귀를 추가했다. 한 번에 본문을 받는 것은 확인했지만 실제 모델의 재조회 감소는 아직 측정하지 않았다.
MCP `code` 기본값·도움말·URL 전파는 이번 범위에서 제외했다.

## 3. B — 요약 오류를 함께 보고하고 실패 비용도 누적

`pursuit_bind._validate_answer`가 각 요약 필드를 기존 `pursuit_ledger.validate`로 검증하고
잘못된 필드의 오류를 모아 보고한다. 제한의 정본은 그대로 한 벌이다. JSON 전체를 한 번
재요청하는 기존 경로를 사용하며 부분 필드 재작성·정상 필드 고정 프로토콜은 추가하지 않았다.
절단으로 통과시키지 않고, 전체 검증 뒤에만 원장에 적용한다. 재시도 상한도 그대로다.

`prepare()`는 다음 턴 실행 전에 미완료 요약을 동기로 처리한다. 따라서 배경 실패가
계속되면 다음 전경을 막을 수 있다. 이 경로에서 두 길이 위반을 함께 알리고, 재요청 성공 시
진행하거나 실패 시 원문과 기존 과제를 보존하며 정지하는 것을 검사했다.

`distill_queue._execute`의 `finally`에서 성공·실패 시도 모두 비용을 기록한다.

- 기존 `postprocess.json`: 큐 행 ID·시도 번호로 실행시간·토큰을 누적하며 재개 시 이어 읽는다.
  같은 시도는 중복 가산하지 않는다. 누락 시도나 미확인 토큰은 `incomplete`와 `tokens:null`로 표시한다.
- 기존 `distillation.cost`: 시도별 증분과 성공 여부를 기록한다. 누계 파일과 다시 합산하지 않는다.
- 범위는 후처리 큐의 시도 실행 합이다. 전경의 동기 요약·큐 대기·backoff는 제외한다.
  토큰은 기존 턴 계측의 차이이며 캐시 포함이다. 새 사용량 집계 체계는 만들지 않는다.
- 계측 파일 쓰기 실패가 성공한 기억 쓰기를 재실행하게 하지 않는다. 기존 큐 영속성과 재시도는 유지한다.

실제 첫 요약 성공률과 재요청 감소는 후속 실사용에서 측정한다. 오류를 함께 알려도 모델이
다시 틀릴 수 있으므로 항상 한 번의 수정으로 끝난다고 보장하지 않는다.

## 4. C — 장기 규정을 보존하고 이번 턴 기준을 전달

`run_consciousness`의 keep/amend 경로에서 기존 과제 갱신을 먼저 저장한 뒤,
실행에 반환할 객체의 `imagined_ibl`·`expert_choice`·`capability_focus`를 제거한다.
옛 `approach`도 현재 실행 지시에서 비우고 `task_framing`은 이미 수행한 검토의
`criteria`로 채운다. `guide_files`는 남긴다. 새 모델 판단은 추가하지 않는다.

원장의 장기 `goal_criteria`·framing·접근법·메타는 보존하며 amend의 명시적 규정 수정과
rewrite·사용자 정정 경로도 유지한다. 저장할 규정과 현재 반환 객체를 구분해 이번 턴의
짧은 질문이 장기 목표를 덮어쓰지 않게 했다.

3536 실행자는 낡은 힌트를 무시하고 옳게 조사했다. C의 평가 대상은 호출 수가 아니라
현재 프롬프트의 낡은 지시 제거와 오작동 위험 축소다.

## 5. 검증과 후속 판단

기존 시험 파일에 회귀를 추가했다. 표시·과제·큐 관련 시험은 53개 통과했다.
전체 backend 회귀는 3,935개 통과·1개 건너뜀(254.45초)이다. 기존 amend 시험의
저장 규정=현재 실행 문구 가정도 새 계약에 맞춰 각각의 보존·전달을 확인하도록 고쳤다.
층·파일 크기·IBL 정합성 검사를 통과했고 Android 번들을 재생성했다.
최종 평가는 도구 없이 수행하며 보완은 최대 1회라는 계약을 유지한다.

운영 확인에서는 기존 자식 작업 11개가 남아 자동 재기동의 drain이 끝나지 않았다.
개발 파일 변경이 만든 재기동 요청을 공식 취소 경로로 보류해 기존 백엔드의 요청 접수를
복구했다. 확인 당시 실행 digest는 수정 전 코드였다. 따라서 정본 코드 반영과 실행 중인
백엔드 반영은 구분하며, 이번 수리의 실사용 효과를 관측하려면 정상 재기동이 먼저 필요하다.

고정 재현과 실사용 절감은 구분한다. 후속 에피소드에서 재조회·요약 실패·전경/후처리
모델 라운드와 출력량·지연·품질을 함께 본다. 추가 본문 비용이 이득을 상쇄하면
기존 정책값을 되돌린다. 새 작업노트, 부분 요약 프로토콜, 세션 강제 초기화는 보류한다.
