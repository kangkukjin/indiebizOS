# 작업 중 생성되는 자료와 판단을 재사용하기 위한 작업노트 구현 계획

상태: **설계 제안 — 실행 코드 미구현, 성능 효과 미측정**.
2026-09-11 정본 저장소의 HEAD `6cba9122`와 작업 트리를 확인했다.
최종 평가 분리 등 다른 세션의 미커밋 변경은 검토만 했으며 이 계획에서 수정하지 않았다.

## 1. 목표와 선택

작업 중 확보한 자료의 의미·위치와 현재 판단을 보존하고, 다음 실행자가 이미 한 일을
찾거나 해석하는 데 쓰는 모델 호출을 줄인다. 사용자가 목표를 수정하면 관련 판단도
재검토할 수 있어야 한다. 특정 업무의 고정 절차를 늘리는 것이 목적은 아니다.

**저장·갱신·문맥 구성은 공통으로 구현하고, 제공자별 연결은 전달 경계에 한정한다.**
첫 적용 범위는 공통 IBL 결과 반환, 실행 시작·재개, 감독·보완 인계다.
IBL 어휘·문법은 그대로 두고 기존 `pursuit` 도구의 읽기·기록 계약을 활용한다.
CLI 자체 도구의 매 단계 개입은 첫 버전의 필수 조건으로 삼지 않는다.

검증할 가설은 두 가지다.

1. 결과를 저장하는 것에 더해 작은 자료 지도를 제공하면 출처 재탐색과 불필요한 재읽기가 감소한다.
2. 근거가 연결된 결정·미해결 사항을 인계하면 같은 판단의 반복이 감소한다.

두 효과를 구분해서 측정한다. 노트만으로 호출이 줄지 않으면 입력과 다음 동작이 이미
정해진 구간을 기존 IBL 조합으로 이어 실행하는 문제를 따로 검토한다.

## 2. 현재 기반과 이번 변경의 차이

| 현재 기반 | 재사용할 부분 | 보완할 부분 |
|---|---|---|
| `pursuit_bind.observe` | 공통 도구 사건 수집·과제 연결 | 사건 목록을 현재 자료 지도와 연결. 외부 CLI에 대한 실시간 전달 경로는 별도 필요 |
| `pursuit_bind.refresh_memory` | 실행 시작 전 과제 상태 주입 | 작업 중 변경과 재개·인계 시의 상태 반영 |
| `pursuit_bind.summarize_pending` | 끝난 턴의 과제 진행 요약 | 현재 실행 중인 작업노트와 구분. 매 도구 뒤 요약 모델을 호출하지 않음 |
| `pursuit_tools` / `api_pursuits` / MCP `pursuit` | 같은 읽기·기록 의미, 버전·소유권 확인 | 명시적으로 열린 장기 과제가 없는 현재 작업도 기록·조회 가능하게 연결 |
| `ibl_turn_vars`, 결과·출처·전송 참조 | 이미 저장한 값과 원문 재사용 | 자료 의미·수명·사용 가능한 참조를 작은 목차로 제공 |
| `supervisor_handoff` | 목표·자료·변수·작업 ID 인계 | 작업노트의 결정·미해결 사항을 중복 없이 합침 |
| 실행 기록 통합 조회 | 기존 원장 신원·원문 연결, 감사 화면 | 전경에서 전체 기록을 매번 조회하는 의존성은 만들지 않음 |

3405·3406 감사에서는 저장된 자료의 재탐색과 결과 표시 문제를 확인했다. 이후 출처
인계·차트·KOSIS·국소 수정 등의 수리가 진행됐으므로 과거 호출 수를 현재 기준선으로
쓰지 않는다. 3507–3510 수리는 전경 디스크 탐색 정지와 기억의 시점·출처 혼동도
다뤘다. 작업노트를 만들기 위해 파일시스템을 다시 훑거나 과거 AI의 제안을 사실로
승격하는 구현은 이 수리 방향과 충돌한다.

현재 작업 트리에는 최종 평가를 도구 없는 원샷으로 분리하는 변경도 있다. 이 계획은
그 방향을 유지한다. 평가자에게 노트와 필요한 증거를 직접 제공하고, 노트를 읽기 위한
도구나 추가 검수 루프를 다시 만들지 않는다. 구현 착수 시 해당 변경의 반영 상태를 확인한다.

## 3. 작업노트의 계약

### 3.1 기록하는 내용과 소유자

| 내용 | 기록 주체 | 의미 |
|---|---|---|
| 현재 사용자 요구와 정정 | 기존 대화·과제 상태를 참조 | 최신 요구가 우선. AI가 제안한 기준과 사용자 요구를 구분 |
| 수행·실패·진행 중 상태 | 실행 코드 | 실제 완료 사건을 근거로 기록. 계획·요청 발행을 완료로 표시하지 않음 |
| 자료 지도 | 실행 코드 + 선택적 AI 설명 | 참조, 호출 입력의 출처·범위, 자료 유형, 명시된 이름, 버전·수명 |
| 확인한 사실·결정 | AI 또는 사용자 | 간결한 결론, 근거 참조, 적용 범위, 불확실성 |
| 미해결 사항·다음 작업 | AI 또는 사용자 | 바로 실행할 수 있는 동작과 추가 판단이 필요한 문제를 구분 |

자료의 이름·컬럼·출처·행수 등 이미 구조화된 정보로 목차를 만든다. 코드가 임의의
산문 결과를 이해한 척하거나, 모든 자료에 모델 요약을 붙이지 않는다. 의미를 알 수
없으면 도구명·입력 범위·참조만 기록하고 설명이 없음을 표시한다.

예를 들어 `고용통계: 결과 참조, 기간, 단위, $고용통계`와
`이 자료는 취업자 수이며 신규 채용 수는 확인하지 못함: 근거 참조`를 구분해 보존한다.
내부 추론 전문을 기록할 필요는 없다. 다음 작업에 필요한 결론과 근거만 남긴다.

### 3.2 저장과 수명

- 작업 키는 검증된 저장소·프로젝트 범위와 자아·`task_id`를 사용한다. `run_id`와
  선택적 `pursuit_id`는 기존 신원 연결을 따른다. 제공자 이름이나 표시 제목으로 연결하지 않는다.
- 제안 구현은 기존 과제 원장이 사용하는 로컬 DB에 현재 작업용 상태 테이블을 추가하는 것이다.
  저장 코드는 `backend/datastore/task_work_note.py`로 분리하고 원장의 연결·접근 계약을 따른다.
  새 전역 기억 DB나 원문 복제 저장소는 만들지 않는다.
- 첫 자료나 의미 있는 기록이 생길 때 지연 생성한다. 한 번의 짧은 질문을 장기 과제로
  자동 등록하지 않는다. 현재 작업의 의미 기록은 이 작업노트가 소유하고, 장기 과제의
  목표·진행은 기존 pursuit가 소유한다. 같은 필드를 양방향 동기화하지 않는다.
- 실행 사실·자료 목차는 기존 사건·참조에서 만든 작은 파생 상태다. 원문은 기존 저장소에
  남긴다. 작업 종료 뒤 장기 과제에 남길 진행 요약은 기존 경로를 사용한다.
- 상태에는 버전과 반영한 사건 위치를 남긴다. 병렬 결과는 실행 ID로 합치고, 동일 사건의
  재전달은 중복 반영하지 않는다. 같은 입력으로 실제 두 번 실행한 사건은 별개로 보존한다.
- 중단·재기동 시 완료된 사실만 복구한다. 노트의 `next`를 읽었다는 이유로 부작용을
  자동 재실행하지 않는다. 본 실행 성공과 노트 저장 실패는 별도로 기록한다.
- 원문 참조의 수명은 원래 저장소의 정책을 따른다. 특히 턴 변수·일부 spill 참조는
  영구 기억이 아니다. 만료·삭제·접근 실패는 구분해 표시하고, 필요 자료의 장기 보존은
  기존 프로젝트 산출물 보존 경로로 연결한다. 노트가 존재한다고 원문도 있다고 가정하지 않는다.
- 첫 버전은 사용자가 소유한 기존 작업 기록과 수명을 맞추며 새 자동 삭제 정책을 도입하지 않는다.
  파일로 내보내는 읽기용 노트·지도는 가능하지만 편집 정본을 두 벌로 만들지 않는다.

### 3.3 재사용의 조건

`저장됨`, `모델 입력에 전달됨`, `AI가 결론을 기록함`, `검증됨`은 다른 상태다.
입력 전송 기록을 실제 이해나 검수의 증명으로 사용하지 않는다.

결정에는 가능한 범위에서 목표 버전·근거 참조·자료 버전을 연결한다. 목표나 의존
자료가 바뀌면 관련 결정을 재확인 대상으로 표시한다. 의미적 의존 관계가 불명확하면
유효하다고 자동 승인하지 않는다. 원문 해석·새 근거 확인에 필요한 재읽기는 허용한다.

옛 실패가 다른 입력의 성공으로 해결됐는지는 단순 입력 해시만으로 결정하지 않는다.
관련 산출물·명시적 해결 조건·AI의 근거 있는 상태 갱신을 연결한다. 노트가 추가됐다는
이유만으로 감독 지시를 폐기하지 않으며, 기존 감독의 조건 검사와 같은 상태를 보게 한다.
범용 자동 해결 판정기를 별도로 만드는 일은 첫 구현에서 제외한다.

## 4. 공통 연결과 프로바이더 차이

공통 흐름은 `실행 → 결과 원문 보존 → 자료 목차 갱신 → 한도 내 문맥 구성 → 전달`이다.
의미 기록은 기존 AI 응답 과정의 선택적 `pursuit.note`로 받는다.

| 경계 | 구현 책임 | 첫 버전 보장 |
|---|---|---|
| API·MCP 공통 IBL 실행 | `system_tools_ibl`에서 공통 작업노트 모듈 호출 | 결과가 반환되기 전에 자료 지도 갱신. 전체 결과의 표시 축소 전에 필요한 구조 정보를 확보 |
| IBL 결과 전송 | `ibl_envelope` / `ibl_result_transport`의 봉투 보존 | 노트 메타데이터가 축소 과정에서 사라지거나 원래 결과·실패 표지를 밀어내지 않음 |
| API 직접 실행 | 공통 도구 반환 + 기존 제공자 메시지 포맷 | 도구 결과와 필요한 현재 상태를 다음 추론 입력에 함께 전달 |
| Claude Code·Codex | 공통 MCP 반환 + `cli_provider` 시작·재개 입력 | IBL 경계와 새 실행 문맥에서 동일 작업 상태 제공 |
| 중간 감독·보완 | 공통 노트의 역할별 문맥 | 이미 확보한 출처·남은 문제·변경 범위를 인계 |
| 도구 없는 최종 평가 | 평가 입력 구성부 | 판단 참고와 필요한 근거를 직접 제공. 기존 응답·파일 증거를 노트로 대체하지 않음 |
| CLI 자체 Read·셸 등 | 기존 제공자 이벤트, 필요 시 해당 훅 | 관측 범위를 표시. 자체 도구의 매 호출 직전 최신 노트 주입은 후속 확장 |

`agent_pipeline`의 바깥 스트림에서 사건을 봤다는 것만으로 외부 CLI의 다음 추론
입력을 바꿀 수는 없다. 자동 자료 등록은 가능한 한 공통 도구가 반환되기 전에 끝내고,
바깥 관측은 보완·계측에 사용한다. 중복 사건은 실행 ID로 제거한다.

`cognition/work_note.py`가 저장·상태·문맥 구성의 연결을 소유하도록 제안한다.
하위 `ibl` 전송 모듈이 `cognition`이나 상위 실행 기록 조회 서비스를 import하는
역방향 의존은 만들지 않는다. 전송 모듈은 이미 구성된 작은 메타데이터만 보존한다.

### 전달량과 노트 작성 비용

- 시작·재개·문맥 압축 후에는 작은 현재 상태를 제공한다. 이후에는 변경된 부분을 우선한다.
  전달 기준은 작업만이 아니라 실제 소비 세션·역할·문맥 세대별로 관리한다.
- 전송 여부를 확정할 수 없거나 이전 상태의 보존 여부를 모르면 제한된 현재 상태를 다시
  제공한다. 이를 확인하려고 모델에게 별도 ACK나 노트 읽기를 시키지 않는다.
- 초기 실험 한도는 현재 상태 3,000자, 도구 반환의 추가 노트 1,000자로 제안한다.
  기존 pursuit·인계와 합친 중복을 제거하고 전체 입력 예산도 지킨다. 수치는 성능 보장이
  아닌 조정 가능한 시작값이다. 원문·목차 전문은 기존 읽기 인터페이스로 접근한다.
- 변경이 없으면 같은 전체 노트를 반복 추가하지 않는다. 안정된 시스템 프롬프트를 매번
  바꿔 캐시를 깨기보다 동적인 도구 결과·실행 문맥 영역에 전달한다.
- `pursuit.note` 호출 자체가 추가 모델 라운드를 만들 수 있다. 여러 tool call을 같은
  응답에 묶을 수 있어도 모든 CLI가 그렇게 처리한다고 가정하지 않는다. 매 단계 기록을
  의무화하지 않고 중요한 결정·인계 때 기록하며, 전용 기록 라운드는 비용으로 계수한다.
- 기록 호출 비용이 이득을 상쇄하면 기존 도구 호출에 의미 패치를 함께 싣는 공통 확장을
  후속 검토한다. 첫 버전에 새 IBL 어휘나 별도 노트 요약 모델을 넣지 않는다.
- 전경에서 폴더 전체 검색·원문 대량 재읽기·블로킹 원격 I/O를 하지 않는다. 로컬 상태
  접근도 한도를 두고 실패하면 미갱신 상태를 표시한다. 노트 장애로 성공한 도구를 재실행하지 않는다.

## 5. 구현 순서와 단계별 완료 조건

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| P0: 기준선·계약 고정 | 진행 중인 평가 분리의 반영 상태 확인. 현재 실행 경로와 입력·출력 표본, 비교 과제·품질 기준, 기능 스위치 확정 | 같은 모델·평가 정책으로 비교 가능한 기준선과 제공자별 전달 위치가 문서화됨 |
| P1: 자동 자료 지도 | 작업 상태 저장, 공통 IBL 결과 등록, 시작·재개와 API/MCP 반환 연결 | API 직접 호출과 CLI 모두 기존 자료를 정확한 참조로 재사용. 새 의미 요약 모델 호출은 0 |
| P2: 판단·인계 연결 | 현재 작업 범위의 `pursuit` 읽기·기록 지원, 기존 과제 계약 호환, 감독·보완·최종 평가 입력 연결 | 과제 미등록 작업도 기록 가능. 목표 정정·자료 변경이 다음 판단에 반영되고 평가 루프가 늘지 않음 |
| P3: 실측·부분 적용 | 자동 목차 효과와 의미 기록 효과를 차례로 비교. 기능 스위치로 단계적 적용 | 품질·원래 요구를 유지하며 재탐색과 순비용이 개선되는 범위 확인. 불리한 경로는 비활성화 가능 |
| P4: 사용자 표면·필요한 확장 | 기존 과제/실행 상세에 읽기 화면과 사용자 정정 연결. CLI 자체 도구의 관측·전달 보강 | 사용자도 현재 목표·자료·판단을 볼 수 있고 정정이 버전과 함께 다음 실행에 반영됨 |

P1에서 우선 작동하는 한 경로는 다음과 같다. 서로 다른 자료 두 개를 IBL로 확보한 뒤
모델 또는 보완 실행자가 바뀌어도 작은 지도에서 각 자료를 찾아 필요한 값을 사용한다.
이미 전달한 요약만으로 충분한 경우 원문을 다시 읽지 않고, 근거가 부족한 경우에는
정확한 참조를 읽는다. 경로를 찾기 위한 파일 검색·재크롤링이 없어지는지 확인한다.

P2는 긴 과제만을 위한 기능이 되지 않도록 현재 작업 범위를 지원한다. 기존
`pursuit open`의 명시적 장기 과제 생성 의미는 보존한다. 범위 선택 필드와 관련
스키마는 Python 도구 정의·HTTP·MCP에서 함께 변경하고 기존 호출 호환을 시험한다.

P4의 사용자 정정은 대화로 먼저 지원하고 기존 UI에 연결한다. 새 대시보드 전체를
만들거나 사용자에게 매 작업마다 노트를 관리할 의무를 부과하지 않는다.

## 6. 검증과 채택 기준

### 기능 시험

1. **반환 손실:** 다중 결과·긴 결과·부분 실패·이미지 결과를 통과시켜 원문 참조와
   노트 메타가 유지되는지 확인한다. 앱·IBL 변수의 값에 노트가 섞이지 않아야 한다.
2. **신원·병렬:** 같은 자아의 동시 작업, 같은 변수 이름, MCP 재진입, 지연 결과를
   재현한다. 다른 작업의 자료가 섞이거나 최신 사용자 정정이 덮이지 않아야 한다.
3. **재개·수명:** 중단, 재기동, CLI 문맥 초기화, 참조 만료, 저장 실패를 재현한다.
   없는 자료를 사용 가능하다고 표시하거나 이미 끝난 쓰기를 재실행하지 않아야 한다.
4. **의미 갱신:** 목표·출처 버전을 바꿔 관련 결정이 재확인 대상으로 표시되는지 본다.
   사용자 사실과 AI 제안, 빈 조회와 조회 불가를 구분해야 한다.
5. **프로바이더:** 각 API 제공자의 실제 메시지 구성과 CLI MCP 전송을 테스트 대역으로
   확인한다. 대표 API 한 개와 대표 CLI 한 개는 실제 호출로 검증하고 둘의 결과를 분리 보고한다.
6. **평가 호환:** 도구 없는 평가자가 노트를 읽기 위해 추가 호출하지 않는지, 노트가
   불완전해도 기존 본문·산출물 증거가 빠지지 않는지 확인한다. 새 열람 영수증 조건은 만들지 않는다.

### 비교 과제와 측정

| 과제 유형 | 확인할 효과 |
|---|---|
| 여러 출처를 수집하고 근거를 대조하는 조사 | 자료 위치 재탐색 감소, 원문 근거 유지 |
| 자료 가공·산출물 생성 후 국소 수정 | 중간 결과 재사용, 이미 완료한 작업 반복 감소 |
| 중간에 목표·조건을 정정하고 재개하는 작업 | 최신 요구 우선, 오래된 판단 수정 |
| 짧은 질문·사실 통보 | 노트 때문에 호출·문맥·대기가 늘지 않는지 |

과제는 특정 관용구에 맞춰 고르지 않고, 구현 과정에 사용하지 않은 변형도 포함한다.
가능한 입력·도구 응답은 고정된 fixture로 비교하고 실제 사용 확인은 별도로 한다.
실제 외부 부작용은 시험용 자료·대상에서 수행하며 사용자 작업을 중복 실행하지 않는다.

먼저 현재 버전(A)과 자동 자료 지도만 켠 버전(B)을 비교하고, 그다음 의미 기록과
인계까지 켠 버전(C)을 B와 비교한다. 모델·기어·프롬프트의 노트 외 부분·평가 정책·
초기 상태를 맞춘다. 세션 캐시·외부 도구 캐시 조건과 실행 순서를 기록하며 반복 표본을
사용한다. 소수 사례의 차이를 통계적 효과나 보편적 절감률로 발표하지 않는다.

주요 지표는 전체 역할의 모델 라운드, 청구 원천의 입력·출력·캐시 토큰, 전경 지연,
후처리 비용, 노트 전용 호출·추가 전달량·처리 시간이다. 동일 usage의 중복 집계를
피하고 미관측 값은 0으로 처리하지 않는다. 호출 수만 줄고 출력 토큰이 크게 늘어나는
경우도 별도로 드러낸다.

재읽기는 최신성 확인·새로운 해석·불충분한 최초 전달과, 위치 상실·같은 정보 재탐색을
구분해 표본 판독한다. 자동 실행 완료 판정만으로 품질을 평가하지 않고 사용자 원문의
대상·기간·측정량·정정 사항을 기준으로 결과를 검토한다.

**채택 조건:** 중요한 요구 충족·정확성이 유지되고, 여러 종류의 작업에서 불필요한
재탐색과 순비용 또는 지연의 개선이 반복 관측되어야 한다. 짧은 작업에 체계적 비용
증가가 있으면 적용 조건을 좁힌다. 개선이 없으면 노트 크기·노출 위치·기록 빈도를
한 번에 하나씩 조정하고, 효과가 없는 상태로 전면 적용하지 않는다.

## 7. 변경 대상과 개발 규약

- 신규 공통 모듈 제안: `backend/datastore/task_work_note.py`, `backend/cognition/work_note.py`.
  이름은 구현 시 기존 모듈과 충돌 여부를 확인하고 층 검사에 등록한다.
- 주요 연결: `pursuit_bind.py`, `pursuit_tools.py`, `agent_pipeline.py`,
  `system_tools_ibl.py`, `supervisor_handoff.py`, 최종 평가 입력 구성부.
- 전송·표면: `ibl_envelope.py`, `ibl_result_transport.py`, `api_pursuits.py`,
  `mcp_server.py`, 필요 범위의 `providers/cli_provider.py` 및 제공자 메시지 포맷.
- 의미·보존·문맥 구성 로직을 제공자별 파일에 복제하지 않는다. 별도 제공자 코드는
  전달 위치·포맷·지원 능력 차이만 처리한다.
- 구현 때 `memory.md`와 과제 원장 문서, 필요한 도구 설명·스키마 표면을 갱신한다.
  오래된 계약을 은퇴시키면 저장소의 은퇴 계약 절차를 따른다.
- 변경에 맞는 회귀 시험 후 저장소 필수 검증인 `.venv/bin/python3 -m pytest backend/ -q`,
  층 검사, 필요한 IBL 빌드 검사와 Android 번들 재생성을 수행한다. UI 변경 시에는
  `npx tsc -p tsconfig.app.json`을 수행한다. 코드 파일은 1,500줄 제한을 지킨다.
- 공통 자동 목차와 의미 기록 기능을 각각 끌 수 있게 한다. 끈 상태에서는 노트의
  전달·추가 처리를 멈추고 기존 실행 경로로 돌아간다. 기존 원문·과제 데이터를 삭제하지 않는다.
