# 트리 기억의 공통 회상 설계 — 심층기억과 세계의 기억

작성: 2026-09-17(같은 날 2차 개정). 상태: **0~3단계(심층기억)·4~5단계의 코드 쪽(세계의 기억) 집행. 트리 정비·되먹임 연결·효용 실험은 미집행** — 아래 §10. 옛 이름 `WORLD_MAP_SEMANTIC_RECALL_HANDOFF`(1판, 세계 지도 전용)를 대체한다 — 1판은 git 이력에.
개정 대상: [세계 지도 구조 계약](WORLD_MAP_STRUCTURE_PLAN_2026_09_17.md) §2("임베딩을 만들지 않는다")·§4(검색)·§5, `data/system_docs/memory.md` §5의 "벡터 Top-3 자동 주입 폐지(2026-09-03)" 문단.

**용어**: 세계 지도를 통해 꺼내는 기억을 **세계의 기억**이라 부른다(2026-09-17 사용자 명명). 심층기억은 사용자에 대한 기억, 세계의 기억은 AI의 지식으로 가는 이름들이다.

## 1. 판정과 목표

네 기억(블로그·심층기억·실행기억·세계의 기억)은 "트리 구조의 기억에서 관련된 것을 꺼낸다"는 같은 구상에서 나왔으나 구현이 갈렸다.
실행기억은 예외다 — IBL 용례이고 해마가 학습으로 자동 연상하므로 지도 주입을 뺐다(`14180cfa`). 남은 둘에 대한 사용자 판정(2026-09-17):

1. 심층기억과 세계의 기억은 **같은 방식으로 구현되고 같은 자리에서 주입**된다 — 모든 의식·실행 에이전트가 받는 자리.
2. **지도와 선택된 기억을 둘 다 자동 주입**한다. 주입된 기억으로 먼저 일하고, 모자라면 지도를 보고 더 찾는다. 8건은 많다.
3. 고르는 방식은 **블로그 방식**이다.
4. 지도와 사전은 앞으로 계속 확장·개선된다. 그래서 **구조**가 중요하다 — 고치는 일이 데이터 편집으로 끝나야 한다.

이 판정은 2026-09-03의 "심층기억 Top-3 자동 주입 폐지"를 같은 판정자가 개정하는 것이다. 그때와 다른 점: 지도가 함께 실리고, 가지를 먼저 고르며, 건수가 적다.
포식 기억의 자동 주입 금지(같은 날 판정)는 이 설계의 범위 밖이며 그대로다.

## 2. 지금의 구현 — 서로 반대쪽 절반

| | 심층기억 | 세계의 기억 | 블로그(본보기) |
|---|---|---|---|
| 지도 자동 주입 | 있음 `<memory_map>` | 없음(스크립트 browse 로만) | 없음(AI가 부를 때만 쓰는 기억) |

| 고르는 방식 | 임베딩 있으나 AI가 부를 때만 | 글자 일치 | 사전→가지→융합 검색 |
| 분류 경로가 검색 텍스트에 | 없음(`내용+키워드+종류`) | 0.5점 가산뿐 | 있음(잎 이름 2회+전체 경로) |

실측(09-03 이후 375턴): 심층기억은 AI가 가지를 고르면 **맞게 고르지만**(아내 선물→`가족`, 전세→`매물 조건·조사`) **열지 않는 턴이 절반**이다 — 속초 여행 대화 25턴 중 12턴이 기억 없이 진행됐다. 지도만 주는 방식의 약점은 "어느 가지인가"가 아니라 "열 것인가"다.

### 3.3 세계의 기억에 없는 것 (2차 실험이 드러낸 것)

세계 지식은 나무가 아니라 **격자**다. 같은 주제가 여러 분야에 걸친다 — 대기행렬 이론은 `운영/생산과 물류`에 있는데 `운영/대기와 자원` 가지가 따로 있고, 전산유체역학(개념)은 `공학/기계와 제작`, OpenFOAM(도구)은 `계산/공학`이다.
개인 기억은 주제가 한 가지에 모이므로 D3만으로 충분하지만, 세계의 기억은 **B4(흩어짐을 사전이 안다)** 없이는 가지 먼저 고르기의 이득이 나오지 않는다.

## 5. 공통 구조

### 5.1 세 가지 단위

| 단위 | 담는 것 | 심층기억의 자리 | 세계의 기억의 자리 |
|---|---|---|---|
| **항목** | 본문(또는 이름+한 줄 뜻) · 찾는 말(키워드/별칭) · **가지 경로 하나** | `memories` 행 = 가지 문서 `## 기억` 의 한 줄 | `world.yaml`·`atlas/*.yaml` 의 entry (`path`) |
| **가지** | 경로 · 아래 표의 **가지 사전 항목** | 가지 문서 `memory.md` 의 머리 | 신설 `branches.yaml`(분야별 조각 가능) — 추적되는 공개 데이터 |
| **지도** | 가지 경로 + 건수 + 요약 — 가지에서 **파생**, 손으로 쓰지 않는다 | `memory_tree.map_text` | 신설(같은 렌더러) |

정본의 자리는 기억마다 다르다(개인 문서 대 추적되는 YAML). **같게 맞추는 것은 저장 형식이 아니라 가지 사전 항목의 모양과 회상 코드**다.

### 5.2 가지 사전 항목 — B1·B2·B4·B7·D2를 한 모양으로

| 필드 | 뜻 | 누가 쓰나 |
|---|---|---|
| `요약` | 이 가지에 무엇이 있나, 한 줄. **지도에 실린다** | 심층=증류기가 가지를 만들 때(지금처럼), 세계=편집자. 사람이 고칠 수 있다 |
| `찾는 말` | 이 가지로 와야 할 **일상 표현** — 상황·증상·가진 것·원하는 것. 전문용어 나열이 아니다(B2) | 같음. 비워 둘 수 있다 — **연상 기준 가지는 비운다**(B7) |
| `함께 볼 가지` | 같은 주제가 걸쳐 있는 다른 가지 경로들(B4). 세계의 기억에서 필수에 가깝다(§3.3) | 편집자 + 아래 5.5의 되먹임 |
| `예외` | 이름과 달리 여기 없는 것·다른 가지에 있는 것 | 필요할 때만 |

지도에는 `요약`만, 가지 고르기에는 `요약+찾는 말`이 쓰인다. 넷 다 **데이터**이고 코드에 가지 이름이 들어가지 않는다(IBL 헌법 '명사의 자리'와 같은 원칙).

### 5.3 색인 — 빌드/동기화 산출물 (B1·B8)

- **항목 벡터**: `잎 이름 ×2 + 전체 경로 + 본문(또는 이름 ×2 + 뜻) + 찾는 말`. 블로그와 같은 꼴.
- **가지 벡터**: `사전 텍스트 벡터 + 소속 항목 벡터의 평균`(§4.1에서 가장 나았던 조합). 소속이 바뀌면 다시 계산.
- **인코더는 하나**: `jhgan/ko-sroberta-multitask`(블로그와 동일). 해마 모델은 재학습마다 공간이 바뀌고 세계 어휘에서 나쁘다. 심층기억의 기존 벡터는 재색인한다(DB당 최대 300행).
  부팅 후 백그라운드 적재, 적재 전에는 의미 채널이 빠지고 글자 채널만 돈다 — 질문 경로에서 모델을 올리지 않는다.
- 색인 메타 = 모델 이름 · 텍스트 규칙 판 번호 · 원본 revision. 어긋나면 의미 채널만 `stale` 로 꺼진다.
- 세계=`build_knowledge_catalog.py` 가 생성·`--check` 가 검증. 심층=기존 문서→색인 동기화(`sync_node`)에 같은 규칙으로 얹는다.

### 5.4 회상 — 한 함수, 두 저장소 (B3·B5·B6)

```
recall(store, 질문) →
  1. 가지 고르기: 가지 벡터와의 유사도 상위 2 (+ 그 가지들의 '함께 볼 가지')
  2. 가지 안: 의미+글자 역순위 융합으로 상위 2
  3. 가지 밖: 같은 융합으로 상위 1            ← 누락 보충이자 5.5의 신호
  → 가지 목록 + 항목 3건
```

- `store` 는 어댑터다: `branches()`·`items()`·벡터·글자 검색·렌더. 심층기억 어댑터(에이전트별 DB)와 세계 어댑터(스냅샷). 새 backend 모듈은 `datastore/` 층 + `LAYERS` 배정.
- **AI가 직접 부르는 검색도 같은 함수**를 쓴다 — 심층 `[self:memory]{op:"search", node}`, 세계 `세계지도` 스크립트의 `search`(선택 인자 `path`·`mode` 추가). 필터의 뜻은 B5로 통일: 전체 경로·잎 이름·상위 그룹·목록. **새 IBL 어휘·op 없음.**
- 건수 기본값 **가지 안 2 + 밖 1 = 3**. 설정으로 바꾸되 상한 4. 심층기억 항목은 **건당 200자**에서 자르고 `‹#id›` 를 남겨 전문은 recall 로 연다(예약 안내문 1,300자 방지).

### 5.5 되먹임 — 검색이 사전을 고친다 (B4)

가지 밖 1건이 가지 안 항목들보다 점수가 높았던 턴은 "사전이 모르는 흩어짐"의 신호다. 회상 사건 기록에 `{질문 요지, 고른 가지, 밖에서 건진 항목의 가지}` 를 남기고,
정기 정리 패스(심층=기존 `memory_consolidation`, 세계=편집 세션)에서 **AI가** 그 목록을 읽고 `함께 볼 가지`·`찾는 말`을 고치거나 항목을 옮긴다.
- 고치는 주체는 AI·사람이고 코드는 목록만 만든다(코드 분류기 없음, D3와 같은 원칙).
- "세어 두고 지켜본다"로 끝내지 않는다: 같은 (고른 가지→밖의 가지) 쌍이 반복되면 정리 패스의 **할 일**로 올라오고, 세계 쪽은 `--check` 가 `요약` 없는 가지·1~2항목 단독 가지를 경고한다.

### 5.6 주입 — 한 자리, 지도와 기억 둘 다

- **자리**: `cognitive_recall._build_execution_memory` 하나로 모은다. 지금 `agent_pipeline` 에서 따로 붙이는 세계 조각을 이 안으로 옮겨, 그 함수를 직접 부르는 경로(위임·통신)도 같은 묶음을 받게 한다.
- **블록**(이름이 뜻을 말하게):

| 블록 | 내용 | 크기 규칙 |
|---|---|---|
| `<memory_map>` | 심층 지도(현행) | 600자를 넘으면 최상위 가지만(건수 포함), 아래는 recall 로 |
| `<recalled_memory>` | 고른 가지 + 심층기억 3건 `- [가지] 내용 ‹#id›` | 건당 200자 |
| `<world_map>` | 세계 지도 **최상위 분야만**(27줄) | 아래 단계는 `세계지도` browse 로 |
| `<world_memory>` | 고른 가지 + 세계의 기억 3건 `분류 경로: 이름` (+ 글자 채널이 잡은 항목의 관계 조각 — 현행 `<method_map>` 의 내용) | 기존 상한 유지 |

  note 속성에 한 줄: "기계가 고른 후보다 — 관련 없으면 무시한다. 모자라면 지도의 가지를 직접 연다."
- **관련 없는 턴**: 기계로 가르지 못하므로(§4.2) 가르려 하지 않는다. 3건·수백 자로 작게 싣고 **판단은 받는 AI가** 한다. 글자 채널이 비고 의미 채널만 있을 때도 같은 표식으로 싣는다.
  1판의 "의식이 도는 턴에만"은 철회한다 — 사용자 판정(모든 의식·실행 에이전트가 받는 자리)과 비용 실측(55~250토큰)에 따른다. 짧은 실행 명령 턴에서 잡음이 해가 되는지는 §7-4의 측정 항목이다.
- **경계는 그대로**: 심층기억은 주인 요청 턴에만(2026-09-14 주체 관문), 세계의 기억은 개인 기억이 아니므로 모든 주체에. 몸-명사 관문·출처 경계 등 심층기억의 쓰기 쪽 규칙은 건드리지 않는다.

## 6. 트리와 사전을 키우는 규칙

| 규칙 | 심층기억 | 세계의 기억 |
|---|---|---|
| 새 항목의 자리 | 증류기가 지도+사전을 보고 정한다(D3, 현행) | 편집자가 같은 방식으로 — 기존 가지 우선, 새 가지는 `요약`과 함께 |
| 가지를 만들 때 | `요약`을 채운다(지금은 24%가 자리표) — 비면 정리 패스의 할 일 | `요약` 없으면 `--check` 실패 |
| 축은 하나 | 주제. 종류는 표식(D4) | 분야→하위 분야. **도구·개념·방법을 다른 축으로 가르지 않는다** — `계산/공학`(도구)과 `공학/기계와 제작`(개념)의 분리가 §3.3의 겹침을 만들었다. 도구는 그것이 섬기는 방법의 가지에 둔다(README 기존 원칙) |
| 걸치는 주제 | 드물다 | `함께 볼 가지`에 적는다. 그래도 부족하다는 측정이 나오면 그때 항목의 보조 경로(`also`)를 데이터 계약에 더한다 — 먼저 넣지 않는다 |
| 단독 가지 | — | 1~2항목 가지(현재 절반)는 상위·이웃 가지로 합친다. ID는 유지, `path`만 고친다 |
| 재편 후 | 문서 동기화가 재색인 | 빌드가 재색인(B8) |

## 7. 검증

1. **가지 고르기**: 심층=실제 연 가지 40건(+이후 누적), `created_at` 절단 적용. 기준 @2 ≥ 85%. 세계=아래 3의 판정으로.
2. **기계 계약**: 색인 stale→의미 채널만 꺼짐 · 모델 미적재→글자 채널만 · 건당 절단과 `‹#id›` · 주체 관문(회원 턴에 심층기억 0) · 위임 경로에도 같은 묶음 · 죽은 태그 없음(`<method_map>` 을 가리키는 프롬프트가 남지 않게 — 실제 조립문에서 표식을 찾는 관문).
3. **쓸 만한 주입인가**(지표 교체): 단일 표적 도달을 버리고, 주입 3건 각각을 "이 질문에 쓸 만한 이름/기억인가"로 판정한다(모델 판정 + 표본은 사람이 확인). 평면 3건과 블로그식 3건을 같은 질문에서 비교. 새 질문 묶음은 사전을 고칠 때마다 새로 쓴다 — 고친 뒤의 질문은 더는 새 질문이 아니다.
4. **효용**(모델 호출, N≥30): 같은 모델·질문에서 ①지금(지도만/글자 조각) ②지도+선택 3건. 지표 = 기억이 필요한 턴에서 기억이 쓰였는가(속초 대화 부류) · 추가 도구 호출 수(가지 열기 감소) · 짧은 명령 턴에서의 오작동 · 총 토큰.
5. **비용**: 사건 기록에 블록별 문자·추정 토큰. §4.3의 예상(일반 ~640, 시스템 AI ~1,000)을 넘으면 지도 절단 규칙부터 본다.

## 8. 하지 않는 것

- 점수 문턱·가지 집중도 같은 코드 관련성 판정기, 후보를 거르는 추가 LLM 호출.
- 해마 모델 재사용, 사용 빈도로 가지·어휘 끄기, 새 IBL 어휘.
- 포식 기억·실행기억으로의 확장(실행기억은 오늘 반대 방향으로 정리됐다).
- 세계 지도 2단 전체의 상시 주입, 관계 그래프의 전면 재설계(글자 채널의 관계 조각은 현행대로 둔다).
