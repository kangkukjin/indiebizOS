# 가치 우선 통합 증류 — 2026-09-21

## 판단 원칙

기억을 많이 남기는 것이 목적이 아니다. 불필요한 기억은 검색과 다음 판단을 오염시킨다.
다음 협업·실행·탐색의 구체적인 판단이나 행동을 개선할 지속 가치가 있는 후보만 선택한다.
가치가 있어도 사용자 귀속·실행 원문·실제 관측이 부족하면 저장하지 않는다.
세 배열이 모두 비어 있는 결과는 정상 성공이며 후보 수 상한은 할당량이 아니다.
가치가 불분명한 후보를 보류 큐에 축적하거나 추가 모델로 살리지 않는다.

## 구현 경로

- `agent_pipeline`: 응답을 만든 실행 provider를 복원하기 전에 모델 descriptor를 캡처한다.
  증류용 도구 이력에도 실제 결과를 보존한다. 포식 표면은 공간 기억만 활성화한다.
- `model_resolver`: 비밀을 제외한 모델·역할·핀·선택 근거를 동결한다. 워커는 현재 자격증명을
  읽되 기어를 다시 해소하지 않는다. 별도 원샷 provider와 기존 전경 우선 잠금을 사용한다.
- `cognitive_distill._after_response_async`: 원문·평가·발화자 쓰기 허용·신원·모델을 복사한
  버전 1 작업을 영속 큐에 넣는다. 적재 실패 시 원문 원장과 오류를 남기며 무기록 저장하지 않는다.
- `unified_distill`: 종류별 관문/자료 준비 → 한 번의 통합 선별·관계 판단 → 판단 영속화 →
  종류별 검증·저장. 과제·가이드 후처리는 통합 판단 밖에 있다.
- `ibl_usage_rag.prepare_experience/apply_experience`: 기존 중복·성공·구문·변수 의존·액션·인자·
  개인 명사 관문을 재사용한다. 실제 선택한 원문만 저장하고 자동 작명/관용구 등록은 계속 중단한다.
- `distill_memory_adapters`: 심층은 사용자 원문 선택, 공간은 실제 관측이나 주소가 있는 명시적
  사용자 선언에 접지한다. AI 답변만으로 사용자 사실·파일 실재·공간 부재를 저장하지 않는다.
- `distill_ledger`: world_pulse DB의 `distill_jobs`에 입력·준비 자료·첫 유효 판단·후보/후처리
  영수증·호출 시간/사용량을 보존한다. 이 자료는 회상 대상 기억이 아닌 운영 원장이다.

조종실의 독립 `/ibl/distill`과 옛 큐 행은 호환 경로를 유지한다. 신규 공통 후처리와 포식
브라우저가 통합 경로를 사용하며 같은 턴을 구·신 양쪽에 저장하지 않는다.
프롬프트 구성 표면은 통합 프롬프트와 턴의 실행 모델을 사용하는 계약을 표시한다.

## 저장과 장애

각 저장소의 `distill_receipts`는 기억 mutation과 같은 SQLite 트랜잭션에 후보 키를 남긴다.
DB 저장 뒤 인덱스·가지 문서 반영이 실패하면 이미 저장한 ID를 재사용해 반영만 재개한다.
문서 반영이 끝나기 전에는 오래된 문서의 역동기화가 DB 기억을 삭제하지 못한다.
기계 생성 절은 임시 파일을 원자 교체한다. 실행기억의 학습 JSON과 주행 절도 같은 후보 키로
재배달을 구분한다. 파일·벡터 반영까지 하나의 DB 트랜잭션이라고 주장하지 않는다.

- 빈 선별 결과: `completed_empty`, 기억 쓰기 0건.
- 가치·원문·스키마가 부족한 개별 후보: 거부 사유를 남기고 종결한다.
- 조회 실패: 해당 종류를 저장하지 않으며 `preparation_failed`를 빈 결과와 구분한다.
- 동시 정정 충돌·위치 변경: 해당 후보를 종결 보류한다. 같은 작업에서 재판정하거나 NEW로 우회하지 않는다.
- 저장/후속 반영의 일시 오류: 첫 판단을 재사용하며 기존 큐의 최대 3회 정책으로 재개한다.
- 잘못된 JSON/출력 봉투: 실패를 보존한다. JSON 수리 모델이나 추가 의미 판단을 호출하지 않는다.
- 모델 응답을 받기 전의 실패: 재시도 가능. 응답 수신과 판단 영속화 사이의 프로세스 종료는
  재호출 가능성이 있어 호출 시도 원장으로 관찰한다.
- 과제·가이드·회상 되먹임: 별도 단계 영수증을 쓴다. 실행 도중 중단되어 효과가 불명확하면
  자동 반복하지 않고 `started/failed`를 남긴다. 이 외부 단계의 정확히 한 번 완료는 보장하지 않는다.

심층 SAME은 새 사실을 저장하지 않는다. 비교를 위한 조회도 `touch=False`이며, 비교에
걸렸다는 이유만으로 기억의 사용 시각을 올리지 않는다. 확인된 SAME의 사용은 후처리 영수증으로
회상 되먹임에 연결한다. UPDATE는 새 원문 사실을 별도로 연결하고 REPLACE는 옛 내용·출처와
비교 버전을 보존한다. UPDATE의 관계 대상 검사와 INSERT도 같은 트랜잭션으로 묶는다.

## 보수적 상한과 현재 범위

- 모델 입력은 UTF-8 24,000바이트 상한으로 시작한다. 24,000토큰 실측치가 아니다.
  완결된 자료 구획만 포함하고 넘친 종류는 이유를 남겨 제외한다. 기존 비교 본문은 중간에서
  잘라 저장 판단에 쓰지 않는다. 이 설정은 저장 정밀도를 우선하며 긴 턴에서 가치 있는 기억도
  생략될 수 있다. 누락을 메우기 위한 후속 요약 모델 호출은 없다.
- 심층 검색은 앞 문맥을 포함한 최대 8개 원문 단위, 단위별 관련 기억 3개다. 검색 재현율이
  완전하다고 주장하지 않는다. 비교 후보 수는 출력 저장 할당량이 아니다.
- 출력 상한은 실행 2·심층 3·공간 3건, 개별 문자열 400자다. OpenAI 계열·Anthropic·Gemini에는 기본 4,000토큰
  한도를 적용하고 이어쓰기를 끈다. 명시적 추론 예산이 있으면 그 예산에 본문 여유 1,024토큰을
  더한 값 이상을 확보한다. 수신 JSON 본문의 별도 길이 상한도 적용한다. CLI의 실제 출력/문맥 상한은 해당 제공자가 소유한다.
- 자동 공간 부재(`dead_branch`)는 v1에서 저장하지 않는다. 실패한 검색을 부재로 확정하는
  오염을 막기 위한 제한이다. 관측 주소가 명시된 공간 지식만 다룬다.
- 새 어휘·모델 티어 설정·기존 기억 재감사/삭제는 이번 변경에 포함하지 않는다.

## 전환과 복구

신규 큐 행은 `distill-v1:` registry 키를 사용한다. 구버전 코드로 돌아가도 이 키를 기존
러너로 해소할 수 없어 신규 통합 작업을 옛 증류로 재실행하지 않는다. 영수증과 큐 행을
보존한다. 재업그레이드하면 같은 접두의 orphaned 행도 재개 대상으로 본다. 옛 작업은 기존
경로로 처리한다. 같은 episode/turn의 신규 작업은 동일 job key로 재배달을 식별한다.
부분 반영된 기억을 일괄 삭제하거나 원문을 옛 증류에 통째로 다시 넣지 않는다.

## 비교와 검증

`docs/experiments/unified_distill_2026_09_21/compare.py`와 `results.json`은 합성 원문 8개를
고정된 기존 기억으로 비교한다. 실제 모델을 호출하되 저장은 캡처만 하므로 라이브 기억 쓰기는 없다.
A는 기존 분리+background, B는 통합+실행 모델, C는 기존 분리+동일 실행 모델이다.
원문·선택된 내용·모델 선택·프롬프트 지문·호출 횟수·시간·제공된 사용량을 보존한다.

최종 프롬프트 비교에서 세 방식 모두 8/8 기대 저장 건수를 충족했다. 일회성 사실·일회성 조건·인용문·
AI 답변만의 사실·이미 있는 선호·대상 없는 지시어는 저장하지 않았고, 지속 선호와 명시적 정정만
남겼다. 저장된 본문도 원문과 대조했다. 통합이 더 좋은 의미 판단을 한다는 증거는 아니다.
정정 사례의 의미 판단은 기존 2회에서 통합 1회로 줄었다.

전체 시간·토큰은 모델 차이와 프롬프트 크기에 영향을 받는다. 특히 CLI 구독 모델의 입력
계측에는 해당 제공자의 호출 문맥이 포함되므로 프롬프트 본문 길이와 같지 않다. 구독 비용을
0원으로 처리하지 않으며 가격 절감을 주장하지 않는다. 실제 측정표는 아래 완료 기록에 둔다.

한계: 과거 에피소드와 당시 기억 스냅샷의 전수 재생은 수행하지 않았다. 합성 심층기억 8개는
역사적 24~40개 에피소드 비교를 대체하지 않으며 희귀한 의미 오판율을 추정하기에도 부족하다.
실행·포식과 장애 복구는 격리된 DB 및 fake provider 회귀로 검증한다.
