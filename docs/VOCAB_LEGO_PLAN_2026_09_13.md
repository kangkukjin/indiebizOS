# 어휘 레고박스 구현 계획

작성: 2026-09-13. 상태: 구현 전 설계. 사용자와 합의한 제품 범위 및 현재 코드 조사에 근거한다.

## 1. 목표와 유지할 것

지금의 일처리 방식은 유지한다. 사용자가 선택한 어휘로 AI가 IBL 문장을 만들고,
기존 문법·실행기·인지 파이프라인으로 처리한다. 변화는 어휘를 보유하고 선택하고
주고받는 방식이다.

- 필수어휘는 항상 유지한다.
- 사용자어휘 묶음을 파일 하나로 주고받는다. 제안 확장자는 `.iblpack`이다.
- 내 레고박스는 보유한 묶음 전체, 사용 중 목록은 그중 깨어 있는 묶음이다.
- 잠재우기는 활성 사전에서 제외하는 동작이다. 파일·설정·기억·코퍼스를 삭제하지 않는다.
- 깨우기는 현재 사전으로 복귀시키는 동작이다. 정상 묶음에 수동 빌드나 백엔드 재시작을 요구하지 않는다.
- AI가 사용자 선택을 우회해 잠든 묶음을 깨우지 않는다.

첫 버전의 선택 단위는 패키지에 대응하는 **어휘 묶음**이다. 한 파일에 낱말 하나도,
관련 낱말 여러 개도 담을 수 있다. 묶음 내부 낱말별 스위치는 이번 범위에 넣지 않는다.
마켓플레이스·자동 업데이트·프로필 프리셋·코퍼스 재학습도 첫 버전의 필수 범위가 아니다.

## 2. 현재 구현과 간극

| 확인한 코드 | 재사용할 기반 / 보완할 점 |
|---|---|
| `backend/ibl/package_manager.py` | 폴더 패키지·검증·목록·공유가 있다. 설치와 제거는 폴더 이동이다. 잠재우기를 이 경로에 연결하면 안 된다. |
| `backend/cognition/ibl_usage_generator.py:remove_for_package` | 제거 시 해당 액션을 참조하는 행과 벡터를 삭제한다. 새 잠재우기·박스 삭제에는 이 정리 동작을 적용하지 않는다. |
| `backend/surface/api_packages.py` | HTTP 설치가 기본적으로 AI 설치를 시도한다. 표준 파일 가져오기는 AI의 코드 생성·수정 없이 검증 가능한 경로로 만든다. |
| `backend/ibl/ibl_routing.py:_package_op` | IBL 설치·제거는 재빌드와 캐시 무효화를 호출한다. HTTP 경로와 절차가 다르고 재빌드 실패도 경고를 얹은 성공으로 나갈 수 있다. 공통 생명주기 서비스가 필요하다. |
| `scripts/iblbuild_derive.py` | fragment 수집·어휘 병합·충돌 판정이 있다. 실행 시 사전 구성과 빌드가 같은 의미론을 쓰도록 재사용한다. |
| `backend/datastore/ibl_registry.py` | 몸별 어휘 필터가 있다. 사용자의 묶음 활성 상태는 추가해야 한다. `foreign_actions`는 직접 적힌 액션을 검사하고 `fn` 내부 의존성은 검사하지 않는다. |
| `backend/cognition/ibl_usage_rag.py` | 검색 뒤 소유 필터가 있다. 실패 시 통과하고, 일부 검색은 top-1을 가져온 뒤 제외한다. 참조 캐시 키에는 활성 사전 버전이 없다. |
| `backend/ibl/tool_loader.py` | 핸들러·도구 매핑 캐시를 재사용할 수 있다. `handler.py` 외 형제 모듈의 갱신은 현재 재시작을 필요로 한다. |
| `frontend/src/components/launcher-components/dialogs/ToolboxDialog.tsx` | 기존 도구 상자를 발전시킨다. 필수 패키지 목록이 UI의 `STANDARD_PACKAGES`에 별도로 있다. |
| `data/core_manifest.json`, `scripts/build_core_manifest.py` | git 추적 집합에서 배포 출처를 파생한다. 여기의 `core`를 그대로 제거 불가능한 필수 집합으로 해석하면 안 된다. |

현재의 설치·공유 기반을 확장하되, HTTP·IBL·UI가 서로 다른 설치 의미를 갖는 문제부터 닫는다.
위 조사는 정적 코드 확인이며, 실제 켜기·끄기 동작을 검증한 기록은 아니다.

## 3. 사용자 경험

조종실에 **내 어휘** 진입점을 두고 기존 도구 상자와 같은 데이터를 보여준다.

- 상단: 필수어휘(기본 제공), 사용 중인 묶음 수, 파일 가져오기.
- 본문: 내 레고박스의 카드. 이름·하는 일·포함 낱말·사용 스위치·상태를 표시한다.
- 사용 중/잠든 묶음으로 좁혀볼 수 있지만 보관 위치가 바뀌는 듯한 복잡한 설치 화면은 만들지 않는다.
- 파일 선택과 끌어놓기를 모두 지원한다. 정상 파일을 넣으면 잠든 상태로 박스에 들어간다.
- 스위치를 켜면 검증과 준비를 거쳐 사용 중으로 바뀐다. 준비 전에는 사용 중으로 표시하지 않는다.
- 카드 메뉴에 내보내기와 박스에서 삭제를 둔다. 삭제와 잠재우기는 별도 동작이다.
- 필수어휘는 사용 스위치·삭제 버튼 대신 기본 제공 표시를 쓴다.
- 연결이나 의존성 준비가 필요한 경우 무엇이 필요한지 해당 카드에서 보여준다.
- 잠재우기에 영향을 받는 앱·예약 작업과 진행 중 작업을 표시한다. 단순한 전환마다 확인창을 추가하지 않는다.

파일을 보내는 행위는 기존 메신저·메일·파일 공유를 이용한다. 첫 버전에 외부 게시 기능을
새로 만들지 않는다. `.iblpack` 더블클릭으로 앱을 여는 OS 파일 연결은 후속 개선이다.

## 4. 상태와 필수어휘의 단일 기준

보유 정보와 실행 선택을 분리하는 로컬 원장을 둔다. 제안 위치는
`data/vocabulary/library.json`이며 git 배포 정의와 분리된 사용자 런타임 상태다.
최종 저장 방식은 기존 상태 저장 관례와 다중 프로세스 접근을 확인해 결정한다.

- 보유 정보: 묶음 ID·버전·파일 지문·경로·출처.
- 사용자 선택: 활성/잠듦.
- 준비 상태: 준비됨/연결 필요/의존성 필요/호환 불가/전환 중/오류.
- 활성 사전에는 선택이 활성이고 필요한 준비가 완료된 묶음만 들어간다.
- 핵심 식: **활성 사전 = 필수어휘 + 사용자가 켠 준비된 묶음의 어휘**, 몸별 실행 가능 조건도 적용한다.

필수 집합은 IBL 헌법의 `always_on`·표준 기능어·필수 인프라와 실제 제공 패키지를
대조하여 먼저 확정한다. 기존 UI의 네 패키지나 배포 출처를 그대로 정답으로 복사하지 않는다.
필수 기능어와 선택 기능이 섞인 패키지는 초기에는 필수 부분을 보호하고,
묶음 전체 스위치를 제공하려면 소유권을 정리한다. 표준 의미가 달라지면 언어 개정 절차를 따른다.

필수 선언은 데이터 한 곳이 소유하고 UI와 백엔드가 같이 소비한다.
HTTP·IBL·기존 제거·박스 삭제 어느 경로에서도 필수 공급자를 제거할 수 없어야 한다.
외부 파일이 자신을 필수로 선언해 보호 규칙을 바꾸게 하지 않는다.

묶음 A가 묶음 B에 의존하면 B가 준비되고 활성화되어야 A를 깨울 수 있다.
A가 활성인 동안 B만 잠재우려 하면 필요한 순서를 표시하고 변경을 적용하지 않는다.
첫 버전은 연관 묶음을 몰래 켜거나 끄지 않는다. 의존성 순환과 충족할 수 없는 버전 조합도 거절한다.

## 5. 파일 계약 v1

`.iblpack`은 ZIP 컨테이너로 제안한다. 별도 실행 파일이나 새 IBL 문법을 만들지 않는다.

```text
manifest.json          형식 버전, 묶음 ID·버전, 설명, 호환 조건, 의존성, 파일 목록·지문
ibl_actions.yaml       기존 어휘 fragment 형식
handler.py             기존 핸들러 진입점
...                    선언된 형제 모듈·정적 자원·사용 설명·작은 예제
```

`tool.json`이 필요한 경로는 기존 파생 규칙으로 생성·대조한다. 전달 파일 안의 복사본을
어휘 정의와 별개 정본으로 신뢰하지 않는다. 기존 다중 디렉터리·바이너리 자원도
manifest에 선언하여 담을 수 있게 한다. 숨은 외부 경로나 개발자 PC의 절대 경로에 기대지 않는다.

가져오기 절차는 임시 공간에서 형식·호환 조건·액션/도구 이름 충돌·경로·파일 지문을
검사한 뒤 박스에 등록한다. 검사 중 핸들러 import나 설치 스크립트 실행을 하지 않는다.
경로 탈출·심볼릭 링크 탈출·과도한 압축 해제 크기를 거절한다. 지문은 무결성 확인이며
제작자 신뢰나 안전한 코드 실행을 보증하는 서명으로 표시하지 않는다.

- 같은 ID·같은 버전·같은 지문은 중복으로 처리한다.
- 같은 ID·같은 버전·다른 내용은 충돌로 거절한다.
- 다른 버전은 조용히 덮어쓰지 않는다. 교체 전 차이와 호환성을 보여주고 이전 버전을 복구 가능하게 보존한다.
- 액션 이름 충돌은 자동 개명하거나 마지막 파일 우선으로 덮지 않는다.
- 계정 키·토큰·사용 기록·DB·개인 코퍼스는 내보내기에 포함하지 않는다. 선언된 배포 파일만 포장한다.
- 외부 라이브러리는 의존성으로 선언한다. 준비에 기존 라이브러리 승인 규약이 필요하면 그 경로를 사용한다.
- 새 표준 파일은 AI가 README를 해석해서 코드를 고치는 기존 설치 경로를 통과하지 않는다.

## 6. 전환과 실행의 일관성

공통 생명주기 서비스를 만들고 가져오기·깨우기·잠재우기·버전 교체·삭제를 맡긴다.
기존 `package_manager`·HTTP·`self:package`는 이를 호출한다. 새 노드나 새 액션은
기본적으로 추가하지 않고 기존 `self:package`의 필요한 op와 데이터 계약을 확장한다.
사용자 활성 선택의 변경 권한은 사람의 조종실 경로가 소유하며 AI 호출은 상태 조회·변경 제안까지만 한다.

전환 절차:

1. 변경 요청을 직렬화하고 의존성·필수 보호·충돌·현재 실행을 확인한다.
2. 후보 사전·도구 매핑·준비 자원을 기존 사전 밖에서 구성하고 검증한다.
3. 성공한 구성에 새 사전 세대 번호를 부여해 원장과 실행 구성을 일관되게 전환한다.
4. 카탈로그·검사기·실행기·해마 조회·함수·앱·능력 명함의 캐시가 해당 세대를 사용하게 한다.
5. 실패 시 이전 정상 구성을 유지한다. 성공 응답을 먼저 보내고 재빌드 실패를 경고로만 남기지 않는다.

필수어휘와 보유 정의를 읽어 활성 뷰를 만들며, 스위치를 누를 때마다 git 추적 중인
`ibl_nodes.yaml`이나 문서 마커를 다시 쓰지 않는다. 빌더의 병합·검증 의미론을
공유 가능한 모듈로 추출하고, 개발 빌드와 런타임 후보 구성이 같은 결과를 내는지 검증한다.
이는 별도 손편집 사전을 만드는 것이 아니라 같은 소스에서 활성 뷰를 파생하는 작업이다.
새 backend 모듈은 저장소 층 규약을 따르며 backend에서 scripts를 역으로 import하지 않는다.

잠재우기 요청 이후 해당 묶음의 새 호출은 차단한다. 이미 실행 중인 외부 동작은
임의로 취소하지 않고 완료를 기다리며 전환 중으로 표시한다. 완료 후 잠듦을 확정한다.
기존 계획의 다음 단계가 잠든 어휘를 요구하면 원인을 알려 중단·재계획하고 임의로 다시 켜지 않는다.
동적 함수·워크플로·직접 도구 호출도 실제 호출 직전 동일한 활성 검사를 통과해야 한다.
MCP 같은 별도 프로세스도 세대를 확인해 변경을 반영하며, 낡은 사전으로 실행을 계속하지 않는다.

핸들러는 지연 로딩을 활용한다. 형제 모듈·동명 모듈·버전 교체의 격리를 검증해
기존 import 캐시 때문에 재시작이 필요한 경로를 닫는다. 단순 `sys.modules` 일괄 삭제로
공유 모듈과 진행 중 호출을 깨뜨리지 않는다. 필요한 묶음에는 전용 실행 프로세스나
명시적 수명주기 관리 중 실제 의존성에 맞는 방식을 적용한다.

묶음이 소유한 타이머·폴링·스레드·프로세스·장치 연결을 조사하고 정지/재개를 연결한다.
아무 선언 없이 임의의 Python 전역 자원을 완전히 해제한다고 약속하지 않는다.
일반 호출형 묶음부터 무재시작 전환을 완성하고, 상주형 묶음도 검증을 마쳐야 제품 완료로 본다.

## 7. 코퍼스와 기존 작업

잠재우기·깨우기·박스 삭제는 코퍼스 행·벡터·개인 설정·에피소드를 삭제하지 않는다.
개인 데이터 정리는 별개의 명시적 작업이다. 기존 제거 API의 자동 코퍼스 삭제도
새 생명주기와 충돌하지 않도록 계약을 이관한다.

- 실행 후보용 회상은 현재 활성 사전과 호환되는 용례만 반환한다.
- 검색 top-k 뒤 단순 제외로 유효한 후보가 사라지지 않도록 의존성 필터를 적용하거나 후보를 보충한다.
- 캐시 키에는 사전 세대를 넣는다. 판정 실패·알 수 없는 의존성은 자동 반사 실행 허가로 바꾸지 않는다.
- `fn`·저장 워크플로·중첩 문장의 정적 의존성을 파서 기반으로 추적한다.
- 동적 script 등 정적으로 확정할 수 없는 부분은 미확정으로 남기고 실제 호출 관문에서 검사한다.
- 같은 어휘라도 버전·파라미터 계약이 달라지면 옛 문장의 재사용을 다시 검증한다.
- 에피소드 등 과거 사실 조회는 계속 가능하다. 잠든 어휘를 쓰는 방법을 새로 참고시키는 고급 회상은 후속 개선이다.

앱·예약 작업은 삭제하지 않는다. 확정 의존성으로 영향 목록을 표시하고 의존성 미확정도
별도로 표시한다. 실행 시에는 같은 관문을 통과한다. 없는 어휘를 자동으로 복구하지 않는다.

## 8. 구현 순서와 단계별 완료 조건

### 1단계 — 분류와 생명주기 기반

필수 공급자·패키지/어휘 소유권·호출 진입점·상주 자원·의존성을 조사한다.
필수 선언과 라이브러리 원장을 만들고 기존 상태를 이관한다.
기존 설치 묶음은 사용 중, 미설치 보관 묶음은 잠듦으로 시작하며 실제 미준비 상태를 별도 표시한다.
초기 이관으로 사용 가능한 능력이 줄지 않아야 한다. 폴더를 대규모 이동하지 않고 경로를 원장에 등록한다.
완료 조건: 현 활성 사전과 이관 후 사전이 같고 필수 공급자 보호가 모든 관리 경로에 적용된다.

### 2단계 — 실제 깨우기·잠재우기

활성 뷰와 공통 호출 관문, 사전 세대, 의존성 판정, 캐시 갱신, 기억 보존을 구현한다.
기존 설치·제거·reload와 직접 도구 호출을 같은 규칙으로 연결한다.
완료 조건: 잠든 어휘가 참조·반사·검사·실행에 남지 않고 다시 켜면 재시작 없이 돌아온다.
코퍼스·설정 불변 및 전환 실패 복구를 검증한다.

### 3단계 — 파일 하나로 왕복

manifest 규격, 포장·검사·등록·내보내기·버전 교체를 구현한다.
깨끗한 별도 테스트 데이터 경로에서 같은 파일을 받아 준비 후 동일한 IBL 예제가 실행되는지 확인한다.
완료 조건: 파일 하나만으로 전달되고 개인 정보가 들어가지 않으며 실패한 가져오기가 기존 박스를 손상하지 않는다.

### 4단계 — 조종실 레고박스

기존 ToolboxDialog를 컴포넌트로 나눠 조종실에서 재사용한다.
카드·스위치·끌어놓기·파일 선택·내보내기·상태·영향 표시를 연결한다.
완료 조건: 사용자가 파일 구조·빌드·터미널을 몰라도 넣기→깨우기→사용→잠재우기→내보내기를 끝낸다.

### 5단계 — 상주 자원·회귀·효율 검증

일반 조회 묶음, 계정 연결 묶음, 형제 모듈이 있는 묶음, 상주 작업 묶음을 각각 검증한다.
현재 일처리의 대표 IBL 프로그램을 전환 전후로 비교한다.
전환 동안의 호출·재시작 후 상태 복원·실패 복구·별도 프로세스의 세대 동기화를 확인한다.
완료 조건: 아래 인수 기준을 모두 통과하고 시스템 문서와 파생물을 갱신한다.

## 9. 인수 기준과 측정

1. 외부 파일을 넣어도 즉시 실행되거나 자동 활성화되지 않는다.
2. 준비된 묶음의 스위치 전환에 수동 빌드·백엔드 재시작이 필요 없다.
3. 잠든 묶음은 AI의 활성 카탈로그·반사 후보·직접/간접 도구 호출에서 제외된다.
4. 필수어휘는 UI·HTTP·IBL·삭제 어느 경로에서도 잠들거나 제거되지 않는다.
5. 전환 전후 코퍼스 행·벡터·설정이 보존되고 호환되는 어휘를 깨우면 용례가 다시 후보가 된다.
6. 종속 묶음·앱·예약 작업·진행 중 작업의 상태를 거짓 성공이나 묵시적 재활성화 없이 처리한다.
7. 중복·충돌·손상·의존성 실패·캐시 실패·프로세스 중단 시 이전 정상 상태로 복구한다.
8. 내보내기→별도 환경 가져오기에서 어휘 계약과 실행 예제가 보존된다.
9. 기존 설치 구성에서 대표 IBL 프로그램의 결과와 인지 경로가 유지된다.
10. 활성 카탈로그 크기/실제 모델 입력, 실행 후보 수, 유휴 CPU·메모리·상주 작업 수,
    준비된 묶음의 전환 지연을 전후 비교한다. 어휘 감소를 추정 비용 절감률로 과장하지 않는다.

검증은 임시 데이터 경로와 대체 핸들러를 우선 사용한다. 실제 사용자의 예약 작업을 끄거나
외부 쓰기를 일으키는 식으로 검증하지 않는다. 실행 차단·코퍼스 보존·실패 복구·파일 왕복에
회귀 테스트를 두며 변경 규모에 맞게 `.venv/bin/python3 -m pytest backend/ -q`,
frontend에서 `npx tsc -p tsconfig.app.json`, 루트에서 `python3 scripts/build_ibl_nodes.py --check`,
층 검사 및 은퇴 계약 검사를 수행한다. backend 변경 시 폰 번들 매니페스트도 재생성한다.

구현 완료 시 `data/system_docs/ibl.md`, `packages.md`, `anatomy.md` 및 관련 가이드에
실제 계약을 반영한다. 문서 마커·어휘 파생물은 빌더로만 갱신한다.
정본 main에서 단계별 pathspec 커밋하고 실제 확인한 커밋만 보고한다.
