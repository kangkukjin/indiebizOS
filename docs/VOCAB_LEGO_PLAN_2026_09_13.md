## 1. 목표와 네 가지 인수 원칙

기존 일처리를 유지한다. AI는 사용 가능한 어휘로 IBL 문장을 만들고 기존 문법·인지
파이프라인·실행기로 처리한다. 사용자는 묶음을 파일 하나로 주고받고 레고박스에서 고른다.

**잠재우기는 다음 네 문장으로 정의한다.**

1. **소개하지 않는다.** 활성 카탈로그와 AI의 도구 안내에서 제외한다.
2. **회상하지 않는다.** 실행용 참고 용례와 자동 반사 후보에서 제외한다.
3. **실행하지 않는다.** IBL과 직접 도구 호출의 실제 호출 관문에서 차단한다.
4. **보존한다.** 묶음 파일·설정·코퍼스 행·벡터·과거 기록을 그대로 둔다.

회상 제외는 실행용 회상을 뜻한다. 과거 사실·에피소드 조회를 막거나 기억을 재작성하지 않는다.
이미 외부에서 진행 중인 호출을 취소한다는 뜻도 아니다. 전환 완료 이후의 새 호출부터 차단한다.
필수어휘는 항상 유지하며 사용자어휘의 활성 선택은 사람이 한다. AI는 변경을 제안할 수 있다.

## 2. 확정한 1판 범위와 제외 범위

1판의 다섯 항목:

1. 필수어휘 선언 단일화와 모든 관리 경로의 보호.
2. 보유·활성 분리, **생명주기 함수 하나**, 기억을 보존하는 스위치.
3. 활성 상태를 카탈로그·실행용 회상·두 층의 호출 관문에 적용.
4. 용례를 동봉한 `.iblpack` 가져오기·내보내기와 옛 공유 형식 전환.
5. 조종실의 묶음 목록·스위치·파일 가져오기·내보내기.

선택 단위는 패키지에 대응하는 묶음이다. 한 묶음에 낱말 하나 또는 여러 개를 담는다.
새 IBL 노드·액션은 만들지 않고 기존 `self:package` 계약을 확장한다.

2판 이후로 미룬다:

- 상주 자원의 정지·재개, 메모리 언로드, 형제 모듈·버전별 격리.
- 진행 중 호출의 완료를 기다리는 전환 프로토콜, 모든 캐시의 세대화, MCP 세대 동기화 체계.
- 의존성 그래프 해결기, 버전 조합 탐색, fn·workflow 내부의 전수 정적 의존성 추적.
- 폴더 통합·폐지, 몸 사이 박스/활성 상태 동기화, 마켓플레이스·자동 업데이트.
- 낱말별 스위치, 프리셋, 앱·예약 작업 영향 분석 화면, 새 삭제 UX, OS 파일 연결.

1판은 호출형 묶음의 선택을 완성한다. 상주형 묶음에도 새 액션 호출 차단은 적용하지만,
이미 떠 있는 프로세스·스레드의 정지와 자원 회수는 보장하지 않는다. 상주형 수와 실제
패키지 간 의존을 조사해 기록하되, 해소 공학을 1판 완료 조건으로 확대하지 않는다.

## 3. 필수 선언 한 곳

현재 UI `STANDARD_PACKAGES`, 에디션 `_PROTECTED`, 코어 src `always_on`은 역할과
집합이 다르다. `core_manifest.json`은 git 추적 배포 출처이며 필수 집합으로 대용하지 않는다.

첫 구현 커밋에서 필수 노드·액션과 이를 제공하는 묶음을 대조하고, 필수 공급자의
선언을 데이터 한 곳으로 통일한다. UI·에디션 스크립트·관리 API는 그 선언을 소비한다.
`always_on`과 표준 헌법의 정합성을 검사하며 별도 하드코딩 목록을 남기지 않는다.
필수/선택 기능이 섞인 묶음은 보수적으로 보호하고 그 근거를 기록한다.
표준의 의미를 바꾸는 조정은 `ibl.md`와 빌드의 표준 가드를 함께 갱신한다.
외부 묶음의 자기 선언으로 필수 보호 규칙을 바꿀 수는 없다.

완료 조건: UI뿐 아니라 HTTP·IBL·에디션·기존 삭제/제거 경로도 필수 공급자를 보호한다.
기존에 동작하던 필수 기능을 빠뜨리지 않는다.

## 4. 사전집은 보유 전체, 활성 사전은 로드 시 결정

**사전집(yaml)은 전체, 활성 여부는 로드 시 prune한다.** 기존 몸별 필터에 사용자 활성
축을 더한다. API 레지스트리에서 합쳐지는 액션과 코어 src의 패키지 소유 액션도 같은
소유권 판정을 거치게 하여 fragment 바깥에서 잠든 어휘가 다시 들어오지 않게 한다.

- 보유: 기존 `installed`와 `not_installed` 양쪽에 있는 묶음의 합집합.
- 빌드: 양쪽 fragment를 합쳐 `ibl_nodes.yaml`을 만든다.
- 도구 인덱스·파생 `tool.json`·핸들러 AST 삼각 검증도 동일한 보유 전체를 대상으로 한다.
- 액션/도구 → 제공 묶음 → 실제 경로의 매핑을 공통으로 사용한다.
- 런타임: 필수 보호와 몸별 실행 가능 조건을 유지하면서 잠든 사용자 묶음을 제외한다.
- `tool_loader`도 양쪽 보관 경로를 해석한다. 깨어 있는 묶음을 옛 폴더 위치 때문에 못 찾지 않아야 한다.

보유 정본을 중복시키지 않는다. 1판에는 별도 보유 목록 DB를 추가하지 않는다.
폴더 스캔이 보유를 결정하고, 사전집·소유권 인덱스는 그 파생물이다.
**몸별 로컬 활성 원장만 새로 둔다.** 제안 경로는 `data/vocabulary/activation.json`이며
묶음 ID별 선택을 저장한다. 기존 몸 식별 규약을 사용하고 PC와 폰의 선택을 동기화하지 않는다.

최초 이관에서 installed는 활성, not_installed는 잠듦으로 기록한다. 이후 폴더명은
활성 의미를 갖지 않는다. 원장이 활성 선택의 유일한 정본이다. 새로 발견되거나 가져온
사용자 묶음은 기본적으로 잠듦이며 필수어휘는 항상 유지한다. 설정 손상은 명시적으로
알리고 전체 사용자 묶음을 자동으로 켜는 식으로 복구하지 않는다.

스위치는 폴더를 옮기지 않고 원장과 런타임 캐시만 바꾼다. 빌드·파생물 쓰기는 없다.
새 파일 가져오기·정의 변경은 보유 집합 변경이므로 사전집/인덱스 갱신이 필요하다.
그 작업은 가져오기 절차가 자동으로 수행한다. **빌드 없는 스위치와 새 묶음 등록을 구분한다.**
등록 시 기존 빌더를 재사용하며 별도 의미론의 런타임 컴파일러를 만들지 않는다.

휴면 폴더에 은퇴·불완전·충돌 정의가 있으면 두 번째 커밋에서 드러내고 정리한다.
삼각 검증을 약화하거나 조용히 덮어쓰지 않는다. 보유 묶음으로 인정할 수 없는 옛 자료는
명시적 상태/진단으로 남기며 자동 삭제하지 않는다. 폰 배포의 물리적 축소 규칙은 유지한다.
'전체'는 그 몸/배포가 보유한 전체이며 폰에 PC 전용 구현을 강제로 넣는 뜻이 아니다.

## 5. 생명주기 함수 하나와 두 층의 실행 관문

HTTP 설치·제거, `self:package`, 조종실 스위치는 **공통 생명주기 함수 하나**를 호출한다.
패키지 관리자의 검증·상태 변경·코퍼스 보존·캐시 갱신을 이 함수가 소유한다.
조종실에서만 맞고 기존 HTTP 버튼에서는 어휘가 남는 별도 경로를 없앤다.
기존 install/remove 이름은 깨우기/잠재우기 의미의 호환 진입점으로 정리하고 문서·도움말을 갱신한다.
신규 파일의 등록은 별도 가져오기 동작이다. 기존 완전 삭제 경로도 필수 보호와 기억 보존을 지킨다.

전환은 다음 순서로 수행한다.

1. 사람의 변경 권한, 필수 보호, 묶음 존재·준비 상태, 선언된 직접 의존성을 검사한다.
2. 변경을 직렬화하고 활성 원장을 원자적으로 저장한다.
3. 기존 캐시 무효화 한 벌을 호출해 카탈로그·레지스트리·실행 매핑을 갱신한다.
4. 회상 캐시에는 활성 구성 revision을 반영하고 전환 완료 후 성공을 반환한다.
5. 실패하면 이전 원장/정상 구성을 복구한다. 갱신에 실패한 상태를 성공이라고 말하지 않는다.

전환 중의 새 호출은 짧게 보류하거나 재시도를 반환해 낡은 선택으로 시작하지 않게 한다.
이미 실행 중인 외부 동작은 기다리거나 취소하지 않는다. UI가 기존 동작까지 정지한 듯 표시하지 않는다.
전체 캐시 키에 세대를 전파하거나 프로세스 간 세대 동기화 체계를 새로 만들지 않는다.
MCP를 포함한 외부 진입도 기존 공통 실행 경로를 이용하는지 확인하고, 독립 실행 우회가
발견되면 최소한의 공통 관문 연결로 닫는다. 새로운 분산 캐시 설계로 범위를 넓히지 않는다.

호출 차단은 두 층에 둔다.

- **IBL 층:** 실제 액션 실행 직전에 활성 상태를 확인한다.
- **직접 도구 층:** 시스템 AI의 직접 호출 및 `tool_loader`의 핸들러 로드/캐시 재사용 경로에서도 확인한다.

두 층은 동일한 상태 조회를 사용한다. `pruned_reason` 계열에 '잠듦'을 추가해
존재하지 않음·다른 몸 전용·잠듦을 구분한다. 직접 도구는 공통 소유권 매핑으로 이 판정에 도달한다.
핸들러가 이미 캐시돼 있어도 차단을 건너뛰지 않는다.

오류는 묶음 ID와 잠든 이유를 돌려주며 AI는 '이 낱말은 잠들어 있습니다. 사용하려면
조종실에서 깨워 주세요'처럼 안내할 수 있다. 사람의 선택 없이 AI가 활성 변경을 실행하지 못하도록
기존 HTTP/IBL 진입점의 실제 요청 신원·권한을 확인한다. 프롬프트 문구만으로 제한하지 않는다.

manifest의 의존성은 선언된 직접 대상의 존재·준비·명시된 버전 조건만 검사한다.
의존 묶음을 자동으로 깨우지 않는다. 활성 묶음이 명시적으로 요구하는 공급자를 잠재우려 하면
이유를 알리고 사용자가 선택을 정리하게 한다. 그래프 해결기나 코드에서 의존성 추론은 만들지 않는다.

## 6. 회상과 동봉 용례

실행용 회상 필터는 활성 원장을 반영한 사전을 사용한다. RAG 주입·자동 반사·상시 관용구
소개 등 실제 소비처를 확인한다. 잠든 액션이 직접 들어 있는 용례는 제외한다.
검색 top-k를 가져온 뒤 제외해서 적합한 후보가 비지 않도록 필요한 만큼 후보를 보충한다.
판정 실패를 자동 반사 실행 허가로 바꾸지 않는다.

fn·workflow 내부를 전수 정적으로 추적하지 않는다. 현재 확인 가능한 의존성으로 후보를
거르고, 간접 호출 속 액션도 실제 호출 직전 두 층의 관문에서 막는다. 의존성이 불명인
과거 문장을 현재 실행 가능한 것으로 보증하지 않는다. 이 제한은 테스트에 명시한다.

파일에는 제작자가 배포용으로 선정한 **시딩 용례**를 반드시 담는다. 단순 README 예제가 아니다.
용례 구조는 기존 `add_examples_batch` 계약에 맞추고 의도·IBL 코드·필요 메타데이터를 포함한다.
등록 시 형식·현재 언어 문법·보유 어휘 계약을 검증하고 동일 경로로 중복 없이 시딩한다.
잠든 묶음도 박스에 들어왔으므로 시딩할 수 있다. 이때 보유 적합성 검사와 활성 회상 검사를
구분한다. 활성 필터 때문에 등록이 거절되거나 시딩을 위해 묶음을 몰래 켜지 않는다.

원문·벡터를 삭제하거나 재임베딩하는 잠재우기는 금지한다. 다시 깨우면 호환되는 용례가
후보로 돌아온다. 이름이 같아도 계약이 바뀐 옛 문장은 기존 문장 검사와 호출 검증을 거친다.
개인 에피소드·키·코퍼스를 내보내기에 자동 포함하지 않는다.

## 7. 파일 계약과 기존 공유 형식의 후계

`.iblpack`은 ZIP 컨테이너로 정한다.

```text
manifest.json          형식 버전, 묶음 ID·버전, 설명, 호환 조건, 직접 의존성, 파일 목록·지문
ibl_actions.yaml       기존 어휘 fragment
handler.py             실행 진입점
examples.json          add_examples_batch로 시딩할 배포 용례
...                    선언된 형제 모듈·정적 자원·설명
```

`tool.json`은 기존 빌더로 파생·대조하며 독립 정본으로 만들지 않는다.
중첩 디렉터리와 필요한 정적 자원을 전달할 수 있어야 한다. 개발자 PC의 절대 경로에 기대지 않는다.
가져오기 중 핸들러를 import하거나 AI가 README에 따라 구현 코드를 고치지 않는다.
경로 탈출·허용 밖 링크·과도한 압축 해제·손상·이름 충돌을 검사한다. 지문은 무결성 검사다.
같은 ID/버전/내용은 중복 처리하고 다른 내용은 조용히 덮어쓰지 않는다. 자동 버전 해결과
활성 코드의 무재시작 업그레이드는 1판에 넣지 않고 충돌/교체 필요 상태를 명확히 표시한다.

가져오기 절차:

1. 임시 공간에서 파일·어휘·용례·호환성을 검사한다.
2. 새 묶음을 기존 보관 경로에 잠든 상태로 등록한다. 원장이 활성 여부를 결정한다.
3. 보유 사전집·도구 인덱스 갱신과 검증, 용례 시딩을 완료한다.
4. 실패 시 중간 등록을 성공으로 노출하지 않는다. 기존 사전과 코퍼스를 손상하지 않도록
   해당 가져오기의 파일·파생물·시딩 변경을 복구한다.
5. 사용자는 준비 상태를 확인하고 스위치로 깨운다. 외부 라이브러리·계정 준비는 기존 절차를 따른다.

정상적으로 보유/준비된 묶음의 스위치에 빌드나 재시작은 없다. 새 모듈 배포·형제 모듈
교체의 기존 재시작 제약은 유지한다. 재시작이 필요한 변경을 일반 스위치의 완료 조건에 묶지 않는다.

기존 `encode_package`/`decode_package` 텍스트 v1의 **생성·직접 설치 경로를 은퇴**시킨다.
옛 파일과 Nostr 게시물은 `.iblpack`으로 변환한 뒤 같은 가져오기 절차를 이용한다.
필수 정보/용례가 부족하면 보완 필요로 표시하며 불완전한 변환물을 몰래 실행하지 않는다.
새 내보내기와 기존 Nostr 공유는 `.iblpack` 계약 하나를 사용한다. Nostr의 크기/전송 제약은
확인해 동일 파일의 첨부·참조 방식으로 연결하고 텍스트 v1 생성으로 되돌아가지 않는다.
은퇴 계약·문서·오류/도움말·테스트도 함께 갱신한다. 실제 게시·전송은 사용자 작업이다.

## 8. 구현 커밋 순서

### 커밋 1 — 필수 선언 단일화

§3의 단일 선언, UI·에디션·관리 경로 소비, 표준 정합 검사와 보호 테스트.
이 커밋에서 필수 집합의 실제 목록·혼합 묶음의 판정을 기록한다.

### 커밋 2 — 사전집 = 보유 전체

두 폴더 fragment·도구 인덱스·삼각 검증의 범위를 보유 전체로 넓힌다.
휴면 정의의 충돌/노후화를 해결하고 보유 액션의 공급자·경로를 동일하게 해석한다.
**이 커밋만 적용해도 기존 잠든 어휘가 노출되지 않아야 한다.** 따라서 최소한의 로드 필터와
초기 활성 이관을 함께 넣는다. 기존 폴더 상태로 최초 원장을 만들고 그 뒤에는 원장만 따른다.
필수 포함 기존 활성 사전이 전후 동일함을 검증한다. 폴더 이동은 없다.

### 커밋 3 — 생명주기 하나와 빌드 없는 스위치

HTTP·IBL·조종실이 호출할 공통 함수를 완성한다. 원장 갱신·기억 보존·기존 캐시 무효화·
회상 revision·두 층 차단·잠듦 오류를 연결한다. 직접/간접 호출과 캐시된 핸들러까지 검증한다.
완료 조건: 네 인수 원칙이 모두 성립하고 세 관리 경로의 결과가 같다.

### 커밋 4 — 용례를 포함한 파일 왕복과 옛 형식 은퇴

§7의 `.iblpack` 포장·검사·가져오기·자동 사전집 갱신, §6의 용례 시딩을 구현한다.
기존 텍스트 생성/직접 설치를 변환 경로로 정리하고 Nostr 소비처도 같은 계약으로 연결한다.
완료 조건: 별도 테스트 환경에서 파일 하나로 받아 깨우면 동봉 예제가 실행되고,
잠재우면 차단되며 다시 깨워도 파일·설정·용례가 보존된다.

### 커밋 5 — 조종실과 최종 인수

기존 ToolboxDialog를 재사용해 필수/사용 중/잠듦 표시와 스위치, 파일 가져오기·내보내기를 제공한다.
파일 선택을 기본으로 하고 같은 가져오기 함수에 끌어놓기를 연결한다.
상태는 준비됨·연결/의존성 필요·오류를 정직하게 보여준다. 정적 의존성 영향 분석 화면은 만들지 않는다.
대표 기존 작업 회귀, 인수 시나리오, 모델 입력/카탈로그와 전환 지연 측정을 마친다.

위는 논리적 커밋 순서다. 커밋이 지나치게 커지면 각 단계 안에서 쪼개되,
보유 전체 노출이나 직접 호출 우회가 남은 상태를 완성품으로 보고하지 않는다.

층·은퇴 계약 검사를 수행한다. backend 변경 시 폰 번들 매니페스트를 재생성한다.
