# 웹앱 제작·수정 관용구

웹앱 수정 때 반복하던 문서·설정 조회와 프로젝트 검사 실행을 두 관용구로 묶었다.
새 IBL 어휘 없이 edition 2 함수와 등록 스크립트 `웹앱작업`을 조합한다.
등록은 해마에 보존하며 `always_on=0`이다. 에이전트는
`data/guides/webapp.md`에서 이름·입력·반환 계약을 읽고 호출한다.

## 소스와 재등록

- `data/idioms/webapp_prepare.ibl`: `웹앱작업준비(프로젝트)`.
  프로젝트 문서 앞 120줄, package 설정, 검사 목록, 런타임 경로, Git 상태.
- `data/idioms/webapp_check.ibl`: `웹앱검사하기(프로젝트, 검사=["test","build"], 시한=120)`.
  선언된 검사를 순서대로 실행하고 통과 여부·종료 코드·로그 근거를 반환.
- `data/scripts/webapp_work.py`: 파일·프로세스 어댑터. 직접 AI를 호출하지 않는다.
- `data/idioms/webapp_seeds.json`: 함수 정의와 호출 용례, 총 4개 등록 입력.
  테스트로 `.ibl` 정의와 일치하는지 검사한다.

```sh
.venv/bin/python scripts/register_webapp_idioms.py
.venv/bin/python scripts/register_webapp_idioms.py --apply --local-encoder
```

첫 명령은 검증만 한다. 두 번째는 실행 중인 로컬 백엔드의 임베딩을 사용한다.
백엔드가 없으면 `--local-encoder`를 빼고 로컬 모델을 로드한다.
적용 전에 SQLite backup API로 `data/_backups/`에 백업하며,
`add_examples_batch`로만 등록한다. 동일 입력 재적용은 중복 행을 만들지 않는다.
다른 본문의 동명 함수는 자동 덮어쓰지 않는다. 의미 검색 색인과 상시 노출 해제도 검증한다.

## 계약과 범위

기본으로 package.json의 test/build를 사용한다. 별도 스택은 프로젝트의
`webapp-checks.json`에 검사 이름과 argv를 선언한다. 누락된 검사나 실행 파일은
실행 전 오류다. 실행된 검사의 실패·시간 초과는 `value.ok=false`다.
IBL 실행의 `success=true`만으로 검사를 통과했다고 판단하지 않는다.
검사마다 최대 600초이며, 전체 로그 경로와 최대 8KB의 출력 꼬리를 반환한다.
명령의 종료 코드가 판정 기준이므로 검사 명령 자체의 실효성은 프로젝트가 책임진다.
설치·배포·브라우저 확인은 자동 추가하지 않는다.

## 검증 기록

- 전용 회귀 8개: 문서 수집, 명령 발견, 누락 검사 거부, 실제 성공·실패 종료 코드,
  설정 변경 거부, 시간 초과, 셸 치환 방지, IBL 실제 조합과 seed 일치.
- 문서 드리프트·테스트 실행 진입점 검사와 전용 회귀를 합쳐 29개 통과.
  전체 회귀 첫 실행은 91% 이후 중단해 발견한 두 실패를 분리 확인했다.
  스크립트 Git 추적 전 상태와 새 테스트의 직접 실행 진입점 누락을 보완했다.
  중단 지점보다 앞선 `test_s*`부터 뒤쪽 81개 파일을 다시 실행해 971개 통과.
  전체 회귀를 한 번에 끝낸 결과는 아니며, 앞선 실행과 보완 후 분할 재검증 기록이다.
- `build_ibl_nodes.py --check` 통과. Git 추적 집합에 새 스크립트를 포함하고
  `core_manifest.json`을 빌드해 설치본에서도 어댑터를 제공한다.
- 라이브 등록: 함수 4862·4863과 호출 용례 2개, 의미 검색 색인 4개,
  `always_on=0`. 재등록 `inserted=0` 확인.
- `webapp.md`·`웹앱 수정`·`웹앱 제작` 가이드 검색에서 두 호출법을 확인했고,
  상시 `idioms_map`에는 두 이름이 없음을 확인했다.
- 라이브 `[fn:]` 실행: KOSPI 보드에서 준비 조회, Node 테스트 3개,
  Wrangler 빌드 dry-run 통과. 배포하지 않았다.
- 별도 임시 프로젝트: 성공 검사와 종료 코드 7 실패 검사를 함께 실행하여
  `ok=false, failed=1` 확인. 미등록 검사 요청은 실행 전 오류 확인.
- 직접 HTTP 호출에는 실행 문맥의 `project_id`가 필요하다. 이를 누락한 초기
  시험은 실패했고 문맥을 전달한 재시험은 통과했다. 실패 이력은 보존했다.

이는 두 프로젝트의 기능 검증이다. 실제 에이전트 작업의 시간·토큰 절감은 아직
측정하지 않았으며, 이후 에피소드에서 가이드 발견·호출률과 결과 품질을 함께 본다.
