## 함께 드러난 구현 문제와 수정

1. 개별 YAML 문서 캐시는 32개였다. 파일 수가 이를 넘자 동일한 지도라도 매 요청
   재해석하는 현상이 발생했다. 원문 바이트로 문서 묶음을 캐시하여 이를 고쳤다.
   같은 크기·수정 시각의 편집과 원복도 계속 감지한다.
2. 글자 검색은 모든 문구에 정규식을 적용했다. 공백을 뺀 문구조차 질문에 없으면
   정규식이 일치할 수 없으므로 먼저 생략한다. 조사·띄어쓰기·영어 경계 규칙은 유지했다.
3. 항목의 의미 벡터에 경로 앞 두 단만 들어가던 것을 전체 경로로 고쳤다. 세부 주제가
   이름만 표시되는 데 그치지 않고 검색 문맥에도 들어간다.

browse는 전체 트리를 따라 내려간다. 자동 회상의 가지 선택은 여전히 앞 두 단을
사용하며, 전체 항목 벡터의 비교와 글자 검색도 수행한다. 재귀적인 로그 시간 트리
검색으로 구현되어 있다는 뜻은 아니다. 심층기억의 공통 회상 엔진은 수정하지 않았다.

## 만 개의 처리 비용

같은 맥에서 실제 로컬 인코더(`jhgan/ko-sroberta-multitask`)와 공통 주입 흐름
`begin → route('THINK')`를 사용했다. 응답 생성 모델 호출은 0회다. 실제 카탈로그에
고유 표제·별칭을 붙인 합성 항목을 추가한 별도 진단 폴더로 만 개 부하를 만들었다.
실제 카탈로그에 가짜 항목을 넣지는 않았다.

전체 비용이다. 모델의 답변 생성 시간이나 심층기억 검색 시간은 포함하지 않는다.

독립적인 만 개 개념의 구별 난도·선택 정확도·완성도를 입증하지 않는다.

## 선택 품질은 별도 문제

모든 진단은 같은 편집자가 작성하거나 읽은 질문이다. 눈가림 평가가 아니며 모델의
실제 조사 행동·판단·답변 품질은 평가하지 않았다. 비교에는 같은 수정 후 검색 코드와
주입 예산을 사용하고 자료만 1,428개 기준판과 3,116개 판으로 바꿨다.

| 개발 질문 묶음 | 기준판 | 확장판 |
|---|---:|---:|
| 기존 고정 28문항 | 24/28 | 24/28 |
| 추가 일상 질문 28문항 | 8/28 | 15/28 |

기존 묶음의 총 적중 수는 같지만 항목별 선택은 달라졌다. 미분 표적 대신 가속도가 나온 사례가 있다.
처음 비교의 25→24는 기준판 FTS 색인이 없는 상태였다. 양쪽에 FTS를 빌드하여 조건을
맞춘 최종 수치는 24→24이며, 위 표는 이 결과다.
인플레이션 질문의 실질임금, 도시 정책 비교의 합성통제법처럼 유용한 다른 개념도 있다.
전자 얽힘 질문에 전압·앨리어싱이 나오는 오선택은 여전히 남았다.

추가 묶음에서는 등재 공백 4건(진사회성, 자가면역, 감각기억, 점화/프라이밍)을 발견했다.
표적을 임의로 가까운 항목으로 바꾸어 성공 처리하지 않았다. 등재되어도 최소공배수·
백래시·피로 파괴 등을 일상 표현에서 놓쳤다. ACID·2단계 커밋처럼 질문에 적절하지만
엄격한 표적 집합 밖인 결과도 있다. 결과를 보고 문구를 추가해 점수를 올리지 않았다.

따라서 3천 개에서 1만 개로 가는 다음 편집은 하위 골격의 빈 기본 대상과 실제 검색
누락을 함께 보아야 한다. 분야마다 균등한 개수를 강제하거나 항목 수를 목표 점수로
삼지 않는다. 새 세부 주제를 선행 선언하고, 작은 묶음으로 작성·중복 검토·별칭 점검을
반복한다. 독립 질문으로 선택을 검증하고, 지도를 제공한 실제 과제의 결과도 별도로
비교해야 한다. 단어 수 증가가 선택 품질 증가를 보장하지는 않는다.
