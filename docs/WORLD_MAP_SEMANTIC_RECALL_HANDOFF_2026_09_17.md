# 세계 지도의 블로그식 회상 — 의미 검색 채널과 주입 설계

작성: 2026-09-17. 상태: **설계(미집행)**. 선행 계약: [구조 구현 계약](WORLD_MAP_STRUCTURE_PLAN_2026_09_17.md).
이 문서는 그 계약의 §2("이번에는 임베딩을 만들지 않는다")·§4(검색)·§5("질문 중 모델 적재 없음")를 개정한다.
집행 시 그 세 곳과 `data/knowledge_catalog/README.md`의 "현재 선택기는 로컬 어휘 검색" 문단을 함께 고친다.

## 1. 왜 — 다리의 약한 고리는 카탈로그가 아니라 선택기다

세계 지도는 지식 본문이 아니라 **지식으로 가는 이름**의 카탈로그다(도서관과 카탈로그의 구별).
이름이 AI의 기억을 불러내려면, 사용자의 명령에서 그 이름까지 가는 길이 먼저 있어야 한다.
사용자는 "간호사 야간 근무를 공평하게 짜줘"라고 말하고, 지식은 `제약 충족`·`OR-Tools`라는 이름에 묶여 있다.
그 사이를 건너는 것이 선택기의 일이다.

현재 선택기(`knowledge_catalog.search`)는 이름·별칭·뜻의 **글자 일치**다. 편집 분류(`path`)는
순위에 최대 0.5점만 보탠다. 트리는 데이터에 있지만(27분야·146가지, `browse`로 열람 가능) 자동 회상에는 쓰이지 않는다.

네 기억(블로그·심층메모리·실행기억·세계 지도)은 "트리 구조의 기억에서 관련된 것을 꺼낸다"는 같은 구상에서
출발했으나 구현이 갈렸다. 이 설계는 그중 블로그의 방식을 따른다(2026-09-17 사용자 판정):

- 트리는 AI에게 **보여주는 것**이 아니라 검색이 **쓰는 것**이다 — 분류 경로를 임베딩 텍스트에 싣고 필터로 쓴다.
- 질문→항목의 대응은 의미 검색이 한다. 글자 일치는 이름을 직접 말한 경우의 빠른 길로 남는다.
- 블로그에 없는 부분(자동 주입과 그 관련성 관문)은 이 문서가 새로 정한다(§4).

## 2. 실측 (2026-09-17, 집행 전 타당성 실험)

1,265항목 전체를 임베딩하고 상위 8건 안에 표적이 드는지를 셌다. 질문 세 묶음:
**새 질문 24**(이 실험을 위해 새로 쓴 일상 표현, 카탈로그의 별칭을 보지 않고 작성, 부록 A) ·
**검증 48**(기존 `audit_cases.json`+`atlas_audit_cases.json`의 validation 분할) ·
**무관 24**(인사·짧은 명령·기존 negative 분할).

| 선택기 | 새 질문 도달 | 검증 도달 | 무관 질문에 후보를 냄 |
|---|---|---|---|
| 글자 일치(현재) | **2/24** (17건은 0건 반환) | 31/48 | **0/24** |
| 임베딩 `ko-sroberta`(블로그와 같은 기본 모델), 경로 제외 | 19/24 | 44/48 | 항상 8건 |
| 같은 모델, **경로 포함** | **20/24** | **45/48** | 항상 8건 |
| 해마 모델(`data/models/ibl_embedding`), 경로 포함 | 13/24 | 34/48 | 항상 8건 |

읽을 것 다섯 가지.

1. **글자 일치는 정밀하지만 다리가 아니다.** 무관 질문에 0건(정직)이나, 별칭을 맞춰 두지 않은 새 표현에는 2/24.
   검증 31/48도 별칭을 그 질문들에 맞춰 편집한 뒤의 수치다(README가 경고한 "별칭 추가로 통과"의 한계).
2. **기본 임베딩 모델이 그 간격을 건넌다**(20/24). 남은 4건은 부록 A에 표시 — 사전 보강의 재료다.
3. **해마 모델은 쓰지 않는다.** 질문→IBL 문장으로 미세조정되어 세계 어휘 공간에서는 기본 모델보다 나쁘다(13/24).
   백엔드에 이미 떠 있다는 이점이 있지만 재학습 때마다 공간이 바뀌는 문제까지 겹친다.
4. **지금의 트리는 검색에 거의 보태지 못한다**(+1/+1). 표적이 속한 가지가 상위 8건의 최다 가지인 경우가 10/24.
   블로그 폴더는 주인의 분류 판단이지만 세계 지도의 `path`는 AI 초안이고, 146가지 중 절반 이상이 1~2항목 단독 가지다.
   블로그식의 이득은 트리 정비(§6) 뒤에 온다 — 코드만 바꿔서는 오지 않는다.
5. **관련성 관문은 점수로 세울 수 없다.** 최고 점수가 새 질문 중앙 0.55(최소 0.42), 무관 질문 중앙 0.33이지만
   **최대 0.64** — "음악 틀어줘→청음"(0.64)·"방금 만든 파일 열어줘→Syncthing"(0.58)·"커밋해→2단계 커밋"(0.51).
   문턱 0.50이면 양성 72건 중 54건만 남고 무관 24건 중 5건이 여전히 통과한다.
   **가지 집중도 가설도 기각**: 상위 8건이 한 가지에 몰리는 정도가 양성 중앙 3.5, 무관 3.0 — 가르지 못한다.

통과하는 무관 질문에는 공통점이 있다. 전부 **몸의 어휘로 곧장 실행되는 짧은 명령**이다. §4가 이 사실을 쓴다.

## 3. 설계 — 두 채널

| | 글자 채널(현행 유지) | 의미 채널(신설) |
|---|---|---|
| 성질 | 고정밀·저재현 — 이름·별칭을 실제로 말했을 때 | 고재현·저정밀 — 표현이 달라도 닿음 |
| 구현 | `knowledge_catalog.search` 그대로 | 항목 벡터 × 질의 벡터 코사인, 상위 k |
| 결과 지위 | seed — 현행대로 관계 2홉 확장(`world_context.assemble`) | **후보** — 관계 확장 없음, 분류 가지별로 묶은 이름 |
| 실패 시 | — | 모델 미적재·색인 낡음이면 조용히 빠짐(글자 채널만) |

### 3.1 항목 텍스트 (블로그 `prepare_search_text`와 같은 꼴)

`잎 분류명 ×2 + 전체 경로 + 이름 ×2 + 별칭들 + 뜻(hint) + scope_note`.
실험에 쓴 조합이다. 반복 횟수는 상수로 두고 `evaluate_world_map.py --semantic`의 도달률로만 바꾼다.
관계 이웃의 이름을 텍스트에 섞는 것은 하지 않는다 — 관계는 글자 채널의 seed 확장이 맡는다.

### 3.2 색인 — 빌드 산출물

- `scripts/build_knowledge_catalog.py`가 항목 벡터를 만들어 기존 색인 DB 옆에 둔다(1,265×768 float32 ≈ 3.9MB).
  규모가 작아 `sqlite-vec` 없이 numpy 내적으로 충분하다 — 새 의존성 없음.
- 색인 메타데이터에 **모델 이름·항목 텍스트 조립 규칙의 해시·snapshot revision**을 적는다.
  `--check`는 벡터 수=항목 수, 세 값의 일치를 본다. 어긋나면 의미 채널만 꺼지고(`semantic:"stale"`) 글자 채널은 산다.
- 벡터는 파생물이다. 손으로 고치지 않고 git에 넣지 않는다(빌드가 재생성, 폰 번들 제외 — §5).

### 3.3 인코더 — 질문 경로에서 적재하지 않는다

- 모델: `jhgan/ko-sroberta-multitask`(블로그 패키지와 동일, 몸에 이미 받아져 있음).
- 적재: 해마 모델과 같은 방식 — 부팅 후 **백그라운드 스레드**(`service_scope`)에서 한 번. 적재 전·실패 시 의미 채널은
  `unavailable`. 기존 계약의 "질문 중 모델 적재·색인 빌드 없음"은 이 형태로 보존된다.
- 위치: `backend/datastore/` 새 모듈(가칭 `catalog_vectors.py`) + `check_backend_layers.py`의 `LAYERS` 배정.
  코어는 패키지 코드를 import하지 않는다(층 규칙) — 블로그의 모델 객체를 빌려 쓰지 않는다.
- 비용(집행 시 실측할 것): 상주 메모리 약 +0.4GB, 질의 1건 인코딩 지연. 블로그 검색이 같은 모델을 따로 올리면
  두 벌이 된다 — 공용 인코더 홀더로 합치는 일은 이 설계의 범위 밖(후속 후보)으로 적어만 둔다.

## 4. 주입 — 관문은 의식이다

§2-5의 결론: 의미 채널은 "관련 없음"을 스스로 말하지 못한다. 그래서 **의미 후보는 판단할 자가 있는 턴에만 싣는다.**

| 턴 | 글자 채널 | 의미 채널 |
|---|---|---|
| THINK · REPAIR (의식이 돈다) | seed+관계 조각(현행) | **후보로 추가** |
| EXECUTE · CONTEXT_UPDATE · Reflex (의식 없음) | 현행 그대로 | **싣지 않음** |

- 근거: 무관한데 점수가 높은 질문은 전부 짧은 실행 명령이고, 그런 턴은 EXECUTE로 분류된다(분류기 실측 정확도 94%).
  의식이 도는 턴에는 이미 "의식은 그 단서의 관련성을 판단한다"는 계약이 있다 — 관문을 새로 짓지 않고 있는 판단자를 쓴다.
  코드로 된 의미 판정기를 두지 않는다는 원칙(AI가 할 일을 고정 프로그램으로 만들지 않는다)과도 맞는다.
- 표현: 기존 `<method_map>` 블록 안에 절을 나눈다. 글자 채널 조각은 현행 표현 그대로,
  의미 후보는 **"후보 — 관련 여부 미판정"** 표식 아래 `분류 경로: 이름, 이름` 꼴로 가지별 한 줄.
  뜻·출처는 싣지 않는다(현행 계약). 글자 채널이 이미 낸 항목은 후보에서 뺀다.
- 예산: 후보 최대 8, 기존 상한(1,800토큰·6,000자) 안. 후보 절은 관계 조각보다 먼저 잘린다.
- 실행자에게 가는 길: 의식이 고른 이름만 실행자에 닿는다. ★09-07 교훈(의식 출력이 실행자에 닿지 않던 5개월) —
  집행 때 표식을 심어 **실제 조립된 실행자 프롬프트에서** 찾는 라우팅 관문을 같이 넣는다.
- 사건 기록: 현행 event에 `semantic_ids`·`semantic_top_score`·`semantic` 상태(`used/unavailable/stale/skipped_no_consciousness`)를 더한다.

**이 설계가 증명하지 못한 것**: 의식이 잡음 후보를 실제로 버리는가, 후보가 방법 선택을 낫게 하는가.
§2는 검색 도달만 쟀다. 이것은 모델 출력 비교 실험(§7-4)의 몫이며, 그 전에는 "품질이 나아졌다"고 쓰지 않는다.

## 5. AI가 직접 부르는 길 · 폰

- `세계지도` 스크립트의 `search`에 선택 인자 `path`(분류 필터 — 전체 경로·상위 분야 모두)와 `mode`(`hybrid` 기본/`lexical`/`semantic`)를
  더한다. 블로그 `category`·`mode`와 같은 꼴. 융합은 블로그와 같은 역순위 융합(RRF). **새 IBL 어휘·op는 없다** — 등록 스크립트의 인자다.
- 자동 주입과 직접 호출이 같은 검색 함수를 쓴다(두 구현이 갈라지지 않게).
- 폰-자아: torch가 없고 `/ibl/embed`는 해마 공간의 벡터를 준다 — 세계 지도에는 못 쓴다.
  1단계에서 폰은 글자 채널만(현행과 동일, 퇴행 없음). 맥의 기본 인코더를 빌려 주는 길(`/ibl/embed`에 공간 선택)은 후속.

## 6. 트리 정비 — 데이터 작업, 코드와 분리

블로그식의 몫은 트리 품질에서 나온다(§2-4). 집행 순서상 코드보다 **먼저** 해도 되고 독립이다.

- 1~2항목 단독 가지를 상위 가지로 합친다(예: `공학/메시 분석`→`공학/기계와 제작`). 옛 도구 지도에서 온 항목이 대부분이다.
- 같은 뜻의 가지 이름 통일(예: `개발/검증`·`개발/설계와 검증`·`개발/브라우저 검증`).
- 관문을 먼저 쓴다: `--check`에 "가지당 최소 항목 수" 경고와 "모든 항목이 browse로 도달" 검사(후자는 현행).
  손으로 고른 범위는 샌다 — 목록은 관문이 뽑는다.
- ID는 바꾸지 않는다(관계·근거가 ID에 걸려 있다). `path`만 고친다.
- 효과 판정: 정비 전후로 §2의 "경로 포함−경로 제외" 차이와 "표적 가지=최다 가지"(현재 10/24)를 다시 잰다.

## 7. 검증

1. **검색 도달**(결정적, 모델 호출 0): `evaluate_world_map.py --semantic` — 부록 A의 새 질문을 `audit_cases.json`에
   `split:"fresh"`로 편입해 글자/의미/융합의 상위 8 도달을 보고한다. 회귀 기준: 의미 채널 새 질문 ≥ 20/24, 검증 ≥ 45/48.
   ★새 질문에 맞춰 별칭을 고친 뒤에는 그 질문이 더는 '새' 질문이 아니다 — 고칠 때마다 새 묶음을 추가로 쓴다.
2. **정직한 0건 보존**: 의식 없는 턴에서 무관 24건의 주입이 현행과 같이 0인가.
3. **기계 계약**: 색인 stale→의미 채널만 꺼짐 · 모델 미적재→글자 채널만 · 예산 절단 순서 · 글자·의미 중복 제거 ·
   실행자 프롬프트 라우팅 표식 · 취소 전파(기존 preparation 경계).
4. **효용**(모델 호출, 별도 실험): 같은 모델·질문·권한에서 지도 없음 / 글자만 / 글자+의미 후보를 비교.
   지표는 구조 계약 §6과 같다(수단 적합성·존재하는 도구 인지·불필요한 개입·제약 보존·완료 품질·총 비용).
   추가로 **잡음 후보를 의식이 버린 비율**. 표본은 A=B 오판을 피할 만큼(N=6 금지).
5. **지연**: 질의 인코딩+내적의 p50/p95를 사건 기록으로. 의식 지연(중앙 45초)에 비해 무시할 수준인지 확인만 한다.

## 8. 하지 않는 것

- 지도(트리 목차)의 매 턴 주입 — 1,265항목·계속 확장이라 지도는 목차도 크고, 질문마다 필요한 조각은 좁다.
- 점수 문턱·가지 집중도로 만든 코드 관련성 판정기(§2-5에서 기각).
- 추가 LLM 호출로 후보를 거르는 단계 — 의식이 이미 그 자리에 있다.
- 해마 모델 재사용, 사용 빈도로 어휘 끄기, 새 IBL 어휘.
