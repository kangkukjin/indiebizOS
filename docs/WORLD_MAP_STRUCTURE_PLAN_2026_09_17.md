# 세계의 지도 — 지식으로 가는 카탈로그의 구조와 탐색

개정: 2026-09-17. 정본: `data/system_docs/vision.md`의 세계 지도 절.
사용자 정정에 따라 구현 목적·범위를 아래 계약으로 개정했다. 최초 설계는 git 이력에 보존한다.

## 1. 목적과 판정 기준

세계의 지도는 이 순간의 세계를 포착한 구조적 어휘 모음이며 AI의 지식과 검색으로 가는 카탈로그다.
도서관의 장서 본문을 옮기는 대신 분야·개념·방법·도구·자료원의 이름과 짧은 구별·연결을 기록한다.
AI가 그 어휘와 접촉하여 전문지식을 회상하거나 검색하고, 해당 분야에서 통용되는 수단을
알고 작업하도록 돕는다. 세계의 명사는 데이터에, 검색·관계 조회 문법은 코드에 둔다.

- 이미 적절한 접근은 유지한다. 관점 전환·뜻밖의 대안·새로움을 의무로 삼지 않는다.
- 도구를 몰라 불필요한 재구현을 하는 경우, 존재하는 수단과 기능의 관계를 보여준다.
- 직접 구현을 통한 학습·연구, 도구 금지 등 명시 제약은 존중한다. 검색 결과는 실행 명령이 아니다.
- 설치·가격·권한·현재 API는 사용 시 별도 확인한다. 확인일 있는 지식과 실시간 사실을 구분한다.
- 자동 문맥 예산은 전달량만 제한한다. 전체 어휘는 조회 가능하며 빈도로 어휘를 끄지 않는다.

대표 대비: ‘Blender로 집을 렌더링’과 ‘집을 그리기 위해 렌더러 전체를 직접 개발’은
같은 세계 어휘와 접촉한다. 전자는 자연스럽게 이어가고, 후자는 기존 도구가 있다는 사실을
알고 판단할 수 있어야 한다. ‘렌더러 원리 학습을 위해 직접 개발’의 목적은 바꾸지 않는다.

## 2. 이번 구현의 범위

`world.yaml`을 version 2의 entries+fragments로 확장한다. 기존 ID·별칭·힌트·분류 path·
source.path·source.section은 보존한다. v1도 계속 읽는다. 초기 관계 데이터는
`data/knowledge_catalog/structure.yaml`로 분리한다. 분야 확장은 `bridges.yaml`,
그 연결과 근거는 `bridge_relations.yaml`에 둔다. 전 분야의 관계 완성을 주장하지 않는다.

모든 기존 어휘는 전체 분류 경로와 뜻을 전달한다. 출처는 내부 검증과 전체 조회에 보존한다. 검토한 가지는 독립 문제·방법·조건
노드와 관계까지 전달한다. 처음 연결한 사례는 건축/대화형 3D, 직원 일정, 여러 파일 조회다.
종류를 아직 판정하지 않은 기존 항목은 term으로 보존하며 임의로 tool/method로 분류하지 않는다.

이번에는 임베딩, 추가 분류 모델, 자동 조건 추론, 세계 전체의 존재론, 강제 재프레이밍을 만들지 않는다.
사용자는 구조적 어휘를 원했고, 자세한 지식과 상황 판단은 소비자 AI가 회상·검색해 수행한다.

## 3. 데이터 계약

- Entry: id, kind, path, name, hint, aliases, source(path/section), scope_note(선택).
- kind: term/concept/problem/method/tool/resource/criterion/condition.
- Edge: id, subject, predicate, object, rationale, evidence_ids, status, condition(선택).
- Evidence: id, path, locator, claim, checked_at, url, content_hash.
- Snapshot: revision, entries, graph(edges/evidence), files. 정본 조각·검색 정책·근거 문서 해시가 revision에 반영된다.

path는 기존 편집 분류 경로다. 인접 문자열을 broader로 자동 변환하지 않는다.
명시 broader는 같은 kind의 개념·문제·방법 일반화이며 직접 간선만 저장한다.
관계는 broader, related, implements, addresses, requires, applicable_when,
unsuitable_when, alternative_to, complements, uses_source, evaluated_by를 지원한다.
도구→implements→방법→addresses→문제의 방향은 저장과 출력에서 유지한다.
조회는 양방향이며, 대칭 관계의 역간선을 손으로 중복 입력하지 않는다.
대안·보완은 범위 condition이 있어야 하고, 형제 개념을 자동으로 대안으로 추론하지 않는다.

ID 중복·미해소 참조·종류/방향 불일치·계층 순환·계층과 related 충돌·근거 누락을 거부한다.
상태는 proposed/verified/disputed/retired다. verified는 근거 대조이며 영구 진실이 아니다.
검토한 로컬 근거의 바이트가 달라지면 해당 verified 관계는 stale이 되고 자동 확장에서 제외한다.
색인 재생성도 재검토 전 거부한다. 외부 웹은 질문 경로에서 재수집하지 않으며 확인일 이후
변경 가능성이 있다. 관계 수정은 원문 대조→근거 문서·해시·확인일 갱신→검사→커밋 순서다.

## 4. 검색과 구조 전달

1. 전체 어휘의 이름·별칭·힌트·scope_note를 검색한다. path는 순위의 보조 단서다.
   어휘 일치가 없고 질의 전체가 정확한 분류명이면 그 분류의 어휘를 반환한다(category_exact).
   일반 문장에 분야 단어가 포함됐다는 이유만으로 후보를 채우지 않는다.
   어휘 매칭이 후보 문턱을, FTS가 동점 정렬을 소유한다. 낡은 색인은 어휘 검색으로 폴백한다.
2. 현재 질문을 우선한다. 짧은 지시어 후속 질문이 0건일 때만 과거 사용자 질문을 보조 질의로 쓴다.
   부정문·조건의 뜻을 키워드로 확정하지 않는다. 현재 발화는 소비자에게 그대로 전달된다.
3. seed에서 관계를 양방향 2홉 조회한다. 문제→방법→도구에 도달할 수 있다.
   related/대안/보완은 seed의 직접 관계만. 조건을 거쳐 무관한 다른 방법으로 번지지 않는다.
4. 경계에 있는 방법의 필수 입력·적합/부적합 조건·평가기준도 동봉한다. 조상은 최대 3단 덧붙인다.
   조건은 현재 충족 여부 unknown으로 전달한다. 명시 제약을 바꾸거나 자동 승인을 만들지 않는다.
5. 최대 seed 4, 노드 16, 관계 20으로 묶고, 필수 조건을 담을 수 없으면 seed 묶음 전체를 생략한다.
   추출 조각의 팽창 방지 상한은 UTF-8 바이트/2 추정 1800토큰·6000문자다.
   전체 지도의 크기 제한이나 에이전트별 사용 예산이 아니며 모델 토큰 실측도 아니다.
6. WorldContext의 revision/digest를 가진 같은 조각을 기존 execution_memory 삽입점에서
   의식과 실행에 한 번 전달한다. system prompt의 영구 prefix에 넣지 않는다.

문맥 정책은 관련 어휘로 회상·검색하되 적절한 접근을 돕고, 전환·대안을 강제하지 않는다고 명시한다.
정본 데이터 문자열은 escape하여 world_data 영역에 넣는다. 이름·뜻·핵심 관계를 렌더한다. 일반 관계의 긴 설명·출처 경로·확인일은 반복 주입하지 않는다.
필수 조건의 뜻·현재 미확인 표지는 보존한다. 상세 근거는 내부 WorldContext와 open에 유지한다.
문맥 선택에는 사용 빈도나 ‘얼마나 낯선가’ 점수를 넣지 않는다.

## 5. 전체 열람과 실패 상태

등록 스크립트 세계지도(`world_map_lookup.py`)를 기존 self:script로 호출한다.
args: op(search/browse/open/neighbors/ancestors), query, id, path, offset, limit, revision.
browse의 path는 최대 5단계 분류명 배열이다. 빈 배열은 최상위 분야를 연다.
바로 아래 category와 현재 경로의 entry를 반환하며 category에는 하위 전체 entry_count와
revision을 고정한 browse 인자가 있다. 경로·페이지를 바꾸어도 같은 snapshot을 유지한다.
분류를 일반화 관계로 승격하지 않으며 어휘의 본문은 open으로 따로 읽는다.
search에서 query 생략은 전체 목록이다. neighbors는 직접 관계의 원래 방향과 상태를 보존한다.
ancestors는 검증된 직접 broader를 따라 깊이와 경유 경로를 제공한다.
반환: items, status, revision, truncated, omitted, next, browse(최상위 탐색 인자). 후속 페이지는 revision을 고정한다.
잘못된 ID는 not_found, 검색 0건은 no_match, 다음 페이지 존재는 partial, 변경된 snapshot은
stale_revision, 잘못된 인자/로더 오류는 error다. 자동 생략은 접근 권한 철회가 아니다.
기존 self:script 실행 권한과 개인 기억의 접근 경계는 유지한다. 세계 어휘 주입은 주체·에이전트·역할로 제한하지 않는다.

자동 모드는 names/structure 두 가지이고 기본값은 structure·켜짐이다. 설정 파일이 없어도 동작한다.
모든 작업 에이전트가 같은 인지 경로를 사용하며 Reflex·강제 역할·문맥 갱신에도 주입한다.
과거 enabled_agents 필드는 무시하고 사건의 ignored_config에 표시한다. 전체 진단용 enabled=false는 유지한다.
모델 호출 없는 세션 제어만 제외한다. 필요 시 names로 전환 가능하다. 잘못된 데이터는 error로 기록하며 검증을 우회하지 않는다.
취소는 기존 preparation 경계로 전파한다. 질문 중 모델 적재·색인 빌드·웹 호출은 없다.

## 6. 코드와 검증 순서

| 단계 | 구현 위치 | 검증 |
|---|---|---|
| 정본/무손실 이행 | knowledge_catalog.py, world.yaml, structure.yaml | v1 호환, 기존 필드 보존, 조각/근거 변경 revision |
| 관계 | datastore/knowledge_graph.py | 종류·참조·순환·역관계·출처 검증, 양방향 도달 |
| 문맥 | cognition/world_context.py, catalog_recall.py | 완전한 묶음, 예산/escape/생략, unknown, 동일 주입 |
| 조회 | world_map_lookup.py, registry.yaml | 실제 stdin 실행, 전체 페이지, ID·상태·revision |
| 근거/가이드 | G_structure_evidence.md, world_map.md, anatomy.md | 실제 구현 계약·열람 한계 |
| 비교 | scripts/evaluate_world_map.py, 검증 fixture | 도구명 없는 질문·알맞은 기존 선택·학습·무관 질의 |

검증은 네 층을 구분한다.
1. 검색: 허용 가능한 어휘에 도달하는가. 없으면 정직한 0건인가.
2. 구조: 문제→방법→도구와 근거가 이어지고 조건이 잘리지 않는가.
3. 소비자: 의식·실행이 같은 묶음을 받고 기존 좋은 선택을 방해하지 않는가.
4. 효용: 지도 없음 / 이름·설명 / 구조를 동일 모델·질문·권한·입력 자료에서 비교한다.

결정적 테스트는 1–3의 기계 계약을 검증한다. 소비자가 실제로 불필요한 재구현을 피하고
좋은 선택을 유지하는지, 직접 구현 학습 목표를 보존하는지는 모델 출력의 별도 비교 실험 대상이다.
평가지표는 수단 적합성·존재하는 도구 인지·불필요한 개입/전환·제약 보존·완료 품질·총 비용이다.
대안 수·관점 전환 횟수·새로움 자체는 성공 지표로 쓰지 않는다.
추가 모델 호출을 실행하지 않은 테스트 결과를 답변 품질 개선의 증거로 부르지 않는다.

## 7. 완료와 운영

관련 단위/통합 테스트, backend 전체 회귀, 카탈로그 build/--check, 층·파일 크기·모듈
충돌·은퇴 계약·IBL 문서 파생 관문을 수행한다. backend 변경의 폰 번들을 재생성한다.
frontend 변경은 없다. 실행하지 못한 검사·실제 모델 품질 미측정은 결과에 명시한다.
본인 파일만 정본 main에 커밋한다. 다른 세션의 미커밋 파일은 포함하지 않는다.

관계 없는 어휘도 전체 경로·출처로 쓸 수 있다. 미등재/잘못된 관계는 해당 데이터와
근거를 수정하여 확장한다. 모든 분야의 관계가 채워져야 사용할 수 있는 거대 온톨로지를 만들지 않는다.

## 8. 카탈로그로서의 확장 기준

- 분야의 편중을 줄인다. 인문·사회·경제·환경·건강 연구근거·언어·공간의 대표 입구를 추가한다.
- 한 항목은 통용 이름·짧은 뜻·분류·탐색 표현을 기본으로 한다. 조건·절차를 의무적으로 늘리지 않는다.
- related는 뜻의 비교와 인접 지식을 찾아가는 참조다. 같은 수단·의무적 대안·필수 순서로 해석하지 않는다.
- 전체 목록의 모든 어휘가 이름 없는 browse 경로로 도달 가능한지 자동 검증한다.
- 기존 검색 고정 질문과 별도의 새 분야 질문을 함께 검사한다. 새 사례는 개발 회귀이며 독립 품질 검증이 아니다.
- 검색·분류 탐색·출처 연결이 있어도 모든 지식에 도달함을 주장하지 않는다. 자유로운 바꿔 말하기는 여전히 검색 공백이 될 수 있다.
