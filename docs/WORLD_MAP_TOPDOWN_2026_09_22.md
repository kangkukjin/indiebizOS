# 세계의 지도: 분야 골격부터 확장한 첫 적용

2026-09-22. 정본 main의 기존 지도에 적용. 특정 인물 조사에 관한 대화는 확장의 계기이며,
분류의 기준으로 삼지 않았다. 조사뿐 아니라 이해·창작·학습·수리·감상·생활을 포괄한다.

## 편집 원칙과 구현

1. `data/knowledge_catalog/outline.yaml`에 전체 분야의 범위와 하위 가지를 먼저 선언했다.
2. 기존 1,279개 항목을 배치했다. ID·이름·힌트·별칭·출처·종류와 검토된 의미 관계는 유지했다.
3. 빈 가지와 기본 원리의 공백을 채웠다. 추가된 149개는 `foundation/*.yaml`에 있으며 기존
   항목과 같은 검색에 참여한다. 총 1,428개, 14개 큰 영역, 86개 가지다.
4. `branches.yaml`의 검색 요약·일상 표현·함께 볼 가지를 새 경로에 맞췄다. 주된 위치는
   하나이며, 여러 분야에서 찾을 필요는 가지 연결로 다룬다. 의미 관계와는 구별한다.
5. 빌드 검사에 골격 대조를 연결했다. 항목에서 목차를 역산하여 빈 영역을 숨기지 못하게
   골격 밖 항목·비어 있는 계획 가지·중복 선언·사전 불일치를 검사한다.

트리는 편집 분류이며 유일한 세계 분류가 아니다. 가지를 채우며 경계를 재검토할 수 있다.
같은 개념은 중복 추가하지 않는다. 예를 들어 패턴 제작은 기존 항목을 재사용했다.
도구는 그것이 쓰이는 분야에 놓는다. 자연과학·공학·생활의 기본 개념을 보강하면서 기존의
전문 도구·분석 기법을 보존했으므로 분야별 수량은 다르다. 이 첫 적용이 모든 가지의
깊이까지 같게 만들었다는 뜻은 아니다.

편집 근거는 [별도 원천](world_map/L_topdown_editorial_2026_09_22.md)에 명시했다.
새 기본 개념은 모델 일반 지식의 편집 초안이며 개별 외부 문헌 검증 완료로 표시하지 않는다.
새로운 절차 매뉴얼·IBL 액션·분야별 고정 결론은 추가하지 않았다.

인구·이동에 분산했다. 인물·기업·대학을 조사할 때도 해당 분야와 공통 탐구 개념을 통해
접근하며 특정 사건의 결론을 지도가 미리 정하지 않는다.

## 검색과 프롬프트

검색 엔진·인코더·선택 예산·주입 렌더러는 변경하지 않았다. 가지는 첫 두 경로 단위로
고르고 의미 채널은 기본 안 2건+밖 1건, 글자 채널은 기존 구조 조립 상한을 유지한다.
이름·분류·검토된 연결만 전달하며 새 outline 전체나 검색용 힌트는 프롬프트에 넣지 않는다.

현재 검색은 항목 전체의 벡터 점수도 계산한다. 트리라는 이유로 O(log N) 검색이라고
설명할 수 없다. 1만 항목으로의 확장은 실제 자료의 중복·품질 검토와 별도 성능 측정이
필요하다. 이번에 확인한 것은 실제 1,428개에서의 동작이다.

## 검증과 한계

- 분류 골격과 실제 항목·가지 사전: 일치, 빈 가지와 1~2항목 가지 없음.
- 기존 1,279개 ID와 이름·힌트·별칭·출처·종류 보존 검사: 통과.
- 기존 글자 검색·구조 주입 개발 회귀: 16/16.
- 관련 회귀: 148개 통과. 신규 기본 개념도 이름 검색과 주입 도달 검사의 대상에 포함했다.
- 전체 backend 회귀: 통과(종료 코드 0, 기존 의존성 경고만 있음).
- 선언만 있고 채우지 않은 시험 가지를 주입하면 골격 검사가 거부함을 확인했다.
- 폰 번들 자료 목록은 정본에서 재생성했다.

실 인코더 진단은 14개 분야에 2문항씩 총 28개다. 분야별 한 문항은 새로운 기본 개념,
다른 하나는 기존 개념을 목표로 했다. 같은 편집자가 작성했고 별칭 작성 뒤 만든 개발
진단이므로 눈가림 시험이나 일반화의 증거가 아니다. 응답 모델 호출은 0회다.

| 항목 | 기존 1,279개 | 적용 후 1,428개 |
|---|---:|---:|
| 미리 정한 허용 개념 포함(두 주입 채널의 합집합) | 13/28 | 24/28 |
| 새 기본 개념을 묻는 문항 | 1/14 | 13/14 |
| 기존 개념을 묻는 문항 | 12/14 | 11/14 |
| 예열 후 조회 지연 중앙값(해당 맥, 해당 실행) | 41.01 ms | 46.38 ms |
| 두 주입 블록의 최대 합계 문자 수 | 750 | 702 |

지연에는 질문 임베딩과 검색·렌더링이 포함되고 최초 인코더 적재·색인 빌드는 분리했다.
서로 다른 시점의 단일 실행이므로 미세한 속도 차이를 개선이라고 해석하지 않는다.
표적 포함은 다른 후보의 관련성이나 최종 답변의 품질을 보장하지 않는다.

미포함 4건도 기록한다.

- 양자얽힘 질문: 물리·전자 분야는 찾지만 앨리어싱·오차 전파가 선택됨. 기존에도 미포함.
- 구매력 질문: 새 인플레이션 항목이 있어도 재무·미시경제 가지로 가고 운전자본·소비자잉여가 선택됨.
- 악기 배합 질문: 기존의 음색이 빠지고 화성이 선택됨. 목표 개념 포함 기준으로는 회귀 1건.
- 도시 정책 비교: 차분의 차분 대신 합성통제법이 선택됨. 합성통제법도 관련된 접근이지만
  사전에 고정한 표적 집합에는 없어 미포함으로 유지했다. 이를 무관한 답이라고 단정하지 않는다.

일부 일상 문장에서 글자 채널이 일반적인 힌트 낱말 두 개만으로 무관한 후보를 고르는
기존 문제도 보였다. 수면 항상성이 구매력 질문에 섞이는 사례가 있다. 이 결과에 맞춘
별칭 덧붙이기로 점수를 끌어올리지 않았다. 검색 규칙의 개선은 별도 변경으로 검증해야 한다.

## 재현과 후속 확장

```bash
.venv/bin/python3 scripts/build_knowledge_catalog.py
.venv/bin/python3 scripts/build_knowledge_catalog.py --check
.venv/bin/python3 scripts/audit_world_map_coverage.py --output outputs/world_map/coverage.json
.venv/bin/python3 scripts/evaluate_world_map.py --output outputs/world_map/lexical.json
.venv/bin/python3 scripts/evaluate_world_map_recall.py --output outputs/world_map/recall.json
.venv/bin/python3 scripts/build_body_bundle.py android --check
.venv/bin/python3 -m pytest backend/ -q
```

실 인코더 진단은 `outputs/world_map/recall_index`에 파생 색인을 쓰며 심층기억 DB나
에피소드 DB를 바꾸지 않는다. 공통 연상 흐름의 세계 지도 공급원 둘을 통해 운영 선택·렌더러를 그대로 사용한다.
개인 기억 등 다른 공급원은 시험에서 제외하고 환경 경로·기본 설정·사건 기록은
오프라인 경계로 바꾼다. `--baseline-root`는 과거 카탈로그와
근거 파일로 만든 시험 자료 폴더를 받아 같은 질문·예산으로 비교한다. 저장소 복제본이 아니다.
이번 비교 원본은 `outputs/world_map/topdown_recall.json`, 분포는 `topdown_coverage.json`.
이 outputs 자료는 로컬 산출물이고 실행 도구·질문·요약은 git으로 보존한다.

다음 확장에서도 outline의 전체 영역을 먼저 훑고 얕은 가지를 한 차례씩 채운다.
임의 개수 달성을 위한 동의어 중복이나 특정 최근 사례 주변의 집중 추가는 피한다.
독립 질문 작성과 동일 응답 모델·동일 예산의 지도 없음/기존/확장 비교를 통해 실제
탐구와 답변의 변화를 확인하는 일은 아직 수행하지 않았다.
