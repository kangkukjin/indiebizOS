# 에피소드 5767 수리 구현·인수 기록

## 변경

| 영역 | 구현과 확인한 경계 |
| --- | --- |
| R0 증거 복구 | 평가 입력과 요청 검증이 동일한 원문 주소 투영을 사용한다. 요청은 absent/invalid/valid/normalized로 구분한다. 같은 턴의 유일한 내용 주소가 원문 판본과 일치할 때만 생략된 revision을 보충한다. 명시적으로 틀린 revision·다른 주소·잘못된 기준·구간은 보충하지 않는다. |
| R0 예산·재개 | 잘못된 요청은 기존 한정 실행자 보완으로 넘긴다. 보완 전 소모 횟수·snapshot을 저장하고 회수 후 packet도 저장한다. 직접 회수에는 실행자 문맥 비용을 예약하지 않는다. 회수한 구간이 평가 입력에 온전히 들어가지 않으면 모델 호출 전 실패한다. 의미 검수도 구조화된 동일 회수 경로를 사용하며 산문의 임의 지문을 전체 읽기 권한으로 쓰지 않는다. |
| R1 발견 | self:task 설명·op 소개·접수증 가이드가 위임 조향과 IBL 다음 경계 조향을 함께 설명한다. 기존 용례 15건은 status/wait/cancel 계약을 유지해 수정 없이 재검토했다. |
| R2 판본 | 기존 함수 소유 저장소·의미 인터페이스를 유지한다. 회상 투영을 반복해도 옛 근거의 evidence_revision이 새 판본으로 바뀌지 않는다. 현재 판본과 다른 적용 근거는 현재 적용 조건으로 소개하지 않는다. |
| R3 축적→사용 | 두 회상 채널이 함수 scope_id/function_id/revision을 넘긴다. 실제 function_result의 호출·실행 신원을 노출하고 제시→호출 시도→성공을 연결한다. 이름/본문 언급은 판본 사용 증거가 아니다. 인터페이스만으로 컴파일된 호출도 같은 신원을 남긴다. 카탈로그 세대 변경은 검색·표시 캐시를 모두 무효화한다. |
| R4 조향 | status 경계에 input_contract와 unresolved_until_boundary/expected_args_hash:null을 공개한다. 미래 인자는 실행하거나 비밀 값을 새로 공개하지 않는다. 기존 CAS/scope/순수 본문/효과 영수증·resume 계약을 사용한다. |
| R5 인수·비용 | 격리 저장소, Python/IBL 사전검사, 실제 모델 호출 제한, 원문과 사용량 보존, 읽기 전용 완료 원장 집계 스크립트를 추가했다. |

신규 언어 문법·액션·학습기·정의 소유 DB는 추가하지 않았다. 등록·계약 조회·함수 이력·
0/1회 통합 증류·부분 제어의 기존 소유 경로를 연결했다. 임의 Python 파일의 자동 추출·등록은 하지 않는다.

## 실제 모델 인수

선택된 운영 검수 모델 **CodexProvider / gpt-6-astra:high**를 사용했다. 각 판단은 새 history,
도구 없는 원샷 호출이며, 실제 모델의 선택을 운영 저장·검색·컴파일·실행·조향·검수 API로 수행했다.
두 실험의 12개 모델 호출에서 네이티브 도구 사용은 0건이다. 저장소·영수증·DB·증류 학습 파일은
`data/outputs/`의 실험 디렉터리에 격리했다. 실제 전송 효과는 실험 어댑터의 관측 목록으로 대체했다.

후속 문제에는 작성 세션의 대화·정답 부품명·본문을 제공하지 않았다. 운영
`search_aliased(alpha=0)`의 검색 결과와 `_describe`의 현재 계약을 제공했다.
따라서 **어휘 검색을 통한 발견·판본 재사용**을 검증했으며 임베딩 검색 품질이나 전체 자율 에이전트
경로의 벤치마크를 측정한 것은 아니다.

| 사례 | 실제 결과 |
| --- | --- |
| 최초 작성·등록 | 모델이 계측 보정 함수를 작성하고 기존 save 경로로 등록했다. `(18-3)*4 = 60`. |
| 독립 세션·새 입력 | 검색된 현재 부품을 실제 호출했다. `(31-7)*3 = 72`, 현재 판본의 호출 영수증과 회상 사용이 연결됨. |
| 새 조합 | 두 보정값 72·45와 별도 지역 변화율 함수를 조합해 3을 계산했다. 저장 부품 두 번의 실제 호출을 확인. |
| 축적 없는 비교군 | 별도의 빈 함수 저장소에서 같은 모델이 직접 계산해 72를 반환. 이 한 쌍으로 비용 우위를 주장하지 않음. |
| 자동 증류 | 기존 통합 선별기가 실행 원문을 검토하고 새 지속 가치가 낮다는 이유로 0건 선택. 강제 저장·자동 성장 주장 없음. |
| 실제 status 조향·재개 | 운영 가이드를 읽은 모델이 경계·판본·입력·본문을 선택. 배율 2→4 변경으로 20, 같은 실행의 resume도 20. 완료 전송은 `[41]` 한 번, 원래/재개 실행의 효과 좌표 동일. |
| 정상 증거 회수 | 실제 검수자가 원장의 마지막 구간을 요청. UNKNOWN → 원문 1회 회수 → APPROVED. |
| 모순 증거 회수 | 실제 검수자가 같은 방식으로 원문 회수. 270이라는 제출과 260인 원장이 충돌하여 UNKNOWN → REWORK. |

요약과 호출별 사용량·영수증 신원은 [results.json](results.json), 집계 코드는
[summarize.py](summarize.py)에 있다. 원본 결과의 경로와 SHA-256도 요약에 기록했다.
기대값은 모델 프롬프트에 넣지 않고 실행 결과와 독립 계산을 대조했다.

### 실패와 실험 장치 보완도 보존

- 첫 조향은 모델이 `definition`에 함수 선언 전체를 보내 운영 검증기가 거절했다. 이후 실제
  접수증 가이드의 본문 계약을 함께 제공했다. 예제의 값을 복사하지 못하도록 후속 배율은 4로 설정했다.
  완성된 좌표·요청 JSON을 시험이 만들어 주지 않았다. 모델이 선택한 기대 인자의 해시만 운영 digest로 계산했다.
- 첫 실험은 7회·101,797토큰에서 사전에 설정한 **호출 사이 100,000토큰 중단 기준**에 도달했다.
  한 호출이 기준을 넘길 수 있음을 manifest에 명시했다. 이후 평가를 호출하지 않고 UNKNOWN으로 보존했다.
  후속 실험은 미완료 조향·복구만 5회·79,976토큰으로 검증했다.
- 최초 조합 정답기는 숫자 `3`만 허용해 `{first:72,second:45,rate:3}`를 실패로 표시했다.
  사용자 과제는 결과 레코드를 금지하지 않았으므로 사후 감사는 세 필드를 모두 독립 정답과 대조했다.
  원본 실패 표시는 수정하지 않았고 요약에 원 판정과 감사 결과를 함께 남겼다.
- 원 보고서의 `type()` 누락을 재현하지 않도록 Python 기본 동작과 IBL 실행을 모델 호출 전에 확인했다.
  모델 생성 Python을 제한 builtins로 실행하는 별도 환경은 사용하지 않는다.

두 실험의 실제 대기 시간은 각각 153.47초와 53.88초, 관측 토큰 합계는 **181,773**이다.
호출의 지연 합을 병렬 작업의 실제 대기 시간으로 바꾸지 않았다. 캐시 읽기는 입력의 부분집합이며,
reasoning 토큰·금액·실제 사용자 수정량은 미측정이다.

새 입력 한 쌍에서는 재사용 판단이 16,006토큰·10.41초, 빈 저장소 직접 계산이
12,612토큰·19.02초였다. 재사용 쪽은 현재 계약을 읽는 입력이 더 컸으며, 최초 작성·등록의
12,657토큰도 별도로 필요했다. 캐시 읽기는 두 후속 호출 모두 8,448토큰이었다.
관측상 지연과 토큰 비용의 방향이 다르므로 일반적인 비용 절감을 결론내리지 않는다.

## 원 에피소드의 비용 재집계

[cost.py](cost.py)는 기존 `trajectory_event`의 run/parent_run/call/parent_call 신원을 연결하고,
`billable_usage`만 집계한다. 응답 관측·경계 기록은 청구에 다시 더하지 않는다.
같은 호출·round의 동일 사용량은 중복 제거하고, 충돌은 별도로 남긴다.

- #5767 연결 청구 기록: 7건, 입력 18,606,131 + 출력 81,373 = **18,687,504토큰**.
- 캐시 읽기 17,971,584는 위 입력에 포함된 수치다.
- 시작/종료가 있는 8개 호출 중 `plan_completion` 1건은 사용량이 없어 미측정이다.
- 별도 실험의 6개 원본 JSON에는 32개 사용량 항목과 관측 토큰 582,160이 있다. 1항목은 미계측이다.
  공통 호출 신원이 없으므로 주 실행과의 중복을 판정할 수 없고 위 합계에 더하지 않았다.
- 에피소드 실제 경과는 4,070.877초. 비용의 `complete:false`를 유지했다. 과거 호출을 재실행해
  비용을 추정하거나 누락을 0으로 처리하지 않았다.

재현:

```bash
.venv/bin/python3 docs/experiments/episode_5767_repair/cost.py \
  --episode 5767 --output data/outputs/episode5767_repair_cost.json \
  --research-artifacts data/outputs/research_plans/e9d7a6dd5ba1423a882639e269922c36
.venv/bin/python3 docs/experiments/episode_5767_repair/live.py \
  --output data/outputs/새로운_인수_디렉터리
```

실제 모델 인수는 유료/구독 호출을 실행한다. `manifest.json`의 호출·시간·입력 크기·관측 토큰
제한을 먼저 기록하며 상한에 도달한 사례는 미완료로 남긴다. `--cases steering recovery`처럼
판단 축별로 실행할 수 있다. 공급자별 출력 토큰 강제 한도 지원은 다르므로 상시 강제 토큰 예산으로 소개하지 않는다.

## 회귀·활성 상태

회귀는 요청 판본 누락·명시 오판본·Unicode 구간·혼합 오류·재요청 제한·복구 구간 잘림·
판본 변경·은퇴·이름만 언급·실패 호출·캐시 변경·기존 효과 조향/재개를 포함한다.
최종 전수(`.venv/bin/python3 -m pytest backend/ -n auto --dist loadfile --ff`, system 포함)는
**12,164 통과·24 건너뜀·실패 0·종료 코드 0**, 424.21초다. 회상 연결 관련 68개 검사도 통과했다.
최초 샌드박스 전수는 소켓/브라우저/하위 프로세스 권한 제한으로 실패해 통과 증거로 쓰지 않았다.
승인 환경의 첫 전수에서 남은 2건은 의미 검수 테스트의 옛 산문 지문 회수 계약과 새 회귀 파일의
직접 실행 진입점을 보완했다. 이후 검사 중 테스트 파일을 추가한 실행은 변경 감지 관문으로
종료 코드 1이었으며, 일반 용례에 빈 참조 필드를 추가한 호환 결함도 고쳤다. 마지막 전수는
코드와 테스트를 고정한 뒤 실행했다. 각 실행의 수치·로그 지문은 [regression.json](regression.json)에 남겼다.

IBL 빌드·`--check`, 용례 재검토 원장, backend 층 검사, Android 번들 재생성을 수행했다.
활성 제어자는 ACTIVE이고 `/health`는 healthy를 반환했다. 변경한 실행 파일 15개의 바이트를
활성 봉인 세대와 대조했다([activation.json](activation.json)). 진행 중 사용자 턴은 없었으며
별도 수동 표식을 조작하지 않았다.

텍스트 부분 관측·현재 지원 조향은 실제 모델로 확인했다. 음성 등 기존 매체 계약은 회귀 범위이며
이번 실제 모델 인수는 텍스트다. 지원 밖 이미지 영역 관측, 장기 성장률, 일반 비용 우위는 주장하지 않는다.
