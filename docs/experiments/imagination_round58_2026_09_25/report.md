## 갭 원장과 근본 수리

### B58-1 / B56-1 부류 확장 — 단항 flow 계약의 파이프 자리가 빠짐

최소 재현: `[{id:"a"}] >> [table:dedup]{by:"id"}`.
실제 잎 도구는 동일 입력을 처리하지만 현재 값 계약에는 수신 인자가 없어 컴파일 단계에서
`PIPE_COLLISION`으로 거절됐다. 이전 결합 도구 수리와 같은 부류여서 또 개별 사례를
고치는 대신 **flow 선언 전체를 전수 조사**했다.

19개 flow 중 each 문형 1개·기존 네이티브 5개·결합 3개는 이미 연결되어 있었다.
나머지 **reduce, judge, ai, brief, chunk, rename, flatten, dedup, since, groupby 10개**에
원천 YAML의 명시 입력 계약을 연결했다. 결과는 원래 Record를 유지하고 하류는 `.items`를
선택한다. 파이프와 명시 items 충돌도 그대로 거절한다. 도구 이름을 파서에 추가하지 않았다.
[전체 flow 대조](flow_census.json), [수리 대상](census.json).
빌드는 이제 단항 flow의 입력 자리 누락도 거부한다.

### B58-2 — 입력을 행 목록으로 해소하면서 원천 불완전 표시를 잃음

최소 재현: `{items:[{id:"a"}],truncated:true} >> [table:dedup]{by:"id"}`.
파이프 복구 후 이 문장이 `success:true, source_complete:true`를 반환했다.
기존 도구가 입력 봉투를 목록으로 정규화하면서 원천 표지를 떨어뜨리고, 현재 어댑터는
반환 봉투만 검사한 것이 원인이다. 각 핸들러에 수동 표지 복사를 반복하지 않았다.

명시 계약 `adapter.input_envelopes:[items]`가 지정한 입력 봉투의 실패·미처리·누락·절단
근거를 공통 어댑터가 결과와 함께 판단한다. 불완전하면 계산된 값을 partial로 제공하고
`PARTIAL_SOURCE`로 보고한다. 업무 행 안 error/truncated나 의도한 selection은 실패로
오인하지 않는다. 빌드도 단항 봉투의 근거 연결 선언 누락을 차단한다.

### B58-3 — 본문 분할의 빈값·잘못된 입력·생략을 구분하지 못함

전수 점검으로 연결한 chunk에서 추가 재현했다.

- 빈 목록을 정상 0건으로 받지 못했다. 빈 items 봉투는 안내 message를 본문으로 고를 수도 있었다.
- 본문 키가 없으면 정의되지 않은 `cands` 변수로 NameError가 발생해 실제 입력 오류를 가렸다.
- 일부 행에 본문이 없거나 비어 있으면 조용히 생략하고 완전 성공으로 표시했다.

입력 목록의 존재와 비어 있음을 구분하고, 잘못된 봉투는 실제 후보 키가 있는 오류를 낸다.
생략한 행은 `rows_dropped`, `skipped_rows`, 0부터 시작하는 `skipped_row_indices`로
남긴다. 현재 어댑터는 이를 부분 원천으로 처리한다. 정상 덩이·순서·원문 위치는 유지한다.
