## 갭 원장·근본 수리

### B59-1 — 펼칠 목록의 존재를 출력 행 수로 판단

최소 재현: `[{refs:[]}] >> [table:flatten]{field:"refs"}`.
출력 out이 비어 있다는 이유로 “목록 필드가 없다”고 거절했다. 입력 목록의 존재와
출력 기수를 혼동한 것이다. 유효한 입력 컬렉션의 수를 별도로 세어, 빈 목록과
잘못된 입력을 구분했다. 전부 잘못된 필드라면 기존의 명확한 오류를 유지한다.
빈 배열·빈 items 봉투·문자열로 직렬화된 빈 배열·혼합 입력을 회귀에 포함했다.

### B59-2 — 펼침 경계에서 생략과 중첩 원천 실패가 사라짐

최소 재현:
`[{refs:[{title:"A"}]},{refs:null}] >> [table:flatten]{field:"refs"}`와
`[{refs:{items:[{title:"A"}],truncated:true}}] >> [table:flatten]{field:"refs"}`.

생략은 `skipped_rows`라는 정보 키에만 있었고, 봉투를 items로 바꿀 때 원천의 상태를
버렸다. 생략 행은 공통 `rows_dropped`와 원래 0 기반 위치로 신고한다. 소비한 items
봉투의 표지를 공통 `markers_of`로 읽어 `row_honesty`에 부모 행·경로와 함께 보존한다.
부분 원천은 현재 실행 경계에서 부분값을 가진 실패로 보고한다.

자동 승격만 고치면 `field:"refs.items"`·`field:"items"`가 같은 근거를 우회한다.
경로 해석을 다시 구현하지 않고 정본 `walk_path`에 선택적 관찰 훅을 추가해, 실제 소비한
items 접근만 관측했다. 숫자 인덱스와 벡터 경로도 같은 해석기를 지난다. 업무 행의
error/truncated, 평문 Record, 무관한 형제 봉투는 원천 실패로 읽지 않는다.

### B59-3 — 공통 근거 수집기가 중첩 누락과 혼합 절단 범위를 놓침

후속 경계 대조에서 `row_honesty`·`branches_honesty`·`incomplete_steps` 아래
`rows_dropped`를 공통 완료 판정이 읽지 못했다. 또한 한 출처의 selection 표지가
하나라도 있으면 다른 출처의 범위 미상 truncated도 설명된 것으로 처리했다.

완료 근거의 공통 수집 대상에 rows_dropped를 추가했다. 절단 범위는 전체 봉투에서
한 번 결정하지 않고 각 경계의 하위 구조에서 판정한다. 그러므로 정상 표본과 잘린
다른 출처를 섞어도 unknown 근거가 남는다. 기존 selection·미리보기·중복 근거 처리는 유지한다.
