## 갭 원장과 근본 수리

### B60-1 — 미확정 누적값의 +를 숫자 연산으로 조기 확정

최소 재현: `$xs=[]; [repeat:3]{$xs=$xs+[$i]}; return $xs`.
컴파일러는 반복 중 값 모양이 바뀔 수 있어 누적값을 Unknown으로 넓힌다. 그런데 +의
목록·문자열 연결은 양쪽 타입이 이미 같은 경우만 허용하고 나머지는 숫자 연산으로 검사했다.
그래서 유효한 `Unknown + List`를 ARITHMETIC으로 거절하고 문자열 누적 결과를 Number로 잘못 추론했다.

공통 이항 연산 검사에서 미확정 피연산자의 +는 실행 시 검사로 남기고 결과도 Unknown으로
유지한다. 숫자·텍스트·목록이 아닌 확정 피연산자는 여전히 거절한다. 실행기의 공통 값 의미론은
그대로 사용한다. 반복뿐 아니라 reduce·람다·사용자 함수의 양쪽 인자에도 적용된다.
잘못된 동적 입력은 실행 시 NUMBER_REQUIRED로 실패하며 거짓 성공하지 않는다.

### B60-2 — while 조건에 현재 회차의 i를 공급하지 않음

독립 재현: `$n=0; [repeat:while $i<3]{$n=$n+1}; return $n`.
검수는 i가 있다고 판단하지만 실행기는 조건을 평가한 다음에야 i를 대입했다.
첫 반복은 UNBOUND, 중첩 반복은 바깥 i, 다음 반복은 이전 i를 읽는 같은 원인이다.

현재 회차 i를 조건 평가 전에 바인딩해 조건과 본문이 같은 번호를 보게 했다.
횟수 식은 기존처럼 바깥 환경에서 한 번만 평가하고, 정상 종료·실패 시 바깥 i 복원과
공유 예산·근거 연결을 유지했다. 검수에서도 횟수 식에 아직 없는 안쪽 i를 허용하지 않는다.

### B60-3 — 반복의 실제 평가 순서·최소 실행 횟수와 다른 변수 검사

최소 재현: `[repeat:until $x==2]{$x=$i}; return $x`,
`[repeat:1]{$winner={id:"a"}}; return $winner.id`.
검사기가 until을 while처럼 본문보다 먼저 검사했고, 반복 전에 있던 변수만 뒤로 넘겼다.
실행기가 이미 지원하는 본문 대입·같은 프레임 유지와 맞지 않아 정상 프로그램을 거절했다.

횟수 식→본문, while 조건→본문, until 본문→조건의 순서로 분석한다.
until·고정 양수 횟수는 반드시 한 번 실행되므로 본문의 모든 진행 경로에서 정의한 바인딩을
뒤에 전달한다. while·동적 횟수는 0회 경로와 교집합을 취하며, 조건부로만 만든 변수는 거절한다.
예약 변수·each 읽기 전용·finally 반환 금지·바깥 i는 그대로 보호한다.
