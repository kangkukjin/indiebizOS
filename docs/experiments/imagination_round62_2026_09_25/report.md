## 갭 원장과 근본 수리

### B62-1 — 내장 함수의 Callable 값 전달을 실행기가 처리하지 않음

최소 재현: `$f=abs; return $f(-7)`.
검수는 Callable로 인정하지만 실행기는 `builtin` IR을 값으로 평가하는 경로가 없어
`IR / protocol / 지원하지 않는 구문: builtin`으로 종료했다. 인자·기본값·컨테이너·누적기에서
동일하게 재현했다. 단순 호출 구문에만 내장 함수 실행을 하드코딩한 것이 원인이다.

내부 Callable 참조를 값으로 평가하고 직접 호출과 간접 호출을 공통 callback 경로로 연결했다.
`reduce`는 Binding과 공통 행 예산을, `evidence`는 실제 값의 출처 근거를 그대로 사용한다.
인자 수 검사는 공통 함수로 뽑아 동적 호출도 인자 접근 전에 거절한다.
도구 Callable 계약의 타입 관찰과 요청 지문에도 같은 값을 반영해 캡처된 내장 함수 때문에
후속 표 도구가 실패하지 않게 했다. Callable 자체의 JSON/외부 결과 전송 제한은 유지한다.

부류 전수는 `BUILTINS`의 **16종 전체**를 변수·인자·기본값·컨테이너의 4맥락에서 검사하며,
새 내장 함수가 추가되면 census 목록 누락 시험이 실패한다. 잘못된 인자 수·런타임 오류·
출처·도구 계약·요청 지문·예산·전송 경계를 함께 검사한다.
새 어휘나 호출 문법을 추가하지 않았으며 검사기가 인정하던 Callable 계약을 실행기에 맞췄다.

### B62-2 — 이름 토큰의 단일 목록을 명령 헤드로 오인

B62-1의 컨테이너 census에서 `[abs]`를 재현한 뒤 일반 값으로 격리했다.
`return [true]`, `return [false]`, `return [null]`도 전부 SYNTAX로 실패했다.
기존 파서는 `[이름]`을 무조건 명령으로 분류했고 Bool·Null 리터럴도 lexer에서는 이름 토큰이다.

콜론이 있는 명령 헤드와 이 자리의 유일한 무콜론 제어문 `[try]`만 명령으로 분류한다.
나머지는 기존 목록 표현식으로 파싱한다. 목록/객체 중첩과 기존 try·catch·finally·if·case·repeat·def
제어문을 함께 검사했다. 일반 이름 어휘를 엔진에 하드코딩하지 않는다.
[격리한 수리 전 4건](parser_before.json), [라이브 수리 후 4건](parser_after.json),
[추가 라이브 확인기](boundary_probe.py).
