## 갭 원장과 근본 수리

### B63-1 — 객체 행의 검증을 생략하고 필터링하여 거짓 성공

최소 재현:

```ibl
[{cost:10},"읽기 실패",{cost:20}] >> [table:reduce]{init:0,step:"acc + cost"}
[table:join]{left:{items:[{id:"a"},"오류"]},right:[{id:"a"}],on:"id"}
```

reduce는 객체만 추린 새 목록으로 합산했고, inner join은 객체 아닌 행을 `continue`로
제외했다. 결과만 보면 각각 30원·매칭 1건의 완전한 성공이었다. 입력을 정규화하는 단계에서
형식 검증과 행 선택을 혼동한 것이 공통 원인이다. 전부 잘못된 reduce 입력은 초기값 0을
성공으로 반환했다.

reduce는 누적 전에 모든 행을 검사하며, join은 모든 결합 모드가 같은 양쪽 입력 검사를
사용한다. 실패 시 원래 0 기반 인덱스(결합은 좌/우 출처)를 오류 문장과 구조 필드에 남긴다.
원본을 바꾸거나 부분 합계를 만들지 않는다. 빈 목록의 정상 초기값, 유효 행의 키 결측과
비매칭, 각 결합 모드의 행 선택 계약은 유지한다.

같은 부류 전수: reduce 5종 비객체 값×혼합/전량×목록/봉투/JSON, join 6모드×좌/우×봉투/JSON.
형제 filter/sort/select/compute/groupby/dedup의 거절과 rename/take/merge/union의 보존도 대조했다.
이 부류는 회차별 반복 채굴 대신 이 census 회귀가 지킨다. 강의·매물·비용 등 데이터 주제와
무관한 입력 검증 수리이며 새 어휘는 없다.

`success`와 `source_complete`는 별개다. 순수 join의 형식 오류는 원천 누락이 아니므로
source_complete=true일 수 있다. 실패 응답을 성공으로 세지 않는 것으로 판정한다.

### B63-2 — 고정 순서 목록을 원소 공통 타입 하나로 축약해 정상 접근 거절

최소 재현: `$r=({text:"본문"} & "2026-09-25"); return $r[0].text`.
실행 계약은 가지 순서의 목록인데 검사기는 이를 `List<Record|Text>` 하나로만 기억했다.
따라서 0번 가지의 Record에서 필드를 읽어도 Text에서 읽을 수 없다는 오류를 냈다.
목록 리터럴·명시 입력·연결에서도 같은 원인이 재현됐다.

기존 List 타입 내부에 선택적인 위치별 타입을 보존한다. 리터럴·병렬·입력 추론이 같은 생성
함수를 쓰고, 제어 분기 합류는 같은 길이의 각 위치를 합치며 목록 연결은 위치를 이어 붙인다.
함수 인자·반환·중첩 레코드도 기존 구조적 타입 전달을 따른다. 길이나 순서를 모르면 공통 원소
타입으로 돌아간다. 동적 인덱스·잘못된 위치의 필드·분기별 다른 형태는 기존 검사를 유지한다.
런타임 값·문법·wire 프로토콜을 추가하거나 바꾸지 않았다.
