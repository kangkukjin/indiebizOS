## 갭 원장과 근본 수리

### B64-1 — 콜백이 사용하지 않는 주변 변수까지 보관

최소 재현:

```ibl
$rules=[2] >> [table:each]{on_error:"collect"}{return ($r)=>$r*$it}
[{name:"가"}] >> [table:select]{columns:($r)=>{name:$r.name}}
```

두 번째 콜백은 rules를 읽지 않는데도 생성 시 전체 env를 복사했다. 호출 지문이 이 불필요한
값까지 펼치면서 수집된 함수의 인코딩 오류를 만났다. 독립 함수를 잇달아 만드는 경우에도
각 함수가 이전 함수들을 전부 붙잡아 불필요한 환경을 누적했다.

순수 식의 자유 변수 분석을 공통 표현식 모듈에 두고 실제 참조하는 변수만 생성 시점의
Binding으로 캡처한다. 중첩 람다의 외부 참조, 내부 인자의 이름 가림, 보간·레코드·인덱스·
reduce 안의 참조를 함께 처리한다. 원래의 생성 시점 값 보존과 실행 근거 연결은 유지한다.
참조하는 입력 변경은 요청 지문을 바꾸고, 무관한 입력 변경은 바꾸지 않는 것을 검사했다.

### B64-2 — 호출 지문 생성이 Result 안의 내부 함수를 재귀 처리하지 않음

최소 재현:

```ibl
$rules=[2] >> [table:each]{on_error:"collect"}{return ($acc,$score)=>$acc+$score*$it}
[{score:30}] >> [table:select]{columns:($r)=>{score:reduce([$r.score],0,unwrap($rules[0]))}}
```

이번에는 rules가 실제 의존이므로 B64-1만 고쳐서는 해결되지 않는다. 요청 지문 변환은
함수·레코드·목록을 처리했지만 ResultValue는 그대로 pack으로 넘겼다. 따라서 정상적인
내부 함수 재사용이 외부 전송 규약 위반으로 오인됐다.

요청 지문 전용 변환에서 ResultValue의 성공값과 오류값도 같은 재귀 변환을 거치게 했다.
내장 함수와 사용자 콜백, Record/List/Result 중첩, select/compute/filter 소비자를 검증했다.
실제 공개 wire의 pack은 바꾸지 않았다. 함수나 함수를 담은 Result의 외부 반환은 계속
VALUE_PROTOCOL로 거절하고, 실제 콜백 인자 수 오류는 CALLABLE로 보고한다.

두 결함은 함께 나타났지만 다른 책임이다. 불필요한 캡처를 없애고, 필요한 캡처를 올바르게
식별하는 두 경로를 각각 수리했다. 새 어휘·문법·업무별 분기는 없다. 같은 부류의 컨테이너와
소비자 조합은 이번 회귀로 고정하며 다음 회차에서 반복 채굴하지 않는다.
