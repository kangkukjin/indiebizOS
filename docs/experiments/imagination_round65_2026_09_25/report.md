## 갭 원장과 근본 수리

### B65-1 — inner 결합의 열 이름을 행마다 결정

```ibl
$r=[table:join]{left:[{id:"a",score:10},{id:"b"}],right:[{id:"a",score:20},{id:"b",score:30}],on:"id"}
return $r.items
```

첫 행의 오른쪽 점수는 score_2인데 두 번째 행에서는 score로 나왔다. 입력마다 선택 필드가
다르면 같은 원천 값이 다른 열로 이동하므로 후속 집계는 실패하거나 다른 출처를 섞게 된다.
원인은 inner/items 경로가 일치한 행 쌍마다 `_suffix_collisions`를 호출한 것이다.
left/right/full과 표형 경로는 이미 입력 전체의 열을 기준으로 한 번 결정하고 있었다.

inner/items도 좌우 입력 전체의 관측 열을 모아 기존 공통 충돌 판정기로 목적 열 지도를
한 번 만든다. 없는 필드를 임의로 추가하지 않고 실제 있는 필드만 그 지도에 따라 옮긴다.
기존 접미사 열, 오른쪽의 희소 필드, 입력 순서 반전, 중복 키의 다대다 결과, semi/anti,
입력 불변성을 검증했다. 일반적인 조밀 자료의 결과와 키 비교 의미론은 그대로다.

### B65-2 — 짧은 표 행을 그대로 이어 붙여 열 위치 손상

```ibl
$r=[table:join]{left:{table:{columns:["id","memo"],rows:[["a"]]}},right:{table:{columns:["id","score"],rows:[["a",20]]}},on:"id"}
return $r.table
```

선언 열은 id·memo·score인데 결과 행은 `["a",20]`이었다. 후속 열 접근에서는 20이 memo가
되고 score는 null이 된다. 원인은 inner/table 경로가 왼쪽 행을 `list(r)`로 복사한 뒤
오른쪽 값을 붙인 것이다. 오른쪽 읽기와 다른 결합은 이미 누락 셀을 null로 취급했다.

왼쪽도 선언된 열 수만큼 위치별로 읽고 생략된 후행 셀을 null로 보완한 뒤 오른쪽 값을
붙인다. 양쪽 행 길이 조합과 inner/left/right/full 전수를 회귀로 고정했다. 별도 결측값
의미론을 만들지 않고 기존 표 읽기의 계약을 동일하게 적용했다.

발견 뒤 이 부류를 결합 모드·입력 형태·희소성의 결정론적 검사로 넘겼다. 다음 회차에서
같은 칸을 다시 채굴하지 않는다. 새 어휘·문법·업무별 분기는 없다.
