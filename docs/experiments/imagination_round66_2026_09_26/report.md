## 갭 원장 — B66-1

**정렬 기준 열이 전체 입력에 없는데 원래 순서를 정상 순위로 반환했다.**

```ibl
[{id:"a",가격:300},{id:"b",가격:100}]
  >> [table:sort]{by:"price"}
  >> [table:take]{n:1}
```

수리 전은 `{id:"a",가격:300}`을 추천하고 `success:true`, `source_complete:true`로 보고했다.
이는 가격 정렬이 아니다. catch는 실행되지 않았고, each의 collect도 이 원천을 성공으로 기록했다.
최소 재현과 열 이름 수정 대조(T18)로 잘못된 기준을 묵인하는 문제를 격리했다.

근본원인은 현재 문법의 `core-table/2` 어댑터가 공통 `sort_records`로 바로 내려가면서
기존 data-ops의 필드 존재 검사를 빠뜨린 것이다. 값 정렬기는 일부 누락값을 뒤에 놓는
역할이므로 전체 필드가 없는 자료도 모든 행이 결측인 자료처럼 다뤘다.

수리는 `backend/ibl/ibl_v2_adapters.py`의 정렬 경계에서 소유한다. 비어 있지 않은 입력
전체에 기준 키가 한 번도 없으면 `MISSING_FIELD`와 실제 필드 이름 예를 반환한다.
공통 값 정렬 의미론은 재구현하지 않는다. 일부 행의 부재·명시 null·동점 안정성·빈 목록의
정상 반환은 유지하고, 진단에 쓰는 20행 표본과 달리 키 존재 판정은 전체 행에서 한다.
새 어휘·문법·업무별 분기는 없다.

같은 core-table 어댑터의 필드 소비 경계를 점검했다. select는 각 행의 지정 열을 검사하고,
filter·compute의 콜백은 공통 필드 접근 검사로 진단한다. take는 필드를 소비하지 않는다.
객체가 아닌 sort 입력은 기존 `List<Record>` 계약이 거절한다.
이 부류의 후속 검사는 회귀시험으로 넘겨 다음 상상훈련에서 같은 칸을 반복 채굴하지 않는다.
