## 갭의 원장

### 공통 뿌리 — 값 운반 통로가 표시 저장본을 읽는다

`resolve_input_refs`(`backend/cognition/model_result_view.py`)는 턴 증거 저장소(`TurnStore`)의 텍스트를 읽는다. 그 저장본은 **모델에게 보여 주고 인용하기 위한 사본**이라 ①공개 투영(`value` — Decimal이 JSON 실수로, 실패도 그냥 JSON 객체로)과 ②디스크 영속 전 비밀 마스킹을 거친다. path 없는 기본 참조만 `value_wire`(손실 없는 타입 전송)를 풀고, 나머지 자리는 표시 사본을 그대로 업무 값으로 삼는다. 아래 B69-1·4·5는 같은 뿌리의 세 얼굴이고, B69-2·3은 그 해석기를 **한 자리(최상위 이름)·한 표면(모델 경로)**에만 둔 데서 생긴 누락이다.

### B69-5 ★최우선 — 참조로 넘긴 업무 값이 **비밀 마스킹으로 조용히 변형**

- **요약**: `TurnStore.evidence`가 저장 전에 `mask_secrets`를 적용한다(영속 기록의 자격증명 보호 — 옳은 정책). 그런데 그 텍스트가 참조 해석의 원천이므로, 마스킹 규칙에 걸린 **일반 문장**이 `****`로 바뀐 채 다음 프로그램의 업무 값이 된다. 성공·경고 0.
- **최소 재현**: `inputs:{v:"와이파이 비밀번호는 cafe2026guest 입니다"}`, `return $v` → 그 `result_ref.input_args`로 `return $입력`.
- **실측**: `"와이파이 비밀번호는 **** 입니다"`(T20) · `"token run 9678****"`(T21, 32자 hex 실행 번호가 `token` 근처 고엔트로피 규칙에 걸림). 반면 `{password:"hunter2hunter2"}`는 wire의 태그 트리 모양이 필드 규칙을 비껴가 무사했다 — 변형 여부가 **값의 모양에 따라 우연**이다.
- **영향**: 강의실 공지·가족신문 안내·점검 보고서처럼 사용자가 실제로 쓰는 문장이 "고쳐진 채" 파일·알림으로 나간다. 잘못된 값이 참으로 보인다(거짓 성공 부류).
- **제안(수리성)**: 저장소가 마스킹으로 **바뀐 자리의 경로를 기록**하고(원문을 저장하지 않는다 — 비밀 보호 정책 유지), 참조 해석이 그 자리와 겹치는 선택을 **정직하게 거절**한다("가려진 값이 업무 값이 됨 — 이 프로그램 안에서 원천을 다시 읽어 계산"). 투영의 `result_ref`는 그런 결과에 `input_args`를 권하지 않고, read_result 페이지는 가려진 경로를 신고한다. 가드: 마스킹 걸림/안 걸림 × {기본 참조, path 참조, 부분결과, 중첩 참조}.

### B69-1 path를 준 참조가 **손실 있는 공개 투영**을 읽는다 — 같은 값이 두 `input_args`에서 다른 산술

- **요약**: path 생략 참조는 `value_wire`를 풀어 Decimal을 보존하지만, `path:["value", …]`는 저장본의 공개 `value`(JSON 실수)를 걷는다. read_result 페이지가 권하는 `input_args`는 항상 `path:["value"]`이므로 **"본문을 확인한 뒤 이어 쓰기"라는 교재 순서 그대로 가면 값이 바뀐다.**
- **최소 재현**: `return {price: 19.9}` → read_result → 페이지의 `input_args`로 `return $입력.price * 3`.
- **실측**: 기본 참조 59.7(T03) vs 페이지 참조 59.699999999999996(T04), 행 선택 3.3000000000000003(T05).
- **제안(수리성)**: edition 2 봉투에서 `value`로 시작하는 경로는 `value_wire`를 푼 타입 값 위를 걷는다(부분결과 `diagnostic.partial`이 이미 `partial_wire`로 하는 것과 같은 규칙 — 한 벌로). wire가 없을 때만 공개 값. 가드: {기본, `["value"]`, 하위 경로, 목록 인덱스} × {Decimal, 문자열, 중첩}이 같은 값.

### B69-4 실패한 실행을 참조하면 **실패 봉투 전체가 업무 값**

- **요약**: edition 2 봉투에 `value_wire`가 없으면(=실패) 기본 참조가 저장본 전체로 떨어진다. 실패 봉투의 키 14개가 `len($입력)=14`로 성공 계산된다. 투영의 `result_ref`는 실패에 `input_args`를 주지 않지만, `result_ref.id`로 참조를 짓는 것은 교재가 허용한 모양이다.
- **실측**: T09 `success:true, value:14`(불완전 표지만 승계).
- **제안(수리성)**: edition 2 봉투의 기본 참조는 성공 값(wire)만 — 실패면 실행 전 거절하며 `partial_reads.input_args`(성공 가지)나 원인 수리를 안내한다. 명시 path(`diagnostic…` 등)는 그대로 허용.

### B69-2 목록·레코드 안의 참조가 **조용히 참조 dict로 남는다**

- **요약**: 해석은 inputs 최상위 이름의 값 자리만 본다. `{반:[ref, ref]}`·`{cfg:{rows: ref}}`는 `{"$ref": …}` dict가 업무 값으로 들어간다. T11은 `len($cfg.rows)=1`로 **성공**(참조 dict의 키 수), T10은 우연히 타입 검사에 걸렸지만 이유는 "Record + Record"라 참조 문제임을 모른다.
- **제안(수리성)**: 같은 해석기를 값 트리 전체에 재귀 적용(참조 모양 = `$ref`·`path`만 가진 객체 — 최상위와 같은 규칙). 참조 모양이 아닌 `$ref` 키 객체(JSON 스키마 등)는 데이터로 둔다. 가드: 목록·중첩 레코드·깊이·섞인 리터럴, 입력 근거가 원소마다 실행기에 전달.

### B69-3 수동 모드 검수 `/ibl/validate`가 참조를 풀지 않아 **거짓 FIELD_TYPE**

- **요약**: 참조 해석이 모델 경로(`system_tools_ibl`)에만 있고, `/ibl/validate`의 `validate_request_code`는 원 inputs를 그대로 검사해 `{$ref: Text}` 레코드로 타입을 잡는다. 같은 요청이 모델 경로 `check:true`에선 valid(T13), 검수 표면에선 invalid(T12) — B53-1(검수 표면 동형성) 부류.
- **제안(수리성)**: 두 표면이 같은 해석기를 통과(검수 표면의 참조는 그 요청의 실행 신원 네임스페이스에서 풀고, 없으면 실행과 같은 정직한 거절).

### F69-1 다른 대화의 참조 — 내부 절대경로·`Errno`가 오류 문구로 샌다

- T14: `저장된 결과 '…'를 읽을 수 없습니다: [Errno 2] No such file or directory: '/Users/…/data/spill/tool_evidence/<hash>/….txt'`. 형식이 틀린 id는 "잘못된 증거 ID"로 깔끔한데, 형식이 맞고 없는 id만 OS 예외가 그대로 나간다. 모델에게 필요한 사실("참조는 그 결과를 만든 같은 대화 안에서만 유효 — 여기선 다시 조회")이 없다. 회원 경로에선 개인 저장소 경로가 노출된다. 수리성: 저장소가 "이 대화에 없는 결과"를 뜻 있는 오류로.

### F69-2 문자열 경로 페이지가 JSON 이스케이프 본문 — 미리보기와 조회의 total이 다르다

- T16: 미리보기 `changes[].total=90000`(원문 글자) · read_result `read_scope.total_chars=102502`. 페이지 본문이 `"0000 … \"따옴표\" \\ …\n`처럼 이스케이프돼 모델이 읽을 글자가 14% 늘고, 따옴표·역슬래시가 원문과 다르게 보인다. 스키마 설명은 "중첩 JSON을 해제한 값의 문자 페이지". 수리성: 선택한 값이 문자열이면 원문 글자로 페이지(offset·total이 원문 기준 — 미리보기와 같은 좌표).

### F69-3 UNBOUND 안내가 실제 입력 이름을 모른다

- T17: `input_hint`가 "이름 변경 가능"이라 권하므로 코드만 `$목록`으로 바꾸는 실수가 예측 가능한데, 안내는 "이 위치 전에 값을 정의하거나…"뿐이다. 수리성: 컴파일러가 inputs 서명을 알고 있으므로 UNBOUND 안내에 제공된 입력 이름을 함께 싣는다.

### 판단의 경계

- 비밀 원문을 따로 저장해 참조를 살리는 안은 **채택하지 않았다** — 영속 기록 마스킹은 사용자 보안 정책이다. 대가: 비밀 후보로 오인된 일반 문장(와이파이 안내)은 참조로 못 넘기고 같은 프로그램 안에서 다시 읽어야 한다. 조용한 변형 대신 정직한 거절이다.
- wire 안 위치는 값 경로로 대응하지 않으므로 wire의 한 곳이라도 가려지면 그 결과의 업무 값 참조 전체를 거절한다(보수적). 가린 자리가 봉투의 다른 곳(실행 기록 등)이면 영향 없음.
- 저장소를 되읽는 다른 소비자(감독 검수·계수 대조·최종 평가)는 전수 확인 결과 **표시·인용** 역할이라 값 통로가 아니다 — 실행 입력으로 되돌아가는 자리는 이제 해석기 한 벌뿐이다.

### 회귀에서 드러난 원래 결함 — 등록 세션이 몸 밖의 파이썬을 띄움

- 첫 전체 회귀의 `test_python_libraries::test_modules_describe_and_decimal` 실패는 수정 전 HEAD 워크트리에서도 똑같이 실패했다(이번 변경과 무관). 원인: `script_session.Session.start`가 `get_python_cmd()`(환경변수·번들 파이썬이 없으면 PATH의 `python3`)로 워커를 띄워, 백엔드와 다른 인터프리터(라이브러리 없는 시스템 파이썬)에서 `modules`가 `numpy`를 못 찾았다. 라이브 백엔드는 PATH가 맞아 우연히 정상이었다.
- 뿌리: 등록 스크립트 실행기는 `_resolve_interpreter`("파이썬 가족 → 이 몸 자신 `sys.executable`", 인터프리터=몸의 명사)를 쓰는데 세션 경로만 그 해소기를 건너뛰었다. 수리: 세션이 원장의 `interpreter`를 받아(`backend/ibl/ibl_script_session.py`) 같은 해소기로 푼다(`script_session.py`). 회원 경로는 `member_script` 값 런타임이라 무관 — 재감사 후 `path_audited.impl` 지문 갱신·`member_manifest.json` 재생성.
