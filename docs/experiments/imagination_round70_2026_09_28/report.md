## 갭의 원장

### B70-2 ★최우선 — 병렬 쓰기 검사가 **값이 아니라 호출 자리의 글자 모양**으로 자원을 식별한다

- **요약**: `PARALLEL_WRITE_CONFLICT`는 `Compiler.writes()`가 구문 트리를 따로 걸으며 쓰기 어휘의 `write_resources` 인자가 **그 자리의 문자 리터럴**(또는 함수 호출 자리의 리터럴 인자)일 때만 자원을 센다. 그래서 같은 뜻의 프로그램이 모양에 따라 다른 판정을 받는다 — 교재가 권하는 "여러 곳에서 쓸 값은 `$이름=A`"와 "함수로 분해"를 따를수록 검사가 눈이 먼다.
- **최소 재현**: `$경로="~workspace/outputs/x.txt"` 다음 `[self:write]{path:$경로,content:"A반"} & [self:write]{path:$경로,content:"B반"}` → check `valid`. `path:"~workspace/outputs/x.txt"`를 두 번 쓰면(T09) 거절.
- **실측**: T10(변수) · T11(기본 인자) · T12(변수를 함수 인자로) · T13(함수 본문 `&`의 인자 경로) · T14(each `parallel:3`의 고정 경로) 모두 `issues:[]`. 대조군 T15(경로가 `$it`에 따름)·T16(다른 파일)은 옳게 통과.
- **영향**: 반별 명단·가계부 요약을 병렬로 같은 파일에 쓰면 최종 내용이 실행마다 다르다(마지막에 끝난 가지만 남음). 검사가 `valid`라고 말했으므로 거짓 안전이다. each 병렬은 `writes()`를 아예 부르지 않는다(검사 자리 자체가 `&` 노드에만 있다).
- **뿌리**: 타입 검사기는 이미 모든 경로(변수 대입·함수 특수화·기본값·each 본문)를 걷는데, 병렬 쓰기 검사만 **별도의 구문 보행기**를 두고 그 보행기가 값 대신 글자를 봤다. 두 보행기가 같은 프로그램을 다르게 읽는 구조다.
- **제안(수리성)**: 자원 식별을 타입 검사와 **같은 보행**으로 옮긴다 — 컴파일 시 알려진 Text 값을 타입의 정제(`positions`와 같은 선례의 선택적 정제, join이 버림)로 싣고, 쓰기 호출을 방문할 때 자원을 기록하며, `&` 가지와 each 병렬 본문이 그 기록을 괄호로 묶어 충돌을 판정한다. 별도 보행기 `writes()`는 제거한다. 동적 경로(`$it`·실행 값)는 여전히 증명하지 않는다(설계 문서의 경계 유지). 가드: 리터럴·변수·기본값·함수 인자·본문 `&`·each 병렬·중첩 병렬·분기 합류(다른 값이면 알 수 없음)·반복 안 재대입·대조군.

### B70-1 코드와 함께 준 `describe:["fn:지역함수"]`가 **등록 함수만 찾아 실행까지 거절**

- **요약**: 교재 작성 순서 1은 "이미 작성한 코드와 describe를 함께 주면 계약 조회가 성공한 뒤 코드를 한 번 실행"이고, 같은 절이 "`describe:["fn:이름"]`은 컴파일러가 계산한 함수 계약을 제공한다"고 한다. 그런데 `describe_actions`는 저장소(`ibl_v2_store.describe`)만 보므로, 제출한 코드 안의 지역 함수는 "등록된 함수가 없습니다"가 되고, 부가 조회 실패 규칙에 따라 **코드 실행까지 막힌다**.
- **최소 재현**: `[def:주간보고]($목록){…}` 를 정의하고 호출하는 코드 + `describe:["fn:주간보고"]`.
- **실측**: T08 `executed:false`, `descriptions:[{action:"fn:주간보고", error:"등록된 함수가 없습니다"}]`. 같은 코드의 `check:true`는 `functions`에 그 계약(`pipe_input:"목록"`)을 이미 싣는다 — 계약은 있는데 조회 통로가 모른다.
- **영향**: 교재가 가르친 분해 순서를 따르는 모델이 자기 함수의 계약을 확인하려는 순간 턴 하나를 잃는다(실행 0, 오류 문구는 등록 여부 문제로 오도).
- **제안(수리성)**: 코드가 함께 오면 그 코드를 같은 컴파일러로 한 번 검사해 **제출 원문 안의 지역 정의**를 먼저 해소하고(저장 함수보다 우선 — 실행기의 이름 해소 순서와 같음), 없을 때만 저장소를 본다. 가드: 지역·저장 둘 다·같은 이름이면 지역 우선·코드 없는 조회는 종전대로.

### F70-1 컴파일 진단 31종 중 **23종이 범용 안내**("해당 위치의 계약과 호출 인자를 확인하세요")

- **요약**: `finish_diagnostics`가 `HINTS`에 없는 코드에 범용 문구를 채운다. census(비시험 backend의 `self.issue(node, "CODE", …)` AST 수집): 31종 중 `ARGUMENT_CONTRACT·ARITHMETIC·ARITY·BUILTIN·CONCURRENCY·DUPLICATE_FUNCTION·EACH_COLLECT·EACH_MODE·FINALLY_RETURN·FORMAT_TYPE·FUNCTION·IR·PARALLEL_WRITE_CONFLICT·PARAMETERS·PIPE_TARGET·PURE_EXPRESSION·READONLY·RECURSION·RESERVED·SLICE_BOUND·STATIC_OPTION·UNSUPPORTED_ADAPTER·VALUE_EXPRESSION` 23종이 범용. 68회차는 실행 Fault의 SYNTAX 폴백만 막았고 컴파일 진단 표는 관문이 없었다.
- **실측**: T20 RECURSION은 메시지가 "**첫 판본**에서는 재귀 함수를 지원하지 않습니다"(판본 2 요청인데 '판본' 어휘가 겹쳐 오독을 부른다) + 범용 안내 — 반복 도구(`repeat`·`reduce`·each)를 모른다. T21·T22 범용. T18은 기본값 식이 앞 인자를 못 본다는 규칙 대신 "함수의 명시 인자로 전달하세요"(이미 인자다).
- **밭 판정**: 기계로 열거 가능(AST census)이므로 훈련 축이 아니라 census+관문이다 — 23종 전부에 안내를 쓰고, 새 진단 코드가 안내 없이 태어나지 못하게 가드를 세운다. 기본값 식의 UNBOUND는 그 자리에서만 별도 안내.

### F70-2 else를 빠뜨린 함수가 **Unit 섞인 결과를 경고 없이** 돌려준다

- T17: `[def:등급]($s){ [if:$s>=90]{ return "A" } }` → check 경고 0, 실행 성공 `["A", {"$ibl":"unit"}]`. 컴파일러는 이미 반환형을 `Text | Unit`으로 안다(뒤의 `join`·보간은 TYPE/FORMAT_TYPE로 잡힌다) — 그러나 결과를 그대로 반환·기록하면 보고서에 `{"$ibl":"unit"}`이 나간다. 문법 전문은 "else 생략은 Unit"이라 정확하지만, 값을 **돌려주는 경로와 떨어지는 경로가 섞인 함수**는 거의 항상 누락이다. 수리성: 명시 return이 있는데 반환형에 Unit이 섞이면 경고(실행은 막지 않음). 효과만 하는 함수(반환형이 Unit뿐)는 경고하지 않는다.

### F70-3 숫자로 시작하는 필드 이름이 "이름이 필요합니다."

- T23: `{3월:120000, 4월:98000}` → SYNTAX "이름이 필요합니다." + 범용 구문 안내. `{"3월":…}`은 된다. 1면·2차시·3월처럼 사용자 도메인에 흔한 키라 예측 가능한 실수인데 고치는 법(따옴표)을 말하지 않는다. 수리성: 레코드 키 자리에서 숫자로 시작하는 이름이면 따옴표 키를 안내.

뿌리 처방은 증상별 문구 수선이 아니라 **판정 근거의 교체**다 — 병렬 쓰기는 글자 모양 대신 값으로, describe는 저장소만이 아니라 실행기와 같은 이름 해소로, 진단 안내는 범용 폴백 대신 코드별 처방과 그 탄생 차단 가드로.

- **B70-2** (`backend/ibl/ibl_v2_types.py`·`ibl_v2_compile.py`): `Type.literal` — Text의 컴파일 시 값을 싣는 선택적 정제(`positions` 선례와 같은 자리, `str`·계약 문자열·지문 불변). 리터럴·그 값에 묶인 변수·기본값·특수화된 함수 인자·정적 보간이 값을 나르고, `join`은 정제를 **깊게** 벗긴 뒤 같으면 원래 모양을 지킨다(흐름 합류·반복 재대입은 값을 잃는다 = 증명하지 않음). 쓰기 호출을 방문할 때 선언 자원을 `write_log`에 적고, `&` 가지와 병렬 each 본문이 그 기록을 괄호로 묶어 충돌을 판정한다. 옛 별도 구문 보행기 `writes()`는 **제거**(타입 검사와 다른 눈으로 같은 프로그램을 읽던 두 번째 보행기). each 병렬은 원소가 하나로 알려졌으면 제외, 원소에 따르는 경로(`f"${$it}"`)는 대조군대로 통과.
- **B70-1** (`backend/ibl/ibl_v2_store.py`·`backend/cognition/model_result_view.py`·`system_tools_ibl.py`): `program_functions(code)`가 제출 원문을 같은 컴파일러로 검사해 **원문 안 정의**(`location.source == "<program>"`)의 계약을 돌려주고, `describe_actions(..., program=code)`가 저장 함수보다 먼저 해소한다(실행기의 지역 우선 해소와 같은 순서). 다른 곳에 오류가 있어도 서명은 `status:"invalid"`와 함께 보이고, 구문 오류면 비워 실행 경로가 정직하게 보고한다. 코드 없는 조회는 종전대로.
- **F70-1** (`backend/ibl/ibl_v2_analysis.py`): 범용 안내로 떨어지던 23종 전부에 코드별 처방(`RECURSION`→repeat·reduce·each, `PARALLEL_WRITE_CONFLICT`→순차·다른 파일, `PURE_EXPRESSION`→먼저 `$이름`에 받기 등). RECURSION 메시지에서 '첫 판본' 오독 제거. 가드가 비시험 backend의 `issue`/`warn` 진단 코드를 AST로 전수 수집해 전용 안내 없는 코드의 탄생을 막는다(68회차 SYNTAX 폴백 가드의 컴파일 진단판).
- **F70-1(T18)**: 기본값 식 안의 인자 참조는 UNBOUND 안내가 "기본값 식은 다른 인자를 볼 수 없음 — 본문에서 계산"을 말한다. 바깥 변수(T19)는 종전 "인자로 전달" 안내 유지. 기본값의 앞 인자 참조를 허용하는 것은 언어 개정이라 하지 않았다.
- **F70-2** (`ibl_v2_compile.py`): 명시 return이 있는데 반환형에 Unit이 섞인 함수는 `UNIT_RETURN_PATH` 경고(함수당 1회, 실행은 막지 않음). 모든 경로가 반환·효과만 하는 함수·빈 `return`만 있는 함수·마지막 식 반환은 경고 없음.
- **F70-3** (`backend/common/expression_parser.py`): 레코드 키 자리의 숫자 토큰은 `{"3월": …}` 따옴표 형태를 보여 주며 실패(원래도 실패하던 입력 — 수용 집합 불변, 문구만).
