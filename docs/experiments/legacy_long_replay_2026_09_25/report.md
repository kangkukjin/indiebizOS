원문의 각 단계와 질의·지시문을 보존하면서 다음 의미 차이를 명시했다.

- 표 변환은 값 목록, 기존 도구는 계약상의 `.items` 등으로 연결한다.

- 예전 `on_error:continue`는 `on_error:"collect"`와 `is_ok/unwrap` 분기로 옮긴다.

## 실행 결과와 근거

[재현 실행기](replay.py), [수리 전](before.json), [수리 후](after.json).
동일한 변환본·입력·기대값을 사용해 **32/36 → 36/36 통과**했다.
수리 전은 시작 커밋의 Runtime 클래스를 메모리에서 불러 비교하며 작업 파일을 되돌리지 않는다.
실패 4건은 서로 다른 결함 4개가 아니라 같은 불완전성 결함의 네 관측이다.

12개 모두 정상·빈 입력을 실행했다. 11개는 실패 주입도 실행했고,
news에는 선택적인 크롤링만 실패하는 경우를 추가했다. ledger는 정상·빈 입력으로
실제 도구 핸들러가 저장한 JSON을 읽어 검증했다. 임시 원장은 저장소 outputs 아래에서 생성·정리했다.

컴파일러·실행기·table 핸들러는 실제 구현이다. 외부 검색·영상·AI 등의 응답은 합성 고정 자료이며
과거 실제 응답의 복원이나 현재 검색·AI 품질 검증은 아니다. 선언된 현재 도구 계약으로 경계를 검사한다.
알 수 없는 외부 효과는 시험 실행기가 거절한다. 컴파일의 incomplete는 미확정 도구 타입이 남는다는 뜻이며,
실행 성공·실제 반환값·원천 완전성·기처리 ID 제외·저장 내용까지 별도로 대조했다.

실제 연결 검사도 수행했다.

- [실제 로컬 순회 조회](live.json): 설정·원장·파일 검색을 거쳐 12행 반환, 성공·원천 완전성 true.
- [실행 중인 HTTP 백엔드의 forex](live_http.json): 연간 5행·구간 2행·주가 2행·뉴스 4행 반환, 성공·원천 완전성 true.
- 별도 CLI 프로세스의 forex는 네이버 환경변수가 없어 실패했다. 서버 경계로 다시 검사해 성공을 확인했다.
  초기 시험기에서 판본 context를 빠뜨린 시간 반환 오류는 시험기를 고쳤으며 제품 결함으로 세지 않았다.
- [실제 API 회귀](live_regression.json): 없는 파일의 catch/fallback은 성공 반환과 함께
  source_complete=false, 순수 나눗셈 복구는 source_complete=true. 수정 코드가 실행 중인 백엔드에 반영됨을 확인했다.

## 발견한 공통 결함과 수정

**외부 호출 실패를 처리한 뒤 결과가 완전하다고 표시되는 문제.**

news의 선택적 크롤링이 실패해 catch로 진행하면 실행 성공은 맞지만 source_complete까지 true였다.
housing·shops·rotation의 순차 외부 실패도 true였다. 기존 Runtime은 partial 오류와
팬아웃의 실패에는 incomplete를 붙였지만 보통의 순차 도구 실패에는 붙이지 않았다.
실제 파일 부재를 catch/fallback으로 처리하는 최소 사례에서도 같은 문제가 적용된다.

`Runtime.invoke`에서 외부 도구 실패를 `tool_failure` 근거로 기록한다.
그 근거는 catch·fallback·저장 영수증 재사용 뒤에도 연결한다. 일반 핸들러 예외도 기존 VALUE
오류 의미로 정규화해 실패 영수증을 남기므로 결과가 불명인 외부 호출을 복구 과정에서 다시 부르지 않는다.
순수 계산의 복구는 외부 원천 누락으로 표시하지 않는다. 새 문법·어휘·도메인 분기는 추가하지 않았다.

[회귀 시험](../../../backend/test_ibl_historical_replay.py) **62개 통과**:
36개 실제 원문 기반 사례 + 효과 4종×오류 2종×제어 3종의 24개 영수증 재사용 검사 + 순수 경계 2개.
전체 백엔드에서는 **6,198개 통과·1개 실패**를 관측했다. 실패는 새 시험 파일에
직접 실행용 pytest 진입점이 없다는 `test_single_runner` 규약 검사였다.
진입점만 추가한 뒤 **규약 검사 4개 + 새 회귀 62개 = 66개 모두 통과**했다.
전체 검사를 다시 돌리지는 않았으며, 전체 검사 이후 제품 코드는 변경하지 않았다.
Android 몸 번들 재생성·어휘 파생 신선도·층 구조·은퇴 계약·차이 공백 검사도 통과했다.
최종 집계·명령·로그 지문은 [tests.json](tests.json)에 기록한다.

실행 성공률은 고정 자료의 의미 보존과 오류 표시에 관한 성과다. 외부 AI 판단 품질·전체 토큰 절감·
사용자 작업 완료 시간 단축은 측정하지 않았다. 미변환 코퍼스 전체의 정상 동작을 보장하지 않는다.
