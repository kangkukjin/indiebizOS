## 1. 과제와 조건

**자연어 과제**: "가을 팀 워크숍(당일) 견적서 3곳(A·B·C)을 요구사항과 맞춰 비교해 보고서를 만들어 줘.

필수 항목 가격이 다 있고 예산 안인 업체 중 가장 싼 곳을 추천하고, 업체에 물어볼 질문도 적어 줘."

- **고른 이유**: 가이드 §3 예시 1(견적 비교)을 첫 회차로. 연속(읽기→정규화→계산→판단→산출)·여러 갈래(병렬 읽기·항목별 반복·
  조건 분기·빈 결과·부분 실패)·여러 층(지역 함수 6개, 함수 안에서 함수 호출)을 한 프로그램에 담을 수 있다.
  저장 관용구가 없는 새 과제다.
- **입력(합성 시험자료, 비민감)**: `input/requirements.json`(인원 30, 예산 2,400,000, 항목 5개·수량 규칙 fixed/per_head/per_bus45),
  `vendor_A.csv`, `vendor_B.json`(형식이 다름 — 이름 필드 `name`, 음향 `price:null`, 간식 없음), `vendor_C.csv`(음향 0원 "대관에 포함").
  세 업체의 파일 형식을 일부러 섞었다.
- **실행 환경**: 라이브 백엔드 `POST /ibl/execute`, `edition:2`, `project_id:"컨텐츠"`, `origin:"training"`,

  ③ 빠진 가격을 0으로 치지 않고 표시 ④ 추천 = 필수 가격 완비·예산 이내 최저가(=C) ⑤ 확인할 질문(B 음향) ⑥ 보고서 파일 생성 후 다시 읽어 일치 확인.

## 4. 발견 (갭 7건, 수리 안 함)

### L1-1 정적 검사기에 null 좁힘이 없다 — ★최우선
- **분류**: 문법·값 계약 공백 (검사기 구현)
- **최소 재현** (`repro/narrow_*.ibl`), 모두 `$rows=[{a:null},{a:3}]` 에 대해:
  - `$it.a == null ? "-" : text($it.a)` → `TYPE` "Bool | Number | Text가 필요하지만 Null | Number입니다."
  - `[if:$it.a == null] { return "-" }; return text($it.a)` → 같은 `TYPE`
  - `$v=$it.a; $v == null ? "-" : f"${v}원"` → `FORMAT_TYPE`
  - 우회 `$it.a == null ? "-" : json($it.a)` → 성공 `["-","3","1500000"]`
- **영향**: 교재·가이드가 권하는 정직 설계("누락 가격을 0으로 간주하지 않는다", "null은 존재하는 값")가 표시 단계에서 곧바로 막힌다.
  null 검사 뒤 가지에서도 형이 좁혀지지 않아, 작성자는 `json()` 같은 우회를 찾거나 0/빈 문자열로 바꾸고 싶어진다 — 정직성과 역방향의 유인.
  `text()` 는 null 을 거절(교재: "null을 몰래 문자열로 바꾸지 않는다")하므로 거절 자체는 옳지만, **검사된 null 가지까지 거절하는 것**이 결함이다.
- **확정 사실**: 위 3형 모두 거절. 가설: 삼항·`[if]`+`return`·filter 술어 어디서도 흐름 좁힘을 하지 않는다(→ L1-2).

### L1-2 filter 술어 뒤에도 합집합 레코드 형이 좁혀지지 않는다
- **분류**: 문법·값 계약 공백 (L1-1 과 같은 뿌리 계열)
- **재현**: `$견적들` = 성공 행 `{vendor,ok,lines}` 와 실패 행 `{vendor,ok:false,error,lines}` 의 목록.
  `$견적들 >> [table:filter]{where:($v)=>not $v.ok} >> [table:each]{ return {error:$it.error} }` → `MISSING_FIELD` "선언된 필드가 없습니다: error" (error).
- **영향**: 교재의 `on_error:"collect"` 부분 실패 패턴을 따라 실패 행만 모으는 가장 흔한 다음 걸음이 막힌다. `get($it,"error","")` 로 우회했지만
  실패 행에는 error 가 반드시 있으므로 기본값 `""` 은 거짓 정보의 자리를 만든다. 판별 필드(`ok`)로 합집합을 좁히는 규칙이 없다.

### L1-3 `self:read` 의 `.data` 가 형식별로 계약 없이 다르다 (CSV 는 구판 봉투가 샌다)
- **분류**: 구현 결함 + 계약 공백
- **재현** (`repro/read_shapes.ibl`, `read_csv_data.ibl`):
  - `.json` → `.data` = 파싱된 JSON 그대로(`vendor,valid_until,lines`). 계약·교재 어디에도 적혀 있지 않다(훈련자가 추측해 맞힘).
  - `.csv` → `.data` = `{success, items:[{type:"paragraph",text:…}], message:<원문 전체>, path, count}` — **구판 봉투가 값 자리에 새며 본문이 text·items·message 에 세 번** 들어간다. 표 파싱 없음.
    교재는 "표와 시트 등 형식별 결과는 `.data.table`" 이라 하지만 CSV 에는 없다 → 작성자가 `split` 으로 CSV 파서를 직접 짰다(따옴표·쉼표 든 칸은 틀림).
  - `describe self:read` 의 `target_description` = null, `result.data` = 막연한 `Record`.
  - `observed_returns` 의 keys = `version, run, config, root, snapshot, snapshot_hash, phase, …` — self:read 의 반환 필드가 아니라 **사용 중 읽힌 어떤 파일의 내용 키**다.
    계약 조회를 오도하고, 사적 파일의 필드 이름이 계약 표면에 노출된다(개인정보 경미 — 값은 없음, 키 이름만).
- **영향**: 여러 형식 자료를 합치는 긴 작업의 첫 단계(읽기·정규화)가 계약 조회로 풀리지 않는다.

### L1-4 보간 `${…}` 안의 이름 해석이 자리마다 다르고, 따옴표 오류 문구가 엉뚱하다
- **분류**: 작성·발견 마찰 (진단 품질)
- **재현** (`repro/interp_*.ibl`, `$x={a:["p","q"]}`):
  | 식 | 결과 |
  | --- | --- |
  | `f"a:${x.a[0]}"` · `f"a:${$x.a[0]}"` | 둘 다 성공 "a:p" |
  | `f"a:${len(x.a)}"` | **`BUILTIN` "알 수 없는 내장 함수: x"** + `FIELD_TYPE` |
  | `f"a:${len($x.a)}"` | 성공 |
  | `f"a:${join(", ", $x.a)}"` | **`SYNTAX` "보간의 닫는 }가 없습니다."** |
  | `f"a:${join(', ', $x.a)}"` · `f"""a:${join(", ", $x.a)}"""` | 성공 |
- **영향**: 문법 전문은 `f"${row.id}"` 처럼 `$` 없는 이름을 가르치는데, 호출 인자 자리에선 같은 이름이 내장 함수로 해석된다. 오류 문구는
  "`$` 를 붙이라"는 처방이 없고, 따옴표 경우는 원인(같은 종류 따옴표) 대신 닫는 괄호를 말한다. 또 SYNTAX 는 첫 오류 하나만 보고해,
  초안의 같은 부류 3곳을 한 번에 고칠 수 없었다. 기존 ep 감사(09-16, "따옴표 중첩")와 같은 계열 — 그 기록에 증거로 연결.

### L1-5 `check:true` 응답의 3/4 이 정보 없는 RUNTIME_GUARD 다
- **분류**: 과도한 비용
- **관측**: 100줄 프로그램의 성공 check 응답 40,242자 중 `guards` 가 30,597자(24건, 모두 severity information). 첫 건은 `message:"Unknown"`,
  `expected:"Unknown"`, `actual:"Unknown"`, hint 는 일반 문구. v3·v5 두 번 모두 같은 크기.
- **영향**: 긴 프로그램일수록 검사 한 번마다 모델 문맥이 수천~만 토큰 커진다(가이드 §5 비용 축). 성공 check 에서 정보 등급 가드를 전부 싣는 것,
  "Unknown" 만 담은 가드를 싣는 것 둘 다 줄일 여지. (모델에게 실제로 몇 자가 전송되는지는 도구 접힘 16K 때문에 미측정 — HTTP 응답 기준 수치)

### L1-6 파일 없음이 `TOOL` + 원시 `[Errno 2]` 로 온다
- **분류**: 작성·발견 마찰 (경미)
- **재현** `repro/missing_file_code.ibl`: `$error.code="TOOL"`, message = 파이썬 `[Errno 2] No such file or directory: '<절대경로>'`.
- **영향**: catch 에서 "파일 없음(재송부 요청)" 과 "읽기 도구 고장" 을 코드로 가를 수 없어 문구 파싱에 기대게 된다. 보고서에 원시 errno 가 그대로 실린다(변형 v5 `unread[].error`).
  `RATE_LIMITED` 처럼 원인 코드가 있는 부류와 대조된다. 교재의 "선택 파일은 list 로 먼저 확인" 패턴으로 피할 수는 있다(그래서 경미).

### L1-7 `describe` 는 한 번에 6개까지 — 교재에 없음
- **분류**: 작성·발견 마찰 (경미)
- **관측**: 7개 요청 → `"describe는 node:action 또는 fn:이름 1~6개 배열입니다"`. 오류는 명확하지만 교재 `describe` 설명에 상한이 없다.

- `origin:"training"` 호출은 `ibl_usage.db action_usage_daily` 에 계상되지 않았다(탐침 전후 self:read 카운트 불변). 통계 분리 의도로 보이나 코드로는 확인하지 않음.
- 숫자에 천 단위 구분이 없는 보고서(1740000) — 표시 품질 한계. 새 내장 함수 제안은 하지 않는다(반-어휘-증식); 다음 회차에 기존 수단으로 되는지만 본다.

## 5. 개선 방향 (다음 수리 턴의 입력 — 이번에는 집행 안 함)

1. **L1-1·L1-2 공통 뿌리 = 흐름 좁힘 부재.** 삼항의 조건, `[if]`+`return` 조기 반환, `table:filter` 술어(판별 필드 Bool·`== null`·`has`)를 같은 좁힘 함수 하나로.
   소유 위치는 정적 검사기(형 추론 모듈) 한 곳. 관문 = 위 재현 4형(+ `not $v.ok` 판별 합집합)을 고정물로, 좁힘 없이 실패하던 원래 전체 프로그램 v2·v4 가 통과하는지.
2. **L1-3** `self:read` 의 `.data` 를 형식별로 선언(JSON=파싱 값, CSV/TSV=행 목록 또는 명시적 부재)하고 구판 봉투가 `.data` 로 새지 않게. `observed_returns` 수집은
   반환 봉투의 필드만 관측하도록(내용 키 오염·사적 키 노출 차단). 교재의 `.data.table` 문장을 실제 계약과 대조하는 관문.
3. **L1-4** 보간 안의 이름 해석을 한 규칙으로(최상위 경로와 호출 인자에서 같게) + 오류 문구에 원인 처방(`$` 붙이기, 안쪽 따옴표는 다른 종류로). SYNTAX 여러 건 수집은 선택.
4. **L1-5** 성공 check 에서 information 가드는 건수 요약 + `read_args` 로 접고, 내용이 전부 Unknown 인 가드는 싣지 않기.
5. **L1-6** 파일 부재를 원인 코드(예: 기존 코드 체계 안의 NOT_FOUND 류)로 — 새 코드 신설 여부는 기존 코드 표를 먼저 볼 것.
6. **L1-7** 교재 한 줄.

재검증 조건: 원래 과제·변형을 **최초 초안 v1 의 의도(보간 안 `??` 제외)** 그대로 다시 써도 우회 없이 통과·달성하는지, `repro/` 전부, 기존 교재 예제 고정물.

## 6. 비용과 잔여

- **시간**: 작성 시작 20:32 → 원래 과제 첫 성공 20:34(초안 ~2분, 수정 2회) → 변형 달성 20:36 → 부수 탐침 ~20:40 → 보고서. 상한 60분 안.
- **수정 주기**: 3회 사용(v2·v3·v5; v4 는 변형의 최초 시도라 제외) = 상한 도달. 이후엔 새 수정 없이 탐침만.
- **토큰**: 훈련 대상 실행에 모델 호출 0. 훈련자(이 세션)의 토큰은 미측정. check 응답 40KB×여러 번이 가장 큰 단일 비용(L1-5).
- **미검증 경계**: 모델(시스템 에이전트)이 자연어만 받고 이 프로그램을 쓸 수 있는지는 이 훈련의 범위 밖(상상행동훈련 몫). AI 판단 액션(`table:ai/judge`)을 넣은 긴 작업,
  `self:write` 외의 외부 효과, 수백 행 규모 입력은 시험하지 않았다.
- **다음 회차 후보**: ① 같은 과제에 `table:ai` 로 "확인할 질문" 문장화를 넣어 모델 호출이 낀 긴 흐름·재개 경계 ② 조사·학습 자료 과제(웹 원천 여러 개, 하나 읽기 실패) ③ 입력 규모 100행+ 에서 check 비용(L1-5) 재측정.

## 8. 후속 수리 (2026-09-29)

사용자 요청: “긴문장 상상훈련 보고서를 읽고 발견된 에러를 고쳐줘”.
수리 코드는 정본 main에 반영하며, 이 절은 최초 훈련의 실패 기록을 덮어쓰지 않는다.

- **L1-1·L1-2**: `ibl_v2_narrow`가 null 비교·Bool 판별·논리식의 타입 좁힘을 소유한다.
  삼항, if와 조기 반환, filter의 행 조건이 같은 함수를 쓴다. 타입 합류에서 Bool 판별값과
  성공·실패 레코드의 차이를 보존한다. 분기 바깥이나 검사하지 않은 가지의 오류는 계속 거절한다.
- **L1-3**: JSON 객체·스칼라는 `.data`, 배열은 `.data.items`로 선언한다.
  CSV/TSV는 표준 CSV 파서로 `.data.items`·`.data.table`을 만들고 빈 셀·0·인용된 구분자·줄바꿈을 보존한다.
  주인·회원 파일 경계가 같은 파서를 사용한다. 일반 본문과 구판 봉투는 `.data`에서 중복하지 않는다.
  내용 키의 관측 수집·과거 건강 기록 재수확·기존 관측 캐시의 계약 노출을 막는다.
  `describe`는 Document의 형식별 설명을 제공한다. JSON `.data`의 정적 형은 `Unknown`이다.
- **L1-4**: 보간에서 bare 이름과 `$` 이름은 호출 인자·필드·인덱스 어디서나 같은 변수 참조다.
  `len(x.a)`가 `len($x.a)`처럼 동작한다. 같은 종류의 안쪽 따옴표 오류는 다른/삼중 따옴표 사용을 안내한다.
  따옴표 중첩 문법을 추가하거나 여러 구문 오류를 한 번에 수집한 것은 아니다.
- **L1-5**: 성공 check의 정보 가드는 건수만 반환하고 `guards_ref.read_args`로 전체 진단을 읽는다.
  확정 오류·경고는 본문에 남고 저장 실패 시 기존 진단을 반환한다. Unknown뿐인 진단도 본문에서 제거한다.
- **L1-6**: 파일·디렉토리 부재는 `NOT_FOUND`, 메시지는 “파일을 찾을 수 없습니다”로 전달한다.
  `error_type`, `errno`, `path`, `base_path`, 부분 결과와 실패 위치는 유지한다.
- **L1-7**: describe의 1~6개 제한을 조합 교재에 명시한다.
