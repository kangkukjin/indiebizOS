## 1. 결론 요약

**방향은 문서가 정확히 겨냥한 사용 사례입니다.** 운영자가 중앙 PC에서 모델과 하네스를 관리하고, 직원은 자기 PC에 설치한 회원 앱에서 자기 작업 폴더로 일하는 구조입니다(D1 L5, L211; D4 L70). 다만 현재 상태는 **설치 베타**입니다(D1 L3, L244). 실제 운영에 필요한 여러 실기기 인수가 아직 기록되어 있지 않습니다.

| 범위 | 내용 (상세는 §3) |
|---|---|
| **지금 시작 가능** | 중앙에서 할 일: 회원 PC 등록, 설치 초대 발급, 회원 공통 모델·기어 설정, PC별 통계 확인. 운영 규칙 준비(작업 폴더 선정, 백업, 중앙 PC 상시 가동) |
| **먼저 확인할 조건** | 직원 PC가 중앙 주소에 HTTPS로 접속할 수 있는지, Mac 실기기에서 처음부터 끝까지 작동하는지, Windows 설치·실행·제거, 직원 두 명의 동시 사용과 격리, 연결 단절 시나리오, 사용할 모델 경로, 데이터가 외부로 나가는 범위, 명령 승인 방식 |
| **보류** | 확인 전 Windows 운영 배포, 서명된 정식 배포와 업데이트 채널, AI의 브라우저·앱·화면 조작, 관리자 원격 지원, 여러 기기 동기화, PC별 다른 모델, 주인용 상주 헬퍼(D3 PC제어)로 대신 운영하는 방식 |

핵심 근거:
- 구현된 것: 단일 설치 앱, 일회 초대, 실제 폴더 파일 작업과 셸, 로컬 승인, v2 접수·상태 조회, 90초 임대(D1 L223-L240)
- 출시 인수에서 남은 것: 배포자 인증서·공증, Windows 실제 설치·제거·권한, 외부 HTTPS에서 서로 다른 실제 PC와 API 모델로 하는 다중 회원 인수(D1 L244, L265)

## 2. 네 축 설명

### 2.1 회원별 실행 위치

| 기능 | 실행 위치 | 층·근거 |
|---|---|---|
| 파일 목록·검색·읽기·생성·수정·이동 | **직원 PC** | [계획] D1 L96-L99 → [구현] D1 L240, L259 → [검증-자동] D1 L247, L265 |
| 셸·스크립트 실행 | **직원 PC**, 중앙으로의 셸 폴백 없음 | [계획] D1 L13, L100 → [구현] D1 L240; D2 L755 → [검증-자동] D1 L247. [검증-실기기] Codex 실제 모델로 `run_command` 실행 기록(D1 L320-L322). 단, 합성 회원 폴더와 별도 중앙 설정에서 실행함(D1 L323) |
| AI 추론(모델 호출)·공개 검색 | **중앙 PC**(와 모델 제공자) | [계획] D1 L101; D1 L7, L63 → [구현] D1 L282-L293 |
| 문서 변환 | 직원 PC 또는 중앙 임시 어댑터 | [계획] D1 L102. 구현 기록은 이번에 확인하지 못함 |
| 브라우저·화면 조작 | 직원 PC | [계획] D1 L103, L119 → [구현] 로컬 설정과 실행별 승인 뒤 Go 드라이버로 전달(D1 L240; D2 L743) → 4단계 인수 미완료(D1 L185, L188) |

- 중앙이 꺼지면 새 AI 작업은 진행되지 않습니다. 로컬 기록 조회와 진행 중 프로세스 중단은 가능합니다(D1 L176, [계획]). 따라서 **중앙 PC가 근무 시간에 켜져 있어야 합니다.**
- 직원 PC는 중앙으로 바깥 방향 연결을 맺습니다. 인바운드 포트를 열 필요는 없습니다(D1 L76, [계획]).
- 회원 PC는 `member-pc-class`로 등록됩니다. 주인의 `guest-pc-class` 실행 대상과 섞이지 않습니다(D1 L219, [구현]).

### 2.2 파일 접근 권한

- **파일 도구**
  - 직원이 OS 선택창으로 고른 폴더 안으로만 동작합니다(D1 L42, L98).
  - 작업 생성 때 폴더의 파일 신원을 고정합니다. Unix는 장치/아이노드, Windows는 볼륨/파일 ID를 씁니다.
  - 선택 폴더 교체와 심볼릭 링크 우회는 거절합니다. Go `os.Root` 핸들 안에서 실행합니다(D1 L259, [구현]).
  - 덮어쓰기 전에 사본과 지문을 남기고, 되돌릴 때 지문이 달라졌으면 중단합니다(D1 L240, [구현]).
- **셸**
  - 직원의 **OS 계정 권한 그대로** 실행됩니다. 폴더 선택은 셸 샌드박스가 아닙니다(D1 L105, L240, L259; D2 L755, 여러 문서 일치).
  - 따라서 셸 명령의 승인이 실질적인 경계입니다. 기본은 구체적 명령을 확인받는 것이고, 직원이 원하면 해당 작업 동안 허용할 수 있습니다(D1 L105, [계획]).
  - 구현 기록에는 "로컬 승인"(D1 L240; D2 L743)과 "로컬 승인 1회 후 run_command"(D1 L321)가 있습니다. 작업 단위 허용의 세부 동작은 이번에 확인하지 못했습니다.
- **관리자 권한의 한계**
  - 관리 창에는 직원 PC의 임의 셸·화면 조작을 붙이지 않습니다(D1 L109, [계획]).
  - 다만 **관리자를 신뢰하지 않아도 되는 격리는 약속하지 않습니다.** 중앙이 모델 입력을 처리하고 명령을 제안할 수 있으므로, 직원의 로컬 승인 범위가 실제 경계입니다(D1 L109).
- **공용 PC·같은 OS 계정**
  - 같은 OS 계정에서 회원을 바꾸는 것은 파일 접근을 차단하는 보안 경계가 아닙니다(D1 L88).
  - 각 직원 PC를 직원 전용 OS 계정으로 쓰는 것이 문서의 전제에 맞습니다.
- **구형 helper**: Go 1.22 legacy 독립 helper는 이 데스크톱 파일 경로를 지원하지 않습니다(D1 L259). 직원에게는 회원 데스크톱 앱을 설치해야 합니다.

### 2.3 결과의 저장 위치와 소유

| 데이터 | 정본 위치 | 층·근거 |
|---|---|---|

| 작업·대화·명령 원장·되돌리기 사본 | 직원 PC의 SQLite. 허브/회원 PC/설치 ID 조합별로 분리 | [계획] D1 L153-L155 → [구현] D1 L236; D2 L755 |
| 모델 자격·정책·공통 도구 | 중앙 PC | [계획] D1 L156 → [구현] D1 L285-L287(키는 중앙 `.env`) |
| 접수 메타데이터(ID·지문·상태) | 중앙 SQLite, 현재 등록 수명 동안 | [구현] D1 L238 |

- 문서가 말하는 "소유"는 **데이터의 정본이 어디에 있는가**입니다. 문서 변환의 입력·결과도 소유자를 회원으로 적었습니다(D1 L102).
- 회사와 직원 사이 업무 산출물의 법적 귀속, 퇴사 때 자료를 회수하는 절차는 **네 문서 모두 다루지 않습니다. [미확인]**
- 운영상 함의
  - 대화와 작업 기록의 정본이 직원 PC에 있습니다. 중앙에는 원문이 장기 보관되지 않습니다(D1 L131, L238).
  - 따라서 직원 PC 백업이 기록 보존의 유일한 경로입니다. 앱에 백업 기능이 있습니다(D1 L174).
  - 관리자는 통계에서 **요청 내용**을 볼 수 있습니다(D1 L295). 직원에게 이 점을 알려야 합니다.
  - 로그아웃은 자격을 제거하지만 로컬 기록 삭제는 별도로 선택합니다(D1 L86).

## 3. 세 범위 분류

### 3.1 지금 시작 가능

판단 기준: 구현 기록이 있고 자동 검증 또는 실기기 검증 근거가 있으며, 중앙 쪽에서 직원 PC에 영향 없이 할 수 있는 일.

| ID | 항목 | 층 | 근거 |
|---|---|---|---|
| S1 | 회원 PC 관리 창에서 직원 PC 두 대 등록. 사용자 표시명은 이웃을 만들지 않음 | 구현 + 검증-자동 | D1 L215-L219, L247; D4 L70; D2 L745 |
| S2 | 회원 공통 모델·기어 설정: 경량·중급·고급 슬롯, 절약·균형·최대. 중앙 PC 개인 설정과 독립이며 주인 인증만 허용. 변경은 다음 요청부터 적용 | 구현 + 검증-자동(backend 10,555 통과, D1 L326) + Codex 실모델 검증(합성 폴더) | D1 L282-L293, L320-L326 |
| S3 | PC별 통계(요청 내용·모델·도구 순서·토큰, 최근 30일)로 사용량 관찰 | 구현 | D1 L295-L301 |
| S4 | 설치 초대(10분 유효 일회 코드) 발급 절차 준비 | 구현 + 검증-자동(서명 인증 통합 검사) | D1 L234, L247 |
| S5 | 운영 규칙 준비: 직원별 작업 폴더 선정, 직원 PC 백업 방침, 중앙 PC 상시 가동, 통계 열람 고지 | 문서 요구사항에서 도출 | D1 L174, L176, L295 |

> S1·S2·S4는 중앙 설정을 바꾸는 일입니다. 이번 검토에서는 실행하지 않았습니다. 운영자가 직접 할 수 있는 범위로만 판정했습니다.

### 3.2 먼저 확인할 조건

| ID | 조건 | 왜 확인해야 하나 | 근거 |
|---|---|---|---|
| C1 | 직원 PC에서 중앙에 **HTTPS**로 접속할 주소 | 연결은 HTTPS를 전제로 합니다. 작업실 내부망 전용 주소로도 되는지는 문서에 없습니다 **[미확인]**. 원격 접근용 터널 설정은 D2에 있지만 회원 경로와의 관계는 명시되지 않았습니다 | D1 L62, L76, L234; D2 L301-L513 |
| C2 | Mac 기종(Apple Silicon/Intel)과 미리보기 빌드 실행 | 기본 ZIP은 Apple Silicon용이고 Intel은 `--x64`입니다. 미리보기는 배포 서명이 완료된 빌드가 아닙니다. 서명되지 않은 앱이 직원 Mac에서 어떻게 실행되는지는 기록이 없습니다 **[미확인]** | D1 L223 |
