근거 메모: `판단메모.md`(같은 폴더). 각 항목 끝의 `→ M#`이 메모 항목, `D#`가 문서 간 차이다.
표시: **[지금 가능]** 문서상 지원되어 바로 쓸 수 있음 / **[먼저 확인]** 시작 전에 확인할 조건 / **[운영 습관]** 장기 조사 중 반복 점검.

## A. 시작 전 확인할 조건 (두 사람 운영)

- [ ] **S1 [먼저 확인]** 두 사람의 대화·자료실을 서로 열 수 없게 하는 사람별 권한이 있는지 확인한다. 세 문서에는 없다. 없다면 대화 분리를 보안 경계로 여기지 않는다. → M2, 미확인 1
- [ ] **S2 [먼저 확인]** 두 사람이 같은 백엔드 하나에 접속하는지 확인한다. 다른 기기의 백엔드로 같은 프로젝트를 서비스하는 운영은 지원 밖이다(R1 L389-390). → M2, 미확인 2
- [ ] **S3 [먼저 확인]** 공통 기억(해마·심층·포식)이 두 사람의 조사 내용을 섞는지 확인한다. 자료실만 대화별이고 공통 기억은 일반 정책을 따른다(R2 L45-47). → M1, 미확인 3
- [ ] **S4 [먼저 확인 → 결정]** S1~S3 결과를 보고 '사람별 별도 프로젝트'(권장)와 '한 프로젝트·사람별 대화' 중 하나를 고른다. 공용 프로젝트를 쓰면 한 사람의 진행 중 대화가 이름 변경·복제·휴지통을 막는다(R2 L105-106). → M2
- [ ] **S5 [먼저 확인]** 나중에 두 사람이 자료를 공유할 계획이 있는지 정한다. 프로젝트 간 가져오기는 후속 범위이고(R1 L392), 대화 간 이동 수단도 문서에 없다. → D1, D4
- [ ] **S6 [먼저 확인]** 지속 연구 질문 기능이 실제로 동작하는지 작은 시험 대화에서 확인한다. 질문 저장 → 재열기 → 판본 이력 조회 순으로 본다. R1에는 이 기능의 검증 기록이 없다. → M7, D3
- [ ] **S7 [먼저 확인]** 백업을 누가 언제 수행하는지 정한다. 문서에는 방법(온라인 backup/VACUUM INTO, R2 L98-99)만 있고 자동 정기 백업은 확인되지 않았다. 사람별 프로젝트면 백업도 사람별로 한다. → M2, 미확인 6
- [ ] **S8 [먼저 확인]** 실행 모델 설정을 확인한다. API 평가 모델이 설정되지 않았으면 모델 설정 오류부터 해결한다(R2 L40). → M9

## B. 지금 가능한 시작 절차 (문서상 지원)

- [ ] **P1 [지금 가능]** 연구 프로젝트를 만들고(런처 → 새 프로젝트 → 연구), 주제마다 대화를 만든다(R2 L3-5, L15-16). 주제가 다르면 대화를 나눈다. 다른 대화의 자료는 자동 조회되지 않는다(R1 L71). → M1
- [ ] **P2 [지금 가능]** 대화 제목은 바꿔도 된다. 이력·자료·uid·인용은 유지된다(R2 L19, L41, L100). → M6, M9
- [ ] **P3 [지금 가능]** 조사 방식을 정한다. 외부 획득을 막고 보존 자료만으로 대화할 때는 '저장 자료만' 모드를 쓴다(R2 L29-30; R1 L379). → M3
- [ ] **P4 [지금 가능]** 사용자의 관점 문서에 출발 질문·판단 기준을 직접 적어 둔다. 직접 수정도 다음 실행에 반영된다(R2 L57, L64). → M8

## C. 장기 조사 중 반복 점검 (원문·판본·질문)

- [ ] **R1c [운영 습관]** 자료실에서 각 자료의 확보 범위를 본다. snippet(검색 발췌)·partial·unknown을 원문 확보로 세지 않는다(R2 L34-35; R1 L373-374). → M3
- [ ] **R2c [운영 습관]** 결론의 핵심 근거가 검색 결과뿐이면 원문 읽기(crawl·첨부·자료실 read)를 요청한다. 링크·URL·spill 경로만 있으면 보존이 아니다(R1 L127, L168). → M3
- [ ] **R3c [운영 습관]** 답변에 실제 인용이 붙었는지 확인한다. 자동 회수된 문단 수나 획득 횟수는 활용·독립 문헌 수가 아니다(R1 L498, L535-539). → M4
- [ ] **R4c [운영 습관]** 인용을 열면 답변 당시 판본과 위치가 열리는지 확인한다(R1 L69, L220). 시점 비교가 필요하면 판본을 지정해 읽는다(R1 L224; R2 L126-127). → M5, M6
- [ ] **R5c [운영 습관]** 긴 원문은 next_cursor로 이어 읽는다. 일부 페이지만 읽고 '전체 검토'로 기록하지 않는다(R2 L91-93). → M3, M6
- [ ] **R6c [운영 습관]** 중요한 전환점마다 질문 기록(잠정 답변·gaps·next_probes·지지/반박)과 관점 문서가 실제로 저장됐는지 확인한다. 모델이 저장하지 않은 턴에는 직전 문서가 남는다(R2 L71-72; R3 L49). → M7, M8
- [ ] **R7c [운영 습관]** 질문을 닫을 때(answered) 반박마다 검토 판단을 남긴다. gaps를 지워서 종결 조건을 맞추지 않는다. 종결은 진위 인증이 아니다(R3 L38-41). → M7
- [ ] **R8c [운영 습관]** 다음 턴 요약은 gaps·next_probes 앞 3건만 싣는다. 남은 확인이 많으면 질문 기록을 조회해 전부 본다(R3 L48). → M7
- [ ] **R9c [운영 습관]** 보존 실패가 표시되면 디스크 공간·권한을 복구한 뒤 새 메시지로 이어 간다. 색인 실패는 원문을 유지한 채 재시도한다(R2 L102-104). → M3
- [ ] **R10c [운영 습관]** 누적 용량을 주기적으로 본다. 원문 자동 삭제·원문 단위 영구 삭제는 없고, 정리는 프로젝트 삭제 단위다(R1 L392-394). → M6, D2
- [ ] **R11c [운영 습관]** 이름 변경·복제·휴지통 전에 진행 중인 대화를 먼저 중단한다(R2 L105-106). → M2
