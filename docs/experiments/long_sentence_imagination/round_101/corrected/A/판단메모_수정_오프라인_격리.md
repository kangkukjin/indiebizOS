## 0. 한 줄 결론

- **N1**은 둘로 나뉩니다.
  - 직원이 일반 프로그램으로 로컬 파일을 다루는 일: **필요한 앱과 파일이 Mac에 준비되어 있고 그 앱이 네트워크 없이 해당 파일을 열기·편집·저장할 수 있는 경우** 가능합니다. 해당 조건은 문서만으로 확인되지 않았고 실제 Mac에서도 시험하지 않았습니다(C17, Q9). D1 L176은 중앙이 꺼졌을 때 로컬 파일 열기를 허용하는 서술이며, 일반 앱의 오프라인 편집·저장까지 검증한 근거는 아닙니다.
  - **AI가 파일 작업을 하는 일**: 네트워크 없이는 **문서상 불가**입니다. 추론이 운영자 PC와 모델 제공자에게 있고, 독립 로컬 AI 추론은 제공하지 않는다고 명시되어 있습니다(D1 L7, L101, L176).
- **N2**는 둘로 나뉩니다.
  - **이 시스템을 통한 접근**: 설계와 구현이 서로 다른 회원 기기로의 실행을 막습니다. 다만 실기기에서 두 회원을 동시에 시험한 기록은 없습니다(D1 L92-L94, L194, L197, L244).
  - **OS 수준의 접근**: 셸이 OS 계정 권한으로 실행되므로, 앱이 보장하지 못합니다. 각 직원의 OS 계정이나 PC에서 상대 폴더가 보이지 않도록 OS·네트워크를 구성해야 충족됩니다(D1 L88, L105, L259). 그 구성 방법은 문서에 없습니다.

## 3. 네 축 재판정(새 조건 반영)

### 3.1 실행 위치

| 기능 | 위치 | 오프라인(N1) | 격리(N2) |
|---|---|---|---|
| 파일 도구 | 직원 PC | 도구 자체는 로컬이지만, 호출하는 AI 턴이 중앙에 있으므로 **오프라인에서는 사용 불가** | 서버가 인증된 `member_id + device_id + installation_id`를 붙임. 본문의 다른 device 주장으로 우회할 수 없음 |
| 셸 | 직원 PC, 중앙으로의 셸 폴백 없음 | 위와 같음. 단절 중 새 명령을 실행하지 않음 | 같은 회원 기기로만 실행됨 |

### 3.2 파일 접근 권한

- **이 시스템을 통한 직원 간 접근 차단**
  - 회원 키는 런처 세션을 만들지 않습니다. 프로젝트·설정 API 인증에도 통하지 않습니다([구현] D2 L746).
  - 통계와 상세 작업은 해당 PC 신원으로 제한됩니다. 회원은 관리자 조회 API를 호출할 수 없습니다([구현] D1 L301).
  - 모델이 다른 회원 기기를 제안해도 거절해야 한다는 조건은 **실기기 인수 시나리오로만** 남아 있습니다([계획] D1 L197; 미인수 D1 L244).
- **설치 앱 안의 폴더 경계**
  - 파일 도구는 선택 폴더의 파일 신원에 고정됩니다. 심볼릭 링크와 폴더 교체로 우회할 수 없습니다([구현] D1 L259).
  - 다만 다른 직원의 폴더를 작업 폴더로 고르는 것 자체를 막는 서술은 없습니다. 고를 수 있는지는 OS 권한에 달려 있습니다 **[미확인]**.
- **셸**: OS 계정 권한 그대로입니다(D1 L105, L240, L259; D2 L755). 따라서 N2는 다음이 갖춰져야 충족됩니다.
  1. 각 직원의 PC 또는 OS 계정이 상대 폴더에 접근할 수 없음
  2. 공유 네트워크 드라이브나 동기화 폴더로 상대 폴더가 마운트되어 있지 않음
  3. 공용 PC라면 서로 다른 OS 계정을 씀(D1 L88)

  2번은 네 문서 모두 다루지 않습니다 **[미확인]**.
- **오프라인(N1)**: 단절 중 새 승인이 실행되지 않으므로 권한 범위가 넓어지는 일은 없습니다(D1 L143, L238).

### 3.3 저장 위치와 소유

- C17 조건 아래 일반 앱으로 편집·저장한 파일은 선택한 Mac 로컬 폴더에 남습니다. 해당 일반 앱의 자동 저장·동기화 및 회원 앱 원장 기록 여부는 이 문서들만으로 확인되지 않았습니다.
  - 중앙 전체의 원문 장기 보관 부재는 단정하지 않습니다. v2 본문 RAM 최대 30분(D1 L238)과 통계·상세 작업의 요청 내용 표시(D1 L295-L301)는 별도 범위이며, 통계 본문 저장·보존·삭제 조건은 처음 메모 C18과 아래 Q10에서 확인해야 합니다.
  - 출장 중 기기 분실에 대비해 로컬 정본의 백업을 준비해야 합니다. 중앙 통계가 기기의 전체 기록·파일을 복원할 수 있다는 근거는 없습니다(C18). 백업·내보내기는 앱 기능으로 서술되어 있고(D1 L174), 중앙이 꺼졌을 때 백업 가능 서술도 있습니다(D1 L176). 장시간 네트워크 단절에서의 기능은 Q2 미확인입니다.
- 직원 간 격리: 기록은 허브/회원 PC/설치 ID 조합별 SQLite와 디렉터리로 분리됩니다([구현] D1 L236; [계획] D1 L153).
  - 이것은 저장 위치의 분리일 뿐입니다. 같은 OS 사용자에 대한 보안 경계는 아닙니다(D1 L88).
- 중앙의 결과 RAM(30분)과 접수 메타데이터는 회원별 소유권으로 조회가 제한되어야 합니다.
  - 설계는 "모든 조회·취소에 회원·기기·요청 소유권을 검사한다."라고 적었습니다([계획] D1 L129).
  - 구현 절(D1 L238)은 데스크톱 v2의 상태 조회에 소유권 검사가 있는지 명시하지 않습니다 → **[미확인]**, 질문 Q5.
- 산출물의 법적 귀속은 여전히 문서 근거가 없습니다 **[미확인]**.

## 4. 세 범위(수정)

### 4.1 지금 시작 가능

- S1~S4(중앙 쪽 등록·초대·모델·통계): 그대로입니다.
- S5에 출장·격리 운영 규칙을 추가합니다(B6).
  - 출발 전 AI 작업을 완료하거나 취소함
  - 백업을 내보냄
  - 직원별 작업 폴더를 상대가 접근할 수 없는 위치로 정함
  - 공유 드라이브·동기화 폴더에 작업 폴더를 두지 않음

  문서 근거는 각각 D1 L174, L176, L88, L259입니다. 규칙 자체는 이 메모가 도출한 것입니다.
- 오프라인 동안 일반 프로그램으로 로컬 파일 작업: **C17의 앱·파일 준비와 오프라인 열기·편집·저장 조건을 확인한 뒤** 가능한 범위입니다. D1 L154는 로컬 파일 위치, D1 L176은 중앙이 꺼졌을 때 파일 열기에 대한 서술이며 실제 Mac의 오프라인 편집·저장 검증이 아닙니다. 현재는 조건 미확인입니다. 단, 이것을 "AI 작업 지속"으로 보고하지 않습니다.

- 처음의 C2~C4, C6~C11과 사후 교정으로 추가한 C18(중앙 보관 범위)을 유지합니다.

- 새로 추가한 조건:
