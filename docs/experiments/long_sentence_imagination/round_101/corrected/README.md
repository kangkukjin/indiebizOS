## 오프라인 작업 조건

- 일반 앱 작업은 필요한 앱·파일이 Mac에 준비되어 있고 네트워크 없이 해당 파일을 열기·편집·저장할 수 있을 때 가능하다. 온라인 인증·클라우드 전용 파일 등 의존 여부도 확인해야 한다. 현재 해당 조건은 미검증이다.
- 후속 메모의 결론·실행 위치 표·U3·시작 가능 범위에 같은 조건을 적용했다. 확인 조건 C17, 질문 Q9, 점검 항목 J10을 연결하고 기존 질문 Q1·점검 J1에도 반영했다.
- 수동 검토 Q13에 따라 사용자가 AI 작업을 명시한 것처럼 쓰지 않고, AI까지 요구하는 경우에 한해 충족 불가로 판정했다. Q16에 따라 일반 앱의 작업을 AI 작업 지속의 성과로 세지 않는다.
- 회원 앱의 장시간 단절 기능(Q2)과 일반 앱의 편집·저장(C17)을 구분했다. D1 L176의 중앙 중단 시 로컬 파일 열기 서술만으로 일반 앱의 오프라인 편집·저장을 보장하지 않는다.
- B2의 진행 중 작업 즉시 정지 단정을 신규 단계 차단으로 한정했다. 이미 OS에서 실행된 명령의 즉시 종료는 D1 L217에서 보장하지 않으며 Q3 확인 대상으로 남겼다. 직접 편집 파일의 로컬 저장과 일반 앱 동기화·회원 원장 기록 여부도 구분했다.

## 중앙 보관 범위 — 코드·기존 DB로 확인

**중앙 `data/member_activity.sqlite3`의 `tasks.request`에 받은 요청 message 전체가 영속 저장된다.** 코드에 본문 요약·가림·TTL·날짜별 정리·PC 해제 연동 삭제가 없다. 실제 기존 DB에서도 10월 16일 요청 3건을 읽기 전용 집계로 확인했다. 내용은 출력·복사하지 않았다.

최근 30일은 `member_usage.json` 일별 사용량의 조회 합산 범위다. 상세 작업 목록에는 날짜 제한이 없고 50건씩 이어 읽는다. PC 등록 해제는 자격 폐기·세션 종료이며 통계 본문을 삭제하지 않는다. 코드상 유한한 보존 기한은 없으므로 별도 삭제가 없으면 남는다. 다만 외부 수동 정리·OS 백업까지 조사한 것은 아니며, DB에 30일 초과 기록은 없어 실제 30일 초과 보존을 관측했다고 주장하지 않는다.

v2 접수 경로의 결과·이벤트 RAM은 별개다. 완료 후 1,800초 초과 항목을 submit/status 시 제거하고 재시작에도 소실한다. 통계 DB의 request에는 이 수명이 적용되지 않는다. 접수 메타데이터에도 코드에서 등록 폐기 연동 삭제를 찾지 못했다. 중앙 통계에는 assistant 답변·파일 바이트·도구 입력/출력 전문 칸이 없어 전체 대화·파일 복원용 백업이 아니다.

A 메모·목록의 C18·Q10·A9·J11은 이제 저장 사실의 미확인이 아니라 **확인된 보존 방식에 따른 보존 기간·삭제 기능/절차·고지 정책 결정**으로 남긴다. 데이터 삭제·제품 정책 변경은 실행하지 않았다. 상세 경로·범위·코드 지문은 [감사 A](code_audit.md)에 있다.

## API 평가 모델 조건 — 코드·커밋·기존 usage로 확인

**연구 대화 시작에 별도 API 평가 모델은 필수가 아니다.** `96a9a6d4`에서 CLI 실행을 평가 모델로 바꾸고 API가 아니면 거절하던 연구 전용 코드가 제거됐다. R2 L40은 그 이전 커밋의 안내가 남은 것으로, 현행 일괄 시작 조건으로 적용할 수 없다.

공통 목표 평가가 실제 실행될 조건(의식 출력·기준·결과 등)이 성립하면 준비된 평가 제공자가 필요하다. 텍스트 평가는 평가 역할의 기어/핀 → system 원샷 → 의식 제공자 순으로 대체를 시도하며 CLI도 지원한다. 이미지 평가는 이미지 지원 평가 제공자 또는 비전 슬롯이 필요하다. **실제 쓰는 제공자가 API 방식일 때 해당 API 인증·모델이 필요**하고 CLI 방식이면 설치·로그인이 필요하다. API 평가 모델이라는 별도 항목을 모든 연구 대화에 일괄 요구하는 조건은 없다.

101회차 기존 usage의 평가 4회는 모두 `ClaudeCode/opus`다. 현재 자격·로그인의 유효성이나 지금 호출 성공 여부는 새 호출 없이 검증하지 않았다. B M10·D8·S8과 후속 K8·Q12가 이 결론을 반영한다. 기존 D7(대화 삭제), Q10·Q11은 유지했다. 정확한 분기·예외·근거는 [감사 B](code_audit.md)에 있다.

## 판정 범위

앞선 인용 10건·오프라인 조건 교정에 이어, 이번에는 A1 중앙 보관 범위와 B1 모델 설정 지적을 A/B 교정본에 반영했다. **지적된 문서 결함은 사후 편집했고, 두 쟁점의 구현 경로는 코드·기존 기록으로 확인했다.** 새 모델 실행이나 삭제 기능 동작을 실증한 것은 아니다. 최초 훈련 산출물의 품질 일부 미충족·독립 전이 및 비용 개선 미검증 판정은 유지한다. 교정본은 새 훈련 성과나 전수 품질 합격본이 아니다.

정답표·원시 비용·원래 인용 검사 결과는 보존했다. 편집의 운영자 토큰은 미측정이며 원래 실행 비용에 합산하지 않았다. 첫 점검 목록도 이제 보관 조건을 추가한 교정본이고, B 과제의 원본 3편을 바탕으로 별도 교정본을 추가했다.

## 파일 대조 검증

- 원문 사본 7편은 `sources.json`의 SHA-256과 일치. 원시 수집 4개·AI 산출물 7개는 `correction_audit.json.source_sha256`과 일치.
- 현재 A/B 교정본 7편을 기존 인용 검사기로 파일 대조: **좌표 827건 모두 범위 안, 따옴표 32건 중 후보 일치 21건·수동 분류 대상 11건**. A만 검토한 첫 교정본 477건, 문서 근거만 반영한 다음 교정본 848건과 다르다. 이번에는 확인된 코드 결론에 코드 감사 링크를 사용했다. 이 좌표 수는 D/R 사본 인용만 세며 코드 링크는 별도로 확인했다.
- 남은 11건은 수동 판정 Q01·Q02·Q03·Q04·Q05·Q16의 자체 용어·내부 참조 6건과 Q18~Q22의 자체 운영 권고 5건이다. 새로운 외부 원문 직접 인용 불일치는 없다. 후보 일치는 문장 전체의 의미 정확성을 보증하지 않는다.
- 앞선 인용 10건·오프라인 조건 보존, 새 확인 항목 ID와 연결, 원본 대비 변경 범위·문서 간 상대 링크를 확인했다. 중앙 저장·자동 삭제 부재와 평가 역할 조건을 확인했고, 보존/삭제 운영 결정 및 현재 제공자의 준비 상태를 남겼다. 감사 코드 14개 파일의 지문은 조사 HEAD 및 최초 훈련 HEAD와 모두 일치했다. 소프트웨어 코드·제품 설정 변경과 훈련·실모델 호출·장치 시험은 없다.
