### (b) "직원끼리 다른 직원의 폴더 접근 차단" — 보장 범위와 한계

| 구분 | 내용 |
|---|---|
| 사본이 보장하는 범위(제품 경로) | 등록 단위=PC, PC별 자격·실행 분리(D1 L84); 서버가 `member_id+device_id+installation_id`로 실행 대상 고정, 다른 device 주장 거절(D1 L92·L94); 실행 목적지=요청한 그 PC(D1 L13); 허브/회원 PC/설치 ID별 SQLite·파일 디렉터리(D1 L236); 통계·상세 작업은 해당 PC 신원으로 제한, 회원이 관리자 API 호출 불가(D1 L301, 구현); 회원 키는 런처 세션·프로젝트·설정 API에 안 통함(D2 L746). 직원 둘이 **서로 다른 물리 PC**를 쓰므로 한 직원의 AI 작업이 다른 직원 PC의 폴더를 대상으로 삼을 경로가 제품에 없다. |
| 계획 단계 근거(실검증 아님) | D1 L194 "상대 파일·기억·명령·승인·산출물이 섞이지 않는다"(반드시 확인할 시나리오) · D1 L197 "다른 회원 기기·임의 작업 ID를 제안해도 로컬과 중앙 관문이 거절한다"(시나리오) · D1 L185 4단계 "주인/타 회원 화면 사용 차단"(계획) · D1 L244 다중 회원 실 PC 인수 미수행 |
| 한계(사본이 명시) | (1) **OS 권한 모델 밖은 보장 없음**: 셸은 OS 계정 권한(D1 L105·L240·L259, D2 L755) → 직원 PC에서 OS가 접근 가능한 공유 드라이브·네트워크 폴더·타 사용자 폴더는 셸로 닿을 수 있음. (2) 같은 PC 안 OS 사용자 간 분리는 OS 몫(D1 L88 "같은 OS 사용자의 파일 접근 자체를 차단하는 보안 경계라고 주장하지 않는다"). (3) 관리자는 신뢰 전제(D1 L109 "암호학적 격리를 약속하지 않는다"; 중앙이 명령을 제안할 수 있음). (4) 하드웨어 증명 없음(D1 L219 "키를 다른 기기에 복사하지 않는 운영이 필요하다"; L234 "TPM/하드웨어 원격 증명은 아니다") → 키 유출 시 타 PC 사칭 가능. (5) 다중 회원 동시 실기 인수 미수행(D1 L244). |
| 기대 결론 | **조건부**: 제품(하네스) 경로에서는 설계·구현상 PC별 분리가 되어 있고 직원 PC가 서로 다른 물리 PC라는 전제에서 교차 접근 경로가 없다. 다만 (i) 실 PC 2대 동시 인수는 미수행, (ii) OS 수준(공유 폴더·NAS·같은 PC 다중 계정·셸)은 제품이 보장하지 않으며 사용자의 OS·네트워크 설정에 달림. "완전 차단 보장"이라 단정하면 오답, "불가"라 단정해도 오답. |

## 5. 요약 — 사본이 답하지 않는 것(실행자가 "미확인"으로 남겨야 정답)

1. 직원별(PC별) 다른 모델 배정 — 자료에 없음(공통 한 벌만).
2. 비용 한도 — 설계 언급(L109)만, 구현은 "한도 없음"(L300).
3. Claude Code 회원 어댑터 실검증 — 자료에 없음(Codex만 L320).
4. 실 PC 2대 동시(직원 2명) 인수 — 미수행(L244).
5. Windows 실기 실행·설치·제거·권한 — 미수행(L244·L247·L265).
6. 네트워크 단절·중앙 재시작·재부팅 실기 시험 결과 — 외부 보고서(L276-277), 사본에 없음.
7. 중앙에 남는 "요청 내용"의 범위 — L157/L238과 L295/L298 사이 긴장.
8. 직원 간 결과 공유·관리자의 결과 파일 열람 — 자료에 없음.
9. 오프라인 AI 작업·로컬 모델·오프라인 편집 후 동기화 — 자료에 없음(동기화는 후속 L164).
10. 15초 임대 갱신의 구현 반영 — 미기재(90초 만료만 L238).
