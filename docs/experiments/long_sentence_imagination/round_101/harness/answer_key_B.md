- 사람(사용자) 단위 계정·권한·접근 제어 — 자료에 없음.
- 두 사람이 **같은** 프로젝트를 동시에 쓸 때의 규칙 — revision 충돌 감지(R1 L249, R2 L65)와 단일 백엔드(L390)만 있음, 사용자 구분은 없음.

- 실제 모델이 자료를 어느 범위까지 자동 등록·활용하는지 — §24(L535-539) 실측에서 자동 회수와 활용을 구분해야 함을 경고.

계획/구현/검증 구분에서 특히 중요한 점:
- **연구 질문(R3) 기능의 구현·검증 기록은 R1 에 없다.** R1 에는 `research_notes`(L101)와 진행 상태 4항목(L207-212) 설계만 있고, §17~§24 어디에도 `questions`·`resolution`·`evidence_id` 언급이 없다. R2 L108 이 구현 정본을 §17 로 지정하지만 §17 은 질문 기록을 다루지 않는다. 따라서 실행자는 "연구 질문 기능은 가이드가 사용법을 기술한다"까지만 말할 수 있고 "구현·검증됨"으로 단정하면 오답.
- 관점 문서는 §23 구현 + 화면 검증(L529), 단 **모델의 자동 정리 행동은 미검증**(L530).
- 체크포인트의 연속 처리·지연 표시(R1 L214)는 설계 서술, 구현 기록 없음.

답변 불가:
- 연구 질문 기능의 구현 여부·검증 결과.
- 실제 모델이 질문·관점을 얼마나 자주 저장하는지(§23 L530, §24 L550-551 모두 미검증).
- 질문 수 상한, 요약 목록 크기, 질문 화면 UI 세부.
- 일정 기간(예: 한 달) 뒤 자동 알림·재개 트리거 — 자료에 없음.

## 5. 핵심 요약(검수자용)

- 현재 동작 정본은 R1 §19 이후 + R2·R3. R1 §1~16 의 **공용 자료 설계(L20·L184·L189·L327)는 대체됨** — 실행자가 이를 현재로 쓰면 오답.
- 사본이 답하지 않는 것: **사람별 권한·계정**, **연구 질문 기능의 구현·검증 상태**, HTML 원바이트, 프로젝트 간 가져오기/내보내기(후속), 원문 단위 영구 삭제, 외부 모델 인용 정확도, 기간 트리거.
- "당시 판단 근거" 확인은 **실제 read 한 본문+남긴 인용**에 한정. snippet 은 발췌만. §24 실측은 인용 0회 — 운용 조건을 점검 목록에 넣어야 정답.
- 충돌 8건 중 실질 4건(자료 범위·질문 자리·API 평가 모델 문구·가져오기 범위), 나머지는 시점 차이·UI·회귀 기록.
