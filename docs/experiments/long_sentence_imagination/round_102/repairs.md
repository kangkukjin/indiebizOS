원본 훈련의 AI Python 일괄 구현은 수행 전략 관측이며, 한 사례만으로 전체 모델 경로를 바꾸지 않았다. 공용 리허설의 독립성 제한도 수리 성공으로 바꾸지 않는다. 검사·저장·수리·재사용의 성과와 미검증은 각 회차 보고서에 그대로 남긴다.

## 실제 실행 세대 재검증

활성 코드 세대6ee16af1a18317a7fac6138087c48205의 세 구현 파일을 정본과 SHA256 대조했다. 자동 세대 교체와 명시 restart 요청이 겹쳐 명시 요청은 stale_generation으로 종료했지만, 실제 ACTIVE 세대의 일치와 HTTP 접수/실행을 별도로 확인했다. 새 등록·원본 전체 IBL·별도 복구 탐침 모두 HTTP로 실행하여 원래 별도 프로세스 우회와 구분한다.

새 탐침 실행25a2eeb0ab984ab5a2a86b50a54b2b0d: 발송2건 뒤 표시 계산 실패→ReportAfterProbe 새 판본 저장→명시 참조 check/repair→같은 실행 resume 모두 통과. 원장 바이트 불변, 영수증2개와 최종 파일의 품목/금액 일치, durable call9건(읽기7·쓰기2)을 보존했다. 위험한 발송 입력 변경은 check에서 거절했으며 실행하지 않았다. 원본102 탐침의 실패 판정은 그대로다.

새 이름 저장은 실제 HTTP에서2.076·3.009·3.039초였다. 기존 판본 개정은 전체 소비자 검사를 유지해175.363초가 걸렸다. 원본 새 저장118~167초와의 관측 차이는 남기되, 실행 환경·카탈로그·경로가 같은 통제 실험이나 전체 모델 비용 절감률로 주장하지 않는다.

## 훈련 능력 일반화 보완 — L102-4

LS102Demand가 품목+필요일별로 묶어 같은 품목의 재고를 중복 적용할 수 있었다. 이제 요청 ID 중복 제거→도서관/품목 합산→가장 이른 필요일 선택→재고1회 결합으로 개정했다. 서로 다른 날짜·중복 신청·예약재고 반례는 요청5·실재고3·부족2·2026-11-01로 통과했다. 저장된 LS103Region을 다시 소비한2400계획행과 최종 파일도 원본 정답과 같다.

일반화된 날짜 선택 계산 때문에 마지막 지역 안에서 기본100만 단계 예산을6616단계 초과했다. 원본 중단 기록을 보존하고 동일 계보를 명시 예산200만으로 resume하여1006616단계에 완료했다. 남은 행을 잘라내지 않았으며 발송은 없는 비교 계획이다. 재사용 가능한 [호출 봉투](repairs/regional_request.json)에 그 예산을 명시했다. 이것은 원본 두 회차의 상한 연장이 아닌 종료 후 별도 수리 검수다.

세 정규화/원장 스크립트는 원본 완료 뒤 내용의 형식을 정리했다. 원본 소스와 의존 지문은 기존 증거에 남아 있다. append JSON의 origin 환경변수 값은 null이어서 이 필드만으로 자식까지 training 표식이 전파됐다고 주장하지 않는다. 실제 호출 위치·진입 요청·원장·영수증으로 효과를 확인했다.
