## 발견과 수리

- **L104-1 — 저장 보고 능력의 선택 필드 처리 누락.** 소유자는 과제 함수 `LS102Report`이다. `label` 직접 접근은 필드 부재에서 실패했고 빈 문자열도 ID로 대체하지 않았다. [수리 본문](report_fixed.ibl)을 기존 함수의 expected_revision으로 개정했다. 새 이름의 업무별 코어 분기는 만들지 않았다.
- **L104-2 — 금액과 정수 수량을 같은 int 변환으로 처리.** 소유자는 등록 과제 스크립트 `ls102_normalize.py`, `ls103_normalize.py`이다. 수치 70.5는 70으로 조용히 잘렸고 문자열 70.5/677.5는 ValueError, 빈 가격은 Text로 남았다. 원본 IBL 지역 실행과 별도 포장 가격 호출은 출력 계약 오류로 실패했다. 원래 프로세스 stderr의 int 변환 예외도 보존했다. 공통 숫자 의미 소유자를 사용해 소수 금액 보존·빈 가격→null·정수 단위 검사로 수리했다. 지원할 수 없는 JSON 정밀도는 조용히 버리지 않고 명시 오류를 낸다.

## 축적과 관측의 범위

기존 `LS102Plan/Read/Demand/Choose/Library/Report`, `LS103Region/Compare`를 재사용했다. `describe`의 인터페이스와 함수 참조로 실행했고, 이전 회차부터 훈련자가 구현 지식을 갖고 있으므로 **본문 미열람 독립 작성**은 주장하지 않는다. 전건 독립 oracle은 원자료에서 별도로 계산하며 과제 정규화 부품을 가져오지 않는다.

시스템 AI는 이전 자기 Python 코드의 사본을 고쳐 `AI104_키트조달대조`로 보관했다. 변형에서는 새 지역 함수가 그 저장 대조 함수를 dry_run으로 호출하고 지역 계획 스크립트에 연결했다. 이 상위 호출 연결은 확인했으나, Python 내부의 결합·정책 전체를 IBL 세부 부품·콜백 재조합 성공으로 세지 않는다. 공용 rehearsal/카탈로그를 사용했으므로 이름·폴더 분리는 접근 격리가 아니며 **독립 발견·전이 미검증**이다. AI에는 훈련자 함수명·코드·정답을 제공하지 않았다.

API `origin:training`과 실제 로컬 append 원장을 함께 관측했다. 하위 append 영수증의 origin 값은 null이어서 그 필드를 격리 증거로 사용하지 않는다. 외부 주문·통신은 없었다. 훈련자 최종 파일 저장은 반환 JSON을 별도 IBL write/read 호출의 인자로 전달하는 수작업 경계가 있다.

코어 검사기의 본문 비열람 계측, 교차 세션 Callable 수명, 취소·정리 경계, 예산 초과는 이번 실사용에서 검증하지 않았다. 전 회차 성공을 이번 관측으로 옮겨 쓰지 않는다.
