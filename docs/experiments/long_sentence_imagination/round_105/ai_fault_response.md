`outputs/report.json`을 만들었고, 대사 방법을 시스템에 관용구 두 개로 등록했습니다. 등록 뒤에는 저장된 이름만으로 새로 호출해서 이번 보고서를 만들었습니다.

## 대사 결과
| 항목 | 값 |
|---|---|
| rows | 600행 (대장 순서와 같음) |
| total_actual | 9,088,100원 (예상 합계 9,065,100원보다 23,000원 많음) |
| duplicates | 24행. I0025부터 I0600까지 25번 간격으로 나온 재접수이고, 금액은 원 청구와 같습니다. 해당 장비마다 duplicate_count=1입니다 |
| missing_checks | 60대 (청구 636행이 아니라 점검기록 540건 기준) |
| mismatches | 46대. 모두 difference=+500입니다 (예: E0013, E0026, E0039 등 13번째마다) |
| unmatched | 12행 (U00–U11, 각 700원). 짝수 번호는 대장에 없는 `UNKNOWNn`이고, 홀수 번호는 asset_id가 null입니다. 원행을 그대로 보존했습니다 |

- **total_actual 범위:** 대장 장비와 연결된 고유 청구만 더했습니다. unmatched 8,400원은 들어가지 않습니다.
- **missing_check 기준:** 규칙대로 점검기록에 asset_id가 있는지만 봤습니다. 이번 자료에는 `checked:false` 행이 없었습니다.

## 등록한 것
기존 기능을 먼저 찾아봤지만 이 대사 기능은 없었습니다. 등록 절차용 `능력변경` 스크립트는 파일이 없어서 실행할 수 없었습니다. 그래서 가이드에 나온 직접 경로인 `self:workflow save`로 등록했습니다.

1. **`장비청구대사`(assets, checks, invoices)**: 파일을 읽거나 쓰지 않고 계산만 합니다.
   - asset_id가 없으면 machine으로 연결합니다.
   - amount 숫자와 `₩1,234` 형식을 같은 원 단위로 읽습니다.
   - 같은 invoice_id는 첫 행만 금액에 넣습니다.
   - 식별번호가 없거나 대장에 없으면 억지로 연결하지 않고 unmatched에 둡니다.
2. **`장비청구대사_파일`**(assets_path, checks_path, invoices_path, output_path): 세 파일을 읽어 1번을 호출하고 보고서를 저장한 뒤 건수 요약을 돌려줍니다. 다음 달이나 다른 지점은 경로만 바꿔 호출하면 됩니다.

## 확인 범위
- **등록 절차:** 두 관용구 모두 컴파일 검사를 통과해 저장됐습니다. 판본 ID(function_ref)가 발급됐고, `detail` 조회에서 `state: active`, `runnable: true`로 나옵니다.
- **실제 동작 1 (이번 자료):** 지역 정의 없이 `[fn:장비청구대사_파일]`을 새로 호출해 보고서를 썼습니다. 그 파일을 다시 읽어 다음을 맞춰 봤습니다.
  - 600행이고 대장과 순서가 같습니다.
  - 모든 행에서 difference = actual_cost − expected_cost입니다.
  - 장비별 duplicate_count 합(24)이 duplicates와 같습니다.
  - 청구가 0원인 장비는 없습니다.
- **실제 동작 2 (합성 표본):** `[fn:장비청구대사]`에 작은 표본을 넣어 손으로 계산한 기대값과 모두 일치했습니다. 표본에는 재접수, `₩` 금액, null 식별번호, 대장에 없는 장비, 점검 누락, 청구 없는 장비를 넣었습니다.
- **하지 않은 것:**
  - 정기 실행 예약은 걸지 않았습니다.
  - 형식이 다른 다른 지점이나 다른 달의 실제 자료로는 실행해 보지 않았습니다.
  - 금액이 비어 있는 청구가 들어오면 `assert`로 실행을 멈추게 했습니다. 이번 자료에는 그런 행이 없어서 이 경로는 실행되지 않았습니다.
