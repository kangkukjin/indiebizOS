## 등록한 스크립트
- **본문:** `data/scripts/invoice_normalize.py`
- **선언한 계약:** 입력 `rows: List<Record>`(필수), 결과 `{items: List<Record>}`, 효과 `pure`, 제한 시간 120초
- **정상 입력:** `{items:[{invoice_id, asset_id, amount, raw}]}`를 돌려줍니다.
  - asset_id가 null이면 machine을 씁니다.
  - fee는 `₩`, `KRW `, 접두 없음 세 형식을 받고 쉼표를 제거합니다.
  - 정상 입력 검사(amount 정수, `₩1,200`, `KRW 12,345`, asset_id null 섞음)는 기대값과 정확히 일치했습니다.
- **잘못된 입력:** 금액을 0으로 바꾸지 않고 호출 전체를 실패시키며, 문제 행을 모두 메시지로 알려줍니다.
  - 금액 없음, 소수 amount(`100.5`)는 등록 검사에서 거절되는 것을 확인했습니다.
  - `₩12a` 같은 해석 불가 fee는 직접 호출로 확인했습니다.
  - 실제 메시지: `금액 해석 실패 2건: rows[0] invoice_id='X1': amount와 fee가 모두 없음; rows[1] … fee 형식을 해석할 수 없음: '₩12a'`
  - 계약 오류가 아니라 스크립트가 직접 거절한 것입니다.
- **정해 둔 엄격한 기준:** `10017.0`처럼 소수점이 붙은 JSON 숫자 amount도 정수가 아닌 것으로 보고 거절합니다.
