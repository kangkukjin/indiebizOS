- **바꿔야 했던 것은 판정이다.** base qrels의 Q04 정답 '30일'과 anchor 정규식 `30일`은 새 판본에서 낡은 값이다. 원본은 두고 `qrels_variant.json`, `anchors_variant.json`, `answers_variant.json`을 새로 만들었다. 세 파일은 재실행 전에 해시로 고정했다(`judgments.sha256`).
- **답이 달라진 질문: Q04. 30일 → 14일.** 검색 적중은 거의 그대로이고 답만 바뀌었다.
- **여전히 알 수 없는 질문: Q06(월 클라우드 비용).** 그런데도 8개 실행 모두 문서 3개를 돌려준다.
- Q05의 S03도 갱신됐지만 답의 판정(조건부 허용·금지)은 바뀌지 않았다.

## 2. 방법을 그대로 써도 되는가 (V2)
- 실행: `python3 -I ai/base/run_experiment.py --input inputs/variant --queries inputs/variant/queries.json --output ai/variant/runs/results_variant.json --qrels ai/variant/qrels_variant.json`
- 실행: `python3 -I ai/base/analyze_passages.py --input inputs/variant --queries … --anchors ai/variant/anchors_variant.json --output ai/variant/runs/passage_ranks_variant.json`
- 실행 전후 해시 비교:
  - run_experiment.py `bba09c58…`, analyze_passages.py `d0b02390…`
  - methods 5개: `methods.sha256` 대조 결과 5/5 OK
  - qrels.json `f83dc6c8…` OK
  - 전체 기록: `base_hashes_after.txt`
  - inputs/base의 S01·S03 해시는 base manifest와 같다(`0a68d880…`, `48d5a5d4…`).
- 실행 사고 1건: 처음에 `--input …/variant/docs`를 잘못 넘겼다. 그래서 문서가 0개로 읽혀 dense와 RRF가 실패했다. 이 잘못된 결과 파일은 내가 만든 것이라 지우고 폴더 경로로 다시 실행했다. 프로그램 결함은 아니다.
- **판단: 방법은 유지하고 판정은 갱신한다.** 방법이 판본 변화에 깨지지는 않는다. 다만 이 방법들은 애초에 판본을 판정하지 않는다. 그래서 '그대로 써도 되는가'의 답은 "검색 부품으로는 그대로 써도 되지만, 현재 답을 고르는 일은 하지 못한다"이다(4절).

- **Q04 dense·RRF(문단·문서):** 3위가 D05/S04에서 S03으로 바뀌었다. S03에 '시행일 2026-11-01'이 추가돼 날짜 표현이 질문과 비슷해진 것으로 보인다(추정, 임베딩 내부는 미확인).
- **Q04 그대로인 실행:** bm25_ws(문서·문단), bm25_ko@paragraph는 여전히 **폐기판 S02(90일)가 1위**다.
- **Q05 dense_ko(문서·문단): S03 1위 → S01 1위, S03 2위.** S01과 S03이 같은 '시행일 2026-11-01' 머리줄을 공유하게 됐다. 그래서 의미 검색에서 두 규정 문서가 더 비슷해진 것으로 보인다(추정). Q05 rrf@doc의 3위도 D01에서 S01로 바뀌었다.
- **Q06 bm25_ws(문서·문단):** 3위가 S03에서 S01로 바뀌었다. **Q06 dense@paragraph:** 3위가 S01에서 D03으로 바뀌었다. 모두 답이 없는 질문에 답 없는 문서끼리 자리를 바꾼 것이다.
- **Q03 rrf@doc:** 3위가 D06에서 D03으로 바뀌었다. 필요한 D01·D02는 둘 다 1~2위로 그대로다. 문서 단위 전체 적중 판정은 변하지 않는다.

## 6. 한계와 미확인
- 질문 6개, 문서 12개의 작은 합성 자료다. 일반 성능으로 확대하지 않는다.
- 판정(qrels_variant, answers_variant)은 자기 판정이다. 결과를 보기 전에 고정했지만 독립 검증은 없다.
- dense 순위 변화의 원인('시행일' 머리줄로 문서가 비슷해짐)은 추정이다. 임베딩 기여도는 분해하지 않았다.
- bm25_ko에서 문서 단위(S01 1위)와 문단 단위(S02 1위)가 왜 갈리는지는 확인하지 않았다. 문단 단위 IDF와 길이 정규화 차이로 추정할 뿐이다.
- 답 단계(판본 메타데이터 비교, 기권, 조건부 답)는 여전히 구현하지 않았다.
