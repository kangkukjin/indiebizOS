# 연구계획: 개인 문서 검색 실패의 원인과 검색 방식 비교 — 106회차 variant 갱신

이 계획은 base 계획(`data/outputs/research_plans/5d92d2b9e2e04b66ba485341ae5e76d3/research_plan.md`, sha256 83d7d2fa…)을 이어 쓴다. 목적은 그대로다: 개인 문서에서 '다시 찾지 못함'과 '결과는 많은데 근거가 없음'이 어디서 생기는지 이 자료에 한정해 판단한다. 이번 회차는 문서 2개가 갱신된 판본에서 그 판단이 유지되는지 확인하는 하위 질문이다.

## 1. 이번 질문
- **V1.** 무엇이 바뀌었는가? 어느 문서의 어느 문단이 어떤 내용(판본 상태, 수치, 조건, 새 사실)으로 바뀌었는가.
- **V2.** 앞서 쓴 4방식×2단위를 그대로 써도 되는가? 프로그램과 설정을 고정한 채 실행되는지, 결과 해석에 쓰인 판정(qrels)이 새 판본에서도 맞는지 확인한다.
- **V3.** 질문별 검색 결과는 어떻게, 왜 달라졌는가?
- **V4.** 실제 답은 어떻게 달라졌는가? 사용자에 따르면 질문 하나는 답이 달라지고, 하나는 여전히 답을 알 수 없다. 어느 질문인지는 문서 차이로 확인한다. base 결과로 보면 Q04(현행/폐기판)와 Q06(답 없음)이 유력하지만 이것은 확인 전의 짐작이다.
- **V5.** base 결론(키워드 개선은 필요하나 부족, 의미 검색과 키워드의 실패 맞바꿈, RRF의 단위·깊이 의존, 문서 단위 적중의 과대평가, 검색 밖 문제) 중 무엇이 유지되고 무엇이 수정되는가?

## 2. 출발점과 범위
- **유효한 근거(재사용):**
  - ai/base의 프로그램, methods/, qrels.json, runs/, REPORT.md
  - 원문 열람 기록: BEIR, DPR, HyDE, Lost in the Middle는 초록, RRF는 1쪽과 표 1~3
  - 새 문헌 조사는 하지 않는다.
- **입력:** `outputs/long_sentence_imagination/2026-11-01_106회차/inputs/variant`. 변경 전 판본은 inputs/base에 있다.
- **출력:** `outputs/long_sentence_imagination/2026-11-01_106회차/ai/variant`. ai/base와 inputs/base는 읽기만 한다.
- **제약:** base와 같다. 문서 외부 업로드, 가입·구매·발송·공개, 제품 코드·운영 설정 변경, 위임·등록·해마 시딩은 하지 않는다. 다른 실행자의 trainer/private/harness/drafts와 정답표는 읽지 않는다.
- **잠정 전제(첫 확인 대상):**
  - variant의 구조가 base와 같다.
  - 바뀐 것은 문서 2개뿐이고 queries는 같다.
  - 임베딩 캐시가 남아 있다.
  - analyze_passages.py가 입력과 qrels를 인자로 받는지는 미확인이다.

## 3. 접근과 선택 이유
판본 갱신의 영향 평가는 '시스템이 같은 조건에서 어떻게 달라지는가'를 묻는다. 그래서 방법은 고정하고 자료만 바꾸는 대조 재실행을 쓴다. 방법을 바꾸면 변화의 원인을 자료와 방법 중 어디에 돌릴지 가를 수 없다.

판정은 두 층으로 나눈다.
- **검색 적중:** 새 판본 기준의 근거 문단이 상위에 있는가.
- **답 정확성:** 그 근거에서 읽은 답이 현재 조건의 답과 맞는가.

base qrels로 새 결과를 채점하면, 문서 ID는 맞는데 답은 낡은 경우를 적중으로 오판할 수 있다. 그래서 새 판정은 재실행 결과를 보기 전에 별도 파일로 고정한다. 이번 판정도 독립 정답표가 아니라 자기 판정이라는 한계를 유지한다.

## 4. 질문별 조사 방법
- **V1:**
  - 방법: manifest와 docs의 파일 해시를 비교하고, 바뀐 문서를 문단 단위로 diff한다. 바뀐 문단의 문구를 그대로 기록한다.
  - 반환: 바뀐 문서 ID, 문단 위치, 변경 전후 문구, 문단 수 변화(문단 ID가 밀리는지).
- **V2:**
  - base run_experiment.py를 `--input inputs/variant`로 실행하고, 실행 전후 methods.sha256과 프로그램 해시를 대조한다.
  - 문단 분할이 바뀌어 base qrels의 문단 ID가 어긋나면 qrels 재판정이 필요한 근거로 기록한다.
  - 스크립트가 경로를 하드코딩해 수정이 필요하면, 원본은 두고 ai/variant에 사본을 만들어 이유를 적는다.
  - 판단: 방법을 그대로 쓸 수 있으면 '방법 유지, 판정만 갱신'으로 결론 낸다. 방법 자체를 바꿔야 할 근거가 나오면 그 근거와 사본을 남긴다.
- **V3:**
  - 방법: qrels_variant 기준으로 질문별 정답 문단 순위와 문서·문단 hit@3를 base와 나란히 표로 만든다.
  - 원인 확인: 순위가 변한 질문은 바뀐 문단의 토큰 겹침(키워드)과 128토큰 앞부분 여부(의미 검색)를 직접 확인한다.
- **V4:**
  - 방법: 바뀐 문서를 읽고 질문별 현재 조건의 답을 answers_variant.json에 적는다. 각 답에는 답, 근거 문단, base 답과의 차이를 남긴다. 답할 수 없으면 '알 수 없음'과 그 이유를 적는다.
  - '알 수 없음' 판정 기준: 새 판본의 어느 문서에도 질문의 조건을 충족하는 진술이 없음을 문서별로 확인한다. 검색 결과에 문서가 나왔다는 사실은 답이 있다는 근거가 아니다.
  - 검색 결과(top_docs)의 answer 필드는 인터페이스대로 null로 둔다. 실제 답은 별도 파일로 낸다. 답 생성 단계는 이번에도 구현하지 않으며, 그 사실을 명시한다.
- **V5:**
  - V3·V4의 결과를 base 결론 항목별로 '유지', '강화', '수정', '판단 불가'로 대조한다.
  - 특히 확인할 것: 검색은 적중했는데 답이 바뀐 사례가 있는가. 있다면 '검색 밖 문제'(판본 판정, 없음 판정)의 근거가 강해진다.

## 5. 종합
질문별 한 줄을 만든다: 변경 문서 관련 여부 → 검색 순위 변화와 원인 → 답 변화 → 결론에 미친 영향. 변화가 없는 질문은 '자료 변경과 무관, 결과 동일'로 확인만 한다. 작은 묶음(문서 12개, 질문 6개)의 결과이므로 일반 성능으로 확대하지 않는다.

## 6. 진행과 멈춤 (약 10분)
**순서**

**멈춤:** V1~V5에 각각 답했거나 미확인으로 표시했다. 두 질문(답 변경, 알 수 없음)의 판정과 근거 문단을 확정했다. 해시 증거를 남겼다.

**축소 경로:** 시간이 부족하면 문단 순위 분석은 변경 문서와 관련된 질문으로 한정하고, 나머지 질문은 top_docs 동일 여부만 확인한다. 임베딩 캐시가 없으면 의미 검색과 RRF는 재실행 불가로 남기고 키워드 방식만 비교한다.

**보고 전 대조:** V1~V5별로 답, 근거 위치(파일·문단), 실제 열람 범위, 남은 불확실성을 대조한다.
