**훈련 완료, 연구의 전체 품질은 부분 달성.** 개인 문서 검색을 주제로 실제 시스템 AI 두 턴과 훈련자 IBL을 실행했다. 의식의 가이드 열람→계획 저장→실행 전달→실험→평가 경로는 작동했다. 시스템 AI가 스스로 문서 적중과 근거 적중을 구별하고 해석을 수정했으며, 후속 문서의 보관기간 30일→14일도 반영했다. 그러나 실제 반환 근거와 다른 보조 실험을 연결하는 해석, 재실행 환경 명세에 공백이 남았다. 제품 코드·프롬프트·운영 가이드 수리는 하지 않았다.

## 발견한 개선 과제

### L106-1 — 실험 단위·집계 순서와 결론의 연결 부족

AI의 주 프로그램은 `문단 점수 → 문서별 최대값 → 문서 순위 RRF → 문서별 대표 문단`이다. 보조 분석은 `전체 223문단 순위 → 문단 순위 RRF`다. 서로 다른 검색 절차다.

Q01의 보조 분석에서는 정답 문단이 RRF 22위다. 이 수치 자체가 계산 오류라는 뜻은 아니다. 하지만 실제 주 프로그램 `rrf_bm25ko_dense@paragraph`의 출력은 D02·D03·D05이고, **세 번째 반환 문단에 “종료 코드 0 + 결과 파일 없음은 RESULT_MISSING”이 그대로 있다.** 보조 분석의 top-3 실패를 주 프로그램이 전달한 근거의 실패로 옮길 수 없다.

원본 보고서는 문서 지표와 문단 지표를 구별했지만, 집계·융합 순서가 달라지는 점과 실제 반환 근거를 연결하지 않은 채 Q01에 대해 “dense·RRF는 악화”, “최종 3건을 고르려면 재순위화나 답변 단계가 따로 필요”라는 해석을 남겼다. 후속에서도 같은 해석을 유지했고 평가 단계는 두 번 승인했다. 이는 RRF의 일반 우열을 입증하지 않는다.

**제안:** 연구계획의 실험 명세에 색인 단위·후보 단위·집계/융합 순서·실제 사용자에게 전달되는 근거를 함께 묶는다. 평가자는 대표 실패 주장 하나를 실제 결과 행까지 내려가 대조한다. 다른 파이프라인의 보조 실험은 별도 방법으로 이름 붙인다. [증거의 L106_1](evidence.json), [주 프로그램](ai/base/run_experiment.py), [보조 분석](ai/base/analyze_passages.py).

평가의 추가 약점으로, 기본 보고서의 “약 15분”과 계획의 “15:08 갱신”을 평가자가 받아들였다. 실제 완료는 15:00:46이며 요청부터 약 7분 39초다. 작성자가 적은 시각보다 실행 영수증을 우선해야 한다. 현재 프로세스 전체를 무능하다고 결론 낼 근거는 아니지만 승인만으로 연구의 정확성을 보장하지 못하는 구체적 사례다.

### L106-2 — 코드·설정 고정만으로는 재현 환경이 고정되지 않음

기본 보고서가 제시한 `python3 -I run_experiment.py ...`를 운영자의 기본 Python 3.12.4에서 실행하자 라이브러리 import 오류로 dense·RRF 네 조합이 빠져 **24행**만 생성됐다. 동일 프로그램·설정·질문을 실제 실행에 사용된 저장소 `.venv` Python 3.13.5로 재실행하자 **48행**, skipped 0이었다. 최초 실패 출력도 보존했다. 알고리즘 성능 저하로 해석하지 않는다.

프로그램은 skipped를 표시했으므로 실패를 숨긴 것은 아니다. 다만 보고서의 재현 명령만으로 전체 실험을 복원할 수 없었다.

**제안:** 연구계획의 재현 조건에 인터프리터, 주요 라이브러리, 모델 revision·캐시 조건을 포함하고, 완료 조건에 예상 방법 수·행수와 skipped 점검을 둔다. 다른 셸에서 명령 한 번을 다시 실행한 영수증을 남긴다. 이번 [환경 관측](runtime_observed.json)은 사후 기록이며 실행 당시 모델 revision 영수증의 대체가 아니다.

### 범위를 좁혀야 할 주장과 훈련자 쪽 잔여

AI가 관측한 것은 이번 네 순위 방법이 판본·조건·없음을 직접 판정하지 못했다는 것이다. 이를 “검색을 바꿔도 해결되지 않는다”로 일반화하면 메타데이터 필터·다른 후보 회수·재검색 가능성을 배제한다. “이번에 시험한 순위 방법만으로는 판정되지 않았다”가 증거에 맞는 표현이다.

훈련자 파이프라인도 완전하지 않았다. `answerable=false`인 행만 원문을 다시 읽었기 때문에, Q02처럼 답은 있지만 설명이 불완전한 경우가 보완 대상에서 빠졌다. 재검토 조건에는 질문의 미해결 부분·근거의 충분성·limitation도 들어가야 한다. 이는 이번 훈련 프로그램의 선택 규칙 문제이며 제품 런타임 결함으로 보고하지 않는다.

## 훈련자의 전체 IBL과 재사용

`sources_v0 → retrieve_v0 → answer_v0 → followup`으로 자료 획득·원문 읽기·검색 부품 실행·모델 판단·저장·재독을 연결했다. 검색 계산만 Python 부품이다. 훈련자의 방법은 단어 BM25·문자 TF-IDF·두 문서 순위의 RRF이며, AI의 dense 혼합과 다른 실험이다. 같은 corpus·질문·상위 문서 3개를 사용했다.

- 기본·보류·변형마다 3방법×6질문=18행, 총 54행의 검색과 답변을 보존했다. 처음부터 모든 질문에 성공하지 않았다.
- Q03에서 정답 문서는 찾았지만 대표 문단이 제목에 그쳐 저장 위치를 못 답했다. 해당 문서 전체를 다시 읽자 계획 파일과 질문별 근거 저장을 구별해 답했다.
- 보류 H02(검색 부재 주장의 범위), H03(파일 결과와 IBL 연결)도 같은 보완 부품으로 답을 회복했다. H06의 임베딩 모델명은 근거가 없어 계속 미확인으로 남겼다. “읽은 후보에 없음”을 “전체 세상에 없음”으로 확대하지 않았다.
- Q04 30일→14일, Q05 조건과 새 기록 의무를 반영했다. Q06 월 비용은 기본·변형 모두 미확인이다.
- 변형 보완에서 Q03은 입력 문서 내용이 동일해 이전 판단을 재사용했다. Q06은 후보 S03이 바뀌어 새로 판단했고 여전히 미확인이었다. 실제 모델 호출은 1회, 경과 9.27초다. 더 큰 작업 전체의 비용 절감을 입증한 것은 아니다.
- Q02는 RRF 답에서 결론 “정상 종료만으로 완료 아님”은 맞지만 설명이 결과 파일 유효성에 머물렀다. 실제 업무 목표 달성의 확인이라는 핵심까지 충분히 설명한 성공으로 세지 않는다.

이번에 보존한 능력은 원문 회수·검색 비교·조건부 답변·불충분 근거 보완·입력 내용 대조를 통한 판단 재사용이다. [IBL v3](followup_v3.ibl)와 검색 부품을 다른 질문에서도 소비했다. 운영 어휘·관용구·등록 스크립트로 등록하거나 해마에 시딩하지 않았다. 낯선 다른 분야로의 전이는 미검증이다.

## 실패·수정·비용

훈련자 IBL 검사 7회 중 6회 통과, 1회 SYNTAX 거절. 실행 12회 중 11회 성공, 1회 TEXT_REQUIRED 실패다. 목록 포함을 문자열 contains로 쓴 v0를 `in`으로 고친 주기 1회, 변형 v2의 if 문법을 고친 주기 1회이며 같은 원인 반복 수리는 없었다. 최초 실패·진단을 보존했다. 보고용 증거 추출기에서도 items 봉투를 목록으로 가정한 오류 1회를 수정했다(제품/IBL 결함 아님).

AI는 기본 도구 호출 18회, 변형 18회였다. 변형의 is_error 3건에는 정상적인 diff 차이 종료 코드도 포함된다. 잘못된 `--input .../docs`로 문서 0개를 읽은 실제 실행 오류는 보고서에 공개하고 올바른 폴더로 재실행했다. 그 중간 결과 파일은 AI가 삭제하여 파일 자체는 남지 않았고, 호출 영수증·출력과 사고 서술은 남아 있다. 실패 산출물의 불변 보존은 다음 연구 절차에서 보강할 사항이다.

| 실행 | 요청→회수 | 입력 토큰(캐시 포함) | 출력 토큰 | cache_read | cache_create |
|---|---:|---:|---:|---:|---:|
| 시스템 AI 기본 ep5670 | 458.80초 | 2,039,588 | 43,119 | 1,718,518 | 317,845 |
| 시스템 AI 변형 ep5671 | 334.76초 | 2,177,595 | 32,922 | 1,897,820 | 275,387 |

시스템 AI는 의식·실행·분류·평가 전 역할의 billable_usage를 call_id·round_index로 중복 검사해 합산했다. cache 항목은 입력에 포함되므로 더하지 않는다. 전체 두 턴 입력 4,217,183·출력 76,041이다. 훈련자 IBL 9회는 모두 계측됐지만 이 보고를 작성하는 Codex 자체 비용과 직접 web 도구 비용은 알 수 없다. 역할별 지연 합은 벽시계 시간이 아니며, 훈련자와 AI는 방법·산출 범위가 달라 비용 우열 비교를 하지 않는다.

## 남은 검증과 다음 개선 방향

현재 구조를 교체해야 한다는 증거는 없다. 먼저 의식이 작성하는 계획에 **실험의 동일성·실제 근거 출력·재현 환경·반례를 만났을 때 결론 수정 기준**을 명시하고, 평가가 그 약속을 영수증과 결과 행에서 검사하도록 보강하는 것이 이번 관측에 맞다. 답이 불완전할 때 원문 재독·재검색으로 돌아가는 조건도 구체화할 수 있다.

이 제안은 아직 제품에 적용하거나 수리 후 재훈련하지 않았다. 자동 라우팅, 새 대화 격리, 장기 재시작 후 계획 회수, 다른 도메인 전이, 대규모 성능, 일반적 비용 절감은 미검증이다. AI 검색 프로그램의 `answer`는 모든 행에서 null이다. 후속의 14일·미확인은 AI가 원문을 읽고 한 판단이며 자동 답 생성기의 성능으로 세지 않는다. 보류 실행 역시 고정된 검색 프로그램의 외부 재실행이고 새로운 AI 대화의 추론 시험은 아니다.
