# 훈련자 사전 연구계획

목적: 개인 문서 질문에서 필요한 근거를 찾는 방식을 비교하고, 성능 차이의 이유와 적용 범위를 확인한다. 사용자 기준은 근거 있는 선택과 재실행 가능성이며 특정 방식의 승리가 아니다.

1. 질문: 정확한 용어·다른 표현·여러 근거·판본·조건 충돌·답 없음에서 기준 검색이 어디서 실패하는가. 현재 문서12개·개발질문6개를 사용하고 보류질문6개는 설정 고정 후 평가한다.
2. 먼저 확인할 방법: BM25 같은 단어 기반 검색, 문자 ngram 기반 TF-IDF, 순위 결합, 의미 임베딩. 1차 연구 또는 공식 문서에서 작동 원리와 일반화 한계를 읽는다. 사전 기대는 한국어 띄어쓰기·조사 차이에 문자 부분일치가 도움이 될 수 있다는 가설이며 사실로 확정하지 않는다.
3. 실행 선택: 현재 로컬 환경에서 구현·재실행 가능한 기준과 대안을 선정한다. 동일 문단 분할과 같은 상위3개 문서 기준으로 비교한다. 형태소 분석·임베딩 등 사용하지 못한 수단은 미실험으로 남긴다.
4. IBL 연결: 자료·질문 읽기 → 공개 원문 수집·근거 보존 → 부품 검색기 작성·문단검색 → 동일 입력의 방법별 결과 합류 → 같은 생성 지시로 답변·인용 판단 → 저장과 재독. 방법 판단 뒤 다음 프로그램으로 이어도 전체 입출력 참조를 남긴다.
5. 판정: 검색의 필수 근거 포함과 답변의 의미 정확성·판본·기권을 나누고 실패 사례를 보존한다. 작은 표본이며 설정 최적화·통계적 우열 주장은 하지 않는다. 보류질문 정답은 평가 시에만 사용한다.
6. 변형: 합성 규정과 자료 모드가 갱신되면 입력 해시를 확인하고 검색을 새 판본에 수행한다. 기간은 새 판본의 14일로 바뀌고 비용·모델명 등 없는 답은 계속 미확인이다. 이는 훈련자만 알고 있는 기대값이며 AI에는 주지 않는다.
7. 멈춤: 15:50:36 KST 전체 상한. 자료 접근 실패는 다른 경로를 한정 시도하고 실험된 범위로 결론을 좁힌다. 라이브 제품·평가 기준·프롬프트를 고치지 않는다. 표본 차이가 결론을 바꾸지 못하면 우열 유보가 가능하다.

훈련자는 정답과 시스템 구현 일부를 알고 있어 독립성 조건이 AI와 다르다. 이 계획은 외부 훈련자가 작성한 것으로 의식 에이전트의 실제 사전계획 성공 증거가 아니다.
