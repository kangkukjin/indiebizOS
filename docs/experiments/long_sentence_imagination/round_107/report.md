# 107회차 — 의식의 문제규정·목적·연구계획 품질

정본 저장소에서 훈련을 완료했다. **의식은 여러 종류의 요청에서 목적과 연구 방법을 구별했지만, 최종 지시의 전제·제약 일관성과 맥락 복원 뒤 계획 작성 책임에는 개선할 문제가 남았다.** 제품 코드·프롬프트·가이드·모델 설정은 바꾸지 않았다.

사용자가 집중하도록 지정한 범위에 맞춰 실제 의식의 문제규정과 연구계획 작성·저장까지만 실행했다. 연구 실행자와 평가자는 호출하지 않았다. 따라서 이 보고서는 계획 품질의 관측이며 실제 연구 성공률이나 수리 효과의 증명이 아니다.

## 무엇을 시험했는가

심층연구 가이드와 현재 의식 경로를 읽고, 모델 호출 전에 [요청 10개와 사례별 확인 조건](cases.json)을 고정했다. 기본 요청 8개와 C05에서 각각 독립적으로 분기하는 후속 2개다. 영상 제작은 넣지 않았다. 운영자 확인 조건·판정·수정안은 모델에 전달하지 않았다.

실제 `ConsciousnessAgent.process → Supervisor.plan → research_planning.prepare/persist`를 사용했다. 현재 설정은 의식 고급 `claude_code/opus`였다. 모든 에피소드는 `training`으로 기록됐으며, 각 모델 호출은 별도 세션을 사용했다. 기본 사례는 빈 대화 이력, 후속은 사용자 요청·이전 의식 출력·저장 계획 영수증을 받았다. 실행자 도구는 연결하지 않았고 관측된 모델 도구 호출은 0건이다.

## 확인한 개선 대상

### L107-1 — 계획 본문이 정정돼도 다른 지시에 잘못된 전제가 남는다

C01의 입력은 “최근 6개월 매출이 전년 같은 기간보다 30%” 줄었고 경쟁점은 2개월 전에 열렸다는 것이다. 월별 실제 수치와 감소 시작 시점은 주어지지 않았다. 초기 규정은 이 시차만으로 경쟁점 단독 원인 가설이 성립하기 어렵다고 보았다.

가이드를 받은 뒤 작성한 [계획 본문](results/C01/research_plan.md)은 합계라는 점을 구별하고, 이전 매출이 월별로 같다는 가정 아래 마지막 두 달에 90% 감소하면 전체 30% 감소가 가능하다고 조건부로 계산했다. 그러나 [최종 규정의 `expert_choice`](results/C01/framing.json)에는 여전히 **“개점 시점과 감소 시작 시점이 어긋나는데도”**라는 단정이 남았다.

논리적 반례는 간단하다. 전년도 여섯 달이 `[100,100,100,100,100,100]`일 때 이번 여섯 달이 `[100,100,100,100,10,10]`이면 합계는 30% 감소하지만 개점 전 감소는 없다. `[60,60,60,60,90,90]`도 합계는 30% 감소하며 이번에는 개점 전 감소가 있다. 같은 입력으로 두 경우가 모두 가능하다. 이는 실제 원인을 밝힌 계산이 아니라 **시점 단정이 입력으로부터 나오지 않는다는 증명**이다. [계산과 결과](counterexample.json).

실제 `compile_user_command`로 최종 규정을 조립하자 문제의 문장이 실행자 입력에 포함됐다([전달 확인](handoff_probe.json)). 원래 요청·실제 관측과 대조하라는 보호 지시도 함께 존재한다. 따라서 실행자가 반드시 틀린다고 결론 내리지는 않는다.

**개선 방향:** 계획 완성 시 계획 본문만이 아니라 문제규정·전문가 주의점·가정·달성 기준을 함께 대조해야 한다. 관측 기간과 변화 시작 시점을 구별하고, 본문에서 정정한 전제는 이를 사용하는 다른 지시에서도 정정해야 한다. 현재 경로는 첫 규정 이후 가이드를 공급해 계획을 완성한다. C01에서는 그 두 번째 호출이 본문을 보완했지만 다른 필드의 전제까지 정정하지 못했다. 소유 위치는 의식의 최종 규정과 계획 완성 단계다. 별도의 평가 AI를 추가해야 한다는 근거는 아니다.

### L107-2 — 제약 설명과 실제 후보 탈락 조건이 다르다

[C02 계획](results/C02/research_plan.md)은 원본 사진의 외부 업로드 금지와 프록시·메타데이터의 허용 여부를 구별한다. 미확인 부분에 대해 “확인 전까지 클라우드 계열은 '조건부'로만 기록한다”고 적었다. 그런데 Q2의 통과/탈락 필터는 **“완전 로컬 운영 가능 여부”**다.

이 둘은 동일한 조건이 아니다. 원본을 로컬에 보존하면서 별도 허용된 정보만 외부에서 쓰는 후보를 선행 확인 없이 탈락시킬 수 있다. 실제 후보 조사·탈락은 실행하지 않았으므로 관측 범위는 계획 내부의 조건 불일치다.

**개선 방향:** 후보를 제외하는 조건마다 사용자 제약의 대상·행위·기간·강도를 그대로 이어야 한다. 미확인 권한은 조건부 후보로 남기고, 탈락 조건에 더 강한 금지를 암묵적으로 넣지 않아야 한다. 이 원칙은 이미 현 가이드에 있다. 이번 발견은 규칙 부재가 아니라 최종 계획에서 적용이 일관되지 않은 사례다.

### L107-3 — 맥락 복원 뒤 의식의 계획 작성으로 돌아가는 연결이 없다

[C08 규정](results/C08/framing.json)은 없는 제안·목적·조건을 발명하지 않았다. 현재 입력에 없다는 이유로 과거 기록까지 없다고 단정하지 않고, 과거 대화·기억에서 먼저 복원한 뒤 부족한 내용만 요청하도록 했다. 이 점은 사전 내용 보존 조건을 충족했다.

그러나 `deep_research=false`로 반환되어 가이드 공급·계획 저장이 일어나지 않았고, 실행 지시는 맥락 세 가지가 모두 확인되면 **“계획서를 작성한다”**고 이어진다. 의식의 연구계획 작성·저장 단계로 돌아오라는 연결은 없다. 현 가이드는 최초 연구계획의 작성자를 의식으로 정하고 있다.

**개선 방향:** 자료가 없어 현재 계획을 유보하는 것과 계획 작성 책임을 실행자에게 넘기는 것을 구별해야 한다. 실행자가 맥락을 회수했다면 원문과 미확인을 의식에 돌려보내고, 의식이 연구계획을 작성·저장한 뒤 전달하도록 후속 행동을 명시하는 것이 맞다. 처음부터 내용을 꾸며 계획을 강제로 쓰거나, 모든 누락에 사용자 질문을 요구하자는 뜻은 아니다.

이는 **현재 지시의 소유권 불일치**에 대한 판정이다. 실제 기억 조회·실행자·재규정은 호출하지 않았으므로, 실행자가 일반 재규정 기능으로 스스로 보완했을 가능성은 미검증이다. 내용 보존 checks는 모두 충족했고, 부분 판정은 별도로 현재 가이드의 작성·저장 계약을 대조한 결과다.

### L107-4 — 익명화의 일반화 예시가 사실 범주를 바꾼다

[C04 계획](results/C04/research_plan.md)의 익명화 예시는 **“'50대 자영업자' 대신 '중년 직장인'”**이다. 연령 범위를 넓히는 것과 직업·고용형태를 바꾸는 것은 다르다. 생활 조건을 해석하는 연구에서 익명화가 원자료의 의미를 바꿀 수 있다.

이는 계획의 한 예시에 국한된 결함이다. 실제 인터뷰를 변경한 것이 아니고, 경험 이해라는 목적이나 질적 접근 전체가 잘못됐다는 판정도 아니다. 일반화는 포함 관계를 지켜야 하며, 의미를 보존하기 어렵다면 해당 세부를 생략하거나 더 넓은 실제 상위 범주를 써야 한다. 우선순위는 앞의 세 문제보다 낮다.

## 잘된 부분과 그 의미

역사 설명에서는 숫자를 평균하는 대신 정의·시점·단위·출처 관계를 따져 보도록 했고, 경험 이해에서는 이탈자 사례를 모집단 이탈률로 바꾸지 않았다. 백업 검증에서는 현재 코드가 그럴듯한 것과 당시 파일이 보존됐다는 것을 구별했다. 서로 다른 질문에 같은 ‘검색·비교·보고’ 틀만 붙이지는 않았다.

열린 탐색의 목적 보존(C05), 같은 목적 아래 질문 구체화(C09), 사용자가 명시한 목적 전환(C10)도 구별했다. C09는 비참여와 외로움을 별도 축으로 두고, 현재 자료로 답할 수 없는 질문을 억지로 채우지 않도록 했다. C10은 이전 목적을 강요하지 않고 운영안 선택에 필요한 시간·비용·참여 부담을 연결했다.

따라서 현재 관측만으로 목적 규정 능력 전체가 부족하거나 더 강한 모델이 반드시 필요하다고 말할 근거는 없다. 먼저 개선할 것은 **원래 요청 → 최종 규정 → 계획의 판단 규칙 → 실행 지시 사이의 일관성**이다. 가이드에 문장을 더 추가하는 것만으로 해결될지도 아직 입증되지 않았다.

## 하네스 수정과 비용

처음 후속 두 사례는 새 사례 폴더를 작업공간으로 지정해 C05 저장 계획이 허용 루트 밖으로 판정됐다. 모델은 대화 이력의 계획 내용을 받았지만 파일을 정상 계승하지 못했다. 이 두 시도를 제품 결함이나 유효한 후속 시험으로 세지 않았다.

하네스의 후속 작업공간만 C05와 같게 고쳐 동일 요청을 각각 다시 실행했다. 원본 시도는 [invalid_attempts](invalid_attempts/)에, 정정된 시도는 `results/C09`, `results/C10`에 보존했다. 프롬프트·가이드·모델·판정 조건은 바꾸지 않았고 운영자 평가도 주지 않았다. 수정 주기는 하네스 1회, 제품·교재 수리 0회다. [상세 경위](harness_notes.md).

입력에는 캐시가 포함되며 캐시를 다시 더하지 않는다. reasoning 계측 17,991도 출력에 다시 더하지 않는다. 전체 22회 모두 시스템 모델 사용량이 계측됐다. 훈련자 Codex 자체 토큰·금전 비용은 미상이다. 비용 절감 전후 비교는 수행하지 않았다. 준비·호출·진단·보존 시간은 [완료 기록](completion.json)에 구분한다.

## 검증 범위와 다음 비교

- 기본 입력과 가이드·의식 프롬프트·관련 코드 지문을 시작/종료에 대조했다. 제품 소스는 불변이다.
- 연구 사례 8개는 각각 가이드 공급 후 의식 계획 저장을 확인했다. C07·C08은 가이드·계획 없음, 각각 호출 1회였다. 문서 저장의 성공과 내용 품질은 별도로 판정했다.
- 후속 2개가 C05 실제 저장본을 읽고 새 판본을 만들었으며, C05 원본이 바뀌지 않았음을 확인했다. C10의 `previous_path`는 제공된 이전 계획의 계보를 가리키지만 본문은 별도 연구임을 명시한다.
- 자동 기억 회수, 실제 채팅의 연구 주제 자동 결속, 무의식의 의식 호출 판단, 실행자의 조사·자기수정, 평가자의 승인은 시험하지 않았다. 실행자 도구 카탈로그도 빈 목록인 분리 환경이므로 운영 환경의 계획 행동과 차이가 있을 수 있다. 각 유효 사례는 1회 출력이므로 재현 빈도·확률은 미상이다.
- 문헌·통계·가격·법률·복원 도구의 실제 타당성을 조사하지 않았다. 계획에 적힌 출처·방법은 조사 예정 항목이지 이번 훈련에서 확인한 근거가 아니다.

개선안을 적용한다면 기존 사례에 맞춘 문구 추가만 시험하지 말고, 아직 사용하지 않은 집계/시점·부분 허용/조건부 후보·맥락 부재 요청으로 비교해야 한다. 같은 요청 충실도·최종 지시 일관성·실행자가 처음 해야 할 행동을 확인하면서 전체 입력/출력과 완료 시간을 함께 측정한다. 현재는 **결함 발견과 수정 방향 제안까지 완료**, 개선 효과는 미검증이다.
