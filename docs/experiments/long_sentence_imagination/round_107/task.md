# 107회차 과제 — 의식이 요청을 연구로 바꾸는 품질

사용자 요청은 심층연구 가이드에 따라 의식이 문제를 규정하고 목적·연구계획을 작성하는 능력을 여러 요청에서 확인하는 것이다. 106회차의 검색 실험은 반복하지 않는다. 이번에는 계획 단계까지만 검사하므로 긴 IBL 전체 업무 및 실행자·평가자 호출을 생략한다. 이 범위는 사용자의 명시적인 집중 요청에 따른다.

모델 호출 전에 cases.json의 8개 기본 요청과 2개 후속 요청, 사례별 기대 조건을 고정했다. 원인 분석·대안 비교·역사 설명·경험 해석·열린 탐색·시스템 검증·단순 설명·핵심 맥락 부재를 포함한다. C09와 C10은 각각 C05에서 독립적으로 분기한다. 사용자 요청과 앞선 모델 산출물만 후속에 전달하며 운영자 판정은 전달하지 않는다.

실제 ConsciousnessAgent.process → Supervisor.plan → research_planning.prepare/persist를 호출한다. 사용자 채팅의 분류·기억 자동 회수·실행·평가 전체 경로는 아니다. 기본 사례는 독립 신원·빈 대화 이력, 후속은 명시된 이력과 실제 이전 계획 영수증을 사용한다. 같은 프로세스에서도 모델은 매 호출 별도 세션을 사용한다. 운영자 기대 조건은 모델 입력에서 제외한다.

사전 판정 축: (1) 요청·제약 보존, (2) 관측·가설·미확인 구분, (3) 전체 목적과 이번 범위, (4) 질문에 맞는 증거·방법, (5) 증거 충돌·종합, (6) 첫 행동·부족할 때 다음 행동, (7) 멈춤·산출물·평가 기준의 일치. 사례별 checks는 반드시 지켜야 할 핵심이며 특정 방법명·목차·글자 수는 합격 요건이 아니다. 기본 비연구·맥락부재 요청에는 불필요한 계획 생성 여부를 본다.

판정은 충족/부분/미달/미검증으로 하고 정확한 원문 근거를 남긴다. 구조 검증 통과와 계획의 의미적 품질을 구분한다. 계획에 쓰인 내용의 존재와 실제 연구 성공을 혼동하지 않는다. 서술의 과도한 확장·사용자 조건의 약화·필요한 질문의 누락도 검토한다. 방법의 실제 효과는 조사하지 않으며 계획 품질 관측만 보고한다.

훈련은 origin=training. 모델은 현재 의식 설정을 그대로 사용한다. 제품 코드·프롬프트·가이드·모델 설정을 수정하지 않는다. 실행자 도구는 연결하지 않으며 계획 저장만 회차의 outputs 하위에 한다. 감독의 계약/증거 읽기 시도와 실패도 기록한다. 이전 중단 전은 읽기·설계만 있었고 이번 실제 회차는 16:39:33 시작, 17:39:33 상한이다.
