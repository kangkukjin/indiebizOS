# 초기 시도와 판본 정리

초기 R01/R02를 시작한 뒤 가이드가 36,558바이트로 기존 36,000바이트 상한을 넘은 것을 확인했다. 107회차 가이드는 35,967바이트였다. 새 지시를 삭제하거나 상한을 늘리지 않고 도입·저장 순서의 중복 설명을 압축했다. 압축 과정의 크기는 36,147→36,009→35,992바이트였다. 초기 두 시도의 가이드는 preliminary_guide.md, 실제 입력·결과는 outputs/R01·R02에 보존한다. 모델의 결과 내용에 따라 판본을 선택한 것이 아니다.

최종 시험은 모든 사례를 _final 폴더에 새로 수행한다. 크기 확인이 실패한 셸에서도 후속 명령이 시작되어 R01_final·N01_final의 초기 규정 호출이 먼저 시작됐다. 실제 입력을 확인하니 R01_final의 계획 완성에는 36,009바이트 판본이 들어갔다. 최종 35,992바이트와의 차이는 도입의 “이 가이드는 ” 17바이트 삭제뿐이며 새 지시를 포함한 나머지는 바이트 단위로 동일하다. 이 실제 판본도 r01_guide.md로 보존한다. N01_final부터는 최종 판본이며 전건 입력의 지문을 대조한다. 초기 규정에는 연구 가이드가 들어가지 않는다. 초기 4호출 비용도 전체에 포함한다.

후속 작업공간과 이전 계획 읽기는 모두 이전 _final 폴더에 맞췄다. R03에서는 최초 결과를 그대로 보존하고 합성 복원 자료로 실제 재규정 경로만 추가 호출한다. 실행자가 스스로 기억을 찾고 재규정을 선택했다는 주장과 구분한다.

복원 연결의 최초 실행은 reframe으로 의식이 계획을 쓰고 저장하는 데 성공했지만, 시험 어댑터가 revision의 previous_research_plan을 process의 같은 인자로 넘기지 않아 previous_path가 비었다. 제품의 cognitive_consciousness.py:130~151은 이 인자를 전달한다. 원본 recover_context_v0.py와 R03_final 결과를 보존하고 어댑터만 맞춘 뒤 R03_relinked에서 원래 초기 규정·동일 원문으로 재규정 부분만 다시 호출한다. 실제 자동 기억 회수·방아쇠 선택은 여전히 미검증이다.
