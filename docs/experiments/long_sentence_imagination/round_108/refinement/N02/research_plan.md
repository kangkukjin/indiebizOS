# 주민회의 녹음 의제별 검색 방식 비교 — 연구계획 (초안)

상태: 계획 작성 단계. 자료 조사·후보 검색·샘플 시험은 시작하지 않았다. 이 문서의 서비스 범주·지표·기준 수치는 모두 잠정 설계 또는 제안값이며 확인된 사실이 아니다.

## 1. 목적과 현재 질문

- **목적:** 주민회의 녹음 약 60시간에서 특정 의제(예: 주차, 관리비, 공사 일정)에 관한 발언을 빠짐없이 정확하게 찾고, 찾은 결과에서 원본 녹음의 해당 시점으로 되돌아가 확인할 수 있는 운영 방식을 다음 분기에 고른다.
- **이번 연구가 답할 질문:** 사용자 조건을 지키는 후보 가운데, 우리 회의 자료에서 의제 검색 정확도와 원문 추적성이 충분하고 월 3만 원 안에서 운영 가능한 방식은 무엇인가. 어떤 조건이면 그 판단이 바뀌는가.
- **답의 형태:** '방식 A를 권고하되 조건 X를 지킨다', '두 방식이 구분되지 않으므로 비용·부담으로 고른다', '필수 정보가 없어 보류한다' 같은 조건부 권고다. 결론을 미리 정하지 않는다.
- **다음 분기:** 2027년 1분기로 잠정 해석한다(U6에서 확인).

## 2. 사용자 조건과 계획에서의 해석

| 사용자 조건 | 적용 대상 | 계획에서의 처리 |
| --- | --- | --- |
| 녹음 원본 외부 업로드 금지 | 음성 파일과 그 일부 구간 | 클라우드 음성인식은 후보에서 제외한다. 전사는 로컬에서 한다. |
| 검토 마친 비식별 전사문은 외부 분석 서비스 가능 | 검토 완료 전사문만 | 검토 전 전사문과 실명↔가명 대조표는 외부로 보내지 않는다. |
| 이번 달 유료 계약 금지, 공개 설명과 샘플로 비교 | 2026-11 중 비교 활동 | 결제 정보 입력이나 자동 갱신이 필요한 체험은 쓰지 않는다. 결제 없는 무료 등급에 비식별 샘플을 넣는 것은 잠정 허용으로 보되, 무료 계정 가입 자체의 허용 여부는 U7로 확인한다. |
| 다음 분기 운영비 월 3만 원까지 | 반복 운영비 | 판정 기준으로 쓴다. 부가세·환율 포함 여부, 일회성 장비비·인력 시간의 포함 여부는 U6로 확인한다. |
| 로컬과 비식별 전사문 클라우드 모두 후보 | 후보 범위 | 두 범주를 같은 샘플·질의·지표로 비교한다. |
| 정확하게 찾기, 원문 근거로 돌아가기 | 평가 기준 | 두 기준을 핵심 지표로 둔다(7절 Q3). |

이번 달 무료로 시험할 수 없는 후보(로컬·클라우드 모두)는 탈락시키지 않는다. '공개 설명 기반·미시험'으로 표시하고 다음 분기 초 시험 후보로 남긴다. 기간 제한은 시험 보류의 이유이지 후보 탈락의 근거가 아니다.

## 3. 데이터 흐름의 경계

원본 음성(로컬) → 로컬 전사: 구간 ID·시작/끝 시각·화자 표시 → 사람의 비식별 검토(로컬) → **[외부 허용 경계]** → 로컬 색인 또는 클라우드 서비스 → 검색 결과(구간 ID·시각) → 로컬 대응표 → 원본 음성의 해당 시점 재생

설계 요구:
- 비식별 처리 뒤에도 구간 ID와 시각을 바꾸지 않는다. 그래야 클라우드 결과도 로컬 원본으로 되짚을 수 있다.
- 구간 ID → 원본 파일·시각 대응표와 실명↔가명 대조표는 로컬에만 둔다.
- 같은 인물·장소에는 일관된 가명을 쓰면 검색 품질 손실이 줄어들 수 있다. 이는 Q4에서 확인할 가설이며 이번 계획의 전제가 아니다.

## 4. 출발점과 미확인 사항

확인된 것: 녹음 분량(약 60시간, 사용자 진술), 2절의 조건. 그 밖의 사항은 아직 확인하지 않았다.

| ID | 미확인 사항 | 확인 주체 | 판단에 미치는 영향 |
| --- | --- | --- | --- |
| U1 | 전사가 이미 있는지, 형식(타임스탬프·화자 유무), 전사 도구 | 사용자 | 전사가 없으면 로컬 전사가 별도 하위 과제가 된다. 범위 변경이므로 재규정한다. |
| U2 | 비식별 검토의 기준·담당·녹음 1시간당 소요 | 사용자 | 클라우드 후보의 실제 운영 부담과 이번 달 샘플 준비 가능 여부 |
| U3 | 로컬 장비 사양(메모리·GPU·저장공간) | 사용자 또는 실행자의 로컬 점검 | 로컬 임베딩·로컬 언어모델 후보의 실행 가능성 |
| U4 | 의제 목록·안건지·회의록이 있는지 | 사용자 | 정답 구간 표시와 질의 세트 작성의 기준 |
| U5 | 누가 어떤 질문으로 찾는지(예: 특정 안건의 모든 논의, 결정·표결 결과, 특정 기간의 발언) | 사용자 | 질의 유형 구성과 지표 비중 |
| U6 | 다음 분기의 정의, 3만 원에 포함되는 항목, 녹음의 월 증가량 | 사용자 | 비용 판정 |
| U7 | 결제 없는 무료 등급 계정 가입이 허용 범위인지 | 사용자 | 이번 달 클라우드 샘플 시험의 가능 여부 |

U1·U2·U7은 이번 달 시험 범위를 바꾸므로 먼저 확인한다. 답이 없으면 7절과 9절의 축소 경로를 따른다.

## 5. 접근과 선택 이유

- 이 연구는 '무엇을 도입하는 것이 적합한가'에 대한 판단이다. 공개 설명만으로는 한국어 구어 회의록에서의 검색 품질을 알 수 없으므로, 후보 지도(공개 설명)와 같은 과제 시험(샘플)을 연결한다. 제품 기능 비교표 하나로 대신하지 않는다.
- 평가 방법은 정보검색의 표준인 시험 모음 방식(질의 세트와 사람이 미리 정한 정답 판정)을 녹음 전사문 구간 단위로 적용한다. 정답은 시스템을 돌리기 전에 정해, 결과를 보고 정답을 맞추는 편향을 막는다. 음성 기록 검색에 맞춰 정답 일치는 시각 허용 범위(제안값 ±30초)로 판정한다.
- 적용 한계: 질의 수십 개 규모의 소표본이다. 통계적 우열 확정보다는 질의별 비교와 실패 유형 분석이 중심이 된다. 정식 체계적 문헌고찰은 하지 않는다. 음성인식 오류가 검색에 주는 영향에 대한 선행 연구는 예비 조사에서 범위만 확인하고, 우리 자료에서 Q5로 직접 확인한다.

## 6. 후보 범주 (잠정)

구체 제품·도구 이름과 링크는 예비 조사(Q2)에서 채운다.

- **로컬:** L1 키워드 전문 검색(한국어 형태소 분석 포함), L2 로컬 임베딩 의미 검색, L3 키워드+의미 하이브리드, L4 로컬 언어모델로 의제 태깅·요약하고 근거 구간을 연결하는 방식
- **클라우드(비식별 전사문만):** C1 문서 업로드형 질의응답 서비스(출처 인용 표시 기능 여부 확인), C2 범용 언어모델 서비스의 파일 첨부 질의, C3 관리형 검색·벡터 검색 API
- **혼합:** 로컬 색인으로 후보 구간을 찾고 비식별 구간만 클라우드에서 재정렬·요약하는 방식
- **제외:** 원본 음성을 외부로 보내는 모든 방식(클라우드 음성인식 포함)

## 7. 핵심 질문과 조사 방법

### Q1. 현재 자료 상태와 실제 사용 장면은 어떠한가
- 증거: 사용자 답변(U1~U7), 로컬 전사 파일 표본의 형식 점검(조사 착수 후)
- 판단: 전사·타임스탬프·비식별본이 준비된 정도에 따라 이번 달 시험 범위를 정한다.
- 부족할 때: 전사가 없으면 비교 범위를 '전사 계획 + 검색 방식 공개 비교'로 줄이고 재규정한다. 비식별본이 없으면 클라우드 시험을 보류하고 로컬 시험만 한다.

### Q2. 후보별 공개 설명은 필수 조건을 충족하는가
- 증거: 각 후보의 공식 문서·요금 페이지·약관과 개인정보 처리방침의 해당 조항. 확인할 항목은 데이터 보관 기간, 학습 사용 여부와 거부 방법, 삭제 방법, 저장 지역, 한국어 지원, 출처·구간 인용 표시, 파일 수·크기 한도, 무료 등급의 결제 정보 요구 여부다.
- 확보: 원 제공자 문서를 우선한다. 각 항목에 URL·확인일·열람 범위(요금표 본문, 약관 특정 조항, 검색 요약만)를 기록한다. 가격은 확인일의 환율과 부가세 포함 여부를 함께 남긴다.
- 판단: 필수 조건별로 충족·불충족·미확인으로 분류한다. 공개 설명은 기능의 존재를 보여 줄 뿐이며 검색 품질의 근거로 쓰지 않는다.
- 부족할 때: 정책이 불명확하면 해당 후보의 클라우드 사용을 '미확인'으로 두고 시험 대상에서 뺀다. 이는 탈락이 아니다.

### Q3. 같은 샘플·같은 질의에서 정확도와 추적성은 어떠한가
- 샘플(제안값): 비식별 검토를 마친 회의 3~5회분(약 4~6시간). 의제가 다양한 회의를 고른다.
- 질의 세트(제안값 20~40개): 명시 안건, 여러 회의에 흩어진 의제, 다른 표현(구어·약칭·사투리), 가명으로 치환된 고유명사 관련, 결정·표결 결과 찾기를 섞는다. U5의 실제 사용 장면을 반영한다.
- 정답 구간: 시스템을 돌리기 전에 사람이 로컬에서 표시한다(구간 ID·시작/끝 시각). 가능하면 두 사람이 일부를 겹쳐 표시해 판정 불일치를 확인한다.
- 정확도 지표: recall@10, 정밀도@5, 의제 전체 정답 구간 중 회수 비율
- 추적성 지표: 결과가 구간 ID 또는 시각을 제시하는 비율, 제시된 시각이 정답과 허용 범위 안에서 일치하는 비율, 생성형 답변의 주장별 근거 지지율(인용 구간이 실제로 그 내용을 담는가)과 인용 없는 주장 비율
- 실행 조건: 모든 후보에 같은 샘플·질의·판정 기준을 쓴다. 클라우드 후보는 결제 없는 범위에서만 시험한다. 시험 날짜, 후보 판본·설정을 기록한다.
- 부족할 때: 시험 가능한 클라우드 후보가 없으면 로컬 시험과 클라우드 공개 설명 비교로 나누어 보고한다. 성능 비교는 결론을 유보한다.

### Q4. 비식별 처리는 검색 품질을 얼마나 바꾸는가
- 방법: 로컬에서만 같은 질의를 비식별 전·후 전사문에 각각 실행해 Q3 지표를 비교한다(비식별 전 자료는 외부로 보내지 않는다).
- 판단: 손실이 크면 클라우드 후보는 구조적으로 불리하다. 일관된 가명 같은 비식별 방식 조정이 대안인지 검토한다.

### Q5. 실패의 주원인은 검색 방식인가 전사 오류인가
- 방법: Q3에서 실패한 질의의 정답 구간을 원본 음성과 대조(로컬 청취)해, 핵심어 전사 오류가 있는 비율을 센다.
- 판단: 실패 대부분이 전사 오류면 서비스 교체보다 전사 품질·용어 사전 개선이 우선이라는 결론으로 바뀐다.

### Q6. 다음 분기 운영비와 운영 부담은 기준 안에 드는가
- 방법: 60시간과 월 증가량(U6)을 가정으로 명시하고, 후보별 월 비용을 공개 요금에서 계산한다. 비식별 검토 인력 시간과 로컬 유지 작업도 함께 적는다(금액 기준 포함 여부는 U6에 따른다).
- 판단: 월 3만 원 이하 충족·불충족·미확인. 사용량에 따라 기준을 넘을 수 있으면 넘는 조건을 적는다.

## 8. 종합과 판정 규칙

1. **필수 조건 필터:** 원본 외부 전송 없음, 비식별본만 외부, 데이터 정책 확인됨, 월 3만 원 이하, 결과→원본 시각 추적 가능. 미확인 항목이 있는 후보는 조건부로 남긴다.
2. **품질 비교:** 필수 조건을 통과한 후보끼리 질의별로 짝지어 비교하고, 평균과 함께 질의별 우열·실패 유형을 보고한다. 차이가 소표본의 불확실성 안이면 '구분 불가'로 판정하고 비용·운영 부담·추적성으로 고른다.
3. **추적성 우선:** 정확도가 높아도 근거 구간을 제시하지 못하거나 인용 지지율이 낮은 후보는 권고하지 않는다. 기준 수치는 제안값으로 두고 사용자와 조정한다.
4. **근거 충돌:** 공개 설명과 샘플 결과가 다르면 우리 자료에서는 샘플 결과를 우선하되 샘플 범위를 넘겨 일반화하지 않는다.
5. **산출 형태:** 후보별 비교표(필수 조건, 지표, 근거 위치, 열람 범위, 시험 여부), 권고안과 대안, 판단을 바꿀 추가 관측(예: 더 큰 질의 세트, 유료 등급 시험)

## 9. 진행 순서와 멈춤

- **0단계(현재):** 계획 저장. 이번 요청은 여기서 끝난다.
- **1단계(사용자 요청 시):** U1~U7 확인, Q2 예비 조사로 후보 명단과 공개 문서 정리. 이 결과로 6절 후보와 7절 샘플 규모를 보완한다.
- **2단계:** 로컬에서 질의 세트와 정답 구간 작성
- **3단계:** Q3~Q5 시험(이번 달 안, 결제 없는 범위)
- **4단계:** Q6 비용 정리와 8절 종합, 권고 작성

멈춤과 방향 전환:
- 필수 조건을 통과한 후보 중 하나 이상이 정확도·추적성 기준을 충족하고 비용이 확인되면 권고하고 멈춘다.
- 비식별 샘플이 준비되지 않았거나 무료로 시험 가능한 클라우드 후보가 없으면, 로컬 시험과 공개 설명 비교로 멈추고 클라우드 시험은 다음 분기 초로 보류한다.
- 전사가 없으면 전사 계획을 먼저 세우도록 재규정한다.
- 추가 질의·후보를 늘려도 권고가 바뀌지 않으면 확인 범위와 한계를 밝히고 멈춘다. 이번 달이 끝나 시험을 마치지 못한 부분은 충족이 아니라 미시험으로 표시한다.
