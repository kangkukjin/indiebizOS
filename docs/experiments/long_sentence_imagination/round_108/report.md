# 108회차 — 의식·연구 가이드 수정 뒤 계획 품질 재시험

의식 프롬프트와 심층연구 가이드를 수정하고 실제 의식 모델로 계획 작성 훈련을 다시 했다. **제약의 범위와 계획 작성 책임에서는 개선을 관측했지만, 집계에서 세부 사실을 추정하는 오류는 재발했다.** 프롬프트·가이드 보완이 필요했던 것은 맞으나 그것만으로 계획의 추론 타당성이 보장되지는 않는다.

사용자가 지정한 범위에 따라 연구의 문제규정·목적·연구계획 작성과 저장을 시험했다. 실제 연구 실행·평가자 승인은 수행하지 않았다. 영상 제작 사례는 쓰지 않았다.

## 제품에서 바꾼 것

변경 소유자는 의식의 규정과 계획 작성 지침이며 제품 변경은 두 Markdown 파일이다. 모델·평가자·스키마·하네스의 단계는 추가하지 않았다.

가이드의 중복 도입·저장 설명을 압축해 기존 36,000바이트 상한을 유지했다. 최종 35,985바이트다. 계획 작성 전 저장, 의식/실행자 역할, 사용자 요청 범위와 승인 절차는 유지했다. 상시 의식 프롬프트는 수정 시 다시 읽고 가이드는 계획 준비 때 읽는 기존 경로이므로 백엔드 재시작이 필요하지 않다.

## 비교 설계

107회차 실패 요청 3개를 R01~R03으로 다시 쓰고 새로운 6개 요청 N01~N06을 먼저 고정했다. 첫 수정의 9개 출력에서 잔여 결함을 확인한 후 원인별 지시를 보완했다. 그 뒤 R01·N01·N02·N03·N04와 새 평균/집단 요청 N07을 고정하여 별도 6개 재시험을 했다. 원래 사례·결과·기준은 덮어쓰지 않았다.

실제 `ConsciousnessAgent.process → Supervisor.plan → research_planning.prepare/persist`와 현재 의식 고급 `claude_code/opus`를 썼다. 기본 요청은 빈 이력, 후속은 이전 요청·의식 출력·저장 계획을 받았다. 운영자의 checks나 판정·정답은 모델에 전달하지 않았다. 도구 카탈로그는 빈 목록인 분리 환경이다. 실제 채팅의 자동 분류·기억·주제 결속 시험과 구별한다.

R03은 합성 맥락 복원 자료를 실제 `execute_reframe → Supervisor.reframe → 의식 → 계획 저장`에 넘겼다. 복원 자료와 재규정 방아쇠는 운영자가 제공했다. 따라서 실행자가 스스로 기억을 찾고 의식에게 되묻는 자율 행동을 확인한 것은 아니다.

## 개선과 잔여를 구별할 근거

R01에서는 첫 수정 뒤에도 전문가 주의에 ‘개점보다 먼저 시작된 감소’가 남았다. 최종 보완 뒤에는 ‘개점 전 4개월에도 전년 대비 감소가 있었다면’으로 바뀌고 본문도 월별 분포를 미확인으로 둔다. **이 특정 단정은 이번 출력에서 사라졌다.** 다만 계획의 ‘방문객(판매 건수 대리)’는 방문과 구매를 혼용한다. 같은 판매 건수 감소는 방문 감소와 구매전환율 하락 양쪽에서 나올 수 있다. 전문가 주의의 ‘기준선 대비 단절만 진입 효과로 읽는다’도 본문의 인과 한계보다 강하다. 전체 원인 분석 계획을 완전히 타당하다고 판정하지 않았다.

N01은 규정과 계획의 오류가 서로 이동했다. 첫 수정에서는 규정에 도입 전 감소 ‘가능성이 높다’가 있었고, 최종 보완에서는 규정이 조건을 보존하지만 **계획 본문에 ‘감소의 상당 부분이 도입 전에 시작됐을 가능성이 크다’**가 남았다. 주별 분포가 균등하다는 가정하의 계산 자체는 맞아도 그 가정의 개연성은 입력에 없다. 조건부라는 단서를 붙여도 실제 경우에 대한 확률 우열이 근거를 얻지는 않는다.

예를 들어 전년도 앞 8주가 주당5건·뒤4주가50건이면 합계240건이다. 올해 앞8주는 그대로5건·뒤4주가26건이면 합계144건, 정확히40% 감소하면서 도입 전 감소는 없다. 다른 분포에서는 도입 전 감소가 가능하다. 둘 다 주어진 집계와 양립한다. 이는 챗봇의 실제 효과가 없다는 증거가 아니라 입력만으로 시점이나 개연성을 정할 수 없다는 반례다. [결정론적 대조](counterexamples.json).

또한 N01의 ‘재문의가 없는 비율’을 해결률로 명명하는 지표에는 해결과 포기 양쪽이 섞일 수 있다. 계획 다른 곳에서 포기를 점검하도록 해도 지표 이름·정의와 효과 판정의 연결은 더 엄격해야 한다. R01의 방문/판매 건수와 함께 **대리 지표를 목적의 직접 측정치로 읽는 문제**가 남는다. 이 회차에서는 같은 원인의 두 번째 보완 뒤 무한히 문구를 늘리지 않고 관측을 보존했다.

N02는 보완 뒤 기간 제한을 명시적으로 시험 단계에만 적용한다. 최종 종합 필터에 이번 달 결제 여부를 후보 영구 탈락 근거로 넣지 않으며 미확인 후보는 조건부로 남긴다. R02도 원본 업로드 금지와 파생물 허용 미확인을 분리한다. 실제 후보 조사를 하지 않았으므로 효과는 계획의 조건 보존에 한정한다.

N03 최종 보완은 간호사라는 사실만으로 교대근무를 추가하지 않도록 예시의 원문에 3교대를 명시했다. 그러나 ‘치매 어머니를 혼자 돌봄’을 ‘단독으로 맡은 **고강도의** 가족 돌봄’으로 바꿨다. 단독 돌봄은 주어졌지만 부담 강도의 판정 근거는 없다. 같은 유형의 추가 속성이 다른 곳에서 남았다.

N04는 기존 오류를 포함한 N03_final에서 다시 시작했는데, ‘간호사→교대 근무가 있는 직종’ 예시를 그대로 유지했다. 추가한 장면 익명화 예시도 ‘특별전 개막 해설’을 ‘**많은 관람객 앞에서** 한 해설’로 바꿔 원문에 없는 규모를 더했다. **기존 AI 계획의 내용도 검증 대상이라는 원칙을 실제 예시에 적용하는 능력은 아직 부족하다.** 실제 면담을 바꾼 것은 아니며 계획 예시의 결함이다.

R03은 복원 책임과 계획 작성 책임을 구별했고 복원 원문에 맞는 계획을 의식이 작성했다. 시험 어댑터를 제품과 같게 맞춘 재호출에서 새 계획의 previous_path가 원래 계획을 가리키며 원래 본문도 불변이다. 이는 연결 경로 검증이고 자동 기억 회수 성공률은 아니다.

## 시험 장치의 한계와 보존

초기 두 시도는 가이드 36,558바이트 판본이었다. 상한 확인 후 중복 설명을 압축하고 9사례를 다시 했다. R01 첫 수정 시험은 최종 첫 판본보다 ‘이 가이드는 ’ 접두어17바이트가 더 있다. 나머지 규범 내용은 바이트 단위로 동일하다. 실제 입력 지문과 두 판본을 모두 남겼다. 결과에 유리한 출력만 고른 것이 아니며 초기4호출도 비용에 포함한다.

R03 최초 복원에서 시험 어댑터가 previous_research_plan 인자를 넘기지 않아 이전 경로가 비었다. 실제 제품은 전달하고 있었으므로 제품 결함으로 세지 않는다. 원본 어댑터·출력은 보존하고 어댑터만 맞춰 같은 초기 계획·복원 원문으로 재규정 부분을 재호출했다. [세부 경위](harness_notes.md).

N04 최종 보완 시험은 잘된 새 계획을 주지 않고 **오류가 있던 원래 N03_final**을 그대로 이어받았다. N06도 원래 N03에서 독립 분기했다. 이후 계획 작성이 원래 계획 파일을 바꾸지 않았는지 지문을 대조한다.
