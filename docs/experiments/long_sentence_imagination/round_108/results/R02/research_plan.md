# 사진 8만 장 정리 방식 개선 판단 — 연구계획 (초안 v1)

상태: 계획만 작성했고 조사는 시작하지 않았다. 아래 후보명과 기능 설명은 확인 전의 잠정 대상이며 사실 확인이 아니다.

## 1. 목적과 판단할 것

작은 독립출판사가 보유한 사진 약 8만 장의 관리 방식을 개선할지 판단한다. 개선 대상은 직원 세 명의 두 가지 일이다.

- **원본 찾기**: 필요한 사진의 원본(최종본)을 빠르고 정확하게 찾는 일
- **중복 처리**: 같은 사진이나 파생본이 여러 개 있을 때 정리하는 일. 원본을 잃지 않는 것이 전제다.

연구 끝에 고를 판단 선택지는 다음과 같다. 이 계획은 결론을 예고하지 않으며, 어느 쪽이든 나올 수 있다.

| 선택지 | 내용 |
| --- | --- |
| A. 현행 유지 | 실패가 드물거나 개선 비용이 효과보다 클 때 |
| B. 폴더 방식 유지 + 보완 | 폴더·명명 규칙 문서, 색인표, 읽기 전용 중복 목록 등 설치가 거의 없는 보완 |
| C. 로컬 카탈로그 도구 | 각 PC나 공유 카탈로그에서 원본을 제자리에 둔 채 색인·검색 |
| D. 사내 자가호스팅 사진 서버·DAM | 내부 NAS나 PC에서 운영 |
| E. 혼합 | 예: 규칙 보완 + 중복 점검 도구만 사용 |

## 2. 사용자 조건과 계획 반영

| 사용자 조건(원문 취지) | 적용 대상·범위 | 계획에서의 처리 |
| --- | --- | --- |
| 원본을 외부 서버로 업로드하면 안 됨 | 원본 파일 | 원본이 외부로 나가는 대안은 탈락시킨다. 아래 두 경우는 허용 여부가 미확인이므로 탈락이 아니라 조건부 보류로 둔다: 사내 NAS가 외부에 해당하는지, 썸네일·메타데이터만 외부에 두는 방식 |
| 이번 주 프로그램 설치·기존 폴더 변경 금지 | 이번 주의 활동 | 이번 주에는 공개 자료 조사와 비변경 정보 수집만 한다. 설치가 필요한 후보는 탈락시키지 않고, 시범을 이후 승인 단계로 미룬다 |
| 공개 설명·샘플 조사로 새 대안 비교 허용 | 근거 수집 방법 | 공식 문서·가격표·데모·샘플을 1차 근거로 쓴다 |
| 월 운영비 5만 원 이하 | 모든 대안 | 필수 판정 항목으로 둔다. 일회성 비용(영구 라이선스, 장비 구입)을 어떻게 처리할지는 확인 질문으로 남기고, 그 전까지 월 비용과 일회성 비용을 따로 표시한다 |
| 기존 파일명 유지 | 모든 대안 | 가져오기 시 재명명을 강제하는 대안은 탈락시킨다. 끌 수 있는 설정이면 조건부 통과로 본다 |
| 지금은 계획서까지만 | 이번 요청 | 조사·실행 결과를 쓰지 않는다 |

### 함께 확인할 경계

- 원본 파일 안에 메타데이터를 써넣는 방식(IPTC/XMP 내장)은 파일명은 그대로지만 파일 내용을 바꾼다. 이번 주에는 하지 않는다. 이후에 허용할지는 확인 질문으로 남긴다.
- 사이드카(.xmp)나 썸네일 캐시를 원본 폴더 안에 만드는 도구는 기존 폴더 변경에 해당할 수 있다. 후보마다 쓰기 위치를 확인하는 항목을 둔다.

## 3. 출발점: 아는 것과 모르는 것

**사용자가 알려준 것**

- 사진은 약 8만 장이다.
- 직원은 세 명이다.
- 현재는 폴더 방식으로 관리한다.
- 개선 대상은 원본 찾기와 중복 처리다.
- 조건은 2절과 같다.

**모르는 것** (첫 정보 수집에서 확인)

- 저장 위치와 구조: PC·NAS·외장 디스크, OS, 공유 방식, 백업 유무
- 파일 형식 구성: RAW·JPEG·TIFF·PSD 등
- 현재 폴더·명명 규칙과 실제로 지켜지는지
- 기존 메타데이터(촬영정보, 캡션, 키워드)가 있는지
- 직원들이 말하는 중복이 무엇인지: 같은 파일의 복사본, 다른 크기·형식, 보정·크롭본, 연속 촬영본
- 찾기 실패와 중복 문제의 빈도, 작업 시간

이전에 같은 주제로 조사한 기록은 없다.

## 4. 접근과 선택 이유

이 연구는 무엇을 도입하는 것이 적합한가를 묻는 판단이다. 도구의 기능 목록보다 현재 어떤 실패가 일어나는지가 해법을 정한다.

- 위치를 몰라서 못 찾는 문제라면 색인·검색이 해법이다.
- 어느 것이 최종본인지 몰라서 생기는 문제라면 파생 관계와 상태 표시가 해법이다.

따라서 다음 순서로 진행한다.

1. 현행 실패를 진단한다.
2. 대안을 지도로 정리하고 조건으로 거른다.
3. 같은 과제를 두고 대안을 대조한다.
4. 사용자가 승인하면 사본 표본으로 시범한다.

제품 비교표 하나로 판단을 대신하지 않는다. 기본 관점(도구를 도입하면 개선된다)과 대안 관점(규칙·색인 보완으로 대부분 해결된다)을 같은 실패 유형 근거로 함께 평가한다.

### 근거의 위계

- 공식 문서, 가격 페이지, 데모·샘플, 릴리스 노트는 1차 근거다.
- 리뷰와 커뮤니티 글은 보조 근거다.
- 문서에 기능이 있다는 것은 기능 존재의 근거일 뿐, 이 출판사에서의 효과를 입증하지 않는다.
- 효과는 같은 과제의 비교나 승인된 시범으로만 판단한다.

## 5. 연구 질문과 조사 방법

### Q1. 현재 원본 찾기는 어디서, 왜 실패하는가

- **증거**: 직원 세 명이 겪은 최근 찾기 사례(성공·실패·오래 걸린 사례)와 이유. 사용자·직원에게 받는 정보다.
- **측정**: 대표 찾기 과제의 실제 작업 시간, 성공 여부, 찾은 파일이 최종 원본이었는지. 과제 수 10~20건은 잠정 제안값이다.
- **분석**: 실패를 다음 유형으로 분류한다.
  - 위치를 모름
  - 이름·날짜로 검색이 안 됨
  - 최종본·파생본을 구분하지 못함
  - 권한·접근 문제
- **판단 변화**: 실패의 대부분이 어느 유형이냐에 따라 B·C·D 중 유력한 방향이 달라진다.
- **부족할 때**: 기록된 사례가 적으면 직원에게 다음 1~2주 동안 찾기 요청을 간단히 기록하게 할지 사용자에게 제안한다.

### Q2. 중복의 실체는 무엇이고, 처리에 어떤 위험이 있는가

- **증거**: 직원이 아는 중복 사례와, 그 사례가 다음 중 어느 유형인지.
  - 바이트가 같은 복사본
  - 같은 사진의 다른 형식·크기
  - 보정·크롭본
  - 연속 촬영 유사본
- **이후 승인 단계의 측정**: 읽기 전용 해시 목록을 만든다. OS 기본 도구로 계산하고, 결과는 원본 폴더 밖에 저장한다. 이를 통해 바이트 동일 중복의 규모를 잰다.
- **판단 변화**: 바이트 동일 중복이 대부분이면 경량 해법(B·E)으로 충분할 수 있다. 파생본 혼동이 주된 문제면 관계를 기록하는 기능(C·D)이 필요하다.
- **안전 원칙**: 자동 삭제는 계획하지 않는다. 바이트 동일 중복도 보존본을 정하고 격리한 뒤 사람이 확인한다. 유사도 후보는 검토 목록으로만 다룬다.

### Q3. 어떤 대안이 있으며 조건을 통과하는가

대안군과 예비 조사 대상(사양 미확인):

- 무설치·규칙형: 폴더·명명 규칙 문서, 색인 스프레드시트, OS 기본 검색
- 로컬 카탈로그: digiKam, Adobe Lightroom Classic·Bridge, XnView MP 등
- 자가호스팅 서버·DAM: PhotoPrism, Immich, ResourceSpace, NAS 제조사의 사진 앱 등
- 중복 점검 전용 도구: dupeGuru, Czkawka 등

후보마다 공식 자료로 확인할 항목:

1. 원본을 제자리에 둔 채 색인하는지, 가져오면서 복사·이동하는지
2. 파일명 변경 여부와 끌 수 있는지
3. 메타데이터를 어디에 쓰는지(원본 내장·사이드카·DB), 원본 폴더 안에 파일을 만드는지
4. 중복 탐지 방식(해시·유사도)과 파생 관계 표시
5. 세 사람이 동시에 사용할 수 있는지, 공유 카탈로그의 잠금 제약
6. 외부 전송: 클라우드 동기화 기본값, 원격 처리 기능
7. 월 비용과 일회성 비용
8. 사용 중인 형식(RAW 등) 지원과 8만 장 규모의 운영 사례
9. 운영 부담: 설치, 업데이트, 백업, 학습

**판정 방법**: 조건 필터(외부 업로드, 파일명, 비용)로 통과·조건부·탈락을 표시한다. 미확인은 탈락 사유가 아니다. 출처마다 문서명, 확인 날짜, 실제 열람 범위(제목·요약 / 본문 해당 절 / 데모 직접 확인)를 기록한다.

**확장 기준**: 위 목록에 없는 후보도 같은 기준으로 넣을 수 있다. 각 대안군에서 조건을 통과한 후보가 1~2개 확인되면 탐색 확장을 멈춘다. 이 수치는 잠정값이다.

### Q4. 우리 과제에서 실제로 나아지는가

- **이번 주 이후, 승인 없이 가능한 범위**: Q1·Q2의 실제 사례를 과제 시나리오로 만든다. 후보별로 문서와 데모상 그 과제를 처리할 수 있는지 대조한다. 결과는 기능상 가능 여부로만 표시한다.
- **승인 후**: 원본이 아닌 사본 표본으로 기준선(현행 폴더)과 후보를 같은 과제로 비교한다. 표본은 수백~수천 장 수준을 잠정 제안한다.
  - 찾기: 작업 시간, 성공률, 최종본 정확도
  - 중복: 탐지 정밀도, 놓친 사례, 오판 위험
- **주의**: 일부 직원이나 일부 과제만 측정했다면 전체 절감 효과를 확정하지 않는다. 전체 절감은 같은 기간에 직원별로 찾기·중복 처리에 쓴 시간 비중과 절감률로 계산한다. 작업 시간은 실제 활동 시간으로 기록하고 대기 시간은 제외한다.

### Q5. 비용과 운영 부담은 감당 가능한가

- **증거**: 가격 문서, 필요한 장비, 유지 작업(업데이트, 백업, 카탈로그 정리)의 예상 시간
- **판단**: 월 5만 원 이하 여부를 판정한다. 그와 별도로 유지 노동이 절감 효과를 상쇄하는지 본다.

## 6. 종합과 판단 규칙

1. **조건 필터**
   - 원본 외부 업로드가 필요한 대안은 탈락
   - 파일명 변경을 강제하는 대안은 탈락
   - 월 5만 원을 초과하는 대안은 탈락
   - 확인되지 않은 항목이 있는 대안은 조건부로 남긴다
2. **실패 유형 대응표**: Q1·Q2에서 비중이 큰 실패 유형마다 어떤 대안이 그 실패를 해소하는지 대조한다.
3. **효과와 부담 비교**: 다음 기준으로 선택지를 정한다.
   - 주요 실패가 규칙·색인 보완으로 해소되면 B 또는 E
   - 규칙으로 해소되지 않는 실패가 주요하고, 승인된 시범에서 개선이 확인되면 C 또는 D
   - 실패가 드물거나 부담이 효과를 넘으면 A
4. **결론의 강도**: 시범 없이 문서 근거만 있으면 결론은 시범을 권고할 후보와 조건까지만 제시한다. 도입이 효과적이라고 확정하지 않는다.
5. **근거 충돌**: 대상·판본·조건의 차이로 설명되는지 확인한다. 해소되지 않으면 조건별 결론이나 미해결로 남긴다.

## 8. 멈춤 조건

다음이 갖춰지면 판단을 보고할 수 있다.

- 각 선택지에 대해 조건 판정이 끝났다.
- 주요 실패 유형과 대안의 대응을 설명할 수 있다.
- 효과를 같은 과제로 비교했거나, 비교하지 못한 이유와 남은 확인 사항을 밝혔다.

시간·접근 한계로 핵심 항목을 확인하지 못하면 결론을 약화하거나 미해결로 남긴다. 조사량이 소진되었다는 이유로 충족 처리하지 않는다.

## 9. 사용자에게 확인할 질문

1. 사진이 어디에 저장되어 있나요? (NAS, PC, 외장 디스크, OS) 사내 NAS에서 돌리는 서버는 외부 서버로 보나요?
2. 썸네일이나 메타데이터만 외부 서비스에 두는 방식도 금지 대상인가요?
3. 이후 단계에서 원본 파일 안에 캡션·키워드를 써넣는 것은 허용되나요?
4. 영구 라이선스나 장비 구입 같은 일회성 비용은 월 운영비에 어떻게 반영할까요?
5. 직원들이 말하는 중복은 주로 어떤 경우인가요? 최근 찾기 실패 사례 몇 건을 공유해 주실 수 있나요?

## 10. 보고 전 대조 절차 (향후 조사 단계용)

보고서를 쓰기 전에 Q1~Q5 각각에 대해 다음을 대조한다.

- 잠정 답
- 근거 위치
- 실제 열람 범위
- 남은 불확실성
- 문서상 기능과 측정된 효과의 구분

조사 중 목적·범위·방법을 크게 바꿔야 하면 이유와 이전 근거를 이 계획서에 남기고 재규정을 요청한다. 진행 상황과 근거는 이 계획서에 갱신한다.
