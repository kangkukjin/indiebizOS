적용한다.\n\n- 적용 한계: 질의 수가 적고 평가자가 소수라 작은 차이는 확정하지 않는다. 대규모 통계 검정도 하지 않는다.\n\n**원문 위치 복귀**\n\n일반 검색 지표에 없는 항목이므로 과제 기반 측정으로 따로 정의한다(지표는 Q5 참조). 같은 사람이 같은 과제를 반복하면 학습 효과가 생긴다. 후보 순서를 바꾸고 질의 집합을 나눠 이 효과를 줄인다.\n\n**비교 축**\n\n- 찾기 계열 (조합 가능)\n  - 정확 문자열·정규식\n  - 한국어 분석기(형태소·n-gram)를 갖춘 전문검색(BM25 등)\n  - 의미검색(임베딩)\n  - 미리 추출하고 사람이 검수한 인물·사건 색인(NER)\n  - 한국어는 조사가 붙은 이름('김철수는')이 공백 기준 색인에서 누락될 수 있으므로 분석기 지원을 점검한다.\n- 배치: 로컬 / 공개 본문 사본 클라우드.\n- 위치 앵커 설계: 5절 참조.\n\n**후보 예시** (미검증, Q2의 출발점)\n\n- 로컬\n  - 사용자 OS 내장 검색(무설치로 쓸 수 있는지 확인)\n  - ripgrep\n  - Recoll, DocFetcher\n  - SQLite FTS5\n  - 자체 운영 Meilisearch·Typesense·OpenSearch(한국어 nori 분석기)\n- 클라우드 (공개 사본 전용)\n  - 호스팅 검색: Algolia, Typesense Cloud, Meilisearch Cloud 등\n  - 문서 저장형 검색\n  - 임베딩 기반 검색 서비스\n- 후보는 고정 개수를 채우지 않는다. 필수 조건을 문서상 충족하거나 미확인으로 남은 후보를 시험 대상으로 둔다.\n\n## 5. 데이터 흐름 설계안\n\n1. **원본** (읽기 전용): 파일별 SHA-256, 원래 파일명, 경로를 기록한다.\n2. **로컬 추출 텍스트**: 원본 쪽 번호와 문단 ID를 부여한다. 스캔본이면 로컬 OCR만 쓴다.\n3. **공개 검토**: 승인된 문단만 남기고, 수정된 문단은 표시한다.\n4. **공개 사본 레코드**: 각 레코드에 article_id, 원래 파일명, 원본 해시, 쪽, 문단 ID, 검토 수정 여부를 담는다.\n5. **색인**: 로컬 또는 클라우드에 만든다.\n6. **결과 → 원문 열기**: 매핑표로 원본 파일의 해당 쪽을 연다.\n\n**점검 사항**\n\n- 검토 수정이 있으면 문자 오프셋이 어긋난다. 그래서 문단 ID를 1차 앵커로, 문자 오프셋을 보조로 쓴다.\n- 원본 뷰어가 특정 쪽·위치로 바로 열 수 있는지 확인한다.\n- 로컬 검색도 같은 앵커 체계를 써서 두 계열을 공정하게 비교한다.\n\n## 6. 질문별 조사 방법\n\n**Q1 자료 특성**\n\n- 증거: 제공 샘플의 형식, 텍스트층 유무, 쪽 표기, 인물 표기 변이(별칭·직함·동명이인), 사건 서술 방식.\n- 확보: 제공 샘플만 로컬에서 읽는다. 외부 전송은 하지 않는다.\n- 이 결과로 판단할 것:\n  - OCR 단계가 필요한가\n  - 어떤 앵커를 쓸 수 있는가\n  - 고정 질의어 검색으로 충분한가, 사전 개체 색인이 필요한가\n- 부족할 때: 형식이 다양하면 대표 샘플 추가를 요청한다. 스캔본이면 로컬 OCR 단계를 넣는 방법 변경으로 보고 재규정을 요청한다.\n\n**Q2 후보의 문서상 조건 충족**\n\n- 증거: 원 제공자의 공식 문서·가격표·약관에서 다음을 확인한다.\n  - 한국어 분석기\n  - 원본 폴더를 바꾸지 않는지\n  - 외부 전송·동기화 여부\n  - 결과에 위치 필드 보존·하이라이트가 되는지\n  - 300편 규모에서의 요금·한도\n  - 데이터 보관·삭제 정책\n- 기록: 주장마다 출처 URL, 확인일, 열람 범위(제목·요약/해당 절/전문)를 적는다.\n- 판단: 필수 조건을 충족, 위반, 미확인 중 하나로 분류한다.\n- 부족할 때: 경쟁사 소개나 검색 요약뿐이면 미확인으로 두고 다음 달 시험에서 확인한다.\n\n**Q3 정답셋 설계**\n\n- 질의 유형: 실명, 별칭·직함, 조사 결합형, 동명이인, 사건 묘사형, 검토 수정 문단에 걸친 정답.\n- 정답 표기: 기사 ID, 원래 파일명, 쪽, 문단 ID.\n- 작성 방식: 실행자가 초안을 만들고 사용자가 검수하는 방식을 잠정안으로 둔다.\n- 이번 주 범위: 질의 유형과 양식 설계까지. 실제 라벨링은 사용자 지시 후에 한다.\n\n**Q4 찾기 정확성** (다음 달 실측)\n\n- 질의별 상위 k개 결과에서 정답 기사 재현율과 정밀도를 잰다.\n- 놓친 사례는 유형별로 분류한다: 표기 변이, 조사, OCR 오류, 의미 질의 등.\n\n**Q5 원문 위치 복귀** (다음 달 실측)\n\n- 시간: 질의 입력부터 원본 파일의 정답 쪽·문단이 화면에 표시될 때까지의 활동 시간.\n- 별도 비용 항목으로 분리: 색인 구축, 사본 준비, 공개 검토 시간.\n- 정확도 등급: 정확 문단 / 정확 쪽 / 다른 쪽 / 실패.\n- 기록 양식 필드: 질의 ID, 후보, 시작·끝 시각, 도달 위치, 등급, 조작 단계 수, 메모.\n\n**Q6 비용·운영·위험**\n\n- 월 총액(부가세·환율·사용량 초과 포함)\n- 공개 검토와 사본 갱신의 부담\n- 원본 보존·업로드 금지를 위반할 수 있는 지점\n\n## 7. 종합과 판단 규칙\n\n**필수 통과 조건**\n\n- 원본·파일명 불변\n- 원본 외부 전송 없음\n- 클라우드에는 공개 사본만\n- 위치 앵커 보존\n- 유료 후보는 월 2만 원 이하\n\n**통과 후보 간 비교 순서** (제안이며 사용자 확인 필요)\n\n1. 찾기 재현율\n2. 위치 복귀 정확도\n3. 복귀 시간\n4. 운영 부담\n\n수치 임계값은 제안값이며 관측 사실이 아니다.\n\n**결론의 형태**\n\n- 조합 결론을 허용한다. 예: 원본 앵커는 로컬에 두고 검색은 사본 클라우드에서 한다.\n- 실측하지 않은 후보는 문서상 사실만으로 조건부로 표시한다. 성능은 예상으로 분리한다.\n- 질의 수가 적어 차이가 작으면 동률로 두고 추가 시험 조건을 적는다.\n- 근거가 충돌하면 자료 형식·질의 유형·측정 조건의 차이로 설명되는지 먼저 본다.\n\n## 8. 진행과 멈춤\n\n**단계 0 (이번 턴)**\n\n이 계획서를 작성하고 여기서 멈춘다.\n\n**단계 1 (이번 주, 사용자 진행 지시 후)**\n\n- 할 일: Q1 샘플 특성 파악, Q2 공개 문서 검토, Q3 정답셋·기록 양식 확정, 계획 갱신.\n- 설치·가입은 하지 않는다.\n- 멈춤: 후보별 필수 조건 판정표(충족/위반/미확인)와 정답셋 설계가 갖춰지면 멈춘다.\n\n**단계 2 (다음 달)**\n\n- 할 일: 설치·가입·유료 후보 시험(결제 전 사용자 승인), Q4·Q5 실측, 7절에 따른 종합.\n- 멈춤: 필수 조건을 통과한 후보에 Q4·Q5 측정이 끝나 판단 규칙을 적용할 수 있으면 멈춘다.\n- 접근·비용 한계로 측정하지 못하면 조건부 결론과 남은 확인 조건으로 마친다. 예산 소진을 근거 충족으로 표시하지 않는다.\n\n**방향 전환**\n\n다음 경우에는 재규정을 요청한다.\n\n- 스캔본이 많아 OCR 단계가 필요할 때\n- 사용자가 인물·사건 범위를 바꿀 때\n- 공개 검토로 본문이 크게 바뀌어 앵커 설계를 다시 해야 할 때\n\n## 9. 기록과 보고 전 대조\n\n**근거표**\n\n주장, 출처, 1차·2차 구분, 실제 열람 범위, 확인일을 적는다.\n\n**실측표**\n\n6절 Q5의 양식을 쓴다.\n\n**보고 전 대조**\n\n- 질문 Q1~Q6마다 답, 근거 위치, 실제 열람 범위, 남은 불확실성을 대조한다.\n- 계획이 조사 전에 저장됐는지, 조사 중 방법 변경이 기록됐는지 확인한다.\n- 이 계획서의 현재 상태를 실제 결과와 맞춘다.\n\n## 10. 현재 상태와 사용자 확인 질문\n\n**현재 상태**\n\n계획 초안을 작성했다. 단계 1은 착수하지 않았다.\n\n**사용자에게 확인할 것**\n\n1. 샘플과 원본은 어떤 형식인가? (텍스트 PDF / 스캔 / HWP 등)\n2. 인물·사건에 단체·장소가 포함되는가? 주로 이름으로 찾는가, 사건 묘사로 찾는가?\n3. 공개 검토는 누가 어떤 기준으로 하며, 본문을 수정하기도 하는가?\n4. 사용하는 OS와 이미 설치된 검색 도구는 무엇인가? 무료 가입·약관 동의도 이번 주에는 피해야 하는가?\n5. 7절의 비교 순서(재현율 → 위치 정확도 → 시간 → 운영 부담)가 맞는가?\n6. 단계 1을 진행할까?"
