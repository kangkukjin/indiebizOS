# 지역 잡지 기사 300편의 인물·사건 검색 방식 선택 — 연구계획서

> 상태: 계획 초안이다. 이 계획을 작성하는 동안 자료 조사·샘플 분석·외부 연락·설치·실행은 하지 않았다. 아래의 후보 이름·기능·가격은 모두 미검증이며 조사의 출발점일 뿐이다.

## 1. 목적과 판단 질문

**최종 판단**

기사 300편에서 인물·사건을 찾고, 결과에서 원문의 정확한 위치(파일·쪽·문단)로 돌아가는 작업에 어떤 방식을 쓸지 고른다. 선택지는 세 가지다.

- 로컬 검색
- 검토를 마친 공개 본문 사본의 클라우드 검색
- 둘의 조합

**이 계획의 역할**

선택에 필요한 비교를 무엇으로, 어떤 순서로, 어떤 기준으로 할지 정한다. 결론은 미리 정하지 않는다. 결과는 조건부 결론이나 미해결로 끝날 수 있다.

**판단 질문**

- Q1. 원본·샘플 자료의 형식과 표기 특성은 무엇이며, 어떤 검색 계열과 위치 앵커가 가능한가?
- Q2. 각 후보가 사용자 조건(원본 보존, 원본 업로드 금지, 사본만 클라우드, 이번 주 무설치·무계약, 다음 달 월 2만 원 이하)을 문서상 충족하는가?
- Q3. 인물·사건 질의와 정답 위치를 담은 정답셋을 어떻게 구성하는가?
- Q4. 후보별 찾기 정확성(놓침·잘못 찾음)은 어떤가?
- Q5. 후보별로 검색 결과에서 원본의 정확한 위치로 돌아가는 시간과 정확성은 어떤가?
- Q6. 비용·운영 부담(공개 검토, 사본 갱신, 색인 유지)과 조건 위반 위험은 어떤가?

## 2. 사용자 조건과 계획에 미치는 영향

| 조건 | 계획에 미치는 영향 |
| --- | --- |
| 원본 파일과 파일명 보존 | 원본은 읽기 전용으로 둔다. 후보 점검 항목: 가져오기 시 파일을 이동하거나 이름을 바꾸는가, 원본 폴더에 사이드카·메타데이터를 쓰는가. |
| 원본 파일 외부 업로드 금지 | 클라우드 OCR, 동기화 폴더, 원본 파일 첨부형 서비스는 원본에 쓸 수 없다. 로컬 도구의 클라우드 동기화·전송 기능도 점검한다. |
| 검토를 마친 공개 본문 사본만 클라우드 허용 | 사본 생성 → 공개 검토 → 업로드 순서의 관문을 둔다. 검토로 삭제·수정된 문단은 표시한다. |
| 이번 주: 설치·계약 없이 공개 문서와 제공 샘플만 | 이번 주는 문서 검토, 샘플 특성 파악, 정답셋·양식 설계까지다. 설치나 가입이 필요한 시험은 보류하며 탈락이 아니다. |
| 다음 달: 월 2만 원 이하 유료 서비스도 후보 | 부가세·환율·사용량 초과를 포함한 월 총액으로 판정한다. 결제 전에 사용자 승인을 받는다. |
| 찾기 정확성과 원문 위치 복귀 시간·정확성을 함께 평가 | 두 지표를 따로 측정하고 판단 규칙에서 함께 쓴다. |
| 이번 턴은 계획서까지만 | 단계 1 이후는 사용자의 진행 지시가 있어야 시작한다. |

## 3. 출발점·잠정 전제·미확인

**확인된 것**

위 사용자 조건뿐이다. 자료 자체는 아직 보지 않았다.

**잠정 전제** (단계 1 첫 확인 대상)

- 원본 300편이 로컬에 있다.
- 샘플이 일부 제공된다.
- 공개 검토는 사람이 수행한다.

**미확인** (결정에 영향을 주는 것)

- 원본·샘플 형식: 텍스트층이 있는 PDF인지, 스캔 이미지인지, HWP·워드·웹 문서인지. 이에 따라 OCR 필요 여부가 정해진다.
- 쪽 번호 체계: 지면 쪽과 파일 쪽이 같은지, 기사 하나가 여러 파일에 걸치는지.
- 인물·사건의 범위: 실명 인물만인지, 단체·장소를 포함하는지. 사건을 어떤 단위로 볼지.
- 사용자의 주된 찾기 방식: 이름을 알고 찾는지, 사건 묘사나 기억으로 찾는지.
- 공개 검토의 주체·기준, 검토 과정의 본문 수정 범위.
- 사용 OS와 이미 설치된 도구. 무설치 시험이 가능한 범위가 여기에 달려 있다.
- 무료 가입·약관 동의가 '계약'에 포함되는지.
- 사용 인원과 사용 빈도.

## 4. 접근과 선택 이유

이 질문은 '무엇을 도입하는 것이 적합한가'에 해당한다. 소개 자료로 기능 존재를 확인하는 것만으로는 부족하므로, 같은 자료·같은 질의로 후보를 시험하는 비교 평가를 택한다.

**찾기 정확성**

정보검색 평가의 테스트 컬렉션 방식(정답셋을 두고 정밀도·재현율을 재는 Cranfield/TREC 계열)을 소규모로 적용한다.

- 적용 한계: 질의 수가 적고 평가자가 소수라 작은 차이는 확정하지 않는다. 대규모 통계 검정도 하지 않는다.

**원문 위치 복귀**

일반 검색 지표에 없는 항목이므로 과제 기반 측정으로 따로 정의한다(지표는 Q5 참조). 같은 사람이 같은 과제를 반복하면 학습 효과가 생긴다. 후보 순서를 바꾸고 질의 집합을 나눠 이 효과를 줄인다.

**비교 축**

- 찾기 계열 (조합 가능)
  - 정확 문자열·정규식
  - 한국어 분석기(형태소·n-gram)를 갖춘 전문검색(BM25 등)
  - 의미검색(임베딩)
  - 미리 추출하고 사람이 검수한 인물·사건 색인(NER)
  - 한국어는 조사가 붙은 이름('김철수는')이 공백 기준 색인에서 누락될 수 있으므로 분석기 지원을 점검한다.
- 배치: 로컬 / 공개 본문 사본 클라우드.
- 위치 앵커 설계: 5절 참조.

**후보 예시** (미검증, Q2의 출발점)

- 로컬
  - 사용자 OS 내장 검색(무설치로 쓸 수 있는지 확인)
  - ripgrep
  - Recoll, DocFetcher
  - SQLite FTS5
  - 자체 운영 Meilisearch·Typesense·OpenSearch(한국어 nori 분석기)
- 클라우드 (공개 사본 전용)
  - 호스팅 검색: Algolia, Typesense Cloud, Meilisearch Cloud 등
  - 문서 저장형 검색
  - 임베딩 기반 검색 서비스
- 후보는 고정 개수를 채우지 않는다. 필수 조건을 문서상 충족하거나 미확인으로 남은 후보를 시험 대상으로 둔다.

## 5. 데이터 흐름 설계안

1. **원본** (읽기 전용): 파일별 SHA-256, 원래 파일명, 경로를 기록한다.
2. **로컬 추출 텍스트**: 원본 쪽 번호와 문단 ID를 부여한다. 스캔본이면 로컬 OCR만 쓴다.
3. **공개 검토**: 승인된 문단만 남기고, 수정된 문단은 표시한다.
4. **공개 사본 레코드**: 각 레코드에 article_id, 원래 파일명, 원본 해시, 쪽, 문단 ID, 검토 수정 여부를 담는다.
5. **색인**: 로컬 또는 클라우드에 만든다.
6. **결과 → 원문 열기**: 매핑표로 원본 파일의 해당 쪽을 연다.

**점검 사항**

- 검토 수정이 있으면 문자 오프셋이 어긋난다. 그래서 문단 ID를 1차 앵커로, 문자 오프셋을 보조로 쓴다.
- 원본 뷰어가 특정 쪽·위치로 바로 열 수 있는지 확인한다.
- 로컬 검색도 같은 앵커 체계를 써서 두 계열을 공정하게 비교한다.

## 6. 질문별 조사 방법

**Q1 자료 특성**

- 증거: 제공 샘플의 형식, 텍스트층 유무, 쪽 표기, 인물 표기 변이(별칭·직함·동명이인), 사건 서술 방식.
- 확보: 제공 샘플만 로컬에서 읽는다. 외부 전송은 하지 않는다.
- 이 결과로 판단할 것:
  - OCR 단계가 필요한가
  - 어떤 앵커를 쓸 수 있는가
  - 고정 질의어 검색으로 충분한가, 사전 개체 색인이 필요한가
- 부족할 때: 형식이 다양하면 대표 샘플 추가를 요청한다. 스캔본이면 로컬 OCR 단계를 넣는 방법 변경으로 보고 재규정을 요청한다.

**Q2 후보의 문서상 조건 충족**

- 증거: 원 제공자의 공식 문서·가격표·약관에서 다음을 확인한다.
  - 한국어 분석기
  - 원본 폴더를 바꾸지 않는지
  - 외부 전송·동기화 여부
  - 결과에 위치 필드 보존·하이라이트가 되는지
  - 300편 규모에서의 요금·한도
  - 데이터 보관·삭제 정책
- 기록: 주장마다 출처 URL, 확인일, 열람 범위(제목·요약/해당 절/전문)를 적는다.
- 판단: 필수 조건을 충족, 위반, 미확인 중 하나로 분류한다.
- 부족할 때: 경쟁사 소개나 검색 요약뿐이면 미확인으로 두고 다음 달 시험에서 확인한다.

**Q3 정답셋 설계**

- 질의 유형: 실명, 별칭·직함, 조사 결합형, 동명이인, 사건 묘사형, 검토 수정 문단에 걸친 정답.
- 정답 표기: 기사 ID, 원래 파일명, 쪽, 문단 ID.
- 작성 방식: 실행자가 초안을 만들고 사용자가 검수하는 방식을 잠정안으로 둔다.
- 이번 주 범위: 질의 유형과 양식 설계까지. 실제 라벨링은 사용자 지시 후에 한다.

**Q4 찾기 정확성** (다음 달 실측)

- 질의별 상위 k개 결과에서 정답 기사 재현율과 정밀도를 잰다.
- 놓친 사례는 유형별로 분류한다: 표기 변이, 조사, OCR 오류, 의미 질의 등.

**Q5 원문 위치 복귀** (다음 달 실측)

- 시간: 질의 입력부터 원본 파일의 정답 쪽·문단이 화면에 표시될 때까지의 활동 시간.
- 별도 비용 항목으로 분리: 색인 구축, 사본 준비, 공개 검토 시간.
- 정확도 등급: 정확 문단 / 정확 쪽 / 다른 쪽 / 실패.
- 기록 양식 필드: 질의 ID, 후보, 시작·끝 시각, 도달 위치, 등급, 조작 단계 수, 메모.

**Q6 비용·운영·위험**

- 월 총액(부가세·환율·사용량 초과 포함)
- 공개 검토와 사본 갱신의 부담
- 원본 보존·업로드 금지를 위반할 수 있는 지점

## 7. 종합과 판단 규칙

**필수 통과 조건**

- 원본·파일명 불변
- 원본 외부 전송 없음
- 클라우드에는 공개 사본만
- 위치 앵커 보존
- 유료 후보는 월 2만 원 이하

**통과 후보 간 비교 순서** (제안이며 사용자 확인 필요)

1. 찾기 재현율
2. 위치 복귀 정확도
3. 복귀 시간
4. 운영 부담

수치 임계값은 제안값이며 관측 사실이 아니다.

**결론의 형태**

- 조합 결론을 허용한다. 예: 원본 앵커는 로컬에 두고 검색은 사본 클라우드에서 한다.
- 실측하지 않은 후보는 문서상 사실만으로 조건부로 표시한다. 성능은 예상으로 분리한다.
- 질의 수가 적어 차이가 작으면 동률로 두고 추가 시험 조건을 적는다.
- 근거가 충돌하면 자료 형식·질의 유형·측정 조건의 차이로 설명되는지 먼저 본다.

## 8. 진행과 멈춤

**단계 0 (이번 턴)**

이 계획서를 작성하고 여기서 멈춘다.

**단계 1 (이번 주, 사용자 진행 지시 후)**

- 할 일: Q1 샘플 특성 파악, Q2 공개 문서 검토, Q3 정답셋·기록 양식 확정, 계획 갱신.
- 설치·가입은 하지 않는다.
- 멈춤: 후보별 필수 조건 판정표(충족/위반/미확인)와 정답셋 설계가 갖춰지면 멈춘다.

**단계 2 (다음 달)**

- 할 일: 설치·가입·유료 후보 시험(결제 전 사용자 승인), Q4·Q5 실측, 7절에 따른 종합.
- 멈춤: 필수 조건을 통과한 후보에 Q4·Q5 측정이 끝나 판단 규칙을 적용할 수 있으면 멈춘다.
- 접근·비용 한계로 측정하지 못하면 조건부 결론과 남은 확인 조건으로 마친다. 예산 소진을 근거 충족으로 표시하지 않는다.

**방향 전환**

다음 경우에는 재규정을 요청한다.

- 스캔본이 많아 OCR 단계가 필요할 때
- 사용자가 인물·사건 범위를 바꿀 때
- 공개 검토로 본문이 크게 바뀌어 앵커 설계를 다시 해야 할 때

## 9. 기록과 보고 전 대조

**근거표**

주장, 출처, 1차·2차 구분, 실제 열람 범위, 확인일을 적는다.

**실측표**

6절 Q5의 양식을 쓴다.

**보고 전 대조**

- 질문 Q1~Q6마다 답, 근거 위치, 실제 열람 범위, 남은 불확실성을 대조한다.
- 계획이 조사 전에 저장됐는지, 조사 중 방법 변경이 기록됐는지 확인한다.
- 이 계획서의 현재 상태를 실제 결과와 맞춘다.
