# 지역 잡지 기사 300편의 인물·사건 탐색 방식 선택 — 비교 연구계획

## 1. 목적과 판단 질문

- **목적(사용자 원문):** 지역 잡지 기사 300편에서 인물·사건을 찾는 방식을 고른다. 로컬 검색과 허용된 본문 사본 클라우드를 모두 비교한다. 검색 결과에서 정확한 원문 위치로 돌아가는 시간·정확성을 함께 본다.
- **이번 산출물:** 문제·목적·연구계획서. 실제 자료 조사·분석·외부 연락·실행은 하지 않는다.
- **판단 질문:** 주어진 조건 안에서 어느 방식(또는 조합)이 다음 둘을 함께 만족하는가?
  - (a) 찾아야 할 인물·사건 언급을 빠뜨리지 않고 찾는다.
  - (b) 그 결과에서 원본의 해당 위치를 빠르고 정확하게 연다.
- 둘 중 하나만 좋으면 목적을 달성하지 못한다. 검색이 정확해도 원본 위치로 못 돌아가면 쓸 수 없다. 위치 복귀가 빨라도 언급을 놓치면 안 된다.

## 2. 조건과 해석 경계

| 조건(사용자 원문) | 계획에서의 적용 |
| --- | --- |
| 원본 파일과 파일명 보존 | 원본은 읽기 전용으로 다룬다. 모든 처리는 사본에서 한다. 이름 변경·덮어쓰기는 하지 않는다. |
| 원본 파일의 외부 업로드 금지 | 로컬 후보도 외부 전송(동기화·텔레메트리) 여부를 확인 항목에 넣는다. |
| 검토를 마친 공개 기사 본문 사본은 클라우드 가능 | 클라우드 입력은 이 사본으로 한정한다. 검토 주체·기준은 사용자 측이다. 계획은 기사별 검토 완료 여부를 입력 상태로 기록할 뿐 검토 기준을 새로 정하지 않는다. |
| 이번 주 설치·계약 없이 공개 문서와 제공된 샘플 | 이번 주에는 문서상 적격성 확인과 시험 설계까지만 한다. 설치·계약이 필요한 후보는 탈락이 아니라 다음 달 실측 대상으로 보류한다. |
| 다음 달 월 2만 원 이하 유료 서비스도 후보 | 유료 후보의 상한이다. 무료 후보를 배제하지 않는다. 사용량 과금이면 300편 규모의 예상 사용량으로 상한 충족을 확인한다. 예상 사용량은 가정으로 표시한다. |
| 지금은 계획서까지만 | 아래 단계 A·B는 사용자가 진행을 지시한 뒤에 시작한다. |

**원문이 정하지 않은 것(미확인):** 원본 파일명·파일 해시·쪽 이미지를 클라우드 레코드에 메타데이터로 넣어도 되는지. 기본 설계는 클라우드에 불투명한 사본 ID와 본문만 보내고, '사본 ID → 원본 파일·위치' 대응표는 로컬에 두는 것이다. 파일명 전송 허용이 확인되면 설계를 바꾼다.

## 3. 출발점: 확인된 것 / 잠정 가정 / 모르는 것

- **확인된 것(사용자 진술):** 위 조건들, 기사가 300편이라는 것, 샘플이 제공됐다는 것. 샘플의 위치와 내용은 아직 열어 보지 않았다.
- **잠정 가정:**
  - 기사는 주로 한국어다. 요청 언어에서 추정했으며 미확인이다. 이 가정이 맞으면 조사가 결합된 이름(예: 인명+'는')과 형태소·n-gram 분석 지원이 중요해진다.
  - 원본은 사용자 측 로컬에 있다.
- **모르는 것:**
  - 원본 형식(PDF·HWP·이미지 스캔·웹 등)과 텍스트층·OCR 필요 여부
  - '정확한 원문 위치'의 단위(파일·쪽·문단·줄·문자)
  - '인물·사건'의 범위(단체·지명 포함 여부, 사건을 어떤 단위로 볼지)
  - 300편 중 공개·검토 완료 기사의 비율
  - 샘플의 수와 300편에 대한 대표성
  - 현재 쓰는 검색 방법
  - 이번 주 '설치 없이'에 OS·뷰어 내장 검색 같은 기존 도구 사용이 포함되는지

## 4. 접근과 선택 이유

- 이 질문은 '목적·제약에 맞는 방식을 도입하는' 문제다. 그래서 두 단계로 접근한다.
  1. 공급자 원문으로 조건 적격성을 먼저 거른다.
  2. 같은 자료·같은 질의로 실측해 성능을 비교한다.
- 문서상 기능 확인과 실측 성능은 구분한다. 이번 주 결과만으로는 성능 순위를 내지 않는다.
- 평가는 정보검색의 테스트 컬렉션 방식(질의셋, 정답 판정, 재현율·정밀도)을 출발점으로 삼는다. 이 방식을 그대로 적용할 수 없는 이유가 있다.
  - 300편은 작은 규모다.
  - 정답셋을 직접 만들어야 한다.
  - 사용자 목적에는 위치 복귀가 포함된다.
  - 따라서 질의에서 시작해 원본 위치 확인까지 가는 종단 과업 지표를 판정의 중심에 둔다. 참고할 평가 방법론의 구체적 출처는 단계 A의 예비 확인 대상이다.
- 비교 축은 두 가지다. 위치 복귀는 별도 축으로 설계한다. 클라우드는 원본을 보지 못하므로 로컬 대응표 없이는 원본 위치로 돌아갈 수 없다.
  - 찾기: 질의 시점 전문검색, 형태소·n-gram 색인, 의미 검색, 사전 개체 색인
  - 위치 복귀: 결과가 원본의 어느 위치를 가리키고 그 위치를 얼마나 빨리 여는가
- 후보 계열(예시이며 이름·가격·기능은 모두 미검증):
  - 로컬: 설치 없는 기존 도구(OS·문서 뷰어 검색), 설치형 전문검색 도구, 개체 색인을 만드는 도구
  - 클라우드: 공개 사본을 넣는 검색 서비스(전문검색·의미검색)
  - 혼합: 클라우드로 찾고 로컬 대응표로 복귀하며, 비공개 기사는 로컬로 찾는 방식

## 5. 핵심 질문과 조사 방법

### Q1. 사용자가 실제로 무엇을 찾는가

- **증거:** 제공된 샘플, 사용자가 찾으려는 질의 예.
- **방법:** 샘플에서 다음 유형을 기록한다.
  - 인물 표기 변이: 본명·직함·별칭·약칭·조사 결합
  - 사건 서술: 고유 명칭이 있는 경우와 서술로만 나오는 경우
- **판단:** 질의 시점 키워드 검색으로 충분한지, 아니면 별칭 사전이나 개체·의미 대응이 필요한지 정한다. 이 결과에 따라 후보군과 정답셋 설계가 달라진다.
- **부족하면:** 사용자에게 실제 질의 예 5~10개를 요청한다(잠정 수).

### Q2. '정확한 원문 위치'는 무엇이고 사본과 어떻게 대응되는가

- **증거:** 원본 형식, 사본 생성 방식, 검토 과정에서 본문이 수정·삭제되는지 여부.
- **방법:**
  - 위치 단위를 정의한다.
  - '사본 ID·사본 내 위치 → 원본 파일·쪽·문단' 대응표 형식을 설계한다(로컬 보관).
  - 검토 편집이나 OCR로 사본 텍스트가 원본과 달라지면 오프셋이 어긋날 수 있다. 그래서 대응 확인 방식(앞뒤 문맥 일치 등)을 함께 정한다.
- **판단:** 각 후보가 결과로 무엇을 돌려주는지 본다(문서 ID, 스니펫, 위치값). 그 반환값이 이 대응표와 연결 가능한지 판단한다.

### Q3. 후보가 문서상 조건을 충족하는가 (단계 A, 공개 문서만)

- **증거:** 공급자의 공식 문서·가격표·데이터 처리 약관. 검색 요약이나 경쟁사 소개만 있으면 판단을 유보한다.
- **확인 항목:**
  - 한국어 분석 지원
  - 결과의 위치·스니펫 반환
  - 외부 전송 여부(로컬 후보 포함)
  - 데이터 보관과 학습 사용
  - 가격 구조와 300편 규모의 비용
  - 설치·계약이 필요한 시점
- **기록:** 출처마다 직접성과 실제 열람 범위(제목·요약·본문 해당 절)를 적는다.
- **판정:**
  - 조건 위반이 문서로 확인되면 제외한다.
  - 불명확하면 조건부로 유지하고 확인 질문을 남긴다.
  - 설치·계약이 필요하다는 이유만으로 제외하지 않는다.

### Q4. 같은 과제에서 찾기와 위치 복귀가 얼마나 되는가 (설계는 단계 A, 실측은 단계 B)

**정답셋**
- 샘플에서 질의를 만들고, 각 질의의 정답 언급 위치 목록을 정한다.
- 작성자·판정 기준·애매한 사례 처리를 기록한다.
- 원본에서 만드는 작업은 로컬에서만 한다.

**지표**
- 찾기: 질의별 재현율(정답 언급 중 찾은 비율), 상위 k 정밀도.
- 위치 복귀: 결과에서 연 원본 위치가 정답 위치와 일치한 비율, 복귀 작업시간. 작업시간은 결과 확인부터 원본 위치 표시까지이며, 색인·응답 대기는 분리한다.
- 종단 과업(판정 중심): 질의 하나에서 모든 정답 위치 확인까지의 성공·누락·총 작업시간.
- 개별 지표는 원인 진단용이다. 개별 지표가 좋아도 종단 과업이 나쁘면 목적을 달성하지 못한 것으로 본다.

**비교 조건**
- 모든 후보에 같은 질의와 같은 문서를 쓴다.
- 클라우드는 공개·검토 완료 사본만 다루므로 비교 방식을 둘로 나눈다.
  - 로컬과의 성능 비교는 공통 부분집합에서 한다.
  - 300편 전체에서 클라우드로 찾을 수 없는 기사의 비율(커버리지)은 따로 보고한다.
- 공통 부분집합의 결과를 300편 전체 성능으로 넓히지 않는다.

**시간 측정**
- 같은 작업자가 측정한다. 후보 순서를 교차해 학습 효과를 줄이고, 첫 사용 여부를 기록한다.
- 샘플이 작아 차이가 측정 변동 안에 들면 우열을 확정하지 않는다.

**기록 양식:** 질의ID, 후보, 반환 결과, 정답 일치, 위치 일치, 작업시간, 대기시간, 비고.

### Q5. 운영 조건

- **확인 내용:** 기사가 추가·수정될 때의 재색인·대응표 갱신 부담, 검토 완료 사본의 반영 절차, 월 비용의 상한 내 유지.
- **증거:** 단계 A의 문서 확인과 단계 B의 실측 중 관찰.

## 6. 종합과 판단 규칙

1. **조건 필터:** 원본 보존·업로드 금지·허용 사본 범위·비용 상한 위반이 확인된 후보는 제외한다. 미확인 후보는 조건부로 남긴다.
2. **종단 과업 비교:** 공통 부분집합에서 성공률·누락·위치 일치·작업시간을 비교한다. 이어서 커버리지 차이를 반영한다. 클라우드가 공통 부분집합에서 우세해도 비공개 기사를 찾지 못하면, 로컬 병행이나 혼합안이 필요한지 판단한다.
3. **허용 기준:** 위치 일치율 하한 같은 수치 기준은 이 계획의 제안값이며 사용자 확인 후 확정한다.
4. **조건부 결론:** 근거가 충돌하거나 차이가 작으면 조건별 결론으로 남긴다. 예: '한국어 형태소 분석이 필요하면 A, 질의가 고유명 위주면 B'.

## 7. 진행과 멈춤

**단계 A — 이번 주, 사용자 진행 지시 후**
- 범위: 공개 문서와 제공된 샘플만 쓴다. 설치·가입·계약·외부 연락은 하지 않는다.
- 순서:
  1. 8절 확인 질문을 해소한다.
  2. 샘플을 로컬에서 열람해 Q1·Q2의 유형과 위치 단위를 기록한다.
  3. Q3 문서상 적격성을 확인한다.
  4. Q4 정답셋과 측정 절차를 작성한다.
- 멈춤 조건: 후보별 적격성을 문서로 판정했거나 미확인 사유를 기록했다. 정답셋·측정 절차가 다음 달에 바로 실행 가능한 수준이다.
- 산출: 후보 적격성 표, 정답셋 초안, 측정 양식. 성능 순위는 내지 않는다.

**단계 B — 다음 달**
- 범위: 설치형 로컬 후보와 월 2만 원 이하 유료·무료 클라우드 후보를 같은 질의셋으로 실측한다. 설치·계약 자체는 그때 사용자 승인을 받는다.
- 멈춤 조건: 공통 질의셋 실측을 마치고 6절 규칙을 적용했다. 비용·기간 안에 실측할 수 없는 후보는 '미실측'으로 남기며, 문서상 기능을 성능 근거로 쓰지 않는다.

**보고 전 대조(두 단계 공통)**
- Q1~Q5 각각에 대해 답, 근거 위치, 실제 열람 범위, 남은 불확실성을 대조한다.
- 계획서가 조사 전에 저장됐는지, 조사 중 변경이 이 파일에 기록됐는지 확인한다.
- 목적·방법이 크게 바뀌면 재규정을 요청한다.

## 8. 사용자에게 확인할 질문(예비 조사 질문)
