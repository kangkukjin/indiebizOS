# 109회차 — 연구계획의 작성 대조와 별도 검토를 채택하거나 기각

사용자는 앞선 제안을 구현해 효과를 실험하고, 개선되지 않으면 기각하도록 요청했다. 이번 대상은 실제 의식의 계획 작성 경로다. 연구 실행·외부 자료 조사·평가자 전체 루프는 범위 밖이다. 합성 요청으로 논리·제약·의미 보존을 비교하므로 실제 외부 자료는 사용하지 않는다. 기존 실제 모델의 오류가 있는 계획은 D2의 입력으로 보존한다.

## 고정 설계

- 사례6개: 기존 실패 D1·D2, 새 H1~H3, 제한을 올바르게 보존해야 하는 새 대조 H4. cases.json의 입력과 checks를 모델 호출 전에 고정한다.
- S: 사례마다 현재 의식의 최초 규정을 실제로 한 번 만들고 A/B에 같은 바이트로 제공한다. 따라서 최초 규정의 우연한 차이를 작성 단계 효과로 세지 않는다.
- A: 현재 research_planning.prepare의 계획 호출·검사·저장 그대로.
- B: 같은 함수의 계획 작성 지시에 planning_check.txt를 넣고 이전 AI 초안의 지위를 표시한 후보. 상시 의식 프롬프트·연구 가이드·모델·스키마·호출 수는 그대로다. 계획 본문의 근거 대조와 모든 필드 반영을 요구한다.
- C: **그대로의 B 산출물**을 별도 문맥의 같은 모델로 review_system.txt에 따라 검토한다. issues가 없으면 B 바이트를 그대로 사용한다. 있으면 정확한 인용이 후보에 있는지 확인하고 최대1회 의식 정정한다. 지적은 사실로 강제하지 않으며 원문과 대조해 성립하는 것만 반영한다. 추가 조사 없음.
- 사례별 A→B와 B→A 순서를 교대한다. 두 작업 프로세스에서 각각3사례를 실행하므로 시각·캐시 효과가 완전히 통제된 실험은 아니다. 모든 사용량·시간과 오류를 보존한다.
- D2의 작업공간·이전 계획은 A/B에 별도로 복제한다. 같은 원문을 읽되 서로의 새 계획을 보지 않는다. C만 의도적으로 B를 이어받는다. 운영자 checks·정답·다른 실험 출력은 모델 입력에서 제외한다.
- 후보는 회차 폴더의 코드 사본으로 실행한다. 운영 파일에 적용은 채택 후이며 기각하면 운영 소스는 기준선과 동일해야 한다. 모델 비교 중 소스를 고쳐 결과를 유리하게 재실행하지 않는다.

## 사전 판정과 비용 한도

각 사례의 4 checks를 충족/부분/미충족으로 판정한다. 실제 잘못된 전제·제약·판정 규칙이 남으면 중요한 결함으로 기록한다. 단순 지침 문구 존재, 계획 길이, 모델 자체 승인 점수로 통과시키지 않는다. 사례 개선은 중요한 결함을 하나 이상 제거하고 새 중요한 결함을 만들지 않은 경우다. 사용자 목적·권한·범위를 잃는 새 결함은 중대 퇴행이다.

B 채택 조건: A보다 사례2개 이상에서 개선하고 그중 새 사례가1개 이상이다. 어느 사례에도 새 중요한 결함이나 기존 충족 check의 퇴행이 없어야 한다. 공통 S를 포함한 총 입력+출력 토큰은 A의1.25배 이하, 사례별 완료시간 중앙값은1.3배 이하다. 완전한 계측이 없거나 최소 개선을 못 보이면 기각한다.

C 채택 조건: B보다 추가로 사례2개 이상 개선하고 그중 새 사례가1개 이상이다. 잘못된 지적을 채택한 정정·새 중요한 결함·check 퇴행이 없어야 한다. 전체 검토 지적의 타당성을 수동 감사하고, 입증된 결함 없이 수정 호출만 늘어난 경우도 비용에 포함한다. 공통 S+B+검토+정정의 총 토큰과 완료시간 중앙값이 B의2배 이하여야 한다. 이 한도는 비용 절감의 증명이 아니라 이번 품질 개선에 허용하는 상한이다.

C가 유효해도 B가 채택 조건을 못 맞추면 A에 대한 결합 효과와 퇴행을 별도로 확인해야 하며 자동 채택하지 않는다. 기준 미달·불명확이면 해당 변경은 기각한다. 한 묶음의 각1회 관측으로 일반 성공률이나 통계적 우월성을 주장하지 않는다. 채택 후보가 있으면 남은 시간에 새 요청으로 재확인한다. 새 요청 결과가 기존 퇴행 금지 조건을 어기면 채택을 철회한다.
