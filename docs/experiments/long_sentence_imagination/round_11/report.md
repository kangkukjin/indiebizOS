# 11회차 — 검침 정산의 전체 IBL과 독립 수행 비교

## 결과와 적용

3,074개 합성 검침을 96계량기·날짜별로 정규화하여 2,872개 인접 구간, 17개 이상 원본행, 계량기별 집계와 보고서를 만들었다. 훈련자 수정본의 주 과제와 요율 변경 변형은 네 산출물 재독 및 독립 전건 검증을 통과했다. 검색 단계에서 확인한 공통 grep 계수 결함을 고쳤고 관련 52개 회귀와 라이브 재현을 통과했다. backend/RED 변경은 없으므로 지연 apply 대상이 아니다.

시스템 AI도 같은 입력의 두 과제를 실제 수행했다. 전체 구간·이상행·합계는 맞았으나 사전 기대와 계량기 한 곳의 빈 합계 표시가 달랐다. 요청의 모호함과 작성자 기준 오류를 구현 결함과 구분한다. 전체 훈련을 최초부터 성공했다고 평가하지 않는다.

## 과제·조건·재현 자료

자연어 원문은 request.txt, 실행 전 계획은 task.md다. 합성 입력 생성과 독립 기대 계산은 generate.py, 최초 완성 초안은 first_draft.ibl, 실행 수정본은 main.ibl/variant.ibl이다. 임의 Python은 입력 생성·독립 검증·HTTP 운반·증거 가공에만 사용했다. 실제 정규화·구간 계산·정산·파일 저장검증은 IBL이 수행했다.

입력: 2026-08의 96계량기, 날짜 슬롯 2,968, 같은 숫자 중복 100행, 충돌 6슬롯, 읽을 수 없는 값 5슬롯, 빠진 날짜 8개, 회전 4구간, 요율 없는 구간 30개. 서로 다른 수집원 두 파일과 계량기·요율 파일을 읽었다. 시스템 AI에는 정답·생성기·훈련자 프로그램 없이 입력 사본 경로와 자연어 요청, 별도 출력 폴더만 전달했다. 실제 발송·구매·공개·기기 설정은 없다. 입력 사본의 동일 지문은 evidence.json에 있다. 저장소 전체를 읽는 권한 자체를 차단한 샌드박스 실험은 아니며, 관측한 도구 흐름에서 정답 자료 열람은 확인되지 않았다.

완료 조건은 intervals.json, anomalies.json, summary.json, report.md의 생성, 전건 보존과 수치·근거 연결이다. 사용량 36,806, 확정 금액 108,800, 요율 B 3→5 변경 시 133,216. 상태는 ok 2,812/gap 8/conflict 12/unreadable 10/unpriced 30. 변형은 요구 변경 용이성 시험이다. task.md의 선택적 빈 수집원 견고성 시험은 실행하지 않았다.

재현 시 저장소 루트에서 generate.py를 실행하면 로컬 outputs/long_sentence_imagination/2026-09-30_11회차에 입력과 기대값을 재생성한다(기존 시험 파일을 덮어쓰므로 보존본이 필요하면 별도 체크아웃에서 실행). HTTP 접수가 가능한 상태에서 run_ibl.py main_fixed check, main_fixed, variant_fixed check, variant_fixed 순으로 저장된 IBL을 보낸다. verify.py trainer_main_fixed 및 trainer_variant_fixed로 전건 비교한다. HTTP 운반기는 origin=training, edition=2, steps=600000/rows=20000을 지정한다. 핵심 계산을 Python으로 대체하지 않는다. 로컬 원본 결과는 git 제외 대상이며 입력 생성기·전체 프로그램·검증기·결과 지문·판정 차이는 이 폴더에 남긴다.

## 작성과 수정

공개 조합 교재·문법·describe 계약으로 작성했고, 전체 초안을 저장한 뒤 검사했다. 정규화/구간/정산/저장검증의 책임으로 나누었다. 전건 계산이라 상위 몇 행을 추리는 관용구는 사용하지 않았다. main의 base 반환과 variant의 cached 명시 입력으로 비싼 읽기·구간 계산을 다시 하지 않도록 했다.

최초 검사에서 빈 객체로 초기화한 분기 값 때문에 필드 오류 5건이 나왔다. 주 과제와 참조 입력 변형을 나누어 고쳤다. 최초 보관 초안 이후 주요 수정 주기는 두 번(검사 오류, unpriced 의미 오류)이며, 최초 저장 전 중복 기준 보정과 HTTP 참조 전달 수정은 별도 운영 개입이다. 세부 작성 시간은 분리 미측정이다. 개발 세션에 이미 제공된 구조 지식의 영향을 완전히 분리할 수 없다. grep 내부 코드는 해당 실패와 최소 재현을 보존한 뒤 원인 진단에만 열었다.

첫 기대 계산은 중복 100행에 충돌 추가 6행까지 합쳤다. 이를 실행 전에 보정했다. 이후 첫 실행과 oracle이 함께 요율 없는 구간을 status=ok로 둔 오류가 시스템 AI와 비교하면서 드러났다. 원문의 unpriced 요구로 복원하고 기대값과 프로그램 이전 판본을 보존했다. criteria_correction.md 참조. 서로 다른 언어로 구현했다는 것만으로 독립 정답이라고 보장되지 않는 실례다.

## 공통 결함 수리: L11-1

증상: 문법을 찾아 읽는 grep가 결과가 다 왔는데 PARTIAL_SOURCE를 신고했다. 최소 자료는 한 줄의 `needle needle needle needle`이다. 내용 결과는 1행이나 total=4로 셌다.

원인 사슬: rg 내용 조회는 매칭 행 → _rg_count는 --count-matches로 부분 문자열 출현 수 → 서로 다른 단위 비교 → 거짓 truncated 및 부분 원천 실패. 소유 위치는 data/packages/installed/tools/system_essentials/fs_grep.py::_rg_count다. --count로 바꾸어 내용·count·files 모드와 Python 폴백의 행 단위를 맞췄다. 누락 표시를 가리거나 호출부 재시도로 우회하지 않았다.

신규 13개 회귀는 rg/Python × regex/literal × content/count/files와 실제 선택 제한·긴 줄 절단을 다룬다. 수정 전 7실패/6통과, 수정 후 기존 39건 포함 52통과. 등록 시험 스크립트로 실행했고 test_before.json/test_after.json에 영수증을 보존했다. 범위: 이 폴더 test_grep_counts.py, backend/test_grep_glob_dialect.py, backend/test_grep_edit_topic_gate_2026_09_05.py, backend/test_exposed_idiom_boundaries.py. 전수 회귀는 실행하지 않았다.

패키지 reload 뒤 실제 MCP 재현은 total=1/items=1/truncated=false/source_complete=true였다(run 1f6e637559a84ad7ad33ce60e88519b0, grep_after.json). 코드 수정 직후에는 캐시가 옛 모듈을 잡고 있어 reload가 필요했다. grep_before.json과 후 결과가 최소 증거다. 원래 전체 주 과제와 새 요율 변형도 수정된 환경에서 다시 실행·검증했다. 이 결함은 발견 경로의 문제이며 정산 수치 오류의 원인은 아니다. 커밋 관문에서 패키지 전체 지문을 쓰는 path_audited 4곳이 갱신을 요구했다. HEAD 대비 실행 코드 차이가 fs_grep의 계수 옵션·독스트링 두 줄뿐임을 재감사했다. read/fill/write/script의 회원 기기 경로·변환기·권한 선언은 그대로이며, 이들의 패키지 감사 지문만 31fa6d8c436f1f48로 갱신하고 정본 빌더로 파생물을 재생성했다.

토큰은 accounting=billable_usage의 실행 역할 필드를 그대로 표시했다. input과 cache_read를 별도 비용으로 더하지 않았다. 훈련자 작성자 토큰은 미측정이며 프로그램 내부 AI 호출 0회를 전체 비용 0으로 말하지 않는다. 따라서 양자 전체 토큰 효율을 비교할 수 없다.

- 풀이: 자료 읽기 후 IBL 단계 프로그램으로 계산했다. 주 과제의 거절은 순수 람다 안 파이프, 보간 따옴표, 읽기 전용 $i 재대입이었다. 진단 후 수정했다.
- 분할·재사용: 변형은 앞 결과 참조와 네 출력 파일을 읽어 구간을 재사용했다. 첫 read_result+describe 혼용은 기존 계약대로 거절됐다.
- 발견: describe와 조합 교재를 조회했다. 회상 후보 최고 점수는 주 .5606, 변형 .6224로 다른 과제의 구판 사례였다. recall.used 사건이 없어 자발적 사용 효과는 확인하지 못했다.
- 완료: 네 파일 재독 검증을 수행했다. 최종 평가 경로는 none이었다. 이 사실을 평가 실패라고 재분류하지 않는다.
- 축적: training이므로 증류를 하지 않는 경로다. 압축 사건은 관측되지 않았다. 증류 품질은 미검증이다.
- 비용 한계: 변형 중 DEFINITION_CHANGED로 출력 재독 4갈래가 거절됐다. 훈련자 수리와 독립 실행이 시간상 겹쳐 지문 변경의 영향을 받았으므로 깨끗한 성능 기준선이 아니다. 실패를 언어 결함으로 세지 않는다. 다음 비교에서는 실행이 끝난 뒤에만 소유 구현을 바꿔야 한다.

## 낭비 검토·종료·미검증

필요 비용은 전건 이상행 보존, 독립 비교와 산출물 재독이었다. 실제로 독립 비교가 oracle과 작성 프로그램의 공통 오류를 잡았다. 줄일 수 있는 일은 과도한 HTTP 전체 증거 반환(주 27.7MB·변형 14.5MB), 이미 있는 본문 재독, 규약 위반 후 재작성, 실험 도중 구현 변경으로 인한 복구다. 필요한 오류·근거·전건 산출물은 유지하면서 모델에 작은 요약과 참조만 전달해야 한다. 자료 재사용으로 변형의 검침 전처리 재실행은 피했다. 이번 수정의 전체 시간/토큰 절감률은 측정하지 않았다.

훈련 시작 21:38:26 KST, 새 탐색 종료 22:18 KST, 상한 22:38:26. 이 구간에 준비·작성·실행·원인 진단과 일부 수리가 겹쳤으므로 순수 작성/수리 시간을 정확히 분리하지 못했다. 증거 정리·보고 검토는 22:21 KST에 마쳤고, 이후는 커밋 관문·정본 반영 확인이다. 이 운영 시간은 훈련 실행 시간에 합치지 않는다. 오류 수를 늘리기 위한 새 실험은 하지 않는다.

개발 파일 변경을 감지한 재기동 제어자가 DRAINING 상태가 되어 HTTP 새 실행을 503/executed:false로 거절했다. 기존 외부 턴이 끝나기를 기다리는 상태였으며 강제 재기동하지 않았다. 수정본은 실행 중인 주체의 MCP로 완료했다. 이 MCP 스키마에는 origin이 없어 훈련 출처를 지정하지 못했으며, 호스트 에피소드/실행 경험에 섞일 가능성을 한계로 남긴다. 최초 HTTP 훈련과 시스템 AI 비교에는 training 표식이 있다.

손대지 않은 것: MCP origin 확장·재기동 정책·시스템 AI 문법 학습은 이번 grep 원인 사슬 밖이다. 추가 빈 수집원 견고성, 전수 회귀, 증류 품질, 전체 비용 개선은 미검증이다. 기존 판정을 뒤집는 언어 개정이나 파괴적 변경은 하지 않았다.
