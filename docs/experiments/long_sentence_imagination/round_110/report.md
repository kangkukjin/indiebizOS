# 110회차 — 다섯 원칙 점검 루틴의 구현과 실제 모델 비교

정본 저장소에서 구현·시험했다. **루틴은 작동했지만 운영 기본 적용은 기각했다.** 네 요청 가운데 중요한 결함을 줄인 것은 K2 한 개이며 새 요청에서는 개선이 없었다. 두 계획은 중요한 충돌이 남은 채 다섯 항목을 모두 통과했다. 비용 상한은 지켰지만 사전에 정한 품질 기준은 충족하지 못했다.

사용자 요청: “그럼 그렇게 만들어서 실험해봐. 시간과 토큰이 얼마나 드는가도 확인하고.”

## 구현과 비교 범위

사용자의 문제를 정확히 규정하고, 연구 결과가 이해·판단을 바꾸며, 질문에 맞는 증거와 방법을 선택하고, 실제로 시작·수정·종료할 수 있고, 근거보다 큰 결론을 만들지 않는 계획을 목표로 했다. 다섯 원칙은 지침을 늘리는 대신 작성 과정의 확인 절차로 구현했다.

1. 현재 의식이 문제규정과 연구계획 초안을 만든다.
2. 같은 급의 모델이 한 호출에서 다섯 원칙을 각각 점검한다. 항목마다 사용자 원문, 계획의 실제 문장·필드, 짧은 판정 근거, pass/fail/uncertain을 남긴다. 의식의 기존 평가기준도 검토 대상이다.
3. 코드는 다섯 항목의 누락·중복, 부정확한 인용, 판본 불일치를 거절한다.
4. 미충족이면 최대 한 번 수정하고 **다섯 항목 전부 다시 점검**한다. 수정 전 통과 기록으로 새 계획을 넘길 수 없다.
5. 여전히 미충족이거나 형식·호출 오류가 나면 후보와 실패를 보존하고 실행용 계획 전달을 차단한다.

구현: [five_principle_gate.py](five_principle_gate.py), [점검 지시](audit_system.txt), [실험 연결 코드](run_experiment.py). 의미의 옳고 그름을 코드가 보증하지는 않는다. `releasable`은 이 루틴이 검증한 기록을 소비하는 내부 함수이며, 외부에서 임의로 만든 승인 객체를 인증하는 보안 장치는 아니다.

실제 설정은 의식과 점검·수정 모두 `claude_code/opus`, 고급이다. 최초 규정 S와 현행 계획 작성 A를 실행한 뒤 **그 A의 동일한 공개 필드와 본문**을 추가 루틴 R에 넣었다. 비교 경로는 현행 S+A 대 후보 S+A+R이다. R은 모델이 만든 계획·기준을 정답으로 받지 않고 사용자 원문과 대조한다. 과제별 채점 checks는 모델에 제공하지 않았다.

K1은 박물관 자원봉사 면담 계획의 후속 수정, K2는 공방 이탈자의 일·가족 경험, N1은 도서관의 정숙·교류 공간 운영 방식, N2는 온라인 수업 자동 알림의 학습 효과다. K1/K2는 이전 실패 유형의 회귀, N1/N2는 새 요청이다. `cases.json`의 K2 `kind=new`는 이전 회차에서 복사된 표기다. 사전 [task.md](task.md)가 정한 구분을 따라 **새 사례 조건에는 N1/N2만** 사용했다. 고정 파일은 사후 수정하지 않았다.

이 회차는 연구계획 작성에 한정했다. 전체 IBL 연구 프로그램, 자료 수집·연구 실행, 실행자와 최종 평가자의 수행은 시험하지 않았다. 기존 의식·계획 저장 부품을 재사용하고 추가 점검 계약을 격리 코드로 연결했으므로 별도의 IBL 어휘는 만들지 않았다. A의 저장물은 비교 기준일 뿐 실험에서 실행자로 전달하지 않았다.

## 결과

| 요청 | 현행 A | 추가 루틴 R | 품질 개선 판정 |
|---|---|---|---|
| K1 박물관 면담 | 경험의 공존·구체 장면·질문 공백 연결, 중요한 결함 미관측 | 5항목 통과, 수정 없음 | 개선으로 세지 않음 |
| K2 공방 메모 | 도서관에 공공 속성 추가; 작성자 미확인인데 2차 기록으로 단정 | 공공 속성 수정 후 재점검 통과, 기록 출처 단정은 남음 | 1개 결함 감소, 부분 개선 |
| N1 도서관 운영 | 조건별 사례 비교→현장 질문, 중요한 결함 미관측 | 5항목 통과, 수정 없음 | 개선으로 세지 않음 |
| N2 자동 알림 | 새 연락 금지와 관리자 자료 요청이 충돌 | 5항목 통과, 수정 없음 | 중요한 미탐지 |

네 루틴 모두 정상 종료했고 형식·인용 검사를 통과했다. 실제 모델에서는 무수정 통과 세 번, 수정과 전항목 재점검 한 번을 관측했다. 미통과 차단·잘못된 인용 거절·오래된 판본 거절은 단위 시험에서 확인했으며 실제 모델 묶음에는 그런 종료가 없었다.

내용 평가는 훈련자가 사용자 원문과 계획·문제규정·기준을 읽어 수행했다. 점검 출력도 읽었으므로 독립·맹검 평가가 아니다. [review.json](review.json)에 8개 계획의 다섯 원칙 판정, 요청별 확인 네 항목, 50개 정확한 인용, 중요 결함, 다섯 점검 기록의 감사를 보존했다. 모델의 pass 수를 성과로 세지 않았다.

## 무엇을 고쳤고 무엇을 놓쳤나

K2의 초안은 “‘도서관에서 근무’ → ‘공공·문화 기관에서 근무’”를 일반화 예로 제시했다. 점검은 원문에 도서관 유형이 없다고 지적했다. 수정본은 원문을 유지하거나 ‘직장에서 근무’로 넓히고 공공·학교·사설 유형을 더하지 않도록 바꿨다. 점검자가 제안한 ‘문화 기관’ 대안도 그대로 따르지 않았다. 이는 의미 보존에 도움이 된 실제 수정이다.

그러나 같은 계획의 `task_framing`은 “메모는 기록자가 남긴 2차 기록이므로 참여자 본인의 말과 구분한다”고 단정한다. 본문은 작성자가 본인인지 다른 사람인지 미확인이고 “메모는 2차 기록일 수 있다”고 한다. **메모가 참여자 자신의 기록일 수도 있다**는 반례가 남아 있는데, 재점검은 본문의 조건부 문장을 인용하며 통과시켰다.

N2의 사용자 조건은 “새 연락·시험·설문은 하지 마”이다. Q0의 첫 행동은 “시스템 관리자나 담당자에게 자료 목록과 메타데이터를 받는다”이다. 기존에 보유한 목록을 직접 읽는 경로로 한정하지 않았다. 점검자는 **학생 연락을 배제했다는 이유**로 execution을 통과시켰다. 연락 금지의 대상을 학생으로 좁힌 것이다. 나중에 연구 진행을 요청받더라도 이 금지가 자동으로 사라지지는 않는다.

**L110-1 — 근거 인용을 갖춘 통과 판정도 다른 필드·실행 단계의 충돌을 놓친다.** 기존 L107-1의 필드 간 전제 불일치, L107-2의 제약 범위 문제와 이어진다. 관측은 위 두 반례다. 긍정 문장을 찾아 통과 근거를 채우는 방식이 반례 탐색을 충분히 유도하지 못한다는 것은 원인 가설이며 확정된 모델 내부 설명이 아니다.

K2의 ‘공공·문화’를 포괄 범주로 관대하게 읽어 결함에서 제외하면 개선 사례는 1개에서 0개가 되어 기각은 유지된다. N2의 연락 금지를 학생만으로 좁게 해석하더라도 새 사례의 개선은 생기지 않는다. 한 문구의 논쟁적인 해석에 채택 결론을 의존시키지 않았다.

## 시간과 전체 토큰

최초 문제규정부터 최종 계획까지 포함했다. 입력에는 캐시 읽기·생성이 포함되며 출력에 포함된 추론 토큰을 다시 더하지 않는다. 공유한 S+A는 비교 경로에는 각각 포함하지만 물리 사용량에서 중복 계산하지 않았다.

| 경로 | 4요청 전체 입력+출력 | 요청당 평균 토큰 | 요청별 단계 시간 합 중앙값 |
|---|---:|---:|---:|
| 현행 S+A | 350,136 | 87,534 | 145.11초 |
| 점검 루틴 S+A+R | 488,831 | 122,208 | 180.08초 |
| 증가 | 138,695 (+39.6%) | 34,674 | 34.97초 (+24.1%) |

‘중앙값의 차이’와 ‘추가 단계 시간의 중앙값’은 다르다. 후자는 28.78초다. 수정이 필요했던 K2는 더 오래 걸렸다.

| 요청 | 현행 전체 시간 | 루틴 포함 전체 시간 | 추가 시간 | 추가 토큰 |
|---|---:|---:|---:|---:|
| K1 | 151.74초 | 180.22초 | 28.47초 | 19,620 |
| K2 | 139.36초 | 281.43초 | 142.07초 | 85,567 |
| N1 | 150.86초 | 179.94초 | 29.08초 | 17,751 |
| N2 | 133.92초 | 158.29초 | 24.36초 | 15,757 |

추가 비용의 구성은 최초 점검 네 번 70,429토큰, 수정 한 번 50,147토큰, 재점검 한 번 18,119토큰이다. 점검만이면 이번 관측에서 약 24~29초가 추가됐고, 수정 사례에서는 점검·수정·재점검 합계 약 142초가 추가됐다. 수정이 없는 사례의 시간 범위를 전체 점검 호출 범위로 일반화하지 않는다(K2 최초 점검 자체 약36초).

실험의 실제 물리 사용량은 **14호출, 입력 402,226·출력 86,605 = 488,831토큰**, 미계측 호출 0이다. 캐시 읽기 192,620·생성 209,572는 입력의 부분집합이다. Codex 훈련자 자신의 토큰은 계측할 수 없었고 청구액으로 환산하지 않았다.

두 프로세스에서 K1→N1, K2→N2를 진행했다. 실제 모델 실행 구간은 **19:24:30~19:31:51 KST, 약7분21초**다. 병렬 작업들의 시간을 합산한 값과 전체 경과 시간을 구분한다. 단계 시간에는 해당 단계의 시작·저장 비용을 포함하며, 사례별 실제 벽시계도 [costs.json](costs.json)에 있다. 순서·캐시·병렬 부하를 완전히 통제한 지연 시험은 아니다.

준비 포함 시작 19:19:57, 상한 20:19:57이다. 판독·기록 종료와 전체 훈련 시간은 [completion.json](completion.json)에 남긴다.

## 채택 판정과 보존

사전 조건은 중요한 결함 또는 실행 가능성 부족을 **두 사례 이상에서 개선하고 새 사례 하나를 포함**, 새 중요한 퇴행이 없으며 토큰·시간이 각각 현행의 2.5배 이하여야 한다는 것이었다. 이번 결과는 개선1·새 사례 개선0, 새 중요한 퇴행 미관측, 토큰1.396배·시간1.241배다. 따라서 **품질 최소치 미달로 기각**했다. 잘못된 통과 두 사례도 별도로 기록했다. 시험을 본 뒤 기준을 낮추거나 후보 지시를 고쳐 같은 비교에 다시 넣지 않았다.

- 점검 계약 **22개 시험 통과**: 누락·중복·인용·판본·한 번 수정·전항목 재점검·미통과 차단·호출 실패를 검증했다. 의미 타당성 증명과 다르다.
- 12단계·14호출·5번의 5항목 점검·50개 수동 인용·A와 동일한 R 입력 4건, 저장 계획 지문, training 출처, 비용 합산을 검증했다.
- 전체 실험 프로세스 종료 확인 후 결과를 회수했다. 실행 도구 이벤트는 없었다.
- 운영 `research_planning.py`, 의식 프롬프트, 심층연구 가이드는 시작 SHA와 동일하다. 108회차 수정을 유지했다.
- 새 기본 회귀·폰 번들·backend 전수는 실행하지 않았다. 제품 코드에 채택하지 않은 격리 실험이며 이 시험은 기본 backend 회귀에 자동 수집되지 않는다.
- 구현·시험·원 응답·수정 전후·판정·계측·실패 반례와 재검증 코드를 정본 Git에 남긴다. 동적 전체 입력은 로컬에 두고 지문을 보존했다.
- 작성 코드·기록의 공백 검사는 통과했다. 원 모델 출력 세 파일의 공백만 있는 줄6곳은 원문 지문을 보존하기 위해 그대로 남겼으며 전체 `git diff --check`는 이를 신고한다.

이번에 확인한 능력은 **다섯 항목을 빠짐없이 기록하고 수정 판본에 다시 결속하는 절차**다. 이것을 연구계획의 내용까지 통과시키는 품질 보증으로 쓰는 것은 지지되지 않았다. 다음 후보로는 각 원칙마다 긍정 근거를 더 쓰는 대신 원문 조건과 실제 행동, 문제규정과 본문의 충돌을 직접 대조하는 방식을 시험할 수 있다. 이는 미검증 후속 가설이며 이번에 적용한 개선은 아니다.

훈련 가이드의 사전 기준 고정, 검사·정상 종료·과제 달성 구분, 전체 비용 기록이 판정에 도움이 됐다. 지침이 부족해서 호출을 더한 실험으로 해석하지 않으며 가이드 문장을 추가하지 않았다. 재검증: [reproduce.md](reproduce.md), 상세 비교: [comparison.json](comparison.json).
