# 13회차 — 센서 보정과 모호한 JSON 원천의 실패 귀속

정본 main에서 수행. 12회차 구현 상태에서 작성했고 첫 커밋 관문과 초기 실행이 겹쳤다.
훈련 중 구현 지문은 바꾸지 않았다. 시작 구현은 12회차 커밋 9ddbae92와 같다.

## 과제와 최초 관측

request.txt/task.md의 같은 자연어를 훈련자와 시스템 AI에 제공했다. 합성 120측정과
12센서 계수를 병렬 읽기→센서 결합→보정값·초과 판정→센서별 집계→두 파일 저장·재독으로
연결했다. 지역 함수 3개, 공개 교재·describe를 참고했다. 이미 앞 회차 진단에서
JSON 읽기 구현을 봤으므로 기본 조건의 독립 작성 용이성으로 일반화하지 않는다.

첫 초안 검사 ok/incomplete, 정상 1.175초: 120행·12그룹 전건 일치, 합계 2024·초과 30.
변형은 calibration.json 첫 센서의 slope 키를 2와 20으로 중복했다. 0.591초에 blocked,
source_complete=false였으나 오류가 `공개 결과 계약 위반: $<json>.text<json>...`이고
error_code=NON_JSON_RESULT여서 원천 경로가 없었다. 마지막 값을 써서 잘못된 계산을
완료한 것은 아니다. 바깥 공통 검사기가 이미 방어했다.

## 발견과 개선

L13-1 작성·복구 진단: 원천 JSON 파서가 중복 키를 소실시킨 후 원문 text를 바깥 출력
검사가 다시 파싱해 차단한다. 원천 문제를 도구 결과 결함으로 오진하고 파일이 빠진다.
원천을 읽는 경계에서 기존 공통 검증을 적용하고 파일 경로와 함께 read 실패로 반환한다.
잘못된 자료의 차단을 유지하며, 서로 다른 객체의 같은 키는 허용한다.

필요한 비용은 전건 계산·저장 검증이다. 원천 오류와 도구 구현 오류를 구분하지 못해
코드·자료를 재조회하는 비용이 개선 후보다. 최초 프로그램 자체 모델 0회, 작성자 토큰
미측정. 전체 비용 절감률은 비교하지 않는다. 최초 초안과 main은 동일하며 수정 주기 0회다.
