## 2. 작성과 수리 고리

분해는 **IBL 수집·메모 의미 판정 → IBL 수치 분석 → 파일 Python의 보고서 조판 → IBL 저장·재읽기**다. 과제 전체를 Python에 숨기지 않았다. 수집·분석의 함수 계약은 기존 10회차를 재사용했으며 이는 새 독립 작성 속도의 증거가 아니다. 훈련자는 구현을 아는 개발자라는 한계가 있고, 작성은 교재·Script 가이드·공개 describe/API 계약으로 진행했다. 원인 진단 때에만 후술한 내부 소스를 읽었다.

- [analysis_v0.ibl](drafts/analysis_v0.ibl): 수집과 분석을 지역 함수로 감싼 최초 초안. 검사 오류0, 실행9.805초. Jev1회, 입력3,515·출력885·캐시0.
- [render_main_v0.ibl](drafts/render_main_v0.ibl): `inputs Text → write(~turn/조판.py) → script(path,args) → write(md/json) → read`. 확정 분석값은 `$ref`. 정상2.094초. [Python 원문](drafts/render.py).
- [render.ibl](drafts/render.ibl): 파일 부분 수정 뒤에도 원래 프로그램을 유지했다. `분석→분서` 오타 주입은 SCRIPT_EXIT/KeyError로 실패했고 `self:edit` 수정 뒤 새 시도2.699초에 정상본과 바이트가 같은 파일을 만들었다. 코드 전체 재전송·셸 편집·AI 재호출은 없었다.
- 같은 실패의 resume은 **같은 execution_id** 영수증을 반환했다. 코드 수정 뒤 같은 resume은 RESUME_DIVERGED로 거절했다. 확인된 실패를 자동으로 다시 돌리지 않았다.
- stdout에 JSON을 찍었지만 결과 파일을 안 쓴 변형은 **RESULT_MISSING**이었다. stdout을 값으로 재해석하지 않았다.
- 독립 CLI는 보존된 코드·stdin으로 **동일 KeyError·줄번호·본문**을 반환했다(새 실행 디렉터리만 다름). inputs에서 파일까지 바이트 보존을 확인했다. [검사](cli_validation.json).
- [전체 IBL](drafts/full_failure_v0.ibl): 수집부터 조판까지 한 문장으로 합쳐 의도적 후반 실패를 냈다. 읽기18+모델1을 19/19 재사용,8.941초. 마지막 Script의 원문 stdin을 읽어 확정값을 회수한 [수리 문장](drafts/full_recovery.ibl)은0.953초에 나머지를 완료했고 파일이 정상본과 바이트 동일했다.
- 같은 전체 IBL에 정상 Python 본문을 공급한 실행은8.033초에 저장·재읽기까지 완료했다. 이는 앞 읽기·모델 재사용을 포함한 수치이며 새 자료 수집 비용으로 세지 않는다.
- 최종 문서 검수에서 `cell(None)`이 오류 없음까지 “확인 필요”로 표시하는 **훈련자 작성 오류**를 발견했다. 값 검사는 통과했으나 v0의 표시 품질은 미흡했다. `self:edit` 한 번으로 “—”로 바꾼 [v1](drafts/render_v1.py)을 저장했다. 메모 유형의 실제 미확정5건은 그대로 유지했다. 의도적 오타와 별개인 실제 수정1주기다.

## 4. 확인된 개선점

### L15-1 — 실패 호출의 확정 입력을 바로 참조하기 (우선)

한 문장 안의 순수 함수가 만든 `$분석` Record는 Script 실패 뒤 공개 `completed_calls`에 없다. 응답은 성공 도구 호출 앞6개만 제시하고 나머지14개를 omitted로 표시했다. 함수 계산값은 도구 영수증도 아니다. **값은 보존돼 있다.** 기록 폴더의 원문 stdin을 `self:list → self:read → .data.분석`으로 읽어 복구했다. 사전 반환으로 분할했을 때의 `$ref`는 바로 동작했다.

[숫자2개 최소 재현](repro_failed_arguments.json)에서도 합계5·건수2를 계산해 실패 Script에 넣으면 completed_calls는 파일 작성 영수증만 반환한다. 원인 진단은 `backend/cognition/model_result_view.py:completed_call_references`와 실제 실패 봉투로 확인했다.

**제안:** 기존 값 저장소의 참조 계약으로 실패 호출의 **해석 완료 args**를 `read_args/input_args`로 제공한다. Script에 별도 재시도 정책을 만들지 않는다. 완료 호출6개 제한에는 전체 조회 경로를 잇는다. 원문·권한·출처·마스킹/만료 규칙을 유지한다. 검증은 원래 단일 문장 후반 실패에서 재수집·모델 재호출·데이터 재전송0으로 부분 수정→새 시도를 닫는 것이다. R2·R4 연결.

### L15-2 — 재개 거절에서 변경된 차원을 구별하기

Python 한 줄만 바꾸고 동일 IBL·inputs로 resume했을 때 `RESUME_DIVERGED: 기록된 호출의 입력이 달라졌습니다`, details={}다. 거절 자체는 옳다. 하지만 코드·실제 인자·인터프리터·환경 중 무엇이 바뀌었는지 알 수 없다.

`ibl_file_script.invocation_identity`는 코드·환경 지문을 만들지만 `ibl_run_journal.begin`은 합친 request_hash 차이만 보고 공통 문구로 거절한다. **제안:** 동일 안전성을 유지하며 변경 차원·이전/현재 지문과 새 시도/확정값 참조 안내를 제공한다. 코드 본문이나 비밀값 표시는 불필요하다. R2·R4 연결.

### L15-3 — 부정한 수리 지시를 긍정 요청으로 분류함

훈련자가 덧붙인 “외부 발송이나 시스템 수정은 요청하지 않습니다” 때문에 최초 route가 REPAIR였다. 의식이 `needs_repair:false`로 판단한 뒤 `consciousness_rejected_core_repair`로 THINK에 정정됐다. 실제 RED권한·시스템 변경은 없었다.

`CognitiveConsciousnessMixin._is_repair_cue`는 구역어와 수리동사의 동시 출현만 본다. 원본 AST에서 상수/메서드만 분리한 [최소 재현](repair_cue_repro.json)에서 “백엔드는 수정하지 말고 자료만 분석해 줘”도 true다. 이번 요청 작성에 들어간 부정문이 실험의 라우팅 조건을 바꿨다는 교란도 명시한다.

**제안:** 금지·인용·가정 속 수리 표현과 긍정 실행 의도를 구별하는 기존 요청 분류를 보강한다. 사후 의식 검증과 권한 경계는 유지한다. 긍정 수리 요청의 탐지를 떨어뜨리지 않는 쌍 시험이 필요하다. 의식 호출 전체가 불필요했다거나26분의 원인이라고 단정하지 않는다. R3·R4 연결.

### 발견·선택의 후속 후보 (결함 확정 아님)

시스템 AI는 조판에서 여덟 정적 필드/서식 오류를 받고도 Script를 조회하지 않고 IBL을 수정해 완료했다. 언어 표현 불가능은 아니며, 이 성공을 “자발적으로 새 Script를 써서 수리했다”는 증거로 세지 않는다. 기능 존재와 자연스러운 선택은 별개다.

후속 비교는 **이미 확정된 분석 결과**로 같은 조판 요구를 두 경로에서 수행한다. 특정 업무용 낱말을 추가하기보다, 복잡한 값 가공·조판에서 inputs→write/edit→script→다음 낱말의 짧은 일반 예제가 필요한 지점에 발견되는지 확인한다. Codex가 공급한 spreadsheets 스킬63,844자 조회와 IBL 실행 경로가 함께 쓰였다. 이 스킬을 읽은 행동은 하네스 지침에 따른 것이므로 작성자의 실수로 세지 않는다. 다만 범용 스킬 상세와 IBL 가이드의 연결 비용을 검토할 근거다. 문자 수를 토큰으로 환산하거나 전체 시간의 원인으로 단정하지 않는다. 가이드 분량을 상시 늘리거나 Script 선택을 강제하는 안은 이번 근거로 확정하지 않는다. R4·R5 연결.

## 5. 필요한 비용·줄일 일·미검증

전수 입력 확인, ID/날짜 정규화, 미응시/퇴원 구별, 상담 의미 판정, 근거 연결과 저장 후 검증은 품질에 기여했다. 선택 필드·인자 추측의 재작성, 실패 입력을 찾기 위한 폴더 조회, 부정문 때문에 수리 경로로 우회한 것은 줄일 후보다. 이미 `$ref` 덕분에 모델 재호출은 피했다.

훈련자 실행은 실제 조판 수리1주기, 통제된 실패 변형은 별도다. 훈련자 작성 토큰은 미측정이며 프로그램 안 Jev4,400토큰만으로 전체 비용을 대체하지 않는다. 시스템 AI는 billable_usage의 전 역할을 합산했으며 리허설이라 증류0이다. 다른 실험 자료는 추가 실행하지 않았다. 불명 영수증·취소·타임아웃·권한 거절·보존 만료는 앞 구현 회귀의 영역이며 이번 라이브 훈련에서 다시 검증하지 않았다.

준비·훈련·진단은 약08:02~08:36 KST, 기본60분 안에 종료했다. 보고서 정리·증거 보존·커밋 시간은 별도다. 자동 승인 검토의 첫 개인정보 우려 거절은 생성 코드/원문 전부를 대조해 합성 자료임을 입증한 뒤 재검토가 허용했다([검증](synthetic_verification.json)).

가이드 소견: 최초 조건·실행/달성 구분·시스템 AI 독립 실행·토큰 포함 범위가 유용했다. 원장 상단 요약표는10회차까지였지만 말미에는11~14회차가 별도 절로 기록돼 있었다. 이를 확인해 다음 번호15를 사용했다. 최초 번호 설명의 착오는 사후 정정했으며 시스템 결함으로 세지 않는다.

## 재검증 자료

`drafts/`는 최초 초안·정상/실패·수정판을 보존한다. 원자료와 기대값은 추적된 `../round_10/input_09/`, `expected_09.json`에 있다. API 요청은 edition2·origin=training·같은 trainer task_id로 실행하며 analysis의 result_ref를 render의 분석 입력에 넣는다. 전체 문장은 폴더/본문/태그/출력만 inputs로 받는다. 정상 본문은 render.py, 의도적 실패는 `report = args["분석"]`를 `report = args["분서"]`로 바꾼 판본이다. write/edit를 포함하는 실패 재현에서 원문 자료를 다시 쓰지 않는다.

시스템 AI 검증기는 `.venv/bin/python docs/experiments/long_sentence_imagination/round_15/validate_ai.py outputs/long_sentence_imagination/2026-10-01_15회차`로 실행했다. outputs의 전체 기록은 비추적이며, 본 보고서·최소 재현·지문·호출 원문·수치 검증은 git에 보존한다. 7일 뒤 Script 원문 기록이 만료될 수 있지만 합성 입력과 본문으로 새 훈련을 재현할 수 있다. 원래 실행 영수증이 그대로 살아 있다고 가정하지 않는다.
