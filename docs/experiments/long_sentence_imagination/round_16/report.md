# 16회차 — 재고 정책 변경과 문맥 단절 뒤 재사용

**L15-1~3을 정본 main `6a4fd95a`에서 수리한 뒤 진행한 훈련이다.** 이번에는 저장 결과의 세션 간 접근 가능성과 실제 선택을 구분했다. 문맥 초기화 실행에서는 앞 결과가 남아 있고 조회 가능했지만 원자료 7개를 다시 읽었다. 문맥 유지 비교는 **훈련자의 상태 복원 누락으로 무효**다. 세 조건의 성능 우열이나 일반 효율 향상을 입증한 회차로 보고하지 않는다.

## 과제·사전 조건

[task.md](task.md), [원래 요구](prompt_seed.txt), [변경 요구](prompt_baseline.txt), [공통 역할](agent_role.txt). 4개 창고×80개 상품, 기초 320행·상품 80행·입출고 3,216행·예약 480행의 **합성 4,096행**이다. 원자료 7파일은 수정하지 않았다. 전체 320쌍·창고 합계·상위 10쌍·처리 건수와 MD/JSON을 만들고 저장 후 재읽기한다. 변형은 `target=threshold+0`에서 `threshold+20`으로만 바꾼다. B 요청 세 개는 출력 폴더를 제외하면 동일하다.

훈련자 계산은 IBL이며 정답은 별도 SQLite 집계·조인·정수 나눗셈으로 산출했다([fixture.py](fixture.py)). 따라서 훈련자 IBL을 그대로 정답 계산기로 복사하지 않았다. 모든 JSON 행과 숫자·순위·합계, MD 표의 모든 창고 합계와 상위 10개 수치를 대조한다. A의 총 발주량은 18,038, B는 23,936이며 가용 재고 합계 13,156은 불변이다.

자연어 실행은 격리된 시험 프로젝트의 두 에이전트를 사용했다. 실행·계획·검수·평가 모델은 `gpt-6-astra:high`, 경량 분류는 `deepseek-flash`로 동일 설정이다. `origin=training`이므로 증류가 꺼진 조건이며 장기기억 축적 전체의 시험이 아니다. 훈련자는 앞선 코드 수리로 내부 지식을 가진 조건이다. 라이브 코드는 모든 훈련 실행 동안 변경하지 않았다.

## 재사용과 비교 조건

baseline은 앞 이력이 없는 별도 행위자다. seed가 A를 수행한 뒤 그 행위자의 메시지·네이티브 세션 연결·참조 원장 상태를 보존했다. cold에서는 메시지와 네이티브 세션 연결만 숨기고 저장 결과·참조 원장은 남겼다. cold 시작 뒤에도 선행 계산 결과와 17개 호출 목록이 조회 가능함을 읽기 전용으로 확인했다([reference_reachability.json](reference_reachability.json)). 이 참조를 모델에게 전달하지는 않았다.

cold는 원자료 7파일을 다시 읽었고 선행 호출 목록(`read_result:{calls:true}`), 선행 프로그램·분석 참조를 선택하지 않았다. 같은 턴 안에서는 자신이 새로 만든 결과를 `$ref`로 이어 썼다. 따라서 **세션 간 값 참조가 끊긴 것은 아니며, 이번 자유 선택에서는 저장→검색→선택→변경 입력 재사용이 이어지지 않았다.** cold가 804초로 기준선 612초보다 비쌌다는 시간만으로 이 결론을 낸 것이 아니다. 실제 호출 경로가 근거다. 이 관측 1회로 모든 새 세션의 행동을 일반화하지 않는다.

warm은 seed의 메시지·세션 연결·참조 원장을 복원하고 cold 산출물을 별도 백업 위치로 숨겼다. 그러나 **pursuit 과제 원장을 복원하지 않았다.** seed 시점 백업에는 이 행위자의 pursuit가 없었는데, cold가 만든 `pursuit_e677f854e3345beeab0f7972cffc802e`에 warm이 연결됐다. 혼합 상태에서 의식은 “이전 산출물을 읽거나 재사용하지 않는다”는 조건을 새로 넣었다([warm_framing.json](warm_framing.json)). 이는 요청·공통 역할에 명시되지 않은 제한이지만, 실험 상태 혼입 때문에 정상 후속 동작의 제품 결함으로 확정하지 않는다.

또한 문자열 `history_summary`가 `_history_replacement`가 되어 네이티브 resume을 끊는 기존 코드 경로를 거쳤다. seed thread `01a0f658-d9e5-7fc1-b060-42f67afe8cfc`를 복원했으나 실제 실행 thread는 `01a0f674-a7f0-7d73-b492-017ba6d95e27`였다. 따라서 **warm은 문맥 유지 상한 비교에서 제외**한다([isolation_verification.json](isolation_verification.json)). 실행된 [harness.py](harness.py)는 이 결함을 보존한 증거이며 올바른 통제 복원기로 재사용하면 안 된다. 전체 서버 상태를 스냅샷했다고 주장하지 않는다.

## 발견과 우선순위

L16-1~2는 [최소 재현](repro_evaluation.py)과 [실제 결과](repro_evaluation_result.json), [평가 입력 대조](evaluation_gap.json)로 남겼다. 라이브 수리는 하지 않았다. 호출은 공통 상관 ID로 합치고, 평가에 필요한 마지막 실행·저장·검증 근거가 긴 앞쪽 결과에 밀리지 않도록 보존하는 것이 후속 수리 후보다. 예산을 무작정 늘리거나 재고 과제 전용 규칙을 추가할 이유는 없다. UNKNOWN을 근거 없는 성공으로 바꾸는 수리도 아니다.

새 언어 개정은 0건이다. AI에서 나온 필드 존재·미지원 `ceil` 거절은 작성·발견 마찰로 기록했으며 언어 구현 결함으로 세지 않았다. 같은 턴 `$ref` 사용은 여러 번 관측됐지만 `reuse`나 임시 Script 선택 효과를 비교한 회차는 아니다. 기존 기억 후보는 제시됐고 `recall.used` 사건은 없었다. 이것만으로 모델이 제시된 기억을 전혀 참고하지 않았다고 단정하지 않는다.

## 비용과 한계

[ai_metrics.json](ai_metrics.json)은 역할별 청구 사용량, [round_costs.json](round_costs.json)은 응답별 사용량·용도·당시 입력의 원본 위치와 관측 도구 입력을 담는다. [ai_programs.jsonl](ai_programs.jsonl)에 실제 요청 코드·입력 참조·거절·실행 결과 참조를 보존했다. [cost_by_purpose.json](cost_by_purpose.json)은 라운드 용도별 합계다. 네이티브 `token_usage_record.response_id`를 궤적 사건과 조인했고 완료 실행의 입력/출력 합계를 `model.usage`와 대사했다. 입력 토큰에는 캐시 적중이 포함된다. 캐시·추론 토큰을 다시 더하지 않는다. 라운드/역할의 경과 시간을 더해 사용자 벽시계라고 쓰지 않는다.

용도는 계획·탐색·수집·검사 거절·재작성·계산·저장/검증·평가로 나눴다. 검사와 탐색을 모두 낭비로 취급하지 않았다. 타입·원천 무결성·포장 단위·보고서 대조는 요구 품질을 지키는 비용이다. 작성 오류의 재수정과 중복된 평가 증거는 줄일 후보지만, 해당 라운드의 모든 토큰을 없앨 수 있다고 가정하지 않는다. 회차 중 원래 데이터를 다시 계산하는 내부 검증도 당시 확인 범위를 기준으로 판단해야 한다.

훈련자 검증기에는 보고서의 동의어 헤더 `active 예약`을 `reserved`에 연결하는 보완이 있었다. 기준·정답을 바꾼 것은 아니며 처음의 MD 검사 false는 검사기의 열 이름 해석 문제였다. 모든 숫자를 독립 정답과 다시 대조했다. 하네스 진단 스크립트의 경로 객체 처리 오기도 고쳤다. 이런 준비·검수 비용을 언어 갭이나 시스템 AI의 오류로 넘기지 않는다.

60분 상한은 [timing.json](timing.json)에 실행 전 고정했다. 판정·보존·정리 시간은 별도로 기록한다. 유효한 warm을 다시 실행해 보기 좋게 맞추기 위해 상한을 늘리지 않았다. 다음 비교는 행위자의 대화·세션·참조뿐 아니라 과제 원장 및 실제 네이티브 문맥 연속성을 **실행 전에 확인하는 관문**이 필요하다. 데이터가 변하지 않았다는 조건도 명시하고, 먼저 강제로 두 경로의 효율을 비교한 다음 자유 선택의 발견 가능성을 분리해 보아야 한다.

## 재현·보존·종료

입력은 `fixture.py`로 재생성하며 [manifest.json](manifest.json)의 SHA-256과 대조한다. 기대값은 expected_0.json/expected_20.json이고 전체 산출물과 원응답은 `outputs/long_sentence_imagination/2026-10-01_16회차/`에 남는다. 이 폴더는 비추적이다. SQL 정답·프로그램·요구·호출 원문·정량 기록·갭과 이 보고서는 git에 보존한다.

실험·검증 종료는 `2026-10-01T08:05:00.743540+00:00`이며 준비부터 **56.29분**이다. ep4215~4218은 모두 ended_at이 있고 원 HTTP 요청도 종료됐다. 메시지·참조 원장과 가렸던 cold 파일을 복구하고 두 시험 에이전트를 중지했다. 프로젝트는 복구 가능한 휴지통 상태이며 시험에서 생긴 pursuit 2개도 이력을 보존해 종료했다. 네이티브 세션 연결은 이 시험 행위자의 키만 정리했다. 임시 프로젝트 생성이 자동으로 바꾼 인벤토리 문서는 시험 전 내용으로 되돌렸다.
