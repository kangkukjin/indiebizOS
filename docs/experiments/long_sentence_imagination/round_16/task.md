# 16회차 — 재고 정책 변경과 문맥 단절 뒤 재사용

합성 자료 4,096행(상품80+기초320+입출고3216+예약480), 입력 7파일. 외부 발송 없음.
최초 요구는 prompt_seed.txt, 동일 변경 요구는 prompt_baseline/cold/warm.txt다. 본문은 출력 위치를 제외하면 B끼리 같다.
완료 조건: JSON의 320개 행·4개 창고 합계·상위10개·건수 전부 SQLite 독립 정답과 일치, 보고서 수치·정책·자료 범위·저장 후 재읽기 검증.

## 사전 설계
훈련자 전체 IBL A와 정책+20 변형(저장 결과 참조), 자연어 독립 실행 A(seed), B(from scratch), B(cold), B(warm)를 계획한다. 자연어에 특정 구현·이전 실행 ID·재사용 방법을 알려주지 않는다. seed 준비 비용은 비교 B 비용과 별도로 공개한다.
새 프로젝트의 두 임시 에이전트에 같은 역할·현재 실행 모델을 사용한다. baseline은 이력이 없는 별도 행위자다. seed 뒤 네이티브 세션·대화 메시지·행위자 턴 원장 상태를 보존한다. cold는 네이티브 세션 연결과 대화 문맥을 제거하되 저장 결과/턴 원장은 유지한다. warm은 cold 결과가 보이지 않도록 seed의 동일 상태를 복원한다. 조작은 이 시험 에이전트의 데이터에만 한다. 실제 세션 ID·원장·원천 읽기 기록으로 조건 성립을 검증한다.

origin=training이므로 증류는 꺼진다. 시험 대상은 최근 결과/프로그램의 발견과 재사용이며 장기기억 축적 전체가 아니다. 개별 실행 1개씩은 탐색 관측이며 일반 효율 입증이 아니다. 시간·토큰·정답률과 실제 수집/재사용 경로를 함께 본다. read_result 자체보다 저장→검색→선택→변경 입력에 재사용이 이어졌는지 판정한다.

60분 상한(timing.json). 남은 시간에 비교를 마칠 수 없으면 신규 실행을 중단하고 실제 종료/미검증 범위를 남긴다. 라이브 수리는 회차 종료 확인 뒤 별도다. 훈련자는 코드 수리로 내부 지식을 가진 조건이며 독립 실행과 구분한다.
