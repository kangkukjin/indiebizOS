# 긴문장 상상훈련 17회차 — 시설 예약 시간구간 감사

진단 완료. 훈련자·시스템 AI의 기본/변형 네 결과가 모두 사전 완료 조건을 충족했다. 새 계약 공백 1건, 실험 지시의 모호함 1건을 기록하고 기존 평가 증거 문제(L16-2)에 재발 의심 증거를 연결한다. 시스템 AI 작성 오류 2건은 검사에서 차단되어 수정됐으며 결과 오산은 발견하지 않았다. 코어 수리는 하지 않았다.

## 1. 과제와 고정 조건

자연어 원문은 `request.txt`, 사전 기준은 `task.md`, 변형 원문은 `harness/variant_request.json`이다. 합성 예약 2,400건(CSV/JSON 각 1,200), 방 240개, 점검 480건을 감사했다. cancelled→unknown_room→invalid_interval 우선순위로 제외하고, 반열린 시간구간의 예약쌍·점검 충돌, 정원 초과/미상, 중복 없는 영향 예약, 모든 방 집계와 동률 규칙을 지킨 상위 10개를 JSON·Markdown으로 만든다.

새 연결은 **다대다 시간구간 결합 → 중복 없는 영향 집계 → 한 건물의 점유 정책만 변경**이다. 이전 재고 과제의 이름·행 수만 바꾼 시험이 아니다. 변형은 E 건물만 종료 뒤 15분을 점유에 더하고 W·점검 구간과 제외/정원 규칙은 유지한다. 추가/제거 충돌쌍과 영향 수 변화를 `delta.json`에 낸다.

시작 2026-10-05 09:45:43 KST, 상한 10:45:43(60분). 실험·진단 종료 10:10:14, **24.52분**. 이후는 증거·원장 정리와 커밋이다. 시작/종료 진단 시 정본 main 리비전은 `f03aea88b27dc783bc9e96bfcc6ac0100462b043`, 작업 트리 변경은 이 회차 문서뿐이었다. 모든 주/변형 작업은 종료했다.

공개 조합 교재·제공된 훈련 가이드·액션/관용구 계약과 이전 원장만 참고해 작성했다. 내부 구현 소스는 열지 않았다. 실행 뒤 읽은 것은 이 회차의 궤적·검사 영수증·시스템 AI가 작성한 IBL이다. 기본 조건에서의 작성과 내부 도움을 받은 작성을 섞지 않았다.

## 2. 작성·실행과 실제 결과

`drafts/p1_v0.ibl`·`p2_v0.ibl`을 검사 전에 보존했다. 실제 실행본은 설명 주석만 뺀 `p1_executed.ibl`·`p2_executed.ibl`이다. **주/변형 초안 수정 0주기**. Python은 합성 입력/독립 기준 생성과 사후 검증에만 사용했고, 핵심 과제 처리는 IBL로 했다.

P1은 병렬 파일 읽기, 숫자 정규화, 제외/유효 분류, 방·날짜 기준 후보 결합을 한다. P2는 P1의 명시 `$ref` 입력에 정책을 적용해 겹침·정원·영향·방별 집계·보고서 저장/재읽기까지 수행한다. 상위 방 선택에는 기존 `정렬해추리기`를 호출했다. 사전 정렬로 동률 room 오름차순을 확보했고 실제 결과를 독립 기준과 전건 대조했다.

## 3. 발견한 오류와 마찰

### L17-1 — 집계의 정적 효과 계약이 조합을 막음(확인)

`describe table:groupby`는 `effects:[unknown]`을 반환한다. 이 때문에 순수 집계 함수를 `map` 람다 안에서 호출하면 `PURE_EXPRESSION`으로 거절된다. 최소 재현은 `repro/groupby_in_lambda.ibl`, 검사 plan `79d8561acd198568ba9387025de34373c63f6a65043d6ae208e3354c925241a4`이다. P2의 사전 검사도 groupby 3곳의 내부 모델 호출을 '미상'으로 표시했다.

반증도 함께 남긴다. 읽기→groupby→반환을 `reuse`로 다시 실행한 실측은 **2/2 복원**이었다(run `15e3addc7f434b5386f80819919bc85c` → `ca9122d1a5784b878e2386c623c3c2ac`). 따라서 이 사례를 'groupby가 읽기 재사용을 차단한다'고 보고하지 않는다. 주 과제는 람다 밖에서 집계하므로 막히지 않았다. 확인된 범위는 정적 효과·사전 안내의 조합 공백이며 내부 구현 원인은 미조사다.

개선 후보: 집계 어휘의 정적 효과 계약과 실제 실행의 효과 해석을 일치시킨다. 새 어휘나 임의 우회 함수 추가는 필요 없다. 수리 시 위 최소 재현, 실제 읽기 reuse, 원래 전체 프로그램·새 조건을 함께 검증해야 한다.

### L16-2 관련 새 증거 — 있는 검증이 최종평가에 충분히 닿지 않음(전달/소비 위치 미확정)

두 시스템 AI 실행 모두 최초 최종평가가 '발췌되어 확인되지 않는다'는 이유로 UNKNOWN을 냈다.

- 기본: 결과가 이미 정확했지만 계산 정확성 근거 보완을 요구했다. 에이전트는 저장 참조를 회수하고 후보 전체 대조를 새로 작성·실행했다. 보완 실행 역할 사용량 180.386초·입력 680,212·출력 3,584토큰. 이 중 전건 대조는 품질에 기여한 검사이므로 **전부 낭비로 세지 않는다**. 초기 검수에서 비교 범위와 원본 예를 간결하게 제시하면 왕복을 줄일 후보다.
- 변형: 기존 결과 영수증 `49d158912d93454ca483ff5ec5f4eccd3b78ee65d04751dff1bc05b54a6b5fff`에 `verification.saved_files_read_back=3`, `exact_content_match=true`, 변형관계 검사와 후보 수가 이미 있었다. 평가자는 verification이 발췌에서 생략됐다고 했다. 보완은 **기존 영수증 열람·응답 보충뿐**, 재계산·파일 변경·새 execute_ibl 없이 끝났고 재평가가 승인했다. 보완 역할만 59.850초·입력 341,707·출력 829토큰이다.

변형은 결과를 바꾸지 않고 증거를 다시 설명하는 모델 왕복이 실제로 추가된 사례다. 상세는 `harness/evaluation_gap.json`, `decisions_and_recall.json`, `agent_variant_trace.json`. L16-2와 닮은 현상이지만 실제 평가 입력 전문을 확보하지 않아 **어느 직렬화·발췌 단계에서 빠졌는지, 평가 모델이 놓쳤는지**는 확정하지 않는다. 기존 수리 상태를 무조건 되돌리거나 새로운 코어 결함으로 확정하지 않았다.

개선 우선순위는 이 경계가 가장 높다. 전체 데이터를 더 많이 싣기보다 기준별 검증 범위·결과·원천/산출물 참조를 작은 증거로 연결하고, 같은 영수증의 보유 사실과 전달 사실을 검사해야 한다. UNKNOWN 안전 판정을 약화시키거나 필요한 검증을 삭제하는 방식은 제외한다.

### L17-2 — 독립 비교의 재사용 금지 범위가 모호함(훈련 설계 오류)

ep4336은 원자료 4개를 다시 읽고 기본 조건도 다시 계산했다. 실제 보고서에도 '기본 결과 파일은 읽거나 수정하지 않고 ... 재계산했다'고 명시했다. 훈련자 변형은 P1 참조를 사용해 원자료 재조회·정규화·후보 결합을 하지 않았다.

그러나 독립 요청의 '입력 밖의 다른 훈련 결과·정답·코드는 참고하지 마'는 훈련자 산출물 누출 차단을 의도했지만, 에이전트가 자기 직전 결과도 금지된 것으로 해석했을 수 있다. 따라서 **재계산은 확인된 사실이나 자발적 재사용 실패라는 인과 판정은 보류**한다. L8-1·L10-6·L16 회상/재사용 관측과 연결하되 새 언어 결함으로 세지 않는다.

다음 비교는 '너 자신의 직전 결과·참조는 사용 가능, 다른 실행자의 trainer/harness/drafts는 참조 금지'를 명시해야 한다. 이번 기록을 사후 수정하거나 추가 재실행으로 최초 조건을 덮지 않았다. `harness/reuse_comparison_limit.md`에 보존했다.

### 작성 오류(엔진 결함과 구별)

시스템 AI 기본 보완에서 `table:rename{mapping:...}`을 썼다가 `map` 안내를 받아 1주기 수정했다(ep4335 seq160). 변형 저장/검증 프로그램은 순수식 자리에 파이프를 넣어 1주기 수정했다(ep4336 seq102). 두 오류 모두 검사에서 잡혔고 실패한 계산이나 외부 쓰기가 실행되지는 않았다. 원 입력·거절·수정은 각 `agent_*_calls/`에 보존했다.

훈련 운영에서도 포트 8000 가정으로 연결 실패 1회, OpenAPI 스키마 이름 추측으로 INDEX 1회, 진단 검색에서 `glob` 대신 `file_pattern`이어야 하는 인자 오류 1회가 있었다. 실제 리스너·공개 계약·오류 안내로 해결했다. 이 3건은 **과제 IBL 최초 초안 오류가 아니라 준비/진단자의 발견 비용**이다. 감추거나 제품 결함으로 올리지 않았다.

진단 종료 뒤 원장 정리 중에도 실제 줄바꿈을 일반 IBL 문자열에 넣어 STRING_LITERAL로 1회 거절됐다. 실패는 파일 변경 전에 발생했고, 반환된 입력 참조를 재사용해 긴 문자열을 inputs Text로 옮겨 수정했다. 이 비용은 종료 후 기록 작업에 별도로 속하며 주 과제 초안 수정 0주기와 섞지 않는다.

## 4. 비용과 줄일 수 있는 일

전체 모델 청구 사용량은 `trajectory_event`의 `model.usage`, `accounting=billable_usage`만 합산했다. 모델 경계 이벤트나 `supervision.cost.summary`를 중복 합산하지 않았다. 캐시 읽기는 입력의 부분집합이며 아래 입력에 다시 더하지 않는다.

| 시스템 AI | 전체 시간 | execute_ibl 요청(검사 포함) | 검사 거절 | 입력 | 출력 | 입력 중 캐시 읽기 |
|---|---:|---:|---:|---:|---:|---:|
| 기본 ep4335 | 605.441초 | 12 | 1 | 1,634,920 | 12,745 | 1,294,848 |
| 변형 ep4336 | 408.958초 | 10 | 1 | 1,507,591 | 12,933 | 1,178,240 |
| 합계 | 시간은 각 행 참조 | 22 | 2 | 3,142,511 | 25,678 | 2,473,088 |

별도 작업대 증거조회/응답편집은 각 6회이며 위 execute_ibl 수에 포함하지 않았다. 두 실행 모두 분류·의식·실행·최종평가·보완을 포함한 토큰이다. 고급 역할은 gpt-6-astra:high, 분류 등은 deepseek-flash. 자동 압축 사건은 두 에피소드에서 관측되지 않았다. 훈련자/운영자의 전체 토큰은 미측정이며 핵심 IBL 안 추가 모델 호출 0회를 작성자 비용 0으로 해석하지 않는다.

- **필요했던 비용:** 혼합 형식 정규화, 제외/정원 null 보존, 시간구간 전건 계산, 저장 재읽기, 독립 기준 대조. 최종 검수 자체를 낭비로 보지 않는다.
- **확인된 줄일 후보:** 변형의 기존 검증 영수증을 다시 읽어 설명하는 보완 왕복; 오기 두 건으로 생긴 재검사; 준비 단계의 포트/스키마 추측. 증거 열람 통로는 동작했지만 처음 평가에 필요한 근거가 충분히 소비되지 않았다.
- **훈련자 코드의 개선 후보:** 변형 P2는 정원 분류와 W 건물 시간 검사를 다시 수행한다. 결과가 같은 것은 전건 대조로 확인했다. 정책 비의존 결과와 W 결과를 보존하고 E만 갱신한 뒤 합집합/집계를 재계산하는 설계를 다음에 비교할 수 있다. 원자료 읽기는 이미 재사용으로 피했다.
- **운영자의 낭비:** 첫 문서 조회에서 `.text`만 필요했는데 Document 전체를 반환해 본문·blocks가 중복 표시됐다. 이후엔 참조/필드를 좁혔다. 후보/결과 전문을 참조로 연결하면서도 모델에 큰 미리보기가 노출된 호출이 있었으며, 이것을 재사용 자체의 실패와 구별한다.
- **절감률 미주장:** 단일 표본, 두 실행자의 제공 정보·작성 범위 차이, 동시 실행 부하, 재사용 지시의 모호함 때문에 일반적인 시간/토큰 개선률은 계산하지 않는다.

## 5. 발견·검수·축적과 격리

시스템 AI는 계산을 머리로 처리하지 않고 여러 연결된 IBL 프로그램과 `$ref`를 사용했다. 같은 실행의 단계 사이 참조 재사용은 확인됐다. 기본 보완도 앞 정규화값을 회수했으며 원자료를 다시 읽지 않았다. 변형에서 자기 직전 산출물 재사용은 위 모호함 때문에 원인 미확정이다.

기본 ep4335의 해마 후보는 empty였고 계약 describe를 사용했다. 저장 관용구의 자발적 선택은 이 표본에서 확인되지 않았다. 이것만으로 기억 검색 결함이라고 판단하지 않는다. 두 실행은 최종평가 보완 후 APPROVED이며 독립 기준 검증도 통과했다. origin:training이므로 장기 증류/학습 효과는 시험하지 않았다.

에피소드 4335의 궤적 209건, 4336의 200건은 전부 source=training이다. 합성 입력과 회차별 파일 쓰기 외 실제 발송·구매·공개·예약은 없다. 22개 보존된 IBL 요청 기록의 코드에서 trainer/harness/drafts/expected 접근과 외부 발송·스케줄 어휘가 없음을 확인했다. 같은 계정의 파일 권한까지 막은 OS 샌드박스는 아니므로 누출 불가능을 보장했다고 쓰지 않는다. 두 동기 HTTP 프로세스와 두 에피소드 모두 정상 종료했으며 중복 요청·재시작은 하지 않았다.

## 6. 보존·재현과 미검증

정본 요약은 `docs/LONG_SENTENCE_IMAGINATION_LEDGER.md`, 재현 가능한 비민감 자료는 `docs/experiments/long_sentence_imagination/round_17/`에 보존한다. 로컬 전체 증거는 `outputs/long_sentence_imagination/2026-10-05_17회차/`에 있다.

1. `harness/generate.py`와 `prepare.ibl`로 새 회차 폴더에 같은 합성 입력·기준을 만든다. prepare는 재현용이며 이미 완료한 훈련을 다시 실행하지 않았다.
2. `drafts/p1_executed.ibl`을 inputs.root=입력 폴더, 예산 steps 1000000/rows 100000으로 검사·실행한다.
3. P1 결과 참조를 P2의 prepared에 전달하고 buffer=0/15, 서로 다른 out 폴더로 검사·실행한다. 코드 수정 없이 정책 인자만 바뀐다.
4. `drafts/delta.ibl`은 두 P2 결과 참조를 받아 차이를 저장하는 재현용 코드다. 실제 최초 delta는 `harness/run_manifest.json`의 검증 실행 안에서 생성했고 이후 저장본을 독립 대조했다.
5. `harness/verify.py`는 기대값/실제 JSON/MD를 stdin Record로 받아 전건 동등성과 보고서 수치를 검사한다. Markdown 의미·미확인 문장은 직접 확인해야 한다.

핵심 실행 id·결과 참조·예산은 `harness/run_manifest.json`에 연결했다. 최초 초안, 실제 코드, 요청, 합성 생성기, 검증기, 원본 도구 입력/응답, 역할별 비용을 보존했다. 훈련 결과와 후속 코어 수리를 섞지 않았다.

미검증: 악성/손상 원천·런타임 실패 후 resume, 실제 0건 방, 여러 제외 사유가 동시에 해당하는 입력, OS 수준 비밀 격리, 원자료 신선도 변화, 네이티브 세션 연속성의 별도 대조, 평가 입력 전문의 잘림 위치, 장기 증류, 수리 후 개선효과. 이번 변형은 정책 변경 시험이며 실패 주입 시험으로 보고하지 않는다. 제품 코드를 바꾸지 않아 pytest 종합 회귀는 실행하지 않았다.

가이드에서 도움이 된 부분은 기대값 사전 고정·두 실행 구분·실행 종료 확인·미측정 분리다. 다음 보완점은 독립 비교의 '다른 실행자 자료 금지'와 '자기 직전 결과 허용'을 명확히 나누는 것이다. 이번에는 가이드나 코어를 고치지 않았다.
