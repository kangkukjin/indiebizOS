# 긴문장 상상훈련 19회차 — FIFO 배분과 주문 취소 전파

훈련자와 시스템 AI의 기본·취소 변형 네 결과가 전건 일치했다. 수치 오류는 최종 산출물에서
발견되지 않았다. 작성 과정의 실패와 시간 낭비를 분리해 기록하고, 훈련 프로그램의 반복 탐색과
공통 실행 경로의 중복 지문 계산을 고쳤다. **검증된 결과를 다시 입력으로 연결할 때의 낭비가 핵심 발견**이다.

  수량 오류5·미등록품목4·재고가 없는 알려진 품목·동률 순서를 포함한다.
  취소는 수량 오류와 미등록품목보다 우선한다. 변형은 취소 후 처음 재고에서 다시 배분하고 변경 내역을 만든다.
- 사전 고정: [task.md](task.md), [기본 요청](request.txt), [변형 요청](variant_request.txt).
  완료 조건은 요약15키·주문1,800·입고472·배분 전건·변경762건·보고서 요약/상위10·저장 재읽기·기본 산출물 보존이다.
- 시작14:17:12 KST, 훈련·원인진단 종료14:33:40(약16.5분), 기본 상한60분.
  준비 파일의 start 필드는 생성 시각14:19:32이며 시작 시각과 다르다. 이후 수리·회귀·문서화는 별도 비용이다.

  시작부터 존재했다. 이 회차는 훈련 중 코어를 편집하지 않았다. 타 세션 작업 트리 전체의 불변은 강제하지 않았다.

  참조 해소 비용의 원인을 진단할 때 처음 열었다. 개발 세션의 기존 내부 지식까지 완전히 분리한 조건은 아니다.

  양쪽 실행은 training, 시스템 에피소드4341/4342도 source=training. 자동 압축0·증류 제외.

## 프로그램과 작성 마찰

P1은 파일3개를 병렬 읽고 수량 정규화·중복제거 결과를 반환한다. P2는 이 결과 참조를 받아
입고·주문 수량의 누적 구간을 만들고 겹친 수량을 배분한다. 저장·재읽기와 수량보존 검증도 같은 프로그램이다.
P3은 기본/변형 결과 참조를 결합해 delta를 저장·재읽기한다. 핵심 조합을 Python으로 우회하지 않았다.
Python은 합성 자료·독립 정답 생성(가변 재고를 직접 소진하는 다른 알고리즘), API 운반, 사후 대조에만 사용했다.

초안은 [drafts](drafts)에 보존했다. 수정 주기는 입력연결1회·IBL2회다.

1. P1 초안은 그대로 통과했다. 다음 입력에 `result_ref.input_args` 전체를 변수의 값으로 한 겹 더 넣은
   훈련자 실수를 MISSING_FIELD가 잡았다. 반환된 안내대로 내부 `$ref` 값을 이름에 연결해 해결했다.
2. P2 v0은 상태 문자열을 보고 qty의 null 여부까지 추론하지 못해 산술 검사에서 거절됐다.
   명시적인 `qty!=null` 필터를 더했고, rename의 Record 반환을 목록으로 오인한 두 len 경고도 `.items`로 고쳤다(v1).
   이는 작성 실수·현재 정적 추론 경계이며 실행기 오답으로 분류하지 않는다.
3. v1은 품목마다 주문 전체/입고 전체를 다시 필터해 100만 단계에서 멈췄다.
   v2는 전체를 품목·순서로 정렬하고 품목이 바뀔 때 누적값을 초기화한다. 동일 기대값을 유지하면서
   기본701,624단계·변형669,630단계로 완주했다. P3은 초안 수정0회다.

운영 실수도 비용에 포함한다: 실행 스크립트 경로를 잘못 지정한 1회, DB 열 이름을 잘못 가정한 조회1회,
사후 보고서 검사기의 `shortage` 요약값을 상태 행수로 덮어쓴 1회가 있었다. 마지막 것은 검사기 수정 후
원본 산출물을 재검사했고 보고서 자체는 수정하지 않았다.

## 시스템 AI 행동·남은 낭비

- FIFO 핵심은 Python 셸로, 정규화 뒤 필터·집계·저장은 IBL로 했다. 언어 전체로 해결한 것은 훈련자뿐이다.
  셸 사용은 18회차에서 허용하기로 정한 통로이며 여기서 새 오류로 세지 않는다.
- 변형은 자기 prepared.json을 재사용했고 allocate.py는 바이트 단위로 동일하다.
  검증기도 `$old.verify`를 문자열 치환해 보완했다. 18회차와 달리 핵심 구현을 다시 작성하지 않았다.
  반면 처음 자료3개를 재읽고 lots를 다시 정렬·raw_orders를 다시 세었다. 실제 사용은 했으므로
  무용한 호출로 단정하지 않지만, 입력 불변을 확인한 준비값 참조를 남기면 더 줄일 후보이다.
- 기본의 검사 거절2회에서 `$rejected`+code_edits가 실제 사용됐다. 한 번은 `.items` 오기,
  한 번은 보간 문자열 안 따옴표 충돌이었다. 거절 후 긴 원문 재전송 대신 부분 치환으로 복구했다.
- 자작 관문은 검증기 쓰기에서 기본·변형 각1회 발생했다. 기본은 pandas 설치 여부, 변형은
  world_tools 안내를 확인하고 같은 내용을 다시 저장했다. 기존 L18-3의 설계대로이며 폐지하지 않았다.
- 평가 두 번 모두 첫 판 승인이다. 근거 누락 때문에 결과를 다시 쓰는 왕복은 없었다.
  지도의 duckdb는 used로 오기되지 않았다. 관용구 자동 축적·증류는 리허설이라 시험하지 않았다.

필요했던 비용은 원자료 처리·FIFO/원가 계산·전건 검증·기본 보존 확인이다. 줄인 것은 반복 탐색과
이미 인증한 원문의 중복 신원 계산이다. 검증을 생략해 시간을 줄이지 않았다.
앞으로 확인할 범위는 충돌하는 중복 주문, 입고 자체 오류/원천 실패, 다른 모델·외부 도구,
참조 해소의 JSON 파싱·큰 입력 타입 추론 비용이다. 이번 결과를 그 범위의 보증으로 쓰지 않는다.
