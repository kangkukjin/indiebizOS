# 20회차 — 배포 파일 대조와 원문 보존

## 과제·작성 조건

[요구와 사전 기준](task.md): 합성 세 CSV의 예정 파일 18행을 실제 파일 목록과 대조하고,
원천·비고를 보존한 JSON/CSV 보고서를 저장·재독한다. 실제 배포·발송·외부 자료는 없다.
훈련자는 공개 조합 교재, `self:read/write`·`table:groupby/join` describe와 HTTP 스키마를 읽고
[전체 초안](drafts/main_v0.ibl)을 작성했다. 초안은 수정 없이 검사와 실행을 통과했다.
소스코드는 주 과제·원천 부재 변형의 완료와 비고 손실을 확인한 뒤 원인 진단에 처음 열었다.
개발 세션의 일반 구현 지식까지 완전히 분리한 실험은 아니다.

작은 일회성 18행 과제이므로 가이드 §4-5에 따라 시스템 AI 독립 실행은 생략했다.
프로그램 내부 모델 호출도 0이다. 이는 자연어 요청을 받은 시스템 AI의 독립 수행 평가가 아니다.
출처는 `training`, 출력은 회차 폴더, 두 실행 모두 completed임을 확인한 뒤 수리했다.
[종료 영수증](evidence/training_end.json). 시작·훈련 종료 HEAD는 `f796cb8899d11686cdf010158b4b257cfb0f9c03`.
기존 미커밋 파일들은 건드리지 않았다.

분해: 세 원천을 병렬 읽고 실패를 명시 → 예정 행별 실제 경로 대조 → 상태 집계 →
JSON/CSV 저장 → 재독 검사. 핵심 계산은 IBL이고 Python은 합성 입력·HTTP 운반·독립 대조만 맡았다.
함수는 등록하지 않았으며 기존 교재 밖 방언이나 새 어휘를 추가하지 않았다.

## 발견과 수리

### L20-1 — CSV/TSV 원문 줄바꿈의 조용한 손실

공통 `read_text_window`의 기본 `open(..., newline=None)`과 회원 경로의 `Path.read_text()`가
파싱 전에 셀 안 CR/CRLF를 LF로 바꿨다. 비고의 `두 줄\r\n유지`와 `캐리지\r리턴`이 변했다.
또한 `delimited_data`의 기본 StringIO는 CR 행 구분을 처리하지 못했다. 이는 기존의
“인용된 줄바꿈 보존” 계약 위반이며, 요청의 새 옵션을 요구할 문제가 아니다.

CSV/TSV 구조 읽기에만 newline=''를 전달하고, 공통 CSV 파서의 StringIO도 같은 방식으로
줄 인식과 변환을 분리했다. 회원 경로도 수신한 임시 파일에서 똑같이 보존한다.
일반 텍스트의 기존 줄 정규화·번호·범위는 유지한다. 저장기는 이미 newline=''로 올바르게
기록했으므로 바꾸지 않았다. 회원 수신·출력 경로, base64/파일 크기 제한, 외부 자원 거절,
오류의 허브 경로 비공개는 바뀌지 않는다.

회원 구현 지문 관문은 수정 직후 기대대로 차단했다. 변경분의 경로 접근을 재검토하고
소스 `ibl_actions.yaml`의 감사 표식을 갱신한 뒤 빌드로 회원 manifest와 노드 사전을 재생성했다.
지문 검사를 끄거나 실패를 무시하지 않았다.

### L20-2 — 동일한 잘못된 값끼리 비교한 검증 맹점

최초 두 실행은 `json_verified=true`, `csv_verified=true`였지만 원문 비고는 손실됐다.
재독은 **저장된 값이 읽힌 값과 같은지**만 검증하며 최초 읽기의 충실성을 보증하지 않는다.
IBL 비교 연산의 오류가 아니라 훈련자의 검증 설계 한계다. 독립 생성 원문과 최종 파일의
전건 비교 및 CR/LF/CRLF 경계 표본을 회귀에 추가하고, 긴문장 가이드의 산출물 검증 절에도 명시했다.
별도 평가 모델이나 검수 목적의 원천 재수집은 추가하지 않았다.

## 비용·낭비 검토

- 필요한 비용: 원천4개 읽기, 대조·집계, 최종 JSON/CSV 저장과 두 번의 재독. 재독 자체는 필요한 검사다.
- 줄일 수 있는 재작업: 잘못된 보존 판정을 뒤늦게 발견한 뒤 전체 보고서를 다시 만드는 일.
  근본 입력 손실을 고쳤으며, 독립 원문 대조는 저장된 합성 자료로 수행했다. 과거 손상된 결과를
  자동 복원했다고 주장하지 않는다. 실제 재수리 확인에는 원래 프로그램을 다시 실행했다.
- 중복 모델 왕복·불필요한 재수집은 이 작은 과제에서 관측하지 않았다. 행마다 실제 목록을
  필터하는 구성은 큰 목록에서 반복 계산 후보지만 18행으로 병목을 입증하지 않았으므로
  새 엔진 최적화나 개선율 주장은 하지 않는다.
- 최초 기본 HTTP 0.602초, 원천부재 0.511초. 수리후 기본 0.593초이며 병렬 변형은 0.527~0.552초.
  이 수치는 작성·검증을 제외한 운반 포함 실행 시간이고 속도 개선의 근거가 아니다.
  작성자 토큰·전체 모델 비용은 미측정이다. 시작 전 교재 탐색 시간도 별도 정밀 계측하지 못했다.
- 과제 등록부터 훈련 종료까지 2분19초, 이후 수리·회귀·기록은 별도 운영 비용이다.
