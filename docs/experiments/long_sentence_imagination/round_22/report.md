# 22회차 — 도서 후보 복합키 정리

정본 main에서 훈련 종료 후 수리. [사전 과제](task.md), [합성 입력](inputs.json), [전체 프로그램](drafts/main_v0.ibl), [별칭 변형](drafts/alias_v0.ibl).

기본12행→7행/280, 두 번째 자료가 빈 변형6행/210 모두 최초 초안으로 달성했다. NFC/NFD·casefold·빈 키·필드 구분을 보존했다. 이후 내부 구현을 읽고 공개 별칭을 사용하는 추가 진단을 작성했다. 이 단계는 도움 받은 진단이며 맹검 성과로 세지 않는다.

**L22-1 (계약 결함·불필요한 재작성)**: `by:["title","author"]` 대신 문서가 안내한 `key:["title","author"]`를 쓰면 TOOL 오류로 종료했다. 타입 선언이 없다면서 항목별 each를 지시했는데, 그렇게 하면 복합키 비교 의미가 달라진다. 최초 읽기2회 뒤 막혀 결과 파일도 못 만드는 불필요한 왕복이었다.

소유 위치는 data-ops의 callable_contract.params. `by`와 별칭 `key`를 독립 인자로 중복 선언해 공통 별칭 투영이 작동하지 않았다. `key` 독립 선언 한 줄을 제거하고 기존 aliases 정본에서 투영하도록 수리했다. 새 별칭·어휘·파서 변경 없음. scalar 별칭은 원래 통과했고 list만 실패했다. 별칭을 계약에 다시 쓰려던 첫 수리안은 두 벌 선언 빌드 관문에 거절되어 제거했다.

모든 동기 실행이 completed/interrupted로 반환한 뒤 적용했다([종료 증거](evidence/training_end.json)). interrupted는 실패 프로그램의 영수증 상태이며 실행 중 티켓이 아니다. 수리 후 기본·빈 자료·별칭·입력순서 반전 새 변형 모두 독립 ID/합계 대조와 저장 재독 통과. 별칭은8행/360, 반전에서도 첫 행 g,h,i,j,k,m,e,f를 유지한다. [실행 ID·진단·비용](evidence/runs.json).

회귀는 backend/test_data_ops.py. 수정 전1실패/1통과 → 수정 후2통과, 선택기2파일→8/569 시험파일(1%), 선택 회귀68통과. 어휘 빌드·폰 번들·--check 통과. 시스템 어휘 검사23통과(60.14초), 결과는 evidence/system_tests.txt. backend 전수·frontend·독립 AI는 미실행. 작은 일회성 과제라 §4-5 규모 미달이며 모델 호출0, 작성자·수리 토큰 미측정이다.

필요 비용은 원문과 독립 기대값 대조·저장 검증이다. 제거한 낭비는 올바른 복합키 표현을 거절하여 생기는 실패/재작성이며, 전체 시간·토큰 절감률은 측정하지 않았다. 초기 실행 약0.4초, 수리 후0.4~0.5초는 한 표본이고 성능 향상 주장이 아니다. 샌드박스 로컬 연결 거절·빌드 중 자동 재기동 연결 거절은 운영 비용으로 남겼고 프로그램 결함에 합산하지 않았다. 훈련은60분 안에 끝냈으며 시각은 task.md·종료 증거 참조. 수리·회귀·기록 비용은 별도 후속 작업이다.

재현은 inputs.json의 a/b를 각각 {items:...} 파일로 저장하고 sources와 out을 inputs로 제공해 전체 IBL을 실행한다. 별칭 변형은 b에 Data/Park/80 행을 추가한다. 모델 해법과 정답은 쓰지 않았다.
