시작 정본 b86315b2. [사전 과제](task.md)·[합성 입력](inputs.json)·[최초 전체 IBL](drafts/main_v0.ibl)·[실행 증거](evidence/runs.json).

**L23-1 구현 결함**: flatten keep의 충돌 접미사가 행마다 달라졌다. 판매자 shipment가 있는 자식은 부모 번호가 shipment_2, 없는 자식은 shipment로 들어갔다. 원래 전체 프로그램은 실행/저장재독 성공이었지만 S1=5·S2=9 대신 S1=2·null=7·S2=5가 나와 과제 미달이다. shipment_2가 원래 있는 새 품목을 추가한 변형은 부모 shipment_3를 어느 행에도 만들지 않아 groupby가 실패했다. 결과 원문을 보존했다.

모든 훈련 동기 실행의 종료를 확인한 [뒤](evidence/training_end.json), handler._op_flatten을 수리했다. 자식 행의 전체 열 집합을 수집하고 부모 필드의 출력 이름을 한 번 정해 모든 행에 적용한다. 원래 자식 키·값, 부모 누락, scalar 자식의 value, 순서·원천 실패 근거를 보존한다. 공개 설명·독스트링도 이 계약으로 맞추고 기존 용례1건(keep 없는 펼침)의 무영향을 확인했다. 추가 메모리는 행별 base/carry 참조와 전체 열 집합이며 출력 바이트를 복제하는 별도 deep copy는 없다.

수리 뒤 같은 전체 프로그램에서 S1=5·S2=9, 기존 접미사 변형 S4=6, 새 역순 변형 S2→S1을 정확히 보존했다. 독립 입력에서 만든 모든 상세행과 JSON 산출물을 대조했고 재독도 일치했다. 첫 초안 작성 수정0회, 제품 수리1회. 22회차에서 내부 구현을 보았으므로 기본 조건의 맹검 작성 성과로 세지 않는다. 소규모 일회성4~5행 작업이라 독립 시스템 AI는 생략했다.

신규 회귀5건은 수정 전 전부 실패→수리 후 통과. scalar/중첩 keep·누락·입력불변·예약된 접미사·순서반전 포함. 직접 관련83통과, 선택기3파일→53/569시험파일(9%)과 원천실패 회귀를 함께 검사했다. 샌드박스 실행1223통과/10실패/1건너뜀은 렌더·수리 프로세스 권한 제한이었고 동일 범위의 실제 권한 재실행에서 **1233통과/1건너뜀**(79.39초)으로 확인했다. 최종 결과는 evidence/tests_selected_native.txt. backend 전수·frontend는 미실행. 파서/실행엔진 변경 없이 패키지 변환자와 설명을 수정했다.

필요 비용은 원래 입력과 상세행·집계의 독립 대조이다. 저장재독만으로 성공을 오판하는 재작업과, 행별 부모열 위치를 추적해 고쳐야 하는 우회를 제거했다. suffix 이름 계산은 행마다가 아니라 호출당1회지만 전체 벽시계 절감률로 환산하지 않는다. 최초 HTTP0.531초/변형0.367초(실패), 수리후0.467/0.593/0.456초, 같은 품질의 전후 시간비교는 아니다. 내부 모델0, 작성·진단·수리·회고 토큰 미측정. 훈련은 task.md~종료 증거의60분 상한 이내이며 수리/회귀/커밋은 이후 비용이다.
