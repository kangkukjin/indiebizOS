24행의 파일 읽기→팀별 count/sum/avg→순위→합계 검사→JSON 저장/재독은 최초부터 달성했다. A=8/92/11.5, B=8/100/12.5, C=8/108/13.5; 순위C,B,A·총300. 빈 자료 변형은0건·0합계. 수정 전후와 새로운 역순 변형까지 모든 값이 독립 기대값과 같다. 초기 프로그램 수정0회. 내부 구현을 앞 회차에서 보아 비용 가설이 있던 도움 받은 훈련이며 맹검 작성 성과로 세지 않는다.

**L24-1 구현 낭비**: `_rows_for_field`는 이미 객체 행이 있는 입력을 전체 열×전체 행의 직사각형으로 만들었다가 다시 dict로 바꿨다. `_op_groupby`는 봉투 메타데이터를 얻으려고 같은 표를 또 만들었다. 행마다 다른 선택항목이 늘면 입력 필드 수보다 훨씬 많은 빈 셀이 생긴다. 필요한 필드를 이미 가진 정본 items를 바로 선택하고, 봉투는 `_get_items`에서 얻도록 수리했다. 원천 도메인 탐색과 실제 table 입력의 기존 경로는 보존했다.

**L24-2 구현 결함**: 같은 경계가 items와 표시용 table이 함께 있는 입력에서 표 미리보기를 먼저 골랐다. 직접 핸들러 진단에서 items의 A=2/B=3 대신 미리보기T=9를 집계했다. 기존 `_explicit_table`의 items 우선 규약에 맞게 정본을 먼저 선택하여 A/B를 보존했다. 공개 v2의 입력 정규화는 이 미리보기를 먼저 벗기므로 원래 전체 IBL의 실패로 세지 않는다. 두 변경은 같은 원천 선택 경계의 수리다.

[훈련 종료](evidence/training_end.json)의 실행·추가 진단이 모두 끝난 뒤 적용했다. 원래 전체·빈 자료·새 역순 전체 프로그램 통과. 수리 직후 자동 재기동의503 응답은 작업 미접수로 기록하며 재기동 후 실행했다. 재전송 전 이미 실행된 작업이 없었고 실행 ID는 증거에 남겼다.
