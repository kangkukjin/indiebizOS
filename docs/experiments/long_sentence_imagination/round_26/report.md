## 3. 발견과 수리
- **L26-1 값 계약 공백**: `[self:task]` 의 투영 칸이 상황마다 달랐다(`error`·`result`·`timed_out`·`progress` 가 있다 없다 함).
  반환 타입 선언이 없어 검사는 통과했고, 실행 중 MISSING_FIELD 는 이미 시작한 작업 4개를 남긴 채 프로그램을 끝냈다.
  수리: 투영을 항상 같은 칸 `{task_ref, state, terminal, timed_out, result, failure, progress}` 으로(`task_receipts.view`·`_stable`),
  어휘 원본에 반환 계약을 **닫힌 Record**(`$closed: true` — `ibl_v2_types.declared` 에 선언 표지 추가)로 선언. 최초 초안은 이제 검사에서 거절된다(작업 시작 0).
- **L26-2 구현 결함(명세 불일치)**: 명세·가이드는 "시간 초과는 실패가 아니다, `timed_out: true` 를 돌려준다"인데 봉투가 `success:false`·`error` 라
  판본 2 에서 도구 실패로 올라갔다. `[catch]` 로 감싸도 `$error.details` 가 비어 시간 초과·작업 실패·모르는 작업을 가를 값이 없었다.
  수리: 시간 초과는 값(`success:true, timed_out:true, note`). 실패한 작업의 **상태 조회**도 값으로 답한다(작업의 사정은 `failure`, 호출의 사정은 `error` — 한 칸에 섞지 않는다).
  기다린 작업이 실패·취소·유실로 끝나면 호출 실패로 남기되 투영 칸을 `$error.details` 에 싣는다(`ibl_v2_adapters.decode_envelope`).
- **L26-3 실행·복구(안내 공백)**: 작업을 시작한 프로그램이 뒤에서 실패하면, 고쳐서 다시 실행하는 순간 작업이 중복된다(`reuse` 는 쓰기 호출을 재사용하지 않는다).
  접수증을 `completed_calls[i].input_args` 로 회수해 이어받는 길은 있고 동작했지만 어디에도 안내가 없었다. `task_receipts.md` 에 절차와 "시작/대기 프로그램 분리" 권고를 넣었다. 실행기 변경 없음.
- **L26-4 발견·학습(미수리)**: 등록 스크립트의 반환 모양이 목록·계약에 없어 시스템 AI 가 스크립트 원문을 읽었다. `[self:script]{op:"register", callable_contract}` 로 선언할 수 있으나 `시험` 은 선언이 없다. 후보로 남긴다.
- **L26-5 비용(관측만)**: 후속처럼 단순한 턴도 의식 단계 45초. THINK 관문은 기존 판정이라 손대지 않았다.
- 훈련 틀 결함: 대조기가 최종 보고서 안의 "이전 1차 상태" 사본을 확정 행으로 잘못 집어 시스템 AI 결과를 한 번 불합격으로 판정했다. 대조기를 고쳐 세 실행을 다시 대조했다(제품 결함 아님).
