## 3. 발견과 수리
- **L27-1 발견·학습(거짓 경고)**: `others:delegate` 가 접수증을 돌려주는데 검사가 "관측된 반환 필드에 없는 이름: task_ref"를 냈다(검사·실행 응답에 세 번 실림).
  원인: 실사용 반환 키 수확(`ibl_shape_sweep.harvest_from_health`)이 **가장 최근 한 줄**만 적었고 시험 대역의 줄도 섞였다 — usage 원천 42건 중 21건이
  실제로 돌려준 키를 빠뜨리고 있었다. 수리: 격리 원천(test·training) 제외, 액션당 최근 60줄의 합집합, 원장의 줄 상한(16키)에 닿은 관측은 `more` 로 기권.
- **L27-2 구현 결함(값 계약)**: 이미 끝난 작업의 `cancel` 이 종류의 지원 여부부터 따져 "지원하지 않습니다 (현재 succeeded)" 실패를 돌려줬다.
  늦어서 취소하려는 순간 끝나 있는 것은 작업의 사정이다. 수리: 끝난 작업의 취소는 **값**(종료 투영 그대로 + `note`), 살아 있는데 못 멈추는 것만 거절.
- **L27-3 능력 공백**: "안 끝난 일은 취소해줘"를 실행할 길이 없었다 — script·위임·렌더 전부 미지원. script 는 이 몸의 프로세스라 멈출 수 있다.
  수리: 취소 어댑터(`script_ops.task_status_cancel`) — 표식 파일을 남기면 러너가 1초 주기로 보고 스크립트와 **자손 프로세스까지** 끝낸 뒤 `cancelled` 를 기록.
  요청만 남고 확인 전이면 `cancel_requested`. 러너의 시간 초과 정리도 같은 나무 정리를 쓴다. 위임·렌더의 취소는 미수리.
- **L27-4 요구 해석(과제 설계)**: 독립 요청문이 시스템 AI 자신에게 위임하라는 글이 됐다. 순환 거절은 설계(`test_system_ai_cannot_delegate_to_itself`). 제품 결함 아님 — 독립 실행의 위임 경로는 미검증.
- **L27-5 구현 결함(평가 원장 이중 집계)**: 모델이 `execute_ibl` 에 붙인 `wait: 1`(회수용 전송 인자)이 스트림 쪽 호출에만 남아 작업대 기록과 지문이 갈렸고,
  모든 호출이 원장에 두 번 실렸다(보관된 증거로 재현: 8호출 → 16). 수리: 호출 지문에서 `wait` 를 뺀다(`final_evaluator.execution_trace`).
- **L27-6 구현 결함(실패의 정상값 위장)**: 수리 후 검증 중 시스템 AI 실행 모델이 초기화되지 않은 상태에서, 위임받은 턴이
  "AI 응답 생성 실패: …" 글을 **결과로 `succeeded`** 가 됐다([증거](evidence/post_repair_validation.json)의 가 요약 29자). 수리: 응답 없이 오류로 끝난 턴은
  `SystemAITurnFailed` 로 올려 작업을 `failed` 로 닫는다(시스템 AI 러너). 프로젝트 에이전트의 위임 보고도 같은 조건에서 `failed`.
- **L27-7 구현 결함(경합)**: 재기동 직후 병렬 대기에서 실행 중인 스크립트가 `unknown`("어댑터 미등록")으로 답했다 — 첫 적재가 '시도함'을 먼저 적어
  동시에 온 조회가 빈 등록부를 봤다. 수리: 첫 적재를 직렬화하고 끝난 뒤에 표시.
- 재관측: L26-4(등록 스크립트 계약 부재로 원문 읽기) 1회 추가. L26-5(의식 단계 56~64초) 관측만.
