## 종합 회귀에서 추가로 발견한 저장 오류 — L32-4

이 항목은 최초 긴문장 훈련의 발견 수에 합산하지 않는다. 전체 회귀의 스프레드시트 브라우저
검사에서 수식 `=B2*0.1`의 저장 캐시가0.7 대신0이었다. 단독 재실행에서도 재현됐다.
실패한 XLSX를 열어 보니 C2뿐 아니라 원래7이어야 할 **B2에 `=B2*0.1`이 들어 있었다**.
계산 완료 대기만 추가한 실행은1회 통과했지만 다음 실행에서 재발해 그 단계로 수리 완료하지 않았다.

원인: 이름 상자의 C2 입력 중 수식 계산·제안 반영이 화면 tick을 만들면, `ExcelFrame`의 효과가
입력 중인지 확인하지 않고 nameBox를 현재 선택 B2:C3으로 되돌렸다. 뒤의 Enter·수식 입력이
의도와 다른 셀에 적용될 수 있었다. 이름 상자에 포커스가 있는 동안 작성 중인 주소를 보존하도록
수정했다. 수식 입력줄의 기존 편집 보호는 유지했다.

별도로 격자 `settle()`은 편집 확정만 기다렸는데, 저장·스냅샷은 수식 계산 결과가 모델에 반영된 뒤

고정 sleep·상시 재계산을 추가하지 않고 실제 완료를 기다리며 실패/시간초과는 저장 성공으로 숨기지 않는다.
