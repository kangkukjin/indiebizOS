## 과제와 작성

[자연어 요청](request.txt)·[사전 조건](task.md). 합성 시설 40개, 예약 1,173행,
점검 195행에서 예약 합집합·동시 2건 이상 시간·점검 합집합·예약/점검 교집합·
이용 가능 시간·최대 동시 예약을 구한다. null 종료·역전 구간·미등록 시설 3행은
제외하되 이상 목록에 보존한다. 모든 구간은 시작 포함·끝 제외다.

변형 A는 점검 빈 목록과 예약 역순이다. 수리 후 새 변형은 맞닿은 두 예약으로
하루 전체를 채우고 240분 점검을 겹치며, 길이 0인 예약을 추가한다. 기대값은
실행 전에 고정했다. 예약 없는 시설도 40개 전부 반환한다.
기존 17회차의 예약 후보 배정과 분야는 비슷하지만 이번 연결은 경계 이벤트의
동시각 집계 → 상태 누적 → 구간 길이/최대 동시성 계산이다.

공개 `ibl_composition.md`, 문법 프래그먼트, describe(read/write/groupby)를 사용해
[최초 전체 프로그램](drafts/main_v0.ibl)을 작성했다. 행 검증과 시설별 집계를 지역 함수로
분리하고 최상위에서 병렬 읽기·합류·저장·재독을 연결했다. 핵심 계산은 IBL이다.
Python은 합성 생성, 분별 독립 oracle, HTTP 운반과 대조에만 썼다.
최초 초안 이후 내부 소스 열람은 아래 최소 재현의 원인 진단 때 시작했다.

작성 오류: 실행 예산을 max_steps/max_rows로 잘못 지정해 BUDGET_ARGUMENT 1회,
project_id를 system_ai로 잘못 지정해 PROJECT_CONTEXT 경고 1회. 각각 공개 진단과
기존 유효 문맥을 확인해 steps/rows 및 수동모드로 바로잡았다. IBL v0 자체는 무수정으로
검사 통과(동적 경계 incomplete)·정상 종료했다. 나중에 보고서 재독 누락과 반복 비용을 보완한
[v1](drafts/main_v1.ibl)은 한 번의 수정으로 검사·실행에 성공했다.

## 발견과 수리

| 갭 | 원인과 최초 관측 | 수리와 범위 |
| --- | --- | --- |
| L34-1 | 잘못 지정한 프로젝트 ID가 “문맥 없음”으로 안내됨. 진단 중 명시 ID 해소 실패가 호출자 project_path로 조용히 폴백함을 회귀로 재현 | HTTP는 PROJECT_NOT_FOUND와 ID를 반환하고 검사/실행 전 거절. 공통 라우팅도 명시 ID 실패 시 다른 프로젝트로 폴백하지 않음. 유효 ID·생략 시 문맥·시스템 프로젝트 자동 준비는 보존 |
| L34-2 | 교재의 “groupby 집계 함수 포함”을 agg 콜백 지원으로 읽고 최소 호출 시 VALUE_PROTOCOL: Closure. 오류 인자 위치가 없고 catch도 불가 | JSON 전용 어댑터의 잘못된 Callable은 ARGUMENT_CONTRACT와 details.path를 반환. Closure·Builtin 모두 적용하며 네이티브 표 콜백은 유지. 교재에서 순수 지역 함수 호출과 agg 명세를 구분 |
| L34-3 | 훈련자 프로그램이 시설마다 전체 1,365행을 필터링(273,240단계). JSON 재독만 하고 보고서 재독 누락 | 한 번의 시설별 행수 집계·정렬 뒤 연속 구간을 잘라 함수에 전달. 빈 시설을 다시 포함하고 보고서도 재독 assert. 업무 프로그램 수정이며 새 언어 기능 아님 |

L34-2의 잘못된 콜백을 자동 지원하도록 언어를 늘리지 않았다. 공통 JSON 경계가
지원하지 않는 인자임을 정확히 설명한다. 정상 인자의 추가 순회는 없고 기존 숫자 정밀도·
비유한 값 거절을 유지한다. 외부 실행이 시작되기 전 인자 변환의 실패만 복구 가능하게 했다.
최소 요청은 evidence/probe_*_request.json, 전후 진단은 runs.json이다.
수리는 공통 계획의 실행 의도 보존·실패 진단·재작업 축소(R2/R4)에 해당한다.

## 비용·낭비·검증

같은 기본 입력을 전수 회귀 종료 후 순서대로 실행한 1회 비교:
v0 546,527단계/3.672초 → v1 277,213단계/2.701초.
계산 단계 49.3% 감소, 엔진 시간 26.4% 감소다. 두 파일 검증은 더 엄격해졌다.
HTTP 전체 완료 시간은 약 5.65→4.95초였다. 별도로 여러 프로그램을 겹쳐 실행한
기록은 부하가 달라 시간 비교에서 제외했다. 표본 1회·이 과제의 결과이며 시스템 AI 전체
토큰/시간 절감이나 일반 성능 향상의 증거로 확대하지 않는다.

필요한 비용은 동시각 경계 집계·빈 시설 보존·이상 행 분리·독립 전건 대조였다.
제거한 낭비는 시설별 전체 재검색, 잘못된 인자의 모호한 진단으로 인한 추가 탐색이다.
남긴 후보는 후속 AI가 자기 Script를 다시 작성하는 비용이다. 독립 AI 수리 후 재실행은
하지 않았다. 문법·어휘 추가, 프런트엔드, 외부 발송·공개는 없다.
