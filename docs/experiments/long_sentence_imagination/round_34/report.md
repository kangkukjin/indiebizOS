## 낭비와 한계

- 필요한 비용: 파일별 기여분 저장(재처리·조건 변경 때 재독 0 의 근거), 실패 사유 보존, 재독 검증.
- 줄일 수 있었던 일: 없음(훈련자). AI 는 요청 밖 분기 시험·재실행을 스스로 했고, 그 결과 상태 설계는 훈련자보다 견고했다(sha256). 비용과 품질의 상충으로 기록한다.
- 한계: mtime 분 해상도는 운영체제 수정 시각을 그대로 믿는 설계의 한계이기도 하다(복사·되돌리기로 mtime 이 옛 값이 될 수 있음). 내용 지문 없이는 어느 설계도 완전하지 않다.
- 미검증: 같은 일이 동시에 두 번 뜨는 경우(상태 파일 경합), 중간 실패 뒤 부분 상태(현재 설계는 끝에 한 번 저장 — 실패 시 재독 비용만 생기고 상태는 안전).
- 전체 토큰·시간 절감률 미측정. 훈련자 작성자 토큰 미측정.
