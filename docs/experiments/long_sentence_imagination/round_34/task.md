# 긴문장 34회차 — 시설 예약·점검 시간 감사

시설 40곳의 하루 예약·점검 자료를 감사해줘. 시간은 0~1440분이며 모든 구간은 시작 포함·끝 제외다. 시설별 예약시간(합집합), 중복 예약시간(동시 2건 이상), 점검시간(합집합), 점검 중 예약시간(양쪽 교집합), 이용 가능 시간(예약·점검 모두 없는 시간), 최대 동시 예약 건수를 계산해줘. 예약 없는 시설도 포함해. end가 null이거나 0 <= start < end <= 1440을 위반하거나 등록되지 않은 시설이면 집계에서 제외하고 id와 kind(booking/maintenance)를 자료 이상에 남겨줘. result.json은 {rooms:[{room,booked,conflict,maintenance,blocked_booking,free,peak}],invalid:[{id,kind}]} 구조, report.md에는 시설별 전건 수치 표와 자료 이상 목록을 담아줘. 저장한 두 파일을 다시 확인해.

합성 rooms 40·bookings 1173·maintenance 195행. 정답은 분별 독립 그리드 oracle. 기본·변형 모두 40시설 6수치 전건 및 이상 id 집합 일치, 보고서 전건 수치, 저장 재독, 입력 불변이 완료 조건.
변형 A: 점검 빈 목록·예약 역순, 같은 프로그램에 다른 입력. 기대 점검/점검중예약=0 및 예약 집계 불변.
수리 후 새 변형: R01 예약 [0,720), [720,1440), 점검 [600,840); 기대 예약1440·충돌0·점검240·점검중예약240·이용가능0·최대1, R02 영구간 이상1, 나머지 빈 시설.
분해: 검증(행→유효성), 시설집계(유효구간→6수치), 최상위 병렬 읽기→집계→두 산출물→재독. 파일 효과는 최상위만.
공개 교재·describe만 참고한 최초 작성, 내부 코드 미열람. 훈련자 토큰 미측정. 상한60분(19:14~20:14 KST), 종료 후 수리는 별도. 독립 AI는 반복 업무이므로 포함.
