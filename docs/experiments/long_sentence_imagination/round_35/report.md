# 35회차 — 국제 접수의 시각 비교·정렬 비용

## 과제와 판정

합성 1,200행·8창구·6시간대 접수를 실제 순간으로 마감 판정하고, 시각/id 순으로 정렬하여 창구별 건수·좌석을 집계했다. [사전 과제](task.md), [첫 전체 프로그램](drafts/main_v0.ibl), [재현 하네스](harness/run.py). 표본이나 합계만이 아니라 모든 행의 순서·원문·집계, 보고서 마감·합계·전건 표, 저장 후 재독과 입력 10파일 불변을 확인했다.

|---|---:|---:|---|---:|
| 훈련자 기본 | 602/598 | 1,805 | 검사 오류0(incomplete 런타임 경계), 정상, 달성 | HTTP 0.905초 |
| 훈련자 역순/마감 1시간 연장 | 902/298 | 2,705 | 같은 프로그램, 정상, 달성 | HTTP 0.714초 |
| 독립 AI ep4434 | 602/598 | 1,805 | 정상, 전건 달성 | 턴 106.402초 |
| 독립 AI ep4435(후속 변형) | 902/298 | 2,705 | 정상, 전건 달성 | 턴 42.156초 |

훈련자는 공개 조합 교재·문법·명세·describe만으로 첫 초안을 작성했고 작성 수정 0회였다. 입력 읽기→지역 분류/보고서 함수→두 파일 저장→병렬 재독을 전체 IBL로 실행했다. 기본과 원변형 성공 후 내부 구현을 열어 비용 및 극단 연도 경계를 진단했다. 연도 경계는 **내부 진단의 도움을 받은 추가 탐침**이지 일상적인 2026년 자료가 실패한 것이 아니다.

시작 정본 main `c7bc6d5be989641c64f0c5ba62da546a08f98b7a`. 훈련 상한 60분(08:31~09:31 KST), 약 12분 안에 종료. 주·변형 AI 작업 `task_sysai_1a67e39d`·`task_sysai_5302199a`는 각각 08:40:58·08:42:07에 succeeded였고 결과를 회수한 뒤 구현을 수정했다. 동기 IBL 실패의 저널 `interrupted`는 반환된 실패/재개 가능 영수증이며 실행 중 백그라운드 작업은 없었다. 실행 ID·상태·비용은 [요약 증거](evidence/summary.json), 첫 실패는 [진단 원문](evidence/boundary_before.json).

## 발견과 수리

| 갭 | 원인·증거 | 공통 수리 |
|---|---|---|
| L35-1 구현 결함 | 유효한 `0001-01-01T00:00:00+14:00` / `9999-12-31T23:59:59.999999-12:00`의 정렬 키가 UTC datetime으로 변환하다 OverflowError. 전체 프로그램이 정렬에서 중단. 관계/그룹 식별자에도 같은 원인 확인 | `common/value_semantics.py`: 정렬에 정수 마이크로초 좌표 사용. 부동소수 timestamp와 범위 밖 datetime 생성 없음. 관계 키는 기존 영속 표기를 보존하고 종전 생성 불가능했던 범위에서만 정수 정본 키 사용 |
| L35-2 과도한 비용 | 기본 1,200행에서 버킷 분류와 버킷 내부 정렬이 같은 날짜 키를 두 번 해석: 2,400회 | 행별 키를 한 번 계산해 버킷 안에서 재사용. 안정 정렬·동률·버킷 방향·결측 뒤 배치·원문 객체 유지 |

R4의 반복 계산 비용과 공통 값/조합의 정확성을 개선한다. 새 문법·어휘·업무 전용 예외는 추가하지 않았다. 처음 시도한 datetime 객체 직접 정렬은 파싱 중복은 줄여도 비교마다 오프셋 계산이 생겨 국소 6.644ms로 느려졌다. 이를 정수 좌표로 바꾼 두 번째 수리안으로 마무리했다. 첫 실패·느린 중간안은 로컬 runs에 보존했다.

동일 입력, 동일 Python 프로세스에서 이전 커밋과 최종 구현을 번갈아 22회씩 측정했다([재현](harness/benchmark.py), [수치](evidence/benchmark.json)). 반환 전체 동일, 날짜 해석 **2,400→1,200회**, 정렬 중앙값 **5.697→2.107ms**, tracemalloc Python peak **126,766→70,056바이트**. 이 수치는 순수 정렬 한 번의 국소 측정이다. 전체 HTTP·작성·모델 비용 절감률을 뜻하지 않는다.

회원 공유 record 조회는 `can_read`·권한 projection 뒤에 같은 sort_records를 사용한다. 이번 변경은 정렬 값과 비용만 다루며 인증·주체·파일 경로·권한 필드를 바꾸지 않는다. `record-ops/ibl_actions.yaml` 의존 지문을 재감사하고 빌더로 중앙 어휘와 회원 manifest를 파생했다. 기존 관계 키가 바뀌지 않는 회귀를 함께 둔다.

## 수리 후 검증

원래 첫 전체 프로그램을 수정하지 않고 라이브 백엔드에서 다음 다섯 입력을 실행했다. 모든 산출물을 독립 Python datetime oracle로 다시 대조했다.

- 기본 602/598·1,805석, 원변형 902/298·2,705석: 전건 동일.
- 연도 경계: MIN1/MIN2 접수, MAX1/MAX2 거절·3석. 마이크로초 순서 보존.
- 새 자정 ±1마이크로초·+14/-12·동일순간: 4/2·12석, 동률 id 정렬 보존.
- 빈 입력: 빈 세 목록, 0/0·0석, 보고서·재독 정상.
- 입력 10파일 SHA256 불변. 기본/원변형의 최초 산출물과 새 산출물은 별도 경로로 유지.

수리 후 HTTP 0.920~1.908초로 최초보다 느린 표본도 있다(전체 회귀 동시 실행·재기동 후 상태 차이). 전체 프로그램 가속은 입증하지 않는다. 회귀 재실행은 제품 검증 비용이며 훈련 최초 기준선과 합치지 않는다. 코어 변경 중 keeper가 감지한 판본과 다음 편집이 달라 자동 재기동이 보류되어, 최종 편집 후 정식 `backend/api.py restart --wait`로 적용했다. 08:50:22 restarted 확인 뒤 전체 프로그램을 재검증했다.

새 회귀 `backend/test_value_semantics.py`: 수리 전 6실패·1통과 → 7통과. 직접 관련 144통과. 첫 전체 회귀는 9,399통과·8실패·12건너뜀. 원인은 의존 지문 미갱신(어휘 가져오기4·회원 API1), 새 시험 직접실행 진입점(본 회차와 기존 미커밋 시험), 기존 미커밋 세계은행 변경의 절단 사유/용례 검토 표식이었다. 원인을 보완한 관련 57검사 전부 통과. 최종 전수 수치는 아래 완료 기록에 남긴다.

기존 미커밋 작업의 기능 구현은 이번 커밋에 포함하지 않는다. 전체 회귀가 발견한 기존 작업의 검증 누락에는 `test_launcher_app_autopilot.py`의 pytest 진입점 4줄, world-statistics truncated의 source 분류 주석, world_bank 단일국가 용례 12건의 검토 표식을 추가했다. 이 보완은 기존 작업과 함께 미커밋 상태로 남긴다. 중앙 파생 YAML은 해당 작업의 world_bank 설명 변경과 이번 의존 지문 변경이 함께 있으므로, 이번 지문 변경만 분리해 커밋한다.

## 독립 AI 관측과 낭비 검토

두 턴 모두 claude_code/opus, origin=training. 핵심 계산은 자체 Python 스크립트였고 IBL은 읽기·쓰기·집계 재검수에 사용했다. 독립 IBL 작성 성공으로 세지 않는다. 기본 5도구 호출·실패0·검사거절0, 최초 평가1회. 후속은 Python 목록 내포(`[x.name for x in $ls]`)를 IBL에 쓴 작성 오류로 실행 전 1회 거절됐고, 스스로 바로 고쳤다. 허용 문법을 제대로 거절한 것이며 실행기 결함으로 세지 않는다. 이후 앞 audit.py를 그대로 복사해 새 입력을 계산했다. 입력 순서와 policy 파일이 바뀌었으므로 재독·재계산을 낭비라고 단정하지 않는다. 자동 압축0, 리허설이므로 증류 시험 제외. 관련 없는 회상 후보를 쓰지 않은 것을 실패로 세지 않았다.

| 턴 | 전체 입력(캐시 포함) | 출력 | 캐시 읽기(입력 부분집합) | 캐시 생성 |
|---|---:|---:|---:|---:|
| 4434 | 782,497 | 10,756 | 563,213 | 213,594 |
| 4435 | 946,470 | 4,436 | 854,267 | 83,753 |

`model.usage(accounting=billable_usage)`의 분류·의식·실행·판정 등 전 역할 합. 훈련자 전체 토큰은 미측정이며 프로그램 내부 모델 호출은0. 두 실행자의 시간 범위가 달라 속도비를 주장하지 않는다.

필요했던 비용: 원문 시각 보존, 독립 실제 순간 비교, 보고서 전건 대조, 저장 재독·입력 해시 확인. 제거한 낭비: 정렬의 같은 키 중복 파싱·UTC 텍스트 생성. 추가 운영 낭비: Python HTTP 호출의 샌드박스 차단 뒤 허용된 진입점으로 재호출, 출력 요약에서 원장 전문을 노출해 하네스 표시를 줄임, 처음 전체 회귀 전 의존 지문·직접실행 관문을 놓쳐 재검사가 필요했음. 다음에는 공통값 변경 때 공유 record 의존 감사를 함께 확인한다.

수리 후 독립 AI 재실행·모델 토큰 절감·비ISO 표기·윤초·지역 이름 시간대/DST의 추가 행태는 미검증이다. 이번 과제는 명시 오프셋의 유효 ISO 시각만 다룬다. 가이드는 최초 초안 보존·전건 독립 기대·훈련 종료 후 수리의 분리가 유효했고, 지침 변경은 필요하지 않았다.

## 재현

정본에서 `python3 docs/experiments/long_sentence_imagination/round_35/harness/run.py prepare`로 합성 입력을 만들고, `check`, `run`, `verify`를 순서대로 호출한다. `mode`는 base/variant/boundary/new/empty, `--label`은 서로 다른 출력 경로다. 기존 원자료 증거를 보존하려면 새로 prepare하지 않고 저장된 입력으로 재생한다. 독립 AI는 `ai` 접수 뒤 반환된 status_url을 `poll --url`로 회수하며 훈련자 자료를 전달하지 않는다. 전체 로컬 증거: `outputs/long_sentence_imagination/2026-10-08_35회차/`.
