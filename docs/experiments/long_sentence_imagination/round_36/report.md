## 작성과 전체 실행

공개 `ibl_composition.md`, `script.md`, `task_receipts.md`, `python_libraries.md`, 문법 교재와
실제 describe·Script 목록을 참조했다. 35회차 운반 하네스는 HTTP 전송 방식만 참고했다.
이전 회고에서 공통 수리 설계를 읽은 지식은 분리할 수 없다는 한계를 사전에 적었다.

- [main_v0.ibl](drafts/main_v0.ibl): 최초 완성 초안. 훈련자가 레코드 펼침을 JS식 `...`로
  잘못 써 검사에서 SYNTAX 거절. 공개 문법의 `**`로 고친 [v1](drafts/main_v1.ibl)은
  검사 오류·경고0, 한 번의 실제 실행으로 기본 과제 달성. 시스템 결함으로 세지 않는다.
- 지역 함수 `시작`은 목록과 실재 파일의 차이를 확인해 blocked 또는 작업 접수증을 반환한다.
  완비한 두 ZIP은 기존 등록 `압축`의 background로 시작한다. `검증완료`는 같은 접수증으로
  기다려 ZIP 목록·중복을 확인하고, 별도 폴더로 해제한 뒤 기존 `python_libraries`의
  `filecmp.cmpfiles(shallow=False)`를 호출해 전건 바이트를 대조한다.
- `인계`는 검증된 값·제목·순서만 받아 JSON/Markdown을 저장·재독한다.
  [설명 변형](drafts/presentation_v0.ibl)은 이 함수와 앞 result.json만 쓴다.
  [복구 변형](drafts/recovery_v0.ibl)은 앞 값 중 blocked만 시작·검증하고 ready는 그대로 전달한다.
  두 변형은 첫 초안 그대로 검사·실행에 성공했다.
- HTTP 기본 응답에는 `result_ref`가 없었으므로 훈련자는 앞 산출물 파일을 명시 입력으로 연결했다.
  값의 수작업 복사나 원자료의 재작성은 없다. AI는 후속 작성에 실제 `$ref`·`$checked`·`$rejected`
  손잡이를 사용했다. 훈련자의 파일 연결을 `$ref` 성공으로 보고하지 않는다.
- 제품 소스 열람은 세 훈련자 실행이 끝난 뒤 검색·평가 증거 문제의 읽기 전용 진단 때 했다.
  라이브 코어·도구·설정·등록 원장·해마는 바꾸지 않았다.

## 독립 AI: 무엇이 달라졌나

주 실행 모델은 ClaudeCode/opus, 세 에피소드와 모든 궤적의 source는 training이다.
최종평가는 각1회, 자동 압축0. 리허설 정책상 장기기억 증류·축적은 평가하지 않았다.

1. **풀이 방식:** 핵심 분기·자료 선택·압축 호출·검증 호출·산출물은 긴 IBL로 연결했다.
   Python은 ZIP의 해시·바이트 검증 부품이다. 이전 네 회차의 계산 전체를 Python에 맡긴 형태와는
   달랐지만, 분야와 요구가 달라 모델의 IBL 작성 능력이 향상됐다고 인과 추론하지 않는다.
2. **분할·재사용:** 설명 변경은 자기 결과를 `$ref`로 받고 ZIP0개를 만들었다. 복구에서는
   기존 검증 Python 본문을 자기 base/work에서 읽어 새 `~turn`으로 옮겼고 gamma만 압축했다.
   다만 alpha/beta까지 ZIP 내용 검증을 반복했으며 source 전체 해시도 다시 읽었다.
   **부분 생성은 달성했지만 검증은 전체에 다시 수행했다.** 검증 비용까지 줄였다는 증거는 없다.
3. **방법 발견:** 전체 Script 목록에서 압축을 찾아 사용했으며 `base/arcname` 의미를 확인하려고
   등록 Script 본문을 grep했다. 계약만으로 끝낸 작성은 아니다. 자동 회상 후보는
   나레이션생성·팁행source중첩·폴더변화였고 사용0이었다. 이 과제의 적합한 압축 부품은
   직접 목록 조회에서 발견했다. 부적합한 후보를 안 쓴 것을 실패로 세지 않는다.
4. **완료 판정:** ZIP 전건 검증·원자료 해시 보존·JSON/보고서 재독을 스스로 수행했고
   훈련자도 독립 대조했다. 직접 읽을 수 있는 증거가 있는데도 능력 주장 검토에서 불필요한
   재조회가 생긴 L36-2는 아래에 분리한다.
5. **축적:** 기존 등록 부품과 자기 직전 코드·결과의 실제 재사용은 확인했다.
   새 관용구 저장·다른 날/다른 분야의 이름 없는 발견·장기기억 증류 성공은 확인하지 않았다.
6. **작성 마찰:** 기본은 따옴표·join 인자 순서 검사 거절2회, 비-`~turn` Python 실행 거절1회.
   설명 변경은 같은 join 인자 순서를 다시 틀려 거절1회, 셸 ls 정책 거절1회.
   복구는 따옴표와 조건식 안 도구 호출/목록 contains를 고치는 검사 거절2회였다.
   모두 허용 계약을 올바르게 거절한 것이며 언어 결함으로 합산하지 않는다.

실제 요청·거절·재조회는 [기본](evidence/ai_base_trace.json), [설명](evidence/ai_presentation_trace.json),
[복구](evidence/ai_recovery_trace.json)에 남겼다. 코드 수정은 자기 오류를 스스로 고쳤으며 훈련자가 해법을 추가로 알려주지 않았다.
