# 36회차 — 교육 자료 전달 묶음의 조합과 부분 복구

합성 교육 자료를 alpha·beta·gamma 세 반에 전달할 ZIP과 인계서를 준비한다. source/catalog.json의 kits에 적힌 files가 각 반에 필요한 상대경로 전부다. 자료 루트 기준 상대경로와 파일 바이트를 그대로 보존하고, 목록에 없는 파일은 넣지 않는다. 필요한 파일이 하나라도 없으면 그 반의 ZIP은 만들지 말고 blocked와 정확한 누락 경로를 남긴다. 나머지 반은 끝까지 준비한다. 모든 ZIP의 전건 경로·중복·바이트를 원자료와 대조한다. result.json은 title과 kits 목록을 가지며 각 kit는 id,status(ready|blocked),archive(절대경로 또는 null),files(필요 상대경로 전체),missing(누락 상대경로),verified_count를 포함한다. report.md는 세 반 모두의 상태·필요 수·검증 수·누락·ZIP 경로를 보여준다. 제목은 ‘교육 자료 인계 v1’, 순서는 alpha,beta,gamma다. 원자료는 바꾸지 말고, 외부 발송·공개 없이 지정 출력 폴더에 저장한 뒤 두 파일을 재독한다. 현재 등록되어 적합한 기능이 있다면 찾아 재사용하고, 새 구현이 필요하면 이유를 남긴다.

## 후속 요구와 사전 완료 조건

1. 기본: 공통 12개+반별 24개, 반마다 36개. 전체 정식 자료는 84개이나 gamma/lesson07.txt만 빠진 상태(83개). 목록 밖 draft/internal 파일은 합성 미끼다. alpha·beta만 ready/36, gamma blocked/0·누락 1. ZIP은 정확히 2개, 서로 이름이 같은 lesson 파일도 디렉터리로 구분한다.
2. 설명만 변경: 제목 ‘교육 자료 최종 인계’, 반 순서 gamma,beta,alpha. 입력과 ZIP 내용은 변하지 않는다. 기본 ZIP의 바이트·mtime_ns 불변, ZIP 생성/재압축 0. 앞 결과·검증 근거를 사용해 새 result.json/report.md만 출력한다. 기존 결과를 덮어쓰지 않는다.
3. 누락 보충: 훈련 준비자가 각 실행자의 source/gamma/lesson07.txt 한 파일만 추가한다. 직전 결과에서 gamma만 다시 준비한다. alpha·beta ZIP의 바이트·mtime_ns 불변. 세 반 모두 ready/36. 기존 실패 사정은 이전 결과에 남는다. 새 인계서는 ‘교육 자료 최종 인계’, gamma,beta,alpha를 유지한다.

## 실행 조건·독립성

- 정본 main `13b82148`, 시작 2026-10-08 09:11 KST, 60분 상한. 훈련 요청이며 시스템 수리는 별도다.
- 모든 자료는 합성. 외부 서비스·회원·발송·구매·예약 없음. 출력은 outputs/long_sentence_imagination/2026-10-08_36회차 아래다.
- trainer/source와 ai/source는 같은 초기 바이트의 별도 사본. 기대값·생성기·훈련자 초안은 AI에 주지 않는다. AI는 같은 리허설 대화에서 세 요청을 이어 받는다.
- 훈련자는 공개 교재·실제 describe·Script 목록만으로 작성한다. 이전 회고에서 공통 수리 설계를 읽은 내부 지식은 분리할 수 없다. 과제 구현 원문은 작성에 사용하지 않는다.
- Python 하네스는 합성 생성·HTTP 운반·외부 독립 검증·계측만 담당한다. 핵심 선택·분기·시작/대기·압축·검증 연결·부분 재실행은 IBL 및 기존 Script로 수행한다.
- 부품을 미리 새로 등록하거나 정답 관용구를 만들지 않는다. 이미 있는 압축/라이브러리 Script가 적합한 부품이며 독립 AI에는 그 이름을 제시하지 않는다.
- 최초 전체 초안과 검사/실행 실패, 사용한 계약, 접수증·종료 상태·결과 참조, 세 단계의 산출물을 각각 보존한다.

## 분해와 계약

- 입력 조사: catalog와 실제 .txt 상대경로 목록 → 각 반의 필요/누락 목록. 원천 읽기 효과.
- 묶음 시작: 누락은 blocked 값, 완비는 기존 압축 Script의 background 접수증. 출력 ZIP만 쓰기.
- 완료·검증: 동일 접수증 대기 → 목록 대조 → 별도 검증 폴더에 해제 → filecmp 전건 바이트 대조. 실패는 해당 반의 사정과 연결.
- 인계서: 검증된 kit 값과 제목/순서 → result.json/report.md 저장·재독, 전체 kit 값을 반환.
- 설명 변형은 반환 참조만 받는다. 복구 변형은 이전 kit 중 blocked만 원천을 새로 확인하고 실행한다.
