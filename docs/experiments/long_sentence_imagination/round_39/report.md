## 2. 과제와 작성

합성 마크다운 36파일 1,154줄(제목·단락·코드 펜스·인라인 코드·파일 간 링크·같은 파일 앵커·깨진 링크 5개). 용어 2개를 **산문에서만**
부분 문자열 치환하고, 제목이 바뀌면 그 앵커를 가리키는 링크 대상을 갱신하며, 깨진 링크를 보고하고, 바뀐 파일만 덮어쓴다.
읽기 실패가 하나라도 있으면 어떤 문서도 쓰지 않는다. 함정: 인라인 코드 제목 `` ### `구독 플랜` 객체 ``(앵커 불변), 코드 펜스 안의 링크 모양 텍스트, 단독 "플랜".
oracle 은 독립 Python(`harness/prepare.py`)이며 AI 입력 사본에는 없다.

분해: 치환·출현수·슬러그·제목글(순수 Text) → 대상재매핑·링크조각·산문변환·줄변환(링크 대상 보호) → 줄표시(펜스 상태 reduce)·줄링크·줄산문 →
적용·재독확인(효과 함수). 최상위: `self:list` → `self:read`(on_error collect) → 실패 분기 → 제목 수집·앵커 맵(`from_entries`) → 파일별 변환·링크 검사 →
바뀐 파일만 `self:write` → 재독·`self:list{hash:true}` 지문 → report.json·summary.md. 정규식이 없어 펜스는 `$line[:3]=="```"` 상태 누적, 인라인 코드는
백틱 `split` 의 홀짝, 링크 대상은 `](` 와 첫 `)` 분할로 구분했다. 교재의 함수표(split/replace/strip/join/enumerate/from_entries/has/get)만으로
막힘 없이 작성됐고, 검사는 첫 제출에서 issues 0 이었다.

## 4. 발견한 갭

### L39-1 — `self:read`(text) 가 CRLF 를 조용히 LF 로 바꿈 (원문 보존·정직성, 중간)

`"줄1\r\n줄2\r\n"` 파일을 `self:read{format:"text"}` 로 읽으면 CR 이 사라져(28자→24자) 그 본문을 그대로 `self:write` 하면 LF 파일이 된다.
`inputs` 로 준 같은 문자열은 CR 을 보존한 채 써진다([재현](repro/crlf_read.ibl), [증거](evidence/probe_crlf_nfd.json)·[isolate](evidence/probe_isolate.json)).
이번 과제에서는 "안 바뀐 파일은 건드리지 마·바뀐 줄 수를 보고하라" 가 CRLF 문서에서 성립할 수 없다 — 모든 줄이 바뀐 것으로 보이거나(비교를 원본과 하면)
전부 LF 로 재작성된다(비교를 읽은 본문과 하면). 소유 위치: system_essentials `handler.py` 의 텍스트 읽기(CSV/TSV 만 `preserve_newlines`, 일반 텍스트는 보편 개행).
개선 방향: 텍스트 읽기도 원문 개행을 보존하거나, 최소한 `Document` 에 `newline:"crlf"|"lf"|"mixed"` 를 신고해 작성자가 되돌릴 수 있게 한다. 업무 전용 예외 아님.

### L39-2 — 문자열 함수가 일치하지 않는 호출에서도 NFD 원문을 NFC 로 재작성 (원문 보존, 중간)

NFD 한글 "워크스페이스 유지"(17 코드포인트)에 `replace($s,"zzz","y")`(일치 없음)·`join("",split($s,"\n"))`·`$s[:3]` 를 적용하면 반환이 NFC(9·3) 다.
`self:read`→`self:write` 원시 왕복과 `inputs` 통과는 바이트 불변이므로 손실 지점은 값 함수다([재현](repro/nfd_replace.ibl), [isolate](evidence/probe_isolate.json)).
교재는 "변환·길이·슬라이싱은 NFC" 를 정책으로 밝히지만, 그 결과 맥에서 흔한 NFD 문서의 용어 개정은 용어가 없는 줄·파일까지 전부 바이트가 바뀐다(38회차 L38-1 의
"줄 strip 으로 코드 손실" 과 같은 부류). 개선 방향: 비교·탐색은 NFC 로 하되 반환은 원문 조각을 잇는다(치환된 구간만 새 문자열). 길이·인덱스 정책은 별도 판정.

### L39-3 — `contains(text, 공백·제어문자·빈 문자열)` 이 항상 true (구현 결함, 중간)

`contains("abc","\r")`·`"\n"`·`"\t"`·`" "`·`""`·`" "` 전부 true, `"z"` 만 false([재현](repro/contains_ws.ibl), [증거](evidence/probe_contains.json)).
부분일치 정책의 정규화가 찾는 문자열을 비워 빈 문자열 포함으로 떨어지는 것으로 보인다. 이번 과제에서 CR 유무 검사(`contains($text,"\r")`)가 CR 이 없는 본문에서 true 를
돌려줘 L39-1 진단을 한 번 오도했다. 개선 방향: 찾는 문자열의 정규화가 빈 문자열이 되면 원문 그대로 비교하거나 거절한다. `split` 은 "\r" 를 정상 처리한다(대조군).

### L39-4 — 순수 IBL 텍스트 변환의 단계 비용 ≈ 줄당 410~580, 상한 100만으로 약 1,700~2,400줄이 천장 (과도한 비용·상한, 중요)

36파일 1,154줄에 673,402단계(v1). 같은 프로그램이 4배(144파일 4,616줄)에서는 요청 가능한 최대 예산 `steps:1000000` 에서 BUDGET 으로 실패하고,
용어·링크 없는 줄을 건너뛴 v2 도 479,545(−29%)로 역시 실패([증거](evidence/trainer_big_main_v1.json)·[v2](evidence/trainer_big_main_v2.json)).
단계는 선형이다(`reduce` 누적 500→4,000행이 7,532→60,032, [증거](evidence/probe_scale_4000.json)) — 2차 비용은 없고 **문자열 람다 한 줄이 수십 단계**인 계수 문제다.
오류 안내 "전건을 여러 실행으로 나누세요" 는 이 과제에 맞지 않는다: 앵커 맵은 전체 제목을 먼저 알아야 하고, 전부-아니면-무 쓰기는 한 실행 안에서만 보장된다.
개선 후보: (a) 순수 내장 함수 호출의 단계 계수 재검토(한 `replace` 가 입력 길이와 무관하게 1 단계인지), (b) 텍스트 전건 변환을 위한 `each` 의 스트리밍/저비용 경로,
(c) 상한 자체의 근거 재검토. 어느 것도 새 어휘가 아니다. 독립 AI 는 Python 으로 풀어 이 천장을 밟지 않았다 — 같은 일을 IBL 로 쓰면 천장이 먼저 온다.

### 관측(갭 아님)
- v0 의 `DUPLICATE_KEY` 진단은 `list_index`·`key`·원문 `line/column` 을 줘 한 번에 고쳤다. 같은 파일의 중복 제목이 같은 앵커를 가지는 것은 자료의 실제 조건(GitHub 는 `-1` 접미).
- `self:read` 무효 UTF-8 → 정직한 실패, `on_error:"collect"`+`is_ok/error_of` 로 파일별 이유 보존, 봉투 `source_complete:false`. 38회차 L38-2 수리 방향과 일치.
- 자작 관문: 377줄 Python 저장을 세상의 도구 확인 전까지 거절. 이 과제의 정답은 자체 코드였으므로 비용 1라운드. 관문의 목적(재발명 방지) 과 상충 없음, 기록만.
- 작업 기록 created_at 의 UTC 표기가 AI 답변의 "어제" 를 만들었다(표시 시간대 후보).

## 5. 비용·낭비 검토와 잔여

- **필요했던 비용**: 36파일 전부 읽기·전건 변환·바뀐 파일 재독·`hash:true` 지문(보고의 sha256). 멱등 재실행도 전부 읽어야 "바뀔 것 없음" 을 증명한다.
- **줄일 수 있었던 일**: 훈련자 — `줄표시` 의 `$acc.rows + [...]` 누적(76K+53K 단계)은 `enumerate`+펜스 토글 계산으로 대체 가능, v2 의 사전필터는 29% 절감.
  AI — 자작 관문 왕복 1회, 재실행 턴에 입력 524K 토큰(캐시 509K; 13초 작업에 의식 문맥 전체) 은 10-07 의식 호출 반성과 같은 부류.
- **원인과 근거**: 단계 계수(실행기), 문자열 정규화 정책(값 함수), 텍스트 읽기 개행(도구). 작성자 선택의 낭비는 누적 reduce 뿐.
- **다음 개선과 보존할 품질**: L39-4 의 계수 재검토가 가장 큰 지렛대. L39-1·2 는 원문 보존 — 치환된 구간 밖의 바이트를 바꾸지 않는 것이 기준. 깨진 링크 보고·전부-아니면-무·멱등은 그대로.
- **미검증 경계**: 중첩 코드 펜스(` ```` `)·닫히지 않은 펜스·같은 줄 안의 홀수 백틱·링크 텍스트 안의 `](`·ATX 닫는 `#`·참조형 링크 `[x][id]` 는 자료에 없어 미시험.
  CRLF·NFD 는 탐침으로만 확인했고 전체 프로그램의 CRLF 입력 실행은 하지 않았다. 훈련자 토큰 미측정.
- **다음 회차 후보**: 같은 과제를 CRLF+NFD 원본으로 돌려 "바뀐 줄 수" 보고가 어떻게 틀리는지(L39-1·2 전체 프로그램 재현), 1,700줄 천장 아래에서 분할 실행 + 전부-아니면-무를
  `resume`/접수증으로 지키는 설계.
