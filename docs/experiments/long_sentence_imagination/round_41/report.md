## 4. 발견한 갭

### L41-3 — 쓰기 자원 미상 도구(`table:chart`) 하나가 프로그램 전체 읽기의 재사용을 조용히 끔 (재사용 공백·침묵, 중요)

읽기 2 + `table:chart` + `self:write` 프로그램의 `continuation.read_calls` 는 0, 차트만 뺀 같은 프로그램은 2([증거](evidence/probe_chartreuse.json)·[대조](evidence/probe_writereuse.json)).
교재 문장 "쓰기 자원과 겹치는 읽기(자원 미상은 전체) 제외" 의 실제 효과다. 전체 보고서 프로그램의 제자리 정정 재실행은 `reuse.skipped` 20건 전부 `no_matching_receipt` 로, 원인(차트의 미상 쓰기 자원)은 어디에도 없다([증거](evidence/trainer_v1b_main_v3_reuse.json)).
차트 없는 작은 프로그램은 12/12 재사용([대조](evidence/probe_reuse_again.json)). 그림이 있는 연구·경영 보고서는 모두 이 길을 밟는다 — 40회차에서 실증한 "비싼 추출 재사용" 이 그림 한 장으로 무효가 된다.
개선: chart 의 `write_resources:{file:"output_path"}` 선언(선언 정정), 자원 미상 쓰기가 있으면 continuation 에 "읽기 제외 이유" 와 해당 호출 위치를 신고. 새 어휘 아님.

### L41-1 — `table:chart` 의 `output_format` 무시·확장자 없는 경로 거절 (계약 불일치, 중간)

설명은 output_path 를 "경로 stem" 으로 안내하고 `output_format` 을 받지만, spec·table 형 모두 "Cannot infer image type" 으로 실패([증거](evidence/trainer_base_main_v2.json)·[probe](evidence/probe_chart_format2.json)). `.png` 를 붙이면 성공. 개선: 렌더 경로에 output_format 적용 또는 설명 정정.

### L41-2 — `table:chart` bar 의 x/y 목록이 string 선언이라 IBL 목록 거절 (계약 불일치, 중간)

`x:["a","b"],y:[1,2]` → "x 에는 string 이 와야 하는데 2개짜리 목록"([증거](evidence/probe_chart_format.json)). 설명("x/y 리스트") 과 param 선언이 어긋나 table 형·spec 으로만 그릴 수 있다. 개선: 목록 param 을 array 로 선언.

### 관측(갭 아님)
- 검사 품질: 보간 null 가능성·`?:` 안 도구 호출·이스케이프 따옴표를 줄·규칙·힌트로 정확히 거절 — 40회차 L40-2 의 "schema 필드 null" 과 달리 이번 오류는 모두 실행 전에 잡혔다.
- 통계를 식으로 쓴 비용: 134K 단계(720 trial·조건 6·가설 4), L39-4 천장의 13%. 정밀도는 oracle 과 일치.
- 변형 1 설계 실수: 정정 자료를 다른 폴더에 두면 경로가 달라 reuse 대상이 아니다(영수증은 경로 기준). 제자리 덮어쓰기(1b)로 바로잡았고 거기서 L41-3 이 드러났다.
- brief 산문의 "한계" 는 입력 표의 결핍을 말한다 — 방법·CI 를 items 에 함께 주어야 연구 한계가 된다(작성 교훈).
- 검수기 보정 3회(AI 의 satisfaction 목록 모양·키 이름·부정문 "입증하지 않는다") — 34·40회차 교훈 재확인.
