## 4. 발견한 갭

### L41-3 — 쓰기 자원 미상 도구(`table:chart`) 하나가 프로그램 전체 읽기의 재사용을 조용히 끔 (재사용 공백·침묵, 중요)

읽기 2 + `table:chart` + `self:write` 프로그램의 `continuation.read_calls` 는 0, 차트만 뺀 같은 프로그램은 2([증거](evidence/probe_chartreuse.json)·[대조](evidence/probe_writereuse.json)).
교재 문장 "쓰기 자원과 겹치는 읽기(자원 미상은 전체) 제외" 의 실제 효과다. 전체 보고서 프로그램의 제자리 정정 재실행은 `reuse.skipped` 20건 전부 `no_matching_receipt` 로, 원인(차트의 미상 쓰기 자원)은 어디에도 없다([증거](evidence/trainer_v1b_main_v3_reuse.json)).
차트 없는 작은 프로그램은 12/12 재사용([대조](evidence/probe_reuse_again.json)). 그림이 있는 연구·경영 보고서는 모두 이 길을 밟는다 — 40회차에서 실증한 "비싼 추출 재사용" 이 그림 한 장으로 무효가 된다.
개선: chart 의 `write_resources:{file:"output_path"}` 선언(선언 정정), 자원 미상 쓰기가 있으면 continuation 에 "읽기 제외 이유" 와 해당 호출 위치를 신고. 새 어휘 아님.

### L41-1 — `table:chart` 의 `output_format` 무시·확장자 없는 경로 거절 (계약 불일치, 중간)

설명은 output_path 를 "경로 stem" 으로 안내하고 `output_format` 을 받지만, spec·table 형 모두 "Cannot infer image type" 으로 실패([증거](evidence/trainer_base_main_v2.json)·[probe](evidence/probe_chart_format2.json)). `.png` 를 붙이면 성공. 개선: 렌더 경로에 output_format 적용 또는 설명 정정.

### L41-2 — `table:chart` bar 의 x/y 목록이 string 선언이라 IBL 목록 거절 (계약 불일치, 중간)

`x:["a","b"],y:[1,2]` → "x 에는 string 이 와야 하는데 2개짜리 목록"([증거](evidence/probe_chart_format.json)). 설명("x/y 리스트") 과 param 선언이 어긋나 table 형·spec 으로만 그릴 수 있다. 개선: 목록 param 을 array 로 선언.

### L41-4 — 독립 AI 의 검사 거절 2건은 `for` 문법 요구가 아니라 파서 안내 공백 (진단, 낮음)

ep4491 의 거절 원문: ① `return {…,files:[x.name for x in $f]}` — Python 컴프리헨션. 응답은 "']'가 필요합니다: for" 뿐이고 `map($f,($x)=>$x.name)` 을 안내하지 않는다.
② `$i = [engines:image_read]{…}` — `$i` 는 repeat 의 예약 바인딩이라 "읽기 전용 바인딩: $i" 로 거절되는데, repeat 밖에서도 예약이고 이유·대안을 말하지 않는다.
둘 다 반복 제어 구문이 없어서가 아니다(`[table:each]`·`map/filter/reduce`·`[repeat:N|while|until]` 이 있다). L33-1 동적 키와 같은 부류 — 파서가 익숙한 다른 언어의 모양을 알아보고 IBL 대응을 안내하면 된다. 문법 추가 아님.

### 관측(갭 아님)
- 검사 품질: 보간 null 가능성·`?:` 안 도구 호출·이스케이프 따옴표를 줄·규칙·힌트로 정확히 거절 — 40회차 L40-2 의 "schema 필드 null" 과 달리 이번 오류는 모두 실행 전에 잡혔다.
- 통계를 식으로 쓴 비용: 134K 단계(720 trial·조건 6·가설 4), L39-4 천장의 13%. 정밀도는 oracle 과 일치.
- 변형 1 설계 실수: 정정 자료를 다른 폴더에 두면 경로가 달라 reuse 대상이 아니다(영수증은 경로 기준). 제자리 덮어쓰기(1b)로 바로잡았고 거기서 L41-3 이 드러났다.
- brief 산문의 "한계" 는 입력 표의 결핍을 말한다 — 방법·CI 를 items 에 함께 주어야 연구 한계가 된다(작성 교훈).
- 검수기 보정 3회(AI 의 satisfaction 목록 모양·키 이름·부정문 "입증하지 않는다") — 34·40회차 교훈 재확인.

## 7. 후속 수리 (2026-10-09)

훈련 종료 기록을 확인한 뒤 `eaa706ec` 정본 위에서 수리했다. 최초 관측·프로그램·산출물은 보존했다.

- **L41-3**: chart 액션에 `write_resources:{file:output_path}`를 선언했다. 기존 봉투에서 유도한 계약도 자원 선언을 전달하며, `path` 같은 별칭은 자원 판정·영수증 키 구성 전에 정규 인자로 해소한다. 원장은 쓰기와 겹쳐 제외된 읽기에 원인 쓰기 ID·액션·소스 위치·사유·제외 수를 저장하고 `continuation.read_exclusions`로 최대 20개 원인 그룹과 전체 수를 신고한다. 자원 미상 쓰기와 동시 읽기의 보수적 차단은 유지한다.
- **L41-2**: x는 열 이름 또는 좌표 목록, y는 값 열 이름/목록 또는 좌표 목록을 받는다. line/bar/scatter 좌표와 pie labels/values를 실제 렌더러 데이터로 변환한다. 길이가 다르거나 빈 좌표는 실패하며 조용히 zip 절단하지 않는다. 기존 표의 열 선택·다중 시리즈도 검증했다.
- **L41-1**: Plotly와 matplotlib 저장기가 PNG 형식을 명시적으로 전달한다. 확장자 없는 경로도 지정한 경로 자체에 PNG를 쓰고 같은 경로를 반환한다. 별도 확장자를 붙여 자원 선언과 실제 경로가 달라지는 문제를 만들지 않는다. 기존 HTML/PNG 충돌 거절은 유지한다.

| 새 변형: 설문 응답 한 항목만 변경 | 입력 읽기 **63건 재사용**, 설문 1건 재독 | 완료시간 그림 유지, 만족도 그림만 재생성 |

§5의 기대치 `65→7`은 파일 읽기와 목록 관측을 섞은 수였다. 실제 입력 파일 읽기는 세션 60 + 설계·참가자·임계값·설문 4 = **64**다. `self:list`는 완전한 자원 범위를 아직 선언하지 않아 쓰기 경계에서 제외되며 새로 실행한다. 이전 stats도 별도 입력이다. 따라서 전체 도구 호출이 7개가 됐다고 해석하면 안 된다.

경로 생략·bare 파일명은 실제 출력 해소가 보장되지 않아 전체 충돌을 유지한다. 이전 버전에서 이미 제외된 영수증을 소급 복원하지 않으며 새 실행부터 후보가 보존된다. 검증 중 샌드박스가 Chrome 실행을 차단한 시도는 실패로 남겼고, 정상 macOS 권한에서 실제 PNG 검사를 통과했다.

### 검증 범위

활성 HTTP `/ibl/execute`에서도 x/y 목록·`path` 별칭·확장자 없는 PNG 생성·읽기 2건 보존과 2건 재사용을 확인했다. 용례 60건을 전문 검토하여 변경 계약과의 충돌이 없음을 확인하고 기존 검토 원장을 갱신했다. 첫 종합 회귀에서 기존 요약의 필드 전체 비교 3건, 신규 시험 직접 진입점 관문, 용례 검토 원장 관문이 실패했다. 기존 기대값에 새 제외 진단을 함께 검증하도록 확장하고 진입점·검토 원장을 보완했으며 관련 67건이 통과했다. 첫 회귀의 live-store 알림 2개 문서는 이 수리에서 회고를 작성한 것으로 시험의 원장 오염이 아니다.
