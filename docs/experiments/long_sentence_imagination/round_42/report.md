## 4. 발견과 공통 개선 방향

### L42-1 — PNG 누락을 skipped로만 반환하고 원천 완전성은 true

**분류: 부분 결과 계약·완료 판정 연결 공백.** 훈련자와 독립 AI 모두 s003 PNG 누락 시
`success:true, slides:3, skipped:["s003"]`인 MP4를 받았다. 훈련자 실행 봉투는
`source_complete:true, run_status:completed`다. 별도 완료 조건은 false로 판정했다.
즉 실패가 완전히 숨겨진 것은 아니지만, 보편적인 원천 불완전성 표지에 연결되지 않는다.

진단: `lecture_workspace/deck_video.py`의 PNG 부재 분기는 skipped에 추가하고 continue하며,
모든 장면이 없을 때만 예외를 낸다. 부분 MP4를 반환하는 정책과 완전한 과제 달성은 다른 계약이다.
최소 재현은 완성 덱의 PNG 1장을 임시 이동하고 [렌더 프로그램](drafts/render_existing_v0.ibl)을
새 output_filename으로 실행하는 것이다. [증거](evidence/missing.json)는 전체 프로그램과 결과를 연결한다.

개선 후보: 누락 이유·expected/rendered를 보존한 부분 산출물 계약을 만들고 공통 PARTIAL_SOURCE/
source_complete에 연결한다. 엄격한 전건 요구에서 실패시키더라도 성공한 부분 파일과 진단은 유지해야 한다.
일부 장을 의도적으로 제외한 편집 정책과 파일 부재를 구분해야 한다. 무조건 모든 skipped를 금지하는
처방은 아니다. 관련 축: 일반 수리 계획 R3(완료), R2(복구). **이번 회차는 수리하지 않았다.**

### L42-2 — 생성된 결과 대신 입력 목표를 기록하고 화면 제약 검증을 늦춤

**분류: 작성·품질 검수 공백, 확정 title/여백과 생성 경로의 연결 마찰.** 훈련자 프로그램의
scenes.title은 실제 생성 결과가 아니라 입력을 복사했다. 첫 제목에 마침표가 추가되어도 그 기록만
재독하면 일치한다고 오판할 수 있다. 실제 deck.json과 입력을 대조해서 차이를 찾았다.
또 하단 25%를 비우라는 장면 지시에도 테마가 삽입하는 우하단 서명은 남았다.
독립 AI도 첫 렌더에서 같은 서명을 발견했으며, 자기 HTML 틀에 제거 CSS를 넣어 해결했다.

개선 후보: 생성 전에 확정 title/note와 자유로운 시각 표현을 구분하고, 생성 뒤 실제 덱 메타·PNG를
계약과 대조한다. 고정 제목·여백이 필요한 반복 제작에는 기존 공통 틀 경로를 먼저 검토한다.
테마 공통 장식이 본문 제약 밖에서 추가되는 조건을 도구 안내·검수에 드러낸다. 새 영상 어휘가 필요한
문제가 아니다. 입력 메타를 결과처럼 보고하는 공통 실수는 문서·표·이미지 제작에도 적용된다.
이는 결정론 도구의 제목 수정 버그로 확정한 것이 아니라, **생성·작성·검수 연결의 실제 실패**다.

  테마 장식·여백 계약을 초기 틀에 반영하면 줄일 수 있다.
- 후속에서 누락된 장면만 복구한 것은 관측된 재사용이다. 영상 합성과 TTS의 내부 캐시/부분 재사용은
  따로 측정하지 않았으므로 전부 재사용했다고 쓰지 않는다.

전체 backend/frontend 회귀는 시스템 구현 변경이 없어 실행하지 않았다.

## 6. 종료와 재현

모든 접수 작업은 종료 상태로 회수했다([종료 기록](evidence/training_end.json)).
PNG를 이동한 훈련자 덱은 원위치 복원했고, AI 덱은 자기 틀로 복구했다. 기본 출력 지문도 보존했다.
새 코드·어휘·설정 적용이나 예약은 없다. 후속 수리는 L42-1 부분 결과 전파, L42-2 실제 생성물 대조
순서로 검토할 수 있다. 가이드의 성공/실행/달성 구분과 준비 결과 명시 연결이 이번 회차에 유효했다.

재현: `evidence/source.json`을 새 회차 작업 폴더의 `input/scenes.json`에 복사한다. 기존 훈련 덱과
충돌하지 않도록 main_v0의 새 덱 제목을 바꾸고, code/inputs(input,out)/project_id/origin을 담은
요청을 `harness/transport.py <label> <request.json>`으로 check 후 실행한다. 누락 시험은 이 실행에서
만든 덱의 세 번째 PNG만 별도로 보존·이동하고 prepared_path/name/report_path를 지정해 render_existing을
실행한 뒤 복원한다. 외부 TTS와 로컬 렌더 환경이 필요하며 영상 바이트·모델 디자인은 결정론 정답이 아니다.
검수는 `harness/verify.py <mp4> <ass> <source.json> <deck_dir> <qa.json>`으로 수행한다.
