## 자연어 요구 (시스템 AI 에도 같은 글 + 자료 위치·저장 위치만 더해 보낸다)
내 동네도서관 이용자 포털(주소는 입력 폴더 account.json 의 portal_url, 계정도 거기)에 들어가서 다음을 해 줘.
1) 로그인하고 '대출 현황' 의 대출 목록을 **모든 페이지** 읽어 와(번호·제목·저자·반납일·상태). 포털의 '오늘' 날짜는 화면 머리에 있어 — 그걸 기준 날짜로 써(내 컴퓨터 시계 말고).
2) 입력 폴더의 my_books.csv(내가 적어 둔 대출 목록: id, title, due) 와 대조해서 **포털에만 있는 책·내 목록에만 있는 책·반납일이 다른 책**을 id 로 보고해.
3) 반납일이 기준 날짜부터 **3일 이내**(오늘 포함, 반납일 ≤ 오늘+3)인 책은 연장을 신청해 줘. 단 상태가 '연장 불가'(예약 대기)면 신청하지 말고 사유를 적어. 연장은 책의 상세 페이지에서 '연장 신청' 버튼을 누르면 확인창이 뜨는 식이야. 신청 뒤에는 **포털 화면에서 새 반납일을 다시 읽어** 확인하고, 그 책의 연장 전·후 상세 화면을 PNG 로 저장해(out/shots/).
4) '공지' 페이지 안의 공지 본문(프레임 안에 있음)에서 **휴관일 안내 문장을 글자 그대로** 옮겨 적어.
5) 마지막으로 **내 컴퓨터 화면 전체를 한 장 캡처**해 out/desktop.png 로 두고, 지금 맨 앞에 있는 앱 이름을 보고해. 마우스·키보드 조작은 하지 마(화면은 읽기만).
6) 결과를 out/result.json(기준일·페이지 수·전체 목록·대조 결과·연장 시도마다 id/결과/사유/이전·새 반납일/캡처 경로·공지 문장·맨 앞 앱)과 out/report.md(사람이 읽는 요약, 실패·미확인은 그대로 적기)로 남겨. 신청에 실패한 책이 있으면 성공으로 꾸미지 말고 실패와 사유를 적어.

[변형 — 같은 프로그램, 다른 포털 상태] 포털이 불안정한 날: 대출 현황 2페이지가 첫 요청에서 "일시적인 오류"(503)를 내고 다시 요청하면 열린다. 또 연장 가능으로 보이던 책 하나(L03)가 신청 시 "연장 횟수 초과" 로 거절된다. 같은 프로그램을 그대로 돌려 **전체 목록은 끝까지 읽고**, 거절된 연장은 실패와 사유로 보고하며, 나머지 연장은 정상 처리되는지 본다.
