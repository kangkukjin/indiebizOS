## 2) 신청 과정
- 지역 → 센터 → 강좌를 차례로 골랐다. 앞 칸을 고를 때마다 뒤 칸에 실제 option(빈 값이 아닌 것)이 생길 때까지 기다렸다. 정해진 시간만큼 쉬는 방식은 쓰지 않았다.
- 증명서는 set_input_files로 올리고 환불 규정에 체크했다.
- 접수 코드 창은 JS prompt였다(`접수 코드를 입력하세요`). dialog 핸들러로 codes.json의 그 사람 코드를 넣었다. 코드 값은 기록하지 않는다.
- 제출 직전마다 포트(127.0.0.1:8942)와 선택값·이름·생년월일·파일명·체크를 확인했다. 2건 모두 통과했다.
- 응답: 두 건 모두 HTTP 303 뒤 `/receipt/R00N` 접수 완료 화면으로 이동했다. 일시 오류와 거절은 0건이고 재제출도 0건이다.
- 성공 판정은 버튼을 누른 사실이 아니라 완료 화면의 '접수번호' 칸으로 했다.

## 4) 합계와 계산기
- 프로그램 합계: 45,000 + 72,000 = **117,000원**
- 계산기: **미실행**
  - 자리·잠금 확인(15:26:04, 읽기 전용): IOConsoleLocked=No, 콘솔 세션 활성, HID 유휴 3초. 자리에 있고 잠기지 않음으로 판단해 진행했다.
  - 계산기를 열었지만, 캡처 화면에서는 ChatGPT 창이 앞에 있었다. 다시 앞으로 가져온 뒤의 캡처에서는 계산기가 맨 앞에 보였다.
  - 그러나 숫자 입력 직전, 같은 osascript 안의 확인에서 맨 앞 앱이 Claude로 바뀌어 있었다. 그래서 중단했고 **키를 하나도 보내지 않았다.**
  - 사용자가 앱을 오가며 작업 중이라 계속 포커스를 빼앗는 것은 방해가 된다. 키가 다른 앱으로 샐 위험도 있다. 그래서 이 단계는 미실행으로 남겼다.
  - 참고: `limbs:screen` snapshot의 app 필드는 같은 시각 osascript가 Calculator로 답할 때도 'Electron'으로 보고해 판정에 쓰지 않았다.
  - 다른 앱은 조작하거나 종료하지 않았다. 계산기는 열린 채로 두었다.
