상한: 자료·탐침·작성·실행·변형·진단 합계 60분. 종료 보고·정리 별도.

## 이 회차가 앞 회차와 다른 점
- 44~48 은 합성 서버가 oracle 이었다. 이번 상대는 **실물 기기**(맥12, 원격 네트워크·실제 디스크·실제 절전)다. oracle 은 셋 — ① 맥12 디스크의 실제 파일(검증 셸로 직접 읽음) ② 중앙 상주 원장(`history` 의 tasks·events) ③ 중앙 원본의 SHA-256.
- 상주 헬퍼·관용구 아홉 개는 오늘 구현·정렬됐고 실전 사용 기록이 없다(자동 검사는 loopback 격리 허브). 첫 실전이다.
- 원격 PC 에는 IBL 도 Python 라이브러리도 없다. 그 PC 로 건너가는 길은 `limbs:guestpc` 하나뿐이라 **이음새가 구조적으로 IBL** 이다. 관측할 것은 "IBL 이냐 Python 이냐"가 아니라 "관용구냐 직접 어휘냐, 접수증을 어떻게 다루느냐"다.

## ★실행 전 조건 — 다른 세션이 지금 맥12 를 재우고 있다
21:24~21:34 에 다른 세션이 맥12 에서 깨우기 시험을 하고 있다(`pmset womp 1` 적용 → `pmset sleepnow` 예약 → 깨움 원인 조회). 훈련 작업이 잠드는 기계에 떨어지면 무엇이 원인인지 가를 수 없다.
- 실행 시작 조건: `history` 에 직전 10분간 이 훈련 것이 아닌 작업이 없고, `pmset -g sched` 에 예약된 잠들기가 없을 것. 아니면 시작하지 않는다.
- 이번 회차는 **재우기·깨우기를 하지 않는다**(그 시험은 그 세션의 것). `sudo` 도 쓰지 않는다.

## 축
① 상주 관용구 아홉 개 중 여섯(준비·파일보내기·작업실행·작업확인·파일가져오기·작업마무리)의 첫 실전 조합 + 직접 어휘 `history`
② 긴 작업 접수증: 대기 시간 초과(`timed_out`) → **재전송 없이 같은 접수증으로 재개**. 원격 실행 횟수가 1 인지를 원격 파일로 확인
③ 병렬 2개(max_parallel 2)의 작업별 cwd·env 분리 — 한 작업의 `cd`·환경변수가 다른 작업에 안 새는지
④ 요청ID: 같은 ID·같은 명령 = 같은 접수증, 같은 ID·다른 명령 = 충돌
⑤ 파일: 수 MB 바이너리 묶음, 0바이트 파일, 한글 이름(중앙 NFC ↔ macOS 파일명 NFD — 39회차 L39-2 의 실기기 판), 덮어쓰기 거절, `read` 200KB 상한을 넘는 로그는 전송으로
⑥ 판정의 층 구분: 접수 ≠ 전달 ≠ 종료 코드 0 ≠ 산출물 규격 맞음 ≠ 중앙 회수·검증됨
⑦ 독립 AI 가 같은 글을 받고 무엇을 고르는가(관용구/직접 어휘, 접수증 재전송 여부, 원격 스크립트를 어떻게 건네는가)

## 자연어 요구 (시스템 AI 에도 같은 글 + 자료 위치·저장 위치만 더해 보낸다)
원격 PC 맥12 한테 사진 변환 일을 맡겨 줘. 일감은 job.json, 사진은 photos 폴더에 있어.
1) 맥12 가 지금 일을 받을 수 있는지, 이 일에 필요한 도구가 그 PC 에 실제로 있는지 먼저 확인해. 없으면 거기서 멈추고 알려 줘.
2) photos 를 하나로 묶어 맥12 로 보내고, 도착한 것이 보낸 것과 같은지 확인한 다음 풀어.
3) 맥12 에서 두 가지를 같이 돌려. (가) job.json 의 규격대로 사진을 줄여 JPEG 로 바꾸기 — 오래 걸리니까 맡겨 놓고 진행을 지켜봐. (나) 받은 원본 사진마다 지문(SHA-256) 목록 만들기. 둘이 서로의 폴더나 설정을 건드리지 않게 해.
4) 변환이 끝나면 맥12 에서 결과를 검사해(장수, 긴 변 크기, 형식). 통과하면 결과 묶음과 변환 로그를 가져와 out/ 에 저장하고, 가져온 것이 맥12 에 있는 것과 같은지 확인해.
5) (나)의 지문 목록을 여기 원본과 대조해서 보내는 길에 달라진 파일이 없는지 봐. 이름이 한글인 사진도 빠짐없이.
6) 맥12 의 작업 기록에서 이번에 시킨 일들의 시작·종료·걸린 시간을 뽑아.
7) 맥12 에 만든 이번 작업 폴더는 지우고, 연결은 그대로 둬.
8) out/result.json 과 out/report.md 로 남겨.
같은 부탁을 한 번 더 받더라도 맥12 에서 변환을 두 번 돌리면 안 돼. 기다리다 응답이 늦어도 다시 시키지 말고 시킨 그 일을 확인해.

## 조건과 사전 기대
- 자료: 전부 합성(`harness/prepare.py`). 사진 48장(PNG, 600~2400px, 합계 6~8MB), 이름에 한글·공백·괄호 섞음(`가을 들판 (1).png`), 0바이트 1장(job.json 의 제외 규칙에 걸림), `job.json`(대상 `맥12`, 긴 변 800, 형식 jpeg, 품질, 묶음 이름, 제외 규칙, 원격 작업 폴더, `pace_ms`). 변환기 = 맥12 에 원래 있는 `sips`. 원격에서 도는 작업 스크립트는 프로그램이 `write` 로 건넨다(맥12 의 python3 3.8.2 표준 라이브러리만).
- 원격 작업 스크립트는 실행될 때마다 `runs.log` 에 한 줄(pid·시각·요청ID)을 덧붙인다 — 중복 실행의 oracle.
- 격리: 맥12 에서는 `~/indiebiz-training/r49/<trainer|varA|varB|agent>/` 안만 쓴다. 그 밖 읽기·쓰기 0, sudo 0, 화면·키보드·소리 0(`mode:"interactive"` 와 `media` 미사용), `self:limb` 는 `list` 만(pause·remove 금지). 중앙 저장 = `outputs/long_sentence_imagination/2026-10-10_49회차/`. 요청ID 는 `r49-<실행이름>-<단계>-<n>`.
- 뒷정리(7단계)의 삭제 대상은 위 훈련 폴더의 해당 하위 폴더 하나, 절대 경로로. 삭제 뒤 `list` 로 없음 확인.
- 완료 조건(기본): 맥12 에 도착한 묶음의 SHA-256 = 중앙 묶음 / (나) 지문 목록 48행이 중앙 원본과 전건 일치(한글 이름 대조 누락 0) / 변환 결과 47장(0바이트 제외)·전부 JPEG·긴 변 ≤ 800 — **원격 검사 셸의 출력으로** / `runs.log` 1줄 / 가져온 결과 묶음·로그의 SHA-256 = 원격 것, 중앙에서 풀어 47장 / 보고에 작업별 시작·종료·소요(원장 값)와 각 층의 판정(접수·종료 코드·규격·회수) / 원격 작업 폴더 없음, `self:limb list` 의 맥12 는 여전히 connected·등록 그대로 / 결과 파일 2 + 묶음 + 로그.
- 같은 프로그램을 한 번 더 실행(재부탁): 맥12 에서 변환이 다시 돌지 않고(`runs.log` 는 정리 전 관측으로 1줄, 원장에 새 변환 작업 0), 이미 회수한 파일은 재확인으로 끝난다. ← 7단계가 폴더를 지운 뒤라 이 조건을 어떻게 만족시키는지가 과제의 일부다(요청ID·원장이 근거가 된다).

## 일부러 넣지 않은 것 (다음 회차 후보)
- 재우기·깨우기(`wake`, `외부PC깨워준비`): 다른 세션이 실기기 시험 중.
- 소리(`media`, `외부PC재생`): 맥12 가 있는 방에서 실제로 소리가 난다. 사용자가 그 자리에 있을 때 afplay 로 따로.

- 실행 중 연결 끊김·헬퍼 재시작: 원격 셸로 헬퍼를 죽이면 다시 못 붙을 때 맥12 앞에 가야 한다.
- 취소(`cancel`·`외부PC작업중지확인`)와 끝난 뒤에도 사는 자식(후보 c): 50회차 주제로 묶기 좋다 — "맡긴 일을 멈추기".
- 등록 일시 중지·해제(`self:limb pause/remove`).
