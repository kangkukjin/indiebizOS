## 4. 발견 (갭 6건, 수리 안 함)

### L5-1 PDF 본문에 문서화되지 않은 페이지 표지가 섞이고, 글자 층 없는 PDF 를 알리지 않는다 ★
- **분류**: 계약 공백 + 정직성.
- **재현**: `repro/read_pdf_edge.ibl` — 스캔본 R11 의 `text` = `"\n--- Page 1 ---\n"`(비어 있지 않음), `data` 는 metadata·`total_pages:1` 뿐, 표지·경고 없음,
  `source_complete:true`. 글자 있는 PDF 도 본문 앞에 `--- Page 1 ---` 가 들어간다(p1 원문). `self:read` 계약·교재에는 이 표지가 없다.
- **영향**: "빈 본문이면 스캔"이라는 자연스러운 검사가 실패해 p1_v0 는 R11 을 "읽음"으로 모델에 넘겼다(모델이 전부 null 을 내고 훈련자 원문 검사가 잡음).
  OCR 이 필요한 문서를 정상 읽기로 보고하는 정직성 경계.

### L5-2 깨진 PDF(페이지 0)가 오류 없이 빈 본문으로 성공한다 ★
- **분류**: 구현 결함(정직성).
- **재현**: 같은 `read_pdf_edge.ibl` — R12 는 `text:""`·`total_pages:0`·성공·`source_complete:true`. 계약의 "빈 파일은 빈 text" 와 손상 파일이 구별되지 않는다.
  P1 전체도 `source_complete:true` 로 끝나, 손상 원천이 실행 수준 불완전성에 남지 않는다(훈련자 코드가 `total_pages` 로 알아냄).

### L5-3 `table:judge` 의 효과가 `unknown` — 낀 프로그램은 읽기 reuse 가 0
- **분류**: 계약 공백 + 과도한 비용. 3회차 L3-1(효과 미상 관용구) 부류의 모델 도구 판.
- **재현**: `repro/judge_reuse_{a,b}.ibl` → `read_calls 0`·`state_change_possible true`·reused 0/0. 대조 `repro/ai_reuse_{a,b}.ibl`(`table:ai`, 효과 `model`) → **1/1**.
  describe: `table:judge` effects `["unknown"]`, `table:ai` `["model"]`. P2 는 쓰기가 있어 이번엔 차이가 없었지만, 판정 뒤 계산만 고치는 흐름에서 모든 읽기를 다시 한다.

### L5-4 `table:judge` 모델 사용량에 모델·기어·출처가 없다(경미)
- `p2_main` usage.model.calls[0] 키 = `provider("TypeSafe Jev")·input·output·elapsed_ms·cache·measured` 뿐. `table:ai` 호출에는 `model·tier·source·role·call_id` 가 있다.
  2회차 L2-8(실행별 모델 사용량) 수리의 사각 — 어떤 판정기가 결정을 냈는지 보고서에 적을 수 없다.

### L5-5 `+` 로 시작하는 줄은 앞 식의 계속이 아니라 버려지는 별개 문장 — 숫자면 조용히 틀린 값 ★
- **분류**: 문법 함정(구현 결함 또는 계약 공백).
- **재현**: `repro/leading_plus_number.ibl` `$합 = 1` / `  + 2` / `return $합` → **check valid, 실행 결과 1, 경고 0**.
  목록(`leading_plus_list.ibl`)은 `ARITHMETIC "산술로 관측할 수 없는 타입: List<Text>"`, 문자열(`leading_plus_text.ibl`)은 `NUMBER_REQUIRED "number(): '나'"` —
  둘 다 원인(줄 시작 `+` 는 계속이 아님)을 말하지 않는다. 교재는 "`&`·`>>`·`??` 로 시작하는 줄은 앞 식의 계속"이라고만 적는다.
- **영향**: p2_v0 의 이상 목록 조립(`$이상 = (…)` 다음 줄 `+ (…)` 7개)이 목록이라 오류로 드러났지만, 합계 같은 숫자 식이면 **보고서 금액이 조용히 틀린다**.
  값을 쓰지 않는 식 문장 자체에 경고가 없다.

### L5-6 FORMAT_TYPE 오류에 expected/actual 이 없다(경미)
- `repro/format_type_detail.ibl` — `f"사유 ${$it.이유}"`(이유 Null|Text) → FORMAT_TYPE, `expected/actual/details` 모두 None. 같은 부류의 TYPE 오류에는 있다.
  p2_v1 에서 어느 필드가 null 가능한지 열 번호로 역추적했다.

**갭 아닌 관측**: `table:judge` 의 미결정 null 은 계약대로(확률 0.71 < 0.8). 결정 여부가 지시문 표현에 민감 — 작성자가 null 가지를 반드시 설계해야 한다(교재에 judge 예제 없음, 다음 회차 후보).
P2 저장본이 결과 값 3KB 대비 31~34만 자(4회차와 같은 관찰).

## 5. 개선 방향

1. **L5-1·L5-2 (문서 읽기 정직성)**: PDF 읽기 결과에 페이지별 글자 수·`no_text_pages`(OCR 필요) 표지를 두고, 페이지 0·파싱 실패는 `CORRUPT`/`TOOL` 오류로,
   `source_complete` 에 반영. 페이지 표지를 쓸 거면 계약·교재에 명시하거나 `blocks` 로만 둔다. 검증 = `read_pdf_edge.ibl` + p1_v0 가 우회 없이 R11·R12 를 구별.
2. **L5-3·L5-4 (모델 도구 계약 한 벌)**: `table:judge`·`table:brief` 등 모델 판정 도구의 효과를 `model` 로 선언하고 사용량 기록 경로를 `table:ai` 와 같은 함수로.
   검증 = `judge_reuse_b` 1/1, judge 호출에 model·source.
3. **L5-5**: 줄 시작 `+ - * /` 등 이항 연산자를 계속 줄로 받거나, 값을 버리는 식 문장을 SYNTAX/경고로. 검증 = 재현 3개가 계속으로 계산되거나 명시 거절.
4. **L5-6**: FORMAT_TYPE 에 실제 타입(`Null | Text`)과 기대(Text·Number·Bool) 채우기.
