## 4. 발견

### ★ L50-1 — 성공하지 않은 일은 `외부PC작업확인` 의 시작·종료·소요가 비어 있다

"얼마나 돌다 멈췄나" 가 가장 궁금한 바로 그 경우에 비는 것이 문제다.

### ★ L50-2 — 출력 통로를 문 자식이 남으면 성공한 명령이 `failed` 로 찍힌다
`nohup 프로그램 & sleep 1; echo started` — 명령은 끝났고 자식은 살아 있는데 6초 뒤 `failed · exec: WaitDelay expired before I/O complete · exit -1`. 49회차 때 다른 세션의 `맥12-수면시험` 2건이 이 모양이었다. 통로를 닫으면 `succeeded`. 사람이 흔히 쓰는 `nohup x &` 가 그대로는 실패로 보이고, 실패 문구는 원인(자식이 출력을 물고 있음)도 처방(통로 닫기)도 말하지 않으며, 가이드에 이 경우가 없다. 다시 시키면 서버가 두 번 뜬다.
- 처방 후보: 실패 대신 "명령은 종료 코드 N 으로 끝났고 자식이 출력을 물고 남았다" 는 구분된 결과 + 가이드 한 줄.

### ★ L50-4 — 일 두 개가 도는 동안에는 짧은 확인 명령도 줄에서 기다린다
동시 한도 2 는 일뿐 아니라 `list`·`ps` 같은 읽기 확인에도 걸린다. 8초짜리 일 둘이 도는 중에 접수한 `list` 는 7.0초 뒤(앞 일이 끝난 뒤)에야 시작했다(실행 자체는 0.03초). 긴 일 둘을 맡겨 둔 동안에는 "그 일이 띄운 프로세스가 남았나", "서버가 살아 있나" 를 맥12 에서 확인할 수 없고, 동기 호출이면 응답 대기 상한까지 붙잡힌다. 훈련자 프로그램은 확인을 전부 줄 세우기 고리 뒤로 미뤄 놓아 밟지 않았다 — 한도를 꽉 채워 접수한 채 도중에 확인하려는 프로그램은 밟는다. 취소는 이 줄과 무관하게 전달된다(도는 일이 바로 멈췄다).
- 처방 후보: 읽기 확인(list·info·짧은 셸)을 위한 별도 자리 1개, 또는 가이드에 "확인용 자리를 하나 남겨 두라".

### L50-3 — 끊긴 것과 진짜 실패가 같은 상태, 끊긴 것과 멈춘 것이 같은 종료 코드
