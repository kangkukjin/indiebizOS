## 2. 발견

### ★★ L51-1 — 화면 찍기와 재생은 일반 자리를 쓴다: 밤일 둘이 돌면 한 장도 못 찍고, 포기한 뒤에 찍힌다
50회차 수리로 `info·list·read·observe 셸` 은 별도 확인 자리를 얻었지만 `screen` 과 `media` 는 일반 자리 2개를 쓴다. 밤일 2건이 도는 변형 D 와, 다른 실행의 밤일과 겹친 변형 B 에서:
- 화면 찍기는 60초 뒤 "응답을 60초 안에 못 받았습니다" 로 실패했다. 저녁 실행이 그만큼 늘어 2분짜리 밤일보다 늦게 끝났다.
- **그 화면 작업은 줄에 남아 152.9초·125.7초 뒤에 실제로 찍혔다**(원장: 접수 00:54:55 → 시작 00:57:28, 접수 01:01:28 → 시작 01:03:33, 둘 다 succeeded). 부른 쪽은 이미 "못 찍음" 으로 끝낸 뒤다. 그림은 원장의 결과에만 있고 화면 보관 폴더에는 없다.
- 재생은 접수만 되고 시작하지 못한 채 취소됐다(이쪽은 깨끗하게 끝남).
이번엔 화면이 꺼져 있어 찍힌 것이 검은 그림이었다. 켜진 화면이었다면 아무도 기다리지 않는 시각의 사용자 화면이 찍혀 원장에 남는다. 안내 문구는 "같은 명령을 다시 보내지 말고 wait 하라" 고 하므로 작업이 살아 있다는 것은 알 수 있지만, **포기하는 길(그 작업을 취소)은 안내하지 않는다.**
- 처방 후보: 화면 찍기를 확인 자리로(읽기 관측이다), 호출자의 대기가 끝나면 줄에 선 화면 작업은 취소하거나 유효 시각을 둔다.

### ★★ L51-2 — 꺼진 화면을 찍으면 검은 그림이 "성공" 으로 온다
닫힌 뚜껑 + 바깥 화면 꺼짐 상태에서 `screen` 은 800×450 PNG 2,054바이트 — 36만 화소 전부 (0,0,0) — 를 `success:true` 로 돌려준다. 화면이 꺼져 있었다는 표시가 없다. 화면 기록 권한이 없어서인지 화면이 잠들어서인지도 이 그림만으로는 가를 수 없다(이번에 확인하지 못했다 — 맥12 화면을 켜려면 입력이 필요하다). 훈련자는 문진에서 읽은 화면 전원 상태(`IODisplayWrangler` 0)와 묶어 "그림은 왔지만 꺼진 화면" 으로 적었다. 그 문진이 없었다면 "화면이 온통 검다" 를 화면 내용으로 읽게 된다.
- 처방 후보: 찍기 결과에 화면 전원 상태(또는 "단색 그림" 경고)를 함께.

### ★ L51-3 — 음량 인자가 맥의 기본 재생기에 전달되지 않는다
`[limbs:guestpc]{op:"media",…,volume:0}` → 맥12 에서 뜬 것은 `/usr/bin/afplay <파일>` — 음량 인자가 없다. 헬퍼 코드도 mpv 에만 `--volume` 을 붙인다(`resident_execute.go`). 맥12 에는 mpv 가 없어 항상 이 길이다. 접수 응답은 음량이 무시됐다고 말하지 않는다. 이번에는 무음 파일이었고 시스템도 음소거 상태여서 소리가 나지 않았다 — **"음량 0 이니 조용하다" 를 믿고 실제 음원을 틀었다면 시스템 음량 그대로 났다.** `외부PC재생` 관용구에는 음량 인자 자체가 없다.

### L51-4 — 원장의 화면 작업 결과에 그림 전체가 들어 있다
`history` 가 돌려주는 화면 작업의 `result` 에 `b64` 가 통째로 있다(이번엔 검은 그림 2KB라 작았다). 켜진 화면이면 목록 조회 한 번이 그림 여러 장을 싣고 온다. 49회차 L49-6(관측 값이 출력만큼 커짐)과 같은 부류.

## 8. 2026-10-11 근원 수리

이번 실패들은 작업 접수·실행 성공과 사용자가 필요한 관측·제어의 성립을 같은 것으로

대기 수명은 촬영 프로세스에 닿지 않았다. 이미지 획득은 내용 해석 가능성을 보장하지
않으며, 재생 접수는 재생기별 인자 적용을 보장하지 않는다. 원장 목록도 원본 저장과
조회 표현을 구분해야 한다. 특정 밤일 조건 대신 이 경계를 수리했다.

- **L51-1:** screen을 기존 확인 자리 1개에 포함했다. 동기 촬영의 60초 대기가 끝나면
  취소를 요청하고 같은 접수증으로 종료를 확인하도록 안내한다. 실행 중 캡처의 부모
  취소를 OS 캡처 프로세스까지 전달한다. 같은 동기화 응답에 새 작업과 취소가 함께
  도착해도 작업을 먼저 영속화한 후 취소해 뒤늦은 촬영을 막는다. 이미 완료된 결과는
  보존한다. 명시적 background 촬영은 접수증의 수명을 따른다. 일반 긴 작업의 대기
  종료는 계속 실행되는 기존 계약을 유지하며 직접 취소하는 길도 안내한다.
- **L51-2:** 원본 화소가 모두 같은 색이면 `image_observation:uniform`과 warning을
  반환한다. 화면 전원 꺼짐·잠금·권한 문제·실제 단색 화면 중 무엇인지는 단정하지 않는다.
  이미지 획득 성공과 해석상의 한계를 함께 보존하며 중앙 이미지 후처리도 이를 전달한다.
- **L51-3:** media 음량을 중앙과 헬퍼에서 0~100으로 검증하고 afplay에는 `-v` 0~1로
