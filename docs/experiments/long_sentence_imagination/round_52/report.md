## 2. 발견

### ★★ L52-1 — 워드 틀의 바닥글(머리글) 자리는 채워지지 않고, 채우기도 조회도 읽기도 그 사실을 말하지 않는다
틀에는 `{{발급번호}}` 가 본문과 바닥글 두 곳에 있다. `[self:fill]` 뒤:
- 본문은 채워지고 **바닥글은 `{{발급번호}}` 그대로**(수료증 25/25, 변형 A 4/4, 변형 B 41/41).
- 채우기 응답은 `filled:["발급번호",…]`, `unmatched:[]` — 다 채운 것으로 읽힌다.
- 산출물에 `[self:fill]{path}`(자리 조회)를 다시 걸어도 `발급번호` 는 남은 자리 목록에 없다 — 조회도 바닥글을 안 본다.
- `[self:read]` 의 글자·블록에도 바닥글은 없다(`contains(text,"진위")` false).
- **`[self:document]{op:"inspect"}` 만 바닥글 문단을 보여 준다**(`"… 발급번호 {{발급번호}} 로 확인합니다."`). 같은 묶음의 낱말 넷 중 하나만 본다.
- 최소 재현: `evidence/probe_repro.json`. 독립 판독: `evidence/trainer_*_qa.json`.
진위 확인 번호가 바닥글에 안 찍힌 증서 25장이 "성공" 으로 나간다. 처방 후보: 채우기가 머리글·바닥글 파트까지 치환하고, 응답에 **채운 뒤에도 남은 자리**(`remaining`)를 싣는다. 자료 값이 없는 자리(`{{대표}}` 를 안 줬을 때)도 지금은 응답 어디에도 없다 — 같은 칸으로 풀린다.

### ★★ L52-2 — 이미 있는 파일에 쓸 때의 태도가 낱말마다 다르고, 복사는 조용히 다른 이름으로 간다
같은 폴더에서 같은 프로그램을 한 번 더 돌리는 것("기준만 바꿔 다시")만으로 드러났다(`evidence/probe_repro.json`, `evidence/trainer_b_main_v2.json`).

| 낱말 | 대상이 이미 있을 때 |
| --- | --- |
| `self:copy` | `success:true`, 기존 것은 두고 **`이름 (2).xlsx`** 를 만든다. `path` 가 요청한 `dest` 와 다르고 `renamed` 에 적힌다 |
| `self:sheet` append | 기존 파일에 행을 **더 붙인다**(당연하지만 위와 겹치면 두 배) |
| `self:sheet` calculate | **거절** — "output 파일이 이미 있습니다" |
| `self:fill` | 조용히 **덮어쓴다** |
| `self:write` | 조용히 덮어쓴다 |

변형 B 의 v2 는 복사가 `(2)` 로 간 줄 모르고 자기가 정한 경로(옛 파일)에 106행을 또 붙였다. 재계산의 거절이 없었다면 212행짜리 장부가 합계 불일치로만 드러났을 것이다(이 프로그램은 합계 대조가 있어 잡았겠지만, 대조가 없는 프로그램은 두 배짜리 장부를 낸다). 복사 응답의 `path`·`renamed` 를 읽으면 피할 수 있으나, 정적 검사는 그 두 칸을 "관측된 반환 필드에 없는 이름"(관측 필드: `message` 뿐)으로 경고한다 — 읽어야 할 칸을 읽으면 경고가 뜬다.
처방 후보: 쓰기 낱말들에 같은 인자(`if_exists: fail|overwrite|rename`)와 같은 기본값. 최소한 복사의 이름 바꿈을 `success:true` 한 줄 뒤에 숨기지 않기.

### ★ L52-3 — 워드 문서를 그려 볼 길이 없다
`[engines:render]{path:"….docx"}` → `HTML 렌더 실패: Page.goto: Download is starting`(확장자 추론이 html 로 떨어져 브라우저가 내려받기를 시작). 계약은 html/pdf/svg/xlsx 뿐이고 DOCX→PDF 로 바꾸는 낱말도 없다(`self:workspace` export 는 같은 형식 사본, `table:document` 는 블록에서 새로 조판). 같은 기계에 LibreOffice 가 있고 xlsx 는 그 길로 그려진다. "만든 서류를 실제로 그려 보고" 를 PDF·엑셀에는 했고 워드에는 못 했다 — L52-1 의 바닥글은 그렸다면 눈에 보였을 자리다.
- 처방 후보: `render` 의 xlsx 길(LibreOffice → PDF → 쪽별 PNG)에 docx 를 태운다. 새 낱말 불필요. 안 되는 형식은 "html 렌더 실패" 가 아니라 "이 형식은 그리지 않는다" 로.

### L52-4 — PDF 글자 칸의 한글 옆 띄어쓰기가 벌어진다
채운 값은 맞고(`도자기 물레 입문`) 그림에서는 `도자기   물레   입문`, `<공방>` 은 `< 공방>` 으로 보인다. 칸의 글꼴이 `Helv` 라 한글만 대체 글꼴로 그려지며 공백 폭이 달라지는 것으로 보인다(확정 아님 — 다른 PDF 보기 프로그램에서는 확인하지 않았다). 프로그램 안의 눈 확인(`image_read`)이 세 번 모두 이 간격을 스스로 짚었다. 기계 관측(`prescreen`)은 21장 전부 깨끗.

### 관측(번호 없음)
- **최상위 `[try]{… return A}[catch]{return B}` 는 프로그램을 끝낸다.** 교재의 예(`[try]{return number($표기)}[catch]{return null}`)는 함수 안의 모양이다. v1 은 검사를 통과했고, 그 뒤 40줄이 닿지 않는 코드라는 경고가 없었고, 실행은 `success:true` 에 값 `{tried:true,ok:false}` 였다. 훈련자 결함이지만 "시도하고 실패를 값으로 받기" 를 문장 자리에서 쓰려는 사람은 같은 자리를 밟는다.
- **읽기 재사용 0**: 세 실행 모두 `continuation.read_calls 0`, 사유 `unknown_write_resources`(`self:copy`·`self:delete`·`self:fill` 마다 1건씩). 41회차 L41-3 과 같은 규칙인데 이제 사유와 위치가 응답에 적힌다. 변형 B 는 기준 하나만 바뀌었지만 DB 읽기·장부·안내서까지 전부 다시 만들었다(19초라 아프지 않았다).
- `self:fill` 의 자리 조회는 run 셋으로 쪼개진 `{{강좌}}` 를 찾고 채운다. 채운 뒤 그 문단의 굵은 글씨는 사라진다.
- 장부 그림: 12열 표가 A~F / G~L 로 쪽이 갈려, v2 의 `max_pages:2` 는 수식 열이 한 칸도 없는 두 쪽만 보여 줬다(`truncated`·`total_pages` 는 정직하게 옴 — 프로그램이 안 읽었다). v3 에서 7쪽 전부 그려 요약 쪽을 눈으로 확인(행 106·16,551,000·13,898,000·1,546,000·7).
- 자료 설계 실수(훈련자): 긴 이름(22자) 수강생은 출석 50%·66.7% 완납이라 어느 서류에도 안 들어갔다. "넘친 이름" 은 장부 그림에서만 봤다(옆 칸에 가려 잘림).
- `printf('%04d')`·`row_number()`·정수 나눗셈을 SQL 에 맡겨 IBL 쪽 계산이 줄었다 — 0 채움 내장 함수를 찾지 않고 넘어갔다.

## 8. 2026-10-11 근원 수리

네 발견의 공통 뿌리는 **"요청한 것과 실제로 된 것이 다를 때 성공 응답이 그 차이를 말하지 않는다"** 였다 — 채우지 못한 자리, 다른 이름으로 간 복사, 그리지 못하는 형식의 엉뚱한 오류, 선언 없이 벌어진 글자 폭. 새 낱말·새 op·새 인자 없이 기존 계약의 구현과 응답을 고쳤다.

- **L52-1 (`self:fill` DOCX)**: 채우기와 자리 조회가 문서 전체의 문단을 본다 — 본문·표(중첩)·글상자, 구역마다의 머리글·바닥글(첫 쪽·짝수 쪽 변형 포함, 앞 구역에 이어진 것은 건드리지 않음). 응답에 `remaining`(값을 못 받아 남은 자리와 위치)과 `warning` 을 싣고, 자리 조회의 각 항목에 `where` 를 붙였다. 치환은 자리표시자가 걸친 run 만 고쳐 **글자 모양을 잇는다**(전에는 문단 전체를 첫 run 에 몰아 굵은 글씨가 사라졌다). PDF 채우기도 값을 못 받아 빈 글자 칸을 `remaining` 으로 낸다. `self:read` 의 DOCX 결과는 머리글·바닥글 글자를 `header_footer` 에 따로 싣는다(본문 `text`·`blocks` 불변).
- **L52-2 (이미 있는 대상)**: 낱말별 태도(복사=보존, 재계산=거절, 채우기·쓰기=교체)는 각 낱말의 성격이라 그대로 두고, **일어난 일을 응답이 말하게** 했다. `self:copy`·`self:move` 는 이름을 바꿔 저장하면 `warning` 과 메시지로 알리고(실행 응답의 `execution_notes` 까지 올라온다), `self:fill` 은 기존 산출물을 바꾸면 `replaced_existing:true`. 도구 설명에 남아 있던 "덮어씁니다" 는 실제와 반대라 바로잡았고, 교재(`ibl_composition_tools.md`)에 낱말별 표와 프로그램이 할 일을 실었다. 공통 `if_exists` 인자는 넣지 않았다 — 보장할 동작(다른 일이 일어났으면 말한다)에 필수가 아니다.
- **L52-3 (`engines:render`)**: 워드류 문서(docx·doc·odt·rtf·pptx·ppt·odp)는 인쇄 모양이 곧 시각 형태이므로 **기존 `pdf` 길**이 LibreOffice 로 PDF 화한 뒤 그린다(op 생략 시 확장자로 추론, 결과에 `pdf_path`·`converted_from`). 장부의 변환 코드를 공통 함수로 뽑아 같은 임시 프로필·한글 대체 글꼴을 쓴다. 브라우저가 그리지 못하고 내려받으려는 파일은 "이 형식은 html 로 그릴 수 없습니다 + 그릴 수 있는 형식 목록" 으로 답한다.
- **L52-4 (PDF 칸의 한글 간격)**: 원인 확정 — 한글 값의 외형은 내장되지 않은 CID 글꼴(`/Batang`)로 만들어지는데 폭 선언(`/W`·`/DW`)이 없어, 그 글꼴로 찍히는 빈칸·기호가 전각으로 벌어진다. 채우며 생긴 그런 글꼴에 ASCII 구간 반각 폭(`/W [1 94 500]`)을 적는다. MuPDF 와 macOS PDFKit(훑어보기) 두 보기 프로그램에서 수리 전 벌어짐·수리 후 정상을 눈으로 확인했다.

### 남긴 것
- `self:copy` 의 반환 필드 관측 원장은 실사용 수확(훈련 제외)이라 아직 `message` 하나뿐이다 — 복사 응답의 `path` 를 읽으면 정적 검사가 "관측 안 된 필드" 로 경고한다. 관측 데이터를 손으로 고치지 않았고, 다음 실사용 복사 뒤 수확으로 풀린다.
- 틀에 동아시아 글꼴 지정이 없을 때 **다른 기계의 Word/LibreOffice** 가 어떻게 그리는지는 미확인(이 기계의 그리기 길은 대체 글꼴을 심어 한글이 나온다).
- Windows·Linux 에서의 문서 그리기, 머리글·바닥글이 구역마다 다른 긴 문서, 하이퍼링크 안의 자리표시자(문단 단위 치환으로 물러남)는 시험하지 않았다.
- 수리 작업 중 실수: 회귀 시험 파일을 backend 에 쓰고 곧바로 고쳐 재기동 제어자가 한 번 FAILED 로 갔고(`restart --wait` 로 복구), 임시 시험 파일을 backend 에 만들었다 지워 재기동이 한 번 더 돌았다. 반환 모양 수집 스크립트를 도움말 인자로 불렀다가 전수 수집이 시작돼 바로 멈췄다(파일 변경 0).
