AI 기본 턴에서 처음 새 계산 코드를176줄 작성하고 도구 확인을 요구받은 것은 기존 정책의 올바른 집행이다. 이 거절은 제거하지 않았다. `return` 뒤 쓰기를 놓은 AI 작성 오류와 잘못된 결과참조 `.v`는 AI가 자체 수정했으며 엔진 결함으로 분류하지 않았다. 훈련자의 `/ibl/check` 경로 착각과 HTTP 결과에 MCP용 result_ref를 기대한 착각도 기록했다. 후자는 v3에서 실제 지원하는 `reuse:{run_id}`를 사용한다.

## 비용·한계

v0→v1은 같은 입력·비교 조건·산출물의 각1회 표본이다. 47.843→2.589초는 **훈련자 프로그램 실행**의 절감이며 작성·AI 대기·수리·회귀 시간을 포함한 전체 절감률이 아니다. 서로 다른 동시 부하의 가능성도 있어 일반 성능 보증으로 쓰지 않는다. 1,539,662→97,910단계와 제거된 반복 검색은 결정론적 근거다. 최종 표 보고서는 읽기 쉬운 전달에 계산을 추가하므로 v1과 동일 산출물 비용 비교로 합치지 않는다.

AI 원장 `accounting=billable_usage`: ep4607 입력1,597,880·출력20,230·cache_read1,300,404·cache_create295,233; ep4608 입력862,751·출력5,701·cache_read713,873·cache_create144,141. 입력은 원장의 전체 입력 관측값이므로 캐시를 다시 더하지 않는다. 모델은 Claude Code/opus(원장 세부 모델 claude-opus-5-5), 도구11회/4회다. 훈련자 자신의 모델 토큰은 미측정이다.

필요한 비용은 견적 전건 계산, 짝수 반올림의 독립 대조, 저장 재독, 누락·배송비 미상 분리다. 줄인 낭비는 품목별 전체 재탐색, 재사용 코드의 거절·재확인·재쓰기, 원시 JSON 보고서의 사용자 재가공이다. 독립 AI는 Python으로 계산했으며 IBL만의 독립 해결 성공으로 세지 않는다. AI의 원자료 프로파일링과 서로 다른 수치 체계의 검증은 정확성에 기여했으므로 단순히 호출 수가 많다는 이유로 삭제하지 않았다.

후속 수리 운영에서도 낭비가 있었다. 첫 전수를 회원 감사 지문 갱신 전에 시작했고, 교재 예제 등록 검사를 먼저 하지 않아 전체 회귀를 다시 돌렸다(앞의 두 전수219.35초·220.74초). 빌드 정합과 변경 교재 검사를 전수보다 먼저 끝내는 기존 절차를 지키면 줄일 수 있는 운영 비용이며, 프로그램 속도 개선에 숨기지 않는다.

실제 온라인 상점 검색·로그인·배송지별 요금·주문·결제는 시험하지 않았다. 합성 견적의 구매 준비 흐름과 코드 재사용 관문의 공통 결함 수리가 이번 범위다. 수리 후 AI를 다시 호출해 전체 토큰/시간 개선량을 측정하지 않았고 실제 실패했던 코드 변환을 결정론적으로 재생했다.
