## 5. 개선 방향(다른 분야에도 통하는 것)

1. **L6-1 예산**: (a) 교재에 단계의 단위와 행당 비용 표를 적고, (b) check 가 입력 건수를 알 때(inputs 인스턴스·리터럴) 단계 추정을 내며, (c) 큰 표의 행 단위 변환을 도구 비용으로 처리하는 길(compute 의 단순 필드 식 네이티브화 또는 요청 단위 예산 상향의 명시 계약)을 정한다. 재검증 = p1_v0 원판이 예산 안에 들거나 check 단계에서 예산 초과를 예고.
2. **L6-2**: schema 필드 ∩ (입력 열 − input_fields) ≠ ∅ 를 check 에서 거절(처방: select 또는 다른 이름). 재검증 = 재현 check 실패 + p1_v1 원판 check 실패.
3. **L6-3**: judge 계약에 배치 의존성 명시, 또는 행별 독립 판정 옵션. 최소한 usage/결과에 batch 크기 기록. 재검증 = 21쌍·6쌍 확률 차 축소 또는 문서.
4. **L6-4**: usage.steps 를 최상위 문장·반복 단위로 귀속(`steps_by_span`), check 에 추정치.
5. **L6-5**: reuse 응답에 후보별 `skipped:{call, reason}`. 재현 조건(재기동 뒤 병렬 each 영수증?)을 관문 시험으로.
6. L6-6·7·8·9: 문서·진단 보강(제외 건수 신고, compute 계약 서술, CSV 인용 함수 또는 `format:"csv"`, 교재 모델 재사용 문장 갱신).
