## 5. 실제 재독·재계산·재사용 범위 (정직한 기록)

- **재사용**: 판정 스크립트 `_build/judge.py`를 수정 없이 그대로 실행(입력·출력 경로 인자, 출력은 `_build/variant/`로 분리해 기본 verdicts.json을 덮지 않음). task.md의 규칙·history 분석·후보 분석은 재사용(history 9파일 해시 불변 확인, 본문 재독 없음). 기본 판정을 읽은 IBL의 두 읽기는 실패한 첫 시도의 영수증을 `reuse`로 되살렸다.
- **실제 재독·재계산**: 스크립트가 입력 65파일 전부를 다시 해시하고 runs·requirements·events 2,400행·전 조건을 **전부 다시 계산**했다(결정론·수초 단위라 부분 계산 코드를 새로 짜는 비용이 더 컸다). 즉 ‘입력 의존 실행만 재계산’이 아니라 **전량 재계산 + 기본과 실행별 전 필드 대조**로 증분을 확인했다. 그 대조에서 신선도상 바뀐 입력에 의존하는 4개 실행만 달라졌고, 나머지 20개는 JSON 전 필드가 기본과 같았다(기대와 실제 일치).
- 직접 열람: 변경된 SYN-R00 artifact·check 원문 2파일만 사람이 읽을 수 있게 다시 열었다. 다른 실행자의 trainer/source/runs/harness/정답은 열지 않았다.
