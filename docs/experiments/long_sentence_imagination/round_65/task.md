## 3. 시스템 AI에게 줄 주 과제

> 연결된 tv1을 제공한 자료 정리 작업에 쓸 수 있게 설정해 줘. 먼저 실제로 연결된 PC와
> 운영체제, 실행 도구, 작업 폴더를 확인하고, 제공한 요구사항과 현재 상태를 비교해 줘.
> 지정한 시험 폴더에 전용 실행 환경과 입력·출력 폴더를 준비하고, 제공한 앱의 처리 설정을
> 맞춰 줘. 이미 맞는 환경과 기존 사용자 메모·설정은 유지하고 바꿀 필요가 있는 것만 바꿔 줘.
> 서비스 포트가 사용 중이면 그 프로그램을 건드리지 말고 허용된 대체 포트로 설정해 줘.
> 준비한 환경으로 앱을 실행하고, 한글·일본어·이모지가 포함된 샘플 자료가 요구대로 처리되는지,
> 응답한 서비스가 이번에 만든 것인지 확인해 줘. 설치 명령이 끝났다는 것과 실제 사용 가능한
> 상태를 구분하고, 실패나 확인하지 못한 항목은 그대로 남겨 줘. 오래 걸리는 작업은 접수 정보를
> 남겨 같은 작업을 확인하고, 이미 끝난 설치를 중복 실행하지 마. 적용 직전에 대상 파일이
> 달라졌다면 최신 내용을 다시 읽어서 내가 바꾼 내용을 보존해 줘. 작업이 끝나면 변경 전후,
> 동작 검사 결과, 남은 일과 이어갈 방법, 되돌리는 방법을 한글 보고서로 저장해 줘.
> 변경은 지정한 시험 폴더와 이번에 띄운 시험 프로세스에 한정하고, 검증 뒤 그 프로세스만
> 종료해 줘. 기존 IndieBiz 설치와 다른 작업은 유지해 줘.

운영자는 여기에 대상·요구사항 파일·자료 및 결과 위치만 추가한다. 함수 이름·IBL 해법·훈련자
프로그램·비공개 정답표는 주지 않는다. 실기기에서 사용자 수준 설정·프로세스를 시험하는 과제다.
실제 IndieBiz 신규 설치·전체 부팅·모델 질의·Electron 화면 성공으로 확대하지 않는다.

## 4. 입력과 기본 상태

시험 앱은 표준 라이브러리로 설정 읽기·자료 처리·HTTP 상태 응답을 제공하는 작은 부품으로
준비한다. 설치·차이 계산·복구·판정 로직을 앱에 넣지 않는다. 두 실행자에게 같은 바이트를 준다.
런타임은 tv1에서 확인한 실행파일·판본을 요구사항에 고정하고, 없으면 준비 전제 부족으로 기록한다.

| 자료 | 고정할 내용 |
| --- | --- |
| `requirements.json` | 기기·허용 루트, 실행파일/판본, 기본 처리 배수 2, 출력 `out-a`, 루프백 포트 후보 |
| `seed/settings.json` | 틀린 배수 1, 이전 출력 경로, 보존할 `user_note`와 미지정 설정 필드 |
| `input/sample.json` | id 01~12, 값 1~12, 한글·일본어·이모지 이름. 별도 빈 입력도 제공 |
| `input/manifest.json` | 입력 해시, 앱 판본, 기대 문자·레코드 수, 실자료/시험자료 구분 |
| `protected/` | 사용자 메모·기존 출력. 실행 전후 바이트 대조용 파일 |
| 검증자 전용 기대값 | 기본 12건·합계 156, 변형 12건·합계 234, id·이름 exact 일치, 빈 입력 0건 |

단순 합계뿐 아니라 각 행의 `결과=입력값×배수`와 원문 문자·순서를 전건 대조한다.
기본 첫 후보 포트에는 운영자가 소유한 작은 시험 서비스를 미리 띄워 충돌 분기를 **실제로** 밟는다.
대체 포트는 시작 시 빈 상태를 확인하되, 검사와 bind 사이 경합은 실패·재관측으로 처리한다.
두 서비스의 nonce·PID·시작 시각·루트·포트로 신원을 구분한다. 운영자는 자기 점유 서비스를 정리한다.

이미 맞는 입력 폴더·보존 파일, 없는 전용 환경, 틀린 설정 두 항목을 시작 상태로 고정한다.
실제 홈·포트·PID를 추측값으로 채우지 않는다. 준비 실패와 실행자 실패를 분리한다.

## 5. 훈련자 프로그램의 책임 분해

| 부품 | 입력 → 반환 | 실패·효과 |
| --- | --- | --- |
| 신원·상태 관측 | 대상·루트 → 신원, 환경, 설정값·지문, 사용 포트 | 조회 불가를 ‘없음’으로 바꾸지 않음 |
| 차이 계획 | 요구 판본·관측 → 유지/변경/보류, 의존 단계, 사전조건 | 읽기만 수행 |
| 적용 | 계획·최신 지문·자료 → 단계 접수증·변경 내역·원본 참조 | 전용 환경·설정 생성, 불일치면 쓰기 전 중단 |
| 동작 검사 | 환경·설정·기대값 → 서비스 신원·행별 결과·조건 판정 | 실제 실행·재독, 실패 원문 보존 |
| 회수·마무리 | 모든 접수증·판정 → 산출물·재개 정보·종료 증거 | 파일 전송·재독·이번 프로세스 종료 |

이 분해는 설계이며 검증된 `.ibl` 코드는 아니다. 실행 때 공개 교재와 `describe`로 계약을
조회하고 최초 완성 초안을 보존한다. 신원·분기·단계 연결·재사용 판단은 IBL에 두며,
원격 셸·파일 전송·기존 단계 실행기는 부품으로 호출한다. 전체 풀이를 새 스크립트에 숨기지 않는다.

설정 변경은 이번 시험의 JSON 필드 병합 부품으로 구현할 수 있다. 예상 지문과 다르면 쓰지 않고
충돌을 반환하도록 계약을 명시한다. 재독한 최신 설정에서 요구 필드만 갱신하고 미지정 필드는
보존한다. 이 부품의 단일 실행 검증을 먼저 남기며, 확인하지 않은 보편적 원자성이나 자동 롤백을
주장하지 않는다. 동시 쓰기 보장은 이번에 통제한 변경 시점까지다.

매 작업에 절대 cwd·실행파일·필요 env를 전달한다. 접수와 종료, exit 0과 업무 성공을 구분한다.
대기 시간 초과는 기존 참조로 관측하고, 불명 작업에 새 요청ID를 만들어 재접수하지 않는다.
계획 판본이 바뀌면 새 run_id를 쓰되 완료된 환경 구성은 관측 근거로 유지한다.

## 6. 변형 하나 — 요구 변경과 사용자의 중간 수정

같은 실행자의 기본 결과가 보존된 뒤 다음 자연어 요청을 보낸다.

> 출력 폴더를 out-b로, 처리 배수를 3으로 바꿔 줘. 앞에서 만든 실행 환경과 입력 자료는
> 재사용하고 out-a 결과는 보존해 줘. 내가 설정의 사용자 메모를 수정할 수도 있으니,
> 이전에 읽은 설정으로 덮어쓰지 말고 적용 전에 확인해 줘. 새 설정으로 같은 자료를 처리하고
> 바꾼 항목과 재사용한 항목을 정리해 줘. 너 자신의 직전 결과·참조는 재사용해도 되지만
> 다른 실행자의 프로그램·산출물·정답은 참조하지 마.

운영자는 변형 계획의 설정 지문이 잡힌 뒤, 쓰기 직전에 시험 설정의 `user_note`만 바꾼다.
실행 경로에 명시적인 계획→적용 경계를 확보하고 거기서 잠시 멈춰 수정한다. 그 경계를
관측·제어하지 못했다면 충돌 주입을 성공으로 세지 않고 미검증으로 남긴다. 네트워크나 헬퍼를 끊지 않는다.
같은 의미의 개입을 각 실행자에 적용하고 운영자 개입 시간·방법을 별도 기록한다.

이는 요구 변경과 상태 신선도를 함께 보는 변형이다. 기대 결과는 다음과 같다.

- 오래된 지문으로 수행한 첫 적용은 쓰기 전에 충돌로 끝나며 기존 바이트를 보존한다.
- 최신 설정을 다시 읽고 배수·출력 경로만 바꿔 새 사용자 메모를 보존한다.
- 전용 환경 재설치 0회, 기존 입력·out-a 변경 0건, 새 결과 12건·합계 234다.
- 새 결과와 서비스 신원까지 확인하며 변형에서 필요한 실행만 다시 한다.
- 기본·변형에서 설치/설정/처리의 실제 실행 횟수를 기록한다. 업무 처리 성공은 각각 한 번을
  목표로 하며 추가 실행이 생기면 숨기지 않고 이유·부작용을 판정한다.

변형 뒤 설정 사본 한 개를 저장된 원본으로 복원·재독해 되돌리기 절차를 시험한다.
설정 원본은 시험 루트의 `data/_backups/YYYY-MM-DD_tv1_setup/`에 둔다.
이 검증을 OS 설정이나 실제 운영 설치의 복원 성공으로 확대하지 않는다.

## 7. 완료 조건과 증거

| ID | 완료 조건 | 독립 확인 |
| --- | --- | --- |
| T1 | 현재 tv1에만 실행 | 모든 변경의 device_id·절대 루트, 다른 루트 불변 |
| T2 | 필요한 환경만 구성 | 실제 실행파일·버전, 환경 경로, 단계 결과와 재설치 횟수 |
| T3 | 설정·보존 정확성 | 요구값과 모든 미지정 필드, 메모·기존 결과 전후 지문 |
| T4 | 실제 충돌 해결 | 점유 서비스 유지, 허용 대체 포트에서 새 nonce/PID/루트 일치 |

검증자는 입력 판본에 묶인 기대값과 실제 파일·응답·작업 기록을 대조한다. 검증 중 대신 설정을
고치지 않는다. 검사 통과 / 실행 종료 / 과제 달성을 별도 판정하고 모든 필수 조건 충족 때만
달성으로 기록한다. 접수 성공·폴더 존재·import 성공만으로 사용 가능을 선언하지 않는다.
실행되지 않은 충돌·복구 분기는 미검증이다. 환경 전제 부족은 정확히 보고해도 설정 달성은 아니다.

## 8. 두 실행, 예산과 기록

훈련자 IBL 기본→변형, 독립 시스템 AI 자연어 기본→변형을 수행한다. 준비 자료의 바이트·모델
조건과 완료 기준을 고정하고 원격 루트·환경·포트·프로세스·요청ID·출력·대화를 실행자별로 분리한다.
공유 OS 캐시 효과 등 남는 차이는 기록한다. AI에는 이 설계서 전체 대신 §3/§6 요청문과
허용 범위·입력/출력 위치만 준다. AI 풀이가 Python 중심이면 과제 달성과 IBL 작성 능력을 구분한다.

지원하는 진입점에 `origin:"training"`을 명시한다. AI background 접수의 task_id/status_url과
원격 작업 참조를 보존하고 동일 작업의 종료를 회수한다. 훈련 표식은 외부 효과 격리를 대신하지 않는다.
전체 준비·작성·기본·변형·진단 상한은 **60분**이다. 준비 10분, 훈련자 18분, AI 22분,
최종 검증·진단 10분을 배분하며 초과를 자동 연장하지 않는다. 종료 보고·증거 보존·정리는 별도 기록한다.

로컬 자료는 `outputs/long_sentence_imagination/YYYY-MM-DD_N회차/`, 비민감 재현·요약은
`docs/experiments/long_sentence_imagination/round_N/`와 누적 원장에 남긴다.
최초 초안·수정본, 입력 지문, 작업/에피소드 ID, 적용 전후 증거, 최종 보고서를 연결한다.
토큰은 입력·출력·캐시와 역할별 포함 범위를 기록하고 미측정은 미상으로 둔다.
설정·결과 전체 재전송, 반복 환경 조회, 성공한 설치의 재실행, 불필요한 모델 왕복을
실제 기록으로 돌아보되 필요한 검수 비용까지 낭비로 취급하지 않는다.

훈련 중에는 제품·헬퍼 수리를 적용하지 않는다. 모든 접수 작업의 종료와 증거 회수 뒤 발견을
신원/발견·계약·상태 신선도·실행·완료 판정·비용으로 분류해 후속 수리에 넘긴다.
64회차의 문자 보존·접수증은 되먹임 관측, 이번 변경 충돌은 신규 관측으로 구분한다.
실제 OS 재부팅·전원/WOL·관리자 설치·IndieBiz 전체 부팅은 별도 후속 과제다.
