## 과제·조건

세 창고의 공지 54건을 행사 ID 36개로 합쳐 10월 15~21일의 지역별·날짜순 소식지,
전건 판정, 재사용 가능한 수집 자료를 만든다. 재게시·수정·동시 충돌·날짜 부재·취소·지난 일정·기간 밖을 구별한다.
변형은 E08 취소, E09 19일→21일 이동, b 창고 HTTP 503이다. 이전 b 공지 18개는 과거 자료로 보존한다.

합성 자료를 쓴 이유는 실제 이웃 개인정보·등록·공개 상태를 건드리지 않고 취소와 장애를 통제하기 위해서다.
루프백 HTTP 서버가 `/manifest`와 파일 URL을 서빙하며 실제 IBL·HTTP·파일 IO를 사용한다.
공개 발행·발송·실이웃 인증은 하지 않았다. 캐시 상태 경계는 별도 임시 SQLite에서 실제 서비스 함수로 검사한다.
이 시험을 실이웃 서비스나 인증의 성공으로 일반화하지 않는다.

시작 HEAD `8ba74cd89938f09e35f00a99e2490ad09686166d`, 수리 시작 HEAD
`dd2e6eba2a8f3c65820bfc8be99832b3cedd2cc6`. 중간의 폰 기능 커밋은 다른 작업이다.
이번 최초 창고 프로그램 작성에는 구현 코드를 사용하지 않았다. v1의 잘못된 결과와 v2 초안 보존 뒤
창고 구현을 열어 원인을 진단했다. 미디어/재기동 코드는 실행 전제 장애 진단에 사용했으며 IBL 해법에 쓰지 않았다.

## 작성·실행

자료는 조합 교재·문법·액션 describe·공유창고 통신 문서였다. 과거 회차에서는 HTTP 운반 코드만 참고했다.
`파일읽기 → 창고읽기 → 행사판정 → 기사/출처 표시 → 세 파일 저장·재독`으로 분해했다.
외부 수집/파일 쓰기와 순수 최신 공지 선택·기간 판정을 구분했다. 전체 IBL은 버전별로 보존했다.

|---|---|---|---|

v1은 `browse`가 로컬 캐시임을 충분히 설명하지 않는 계약을 따라 신규 URL을 조회했다.
실제 네트워크 요청 없이 `success:true, files:[], total:0`을 받았다. “빈 목록”과 “아직 읽지 않음”이
같은 값이어서 프로그램의 성공 경로를 통과했다. 단순 호출과 전체 기본/변형에서 재현했다.
v2는 문서화된 `/manifest`를 내려받고 각 파일을 읽는 명시적 우회다. 코어를 고쳐 훈련을 통과시키지 않았다.

독립 AI는 자연어 요청과 입력·출력 위치만 받았다. 자기 이전 결과만 후속에서 재사용하도록 했다.
실행 궤적은 IBL로 HTTP 수집·파일 파싱·판정을 수행하고 Bash로 입력/검증을 보조했음을 보인다.
기본 8 IBL+3 Bash, 변형 9 IBL+5 Bash. 기본의 검사 거절 2건과 실패 1건을 성공 호출 수에 섞지 않았다.
AI는 창고 browse 문제를 밟지 않고 직접 HTTP 경로를 택했다. 변형은 a/c 파일 36개를 다시 읽었다.
기본 원본은 보존했고 b 18개를 과거 자료로 분리했다. 해법·정답 파일을 읽은 흔적은 확인되지 않았다.
훈련자 성공으로 AI 독립 능력을 대신 판정하지 않았다.

## 수리 후 원래 과제·새 변형

v3 기본과 취소/장애 변형의 36개 판정·모든 출처·정렬·파일을 독립 Python 계산과 전건 대사했다.
새 변형은 b 창고 복구와 E21 16일→17일 이동이다. 추천10·취소4·기타 판정 전부 일치했고
54공지 중 53개를 재사용하여 E21 파일 하나만 다시 받았다.
원래 v1도 재실행했다. 빈 목록 0건을 “전부 확인”이라고 쓰던 경로가 이제 실패한 창고 3개와
`source_complete:false`를 남긴다. 이 정직한 부분 결과를 소식지 과제 달성으로 세지는 않는다.

같은 자연어 요청을 출력 폴더만 바꾸어 시스템 AI에 다시 맡겼다(ep4786,
task_sysai_90394faa, succeeded). 새 HTTP 수집 54건·36행사 판정·JSON 출처는 전건 일치하고
E06 수정 표기도 올바르다. 다만 소식지는 창고·파일명만 남기고 직접 URL 54개를 빠뜨려
사전 검증 기준에서는 **부분 달성**이다. 원본 `ai-repaired-base`와 실패 검증 결과를 보존했다.
원문 링크를 보충하라는 별도 후속 요청은 재수집·재판정 없이 자기 판정 자료만 쓰도록 했다.
후속 ep4787/task_sysai_e918dbb8도 succeeded로 종료했고 `ai-repaired-links`의 36행사·54출처
검증이 통과했다. 두 JSON은 바이트 동일, 소식지는 링크를 벗기면 최초 본문과 동일함을
별도 검증했다([verify-links-only.json](evidence/verify-links-only.json)). 후속 성공으로 최초 부분 달성을 덮지 않는다.
이 재실행은 앞 대화를 가진 상태여서 콜드 스타트 비교가 아니며, AI의 경로 선택 변화를
코어 수리의 효과로 귀속하지 않는다. IBL HTTP·파일 수집 후 판정은 Python 스크립트를 사용했다.
최종 답변의 “IBL에는 JSON 문자열 해석 내장이 없다”는 설명도 능력 검증 사실로 채택하지 않는다.

첫 전수에서는 이 항목이 통과했지만 원인은 확정하지 않았다. 최종 전수에서는 이 항목을 포함해
