## 자연어 요구

제공한 세 이웃 공유창고에서 2026-10-15~21의 행사·모집·나눔을 모아 동네 소식지를 만들어줘.
지역별로 묶고 각 지역 안에서는 날짜순으로 정리해줘. 같은 행사 ID의 재게시물은 하나로 합치고
모든 출처를 남겨줘. 같은 ID에 수정 공지가 있으면 가장 최근 공지로 날짜·상태를 정하되,
같은 시각에 내용이 충돌하면 임의로 고르지 말고 확인 필요로 분리해줘.
지난 일정과 기간 밖 일정, 취소된 행사는 추천 목록에서 제외하고 이유와 출처를 별도로 남겨줘.
날짜가 없는 소식도 확인 필요로 남겨줘. 자료를 못 읽으면 없는 소식으로 취급하지 말고
실패한 창고/파일과 확인 범위를 알려줘. 읽기 쉬운 newsletter.md와 전건 판정 decisions.json,
재사용 가능한 수집 자료 collected.json을 지정한 출력 폴더에 저장해줘. 실제 공개·발송은 하지 마.

변형: 행사 한 건 취소·한 건 일정 변경·창고 하나 503. 자신의 이전 결과는 재사용할 수 있으나
다른 실행자의 trainer/harness/초안/정답은 읽지 않는다. 최신 확인 실패 자료는 과거 정보임을
표시하고 현재 확인된 추천과 구분한다. 실패를 이유로 전체 결과를 버리지 않는다.

## 자료·완료 기준

세 창고의 HTTP /manifest·파일 URL 계약을 제공하는 루프백 시험 서버에 합성 공지를 제공한다.
실제 이웃 개인정보·등록 상태·공개창고를 변경하지 않고 취소/장애를 재현하기 위해 합성 자료를 쓴다.
실제 IBL 엔진·창고 읽기 구현·HTTP·파일 IO를 사용하며 실이웃 인증/폴러는 범위 밖이다.
생성 스크립트와 기대값은 AI 입력 폴더 밖에 둔다. 기본/변형 URL 공간은 구분한다.
예정 자료 3창고×18건=54개 공지. event_id로 합쳐 36건, 재게시·기간 밖·취소·날짜 부재·동시 충돌 포함.
세 출력 파일 존재·재독, 모든 공지/행사 전건 대사, 지역/날짜 정렬, 출처 누락0,
실패 원천 명시, 변형에서 취소/날짜 이동 반영, HTTP 요청 로그로 수집 범위 확인.
숫자 정답은 준비 후 실행 전 evidence/expected.json에 고정한다.

## 작성 조건·분해

가이드·조합 교재·액션 describe·문법·자료만으로 작성한다. 과거 회차는 HTTP 운반 코드만 참고.
창고 읽기→파일 읽기→정규화→ID별 최신 판정→지역/날짜 정렬→본문/판정/수집 파일 저장과 재독.
실행기·창고 내부를 읽어야 하면 최초 초안/장벽 보존 후 도움받은 시도로 구분한다.
훈련 작업 전부 종료 및 증거 회수 전 라이브 코드·어휘를 수리하지 않는다.
