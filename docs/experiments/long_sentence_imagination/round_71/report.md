## 과제·환경·작성

[사전 과제](task.md): 두 회원의 독립 폴더에서 6개 파일×8개 주문을 읽고 취소를 제외한
건수·금액을 집계해 JSON과 읽을 수 있는 요약을 저장한다. CRLF·한글·이모지를 포함한 원문을
복사하고 세 결과를 재독한다. 변형은 한 입력 손상 뒤 기존 결과 갱신이다.
실제 IBL 판본2·MemberSessionManager·서명 HTTP·Go 실행부·SQLite·로컬 승인·파일 IO를 썼다.
같은 macOS에서 기기 프로세스 둘을 분리했다. 중앙 인증·요청 원장과 회원 데이터는 회차 폴더에 격리했다.
실제 회원 키·파일은 사용하지 않았다. 루프백 시험 서버이므로 배포 HTTPS 인수는 아니다.

분해는 파일별 집계 함수 → 목록 조합/실패 표시 → 저장 → 재독이다.
Python harness는 준비·전송·승인·증거 수집이며 업무 집계는 IBL에 있다.
공개 교재·회원 가이드·액션 선언을 사용했다. 실행 기반을 연결할 때 기존 통합 테스트와
회원 진입점의 내부 코드를 읽었으므로 환경 구축은 도움 받은 시도다.
첫 완성 초안 [v0](draft_v0.ibl)를 보존했다. 기존 출력도 먼저 읽는 [v1](draft_v1.ibl)로
한 번 수정했고 수리 전에도 같은 실패를 확인했다. 첫 두 실행의 별도 `check:true`를
빠뜨렸으며 실행기의 자동 검사는 거쳤다. 수리 후 별도 검사는 `ok:true`, `issues:[]`,
`status:incomplete`(실행 시 확인할 도구 경계)였다. 사전 검사 누락을 통과로 소급하지 않는다.

기본 60분 상한을 적었지만 승인·환경 준비·AI 대기 중 벽시계 상한을 넘겼다.
최초 harness에는 전체 회차 마감시각과 timeout 뒤 종료 영수증 회수도 부족했다.
이 운영 한계를 남기며 이후 실행을 최초 훈련 성과에 합산하지 않는다.
후속 수리 검증 harness는 AI를 120초로 제한하고 취소 뒤 종료 상태를 회수한다.

지문은 턴 메모리에만 둔다. 다른 회원/턴/작업/연결에 상속하지 않는다. 유효하지 않은 지문과
실패한 읽기는 권한 증거가 되지 않으며, 명시한 expected_hash는 덮어쓰지 않는다.
쓰기 직전 자동 재독을 하지 않아 사람의 중간 편집을 새 승인으로 오인하지 않는다.
Go의 파일 경계·승인·비교·사본 보관은 그대로 소유자로 남는다. 새 어휘·op·파일 저장 엔진은 없다.

최소 재현: 같은 회원 턴에서 `[self:read]{path:"proof.txt"}` 뒤
`[self:write]{path:"proof.txt",content:"revised"}`. 수리 전 거절, 수리 후 성공;
둘 사이 원본을 바꾸면 여전히 거절된다. 실제 signed Go↔FastAPI 회귀에도 이 쌍을 추가했다.

## 독립 AI와 비용

동일 자연어 요구만 전달하고 자료와 결과는 AI 전용 폴더에 뒀다. 훈련자 초안·정답은
회원 폴더 밖에 있으며 회원 파일 경계가 접근을 막는다. `/m/desktop` 표면은 origin:training을
받지 않으므로 임의 인자를 넣지 않았다. 실제 member 신원과 격리된 회원 원장을 사용한다.
회원 경로는 주인 episode/trajectory에 본문을 기록하지 않는다. 따라서 시스템 AI 에피소드 번호와
같은 집계로 비교할 수 없다. 정확한 모델명·역할별 billable 토큰은 이번 실행에서 회수하지 못했다.

첫 AI 작업 `bacb60535c6f8d5eb83b5361`은 900초 제한 뒤 로컬 close와 프로세스 종료로 끝냈다.
종료 직전 로컬 DB의 running 표기는 그대로 보존했다. 이를 성공 또는 취소 영수증으로 취급하지 않는다.
서버와 실행부 프로세스의 종료는 확인했고 추가 명령은 남아 실행되지 않는다.
후속 진단 작업 `33e3d67dec7113440f224122`는 120.694초 뒤 **cancelled**를 회수했다.
읽기/쓰기 과제 도구 호출은 0, 결과 산출물은 없다. 자연어 변형 및 수리의 AI 선택·비용 효과는 미검증이다.

훈련자 v0 기본 A/B 3.05/1.07초, v1 수리 전 3.09/1.07초; 수리 후 기본/손상/복구/충돌은
각 기기에서 약1.07~1.09초였다. 최초 준비·모듈 적재가 달라 속도 개선률로 해석하지 않는다.
IBL 안 모델 호출0이며 작성자 토큰은 미측정이다. 사용자 승인 대기와 운영 비용도 총 소요에서 제외하지 않는다.
필요했던 비용은 기기 격리·독립 바이트 대조·충돌 검사다. 피할 수 있는 비용은 지문 연결 부재로
정상 입력을 다시 읽고도 쓰기에서 실패하던 재작업이다. 수리는 그 실패를 제거했다.
전체 시간·토큰 절감은 입증하지 않았다. 모델 대기에 별도 재시도나 모델 변경을 계속 붙이지 않는다.
