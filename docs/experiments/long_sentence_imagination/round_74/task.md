# 74회차 사전 계약 — 회원 PC의 범위 발췌·배포본 갱신

시작 2026-10-15 18:31 KST, 시작 HEAD ab0aeec9. 훈련 상한 60분(19:31 KST).
주제는 사용자가 지정한 중앙관리형 회원 데스크톱이다. 71/72회차의 집계와 달리
지정 행 범위·줄끝 보존·불완전 자료·회원별 동일 경로·기존 결과 갱신의 이음새를 본다.
실자료에는 사적 회원 파일이 필요하므로 합성 절차서 12개를 사용한다. 실제 중앙 회원 경로,
서명 HTTP, Go 실행부, 로컬 SQLite/파일 IO를 격리된 두 회원으로 실행한다.
동일 Mac의 두 프로세스이며 실제 두 물리 PC나 Electron 출시 인수는 아니다.

## 자연어 요청 원문
현재 작업 폴더에서 교육용 안내 묶음을 만들어 줘. manifest.json의 sections 배열에는 순서대로 id, path, start_line, end_line이 있고 각 파일에서 1부터 세어 양끝을 포함하는 지정 줄만 공개할 수 있어. 각 지정 구간을 원래 줄바꿈과 공백 그대로 추출하고, excerpts.json에 sections 배열(각 id, path, start_line, end_line, status, text)과 missing_files 배열을 저장해 줘. 읽은 구간은 status를 ok, 읽지 못한 파일은 unavailable과 text null로 남겨. handbook.txt에는 명세 순서대로 "## ID\n" 다음에 추출 원문을 그대로 붙이고 그 뒤 "\n"을 하나 더 붙여 줘. 읽지 못한 구간은 원문 대신 "[미확인: 파일경로]"를 넣고, 맨 끝에는 "미확인 N건\n"을 붙여 줘. 지정 범위 밖의 비공개 줄은 배포본에 넣으면 안 돼. 기존 두 결과는 먼저 읽고 갱신하며, 저장 뒤 두 파일을 다시 읽어 내용이 맞는지 확인해 줘. 입력 절차서와 명세는 고치지 말고, 이 폴더 밖 접근이나 외부 발송은 하지 마.

## 고정 입력·기대와 변형
- 회원 A/B의 같은 상대경로에 서로 다른 본문, 한글·이모지·따옴표·탭·후행 공백.
- LF/CRLF/CR 줄끝을 4개씩 섞은 12파일, 각8줄. 지정 범위는 3~5줄.
- 1/2/6/7/8줄은 제외. 독립 기대는 원본 바이트의 CR/LF/CRLF 행 분할의 [2:5].
- 모든 JSON 필드·배포본 UTF-8 바이트·IBL 재독·입력 해시를 전건 대조.
- 기본 변형: doc04.txt 하나가 없어짐. 같은 IBL을 다시 실행하며 이전 결과를 갱신;
  unavailable1·missing_files1·나머지11개와 순서/바이트 보존. 자동 완전 성공으로 위장 금지.
- 수리 후 새 변형: 파일 복구·명세 역순·첫 항목의 범위를 1~1로 명시 변경.
- 별도 중단 진단: 로컬 쓰기 승인 전 취소한 작업은 종료되며 결과 두 파일은 생기지 않아야 함.
  승인 후 이미 생긴 쓰기는 취소로 되돌렸다고 주장하지 않음.
