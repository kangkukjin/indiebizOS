## 수정과 책임

- `data/idioms/pc_control_check.ibl`: evidence_ref와 plan/job의 Record 경계를 확인한다. 생략·null·목록·문자열·내부 참조 손상은 기존 검증기의 unknown/failure로 모은다. 원 task_ref와 입력을 보존하며 장치 명령을 재전송하지 않는다. 정상 영수증의 대기·검증 경로는 그대로 공유한다. 새 어휘·별도 검증기 없음.
- PC 네이티브 구현: Windows의 클래스 기본 true를 없애고 EndpointVolume 활성화·조회 성공 뒤 API 지원을 표시한다. `capability_basis`는 Windows의 인터페이스와 macOS의 쓰기 가능한 속성을 구분한다. 하드웨어 지원 비트로 can_set_volume/can_mute를 대체하지 않는다.
- `data/scripts/pc_control.py`: 계약 조회와 실제 음량 관련 반환 모두에 `audio_capabilities.scope=os_api_support`와 의미·한계를 싣는다. `verification_scope`는 상태 조회와 설정 후 재조회를 구분한다. 가이드도 같은 뜻으로 맞췄다. 상태 조회가 setter 성공·물리적 소리를 검증했다는 뜻은 아니다.
- `compile_user_command`: 사용자 원문과 시스템 실행 지침의 출처를 나눈다. 의식의 절차는 실행 지시로 유지하되, 생성된 수량·조건을 사용자 인용이나 관측으로 취급하지 않는다. 기존의 출처를 숨기는 융합 설명은 대체했다. 후속 framing 패치와 기존 최종 평가에도 원문 대조 규칙을 연결했다. 새 모델 호출·숫자별 정규식은 추가하지 않았다.
