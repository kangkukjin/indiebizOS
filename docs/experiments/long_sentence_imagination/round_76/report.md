# 긴문장 76회차 — 문서 근거의 범위와 변경 검토

정본 main에서 훈련·안내 수리·재검증 완료. 실행기 결함은 발견하지 않았으며, 근거 영수증을 연결하는 가이드의 작성 공백 1건을 수리했다. 시작 HEAD `13b9d6ac`, 2026-10-18 21:41 KST 시작, 기본 상한 22:41. 최초 훈련 종료 확인 21:49:50, 수리 예제·새 변형·정리 검증은 21:52까지, 증거·보고·커밋은 이후 별도 운영 비용이다.

## 과제와 작성

[task.md](task.md)의 자연어 요구대로 실제 system_docs 6개를 두 실행자용 입력 사본으로 나눴다. 1~3줄의 원문·줄 번호·선언·관측 영수증을 연결해 파일별 의미 기억을 만들고 content 현재성을 회상해 JSON/Markdown 검토표를 저장·재독했다. 기본 다음에 범위 안 수정, 범위 밖 수정, 파일 부재를 함께 만들었다. 정본 문서 6개 바이트는 불변이다.

분해: `기억(row)`는 읽기→파일에만 적용되는 note와 원 발췌를 반환하고, `검토(row)`는 기존 단언의 실제 evidence_status를 반환한다. 최상위는 명부→각 함수→상태 집계→두 파일 저장→재독 검증이다. 변형은 이전 report를 명시 입력으로 삼아 note·발췌를 보존하고 recall만 다시 한다. 실패를 최신 상태로 바꾸지 않는다.

공개 조합 교재·폴더 조사 가이드·describe(self:read/list/write/forage)를 사용했다. 내부 구현·테스트를 열어 해법을 채우지 않았다. 작은 반환 탐침에서 실제 영수증 위치를 확인했다. 최초 HTTP 탐침의 edition:2 누락 1회는 작성 환경 오류이며 전체 프로그램 수정과 구별한다. 최초 완성 [base_v0.ibl](base_v0.ibl)은 검사 통과(ok=true, 도구 경계의 incomplete), 수정 0회로 기본·변형을 마쳤다. 훈련자 자신의 토큰은 미측정이다.

## 독립 AI 관측

동일 자연어 요청을 `/system-ai/chat`의 training/background로 보냈다. 두 작업 `task_sysai_3a93ec10`, `task_sysai_8dc4e68e`의 succeeded를 회수한 뒤 수리를 적용했다([종료 영수증](evidence/training_closed.json)). 풀이·정답·훈련자 산출물은 제공하지 않았다. 변형에는 자기 결과 재사용을 허용했다.

- **풀이:** 주 처리·기억·현재성 대조·집계·저장·재독 모두 IBL. 기본 Bash 2/IBL 8, 변형 Bash 4/IBL 7. Bash는 목록·표시·지문/DB 검사에 썼으며 핵심 계산을 Python으로 대체하지 않았다.
- **분할·재사용:** 읽기/note → 회상 → 표현을 결과 참조로 나눴다. 잘못 쓴 렌더를 수정할 때 성공한 읽기/note를 반복하지 않았다. 변형은 기존 note_id와 원 발췌를 유지하고 새 note 0개. 추가 원문 대조를 수행했으며 이 읽기는 현재 상태 확인 비용으로 별도 인정한다.
- **발견:** 반환 탐침으로 텍스트의 `.data.source_observation_ref`를 찾았다. 가이드의 잘못된 복수 필드를 직접 사용했다는 증거는 없다. 제시된 회상/관용구의 실제 사용은 0이며 이를 회상 실패로 단정하지 않는다.
- **작성 오류:** 기본은 보간 따옴표, 파이프 대상/잘못된 내장 호출을 두 주기로 수정. 변형은 순수식 자리 호출/try return, catch 구문, 선택 필드 접근을 세 주기로 수정했다. 컴파일러는 실행 전에 거절했고 AI가 스스로 고쳤다. [요청 원문](ai/)과 [거절 증거](evidence/ai_errors.json)를 보존한다. 기존 교재에 계약이 있어 실행기 결함으로 세지 않는다.
- **완료:** 두 파일 재독과 기본 결과 해시 보존, 최종 평가 사건을 확인했다. 원문과의 독립 대조도 전건 통과했다.
- **축적:** training이므로 증류하지 않았다. 이번 시험 단언은 15개 모두 정확한 id+locus를 확인해 forget하고 재회상으로 부재를 확인했다. 산출물·실행 영수증은 보존한다. 관용구 등록·해마 시딩은 하지 않았다.

## L76-1 — 영수증 연결 안내 수리

분류: 작성·발견 마찰. 폴더 조사 가이드는 `source_observation_refs`를 연결하라고 했지만 Document에는 그 최상위 필드가 없다. [최소 재현](guide_ref_repro.ibl)은 `필드가 없습니다: source_observation_refs`로 실패했다. 텍스트 반환 탐침으로는 단일 `.data.source_observation_ref`를 찾을 수 있으나, 이를 JSON에 일반화하면 같은 이름의 **원자료 필드**를 시스템 영수증으로 오인할 수 있다. JSON 업무 필드 자체의 값 보존은 정상이며 데이터 덮어쓰기 결함은 아니다.

[folder_survey.md](../../../../data/guides/folder_survey.md)에 현재 반환 구조와 실행 가능한 [예제](guide_example.ibl)를 넣었다. `evidence(value).events`에서 해당 값의 마지막 self:read/self:list 호출에 직접 붙은 영수증만 선택한다. 상위 명부를 읽은 영수증을 함께 붙이지 않고, 실제 영수증이 없으면 빈 목록을 유지한다. 새 문법·액션·등록 함수·실행기 변경은 없다.

검증: 가이드 원문 실행, 전체 JSON의 동명 업무 필드, 명부→파일의 두 읽기 연결, 목록 반환, 무관측 값, 무관측 note의 unknown, 원래 전체/변형과 복구·역순 새 변형. 모두 통과했다([수리 증거](evidence/repair_checks.json)). 수리 예제로 새로 주입한 참조는 실제 receipt이며 공급자 업무 문자열과 다르다. 기존 텍스트 전용 초안은 보존하고 [base_v1.ibl](base_v1.ibl)을 일반 반환 구조를 쓰는 판본으로 추가했다.

## 비용·낭비와 미검증

[계측 원본](evidence/metrics.json)의 청구 model.usage만 집계했다. 분류·의식·실행·평가·관측된 background 역할을 포함하며 캐시는 input에 다시 더하지 않았다.

| AI 실행 | input | output | cache_read(별도 표시) | cache_create(별도 표시) |
|---|---:|---:|---:|---:|
| 기본 | 1,698,310 | 11,005 | 1,451,781 | 239,676 |
| 변형 | 2,855,691 | 9,872 | 2,716,220 | 133,752 |

필요한 비용은 실제 관측·근거 대조·전건 출력 검증이다. 줄일 수 있는 일은 반환 경로를 찾는 추가 탐침과 AI의 문법 오기로 인한 5개 거절·재작성이다. 전자는 정확한 예제로 수리했고, 후자는 기존 교재/진단을 조회해 복구한 작성 마찰로 남긴다. 가이드의 안내 오류가 AI 문법 오기의 원인이라는 증거는 없다.

일반 영수증 선택은 전체 기본 프로그램에서 계산 단계 1,440→4,891로 증가했다. 함수가 근거 그래프를 훑는 비용이며 텍스트에만 통하는 짧은 경로와의 상충이다. 전후 HTTP 시간은 각각 한 번의 따뜻함이 다른 실행으로 성능 절감 근거가 아니다. AI에 같은 요청을 수리 후 다시 맡기지는 않았고 안내 변경의 AI 시간·전체 토큰 절감은 미측정이다. 사용자에게 본문/근거 확인을 떠넘기거나 원문 요구를 줄이지 않았다.

실행기·어휘 계약은 바꾸지 않았으므로 backend/frontend 전수 회귀·기기/원격/웹·대용량 대조는 실행하지 않았다. 이번 결과는 로컬 문서 범위/전체 JSON·목록과 공개 가이드 예제에 한정된다. 저장소의 다른 미커밋 작업은 변경·커밋 대상에서 제외했다.

## 재현 자료

최초/수리 프로그램, 독립 AI의 IBL 요청과 거절, 최종 파일, 계측, 독립 검수 결과를 이 폴더에 보존한다. `fixtures/`는 원 자료의 첫 3줄과 범위 밖 시험 줄로 줄인 비민감 자료다. 원래 전체 파일 지문·크기는 [sources.json](evidence/sources.json)에 있다.

새 전용 출력 폴더에 fixtures를 복사하고 manifest의 파일명을 그 사본의 절대경로로 치환한다. `base_v0.ibl` 또는 `base_v1.ibl`을 `edition:2, origin:training, project_id:study, inputs:{manifest_path,previous_path:"",out}`로 검사·실행한다. 변형은 1번 첫 줄 변경, 2번 마지막에 줄 추가, 3번 이동 후 `previous_path`를 기본 report.json으로 지정한다. 원래 시험 note_id는 정리했으므로 재현은 새 영수증과 note를 만든다. 시험을 마치면 자신의 note_id+locus만 확인해 정리한다. 실행 기반은 실제 로컬 API가 필요하며 오프라인 증거 대조와 실제 재실행을 구분한다.
