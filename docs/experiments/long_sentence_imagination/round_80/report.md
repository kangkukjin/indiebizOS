## 발견과 공통 수리

**L80-1 — 완료 공개가 저장·턴 해제보다 앞서는 구현 결함.**
`api_system_ai._process_turn`이 complete_task → save_conversation 순서였고,
conversation_sessions.owned_turn의 finish는 그 뒤였다. A2 완료를 회수한 뒤 A3를 보냈지만
A3 접수 14:28:32.600760은 A2 턴 마감 14:28:32.611189보다 약 10ms 빨랐다.
순차 후속이 동시 요청처럼 처리돼 소유권 없이 다른 CLI 문맥을 사용했고 REFLEX 영수증도 없었다.
A4는 다시 소유권 있는 세션으로 돌아가 직전 산출물의 작성 이력을 인계받지 못했다.
[evidence/race_before.json](evidence/race_before.json), [실행 원장](evidence/training_runs.json).

소유 위치는 HTTP 작업 수명과 세션 마감이다. 업무·파일명·합계·REFLEX 태그에 따른 특례는 추가하지 않는다.
수리: 답변 저장 → 소유 턴 마감 → complete_task의 순서로 바꾸고 turn_hold는 작업 완료까지 유지한다.
위임 대기 작업의 완료는 기존 처리자에게 남긴다. 턴 마감 DB 오류를 출력만 하고 숨기지 않아 성공 공개를 막는다.
새 어휘·상시 프롬프트·모델 호출·별도 완료 저장소 0.

재현 시험 `backend/test_api_system_ai.py`에서 저장 지연·마감 지연·답변 저장 실패가 수리 전 3실패,
위임 대기는 통과했다. 수리 후 마감 DB 실패까지 포함해 성공 오표시를 막는다.

## 비용·낭비와 잔여

원 AI 6회 비용은 evidence/metrics_before.json의 역할별 provider 사용량이다. cache_read/cache_create는
input에 포함돼 있으므로 다시 더하지 않는다. 작성자·운영 토큰은 미측정이고 총비용 절감은 주장하지 않는다.
A3는 다른 세션의 이전 79회차 자료를 먼저 읽고 현재 판본을 다시 확인했다. A4도 79·80회차를 탐색했다.
이 우회는 대화 인계 단절과 함께 관측됐으며, 모델 선택의 기여와 분리한 인과 절감률은 아니다.
필요한 비용은 독립 AI 실행·파일 해시 대조·마감 경합의 결정론적 재현·관련 및 전체 회귀다.
프로젝트 ID 오지정, trainer 출력 경로 중복, 반환 타입 표기 보완으로 추가된 자동 재기동, 새 테스트의 직접 실행 진입점 누락으로 인한 회귀 재실행은 운영 비용이다.
재기동은 제어자를 따랐으며 코드 편집 중 artifact_changed_before_start 한 번, 안정화 후 재기동·부팅 검사 대기가 있었다.

기존 HTTP 최근 7메시지 경계, 실제 동시 요청의 무소유 fallback, 장기 CLI 문맥 검색은 이번 수리 범위 밖이다.
현재 회차의 발견은 R2 연속성·R3 완료 근거·R4 재작업 비용에 해당한다. 과거 수리 계획의 철회된 우선순위는 재사용하지 않는다.
가이드의 이음새/불변식 회차 선택과 훈련 종료 후 수리 원칙은 유효했다. 완료 조회 뒤 즉시 후속을 보내는 시험이
수동 대기보다 경합을 잘 드러냈다. 새 상시 가이드 절차나 관측 전용 모델은 추가하지 않는다.

폰 번들 매니페스트 재생성 및 backend 층 가드 통과. 기존 다른 세션의 finance·폰 UI·registry 등 변경은 커밋에서 제외한다.
