시작 2026-10-20T06:06:44.138286+09:00, 훈련 상한 2026-10-20T07:06:44.138286+09:00, 시작 HEAD 99e536acae985fb5a1b5f3f5a941155b36f48aa7.
형식: 새 이음새 없는 불변식 탐침 묶음. R2 연속성·R3 완료 근거. 독립 AI 생략: 결정론적 파일 신선도 검사이며 AI 행동/비용이 질문이 아님.

요구: 지정 폴더의 모든 txt 파일을 목록으로 발견하고 각 파일의 숫자를 읽어 파일별 값·내용 지문과 총합을 JSON에 저장하고 재독한다. 파일이 사라지면 이전 값을 정상 결과로 쓰지 않는다. 빈 폴더는 정상 빈 목록·합계 0이다. 출력은 입력과 다른 폴더에 둔다.

입력은 합성 a.txt=10, b.txt=20. 기본 기대 2행/30. 같은 입력 재사용은 값/내용 지문 동일, 읽기 호출 재사용. 변형1 a.txt=90(동일 길이, 원 mtime_ns 복원): 2행/110이고 목록의 sha256도 현재 파일과 같아야 한다. 변형2 c.txt=30 추가: 3행/140. 변형3 b 삭제: 2행/120. 변형4 빈 폴더: 0행/0. 삭제는 회차가 만든 시험자료에만 수행.

공개 교재 ibl_composition.md, ibl_composition_tools.md, system_docs/ibl.md 및 describe만으로 초안 작성. 구현은 실패 증거 보존 뒤 진단에만 읽는다. 검사/종료/산출물 달성 따로 판단. HTTP origin=training, 프로젝트 문맥 명시. 훈련 작업 모두 종료 뒤 수리.

최초 초안·수정·실행 요청/응답·독립 SHA256 대조 보존. 시스템 모델 호출 없음, 훈련자 토큰 미측정. 훈련/진단/수리/검증 시간을 구별하고 절감률을 추정하지 않는다.

추가 경계: 읽기 전용 self:list의 새 파일 누락을 발견. 동일 전체 집계를 저장 직전 반환하는 판본(읽기 전용)을 기본 30 → a=90/c=30 추가 140으로 재현한다. 저장 유무가 목록 신선도를 바꾸면 결함이다. 내부 소스 진단 시작은 이 최소 실패 관측 뒤다.
