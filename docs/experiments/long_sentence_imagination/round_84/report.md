### L84-1 — 추출값 null을 제약 '불충족'으로 떨어뜨림 (훈련자 작성 결함, 요구 해석 오류/작성 마찰)

T5b v2에서 문제설정 모델이 세 개입 후보의 `hours`를 null로 냈고(T2·T3에서는 0.3~0.5시간을 냈음 — 같은 지시에 `previous_state` 입력이 더해진 뒤 결측), 제약확인이 `null ? false`로 처리해 채택 0·거절 3이 됐다.
brief는 그 결과를 그대로 "채택된 개입안이 없다… 거절 사유는 자료에 없다"로 썼다([one_pager_t5b_v2](outputs_trainer/one_pager_t5b_v2.md)). 실행은 성공, 재독 일치, 그러나 사용자 목적(개입안) 미달.
교재는 "미확인과 0을 섞지 않는다", judge의 "null은 미결정, false로 바꾸지 말고 확인 목록으로"를 이미 적고 있다. 작성자(훈련자)가 순수식 필터에서 그 규칙을 어긴 것이며 언어·실행기 결함이 아니다.
v3는 `unverified` 묶음을 분리하고 brief 지시에 세 묶음을 구분해 넘겼다. 재실행은 brief 1회만 새로 호출(11/13 재사용)해 "미확인 3건·가정·확인 항목" 메모가 나왔다([one_pager_t5b_v3](outputs_trainer/one_pager_t5b_v3.md)). 최소 재현은 결정적 검사 `T5b v2 결함 재현`·`T5b v3 unverified 3`.
공통 교훈: 모델 추출 필드는 전부 nullable이므로, **제약·합격 판정 식은 "충족/불충족/미확인" 3값으로 설계**해야 한다. 2값 Bool 필터는 결측을 조용히 한쪽으로 밀어 넣는다. 이 패턴은 83회차 L83-2(미확인 기능을 확인으로 단정)의 거울상(미확인을 불충족으로 단정)이다.

### L84-2 — 완료된 백그라운드 작업의 접수증이 재기동 뒤 404 (구현 결함·관측 공백, 기존 함정 재확인)

소비자는 "접수된 적 없음"과 "종료됐으나 기록 소실"을 가를 수 없고, 가이드가 요구하는 "`succeeded`/`failed`와 result 전문 회수"가 불가능해진다. 답변 전문은 `model.response_snapshot`에도 없었고(빈 text), 산출물 파일과 `supervision.tool.started`의 Write 입력에서만 복원됐다.
2026-10-07 코딩 앱 작업의 "완료 작업은 재기동 때 지워져 접수증 unknown"과 같은 원인이다. 이 회차는 재현 증거(네 작업·시각·404 본문)를 보존하고 수리는 하지 않았다 — 접수증 영속화는 `api_agents` 작업 저장소의 설계 변경이며, 동시 세션이 backend를 편집 중인 상태에서 backend 수정을 더 보태면 재기동 FAILED가 반복된다(이 회차 중 4회). 별도 수리 작업으로 넘긴다.
부수 관측: 프로젝트 에이전트의 start 상태도 재기동 뒤 사라져 매번 400 "에이전트가 실행 중이 아닙니다" → `start`를 다시 보내야 했다(83회차에도 동일). 의도된 수명인지 결함인지는 미판정.

**수리 후기(2026-10-20, 커밋 `b2c9e495`)**: 원인은 저장소가 아니라 부팅이었다 — 작업 행은 처음부터 SQLite(프로젝트 `conversations.db`·`system_ai_memory.db` 의 `tasks`)에 있었고, `boot_common._cleanup_completed_tasks` 가 맥·폰 공통 부팅마다 `status='completed'` 행을 전부 지웠다(2026-06-27 `065c5a91`, failed/cancelled 는 남김). 수리 = 보존 30일 지난 종료 행만 묘비(`task_tombstones`)로 바꾸고, GET 은 '접수 기록 없음' 404 와 '종료 후 소실' 410 을 가른다(접수증 어댑터는 `missing: unknown|lost`). 회귀 `test_boot_common.py`·`test_delegation_tasks.py`, 라이브 재검증(ai_execute background 1건 완료 → `restart --wait` → 같은 status_url `succeeded`+result) 통과.
부수 관측 판정 — 에이전트 start 상태의 재기동 뒤 소실은 **의도된 수명**: `agent_registry.agent_runners` 는 "살아있는 에이전트 런너 등기부"(프로세스 내 dict)이고 agents.yaml 에 running 표식·lifespan 에 에이전트 자동 start 가 없다. 바꾸려면 부팅 자동 start 정책(데이터)이 먼저 필요하므로 수리 범위 밖에 둔다. 남긴 것: 재기동 당시 pending 이던 작업은 재기동 뒤에도 running 투영(interrupted 표식 없음) — 별도 후보.

### L84-3 — 한국어 사용자에게 영어로 답함 (발견·학습 문제, 표현)

독립 AI 7턴 중 6턴의 채팅 답변이 영어였고 저장 파일은 모두 한국어였다(탐침도 동일). 사용자 발화·역할·자료가 전부 한국어다.
프로젝트 에이전트 프롬프트 조립(`prompt_composition` 기본 프롬프트 절)은 `base_prompt_v6.md`의 "사용자가 쓰는 언어로 응답하라"를 포함하므로 **규칙 부재가 아니다**. 규칙이 있는데도 ClaudeCode 공급자 EXECUTE 답변이 영어로 나왔다 — 프롬프트 문장을 더 보태는 수리는 원인에 맞지 않는다.
가설: ① 공급자 CLI의 자체 시스템 지시(영어)가 뒤에 붙어 우선된다, ② 48K 시스템 프롬프트 안에서 한 줄 규칙의 위치가 약하다, ③ 파일 작성(한국어)과 채팅 요약(영어)이 다른 단계로 갈린다. 어느 것도 이 회차에서 확정하지 못했다. 재현은 쉽다(이 회차 어느 턴이든). 실제 모델 입력의 시스템 본문 저장분 대조가 다음 단계다.

### 관측(갭 아님)

- 훈련자 T2 요구갱신이 target을 '이탈'로 좁혀 읽었다(사용자는 "중간에 그만두는 일"만 말함). T3의 명시 분리로 교정됐고 산출물 가설은 T2에도 두 집단을 다뤘다. 모델 해석 폭의 문제이며 발화 전달 결함이 아니다.
- 독립 AI는 T3에서 T2 파일을 덮어썼다(사용자 요구는 아니었음). 변형 V와 T5b는 새 파일을 만들고 기존 파일을 보존했다. 탐침 T3는 "이전 판본은 같은 폴더에 남겨 뒀다"고 명시했다.
- 작성 마찰: nullable 모델 필드를 Text 자리에 쓸 때 `text()`도 TYPE으로 거절돼 `get($r,"f","")`로 돌아갔다(v1→v2). 교재에 "결측 필드를 쓰기 인자로 확정하는 법"이 한 줄 없다.
- `[case]` 안 `return`은 함수 본문에서만 썼고 문제없음. `date_diff`·`split(maxsplit)`·`difference`·`[table:join]{how:"left"}`·`groupby by:[...]` 계약은 교재대로 동작.

## 5. 개선 방향

- **3값 판정 패턴(L84-1)**: 제약·합격 식을 쓰는 지역 함수의 반환을 `{accepted,rejected,unverified}`로 두고 brief 지시에 세 묶음을 넘기는 형태를 교재 「AI 추출값의 결측과 타입」 절에 **분야 중립 예제 한 토막**으로 보탤 가치가 있다(새 어휘·규칙 추가 아님, 기존 "null은 미결정" 규칙의 조합 예). 이 회차는 교재를 수정하지 않았다 — 훈련 중 교재 수정 금지 규약.
- **접수증 영속(L84-2)**: 백그라운드 작업의 terminal 상태·result 참조를 재기동을 넘겨 보존하고, 모르는 task_id에는 404 대신 "기록 없음/소실"을 구분해 알리는 것이 공통 경계다. 소유 위치는 `backend/surface/api_agents.py`의 작업 저장소(+`/system-ai/chat` background). 재검증 조건: 작업 완료 → `restart --wait` → `GET status_url`이 `succeeded`+result를 반환. 이 회차의 네 사례가 재현 입력이다.
- **언어 규칙 도달(L84-3)**: 프롬프트 추가 전에 실제 모델 입력 시스템 본문(spill 저장분)에 base_prompt 절이 어디에 놓이는지, ClaudeCode 공급자 호출에서 시스템 프롬프트가 어떻게 전달되는지 확인한다. 규칙이 도달했는데 무시되면 공급자 어댑터 쪽(출력 언어 보정 또는 시스템 지시 순서)이 소유 위치다.
- 분야 전이: 조건 교체/유지의 범위 추적(지출 교체·시간 유지)은 훈련자·AI 모두 통과했으므로 81회차 L81-1·L81-2(규정 계승·평가 전달) 수리의 다른 분야 회귀 근거로 쓸 수 있다. 단, 이 경로는 프로젝트 에이전트 EXECUTE이며 시스템 AI 의식 경로의 재검증은 아니다.
