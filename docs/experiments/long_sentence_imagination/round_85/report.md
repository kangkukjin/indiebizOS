### 구현

- **L85-1:** Safari 변경 전송 전 조회 timeout은 `OBSERVATION_FAILED`로 분류한다. `failure.stage=observation`, `failure.state_change_possible=false`를 기존 실패 봉투로 전달해 일반 catch가 근거를 보존할 수 있다. 즉시 status 재시도를 권하지 않는다. 앱 실행 요청 또는 탭 변경 전송 뒤 timeout은 여전히 UNKNOWN/protocol이며 자동 재전송하지 않는다. 실제 Apple Events가 응답하지 않는 환경 원인은 해결됐다고 주장하지 않는다.
- **L85-2:** Type의 공유 구조를 재귀 repr로 펼쳐 정렬하던 경로를 제거했다. 불변 자식 지문을 캐시하고, 동등성은 지문으로 빠르게 제외한 다음 방문한 쌍을 재확장하지 않고 실제 구조를 대조한다. join/정제 캐시와 제한된 진단 표시를 사용하며, 전체 위치·필드·Bool 판별자는 그대로 검사한다. 24겹 별도 프로세스 회귀와 계약·합집합 검사를 추가했다.
- **L85-3:** 등록 스크립트의 op별 효과를 선언했다. Safari contract/status는 read_external, 변경은 write_external이다. PC 내부 선택·준비·검증과 정확히 알려진 읽기 요청도 읽기로 분류한다. 부분적인 Record 리터럴의 알려진 선택자는 계약 특수화에만 쓰고, 동적 op/전개는 보수적으로 남긴다. 살아 있는 기기 상태는 per_run으로 새로 읽는다. Safari 실패 호출의 원장 state_change는 네 재실행 모두 0이다.
- **L85-4:** PC제어는 본체에서 원격 목록을 읽지 않는다. PC조회묶음은 한 대상·실행 파일을 공유해 읽기 항목을 순차 실행하고 실패를 행별로 남긴다. 지원하지 않는 동작은 전송 전에 거절한다. PC제어실행으로 기존 단일 요청과 묶음의 실제 전송·영수증 검증을 공유하며, 원격 전송의 실제 연결·권한 검사는 유지한다. target/prepare 실패는 미접수라고 안내한다. 배포 목록·가이드·기존 정의 개정과 의미 검색 시딩도 반영했다.
- **L85-5:** 하네스는 기본/변형 입력 폴더를 분리하고 수리 뒤 출력 위치를 따로 둔다. `base_v1.ibl`은 새 묶음을 사용하며, Safari 후속 관측이 실패하거나 revision이 달라지면 전체 Safari 검증을 true로 만들지 않는다. 원 v0는 역사 기록으로 유지한다.
