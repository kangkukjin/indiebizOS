# 86회차 — 본체 PC와 Safari 실기 점검

## 과제와 완료 조건

가상 요청: “이 본체에서 배경 업무를 시작할 수 있을지 판단할 자료를 모아 줘.
음향·사용자 입회 관련 상태·화면·전원·실행 앱·네트워크 상태와 Safari 창·탭 상태를 함께
점검하고, Safari 창이 있으면 첫 창을 지정해 다시 읽어 대상과 판본이 일치하는지 확인해 줘.
어느 조회가 실패해도 성공한 관측과 실패 근거를 한 JSON 보고서에 남겨 줘.
현재 상태 조회와 실제 소리·페이지 로드·사람이 보고 있다는 판단은 구분해 줘.
기존 탭이나 설정은 바꾸지 마.”

변형 요청: “같은 점검의 PC를 존재하지 않는 `L86_missing_pc_20261020`으로, Safari 창을
`2147483646`으로 바꿔 줘. 본체나 첫 창으로 대신하지 말고 실제 실패를 기록해 줘.
원래 보고서는 보존해 줘.” 추가 불변식은 빈 PC 항목 목록을 주었을 때 전체 점검 성공이
되지 않는지, 이미 저장한 보고서를 회수할 때 기기를 다시 조회하지 않는지다.

- 실제 원천: 현재 본체 macOS와 Safari 드라이버. 합성 입력: 부재 대상 ID·창 번호·빈 항목.
- 주 실행 PC 항목: status, presence, display, power, apps, network. 반환 순서와 개수 6을 대조한다.
- 기본/변형은 같은 최초 IBL과 다른 inputs로 실행한다.
- Safari 전체 조회 성공 후 창이 있을 때만 지정 창 1회. 실패를 즉시 재시도하지 않는다.
- 판본 변경은 별도 관측이며 같다고 꾸미지 않는다. 창 0개는 창/탭 검증 미검증으로 표시한다.
- 검사 통과, 실행 종료, 장치 관측 달성, 실패 보고 달성을 각각 구분한다.
- JSON 저장 후 재독 일치, 변형 뒤 기본 파일 SHA-256 보존을 검사한다.
- 실패·pending·unknown은 verified로 세지 않는다. pending은 원 반환으로 한정 회수한다.
- 사용자 입회 확정·물리적 음향·페이지 로드 완료·탭 변경은 미검증으로 표시한다.
- 실기 쓰기는 공유 기기의 격리 부재로 실행하지 않는다. 외부 발송·공개·예약 없음.

## 분해와 계약

PC 점검 함수는 대상·항목을 받아 묶음 조회와 pending 회수 후 행별 검증 결과를 반환한다.
Safari 함수는 지정 창 또는 전체를 읽고, 전체의 첫 창을 다시 관측해 판본을 대조한다.
조회 실패는 원 오류를 보존한다. 둘은 독립 원천이라 병렬로 수집하고, 최상위에서 개수·검증 수·
미검증 범위를 결합해 저장 및 재독한다. 실패 자체를 정상 관측으로 바꾸는 폴백은 없다.

## 경계 탐침의 추가 고정 (기본·부재 대상 실행 후, 탐침 실행 전)

빈 항목 외에 미지원 항목 `L86_unknown_action`이 섞인 묶음과 영수증이 소실된 pending 반환을 검사한다.
미지원 항목은 성공하지 않아야 하고, 소실 영수증은 unknown/verified=false여야 한다.
전송 원장으로 실제 장치 호출이 없는지 별도로 확인한다. 기본 보고서는 self:read로 회수하고
6건 성공·Safari 미확인이라는 기존 결과를 보존한다. 이 회수에는 기기 재조회가 필요 없다.
조회 실패 뒤에만 원인 진단으로 safari_control.py와 기존 driver 시험을 읽었다.
제품 수정 없이 기존 PC·Safari 회귀를 추가 실행해 변경 동작의 모의 끝단 검증을 별도로 기록한다.
