# 88회차 — 복잡한 프로젝트를 오래 이어가기

사용자 주제: “복잡한 프로젝트에 관해 장시간 일하기”. 정본 main에서 진행.
준비 시작 2026-10-22 11:02 KST, 전체 훈련·진단 상한 12:02(60분), 기록·정리 별도.
형식: 사용자 지정 주제 + 독립 AI 행동·비용이 질문(가이드 §4-5 ③).

## 과제와 가정

지역자료실 이전·검색 서비스 시범 개통. 작업 72개·6분야·선행관계 66개,
자료 검증 1800건·4조건을 종합하고 예산·범위 변경, 담당자 완료/검증 불일치,
중단 인계, 같은 경로 자료 정정, 오래된 제안 도착, 잘린 검증 자료, 복구를 차례로 반영한다.
개인 자료와 실서비스 변경 없이 정답을 독립 계산하기 위해 전부 합성했다.
실제 외부 이전·배포·연락·예약은 없고 입력 읽기/회차 폴더 쓰기만 한다.
시간을 채우는 반복·sleep을 넣지 않는다. 다일 작업 상황은 모사하며 실제 경과시간과
자연 발생한 문맥 압축을 별도로 기록한다. 강제 압축·운영 백엔드 재기동은 하지 않는다.
T4 종료 뒤에는 공개 API의 훈련 에이전트 stop/start로 정상 수명 중단·재개를 한 번 수행한다.
프로젝트 대화·원장·산출물은 복원/초기화하지 않는다. 전체 백엔드 재기동·강제 장애 실험은 아니다.

## 입력과 결과

`setup.py`는 입력·변형 자료·자연어 요청·독립 기대값만 만든다.
로컬 정본: `outputs/long_sentence_imagination/2026-10-22_88회차/`.
실행자는 inputs와 자신의 ai 출력만 접근하도록 요청한다. staged·reference·trainer·snapshots 및
본 docs는 실행자 입력이 아니다. 실제 도구 기록으로 접근 여부를 감사하며 OS 접근차단으로 주장하지 않는다.
훈련자 .ibl은 같은 입력을 직접 읽어 계산·저장·재독한다. Python은 자료 준비·전송·독립 검증용이다.
초기 상태·조건 변경은 명시 입력, 사람의 새 결정은 실행 경계를 나누는 이유다.

|---|---|---|
| T1 | 초기 전량 분석 | 1800건, 적합1616, 동의누락90/체크섬실패40/검색불가60/접근성실패72(중복 존재), 72작업 |
| T2 | 예산420만·SaaS/얼굴/W6 제외 | 필수60·선택취소12, 기한11/20·개인정보/접근성 유지, 철회안 부활 없음 |
| T3 | 완료 보고12건 | 필수 검증완료9, W4-02 미검증, W6 취소 유지; 다음 필수 W1/2/3/5-03와 W4-02 |
| T4 | 중단·인계만 | 결정·근거·진행·다음 행동 보존, 새 전체 분석 불필요 |

작업원가와 선택안 견적의 관계는 입력의 명시 설명을 따른다. 예산 맞추려고
필수 작업·검증 조건을 임의 철회하지 않는다. T1~T8 산출물은 판본별로 보존한다.
정답을 이후 출력에 맞춰 변경하지 않는다. 부정확·불완전한 결과는 부분 달성/미달로 남긴다.

## 훈련자 분해와 공개 계약

자료 읽기 → 검증 항목별 분류 → 완료 영수증 반영 → 선행조건 판정 →
현재 정책과 결합 → 상태·보고서 저장 → 재독 검증. 독립 자료 읽기는 병렬로,
행 판정/합산/의존관계는 지역 함수·순수 목록 연산으로 조합한다.
입력/반환/실패는 .ibl 함수와 describe/check 결과에 남긴다.
수정 전 초안 보존, 수정 이유·횟수 기록. 접수 API는 기존 회차 하네스를 참고했으며
업무 프로그램 작성에는 공개 교재·describe만 사용한다.

## 판정·비용·종료

검사/실행 종료/과제 달성은 구분한다. 같은 독립 기대값으로 훈련자와 AI 산출물을 확인한다.
AI는 자연어 요청만 받고 풀이·훈련자 결과는 받지 않는다. 턴마다 terminal 확인 후 다음 요청.
작업/에피소드/도구/산출물/판본을 연결하고 역할별 billable_usage와 문맥 압축을 기록한다.
접수 오류·관측 누락·미측정은 숨기지 않는다. 시스템 구현 수리는 이 요청에 포함하지 않고
훈련자 프로그램 수정과 원인 진단까지 수행한다. 모든 훈련 작업 종료 확인 뒤 보고·pathspec 커밋.
