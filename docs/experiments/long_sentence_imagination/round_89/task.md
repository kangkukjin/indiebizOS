## 분해와 계약

A 자료검증: 자료와 기대 ID → 적합·실패·미확인·행별 판정.
B 비용검토: 작업·선택안 설명·정책 → 유효 작업비·예산 차이·취소 목록.
C 일정검토: 작업·영수증·정책 → 검증 완료·착수 가능·미완료·선행관계와 병목 작업시간.
D 운영조건: 프로젝트 요구·정책 → 전량·네 검증조건·필수 작업 완료 등의 인수조건.
E 보완대상: A+D 합류 → 자료 보완·미확인 확인 목록. B/C 완료를 불필요하게 기다리지 않는다.
F 최종조치: E+B+C 합류 → 예산·자료·필수 작업 차단 사유, 우선 조치, 인수 검토서.
모든 결과는 작업 ID·입력 판본·시작/종료·근거를 갖는다. 가지별 자기 산출물, 최종 쓰기 단일 소유.
현재 공개 교재·describe만으로 IBL 작성. 88회차 프로그램은 공개된 기존 실행 예제로 참조.

## 비교·검증·예산

동일 함수·입력·산출 조건에서 순차/병렬을 교대 실행하고 시간 표본을 보존한다.
AI 실행과 부하가 겹친 표본은 표시하고 성능 비교에서 분리한다. 내부 시간 계측 호출 비용도 포함한다.
원래 결과의 상세행·합계·근거·필수 조건을 독립 Python oracle로 전건 대조한다.
Python은 입력 준비·전송·검증만 담당하며 훈련자 업무 조합은 IBL로 실행한다.
AI에는 분해안/IBL/정답을 전달하지 않고 같은 자연어 요청으로 독립 수행시킨다.
실제 작업 구간 겹침, 의존관계 시작/종료, 판본, 재사용·재실행·쓰기, 역할별 모델사용량을 기록한다.
검사 통과/실행 정상/과제 달성/병렬 능력은 별개로 판정한다. CPU 계산의 실제 동시 수행을
함수 구간 겹침만으로 주장하지 않는다. 시간 이득이 없어도 숨기지 않는다.
기본+조건변경 필수, 누락+복구는 예산이 허용하면 수행. 지연·중복·이전 판본 도착은 이번 필수 범위 밖.
작업 종료와 자식0 확인, 에이전트정지·health·전후revision 기록 후 pathspec 커밋한다.
