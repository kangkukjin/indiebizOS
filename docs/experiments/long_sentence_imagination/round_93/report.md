## 발견과 수리

**L93-1 — 재현 코드의 파일 집합 누락.** `file_script.inspect_record`는 manifest에
적힌 파일만 비교했고 `reproduce`는 폴더 전체를 `copytree`했다. 따라서 나중에 추가된
모듈이 새 실행에 들어갔다. 실제 선택적 import 탐침에서 원래 값7이 재현 값99로
달라졌고 새 manifest에는 추가 모듈이 들어갔다. 파일명만 다른 같은 과제뿐 아니라
아무 스크립트의 import·이전 실패 재현에도 적용되는 원인이다.

**L93-2 — 검사한 바이트와 실행한 바이트의 분리.** 검사 뒤 코드는 copytree가,
stdin은 별도 read가 다시 읽었다. 그 사이 변경은 원래 지문과 대조하지 않았다.
시험에서 검사 직후 각각을 교체해 다른 바이트가 실행부에 전달됨을 확인했다.

공통 소유자 `backend/base/file_script.py`를 수정했다. 보존 코드 폴더의 **전체 파일
집합·지문·링크 여부**와 stdin을 검증하고, 실제로 검증한 바이트만 새 작업 폴더에
복사한다. 실행기의 기존 `expected_hashes`도 이어서 사용한다. 원본 기록을 수정하는
대신 원래 `~turn` 파일을 수정해 새 시도하는 흐름은 유지한다. 새 어휘·모델 호출·
저장소·승인 절차는 추가하지 않았다. 가이드에도 재현과 새 시도 경계를 명시했다.

R2의 복구 연속성과 R3의 근거 동일성을 강화하는 수리이며, R4의 임시 Script 경로를
그대로 사용한다. 기존 잘못된 기록을 수리된 CLI에 넣자 `SCRIPT_RECORD_INVALID`,
종료코드1, 새 실행0으로 거절했다. 정상 지역 모듈의 수정·원본 재현도 함께 통과했다.
