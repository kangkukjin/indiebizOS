## 2. 작성과 조합

훈련자는 공개 교재 `ibl_composition.md`, `script.md`, live describe의
`self:read/write/script` 계약을 사용했다. 내부 엔진·테스트 구현은 해법 작성에 읽지 않았다.
이전 95회차의 HTTP 운반·에피소드 회수 코드만 운영용으로 참고했다.

전체 IBL은 자료 확인 → JS 엔진/UI 파일 저장·재독 → 사례별 Node 실행 → 결정론·충돌·
명령 결과 판정 → JSON/보고서 저장·재독을 연결한다. Node는 전투 시뮬레이션과 프레임
측정을, Python은 Node 1회 호출을 담당한다. 성공·실패 집계와 최종 판정은 IBL에 있다.
직접 작성한 게임 부품을 inputs로 전달한 시험이므로 이 실행을 독립 AI의 생성 능력으로 세지 않는다.

필요한 비용은 게임 구현·근거 구분·독립 검수와 재생 실패 진단이었다.
줄일 수 있었던 비용은 훈련자의 혼잡 경로 매회 재계산, 원문 인코딩 사전 확인 누락,

필요했다. 다만 후속 입력량이8.5백만이고 보고서에 시험 출력 전문을 길게 반복한 것은
반환·문맥 비용 후보이며, 시나리오별 지표와 원문 참조로 줄일 수 있다. 읽기 재사용/부분 배치를 더 쓰면 줄일 수 있으나, 같은 조건의
작성·전체 토큰 절감은 측정하지 않았다. 보완판은 더 많은 유닛을 통과시키는 대신 실행 비용이 늘었다.
최종 검수나 실패 보존을 낭비로 세지 않는다.

재현: 공식 HTML을 ai/inputs·trainer/inputs에 저장하고 sources.json에 원본 자료의
존재 여부를 사실대로 적는다. 원본 HTML은 보존하고 trainer용 UTF-8 사본을 생성한다.
`prepare.py VERSION [--variant]`가 코드·입력·예산을 가진 HTTP 봉투를 만들고,
`live.py ibl LABEL`이 검사 후 동일 코드를 실제 실행한다. `holdout.js`, `compare.js`,
`browser_check.py`, `ai_browser_check.py`는 외부 대조이며 제품의 전수 회귀시험이 아니다.
ai_final_scenarios.js의 기본 엔진 경로만 보존 폴더에 맞췄으며 검사 조건은 AI가 실행한 원문과 같다.
