## 자연어 요청 원문

스타크래프트 1의 마린 소규모 전투를 관찰 가능한 근거에 따라 재현해 줘.
먼저 제공 자료에 원본 게임 실행·리플레이·관찰 영상이 있는지 확인하고, 실제 관측과
공식 문서에서 읽은 사실, 네가 선택한 근사 규칙을 구분해 줘. 원본이 없으면 그 경계를
명시한 실행 가능한 프로토타입까지 만들되 원본과 일치한다고 주장하지 마.
원본 엔진 코드나 다른 구현을 복사하지 말고 직접 작성해 줘.

결과는 네트워크·설치 없이 index.html을 열어 조작 가능한 2D 전투장이다.
마린 양측20기, 평지와 좁은 입구가 있는 벽, 드래그 선택·다중 선택·이동·지정 공격·
공격 이동·정지·일시정지·재시작을 지원해 줘. 적 병력은 전투에 참여해야 한다.
유닛이 벽이나 다른 살아 있는 유닛을 관통하지 않고 입구를 통과해야 한다.
선택과 명령은 실제 시뮬레이션에 영향을 주어야 하며 체력·사거리·공격 주기·사망을
표시해 줘. 자원·건물·생산·캠페인은 범위 밖이며 유닛은 처음부터 배치한다.
같은 초기 상태와 명령이면 결과가 같아야 하고, 명령 기록을 내보내고 다시 재생할 수 있어야 한다.
공식 자료로 확인한 수치는 출처와 연결하고, 시간 단위·좌표 변환·이동·충돌·타깃 선택·
시야 등 확인하지 못한 규칙은 근사 또는 미구현으로 밝혀 줘.

독립 평가를 위해 engine.js는 브라우저 window.RTS와 Node module.exports로 simulate(scenario)를
노출해 줘. 입력 scenario는 {width,height,walls:[{x,y,w,h}],units:[{id,team,x,y,hp?}],
commands:[{tick,ids,kind,x?,y?,targetId?}],ticks,seed}다. 좌표는 픽셀이고 kind는
move/attack/attackMove/stop이다. commands는 tick 시작에 적용하고 결과 final은
모든 원래 유닛의 {id,team,x,y,hp,alive}를 포함해 줘. events는 발사/피해/사망의 tick과
관련 유닛을 보존하고, frames는 매 tick 종료 뒤 모든 유닛 상태를 담아 줘.
추가 필드는 자유지만 이 계약은 지켜 줘. 잘못된 입력은 명확히 거절해 줘.

index.html, engine.js, 구현에 필요한 파일, rules.json(수치·근거·가정), report.md를
출력 폴더에 만들고 실제 실행 검증해 줘. 문서 출처, 조작법, 실행 명령, 확인한 항목과
미검증 항목을 보고해 줘. 부족한 원본을 합성 결과로 대체해 검증 성공으로 쓰지 마.
파일은 자기 출력 폴더 안에만 만들고 입력은 바꾸지 마. 공개 배포·설치·제품 코드 수정은 하지 마.

## 후속 요청 원문

기존 구현과 네 자신의 결과를 이어 써서 변형을 검증해 줘. 40대40기, 입구 폭 축소,
유닛 입력 배열 역순, 이동 중 정지 명령, 상대가 전혀 없는 상황에서도 실행해 줘.
원래 기능·근거·원본 미검증 표시는 유지하고 첫 판본은 보존해 줘.
변경이 필요하면 variant 하위 폴더에 두 번째 판본을 만들고 어떤 조건에서 왜 바꿨는지
report_variant.md에 기록해 줘. 변경이 필요 없으면 기존 구현을 재사용해도 된다.
실제 검증 결과와 아직 실패하거나 확인 못 한 항목을 함께 밝혀 줘.
다른 실행자의 trainer/reference/runs, docs/experiments의 해법·정답은 참조하지 마.

## 사전 완료 조건과 판정

1. 원본 관측·원본 대비 궤적/전투 결과 비교: 원본 실행/리플레이가 없으면 미검증.
2. 독립 AI/훈련자 모두 오프라인 조작 가능한 실물과 위 API 계약을 제공한다.
3. 공식 Marine 체력/피해/사거리/공격 주기를 출처에서 추출하고 근사 규칙과 구별한다.
4. 같은 입력 두 번 결과 동일, HP 유한·비음수·상한, 사망 후 행동 없음.
5. 벽 관통·살아 있는 유닛 중첩 없음, 통로가 있는 이동에서 진행함.
6. move/attack/attackMove/stop 의미와 적 전투, 명령 재생을 실제로 검증한다.
7. 기본20대20 + 위 변형의 기대/실제/실패를 보존한다. 역순 입력은 결과 변화 관측이며
   원본의 배열 순서 독립성을 알 수 없으므로 그 자체를 실패로 단정하지 않는다.
8. 실제 관측이 없으면 prototype_verified와 original_equivalence_verified를 구분한다.

전체 재현 달성에는1~8이 필요하며, 실행 성공만으로 달성으로 바꾸지 않는다.
주요 불변식은 공식 수치와 입력 조건으로 독립 검수한다. 원본과의 일치는 별도로 남긴다.
미리 고정한 holdout: 사거리 바깥 정지 표적, 사거리 안 표적, 좁은 통로 이동,
move 중 stop, 빈 적, 빈 유닛, 중복 id/비유한 좌표 거절. 원본의 미공개 규칙을 정답으로 꾸미지 않는다.

## 실행·분해 계약

공개 IBL 교재·live describe를 사용하며 내부 엔진/테스트 코드는 해법 작성에 읽지 않는다.
과거 회차 live.py는 HTTP 운반/에피소드 회수에만 참고한다.
훈련자는 자료 읽기·사실/가정 계약→엔진/UI 파일 저작→시나리오별 실행→결과 불변식 판정→
보고서/기계 결과 저장·재독을 전체 IBL로 연결한다. JS가 게임 시뮬레이션을 담당하며
Python 어댑터는 Node 한 번 실행만 담당한다. 핵심 과제 조합·판정은 IBL에 둔다.
독립 AI에는 자연어 요청과 자기 자료/저장 경로만 주며 훈련자 소스·가정·정답을 주지 않는다.
훈련자 게임 구현은 작성자가 만든 부품이므로 독립 AI의 생성 능력과 혼동하지 않는다.
제품 결함은 발견으로만 남기고 이번 요청에서 수리하지 않는다.
