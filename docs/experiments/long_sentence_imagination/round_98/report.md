## 5. 개선 방향(공통 능력)

- **검사 판본 연결**: 영수증은 내용 해시를 싣고, 조회는 현재 해시와 대조한다 — 시간·크기·"통과" 표식만으로 재사용하지 않는다(L98-1·2). 제품 apply 는 이미 readiness.candidate_hash 로 지키고 있었고, 제안·상태 조회 층에 같은 규칙을 넣었다.
- **변경 범위 회수**: "무엇이 바뀌었나" 는 제안 시점 저장이 아니라 조회 시점 재수집(L98-1 files)과 미추적까지 보는 diff(L98-3).
- **정직한 요약의 세 축**: 기계 검증 / 시험 실행 / 요구 충족 / 범위 / 근거 / 적용 을 한 칸에 접지 않는 보고 형식이 탐침 b·c·d·e·f 를 전부 갈랐다. 가이드에 새 절을 두지 않고 설계 §5 표를 그대로 썼다.
- 재검증 조건: 원래 v3 주 과제·변형을 수리 뒤 다시 돌리면 `evidence_product` 가 "미확인"→"재사용가능/불가" 로, 탐침 d 의 제품 `files` 가 2건으로 바뀌어야 한다(§7 라이브 재실행).
