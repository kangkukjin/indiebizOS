# 맥12 미디어 설치 — 2026-10-14

맥12(2012 MacBook Air, Intel)의 실제 운영체제는 macOS 15.7.9다. 기존 Go 1.22
legacy 헬퍼에는 WebRTC 엔진이 없었고 FFmpeg·FFplay도 없어서 조종실의 카메라 기능을
사용할 수 없었다. 등록을 유지한 채 기존 헬퍼 교체 절차로 일반 Intel 서명본을 설치했다.

## 설치한 구성요소

- 헬퍼: 정본 `helper/dist/indiebiz-helper-mac-amd64`, Go 1.26.5, Pion v4.2.23.
  SHA-256: `a1634f86821d49645fc3ebc4668a84f9448774642cfb6ec55e63cd5e159f95e2`.
- FFmpeg·FFplay: Martin Riedl의 서명된 macOS amd64 9.0.2 배포본.
  다운로드 기준 URL: <https://ffmpeg.martin-riedl.de/download/macos/amd64/1789931006_9.0.2/>.
  게시된 ZIP 해시와 대조하고 각 실행파일의 `codesign --verify --strict`를 확인했다.
  두 실행파일의 서명 TeamIdentifier는 `KU3N25YGLU`다.
- 기존 mpv 0.37.0은 그대로 사용한다.

| 다운로드 파일 | SHA-256 |
| --- | --- |
| ffmpeg.zip | `7c6b4125b191cbf773832dc51f424cf2b6bb7da43007d1e066f95909e47cacd4` |
| ffplay.zip | `8c64d2bbd884e533f25e30aacff3f637cd298213a083ef900de667fa91e22ada` |

헬퍼 데이터 폴더는 대상 맥의 `~/Library/Application Support/IndieBiz/resident-*/`다.
서명된 FFmpeg 원본은 `libexec/ffmpeg`, FFplay는 `bin/ffplay`에 설치했다.
`bin/ffmpeg`에는 아래 호환 어댑터를 배치했다. 원본 바이너리의 서명은 변경하지 않았다.

## FaceTime HD 프레임 속도 호환

기본 헬퍼는 AVFoundation 카메라에 30fps를 요청하지만, 이 카메라는 해당 모드에서
29.97fps를 지원한다. 덮개를 연 뒤에도 정확히 30fps를 요청하면 캡처가 실패했다.
[`helper/media_compat/ffmpeg-macos-ntsc.sh`](../../helper/media_compat/ffmpeg-macos-ntsc.sh)는
AVFoundation 영상 입력의 `-framerate 30`만 `30000/1001`로 변환한다.
마이크 전용 입력(`none:*`), 다른 입력 형식, 다른 프레임 속도는 그대로 전달한다.
이 어댑터는 이 장비에만 설치했으며, 전체 Mac 배포본의 기본 동작을 바꾸지 않았다.

재설치 시 서명된 원본을 `libexec/ffmpeg`에 먼저 두고 위 스크립트를 실행 가능 모드로
`bin/ffmpeg`에 설치한다. 미디어 설치기가 `bin/ffmpeg`를 덮어쓰면 어댑터를 다시 적용해야 한다.
호환 조치를 제거하려면 `libexec/ffmpeg` 원본을 `bin/ffmpeg`로 복원한다.

## 실기기 검증

- 교체 후 재연결 및 최신 헬퍼 상태 확인. camera·microphone·speaker·playback·display
  기능과 Pion 엔진이 등록됨을 확인했다.
- 사용자가 덮개를 열고 권한을 허용한 뒤, 조종실 카메라 보기에서 실제 **1280×720 영상**을 확인했다.
- 카메라·마이크의 macOS 권한이 모두 허용 상태임을 읽기 전용으로 확인했다.
- 마이크 2초 입력을 파일 저장 없이 처리했고 비영(非零) 신호를 확인했다.
  FFmpeg 종료 코드 0, 측정 최대 음량 -26.3dB.
- FFplay로 1초 무음 입력을 재생하고 종료 코드 0을 확인했다. 실제 스피커의 가청 출력이나
  상대방과의 양방향 음성 통화는 검증하지 않았다.
- 어댑터 `bash -n` 및 인자 전달 5개 사례 확인: 버전 조회, 영상 30fps 변환,
  25fps 유지, 마이크 전용 입력 유지, 공백 포함 일반 입력 유지.

영상 연결은 성공했지만 시험 중 RTT 약 1.9초, 패킷 손실 약 28%가 관측됐다.
설치와 실제 영상·마이크 입력 성공을 확인한 것이며, 끊김 없는 통화 품질을 보장하는 결과는 아니다.
이 변경은 설치용 스크립트와 기록에 한정되어 전체 backend/frontend 회귀는 실행하지 않았다.
