# Mac 헬퍼 교체 준비본 — 2026-10-14

> 아래는 설치 전 준비 시점의 기록이다. 같은 날 맥12의 실제 OS가 macOS 15.7.9임을
> 확인한 뒤 **일반 Intel 헬퍼를 설치**하고 카메라·마이크를 검증했다.
> 현재 설치 상태와 호환 조치는 [맥12 미디어 설치 기록](MAC12_MEDIA_2026_10_14.md)을 따른다.
> 아래의 legacy 선택 안내는 당시 구형 Go 등록에 따른 것으로, 현재 맥12에는 적용하지 않는다.

맥12에 나중에 설치할 **인증서 서명 완료 교체본**을 정본 `helper/dist`에 준비했다.
현재 맥12의 실행파일·등록·권한은 변경하지 않았다. 원격 교체 작업도 접수하지 않았다.

## 준비 당시 교체 안내 (맥12 설치 후 상태는 위 기록 참조)

1. 맥12에 로그인해 두고 중앙 IndieBiz OS에서 연결 상태를 확인한다.
2. 조종실 → 손발(USB) → **맥12 → 헬퍼 교체**를 누른다.
3. 새 헬퍼가 다시 연결되어 **헬퍼 최신**으로 표시되는지 확인한다.
4. 화면 공유로 실제 창이 보이는지와 입력 동작을 확인한다. 배경화면만 보이면 맥12의
   시스템 환경설정 → 보안 및 개인 정보 보호에서 화면 기록·손쉬운 사용의
   **IndieBiz Screen** 항목을 확인한다. 기존 ad-hoc 서명에서 인증서 서명으로 처음
   넘어가는 교체이므로 기존 항목을 지우고 설치된 새 앱을 다시 추가해야 할 수 있다.
   설치된 `indiebiz-helper`의 전체 디스크 접근 권한도 필요한 경우 다시 확인한다.

준비 당시 맥12는 Intel `go1.22.12` 계열을 사용했다. 중앙은 이 정보를 보고 자동으로
**`indiebiz-helper-mac-amd64-legacy`**를 선택한다. 이름의 ‘12’를 macOS 버전으로 해석해
일반 Intel 파일을 선택하지 않는다. 새 등록이나 등록 해제는 필요 없다.
기존 교체 절차는 설정을 보존하고 이전 실행파일을 남기며, 새 판 확인에 실패하면 되돌린다.

## 보관한 실행파일

정본 경로: `helper/dist/`.
별도 보관본: `outputs/mac-helper-signed-2026-10-14/` 및 같은 이름의 `.zip`.
보관본은 실행파일·안내·해시·검증 기록만 포함한다. 등록 키나 개인키는 포함하지 않는다.

| 파일 | 용도 |
| --- | --- |
| `indiebiz-helper-mac-amd64-legacy` | Intel macOS 10.15~11, Go 1.22.12 (준비 당시 맥12 교체 후보) |
| `indiebiz-helper-mac-amd64` | Intel macOS 12 이상 |
| `indiebiz-helper-mac-arm64` | Apple Silicon macOS 12 이상 |

수동 USB 교체가 필요하면 기존에 준비한 USB 등록 폴더의 해당 실행파일만 이 보관본으로
바꾸고 기존 `indiebiz-helper.json`은 유지한다. 맥12에서 legacy 파일을 열어 기존 설치의
교체 버튼을 사용한다. 이 보관 ZIP 자체에는 등록 설정이 없으므로 신규 설치용 USB 전체 묶음은 아니다.

일반 개발 빌드(`helper/build.sh`)를 실행하면 `helper/dist`가 ad-hoc 판으로 바뀐다.
그 뒤 이 배포본을 쓰려면 보관 폴더의 Mac 실행파일 3개를 `helper/dist`에 다시 복사한다.
`SHA256SUMS.txt`로 파일을 대조할 수 있다. 인증서로 다시 서명할 필요는 없다.

## 검증과 한계

- 중단된 수리 사본에 이미 서명이 완료된 실행파일을 회수했다. 같은 내용의 재빌드·재서명은 하지 않았다.
- 회수 시 helper 소스 전체를 현재 정본과 바이트 대조했다. 원래 Go 빌드 기록은
  `063582f650ead7b6e366158e0e989ca9254bbffa` 및 수정 작업 트리를 가리킨다.
- 헬퍼 3개와 화면 워커 2개의 `codesign --verify --strict` 통과. 각 헬퍼에 해당 서명된
  워커 바이트가 정확히 하나 들어 있는 것도 확인했다.
- 지정 요구사항은 각각 `com.indiebiz.helper` / `com.indiebiz.screen`과 같은 인증서
  `6ee4cda7d4f240d9cb35fcae77b1fe56fca7f4f2`에 연결된다. 파일마다 달라지는 ad-hoc 해시 요구사항이 아니다.
- 자체 인증서 서명이며 Apple 공증 배포본은 아니다. 실제 대상 Mac의 최초 권한 재등록과
  화면 공유 성공은 교체 후 확인해야 한다. 현재 맥12 화면 문제가 해결됐다고 판정하지 않았다.

파일별 SHA-256·빌드 버전·서명 요구사항·소스 해시는
`MAC_HELPER_2026_10_14_MANIFEST.json`을 따른다. 기존 정본 바이너리는
`data/_backups/2026-10-14_helper_before_signed_release/`에 보존했다.

최종 검사: 관련 Python 회귀 62개 통과. Go 교체·되돌림·화면 워커 시험 `-race` 통과.
이번 arm64 배포 실행파일을 임시 허브에 연결한 실프로세스 시험 1개 통과(명령 실행,
파일 왕복, 중복 요청, 비정상 종료 자식 회수, 재시작 복구). Intel 실기기 실행은 미검증이다.
중앙의 맥12 헬퍼 상태는 `available`이며 설치된 파일의 해시는 준비 전과 같음을 확인했다.
